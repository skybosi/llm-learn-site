不同 GPU 规格对比#

到了选型这一步，面对琳琅满目的显卡，你需要的不是记参数表，而是知道该盯着哪几个数字看。学完本课，你应当能读懂一张 GPU 规格表，并判断它适不适合跑某个规模的模型推理。

一、概念讲解#

1. 四个关键规格#

一张 GPU 对 LLM 推理是否合适，主要看四个数：

  • 显存容量（VRAM）：决定"权重 + KV cache + 激活"能不能装下，是硬门槛；
  • 显存带宽（memory bandwidth）：回顾第 4 章 Roofline——LLM 解码是访存密集，吞吐 ≈ 带宽 ÷ 每 token 要读的权重字节数，带宽几乎直接决定生成速度；
  • 算力（FP16/BF16/INT8 的 FLOPS 或 TOPS）：影响首个 token 的延迟（prefill 阶段是计算密集）；
  • 功耗与价格：决定单位算力/带宽的拥有成本。

对"每分钟生成多少 token"这个核心指标，显存带宽通常比算力更关键——这是选型时最容易搞反的一点。

2. 消费级 vs 数据中心级#

型号 显存 带宽 定位
RTX 3090 24 GB GDDR6X ≈ 936 GB/s 消费级
RTX 4090 24 GB GDDR6X ≈ 1008 GB/s 消费级
L40S 48 GB GDDR6 ≈ 864 GB/s 数据中心（推理向）
A100 40G / 80G 40/80 GB HBM2e ≈ 1.6 / 2.0 TB/s 数据中心
H100 80G 80 GB HBM3 ≈ 3.35 TB/s 数据中心旗舰

规律很清楚：数据中心卡（HBM）在带宽上碾压消费级卡（GDDR），但价格也高一个量级；消费级卡胜在每 GB、每 TB/s 的价格极低，代价是显存小、无 NVLink、软件/散热受限。

3. 从规格到"能跑什么"#

用第 5 章的显存账本就能快速判断：

  • 24 GB 消费卡：7B 模型 FP16 舒适，13B 需 INT8/INT4 量化；
  • 48 GB（L40S）：13B FP16 可行，70B 需量化；
  • 80 GB（A100/H100）：70B FP16 可行，175B 需量化或多卡。

再结合带宽估算生成速度，就能在"能不能跑"之上再问一句"跑得够不够快"。

二、可运行示例#

用纯 Python 建一张小规格表，按"带宽 ÷ 每 token 权重字节数"估算各卡的解码吞吐。

# -*- coding: utf-8 -*-
# 从规格表估算：各 GPU 跑某个模型时的解码吞吐（tokens/s）
# 解码是访存密集：每生成 1 个 token 要读一遍全部权重，吞吐 ≈ 带宽 / 每token读取字节数

gpus = {
    # 名称: (显存 GB, 带宽 GB/s)
    "RTX 3090":  (24, 936),
    "RTX 4090":  (24, 1008),
    "L40S":      (48, 864),
    "A100 80G":  (80, 2039),
    "H100 80G":  (80, 3350),
}

def decode_throughput(bandwidth_gb_s, params, bytes_per_param=2):
    """解码吞吐 = 带宽 / 每 token 需读的权重字节数（忽略 KV 读取等次要项）。"""
    bytes_per_token = params * bytes_per_param
    return bandwidth_gb_s * 1e9 / bytes_per_token

# 三个常见规模的模型（参数量）
models = {"7B": 7e9, "13B": 13e9, "70B": 70e9}

print("各 GPU 的解码吞吐估算（tokens/s，FP16）：")
print(f"{'GPU':<10} {'带宽GB/s':>9} " + "".join(f"{m:>10}" for m in models))
for name, (vram, bw) in gpus.items():
    row = "".join(f"{decode_throughput(bw, n):>10.1f}" for n in models.values())
    print(f"{name:<10} {bw:>9.0f} {row}")

# 能不能装下？用第 5 章的账本：权重（FP16）+ 预留 2 GiB
print("\nFP16 权重能否装下（预留 2 GiB）：")
for name, (vram, bw) in gpus.items():
    fits = [m for m, n in models.items() if n * 2 / 1e9 + 2 <= vram]
    print(f"  {name:<10} {vram} GB -> 可装 {', '.join(fits) if fits else '（仅量化后）'}")

# 量化视角：INT4 后权重缩到 1/4，能装的模型更多
print("\nINT4 权重（每参数 0.5 字节）能否装下：")
for name, (vram, bw) in gpus.items():
    fits = [m for m, n in models.items() if n * 0.5 / 1e9 + 2 <= vram]
    print(f"  {name:<10} {vram} GB -> 可装 {', '.join(fits) if fits else '（仍不够）'}")

运行后你会看到两个清晰结论：H100 的吞吐约是 4090 的三倍（带宽差约三倍），而 24 GB 卡即便量化也装不下 70B——带宽决定快慢，容量决定能不能跑，二者缺一不可。

三、练习#

  1. 手算吞吐：A100 80G 带宽约 2.0 TB/s，跑 7B FP16（每 token 读约 14 GB）的吞吐是多少 token/s？
  2. 改参数：把 7B 模型改成 INT4 量化（每 token 读约 3.5 GB），重算各卡吞吐，解释为什么量化既能省显存又能提速。
  3. 加显卡：往 gpus 里加 A100 40G（40 GB，1555 GB/s）和 RTX 4080（16 GB，717 GB/s），看它们落在什么位置。
  4. 容量 vs 带宽：找一对"容量相同但带宽不同"或"带宽相近但容量不同"的卡，说明哪种卡适合"跑得快"，哪种卡适合"跑得下"。
  5. 思考：为什么数据中心卡用 HBM 而消费卡用 GDDR？HBM 的带宽优势对 LLM 推理为什么比"更多的 CUDA Core"更重要？（回顾第 4 章 Roofline 结论）
