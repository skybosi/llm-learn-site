张量并行配置#

单卡装不下的模型，就要拆到多卡上。最常用的拆法是张量并行（Tensor Parallelism，TP）：把每一层的大矩阵切分到多张卡上并行计算，卡与卡之间用高速互连（NVLink/PCIe）在每一步做通信归约。vLLM 里配置张量并行只需要一个参数 --tensor-parallel-size，但背后是"显存收益 vs 通信开销"的权衡，选不好反而更慢。学完本课，你应当能解释张量并行的原理与通信代价，并为一个装不下的模型选出合理的 TP 大小。

一、概念讲解#

1. 为什么单卡会装不下#

上一课算了显存账：模型权重 + KV Cache + 激活。以 70B 模型 FP16 为例，权重就约 140GB，单张 A100-80G 直接放不下——不是调参数能解决的，必须拆卡。拆卡的目标很朴素：把权重（以及对应的计算）分摊到多张卡的显存里。

2. 张量并行怎么拆#

TP 的核心思想是按"层内维度"切分权重，而不是按"层"切（那是流水线并行，下一课讲）。举例：Transformer 里一个前馈/注意力矩阵 W 的形状是 [din​,dout​]，TP=2 时把它沿输出维度切成两半，两张卡各存一半、各算一半，得到两段输出再拼起来。

  • 列切分（按输出维度）：每卡算一半输出，最后拼接即可，无需通信归约；
  • 行切分（按输入维度）：每卡输入只有一半，算完后需要 all-reduce 把各卡的部分和加起来。

所以 TP 的每一步都伴随一次集合通信（all-reduce / all-gather），通信量正比于"激活大小 × 卡数"。这就是 TP 的代价。

3. 显存收益与通信开销的权衡#

  • 收益：TP=N 时，权重和激活约分摊为原来的 1/N（KV Cache 也可随头数切分），让大模型"装得下"；
  • 开销：每一步都要跨卡通信，N 越大、单卡算的越少、通信占比越高，扩展效率越低；
  • 经验：TP 首选 2（收益最大、通信最少），再考虑 4；超过 8 时通信往往吃掉大部分收益，要改用流水线并行或数据并行。

4. TP 大小怎么定#

最小 TP = 向上取整( 权重 + KV Cache + 激活 ) / 单卡可用显存 )

但还要满足一个约束：TP 最好能整除 KV 头数/注意力头数（很多实现要求），且卡数 = 2 的幂最常见（2/4/8）。例如 70B FP16 权重 140GB，A100-80G 可用约 65GB（留 KV/激活）：

140 / 65 ≈ 2.2 → 取 TP=2 不够，TP=4 稳妥（或用 AWQ 4-bit 把权重压到 40GB，TP=2 即可）

量化 + TP 常常配合使用：量化先砍权重，TP 再补齐剩余缺口，比单纯加卡更省。

二、可运行示例#

示例 1：TP 大小决策脚本#

# -*- coding: utf-8 -*-
# 张量并行大小决策：按权重+KV Cache 显存需求，反推最小 TP
import math

def min_tp(params_b, quant_bits, layers, kv_heads, head_dim,
           max_num_seqs, max_model_len, gpu_mem_gb, dtype_bytes=2):
    weight_gb = params_b * quant_bits / 8
    per_token_kv = 2 * layers * kv_heads * head_dim * dtype_bytes
    kv_gb = max_num_seqs * max_model_len * per_token_kv / 1e9
    act_gb = 2.0                                    # 激活粗估
    need_gb = weight_gb + kv_gb + act_gb
    usable = gpu_mem_gb * 0.85                      # 单卡可用(留 15% 碎片)
    tp = math.ceil(need_gb / usable)
    # 归一到 2 的幂，方便通信拓扑
    tp_pow = 1
    while tp_pow < tp:
        tp_pow *= 2
    return dict(weight=weight_gb, kv=kv_gb, need=need_gb, tp_raw=tp, tp=tp_pow)

# 70B 模型，A100-80G，FP16 vs AWQ 4-bit
for name, bits in [("70B FP16", 16), ("70B AWQ4", 4)]:
    r = min_tp(70, bits, layers=80, kv_heads=8, head_dim=128,
               max_num_seqs=64, max_model_len=4096, gpu_mem_gb=80)
    print(f"{name}: 权重={r['weight']:.0f}GB KV={r['kv']:.0f}GB 需求={r['need']:.0f}GB "
          f"-> 最小 TP={r['tp_raw']}，取 2 的幂 = {r['tp']}")

# 结果解读：70B FP16 需 TP=4；量化到 AWQ4 后权重减半，TP=2 即可

示例 2：vLLM 启动命令（TP 参数）#

# TP=1 单卡：小模型
vllm serve Qwen/Qwen2.5-7B-Instruct --tensor-parallel-size 1 \
    --gpu-memory-utilization 0.9 --max-model-len 8192

# TP=2 双卡：70B AWQ4 分到 2 张 A100-80G
vllm serve Qwen/Qwen2.5-72B-Instruct-AWQ --quantization awq \
    --tensor-parallel-size 2 --gpu-memory-utilization 0.9 \
    --max-model-len 8192 --max-num-seqs 128

# 查看双卡是否都跑起来（两个 GPU 进程、显存均衡）
nvidia-smi            # 观察两张卡显存占用是否相近（负载均衡）

启动后可用 nvidia-smi 观察：TP 正常时各卡显存占用应大致均衡。若严重不均，说明切分没生效或 KV Cache 分布不匀，需回查参数。

三、练习#

  1. 改卡型：把示例 1 的 gpu_mem_gb 改成 40（A100-40G），重算 70B FP16 与 AWQ4 的最小 TP，说明显存更小的卡为何需要更多卡、通信开销随之如何变化。
  2. 查通信：在你的机器上运行 nvidia-smi topo -m 查看卡间拓扑，找出 NVLink 直连与 PCIe 桥接的卡对，说明为什么 TP 应优先用 NVLink 直连的卡。
  3. TP 整除约束：查 vLLM 文档，了解 TP 大小对注意力头数/KV 头数的整除要求，解释为什么 70B（8 个 KV 头）不适合 TP=3 或 TP=5。
  4. 量化 + TP 组合：一个 120B 模型在 4 张 A100-80G 上，分别用"FP16 纯 TP"和"AWQ4 + TP"两套方案，估算各需几张卡，说明量化如何省下 TP 的卡数与通信。
