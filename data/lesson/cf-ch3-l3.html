隐式转换、绑定与语义动作的落点#

上一课我们让 f / x（float 除以 int）直接报错，真实语言不会这么强硬：它会在中间悄悄补一次转换。这次"悄悄"很危险——1 / 2 + 0.5 里转换补在除法之前还是之后，结果是 1.0 还是 0.5，而两份代码都通得过类型检查。本课把隐式转换写成显式规则，并回答本章最后一问：语义动作放在树的哪个位置，决定编译器生成什么程序。

一、概念讲解#

1. 强制转换与隐式转换#

龙书 §6.5.2 把这个选择摆得很清楚：严格类型系统不做任何自动转换，只提供程序员调用的转换函数，这叫类型转换（cast），程序要么类型相容、要么报错；宽松做法允许语言规定某些转换由编译器自动补上，这叫隐式转换 / 强制转换（type coercion）。

转换按方向分两类：加宽（widening，如 int → float）值域变大、通常安全；收窄（narrowing，如 float → int）会丢信息，多数语言要求显式写出。龙书用偏序集描述：类型之间存在 widening 关系，一对类型取最小上界（LUB，least upper bound），二元算术就是三段式——

1. 结果类型 t = LUB(左类型, 右类型)
2. 把每个操作数 widen 到 t   ← 要么生成一条转换指令，要么是 no-op
3. 在 t 上做运算

必须强调第二步：隐式转换在编译器内部绝不"隐式"——它必须变成一条真实指令，否则后端不知道该插什么机器码。

2. 转换规则表：允许哪些、禁止哪些#

规则表要写全，否则"能转就转"会让类型系统失去意义：

源 → 目标 类别 常见处理
int → float widening 隐式允许，浮点可精确表示时无损
float → int narrowing 通常要求显式；若隐式，须规定截断或舍入
小整数 → 大整数 widening 隐式允许
大整数 → 小整数 narrowing 截断，多要求显式
有符号 ↔ 无符号 重新解释 最危险的一类，见下

有符号/无符号混用是经典事故源。C 的 usual arithmetic conversions 在 int 与 unsigned int 混合时把 int 转成 unsigned，于是 -1 < 0u 为假：-1 先变成 4294967295。例 1 末尾复现了这个结论。

3. 隐式转换在 IR 里长什么样#

LLVM 把每种转换都做成一等指令（LangRef）：sitofp（有符号整数 → 浮点）、uitofp（无符号整数 → 浮点）、fptosi / fptoui（浮点 → 整数）、fpext / fptrunc（浮点加宽 / 收窄）、sext / zext / trunc（整数扩展 / 截断）、bitcast（同尺寸重解释）。LLVM IR 是强类型的：add 的两个操作数必须类型相同、且等于结果类型，所以加宽必须写成一条指令，没有"自动升级"这回事。

Kaleidoscope 教程第 3 章有个现场例子：fcmp 结果类型固定是 i1，而教程里所有值都是 double，于是必须补一条 uitofp；若误用 sitofp，< 会返回 0.0 和 -1.0 而不是 0.0 和 1.0。转换指令选错，值就错了。

4. 两种"绑定"别混：名字绑定与存储绑定#

绑定 何时确定 谁负责
名字 → 声明 编译期（第 1 课的作用域链） 符号表 / 解析器
变量 → 存储位置 运行期（活动记录 / 栈帧） 后端 + 运行时

局部变量住在活动记录（activation record）里，编译期只能确定它相对于帧指针的偏移，帧基址要到调用时才定。所以符号表里存 storage + offset，而"这个名字是哪个声明"必须在此之前钉死。

5. 语义动作的落点：S 属性 vs L 属性#

龙书 §5.1/§5.2 给每个产生式配语义规则（SDD）：综合属性（synthesized）从子节点流向父节点，继承属性（inherited）从父节点（或左兄弟）流向子节点。§5.4 的语法制导翻译方案（SDT）把动作嵌在产生式右部的某个位置，位置决定动作何时执行。

本课最反直觉的结论是：动作的落点会改变程序含义。对 1 / 2 + 0.5：

  • S 属性（自底向上综合）：1 / 2 的类型由两个子节点决定 → 整数除法得 0；父节点 + 再按 LUB 把它加宽成 0.0 → 0.5。这正是 C 的行为。
  • L 属性（上下文下传）：把"我要 float"当继承属性往下传 → 1 / 2 变成 1.0 / 2.0 → 1.0。

两条路都不报错、都能跑，却生成不同的程序。所以"类型规则是自底向上还是自顶向下"不是实现自由度，而是规范必须写死的事。工程后果也直接：消除左递归会改变动作的自然落点，必须重排动作或改用继承属性（§5.4.4、§5.5）。

6. 常见坑#

  1. 转换插入的时机错了：转换必须在类型检查之后、常量折叠之前写进 IR，并成为可见的一条指令；顺序一乱，折叠就在错的类型上算。
  2. 静默收窄：float → int 若允许隐式，须规定截断（向零）还是舍入，并明确"超出目标范围"这类边界的语义（LLVM 对应 fptosi，边界行为以 LangRef 为准）。
  3. 转换路径不唯一：int → float → double 与 int → long → double 精度可能不同；规范应给出唯一路径（通常就是"直接转成 LUB"）。
  4. 把 no-op 当没发生过：LUB 相等时 widen 什么都不做，但类型标注仍要写进 IR 节点，否则下游 pass 拿不到类型。

二、可运行代码示例#

例 1 把两条策略都实现出来：Gen.bottom_up 是 S 属性，Gen.expected 是 L 属性；两者都把隐式转换落地成一条 cast 指令，再由同一个解释器执行。

# ---- 隐式转换插在哪：自底向上综合 vs 上下文下传（语义动作的落点）----
INT, FLOAT = 'int', 'float'

def lub(t1, t2):
    """最小上界（龙书 §6.5.2 的 LUB）：int 与 float 的上界是 float"""
    if t1 == t2:
        return t1
    if {t1, t2} == {INT, FLOAT}:
        return FLOAT
    raise TypeError(f'{t1} 与 {t2} 在类型格上没有上界')

def natural_type(node):
    """节点的"自然类型"：不看上下文，只由自己和子节点决定"""
    if node[0] in ('num', 'var'):
        return node[2]
    _, _, l, r = node
    return lub(natural_type(l), natural_type(r))

def c_int_div(x, y):
    """C 的整数除法：向零截断"""
    q = abs(x) // abs(y)
    return q if (x < 0) == (y < 0) else -q

class Gen:
    """把带类型的 AST 降成三地址码；隐式转换落地成一条显式 cast 指令"""
    def __init__(self):
        self.code, self.n = [], 0

    def tmp(self):
        self.n += 1
        return f't{self.n}'

    def emit(self, *ins):
        self.code.append(ins)
        return ins[1]

    def widen(self, a, ta, want):
        if ta == want:
            return a                     # 类型已经一致：隐式转换退化成"什么都不做"
        d = self.tmp()
        self.emit('cast', d, a, ta, want)
        return d

    def bottom_up(self, node):
        """策略 A：S 属性 —— 子节点类型决定父节点，上下文不回传（C 的做法）"""
        if node[0] == 'num':
            return self.emit('const', self.tmp(), node[1], node[2]), node[2]
        if node[0] == 'var':
            return self.emit('var', self.tmp(), node[1], node[2]), node[2]
        _, op, l, r = node
        a, ta = self.bottom_up(l)
        b, tb = self.bottom_up(r)
        t = lub(ta, tb)
        a, b = self.widen(a, ta, t), self.widen(b, tb, t)
        return self.emit('bin', self.tmp(), op, a, b, t), t

    def expected(self, node, want):
        """策略 B：L 属性 —— 把上文期望的类型向下传（继承属性）"""
        if node[0] == 'num':
            return self.emit('const', self.tmp(), node[1], want), want
        if node[0] == 'var':
            d = self.emit('var', self.tmp(), node[1], node[2])
            return self.widen(d, node[2], want), want
        _, op, l, r = node
        t = lub(natural_type(node), want)          # 本节点最终按这个类型算
        a, _ = self.expected(l, t)
        b, _ = self.expected(r, t)
        return self.emit('bin', self.tmp(), op, a, b, t), t

def render(ins):
    k = ins[0]
    if k == 'const':
        return f'{ins[1]} = const {ins[2]}:{ins[3]}'
    if k == 'var':
        return f'{ins[1]} = load {ins[2]}:{ins[3]}'
    if k == 'cast':
        llvm = 'sitofp i32 -> double' if ins[4] == FLOAT else 'fptosi double -> i32'
        return f'{ins[1]} = cast {ins[2]} ({ins[3]} -> {ins[4]})   # LLVM: {llvm}'
    if k == 'bin':
        return f'{ins[1]} = {ins[3]} {ins[2]} {ins[4]}   ({ins[5]})'
    return f'{ins[1]} = {ins[2]}   ({ins[3]})'

def run(code, env=None):
    """执行三地址码；整数除法按 C 的语义（向零截断）"""
    env = dict(env or {})
    for ins in code:
        k = ins[0]
        if k == 'const':
            env[ins[1]] = ins[2]
        elif k == 'var':
            env[ins[1]] = env[ins[2]]
        elif k == 'cast':
            _, d, a, _, want = ins
            env[d] = float(env[a]) if want == FLOAT else int(env[a])
        elif k == 'bin':
            _, d, op, a, b, t = ins
            x, y = env[a], env[b]
            if op == '+':
                v = x + y
            elif op == '-':
                v = x - y
            elif op == '*':
                v = x * y
            else:
                v = c_int_div(x, y) if t == INT else x / y
            env[d] = v
        elif k == 'store':
            env[ins[1]] = env[ins[2]]
    return env

# 源码：r: float = 1 / 2 + 0.5
EXPR = ('bin', '+', ('bin', '/', ('num', 1, INT), ('num', 2, INT)), ('num', 0.5, FLOAT))
TARGET = FLOAT

for label, mode in (('A 自底向上（S 属性）', 'A'), ('B 上下文下传（L 属性）', 'B')):
    g = Gen()
    d, t = g.bottom_up(EXPR) if mode == 'A' else g.expected(EXPR, TARGET)
    d = g.widen(d, t, TARGET)                # 最终落到声明类型 float
    g.emit('store', 'r', d, TARGET)
    print(f'== 策略 {label} ==')
    for ins in g.code:
        print('   ', render(ins))
    print(f'    r = {run(g.code)["r"]}\n')

# ---- 附：C 的 usual arithmetic conversions 里最著名的一个坑 ----
u32 = lambda v: v % 2**32                    # 模拟 32 位无符号数
print('-1 < 0u 在 C 里为:', u32(-1) < 0)     # False：-1 先被转成 4294967295
== 策略 A 自底向上（S 属性） ==
    t1 = const 1:int
    t2 = const 2:int
    t3 = t1 / t2   (int)
    t4 = const 0.5:float
    t5 = cast t3 (int -> float)   # LLVM: sitofp i32 -> double
    t6 = t5 + t4   (float)
    r = t6   (float)
    r = 0.5

== 策略 B 上下文下传（L 属性） ==
    t1 = const 1:float
    t2 = const 2:float
    t3 = t1 / t2   (float)
    t4 = const 0.5:float
    t5 = t3 + t4   (float)
    r = t5   (float)
    r = 1.0

-1 < 0u 在 C 里为: False

两段 IR 的差别只有一处：策略 A 在 int 除法之后插了一条 cast（对应 LLVM 的 sitofp），策略 B 干脆让除法一开始就在 float 上做。转换的位置变了，算术的含义就变了——这正是 §5.4"动作的位置决定动作何时执行"的代价。C 的行为是策略 A，所以 1 / 2 + 0.5 在 C 里是 0.5；若在别的语言里看到 1.0，那门语言的类型规则多半是自顶向下的。

三、练习#

  1. 实现：给 Gen 加 narrowing：want == INT 而实际是 FLOAT 时生成 fptosi 风格指令，并让 run 按"向零截断"执行；用 r: int = 3.7 验证。
  2. 解释：为什么 LLVM IR 里"没有隐式转换"？若 add 能自动升级操作数，出错信息、常量的可表示范围、优化 pass 的合法性判断各会遇到什么麻烦？
  3. 对比/验证：把 EXPR 换成 1 / 2 * 1.0 + 0.5，先推导两条策略的结果再实测，指出哪一步的落点差异起了作用。
  4. 思考：龙书 §5.4.4 说消除左递归时动作必须重排。若不重排，本课这个例子会得到策略 A、策略 B，还是第三种结果？
