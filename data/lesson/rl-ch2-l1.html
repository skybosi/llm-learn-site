价值函数#

第 1 章我们搞清了环境（MDP）和回报 G_t，但还缺一块关键的拼图：怎么评价一个"决策规则"的好坏？ 一个智能体在状态 s 时该选哪个动作，取决于它有一套"选动作的规则"——这叫策略（policy）。而价值函数（value function） 就是给这套规则打分的标尺：它回答"从某个状态（或某个状态-动作）出发，按照这个策略走，长期能期望拿到多少回报"。这一课我们先说清"为什么价值函数要这样定义"，再讲清两种价值函数之间的换算关系——这是下一课贝尔曼方程的前置。

一、概念讲解#

1. 策略：决策规则的概率化描述#

策略 π 定义了智能体在每个状态下如何选动作。形式上，π(a|s) 是"在状态 s 下选动作 a 的概率"：

π(a | s) = P( A_t = a | S_t = s )

它把"决策"这件事做成了概率分布，理由有二：

  • 允许探索：随机策略天然带有不确定性，方便智能体去尝试不同动作（呼应第 1 课的探索-利用）；
  • 可以平滑优化：后面策略梯度方法要对策略求梯度，概率化的 π(a|s) 才能求导。

当 π(a|s) 对某个动作取 1、其余取 0 时，就是确定性策略（记作 a = π(s)）。策略是强化学习的终极对象——所有算法最终的产出，都是一个（尽量好的）策略。

2. 状态价值函数 v_π：这个状态"值"多少#

给定策略 π，状态价值函数（state-value function） v_π(s) 定义为：从状态 s 出发，之后一直按策略 π 行动，所能获得的期望回报：

v_π(s) = E_π[ G_t | S_t = s ] = E_π[ Σ_{k=0}^{∞} γᵏ R_{t+k+1} | S_t = s ]

记号 E_π 的意思是：期望是在"动作按 π 选择、状态按环境动力学转移"这条随机路径上取的。v_π(s) 是一个标量，它把"从 s 出发的整条随机未来"压缩成一个数——"这个状态长期来看有多值钱"。

为什么要把"整条未来"压成期望这一个数？因为未来的奖励流是随机的（动作随机、转移随机），无法用一个确定值表示。期望是压缩随机性的最小充分统计量：它让我们能直接比较"状态 s1 比状态 s2 更好"，而不必罗列所有可能的未来。这就是价值函数"为什么这样定义"的第一层答案——可比较性。

3. 动作价值函数 q_π：这个"状态-动作"值多少#

v_π(s) 只评价"状态"，但决策发生在"状态-动作"层面。于是引入第二个价值函数——动作价值函数（action-value function） q_π(s, a)：在状态 s 先选动作 a，之后一直按 π 行动，所能获得的期望回报：

q_π(s, a) = E_π[ G_t | S_t = s, A_t = a ]

注意与 v_π 的唯一区别：q_π(s, a) 把第一步动作固定为 a，之后才回到 π。这个"先固定一步"的定义，是后面"策略改进"（第 3 章）的抓手——因为要判断"在 s 改选别的动作好不好"，直接看 q_π(s, a) 就够了。

4. v 与 q 的互推关系：两个价值函数如何换算#

v_π 和 q_π 不是两个孤立对象，它们互为对方的"加权平均"。这是本课最核心的一对关系式，必须逐字推导清楚。

关系①：v 是 q 按 π 的加权平均。 在状态 s，策略 π 以概率 π(a|s) 选择动作 a；而选 a 后能拿到的期望回报正是 q_π(s, a)。由全期望公式：

v_π(s) = Σ_a π(a|s) · q_π(s, a)

读作：一个状态的价值，等于它所有可能动作价值按策略概率的加权平均。 这个关系不依赖环境动力学，是纯定义层面的，永远成立。

关系②：q 用 v 表示（需要环境动力学）。 反过来，在状态 s 选了动作 a 之后，环境以 p(s', r | s, a) 转移到 s' 并给奖励 r，之后从 s' 继续按 π 行动，价值是 v_π(s')。于是：

q_π(s, a) = Σ_{s', r} p(s', r | s, a) · [ r + γ · v_π(s') ]

读作：动作价值 = 这一步的期望奖励 + 折扣后的下一步状态价值的期望。 这里用到了回报的递推形式 G_t = R_{t+1} + γ·G_{t+1}（第 1 章第 5 节的结论），所以这条关系需要 MDP 的动力学 p 才写得出来。

把 ①② 互相代入，就得到两个价值函数各自的自洽方程——这正是下一课的贝尔曼方程。现在你只需先把这两条"换算公式"刻进脑子：① 是"策略加权"，② 是"动力学加权"。

5. 价值函数的两种用法：评价与改进#

价值函数之所以重要，是因为它同时服务于两件事：

  • 评价（prediction）：给定策略 π，算出 v_π 或 q_π，量化"这套策略有多好"（第 3 章策略评估）。
  • 改进（control）：比较不同动作的 q_π(s, a)，把策略往"价值更高的动作"上改（第 3 章策略改进）。

一句话：价值函数是"评价"和"改进"之间唯一的桥梁——没有它，我们就无法判断该往哪个方向调整策略。这回答了"为什么这样定义"的第二层答案：价值函数把"评价"变成了可计算的标量，从而让"改进"有了方向。

二、可运行代码示例#

用第 1 章那个三状态链式 MDP，固定一个策略，分别用蒙特卡洛采样和解析枚举两种方式估计 v_π，验证"期望压缩随机性"这件事。

import numpy as np

rng = np.random.default_rng(0)

# 三状态链式 MDP：s0,s1,s2（s2 吸收），动作 a0,a1
nS, nA = 3, 2
P = np.zeros((nA, nS, nS))        # P[a, s, s'] = p(s'|s,a)（奖励并入期望奖励）
R = np.zeros((nA, nS))            # R[a, s] = r(s,a) 期望奖励
P[0, 0, 1] = 1.0                  # s0,a0 -> s1
P[1, 0, 0] = 1.0                  # s0,a1 -> s0
P[0, 1, 0] = 0.5; P[0, 1, 2] = 0.5  # s1,a0 -> s0/s2
P[1, 1, 2] = 1.0                  # s1,a1 -> s2
P[0, 2, 2] = 1.0; P[1, 2, 2] = 1.0  # s2 吸收
R[1, 1] = 1.0                     # 只有 s1,a1 得 1 分
GAMMA = 0.9

# 固定策略：在 s0 永远选 a0，在 s1 永远选 a1（s2 吸收无所谓）
policy = {0: 0, 1: 1, 2: 0}       # policy[s] = 选中的动作

# ---- 方式①：蒙特卡洛采样估计 v_π ----
def rollout(s0, n_steps=20):
    """从 s0 按 policy 走一条轨迹，返回折扣回报。"""
    s, G, g = s0, 0.0, 1.0
    for _ in range(n_steps):
        a = policy[s]
        s_next = rng.choice(nS, p=P[a, s])
        G += g * R[a, s]          # 累加 γ^t * r
        g *= GAMMA
        s = s_next
    return G

print("蒙特卡洛估计 v_π（各 2000 条轨迹）：")
for s in [0, 1, 2]:
    est = np.mean([rollout(s) for _ in range(2000)])
    print(f"  v_π({s}) ≈ {est:.4f}")

# ---- 方式②：解析枚举——直接用定义展开期望 ----
# 对这个小 MDP，v_π 满足 v_π(s)=Σ_s' p(s'|s,π(s))[r+γ v_π(s')]，
# 即线性方程组 (I - γP^π) v = r^π。这里解它得到精确值。
P_pi = np.array([P[policy[s], s] for s in range(nS)])  # P^π[s,s']=p(s'|s,π(s))
r_pi = np.array([R[policy[s], s] for s in range(nS)])  # r^π[s]=r(s,π(s))
v_exact = np.linalg.solve(np.eye(nS) - GAMMA * P_pi, r_pi)
print("\n解析解 v_π：", np.round(v_exact, 4))

运行结果大致是：

蒙特卡洛估计 v_π（各 2000 条轨迹）：
  v_π(0) ≈ 0.9000
  v_π(1) ≈ 1.0000
  v_π(2) ≈ 0.0000

解析解 v_π： [0.9 1.  0. ]

读三件事：① v_π(2)=0——吸收状态之后再无奖励，价值自然为 0；② v_π(1)=1——从 s1 出发按策略选 a1，立刻得 1 分；③ v_π(0)=0.9——从 s0 出发要先走一步（0 分）才到 s1，那 1 分被折扣成 γ·1 = 0.9，完美印证了"价值 = 期望回报"的定义。蒙特卡洛估计与解析解吻合，说明"取期望"确实把随机未来稳定地压缩成了一个数。

三、练习#

  1. 把策略改成"在 s1 选 a0"（即 policy = {0: 0, 1: 0, 2: 0}），重算解析解 v_π。为什么 v_π(1) 变小了？提示：a0 从 s1 去 s0/s2 都不得分。
  2. 手推关系① v_π(s) = Σ_a π(a|s) q_π(s,a)：设 π(a0|s1)=0.3, π(a1|s1)=0.7，q_π(s1,a0)=0.45, q_π(s1,a1)=1.0，算出 v_π(s1)。
  3. 手推关系② q_π(s,a) = Σ p(s',r|s,a)[r + γ v_π(s')]：用代码里的 MDP，已知 v_π(s0)=0.9, v_π(s2)=0，验证 q_π(s1, a1) = 1 + 0.9·v_π(s2) = 1.0。
  4. 思考：为什么 q_π(s, a) 的定义要"把第一步动作固定为 a，之后才回到 π"，而不是"所有步都自由选"？这个"只固定一步"的设计，在后续"比较不同动作好坏"时带来了什么方便？
