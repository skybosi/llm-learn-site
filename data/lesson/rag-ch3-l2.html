cross-encoder 与 late interaction 的取舍：质量-延迟前沿#

这一节要解决什么#

上一节证明了重排的必要性：双塔的"独立编码 + 单个内积"看不见少数决定性 token。但结论只说了"该加重排"，没说加多重。

重排不是一个二值选择，而是一条连续的前沿：

弱 ←───────────────── 交互强度 ─────────────────→ 强
点积(双塔)      MaxSim(late interaction)      全交叉(cross-encoder)
doc 侧全离线     doc 侧 token 离线、交互在线    完全不能离线
每候选 O(d)      每候选 O(Lq·Ld)               每候选一次完整前向

这条前沿上有三个必须回答的工程问题，而它们都有能算出来的答案：

  1. 每档的代价到底差多少？ 不是"cross-encoder 慢"这种定性说法，而是每候选多少次乘加、doc 侧要存多少字节、在给定延迟预算下能精排多少候选。
  2. 质量差多少？ 这个答案不像直觉那样单调 —— 本节代码会实测出"更强的交互不一定更准"，并说明原因（决定重排增益的是"重排信号是否与召回信号互补"，不是"模型表达力多强"）。
  3. 两段式（粗排 + 精排）的池要开多大？ 这个问题有确定答案：池的大小由第一阶段名次分布的高分位数决定（例如 P99），而不是拍一个"100"。池开小了是召回上界的损失，开大了是纯粹的成本浪费。

结论先放在这里：

重排的质量-延迟前沿不是"选一个模型"，而是"在延迟预算下决定在哪一层做多少交互"。而重排池的大小是一个可从数据推导的量：把第一阶段正例名次的分布测出来，池就定了。开超过那个分位数，你只是在为"永远不会出现的候选"付算力。

一、三种交互强度的形式化定位#

1.1 定义与它们能表达的交互族#

设文档被编码成 token 级向量序列 D=(d1​,…,dLd​​)、查询为 Q=(q1​,…,qLq​​)。

点积（双塔）：

sbi​(q,d)=⟨f(q),g(d)⟩,f(q)=pool(Q), g(d)=pool(D)

交互发生在池化之后，即两个 de​ 维向量的内积。这是一个双线性函数：固定 d 时它对 q 线性，反之亦然。

late interaction（MaxSim）：

slate​(q,d)=aggi∈[Lq​]​ j∈[Ld​]max​⟨qi​,dj​⟩

交互发生在token 对上（Lq​×Ld​ 个内积），但聚合方式固定（文档侧取 max、查询侧取某个不依赖具体 token 的聚合）。关键的工程性质：maxj​⟨qi​,dj​⟩ 里的 dj​ 是预计算并存储的，所以在线只需要算内积与取 max。

cross-encoder：

scross​(q,d)=h(Transformer([q;d]))

q 与 d 在每一层的注意力里互相可见。这带来两个后果：(a) 表达力最强（可以表达任意 token 之间的依赖，包括"文档内部 token 之间的关系"）；(b) d 的表示依赖 q，所以 Transformer([q;d]) 不能离线算。

1.2 为什么质量阶梯在理论上单调#

把三者的函数族写成集合关系：

Fbi​ ⊂ Flate​ ⊂ Fcross​

  • Fbi​⊂Flate​：取 qi​ 全部相同（查询只有一个"池化 token"）、聚合取平均，MaxSim 退化为 ⟨qpool​, pool(d)⟩ 型 —— 也就是说双塔是 late interaction 的一个特例。
  • Flate​⊂Fcross​：设 Transformer 的一层注意力以 qi​ 为查询、dj​ 为键做加权，再把结果线性投影，就能算出 ∑j​softmax(⟨qi​,dj​⟩)j​⋅vj​；取 vj​=dj​ 与合适的温度，它逼近 maxj​（softmax 在低温下趋近 argmax）。所以 MaxSim 是可被 cross-encoder 逼近的。

重要：⊂ 只保证"表达力上界更高"，不保证"在有限数据与有限训练下更准"。这是本节代码会实测出来的反例的来源（下一小节）。

1.3 三档的对照表#

点积（双塔） late interaction cross-encoder
交互层级 池化后 1 次内积 Lq​×Ld​ 次内积 每层全交叉注意力
doc 侧可离线 ✅ 整个向量 ✅ token 向量（需存储） ❌ 完全不能
在线每候选代价 O(de​) O(Lq​Ld​de​) O(层数×(L2de​+Lde2​))
doc 侧存储 de​ 个数 Ld​×de​ 个数 0（但要在算力上付）
可倒排/剪枝 ✅（向量索引） ✅（token 级倒排，如 PLAID 类） ❌
能否表达文档内部结构 ❌ ❌ ✅

读表的方式：这张表里没有"更好"，只有"把成本放在哪"。点积把成本放在离线（存一份向量就够），late interaction 放在存储 + 在线内积，cross-encoder 放在在线算力。工程决策的第一步是问：你的瓶颈在哪一侧？ 索引内存紧 → late interaction 的 token 级存储更贵；在线延迟紧 → cross-encoder 更贵。

二、代价模型：能算，不许定性#

2.1 cross-encoder 每候选的浮点代价#

一个 L 层 Transformer 的前向，每层的主要计算量：

QKVO 四个投影4Lseq​de2​​​+注意力矩阵2Lseq2​de​​​+FFN（两矩阵 de​→4de​）8Lseq​de2​​​

合并后每层约 12Lseq​de2​+2Lseq2​de​ 次乘加。取 Lseq​=Lq​+Ld​=32+480=512、de​=768、12 层：

每候选≈12×(12×512×7682+2×5122×768)≈4.8×1010 乘加

Hmm —— 这个数字看起来大得离谱，检查一下：12×512×7682=12×512×589824≈3.6×109；2×5122×768≈4.0×108；每层约 4.0×109，12 层约 4.8×1010。对，单候选约 5×1010 次乘加是量级正确的（一个 12 层、512 长度的编码器前向，本来就是这个量级）。

这就是为什么 cross-encoder 只能做精排：粗排 1000 条候选要 5×1013 次乘加；而双塔对 1000 条候选只要 1000×768≈8×105 —— 差了 7 个数量级。

2.2 late interaction 的存储账#

doc 侧要存 N×Ld​ 个 de​ 维向量。取 N=107、Ld​=180、de​=128、fp16：

存储=107×180×128×2 字节=460 GB

460 GB —— 而第 2 章算过，单向量 768 维 fp32 的存储是 30.7 GB。也就是说：late interaction 把存储从 30 GB 抬到 460 GB（15 倍），换来的是"不用重新编码文档"。这就是它的取舍本质：

late interaction 不是"更省内存的 cross-encoder"，它是"把 cross-encoder 的部分交互能力，用 doc 侧 15 倍的存储买下来"。

工程上降低它有两个方向：(a) 压维（de​ 从 128 降到 64，存储减半，质量会掉多少可测）；(b) 量化（token 向量 8 bit/维，存储再减半，但 quant 误差直接进打分，回指第 2 章 4.4 节的 ε/Δ 判据）。本节代码把两个方向都做成开关。

2.3 两段式的池大小：一个可推导的量#

设第一阶段（召回）返回的候选里，真正相关文档的名次为随机变量 R。两段式精排池取 k′ 时：

端到端 recall@k ≤ P(R≤k′)

这是硬上界：正例不在池里，任何重排都救不回来。于是池大小的选择规则是

 k′=Q1−δ​(R) 向上取整到工程好用的档位 ​

其中 Q1−δ​ 是你愿意承受的"召回上界损失"对应的分位数。这个量可以直接测：跑一批带标注（或人工核对的）查询，记录第一阶段里正例的名次，取分位数。

  • 取 δ=0.01（P99）→ 上界损失 1%，代价按 P99 的名次算；
  • 取 δ=0.05（P95）→ 上界损失 5%；
  • 拍一个"池=100" → 你既可能付了 3 倍的算力，也可能还在漏 8% 的查询。

这是本节最重要的可操作结论：池不是超参数，是一个从数据分布读出来的量。

三、质量-延迟前沿：工作点怎么选#

3.1 三个必须先测的量#

在选任何方案之前，先测：

① 第一阶段候选池里，正例名次的分布（P50/P90/P95/P99）
   → 它决定池大小的上界，也决定"重排的价值上限"
② 不同交互强度的**互补性**：重排信号与召回信号有多不一致？
   → 用"重排前后 Top-10 的重合度"衡量
   → 重合度接近 1（重排没改顺序）→ 重排的收益≈0，无论它多强
③ 你的延迟预算与每候选代价
   → 池大小 × 每候选代价 ≤ 预算；由此反推能用的最强档

这套顺序的理由：量 ② 是决策性的 —— 如果重排信号与召回信号高度相关（例如用同一个模型的另一层），再强也没用。很多团队跳过 ②，直接用最大最强的重排模型，结果发现指标只动了 1 个点，然后就得出"重排没用"的错误结论。

3.2 "更强 = 更准"为什么不一定成立#

有三个机制会让强交互档实测更差或不升：

  1. 训练不充分：cross-encoder 参数多、无预训练时收敛慢；相同训练预算下它可能打不过 late interaction（本节代码里 cross 代理是未训练的，实测就落在 late 之后）。
  2. 池构成变了：池开大时，进入精排的候选里混入了更多"低质量但碰巧在池里的"文档，强模型会花容量去对这些做正确拒绝 —— 而在小池里它只需处理强干扰。这就是为什么"池开大 → 指标不升反降"是常见现象：不是模型差，是精排任务本身变难了。
  3. 信号冗余：如果第二阶段用的是与第一阶段同源的表示（例如都来自同一个嵌入模型），它的排序只会复现第一阶段的排序。重排的必要条件是"它看到第一阶段看不到的东西" —— 对 cross-encoder 来说就是 token 级对齐，对 late interaction 来说就是文档侧 token 保留。

3.3 蒸馏：把强档的能力压进弱档#

一个自然的工程问题是：cross-encoder 的精度能不能被"压"进 late interaction 或双塔，从而在线省算力？

能，但要付可测的代价。 做法是让学生模仿教师的排序分布（listwise 蒸馏，第 4 节会展开）。判断"压进去多少"的量不是损失函数，而是：

  • Kendall τ：学生排序与教师排序的一致度；
  • Top-10 重合率：工程上最关心的量；
  • 分层 τ：按文档长度/来源分组，看学生是否只学到了教师的系统性偏差（若某组 τ 显著低，说明学生没学到那类文档的判别逻辑）。

优先级判据：若教师的 Top-10 重合率能到 0.9 以上，用蒸馏后的学生替代教师；若只有 0.6，那说明教师的判别依赖学生在结构上无法表达的交互（回指 1.2 节的 ⊂ 关系）。

四、代码：三档交互的质量-代价对照#

下面的脚本用同一张嵌入表、同一批查询，测出三档交互的实测 Top-1 与实测每候选乘加次数，并测出"池大小与召回上界/成本"的关系。

"""
三档交互强度的质量-延迟对照：点积（bi）/ MaxSim（late）/ 全交叉（cross 代理）。

设计决策（四处，都直接对应正文论断）：
  1. 三档共享同一张随机嵌入表，交互形式严格按正文定义：
       bi    : cos(mean(q), mean(d))                     —— 低秩双线性
       late  : 逐对相似度 → 文档侧 max → 查询侧聚合       —— MaxSim
       cross : 以文档 token 为值的软注意力 + "最差对齐"惩罚 —— cross-attention 替身
     都**不训练**：性能差只能归因于交互结构，而不是优化质量。
  2. 每候选的代价用**计数器实测**（不引用论文公式）：质量与代价都实测，
     前沿上的工作点才可信。
  3. 第一阶段候选池的难度做成显式参数：正例命中**全部 3 个查询 token**，
     干扰最多命中 2 个 —— 于是"正例在池里排第几"与"重排池要开多大"
     都变成可测量、可推导的量（正文 2.3 节）。
  4. late interaction 的现实约束（文档侧 token 向量必须低精度存储）做成显式开关，
     因为那是它在真实系统里的主要代价来源（正文 2.2 节）。
"""
import numpy as np

EMB, N_TOK = 48, 256


def make_embedding(seed=0, dim=EMB):
    """固定随机嵌入表：token id → 单位向量（所有打分器共用，保证公平）。"""
    rng = np.random.default_rng(seed)
    E = rng.normal(0, 1, (N_TOK, dim))
    return E / np.linalg.norm(E, axis=1, keepdims=True)


def make_pool(E, n_q=100, n_list=50, n_topic=6, seed=11, align_noise=0.12,
              p_match2=0.6):
    """
    ⚠️ 合成数据。查询 = [topic, k1, k2]（3 个 token）。
    正例命中**全部 3 个**；干扰最多命中 2 个：
      · 类型 A（"极难"）：命中 k1,k2（内容全同）、topic 不同 → 命中 2
      · 类型 B（"极难"）：命中 topic + 一个内容 token          → 命中 2
      · 类型 C（"容易"）：命中 topic（半数情形）或全不命中       → 命中 1 或 0
    p_match2 控制"命中 2 个"的干扰占比。第一阶段（bi）的排序**
    主要由命中数决定，因此正例名次的分布是可推导的**（正文 2.3 节）。
    """
    rng = np.random.default_rng(seed)
    queries, poss, negss = [], [], []
    for _ in range(n_q):
        topic = int(rng.integers(0, N_TOK))
        k1, k2 = (int(t) for t in rng.choice(N_TOK, 2, replace=False))
        q = np.vstack([E[topic], E[k1], E[k2]])
        queries.append(q + rng.normal(0, align_noise, q.shape))
        p = np.vstack([E[topic], E[k1], E[k2]] + [E[topic]] * n_topic)
        poss.append(p + rng.normal(0, align_noise, p.shape))
        cand = [t for t in range(N_TOK) if t not in (k1, k2) and t != topic]
        negs = []
        for _ in range(n_list):
            other = int(rng.choice([t for t in range(N_TOK) if t != topic]))
            u = rng.random()
            if u < p_match2 * 0.5:            # A：内容全同、主题不同
                rows = [E[other], E[k1], E[k2]]
            elif u < p_match2:                # B：主题 + 一个内容 token
                miss = k2 if rng.random() < .5 else k1
                keep = k1 if miss == k2 else k2
                ids = [keep, int(rng.choice(cand))]
                rng.shuffle(ids)
                rows = [E[topic]] + [E[i] for i in ids]
            else:                             # C：命中主题（半数）或全不命中
                ids = [int(t) for t in rng.choice(cand, 2, replace=False)]
                top_i = topic if rng.random() < 0.5 else int(rng.choice(cand))
                rows = [E[top_i]] + [E[i] for i in ids]
            negs.append(np.vstack(rows + [rows[0]] * n_topic))
        negss.append(negs)
    return queries, poss, negss


def quantize_doc_tokens(d, bits):
    """文档侧 token 向量的低精度存储（先单位化，再对称量化到 2**(bits-1) 档）。
    这是 late interaction 在真实系统里的必备手段，也是它的主要质量损失来源。"""
    d = d / (np.linalg.norm(d, axis=1, keepdims=True) + 1e-12)
    levels = 2 ** (bits - 1)
    return np.round(d * levels) / levels


class Counter:
    """乘加计数器：所有"代价"都从这里读，不引用外部公式。"""

    def __init__(self):
        self.mac = 0

    def reset(self):
        self.mac = 0


C = Counter()


def score_bi(q, d):
    """双塔：两侧均值池化后取余弦（低秩双线性交互）。"""
    qv, dv = q.mean(0), d.mean(0)
    C.mac += q.shape[1]
    return float(qv @ dv / (np.linalg.norm(qv) * np.linalg.norm(dv)))


def score_late(q, d, agg="mean", bits=None):
    """late interaction（MaxSim）：逐对相似度 → 文档侧 max → 查询侧聚合。
    在线部分只有"内积矩阵 + 取 max + 一次聚合"，文档侧 token 向量可离线存储。"""
    dd = quantize_doc_tokens(d, bits) if bits else d
    S = q @ dd.T
    C.mac += S.size
    per_q = S.max(axis=1)
    if agg == "max":
        return float(per_q.max())
    if agg == "mean":
        return float(per_q.mean())
    m = per_q.max()
    return float(m + np.log(np.exp(per_q - m).mean()))     # logsumexp


def score_cross(q, d):
    """cross 代理：① 以文档 token 为值的软注意力（内容可寻址）；
    ② 查询与注意力上下文的对齐分数；③ 乘"最差对齐 token"的惩罚。
    它允许任意 token 对的交互 —— 这是 cross-attention 的最小结构替身。"""
    S = q @ d.T
    C.mac += S.size
    A = np.exp(S - S.max(axis=1, keepdims=True))
    A = A / A.sum(axis=1, keepdims=True)
    C.mac += 2 * A.size
    ctx = A @ d
    C.mac += A.shape[0] * d.shape[1] * d.shape[1]
    base = float((q * ctx).sum(1).mean())
    C.mac += q.size
    worst = float(np.exp(-np.clip(S.max(axis=1), -10, 0)).mean())
    C.mac += S.shape[0] * 3
    return base * worst


SCORERS = {"bi（点积）": score_bi,
           "late（MaxSim·均值聚合）": score_late,
           "cross（全交叉代理）": score_cross,
           "late + 8bit 存储": lambda q, d: score_late(q, d, bits=8)}


def evaluate_one(scorer, qs, ps, ns):
    """单档打分器在"全池"上的质量与每候选实测代价。"""
    C.reset()
    top1 = 0
    for q, p, ds in zip(qs, ps, ns):
        sp = scorer(q, p)
        top1 += int(sp > max(scorer(q, d) for d in ds))
    return top1 / len(qs), C.mac / (len(qs) * (1 + len(ns[0])))


def first_stage_rank(q, p, ds):
    """第一阶段（bi）里正例的名次 —— 池大小的推导依据（正文 2.3 节）。"""
    sp = score_bi(q, p)
    return 1 + sum(1 for d in ds if score_bi(q, d) > sp)


def pipeline_recall(scorer, qs, ps, ns, kp, topk=10):
    """完整两段式：bi 取前 kp 条 → scorer 对这 kp 条重新排序 → 取前 topk。
    k′ 决定"候选上界"（正例不在池里就永远救不回），reranker 决定"池内顺序"。"""
    hit = 0
    for q, p, ds in zip(qs, ps, ns):
        order = np.argsort([-score_bi(q, d) for d in ds])[:kp]
        pool = [(scorer(q, ds[j]), j) for j in order]
        pool.sort(key=lambda t: -t[0])
        sp = scorer(q, p)
        rank = 1 + sum(1 for s, _ in pool if s > sp)
        hit += int(rank <= topk)
    return hit / len(qs)


def main():
    E = make_embedding()
    qs, ps, ns = make_pool(E)

    print("=" * 78)
    print("表一：三档交互的质量与每候选实测乘加次数（nq=3, nd=9）")
    print("=" * 78)
    print(f"{'打分器':<24} {'Top-1':>8} {'每候选乘加':>12} {'相对 bi':>10}")
    base = None
    for name, sc in SCORERS.items():
        t1, mac = evaluate_one(sc, qs, ps, ns)
        base = base or mac
        print(f"{name:<24} {t1:>8.3f} {mac:>12.0f} {mac / base:>10.1f}x")

    print()
    print("=" * 78)

逐行读这张表（三个必须说清的结论）：

  1. 强交互档没有明显优势，代价却高两个数量级 —— cross 代理（0.980）几乎追平 late（1.000），但要付 148.9 倍的在线算力。这不是"cross-encoder 不行"，而是它没训练：cross 代理的参数最多、最依赖训练，随机初始化时它的软注意力接近均匀分布，只能靠"最差对齐惩罚"这个手工项工作。这正是正文 3.2 节第 1 条机制：表达力上界更高 ≠ 有限训练预算下更准。真实系统里的 cross-encoder 有大规模判别式预训练，通常能赢 —— 但这个"通常"必须用自己的验证集确认，不能靠理论包含关系推断。
  2. late interaction 的每候选在线代价（27 次乘加）比双塔（48）还低 —— 反直觉，但原因是代价的位置不同：双塔在池化后做一次 48 维内积；late 在 3×9 的相似度矩阵上做 27 次内积，而 max 与聚合不计入乘加。所以"逐 token 交互"的在线代价可以低于"池化后交互" —— late interaction 真正的代价不在在线算力，而在离线存储（正文 2.2 节：460 GB 量级）。
  3. 8 bit 量化把 late 从 1.000 打到 0.590 —— 这是本节最刺眼的数字。late 存的是单位化后的 token 向量，8 bit（每维 8 档）在 48 维上的角度误差，足以让"最强的 max 对齐"选错 token。结论不是"不能量化"，而是"比特数必须由 ε/Δ 判据定，不能拍"（回指第 2 章 4.4 节）。真实系统的 ColBERT 类方案用 2 bit 压缩，但配合残差补偿与专门的压缩训练，而不是对现成向量做朴素均匀量化 —— 本节保留朴素版本，正是为了暴露"直接量化要付什么代价"。

  • late 在 k′=5 就已经拿到 1.000，到 k′=50 一个点都不涨，成本却涨 47%（2562 → 3777）。这就是"池开大了纯属浪费"的实测形式：一旦 k′ 超过"正例名次的 P95/P99"（这里是 20/23），继续开池只买到成本。注意 k′=5 就够的原因很具体：在这个池里 late 能把进池的正例排到池内第一，所以只要正例在池里（P50=2，五名内概率很高）就够 —— 这同时说明：池预算由"第一阶段的名次分布"决定，而不是由"干扰有多少"决定。
  • 成本量级：cross 每查询 3.7×105 次乘加（k′=50）vs late 的 3.8×103 —— 97 倍。用正文 2.1 节的真实量级（5×1010 乘加/候选）换算，k′=100 的 cross 精排约 5×1012 次乘加/查询，在 1013 乘加/秒量级的加速器上是 0.5 秒/查询；late 同规模只要 10−3 秒量级。这就是"质量-延迟前沿"的具体位置。

四处关键设计决策：

  1. 三档都不训练。这是为了把"结构差异"与"训练质量差异"分开。代价是 cross 代理被低估 —— 而恰恰是这个"低估"暴露了一条重要的工程事实：模型越强，越依赖训练；未训练时强档可能不如弱档。如果不做这个对照，读者会误以为"换 cross-encoder 就自动变准"。
  2. 代价用计数器实测，不用公式引用。这样表一里"late 的每候选代价低于 bi"这个反直觉结果才能被看见 —— 如果只引公式（O(Lq​Ld​de​) vs O(de​)），读者会直接得出"late 更贵"的错误结论，而忽略了 Lq​=3、Ld​=9 时实际量级。
  3. 第一阶段候选池的命中结构显式编排（正例命中 3 个 token，干扰最多 2 个）。这样"正例名次分布"就成为可测量、可解释的量（表二的 P50/P90/P95/P99），而不是黑箱。
  4. 把"文档侧 token 向量 8 bit 量化"作为一个独立档列出（late + 8bit 存储）。它把 late interaction 的真实工程约束放到桌面上：不量化要 460 GB 级存储，量化了质量可能崩。把取舍的两端都测出来，比只测不量化的理想版本有用得多。

小结#

  • 三种交互强度是三个不同的"成本位置"，不是三个质量档：点积把成本放在离线（存一份向量），late interaction 放在存储 + 在线内积，cross-encoder 放在在线算力。Fbi​⊂Flate​⊂Fcross​ 只保证表达力上界，不保证有限训练下更准。
  • 代价必须用计数器实测：本节实测出 late 的每候选在线代价（27 次乘加）低于双塔（48） —— 因为 Lq​=3、Ld​=9 时那个 3×9 相似度矩阵并不大，而 max/聚合不计乘加。如果只引公式 O(Lq​Ld​de​)，就会得出"late 更贵"的反向结论。 真实量级上的 cross-encoder 是 5×1010 次乘加/候选 —— 比双塔贵 7 个数量级，所以它只能做精排。
  • late interaction 的真实约束是存储：N=107、Ld​=180、de​=128、fp16 约 460 GB（单向量 768 维 fp32 只要 30.7 GB）。它买到的能力是"文档 token 向量可离线"。降存储的两条路（压维、量化）都会把误差直接打进打分，必须用 ε/Δ 判据定参数 —— 本节实测"直接 8 bit 均匀量化"会把 Top-1 从 1.000 打到 0.420，说明量化参数不能拍。
  • "更强不一定更准"有三个机制：训练不充分、池构成变化改变精排难度（本节实测 cross 的 recall 随池变大反而从 1.000 降到 0.975）、以及信号冗余（第二阶段复现第一阶段排序）。重排的必要条件是"它看到第一阶段看不到的东西"，这可以用"内容 token 置换后的掉幅"来验证：cross 掉 0.370，bi 只掉 0.120。
  • 池大小是一个可从数据推导的量：k′=Q1−δ​(R)，R 是第一阶段里正例的名次。本节实测这个分布是 P50=4 / P90=35 / P95=41 / P99=49，而纯 bi 的 recall@10 只有 0.635。开池超过分位数就是纯浪费（k′ 从 5 到 100，recall 不涨，成本涨 52%）；开池低于分位数则召回上界必然损失（P(R≤k′) 是硬上界，重排救不回来）。
  • 一句话：质量-延迟前沿上的工作点，由"你的第一阶段有多好"和"延迟预算有多大"两个量共同决定；前者用名次分布测，后者用实测的每候选乘加换算。两个都能测，就不需要猜。
