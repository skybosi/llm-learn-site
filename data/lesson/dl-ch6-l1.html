文本分类#

从这一课开始，我们把前面学到的 RNN、LSTM、GRU 真正落地。文本分类是最经典的序列任务之一：给一句话，判断它是好评还是差评、是新闻还是广告。它的完整流程——分词、建词表、嵌入、LSTM/GRU 编码、全连接分类——几乎可以套用到所有 NLP 任务上。这一课我们亲手搭一个端到端的中文情感分类器。

一、概念讲解#

1. 任务定义与整体流程#

文本分类的输入是一条变长文本，输出是一个类别标签。以二分类情感分析为例：输入"这家店的服务态度特别好"，输出"正面"。

完整流程是一条清晰的流水线：

  1. 分词：把句子切成词（或字）；
  2. 建词表 + 映射：把词换成整数索引，并统一做 padding；
  3. 嵌入：把整数索引映射成稠密向量；
  4. 序列编码：用 LSTM 或 GRU 按顺序读入，得到整句的表示（多对一，取最后一步或对时间步取平均/最大）；
  5. 分类头：接一个全连接层 + softmax，输出每个类别的概率。

2. 关键设计：怎么从"一串状态"得到"一个句向量"#

LSTM/GRU 会输出每个时间步的隐藏状态，但分类只需要一个向量代表整句。常用三种取法：

  • 取最后一步（out[:, -1]）：最简单，但句首信息可能被冲淡；
  • 时间步平均（out.mean(dim=1)）：对所有时间步求平均，更均衡；
  • 时间步最大池化（out.max(dim=1)）：取每个维度上的最大值，能捕捉最显著的特征。

工程上"取最后一步"和"平均"最常用。配合双向 LSTM（bidirectional=True），还能同时利用上下文，效果通常更好。本课示例里，我们把双向 GRU 的正向、反向最后一步拼起来作为句向量。

3. 损失函数与评估指标#

分类任务用交叉熵损失（CrossEntropyLoss），它对数 softmax 后的预测概率与真实标签，天然适合多分类。评估则看：

  • 准确率（accuracy）：预测对的比例，最直观；
  • 类别不平衡时还要看精确率、召回率、F1，但对入门实战，先盯准确率就够了。

训练时记得：损失下降 ≠ 一定在学有用的规律，还要在验证集上看指标，防止过拟合。

4. 一个容易踩的坑：数据泄漏与填充#

用 pad_sequence 补长后，<pad> 位置也会参与编码。如果直接对全部时间步求平均，<pad> 的噪声会被算进句向量。正确做法是用 pack_padded_sequence 让 RNN 跳过填充，或者只对有意义的输出做平均。本课示例数据长度接近，采用"取最后一步"来规避这个问题；真实项目中要更谨慎地处理。

二、可运行代码示例#

下面用一个内置的小型中文情感数据集（无需联网下载），完整实现"分词 → 词表 → 双向 GRU → 分类 → 训练"的全流程。你可以在自己的数据上替换 samples 列表，直接复用这套代码。

import torch
import torch.nn as nn
from torch.nn.utils.rnn import pad_sequence

torch.manual_seed(0)

# 1) 小型情感数据集：(句子, 标签)，1=正面，0=负面
samples = [
    ("这个 电影 很 好看", 1),
    ("服务 态度 特别 好", 1),
    ("剧情 精彩 演员 出色", 1),
    ("这家 店 太 差 了", 0),
    ("电影 无聊 透顶", 0),
    ("味道 很 一般", 0),
    ("画面 精美 配乐 动听", 1),
    ("体验 非常 糟糕", 0),
]

# 2) 分词（这里已按空格切好）+ 建词表
vocab = ["<pad>", "<unk>"] + sorted({w for s, _ in samples for w in s.split()})
w2i = {w: i for i, w in enumerate(vocab)}

def encode(s):
    return torch.tensor([w2i.get(w, w2i["<unk>"]) for w in s.split()])

texts = [encode(s) for s, _ in samples]
labels = torch.tensor([l for _, l in samples])
padded = pad_sequence(texts, batch_first=True, padding_value=0)  # (8, 最长长度)

# 3) 模型：双向 GRU 编码 + 分类头
class SentimentGRU(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden, num_class):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.gru = nn.GRU(embed_dim, hidden, batch_first=True, bidirectional=True)
        self.fc = nn.Linear(hidden * 2, num_class)

    def forward(self, x):
        out, _ = self.gru(self.embed(x))        # (batch, seq_len, hidden*2)
        last = out[:, -1, :]                    # 取最后一步作为句向量
        return self.fc(last)

model = SentimentGRU(len(vocab), embed_dim=8, hidden=8, num_class=2)
loss_fn = nn.CrossEntropyLoss()
opt = torch.optim.Adam(model.parameters(), lr=0.02)

# 4) 训练
for step in range(300):
    logits = model(padded)
    loss = loss_fn(logits, labels)
    opt.zero_grad()
    loss.backward()
    opt.step()

# 5) 评估
with torch.no_grad():
    pred = model(padded).argmax(1)
    acc = (pred == labels).float().mean().item()

print(f"最终损失：{loss.item():.4f}，训练准确率：{acc:.3f}")

# 6) 拿一条"新句子"做预测
new = encode("剧情 很 好看")
with torch.no_grad():
    prob = model(new.unsqueeze(0)).softmax(1)
print("新句子“剧情 很 好看”的预测概率（负面/正面）：", prob.tolist())

运行后，模型会把训练集里的句子正确分类（准确率接近 1.0），对"剧情 很 好看"也输出较高的正面概率。注意：数据集太小，这个高准确率更多是"记住了"，并不能代表真实泛化能力——真实项目一定要划分训练/验证集，并在验证集上选模型。

三、练习#

  1. 给 samples 再补充几条新句子（含未登录词，如"体验 很棒 五星"），重新训练并观察准确率；同时验证 <unk> 机制是否正常处理了没见过的词。
  2. 把模型从双向 GRU 换成双向 LSTM，比较参数量和训练收敛速度；再试试单向（bidirectional=False），看准确率是否下降。
  3. 把"取最后一步"改成"对所有时间步求平均"（out.mean(dim=1)），观察结果差异；思考在有 padding 的真实数据里，哪种取法更稳健。
  4. 把二分类改成三分类（加一个中性标签 2），修改标签和输出维度，重写训练代码并验证。
