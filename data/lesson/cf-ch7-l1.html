LLVM 实战：写一个 pass 并观察 IR 变化#

前六章我们都是自己造轮子：自己建 CFG、自己插 φ、自己做寄存器分配。真实工程里很少这样干——"改 IR"这件事有一个工业标准形态，就是 LLVM 的 pass。本课用一个半小时能跑完的闭环把它走通：从 clang 拿到文本 IR，定位一个可替换的模式，写一个函数级 pass，用 opt 把它挂进管道，最后看到每个 pass 前后的 IR 差异。下面每条命令和每段输出都是本机实测的，你可以逐条复核。

一、概念讲解#

1. 闭环的五个动作#

  1. 拿到 IR：clang -O0 -S -emit-llvm demo.c -o demo.ll，得到文本 IR（.ll），可直接读、可手改。
  2. 定位模式：本课挑最简单的真优化——%8 = mul nsw i32 %0, 8 换成 %.shl = shl i32 %0, 3，即强度削减（strength reduction）：乘 2 的幂改成左移。
  3. 写 pass：新 PassManager（New PM）里一个函数 pass 就是"继承 PassInfoMixin<你的类型>，实现 PreservedAnalyses run(Function &F, FunctionAnalysisManager &AM)"。
  4. 注册：插件导出 extern "C" llvmGetPassPluginInfo()，在 PassBuilder 的回调里把命令行名字映射到你的 pass。
  5. 运行与对照：opt -passes='mem2reg,strength-reduce' -load-pass-plugin ./MyPass.so demo.ll -o out.ll；加 -print-after-all 就能看到管道里每一个 pass 前后的 IR。

2. pass 的粒度决定它能做什么#

粒度 作用对象 典型用途 核心约束
ModulePass 整个模块 过程间分析、增删全局量 最自由、最慢，PassManager 无法优化调度
FunctionPass 单个函数 局部优化、指令替换 不能碰别的函数；不能跨调用保存状态
LoopPass 函数内每个循环 不变量外提、展开 只能改当前循环，循环嵌套由 LPM 维护
MachineFunctionPass 机器级 IR（MIR） 寄存器分配、调度 由后端 addPassesToEmitFile 调度，不能从 opt 跑

"函数 pass 不能跨调用保存状态"不是洁癖，而是 PassManager 敢重排、并行、按需失效分析结果的前提：只要每个 pass 只依赖入参，调度器就能自由决定顺序。第 6 章的寄存器分配、调度都属于最后一行的机器级 pass，这也是为什么它们必须挂在后端管道里而不是 opt 里。

3. 返回值是正确性契约，不是礼貌#

run() 返回 PreservedAnalyses：改了就 none()，没动就 all()，只改了局部信息就精确声明保住了哪些分析。PassManager 按这个声明决定 DominatorTree、LoopInfo 等分析结果是否失效。谎报的后果不是"慢一点"，而是后续 pass 拿着过期的支配关系做变换，生成语义错误的代码——这正是第 5 章讲的"优化正确性"在工程里的落点。

4. 分析要显式索取，也必须能单独观察#

pass 里用 AM.getResult<DominatorTreeAnalysis>(F) 要分析结果；命令行上可以只跑分析：opt -passes='print<domtree>' -disable-output demo.ll 会直接打印支配树。能"单独把分析打出来"是调试优化问题的第一手段。

5. opt 的四件套（本课全部实测）#

参数 作用
-passes='mem2reg,early-cse' 显式指定管道（New PM 语法；default<O2> 是预置管道）
-load-pass-plugin=./MyPass.so 加载动态插件里的 pass
-print-after-all / -print-before-all 每个 pass 前后 dump IR（clang 侧对应 -mllvm -print-after-all）
--version 确认版本：插件 ABI 必须与 opt 一致，混用会加载失败

6. 两个真实的坑（都是实测撞出来的）#

  • -O0 的 optnone 陷阱：clang -O0 会给函数加 optnone 属性，标准优化 pass 会跳过它。实测 opt -S -passes='mem2reg' 跑 -O0 的 IR，函数体逐字节不变（仍有 6 条 alloca）；加 -Xclang -disable-O0-optnone 重新生成后，alloca 降到 0 条。官方文档明确：optnone 函数会被跳过，但标记为 required 的 pass 仍会执行。
  • 头文件位置随版本漂移：本机 opt --version 是 Homebrew LLVM 22.1.5，PassPlugin.h 在 llvm/Plugins/ 下，而不在教程里常见的 llvm/Passes/ 下。找不到就先 ls $(llvm-config --includedir)/llvm/*/PassPlugin.h 定位——照抄旧教程的 include 会直接编译失败。

7. 常见坑清单#

  • 该失效的分析没失效：改了 IR 就返回 none()（或精确声明保住了哪些分析）；谎报 all() 会让后续 pass 拿着过期事实做变换。
  • 遍历时删除指令：必须用 make_early_inc_range(BB)，否则迭代器失效。
  • 以为 -O2 的 pass 顺序是固定的：同名 pass 会跑很多遍——实测 default<O2> 在这段 6 行 C 函数上跑了 8 次 InstCombinePass、8 次 SimplifyCFGPass、2 次 EarlyCSEPass，因为简化与展开会互相触发；-print-after-all 数一遍就明白。
  • 用 errs() 当调试输出：插件日志走 stderr，和 stdout 的 IR 混在一起读会头疼；本课示例刻意把日志打 stderr，方便 -o - 只看 IR。

二、可运行代码示例#

1. 纯 Python 版：不装 LLVM 也能完整观察 pass 链#

下面这段解析 LLVM 风格的 SSA 文本 IR，顺序跑 early-cse → const-fold → strength-reduce → dce 四个 pass，并逐步打印 IR 与改动日志——相当于自己实现一个迷你 opt。无第三方依赖，任何 Python 3 都能跑。

# ---- 迷你 opt：解析 LLVM 风格 SSA 文本 IR，跑一串 pass，并打印每个 pass 前后的 IR ----
# 纯 Python，无第三方依赖；语义刻意与真实 opt 对齐，便于与 clang/opt 的输出并排核对
import re

PURE = {'add', 'sub', 'mul', 'sdiv', 'udiv', 'srem', 'shl', 'and', 'or', 'xor'}


class Inst:
    """一条 SSA 指令：dest/op/flags/ty/ops；无 dest 表示 ret 这类终结指令"""
    def __init__(self, dest, op, flags, ty, ops):
        self.dest, self.op, self.flags, self.ty, self.ops = dest, op, flags, ty, ops

    def __str__(self):
        head = f'{self.dest} = ' if self.dest else ''
        fl = (' '.join(self.flags) + ' ') if self.flags else ''
        body = f'{self.op} {fl}{self.ty}'.rstrip()
        if self.ops:
            if self.op == 'ret':
                return f'  ret {self.ty} {self.ops[0]}'.rstrip()
            body += ' ' + ', '.join(self.ops)
        return f'  {head}{body}'.rstrip()


LINE = re.compile(r'^\s*(?:([%\w.]+)\s*=\s*)?([a-z]+)\s+(.*)$')
HDR = re.compile(r'^((?:nsw |nuw |exact )*)(i\d+|float|double|ptr|void)?\s*(.*)$')


def parse(src):
    """只解析函数体中的直线 SSA 指令（本课示例不含 CFG，控制流见第 4 章）"""
    insts = []
    for raw in src.splitlines():
        ln = raw.split(';')[0].strip()
        if not ln or ln.startswith('define') or ln == '}':
            continue
        m = LINE.match(ln)
        dest, op, rest = m.group(1), m.group(2), m.group(3).strip()
        m2 = HDR.match(rest)
        flags = m2.group(1).split()
        ty = m2.group(2) or ''
        tail = m2.group(3).strip()
        ops = [o.strip() for o in tail.split(',')] if tail else []
        insts.append(Inst(dest, op, flags, ty, ops))
    return insts


def is_const(x):
    return re.fullmatch(r'-?\d+', x) is not None


def early_cse(insts):
    """函数内值编号：右值相同的指令只保留第一条，其余改为复用它的结果（对齐 opt 的 early-cse）"""
    vnum, log = {}, []
    for i, ins in enumerate(insts):
        if not ins.dest or ins.op not in PURE or len(ins.ops) != 2:
            continue
        key = (ins.op, tuple(ins.ops))
        if key in vnum:
            old, _ = vnum[key]
            for later in insts[i + 1:]:
                later.ops = [old if o == ins.dest else o for o in later.ops]
            log.append(f'{ins.dest} 与 {old} 右值相同 → 复用 {old}')
            insts[i] = None
        else:
            vnum[key] = (ins.dest, i)
    return [x for x in insts if x is not None], log


def const_fold(insts):
    """常量折叠：两个操作数都是常量就直接算出，并用字面量替换所有使用（对齐 instcombine）"""
    log = []
    for i, ins in enumerate(insts):
        if ins.op not in PURE or len(ins.ops) != 2 or not all(is_const(o) for o in ins.ops):
            continue
        a, b = int(ins.ops[0]), int(ins.ops[1])
        if ins.op == 'add': val = a + b
        elif ins.op == 'sub': val = a - b
        elif ins.op == 'mul': val = a * b
        elif ins.op == 'shl': val = a << b
        elif ins.op in ('sdiv', 'udiv'):
            if b == 0:
                continue
            val = int(a / b)
        else:
            continue
        for later in insts:
            later.ops = [str(val) if o == ins.dest else o for o in later.ops]
        log.append(f'{ins.dest} = {ins.op} {a}, {b} → {val}')
        insts[i] = None
    return [x for x in insts if x is not None], log


def strength_reduce(insts):
    """强度削减：乘以 2^k 的常量 → 左移 k 位（本课要写的那个 pass）"""
    log = []
    for ins in insts:
        if ins.op != 'mul' or len(ins.ops) != 2:
            continue
        for k, pos in ((0, 1), (1, 0)):            # 常量可能在任一侧
            if is_const(ins.ops[pos]) and int(ins.ops[pos]) > 0:
                v = int(ins.ops[pos])
                if v & (v - 1) == 0:               # v 是 2 的幂
                    sh = v.bit_length() - 1
                    other = ins.ops[1 - pos]
                    log.append(f'{ins.dest} = mul {other}, {v} → shl {other}, {sh}')
                    ins.op, ins.ops = 'shl', [other, str(sh)]
                    ins.flags = [f for f in ins.flags if f != 'nsw']
                    break
    return insts, log


def dce(insts):
    """死代码消除：结果没人用、且无副作用的纯指令直接删掉"""
    used = {o for ins in insts for o in ins.ops}
    keep, log = [], []
    for ins in insts:
        if ins.dest and ins.op in PURE and ins.dest not in used:
            log.append(f'{ins.dest} = {ins.op} ... 结果无使用者 → 删除')
            continue
        keep.append(ins)
    return keep, log


def stats(insts):
    c = {}
    for ins in insts:
        c[ins.op] = c.get(ins.op, 0) + 1
    return c


SRC = """
define i32 @f(i32 %0, i32 %1, i32 %2) {
  %4 = add nsw i32 %0, %1
  %5 = mul nsw i32 %4, %2
  %6 = add nsw i32 %0, %1
  %7 = sdiv nsw i32 %6, %2
  %8 = mul nsw i32 %0, 8
  %13 = mul i32 6, 7
  %9 = add nsw i32 %5, %7
  %10 = add nsw i32 %9, %8
  %11 = mul nsw i32 %10, %13
  %12 = sdiv nsw i32 %5, %4
  ret i32 %11
}
"""

PIPELINE = [('early-cse', early_cse), ('const-fold', const_fold),
            ('strength-reduce', strength_reduce), ('dce', dce)]

code = parse(SRC)
print('=== 输入 IR（clang -O0 -emit-llvm 之后、mem2reg 之前的样子）===')
print(*code, sep='\n')
print(f'\n初始指令数：{len(code)}（{stats(code)}）\n')

for name, fn in PIPELINE:
    code, log = fn(code)
    print(f'--- pass: {name} ---')
    print(*code, sep='\n')
    print(f'  改动 {len(log)} 处：' + ('；'.join(log) if log else '无') + f'   [指令数 {len(code)}]\n')

print(f'最终指令数：{len(code)}（{stats(code)}）')

2. 可选（需本机 clang/LLVM 开发库）：真写一个 pass 插件#

把下面 48 行存为 MyPass.cpp：

#include "llvm/Passes/PassBuilder.h"
#include "llvm/Plugins/PassPlugin.h"   // LLVM 22 的路径；更早的版本是 "llvm/Passes/PassPlugin.h"
#include "llvm/IR/Function.h"
#include "llvm/IR/Instructions.h"
#include "llvm/IR/IRBuilder.h"
#include "llvm/IR/Constants.h"
#include "llvm/Support/raw_ostream.h"

using namespace llvm;

namespace {
struct StrengthReduce : PassInfoMixin<StrengthReduce> {
  PreservedAnalyses run(Function &F, FunctionAnalysisManager &) {
    bool Changed = false;
    for (BasicBlock &BB : F)
      for (Instruction &I : make_early_inc_range(BB)) {
        auto *BO = dyn_cast<BinaryOperator>(&I);
        if (!BO || BO->getOpcode() != Instruction::Mul) continue;
        auto *C = dyn_cast<ConstantInt>(BO->getOperand(1));
        if (!C) continue;
        APInt V = C->getValue();
        if (!V.isPowerOf2()) continue;
        unsigned K = V.logBase2();
        errs() << "  [strength-reduce] " << *BO << "  ->  shl by " << K << "\n";
        IRBuilder<> B(BO);
        Value *Sh = B.CreateShl(BO->getOperand(0), K, BO->getName() + ".shl");
        BO->replaceAllUsesWith(Sh);
        BO->eraseFromParent();
        Changed = true;
      }
    return Changed ? PreservedAnalyses::none() : PreservedAnalyses::all();
  }
  static bool isRequired() { return true; }
};
}

extern "C" LLVM_ATTRIBUTE_WEAK ::llvm::PassPluginLibraryInfo
llvmGetPassPluginInfo() {
  return {LLVM_PLUGIN_API_VERSION, "MyPass", LLVM_VERSION_STRING,
          [](PassBuilder &PB) {
            PB.registerPipelineParsingCallback(
                [](StringRef Name, FunctionPassManager &FPM,
                   ArrayRef<PassBuilder::PipelineElement>) {
                  if (Name == "strength-reduce") { FPM.addPass(StrengthReduce()); return true; }
                  return false;
                });
          }};
}
# 构建插件并造出 IR（需要与 opt 版本一致的 LLVM；Linux 上前缀常是 /usr/lib/llvm-<ver>）
LLVM=/opt/homebrew/opt/llvm
$LLVM/bin/clang++ -std=c++17 -fPIC -shared -I$LLVM/include MyPass.cpp -o MyPass.so \
  -L$LLVM/lib -lLLVM -Wl,-rpath,$LLVM/lib

cat > demo.c <<'EOF'

  int d = (a + b) * c;
  int e = (a + b) / c;
  int g = a * 8;
  return d + e + g;
}
EOF

三、练习#

  1. 实现：给迷你 opt 加第五个 pass instcombine-lite：把 add i32 %x, 0 直接替换成 %x（再删掉该指令），用 %9 = add nsw i32 %5, 0 的输入验证使用者被正确改写成 %5。
  2. 解释：为什么 PreservedAnalyses::none() 是"最安全但最慢"的选择？如果一个 pass 只改了调试信息（debug info），返回 all() 算不算撒谎？
  3. 对比/验证：跑 opt -passes='default<O2>' -print-after-all demo.ll -o /dev/null（demo.ll 是关掉 optnone 的那份；换成 demo_optnone.ll 的话函数级 pass 全被跳过、一个都数不到），数出 PromotePass、EarlyCSEPass、InstCombinePass 各出现几次，并解释同一个 pass 为什么要跑很多遍。
  4. 思考：本课的插件 pass 没有检查 optnone，所以在 -O0 的 IR 上照样改了代码。这是 bug 还是特性？如果要求它遵守 optnone，应该在哪一层判断？
