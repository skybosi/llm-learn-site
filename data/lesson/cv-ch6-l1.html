项目规划#

前面五章，你学完了从 CNN 检测分割到视觉 Transformer、再到自监督学习的完整技术栈。这一章把所学落地成一个真实的 CV 实战项目：从规划、实现到评估复盘，走完一个完整的闭环。很多人在实战时急于写代码，结果做到一半才发现数据、指标、基线都没想清楚。所以这一课不写训练循环，只做一件事——把项目在动手前规划明白。一个清晰的项目定义和一份可执行的计划，往往比调参更值钱。

一、概念讲解#

1. 先定义问题：你要解决什么，用什么任务形式#

一个 CV 项目开始于一个明确、可度量的问题，而不是一个模糊的想法。问自己三件事：

  • 业务目标：最终要优化什么？是"减少人工质检漏检率"，还是"识别遥感图里的违建"？
  • 任务形式：这个问题最适合用什么 CV 任务来表达——分类、目标检测、实例分割、语义分割，还是它们的组合？例如"数清人群里有多少人"可能是检测，"画出每辆车轮廓"是实例分割。
  • 成功标准：做到什么程度算成功？精度到多少、召回到多少、推理多快？没有量化目标的项目无法收尾。

以一个贯穿本章的例子来说明："工业缺陷检测——识别 PCB 电路板上的焊点缺陷并给出位置"。这是一个典型的目标检测 + 实例分割任务（既要框出缺陷，也最好描出缺陷轮廓）。

2. 数据：从哪来、怎么标注、怎么切分#

数据是 CV 项目的命脉，规划阶段就要把数据问题谈透：

  • 来源：优先用公开数据集（COCO、Pascal VOC、Cityscapes、VisDrone 等）做起步和基线验证；若业务数据私有，先评估能否获得、体量多大。
  • 标注：检测需要边界框，分割需要像素级掩码。标注成本极高，规划时要算清"标注多少张、用哪种工具（Labelme、CVAT、LabelImg）"。工业缺陷这类数据，常常只能靠少数专家标注，样本天然稀缺——这正是第 5 章自监督预训练能发挥作用的地方。
  • 切分：训练 / 验证 / 测试严格分离，避免数据泄漏。工业场景尤其要注意：同一张电路板的不同视角不能同时出现在训练和测试集里，否则会高估性能。

3. 基线与指标：先跑通一个"能比较"的参照#

不要一上来就上最复杂的模型。先定一个基线（baseline）和一套指标，让后续所有改进都有参照系：

  • 指标：检测常用 mAP（mean Average Precision）、召回率；分割常用 IoU（Intersection over Union）、Dice 系数；还要看推理速度（FPS）和模型大小。第 3 课会详细讲这些指标怎么算、怎么用。
  • 基线：选一个成熟、易复现的模型作为起点。Faster R-CNN / Mask R-CNN（两阶段、精度稳）或 YOLO（单阶段、速度快）都是好的检测基线；想要 ViT 系骨干可以上 DETR 或 Mask2Former。基线的作用是给你一个"及格线"，之后的改进必须证明比它强。

4. 技术选型与计划#

把选型落成一张可执行的表，规划才算是真的做完了：

  • 框架：PyTorch 是主框架；检测分割建议直接用 mmdetection、detectron2 或 ultralytics（YOLO），它们内置了大量模型、数据增强、评估脚本，能把工程成本降到最低。
  • 骨干选择：ResNet 系列（稳）、Swin（第 4 章学过的分层 Transformer，强但更重）。可以先用 ResNet 跑通，再换 Swin 做提升。
  • 预训练策略：是否用自监督预训练（第 5 章）？数据稀缺时值得一试。
  • 硬件与里程碑：单卡还是多卡、训练多久；把项目拆成"数据就绪 → 基线跑通 → 模型迭代 → 评估复盘"几个里程碑，每个都有明确的交付物。

一份好计划的标准是：任何一个里程碑失败，你都知道下一步该往哪走，而不是像无头苍蝇一样堆数据、堆算力。

二、可运行代码示例#

这一课不写训练循环，但可以先把"规划"本身变成代码——用一个项目配置对象，把问题定义、数据、模型、指标都固化下来，作为后面两课的起点：

from dataclasses import dataclass, field
from typing import List


@dataclass
class ProjectConfig:
    """把一个 CV 项目的规划固化成配置，保证各环节口径一致。"""
    # —— 问题定义 ——
    task: str = "detection+segmentation"          # 任务形式
    business_goal: str = "识别 PCB 焊点缺陷并定位"   # 业务目标
    success_metric: str = "mAP@0.5:0.95 >= 0.55"  # 量化成功标准

    # —— 数据 ——
    dataset: str = "custom_pcb_defect"            # 数据集名
    num_classes: int = 4                          # 缺陷类别数
    split: List[float] = field(default_factory=lambda: [0.7, 0.15, 0.15])  # 训练/验证/测试

    # —— 模型 ——
    backbone: str = "resnet50"                    # 先用 ResNet 跑通基线
    head: str = "mask_rcnn"                       # Mask R-CNN 检测+分割
    pretrained: bool = True                       # 是否用 ImageNet 预训练
    use_ssl_pretrain: bool = False                # 数据稀缺时可开自监督预训练

    # —— 训练 ——
    batch_size: int = 8
    max_epochs: int = 24
    lr: float = 1e-4
    device: str = "cuda"


cfg = ProjectConfig()
print("任务形式:", cfg.task)
print("量化成功标准:", cfg.success_metric)
print("数据切分比例:", cfg.split)
print("骨干网络:", cfg.backbone, "| 检测头:", cfg.head)

再用一段代码做"数据摸底"——在正式训练前，先统计数据集的图片数量、标注框/掩码数量、类别分布，及早发现"类别极度不平衡"这类隐患：

import json
import numpy as np
from collections import Counter


def survey_dataset(annotation_file):
    """极简数据摸底：统计样本数、目标数、类别分布。"""
    with open(annotation_file, "r", encoding="utf-8") as f:
        coco = json.load(f)

    images = coco["images"]
    annotations = coco["annotations"]
    cat_map = {c["id"]: c["name"] for c in coco["categories"]}

    cat_counter = Counter(ann["category_id"] for ann in annotations)
    print("图片总数:", len(images))
    print("目标总数:", len(annotations))
    print("平均每图目标数:", len(annotations) / max(len(images), 1))
    print("类别分布:")
    for cid, cnt in cat_counter.most_common():
        print(f"  {cat_map[cid]}: {cnt} ({cnt/len(annotations)*100:.1f}%)")
    return cat_counter


# 用一段假的 COCO 格式数据演示调用（真实项目里传你的 annotation.json）
demo_ann = {
    "images": [{"id": i} for i in range(100)],
    "annotations": [
        {"id": k, "category_id": c}
        for k, c in enumerate(np.random.choice([1, 2, 3], size=180, p=[0.7, 0.2, 0.1]))
    ],
    "categories": [
        {"id": 1, "name": "少锡"}, {"id": 2, "name": "桥连"}, {"id": 3, "name": "虚焊"}
    ],
}
import tempfile, os
with open("_demo_coco.json", "w", encoding="utf-8") as f:
    json.dump(demo_ann, f)
survey_dataset("_demo_coco.json")
os.remove("_demo_coco.json")

运行后会看到三个类别的占比（70% / 20% / 10%）严重不均衡——这正是规划阶段就该发现、而不是训练完才发现的问题。针对它，规划里可以提前定好对策（加权损失、过采样、聚焦长尾类别等）。

三、练习#

  1. 为你自己的兴趣领域（如"道路裂缝检测""口罩佩戴检测""农田杂草分割"）写一份 ProjectConfig，明确任务形式、成功指标、数据集与基线模型，并说明为什么选这个任务形式。
  2. 找一个公开数据集（如 COCO 或 VisDrone），下载其标注文件，用 survey_dataset 统计它的类别分布，分析是否存在长尾问题，并写出你的应对策略。
  3. 比较两阶段（Mask R-CNN）与单阶段（YOLO）检测器在"工业缺陷检测"场景下的取舍：精度、速度、小目标能力、标注需求各有什么差异？给出你的选型结论。
  4. 规划阶段最容易忽视的坑是"数据泄漏"。举出三种在检测/分割项目中可能出现的数据泄漏场景，并说明如何在切分数据时规避。
