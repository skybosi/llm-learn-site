算子级 IR 与分解（decomposition）的取舍#

第 1 课把模型捕获成了一张图，但图上写的是什么？前端最容易记下的节点是 layer_norm、gelu、softmax 这类高层算子（high-level op）——语义清楚、与框架一一对应；而后端要生成代码时，面对的是只认几十个原语（primitive）的机器：加减乘除、指数、归约、条件选择。于是编译器必须在某个时刻回答：这些算子什么时候拆、拆到什么粒度、拆完谁把它们再拼回去。本课用同一段 LayerNorm+GELU 管线，把"整体保留"与"分解成原语"两种 IR 都建出来，算清规模、数值、显存与融合四笔账。

一、概念讲解#

1. 算子级 IR 记了什么#

一个算子节点至少带三样东西：算子身份（哪个 op）、输入输出契约（每个张量的 shape 与 dtype）、参数（eps、dim、approximate='tanh' 等）。它在语义上是个黑盒：softmax 节点只说"输出是输入在 dim 上的归一化指数"，不说乘了几次、有没有减最大值、中间张量多大。分解的切入口就在这里——黑盒内部是可替换的实现：前端捕获得越"高"，IR 越短，能看见的自由度也越少。

2. 分解的三种类型#

类型 含义 例子 动了什么
结构拆分 一个 op 展开成一段子图 layer_norm → mean/sub/mul/mean/add/sqrt/div/mul/add 图结构
恒等改写 等价但更基础的形式 gelu → tanh 近似式；a/b → a * (1/b) 算子代数
位置迁移 op 留图里，下沉到后端按 pattern 处理 后端匹配成 library call 流水线阶段

前两类发生在图 IR 上；第三类是"不分解"的路。选哪条取决于后端有多少条 pattern 可匹配。

3. 为什么非要分解：N 个算子 vs M 个后端#

设前端有 N 个高层算子、后端有 M 个目标，每个后端都为每个算子写一条生成路径，工作量是 O(N×M)。分解把这个积压拆成两个和：前端把 N 个算子降到 K 个原语（K≪N，与后端数量无关），后端只为 K 个原语做代码生成。MLIR 用 linalg 作共享下降层、TVM 用算子 + 调度描述的也是同一件事：把组合爆炸压成两段线性工作。

4. 代价一：分解会拆掉融合机会，也会摧毁必须保留的结构#

融合的依据是"生产者-消费者边界在哪"。保留整体算子时 layer_norm 与 gelu 都是不可融的黑盒，分组结果是 2 组；分解成原语链后，18 个节点能整段进一个 kernel。

反向的例子同样硬：注意力依赖"QK^T→softmax→PV"这个整体结构才能套在线 softmax 与 tiling；把 softmax 拆散落地，中间张量就把显存吃光——本课的账是 (8,1024,32000) 的 exp 结果要 1000 MiB，整段融合只常驻 (B,T) 的 running max/sum，64 KiB。分解粒度不是越细越好，上限由"哪些结构必须留给后端识别"决定。

5. 代价二：分解会改变浮点结合序#

分解出的求和顺序与原算子不一定一致，而浮点加法不满足结合律。1024 个 float32（|x|∼10）的 200 组随机实验中，逐项相加相对 f64 基准的中位偏差 3.9 ULP（最大 211.4），树形归约中位 0.8 ULP（最大 126.9）。量级远小于一般训练容差，但它说明两件事："分解前后逐位相等"不能当验收标准；改写是否安全必须由编译器显式记账（第 4 章）。

6. 常见坑#

  • 在捕获阶段就分解：中间端拿不到原始算子名、参数与模块层级，按算子做 pattern 匹配就没有锚点。
  • 分解完忘做 shape 推导："sum 之后丢了 keepdim"这类偏差是图级优化最常见的事故。
  • 把分解当纯替换：tanh 近似 gelu 与精确 erf 版数值分布不同，精度验收要跟着改。

二、可运行代码示例#

下面用 numpy（python3.10 + numpy 1.26.2，纯 CPU）搭一个极简图 IR：Builder 建节点、evaluate 按原语求值、dec_* 是分解规则。同一段 LayerNorm+GELU 管线用两条路各建一张图，再比节点数、融合分组、数值一致性与浮点结合序。

# ===== 算子级 IR：同一语义，"保留整体算子" vs "分解成原语" =====
# 需要 numpy（本机 python3.10 + numpy 1.26.2，纯 CPU 验证）
import numpy as np

EPS = 1e-5

# ---------- 原语集合：后端只要认识这些就够，每个原语一个数学定义 ----------
PRIMS = {
    'add':      lambda a, b: a + b,
    'sub':      lambda a, b: a - b,
    'mul':      lambda a, b: a * b,
    'div':      lambda a, b: a / b,
    'exp':      lambda a: np.exp(a),
    'sqrt':     lambda a: np.sqrt(a),
    'sum_dim':  lambda a, d, keep=False: np.sum(a, axis=d, keepdims=keep),
    'mean_dim': lambda a, d, keep=False: np.mean(a, axis=d, keepdims=keep),
    'max_dim':  lambda a, d, keep=False: np.max(a, axis=d, keepdims=keep),
    'tanh':     lambda a: np.tanh(a),
    'input':    lambda name: None,   # 占位：求值时由 evaluate 用外部 inputs 覆盖
}

class Builder:
    """极简图 IR 构建器：节点 = (op, args)，args 里 str 指向已有值名。"""
    def __init__(self): self.nodes, self.env = [], {}
    def emit(self, op, *args):
        i = len(self.nodes); self.nodes.append((op, list(args)))
        self.env[f'v{i}'] = None; return f'v{i}'
    def ops(self): return [op for op, _ in self.nodes]
    def evaluate(self, inputs):
        env = dict(self.env); env.update({k: np.asarray(v, dtype=np.float32) for k, v in inputs.items()})
        for i, (op, args) in enumerate(self.nodes):
            if op == 'input':                       # 输入节点：把外部张量绑到这个值名上
                env[f'v{i}'] = env[args[0]]; continue
            vals = [env[a] if isinstance(a, str) else a for a in args]
            env[f'v{i}'] = PRIMS[op](*vals)
        return env[f'v{len(self.nodes) - 1}']

# ---------- 高层算子：一个节点顶一整段算法（前端"保留整体"的形态） ----------
def layer_norm(a, w, b, eps=EPS):
    mu = a.mean(axis=-1, keepdims=True)
    var = ((a - mu) ** 2).mean(axis=-1, keepdims=True)
    return (a - mu) / np.sqrt(var + eps) * w + b

def gelu_tanh(a):
    return 0.5 * a * (1.0 + np.tanh(0.7978845608 * (a + 0.044715 * a ** 3)))

PRIMS.update({'layer_norm': layer_norm, 'gelu_tanh': gelu_tanh})

# ---------- 分解规则：每个高层算子展开成一段原语子图 ----------
def dec_layer_norm(G, x, w, b, eps=EPS):
    mu = G.emit('mean_dim', x, -1, True)
    c = G.emit('sub', x, mu)
    sq = G.emit('mul', c, c)
    var = G.emit('mean_dim', sq, -1, True)
    ev = G.emit('add', var, eps)
    sd = G.emit('sqrt', ev)
    n = G.emit('div', c, sd)
    return G.emit('add', G.emit('mul', n, w), b)

def dec_gelu_tanh(G, a):
    half = G.emit('mul', a, 0.5)
    sq = G.emit('mul', a, a)
    cube = G.emit('mul', sq, a)
    t1 = G.emit('mul', cube, 0.044715)
    t2 = G.emit('add', a, t1)
    t3 = G.emit('mul', t2, 0.7978845608)
    t4 = G.emit('tanh', t3)
    return G.emit('mul', half, G.emit('add', t4, 1.0))

# ---------- 两张图：保留整体算子 vs 分解成原语，语义应当一致 ----------
def build_whole():
    G = Builder()
    x = G.emit('input', 'x')          # 输入也记一个节点，便于统一计数
    ln = G.emit('layer_norm', x, 'w', 'b')
    return G, G.emit('gelu_tanh', ln)

def build_decomposed():
    G = Builder()
    x = G.emit('input', 'x')
    ln = dec_layer_norm(G, x, 'w', 'b')
    return G, dec_gelu_tanh(G, ln)

def fusion_groups(G, fused_ops):
    """按 op 名分组统计：整体算子每个单独成组，原语则让它连成一段。"""
    groups, cur = [], 0
    for op in G.ops():
        if op == 'input': continue
        if op in fused_ops:
            cur += 1
        else:
            if cur: groups.append(('原语链', cur)); cur = 0
            groups.append((f'{op}(不可融合)', 1))
    if cur: groups.append(('原语链', cur))
    return groups

def fmt(a):
    return np.array2string(a, precision=6, suppress_small=True, floatmode='fixed')

if __name__ == '__main__':
    rng = np.random.default_rng(0)
    x = rng.standard_normal((4, 8)).astype(np.float32)
    w = rng.standard_normal(8).astype(np.float32)
    b = rng.standard_normal(8).astype(np.float32)
    inputs = {'x': x, 'w': w, 'b': b}

    whole, _ = build_whole()
    dec, _ = build_decomposed()
    yw, yd = whole.evaluate(inputs), dec.evaluate(inputs)

    print('=== 同一语义，两种 IR 的规模 ===')
    print(f'保留整体算子：{len(whole.nodes)} 个节点 → {whole.ops()}')
    print(f'分解成原语：  {len(dec.nodes)} 个节点 → {dec.ops()}')
    print(f'数值一致性：最大绝对差 = {np.abs(yw - yd).max():.3e}')
    print('前两个元素  整体版 =', fmt(yw[0, :2]))
    print('            分解版 =', fmt(yd[0, :2]))

    print('\n=== 浮点结合序：分解会改变"谁跟谁先相加" ===')
    def seq_sum(a):                      # 逐项相加（分解后的朴素写法）
        s = np.float32(0.0)
        for v in a: s = np.float32(s + v)
        return s
    def pair_sum(a):                     # 两两分组的树形归约（融合 kernel 的常见写法）
        while len(a) > 1:
            a = [np.float32(a[i] + a[i + 1]) if i + 1 < len(a) else a[i]
                 for i in range(0, len(a), 2)]
        return a[0]
    worst, worst_ulp, seq_ulp, tree_ulp = 0.0, 0.0, [], []
    for seed in range(200):
        r = np.random.default_rng(seed)
        v = (r.standard_normal(1024) * 10).astype(np.float32)
        ref = float(np.sum(v.astype(np.float64)))            # f64 作基准
        ulp = 2.0 ** -23 * abs(ref)
        for got in (float(seq_sum(v)), float(pair_sum(list(v)))):
            worst, worst_ulp = max(worst, abs(got - ref)), max(worst_ulp, abs(got - ref) / ulp)
        seq_ulp.append(abs(float(seq_sum(v)) - ref) / ulp)
        tree_ulp.append(abs(float(pair_sum(list(v))) - ref) / ulp)
    print(f'  1024 个 float32、|x|~10，200 组随机数：与 f64 基准的最大偏差 = {worst:.3e}')
    print(f'  折合最大 {worst_ulp:.1f} ULP（ULP = 2**-23 × |sum|）；'
          f'中位：逐项 {np.median(seq_ulp):.1f} ULP，树形 {np.median(tree_ulp):.1f} ULP')

    print('\n=== 中间张量的体积：分解把"不落地"变成了"要落地" ===')
    B, T, V = 8, 1024, 32000
    softmax_mid = B * T * V * 4                                   # 未归一化指数张量，float32
    print(f'  softmax 输入 (B,T,V)=({B},{T},{V})：分解出的 exp 结果需要 {softmax_mid / 2**20:.0f} MiB 显存')
    print(f'  整段融合（在线 softmax 一类写法）只需常驻 (B,T)=({B},{T}) 的 running max/sum，'
          f'即 {B * T * 4 * 2 / 2**10:.1f} KiB——相差 {softmax_mid / (B * T * 4 * 2):.0f} 倍')

    print('\n=== 融合分组：分解把"算子边界"变成了可融合的原语链 ===')
    for name, G in (('保留整体', whole), ('分解成原语', dec)):
        groups = fusion_groups(G, fused_ops=set(PRIMS) - {'layer_norm', 'gelu_tanh'})
        print(f'  {name}：{len(groups)} 组 → {groups}')

实际运行结果（python3.10.16 + numpy 1.26.2）：

=== 同一语义，两种 IR 的规模 ===
保留整体算子：3 个节点 → ['input', 'layer_norm', 'gelu_tanh']
分解成原语：  19 个节点 → ['input', 'mean_dim', 'sub', 'mul', 'mean_dim', 'add', 'sqrt', 'div', 'mul', 'add', 'mul', 'mul', 'mul', 'mul', 'add', 'mul', 'tanh', 'add', 'mul']
数值一致性：最大绝对差 = 0.000e+00
前两个元素  整体版 = [-0.138962  0.888542]
            分解版 = [-0.138962  0.888542]

=== 浮点结合序：分解会改变"谁跟谁先相加" ===
  1024 个 float32、|x|~10，200 组随机数：与 f64 基准的最大偏差 = 6.539e-04
  折合最大 211.4 ULP（ULP = 2**-23 × |sum|）；中位：逐项 3.9 ULP，树形 0.8 ULP

=== 中间张量的体积：分解把"不落地"变成了"要落地" ===
  softmax 输入 (B,T,V)=(8,1024,32000)：分解出的 exp 结果需要 1000 MiB 显存
  整段融合（在线 softmax 一类写法）只需常驻 (B,T)=(8,1024) 的 running max/sum，即 64.0 KiB——相差 16000 倍

=== 融合分组：分解把"算子边界"变成了可融合的原语链 ===
  保留整体：2 组 → [('layer_norm(不可融合)', 1), ('gelu_tanh(不可融合)', 1)]
  分解成原语：1 组 → [('原语链', 18)]

四笔账：规模——3 节点 vs 19 节点，分解换来代数化简与融合空间，代价是后端要多支持原语；正确性——两条路输出差为 0，因为本课让二者用了同一次求和顺序；数值——仅换一种结合序，中位偏差就从 3.9 ULP 降到 0.8 ULP（最大 211 ULP），所以"逐位相等"不能当验收标准；显存——把 softmax 拆散落地，(8,1024,32000) 的 exp 中间结果要 1000 MiB，整段融合只留 64 KiB running 状态。

三、练习#

  1. 实现：给 dec_gelu_tanh 再写一版按精确 erf 分解（先声明 erf 原语再在 PRIMS 里定义），比较两版在 x 取 −6…6 上的最大差异，说明哪版更该进编译器。
  2. 解释：为什么保留整体算子会让融合分组退化成每组一个算子？若 100 个模型各定义了略有差异的 layer_norm，你希望 IR 里存什么？
  3. 对比/验证：把 dec_layer_norm 的 mean_dim 换成"先 sum_dim 再 mul 1/n"，重跑一致性对比；再用 1000 个 float32 比三种求和顺序的 ULP。
  4. 思考：若目标后端只认 matmul 与 elementwise，你会把 softmax 分解到哪一步、保留哪一步？用本课的显存账说明边界画在哪。
