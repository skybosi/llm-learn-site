注意力打分#

上一课我们建立了直觉：注意力是用 Query 去"比对"每个 Key，得到相关程度。这个"比对"在数学上就是打分函数（scoring function），它输出一个标量，衡量"这个 Key 和当前 Query 有多相关"。打分方式不止一种——点积、缩放点积、加性、双线性——各自有不同的代价与适用场景。这一课我们把它们逐一拆开，用 PyTorch 亲手实现并比较。

一、概念讲解#

1. 打分函数是注意力的"心脏"#

注意力的计算链条是：打分 → 归一化（softmax）→ 加权求和。其中打分决定了一切：打分准，权重才分得清"谁重要、谁无关"；打分糊，后面的归一化和加权再精致也白搭。所以理解打分函数，是理解所有注意力变体的关键。

统一记法：给定查询向量 q 和键向量 k，打分函数 score(q, k) 输出一个标量。实际中 q 只一个，k 有一串（编码器每个位置一个），于是得到一列标量分数，再交给 softmax。

2. 点积打分与它的"膨胀"隐患#

最简单直接的想法：把 q 和 k 做点积。

score(q, k) = q · k = qᵀ k

点积衡量两个向量方向一致的程度，计算量极小。但它有个隐患：向量的维度 d 越大，点积的数值越容易"爆炸"。因为点积是 d 个分量乘积之和，d 越大，这个和的标准差越大。数值一大，softmax 就会退化成近似 one-hot——权重几乎全压在最大值上，梯度趋近 0，训练不动。这个隐患在下一章"缩放点积"里会正式解决，这里先记住点积打分很"贪快但容易飘"。

3. 加性打分（Bahdanau 风格）#

加性注意力不直接点积，而是把 q 和 k 拼接起来，喂进一个小的前馈网络，输出一个标量：

score(q, k) = vᵀ tanh(W_q q + W_k k)

这里的 W_q、W_k 先把 q、k 各自投影到同一个隐空间，相加后过 tanh 压一压，再由向量 v 投影成标量。加性打分的好处是表达能力强——q 和 k 不必同维度，网络可以学到任意复杂的相关性；代价是多几层矩阵乘，参数更多、更慢。它是最早被用在神经机器翻译里的注意力打分（Bahdanau 2014），可以看作是"可学习的两两匹配器"。

4. 双线性打分（Luong "general" 风格）#

在点积和加性之间取一个折中：在 q 与 k 之间夹一个可学习矩阵 W：

score(q, k) = qᵀ W k

当 W 是单位矩阵时，它退化成普通点积；当 W 是任意矩阵时，它让 q 和 k 的不同维度之间可以"交叉配对"，比点积更灵活，又比加性更轻量。它只多一个 d×d 的参数矩阵，是工程里很实用的选择。

5. 三种打分怎么选#

打分方式 公式 参数 特点
点积 qᵀ k 无 最快，维度大时数值易膨胀
加性 vᵀ tanh(W_q q + W_k k) 多 表达力最强，q/k 可不同维度
双线性 qᵀ W k 一个矩阵 折中，轻量且灵活

实践中，Transformer 用的是"点积 + 缩放"，因为它在大规模并行训练下又快又稳；加性和双线性则在"查询与键含义不对称"的场景里仍有价值。选哪种，本质是在表达力、参数量、计算速度三者间权衡。

二、可运行代码示例#

下面用 PyTorch 把三种打分都实现出来，对同一个 q 和同一串 keys 分别打分，直观比较它们的输出。

import torch
import torch.nn as nn

torch.manual_seed(0)

d = 6                                    # 向量维度
q = torch.randn(d)                       # 一个查询向量
keys = torch.randn(3, d)                 # 3 个键（可理解为编码器 3 个时间步）

# 1) 点积打分：q 与每个键直接点积
dot_scores = keys @ q
print("点积打分:      ", dot_scores)

# 2) 缩放点积打分：除以 sqrt(d)，抑制维度变大时点积数值膨胀
scaled_scores = dot_scores / (d ** 0.5)
print("缩放点积打分:  ", scaled_scores)

# 3) 加性打分（Bahdanau 风格）：q 和 k 各自投影、相加、tanh，再投影成标量
class AdditiveScore(nn.Module):
    def __init__(self, d, hidden):
        super().__init__()
        self.Wq = nn.Linear(d, hidden, bias=False)
        self.Wk = nn.Linear(d, hidden, bias=False)
        self.v = nn.Linear(hidden, 1, bias=False)

    def forward(self, q, k):
        # q 与 k 投影到同一隐空间后相加，tanh 压缩，最后投影成标量
        return self.v(torch.tanh(self.Wq(q) + self.Wk(k))).squeeze(-1)

add = AdditiveScore(d, hidden=8)
add_scores = add(q, keys)
print("加性打分:      ", add_scores)

# 4) 双线性打分（general 风格）：用可学习矩阵 W 夹在 q 与 k 之间
class BilinearScore(nn.Module):
    def __init__(self, d):
        super().__init__()
        self.W = nn.Linear(d, d, bias=False)

    def forward(self, q, k):
        return k @ self.W(q)             # 等价于 kᵀ W q

bi = BilinearScore(d)
bi_scores = bi(q, keys)
print("双线性打分:    ", bi_scores)

注意几个细节：

  • 加性打分里，self.Wq(q) 形状是 (hidden,)，self.Wk(k) 是 (3, hidden)，二者相加靠广播变成 (3, hidden)，最后 v 把它压成 (3,)，正好是每个键一个标量分；
  • 双线性打分里 self.W(q) 得到 (d,)，再与 (3, d) 做矩阵乘，得到 (3,)；
  • 三种打分的输出形状一致（都是"键的个数"个标量），所以后接的 softmax 与加权求和可以共用一套逻辑，这正体现了"打分函数可插拔"的设计。

三、练习#

  1. 把 d 从 6 改成 256，重新运行点积打分部分，观察未缩放的 dot_scores 数值量级膨胀了多少，验证"维度越大点积越飘"的现象。
  2. 给 BilinearScore 的 W 初始化成单位矩阵，比较它的输出与点积打分是否一致，从而理解"点积是双线性在 W=I 时的特例"。
  3. 把加性打分里的 tanh 换成 ReLU，观察输出分布的变化，思考非线性激活在"可学习匹配器"里起什么作用。
  4. 思考：如果 q 的维度是 8 而 k 的维度是 6，上面哪种打分能直接工作？哪种需要先对齐维度？这如何影响你在异构特征上的选型？
