强度削减、循环展开与向量化预备（与 GPU tiling 呼应）#

前几课的改写都在"少算几条指令"的量级上。真正决定性能的是循环：循环体里少一条乘法，乘以迭代次数就是可观的工作量；而循环能不能向量化（vectorization），决定同一段时间里一条指令处理几个数据。这一课讲三个必须连起来看的变换——强度削减（乘法换成加法）、循环展开（用代码体积换并行素材）、向量化的可行性判据；最后把"连续访存"这个前提推进到 tiling，你会看到它和 GPU 上分块复用数据是同一件事的两种后端。

一、概念讲解#

1. 强度削减：先找归纳变量，再替换派生计算#

归纳变量（induction variable）是在循环里按固定步长变化的变量，形如 i = i + k（k 为常量）。它的派生值几乎都能用"再加一个常量"代替：

  • i * m：每轮固定增加 k * m；
  • base + i * m：每轮固定增加 k * m（地址算术，最典型的用法）。

前提三条缺一不可：步长 k 必须是编译期常量；初值能算出来；派生变量必须和归纳变量同步更新（i 在循环体里被改写多次时，每轮净变化不再是 k）。

本课代码实测：循环体里 t2 = i * 4 变成 preheader 的 p_t2 = 0 加循环内的 p_t2 = p_t2 + 4，循环体内乘法 1 → 0，加法 2 → 3。更通用的版本由 LLVM 的 Scalar Evolution（SCEV）处理：整条地址算术链从"每轮重算"变成"每轮加常数"。

2. 循环展开：用代码体积换两类收益#

展开（loop unrolling）把循环体复制 k 份，归纳变量步长改成 k：

  • 收益一：减少循环控制开销——本课实测每 2 次迭代的条件判断从 2 次降到 1 次，主循环体指令 6 → 11。
  • 收益二：把不同迭代的独立指令摆到一起，给指令调度与向量化提供素材（LLVM 的向量化器自己也会做 partial unrolling）。

代价同样明确：代码体积约 ×k（余数循环本课再补 6 条）、寄存器压力上升、trip count 不整除时必须补余数循环（epilogue）。展开因子是代价模型的输出，不该照抄。

3. 向量化的四个前置条件#

向量化把"多条相同运算的标量指令"换成一条向量指令。能不能做，先查这张清单：

条件 不满足时的表现 本课检查器的判定
循环可数（trip count / 步长已知） 无法确定向量宽度与余数 L5 链表遍历 → 否
访存步长为 1（连续） 需要 gather/scatter，代价模型通常否决 L3 步长 4 → 否
无循环携带依赖 第 i 次依赖第 i-1 次，不能并行重排 L2 A[i] = A[i-1] + 1 → 否
归约允许重排 整型可重排；浮点不满足结合律 L4 归约 → 可（浮点需 fast-math）

LLVM 的自动向量化文档把后两条讲得很具体：归约能被向量化，但"完全向量化归约需要重排运算"，而浮点不满足结合律，因此 LLVM 只在启用 -fassociative-math -fno-signed-zeros -fno-trapping-math 这组 fast-math 时才向量化浮点归约。文档还指出：两个指针可能重叠（无法证明不别名）时，向量化必须插入运行时指针检查，检查失败就退化为标量版本——所以"能向量化"有时意味着"代码里多了一段判断"。

展开与向量化不是重复劳动：展开把多个标量迭代并排放，向量化把它们真的塞进一条指令。一般经验：先做完强度削减与不变量外提（让循环体更干净、依赖更少），再考虑展开与向量化。

4. tiling：把"连续"变成可向量/可映射到线程的维度#

以 for i in 0..1000: A[i] = B[i] + K 为例，按 T = 8 分块后：

for io in 0..1000 step 8:        # 外层 125 轮（1000 能被 8 整除，无余数）
    for ii in 0..8:              # 内层 8 轮 ≈ 一个向量宽度
        A[io + ii] = B[io + ii] + K

内层循环连续访问、无跨迭代依赖，因此可以整块向量化。把这个形状搬到 GPU：CUDA 的 tiling 让 threadIdx.x 沿连续维取数，使一个 warp 的一次访存覆盖连续地址（合并访存），每个线程还能一次搬 4 个元素。同一件事、两种后端：CPU 用 SIMD 指令与向量寄存器，GPU 用多线程 + 合并访存；共通前提都是"内层连续、无跨迭代依赖"，差别只在效率来源（一条指令几个元素 vs 数据复用与合并访存）。

5. 常见坑#

  • 展开后忘了余数循环：trip count 不整除时漏算或越界。
  • 归纳变量被多次改写：i 在循环体里改了两回，累加变量的步长必须按每轮净变化算。

二、可运行代码示例#

下面这段纯 Python 分三部分：强度削减（含外提前后的对照）、因子 2 的循环展开（含余数循环）、把四个前置条件写成判定的向量化检查器，最后打印 tiling 后的循环结构。

# ---- 强度削减 / 循环展开 / 向量化可行性检查 / tiling（纯 Python，无第三方依赖）----
BIN = {'add', 'sub', 'mul', 'div'}


def nm(x):
    return ('name', x)


def ct(k):
    return ('const', k)


def op_str(x):
    return str(x[1]) if x else '-'


def fmt(ins):
    op = ins[0]
    if op == 'copy':
        return f'{ins[3]} = {op_str(ins[1])}'
    if op in BIN:
        return f'{ins[3]} = {op_str(ins[1])} {op} {op_str(ins[2])}'
    if op == 'cmp':
        return f'{ins[4]} = {op_str(ins[2])} {ins[1]} {op_str(ins[3])}'
    if op == 'ifgoto':
        return f'if {op_str(ins[1])} goto {ins[2]} else {ins[3]}'
    if op == 'goto':
        return f'goto {ins[1]}'
    if op == 'load':
        return f'{ins[3]} = {op_str(ins[1])}[{op_str(ins[2])}]'
    if op == 'store':
        return f'{op_str(ins[1])}[{op_str(ins[2])}] = {op_str(ins[3])}'
    if op == 'return':
        return f'return {op_str(ins[1])}'
    return str(ins)


def def_use(ins):
    op = ins[0]
    if op == 'copy':
        return ins[3], [ins[1]]
    if op in BIN:
        return ins[3], [ins[1], ins[2]]
    if op == 'cmp':
        return ins[4], [ins[2], ins[3]]
    if op == 'load':
        return ins[3], [ins[1], ins[2]]
    if op == 'store':
        return None, [ins[1], ins[2], ins[3]]          # 有副作用：不能删
    if op in ('ifgoto', 'return'):
        return None, [ins[1]]
    return None, []


def show(prog, title):
    print(title)
    for b in prog:
        for ins in prog[b]:
            print(f'  {b}: {fmt(ins)}')


def subst(ins, old, new):
    """把指令里所有"使用 old"的操作数换成 new（定义名是裸字符串，不动）"""
    out = []
    for x in ins:
        if isinstance(x, tuple) and x[0] == 'name' and x[1] == old:
            out.append(nm(new))
        elif isinstance(x, list):
            out.append([nm(new) if (isinstance(y, tuple) and y[0] == 'name' and y[1] == old) else y
                        for y in x])
        else:
            out.append(x)
    return tuple(out)


# ============ 第一部分：归纳变量 + 强度削减（i*4 → 每轮加 4）============
# 循环：for (i = 0; i < n; i = i + 1) A[i * 4] = A[i * 4] + 1;
LOOP = {
    'B1': [('copy', ct(0), None, 'i'), ('goto', 'B2')],
    'B2': [('cmp', '<', nm('i'), nm('n'), 't1'),
           ('ifgoto', nm('t1'), 'B3', 'B5')],
    'B3': [('mul', nm('i'), ct(4), 't2'),
           ('load', nm('A'), nm('t2'), 'x'),
           ('add', nm('x'), ct(1), 'y'),
           ('store', nm('A'), nm('t2'), nm('y')),
           ('add', nm('i'), ct(1), 'i'),
           ('goto', 'B2')],
    'B5': [('return', ct(0))],
}


def strength_reduce(prog, iv, step, pre='B1', latch='B3'):
    """iv: 归纳变量名；step: 每轮步长；把循环内 iv*常量 换成累加变量"""
    init = 0
    for ins in prog[pre]:
        if ins[0] == 'copy' and ins[3] == iv and ins[1][0] == 'const':
            init = ins[1][1]
    report, loop_blocks = [], [b for b in prog if b not in (pre,)]
    for b in list(prog):
        for ins in [x for x in prog[b] if x[0] == 'mul' and x[1] == nm(iv) and x[2][0] == 'const']:
            m, t, p = ins[2][1], ins[3], f'p_{ins[3]}'
            for bb in loop_blocks:                      # 循环内所有用到 t 的地方改读 p
                prog[bb] = [subst(x, t, p) for x in prog[bb]]
            prog[b] = [x for x in prog[b] if x != ins]  # 删掉乘法本身
            pos = len(prog[pre]) - 1                    # 循环前算一次初值
            prog[pre] = prog[pre][:pos] + [('copy', ct(init * m), None, p)] + prog[pre][pos:]
            prog[latch] = prog[latch][:-1] + [('add', nm(p), ct(step * m), p)] + [prog[latch][-1]]
            report.append(f'  {iv} 每轮 +{step}，{fmt(ins)} 的右值每轮固定加 {step * m} → '
                          f'用累加变量 {p}（初值 {init * m}）代替')
    return prog, report


print('=== 强度削减：把循环里的乘法换成加法 ===')
show(LOOP, '削减前：')
reduced, rep = strength_reduce({b: list(v) for b, v in LOOP.items()}, 'i', 1)
for line in rep:
    print(line)
show(reduced, '削减后：')
count = lambda body, op: sum(1 for i in body if i[0] == op)
print(f'  循环体内乘法：{count(LOOP["B3"], "mul")} → {count(reduced["B3"], "mul")}；'
      f'循环体内加法：{count(LOOP["B3"], "add")} → {count(reduced["B3"], "add")}'
      f'（多出来的是累加变量的自增）\n')

# ============ 第二部分：循环展开（因子 2 + 余数循环）============
BODY = [('mul', nm('@i@'), ct(4), 'off'),
        ('load', nm('A'), nm('off'), 'x'),
        ('add', nm('x'), ct(1), 'y'),
        ('store', nm('A'), nm('off'), nm('y'))]


def rename(instrs, suffix, index='i'):
    d = {'@i@': index, 'off': f'off{suffix}', 'x': f'x{suffix}', 'y': f'y{suffix}'}

    def opd(x):
        return nm(d[x[1]]) if x and x[0] == 'name' and x[1] in d else x
    out = []
    for ins in instrs:
        op = ins[0]
        if op == 'mul':
            out.append(('mul', opd(ins[1]), ins[2], d.get(ins[3], ins[3])))
        elif op == 'load':
            out.append(('load', ins[1], opd(ins[2]), d.get(ins[3], ins[3])))
        elif op == 'add':
            out.append(('add', opd(ins[1]), ins[2], d.get(ins[3], ins[3])))
        elif op == 'store':
            out.append(('store', ins[1], opd(ins[2]), opd(ins[3])))
    return out


unrolled = {
    'B1': [('copy', ct(0), None, 'i'), ('goto', 'B2')],
    'B2': [('add', nm('i'), ct(1), 'i_next'),
           ('cmp', '<', nm('i_next'), nm('n'), 'c2'),
           ('ifgoto', nm('c2'), 'B3', 'B4')],
    'B3': rename(BODY, '_1') + [('add', nm('i'), ct(1), 'i')] +
          rename(BODY, '_2') + [('add', nm('i'), ct(1), 'i'), ('goto', 'B2')],
    'B4': [('cmp', '<', nm('i'), nm('n'), 'c1'),
           ('ifgoto', nm('c1'), 'B5', 'B6')],
    'B5': rename(BODY, '_r') + [('add', nm('i'), ct(1), 'i'), ('goto', 'B4')],
    'B6': [('return', ct(0))],
}
print('=== 循环展开（因子 2 + 余数循环兜住 0/1 个剩余迭代）===')
show({'B2': LOOP['B2'], 'B3': LOOP['B3']}, '展开前的一个循环：')
show(unrolled, '展开后：')
print(f'  主循环体指令：{len(LOOP["B3"])} → {len(unrolled["B3"])}'
      f'（两份体各 {len(BODY)} 条 + 2 次自增 + 1 条回边）')
print(f'  每 2 次迭代的条件判断：2 次 → 1 次；代价：代码体积约 ×2（余数循环再补 '
      f'{len(unrolled["B5"])} 条），同时活跃的中间值变多 → 寄存器压力上升\n')

# ============ 第三部分：向量化可行性检查 + tiling ============
CAND = [
    {'name': 'L1  A[i] = B[i] + K', 'stride': 1, 'carried': False, 'trip_known': True, 'reduc': False},
    {'name': 'L2  A[i] = A[i-1] + 1', 'stride': 1, 'carried': True, 'trip_known': True, 'reduc': False},
    {'name': 'L3  A[4*i] = B[4*i] + K', 'stride': 4, 'carried': False, 'trip_known': True, 'reduc': False},
    {'name': 'L4  s = s + A[i]', 'stride': 1, 'carried': True, 'trip_known': True, 'reduc': True},
    {'name': 'L5  while (p) A[i] = *p, p = p->next', 'stride': 0, 'carried': True,
     'trip_known': False, 'reduc': False},
]
print('=== 向量化可行性检查（每条给结论与理由）===')
for c in CAND:
    if not c['trip_known']:
        ok, why = False, '循环次数未知且访问步长不固定（无法确定向量宽度与余数）'
    elif c['stride'] != 1:
        ok, why = False, f'步长 {c["stride"]} ≠ 1（跨步访问，需要 gather/scatter，代价模型通常否决）'
    elif c['carried'] and not c['reduc']:
        ok, why = False, '存在循环携带依赖（第 i 次用到第 i-1 次的结果），不能并行重排'
    elif c['carried'] and c['reduc']:
        ok, why = True, '是归约：整型可向量化（允许重排）；浮点需 fast-math 才允许重排'
    else:
        ok, why = True, '步长 1、无携带依赖 → 可向量化（若指针可能重叠，还需运行时指针检查）'
    print(f'  {c["name"]:<40} {"可" if ok else "否":<2} ← {why}')

print('\n=== tiling：把步长 1 的循环切成两层 ===')
n, T = 1000, 8
print(f'  原循环：for i in 0..{n}: A[i] = B[i] + K        （每次迭代 1 次读 + 1 次写）')
print(f'  tiling：for io in 0..{n} step {T}: for ii in 0..{T}: A[io+ii] = B[io+ii] + K')
print(f'  外层 {n // T} 轮（{n} 能被 {T} 整除，无余数）× 内层 {T} 轮：'
      f'内层正好 1 个向量宽度，可整块向量化')
print('  对照：这个"外层 tile + 内层连续"的形状，与 GPU 上 tiling 后'
      '"块内线程沿连续维取数"是同一件事的两种后端（见第 4 章 GPU tiling）')

三、练习#

  1. 实现：给 strength_reduce 增加 base + i * m 形式的支持（现在只处理裸 i * m），并处理 i 在循环体里被改写多次的情况——提示：按"每轮回到 header 时 i 的净变化"计算累加变量的步长。
  2. 解释：为什么展开能提升向量化的机会，而向量化本身又常常需要先做 partial unrolling（interleave）？两者各自解决的是"哪种资源不够"？
  3. 对比/验证：把 tiling 的 T 从 8 改成 7 再手算一遍（1000 = 142 × 7 + 6），说明为什么向量化必须补 epilogue；再把 L1 改成 A[i] = A[i-1] + K 跑检查器，观察结论与理由的变化。
  4. 思考：CPU 的 SIMD 宽度固定（一条指令处理固定个元素），GPU 的一个 warp 固定 32 个线程。为什么两边都要求"内层循环连续访存"？两边"效率的来源"分别是什么（一条指令搬多个元素 vs 一次访存覆盖连续地址）？
