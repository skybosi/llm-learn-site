NVLink/NVSwitch#

上一课讲了 PCIe 这条"窄路"，这一课讲 NVIDIA 为绕过它而专门打造的"高速立交"——NVLink 与 NVSwitch。学完本课，你应当能说清 NVLink 比 PCIe 快多少、NVSwitch 解决了什么问题，以及为什么多卡集群离不开它们。

一、概念讲解#

1. NVLink：GPU 之间的专用高速互连#

NVLink 是 NVIDIA 的 GPU 到 GPU 点对点互连技术，用多条高带宽链路把两张 GPU 直接接起来，不经过 CPU、不走 PCIe。它的带宽远高于 PCIe，是数据中心多卡通信的主力。按代际看：

代际 典型产品 每 GPU 总带宽
NVLink 3.0 A100 约 600 GB/s（12 条链路）
NVLink 4.0 H100 约 900 GB/s（18 条链路）

对比 PCIe 5.0 ×16 的约 63 GB/s，NVLink 4.0 快了 十几倍，这也是 H100 相比 PCIe 版更适合大规模训练与推理的根本原因之一。

2. NVSwitch：把"两两相连"升级成"全互联"#

只靠 NVLink 做点对点连接，8 张 GPU 两两全连需要的链路数量会爆炸，而且任意两卡之间可能还要经中间卡转发。NVSwitch 是一颗高速交换芯片：把多张 GPU 的 NVLink 都接到 NVSwitch 上，任意两卡都能以满带宽无阻塞地通信，相当于一个"全互联交换机"。

3. 为什么多卡推理/训练需要它#

多卡做张量并行（tensor parallelism）时，一层矩阵乘被切到多张卡上，每算完一步都要在卡之间交换中间结果（all-reduce / all-gather）。这种通信极其频繁、数据量大，若走 PCIe 会立刻成为瓶颈；有了 NVLink/NVSwitch，通信开销被大幅压低，多卡才真正"划算"起来。

4. NVLink 也有限度#

NVLink 再快，也跨不出单台服务器：它只连接同一机箱内的 GPU。跨机器的多卡通信仍要回到 InfiniBand / 以太网（RDMA）这类网络，带宽又降一个台阶。所以"单机 8 卡 NVSwitch 全互联 + 跨机高速网络"是大型集群的典型形态。

二、可运行示例#

用纯 Python 对比"同一批数据走 PCIe 还是走 NVLink 要多久"，量化多卡通信的收益。

# -*- coding: utf-8 -*-
# 对比 PCIe 与 NVLink 搬运同一批数据的耗时

def transfer_time_ms(data_bytes, bw_bytes_per_sec):
    return data_bytes / bw_bytes_per_sec * 1000   # 毫秒

# 各互连的带宽（B/s）
links = {
    "PCIe 4.0 x16": 31.5e9,
    "PCIe 5.0 x16": 63.0e9,
    "NVLink 3.0 (A100)": 600e9,
    "NVLink 4.0 (H100)": 900e9,
}

# 场景：张量并行时，单层需要 all-reduce 的数据量。
#   以 70B 模型为例，一次通信交换的中间结果约等于一层权重的数据量。
#   70B / 80 层 ≈ 每层 0.86B 参数，FP16 下约 1.7 GB（这里取整估 2 GB）。
comm_bytes = 2.0e9

print("单层 all-reduce 通信（约 2 GB）耗时：")
for name, bw in links.items():
    t = transfer_time_ms(comm_bytes, bw)
    print(f"  {name:<22} {t:>8.2f} 毫秒")

# 速度倍数
pcie5 = links["PCIe 5.0 x16"]
for name, bw in [("NVLink 3.0 (A100)", links["NVLink 3.0 (A100)"]),
                 ("NVLink 4.0 (H100)", links["NVLink 4.0 (H100)"])]:
    print(f"  {name} 带宽是 PCIe 5.0 x16 的 {bw/pcie5:.1f} 倍")

# 换个视角：同样 10 毫秒内，各互连能搬多少 GB？
print("\n10 毫秒内各互连可搬运数据量：")
for name, bw in links.items():
    gb = bw * 0.010 / 1e9
    print(f"  {name:<22} {gb:>7.1f} GB")

# 通信是"每层都要发生"的：70B 共 80 层，估算整轮前向的通信总量耗时
print("\n70B 模型 80 层各通信一次（每层 2 GB）的总耗时：")
for name, bw in links.items():
    total_s = 80 * transfer_time_ms(comm_bytes, bw) / 1000
    print(f"  {name:<22} {total_s:>7.2f} 秒")

运行后你会看到，同样 2 GB 的通信，PCIe 4.0 要 60 多毫秒，NVLink 4.0 只要 2 毫秒出头——一层看似差别不大，但 80 层叠加起来，PCIe 会吃掉数十倍的时间，直接决定多卡并行还有没有意义。

三、练习#

  1. 手算：NVLink 4.0 每 GPU 约 900 GB/s，搬 18 GB 数据要多少毫秒？同样数据走 PCIe 4.0 ×16（约 31.5 GB/s）要多少毫秒？
  2. 换代：把 links 里的 NVLink 3.0 换成 600 GB/s 的 2 倍，模拟"链路翻倍"，观察总耗时如何变化，说明为什么 H100 比 A100 更适合大模型。
  3. 通信量：把 comm_bytes 改成 0.5e9 和 8e9，观察耗时变化，体会"通信量由模型规模和并行切分方式决定"。
  4. 跨机：假设跨机网络（InfiniBand）只有 400 GB/s，且多一跳交换，把它的带宽写进 links，对比与单机 NVSwitch 的差距。
  5. 思考：为什么说 NVLink 解决的是"单机内"的通信瓶颈？跨机器的通信瓶颈靠什么解决？这对"单机 8 卡"和"多机 64 卡"两种部署意味着什么？
