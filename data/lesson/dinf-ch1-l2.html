张量并行：通信量下界、切法选择与"它省下的到底是什么"#

这一节要解决什么#

上一节把三类并行当成同质的通信算了 N∗。但张量并行（TP）的通信量不是"随便多少"—— 它由切在哪一层、每层切几次决定，而不同的切法给出的字节数差好几倍。训练课（dts-ch5-l2）讲了切分数学，这一节要补三件推理侧必须自己回答的事：

  1. TP 的通信量下界是多少，它紧不紧？ 如果下界已经被达到，那么"TP 拆到 8 变慢"就不是实现问题，而是结构问题——调库没有用。
  2. 切在同一处，是否只有一个最优切法？ 列并行、行并行、头并行、隐藏维并行、残差的全量复制……这些选择在字节数上的差别是多少？
  3. TP 省的到底是访存还是算力？ 这个问题的答案决定了 TP 与低精度权重是可叠加还是互相替代——一个直接影响选型的问题。

先给结论：

\boxed{\text{TP 在 decode 上省的是「每 token 的权重访存字节」，代价是「每 token 每层的 }2\text{ 次全归约」}

而 decode 是访存瓶颈（算术强度 ≈1 FLOP/byte vs 拐点 330），所以 TP 的收益是真实的。但这个收益可以被"加大 batch"部分替代 —— 这是本节最后一条，也是全章最容易被忽略的结论。

一、TP 的通信量：把每一层数一遍#

1.1 Megatron-LM 口径：每层两次全归约#

decoder-only 的 Transformer 层（pre-LN，GQA）在 TP 下的标准切法：

输入 X [b, s, h]（在 TP 组内是**完整**的）
  ① QKV 投影：列并行 → 每 rank 算出自己那部分头/维度
  ② 注意力（每 rank 本地做自己那部分头，故无需通信）
  ③ 输出投影 Wo：行并行 → ★ AllReduce #1（[b,s,h] 部分和求和）
  ④ MLP up/gate：列并行 → 激活 → down：行并行 → ★ AllReduce #2
  ⑤ 残差 + LN：在完整 h 上做（因为 ①③④ 的输入输出都是完整的 h）
输出 X' [b, s, h]（完整）

关键结构事实：因为每一层的输入输出都是完整的隐藏维（不是被切的），所以一次前向只有两次全归约，且每次的数据量恰好是 b⋅s⋅h 个元素。这不是实现选择，而是"残差连接必须作用在完整表示上"这个数学要求的结果。

每次全归约的元素数=bsh,每层次数=2,每 token 次数=2L

1.2 下界：为什么 2L⋅2NN−1​bh 不可改进#

命题：在"每层输入输出为完整隐藏维"的架构下（即不做序列/隐藏维并行），N 卡 TP 的前向每 token 每卡至少收 2L⋅NN−1​bh 个元素。

证明：考虑某一层的输出投影。列并行把 Wo​ 的输入维切成 N 份，rank i 算出 Yi​=Xi​Wo(i)​，最终 Y=∑i​Yi​ 必须是每个 rank 都持有的完整 b×h 张量（因为下一层的残差与 LN 需要它）。要算出 Y 的每个元素，rank i 必须知道其余 N−1 个 rank 的贡献 —— 即 (N−1)/N 的信息量。所以

Ri​≥NN−1​⋅bh(元素)每层 2 次全归约⟹Ri​≥2L⋅NN−1​bh

紧性：把"每层两次全归约"的下界加起来就是整模型的字节下界；环形 AllReduce 每次接收 2NN−1​bh 个元素（reduce-scatter 收 NN−1​bh、all-gather 再收 NN−1​bh），所以环形与下界只差一个常数因子 2、与 N 无关：

RTPper token, per rank​∈[下界2LNN−1​bhσ​​,环形实现4LNN−1​bhσ​​]

（σ 为每元素字节数。）下界与环形算法只差 2 倍，且这 2 倍对 N 是与 N 无关的常数 —— 所以：

"换更省带宽的 AllReduce"最多赢 2 倍；"换更少步数的 AllReduce"能赢 O(N/logN) 倍

这与上一节 2.2 的结论一致，但这里是从 TP 的结构直接推出来的，不依赖对通信库的假设。

1.3 数值账#

示例模型（L=32,h=4096、fp16、b=1）：

N 每 rank 接收（每 token） 每次 AllReduce 全组合计 每层总时间（环形）
2 8.0 KiB 8 KiB 16 KiB 20.0μs
4 12.0 KiB 12 KiB 48 KiB 60.1μs
8 14.0 KiB 14 KiB 112 KiB 140.1μs
16 15.0 KiB 15 KiB 240 KiB 300.1μs

两处要点：

  • 字节数趋于饱和（(N−1)/N→1），N 从 2 到 8 只涨 1.75 倍；
  • 但时间涨 7 倍（20→140μs）—— 因为步数 ∝N。

TP 的通信代价不是"字节"驱动的，是"步数"驱动的​

这解释了为什么"把两次 AllReduce 合并成一次"收益有限（字节减半、步数减半在 N 大时才是 2 倍），而"把 8 卡换成 4 卡"收益巨大（步数减半）。TP 越宽，边际成本越贵 —— 这条性质在训练里被"反向传播能把通信藏进计算"缓解，在 decode 里没有地方藏。

二、切法本身也会改变字节数#

2.1 五种切法在通信上的差别#

切法 切什么 每层通信 对 TPOT 的影响
列并行（QKV、MLP up/gate） 输出维 无（下游消费本地分片） —
行并行（Wo​、MLP down） 输入维 1 次 AllReduce ∝2LαN
头并行（注意力） 注意力头 无（若 Wo​ 仍行并行则合并进那次 AR） —
隐藏维并行（X 也切） 隐藏维 额外 AllGather/LN 通信 更差
序列并行（X 按 token 切） 序列维 LayerNorm/Dropout 处 AllGather 省激活显存，但推理无需存激活

为什么"头并行 + 行并行 Wo​"是最优组合：它让每层恰好两次 AllReduce，不多不少。任何额外的切法（比如把 LN 的输入也切了）都会引入第三次通信，因为 LN/residual 需要完整隐藏维。这就是 2.1 里"输入输出为完整隐藏维"这条不变式的价值 —— 它把"每层两次"从实现习惯变成了架构约束。

2.2 数值验证：列/行并行的切分是数值等价的#

这一点必须在代码里验一遍，因为它是"TP 不改变模型输出"这个承诺的全部依据（推理侧比训练侧更依赖它：训练错了 loss 会抖，推理错了用户直接看见）。第 2 节的代码用纯 Python 的矩阵切分验证 max∣YTP​−Ysingle​∣=0。

⚠️ 但"逐位相等"只在同一个求和顺序下成立。真实多卡里 AllReduce 的归约顺序（环形 vs 树形、chunk 顺序）与单卡的顺序不同，而浮点加法不满足结合律。本节代码实测的差异量级（H=64，batch=2）：

N |顺序归约 − 单卡| |成对归约 − 单卡| |顺序 − 成对| 相对值
2 3.5×10−18 3.5×10−18 0 0
4 3.5×10−18 3.5×10−18 3.5×10−18 1.7×10−16
8 3.5×10−18 3.5×10−18 3.5×10−18 1.7×10−16

读法有两处：

  1. 绝对值都在 10−18 量级（相对 10−16，即机器精度 ε），不是 10−7 那种量级 —— 所以"TP 是数值等价的"这句话在工程上是成立的，不需要为它辩护；
  2. N=2 时"顺序"与"成对"完全相同（差 0），因为两个数相加没有顺序自由度；N≥4 才出现差异。这解释了为什么在 N=2 的部署里看不到"换配置输出变了"，而 N=4 以上会看到 —— 它是组合自由度的问题，不是误差大小的问题。

这在训练里无关紧要，在推理里会表现为"换并行配置后同一 prompt 输出不同" —— 可复现性口径问题，不是 bug。要用贪心解码 + 固定并行配置才谈得上逐位复现（agent-ch4-l4 里把这件事叫"锁定外部输入"，这里是它的一个具体来源）。

2.3 KV cache 在 TP 下怎么分#

这是 TP 与推理特有的一笔账。KV 有两种分法：

按 KV 头分：KVper rank​=NKV​  (GQA 下 nkv​ 必须能被 N 整除)

按 token 分页分：每个 rank 只存一部分 token 的 KV，注意力时需 AllGather

按头分是默认选择，因为它不需要额外通信：rank i 只算自己那 nkv​/N 个头的注意力，输入 X 本来就是完整的（2.1 的不变式），输出经 Wo​ 行并行时那一次 AllReduce 已经把结果合拢了。按 token 分则每个 rank 缺别的 token 的 KV，注意力前必须 AllGather —— 在 decode 上是灾难（每 token 一次，s 越大越贵）。

推理侧的 KV 分片要沿「头」而不是沿「token」​

（沿 token 分片在训练里配合 Ring Attention 有价值，因为训练要省激活显存；推理的 KV 是要读的，不是要省的激活。）

三、TP 省的到底是什么：三个候选的定量筛选#

很多人把 TP 的收益笼统说成"算得快一倍"。准确的答案是依阶段而定，而且这个区分直接决定"TP 和低精度权重能不能叠加"。

3.1 三个候选#

候选 表达式（N 卡） N 从 1→2 的变化
权重访存 2Ψ/(NB) 4.382 ms → 2.191 ms
算力 2Ψb/(NC) 0.013 ms → 0.007 ms
KV 访存 KVB​b/B（不随 N 变，除非切 KV） 不变

3.2 判据：谁在瓶颈上#

TP 有效⟺Tmem​ 是瓶颈⟺I=ΨB​+KVB​2Ψb​<BC​

  • decode、b 小：I≈1≪330 → 访存瓶颈 → TP 省的是访存；
  • prefill、s 大：I 随 s 上升并越过 330 → 算力瓶颈 → TP 省的是算力；
  • b 很大（≳330）：即使 decode 也进入算力瓶颈 → TP 的收益从"访存"切到"算力"。

3.3 由此得出的两条可操作结论#

(a) TP 与低精度权重在 decode 下部分替代。 两者都压 ΨB​：

ΨB​=Ψ⋅σ,Tmem​=NBΨσ​

fp16 → int8（σ:2→1）与 N:1→2 对访存项的作用完全等价。而低精度的"代价"是精度损失（可量化评估）、TP 的代价是通信（cN，在关键路径上）。所以在 decode 下，先上 int8/fp8、再考虑 TP，通常更划算 —— 因为前者不引入 cN。

⚠️ 但低精度的收益有界：Tmem​ 不能低于 Tflop​（拐点），而 int4 会让反量化开销进入关键路径。两者的最优组合是"低精度把 Ψσ 压到拐点附近，TP 只用来补剩下的差距"。

(b) TP 在 prefill 与 decode 上的最优 N 不同。 同一次前向里两个阶段都发生，所以引擎必须选一个 N（权重切了就不能只对 decode 生效）。这是一个真实的取舍：

若 N 按 prefill 的最优取（更大），decode 的 TPOT 会变差 —— 反之亦然

工程上的常见处置是分块预填充（chunked prefill，第 2 章）：把 prefill 切成小块，让它与 decode 混在同一批里，于是两者共享一个 N，且这个 N 会被两类请求的混合比"投票"决定。

3.4 一个反直觉的定量结论：batch 可以替代 TP（在吞吐上）#

这是本节最重要的结论，也是"推理侧最优切法与训练不同"的最具体体现。

每 token 时间Ttoken​(N)=随 b 几乎不变NBΨB​+KV1​b​​​+随 b 微增2LTAR​(N,b)​​

关键：Ttoken​ 里没有 b 的线性项（在访存瓶颈区间内）。所以：

  • 单流延迟（1/Ttoken​）只由 N 决定 → 要降 TPOT 只能靠 TP；
  • 总吞吐 =b⋅Ttoken​1​ 随 b 线性上升 → 要提吞吐靠 batch。

数值对比（示例模型、单卡 vs TP）：

方案 每 token 时间 单流 tok/s 达到 2000 tok/s 所需并发 8 卡能提供
单卡 4.382 ms 228 b=9 228×8 = 1826（8 个副本）
TP=2（环形） 2.832 ms 353 b=6 353×4 = 1412（4 组）
TP=4（环形） 3.017 ms 331 b=7 331×2 = 662
TP=8（环形） 5.030 ms 199 b=11 199（1 组）

读法：

  • 只看吞吐，单卡 + 8 副本（1826 tok/s）胜过 TP=2 + 4 组（1412），更远胜 TP=8（199）；
  • 但要看 TTFT/TPOT 的分布：TP 组越大，单请求延迟越低。TP=2 的 2.832 ms/token 比单卡的 4.382 ms 低 35%；
  • 单卡的 1826 tok/s 是8 个独立请求的吞吐，TP=2 的 1412 是 4 组 × 353 —— 后者每组的 353 tok/s 里每个 token 的延迟更低（2.83 ms vs 4.38 ms）。

决策规则：如果 SLO 只看吞吐，TP 在 decode 上没有价值；如果 SLO 含单请求 TPOT 上界，TP 才必要​

这条规则解释了为什么离线批处理（跑数据集、离线生成）几乎从不用 TP，而在线交互（chat、语音）必须用。它们的 SLO 形状不同。

四、取舍与失效模式#

选择 收益 代价 什么时候变得不划算
加大 TP 降 TPOT（∝1/N） 每层 2 次 AR，时间 ∝N N>2N∗（时间账）
换树形/递归 AllReduce α 项从 O(N) 到 O(logN) 实现/拓扑限制，大消息收益趋同 消息 > 2 MB（带宽主导）
低精度权重 直接压 ΨB​，无关键路径代价 精度损失、反量化开销 进入算力瓶颈后收益消失
加副本（DP） 吞吐 ∝ 副本数，不动关键路径 显存翻倍、无单流收益 显存不够放副本的 KV
KV 按头分片 零额外通信，KV 显存 ∝1/N nkv​ 必须被 N 整除，GQA 下 N 受限 N>nkv​（如 GQA nkv​=8 时 N≤8）

⚠️ 最后一行是一个常被忽略的硬约束：GQA 模型 nkv​=8 时，按头分片最多支持 TP=8；要 TP=16 就必须按 token 分 KV（引入 AllGather）或复制 KV（显存不省）。这是"TP 上限 8"这条经验值的一个真实来源 —— 对 GQA 模型它比 α-β 账本更硬。

代码：TP 通信量账本 + 最优切法 + batch 替代效应#

脚本做四件事：(1) 把一层的切分与通信逐项数出来，验证"每层两次全归约"；(2) 用纯 Python 验证列/行并行的数值等价性（含归约顺序对逐位复现的影响）；(3) 算 TP 的字节下界与环形实现的差距；(4) 打印"吞吐替代表"，把 3.4 的结论算成数字。

"""
张量并行的通信量账本与 batch 替代效应（只用 Python 标准库）。

设计决策：
  1. 用手写矩阵切分验证数值等价，并**显式对比两种归约顺序**（顺序求和 vs 成对求和），
     把「TP 是数值等价的」与「逐位复现需要固定归约顺序」两件事分开说清（正文 2.2）。
  2. 通信量按「每 token 每 rank 接收字节」统计，因为这是下界的形式（正文 1.2）；
     同时打印「步数」，因为时间由步数而非字节驱动（正文 1.3）。
  3. 显式把「单流延迟」与「总吞吐」分开输出（正文 3.4）：这一处混淆是
     「TP 到底有没有用」这类争论的主要来源。
  4. KV 分片只算按头分（零通信）与按 token 分（每 token 一次 AllGather）两种，
     D=按 token 分在 decode 上的代价是本节要暴露的坑（正文 2.3）。
"""
import random
from math import ceil, log2

random.seed(7)


# ==================== (1) 一层 TP 的通信量逐项数 ====================
def layer_comm_bytes(L, H, N, batch=1, seq=1, dtype=2):
    """
    返回 (每 rank 每 token 接收字节, 每层全归约次数, 每次元素数, 环形步数/次)。
    口径：Megatron-LM —— MLP 输出投影 1 次 + 注意力输出投影 1 次。
    """
    elems = batch * seq * H
    ars = 2                                   # 每层 2 次
    per_ar_recv_elems = (N - 1) / N * elems   # 下界口径
    ring_recv_elems = 2 * (N - 1) / N * elems  # 环形实际接收
    steps = 2 * (N - 1)
    return (ring_recv_elems * dtype, ars, elems, steps)


def tp_bounds(L, H, N, batch=1, seq=1, dtype=2):
    """下界 vs 环形 vs 树形（每 token 每 rank 接收字节、步数）。"""
    elems = batch * seq * H
    lo = 2 * L * (N - 1) / N * elems * dtype
    ring_b = 2 * L * 2 * (N - 1) / N * elems * dtype
    tree_b = 2 * L * 2 * (N - 1) / N * elems * dtype
    return {"下界": lo, "环形字节": ring_b, "树形字节": tree_b,
            "环形步数": 2 * L * 2 * (N - 1),
            "树形步数": 2 * L * 2 * int(ceil(log2(N)))}


# ==================== (2) 切分的数值等价性 ====================
def matmul(A, B):
    n, k, m = len(A), len(B), len(B[0])
    return [[sum(A[i][t] * B[t][j] for t in range(k)) for j in range(m)]
            for i in range(n)]


def col_split(W, N):
    """列并行：把 W 的输出维切成 N 份。"""
    k, m = len(W), len(W[0])
    step = m // N
    return [ [row[j * step:(j + 1) * step] for row in W] for j in range(N) ]


def row_split(W, N):
    """行并行：把 W 的输入维切成 N 份。"""
    k = len(W)
    step = k // N
    return [ W[j * step:(j + 1) * step] for j in range(N) ]


def row_reduce(parts):
    """顺序归约：((p0+p1)+p2)+... —— 与环形 AllReduce 的累加顺序近似。"""
    out = [row[:] for row in parts[0]]
    for p in parts[1:]:
        for i in range(len(out)):
            for j in range(len(out[0])):
                out[i][j] += p[i][j]
    return out


def pairwise_reduce(parts):
    """成对归约：树形 AllReduce 的归约次序。"""
    cur = [[row[:] for row in p] for p in parts]
    while len(cur) > 1:
        nxt = []
        for i in range(0, len(cur) - 1, 2):
            a, b = cur[i], cur[i + 1]
            nxt.append([[a[r][c] + b[r][c] for c in range(len(a[0]))]
                        for r in range(len(a))])
        if len(cur) % 2:
            nxt.append(cur[-1])
        cur = nxt
    return cur[0]


def check_equivalence(H=64, N=4, batch=2):
    """手算一个小规模 TP 层：列并行 up → 逐元素激活 → 行并行 down → AllReduce。"""
    d_ff = H * 2
    X = [[random.gauss(0, 1) for _ in range(H)] for _ in range(batch)]
    W_up = [[random.gauss(0, 1 / H) for _ in range(d_ff)] for _ in range(H)]
    W_dn = [[random.gauss(0, 1 / d_ff) for _ in range(H)] for _ in range(d_ff)]

    ref = matmul([[max(0.0, v) for v in row] for row in matmul(X, W_up)], W_dn)

    up_c, dn_r = col_split(W_up, N), row_split(W_dn, N)
    partials = []
    for r in range(N):
        h = [[max(0.0, v) for v in row] for row in matmul(X, up_c[r])]
        partials.append(matmul(h, dn_r[r]))

    seq_r = row_reduce(partials)
    pair_r = pairwise_reduce(partials)
    err = lambda A, B: max(abs(A[i][j] - B[i][j])
                           for i in range(len(A)) for j in range(len(A[0])))
    return err(seq_r, ref), err(pair_r, ref), err(seq_r, pair_r)


# ==================== (3) 时间账 ====================
def ar_time(N, n_bytes, alpha, beta, algo="ring"):
    steps = 2 * (N - 1) if algo == "ring" else 2 * int(ceil(log2(N)))
    return steps * alpha + 2 * (N - 1) / N * n_bytes / beta


def token_time(params_bytes, kv_bytes, L, H, N, batch, hbm_bw, flops,
               alpha, beta, algo="ring"):
    t_mem = (params_bytes / N + kv_bytes * batch) / hbm_bw
    t_flop = 2 * (params_bytes / 2) * batch / (N * flops)
    n_bytes = batch * H * 2
    t_comm = L * 2 * ar_time(N, n_bytes, alpha, beta, algo)
    return max(t_mem, t_flop) + t_comm, t_mem, t_flop, t_comm

五处关键设计决策：

  1. layer_comm_bytes 返回四元组（接收字节、次数、每次元素数、步数）而不是一个字节数。因为时间由步数决定、下界由字节决定，把两者压成一个数字就丢掉了本节的核心区分（正文 1.3）。
  2. row_reduce 与 pairwise_reduce 都实现，并打印它们之间的差。这是把"TP 是数值等价的"与"逐位可复现需要固定归约顺序"分开的唯一办法 —— 只说前者会让读者在换并行配置后看到输出变化时误判为 bug。
  3. col_split / row_split 用真实的下标切片，不用任何库。这样"列并行输出维减半、行并行输入维减半"在代码里是可见的，而不是一句断言。
  4. token_time 同时返回 Tmem​,Tflop​,Tcomm​ 三项，让"谁在瓶颈上"随时可查。这也是正文第三节"TP 省的到底是什么"的可执行版本。
  5. 第 (4) 段的输出按"组数 × 单流"而不是"单流"排序。这是本节的结论在代码里的落点：同一个 N 在"看延迟"和"看吞吐"两种口径下的评价可以完全相反。

三处值得单独读的数字：

  • 第 (2) 段的"环形/下界"整列都是 2.0 —— 这是"下界紧、实现与它只差常数"的直接证据。看到任何"我们的 AllReduce 比 NCCL 快 5 倍"的说法，都应该先问"在哪个消息大小区间、相对哪条下界"。
  • 第 (4) 段 TP=4 的合计 663 < TP=2 的 1412 < 单卡的 1825 —— "拆得越多总吞吐越低"在这里被算成了确定数字。这不是反直觉，而是 cN 项的直接后果；直觉之所以相反，是因为人们默认"8 张卡 = 8 倍算力"，而 decode 的瓶颈从来不是算力。
  • 第 (5) 段拐点在 b≈330 —— 与上一节算出的 roofline 拐点 C/B=330 完全一致。这不是巧合：b 就是 decode 的算术强度。所以在 b<330 的区间谈"TP 省算力"是错的，那段区间省的一直是访存。

小结#

  • TP 每层恰好两次全归约，每次 b⋅s⋅h 个元素。这不是实现习惯，而是"残差与 LayerNorm 需要完整隐藏维"这个数学要求的推论。每 token 共 2L 次。
  • 字节下界是 NN−1​bh /次，环形是 2NN−1​bh /次 —— 只差常数 2 倍，与 N 无关。所以"换更省带宽的 AllReduce"上限是 2 倍；真正的杠杆是步数：环形 2(N−1) vs 树形 2⌈log2​N⌉。
  • TP 的通信代价是步数驱动的，不是字节驱动的：N 从 2 到 8，字节只涨 1.75 倍，每层时间涨 7 倍（20→140μs）。TP 越宽，边际成本越贵。
  • 切法本身改变通信量：头并行 + 行并行 Wo​ 让每层恰好两次；任何把 LN/residual 的输入也切了的做法都会引入第三次通信。"每层两次"是最优切法的标志。
  • TP 是数值等价的（舍入量级），但逐位复现需要固定归约顺序（顺序 vs 成对求和会有差异）。换并行配置后输出最后几位变化是预期行为，不是 bug。
  • KV 必须沿"头"分片，不能沿"token"分片：按头分零额外通信；按 token 分需要每 token 一次 AllGather（对 s 敏感，decode 上是灾难）。GQA nkv​=8 时按头分片最多支持 TP=8 —— 这是"TP 上限 8"的一个比 α-β 账本更硬的真来源。
  • TP 省的是"每 token 的权重访存"（decode）或"算力"（prefill / 大 batch），判据是算术强度 I=2Ψb/(ΨB​+KVB​) 是否低于拐点 C/B。由此推出：decode 下 int8/fp8 与 TP 部分替代，而低精度不引入关键路径通信，所以应先上低精度再考虑 TP。
  • 最反直觉的一条：Ttoken​(N) 里没有 b 的线性项，所以单流延迟只由 N 决定，而总吞吐 ∝b。于是"单卡 × 8 副本"（1826 tok/s）在吞吐上胜过"TP=2 × 4 组"（1412）、更远胜 "TP=8"（199）。
  • 决策规则：SLO 只看吞吐 → decode 上 TP 没有价值（用 batch 与副本）；SLO 含单请求 TPOT 上界 → TP 才必要。 这解释了离线批处理几乎不用 TP、在线交互必须用的现象。
  • 一句话：TP 是用"每 token 每层两次、步数 ∝N 的全归约"去买"权重访存 ∝1/N"；买之前先确认瓶颈真的在访存，且 batch 已经用尽。

下一节：TP 把层内切开。但当模型大到"一层的权重也放不下"、或需要跨节点时，另一条路是把层分段放到不同卡上 —— 流水线并行。它的代价与 TP 完全不同：不是通信，而是流水线气泡。而在推理侧（没有反向传播）气泡的形状和训练时不一样，它直接加在 TPOT 上。
