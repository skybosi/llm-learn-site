优化的安全性：什么时候"等价变换"其实不等价#

前三课一直在改写图：折叠常量、换 layout、复用内存。每一步都写着"等价"，但"等价"到底指什么，决定了哪些改写合法。同一个 (x+y)+z，在实数域等于 x+(y+z)，在 float32 上有 9.78% 的随机输入组合给出不同结果；同一个 x*0，x 有限时等于 0，x 是 NaN 时等于 NaN。这一课把"等价"拆成可判定的层级，给出四条改写规则的实测反例率，并给出编译器真正依赖的那份东西——语义契约。

一、概念讲解#

1. "等价"有三个层级#

层级 含义 允许的改写 谁需要
位一致（bit-exact） 逐位相同 恒等式、常量折叠（同 dtype）、布局视图、内存复用 复现性要求高的训练/科学计算
数值近似（within tolerance） 差在容差内 重排归约树、融合、用 FMA 替乘加、fast-math 大多数推理与训练
统计等价 分布/最终指标不变 采样、随机丢弃 少见的宽松场景

没有普适的"正确"，只有"相对契约的正确"。编译器优化的每一步都必须问：这一步在哪个层级上成立？

2. 七类真实反例（附实测）#

前四项是本课程序在 20000 组 float32 随机输入上跑出来的不等价比例：

改写 不等价比例 最大绝对差 原因
(x+z)-z → x 48.63% 8.0 消去律在有限精度下失效
(x*y)*z → x*(y*z) 35.24% 1.1e15 中间量溢出/下溢方向不同
(x+y)+z → x+(y+z) 9.78% 8.0 结合律不成立
x*0 → +0（丢符号） 49.98% 0 一半输入产生 -0.0，符号可被后续 1/x 观察到
x*0 → ±0（保号） 0% 0 这才是正确写法

剩下三类要单独看：

  • NaN / Inf：nan*0.0 = nan、inf*0.0 = nan。想消掉 x*0→0 就必须能证明 x 有限。
  • 大数吞小数：float32 下 1e16 + 1.0 还是 1e16——加法结果与左操作数逐位相同。
  • 归约顺序：8 个 float32 的顺序累加与配对累加分别是 6.900000215637192e-08 与 6.899999505094456e-08。融合与并行归约必然改这条链的形状，所以任何声称"融合后位一致"的说法都不成立。
  • 整数与 dtype：int8 下 100+100 回绕成 -56；-7/2 在向下取整与向零取整下是 -4 与 -3；float32 表示不了 2^24+1。

3. 契约：把"允许什么"写下来#

主流编译器的做法都是把一个显式的数值契约暴露给用户，而不是偷偷选一种：

  • XLA 的语义由官方文档定义（含各算子对 NaN/Inf 与精度的规定），后端选择是否可以重排由编译选项控制。
  • torch.compile / TorchInductor 默认在"保持可接受的数值行为"的前提下做图改写；具体策略随版本演进，以官方文档为准，本课不写死版本号。
  • TVM 把常量折叠与化简作为独立 pass，是否重排归约取决于 pass 的规则集与目标后端。

写进契约的典型条款：是否允许重排归约、是否允许用 FMA、是否允许 ÷c→×(1/c)、是否要求 NaN/Inf 语义、容差是多少。契约之外的一切"优化"都是 bug。

4. 守卫：把"条件"变成可检查的 IR#

知道"什么条件下成立"之后，编译器把它变成守卫（guard）：x*0→0 加一条"x 有限"的假设；÷c→×(1/c) 加一条"c ≠ 0"；动态 shape 加一条 shape 断言（第 2 章讲过 guard 与重编译的关系）。守卫有两种命运：静态证得（编译期消掉）或运行时检查（不合就回退）。

5. 验收：三重检查缺一不可#

一次改写要过三关：

  1. 类型/形状：类型推导与形状校验（图 IR 自带，pass 必须维护）；
  2. 数值：同一组输入跑"改前改后"两条路，逐元素对拍——本课程序用的就是这一手；
  3. 端到端：真实模型上跑测试集，确认精度指标没有回归。

第 2 关是唯一能在没有 GPU、没有大模型时完成的，也是本课的全部内容：对拍不是可选项。

6. 常见坑#

  • 只在"典型输入"上对拍：随机测试的价值恰恰在极端量级（1e16、1e-30、NaN）。
  • 用 == 比 NaN：NaN ≠ NaN，必须显式判 isnan，否则"全部通过"是假象。
  • 忘了负数零：math.copysign 才能区分 -0.0 与 +0.0，这是本课发现 49.98% 不等价的唯一原因。
  • 把"默认设置"当"保证"：框架的默认数值行为会随版本变化，落进契约里的才算数。

二、可运行代码示例#

下面这段纯 Python（标准库 struct / math / random）把上面所有反例变成可执行的判定：五条改写规则各跑 20000 组随机 float32 输入、特殊值检查、归约顺序对照、整数/dtype 边界，最后打印一张判定表。

# ---- 第 4 课示例：等价性判定 —— 四条改写规则在 float32 上的实测（纯 Python + struct）----
# f32(x) 用 struct 做真正的 4 字节舍入，模拟"目标 dtype 是 float32"
import struct, math, random

def f32(x):
    try:
        return struct.unpack('f', struct.pack('f', x))[0]
    except OverflowError:
        return math.inf if x > 0 else -math.inf

def same(a, b):
    """浮点等价：NaN 只与 NaN 等价；-0.0 与 0.0 按 IEEE 不等价（符号可被观察）。"""
    if isinstance(a, float) and isinstance(b, float):
        if math.isnan(a) or math.isnan(b): return math.isnan(a) and math.isnan(b)
        if a == 0.0 and b == 0.0: return math.copysign(1, a) == math.copysign(1, b)
    return a == b

# 每条规则：给 (x, y, z) 返回 (原始结果, 优化后的结果)；优化必须判恒等
def rule_add_zero(x, y, z):  return f32(f32(x + z) - z), x           # x+z-z 想换成 x
def rule_swap_add(x, y, z):  return f32(f32(x + y) + z), f32(x + f32(y + z))
def rule_swap_mul(x, y, z):  return f32(f32(x * y) * z), f32(x * f32(y * z))
def rule_mul_zero(x, y, z):  return f32(x * 0.0), math.copysign(0.0, x)   # 保留符号的正确版本
def rule_mul_zero_naive(x, y, z): return f32(x * 0.0), 0.0                # 直接写 0.0 的版本

print('=== 1. 改写规则的随机对照（20000 组 float32 输入，量级 1e-8 ~ 1e8）===')
random.seed(11)
def rnd():
    return f32(random.choice([-1, 1]) * random.random() * 10 ** random.randint(-8, 8))
vals = [(rnd(), rnd(), rnd()) for _ in range(20000)]
for name, fn in (('(x+z)-z → x', rule_add_zero),
                 ('(x+y)+z → x+(y+z)', rule_swap_add),
                 ('(x*y)*z → x*(y*z)', rule_swap_mul),
                 ('x*0 → ±0（保号）', rule_mul_zero),
                 ('x*0 → +0（不保号）', rule_mul_zero_naive)):
    bad, worst = 0, 0.0
    for x, y, z in vals:
        got, want = fn(x, y, z)
        if not same(got, want):
            bad += 1
            if math.isfinite(got) and math.isfinite(want):
                worst = max(worst, abs(got - want))
    print(f'  {name:<20} 不等价 {bad:>6}/{len(vals)} 组（{100 * bad / len(vals):5.2f}%）'
          f'  最大绝对差 {worst:.3e}')

print('\n=== 2. 特殊值：NaN / Inf / 溢出 / 大数吞小数 ===')
specials = [('nan', float('nan')), ('+inf', float('inf')), ('-inf', float('-inf'))]
print(f'  nan*0.0 = {f32(float("nan") * 0.0)!r}   inf*0.0 = {f32(float("inf") * 0.0)!r}'
      f'   (-inf)*0.0 = {f32(float("-inf") * 0.0)!r}   → "x*0→0" 前提是 x 有限')
a, b = f32(1e16), f32(1.0)
print(f'  a+b = {f32(a + b)!r}（与 a 相同：1.0 小于 a 的 ULP，被吞掉）')
x16, y1, z16 = f32(1e16), f32(1.0), f32(-1e16)
print(f'  (x+y)+z = {f32(f32(x16 + y1) + z16)!r}   x+(y+z) = {f32(x16 + f32(y1 + z16))!r}'
      f'   ← 这一组恰好都是 0.0；真正的差异在随机测试里（9.78% 不等价）')
p, q = f32(1e20), f32(1e-30)
print(f'  (p*q)*q = {f32(f32(p * q) * q)!r}   p*(q*q) = {f32(p * f32(q * q))!r}'
      f'   ← 下溢/溢出方向不同')

print('\n=== 3. 归约顺序：顺序累加 vs 配对累加（float32）===')
xs = [f32(v) for v in (7e-9, 1e-8, 5e-9, 1e-8, 1e-8, 1e-8, 7e-9, 1e-8)]
seq = 0.0
for v in xs: seq = f32(seq + v)
def tree(v):
    if len(v) == 1: return v[0]
    m = len(v) // 2
    return f32(tree(v[:m]) + tree(v[m:]))
print(f'  顺序累加 = {seq!r}')
print(f'  配对累加 = {tree(xs)!r}')
print(f'  差 = {seq - tree(xs):.3e}   → 融合/并行归约会改这条链的形状，必须写进数值契约')

print('\n=== 4. 整数与 dtype：溢出、取整、收窄 ===')
i8 = lambda v: ((v + 128) % 256) - 128
print(f'  int8 100+100 = {i8(200)}（回绕）   Python 大整数 = {200}')
print(f'  -7 整除：向下取整 {(-7) // 2}（Python/floor）  向零取整 {int(-7 / 2)}（C/trunc）')
print(f'  float32 表示 2^24+1 = {f32(16777217.0)!r}（丢掉最低位）')

print('\n=== 5. 可执行的等价性判定表 ===')
rules = [('x+0 → x', '浮点', '成立（含 NaN/Inf；但 -0.0+0.0=+0.0 会改符号，按 strict 语义要保号）'),
         ('x*1 → x', '浮点', '成立（含 NaN/Inf）'),
         ('x*0 → ±0（保号）', '浮点', '有限值上成立（含 -0 符号）；NaN/Inf 上应为 NaN，不能折'),
         ('x*0 → +0（丢符号）', '浮点', '不成立：随机测试里约一半输入是 -0.0，符号可被后续 1/x 观察到'),
         ('(x+y)+z → x+(y+z)', '浮点', '不成立（随机测试 20000 组里有不等价）'),
         ('(x*y)*z → x*(y*z)', '浮点', '不成立（同上，且有下溢方向差异）'),
         ('(x+z)-z → x', '浮点', '不成立（消去律在有限精度下失效）'),
         ('归约改树形/并行', '浮点', '不位一致，需数值契约声明容差'),
         ('100+100 → 200', 'int8', '不成立（回绕成 -56）'),
         ('-7/2 → 结果', 'int', '随语言（floor -4 / trunc -3）'),
         ('f64 常量降为 f32', 'dtype', '先确认可表示（2^24+1 → 16777216.0）')]
for i, (r, k, v) in enumerate(rules, 1):
    print(f'  {i:>2}. {r:<20} [{k:<4}] {v}')

  x*0 → +0（不保号）        不等价   9996/20000 组（49.98%）  最大绝对差 0.000e+00

=== 5. 可执行的等价性判定表 ===
   1. x+0 → x              [浮点  ] 成立（含 NaN/Inf；但 -0.0+0.0=+0.0 会改符号，按 strict 语义要保号）
   2. x*1 → x              [浮点  ] 成立（含 NaN/Inf）
   3. x*0 → ±0（保号）         [浮点  ] 有限值上成立（含 -0 符号）；NaN/Inf 上应为 NaN，不能折
   4. x*0 → +0（丢符号）        [浮点  ] 不成立：随机测试里约一半输入是 -0.0，符号可被后续 1/x 观察到
   5. (x+y)+z → x+(y+z)    [浮点  ] 不成立（随机测试 20000 组里有不等价）
   6. (x*y)*z → x*(y*z)    [浮点  ] 不成立（同上，且有下溢方向差异）
   7. (x+z)-z → x          [浮点  ] 不成立（消去律在有限精度下失效）
   8. 归约改树形/并行             [浮点  ] 不位一致，需数值契约声明容差
   9. 100+100 → 200        [int8] 不成立（回绕成 -56）
  10. -7/2 → 结果            [int ] 随语言（floor -4 / trunc -3）
  11. f64 常量降为 f32         [dtype] 先确认可表示（2^24+1 → 16777216.0）

四处可核对的结论：不等价是常态不是例外（最高 48.63%，四条"看起来显然"的改写里三条有反例）；符号与 NaN 是规则的一部分（保号版本 0% 失败、丢符号版本 49.98% 失败，差别只在 copysign）；归约链的形状本身就是语义（顺序与配对累加差 7.105e-15，融合必然引入这一项）；整数与 dtype 各有一类边界（回绕、取整方向、2^24+1 不可表示）。
