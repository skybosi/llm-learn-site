思维链#

面对多步推理问题，让模型"直接蹦出答案"常常翻车；但只要诱导它把中间推理步骤写出来，正确率就大幅提升。这个技巧叫思维链（Chain-of-Thought, CoT）。本课讲清 CoT 为什么有效、zero-shot 与 few-shot 两种用法，以及在此基础上衍生出的自一致性（self-consistency）。

一、概念讲解#

1. 直接回答的困境#

考虑问题："小明有 12 颗糖，给了小红 5 颗，又买了 9 颗，还剩几颗？"模型直接算 12-5+9 也许能碰对，但换成一个需要四五步的题，一次生成的每个 token 都可能出错，错误还会累积。语言模型是逐 token 自回归的，它没有一个"草稿纸"来存放中间结果——除非你让它把中间过程说出来。

2. 什么是思维链#

思维链（Chain-of-Thought）就是让模型在给出最终答案前，先输出一系列中间推理步骤，就像把草稿纸写进文本：

问题：小明有 12 颗糖，给了小红 5 颗，又买了 9 颗，还剩几颗？
推理：一开始有 12 颗；给了 5 颗后剩 12−5=7 颗；又买 9 颗后共 7+9=16 颗。
答案：16 颗

因为每一步都变成了"下一个 token 的强条件"，模型被迫把复杂问题分解成一个个简单、局部可验证的步骤，正确率因此显著上升。

3. 两种用法#

  • few-shot CoT：在示例里不仅给最终答案，还给完整推理过程，让模型模仿"先推理后作答"的格式（Wei et al., 2022）。
  • zero-shot CoT：不加示例，只在问题后追加一句魔法咒语 "Let's think step by step"（让我们一步步思考），就能诱导模型自发展开推理（Kojima et al., 2022）。成本极低，效果却常常立竿见影。

4. 自一致性（self-consistency）#

思维链让单次推理更可靠，但单条推理路径仍可能"过程对、结论错"或"过程错、结论碰对"。自一致性的思路是：多采样几条推理路径，对最终答案做多数投票。推理有多条路，但正确答案通常只有一个——投票能显著提升最终准确率。

5. 局限与注意#

CoT 不是银弹：模型可能编造看起来合理但错误的推理（这和第 6 章的幻觉直接相关）；对于模型本身不会的领域知识，再长的思维链也无济于事；而且长推理消耗更多 token、更慢。把 CoT 与"验证、外部工具、检索"结合，才是更稳健的做法。

二、可运行示例#

下面用一个可计算的算术 mock，对比"直接作答"与"思维链分解"，并演示自一致性的多数投票。

import re

def solve_direct(problem):
    """模拟'直接作答'：试图从一句话里一次性算结果，容易出错。"""
    nums = list(map(int, re.findall(r"\d+", problem)))
    ops = re.findall(r"[+\-*/]", problem)
    # 只做粗略匹配：把找到的数字和运算符从左到右硬算（可能对不上步骤）
    if not nums:
        return None
    result = nums[0]
    for i, op in enumerate(ops[:len(nums) - 1]):
        nxt = nums[i + 1]
        result = {"+": result + nxt, "-": result - nxt,
                  "*": result * nxt, "/": result / nxt}[op]
    return result

def solve_cot(problem):
    """模拟'思维链'：把问题拆成有序步骤，每步打印中间结果，再汇总。"""
    start = int(re.search(r"有\s*(\d+)", problem).group(1))   # 初始数量
    total = start
    print("  初始：", total)
    # 依次找出 "动作 + 数字"：给了/花了 为支出，买了/赚了 为收入
    for verb, num in re.findall(r"(给了|买了|花了|赚了|买)\s*(\d+)", problem):
        num = int(num)
        if verb in ("给了", "花了"):          # 支出
            total -= num
            print(f"  {verb} {num}，剩余 {total}")
        else:                                  # 买了 / 赚了 -> 收入
            total += num
            print(f"  {verb} {num}，现有 {total}")
    return total

problem = "小明有 12 颗糖，给了 5 颗，买了 9 颗"

print("【直接作答】", solve_direct(problem))   # 可能算错或对不上
print("【思维链】")
print("  最终答案：", solve_cot(problem))

# —— 自一致性：多次采样不同推理路径，对答案做多数投票 ——
import collections
votes = [16, 16, 18, 16, 14]        # 5 次采样得到的候选答案（示意）
winner, count = collections.Counter(votes).most_common(1)[0]
print("【自一致性】各路径答案:", votes, "→ 多数投票:", winner, f"({count} 票)")

solve_cot 把"给了/买了"这类动作逐一拆成可打印的中间步骤，任何一步算错都能被定位——这正是思维链"分解复杂问题"的价值；最后的多票投票则演示了自一致性如何把少数错误路径"稀释"掉。

三、练习#

  1. 手写思维链：为"小王有 20 元，买书花 8 元，妈妈又给 15 元，再买笔花 6 元，还剩多少？"写一条完整的 few-shot 思维链示例（含中间步骤）。
  2. 对比 direct vs CoT：把 solve_cot 扩展支持 * 和 /，并构造一个"直接作答会错、思维链才对"的题目，说明为什么分解有效。
  3. 实现自一致性：修改示例，让 votes 来自 solve_cot 的多次运行（可给中间步骤加入随机扰动模拟"不同路径"），再投票，观察多数投票是否更稳。
  4. 思考零样本咒语：为什么一句"让我们一步步思考"就能诱发思维链？它改变了模型续写时的什么条件分布？
  5. 思考局限：给出一个"模型把推理写得很漂亮、但结论是错的"的案例，并讨论如何用外部验证（计算器、检索）来纠错。
