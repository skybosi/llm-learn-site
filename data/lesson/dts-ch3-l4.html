多卡为何不线性：带宽、延迟、同步三处找原因#

256 张卡不会快 256 倍。可运行的模型里：单卡每步 2000 ms、1 GiB 梯度、β 取跨机 rail 口的 50 GB/s、通信完全不重叠时，8 卡扩展效率 86.9%、64 卡 42.1%、256 卡只剩 14.7%；而把 90% 的通信藏进计算之后，256 卡还能保住 63.3%。差出来的部分不是"机器不行"，而是三本账：带宽、延迟、同步。本课把三本账都写成能跑的数。

一、概念讲解#

1. 先把"线性"定义清楚#

扩展效率（scaling efficiency）E(N)=N⋅TN​T1​​：理想线性时 TN​=T1​/N，E=1。要注意两种口径：

  • 强扩展（strong scaling）：问题规模固定，加卡是为了更快。此时每卡计算量随 N 反比下降，通信量几乎不变——通信占比必然上升，效率下降是数学结果。
  • 弱扩展（weak scaling）：每卡的问题规模固定，加卡是为了算更大的问题。此时计算量随 N 增长，通信占比稳定，效率曲线好看得多。

本课用强扩展（1 GiB 梯度固定、单卡每步 2000 ms），因为它才是"训练大模型时加卡"的真实场景。示例 1 的 [A] 就是它的完整曲线：

N 每步 ms 理想 ms 扩展效率
1 2000.00 2000.00 100.0%
8 287.65 250.00 86.9%
32 104.42 62.50 59.9%
64 74.16 31.25 42.1%
256 53.14 7.81 14.7%

2. 带宽账：有一道与卡数无关的墙#

数据并行每步做一次梯度 AllReduce。ring 的账：每个 rank 总搬运约 2S，带宽项 p2(p−1)​⋅βS​≈β2S​，延迟项 2(p−1)α：

Tcomm​(N)≈与 N 无关β2S​​​+随 N 线性2(N−1)α​​

第一项就是那道墙。示例 2 把 1 GiB 在不同 β 下的 2S/β 列出来：

β 2S/β（1 GiB 梯度）
450 GB/s（NVLink） 4.77 ms
100 GB/s 21.47 ms
50 GB/s（单口 NDR） 42.95 ms
25 GB/s 85.90 ms
12.5 GB/s 171.80 ms

墙的物理含义很直接：不管有多少张卡，梯度总得整个搬一遍。所以强扩展下，计算项 T1​/N 一直缩小，通信项却收敛到 42.95 ms——本例两者在 N≈47（约 6 台 8 卡机）相交：再往前加卡，每步时间几乎只由 AllReduce 决定。这就是"再加一批卡却不涨"的算术原因：不是并行不够，是每步被通信下限卡住。

3. 延迟账：2(N−1) 次固定成本#

第二项 2(N−1)α 随 N 线性增长，但绝对值常常不大：N=256、α=5 μs 时是 2.55 ms，只占通信的 5% 出头。它会反超的场合很具体：

  • 消息变小：梯度分桶太小、或张量并行把每层都切成小包，2S/β 变小而 2(N−1)α 不变，延迟就成了主角。
  • 步数变多：流水线并行的每个 micro-batch、专家并行的 all-to-all，都是"小消息 × 多次数"。

这正是第 2 章算法选择的落点：小消息换 tree / recursive-doubling 降步数，大消息用 ring 保带宽。

4. 同步账：整步时间取 max，不取平均#

集合通信是同步点：所有 rank 必须到齐，于是每步时间由最慢的 rank决定，而不是平均值。示例 3 用蒙特卡洛（每步每 rank 用时服从正态分布，整步取最大值，1000 步、固定随机种子）区分了两种情况：

N 抖动 0.5% 抖动 2% 抖动 5%
8 99.3% 97.2% 93.4%
256 98.6% 94.6% 87.6%
4096 98.2% 93.2% 84.6%

独立抖动只被"极值统计"温和地惩罚：抖动 5% 时 N 从 8 涨到 4096，效率从 93.4% 掉到 84.6%，几乎没有额外恶化。但相关抖动（示例 4：某个节点一直慢 r）是另一回事——不重叠时整步时间直接等于它的时间，效率上限就是 1/(1+r)：慢 5% → 95.2%，慢 20% → 83.3%。所以"慢节点"要比"抖动"重视得多，这也是多机多卡排障里最值钱的一项技能。

5. 重叠：唯一能改墙的办法#

通信与计算能不能并行，决定你是否真的付那 42.95 ms。示例 1 的 [B] 取重叠率 0.9（10% 的通信仍露出）后：

N 不重叠 90% 重叠
8 86.9% 98.5%
64 42.1% 87.9%
256 14.7% 63.3%

机制是反向传播里边算边发：梯度按桶凑够大小就发一次 AllReduce，并排在与计算不同的流上（PyTorch DDP 的梯度分桶就是干这件事）。但要注意两点：

  • 重叠只藏时间，不改墙：前提是"该步通信量 < 该步计算时间"。N=256 时计算仅 7.81 ms、通信 45.3 ms，再完美的重叠也藏不住。
  • 重叠会争资源：通信内核占 SM、HBM 带宽与 PCIe，计算会因此变慢，实践中重叠率很少到 100%。

6. 常见坑#

  • 只报加速比、不报 batch/LR：卡数一多，全局 batch 变大，收敛变差，看起来"加卡没用"，其实是超参没跟着调。
  • 用单卡时间线性外推：漏掉固定开销、同步与通信墙。
  • 只看平均吞吐：不看最慢 rank，就看不到相关慢节点。
  • 以为"重叠了通信就免费"：重叠只是把通信藏进计算，资源仍在竞争。
  • 不管 β 是怎么来的：8 张卡共享 2 条 rail 口时，β 是分摊后的值，曲线会比示例难看得多。

7. 这一课到哪里为止#

到这里，第 3 章的三层链路、跨机路径、拓扑分层与三本账都齐了。但"谁来选算法、谁来探测拓扑、谁来把重叠做实"还没有答案——那是第 4 章 NCCL 工程的内容。

二、可运行代码示例#

四段纯 Python：强扩展曲线与重叠收益、通信墙、独立抖动蒙特卡洛、相关慢节点。

import random

# ===== 示例 1：数据并行的每步时间与扩展效率 T(N) = T1/N + (1-o)·T_comm(N) + T_sync =====
def step_ms(N, compute1_ms, grad_mib, alpha_us, beta_gbps, overlap=0.0, sync_ms=0.0):
    """每步时间 = 计算/N + (1-重叠率)·通信 + 同步。
    ring AllReduce 通信 = 2(N-1)·α + 2(N-1)/N · S/β（S 是总梯度字节数，β 是单向带宽）。"""
    comp = compute1_ms / N                                          # 计算随卡数摊薄
    lat = 2 * (N - 1) * alpha_us                                    # 延迟项随步数线性涨
    bw = 2 * (N - 1) / N * grad_mib * 2**20 / (beta_gbps * 1e9) * 1e6
    comm = (lat + bw) / 1e3
    return comp + (1.0 - overlap) * comm + sync_ms


def table(Ns, compute1_ms, grad_mib, alpha_us, beta_gbps, overlap=0.0, sync_ms=0.0):
    base = step_ms(1, compute1_ms, grad_mib, alpha_us, beta_gbps, overlap, sync_ms)
    print(f"  {'N':>5} {'每步 ms':>10} {'理想 ms':>10} {'扩展效率':>9}")
    for N in Ns:
        t = step_ms(N, compute1_ms, grad_mib, alpha_us, beta_gbps, overlap, sync_ms)
        print(f"  {N:>5} {t:>10.2f} {base / N:>10.2f} {base / (N * t):>8.1%}")


Ns = [1, 2, 4, 8, 16, 32, 64, 128, 256]
print("单卡每步 2000 ms、1 GiB 梯度、α=5 μs、β=50 GB/s（跨机 rail NIC）：")
print(" [A] 完全不重叠：")
table(Ns, 2000.0, 1024.0, 5.0, 50.0, overlap=0.0)
print(" [B] 90% 通信藏进计算：")
table(Ns, 2000.0, 1024.0, 5.0, 50.0, overlap=0.9)


# ===== 示例 2：通信墙 2S/β —— 与卡数无关的那道下限 =====
print("\n1 GiB 梯度 ring AllReduce 的带宽下限 2S/β（每步，与 N 无关）：")
for beta in (450.0, 100.0, 50.0, 25.0, 12.5):
    print(f"  β={beta:6.1f} GB/s → {2 * 2**30 / (beta * 1e9) * 1e3:8.2f} ms")


# ===== 示例 3：同步代价 —— 每步 t = max(各 rank)，慢的那个决定全队 =====
def straggler(N, mu_ms, rel_sigma, steps=1000, seed=0):
    """蒙特卡洛：每步每个 rank 用时 ~ N(mu, σ)，整步时间 = 最大值。返回 (每步 ms, 相对效率)。"""
    rng = random.Random(seed)
    sigma = mu_ms * rel_sigma
    total = sum(max(rng.gauss(mu_ms, sigma) for _ in range(N)) for _ in range(steps))
    return total / steps, mu_ms / (total / steps)


print("\n独立抖动对效率的影响（每步标称 100 ms、1000 步、固定随机种子）：")
print(f"  {'N':>5} {'抖动 0.5%':>20} {'抖动 2%':>20} {'抖动 5%':>20}")
for N in (8, 64, 256, 1024, 4096):
    cells = []
    for rel in (0.005, 0.02, 0.05):
        t, eff = straggler(N, 100.0, rel)
        cells.append(f"{t:6.2f} ms / {eff:5.1%}")
    print(f"  {N:>5} " + " ".join(f"{c:>20}" for c in cells))

# ===== 示例 4：相关抖动（同一个节点一直慢）—— 效率被最慢的那个直接打折 =====
print("\n相关慢节点：某节点每步稳定慢 r，不重叠时整步时间就是它的时间：")
for r in (0.01, 0.05, 0.20):
    print(f"  慢 {r:>4.0%} → 扩展效率上限 {1 / (1 + r):6.1%}")
