正则与有限自动机：为什么词法器可以自动生成#

上一课那个 100 行的扫描器，换成 C 语言再加 40 个关键字、十几条运算符规则，scan_token 就会膨胀成一个没人敢改的分支迷宫——每加一个运算符都得重新审视所有前瞻分支。但词法分析器早就可以从规则自动生成：Lex/Flex、JavaCC、ANTLR 的词法部分都是这么做的，输入是几十条正则，输出是一份状态转移表。这不是黑魔法，它的数学基础就是这一课要拆开的那条链：正则 → NFA → DFA → 表驱动的循环。

一、概念讲解#

1. 三类规则，三种能力#

用 Kleene 在 1956 年提出的三个算子（连接、或 |、闭包 *）拼出来的表达式叫正则表达式（regular expression）。它和有限自动机（finite automaton，只有有限个状态 + 状态转移的机器）描述的恰恰是同一类语言：

规则 例子 能不能用有限状态机描述
标识符 [a-zA-Z_][a-zA-Z0-9_]* 能（自环 + 有限状态）
数字字面量 [0-9]+(\.[0-9]+)? 能
括号配对 (…) 嵌套任意深度 不能（需要无界计数）

第三行是分界线：一次扫描只走一遍、不记额外栈结构，所以扫描器天然只能处理正则语言。这也是第 1 课练习题里 vector<vector<int>> 的 >> 到底切不切开，必须拖到语法分析阶段决定的原因——它的判断依赖嵌套深度，超出了有限自动机的能力。

2. Thompson 构造：正则 → NFA#

正则表达式可以直接变成非确定有限自动机（NFA，nondeterministic finite automaton）：同一个状态、同一个输入字符可能有多条出边，还可以有ε 边（不读任何字符就能走的边）。Ken Thompson 给出的构造规则只有三条，每一条都保持"一个入口、一个出口"的片段形状：

  • 单字符 a：两个状态，一条标 a 的边；
  • 连接 AB：把 A 的出口与 B 的入口用 ε 边连起来；
  • 或 A|B：新起止状态，各自 ε 连到两个片段；
  • 闭包 A*：把 A 的出口 ε 连回自己的入口，并允许直接跳过。

状态数只与正则长度成正比，没有指数爆炸——这是这个构造最有价值的性质。

3. NFA 为什么必须变成 DFA#

NFA 的"不确定"在实现上是并行探索多个状态：读完一个字符后可能同时处在若干状态。把它当代码跑，就是每个字符做一次集合运算，慢且要记录回退。

子集构造（subset construction）换个角度：让 DFA 的一个状态代表 NFA 状态的一个集合。从初始集合出发，对每个输入字符算"能到达的所有状态"，如果这个新集合没见过就把它变成一个新 DFA 状态。ε 边在每步前用ε 闭包一次性走完。得到的是确定有限自动机（DFA）：每个状态对每个字符至多一条出边。

代价是理论最坏情况 2^n 个状态（所以工业词法器只敢取 DFA 的近似最小化，或用 LALR 之类更弱的模型），但实际规则集的膨胀率很小，值得。

4. 最长匹配与规则优先级都是"自动"的#

把 n 条词法规则各自的 NFA 用 ε 边并到一个起点、并把接受态标上规则类型，就得到一个同时识别所有词法单元的机器。于是第 1 课手写的两条规则变成自动行为：

  • 最长匹配：沿着 DFA 走，记下最后一次落在接受态的位置，取那个前缀——贪心吃最长，且不回溯；
  • 规则优先级：当一个前缀同时被多条规则接受（if 既是关键字又是标识符），取声明顺序更靠前的规则。

5. 生成器到底生成了什么#

Lex/Flex 的 .l 文件里，规则按行写，动作是 C 代码。生成器的工作流是纯机械的：

规则（正则）──flex──▶ NFA ──子集构造──▶ DFA ──查表压缩──▶ C 源码 yylex()

生成的 yylex() 本质是一个循环：每个字符一次数组查表，state = table[state][ch]，走到死状态或文件尾就回退到最近一次接受位置，执行对应动作。所以匹配一段长度为 L 的输入只要 O(L)，与规则条数无关——这才是"表驱动"相对"手写分支"的真正优势。

二、可运行代码示例#

下面这段 Python 手写了一个小 NFA（等价于 Thompson 构造的产物），再用子集构造把它确定化，最后用"记下最远接受位置"的办法实现最长匹配。

# ---- 例 1：NFA → 子集构造 → DFA → 最长匹配（纯标准库） ----
# 模式集合（正则风格）：if | while | [a-z][a-z]* | < | <= ，规则声明顺序 = 优先级
class NFA:
    def __init__(self):
        self.moves, self.eps = [], []            # moves[i]=[(标签,目标)]，eps 是 ε 边集合
        self.accept = {}                         # 状态号 → (优先级, 类型)

    def state(self):
        self.moves.append([]); self.eps.append(set()); return len(self.moves) - 1

    def path(self, seq, label):
        """顺着 seq（如 'while' 或字符类）串一条链，返回 (链首, 链尾)。"""
        s = self.state(); cur = s
        for ch in seq:
            nxt = self.state(); self.moves[cur].append((label(ch), nxt)); cur = nxt
        return s, cur

    def loop(self, label):
        """[a-z]* 的自环：一个状态 + 一条回到自己的边。"""
        s = self.state(); self.moves[s].append((label, s)); return s

    def matches(self, label, ch):
        return label[1] <= ch <= label[3] if label.startswith('[') else label == ch

nfa = NFA()
ENTRY = []
loop = nfa.loop('[a-z]')                         # [a-z]* 的自环状态
KW_TAILS = []
for prio, (name, spec) in enumerate([('IF', 'if'), ('WHILE', 'while')]):
    head, tail = nfa.path(spec, lambda ch: ch)
    ENTRY.append(head); nfa.accept[tail] = (prio, name)
    KW_TAILS.append(tail)                        # 关键字后再接字母 → 走 ID（iffy）
head, tail = nfa.path('a', lambda ch: '[a-z]')   # ID：首字母 + 自环
nfa.eps[tail].add(loop); ENTRY.append(head)
nfa.accept[loop] = (2, 'ID')
for t in KW_TAILS:
    nfa.moves[t].append(('[a-z]', loop))
for lab, name in [('<=', 'LE'), ('<', 'LT')]:    # 先声明 <=，所以它优先于 <
    head, tail = nfa.path(lab, lambda ch: ch)
    ENTRY.append(head); nfa.accept[tail] = (3 if name == 'LE' else 4, name)

def closure(states):
    """ε 闭包：不读字符就能到达的全部状态。"""
    seen, stack = set(states), list(states)
    while stack:
        for j in nfa.eps[stack.pop()]:
            if j not in seen:
                seen.add(j); stack.append(j)
    return frozenset(seen)

def convert():
    """子集构造：一个 DFA 状态 = 一组 NFA 状态。"""
    d0 = closure(ENTRY)
    ids, queue, trans, accept = {d0: 0}, [d0], [], {}
    while queue:
        cur = queue.pop(0)
        row = {}
        for i in cur:
            for label, j in nfa.moves[i]:
                row.setdefault(label, set()).add(j)
        out = {}
        for label, targets in row.items():
            sub = closure(targets)
            if sub not in ids:
                ids[sub] = len(ids); queue.append(sub)
            out[label] = ids[sub]
        trans.append(out)
        hit = [nfa.accept[i] for i in cur if i in nfa.accept]
        if hit:
            accept[len(trans) - 1] = min(hit)[1]     # 同长度时优先级小的赢
    return trans, accept

trans, accept = convert()
print('NFA 状态数 =', len(nfa.moves), '  DFA 状态数 =', len(trans))
print('DFA 接受态 =', dict(sorted(accept.items())))

def longest_match(text):
    """最长匹配：记下最后一次落在接受态的位置——它给出"最长"的那个词。"""
    state, best = 0, None
    for i, ch in enumerate(text):
        nxt = next((t for lab, t in trans[state].items() if nfa.matches(lab, ch)), None)
        if nxt is None:
            break
        state = nxt
        if state in accept:
            best = (accept[state], i + 1)
    return best

for w in ['if', 'iffy', 'while', 'whil', 'w', 'i']:
    print('  最长匹配 %-6s → %s' % (w, longest_match(w)))

运行输出：

NFA 状态数 = 17   DFA 状态数 = 12
DFA 接受态 = {3: 'ID', 4: 'LT', 5: 'IF', 7: 'ID', 8: 'LE', 11: 'WHILE'}
  最长匹配 if     → ('IF', 2)
  最长匹配 iffy   → ('ID', 4)
  最长匹配 while  → ('WHILE', 5)
  最长匹配 whil   → None
  最长匹配 w      → None
  最长匹配 i      → None

三个结果正好是第 1 课手写扫描器的两条规则自动长出来的样子：iffy 走 ID 分支（关键字必须整词相等），while 走关键字分支，而 whil/w/i 因为没有任何规则接受这个前缀而返回 None（真实词法器此时应报"非法字符"而不是切一个残缺 token）。也注意 <= 与 < 谁赢，是由接受态上的优先级数字决定的，不是 DFA 结构决定的。

三、练习#

  1. 实现：给例 1 加一条数字规则 [0-9]+(\.[0-9]+)?，让 3.14 被整体接受、3. 只接受 3。提示：两条规则比在一条正则里写可选组更容易验证。
  2. 解释：为什么 NFA 的状态数与正则长度成正比，而 DFA 在最坏情况下可能有 2^n 个状态？举一个会触发明显膨胀的小正则（如 (a|b)*a(a|b)^n）。
  3. 对比：分别用第 1 课的手写扫描器与本课的机器识别同一段源码，统计每个字符做了多少次判断；解释为什么表驱动版本与规则条数无关。
  4. 思考：({[]}) 配对、#include 的宏展开、C 的 typedef 依赖上下文判断——哪些是词法级问题、哪些必须留给语法或语义阶段？给出你划分界线的依据。
