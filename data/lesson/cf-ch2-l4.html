错误恢复：让编译器能继续而不是崩掉#

前几课的解析器遇到第一个语法错误就抛异常退出。这在学习代码里没问题，在真实编译器里却不可接受：一个 5000 行的文件里漏了一个分号，你希望编译器报出这一个错误，改完就完事；更糟的是错误连锁——手一抖删掉一个括号，解析器报出一串莫须有的错误，真正的错因被埋掉。错误恢复（error recovery）就是让解析器出错后回到一个已知安全的位置继续扫描。

一、概念讲解#

1. 编译器对错误的三个义务#

龙书把错误处理的目标总结成三条，顺序不能颠倒：报告要准确（定位出错位置，不报"其实没错"的错误）、要能恢复（继续检查后面代码，报出尽可能多的独立错误）、不能崩（任何输入，哪怕是二进制垃圾，都不能让它崩溃或死循环）。第三条是工程底线：解析器处理的是不可信输入，必须假设它被故意写坏。第二条决定体验——只报第一个错误的编译器等价于让用户"改一个、编译一次"。

2. 恐慌模式：最便宜也最常用的恢复策略#

恐慌模式（panic mode）的思想是：出错了别硬撑，把 token 一路丢掉，直到遇见同步点（synchronization point）——一个几乎肯定标志"新语句开始"的位置。语句级同步点有两类：语句终结符（;、}）与语句起始关键字（var、print、if……）。代价是该语句剩下的部分不再被检查（内部错误可能漏报），收益是其后的语句全部照常解析。工业实现几乎都把它当第一道防线。

3. 恢复之后，AST 必须是"合法的坏树"#

恢复点有一个容易被忽略的约束：调用者拿到的返回值必须是它能安全处理的。factor() 报"表达式起始处非法"时如果直接抛出去，expr()／stmt() 栈上的中间变量都是半成品。做法是返回一个 ('error',) 错误节点当作"这里有个表达式但内容不可信"，让树结构保持完整，交给语义分析跳过；而在括号、参数列表这类有明确边界的结构里，就地同步到 ) 比全局 panic 更精准——它不会跳过外层语句的其余部分。

4. 三种恢复策略的取舍#

策略 做法 代价
panic mode 丢 token 到同步点 简单、不卡死；可能漏报被丢区域内的错误
短语级恢复 在出错处插入/删除一个 token 后重试（如自动补 ;） 能报更多真错；需要判断"插谁"，可能引出假错
错误产生式 文法里直接写 stmt → error ";" 这样的规则 与递归下降结合自然（ANTLR 风格）；文法变脏

5. 防止错误级联：给恢复加约束#

恐慌模式最容易失控的地方是无限循环：如果恢复时一个 token 都不消费、而当前 token 又永远无法启动任何语句，while not EOF 就会原地打转。两条防线缺一不可：强制前进（主循环记录每轮开始位置，解析后位置没变就强制丢弃一个 token）与同一行不重复报（恢复前后仍在同一行时直接丢 token）——后者正好压掉"删一个括号引发一串错误"里的绝大多数。

二、可运行代码示例#

下面这个解析器在第 3 课的基础上加了三样东西：Report 收集错误、synchronize() 做语句级 panic 恢复、program() 里的强制前进兜底。它对三份坏源码都能跑完并给出结果。

# ---- 例 1：带错误恢复的解析器——一次报出多个错误且不崩 ----
class ParseError(Exception):
    pass

class Report:
    def __init__(self): self.errors = []
    def error(self, tok, msg):
        self.errors.append((tok[2], f'第 {tok[2]} 行：{msg}（遇到 {tok[1]!r}）'))

STARTERS = {'var', 'print', 'if', 'while'}

class Parser:
    def __init__(self, tokens, report):
        self.toks, self.report, self.pos = tokens, report, 0
        self.last_error_line = -1

    def peek(self, k=0):
        i = min(self.pos + k, len(self.toks) - 1)
        return self.toks[i]
    def check(self, kind, value=None):
        k, v, _ = self.peek()
        return k == kind and (value is None or v == value)
    def advance(self):
        tok = self.peek()
        if not self.check('EOF'): self.pos += 1
        return tok
    def match(self, kind, value=None):
        if self.check(kind, value): return self.advance()
        return None
    def expect(self, kind, value=None, what=''):
        tok = self.match(kind, value)
        if tok is None:
            raise ParseError(f'期望 {what or (value or kind)}')
        return tok

    # --- 恐慌模式：丢掉 token，直到下一个语句边界 ---
    def synchronize(self):
        line = self.peek()[2]
        if line == self.last_error_line:      # 同一行的级联错误：丢掉一个 token 就够
            self.advance(); return
        self.last_error_line = line
        while True:
            k, v, _ = self.peek()
            if k == 'EOF': return
            if k == 'OP' and v == ';': self.advance(); return
            if k == 'NAME' and v in STARTERS: return    # 下一个语句的开头
            self.advance()

    def program(self):
        stmts = 0
        while not self.check('EOF'):
            before = self.pos
            stmts += self.statement()
            if self.pos == before:            # 兜底：本轮一个 token 都没消费 → 强制前进
                self.advance()
        return stmts

    def statement(self):
        before = self.pos
        try:
            if self.match('NAME', 'var'):
                self.expect('NAME', what='变量名')
                self.expect('OP', '=', what='=')
                self.expression()
                self.expect('OP', ';', what=';')
            elif self.match('NAME', 'print'):
                self.expression()
                self.expect('OP', ';', what=';')
            else:
                self.expect('NAME', what='变量名')
                self.expect('OP', '=', what='=')
                self.expression()
                self.expect('OP', ';', what=';')
            return 1
        except ParseError as e:
            self.report.error(self.peek(), str(e))
            self.synchronize()
            return 1 if self.pos > before else 0     # 没推进就不算一个语句

    # expr → term (("+"|"-") term)* ；term → factor (("*"|"/") factor)*
    def expression(self):
        node = self.term()
        while self.check('OP', '+') or self.check('OP', '-'):
            op = self.advance()[1]; node = ('bin', op, node, self.term())
        return node

    def term(self):
        node = self.factor()
        while self.check('OP', '*') or self.check('OP', '/'):
            op = self.advance()[1]; node = ('bin', op, node, self.factor())
        return node

    def parenthesized(self):
        """括号恢复：只在括号这层同步，外层调用者的位置不受影响。"""
        self.expect('OP', '(', what='(')
        try:
            node = self.expression()
        except ParseError as e:
            self.report.error(self.peek(), str(e))
            while not self.check('OP', ')') and not self.check('EOF'):
                self.advance()
            node = ('error',)                        # 返回"坏树"，让上层继续
        self.expect('OP', ')', what=')')
        return node

    def factor(self):
        if self.check('NUMBER'):
            return ('num', self.advance()[1])
        if self.check('NAME'):
            return ('var', self.advance()[1])
        if self.check('OP', '('):
            return self.parenthesized()
        raise ParseError('表达式起始处')

# 扫描器与第 1 课一致：token = (类型, 字面值, 行号)
def scan(src):
    import re
    TOKEN_RE = re.compile(r'[A-Za-z_]\w*|\d+(?:\.\d+)?|[-+*/(){}=;]')
    tokens, i, line = [], 0, 1
    while i < len(src):
        c = src[i]
        if c == '\n': line += 1; i += 1; continue
        if c in ' \t\r': i += 1; continue
        if src[i:i + 2] == '//':
            i = src.find('\n', i); i = len(src) if i < 0 else i; continue
        m = TOKEN_RE.match(src, i)
        if not m: raise SyntaxError(f'第 {line} 行：非法字符 {c!r}')
        text = m.group(); i = m.end()
        if text.isidentifier():   tokens.append(('NAME', text, line))
        elif text[0].isdigit():   tokens.append(('NUMBER', float(text), line))
        else:                     tokens.append(('OP', text, line))
    tokens.append(('EOF', 'EOF', line))
    return tokens

SOURCES = {
    '缺分号（第二行）': 'var a = 1\nvar b = a + 2\nprint a;\n',
    '括号未闭合':       'print (a + 2;\nprint a;\n',
    '一行多个错误':     'var x = ;\nvar y = 3\nz = 4;\n',
}
for name, src in SOURCES.items():
    report = Report()
    parser = Parser(scan(src), report)
    n = parser.program()
    print(f'【{name}】解析完成 {n} 个语句，报出 {len(report.errors)} 个错误')
    for ln, msg in report.errors:
        print('   ', msg)

运行输出（没有异常逃出来，三份输入都跑完了）：

【缺分号（第二行）】解析完成 3 个语句，报出 2 个错误
    第 2 行：期望 ;（遇到 'var'）
    第 3 行：期望 ;（遇到 'print'）
【括号未闭合】解析完成 2 个语句，报出 1 个错误
    第 1 行：期望 )（遇到 ';'）
【一行多个错误】解析完成 2 个语句，报出 2 个错误
    第 1 行：表达式起始处（遇到 ';'）
    第 3 行：期望 ;（遇到 'z'）

诚实地读这份输出，两个现象值得注意：

  • "缺分号"那份报了两条：第二行的 var b = ... 缺 ;，恢复时把 var b 当成了赋值语句的 NAME "=" ...，于是第三行开头又撞上一次。这说明恢复是尽力而为，不是"语义无损"；但它没有连锁成十几条，也没丢下第三行不查——这才是恢复的意义。
  • "一行多个错误"原本有三处问题，只报了两条：var x = ; 触发表达式错误，又因 ; 是语句终结符被恢复逻辑吞掉，第三处被"同一行不重复报"压掉。这是准确率与覆盖率的取舍：真实编译器同样在这条曲线上做选择，只是把"报错预算"（-ferror-limit=N）交给用户调。

三、练习#

  1. 实现：给 synchronize() 加一层"恢复成功计数"，若连续 5 次恢复都没能解析出任何一个合法语句，就打印"后续内容已放弃检查"并跳到 EOF。这对应真实编译器的"错得太离谱就停止"策略。
  2. 解释：为什么恢复后必须返回 ('error',) 这样的节点，而不是返回 None 让上层自行判断？从 evaluate／语义分析的历史代码角度回答。
  3. 对比：把 synchronize() 里的"同一行不重复报"那两行删掉，重跑三份坏源码，比较报错条数。再删掉 program() 里的强制前进兜底，构造一份会让它原地打转的输入（提示：var 后面全是 )）。
  4. 思考：错误恢复的质量该用什么指标衡量？试着定义"真错召回率"与"假错率"，并说明为什么一个什么都不恢复的解析器（只报第一个错）在这两个指标上看起来"假错率很低"却依然不可接受。
