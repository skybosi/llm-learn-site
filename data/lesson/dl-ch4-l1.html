序列数据#

前面几章我们用 CNN 处理的是网格状数据——图像、特征图，它们有一个共同点：大小固定、位置有序、每个位置与邻居的空间关系最重要。但从这一章开始，我们要面对另一类数据：序列数据。一句话、一段语音、一支股票的日线、一段 DNA，都是序列。它们的长度不固定，而且先后顺序本身就携带信息——"我打你"和"你打我"是两个意思。这一课先把序列数据的"脾气"摸清楚，为后面搭 RNN 打地基。

一、概念讲解#

1. 什么是序列数据#

序列数据是由一串按顺序排列的元素组成的样本，每个元素叫做一个时间步（time step）。它有三个关键特征：

  1. 有序性：元素之间的先后顺序不能被随意打乱，顺序本身就是信息的一部分；
  2. 变长性：不同样本的长度可以不一样——句子有长有短，语音有长有短；
  3. 上下文依赖：理解某个位置的元素，往往要回头看它前面的元素。

把序列和图像放一起对比，差别一目了然：

维度 图像（CNN 的菜） 序列（RNN 的菜）
结构 固定大小的二维网格 一维、变长的元素链
顺序 空间相邻关系 时间/先后顺序
长度 固定 可变
典型例子 照片、医学影像 文本、语音、股价、DNA

生活中的序列无处不在：文本是字符或词的序列，音频是采样点的序列，股票是每天收盘价的序列，视频是帧的序列。

2. 序列数据带来的三个新难题#

CNN 之所以好训，是因为图像尺寸可以统一缩放到固定大小，而且卷积核在空间上滑动时"平移不变"。序列数据就没这么省心了：

  • 长度不统一：全连接层和固定结构的网络接受不了任意长度的输入。解决思路是截断（截长）和填充（padding）（补短），以及用 RNN 这类天然支持变长的结构。
  • 顺序敏感：不能把句子里的词像像素一样乱序输入。模型必须有一个按时间顺序读取的机制，并且记住"前面读到了什么"。
  • 长距离依赖：有时候关键信息藏在很远的前面。比如"小明在图书馆借了一本关于……的书"，谓语"借"可能和句末的主语隔了很远。能否跨越长距离记住信息，是序列模型的核心难题，也是后面 LSTM、GRU 登场的动机。

3. 把文本变成数字：分词与词表#

神经网络只吃数字，所以第一步是把文本序列转成数字序列。常用流程是：

  1. 分词（tokenization）：把句子切成一个个"单元（token）"。英文可按空格切词，也可按字符切；中文常按词或按字切。
  2. 建词表（vocabulary）：给每个 token 分配一个唯一整数编号，再预留几个特殊编号，比如 <pad>（填充）、<unk>（未知词）、<bos>/<eos>（句首/句尾）。
  3. 映射为索引：把每个 token 换成它的编号，得到整数序列。

例如"我爱深度学习"，按字切分、建立词表后，可能得到 [10, 7, 3, 2, 5, 8] 这样的索引序列。整数的顺序编码本身没有"含义距离"（编号 10 不比 9 更"大"），所以通常再接一个词嵌入层（Embedding），把每个整数映射成一个稠密向量，让语义相近的词向量也相近。

4. 批处理：padding 与掩码#

训练时我们把多条序列拼成一个 batch，但 batch 里要求每行等长。做法是：

  • 找到本 batch 里的最长长度；
  • 短的序列用 <pad> 补到同样长；
  • 同时记录每条的真实长度，生成一个掩码（mask），告诉模型哪些位置是真实内容、哪些是凑数的填充。

PyTorch 提供了 nn.utils.rnn.pad_sequence 和 pack_padded_sequence 来高效处理这件事，后面章节会用到。

二、可运行代码示例#

下面用 PyTorch 完整走一遍"文本 → 索引 → 填充 → 词嵌入"的流程，看看一条句子是如何变成张量进入网络的。

import torch
import torch.nn as nn
from torch.nn.utils.rnn import pad_sequence

# 1) 一个小型语料：三条长度不一的句子
sentences = [
    "我 爱 深度 学习",       # 4 个词
    "你 喜欢 什么",          # 3 个词
    "今天 天气 真 好 啊",    # 5 个词
]

# 2) 手动分词：这里直接用空格切开（真实项目可用分词工具）
tokenized = [s.split(" ") for s in sentences]
print("分词结果：", tokenized)

# 3) 建词表：收集所有出现过的词 + 两个特殊标记
vocab = ["<pad>", "<unk>"] + sorted({w for s in tokenized for w in s})
word2idx = {w: i for i, w in enumerate(vocab)}
print("词表大小：", len(vocab))

# 4) 把每条句子转成整数索引序列
indexed = [torch.tensor([word2idx[w] for w in s]) for s in tokenized]
print("索引序列：", [t.tolist() for t in indexed])

# 5) 用 pad_sequence 把所有序列补到同样长（默认在末尾补 0，即 <pad>）
padded = pad_sequence(indexed, batch_first=True, padding_value=word2idx["<pad>"])
print("填充后的形状：", padded.shape)   # (batch=3, 最长长度=5)
print("填充后的张量：\n", padded)

# 6) 记录每条的真实长度，作为后续掩码的依据
lengths = torch.tensor([len(t) for t in indexed])
print("真实长度：", lengths)

# 7) 接一个词嵌入层，把索引映射成稠密向量
embedding = nn.Embedding(num_embeddings=len(vocab), embedding_dim=8)
embedded = embedding(padded)
print("词嵌入后的形状：", embedded.shape)   # (3, 5, 8)

运行后你会看到：三条句子被补成了 (3, 5) 的整数张量（短的补 0），再经嵌入层变成 (3, 5, 8) 的浮点张量。到这里，一段"人类看得懂"的文本就变成了"网络吃得下"的张量，接下来的 RNN、LSTM 就是在这个张量上沿时间步逐个读取。

三、练习#

  1. 把上面代码里的 padding_value 改成 -1，观察填充位置的变化；再想一想：为什么 <pad> 的编号通常设为 0 更省事？
  2. 给词表加入 <bos> 和 <eos> 两个标记，改写分词与索引代码，让每条句子都以 <bos> 开头、以 <eos> 结尾，并打印新的索引序列。
  3. 思考：按"字"切分和按"词"切分各有什么优缺点？哪种情况下词表会爆炸、哪种情况下序列会更长？
  4. 手动模拟 pad_sequence：对索引 [[1,2,3],[4,5]]，写出它填充成长度为 3 后的结果，并用代码验证。
