同一段程序的四层形态：源码 / AST / IR / 汇编#

上一课给了地图，这一课看实物：同一段程序在四个层级上分别长什么样。我们只用一个算式 average = (min + max) / 2，走完四层。看懂这四层之间的"翻译动作"，你就掌握了整门课的主线——每一层都在把某类信息变得更显式。

一、概念讲解#

1. 第 0 层：源码文本——只是字符串#

average = (min + max) / 2 在计算机眼里是 24 个字符（或字节）。它没有"变量""加法""优先级"这些概念，只有编码。编译器的第一个动作，就是给这串字符赋予结构。

2. 第 1 层：token 序列——切出"词"#

词法分析把字符流切成有类型的词：

('NAME','average') ('OP','=') ('OP','(') ('NAME','min') ('OP','+')
('NAME','max')     ('OP',')') ('OP','/') ('NUM',2)

关键点：空白与注释被丢掉了。编译器从此不再关心"你在哪里换行"，只关心"有哪些词、什么类型"。这一步的产物是扁平的——它还没有任何嵌套结构。

3. 第 2 层：AST——恢复嵌套结构#

语法分析依据文法，把扁平序列组织成树：

('assign', 'average',
   ('bin', '/',
      ('bin', '+', ('var','min'), ('var','max')),
      ('num', 2)))

这棵 S 表达式形态的树已经表达了语法结构：除法作用在"加法结果"和"常数 2"上。但注意它还不知道 min/max 是局部变量还是全局变量、是什么类型——名字解析与类型检查属于语义分析（本章只铺地板，细节在第 3–4 章）。

4. 第 3 层：IR——把依赖关系拉平成指令#

把 AST 降成三地址码（每条指令最多一个运算，结果写进临时名）：

t1 = min + max
t2 = t1 / 2
average = t2

AST 与 IR 的差别是理解优化的钥匙：

AST IR（三地址码 / SSA）
形状 嵌套树 扁平指令序列
数据流 隐含在树形里 显式：谁用了谁的输出一眼可见
优化难度 要不断递归匹配子树 可以按指令做数据流分析、局部重写

为什么现代编译器偏爱 SSA（Static Single Assignment，静态单赋值）：在 SSA 里每个变量只被赋值一次，于是"这个值从哪来"这个问题有唯一答案——t2 的定义只有一个地方。这让"某处的计算是否还有用"（死代码消除）、"这个值是不是常数"（常量传播）这类问题从"路径敏感的难题"退化成查定义。代价是控制流汇合处需要 φ 函数（x3 = φ(x1, x2)），这会在第 4 章正式展开。

5. 第 4 层：汇编——机器的视角#

demo(int, int):            # 输入在寄存器 edi / esi
        lea     eax, [rdi+rsi]   # eax = rdi + rsi（加法）
        mov     ecx, 2
        cdq
        idiv    ecx              # eax = eax / 2
        ret                      # 返回值放在 eax

到这里，"算一个平均值"已经变成寄存器编号 + 具体指令。两个新增的约束出现了：

  1. 寄存器数量有限 → 需要寄存器分配（不够就溢出到栈，代价是访存）；
  2. 指令有延迟与吞吐 → 需要指令调度（把互不依赖的指令排在一起，掩盖延迟）。

这两件事是后端的核心工作，也是第 6 章的主题。注意 lea（load effective address）被拿来算加法——这类"指令选择"的细节，就是后端要替程序员做的决策。

6. 四层之间的"信息去向"#

越往下，语义越少、机器细节越多；但四层里没有任何一层是多余的：

  • 去掉 token → 无法报告精确的词法错误；
  • 去掉 AST → 语法结构与优先级检查无处安放；
  • 去掉 IR → 优化无法与源语言/目标机解耦（回到 M×N 灾难）；
  • 去掉汇编 → 无法贴近真实机器的约束（寄存器、指令集）。

二、可运行代码示例#

# ---- 例 1：把四层形态一次打印出来（复用上一课的骨架）----
import re
TOKEN = re.compile(r'\s*(?:(\d+)|([a-zA-Z_]\w*)|([-+*/()=]))')

def tokenize(src):
    out, i = [], 0
    while i < len(src):
        m = TOKEN.match(src, i); i = m.end()
        num, name, op = m.groups()
        out.append(('NUM', int(num)) if num else ('NAME', name) if name else ('OP', op))
    return out

def indent(node, level=0):
    """把 AST 打印成可读的缩进文本"""
    if not isinstance(node, tuple):
        return '  ' * level + repr(node)
    head, *rest = node
    lines = ['  ' * level + str(head)]
    for r in rest:
        lines.append(indent(r, level + 1))
    return '\n'.join(lines)

src = 'average = (min + max) / 2'
print('第 0 层 源码 :', src)
print('第 1 层 token:', tokenize(src))
print('第 2 层 AST  :'); print(indent(('assign', 'average',
      ('bin', '/', ('bin', '+', ('var', 'min'), ('var', 'max')), ('num', 2)))))
print('第 3 层 IR   :')
print('  t1 = min + max'); print('  t2 = t1 / 2'); print('  average = t2')
# ---- 例 2：三地址码生成器——把"降级"写成代码（含临时变量分配）----
class TempAlloc:
    def __init__(self): self.n = 0
    def new(self):
        self.n += 1; return f't{self.n}'

def lower(node, out, T):
    """AST → 三地址码列表；返回"结果的名字"（或常量）"""
    kind = node[0]
    if kind == 'num':  return ('const', node[1])
    if kind == 'var':  return ('name', node[1])
    if kind == 'bin':
        _, op, l, r = node
        a, b = lower(l, out, T), lower(r, out, T)
        t = T.new(); out.append((t, op, a, b)); return ('name', t)
    raise ValueError(kind)

ir, T = [], TempAlloc()
lower(('assign', 'average',
       ('bin', '/', ('bin', '+', ('var','min'), ('var','max')), ('num', 2))), ir, T)
for (t, op, a, b) in ir:
    print(f'  {t} = {a[1]} {op} {b[1]}')
# ---- 例 3：观察 SSA 与"非 SSA"的差别 ----
# 非 SSA：同一个名字被赋值两次，问"这行的 x 是哪个 x"必须看控制流
non_ssa = ['x = a + b', 'x = x * 2', 'return x']
# SSA：每次赋值都是新名字，问"来源"只需查唯一的一行
ssa     = ['x1 = a + b', 'x2 = x1 * 2', 'return x2']
print('非 SSA:', non_ssa)
print('SSA   :', ssa)
print('→ SSA 下，"x2 从哪来"只有一个答案：x1 * 2。这就是优化的地基。')
# ---- 例 4（可选，需要 clang）：真实工具链的四层对照 ----
# demo.c:  int demo(int min, int max) { return (min + max) / 2; }
clang -S -emit-llvm demo.c -o demo.ll   # 看 LLVM IR（文本形式）
clang -S          demo.c -o demo.s      # 看汇编
opt -passes=mem2reg -S demo.ll -o demo.opt.ll   # 把 alloca 提升为 SSA 寄存器
# 对比 demo.ll 与 demo.opt.ll：mem2reg 之后就是标准 SSA 形态
# 没有 clang：用例 1–3 的 Python 版即可，理解不受影响。

运行例 1 会看到：同一段源码的四种形态依次展开；例 3 则把"为什么 SSA 让优化变简单"讲到了代码层面——它是第 5 章（优化）的引子。

三、练习#

  1. 实现：给 lower 增加减号和比较运算，并让它对 a = b - c * d 生成正确的三地址码（注意优先级）。
  2. 解释：为什么 token 序列是扁平的、而 AST 是嵌套的？如果编译器只有 token 序列，会丢失什么信息？
  3. 比较：找一段你熟悉的 C 代码，用 clang -S -emit-llvm 得到 IR，标出哪些指令对应源码里的哪些操作；再对照 -O0 与 -O2 的 IR 差异，指出至少两处优化。
  4. 思考：SSA 让"值的来源唯一"，但循环里每个变量每轮都会被重新赋值——SSA 怎么处理循环？（提示：φ 函数与支配边界）
