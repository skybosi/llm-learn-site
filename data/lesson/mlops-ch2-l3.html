影子流量与灰度放量：放多少、看什么指标、什么时候可以停#

这一节要解决什么#

第 2 节把离线门禁写成了可复算的判据，但离线评测集永远只是线上分布的一个样本。三类偏差让"离线通过"和"线上没事"之间始终有缝：

偏差 机制 离线门禁能发现吗
分布偏差 评测集由人工/历史构造，与真实流量分布不同 不能（除非在线数据回灌）
选择偏差 评测集里的样本是被挑出来的（难的、典型的） 不能
系统偏差 离线没有真实并发、缓存、超时、限流、下游依赖 不能

所以门禁必须推出到线上。本节处理发布门禁（G4）：影子流量与灰度放量。三个必须量化的问题：

  1. 放多少：1% 还是 10%？总样本 N 要多大才能判出关心的劣化？为什么"对照组只占 1%"会让所需样本量涨到接近 106？
  2. 看什么：小流量阶段主指标判不动时，该看哪些指标（护栏、分歧率、p99）？不同阶段该看不同指标，混着看会得出错误结论。
  3. 什么时候可以停：连续观察数据必然导致 FWER 膨胀；预定 look + α/k 花费怎么设计？SPRT 的收益与代价在哪？

一句话给出本节的结论：灰度不是"小步上线"的仪式，而是一次有明确样本量、明确分配单元、明确停止边界的实验；放量比例的每一个台阶只回答一个特定的问题，用错阶段看错指标，比不看更危险。

一、影子流量与灰度流量：能回答的问题不一样#

1.1 三种流量形态#

形态 用户可见 流量 能回答 不能回答
影子（shadow） 否 100%（复制） 新旧模型的分歧率、异常率、延迟、成本、崩溃 任何业务影响（用户看不到）
灰度（canary） 是 1%→100% 逐级 护栏劣化（粗效应）、最终的业务指标 小流量下的细效应
全量 A/B 是 50/50 主指标的精细效应 成本最高，且长期不公平

影子流量最容易被误用：因为它全量、"无风险"，团队常把它当成"免费的全量评测"。它的结构性局限是没有用户反应——你只能比较"两个模型输出一不一样""延迟高不高"，不能比较"用户更满意吗"。它能抓住的是分歧与荒诞（"两个模型在 12% 的请求上给出完全不同的答案，其中 3% 是明显错误"），而不是价值。

1.2 影子流量的三个可算判据#

(a) 分歧率。定义新旧模型输出不一致的比例 pd​。要检测"分歧率比预期上升了 50%"（p1​=1.5p0​），两比例样本量（对等分配、α=0.05、power 0.80）代码实测：

      影子分歧率 p0  p1 = 1.5 p0         所需样本     1e6/天 → 天
        0.500%       0.750%        24574          0.02
        1.000%       1.500%        12208          0.01
        5.000%       7.500%         2318          0.00

影子拿到全量流量，所以罕见事件（0.5% 量级）在几分钟内可判 —— 这是它相对灰度的最大优势。

(b) 影子与生产的差异率。更常用的是"影子输出与外发输出的差异率"（shadow divergence），它同时是正确性探针：差异率高不一定是坏事（可能新模型更好），但差异率突然跳变一定是坏事（换版本、缓存错位、prompt 没同步）。

(c) 成本差。影子流量跑在真实流量上，token/算力/延迟都是真实成本：

ΔCshadow​=TPS×Tshadow​×(单请求成本new​−单请求成本old​)

这一项经常是放弃影子、改小流量灰度的真实原因：纯复制一份线上流量，成本翻倍。

1.3 分配单元：请求、用户还是会话#

这是灰度设计里最容易被忽略、后果最严重的一个决定：

分配单元 一致性 独立性（无干扰） 适用
请求级 同一用户可能被分到两组 会话内污染（同一段对话换模型） 无状态、单轮任务
用户级 同一用户始终一组 用户间仍可能有社交干扰 大多数推荐/搜索/对话
会话级 同一会话一组 会话间干扰小 多轮对话
时间片/区域 同一切片内一致 避免不了跨切片污染 无法按用户分流（缓存、频道）

选择规则：随机化单元必须 ≥ 干扰的作用范围。如果新模型的效果会通过"用户下一次访问"体现，请求级分流会让你把效果平均掉；如果同一个会话里来回换模型，用户体验会直接崩。

一致性的实现（本节代码）：

def bucket(key, salt, buckets=10000):
    h = hashlib.md5(f"{salt}:{key}".encode()).hexdigest()
    return int(h[:8], 16) % buckets

同一 key 永远落同一桶，网关本地一次哈希 + 取模即可，无需中心查询。实测输出：

  key=user-0000  桶= 7121  进 1%: False  进 5%: False  重复一致: True
  key=user-0001  桶= 5773  进 1%: False  进 5%: False  重复一致: True
  key=user-0002  桶= 5557  进 1%: False  进 5%: False  重复一致: True
  key=req-00000  桶=  870  进 1%: False  进 5%: False  重复一致: True
  key=req-00001  桶= 2800  进 1%: False  进 5%: False  重复一致: True

两个工程细节：

  1. salt 就是"实验边界"：换 salt = 重新分流。发布新实验必须换 salt，否则会把上一轮实验的分组带进来（同一批用户永远当小白鼠）。
  2. 桶数取 104 而不是 100：为了支持 0.01% 级别的细粒度放量（104 桶 = 0.01% 分辨率），同时保持整数比较的零开销。

二、放多少：样本量与分配比#

2.1 样本量公式（不对等分配）#

对照组占比 s（通常 s≪1，因为要尽量让新模型服务用户），要检出 p0​→p1​：

N≈​p1​−p0​z1−α​pˉ​(1−pˉ​)(s1​+1−s1​)​+z1−β​sp0​(1−p0​)​+1−sp1​(1−p1​)​​​​2

注意两个标准差用的是不同的假设：第一项是 H0​ 下的池化比例，第二项是 H1​ 下各自的方差。只用池化比例（把 H0​ 的标准误用在 H1​ 上）会系统性低估样本量 —— 这是实现里最常见的错误之一，本节代码第 2/3/4 节的数字都用了正确的混合形式。

代码实测（p0​=0.5%，α=0.05，power 0.80，对等分配）：

劣化 δ p1​ 总样本 N 对照组（50%） 实验组
0.1pp 0.0060 135266 67633 67633
0.2pp 0.0070 36871 18435 18435
0.5pp 0.0100 7361 3681 3681
1.0pp 0.0150 2446 1223 1223

分配比的影响（δ=+0.2pp）：

对照组占比 s 总样本 N 对照组 n 实验组 n 1e6 请求/天 → 天
0.50 36871 18435 18435 0.0
0.10 106391 10639 95752 0.1
0.01 974279 9743 964536 1.0

这张表给出一个反直觉但正确的结论：把对照组从 50% 压到 1%，只需要多约 26 倍的流量（不是 50 倍），因为对照组虽然少，实验组变大了、方差下降。但要小心：s=1% 时对照组的绝对样本数只有 9743，它在 0.5% 基线下的期望错误数只有约 49 次 —— 小样本下的比例估计很不稳，实际用时应当留一点余量（例如 s=5%）。

2.2 小流量阶段的判别力：MDE 表#

固定流量上限（只放 1%），能判出什么？代码实测：

总样本 N MDE（pp） 功效（δ=+0.2pp） 功效（δ=+1pp）
105 0.557 0.2253 0.9972
106 0.176 0.8792 1.0000
107 0.056 1.0000 1.0000
108 0.018 1.0000 1.0000

读法：

  • N=106 时 +0.2pp 的功效是 0.879，+1pp 是 1.000。 所以"1% 流量放一天"能可靠抓出粗的劣化，抓细效应则要看运气；
  • N=105 时 +0.2pp 的功效只剩 0.225。 如果 1% 流量只跑了几个小时就下结论"没变差"，那是证据不足，不是"安全"（第 2 节的纪律在这里再次生效：p 不显著 ≠ 等价）。

分阶段的正确用法：

阶段 流量 该回答的问题 判据
影子 100% 新旧输出是否异常分歧？延迟/成本是否达标？ 分歧率、p99、错误率（粗效应）
1% 1% 会不会崩？护栏是否劣化？ 护栏（粗效应，N≥106）
5–20% 逐级 主指标是否有信号？ 主指标（中等效应）
50%+ 持续 主指标是否显著改善？ 主指标 + 护栏（第 2 节的全套判据）

一张表只做一件事：让 1% 阶段去回答"主指标有没有提升"，是最常见的灰度误用 —— 它在样本量上必然失败。

三、什么时候可以停：预定 look 与 α 花费#

3.1 多看几眼的代价#

流水线上的真实行为是"数据分批回来，每批看一眼"。k 次查看、每次都用 α 的代价：

FWER=1−(1−α)k(独立)或更大（正相关时）

等额花费方案（每次用 α/k）代码实测（δ=+0.2pp、p0​=0.5%）：

查看次数 k 每次 α/k z 边界 所需总样本 相对单看
1 0.05000 1.6449 36871 1.00×
2 0.02500 1.9600 46808 1.27×
4 0.01250 2.2414 56685 1.54×
10 0.00500 2.5758 69650 1.89×

多看不是更严谨，而是更贵：每次的阈值被推高，样本量按 z2 增长。k=10 时样本量要 1.89 倍。所以正确做法是在实验开始前写死 look 计划（例如"第 1 天和第 3 天各看一次"），而不是"每来一批数据看一眼"。

3.2 一个可手算的两 look 设计#

设计：α=0.05、看 2 次、每次 α/2=0.025：

FWER≤1−(1−0.025)2=0.0494≤0.05

这是标准 group sequential 的最简形式，上界可用独立情形精确算出：FWER=1−Pr(两次都不越界)。

3.3 累积 z 轨迹：真值不同，路径完全不同#

代码的合成轨迹（N=106、1% 对照、固定种子 ⚠️，输出逐字）：

  真值无差         z: 200k:-2.10 → 400k:-2.02 → 600k:-2.10 → 800k:-2.10 → 1000k:-2.12
               首次越界(z>1.64): 未越界
  真值 +0.2pp    z: 200k:0.56 → 400k:0.53 → 600k:0.48 → 800k:0.56 → 1000k:0.55
               首次越界(z>1.64): 未越界
  真值 +1pp      z: 200k:6.90 → 400k:6.90 → 600k:6.89 → 800k:6.95 → 1000k:6.96
               首次越界(z>1.64): 第 10000 条（流量 1.0%）

三个读法：

  1. 真值无差时 z 在 0 附近抖动：本路径落在 −2.1（负号只表示方向），这是抽样噪声，不是"候选更好"的证据 —— 差分方向事先定死（z>0 才算劣化），否则会犯"看符号下结论"的错。
  2. +1pp 的期望 z≈4.3（​ 量级的信息积累），在 106 内稳定越界 —— 本路径 106 时约 7.0，比期望高是因为固定种子的单次抽样。
  3. +0.2pp 的期望 z≈1.13<1.645：即使跑满 106 也判不动。要让 z 到 2.4（有把握的检出）需要约 (2.4/1.13)2≈4.5 倍的样本（约 4.5×106），这正是第 2 节 N≈9.7×105 与 80% 功效口径的对应关系。

3.4 误报率的核对#

代码用 400 次独立模拟（真值无差、106 样本、1% 对照、阈值 z>1.96）实测：

  单个 look（1e6 总样本、1% 对照）在真值无差下越界比例 = 0.015（阈值 α/2=0.025 → z>1.960）
  两 look 设计的 FWER 上界 = 1-(1-0.025)^2 = 0.0494；
  无预定计划地滚动查看必须按 α/k 放大阈值，否则 FWER 会膨胀。

实测 0.015 低于名义 0.025，符合预期（两比例检验在小 p、极端分配下略保守；且 400 次模拟的蒙特卡洛标准误约 0.006）。关键纪律是：如果实现在每次数据到达时都检查一次（可能几百次），名义 α 完全失真 —— 这正是"看到通过为止"的统计后果。

四、工程细节：影子/灰度必须对齐的四样东西#

灰度最容易失败的地方不是统计，而是一致性。发布一个模型，实际换掉的东西至少有四样，任何一样错位都会让灰度结论无效：

要对齐的 错位后果 检查方式
权重版本 实验组其实跑的是旧权重 启动时上报 weights_hash，与 manifest 比对
tokenizer / prompt 模板 输出风格变了但权重没变，指标变化不可归因 把模板哈希进 manifest（ch1-l2 的推理单元）
缓存 key 命中旧缓存 → 实验组看到旧模型的输出 缓存 key 必须含 manifest_hash（第 4 节）
分流 salt 分组不稳定 / 实验间互相污染 salt 随实验 ID 变化，落库可审计

影子的额外要求：影子请求不能写回任何用户可见状态（对话历史、推荐曝光、计费）。一旦影子写入，你就污染了对照组，而且无法撤销 —— 这条纪律必须在代码层面强制（只读副本 + 独立事务）。

五、取舍与边界#

  1. 影子流量的成本可能是双倍：全量复制意味着全量算力。实践中常用采样影子（复制 5%–10%）而不是全量，代价是罕见事件要更久才判得出。
  2. 一致性哈希不是免费的：每个请求多一次 MD5（约 µs 级）。在 p99 < 10ms 的服务里可忽略，但在边缘设备/极低延迟路径上要用更便宜的哈希（murmur/xxhash）或预分桶（把用户 ID 预分配到固定桶）。
  3. salt 换了以后，"同一用户"的历史会断裂：长期指标（留存、复购）无法跨实验累积。所以长期指标要用固定分配单元 + 专门的 holdback 组（永久保留 1% 用户不用新模型），而不是靠每一轮灰度拼接。
  4. 灰度的"停止"有两种含义：统计停止（判据越界）与工程停止（护栏崩了，立即回滚）。后者不应等统计判据 —— 明确的熔断阈值（错误率 > 1%、p99 > 1.5 倍）要独立于实验设计。
  5. 网络效应/干扰：如果新模型会改变用户行为从而影响其他用户（社交、市场类产品），请求级/用户级分流都会低估或高估效应。可用 switchback（时间片轮换）或区域级分流，代价是样本量与方差都变差。
  6. 短期指标与长期指标的冲突：灰度看的是短期（点击、转化），而发布决策常常关心长期（留存、信任）。短期涨、长期跌是最贵的失败模式，唯一可靠的对策是holdback 组长期观测，而不是更长的灰度。

代码#

本节代码只用标准库，覆盖：分阶段指标表、对等/不对等分配的样本量与 MDE、功效、α 花费的停止边界、确定性分流、累积 z 轨迹、误报率蒙特卡洛、影子流量样本量。合成观测 ⚠️ 用固定种子生成，输出可逐字节复现。

"""第 2 章第 3 节：影子流量与灰度放量 —— 样本量、停止边界、分配一致性。

只用标准库。合成数据 ⚠️ 与模拟均已标注（固定种子，可逐字节复现）。
"""
import hashlib
import math
import random

# ------------------------------------------------------------------ 正态工具
def phi(x):
    return 0.5 * (1.0 + math.erf(x / math.sqrt(2.0)))


def z_quantile(p, lo=-40.0, hi=40.0):
    for _ in range(200):
        mid = (lo + hi) / 2
        if phi(mid) < p:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2


# ------------------------------------------------- 分组样本量（不对等分配）
def split_sample_size(p0, p1, s=0.5, alpha=0.05, power=0.80):
    """A/B 两比例、对照组占比 s。返回总样本 N。

    标准两比例公式：H0 下用池化比例、H1 下用各自比例（混合标准差）。
    只用池化比例（等价于把 H0 的 SE 用在 H1 上）会系统性低估 N。
    """
    za, zb = z_quantile(1 - alpha), z_quantile(power)
    pbar = s * p0 + (1 - s) * p1
    se = math.sqrt(pbar * (1 - pbar) * (1 / s + 1 / (1 - s)))
    se_alt = math.sqrt(p0 * (1 - p0) / s + p1 * (1 - p1) / (1 - s))
    return ((za * se + zb * se_alt) / (p1 - p0)) ** 2


def mde_two_prop(p0, N, s=0.5, alpha=0.05, power=0.80):
    """给定总样本 N 与分配比 s，反推可分辨的绝对差。"""
    za, zb = z_quantile(1 - alpha), z_quantile(power)
    se = math.sqrt(p0 * (1 - p0) * (1 / (s * N) + 1 / ((1 - s) * N)))
    return (za + zb) * se


def power_two_prop(p0, p1, N, s=0.5, alpha=0.05):
    """在真实差 p1-p0 下的功效：z 的期望 = (p1-p0)/SE_alt，判据阈值是 z_{1-α}。"""
    se_alt = math.sqrt(p0 * (1 - p0) / (s * N) + p1 * (1 - p1) / ((1 - s) * N))
    return 1 - phi(z_quantile(1 - alpha) - (p1 - p0) / se_alt)


def z_test_worse(xb, nb, xc, nc):
    """H0: p_cand <= p_base  vs  H1: p_cand > p_base（候选更差才报警）。"""
    pb, pc = xb / nb, xc / nc
    pbar = (xb + xc) / (nb + nc)
    se = math.sqrt(pbar * (1 - pbar) * (1 / nb + 1 / nc))
    return (pc - pb) / se if se > 0 else 0.0


# ------------------------------------------------- 确定性分流（同一 key 一致）
def bucket(key, salt, buckets=10000):
    """把任意 key 稳定映射到 [0, buckets)；同一 key 永远同一桶。"""
    h = hashlib.md5(f"{salt}:{key}".encode()).hexdigest()
    return int(h[:8], 16) % buckets


def assign(key, salt, treatment_pct):
    return bucket(key, salt) < int(round(treatment_pct * 100))


# ------------------------------------------------- 确定性比特流（合成观测 ⚠️）
def stream(n, seed):
    rng = random.Random(seed)
    return [rng.random() for _ in range(n)]


def bern(n, rate, seed):
    """固定种子的 Bernoulli 0/1 流（独立同分布，才能用两比例 z 判据）。"""
    rng = random.Random(seed)
    return [1 if rng.random() < rate else 0 for _ in range(n)]


def canary_obs(n_total, ctrl_pct, p_ctrl, p_treat, seed=7):
    """按顺序灌入流量；(是否进实验组, 是否出问题) 的序列。

    两组各自独立同分布地按 p 抽 0/1，因此 z 判据合法；单条路径仍有抽样噪声。
    """
    n_c = max(1, round(n_total * ctrl_pct / 100))
    n_t = n_total - n_c
    bc, bt = bern(n_c, p_ctrl, seed), bern(n_t, p_treat, seed + 1)
    out = []
    for i in range(max(n_c, n_t)):
        if i < n_c:
            out.append((False, bc[i]))
        if i < n_t:
            out.append((True, bt[i]))
    return out


def z_path(obs, checkpoints):
    """按累积观测数输出 z 轨迹（只在 checkpoints 上算）。"""
    xb = nb = xc = nc = 0
    path = []
    j = 0
    for i, (treat, bad) in enumerate(obs, start=1):
        if treat:
            nc += 1
            xc += bad
        else:
            nb += 1
            xb += bad
        if j < len(checkpoints) and i == checkpoints[j]:
            j += 1
            path.append((i, round(z_test_worse(xb, nb, xc, nc), 3)))
    return path


def first_cross(obs, zc, every=5000):
    """滚动检查（每 every 条算一次），返回第一次越界的位置与 z。"""
    xb = nb = xc = nc = 0
    for i, (treat, bad) in enumerate(obs, start=1):
        if treat:
            nc += 1
            xc += bad
        else:
            nb += 1
            xb += bad
        if nb and nc and i % every == 0:
            z = z_test_worse(xb, nb, xc, nc)
            if z > zc:
                return i, z
    return None, None

小结#

  • 影子 / 灰度 / 全量 A/B 回答不同的问题，不能互相替代：影子（100% 流量、用户无感）只能抓分歧与资源问题；灰度（1%→100%）抓护栏与粗劣化；主指标的细效应要靠放量。用 1% 阶段判断主指标是最常见的灰度误用。
  • 样本量由效应量与分配比共同决定：p0​=0.5% 下检出 +0.2pp 需总样本约 3.7×104（对等分配）到 9.7×105（1% 对照）。两比例公式必须用混合标准差（H0​ 池化 + H1​ 各自方差），只用池化会系统性低估 N。
  • 小流量的判别力表（MDE）必须事先算：1% 流量 + 106 请求时 MDE 约 0.176pp，+0.2pp 的功效 0.879、+1pp 约 1.0；只有 105 请求时 +0.2pp 的功效只剩 0.225 —— 此时"没发现"是证据不足。
  • 多看几眼的代价是算出来的：α/k 花费把 FWER 压回 0.05（k=2 时 0.0494），但样本量要涨到 1.27×（k=2）、1.89×（k=10）。look 计划必须写死在实验开始前；滚动查看等于把 α 花光。
  • 分组一致性是可验证的工程属性：确定性哈希（md5(salt:key) % 10^4）保证同一 key 永远同一桶，网关本地完成；salt 是实验边界，换 salt = 重新分流。
  • 发布要同时对齐四样东西：权重、tokenizer/prompt、缓存 key（必须含 manifest_hash）、分流 salt。任何一样错位，灰度的结论都无效。
  • 灰度的停止有两种：统计停止（判据越界）与工程熔断（护栏崩了立即回滚）。后者不该等统计判据；同时要有 holdback 组来观测长期指标，因为"短期涨、长期跌"不会在灰度窗口里显形。

下一节：灰度发现问题要回滚，但"回滚"在生产里远不是"把代码切回去"。第 4 节要把回滚做成一个可承诺的能力：版本一致性（权重/tokenizer/prompt/缓存/下游依赖如何绑成一个不可变的 manifest）、指针层与历史可解析（怎么保证回滚到的是当时那个模型，而不是"用今天的数据重建的同一个 commit"）、以及回滚时间账本（探测、决策、传播、重启、缓存预热各占多久，怎么把它压进 SLO）。
