自监督 vs 监督#

前两课我们分别学了对比学习（SimCLR/MoCo）和掩码自编码（MAE）两条自监督路线。这一课把它们放回更大的坐标系里，正面回答一个实务问题：自监督和监督学习到底该怎么选？ 我们不空谈"自监督是未来"，而是从"数据、任务、评估协议"三个维度，把两者的边界划清楚，并给出可操作的决策依据。学完这一课，你在面对一个新项目时，应该能立刻判断"要不要上自监督、上哪一种"。

一、概念讲解#

1. 先分清：这是两种"给模型找老师"的方式#

监督学习需要一个外部老师——人工标注的标签。自监督学习则是让数据自己当老师：模型从数据内部构造一个"伪任务"（pretext task），通过完成伪任务来学习表征，再用少量标签做下游任务。两者的差别不在网络结构，而在"监督信号从哪来"：

  • 监督：图像 → 标签（外部、昂贵、有偏）
  • 自监督：图像 → 伪任务 → 预测（内部、免费、海量）

自监督的伪任务家族其实很丰富，按"任务形式"可以分成几类：

  • 对比式：拉近正样本、推远负样本（SimCLR、MoCo、SwAV）；
  • 掩码式：盖住一部分，重建被盖的部分（MAE、BEiT、SimMIM）；
  • 预测式：预测人为施加的变换，比如预测旋转角度、拼图块顺序、灰度图着色；
  • 生成式：自编码器、扩散模型这类"重建/生成整张图"的路线。

前两类是当前视觉自监督的主力，也是你在生产中会真正用到的东西。

2. 什么时候自监督更占优#

自监督的价值，在三个典型场景里最突出：

  • 标签稀缺：下游任务只有几千甚至几百张标注图。这时从海量无标注数据里先自监督预训练，再微调，通常显著优于从零训练或纯监督。
  • 数据分布漂移：自监督学到的表征对增广、噪声更鲁棒，迁移到新的域（比如从自然图像迁移到医疗影像）时，往往比监督预训练更稳。
  • 多任务复用：一个自监督骨干可以同时服务分类、检测、分割等多个下游头，预训练一次、处处受益，摊薄了成本。

反过来，如果下游任务标签充足、且和数据分布完全匹配，那么在足够数据上直接监督训练，常常仍是精度天花板。自监督的主要卖点是"用更少的标签达到接近监督的水平"，而不是"无条件超越监督"。

3. 公平比较的钥匙：评估协议#

自监督模型好不好，必须靠统一的评估协议来说话。上一课提到过两个，这里把它们系统化，因为没有统一协议，任何"自监督 vs 监督"的榜单都不可信：

  • 线性探测（linear probing）：冻结骨干，只训练一个线性分类头。它衡量的是特征本身的可分性，最严格，也是最容易被"投机的特征"骗过的指标。
  • 微调（fine-tuning）：解冻骨干端到端训练。它衡量的是特征的初始化和可塑性，是实际应用中最常用的方式。
  • 少样本（few-shot）：只用每个类几张图做下游任务。它衡量样本效率，最能体现自监督"少标签"的价值。
  • 半监督：用少量标签 + 大量无标签联合训练，介于自监督和监督之间的混合路线。

一个常见的坑是：只看"微调精度"而忽略"用了多少标签"。自监督的价值恰恰要在少标签、少样本的设定下才显现，在标签拉满时两者的差距会被压缩。

4. 选型决策：一张可操作的判断表#

把上面的分析落成决策，可以用三个问题来串：

  1. 我有多少标注数据？ 很少 → 自监督预训练 + 微调几乎是必选项；很多 → 监督直接训练或监督预训练更直接。
  2. 我有多少无标注数据？ 自监督的前提是"有大量未标注图像可榨"。没有无标注数据，自监督无从谈起。
  3. 下游任务和数据域匹配吗？ 匹配且标签足 → 监督；跨域、分布漂移 → 自监督更鲁棒。

综合起来：标签稀缺 + 无标注数据充足 + 任务多变，是自监督的黄金场景；标签充足 + 数据域单一，监督学习仍然是性价比最高的选择。成熟的工程实践里，两者常常组合使用——自监督预训练打底，监督微调收尾。

二、可运行代码示例#

先写一个对比"线性探测 vs 微调"的最小实验框架，用 ResNet 在 CIFAR-10 上演示两种评估协议的差异：

import torch
import torch.nn as nn
import torchvision
import torchvision.transforms as T
from torch.utils.data import DataLoader

torch.manual_seed(0)

# 加载一个在 ImageNet 上预训练的 ResNet18（模拟"预训练好的骨干"）
backbone = torchvision.models.resnet18(weights=torchvision.models.ResNet18_Weights.IMAGENET1K_V1)
backbone.fc = nn.Identity()          # 去掉分类头，只留特征提取部分（512 维）
backbone.eval()

def make_head(in_dim, num_classes):
    return nn.Linear(in_dim, num_classes)

# 线性探测：冻结骨干，只训练一个线性头
print("线性探测：只更新分类头的参数")
head = make_head(512, 10)
# 实际训练时：
#   for p in backbone.parameters(): p.requires_grad = False
#   optimizer = torch.optim.SGD(head.parameters(), lr=0.01)
#   在 CIFAR-10 上训练 head，评估精度

# 微调：解冻骨干（或部分解冻），端到端更新
print("微调：骨干与分类头一起更新")
backbone2 = torchvision.models.resnet18(
    weights=torchvision.models.ResNet18_Weights.IMAGENET1K_V1)
backbone2.fc = nn.Linear(512, 10)    # 接新的任务头
# 实际训练时：
#   optimizer = torch.optim.SGD(backbone2.parameters(), lr=1e-4)
#   全参数更新（或分层设置学习率），在 CIFAR-10 上训练

# 观察：两者的"可训练参数规模"差别，解释了为何线性探测快、微调慢但更强
print("线性探测可训练参数量:", sum(p.numel() for p in head.parameters()))
print("微调可训练参数量:", sum(p.numel() for p in backbone2.parameters()))

这段代码的关键不是真的训练，而是让你亲眼看清楚两种协议在"冻结什么、更新什么"上的区别——这正是理解"线性探测衡量特征可分性、微调衡量可塑性"的落脚点。

再写一个更聚焦的实验：对比"自监督预训练的特征"和"监督预训练的特征"在少样本下的表现。这里用冻结骨干 + 近邻分类的简单代理来感受：

def knn_eval(train_feats, train_labels, test_feats, test_labels, k=5):
    """极简 KNN 评估：在冻结特征上做最近邻分类，衡量特征可分性。"""
    train_feats = F.normalize(train_feats, dim=-1)
    test_feats = F.normalize(test_feats, dim=-1)
    sim = test_feats @ train_feats.T               # (N_test, N_train) 余弦相似度
    topk = sim.topk(k, dim=1).indices              # 每个测试样本最近的 k 个训练样本
    # 多数投票
    votes = train_labels[topk]                     # (N_test, k)
    preds = votes.mode(dim=1).values
    acc = (preds == test_labels).float().mean()
    return acc.item()


import torch.nn.functional as F
# 模拟两组不同的"骨干"提取出的特征，验证 KNN 评估能区分它们
# (现实中 train_feats/test_feats 应来自真实骨干的前向输出)
torch.manual_seed(0)
feats_good = torch.randn(200, 512)                # 假设"可分性好的特征"
labels = torch.randint(0, 10, (200,))
# 为让 KNN 有意义，给同类样本加聚类结构：把特征往各自的类中心靠
centers = torch.randn(10, 512)
feats_good = feats_good + centers[labels]
feats_test = feats_good[:50] + torch.randn(50, 512) * 0.1
labels_test = labels[:50]
print("KNN 分类准确率:", knn_eval(feats_good[50:], labels[50:], feats_test, labels_test))

KNN 在冻结特征上的准确率，正是"线性探测"的一种无参近似——它不引入任何可训练头，纯粹反映特征空间本身是否已经"聚成可分的团"。自监督方法（尤其 MAE）在线性探测上表现突出，指的就是这类指标。

三、练习#

  1. 用 torchvision 的预训练 ResNet 和随机初始化的 ResNet，分别在冻结骨干 + KNN 的设定下评估 CIFAR-10 特征，比较两者的 KNN 准确率，说明"预训练"到底带来了多大的特征可分性提升。
  2. 在同一骨干上分别做"线性探测"和"微调"，记录两者的精度与训练时间，结合可训练参数量解释差异，并判断哪种协议更适合报告你的自监督模型。
  3. 设计一个少样本实验：每类只留 1、5、20 张标注图，比较"自监督预训练 + 微调"与"从零监督训练"的精度曲线，找出自监督优势最明显的那个数据量区间。
  4. 思考：为什么说"监督信号来自外部"意味着它自带标注者的偏见？自监督的信号"来自数据内部"，是否就一定没有偏见？结合数据分布偏差谈谈你的看法。
