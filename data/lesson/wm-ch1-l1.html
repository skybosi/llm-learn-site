定义与判别标准：状态表征 + 前向动力学，以及与 LLM 的界线#

这一节要解决什么#

"世界模型"是当下被滥用最严重的技术词之一。同一周里，你可能读到四篇稿子分别把下面四样东西叫世界模型：

  • 一个能逐帧生成视频的扩散模型；
  • 一个能预测"下一帧会发生什么"的预测网络；
  • 一个游戏引擎或物理仿真器；
  • 一个能陪你推演"如果我把杯子推下去会怎样"的对话模型。

当同一个词覆盖四类结构完全不同的东西时，这个词就不再传递信息。 而这不是学究式的洁癖：如果定义不清，评价标准就必然走样 —— 一个只能逐帧生成漂亮画面、却对"动作"完全无感的模型，会因为"生成的视频很像"被判定为好的世界模型，而它在规划里的价值是零。

所以这一节只做一件事：把定义收紧到可操作，并把它变成一组能直接问出口的判别问句。 具体要回答：

  1. 世界模型的最小定义是哪两个部件？缺了任一个，系统会退化成什么？
  2. 它与 LLM 的差别到底在哪一层 —— 是模态不同、架构不同，还是建模的对象根本不同？
  3. 与视频生成模型、与模拟器的界线怎么划？什么条件下视频模型可以算世界模型？
  4. 怎么把上面这些变成可执行的判别问句：不问作者，只看接口与行为就能判？
  5. 不能算世界模型的东西，就"没有价值"吗？—— 不。要讲清它们各自的价值与不可替代的缺口。

定位提醒：世界模型是一个与 LLM 并列的独立模型方向，不是 LLM 的补充、也不是"多模态的一个分支"。 它属于"建模环境动力学"这一支：研究对象是状态—动作—观测的动力学，而不是离散 token 序列的条件分布。这一节要把这条分界线画准，因为后面七节全部建立在它上面。

一、最小定义：状态表征 + 前向动力学#

1.1 两个部件，缺一不可#

我们把一个系统称为世界模型，当且仅当它同时提供下面两件事：

部件 ① 状态表征（state representation）：一个映射，把高维、部分可观测、带噪的观测历史，压成一个足以预测未来的内部量 st​。

st​=ϕ(o≤t​,a<t​),st​∈S

部件 ② 前向动力学（forward dynamics）：一个在状态空间里推进的预测器，以动作为条件：

st+1​∼pθ​(st+1​∣st​,at​),o^t+1​=ψ(st+1​)

（ψ 是解码/观测映射；若状态本身就是观测，则 ψ 是恒等映射。）

这个定义有两个容易被忽略的地方，值得单独说。

第一，"状态"不等于"观测"。 st​ 是为了预测而保留下来的信息，它可以是隐向量、可以是显式的物理量（位置、速度、库存、余额）、也可以是一个符号结构。这一点在下一节（wm-ch1-l2）会展开成完整的 POMDP 论证。

第二，"动力学"必须能接受动作。 一个只预测"接下来会发生什么"的模型（p(ot+1​∣o≤t​)）不是世界模型：它无法回答"如果我改成做 a′ 会怎样"。而这个反事实问题，恰恰是世界模型在规划与决策里被使用的唯一理由。第 3 节会把这条变成判别问句 D2。

1.2 一个反例检验：把两个部件各去掉一个#

去掉的部件 剩下什么 它能做什么 它不能做什么
去掉 ②（只留表征） 一个自编码器 / 对比学习编码器 聚类、检索、可视化、下游特征 不能往前推一步；不能回答"下一步"
去掉 ①（只留动力学） 一个直接 o→o′ 的序列预测器 拟合训练分布内的短期续写 无法处理部分可观测（第三节的代码会实测到它失明）；无法泛化到分布外的动作
两个都不去，但没有动作输入 一个"被动"的动力学模型 预测自然演化（天气预报式的） 不能用于控制：它不知道"我做了什么"和"世界做了什么"的差别

所以"世界模型"这个词的信息量全在这两个部件上。 一个系统如果只满足其中一个，它就是别的东西 —— 有价值，但不是世界模型。这也是为什么下一节我们要专门讨论"为什么必须显式地把状态提出来"：不是为了好看，而是因为不提出状态，动作条件与反事实问题都无法被表达。

⚠️ 一个常见混淆：把"世界模型"当成"环境的一份高保真副本"。定义里没有任何"高保真"的字样。世界模型的保真度是相对于任务而言的 —— 用来做规划时，重要的是"模型里最优的动作在真实环境里也近似最优"，而不是"预测的画面与真实画面逐像素相同"。这条会在第 4 节的设计目标与后面的评测里反复出现。

二、与 LLM 的界线：建模的对象不同，不是模态不同#

2.1 先把 LLM 说清楚：它在建模什么#

一个自回归语言模型建模的是离散 token 序列的条件分布：

pθ​(x1​,…,xT​)=t=1∏T​pθ​(xt​∣x<t​),xt​∈V, ∣V∣∼104–105

它的训练目标是同一形式下的交叉熵：在给定前缀的条件下，对下一个 token 的对数似然最大化。这里有三件事是"结构性"的、不是实现细节：

  1. 取值空间是离散且有限的（词表 V）。于是"预测得好不好"有一个规范化的概率语义：困惑度、对数似然都是良定义的评分规则。
  2. 没有外生的控制输入。序列自己往下走；"动作"若要进来，只能被编码成 token，与语言内容混在同一个通道里。
  3. 时间步与语义步重合。一个 token 就是一个时间步，"接下来"由序列位置定义，而不是由物理时间的 Δt 定义。

2.2 世界模型在建模什么#

世界模型建模的是动力学转移，条件里同时有状态与动作，而且动作是一个外生的、与观测分离的输入：

pθ​(st+1​∣st​,at​),ot​=ψ(st​)+ηt​

结构性差别同样有三条：

  1. 取值空间通常是连续、高维的（图像、点云、传感器向量、连续控制量）。"预测得好不好"必须借一个度量来定义（MSE、负对数似然、下游任务收益），而度量一换，最优模型就换。
  2. 动作是分离的通道，并且它带有干预语义：do(at​) 与"观察到 at​"不是一回事。这是因果推断里的干预与观测之别，也是"世界模型能规划"与"序列模型只能续写"的分水岭。
  3. 时间步是物理量。Δt 决定了动力学的尺度（快变量/慢变量），也决定了复合误差怎么累积。
LLM 世界模型
建模对象 token 序列的条件分布 状态—动作—观测的动力学
取值空间 离散、有限词表 连续/高维（或结构化符号）
控制输入 无（动作只能混进 token 通道） 有，且与观测分离
时间语义 序列位置 物理时间步 Δt
目标函数 交叉熵（天然规范化） 需要一个度量或似然模型（度量即归纳偏置）
核心困难 长程依赖、幻觉 复合误差、部分可观测、不确定性校准
数据来源 人类文本（被动、相关性强） 交互轨迹（主动、含反事实）

2.3 为什么"数据来源"那一行是本质差别#

上表最后一行值得单独强调，因为它是"世界模型不能靠读文本训出来"的根因，而不是程度差别。

文本语料记录的是已经发生的事（observational data）：世界上只发生了一条轨迹，且动作与结果高度相关 —— 做 a 的人往往正是因为它看起来对。要回答反事实问题（"如果我做了 a′ 呢"），你需要干预数据，或者需要一个可识别的因果结构假设。前者要靠智能体自己去试（这正是强化学习的数据来源），后者要靠额外假设。

这意味着世界模型天然是一个"主动学习"问题：数据分布本身是被策略决定的，策略又依赖世界模型 —— 于是形成一个循环（这也是基于模型的强化学习里"探索 vs 利用"的核心张力）。相比之下，LLM 的数据分布是给定的、被动的。这个差别决定了两个方向的研究议程根本不同。

⚠️ 不要把上面的话读成"LLM 做不了动力学"。给定足够好的结构化输入，LLM 当然可以被当作动力学预测器（例如把状态序列化成 JSON 再预测下一个状态）。那不是定义问题，而是接口问题：一旦你这么做，你其实是在用它实现部件 ②，前面还得自己补部件 ①，而且它天然对连续量的误差与不确定性不敏感。界线不是"能不能"，而是"建模对象的默认假设是什么"。

三、与三个邻居划界：视频生成、模拟器、纯序列模型#

3.1 与视频生成模型：差在"动作"与"状态"#

视频生成模型（自回归视频预测、视频扩散、以及各种"可交互视频生成"）是最容易被叫成世界模型的一类。判别的关键是两点：

(a) 动作是否在条件里。 若条件是 p(ot+1​∣o≤t​) 或 p(ot+1​∣o≤t​,文本)，它没有控制输入，不能用于规划，只是分布内的未来续写。若条件是 p(ot+1​∣o≤t​,at​) 且 at​ 是一个可被外部指定的控制量，那么它至少在接口上具备部件 ②。

(b) 状态是否被显式建模。 一个把历史帧全部塞进上下文的模型，可能隐式地携带了状态，但它对"哪些信息重要"没有结构。这带来两个可观测后果：长时 rollout 的误差累积与对动作的敏感度不可控（可能过度敏感，也可能近乎无感）—— 本节的代码会同时实测到这两种失效。

(c) 还有一条常被忽略的：是否具备"可独立查询的动作空间"。 如果动作只能通过"文字提示"间接影响生成结果，那么动作空间不是结构化的、也不是可枚举的，规划算法（要在 A 上做搜索/优化）就无法接入。这是"看起来可交互"与"真的可规划"的差别。

3.2 与模拟器：差在"是不是学出来的"#

物理引擎、游戏引擎、排队论仿真器都提供状态与动作转移 —— 它们在功能上完全满足定义！那为什么通常不把它们叫世界模型？

因为惯例上"世界模型"特指从数据中学出来的那类模型。这条惯例不是任意的，它对应一个真实的能力差别：

模拟器（引擎） 学出来的世界模型
动力学来源 人工写下的方程/规则 从交互数据拟合
保真度 在建模过的范围内精确 在数据覆盖的范围内近似
未知现象 直接缺失（没写就没有） 会外推（可能对也可能错）
校准度 通常不提供 可以给出预测分布（也可能过度自信）
成本 精确但昂贵（复杂场景实时性差） 便宜、可批量并行 rollout
用途 ground truth、数据生成 规划、想象、加速仿真

这两者不是替代关系，而是互补的：常见的工程做法是"用模拟器生成数据 → 学一个世界模型 → 用世界模型做快速规划 → 只用真实/模拟器校验少数候选"。这个组合正是基于模型的强化学习的标准形态。

3.3 与纯序列预测模型：差在"干预"#

时间序列预测（ARIMA、时序 Transformer、视频预测）与气象预报都在做 p(ot+1​∣o≤t​)。区分它们与世界模型的唯一必要问句是：模型里面有没有一条"把动作从观测里分离出来"的通道？ 没有这条通道，"我做了 a 之后会怎样"这个问题在该模型里根本没有对应的接口 —— 不是它答得差，是它没地方答。

四、四个判别问句：把它们变成可以当场问出口的东西#

上面三节是概念。工程上需要能当场判定的判据。下面四条是我建议的标准，每一条都对应一个可观测的行为测试，而不是一句定义复述。

D1  状态问句：模型内部有没有一个"状态"，它比原始观测历史短，却足够预测？
    → 可操作测试：把观测历史做受控扰动（加噪、遮蔽早期帧、删掉冗余帧），
      看预测误差是否只在"真正丢失信息"时才恶化。
      若换个历史长度就崩、或必须喂完整历史才准 → 只是序列模型，没有状态。

D2  动作问句：给定同一个状态/观测，改变动作，预测会不会按预期改变？
    → 可操作测试（反事实分离度）：
      取同一观测、两个不同动作序列，测 |预测(a_1) - 预测(a_2)| 与真值之比。
      比例 ≈ 0   → 动作条件失效（动作被忽略）
      比例 ≫ 1   → 动作被过度放大（外推不稳）
      两者都不合格；合格是"接近 1 且跨动作幅度稳定"。

D3  rollout 问句：能不能只吃起点、之后喂自己的预测走 N 步？
    → 可操作测试：teacher forcing（每步喂真值）与自由 rollout 的误差之比。
      这个比值就是"误差放大的倍数"。若 N 步后误差与观测尺度同量级 → 不可用于规划。

D4  校准问句：模型说"我有 90% 把握"时，实际命中率是不是 90%？
    → 可操作测试：分箱统计置信度 vs 实际频率；再看 epistemic 项是否随数据量下降。
      只给点预测、或永远过度自信 → 规划无法用它做风险取舍。

四条问句的逻辑关系是：D1 是前提（没有状态就谈不上动力学），D2 是"能不能用来做决策"，D3 是"能用多久"，D4 是"能不能安全地用来做决策"。任何一条挂了，系统在那个用途上就不成立。

为什么是这四条，而不是别的？ 因为它们分别对应世界模型在决策回路里被用到的四个必要环节：

D1感知压缩​​→D2反事实预测​​→D3多步想象​​→D4风险取舍​​

缺任何一环，规划要么写不出来（D1/D2），要么写出来不可信（D3/D4）。

4.1 把 D2、D3、D4 写成可计算的量#

上面的描述必须能落到公式上，否则四条问句又会变成口号。下面给出全课统一使用的三把尺子。

D2：反事实分离度。 固定同一个状态 s，取两个不同的动作 a1​=a2​，比较"模型的预测差"与"真实世界的差"：

ρcf​(s)=​f(s,a1​)−f(s,a2​)​​f^​(s,a1​)−f^​(s,a2​)​​,ρˉ​cf​=Es∼peval​​[ρcf​(s)]

合格线不是"越大越好"，而是：

ρˉ​cf​ 含义 在规划回路里的可观测后果
≈0 动作通道失效，动作被当噪声平均掉 搜索算法看到"所有动作结果相同"，无法排序；策略退化
≈1 动作敏感度与真实世界同量级 动作的相对排序可信（这是规划唯一需要的东西）
≫1 动作被过度放大（外推不稳） 搜索被虚假的大梯度吸引，选出实际无效的极端动作

注意"跨动作幅度稳定"这一条：整体缩放 ρcf​≡c=1 其实无害（规划只要排序），真正致命的是 ρcf​ 随动作幅度剧烈变化——小动作无感、大动作爆炸。所以工程上要同时看 ρˉ​cf​ 与 std(ρcf​)。

D3：误差放大倍数。

κH​=RMSE(teacher forcing 的 H 步预测)RMSE(自由 rollout 的 H 步预测)​

κH​ 随 H 的增长形态就是模型的稳定性画像：接近 1 说明模型能自洽地走下去；指数上升说明进入了第 3 节的放大区；先升后平说明动力学本身收缩，误差有饱和。合格线由任务定：规划视界 H 上允许的误差是 Δ，则要求 εκH​≤Δ。

D4：校准误差。 对每个预测区间/分位数设置信度 p，按置信度分箱 Bm​，比较"声称的把握"与"实际命中率"：

ECE=m∑​n∣Bm​∣​​acc(Bm​)−conf(Bm​)​

合格线不是"ECE 越小越好"，而是两件事同时成立：① 分箱对角线（校准）；② 区间宽度不退化（锐度）。一个把方差预测成无穷大的模型 ECE 可以很漂亮，但它对规划毫无用处——这就是第 4 节"可校准"目标里那个陷阱的定量形式。

4.2 怎么用这四条问句打分：一个可复制的判据表#

把上面的测试结果记成下表，就是一个可复制的"是不是世界模型、缺哪一块"的判据：

系统 D1 状态 D2 动作 D3 rollout D4 校准 判定
自回归视频生成（无动作条件） 隐式（长历史） ✗ 无接口 有（逐帧自回归） 通常无 不是世界模型：缺 ②
动作条件视频预测 隐式 部分（常过/欠敏感） 有 通常无 弱世界模型：①②都有，但 D2/D4 不达标
隐空间动力学 + 规划（Dreamer 类） 显式（隐向量） 有 有（在隐空间） 部分（有集成/离散 latent） 世界模型
物理引擎 显式（人工状态） 有 有（精确） 无（确定性） 模拟器（功能上等价，来源不同）
纯时序预测模型 可能有 ✗ 有 通常无 不是世界模型：缺动作通道
LLM（文本进、文本出） 无显式状态 ✗（动作只能混进 token） 有（逐 token） 部分（logprob 可校准） 不是世界模型：建模对象不同

⚠️ 这张表最容易被误读的一格是"动作条件视频预测 = 弱世界模型"。它的意思不是"差不多是世界模型"，而是"接口上有了，但行为上没达标" —— D2 的比值不对、D4 缺失，用它做规划会得到"看起来能搜、搜出来的动作没用"的结果。接口达标与行为达标是两件事，后面的评测一节会专门讲怎么把行为达标变成可测的数字。

五、不能算世界模型的东西，各自的价值在哪#

严格划界的目的不是贬低别的方向。要把它们的价值与缺口一起说清，否则读者会得出"只有世界模型重要"的错误结论。

  • LLM：在语言、代码、常识推理上是通用的接口层。它的缺口是没有对环境的干预式理解，也没有对连续量的不确定性的显式建模。但它可以是世界模型的使用者：LLM 负责把任务变成计划与子目标（符号层），世界模型负责在低层预测与搜索（动力学层）。这两者组合是目前最现实的分工。
  • 视频生成模型：在视觉真实感、数据增广、内容创作上不可替代。它的缺口是因果与动作结构：像素相似不等于动力学正确（一个把所有物体都预测成"慢慢淡出"的模型可能在像素度量上表现不差，因为它赌的是不确定性大的区域）。
  • 模拟器：提供可验证的 ground truth 与可控的数据生成。它的缺口是建模成本与未知现象：凡是没写进引擎的效应，仿真里不存在，学到的策略会在这里栽跟头（sim-to-real gap）。
  • 纯时序预测：在预测本身就是目的的场合（需求预测、气象、金融）非常有用。它的缺口是没有决策接口。

一句话：世界模型不是"更好的视频生成"或"更强的 LLM"，而是决策回路里专门负责"如果我这样做会怎样"的那个部件。 它在系统中的位置，决定了它的设计目标（第 4 节）与评价方式（评测一节）。

六、五个最常见的误用（以及各自的纠正）#

定义与判据如果不落到"会被怎么用错"，就还是纸上的。下面五条是本领域最高频的误用，每一条都给出可观测的症状与纠正方式。

误用 1：把"能预测下一帧"当成世界模型。 症状：模型在视频续写上表现很好，但把同一段历史配上不同动作，输出几乎不变（ρcf​≈0）。根源是把 p(ot+1​∣o≤t​) 与 p(ot+1​∣o≤t​,at​) 混为一谈。纠正：先做 D2 的反事实测试，再谈"能不能用来做决策"。

误用 2：用外观相似度当评测。 症状：FVD/PSNR/CLIP 相似度很好，但模型里规划出来的动作在真实环境里没用；或者模型学会了"让物体慢慢淡出"这种在像素度量上不吃亏、在动力学上完全错误的解。根源是像素相似 ≠ 动力学正确：像素误差对"不确定区域的糊"是宽容的，而规划恰恰需要那些区域的分叉结构。纠正：用反事实分叉测试（D2）、长时一致性（物体恒存/计数/遮挡）与规划收益（模型内规划、真实环境执行）来评测。

误用 3：在错误的空间里跟 LLM 比。 症状：争论"世界模型参数量什么时候追上 LLM"、"世界模型是不是 LLM 的一个模态"。根源是把两个建模对象不同的方向放在同一条缩放曲线上比较。LLM 的缩放建立在被动、海量、可并行采样的文本上；世界模型的数据是主动交互轨迹，数据分布由策略决定（下一段会讲）。纠正：比较应放在各自的目标上——LLM 比条件分布的似然/下游任务，世界模型比 D1–D4 与规划收益。

误用 4：把"高保真环境副本"当成目标。 症状：为了把重建损失从 0.01 压到 0.008 投入大量工程，而规划收益毫无变化；或者反过来，因为"预测未来图像比真实图像模糊"就判定模型不可用。根源是定义里从来没有"高保真"二字——保真度是相对于任务而言的。纠正：先写清用途（规划 / 数据增广 / 生成 / 评测），再选度量；MuZero 式的做法甚至完全不重建观测（第 3 章第 2 节）。

误用 5：只看单步精度选模型。 症状：几个候选在留出集上的一步误差几乎相同，于是"随便选一个"，结果规划表现差出一个量级。本节代码就是这个症状的实测：三个模型的一步误差在 0.0427~0.0506 之间，而反事实分离度相差约 50 倍。纠正：模型选择必须用多目标（至少 D1–D4 各测一项），单步误差只能用来排查"训练是否收敛"。

这五条误用的共同结构是：在一个指标上优化得很好的系统，可能在决策回路里毫无价值，甚至有害。 这正是第 4 节要系统化处理的问题：五个设计目标为什么会互相冲突，以及冲突时该牺牲谁。

代码：用四个判别问句实测一个模型的缺陷#

下面的代码不调用任何 API。它构造一个部分可观测的环境（观测只有位置，速度是隐状态），训练三个候选，然后实测它们的 D1/D2/D3 表现。注意每一处注释写的是设计决策，不是实现细节。

⚠️ 数据全部为本代码合成，不代表任何真实数据集。

"""WM ch1-l1 演示：判别问句 D2（动作条件 / 反事实敏感）与 D1/D3（状态与自由 rollout）。
环境与数据全部为合成数据（⚠️ 不代表任何真实数据集），只依赖 numpy。
运行：/opt/homebrew/bin/python3.10 <file>   环境：python 3.10.16 / numpy 1.26.2
"""
import numpy as np

rng = np.random.default_rng(0)

# ---------- 1. 环境：非线性阻尼振子，动作 u 是外生加速度 ----------
DT = 0.05
K, C, G, B = 2.0, 0.35, 0.35, 1.6    # 刚度 / 线性阻尼 / 非线性阻尼 / 控制增益
OBS_NOISE = 0.02                     # 观测噪声：让"观测 != 状态"这件事真实存在
# 设计决策：把噪声写进来，是因为无噪声的部分可观测问题可以被"猜得很准"，
#           一旦有噪，能不能把速度从位置历史里提出来才成为硬约束。

def step(x, u):
    """x = [位置, 速度]；u = 加速度输入。非线性来自速度平方阻尼。"""
    pos, vel = x
    acc = -K * pos - C * vel - G * vel * abs(vel) + B * u
    vel = vel + DT * acc
    return np.array([pos + DT * vel, vel])

def simulate(u, x0):
    x = np.asarray(x0, dtype=float).copy()
    obs = np.empty((len(u), 2))
    for t, ut in enumerate(u):
        x = step(x, ut)
        obs[t] = x
    return obs

H, N_TRAIN, N_TEST = 4, 6000, 100
u_tr = rng.normal(0.0, 1.0, N_TRAIN)
x_tr_true = simulate(u_tr, [1.0, 0.0])
x_tr = x_tr_true + rng.normal(0.0, OBS_NOISE, x_tr_true.shape)   # 只把带噪观测给模型

def chirp(n):
    t = np.arange(n) * DT
    return 1.5 * np.sin(2 * np.pi * (0.1 + 1.5 * t) * t) + 0.4

# ---------- 2. 训练集：最近 H 步观测（位置）拼成窗口 ----------
idx = np.arange(H, N_TRAIN - 1)
W_all = x_tr[idx[:, None] - np.arange(H, 0, -1)[None, :], 0]    # (N, H) 位置历史
y_all = x_tr[idx + 1, 0]                                        # 下一位置
u_all = u_tr[idx + 1]                                           # 下一步动作
cut = int(len(W_all) * 0.9)

# ---------- 3. 三个候选：区别只在"状态从哪里来" ----------
class WindowMLP:
    """状态 = 位置历史窗口 + 动作。隐状态（速度）由历史窗口隐式给出。"""
    def __init__(self, h, w, seed=1):
        r = np.random.default_rng(seed)
        self.W1 = r.normal(0.0, 1.0 / np.sqrt(w), (h, w))
        self.b1 = np.zeros((h, 1)); self.w2 = r.normal(0.0, 0.3, (1, h))
        self.b2 = np.zeros((1, 1))
    def _feat(self, X, u):
        return np.vstack([X.T, u[None, :]])
    def predict(self, X, u):
        return (self.w2 @ np.tanh(self.W1 @ self._feat(X, u) + self.b1) + self.b2).ravel()
    def fit(self, X, y, u, epochs=4000, lr=0.08):
        Xa = self._feat(X, u)
        for _ in range(epochs):
            Hh = np.tanh(self.W1 @ Xa + self.b1)
            d = (self.w2 @ Hh + self.b2 - y[None, :]) / Xa.shape[1]
            self.w2 -= lr * d @ Hh.T
            self.b2 -= lr * d @ np.ones((Xa.shape[1], 1))
            dz = (self.w2.T @ d) * (1 - Hh ** 2)
            self.W1 -= lr * dz @ Xa.T
            self.b1 -= lr * dz @ np.ones((Xa.shape[1], 1))

class MemorylessMLP:
    """状态 = 当前观测 + 动作。缺速度：凡是要靠速度才能分辨的情形都会失明。"""
    def __init__(self, h, seed=2):
        r = np.random.default_rng(seed)
        self.W1 = r.normal(0.0, 0.5, (h, 2))
        self.b1 = np.zeros((h, 1)); self.w2 = r.normal(0.0, 0.3, (1, h))
        self.b2 = np.zeros((1, 1))
    def _feat(self, X, u):
        return np.vstack([X.T, u[None, :]])
    def predict(self, X, u):
        return (self.w2 @ np.tanh(self.W1 @ self._feat(X, u) + self.b1) + self.b2).ravel()
    def fit(self, X, y, u, epochs=4000, lr=0.08):
        Xa = self._feat(X, u)
        for _ in range(epochs):
            Hh = np.tanh(self.W1 @ Xa + self.b1)
            d = (self.w2 @ Hh + self.b2 - y[None, :]) / Xa.shape[1]
            self.w2 -= lr * d @ Hh.T
            self.b2 -= lr * d @ np.ones((Xa.shape[1], 1))
            dz = (self.w2.T @ d) * (1 - Hh ** 2)
            self.W1 -= lr * dz @ Xa.T
            self.b1 -= lr * dz @ np.ones((Xa.shape[1], 1))

class RidgeState:
    """显式状态：s_t = (o_t, o_t - o_{t-1}) 顶替 (位置, 速度)，线性一步动力学。"""
    @staticmethod
    def _phi(X, u):
        return np.column_stack([X[:, -1], X[:, -1] - X[:, -2], u])
    def fit(self, X, y, u, lam=1e-6):
        Phi = self._phi(X, u)
        self.W = np.linalg.solve(Phi.T @ Phi + lam * np.eye(Phi.shape[1]), Phi.T @ y)
    def predict(self, X, u):
        return self._phi(X, u) @ self.W

win = WindowMLP(24, H + 1); win.fit(W_all[:cut], y_all[:cut], u_all[:cut])
mem = MemorylessMLP(24);    mem.fit(W_all[:cut, -1:], y_all[:cut], u_all[:cut])
rid = RidgeState();         rid.fit(W_all[:cut], y_all[:cut], u_all[:cut])

# ---------- 4. 评测 ----------
rmse = lambda a, b: float(np.sqrt(np.mean((a - b) ** 2)))
one_step = lambda m, X, y, u: float(np.sqrt(np.mean((m.predict(X, u) - y) ** 2)))

def rollout(model, x_hist, u, patch=False):
    """自由 rollout：只吃真实历史帧，之后每一步都吃自己的预测（判别问句 D3）。
    patch=True 是无记忆模型的适配器：它只接受当前观测这一帧。"""
    W = np.array([x_hist], dtype=float)
    P = []
    for ut in u:
        o = float(model.predict(W if not patch else W[:, -1:], np.array([ut]))[0])
        W = np.hstack([W[:, 1:], [[o]]])
        P.append(o)
    return np.array(P)

ho = slice(cut, None)
print(f"[数据] 训练 {cut} 窗口 / 留出 {len(W_all) - cut} 窗口；观测噪声 sigma={OBS_NOISE}")
print("\n[一步误差 · 留出集 teacher forcing]")
print(f"   无记忆 MLP（只有 o_t, u_t） : {one_step(mem, W_all[ho, -1:], y_all[ho], u_all[ho]):.4f}")
print(f"   历史窗口 MLP（H=4 + u_t）   : {one_step(win, W_all[ho], y_all[ho], u_all[ho]):.4f}")
print(f"   显式秩-2 状态（线性）       : {one_step(rid, W_all[ho], y_all[ho], u_all[ho]):.4f}")

# 测试 A（D3）：从一段真实历史出发，自由 rollout
j = 3000
h_true = x_tr[j - H:j, 0]
print("\n[测试 A · 自由 rollout 100 步 · 位置 RMSE，振幅 ~2 m]")
for tag, u_seq, ref_j in (("分布内动作", u_tr[j:j + N_TEST], j),
                          ("分布外 chirp", chirp(N_TEST), j)):
    ref = x_tr_true[ref_j:ref_j + N_TEST, 0]
    for k in (10, 100):
        rm = rmse(rollout(mem, h_true, u_seq, patch=True)[:k], ref[:k])
        rw = rmse(rollout(win, h_true, u_seq)[:k], ref[:k])
        print(f"   {tag:>10} 前 {k:>3} 步 | 无记忆 {rm:.4f} m | 窗口 MLP {rw:.4f} m")

# 测试 B（D2）：同一个观测、同一个动作，但两个环境的隐状态相反
x_A, x_B = np.array([0.0, 2.0]), np.array([0.0, -2.0])
tr_A = simulate(np.zeros(N_TEST), x_A)[:, 0]
tr_B = simulate(np.zeros(N_TEST), x_B)[:, 0]
near = np.argsort(np.abs(x_tr_true[:, 0]))[:50]          # 找训练分布里 x≈0 的帧
iA, iB = near[np.argmax(x_tr_true[near, 1])], near[np.argmin(x_tr_true[near, 1])]
h_A = x_tr[iA - H + 1: iA + 1, 0]                        # 位置≈0、速度为 +2 的历史
h_B = x_tr[iB - H + 1: iB + 1, 0]                        # 位置≈0、速度为 -2 的历史
print("\n[测试 B · 反事实分离度 · 判别问句 D2]  起点位置相同、速度相反，动作都是 u=0")
print(f"   真实轨迹 A vs B 的 RMSE        : {rmse(tr_A, tr_B):.4f} m")
print(f"   无记忆 MLP 预测 A vs B 的 RMSE : "
      f"{rmse(rollout(mem, h_A, np.zeros(N_TEST), patch=True), rollout(mem, h_B, np.zeros(N_TEST), patch=True)):.4f} m")
print(f"   窗口 MLP   预测 A vs B 的 RMSE : "
      f"{rmse(rollout(win, h_A, np.zeros(N_TEST)), rollout(win, h_B, np.zeros(N_TEST))):.4f} m")
print("\n读法：无记忆模型把 A 与 B 映到同一条轨迹上 —— 它无法回答")
print("      '如果隐状态不同、动作相同，未来会不会不同'。这就是判别问句 D2。")

实测输出（本机 python 3.10.16 / numpy 1.26.2，随机种子见代码）：

   真实轨迹 A vs B 的 RMSE        : 0.9560 m
   无记忆 MLP 预测 A vs B 的 RMSE : 0.0142 m

读法：无记忆模型把 A 与 B 映到同一条轨迹上 —— 它无法回答
      '如果隐状态不同、动作相同，未来会不会不同'。这就是判别问句 D2。

这段代码想让你看到的四件事（而不是让你抄）：

  1. 一步误差完全区分不出好坏。 三个模型在留出集上的 teacher forcing 误差是 0.0506 / 0.0427 / 0.0494 —— 几乎同一个量级。如果你只看这个指标，你会得出"用哪个都行"的结论。而它们在 D2 上的表现差了 50 倍。这是"不能用单步精度评价世界模型"的第一个具体证据。
  2. 无记忆模型在 D2 上系统性失明。 它的反事实分离度是 0.0142 m，真值是 0.9560 m —— 约 1.5%。它不是"预测不准"，而是"把两个不同的世界映到同一条轨迹上"。这种模型在规划里是灾难：搜索算法会认为两个完全不同的动作导致同样的结果，于是无法据此排序动作。
  3. 有状态也可能"过度敏感"：窗口 MLP 的分离度是 0.7187 m，真值 0.9560 m —— 方向对了、量级接近但偏小；而它在前 10 步的 rollout 误差（0.1633 m）明显好于无记忆模型（0.2829 m），到 100 步却又被反超（0.3233 vs 0.2684）。这说明"分离度接近 1"和"rollout 稳定"是两个独立的性质，必须分开测（第 2 章第 4 节专门讲后者）。
  4. 分布外动作（chirp）让两个模型的 rollout 都变差，但变差的方式不同：这是"动作条件在训练分布外如何退化"的可观测形态。能造出这种测试本身，就是世界模型工程的核心能力之一 —— 它要求你知道自己在乎的是哪一类动作。

⚠️ 诚实说明这个实验的边界：这是一个低维、确定性、状态空间只有 2 维的环境，因此"用最近 4 帧位置代替速度"已经能拿到大部分信息。它证明的是判别问句可操作、且能区分模型，而不是"某某方法好用"。放到高维图像观测上，D1 的难度会陡增（这正是第 2 章第 1 节的主题）。

练习#

  1. 用自己的话重写定义：不看正文，写出世界模型的两个部件与它们各自的输入输出。然后针对"一个能把论文摘要扩写成全文的模型"，逐条判断 D1–D4 是否满足，并指出它最接近上表里的哪一类。
  2. 构造反例：设计两个系统，它们的 D1 与 D3 都表现很好，但 D2 失败。要求：一个是"动作被忽略"（分离度 ≈ 0），另一个是"动作被过度放大"（分离度 ≫ 1）。对每一个，说明它在规划回路里会以什么可观测的错误行为暴露出来（提示：搜索会挑出什么动作？）。
  3. 判别表实测：从你熟悉的模型里挑两个（一个视频生成、一个时序预测），对每个写出你会怎么具体地测 D1–D4：需要什么样的数据、什么样的对照、判据阈值怎么定。不许写"看效果好不好"这种不可执行的判据。
  4. 推导边界的紧致性：把本节代码里的环境换成纯线性阻尼振子（G=0），重跑测试 B。解释为什么线性情形下"最近两帧线性组合"能精确恢复速度，而 D2 的分离度会接近真值；再说明：为什么非线性项的存在才是"必须有状态表征"的硬理由（提示：从"有限差分能否恢复速度"的角度看，非线性在差分中起什么作用？）。
  5. 设计一个"模拟器 vs 世界模型"的对照实验：给定一个你了解的领域（例如排队系统、机器人抓取、推荐系统），设计一个实验回答"学出来的模型在哪个区域比模拟器更可信、在哪个区域更不可信"。要求给出具体的度量与至少两个会翻转结论的条件。
  6. 讨论题（有唯一答案）：本节说"LLM 建模 token 序列，世界模型建模状态—动作—观测动力学"。有人反驳："把动作和观测都序列化成 token，LLM 不就在建模动力学了吗？"请给出至少三条结构性反驳，每条都要落到"会导致什么可观测的失败"，而不是停留在名词之争。

小结#

  • 世界模型的最小定义是两个部件：状态表征 ϕ（把观测历史压成足以预测的内部量）与前向动力学 pθ​(st+1​∣st​,at​)（以动作为条件）。缺 ① 退化成序列预测器，缺 ② 退化成编码器。
  • 与 LLM 的界线在建模对象，不在模态：LLM 建模离散 token 序列的条件分布（有限词表、无外生控制输入、时间步 = 序列位置、目标天然规范化）；世界模型建模连续/高维状态—动作—观测动力学（需要度量、动作是分离通道且带干预语义、时间步是物理量）。
  • 数据来源的差别是本质的：文本是被动的观测数据，动作与结果高度相关；世界模型需要干预数据，因此它天然是一个主动学习问题，且数据分布由策略决定 —— 这形成了"模型 ↔ 策略"的循环。
  • 与三个邻居划界：视频生成模型常缺动作通道与结构化动作空间；模拟器有状态与动作但动力学是人工写下的（互补而非替代）；纯时序预测没有动作通道，因此"反事实"在它里面没有接口。
  • 四个判别问句（D1–D4）：状态（有无足以预测的压缩）、动作（反事实分离度是否 ≈ 1）、rollout（自由 rollout 误差放大多少倍）、校准（置信度是否等于命中率）。它们分别对应规划回路的四个必要环节：感知压缩 → 反事实预测 → 多步想象 → 风险取舍。
  • 代价实测：同一个环境里，三个模型的一步误差几乎相同（0.0506 / 0.0427 / 0.0494），而反事实分离度相差 50 倍（0.0142 vs 0.7187，真值 0.9560）。只看单步精度评价世界模型，等于不评价。
  • 划界不是为了贬低别的方向：LLM 是通用的符号接口层、视频模型在视觉真实感上不可替代、模拟器提供可验证的 ground truth。世界模型是决策回路里专门回答"如果我这样做会怎样"的那个部件 —— 它的位置决定了它的设计目标与评价方式。

下一节：定义里说状态是"足以预测未来的压缩"，但观测到状态这一步凭什么必要？这一节要用 POMDP 把这个论断证出来：同一个观测可以对应互相矛盾的最优动作，此时任何"观测 → 动作"的映射都必然在某些情形下错。然后我们会看到"压缩"与"可预测"之间有一场真实的拉锯 —— 压得太狠会丢掉未来需要的信息，压得太松则等于没压。
