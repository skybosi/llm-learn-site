序列生成#

分类是"读进一句话、吐出一个标签"，而序列生成是"给定一个开头，逐字逐词地吐出一段新文本"。它比分类多了一个关键环节：模型要一个词一个词地自己写下去，每一步的预测又成为下一步的输入。这一课我们搞懂"训练时"和"生成时"两套不同的玩法——teacher forcing 与自回归采样，并亲手训练一个字符级生成器。

一、概念讲解#

1. 语言模型：预测下一个词#

序列生成的核心是一个语言模型（language model）：给定前面已经出现的字符或词，预测下一个最可能是什么。用条件概率表示：

P(w₁, w₂, …, w_T) = P(w₁) · P(w₂|w₁) · P(w₃|w₁,w₂) · … · P(w_T|w₁…wₜ₋₁)

整段文本的概率，被拆成一连串"已知上文、猜下一个"的乘积。用 LSTM/GRU 实现语言模型非常自然：每一步输入当前字符，输出对"下一个字符"的概率分布，训练目标就是让这个分布尽量命中真实的下一个字符。

2. 训练时的 teacher forcing#

训练语言模型时，每一步都要预测"下一个词"，那输入给网络的"当前词"用谁？有两种选择：

  • Teacher forcing：每一步都喂真实的历史词（老师给的答案），而不是模型自己上一步的预测。这样训练稳定、收敛快，是默认做法。
  • 不用 teacher forcing：把模型自己上一步的预测喂给下一步，更接近真实生成场景，但训练初期预测很烂，误差会一路累积，很难收敛。

实际训练几乎都采用 teacher forcing：把整段文本整体喂进去，让网络一次输出每个位置对"下一个字符"的预测，再和错开一位的真实序列算交叉熵。PyTorch 里这只是一次前向传播，非常高效。

3. 生成时的自回归采样#

训练用的是真实历史，但生成时没有老师，只能自回归：从一个起始字符（种子）出发，每一步把"当前已有序列"喂给模型，取预测出的下一个字符，拼到序列末尾，再重复。如此循环，直到生成指定长度或遇到结束符。

关键问题：怎么从概率分布里挑下一个字符？ 有三种采样策略：

  • 贪心（greedy）：每步都取概率最大的那个。简单，但容易陷入重复、单调；
  • 随机采样：按概率分布随机抽。多样，但可能出乱码；
  • 带温度采样（temperature）：把 logits 除以温度 T 再 softmax。T 越小越接近贪心、越确定；T 越大分布越平滑、越多样。这是实际生成时最常用的旋钮。

4. 训练与生成的分工#

一句话总结：

训练用 teacher forcing（并行、喂真实历史），生成用自回归采样（串行、喂自己的预测）。

这个"两套模式"的分工，是理解所有生成式模型（从字符 RNN 到 GPT）的第一块敲门砖。它们共享同一个网络，只是"数据怎么流"的方式不同。

二、可运行代码示例#

下面训练一个字符级 LSTM 语言模型：给它一段文本，让它学会每个字符后面最可能跟什么，然后用不同的采样策略生成新文本。为了可复现，语料用一段重复性较强的简单文本。

import torch
import torch.nn as nn

torch.manual_seed(0)

# 1) 语料：一段有规律的文本，让模型学出"字符间的依赖"
text = "abcdefghij abcdefghij abcdefghij abcdefghij"
chars = sorted(set(text))
c2i = {c: i for i, c in enumerate(chars)}
i2c = {i: c for c, i in c2i.items()}
data = torch.tensor([c2i[c] for c in text])

class CharLM(nn.Module):
    def __init__(self, vocab_size, hidden):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, 8)
        self.lstm = nn.LSTM(8, hidden, batch_first=True)
        self.fc = nn.Linear(hidden, vocab_size)

    def forward(self, x, h=None):
        # x: (batch, seq_len) -> 输出每个位置对下一个字符的预测
        out, h = self.lstm(self.embed(x), h)
        return self.fc(out), h

model = CharLM(len(chars), hidden=32)
loss_fn = nn.CrossEntropyLoss()
opt = torch.optim.Adam(model.parameters(), lr=0.01)

# 2) 训练：teacher forcing。输入 data[:-1]，目标是 data[1:]
seq_len = 16
for step in range(500):
    # 随机截一段作为 batch（batch=1，这里简化）
    i = torch.randint(0, len(data) - seq_len - 1, (1,)).item()
    x = data[i:i + seq_len].unsqueeze(0)        # (1, 16)
    y = data[i + 1:i + seq_len + 1].unsqueeze(0)
    logits, _ = model(x)
    loss = loss_fn(logits.reshape(-1, len(chars)), y.reshape(-1))
    opt.zero_grad()
    loss.backward()
    opt.step()

print(f"训练完成，最终损失：{loss.item():.4f}")

# 3) 生成：自回归 + 带温度采样
def generate(model, seed, length, temperature=1.0):
    model.eval()
    idxs = [c2i[c] for c in seed]
    with torch.no_grad():
        for _ in range(length):
            x = torch.tensor([idxs[-seq_len:]]).long()   # 只取最近 seq_len 步
            logits, _ = model(x)
            logits = logits[0, -1] / temperature          # 最后一步 + 温度
            probs = torch.softmax(logits, dim=0)
            nxt = torch.multinomial(probs, 1).item()      # 按概率抽样
            idxs.append(nxt)
    return "".join(i2c[i] for i in idxs)

print("贪心（温度 0.5）：", generate(model, "abc", 12, temperature=0.5))
print("随机（温度 1.5）：", generate(model, "abc", 12, temperature=1.5))

运行后你会看到：低温度下的生成更像语料里的规律（"abcdefghij"循环），而高温度下会出现更多随机、甚至不存在的组合。这正是温度旋钮的作用——在"确定"与"多样"之间做取舍。真实文本生成（写诗、写代码）都靠这套机制调出想要的效果。

三、练习#

  1. 把语料换成一句自然语言（如重复一段中文拼音），重新训练，观察生成结果是否比字母循环更"像话"；说说为什么语料的规律性会影响生成质量。
  2. 分别用 temperature=0.1、1.0、2.0 各生成 3 次，对比输出的确定性与多样性，并解释温度如何改变了 softmax 的概率分布。
  3. 把采样策略从 torch.multinomial 改成贪心（每步取 argmax），生成一段长文本，观察是否出现重复循环，说说贪心为什么容易"卡住"。
  4. 思考：teacher forcing 训练出的模型，在自回归生成时为什么会"越走越偏"？这种现象叫什么，有什么缓解思路？
