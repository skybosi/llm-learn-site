红队与上线门禁：把第 3 章的流程落成「上线前必须通过什么」#

这一节要解决什么#

上一节交出了一张设计评审表，六条判据各有"当前值 → 阈值"，还有一条第 7 层的门槛 ε7​≥0.509233。

但那六条"当前值"全是设计文档里写的数。它们没有样本量、没有置信区间、没有判定器版本 —— 用第 3 章第 4 节的话说，它们停在"点估计"这一层，甚至更差（很多是"设计意图"而不是测量）。

这一节要回答的是上线前那一刻被问到的那个问题：

"可以上线了吗？"—— 这个"可以"的依据是什么？

它的答案不是一个"通过/不通过"，而是一张门禁表：每个 gate 给出统计量、阈值、最小样本量、判定规则、以及在多重比较下的校正方式。本节把第 3 章的红队四段流水线（目标 → 假设 → 用例 → 判定）落成这张表。

 门禁=(统计量, 阈值, n, α, 判定规则, 失效时间) ​

六个字段缺任何一个，这条门禁就无法被执行，也无法被审计。

本节的结构是"从单个 gate 到整条流水线"：

§1–§4：四类判据一个 gate 怎么定​​→§5：FWER 与选择效应八个 gate 一起怎么看​​→§6：期望损失最小化报警了怎么办​​→§7：有效期门禁什么时候过期​​

⚠️ 本节所有数值均为合成的：α、τ、U∗、sj​（各 gate 对真缺陷的检出率）、损失金额、对手能力年增长率都是手写常量；门禁有效期的模型是明确的推测，会在正文与代码输出里双重标注。

1.2 三个读数#

第一，八个 gate 里有五个是计数型（U 型）：G1、G2、G4 是零成功上界，G5 是双侧上界，G7 是占比下界。它们的共同点是结论形式是"小于某个数"，因此样本量由要排除多大的值决定，而不是由点估计的精度决定（第 3 章 §1.1 的尾部这一行）。

第二，两个是结构型：G3（危险组合 =0）与 G6（汇点覆盖率 ≥0.90）。它们的 n 是枚举数，不是样本量：

 结构型 gate 没有抽样误差，只有遗漏误差 —— 清单不全时 n 是下界 ​

G3 的 n=8 是"危险组合对数"，它由 §2.1 的工具-作用域表枚举得到；如果漏了一个工具，n 就错了，而 U 型 gate 的那种"多测几次"在这里完全无效。

第三，只有 G8 是能力侧。这是第 2 章"对齐税"在本章的接口：加固会带来能力代价，所以上线门禁必须包含一条能力侧的非劣效检验。它是唯一一个双侧（等价）而不是单侧的 gate。

2.3 失效条件与边界#

  1. U 型 gate 只覆盖"在用例集上"的成功率。用例集的覆盖度是另一条 gate（G6）的事。所以 G1 与 G6 之间有一个乘法关系：G1 通过 ≠ 系统安全，它只说明"在我列的这些攻击上做不到"。
  2. 零成功时不能报"成功率 =0"，只能报 U。这条在第 3 章 §1.3 已经确立，写进门禁时要把它做成"报告模板里没有'0'这个数"。
  3. α 的选择会进入多重比较（§5），所以每条 gate 的 α 不能在本地定，必须与整条流水线一起定。

三、判定器门禁：它自己先过门禁#

3.1 Se 与 Sp 的置信下界#

一个判定器（分类器、审计规则、LLM 裁判）在被用来"判定攻击是否成功"之前，必须先证明自己的两个错误率。用零成功/全检出的闭式：

Sp≥0.995 0 假阳 597.65 598 598 条对照全对 → 下界 0.9950
Sp≥0.999 0 假阳 2994.23 2995 2995 条对照全对 → 下界 0.9990

  1. 把假阳率压到 0.001 需要 2995 条阴性对照。 而"阴性对照"不是随机正常流量 —— 必须是真实但看起来像攻击的样本（例如"讨论安全话题的正常提问"）。用随机流量估不出尾部，这是第 3 章 §4.3 的原话在门禁上的形态。
  2. Se 的门禁便宜得多（29 条 vs 299 条）：因为阳性样本容易造，阴性对照难造。这个不对称应当直接反映在评测预算的分配上。

3.3 失效条件与边界#

  1. 判定器的 Se/Sp 是在对照集上测的，而对照集与真实流量分布不同。所以 Sp 的门禁结论只能用在"与对照集同分布"的流量上；跨分布使用时必须重测（第 4 章的数据卡字段在这里有直接用处）。
  2. LLM 裁判的不稳定性是额外一层误差。同一个输入多次判定可能不一致，此时 Se 本身是一个随机变量，报告里要给它的区间而不仅仅是点估计。
  3. 判定器变更必须触发重测。Se/Sp 是判定器版本的属性；换了模型或改了 prompt，旧的判据失效（见 §7 的变更影响矩阵）。

4.2 占比型（G7）：从"报出的事件真不真"反解 Sp#

G7 的阈值是"报出的事件里真问题占比 ≥0.60"。给定基率 p 与 Se，这个阈值可以反解成对 Sp 的要求：

pSe+(1−p)(1−Sp)pSe​≥κ⟹Sp≥1−κ(1−p)pSe(1−κ)​

在 p=0.01、Se=0.90、κ=0.60 时，Sp≥0.987755 —— 这与 §3.1 的"Sp≥0.99 要 299 条阴性对照"是同一条门禁的两种写法。门禁表里应当同时给两种写法，因为 Sp 是判定器的属性（可跨 gate 复用），而"占比"是业务方看得懂的口径。

4.4 失效条件与边界#

  1. G8 的失效条件是"评测集与业务分布不一致"。能力评测的 MDE 是在给定 p 下算的；如果业务分布让 p 落在 0.20 附近，同样的 τ 需要 3736 条/臂（3.37 倍）。
  2. p 本身是估计值。样本量公式里的 p(1−p) 应当在设计阶段用一个保守上界（例如 p=0.25 时 p(1−p) 最大），否则会出现"算出来够、跑出来不够"。
  3. 结构型 gate 不能靠抽样替代。G3 的"危险组合 =0"是全量枚举，抽样核对只能证明"枚举过程可靠"，不能证明"危险组合不存在"。

注意 1.9463 这个倍数：把八条 gate 都做严格（Bonferroni）会让每条的样本量接近翻倍 —— 这就是"门禁越多越贵"的算术。

但门禁与科研假设有一个关键区别：门禁的默认是保守（宁可误阻，不可漏放），所以"不校正"在门禁场景里比在科研场景里更危险 —— 一次假阳性会导致一次不必要的上线延迟。这也是 §6 要算的东西。

5.2 共线：八条 gate 读的是不是同一批证据#

串行 gate 的总检出率（各 gate 独立时）：

Pdetect​=1−j∏​(1−sj​)=1−2.835×10−5=0.99997165

但门禁之间同样会共线：

  • G1/G2/G4 共用同一批红队用例；
  • G5 是它们共用的判定器；
  • G6/G7 依赖同一份汇点清单。

按"同组只算最强项"的口径：

Pdetect共线​=1−组∏​(1−j∈组max​sj​)=1−0.001200=0.998800

读数：独立口径说"几乎必被发现"（0.999972），共线口径只给 0.998800。

 "我们有八个 gate"这句话的检出率，取决于它们是否读同一批证据 ​

这与第 2 节 §7 的残余风险共线是同一个现象的两面：一个算的是"攻击会不会被挡住"，一个算的是"缺陷会不会被发现"，而两者的数学形式完全一样。

红队报告里最常见的形态是"我们试了 M 个变体，最差/最好的那个是……"。用顺序统计量算期望：

读数三条（这一节最反直觉的一条）：

  1. 只要 M⋅n 足够大，"挑最大值"的期望点估计就逼近 1/n，与真实 p 无关：(n=30, M=30) 与 (n=30, M=100) 都报 0.0333。
  2. 反过来 (n=60,p=0.05) 报 0.0167，低估了真实值 —— 选择效应不是单向的。
  3. 可操作判据：报告里的成功率若恰好 ≈1/n，就必须怀疑它是选择效应的产物。 处理办法是分裂样本 —— 在一半变体上挑选、在另一半上复测，复测期望回到真实 p。

5.4 失效条件与边界#

  1. "1/n 现象"在门禁里是致命的：如果门禁的阈值恰好落在 1/n 附近，那么通过或失败完全由样本量决定，与系统无关。判据是"把 n 翻倍后结论是否变化"。
  2. 共线分组的划分同样是判断而非观测。近似做法与第 2 节 §7.6 相同（三个问题：同一批数据？同一个判定器？同一份清单？），收窄方法与第 2 节一样靠故障注入（把某条 gate 故意改成永远通过，看总检出率掉多少）。
  3. 门禁的 α 与 sj​ 由同一条 ROC 决定（§6 会看到这个限制的影响）。把 α 调小会让 gate 更保守，但它同时会降低 sj​ —— 所以"把门禁做严"的净效果不是单调的。

六、发布决策：门禁是一个期望损失最小化问题#

6.1 把门禁写成决策#

设 π=P(系统存在未被设计覆盖的真缺陷)=0.10，漏放损失 LFN​=200000 元，误阻损失 LFP​=30000 元。"放行"= 所有 gate 都不报警。则：

E[loss]=π⋅P(放行∣有缺陷)⋅LFN​+(1−π)⋅P(报警∣无缺陷)⋅LFP​

策略 单 gate α 总误阻率 漏放率 期望损失（元）
严格：α=0.01，全通过 0.010 0.077255 2.835×10−5 2086.5
当前：α=0.05，全通过 0.050 0.336580 2.835×10−5 9088.2
宽松：允许 2 个 gate 失败 0.050 0.005788 8.773×10−3 331.7

读数：漏放概率只有 2.835×10−5，期望损失几乎全由误阻构成。所以：

 "门禁该多严"实际是在问"一次误阻值多少钱"，而不是在问安全性 ​

把 α 从 0.05 收到 0.01，误阻损失从 9087.6 元掉到 2085.9 元，代价是评测样本量膨胀到 1.7272 倍（+72.7%）。

⚠️ 这是一次部分敏感性分析：本算例固定 sj​ 只改 α。真实系统里 α 与 sj​ 由同一条 ROC 决定，抬高 α 也会抬高 sj​ —— 两个方向都要报，否则会得出"门禁越松越安全"的荒谬结论。

6.2 第三种动作：人工复核#

报警时不直接阻断，而是送人工复核（复核成本 4000 元/次、纠正率 0.85）：

策略 误阻率 复核成本/次 残余漏放率 期望损失（元）
直接阻断（α=0.05） 0.336580 — 2.835×10−5 9088.2
人工复核（α=0.05） 0.336580 4000 1.500×10−1 5575.3
人工复核（α=0.05，允许 2 失败） 0.005788 4000 1.500×10−1 3044.8
人工复核（α=0.20） 0.832228 4000 1.500×10−1 9367.0

读数：人工复核把"误阻一次"的单价从 30000 元降到 8500 元/次，在 α=0.05 下把期望损失从 9088.2 降到 5575.3 元；但把 α 抬到 0.20 反而更差（9367.0），因为误阻次数涨得比单价降得快。

 复核不是"可以更松"的许可证，它改的是斜率 ​

最优 α 由"复核单价 × 误阻频次"决定。这正是第 4 章 §2 的申诉与复核机制在门禁上的对应物：复核能力决定了门禁该多严 —— 一个没有复核通道的组织，只能把门禁做到极保守（或用极宽松的口径蒙混过去）。

6.3 失效条件与边界#

  1. LFN​ 与 LFP​ 都是估计值，且它们的比值决定结论。LFN​/LFP​ 从 6.67（本例）变成 1 时，最优策略会完全改变。所以这两个数必须由业务方给，并写进门禁表。
  2. "允许 2 个 gate 失败"要区分是哪两个。如果允许失败的两个恰好是共线组里最强的两个，那么实际检出率会掉得比算出来的多 —— 所以"允许 k 个失败"必须配一个"哪 k 个"的白名单。
  3. 门禁的期望损失是"每次放行决策"的量，不是年度的。要折算成年度必须乘上"一年放行几次"（版本节奏，见 §7）。

七、门禁的有效期：它会悄悄过期#

7.1 两件事会让门禁失效#

  1. 对手能力增长：今天测出来的 U0​ 是今天的上界，不是明年的；
  2. 系统变更：模型换了、工具加了、策略改了、语料变了、汇点多了、判定器升了 —— 每一样都可能让某几条 gate 的结论失效。

7.2 对手增长项（⚠️ 推测模型）#

用一个显式的、可被质疑的模型：

真实成功率(t)=U0​(1+g)t⟹T=ln(1+g)ln(U∗/U0​)​

真实成功率(t)=U0​(1+g)t⟹T=ln(1+g)ln(U∗/U0​)​

U∗ U0​ g（年增长） T（年） T（月）
0.010 0.003 0.30 4.5889 55.07
0.010 0.003 0.60 2.5616 30.74
0.005 0.003 0.30 1.9470 23.36
0.010 0.008 0.30 0.8505 10.21
0.020 0.003 0.30 7.2309 86.77

⚠️ 这个模型是推测，不是事实。 g 是一个没有可靠公开估计的量；把它写成指数增长也只是为了方便。它的价值不在数字，而在逼迫写出 g 与 U0​ 的估计来源：

 说不出 g 从哪来，就等于承认门禁没有有效期，也就等于承认它会悄悄过期 ​

两条读数：g=0.30,U0​=0.003 时有效期约 4.59 年；若实测上界已经靠近阈值（U0​=0.008），有效期缩到 0.85 年 —— 门禁测得越"刚好达标"，它过期得越快。这是一条非常实用的直觉：余量本身就是有效期。

7.3 变更项：变更影响矩阵#

第 4 节会用一张 8×6 的矩阵来裁剪重测（gate × 变更类型）。这里只给结论：

全量重测=8×28=224 次⟶按矩阵裁剪=115 次（节省 48.66%）

7.4 失效条件与边界#

  1. 有效期是"两条约束取 min"：min(T对手增长​,T下一次变更​)。第 4 节会看到在合成参数下变更节奏比对手增长紧得多（30.4 天 vs 1675.0 天），所以重测是"跟着变更走"。
  2. g 的估计应当来自实测（例如每次重测时比较同一条攻击的成功率变化）。如果拿不到，就应把有效期设成"下一次重测"而不是"某个年数" —— 后者的风险是它变成一句没有内容的承诺。
  3. 门禁表必须带"签发日期 + 有效期 + 下次重测触发条件"，否则它无法被审计（第 4 章 §1 的可证伪与可动作两条判据）。

    return sum(2 if unicodedata.east_asian_width(ch) in "WF" else 1 for ch in s)

    d = width - w(s)
    if d <= 0:
        return s
    return (" " * d + s) if right else (s + " " * d)


def row(items, widths, rights=()):
    return "  " + "  ".join(pad(str(v), wd, i in rights) for i, (v, wd) in enumerate(zip(items, widths)))


def pct(x, nd=2):
    return ("%." + str(nd) + "f%%") % (100.0 * x)

        说不出 g 从哪来，就等于承认门禁没有有效期，也就等于承认它会悄悄过期。

小结#

  • 门禁是六元组：(统计量,阈值,n,α,判定规则,失效时间)。缺任何一个，它就无法执行也无法被审计。
  • 八个 gate 里五个是计数型、两个是结构型、一个（能力非劣效）是双侧。结构型 gate 没有抽样误差，只有遗漏误差 —— 清单不全时 n 是下界，"多测几次"对它无效。
  • 零成功上界按 1/n 收缩：U∗=0.010→299 次、0.005→598 次、0.001→2994 次。反向读：n=100 全失败只能声明 U=0.029513（比目标宽 2.95 倍）。
  • 重复采样不算独立样本：60 个用例各采 5 次在 ρ=0.15 时只等于 187.5 个独立样本，能声明的上界从 0.009936 退化到 0.015850（放宽 59.5%）。报告必须同时给 ncases​、k 与 ρ。
  • 判定器自己必须先过门禁：Sp≥0.99 要 299 条阴性对照，Sp≥0.999 要 2995 条；而 Se≥0.90 只要 29 条 —— 阴性对照难造、阳性样本易造，这个不对称直接决定评测预算分配。未校准的读数在 p=0.01,Sp=0.99 时只有 47.62% 是真的。
  • 结构型 gate 的清单质量需要抽样核对：抽 20 行全对只能声明质量 ≥0.8609；要声明 ≥0.95 得抽 59 行。它证明的是清单写得对，不是系统安全。
  • 等价界必须事前写死：τ 从 0.03 收到 0.01 样本量涨 9.00 倍；每臂 200 条时 MDE 是 0.070647 —— 那时"能力没变差"不可证伪，只能报 MDE。
  • 八个 gate 的 FWER=0.336580，Bonferroni 让样本量膨胀 1.9463 倍。串行检出率取决于是否读同一批证据：独立口径 0.999972、共线口径 0.998800。
  • 选择效应把"挑最好的"拉到 1/n：(n=30,M=30) 与 (n=30,M=100) 都报 0.0333（真实 p=0.01）；而 p=0.05 时反而低估（0.0167）。判据：报告里的成功率若 ≈1/n，就要怀疑它是选择效应的产物；处理靠分裂样本。
  • "门禁该多严"是一个价格问题：漏放概率只有 2.835×10−5，期望损失几乎全由误阻构成；α 从 0.05 收到 0.01 让误阻损失从 9087.6 掉到 2085.9 元，代价是样本量 ×1.7272。人工复核把误阻单价从 30000 降到 8500 元/次，但抬到 α=0.20 反而更差 —— 复核改的是斜率，不是许可证。
  • 门禁会过期：T=ln(U∗/U0​)/ln(1+g)（⚠️ 推测模型）在 g=0.30,U0​=0.003 时约 4.59 年，U0​=0.008 时只剩 0.85 年 —— 余量就是有效期。且有效期取 min(T对手​,T下一次变更​)。
  • 本节交付物四件：① §一 的八 gate 总表；② §二–§四 的四类判据各自的样本量公式与算例；③ §五 的 FWER/共线/选择效应三重校正；④ §六–§七 的发布决策期望损失表与有效期。

下一节：本节把上线的那一刻管住了，但门禁是一次性的 —— 它证明"某一天、某个版本、在某批证据上"达标，而系统此后每天都在变。第 4 节处理运营期：把四类信号接到第 1 章 R 的某一项上；用精确马尔可夫链解算 CUSUM 的 ARL（k=3,h=6 时 ARL0​=434.95 天、对 2 倍漂移 ARL1​=6.19 天，而 Shewhart 图要 9.2 天，且漂移放大到 3 倍以上两者趋同）；把"收紧还是放宽"写成四个动作的期望损失最小化，解出后验概率分区 0.009901/0.062500/0.464286（熔断门槛比收紧高 7.4 倍）；把事故复盘变成可检验量（闭环率 0.7500 但复发率 0.4444）；最后用变更影响矩阵决定重测周期。一句话：第 3 节回答"能不能上线"，第 4 节回答"上线之后怎么不烂掉"。
