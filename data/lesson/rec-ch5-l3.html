粗排与精排#

召回捞出了几千个候选，精排模型又重又慢，没法对几千个候选逐一精算。于是工业界在召回和精排之间再插一层粗排，用轻量模型先砍掉大部分候选。本课把"粗排—精排—重排"这条链路讲清楚，重点解释为什么中间要加粗排、粗排怎么设计，以及各阶段之间怎么保持目标一致。

一、概念讲解#

1. 完整的漏斗：每一层都在"用精度换速度"#

把前几课串起来，推荐系统的排序链路是一个层层收紧的漏斗：

召回（百万 → 数千）→ 粗排（数千 → 数百）→ 精排（数百 → 数十）→ 重排（数十 → 最终展示）

每一层的模型越来越重、越来越准，但能处理的候选量越来越小。这个设计背后是一条朴素的工程经济学：算力有限，时延有上限。精排模型（DeepFM、DIN）一次前向可能涉及几百上千个特征，还要过几层网络，跑几千次会超时，所以只能留给"最可能是正确答案"的几百个候选。而召回阶段要面对百万级物品，只能用双塔内积这种极轻的打分。

问题的关键在中间：召回给精排的候选可能有两三千个，精排吃不下；但直接让召回把候选砍到几百个，又会漏掉好物品。 粗排就是为这个矛盾而生——它比召回更准、比精排更快，负责把"数千"先压到"数百"，让精排聚焦在高质量候选上。

2. 粗排怎么设计：既要快，又要和精排"对齐"#

粗排的候选量是数千级，时延预算比精排宽松一点、比召回紧一点。常用的粗排方案有几种：

  • 双塔内积粗排：直接复用向量召回的双塔，但候选量小到可以直接暴力算内积（不必 ANN），用内积分排序过滤。这是最轻量的粗排，几乎零额外成本。
  • 轻量特征版 LR / 浅层网络：用一个特征少、结构浅的模型（如少量特征的 LR 或两三层 MLP）做粗排，快但表达能力有限。
  • 知识蒸馏粗排：让一个轻量"学生模型"去拟合精排"教师模型"的打分，用更小的算力逼近精排的排序结果。这是近年提升粗排精度的主流手段。

粗排最容易被忽视、却最关键的问题是与精排的一致性。粗排如果把精排"本来会给高分"的候选误杀，那么精排再准也救不回来——因为候选已经没了。所以要刻意保证：粗排和精排的优化目标一致（都朝点击/转化优化）、特征口径一致、排序偏好一致。蒸馏正是一种"显式地对齐粗排与精排"的方法：学生模型的训练目标就是教师模型的分数，天然保证了两者偏好同向。

3. 精排：重模型的"最终裁决"#

精排是漏斗里模型最重、特征最全的一层，前面第 4 章的 GBDT+LR、DeepFM、DIN 都用在精排。精排的目标是把粗排筛出的几百个候选，按 pCTR（以及转化、时长等多目标）精确排序。它和粗排的核心区别在表达能力：

  • 精排可以做用户与物品的全程特征交叉（不像双塔只在最后内积）。
  • 精排可以吃序列特征（用户历史行为序列 + 注意力）。
  • 精排可以做多目标融合（点击率、转化率、时长、多样性加权成一个最终分）。

精排的输出通常是一个带分数的候选列表，交给最后一层重排。

4. 重排：在"准"之外补上"体验与业务"#

精排只关心"单个物品被点击的概率"，但真实的推荐流还要考虑列表整体的体验。重排（rerank）在这一步做精排之外的规则与优化：

  • 多样性：避免同一个类目/作者霸屏，把相似物品打散（如 MMR 最大边际相关算法）。
  • 业务规则：广告插入位置、新物品保底曝光、已读内容过滤、敏感内容规避。
  • 序列优化：考虑物品之间的互补与替换（比如看完手机推荐手机壳）。

重排把"单点最优"修正为"列表最优"，是纯模型打分到业务落地之间的最后一道桥。

二、可运行示例#

示例 1：模拟"粗排 + 精排"两阶段筛选#

先生成几千个候选，用轻量内积粗排砍到几百，再用一个更精细的打分函数精排到最终 topK，直观看到两阶段如何分工。

import numpy as np

np.random.seed(0)
n_cand = 2000          # 召回后的候选量
user_vec = np.random.randn(16)
user_vec /= np.linalg.norm(user_vec)

# 候选物品：每个有一个"粗排向量"和一组"精排特征"
item_vecs = np.random.randn(n_cand, 16)
item_vecs /= np.linalg.norm(item_vecs, axis=1, keepdims=True)
item_feats = np.random.randn(n_cand, 4)     # 精排用的 4 个特征

def coarse_score(user_vec, item_vecs):
    """粗排：内积打分，快。"""
    return item_vecs @ user_vec

def fine_score(idx, user_vec, item_vecs, item_feats):
    """精排：内积 + 特征的非线性组合，更重但更准。"""
    sim = item_vecs[idx] @ user_vec
    f = item_feats[idx]
    return sim * 2.0 + (f[0] * f[1]) + np.tanh(f[2] + f[3])   # 精细的非线性打分

# 第一段：粗排把 2000 砍到 300
coarse = coarse_score(user_vec, item_vecs)
coarse_top = np.argsort(-coarse)[:300]

# 第二段：精排对 300 个算精细分，取 top10
fine = np.array([fine_score(i, user_vec, item_vecs, item_feats) for i in coarse_top])
fine_top_idx = coarse_top[np.argsort(-fine)[:10]]

print("候选总数:", n_cand)
print("粗排后候选:", len(coarse_top))
print("精排最终 top10:", fine_top_idx.tolist())

# 对比：若跳过粗排直接精排全部候选，计算量是粗排后精排的约 6.7 倍
print("跳过粗排的精排计算量 / 有粗排的精排计算量 =", round(n_cand / len(coarse_top), 1))

示例 2：多样性重排（MMR 打散）#

精排给了 top 结果，但可能全是同一个类目。用 MMR 的思路在"相关性"和"多样性"之间做平衡。

import numpy as np

# 精排 top10 的物品：每个有相关分数和类目 id
scores = np.array([0.95, 0.93, 0.90, 0.88, 0.85, 0.80, 0.78, 0.75, 0.70, 0.65])
cats   = np.array([0, 0, 0, 0, 0, 1, 1, 2, 2, 3])   # 前 5 个都是类目 0，明显霸屏

def mmr_rerank(scores, cats, lam=0.5, k=6):
    """MMR：每一步选 '相关性 - λ·与已选物品的最大类别重叠' 最大的候选。"""
    n = len(scores)
    selected, remain = [], list(range(n))
    for _ in range(k):
        best, best_val = None, -np.inf
        for idx in remain:
            rel = scores[idx]
            div = max((1.0 if cats[idx] == cats[s] else 0.0) for s in selected) if selected else 0.0
            val = lam * rel - (1 - lam) * div
            if val > best_val:
                best, best_val = idx, val
        selected.append(best)
        remain.remove(best)
    return selected

order = mmr_rerank(scores, cats, lam=0.6, k=6)
print("重排顺序(下标):", order)
print("重排后类目序列:", [cats[i] for i in order])
# 原始 top6 全是类目 0，重排后类目被有效打散

三、练习#

  1. 在示例 1 中，把粗排保留的候选量从 300 改成 50，观察最终 top10 与"粗排保留 300"时的差异，说明"粗排砍太狠会漏掉精排高分候选"这一风险。
  2. 用一句话分别概括粗排、精排、重排各自优化的目标，以及它们"精度—速度"的定位差异。
  3. 解释为什么"知识蒸馏"能同时提升粗排精度又保证它与精排目标一致；学生模型的训练目标是什么？
