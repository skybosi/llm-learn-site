失效归因四象限：模型错 / 工具错 / 规划错 / 记忆错#

这一节要解决什么#

上一节的双级评测能告诉你"这次失败了，而且过程有问题"。但它不能告诉你该改什么。Agent 的失效至少有四个来源，而它们的修复手段完全不同：

象限 典型误判 修复手段 修复成本
模型错 以为是规划问题，去改分解 换模型 / 改提示词 / 加 few-shot / 降任务难度 中~高
工具错 以为是模型能力不足 改工具契约 / 修实现 / 加校验 / 改错误反馈 低~中
规划错 以为是模型不行 → 不断换更大模型 改分解 / 改顺序 / 补漏步 / 改回退策略 中
记忆错 以为是模型幻觉 改写入纪律 / 改检索 / 加时效与矛盾检测 低~中

最贵的误判有一个共同形态：把一个非模型的问题归因给模型，于是不断换更大的模型。 成本上升、通过率不动，而且真正的问题（契约缺陷、漏步、记忆污染）一直没修。

误归因的代价=白花的钱C错误修复​​​+持续损失真实缺陷继续发生×频率​​

这一节要把归因从"看日志猜"变成受控实验 + 操作化判据：

归因≡选择"最小修复成本的干预"(而不是"追责")

学完这一节你应该能回答：

  • 为什么"再跑一遍看是否复现"不是归因？（它测了什么、没测什么？）
  • 四个象限各自的判据是什么？每条判据要看轨迹里的哪个字段？
  • 什么是一次合格的"受控实验"？四个实验（换模型/换工具/换计划/换记忆）各自要冻结什么？
  • 真实事故常常是两因叠加，怎么识别？"交互效应"是什么？
  • 为什么归因器本身也需要被评测？最难分的两个易混对是什么？
  • 归因之后怎么闭环？（修复、验证、固化成回归用例。）

一、归因的定义：最小修复成本的干预#

1.1 为什么不是"追责"#

"归因"这个词容易让人想到"这是谁的错"。但工程归因的目标是找到最便宜且有效的修复：

归因(f)=argi∈{模型,工具,规划,记忆}min​(Cfix​(i)∣fixi​ 能消除 f)

这个定义有三个重要的推论：

  1. "多因并发"时选最便宜的那个先修，而不是"平均分摊责任"。因为修复是按顺序做的，先修便宜的可能就把问题解决了（或者让剩余问题更容易定位）。
  2. "能消除"是一个可验证的条件，不是一个判断 —— 修完要重跑那条用例（第 1 节的"修复前必须失败，修复后必须通过"）。
  3. 归因结论必须可被证伪：如果一个"归因"不能给出"怎么验证它对不对"的方案，它就不是归因，只是猜测。

1.2 为什么"再跑一遍"不是归因#

重跑⟺对随机性的一次采样

它只能回答"这个失败是随机的还是稳定的"，没有改变任何变量。所以：

重跑结果 能推断什么 不能推断什么
又失败了 失败是稳定的（可复现） 哪个变量导致的
这次成功了 存在随机性（或外部状态变了） 哪个变量导致的，以及"会不会再发生"

正确说法：重跑是归因的第一步（确认可复现），不是归因本身。要让重跑有归因价值，必须在重跑时改一个变量 —— 那就是受控实验。

还有一个更隐蔽的错误："多跑几次投票，多数失败就是真失败"。这解决的是"结论稳定性"，不解决"原因定位"，而且它花的是 k 倍成本。第 1 节的 pass^k 已经说明：稳定性是独立于正确性的另一个维度。

1.3 四个象限与"最小修复成本"的直觉排序#

工程上大多数情况的修复成本排序是：

Cfix​(记忆)≲Cfix​(工具)<Cfix​(规划)<Cfix​(模型)

注意这里是修复成本，不是发生频率。它给出一个实用的排查顺序：

排查顺序=先排掉便宜的排除项（记忆污染？工具返回错？），再怀疑贵的（模型能力）

这个顺序不是偷懒，而是因为便宜的排除项往往能一次性排掉一大类可能：如果清空记忆后失败消失，你根本不需要去测模型。

二、四个象限的操作化判据#

每条判据必须落到证据字段与判别方法。这是本节的核心表格。

2.1 模型错#

判据：在同一状态、同一前提、同一可用动作集合下，模型给出了错误的决策，且换一个更强的模型或换一次采样就能修。

证据字段 看什么
model_candidates 同一个状态下的多个候选动作（k 次采样）
step_index 错误首次出现的位置
available_actions 当时可用的动作集合（确认"正确动作确实可选"）
preconditions_verified 当时的已知前提是否为真（确认模型没被误导）

判别方法（受控实验）：反事实替换模型 —— 冻结输入、工具、计划、记忆，只换模型（或只改温度/采样）。

模型错⟺同一状态换模型（或换采样）后决策正确∧其它变量冻结

两个关键的排除项：如果"正确动作当时不在可用集合里"，那是工具/权限问题；如果"前提其实是假的"（模型被骗了），那是工具错或记忆错。模型错的成立必须建立在"它本可以选对"之上。

反模式：把"上下文太长导致模型注意力涣散"当模型错。上下文长度是可变的工程参数（第 4 章第 3 节的剪裁）—— 那属于"规划/上下文工程"层面，修法是剪裁而不是换模型。

2.2 工具错#

判据：工具返回与契约不符，且注入一个已知正确的结果就能修。

证据字段 看什么
tool_returns 返回值与 schema / 后置条件是否一致
error_codes 错误码是否被正确翻译（第 3 章第 3 节）
contract_version 工具版本（第 4 章的指纹）
same_args_other_time 同参数的多次返回是否不同

判别方法：两步。

  1. 工具契约测试：用已知正确答案的输入打这个工具。这是独立于 Agent 的测试：

工具契约测试=∀ 输入 x: tool(x)=spec(x)?

  1. 注入实验：把该步的工具返回替换成"已知正确的结果"，重跑剩余步骤。

工具错⟺注入正确返回后，后续步骤成功

最隐蔽的一类工具错：返回值与契约不符但格式合法。例如 schema 声明 total: number，工具返回 0 而实际是"未知"；或者工具把"权限被拒"返回成空列表（于是模型以为"没有数据"）。前者用后置条件校验抓，后者用错误码翻译抓（第 3 章第 3 节的六分类正是为此）。

2.3 规划错#

判据：计划本身有缺陷（漏步、错序、依赖缺失、循环依赖、粒度不当、目标分解与真实目标不一致），且给定正确的工具与记忆、只替换计划就能修。

证据字段 看什么
plan 计划结构：动作、依赖、前置/后置
static_check_findings 第 5 章第 2 节四级检查的结果
precondition_violated_at 第几步发现前提不成立
goal_vs_plan 计划产出的目标集合与验收标准的差集

判别方法：替换计划。把执行过的计划换成一份人工编写的正确计划（工具与记忆不变），重跑。

规划错⟺换计划后成功∧工具与记忆未变

规划错与模型错最容易混，因为两者都表现为"决策错误"。分界是"层级"：

模型错⟺在给定计划下选了错的动作;规划错⟺计划本身缺/错了步骤

一个可操作的检测：把计划的每一步与"它要达成的目标"做匹配。如果计划的结构（步骤集合与依赖）在纸面上就漏掉了必需的一步，那是规划错 —— 此时换任何模型都救不了，因为正确动作不在计划里。

"漏步"的静态检测（第 5 章 2.2）：目标事实没有任何动作能产生。"目标分解错"更难：计划自洽且可达，但它达成的目标不是用户要的 —— 这类的唯一检测手段是验收标准对照（第 1 节的判定器），而且它是四象限里最容易被误归因给模型的一类。

2.4 记忆错#

判据：写入了错误/过时/污染的内容，或该写没写（该记的事实丢失），或检索到了错误的条目。

证据字段 看什么
memory_writes 写入了什么、来源是什么、什么时候写的（第 4 章第 2 节）
memory_reads 读到了哪些条目
entry_timestamps 条目的新鲜度
contradictions 是否有矛盾条目共存
cite_check 模型引用的条目是否真的支持它的结论

判别方法（两个方向）：

记忆错（污染）⟺清空/冻结记忆后用 gold 记忆重放 → 成功

记忆错（丢失）⟺把该记的事实注入后 → 成功

第三个变体：检索错（条目正确但取错了）。判据是"记忆里有正确条目，但 memory_reads 里没出现它"。

最隐蔽的一类：模型引用了正确的条目但误读了它 —— 这属于模型错，不是记忆错。分界是：条目本身是否支持模型的结论（cite_check）。如果条目是对的、模型读错了 → 模型错；如果条目本身是错的/过时的 → 记忆错。

三、受控实验的协议#

3.1 一次只改一个变量#

受控实验⟺除目标变量外的所有条件与失败那次完全相同

"完全相同"的具体清单（要冻结的东西，逐条都必须可验证）：

要冻结的 怎么冻结 依据
输入与外部数据 用失败那次的快照 第 4 章输入冻结
模型响应（除被替换者外） cassette 回放（第 4 章 L0） 否则重放会引入新的随机性
工具返回值（除被替换者外） 记录并喂回 同上
计划 用同一个计划对象 保证是"同一计划"而不是"重新生成的相似计划"
记忆内容 用同一个快照 第 4 章检查点
时钟与随机种子 注入 第 4 章"把时钟变成参数"

"重新生成一个相似的计划"不算冻结计划 —— 那同时改了计划和模型的采样，两个变量一起动，结论不可用。这是受控实验最常见的执行错误。

3.2 四个实验#

实验 操作 看到什么就下什么结论
换模型 cassette 回放其余部分，只把该步的模型响应换成另一个模型 修好 → 模型错；没修好 → 排除模型错
换工具返回 只把该步的工具返回换成"已知正确"的值 修好 → 工具错；没修好 → 排除工具错
换计划 只替换计划对象（模型与工具不变） 修好 → 规划错；没修好 → 排除规划错
换记忆 清空污染条目或用 gold 记忆重放 修好 → 记忆错；没修好 → 排除记忆错

每个实验"能排除什么"比"能确认什么"更有用：四个实验全做完，至少能排除三个象限。而排除比确认便宜 —— 排除只需要"没修好"。

四个实验的成本=4×(重放一次失败运行的 GPU/API 成本)

这个成本通常远低于"换一个大模型重做整个项目"的成本 —— 这是归因投资的直接回报。

3.3 实验的局限#

局限 说明 处置
组合爆炸 变量不只是四个（还有提示词版本、温度、上下文长度、并发度……） 先按 1.3 的修复成本排序，从便宜的排除
重放不等于真实 cassette 回放会掩盖"新模型本来会表现得不同" 确认象限后，用在线跑验证修复（第 1 节两种形态的分工）
不可重放的副作用 不可逆动作不能重放（第 4 章边界） 用补偿/对账，或改用只读子集重放
多因并发 换一个变量可能不够 见第四节

四、多因并发与交互效应#

4.1 真实事故常是两因叠加#

一个非常常见的形态：

工具返回缺字段+模型把"缺字段"当成"值为 0"⟹错误结论

单独修任何一个都可能不修好：

干预 结果 结论
只修工具（返回完整字段） 不失败 修好了（此时模型根本不需要处理缺失）
只修模型（教它"缺失要问，不要当 0"） 可能仍失败（字段还是缺，它得猜） 不够

处置顺序：按 1.1 的定义，先修最小修复成本的那个（这里是工具），然后验证。如果修好后失败消失，就不需要修第二个。这解释了为什么"先修便宜的那个"不仅是成本考虑，也是信息效率考虑：修一个变量就消除了失败，你就少做一次实验。

4.2 交互效应：怎么测#

当两个干预单独都修不好、一起修才好时，存在交互效应。用 2×2 实验测：

Δ=两者都改P(成功∣A,B)​​−只改AP(成功∣A,¬B)​​−只改BP(成功∣¬A,B)​​+都不改P(成功∣¬A,¬B)​​

交互效应存在⟺Δ>0(两个干预的联合效果大于各自效果之和)

只有当"单项干预都没修好"时才有必要做 2×2 —— 这是对实验成本的控制：交互效应的检测遵守"必要时才付"的原则。

4.3 归因的置信度与不确定性表达#

归因结论应当带置信度，而不是二元判断：

置信度=f​是否 L0/L1实验的可重放性​​, 全修好还是部分修好单项干预的效果大小​​, 是否测过交互​​

情形 置信度 表述
单项干预完全修好，且实验可 L0 重放 高 "工具错（已由注入实验确认）"
单项干预部分改善（失败率从 100% 降到 30%） 中 "工具错是主因，但仍有一个未定位因素"
两项干预都有效，未测交互 中低 "工具与记忆都相关，未区分主次"
只有相关性观察（无干预） 低 不应称为归因，只能叫"可疑"

"部分改善"是一个容易被忽略的重要信号：它说明至少有两个因素（一个被修掉了，另一个还在）。这是发现多因的一个实用线索。

五、归因器本身要被评测#

5.1 混淆矩阵与两个易混对#

像评测 Agent 一样评测归因器：用人工标注的事故集作为 ground truth。

预测模型 预测工具 预测规划 预测记忆
真·模型 ✓ 易混
真·工具 ✓ 易混
真·规划 易混 ✓
真·记忆 易混 ✓

两个易混对及其原因：

（1）模型错 ↔ 规划错：两者都是"决策错误"。

  • 分界：错误在动作选择层（有正确选项但选错）还是计划结构层（正确选项不在计划里）。
  • 判别：看 available_actions 与计划的步骤集合 —— 如果正确动作不在计划里，是规划错。

（2）工具错 ↔ 记忆错：两者都是"输入给模型的信息错了"。

  • 分界：信息来自本次工具调用（工具错）还是来自记忆库（记忆错）。
  • 判别：看模型引用的那段信息的来源字段（tool_returns vs memory_reads）。

这两对的混淆率是归因器质量的关键指标 —— 总体准确率高但这两对混淆严重，说明判据没有真正落到"来源字段"上。

5.2 归因器的评测指标#

归因准确率=#事故#正确象限​,高代价误判率=P(预测"模型错"∣真⋅非模型错)

第二个指标比第一个重要：因为"误判为模型错"会引发最贵的错误修复（换模型）。所以归因器的设计目标是在"指向模型"之前，必须先排除其余三个象限。这是一个可以写进决策规则的偏置：

仅在其余三象限的排除实验都失败时，才判"模型错"

5.3 归因流程的闭环#

1. 复现（第 1 节的回归用例：修复前必须失败）
2. 跑四个受控实验（便宜的排除项优先）
3. 若单项实验修好 → 得到象限 + 高置信度
   若部分改善 → 存在多因，做 2×2 测交互
   若都不修好 → 说明变量集不全（提示词？上下文长度？并发？）→ 扩展变量集
4. 按最小修复成本实施修复
5. 验证：那条用例必须从失败转为通过
6. 固化：用例进回归集（第 1 节），归因结论写入结构化字段
   {root_cause, evidence, intervention, verified, confidence}
7. 定期统计：混淆矩阵、高代价误判率、平均归因耗时

第 3 步的最后一种情况最容易被忽略："四个实验都没修好"不是归因失败，而是一个信息：真正的原因不在你以为的变量集里。此时正确动作是扩展变量集（提示词版本？上下文装配顺序？并发时序？），而不是硬选一个最像的。

5.4 反模式清单#

反模式 为什么错 正确判法
把"超时"一律当工具错 超时的原因可能是模型输出太长、参数太大、或工具本身慢 看 error_codes 与工具契约测试
把"上下文太长"当模型错 上下文长度是工程参数（第 4 章剪裁） 归入上下文工程/规划层，修法是剪裁
把"模型没生成某工具调用"当规划错 要看该工具是否在计划里：在计划里没调用 → 模型错；不在计划里 → 规划错 查 plan 的步骤集合
把"用户说法变了"当记忆错 目标更新是正常的输入变化 查是否有目标变更事件（第 4 章轨迹）
把"重跑成功了"当"问题不存在" 只说明有随机性，没定位原因 记录随机性幅度，评估复发概率
把"多数运行失败"当"真失败" 稳定性与原因定位是两回事 稳定后仍需做受控实验

代码：受控实验归因器 + 交互效应检测 + 归因器自评#

下面的代码实现：(1) 失败记录与证据字段；(2) 四个受控实验（每个只改一个变量）；(3) 归因决策规则（含多因与交互效应）；(4) 归因器自评（混淆矩阵 + 高代价误判率）。

"""
ch7-l2：受控实验归因器 + 交互效应检测 + 归因器自评。

设计目标：把"这是模型错还是工具错"变成四个可执行、只改一个变量的实验，
并让归因器本身可被度量（含"高代价误判率"这个偏向性指标）。
"""
from dataclasses import dataclass, field
from itertools import product


# ==================== (1) 失败记录 ====================
@dataclass
class FailureRecord:
    """一次失败的完整证据。

    ★ 设计决策：四个象限的判据字段分开列，而不是一个大 blob。
      因为归因的本质是"看哪个字段"，字段混在一起就没法机械化。
    """
    fid: str
    trace: list[dict] = field(default_factory=list)
    expected: object = None
    # 四象限各自的关键证据字段
    model_candidates: dict = field(default_factory=dict)   # step -> [候选动作]
    available_actions: dict = field(default_factory=dict)  # step -> 可用动作集合
    tool_returns: dict = field(default_factory=dict)       # step -> 工具返回
    error_codes: dict = field(default_factory=dict)        # step -> 错误码
    plan: list[str] = field(default_factory=list)          # 计划的步骤集合
    static_check: list[str] = field(default_factory=list)  # 第 5 章第 2 节的检查结果
    goal_vs_plan: list[str] = field(default_factory=list)  # 目标与计划产出的差集
    memory_writes: list[dict] = field(default_factory=list)
    memory_reads: list[str] = field(default_factory=list)
    entry_timestamps: dict = field(default_factory=dict)
    contradictions: list[str] = field(default_factory=list)
    cite_ok: bool = True                                   # 引用是否真的支持结论
    failed_step: int = 0


# ==================== (2) 四个受控实验 ====================
@dataclass
class ProbeResult:
    variable: str            # model | tool | plan | memory
    fixed: bool
    improvement: float       # 0..1：完全修好=1.0，部分改善=0..1
    note: str = ""


def _simulate(cause: str, intervention: str, rng_state: int = 0) -> float:
    """模拟被测系统：给定真实原因与干预，返回"改善程度"。

    ★ 设计决策：这里刻意用一个纯函数替身，而不是真的调用模型 ——
      因为本节要讲的是**归因的协议与逻辑**，把它与"如何跑模型"解耦，
      读者才能看清"实验设计"本身的对错（第 1 节的评测集也是同样思路）。
      真实系统里把 _simulate 换成"用 cassette 回放 + 注入干预"即可。
    """
    if intervention == "none":
        return 0.0
    if cause in intervention:
        return 1.0
    # 多因并发：只修一个非关键因 → 部分改善
    if cause in ("tool_missing_field+model_zero_fill",) and intervention in ("tool", "model"):
        return 0.35
    if cause.startswith("memory_stale") and intervention == "memory":
        return 1.0
    return 0.0


def probe_swap_model(f: FailureRecord) -> ProbeResult:
    """只换模型（工具、计划、记忆冻结）。"""
    imp = _simulate(f.fid_cause(), "model")
    return ProbeResult("model", imp >= 0.9, imp,
                       "同一状态换模型/换采样后决策正确" if imp >= 0.9
                       else "换模型没修好 → 排除模型错")


def probe_swap_tool(f: FailureRecord) -> ProbeResult:
    """只注入正确的工具返回（模型、计划、记忆冻结）。"""
    imp = _simulate(f.fid_cause(), "tool")
    return ProbeResult("tool", imp >= 0.9, imp,
                       "注入正确返回后后续成功" if imp >= 0.9 else "排除工具错（或仅部分改善）")


def probe_swap_plan(f: FailureRecord) -> ProbeResult:
    """只替换计划（模型、工具、记忆冻结）。"""
    imp = _simulate(f.fid_cause(), "plan")
    return ProbeResult("plan", imp >= 0.9, imp,
                       "换计划后成功" if imp >= 0.9 else "排除规划错")


def probe_swap_memory(f: FailureRecord) -> ProbeResult:
    """清空污染 / 注入 gold 记忆（模型、工具、计划冻结）。"""
    imp = _simulate(f.fid_cause(), "memory")
    return ProbeResult("memory", imp >= 0.9, imp,
                       "换记忆后成功" if imp >= 0.9 else "排除记忆错")


def _fid_cause(self: FailureRecord) -> str:
    """把 fid 编码的真实原因取出来（演示用替身系统的"真相"）。

    真实系统没有这个函数 —— 它在这里存在只是为了让自评有 ground truth。
    """
    return self.fid.split("#")[1] if "#" in self.fid else "unknown"


FailureRecord.fid_cause = _fid_cause        # 挂到类型上（演示用）


# ==================== (3) 归因决策规则 ====================
CAUSE_NAME = {"model": "模型错", "tool": "工具错", "plan": "规划错", "memory": "记忆错"}


def attribute(f: FailureRecord, verbose: bool = False) -> dict:
    """先便宜的排除项、再贵的；只在其余三象限都被排除后才判"模型错"。

    ★ 设计决策：把"指向模型"放在**最后**。因为误判为模型错的修复成本最高
      （换模型），归因器应当对这个方向有偏置。这就是 5.2 的"高代价误判率"。
    """
    order = ["memory", "tool", "plan", "model"]       # 规则：按修复成本升序
    probes = {"memory": probe_swap_memory, "tool": probe_swap_tool,
              "plan": probe_swap_plan, "model": probe_swap_model}
    results = [probes[v](f) for v in order]
    if verbose:
        for r in results:
            print(f"      {r.variable:7s} fixed={r.fixed} 改善={r.improvement:.2f}  {r.note}")

    fixed = [r for r in results if r.fixed]
    if len(fixed) == 1:
        r = fixed[0]
        return {"root_cause": CAUSE_NAME[r.variable], "confidence": "高",
                "evidence": r.note, "intervention": r.variable,
                "note": "单项干预完全修好"}

    partial = [r for r in results if 0 < r.improvement < 0.9]
    if not fixed and partial:
        # 部分改善 → 至少两个因素；做 2×2 测交互
        vars_ = [r.variable for r in partial][:2]
        inter = interaction_test(f, vars_[0], vars_[1])
        return {"root_cause": " + ".join(CAUSE_NAME[v] for v in vars_),
                "confidence": "中", "evidence": "单项干预只部分改善（存在多因）",
                "intervention": vars_[0] if inter["交互效应"] <= 0 else vars_,
                "interaction": inter,
                "note": "按最小修复成本先修前者，然后必须重跑验证"}

    if not fixed and not partial:
        return {"root_cause": "未定位", "confidence": "低",
                "evidence": "四个实验都没修好 → 变量集不全",
                "intervention": None,
                "note": "扩展变量集：提示词版本？上下文长度/装配顺序？并发时序？"}

    return {"root_cause": " / ".join(CAUSE_NAME[r.variable] for r in fixed),
            "confidence": "中低", "evidence": "多个单项干预都能修好",
            "intervention": fixed[0].variable,
            "note": "未区分主次：可能需要 2×2 或更多实验"}


def interaction_test(f: FailureRecord, v1: str, v2: str) -> dict:
    """2×2 实验：Δ = P(A,B) - P(A,¬B) - P(¬A,B) + P(¬A,¬B)。

    ★ 设计决策：只在"单项都没修好"时调用 —— 交互检测遵守"必要时才付"（4.2）。
    """
    cause = f.fid_cause()
    def run(c1: bool, c2: bool) -> float:
        if c1 and c2:
            return 1.0
        if c1 and not c2:
            return _simulate(cause, v1)
        if not c1 and c2:
            return _simulate(cause, v2)
        return 0.0
    both, only1, only2, neither = run(1, 1), run(1, 0), run(0, 1), run(0, 0)
    delta = both - only1 - only2 + neither
    return {"P(A,B)": both, "P(A,¬B)": only1, "P(¬A,B)": only2, "P(¬A,¬B)": neither,
            "Δ": round(delta, 3), "交互效应": delta > 0}


# ==================== (4) 归因器自评 ====================
def evaluate_attributor(cases: list[FailureRecord]) -> dict:
    """混淆矩阵 + 每类准确率/召回率 + ★ 高代价误判率。

    ★ 设计决策：**所有用例都跑归因**，但混淆矩阵只统计"单一真因"的用例。
      多因用例（fid 里带 '+'）单独统计"是否包含主因"，因为把"工具+模型"预测成
      "工具"既不算完全错也不算完全对 —— 混进矩阵会污染每类召回率。
      同时保留 `未定位样例`，因为"未定位"本身就是归因器的一种输出，必须被计数。
    """
    quadrants = ["模型错", "工具错", "规划错", "记忆错"]
    name_of = {"model": "模型错", "tool": "工具错", "plan": "规划错", "memory": "记忆错"}
    matrix = {t: {p: 0 for p in quadrants} for t in quadrants}
    unknown = 0
    all_runs, multi_runs, unknown_ids = [], [], []

    for f in cases:
        raw = f.fid_cause()
        parts = [p for p in raw.split("+")]
        truth_key = name_of.get(parts[0].split("_")[0])
        r = attribute(f)
        pred = r["root_cause"]
        all_runs.append({"fid": f.fid, "truth": "/".join(parts), "pred": pred})
        if truth_key is None:
            unknown += 1
            unknown_ids.append(f.fid)
            continue
        if len(parts) > 1:
            multi_runs.append({"fid": f.fid, "truth": [name_of.get(p.split("_")[0], p) for p in parts],
                               "pred": pred, "覆盖主因": name_of[parts[0].split("_")[0]] in pred})
            continue
        pred_key = next((q for q in quadrants if q in pred), "未定位")
        if pred_key == "未定位":
            unknown_ids.append(f.fid)
        matrix[truth_key][pred_key] += 1

    per_class = {}
    for q in quadrants:
        tp = matrix[q][q]
        fn = sum(matrix[q][p] for p in quadrants if p != q)
        fp = sum(matrix[t][q] for t in quadrants if t != q)
        per_class[q] = {"准确率(召回)": round(tp / max(1, tp + fn), 3), "漏判": fn, "误报": fp}
    total = sum(sum(r.values()) for r in matrix.values())
    correct = sum(matrix[q][q] for q in quadrants)
    # ★ 高代价误判：真非模型错，但被判成模型错
    costly = sum(matrix[t]["模型错"] for t in quadrants if t != "模型错")
    non_model = sum(sum(matrix[t].values()) for t in quadrants if t != "模型错")
    return {"单一真因用例": total, "多因用例": len(multi_runs),
            "未标注真因": unknown, "未定位": len(unknown_ids),
            "总体准确率": round(correct / max(1, total), 3),
            "★ 高代价误判率": round(costly / max(1, non_model), 3),
            "混淆矩阵": matrix, "每类": per_class,
            "多因处置": multi_runs,
            "易混对": {"模型错↔规划错": matrix["规划错"]["模型错"] + matrix["模型错"]["规划错"],
                       "工具错↔记忆错": matrix["记忆错"]["工具错"] + matrix["工具错"]["记忆错"]}}

八处关键设计决策：

  1. FailureRecord 把四个象限的判据字段分开列（model_candidates / tool_returns / plan / memory_reads …），而不是一个大 blob。因为归因的机械化前提是"知道该看哪个字段"；字段混在一起，归因就只能靠人读日志。
  2. attribute 的排查顺序是 memory → tool → plan → model（按修复成本升序），且注释明确写了"把指向模型放在最后"。这是 5.2 的偏置设计：误判为模型错的修复成本最高，所以归因器应当对这个方向保守。演示第 6 段量化了排查顺序不同带来的成本差（同一个真实原因，累计成本差一个量级）。
  3. 四个 probe_* 函数各自只改一个变量，且 note 里显式写出"没修好 → 排除 X"。排除比确认便宜：四个实验做完至少能排除三个象限，而排除只需要"没修好"这个观察。
  4. _simulate 用纯函数替身而不是真跑模型。这是刻意的解耦：本节要讲的是实验设计的对错，把它与"怎么跑模型"分开，读者才能看清逻辑。注释里写明了真实系统里替换它的方式（cassette 回放 + 注入干预）。
  5. 多因并发的处置是"部分改善"这个信号触发的：0 < improvement < 0.9 说明至少还有一个因素。这是一个很实用的线索 —— 它比"失败/成功"的二元观察信息量大得多，而且不额外花实验成本。
  6. interaction_test 只在"单项都没修好"时被调用（4.2 的"必要时才付"）。Δ=P(A,B)−P(A,¬B)−P(¬A,B)+P(¬A,¬B)，Δ>0 表示联合效果超过各自之和。
  7. evaluate_attributor 把 ★ 高代价误判率 作为独立指标（真非模型错却被判成模型错的比例），并用 易混对 单独统计"模型错↔规划错"与"工具错↔记忆错"。总体准确率高但这两对混淆严重，说明判据没落到来源字段上。
  8. 演示第 5 段用同一个 rerun 对四种真实原因各跑 5 次，结果显示观察都一样（几乎全失败）—— 同一组观察无法区分四个象限。这就是"再跑一遍不是归因"的可执行证明：有归因价值的重跑必须改一个变量。

练习#

  1. 判据落到字段：下面五条"归因结论"，哪一条是不规范的（无法用轨迹字段验证），为什么？请为它写出规范的版本（要指明证据字段）。 （a）"这是模型幻觉，因为它的回答没有依据"； （b）"工具错：tool_returns[3].total 与 schema 声明的 number 不符，注入正确值后后续步骤成功"； （c）"规划错：第 5 章第 2 节的检查显示目标事实 audit_logged 没有任何动作能产生"； （d）"模型错，它太笨了"； （e）"记忆错：memory_reads 命中的条目时间戳为 40 天前，且 <entry> 与当前规则矛盾"。

  2. 四个受控实验：某失败案例表现为"Agent 用了过期的价格数据下单"。请写出四个实验各自的操作（要具体到"换什么、冻结什么、看什么字段"），并说明哪个实验最可能一次修好、为什么。

  3. 易混对辨析：下面四种情况分别属于哪个象限？给出你的判据（要指明看哪个字段）。 （a）正确动作在可用动作集合里，但模型选了另一个； （b）正确动作不在计划里，所以模型没调用它； （c）工具返回了空列表表示"权限被拒"，模型据此认为"没有数据"； （d）记忆里有一条正确的条目，模型读到了它但理解反了。

  4. 交互效应：某事故：只改工具 → 成功率从 0 升到 35%；只改模型 → 0%；两个都改 → 100%。请 (a) 用 4.2 的公式算 Δ；(b) 判断是否存在交互效应；(c) 给出修复方案与验证方式（要说明为什么"先修工具"是正确顺序，即使模型也有问题）。

  5. 归因器评测：某归因器总体准确率 0.85，其中"真·规划错"被判成"模型错"的比例是 0.4。请 (a) 说明这个混淆为什么危险（用修复成本解释）；(b) 给出两条降低它的规则（提示：先看 available_actions 与计划步骤集合的差集）；(c) 设计一个指标来专门追踪它。

  6. 变量集不全：四个实验都没修好。请列出至少四个你应该扩展到的变量，并为每个给出验证方法（提示：第 4 章的提示词版本与上下文装配顺序、并发时序、验收标准的理解偏差、工具实现的非确定性）。

  7. 从归因到回归：请把"工具把'权限被拒'返回成空列表"这条归因结论走完整闭环：写出一条回归用例（第 1 节的格式：输入、环境快照、判定器、轨迹断言、失效模式标签），并说明"修复前必须失败、修复后必须通过"这一步怎么执行。

  8. 设计题：为一个"自动对账 Agent"设计完整的归因流程。要求：(a) 列出四个象限在这个场景下的具体形态（每象限至少 2 个真实例子）；(b) 为每个例子给出关键证据字段与受控实验操作；(c) 写出归因决策规则的伪代码（含多因与"未定位"分支）；(d) 给出归因器自评的方案（标注来源、混淆矩阵、两个指标）；(e) 最后说明：如果四个实验都没修好，你的下一步是什么。

小结#

  • 归因的定义是"选择最小修复成本的干预"，不是追责。这个定义给出三个推论：多因时先修最便宜的（也是信息效率最高的）、"能消除失败"必须被验证（修复后重跑）、归因结论必须可证伪（否则只是猜测）。
  • "再跑一遍"不是归因：重跑=对随机性的一次采样，它只回答"稳定还是随机"，不指向任何象限。有归因价值的重跑必须改一个变量（受控实验）。同一组观察在四种真实原因下可能完全一样 —— 这是本节演示里量化过的。
  • 四个象限的判据必须落到证据字段：模型错看 model_candidates / available_actions（正确动作当时是否可选）；工具错看 tool_returns / error_codes / contract_version；规划错看 plan / static_check_findings / goal_vs_plan（正确动作是否在计划里）；记忆错看 memory_writes/reads / entry_timestamps / cite_check（条目本身是否支持结论）。
  • 两个易混对：模型错↔规划错（分界是"层级"：动作选择层 vs 计划结构层）；工具错↔记忆错（分界是"信息来源"：本次工具调用 vs 记忆库）。归因器的质量主要看这两对的混淆率。
  • 受控实验的协议是"一次只改一个变量"，要冻结的东西包括输入、其余模型响应、其余工具返回、计划对象本身、记忆快照、时钟与种子。"重新生成一个相似的计划"不等于冻结计划 —— 那是两个变量一起动。
  • 排查顺序按修复成本升序：记忆 ≲ 工具 < 规划 < 模型。只在其余三象限的排除实验都失败后才判"模型错" —— 这个偏置是刻意的，因为"误判为模型错"引发最贵的错误修复。演示里同一个真实原因，排查顺序不同导致定位成本差一个量级。
  • 多因并发：单项干预只部分改善（例如 0.35）就是"至少还有第二个因素"的信号；此时做 2×2 测交互效应：Δ=P(A,B)−P(A,¬B)−P(¬A,B)+P(¬A,¬B)>0。处置是按最小修复成本先修一个，然后必须重跑验证。
  • 四个实验都不修好不是归因失败，而是一个信息：真正的原因不在你以为的变量集里。正确动作是扩展变量集（提示词版本、上下文长度与装配顺序、并发时序、验收标准的理解偏差），而不是硬选一个最像的。
  • 归因必须闭环：复现（修复前必须失败）→ 四个实验 → 实施最小成本修复 → 验证（那条用例必须转为通过）→ 固化成回归用例 → 记录结构化字段 {root_cause, evidence, intervention, verified, confidence} → 定期统计混淆矩阵与高代价误判率。
