视频/音频多模态#

前两课的多模态停留在"静止图像 + 文本"。但真实世界的信号还有两个维度：视频（多了一根时间轴）和音频（连续的波形而非离散的像素）。把 LLM 的能力扩展到视频和音频，就是本章最后一课的主题。核心问题是同一个：如何把"会流动"的信号，翻译成语言模型能读的 token 序列？

一、概念讲解#

1. 视频理解：把时间轴"折进" token 序列#

视频 = 一叠按时间排列的帧。要让 LLM 理解视频，主流做法分三步：

  1. 抽帧：从视频里均匀采样 T 帧（例如 8 帧或 32 帧）。帧数太少会漏掉动作，太多则序列过长、显存爆炸。
  2. 逐帧编码：每一帧都像 LLaVA 那样，用视觉编码器切成 patch token。
  3. 时间信息注入：把"这一帧 token 来自第几帧"的信息告诉模型。常见做法是给 token 加时间位置编码，或用额外的"视频级 token"（如 Video-LLaVA 的做法）汇总整段视频的语义。

最终得到一条"帧1 的 patch 们 + 帧2 的 patch 们 + …"的长序列，拼上问题文本，交给 LLM 自回归生成。代表模型有 Video-LLaVA（在投影前先把图像和视频对齐到统一表征）、LLaVA-Video（可处理长达数小时的视频，靠更强的抽帧与时间建模）。

2. 视频生成：扩散模型的时间维度#

视频生成延续了你在扩散模型章节学到的思路，只是把"单张图"升级成"时空块"：

  • Sora（OpenAI）：把视频切成时空 patch（spacetime patches），像 ViT 把图切 patch 一样把视频切成小块，然后用一个 DiT（Diffusion Transformer）在潜空间里做去噪。核心思想是：视频不过是一个"有时间轴的图像"，把 2D 的 patch 机制推广到 3D（宽、高、时间），就能用同一个框架生成。
  • Stable Video Diffusion：以图像扩散模型为底座，加入时间注意力层，从一张静态图"动起来"生成短视频。

技术上最关键的一点是时间一致性：视频的每一帧之间必须连贯，否则就成了"逐帧重画的幻灯片"。这通过时间维度的注意力/卷积来保证。

3. 音频理解：波形 → 声谱 → token#

音频是连续波形，不能直接当 token。理解侧的代表是 Whisper（OpenAI 的语音识别模型）：

  • 把原始音频转成对数梅尔声谱图（log-Mel spectrogram）——一张"时间 × 频率"的二维图；
  • 用卷积把声谱图切成 patch，得到一串音频 token；
  • 交给一个编码器-解码器 Transformer，输出文字。

Whisper 的魅力在于它在一个模型里支持多语言识别 + 翻译 + 时间戳等多种任务，靠的还是"音频 token → 文本 token"这一套自回归框架。更进一步的 Qwen-Audio 则把"音频理解"扩展到更广的任务：不只转写，还能听懂音乐、环境音、情绪，做音频问答。

4. 音频生成：把扩散模型搬到"听"的领域#

音频生成几乎可以照搬图像扩散的范式：

  • AudioLDM：用 CLAP（音频版的 CLIP，把文本和音频对齐到同一空间）做文本条件，用潜空间扩散模型（LDM）在梅尔声谱的潜空间里去噪，再反变换回波形。整个流程和 Stable Diffusion 如出一辙——只是"像素"换成了"声谱"，"CLIP"换成了"CLAP"。
  • Make-An-Audio 等模型进一步支持文本转音频、音频续写等任务。

5. 走向任意到任意：NExT-GPT#

把图像、视频、音频的理解与生成全部接起来，就是 NExT-GPT 这类"任意到任意（any-to-any）"模型：一个 LLM 作为中枢，负责理解输入（各模态经各自编码器变成 token）、推理、再决定输出哪种模态，最后调用对应的扩散模型去生成。它把本课程"LLM 当大脑、扩散模型当画笔"的分工思想推到了最广的边界。

二、可运行代码示例#

示例 1：用 Whisper 做语音识别（音频理解）#

用 Hugging Face 的 pipeline 几行完成语音转文字（首次运行会下载模型）。

from transformers import pipeline

# 自动语音识别 pipeline, 内部加载 Whisper 模型
asr = pipeline("automatic-speech-recognition", model="openai/whisper-small")

# 替换为你的音频文件路径 (支持 mp3/wav/flac 等)
result = asr("your_audio.mp3")
print("识别结果：", result["text"])

Whisper 在内部完成了"波形 → 声谱 → 音频 token → 文本 token"的整条链路，你只需要关心输入音频和输出文字。

示例 2：从零理解"视频抽帧 + 时间位置编码"#

下面用张量实验演示视频多模态的骨架：多帧 patch 拼接 + 时间信息注入。

import torch

# 假设一段视频抽了 T 帧, 每帧切成 P 个 patch, 每个 patch 维度 d
T, P, d = 8, 256, 512
frames = torch.randn(T, P, d)          # (8, 256, 512): 8 帧, 每帧 256 个 patch token

# 1. 时间位置编码: 给每帧的 token 都打上"第几帧"的标记
time_ids = torch.arange(T).view(T, 1, 1).expand(T, P, 1).float()   # (T, P, 1)
frames = torch.cat([frames, time_ids], dim=-1)  # 把时间标记拼进每个 token -> (T, P, 513)

# 2. 把 T 帧按顺序铺平成一条长序列
video_tokens = frames.reshape(T * P, -1)        # (8*256, 513) = (2048, 513)
print("铺平后的视频 token 序列长度:", video_tokens.shape[0])

# 3. (示意) 拼上文本 token 后交给 LLM; 这里只演示拼接维度
text_tokens = torch.randn(32, 513)              # 问题文本的 token (假设已映射到同维度)
full_seq = torch.cat([video_tokens, text_tokens], dim=0)
print("送入 LLM 的完整序列长度:", full_seq.shape[0], "= 视频 2048 + 文本 32")

要点在第 1 步的 time_ids：把"帧编号"显式拼进 token，模型才能区分"画面里同一个人，出现在第 1 帧还是第 8 帧"。这正是视频与静态图像在建模上最根本的差异。

三、练习#

  1. 流程复述：分别画出"视频理解"和"音频生成"的数据流，标出每一步对应哪个组件（编码器 / tokenizer / 扩散模型 / LLM）。
  2. 动手实验：在示例 2 中把抽帧数从 T=8 改成 T=64，观察 token 序列长度的变化。结合显存与序列长度，解释为什么抽帧数不能无脑加大，以及 LLaVA-Video 这类模型如何应对长视频。
  3. 对比分析：Whisper 的音频理解和 AudioLDM 的音频生成，都涉及"声谱图"。它们在"用声谱做什么"这件事上有什么本质区别？
  4. 思考题：Sora 把视频当"3D 时空 patch"处理，这与你学过的 ViT"把图当 2D patch"处理有什么对应关系？为什么说"视频生成是图像扩散的时间推广"？
