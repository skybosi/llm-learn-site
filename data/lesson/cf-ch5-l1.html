数据流分析框架：活跃变量、到达定值、可用表达式#

第 4 章把源码降成了一堆基本块和一张 CFG，但"能看见控制流"不等于"知道值从哪来、到哪去"。一个 pass 想动程序，先要在图上回答三件事：这个变量在这里还可能被谁读？这条赋值能不能走到这个使用点？这个表达式是不是每条路径都算过？三个问题一个后向、一个前向，一个 May、一个 Must，却能塞进同一台引擎。这一课把数据流分析（data-flow analysis）拆成四个可替换的零件，再用一个 60 行的 worklist 引擎把三种经典分析跑出来。

一、概念讲解#

1. 一台引擎、四个零件#

数据流分析不是"三种分析"，而是一个通用框架 + 三份配置。龙书第 9 章 §9.2 把这套框架写成四个要素：

要素 要回答的问题 到达定值 活跃变量 可用表达式
方向 事实沿边往哪流 前向（入口→出口） 后向（出口→入口） 前向
值域（格） 每个程序点上的事实 定值集合 变量集合 表达式集合
传递函数 一条语句怎么改事实 先 kill 同名定值再 gen 本条 先 kill 定义再 gen 使用 先 kill 含被定值变量的表达式再 gen 本条右值
汇合算子 多条路径怎么合并 ∪（May） ∪（May） ∩（Must）

前向与后向各有一对方程（f_B 是块 B 的传递函数，⊔ 是汇合算子）：

  • 前向：OUT[B] = f_B(IN[B])，IN[B] = ⊔ over P ∈ pred(B) : OUT[P]
  • 后向：IN[B] = f_B(OUT[B])，OUT[B] = ⊔ over S ∈ succ(B) : IN[S]

传递函数几乎总能写成 GEN/KILL 形式：f_B(x) = GEN_B ∪ (x − KILL_B)。这条形式很重要——第 4 节的终止性靠它。

2. 方向与 May/Must 是两件独立的事#

方向由"事实从哪来"决定，May/Must 由汇合算子决定。

  • 到达定值是前向的：一条 sum = 0 定义完，事实顺着控制流往下走。
  • 活跃变量是后向的：i 是否活跃取决于"从这一点出发会不会有人读 i"——需求来自程序的未来，所以要逆着边传播。
  • 可用表达式用 ∩ 而不是 ∪：它支撑的改写（CSE）要求这个右值在这一点必然已经算好。若改用 ∪，只要一条路径算过就宣布"可用"，另一条路径上的改写就会读到没算过的值——把 May 当 Must 的经典错误。

还有一个容易忽略的细节：Must 分析的初值取全集（格顶）再向下迭代，May 分析从空集向上迭代。本课代码用 top() 与 boundary() 两个钩子把这件事显式化。

3. 三个分析的传递函数，逐条看#

以本课程序里的三条指令为例：

  • sum = 0（B1）：到达定值 GEN = {sum@B1}、KILL = 其他所有对 sum 的定值；活跃变量视角下 def = {sum}、use = {}，后向方程里就是 live_in = live_out − {sum}。
  • t2 = a + b（B2）：到达定值 GEN = {t2@B2}；可用表达式 GEN = {a+b}、KILL = 含 t2 的表达式（本程序里没有）。
  • sum = sum + t2（B2）：可用表达式先 KILL 含 sum 的右值，再 GEN 新的 sum+t2。

"先 kill 后 gen"不是风格问题：反过来写，循环里的定值集合只增不减，要么不收敛，要么收敛到错误答案。

4. 不动点为什么一定达到，以及解为什么保守#

三个条件保证迭代停下：格有限（集合包含关系构成有限偏序）、传递函数单调（GEN/KILL 形式显然满足）、每轮至少动一格（格子有限高，总步数上界 ≈ 块数 × 格高度）。本课程序 4 个块，三种分析都恰好扫 3 轮、调用 12 次传递函数就收敛。按逆后序（reverse postorder）排通常收敛最快，这是真实编译器的常规做法。

精确解要枚举路径（路径爆炸），框架给的是"所有路径"层面的近似：May 说"可能"，Must 说"必然"，两者都只会比精确结果更保守——这正是 pass 敢拿它当改写依据的原因。

5. 常见坑#

  • 用 ∪ 做 Must 分析：得到"某条路径成立"的结论，改写后程序在别的路径上崩。
  • 边界值放错端：活跃变量的边界在出口（OUT[exit] = ∅），到达定值的边界在入口。
  • 拿可用表达式直接做 CSE：它只说"这个右值算过"，还得知道"结果落在哪个变量里"——下一课补上值编号。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）实现通用 worklist 引擎，再把三种分析写成三个小类——每个类只改方向、汇合算子、传递函数与边界。程序是一段同时含 while 循环与 if-else 汇合的 4 元式（指令形状与第 4 章一致），三个分析的结果都不平凡。

# ---- 数据流分析框架：一个 worklist 不动点引擎跑三种分析（纯 Python，无第三方依赖）----
# 程序用"基本块 + 三地址码"表示，指令形状沿用第 4 章的四元式
BIN = {'add', 'sub', 'mul', 'div'}


def nm(x):
    return ('name', x)


def ct(k):
    return ('const', k)


# 一段同时含"循环"和"分支汇合"的程序（i 与 sum 在循环里被反复重定义）
BLOCKS = {
    'B1': [('copy', ct(0), None, 'i'),
           ('copy', ct(0), None, 'sum'),
           ('cmp', '>', nm('n'), ct(0), 't1'),
           ('ifgoto', nm('t1'), 'B2', 'B5')],
    'B2': [('add', nm('a'), nm('b'), 't2'),
           ('add', nm('sum'), nm('t2'), 'sum'),
           ('add', nm('i'), ct(1), 'i'),
           ('cmp', '<', nm('i'), nm('n'), 't3'),
           ('ifgoto', nm('t3'), 'B2', 'B4')],
    'B4': [('add', nm('a'), nm('b'), 't4'),
           ('copy', nm('t4'), None, 'r')],
    'B5': [('add', nm('a'), nm('b'), 't5'),
           ('goto', 'B4')],
}
SUCC = {'B1': ['B2', 'B5'], 'B2': ['B2', 'B4'], 'B4': [], 'B5': ['B4']}
PRED = {b: [p for p in SUCC if b in SUCC[p]] for b in SUCC}
ENTRY = 'B1'
EXITS = [b for b in SUCC if not SUCC[b]]


def names(xs):
    return [x[1] for x in xs if x and x[0] == 'name']


def def_use(ins):
    """(定义的名字或 None, 使用的名字集合)"""
    op = ins[0]
    if op == 'copy':
        return ins[3], set(names([ins[1]]))
    if op in BIN:
        return ins[3], set(names([ins[1], ins[2]]))
    if op == 'cmp':
        return ins[4], set(names([ins[2], ins[3]]))
    if op in ('ifgoto', 'print'):
        return None, set(names([ins[1]]))
    return None, set()                      # goto


def rhs(ins):
    """本条指令算出的右值（可用表达式的键）；非运算指令为 None"""
    if ins[0] in BIN:
        return (ins[0], ins[1], ins[2])
    if ins[0] == 'cmp':
        return ('cmp', ins[1], ins[2], ins[3])
    return None


# ---------- 三种分析：只改 direction / meet / top / boundary / transfer_block ----------
class ReachingDefs:
    title, direction = '到达定值（前向 · May · ∪）', 'forward'
    meet = staticmethod(lambda sets: set().union(*sets) if sets else set())

    def top(self):
        return set()

    def boundary(self):
        return set()                        # 入口之前没有任何定值

    def transfer_block(self, b, facts):
        out = set(facts)
        for k, ins in enumerate(BLOCKS[b]):
            d, _ = def_use(ins)
            if d is not None:
                out = {f for f in out if f[0] != d} | {(d, b, k)}   # 先 kill 同名，再 gen
        return out


class LiveVars:
    title, direction = '活跃变量（后向 · May · ∪）', 'backward'
    meet = staticmethod(lambda sets: set().union(*sets) if sets else set())

    def top(self):
        return set()

    def boundary(self):
        return set()                        # 出口之后没有变量还活跃

    def transfer_block(self, b, facts):
        live = set(facts)
        for ins in reversed(BLOCKS[b]):     # 后向：从块尾往块头走
            d, u = def_use(ins)
            live = (live - {d}) | u if d is not None else live | u
        return live


class AvailableExprs:
    title, direction = '可用表达式（前向 · Must · ∩）', 'forward'
    meet = staticmethod(lambda sets: set.intersection(*sets) if sets else set())

    def top(self):
        return {e for b in BLOCKS for e in (rhs(i) for i in BLOCKS[b]) if e is not None}

    def boundary(self):
        return set()                        # 入口处没有任何表达式"已算好且未被重定义"

    def transfer_block(self, b, facts):
        avail = set(facts)
        for ins in BLOCKS[b]:
            d, _ = def_use(ins)
            if d is not None:               # 变量被重定义 → 所有含它的表达式失效
                avail = {e for e in avail if d not in names(list(e[1:]))}
            r = rhs(ins)
            if r is not None:
                avail.add(r)
        return avail


def solve(an, max_rounds=200):
    IN = {b: set(an.top()) for b in BLOCKS}
    OUT = {b: set(an.top()) for b in BLOCKS}
    if an.direction == 'forward':
        IN[ENTRY] = set(an.boundary())
        OUT[ENTRY] = an.transfer_block(ENTRY, IN[ENTRY])
    else:
        for b in EXITS:
            OUT[b] = set(an.boundary())
    rounds = evals = 0
    while rounds < max_rounds:
        rounds += 1
        changed = False
        for b in BLOCKS:
            if an.direction == 'forward':
                nin = IN[ENTRY] if b == ENTRY else an.meet([OUT[p] for p in PRED[b]])
                nout = an.transfer_block(b, nin)
            else:
                nout = OUT[b] if not SUCC[b] else an.meet([IN[s] for s in SUCC[b]])
                nin = an.transfer_block(b, nout)
            evals += 1
            if nin != IN[b] or nout != OUT[b]:
                IN[b], OUT[b], changed = set(nin), set(nout), True
        if not changed:
            break
    return IN, OUT, rounds, evals


def show(f):
    if isinstance(f, tuple) and len(f) == 3 and isinstance(f[2], int):
        return f'{f[0]}@{f[1]}#{f[2]}'
    if isinstance(f, tuple):
        return ' '.join(str(x[1]) if isinstance(x, tuple) else str(x) for x in f)
    return str(f)


def dump(s):
    return '{}' if not s else '{' + ', '.join(sorted(show(f) for f in s)) + '}'


for an in (ReachingDefs(), LiveVars(), AvailableExprs()):
    IN, OUT, rounds, evals = solve(an)
    print(f'=== {an.title} ===')
    for b in BLOCKS:
        print(f'  {b}  in={dump(IN[b]):<44} out={dump(OUT[b])}')
    print(f'  → {len(BLOCKS)} 个块，worklist 扫 {rounds} 轮 / {evals} 次 transfer，达到不动点\n')

rd_in = solve(ReachingDefs())[0]
lv_in, lv_out = solve(LiveVars())[:2]
av_in = solve(AvailableExprs())[0]
E = ('add', nm('a'), nm('b'))
print('事实核对（把集合读成人能懂的话）：')
print(f'  B2 入口的 a+b 可用？ {"是" if E in av_in["B2"] else "否"}（循环首次进入时还没算过）')
print(f'  B4 入口的 a+b 可用？ {"是" if E in av_in["B4"] else "否"}（两条路径都算过 → Must 成立）')
print(f'  B1 出口的 i 活跃？  {"是" if "i" in lv_out["B1"] else "否"}（i 在循环体里被读）')
print(f'  B4 入口的 sum 活跃？{"是" if "sum" in lv_in["B4"] else "否"}（循环之后没人再读 sum）')
print('  到达 B2 入口的 sum 定值：'
      + str(sorted(f'{f[1]}#{f[2]}' for f in rd_in['B2'] if f[0] == 'sum')))
print('  到达 B2 入口的 t2 定值（含回边那一份）：'
      + str(sorted(f'{f[1]}#{f[2]}' for f in rd_in['B2'] if f[0] == 't2')))

运行结果（i@B1#0 表示"B1 块第 0 条指令对 i 的定值"）：

=== 到达定值（前向 · May · ∪） ===
  B1  in={}                                           out={i@B1#0, sum@B1#1, t1@B1#2}
  B2  in={i@B1#0, i@B2#2, sum@B1#1, sum@B2#1, t1@B1#2, t2@B2#0, t3@B2#3} out={i@B2#2, sum@B2#1, t1@B1#2, t2@B2#0, t3@B2#3}
  B4  in={i@B1#0, i@B2#2, sum@B1#1, sum@B2#1, t1@B1#2, t2@B2#0, t3@B2#3, t5@B5#0} out={i@B1#0, i@B2#2, r@B4#1, sum@B1#1, sum@B2#1, t1@B1#2, t2@B2#0, t3@B2#3, t4@B4#0, t5@B5#0}
  B5  in={i@B1#0, sum@B1#1, t1@B1#2}                  out={i@B1#0, sum@B1#1, t1@B1#2, t5@B5#0}
  → 4 个块，worklist 扫 3 轮 / 12 次 transfer，达到不动点

=== 活跃变量（后向 · May · ∪） ===
  B1  in={a, b, n}                                    out={a, b, i, n, sum}
  B2  in={a, b, i, n, sum}                            out={a, b, i, n, sum}
  B4  in={a, b}                                       out={}
  B5  in={a, b}                                       out={a, b}
  → 4 个块，worklist 扫 3 轮 / 12 次 transfer，达到不动点

=== 可用表达式（前向 · Must · ∩） ===
  B1  in={}                                           out={cmp > n 0}
  B2  in={cmp > n 0}                                  out={add a b, add i 1, add sum t2, cmp < i n, cmp > n 0}
  B4  in={add a b, cmp > n 0}                         out={add a b, cmp > n 0}
  B5  in={cmp > n 0}                                  out={add a b, cmp > n 0}
  → 4 个块，worklist 扫 3 轮 / 12 次 transfer，达到不动点

事实核对（把集合读成人能懂的话）：
  B2 入口的 a+b 可用？ 否（循环首次进入时还没算过）
  B4 入口的 a+b 可用？ 是（两条路径都算过 → Must 成立）
  B1 出口的 i 活跃？  是（i 在循环体里被读）
  B4 入口的 sum 活跃？否（循环之后没人再读 sum）
  到达 B2 入口的 sum 定值：['B1#1', 'B2#1']
  到达 B2 入口的 t2 定值（含回边那一份）：['B2#0']

三份输出对照着读：到达定值最长的那行在循环头与汇合点（回边带来的定值也到达了）；活跃变量里 B4 入口的 sum 已不活跃，a、b 一路活跃；可用表达式在 B2 入口保留了 n > 0——它是循环不变量，正是第 3 课不变量外提要用的原料。

三、练习#

  1. 实现：给引擎加第四个分析——非常忙表达式（very busy expressions：后向 + ∩），用它支撑"把 a+b 提到分支之前算一次"。用 if (c) x = a + b else x = a + b 验证：分支汇合处 a+b 必须"在上方所有路径上都用得到"才成立。
  2. 解释：为什么可用表达式的初值要取全集 U，而到达定值取 ∅？如果可用表达式也从 ∅ 开始迭代，得到的解为什么不安全？
  3. 对比/验证：把程序里的回边去掉（ifgoto t3 B2 B4 改成 goto B4），观察三种分析的迭代轮数与事实集合怎么变；解释为什么此时"直线代码"一轮就够。
  4. 思考：到达定值告诉你"哪些赋值可能到达这里"。要判断"这里 x 一定是常量 3"，值域要从"定值集合"换成什么？换完之后汇合算子该怎么改？
