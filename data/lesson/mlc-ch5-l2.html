pattern 匹配与融合边界（点链 / 归约链）#

上一课算清了收益，但收益只在"能融"时存在。编译器凭什么决定哪两个算子可以融？判据不是"相邻"——relu 紧跟 matmul 就不能融，被两处读取的中间值也不能随手融进其中一处。本课用一个 40 行的图级 pass 跑通"分类 → 沿生产者扩张 → 遇边界停下 → 写清理由"，并给出多消费者下"重算还是物化"的利润公式。

一、概念讲解#

1. 先给算子分类：类别决定可融性#

融合判定几乎都建立在一个分类上：逐元素（elementwise / injective，输出每个元素只依赖输入的对应位置，如 add/relu）、广播（broadcast，索引式改写）、归约（reduction，输出依赖输入的多个位置，如 sum）、不透明（opaque，如外部库实现的矩阵乘）。真实编译器里的 OpPatternKind 就是这张表——TVM 的融合流水线（relax.FuseOps + relax.FuseTIR）官方文档写到它"把多个连续的张量算子融合成单个 kernel"，能否融进同一个 kernel 取决于模式类别。

类别 例子 能融进什么 为什么
逐元素 add mul relu sigmoid 逐元素、归约、归约的 epilogue 每个输出只依赖对应输入，表达式可直接写进消费者的循环体
广播 加偏置 逐元素、归约 索引式改写，不增加数据依赖
归约 sum mean 逐元素（epilogue） 归约结果可在同一内核里继续做逐元素计算；归约不能融进归约（要重排归约树或两遍）
不透明 矩阵乘、extern kernel 都不行 外部实现不暴露循环结构，无法注入别的算子

2. 点链融合：把生产者写进消费者的循环体#

若生产者是逐元素、且结果只被这一个消费者使用，就可以把它"内联"进消费者的循环体：消费者不再读中间张量，而是现算。一条 N 个逐元素算子的链因此收成 1 个内核、1 趟访存。判据里两个条件缺一不可：类别允许、且中间值只有一个读者。后者是下节主角。

3. 归约链的两个方向#

归约最容易搞反，它的两个方向收益不对称：

  • 输入侧（逐元素 → 归约）：把生产者算进归约循环——归约本就要遍历输入，内联后中间值不落地。
  • 输出侧 / epilogue（归约 → 逐元素）：归约结果继续在同一内核里做逐元素变换（sum → ×2 → relu）。代码里 total 把生产者 proj 融进来，成为一个内核 ['total', 'proj']。
  • 归约 → 归约：不许。外层归约要消费内层的全部结果，直接内联会让内层被重复求值，真实编译器普遍退回两遍或改成 split reduction。

4. 边界从哪来#

边界有四类，代码逐条打印：

  1. 不透明算子：q/k 是矩阵乘，任何与 opaque 的组合都停住。本机 torch 2.3.1 调度器源码对应的拒绝是"节点是 extern 或 nop 就不再尝试融合"（can_fuse 的 node1 is extern or nop 分支）。
  2. 多消费者：中间值被两处读，融进其中一处会让另一处重算或继续读显存。这不等于禁止——两处若落在同一个簇里就只是"算一次、用两次"（CSE）；只有落在不同簇才要过利润模型。
  3. 归约 → 归约：见上。
  4. 已被别的簇吸收：一个值只有一个生产者，被吸收后其他路径要另找边界。

四类边界在不同编译器里名字不同：XLA 在 HLO 层也做 producer-consumer 融合与 multi-output 融合（多个消费者合成一个多输出内核），依据同样是编译期的依赖与读者分析。

5. 多消费者的利润模型#

设生产者链长 m（每元素 m 次运算）、消费者 nc​ 个、中间张量 E 个元素、带宽 B、算力 F（元素算子/秒）：

t_{\text{物化}} = \frac{(2+n_c)\cdot 4E}{B},\qquad\rt_{\text{重算}} = \frac{n_c \cdot 4E}{B} + \frac{n_c\,mE}{F}

令二者相等得 m∗=nc​B8F​。代入示例参数（B=1.5 TB/s、F=375 G 元素算子/s、nc​=2）得 m∗=1.0：生产者只有 1 个算子时两者持平，再长就该物化。这就是"多消费者"是条件而非禁忌的原因，也说明结论随硬件算术强度变化。

6. 常见坑#

  • 只看相邻不看读者数：会漏掉多消费者与不透明边界。
  • 把归约当逐元素处理：两个归约融进一个内核只会重复计算、难以向量化。
  • 忽略 epilogue：归约输出后的逐元素链不融，就白多一趟往返。
  • 拿"融得多"当目标：簇越大，寄存器与 occupancy 越紧张（下一课），要与代价核算一起看。

二、可运行代码示例#

纯 Python（无第三方依赖）。图沿用第 3/4 课的节点表，类别写在节点上；pass 分两阶段：反向成簇（吸收生产者），再把"外部消费者全落在同一簇"的簇并进去（同一内核内的 CSE）；最后打印跨簇连边与理由。

# ---- 第 2 课示例：pattern 匹配与融合边界（纯 Python，无第三方依赖）----
# 图表示沿用第 3/4 课的节点表：节点 = (名字, 类别, [输入])；类别决定"能不能融"
NODES = [('h',      'add',       ['x', 'b']),
         ('q',      'matmul',    ['h', 'Wq']),
         ('k',      'matmul',    ['h', 'Wk']),
         ('score',  'mul',       ['q', 'k']),
         ('p',      'sigmoid',   ['score']),
         ('rowsum', 'sum',       ['p']),
         ('norm',   'mul',       ['p', 'rowsum']),
         ('act',    'relu',      ['norm']),
         ('o',      'matmul',    ['act', 'Wv']),
         ('proj',   'add',       ['o', 'bo']),
         ('total',  'sum',       ['proj']),
         ('r2',     'sum',       ['total'])]
KIND = {'matmul': 'opaque', 'add': 'pointwise', 'mul': 'pointwise', 'relu': 'pointwise',
        'sigmoid': 'pointwise', 'sum': 'reduction', 'broadcast': 'broadcast'}
DEPS = {n: list(d) for n, k, d in NODES}
KIND_OF = {n: KIND[k] for n, k, d in NODES}
ORDER = [n for n, k, d in NODES]
EXT = {'x': 1536, 'b': 1536, 'Wq': 2304, 'Wk': 2304, 'Wv': 2304, 'bo': 1536}
ELEMS = {n: 1536 for n in ORDER}
CONS = {n: [] for n in ORDER}
for n in ORDER:
    for d in DEPS[n]:
        CONS.setdefault(d, []).append(n)

# 规则表写成数据：真实编译器里它就是 OpPatternKind 的判定表
RULES = [('pointwise', 'pointwise', '逐元素融进逐元素：同一次遍历里算完'),
         ('pointwise', 'reduction', '逐元素融进归约：在归约循环里直接算'),
         ('reduction', 'pointwise', '归约融进逐元素：epilogue，结果直接往下用'),
         ('broadcast', 'pointwise', '广播融进逐元素：只是索引式改写'),
         ('layout',    'pointwise', '布局视图可融，但访存连续性要另算（条件允许）'),
         ('layout',    'reduction', '布局视图融进归约（同上）')]
ALLOWED = {(p, c) for p, c, _ in RULES}

print('=== 1. 先分类：一个算子能不能被融，由它的类别决定 ===')
for n, k, d in NODES:
    flag = '  ← 融合边界（不透明）' if KIND_OF[n] == 'opaque' else ''
    print(f'  {n:<7}{KIND_OF[n]:<10}输入={str(d):<18}{flag}')
print('\n  规则表（生产者类别 → 消费者类别）：')
for p, c, w in RULES:
    print(f'    {p:<10} → {c:<10}{w}')
print('    不接受：任何 → opaque；opaque → 任何；reduction → reduction；跨簇的多消费者要过利润模型')

# ---- 阶段 1：按执行序反向成簇（每个节点先自成一簇，再吸收生产者）----
owner, groups = {}, {}
for n in reversed(ORDER):
    if n in owner:
        continue
    members, frontier = [n], [n]
    owner[n] = n
    if KIND_OF[n] != 'opaque':
        while frontier:
            c = frontier.pop()
            for p in DEPS.get(c, []):
                if p in EXT or p in owner:
                    continue
                if KIND_OF[p] == 'opaque':
                    continue
                if KIND_OF[p] == 'reduction' and KIND_OF[c] == 'reduction':
                    continue
                if (KIND_OF[p], KIND_OF[c]) not in ALLOWED:
                    continue
                if len(CONS.get(p, [])) > 1:
                    continue
                members.append(p); owner[p] = n; frontier.append(p)
    groups[n] = members

# ---- 阶段 2：整个簇的"外部消费者"若都落在同一个簇里，就并入那个簇（同一内核里做 CSE）----
changed = True
while changed:
    changed = False
    for head, members in list(groups.items()):
        targets = {owner[c] for m in members for c in CONS.get(m, [])
                   if c in owner and owner[c] != head}
        if len(targets) != 1:
            continue
        G = targets.pop()
        if G not in groups:
            continue
        ok = all((KIND_OF[m], KIND_OF[c]) in ALLOWED
                 for m in members for c in CONS.get(m, []) if owner.get(c) == G)
        if not ok:
            continue
        groups[G] = groups[G] + members
        for m in members:
            owner[m] = G
        del groups[head]
        changed = True
        break

# ---- 边界：所有"生产者与消费者不在同一簇"的连边，都记下原因 ----
boundary = []
for c in ORDER:
    for p in DEPS[c]:
        if p in EXT or owner.get(p) == owner.get(c):
            continue
        if KIND_OF[p] == 'opaque':
            boundary.append((p, c, f'生产者 {p} 是不透明算子'))
        elif KIND_OF[c] == 'opaque':
            boundary.append((p, c, f'消费者 {c} 是不透明算子（extern kernel 不吃 epilogue）'))
        elif KIND_OF[p] == 'reduction' and KIND_OF[c] == 'reduction':
            boundary.append((p, c, '归约不能融进归约'))
        elif (KIND_OF[p], KIND_OF[c]) not in ALLOWED:
            boundary.append((p, c, f'{KIND_OF[p]} → {KIND_OF[c]} 不在规则表里'))
        elif len(CONS.get(p, [])) > 1:
            boundary.append((p, c, f'生产者 {p} 的 {len(CONS[p])} 个消费者落在不同簇'))
        else:
            boundary.append((p, c, '所属簇不同'))

print('\n=== 2. 成簇结果（一个簇 = 一个内核）===')
for head, members in groups.items():
    tail = members[1:]
    print(f'  内核「{head}」：{members}' + (f'   融掉 {tail}' if tail else '   只有它自己'))

print('\n=== 3. 留下的边界（扩张在这里停住，以及为什么）===')
seen = set()
for p, c, r in boundary:
    if (p, c, r) in seen:
        continue
    seen.add((p, c, r))
    print(f'    {p} → {c}: {r}')
same = [n for n in ORDER if len(CONS.get(n, [])) > 1
        and len({owner[c] for c in CONS[n]}) == 1]
print(f'  多消费者但不算边界：{[(n, CONS[n]) for n in same]}'
      ' —— 它们落在同一个簇里，内核里算一次用两次（CSE），没有额外访存')

fused = [n for head, m in groups.items() for n in m[1:]]
print(f'\n=== 4. 两笔账 ===')
print(f'  内核数：{len(ORDER)} → {len(groups)}')
print(f'  融掉、不再落地的中间张量：{fused}')
print(f'  省下的写 + 读 = {2 * sum(ELEMS[n] for n in fused) * 4 / 1024:.1f} KiB'
      f'（每个被融掉的张量写一次、读一次，按 1536 元素 = 6 KiB 计）')

print('\n=== 5. 多消费者的利润模型：重算还是物化？ ===')
BW, OPS_PER_SEC = 1.5e12, 1.5e12 / 4        # 示例参数：带宽 1.5 TB/s、375 G 元素算子/s
def cost(materialize, m_ops, n_cons, elems):
    if materialize:                          # 写中间值 + 生产者读输入 + 每个消费者读中间值
        return (2 + n_cons) * elems * 4 / BW
    return n_cons * elems * 4 / BW + n_cons * m_ops * elems / OPS_PER_SEC
elems, n_cons = 512 * 768, 2
m_star = 8 * OPS_PER_SEC / (n_cons * BW)     # 由两条代价相等解出的临界生产者长度
print(f'  设消费者 {n_cons} 个、中间张量 {elems} 元素；'
      f'临界生产者长度 m* = 8·F/(n_c·B) = {m_star:.1f} 个算子')
for m_ops in (1, 2, 4, 16):
    t_m, t_r = cost(True, m_ops, n_cons, elems), cost(False, m_ops, n_cons, elems)
    verdict = '重算更省' if t_r < t_m * 0.999 else ('物化更省' if t_m < t_r * 0.999 else '持平')
    print(f'    生产者 {m_ops:>2} 个算子：物化 {t_m * 1e6:6.1f} us，'
          f'重算 {t_r * 1e6:6.1f} us → {verdict}')
print('  重算省掉"最后写一次 + 多读一次"，代价是生产者多算 n_c-1 遍；')
print(f'  生产者短于 {m_star:.1f} 个算子才值得重算；刚好相等时两者持平。')
print('  多消费者不是禁忌，是要过账：这笔账的结论随带宽/算力比与消费者个数变化。')
