「检索到了却没用」：证据利用率的机理与归因#

这一节要解决什么#

上一节把证据放进了预算、也选了覆盖度最高的 chunk。但一个在真实系统里反复出现的现象是：

检索日志里明明白白有正确的那一段，模型的回答却像没看见它。

这个现象的名字很多 —— "检索到了但没用""模型不 grounding""答案和上下文无关"。它们描述的是同一类故障，但原因至少有五种，处方完全不同。把五种混在一起，最常见的后果是：明明问题在位置或指令，却去换嵌入模型；明明问题是参数记忆压过了证据，却去加检索路数。

本节要回答四个问题：

  1. "用了没有"到底怎么测量？有没有能证明因果的测试，而不是看一眼觉得像？
  2. 证据位置、顺序、干扰分别通过什么机制削弱证据的使用？各自的可测信号是什么？
  3. 参数记忆与外部证据冲突时，模型偏向谁？这个偏向能不能测、能不能被指令改变？
  4. 强制引用、拒答、证据重排这些修法，各自能修哪一类，代价是什么？

结论先放在这里：把"检索到了却没用"当成一个可观测现象之前，它不可修。必要性与充分性测试（删证据 / 只留证据）+ 反事实交换（改关键值看输出是否跟随）能把"没进上下文""进了没读到""读到了但被先验压过""读到了但答错"四件事分开；而这四种情况对应的修法分别是召回、重排/位置、grounding 指令/去干扰、以及生成质量本身。

一、先把"用了没有"变成可测量的东西#

1.1 四个测试#

设 f(q,C) 是系统在问题 q、上下文 C 下的输出，e 是目标证据（黄金证据 chunk），C−e​ 是去掉 e 的上下文，Ce​ 是只留 e 的上下文。

测试 形式化 证明了什么 不能证明什么
必要性 f(q,C)=f(q,C−e​) 证据对输出有因果影响 反过来不成立：输出没变也可能两路都错
充分性 f(q,Ce​) 是否正确 证据本身足以支撑答案 不能说明完整上下文下用不用
反事实交换 把 e 里的关键值改成 v′，看 f 是否跟着变成 v′ 模型是照抄/依据证据而不是凭记忆 交换后的答案可能"恰好"等于某错误记忆
引用一致率 输出中每条引用所声称的内容是否被所引 chunk 支持 引用是否可信（是证据而非装饰） 不引用也可能答对

反事实交换是最强的一个，因为它把"用证据"操作化成了"跟着证据变"。定义跟随率：

Follow=∣Q∣1​q∈Q∑​1[f(q,C with e’s value→vq′​)=vq′​]

其中 vq′​ 是一个在语料里不存在、也不可能被参数记忆猜到的新值（例如把"2023 年营收 3.2 亿"改成"3.7 亿"）。如果输出不跟着变，那这个系统在答案上就没有真正依赖检索 —— 无论引用写得多漂亮。

1.2 为什么要四个一起做#

单个测试容易给出误导性结论：

  • 只看必要性：如果模型本来答错，删掉证据输出也不变，会误判为"证据没用"；
  • 只看引用率：模型可以抄一个 doc id 而答案来自记忆（引用装饰）；
  • 只看充分性：可能是 prompt 里"只给一条证据"这个格式本身让模型变谨慎了。

四个测试的组合给出一个诊断矩阵：

必要性有影响 充分性可答对 跟随率高 诊断
是 是 高 证据有效利用（无需修）
否 是 低 模型没用证据，靠先验：grounding 指令/位置问题
是 否 高 证据被用了，但证据本身不足：召回/切分问题
否 否 低 证据没进上下文或没被读到：回到召回层或位置层

1.3 四个测试的测量成本#

四个测试看起来要跑很多次推理，但成本是可以算的，也不是所有测试都要常跑：

测试 额外推理次数（每题） 需要的数据 可否离线自动化 建议频率
必要性 1（删证据重跑） 黄金证据 id 可以 每次评测
充分性 1（只留证据重跑） 黄金证据 id 可以 每次评测
反事实交换 1（改值重跑） 一个"语料不存在"的新值 可以 每次评测
引用一致率 0（只需输出与引用） 引用 id + 支持判定 可以 每次评测

关键判据：四个测试都需要黄金证据标注（ch7-l2 §2.2）。没有它，必要性测试无法构造（不知道删哪一块），充分性测试也无法判定。所以"评测集标注黄金证据"是这一节所有方法的前置条件，而不是可选的加分项。

反事实交换里的"新值"有一个硬要求：必须是语料里不存在、且参数记忆不可能猜到的新值（例如把"2023 年营收 3.2 亿"改成"3.7 亿"）。若换成一个真实存在过的旧值，测出来的"跟随率"会把"照抄证据"与"恰好回忆到旧值"混在一起，结论不可用。

二、位置与顺序：注意力先验造成的损耗#

2.1 机制#

上一节已经给出位置折扣的形式：注意力对"开头"和"结尾"有偏好，对中段压制。把证据放在不同深度，输出正确率呈 U 形。这不是模型的 bug，而是训练分布 + 位置编码共同塑造的先验，因此它不能靠"再训一遍"消失，只能靠布局规避。

2.2 可测判据：顺序敏感度#

Sorder​=πmax​acc(π)−πmin​acc(π)

π 遍历证据的排列/深度。Π 太大时抽样：只移动目标证据的深度（其余保持随机），是成本最低的测法。

⚠️ 合成实验（证据在正中 vs 首尾）给出：

证据深度 0.00 0.35 0.50 0.65 1.00
正确率 1.000 1.000 0.785 1.000 1.000

Sorder​=0.215。含义：仅仅因为把证据放在中段，就损失了约 21.5 个百分点的正确率；而这个损失可以通过"把最相关证据放到首尾"免费拿回来（代码里的 depths=(0.0, 1.0) 策略从 0.785 升到 1.000）。

2.3 边界#

  • Sorder​ 大不等于"重排能修好一切"：重排只能把已知最相关的放首尾；如果最相关的判断本身错了，重排只是在错误的候选里挑。
  • "sandwich"（首尾各放一份）在预算上等于把该 chunk 的成本翻倍。它值不值，要看 Sorder​ 带来的收益是否超过这份 token 成本（上一节的预算框架）。
  • 位置效应与任务类型有关：抽取式问答受影响大，全局摘要受影响小而干扰更致命。

三、干扰与冲突：分母效应与先验竞争#

3.1 干扰：softmax 分母的直接后果#

把"证据被读到"建模为一次注意力竞争：

Pread​=eℓe​+∑j=1m​eℓj​eℓe​​

m 是干扰块数。注意这个式子的性质：Pread​ 随 m 单调下降，且与 eℓe​ 的相对关系才是关键。 所以"多召回几条做保险"的直觉在这里是负面的 —— 上一节已经算过它的成本，这里给出它的证据利用率代价。

⚠️ 合成实验（P_read 均值）：

干扰块 m 0 5 10 25 50 100 200 500
Pread​ 0.604 0.187 0.110 0.050 0.026 0.013 0.0066 0.0027
P10 0.462 0.089 0.051 0.022 0.012 0.006 0.003 0.001

对应到端到端正确率：m=10 时 0.250、m=50 时 0.055、m=200 时 0.015（plain 参数下基线 0.785）。这就是"上下文里塞满无关文档，模型就看不见答案"的定量版本。

3.2 冲突：参数记忆与证据谁赢#

当证据说 ve​、模型参数记忆里是 vp​（陈旧值、常见误解、训练集里的旧数字），两个假设在竞争。可测的判据是：

PriorWin=#{先验值与证据值不同的查询}#{输出等于先验值而非证据值}​

⚠️ 合成实验里 plain 策略的 PriorWin = 0.215：即使证据已经在上下文里，仍有 21.5% 的问题被参数记忆压过。 在没有证据时（depths=()），这个数字是 1.000 —— 也就是"完全不检索，全靠记忆"的行为。

注意一个反直觉的结果：加干扰块会同时降低正确率、提高 PriorWin（m=50 时 PriorWin=0.945）。原因不是干扰让先验变强，而是干扰把注意力从证据上抢走之后，剩下的竞争中只有先验。这解释了为什么"提高召回数量"经常让答案更"自信地错"。

3.3 边界#

  • 干扰的危害取决于它与证据的相似度分布：同主题不同事实的干扰（near-duplicate）最毒；完全无关的噪声影响小（logit 低）。
  • 冲突只在"先验与证据不同"时才可测：要先构造反事实值，不能靠真实语料自然出现。
  • 若模型在语料没见过该事实，PriorWin 会显著下降 —— 所以"记忆冲突"是训练数据覆盖的函数，会随模型版本变化。

3.4 冲突的三种形态（处方不同）#

"先验压过证据"是一句笼统的话，实际有三种形态，处理方式不同：

形态 表现 检测信号 处方
旧值冲突 证据是新值、参数里是旧值 PriorWin 高，且先验值与证据值同量纲 grounding 指令 + 在证据里显式给出时间戳/版本
常识冲突 证据违反常识（例如"水在 50°C 沸腾"） 模型给出常识答案并可能加解释 要求"仅依据资料"并给出处；同时对异常值加人工复核
多来源冲突 上下文里两段证据互相矛盾 输出在两次运行间跳变（答案方差高） 先做来源可信度排序（时间/权威/版本），再决定采信哪条

判据：三种形态的检测信号不同 —— 旧值冲突看 PriorWin，常识冲突看"输出与证据的语义偏离度"，多来源冲突看同一问题的输出方差。只测 PriorWin 会漏掉后两种，而它们的业务后果可能更严重（模型主动"纠正"了正确证据）。

四、修法与它们的失效条件#

4.1 四类修法#

修法 修的机理 代价 失效条件
证据重排/首尾放置 位置损耗（§2） 可能复制 chunk → token 成本翻倍 相关性判断本身错
grounding 指令 + 强制引用 先验竞争（§3.2）与格式自由 输出更长、更啰嗦；引用幻觉 指令与证据冲突时优先级不明；证据不足仍硬答
去重 + 减少无关召回 干扰（§3.1） 召回率下降（可能漏） 去重误删互补证据
拒答阈值 证据不足时避免错答 覆盖率下降 阈值过高 → 大量该答的也拒

4.2 grounding 的效果与代价（量化）#

⚠️ 合成实验（把证据权重 ×2、先验权重 ×0.2）：

策略 acc 拒答 先验赢 跟随率
plain 0.785 0.000 0.215 0.785
+ ground ing 指令 1.000 0.000 0.000 1.000
+ 拒答阈值 Pread​<0.85 0.730 0.270 0.000 0.730
无证据 0.000 0.000 1.000 0.000

关键读数：grounding 指令把正确率从 0.785 抬到 1.000、把 PriorWin 清零 —— 但这是在证据已经进上下文的前提下。它修不了召回，也修不了"证据本身不足"。因此 grounding 指令的正确位置是"生成层加固"，不是"检索层的替代品"。

4.3 拒答：风险-覆盖曲线#

拒答阈值 τ 控制"多确定才回答"。⚠️ 合成实验（plain 参数，Pread​​=0.60）：

τ 覆盖率 答对（占全体） 答对（占已答）
0.00 1.000 0.785 0.785
0.45 0.965 0.785 0.813
0.60 0.510 0.510 1.000
0.75 0.045 0.045 1.000
0.90 0.000 0.000 —

这是一条典型的风险-覆盖曲线（risk-coverage curve）：阈值抬高，已答部分的正确率上升，但覆盖率下降。工程判据不是"正确率越高越好"，而是选在业务可接受的覆盖率下最大化已答正确率 —— 例如客服场景可能接受覆盖率 0.51 换取 100% 已答正确率，而内部检索助手更愿意接受 0.81 的已答正确率保留 96.5% 的覆盖率。

4.4 修法的优先级顺序#

四类修法的成本与影响面差别很大，顺序不能乱。可执行的顺序是：

① 先跑四个测试，确定属于哪一类（§1.2 的诊断矩阵）
② 若是"没进上下文"：回到召回层（ch2/ch3），不要在生成层花时间
③ 若是"进了没读到"：先调位置/顺序（零成本），再考虑去干扰
④ 若是"读到了被先验压过"：加 grounding 指令 + 在证据里显式给出版本/时间
⑤ 若是"证据不足"：要么补召回，要么上拒答（不要靠 prompt 硬救）
⑥ 最后才考虑换模型 —— 它同时改变所有环节，是最难归因的一步

判据：如果一次改动同时改了两个环节（例如既换模型又改 prompt），你无法知道收益来自哪里。一次只动一处是归因的前提。这也是 ch7-l3 案例里"v2 只加一个特征"的原因。

4.5 边界与常见错误#

错误 表现 修正
用引用率当 grounding 证据 引用 id 齐全是"装饰性引用" 同时测引用一致率与跟随率
只测必要性 删证据输出不变就下结论"没用" 四测试组合（§1.2 矩阵）
用真值做反事实 交换后的值可能被参数记忆"猜到" 交换值必须语料不存在、记忆不可能知道
把拒答当万能 覆盖率崩到无法使用 画风险-覆盖曲线，按业务选工作点
在召回层问题上下 grounding 功夫 指标不涨 先跑必要性/充分性把层次分开

代码#

一个两阶段答案选择模拟器：先用 softmax 决定"哪一块被读到"（注意力竞争），再决定答案。它把位置折扣、干扰分母、先验竞争三个机制放在同一个可运行模型里。

# -*- coding: utf-8 -*-
"""⚠️ 合成数据：两阶段答案选择模拟器 —— 先竞争注意力(softmax)，再决定是否用证据。
   它演示机制，不是任何真实 LLM 的实测数值。"""
import numpy as np

rng = np.random.default_rng(0)
NQ = 200
Q = []
for _ in range(NQ):
    v_true = int(rng.integers(100, 999))
    Q.append({"true": v_true,
              "prior": v_true + int(rng.choice([-1, 1]) * rng.integers(1, 40)),  # 参数记忆陈旧值
              "rel_ev": float(rng.uniform(1.6, 2.6)),   # 证据与查询的相关度
              "rel_d": float(rng.uniform(0.4, 1.0))})   # 干扰块的相关度

def pos_pen(depth, kappa=1.2):
    """位置折扣：中部最大 -> 注意力 U 形。"""
    return kappa * (1 - abs(2 * depth - 1))

def step(q, w_sup=1.0, w_prior=1.0, depths=(0.5,), m_dist=0, temp=0.7,
         tau_read=0.0, swap=None, seed=0):
    """返回 (答案, P(读到证据), 是否拒答)。答案 ∈ {证据值, 先验值, None}"""
    r = np.random.default_rng(seed)
    v_ev = q["true"] if swap is None else swap       # 反事实交换：换掉证据里的关键值
    logits = [w_sup * (q["rel_ev"] - pos_pen(d)) for d in depths]      # 证据块
    if m_dist:
        logits += list(r.normal(q["rel_d"], 0.35, m_dist))             # 干扰块
    logits.append(w_prior * 0.6)                                       # 先验伪块
    z = np.array(logits) / temp
    p = np.exp(z - z.max()); p /= p.sum()
    m_ev = len(depths)
    p_read = float(p[:m_ev].sum()) if m_ev else 0.0
    if p_read < tau_read:                       # 不确定就拒答
        return None, p_read, True
    if m_ev and int(np.argmax(p)) < m_ev:       # 注意力落在证据上 -> 照证据回答
        return v_ev, p_read, False
    return q["prior"], p_read, False            # 否则回落到参数记忆

def evaluate(**kw):
    hit = ref = prior = 0
    for i, q in enumerate(Q):
        a, _, _ = step(q, seed=i, **kw)
        if a is None:
            ref += 1
        elif a == q["true"]:
            hit += 1
        elif a == q["prior"]:
            prior += 1
    n = len(Q)
    return hit / n, ref / n, prior / n

def copy_rate(**kw):
    """反事实交换的跟随率：把证据值换成语料里不存在的新值，看输出是否跟着变。"""
    return sum(step(q, seed=i, swap=q["true"] + 777, **kw)[0] == q["true"] + 777
               for i, q in enumerate(Q)) / len(Q)

print("== ⚠️ 合成数据：两阶段答案选择模拟器（机制演示，非真实 LLM 数值）==")
print(f"{'策略':<32} {'acc':>7} {'拒答':>7} {'先验赢':>8} {'copy率':>8}")
for name, kw in [
    ("plain（证据在正中）",              dict()),
    ("sandwich（证据首尾各一份）",        dict(depths=(0.0, 1.0))),
    ("加 10 个干扰块",                   dict(m_dist=10)),
    ("加 50 个干扰块",                   dict(m_dist=50)),
    ("加 200 个干扰块",                  dict(m_dist=200)),
    ("grounding（w_sup2 / w_prior0.2）", dict(w_sup=2.0, w_prior=0.2)),
    ("grounding + 拒答 P_read<0.85",     dict(w_sup=2.0, w_prior=0.2, tau_read=0.85)),
    ("无证据（只剩先验）",                dict(depths=())),
]:
    acc, ref, pw = evaluate(**kw)
    print(f"{name:<32} {acc:>7.3f} {ref:>7.3f} {pw:>8.3f} {copy_rate(**kw):>8.3f}")

print("\n-- 顺序敏感度 S_order（只移动证据深度，plain 参数）--")
table = []
for d in (0.0, 0.2, 0.35, 0.5, 0.65, 0.8, 1.0):
    acc, _, _ = evaluate(depths=(d,))
    table.append((d, acc))
    print(f"   depth={d:.2f}  acc={acc:.3f}")
print(f"   S_order = max-min = {max(a for _, a in table) - min(a for _, a in table):.3f}")

print("\n-- 拒答阈值 tau_read -> 覆盖率 / 准确率（plain 参数）--")
print(f"{'tau_read':>9} {'覆盖率':>8} {'答对(全体)':>11} {'答对(已答)':>11}")
for tau in (0.0, 0.3, 0.45, 0.6, 0.75, 0.9):
    acc, ref, _ = evaluate(tau_read=tau)
    cov = 1 - ref
    print(f"{tau:>9.2f} {cov:>8.3f} {acc:>11.3f} {(acc/cov if cov else 0):>11.3f}")

print("\n-- 干扰数 -> P(读到证据)（机制：softmax 分母）--")

关键设计决策：把生成拆成"先竞争注意力、再决定答案"的两阶段，而不是直接用 argmax 选答案。原因很实在：argmax 模型里，干扰块只要分数低于证据就完全不起作用，于是"干扰越多越糟"这个真实机制根本出不来。改成两阶段（Pread​ 决定是否采信证据，否则回落到先验）之后，干扰通过 softmax 分母影响 Pread​，位置通过折扣影响 logit，先验作为一个竞争块参与竞争 —— 三个机制都从公式里长出来，而不是被硬编码成结论。这也让"跟随率 = Pread​"成为一个可解释的等式。

练习#

  1. 补齐诊断矩阵。用上面的模拟器构造出 §1.2 表格里的四种情形（证据有效利用 / 靠先验 / 证据不足 / 没被读到），对每种情形打印必要性、充分性、跟随率三个数值，验证矩阵分类正确。提示："证据不足"可以用把证据里的值改成错误值来构造。

  2. 把 Sorder​ 测成置信区间。对每个深度跑多次随机种子，给出 Sorder​ 的 95% bootstrap 区间。回答：需要多少条查询才能把区间宽度压到 ±0.05？这个数量与"每深度样本量"是什么关系？

  3. 位置折扣 κ 与干扰数 m 的交互。扫描 κ∈{0,0.6,1.2,2.0} 与 m∈{0,10,50}，画出正确率矩阵。回答：(a) κ=0（无位置效应）时"把证据放首尾"还有收益吗？(b) 干扰很多时，位置优化能挽回多少？给出"先修哪一个"的判据。

  4. 去重与召回的权衡。在模拟器里模拟"去重"：把与目标证据相似度高于阈值 θ 的干扰块删掉。扫 θ，画出正确率与"证据被误删率"。回答：在什么 θ 下，去重的净收益最大？如果把"误删互补证据"的代价设为漏答，结论会怎么变？

  5. 引用一致率的可执行测量。设计一个算法：给定输出文本与它引用的 chunk，用逐句蕴含判定（可以用一个规则式的词项重叠基线）计算引用一致率。说明你如何构造负例（让引用与内容不符）来验证这个测量本身是否有效。

  6. 拒答阈值与业务选择。为两个场景画出风险-覆盖曲线并选工作点：(a) 医疗问答（错答代价 ≫ 拒答代价）；(b) 内部搜索助手（拒答代价高，错答可接受）。给出你对两个场景的"代价比"假设，并用它算出理论最优 τ（提示：最大化 cov(τ)⋅(prec(τ)⋅V−(1−prec(τ))C)）。

  7. grounding 指令的失效实验。构造"证据与先验冲突且证据可信度低"的场景（例如证据来自一个低权威来源）：回答：(a) grounding 指令会让模型盲信证据吗？(b) 如果会，怎么设计一个"按来源可信度加权"的 prompt 策略，并测它的代价（漏用正确证据的比例）？

  8. 跟随率与真实正确率的关系。在模拟器里同时记录"跟随率"和"正确率"，扫描先验偏置强度，画出两条曲线。回答：跟随率高是否一定意味着正确率高？（提示：当证据本身错误时，高跟随率 = 高错误率。）由此给出"只用跟随率做验收指标"的风险与补充指标。

小结#

  • "用了没有"必须先变成可测量：四个测试 = 必要性（删证据）、充分性（只留证据）、反事实交换（改值看跟随）、引用一致率；跟随率的交换值必须是语料不存在且记忆不可能知道的新值。
  • 反事实交换是最强的因果测试：它把"依赖检索"操作化为"输出跟着证据变"。⚠️ 合成实验里 plain 策略跟随率 0.785，而"无证据"策略 0.000。
  • 位置损耗可测：Sorder​=maxπ​acc−minπ​acc。⚠️ 实测 0.215 —— 仅把证据从中段挪到首尾就免费拿回；sandwich 策略（首尾各一份）把正确率从 0.785 抬到 1.000，代价是 token 翻倍。
  • 干扰通过 softmax 分母削弱证据：⚠️ Pread​ 从 m=0 的 0.604 掉到 m=10 的 0.110、m=50 的 0.026；端到端正确率 0.785 → 0.250 → 0.055 →（m=200）0.015。"多召回几条保险"在证据利用率上是负收益。
  • 先验竞争可测：PriorWin（输出等于先验值而非证据值的比例）在 plain 策略下为 0.215；加干扰后升到 0.945 —— 因为证据被抢走后，剩下的竞争里只剩先验。这解释了"为什么提高召回数量会让模型更自信地错"。
  • grounding 指令修的是先验竞争：把正确率 0.785→1.000、PriorWin 0.215→0；但它修不了召回、也修不了证据不足。它的正确位置是生成层加固。
  • 拒答是一条风险-覆盖曲线：⚠️ τ=0.60 时覆盖率 0.510、已答正确率 1.000；τ=0.45 时覆盖率 0.965、已答正确率 0.813。工作点由业务的错答/拒答代价比决定，不由"正确率越高越好"决定。
  • 常见错误：用引用率当 grounding 证据（装饰性引用）、只测必要性、用真实存在的值做反事实、把拒答当万能药、在召回问题上做 grounding 优化。
  • 修法有优先级：先确定类别 → 召回问题回召回层 → 位置问题先调顺序（零成本）→ 先验冲突加 grounding → 证据不足补召回或拒答 → 最后才换模型；一次只动一处，否则收益无法归因。
  • 补一句关于冲突：先验压过证据有三种形态 —— 旧值冲突（看 PriorWin）、常识冲突（看输出与证据的语义偏离）、多来源冲突（看同一问题的输出方差）。三种的处方不同，只测一种会漏掉更危险的两种。
  • 一句话："检索到了却没用"不是一种故障，而是四种 —— 没进上下文、进去了没被读到、读到了被先验压过、读到了但证据不足。四种对应四个层次，先用四个测试分开，再动手；而且一次只动一处。
