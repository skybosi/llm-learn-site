图捕获三条路：TorchScript / TorchDynamo / FX#

第 1 章的全景里第一环是捕获（capture）：把 Python 模型变成一张编译器能读的图。它看似只是"记下算子"，其实每个前端都在回答同一个清单——哪些算子执行了、输入是谁、结论在什么条件下成立。三家答案差别极大：同一段 if，有的前端捕获期就把它定型成一条路，有的变成一条必须事后核对的假设，还有的干脆说"这里不编译"。本课用真实 CPython 字节码对上三者的取材范围。

一、概念讲解#

1. 捕获的三步：取材、派发、收尾#

任何图捕获都能拆成三步：

步骤 要回答的问题 出错的样子
取材 编译器的输入是源码、字节码，还是"运行时真正发生的调用" 看到了没执行的分支 / 漏掉了动态派发
派发 谁把一次算子调用变成 IR 里的一个节点 记录不到算子（走不到该方法）/ 重复记录
收尾 这次捕获的结论在什么条件下还能用 没有条件，于是换一种输入就悄悄算错

术语先立住：计算图（computation graph）是"算子节点 + 张量边"的有向无环图；IR（intermediate representation）是编译器内部的数据结构；guard（守卫）是"这份结果只在这些条件下可用"的断言。

2. 路线 A：TorchScript —— 在源码层面做子集检查#

TorchScript 的 torch.jit.script 把 Python 源码重解析成自己的 IR，所以要为"这段 Python 属不属于可编译子集"给出静态答案：.item()（张量→Python 标量）、print（副作用）、迭代次数依赖运行时值的 while，都得显式处理或拒绝。好处是不依赖一次实际执行（可导出、可无输入编译）；代价是子集追不上 Python 生态，这也是重心后来转向动态捕获的原因之一。

3. 路线 B：FX —— 一次符号跟踪，路径即图#

torch.fx.symbolic_trace 用符号代理（Proxy）做单次跟踪：把示例输入换成会记录调用的代理对象，真跑一遍函数，每次算子调用写成一个节点——本课路线 A 就是它。弱点也在这"单次"上：if 是原生 Python 控制流，跟踪期走哪条路，图里就只有哪条路，事后没人提醒你"这张图只在另一次成立"。

4. 路线 C：TorchDynamo —— 在字节码层逐条派发#

TorchDynamo 取的材不是源码，而是 CPython 的字节码（bytecode）：它挂上求值循环的 frame 钩子，在函数即将执行时接管指令派发，一边按运行时真值走控制流，一边把张量相关指令记成 FX 图。相比源码方案它多看见两样东西：运行时真值（所以走得对分支），以及该分支本次成立这件事本身——后者记成 guard，下次不成立就重编译（第 3 课）。代价是只能在真正执行时捕获：产物是三件套（图、guard、运行时状态）；遇到无法安全接管的语义时，函数只能被切成若干段（第 4 课）。

5. 三条路的对照表#

TorchScript FX TorchDynamo
取材 Python 源码 / 子集 AST 一次符号跟踪的调用序列 CPython 字节码 + 运行时真值
控制流 静态分析，可保留 烧进图（当场定型） 按真值走，记 guard
需要样例输入 不需要 需要 不需要（在真实执行时捕获）
未知算子 编译期报错或走子图 记录成 call_function 节点 按图断裂处理
典型代价 子集覆盖不足 无 guard，换输入即错 运行时捕获开销 + 重编译

6. 常见坑#

  • 把 trace 当成"分析"：trace 只是"跑一遍并记录"，不证明普遍性；没有 guard 的图只是一个样例的执行记录而已。
  • 以为 torch.jit.trace 与 symbolic_trace 是一回事：前者用真实张量跑、记数值路径，后者用代理对象跑、记调用序列，二者都不记控制流条件。
  • 忽略 guard 的粒度：guard 可细到 x.shape[0] == 4；细粒度换精确，也换频繁重编译（第 3 课的账）。

二、可运行代码示例#

下面这段只依赖标准库（python3.10 与 python3.14 都逐字跑过，输出一致）：Proxy 是 FX 式记录代理；run_bytecode 是手工版 Dynamo，逐条读真实字节码、按运行时真值选路，并把用到的条件记成 guard；script_check 是 TorchScript 式子集检查器。

# ===== 三条捕获路线的可打印骨架：tracer / 字节码前端 / 子集检查器 =====
# 只依赖标准库；本机验证：python3.10（输出与 3.14 一致）
import ast, dis, inspect

# ---------- 0. 统一 IR：节点 = (op, args)；args 里 str/float = 叶子，V = 前面节点的引用 ----------
GRAPHS = []                                                  # 本演示同时只有一个活跃图

class Graph:
    def __init__(self): self.nodes = []; GRAPHS.append(self)   # nodes[i] = (op, [arg, ...])
    def emit(self, op, *args):
        self.nodes.append((op, list(args))); return V(op, len(self.nodes) - 1)
    def ops(self): return [op for op, _ in self.nodes]
    def dump(self):
        L = []
        for i, (op, args) in enumerate(self.nodes):
            a = ', '.join(f'%{x.id}' if isinstance(x, V) and x.id is not None else repr(x)
                          for x in args)
            L.append(f'  %{i} = {op}({a})')
        return '\n'.join(L)

class V:
    """IR 里一个值：id 是节点编号；算子重载只负责建节点，不负责算数。"""
    def __init__(self, op, i): self.op, self.id = op, i
    def __add__(self, o):  return _mk('add', self, o)
    def __radd__(self, o): return _mk('add', o, self)
    def __sub__(self, o):  return _mk('sub', self, o)
    def __rsub__(self, o): return _mk('sub', o, self)
    def __mul__(self, o):  return _mk('mul', self, o)
    def __rmul__(self, o): return _mk('mul', o, self)
    def __gt__(self, o):   return _mk('gt', self, o)
    def __repr__(self):    return f'%{self.id}'

def _mk(op, a, b):
    for v in (a, b):                                         # 找到这次运算所属的图
        if isinstance(v, Proxy): return v.g.emit(op, a, b)
    return GRAPHS[-1].emit(op, a, b)                         # 图到图之间的运算（简化）

class Proxy(V):
    """路线 B（FX 式）的输入代理：只是个"原样记录"的值。"""
    def __init__(self, g, name): self.g, self.name, self.id = g, name, None
    def __repr__(self): return self.name

# ---------- 1. 路线 A：FX 式 tracer —— 喂数据跑一遍，算子调用被记成节点 ----------
def fn(x, flag):                       # 同一份 Python 函数：赋值与 if 都是原生 Python 控制流
    a = x + 1.0
    if flag > 0:
        b = a * 2.0
    else:
        b = a - 3.0
    return b

def trace(flag):
    g = Graph()
    return g, fn(Proxy(g, 'x'), flag)  # 走哪条路，图里就只有哪条路

# ---------- 2. 路线 B：字节码前端 —— 解释 CPython 字节码，分支按运行时真值走 ----------
BIN10 = {'BINARY_ADD': 'add', 'BINARY_SUBTRACT': 'sub', 'BINARY_MULTIPLY': 'mul',
         'BINARY_TRUE_DIVIDE': 'div', 'BINARY_POWER': 'pow'}
BINSYM = {'NB_ADD': 'add', 'NB_SUBTRACT': 'sub', 'NB_MULTIPLY': 'mul',
          'NB_TRUE_DIVIDE': 'div', 'NB_POWER': 'pow'}

def binop_name(ins):
    """3.11 及以前算术是独立指令；3.12 起合并成 BINARY_OP，arg 是操作编号。"""
    if ins.opname in BIN10: return BIN10[ins.opname]
    nb = getattr(dis, '_nb_ops', [])
    return BINSYM.get(nb[ins.arg][0] if ins.arg < len(nb) else '?', f'op{ins.arg}')

def run_bytecode(func, **args):
    """极简字节码前端：算术/比较/跳转/返回记成节点。与 TorchDynamo 的差别只在"谁逐条派发"
    ——Dynamo 挂的是 CPython 求值循环的 frame 钩子，这里我们手工走一遍同样的字节码。"""
    co, instrs, g = func.__code__, list(dis.get_instructions(func)), Graph()
    consts, env, stack = co.co_consts, dict(args), []
    idx = {ins.offset: k for k, ins in enumerate(instrs)}    # 3.10 跳转目标是绝对字节偏移
    def jump(ins):
        return idx.get(ins.argval, ins.arg if isinstance(ins.arg, int) else 0)
    i = 0
    while i < len(instrs):
        ins = instrs[i]; op, arg = ins.opname, ins.arg
        if op in ('LOAD_FAST', 'LOAD_FAST_BORROW', 'LOAD_FAST_CHECK'):
            stack.append(env.setdefault(co.co_varnames[arg], co.co_varnames[arg]))
        elif op == 'LOAD_CONST':      stack.append(consts[arg])
        elif op == 'LOAD_SMALL_INT':  stack.append(arg)
        elif op in BIN10 or op == 'BINARY_OP':
            b, a = stack.pop(), stack.pop()
            stack.append(g.emit(binop_name(ins), a, b))
        elif op == 'COMPARE_OP':                             # argrepr 形如 "bool(>)" 或 ">"
            b, a = stack.pop(), stack.pop()
            if isinstance(a, V) or isinstance(b, V):         # 含张量 → 记节点，条件由 guard 承担
                stack.append(g.emit('gt' if '>' in ins.argrepr else 'lt', a, b))
            else:                                            # 全是 Python 值 → 在捕获期直接算掉
                stack.append(bool(a > b) if '>' in ins.argrepr else bool(a < b))
        elif op.startswith('POP_JUMP') and 'IF_FALSE' in op:
            v = stack.pop()
            g.emit('guard', 'T' if v else 'F', '命中分支')    # 这个条件只有本次为真，必须记下来
            if isinstance(v, bool):                           # Python 真值 → 按它选路
                if not v: i = jump(ins); continue
            else:                                             # 张量条件：真前端必须在这里断裂
                g.emit('break', '条件依赖张量值'); break
        elif op == 'STORE_FAST':
            env[co.co_varnames[arg]] = stack.pop(); g.emit('store', co.co_varnames[arg])
        elif op == 'RETURN_VALUE':
            return g, stack.pop()
        i += 1
    raise RuntimeError('没有 RETURN_VALUE')

# ---------- 3. 路线 C：TorchScript 式子集检查器 ----------
UNSUPPORTED_CALLS = {'item': '张量→Python 标量', 'print': '有副作用', 'open': 'I/O 副作用'}
UNSUPPORTED_NODES = (ast.Import, ast.ImportFrom, ast.While, ast.Try, ast.Global, ast.Nonlocal)

def script_check(func):
    tree = ast.parse(inspect.getsource(func)) if inspect.isfunction(func) else func
    bad = []
    for node in ast.walk(tree):
        if isinstance(node, UNSUPPORTED_NODES):
            bad.append(type(node).__name__)
        if isinstance(node, ast.Call) and getattr(node.func, 'attr', '') in UNSUPPORTED_CALLS:
            bad.append(f'{node.func.attr}() ← {UNSUPPORTED_CALLS[node.func.attr]}')
    return bad

def leaky(x, thresh):
    s = x.item()
    print(s)
    while s > 0:
        s = s - thresh
    return x

if __name__ == '__main__':
    print('--- A：FX 式 tracer（同一函数，两条真值路径）---')
    for flag in (1, -1):
        g, out = trace(flag)
        print(f'flag={flag:>2} → 节点 {g.ops()}，输出 = {out}')
    print('--- B：字节码前端（分支按运行时真值走，并在图里留下 guard）---')
    for flag in (True, False):
        g, out = run_bytecode(fn, x=Proxy(Graph(), 'x'), flag=flag)
        print(f'flag={flag!s:<5} →')
        print(g.dump())
    print('--- C：子集检查器 ---')
    print('fn     →', script_check(fn) or '整图可编译')
    print('leaky  →', script_check(leaky))

实际输出（python3.10.16，与 python3.14.5 输出一致）：

--- A：FX 式 tracer（同一函数，两条真值路径）---
flag= 1 → 节点 ['add', 'mul']，输出 = %1
flag=-1 → 节点 ['add', 'sub']，输出 = %1
--- B：字节码前端（分支按运行时真值走，并在图里留下 guard）---
flag=True  →
  %0 = add(x, 1.0)
  %1 = store('a')
  %2 = guard('T', '命中分支')
  %3 = mul(%0, 2.0)
  %4 = store('b')
flag=False →
  %0 = add(x, 1.0)
  %1 = store('a')
  %2 = guard('F', '命中分支')
  %3 = sub(%0, 3.0)
  %4 = store('b')
--- C：子集检查器 ---
fn     → 整图可编译
leaky  → ['While', 'item() ← 张量→Python 标量']

三处对照值得逐条读：

  1. 路线 A 的图随输入变：flag=1 得 ['add','mul']，flag=-1 得 ['add','sub']，两张图都不告诉你"另一条分支存在"——这正是 torch.fx.symbolic_trace 面对标量控制流的行为。
  2. 路线 B 多留一个 guard 节点：它记的是"本次 flag > 0 成立"；没有 guard，编译器就没资格复用这张图。
  3. 路线 C 的两条诊断：item() 把张量降成 Python 标量，while 的迭代次数依赖运行时值，按子集规则都该在编译期拒掉。

三、练习#

  1. 实现：给 run_bytecode 加"常量折叠"：BINARY_OP 两个操作数都是 Python 数值时直接算结果、不建节点；用两个 flag 各跑一遍，说明它为什么不影响正确性。
  2. 解释：路线 A 的两张图为何"各自都对、合起来错"？什么输入会拿到错误答案？
  3. 对比/验证：把 if flag > 0 换成 if x.sum() > 0（张量条件），用两条路线各跑一遍。路线 B 会在 guard 后记一个 break 节点——它与 while 被拒绝是否同一类原因？
  4. 思考：路线 A 想补上"另一条分支"，除了加 guard，还能用多组输入各捕获一次再合并？列出代价。
