内存规划与融合的联合决策#

第 4 章第 3 课把 512-token Transformer 层的中间池峰值从 96.0 KiB 压到 42.0 KiB；本章前三课又删掉中间张量、把 10 个内核收成 8 个。两件事单独看都对，却互为输入：融合改变了"要规划的对象集合"，内存规划的结果又决定融合值不值。顺序错了就白算——先做内存规划再融合，已融掉的张量仍会被分配、被算进峰值。本课把两者放进同一个决策循环，用一组可对照的数字说明耦合在哪里。

一、概念讲解#

1. 融合对内存规划做了两件事#

  • 删掉张量：被融进消费者的中间值不再需要缓冲。本课场景里 mid（24.0 KiB）与 attn（6.0 KiB）消失，中间张量总量 96.0 → 66.0 KiB。
  • 改写生命周期：簇的输入必须在簇执行时还活着（簇把多个张量的生死合成一个区间）。所以融合不一定让张量活得更短：簇的输出常要活到原末成员的最后一次读。

2. 省下的张量 ≠ 省下的峰值#

这是本课最反直觉的一处。代码实测：融合后"不复用峰值"从 96.0 降到 66.0 KiB（这是简单的求和减少），但"复用 + 原地写回"的峰值仍然是 42.0 KiB。原因在输出的第 3 节：峰值时刻在世的张量是 ['mid+act', 'out']（融合后）与 ['act', 'out']（融合前）——attn 与 mid 的消失并未改变"此刻同时在世多少"。融合省流量是确定的账，省多少峰值必须重跑分配器才知道，不能拿被删掉的张量大小去减峰值。

3. 与原地写回的相互作用#

第 4 章第 3 课的原地写回清单是 [('v','h'), ('attn','q'), ('p','attn'), ('o','p'), ('act','mid'), ('out','act')]；本课把 mid→act、attn→p 融合之后，同一份清单变成 [('v','h'), ('attn+p','q'), ('o','attn+p'), ('out','mid+act')]。两处变化值得注意："act 原地写进 mid"这条决策随 mid 一起消失了；而新的原地对出现在簇的输出上。实践含义：原地写回与融合都会引入别名，两者叠加时"谁覆盖谁、什么时候可以覆盖"必须用同一份生命周期表判定，不能各算一份。

4. 联合目标与搜索#

两个指标同时存在时，决策就不再是"能融就融"。一个可用的目标函数是加权和：

score=traffic+α⋅peak+β⋅nkernel​

三个权重按部署目标定：显存紧张时调大 α，启动开销敏感（小 batch、端侧）时调大 β。本课代码做枚举式评估：第 1 节逐个算候选（含不合法理由），第 2 节把"接受全部合法点链融合"与"复用 / 原地写回"组合成五张方案。工业编译器通常再加一层搜索：按收益排序逐个试，每接受一个就把生命周期、峰值、内核数重算一遍，收益为零或与已有融合重叠就拒绝。这是贪心，不保证全局最优，但比枚举全组合可行——练习 3 让你补上这层搜索。

5. 决策要进编译缓存#

融合决策依赖形状（tile、生命周期、原地合法性都可能随 shape 变化），必须与第 2 章的编译键绑在一起：守卫命中就复用上次的融合方案与内存布局，守卫失败就整条重编译。把融合决策当作"编译期一次性、可缓存的产物"，否则省下的带宽会被决策开销吃掉。

6. 常见坑#

  • 先后各算一遍：内存规划 → 融合，或融合 → 内存规划，都只做了一次单向传递，得到的峰值/流量与联立结果不一致。
  • 把删除的张量从峰值里再减一次：峰值是"同时在世的最大值"，不是求和，删掉的张量未必在峰值时刻。
  • 忽略别名交互：融合簇的输出与原地写回的目标可能是同一块缓冲，别名冲突要靠生命周期表统一判定。
  • 只优化一个指标：融合降流量但抬寄存器（上一课）；复用降峰值但可能让某个输入活得更久。三个指标要一起看。

二、可运行代码示例#

纯 Python（无第三方依赖），场景与第 4 章第 3 节一致（512-token Transformer 层、1 元素 = 4 字节），分配器同为贪心首次适配。第 1 节逐个评估候选（含不合法原因），第 2 节把融合 × 复用 × 原地写回放进同一张表，第 3 节打印"峰值时刻谁在世"，第 4 节对比融合前后的原地写回清单。

# ---- 第 4 课示例：融合与内存规划的联立决策（纯 Python，无第三方依赖）----
# 场景沿用第 4 课第 3 节的 512-token Transformer 层；1 元素 = 4 字节（fp32）
KiB = lambda elems: elems * 4 / 1024

OPS = [('h',    ['x'],        1536), ('q',    ['h', 'Wq'],  1536),
       ('k',    ['h', 'Wk'],  1536), ('v',    ['h', 'Wv'],  1536),
       ('attn', ['q', 'k'],   1536), ('p',    ['attn'],     1536),
       ('o',    ['p', 'v'],   1536), ('mid',  ['o', 'W1'],   6144),
       ('act',  ['mid'],      6144), ('out',  ['act', 'W2'], 1536)]
PARAMS = {'x': 1536, 'Wq': 2304, 'Wk': 2304, 'Wv': 2304, 'W1': 18432, 'W2': 6144}
SEQ = [o for o, _, _ in OPS]
SIZE = {o: s for o, d, s in OPS}
DEPS = {o: list(d) for o, d, s in OPS}

class Cluster:
    """融合簇：成员之间的中间张量不落地；输入 = 成员的外部输入；输出 = 末成员输出。"""
    def __init__(self, members):
        self.members, self.name = members, '+'.join(members)
        inner = set(members)
        self.deps = [d for m in members for d in DEPS[m] if d not in inner]
        self.size = SIZE[members[-1]]

def build(fused_pairs):
    """fused_pairs：[(生产者, 消费者)]，只支持执行序里相邻的点链。"""
    producer_of = {c: p for p, c in fused_pairs}
    order, i = [], 0
    while i < len(SEQ):
        members = [SEQ[i]]
        while i + 1 < len(SEQ) and producer_of.get(SEQ[i + 1]) == members[-1]:
            members.append(SEQ[i + 1]); i += 1
        order.append(Cluster(members)); i += 1
    return order

def analyze(order):
    owner = {m: c.name for c in order for m in c.members}
    readers = {c.name: [] for c in order}
    for c in order:
        for d in c.deps:
            readers.setdefault(owner.get(d, d), []).append(c.name)
    pos = {c.name: t for t, c in enumerate(order)}
    spans = {}
    for t, c in enumerate(order):
        last = max([pos[r] for r in readers.get(c.name, []) if r in pos] + [t])
        spans[c.name] = (t, last)
    return owner, readers, spans

def traffic(order, owner):
    """DRAM 流量（元素数）：每个张量写一次；每个读它的内核读一次；参数按读次数计。"""
    moved = sum(c.size for c in order)                       # 写
    for c in order:
        for d in c.deps:
            src = next((x for x in order if x.name == owner.get(d, d)), None)
            moved += src.size if (src is not None and d in owner) else PARAMS.get(d, 0)
    return moved

def peak_greedy(order, spans, inplace=False):
    """第 4 课第 3 节的贪心首次适配；inplace 允许"输入最后一读"原地写回。"""
    owner = {m: c.name for c in order for m in c.members}
    size = {c.name: c.size for c in order}
    last_read = {}
    for t, c in enumerate(order):
        for d in c.deps:
            last_read[d] = t; last_read[owner.get(d, d)] = t
    taken, high, table, used = [], 0, {}, []
    for t, c in enumerate(order):
        need = size[c.name]
        if inplace:
            for d in c.deps:
                k = owner.get(d, d)
                if last_read.get(d) == t and k in size and size[k] >= need and k in table:
                    table[c.name] = table[k]; used.append((c.name, k)); need = None; break
        if need is None: continue
        active = [(a, b) for a, b, rel in taken if rel >= t]
        free, end = [], 0
        for a, b in sorted(active):
            if a > end: free.append((end, a - end))
            end = max(end, b)
        if end < high: free.append((end, high - end))
        off = next((a for a, sz in free if sz >= need), None)
        if off is None: off, high = high, high + need
        taken.append((off, off + need, spans[c.name][1])); table[c.name] = (off, need)
    return high, used, table

def report(tag, fused_pairs, inplace):
    order = build(fused_pairs)
    owner, readers, spans = analyze(order)
    moved = traffic(order, owner)
    pk, used, table = peak_greedy(order, spans, inplace)
    print(f'  {tag:<24}{sum(c.size for c in order) * 4 / 1024:>9.1f}{pk * 4 / 1024:>12.1f}'
          f'{moved * 4 / 1024:>11.1f}{len(order):>7}')
    return order, spans, table, used, moved, pk

def peak_live(order, spans, table):
    hi = max(off + sz for off, sz in table.values())
    t_hi = max(t for t, c in enumerate(order) if table[c.name][0] + table[c.name][1] >= hi)
    live = [c.name for c in order if table[c.name][0] + table[c.name][1] >= hi
            and spans[c.name][0] <= t_hi <= spans[c.name][1]]
    return hi, t_hi, sorted(live)

print('=== 0. 场景：512-token Transformer 层（沿用第 4 课第 3 节）===')
o0 = build([]); own0, rd0, sp0 = analyze(o0)
print(f'  中间张量 {len(o0)} 个共 {KiB(sum(c.size for c in o0)):.1f} KiB；'
      f'参数池 {KiB(sum(PARAMS.values())):.1f} KiB（常驻，不参与复用）')
base_moved = traffic(o0, own0)
print(f'  不融合 + 不复用：峰值 {KiB(sum(c.size for c in o0)):.1f} KiB，流量 {KiB(base_moved):.1f} KiB')

print('\n=== 1. 候选逐一评估：融掉一个生产者，就省掉它的"写一次 + 读一次" ===')
CAND = [('mid',  'act', True,  '点链：act = gelu(mid)'),
        ('attn', 'p',   True,  '点链：p = softmax(attn)'),
        ('act',  'out', False, '不透明算子：out = act @ W2（矩阵乘）'),
        ('p',    'o',   False, '不透明算子：o = p @ v（矩阵乘）'),
        ('h',    'q',   False, 'h 有 3 个消费者：融进 q 就要为 k/v 重算或保留')]
print(f'  {"候选":<11}{"判定":<5}{"省流量":>12}{"内核":>7}   依据')
for p, c, legal, why in CAND:
    if legal:
        o = build([(p, c)]); own, rd, sp = analyze(o)
        saved = f'{KiB(base_moved - traffic(o, own)):.2f} KiB'
        kn = f'{len(o0)}→{len(o)}'
    else:
        saved, kn = '—（不合法）', '—'
    print(f'  {p + "→" + c:<11}{"可融" if legal else "拒绝":<6}{saved:>12}{kn:>7}   {why}')

print('\n=== 2. 联合决策：融合 × 复用 × 原地写回，三个指标一起算 ===')
print(f'  {"方案":<24}{"不复用峰值":>9}{"复用峰值":>12}{"流量":>11}{"内核":>7}')
print(f'  {"":<24}{"KiB":>9}{"KiB":>12}{"KiB":>11}')
FUSE = [('mid', 'act'), ('attn', 'p')]
report('A 不融合 + 不复用', [], False)
oB, spB, tbB, usedB, mB, pB = report('B 不融合 + 复用 + 原地', [], True)
report('C 只融合，不复用', FUSE, False)
report('D 融合 + 复用', FUSE, False)
oE, spE, tbE, usedE, mE, pE = report('E 融合 + 复用 + 原地', FUSE, True)

print('\n=== 3. 峰值时刻谁在世：省掉的张量 ≠ 省下的峰值 ===')
for tag, order, sp, tb in [('不融合', oB, spB, tbB), ('融合后', oE, spE, tbE)]:
    hi, t_hi, live = peak_live(order, sp, tb)
    print(f'  {tag:<4} 峰值 {KiB(hi):5.1f} KiB，出现在第 {t_hi} 步，此刻在世：{live}')
print('  attn 与 mid 已经不存在了，但峰值仍由"此刻同时在世的张量"决定：')
print('  融合省流量是确定的（省掉一次写 + 一次读），省多少峰值必须重跑分配器才知道。')

print('\n=== 4. 为什么必须联立：融合改变了"要规划的对象" ===')
print(f'  不融合时可原地写回的对：{usedB}')
print(f'  融合后可原地写回的对：{usedE}')
print(f'  融合掉的张量 ["attn", "mid"] 已不存在，"act 原地写进 mid" 这条决策随之作废：')
print(f'  峰值 {KiB(pB):.1f} → {KiB(pE):.1f} KiB，流量 {KiB(mB):.1f} → {KiB(mE):.1f} KiB，内核 10 → 8。')
print('  先做内存规划再融合，会为已经不存在的张量分配内存、并把它算进峰值——两件事必须一起算。')

三、练习#

  1. 实现：在 OPS 里给 p 后面插一个逐元素节点 scale（['p']，1536 元素），把融合候选从 attn→p 扩成 attn→p→scale 三段链，重跑第 2 节的五张方案，观察流量与峰值各变化多少，并解释为什么两者幅度不同。
  2. 解释：为什么"只融合，不复用"（方案 C）的峰值（48.0 KiB）比"不融合 + 复用"（方案 B 的 42.0 KiB）更高？把两个方案的峰值时刻在世张量列出来对照。
  3. 对比/验证：在 CAND 上实现一个贪心接受循环（按省流量排序，每接受一个候选就重算流量、峰值、内核数），再把目标函数 score=traffic+α⋅peak+β⋅nkernel​ 写成代码，令 α 从 0 增到很大，观察被选中的候选集合是否改变；给出一个 α 的临界值并解释它的物理含义。
  4. 思考：训练场景下激活要活到反向（第 4 章第 3 节提过），融合的收益与内存规划的空间都会变。如果只允许你改一处，你会先做融合还是先做内存复用？给出判据（提示：分别对流量与峰值求偏导，看哪个更接近瓶颈）。
