INT8/INT4 量化精度#

上一课说 FP16/BF16 把显存减半，那还能更省吗？能——把浮点权重进一步压缩成 8 位甚至 4 位整数，这就是量化（Quantization）。INT8 让 70B 模型从 140 GB 降到 70 GB，INT4 降到约 35 GB，带宽需求同步下降，速度近乎翻倍/翻四倍。代价是精度损失，本课就讲清楚这笔账怎么算。

一、概念讲解#

1. 量化的核心：一个 scale 映射#

量化把一段浮点区间线性映射到整数区间。以对称 INT8 为例（整数范围 −127∼127，一般用 127 作正界、避免 −128 的绝对值不对称）：

scale=127max∣w∣​,wint​=round(scalew​)

反量化就是乘回去：

w≈wint​×scale

整个思想就是用一个 scale 因子，把"浮点的分布"压缩成"整数的刻度"。scale 越贴合权重分布，量化误差越小。

2. 量化粒度：per-tensor vs per-channel vs per-group#

  • per-tensor：整个张量共用一个 scale，最简单，但误差大（不同行/列的数值范围可能差很多）；
  • per-channel / per-row：每一行（每个输出通道）一个 scale，误差小很多，是推理的常见选择；
  • per-group：把每行再切成若干组，每组一个 scale，是 INT4 量化的主流做法（GPTQ/AWQ 等都基于 group-wise）。

粒度越细，scale 越多、误差越小，但需要存储的 scale/零点也越多——这是"精度 vs 开销"的又一次权衡。

3. INT4：更省，但更要小心#

INT4 的整数范围只有 −8∼7，只有 16 个刻度，单个 scale 的量化误差比 INT8 大得多。因此 INT4 几乎必须配合 per-group scale + 权重校正（如 GPTQ 的误差补偿、AWQ 的异常值保护） 才能把精度损失控制在可接受范围。好处是显存再减半：70B 模型 INT4 约 35 GB（外加少量 scale 开销）。

4. 收益清单（以 70B 模型为例）#

精度 权重显存 相对 FP16 H100 读一遍的时间
FP16 140 GB 1× ~42 ms
INT8 70 GB 0.5× ~21 ms
INT4 35 GB 0.25× ~10 ms

配合"读一遍权重决定吞吐"的结论，量化带来的速度提升几乎是线性的——这就是为什么量化是推理优化第一板斧。

5. 代价与取舍#

量化不是免费的：权重被压缩后，矩阵乘要先把整数反量化回浮点再算（或直接用整数乘加），引入额外开销；过度的 INT4 可能让模型"变笨"（困惑度上升、任务性能下降）。工程上的判断标准永远是：在可接受的精度损失内，把字节数压到最小。

二、可运行代码示例#

亲手实现对称 INT8 量化，比较 per-tensor 与 per-channel 的误差，并算显存收益。

import numpy as np

# ---- 例 1：对称 per-tensor INT8 量化与反量化 ----
def quantize_int8(w):
    scale = np.max(np.abs(w)) / 127.0
    q = np.round(w / scale).astype(np.int8)
    return q, scale

def dequantize_int8(q, scale):
    return q.astype(np.float32) * scale

w = np.random.randn(4, 8).astype(np.float32) * 0.5
q, scale = quantize_int8(w)
w_hat = dequantize_int8(q, scale)
print("per-tensor 量化 均方误差(MSE) =", np.mean((w - w_hat) ** 2))

# ---- 例 2：per-channel（按行）量化，误差更小 ----
def quantize_int8_per_channel(w):
    scale = np.max(np.abs(w), axis=1, keepdims=True) / 127.0
    q = np.round(w / scale).astype(np.int8)
    return q, scale

q2, scale2 = quantize_int8_per_channel(w)
w_hat2 = dequantize_int8(q2, scale2)
print("per-channel 量化 MSE =", np.mean((w - w_hat2) ** 2))

# ---- 例 3：INT4 的刻度更粗，误差更大 ----
def quantize_int4(w):
    scale = np.max(np.abs(w)) / 7.0          # INT4 范围 -8..7，用 7 作正界
    q = np.round(w / scale).astype(np.int8)   # numpy 无 int4，用 int8 存值
    return q, scale

q4, scale4 = quantize_int4(w)
w_hat4 = q4.astype(np.float32) * scale4
print("per-tensor INT4 量化 MSE =", np.mean((w - w_hat4) ** 2))

# ---- 例 4：离群值对量化误差的影响 ----
w_outlier = w.copy()
w_outlier[0, 0] = 20.0                        # 塞进一个大离群值
qo, scaleo = quantize_int8(w_outlier)
w_hat_o = dequantize_int8(qo, scaleo)
print("\n有离群值时 per-tensor INT8 MSE =", np.mean((w_outlier - w_hat_o) ** 2),
      "（scale 被拉大，整体误差变高）")

# ---- 例 5：量化的显存收益 ----
params = 70e9
for name, bits in {"FP16": 16, "INT8": 8, "INT4": 4}.items():
    print(f"\n70B 模型 {name}: 权重约 {params * bits / 8 / 1e9:.0f} GB")

要点：例 1 到例 3 让你看到"粒度越粗、位数越少，误差越大"；例 4 是量化里最著名的坑——少数离群值会撑大 scale，拖累整体精度，这正是 per-channel、per-group 以及 AWQ"保护异常值"要解决的问题；例 5 落到收益：INT4 把 140 GB 压到 35 GB。
