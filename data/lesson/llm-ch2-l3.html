GPT 演进#

从 2018 年的 GPT-1 到 ChatGPT，GPT 家族走过了一条清晰的演进路线：先堆规模，再学对齐，最后走向多模态与工具使用。这一课按时间线把每一代"解决了什么问题、引入了什么新东西"讲清楚，重点落在 GPT-3 的上下文学习、以及从 InstructGPT 到 ChatGPT 的 RLHF 对齐——因为这两个转折，一个决定了"大模型能做什么"，一个决定了"大模型敢不敢用"。

一、概念讲解#

1. GPT-1（2018）：提出"生成式预训练 + 微调"#

GPT-1 的贡献不在规模（只有 1.17 亿参数），而在路线：先在无标注文本上做"预测下一个词"的生成式预训练，再在每个下游任务上微调。它证明了"先学通用语言、再适配任务"（第 1 章的范式二）可行，为整个 GPT 家族定下了基调。它的局限是仍需为每个任务微调一份模型，且规模尚小。

2. GPT-2（2019）：放大规模，验证"零样本迁移"#

GPT-2 把参数提到 15 亿、数据更大，并做了一个前瞻性实验：不做任何微调，直接让模型在下游任务上"零样本"推理。它在部分任务上已能靠"自然语言描述 + 答案"的方式表现不错。虽然当时看效果还不稳定，但它是 GPT-3 上下文学习的先声，也第一次把"多任务学习者"作为语言模型的定位提了出来。

3. GPT-3（2020）：1750 亿参数，上下文学习登场#

GPT-3 是关键一跃：1750 亿参数、训练约 3000 亿 token。它没有为下游任务微调，而是靠上下文学习（in-context learning）——在提示里给几个示例（few-shot），模型当场"学会"新任务。它展示了"一个模型、多种任务"（范式三）的惊人能力，也让人们第一次普遍意识到：规模本身就能带来新能力。GPT-3 是今天所有"提示工程"的起点。

4. InstructGPT / ChatGPT（2022）：从"会接话"到"听指令、更安全"#

GPT-3 虽然强大，但它是"续写"模型：你问它问题，它可能继续往下编故事，而不是乖乖回答；还会输出有害、不实的内容。为了让模型对齐人类意图，OpenAI 在 InstructGPT 里引入了 RLHF（基于人类反馈的强化学习），分三步：

  1. 监督微调（SFT）：请标注员写下"高质量的回答"，用这些 (指令, 理想回答) 数据微调模型，让它先学会"听指令、好好回答"；
  2. 训练奖励模型（RM）：让模型对同一指令生成多个回答，标注员给这些回答排序，训练一个"奖励模型"来给回答打分（越符合人类偏好分越高）；
  3. PPO 强化学习：用奖励模型的打分作为奖励信号，用 PPO 算法继续优化模型，让它生成的回答"奖励分"更高。

经过这三步，模型从"预测下一个词"转向"生成人类觉得有用、无害、诚实的回答"。ChatGPT 就是 InstructGPT 的对话化版本：用对话格式组织，配合这一套对齐流程，才成为能广泛使用的产品。

5. GPT-4（2023）及以后：多模态、长上下文、更强的对齐#

GPT-4 在 GPT-3.5 的基础上继续放大，并引入多项能力：多模态输入（能看图像）、更长的上下文、更强的推理与事实一致性，以及对安全对齐的进一步强化。此后方向继续分叉：一端追求更强的通用能力与工具调用，一端追求更高效的推理与可控成本。贯穿始终的，仍是 GPT-1 定下的那条主线——统一的生成式目标 + 不断放大的规模 + 逐步加强的对齐。

6. 演进背后的三条主线#

回头看，GPT 的演进可以用三句话概括：

  1. 规模：GPT-1 → GPT-3，参数扩大 1500 倍，能力随缩放定律涌现；
  2. 对齐：GPT-3 → InstructGPT/ChatGPT，从"续写"变成"服从指令、安全有用"；
  3. 扩展：GPT-4 之后，向多模态、长上下文、工具使用延伸。

二、可运行代码示例#

先直观感受 GPT-3 的标志性能力——few-shot 提示。我们用一个提示构建函数，把"示例 + 新问题"拼好交给模型：

from transformers import pipeline, set_seed

gen = pipeline("text-generation", model="sshleifer/tiny-gpt2")

def few_shot(prefix, examples, query):
    """把若干 (输入, 输出) 示例和新问题拼成 GPT-3 风格的 few-shot 提示。"""
    parts = [prefix]
    for src, tgt in examples:
        parts.append(f"{src} -> {tgt}")
    parts.append(f"{query} ->")
    return "\n".join(parts)

prompt = few_shot(
    "把中文翻译成英文：",
    [("狗", "dog"), ("猫", "cat"), ("鸟", "bird")],
    "鱼",
)
set_seed(0)
print("few-shot 提示:\n" + prompt + "\n")
print("模型续写:", gen(prompt, max_new_tokens=10)[0]["generated_text"])

注意：tiny-gpt2 太小，few-shot 效果不稳定——这正说明第 1 章的结论：上下文学习是规模带来的能力，小模型做不好，GPT-3 级别的大模型才行。

再看"基础模型 vs 指令模型"的区别，理解 RLHF 到底改变了什么：

from transformers import pipeline, set_seed

# 基础模型：只会按训练目标"续写"，不保证服从指令
base = pipeline("text-generation", model="sshleifer/tiny-gpt2")
question = "3 加 5 等于几？请只回答一个数字。"
set_seed(0)
print("基础模型（续写式）输出:")
print(base(question, max_new_tokens=20)[0]["generated_text"])

# 对话/指令模型：按 messages 组织，内部套用聊天模板，学会"只回答结果"
# 示意（真实流程由 tokenizer.apply_chat_template(messages) 自动拼特殊标记）：
messages = [
    {"role": "system", "content": "你是一个严谨的数学助手，只输出最终答案。"},
    {"role": "user", "content": "3 加 5 等于几？"},
]
template = ("<|system|>你是一个严谨的数学助手，只输出最终答案。\n"
            "<|user|>3 加 5 等于几？\n<|assistant|>8")
print("\n对话模型（指令式）示意输出:\n" + template)

基础模型面对"请只回答一个数字"往往继续往下写废话或编故事，而经过 SFT + RLHF 的对话模型学会了"识别指令、只给结果"。对齐的本质，就是让模型的生成分布从"像人话"进一步变成"有用且无害"。

三、练习#

  1. 修改 few_shot 函数，把示例从 3 条减到 0 条（zero-shot），用 tiny-gpt2 分别跑，比较 zero-shot 与 few-shot 的输出差异，并解释为什么示例数量在 GPT-3 上影响显著、在 tiny-gpt2 上不明显。
  2. 画出 RLHF 三阶段的流程图，并在每阶段旁标注"输入是什么、优化目标是什么、谁在提供信号（人类/模型）"。
  3. 查 InstructGPT 论文，找出"SFT 之后为什么还需要奖励模型 + PPO，而不是直接停在 SFT"的理由，用一两句话概括。
  4. 思考题：为什么 ChatGPT 能"听懂"并拒绝有害请求，而 GPT-3 原始模型不能？把答案落到"预训练目标 vs 对齐目标"的区别上。
