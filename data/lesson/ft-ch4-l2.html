PEFT 库#

上一课我们把 LoRA 挂到了量化基座上，但那些 LoraConfig、get_peft_model 到底是哪来的？它们来自 Hugging Face 的 PEFT（Parameter-Efficient Fine-Tuning） 库——一个把 LoRA、Prefix-tuning、Prompt tuning、IA3 等所有"只训一小撮参数"的方法统一起来的上层框架。这一课我们学透 PEFT 的抽象：怎么注入、怎么保存、怎么合并，以及它为什么能让不同微调方法"换汤不换药"地切换。

一、概念讲解#

1. PEFT 在解决什么#

所有高效微调方法共享同一套模式：冻结基座 → 在结构里插入一小块可训练模块 → 只训练那块模块。差别只在于"这块模块长什么样、插在哪里"。PEFT 把这套模式抽象成统一的 API，让你改一行配置就能从 LoRA 换成 IA3，而训练循环、保存加载、部署逻辑完全不用动。

它的两个核心抽象是：

  • PeftConfig：描述"插什么、怎么插"的配置对象（如 LoraConfig、IA3Config）；
  • PeftModel：包裹基座模型、持有适配器权重的模型对象。

2. 注入适配器：get_peft_model#

get_peft_model(base_model, config) 做的事是：遍历基座的每一层，按 config 里的 target_modules 找到目标模块，把原始 Linear 换成"原始层 + 适配器"的复合层，并冻结基座、只放开适配器参数。之后这个 PeftModel 就能像普通 nn.Module 一样前向、反向、交给 Trainer 训练。

对 LoRA 来说，核心是 LoraConfig 的几个关键参数：

参数 含义 常见取值
r 低秩维度，决定增量矩阵的大小 8 / 16 / 64
lora_alpha 缩放系数，与 r 一起决定有效学习率 16 / 32
target_modules 要挂适配器的模块名列表 ["q_proj","v_proj"] 等
lora_dropout 适配器上的 dropout，防过拟合 0.05
task_type 任务类型，决定加不加因果/序列头 "CAUSAL_LM"

lora_alpha 是新手最容易困惑的参数：LoRA 的输出会乘以 alpha / r，所以真正决定"增量有多强"的是这个比值，而非 alpha 的绝对值。把 alpha 和 r 同时翻倍，效果不变。

3. 保存与加载：适配器是独立的#

训练完 LoRA 后，你不需要保存整个模型——model.save_pretrained() 只把适配器权重（几 MB 到几十 MB 的 adapter_model.safetensors）连同 adapter_config.json 存下来。部署时用 PeftModel.from_pretrained(base_model, adapter_path) 把适配器重新挂回基座。这意味着：同一个基座可以挂无数个不同任务的适配器，像"换插件"一样切换能力。

4. 合并：merge_and_unload#

适配器在推理时每次前向都要做"基座输出 + 适配器增量"的加法，多一层计算。若你不再需要"可插拔"，可以调用 merge_and_unload()，把 W + B A 直接算进基座权重里，返回一个普通模型。合并后体积和原基座一样，推理无额外开销，适合最终部署。

5. 与量化的组合#

上一课看到，get_peft_model 前先 prepare_model_for_kbit_training，PEFT 就能把 LoRA 挂在 4-bit 基座上。PEFT 的量化支持和 bitsandbytes 深度整合，这也是 QLoRA 能"开箱即用"的原因。

二、可运行代码示例#

下面完整走一遍"注入 → 训练一步 → 保存 → 加载 → 合并"，代码依赖 transformers、peft。

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model

model_id = "gpt2"  # 用小型模型，CPU 也能跑通流程

model = AutoModelForCausalLM.from_pretrained(model_id)
tokenizer = AutoTokenizer.from_pretrained(model_id)
tokenizer.pad_token = tokenizer.eos_token

# 1) 定义 LoRA 配置
config = LoraConfig(
    r=8,
    lora_alpha=16,                       # 缩放比值 = alpha/r = 2
    target_modules=["c_attn", "c_proj"], # GPT-2 的注意力层名（不同模型名称不同）
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

# 2) 注入适配器：基座被冻结，只有 LoRA 参数可训练
model = get_peft_model(model, config)
model.print_trainable_parameters()
# 输出形如：trainable params: 294,912 || all params: 124,734,720 || trainable%: 0.2364

# 3) 模拟一步训练（真实任务请用 Trainer + 数据集）
opt = torch.optim.AdamW(model.parameters(), lr=1e-4)
inputs = tokenizer("今天天气不错", return_tensors="pt")
loss = model(**inputs, labels=inputs["input_ids"]).loss
loss.backward()
opt.step()
print(f"示例损失：{loss.item():.4f}")

# 4) 保存适配器：只存几 MB 的 adapter 权重 + 配置
model.save_pretrained("./my-lora-adapter")

# 5) 重新加载：把适配器挂回同一个基座
from peft import PeftModel
base = AutoModelForCausalLM.from_pretrained(model_id)
loaded = PeftModel.from_pretrained(base, "./my-lora-adapter")

# 6) 合并进基座并卸载适配器：得到普通模型，推理无额外开销
merged = loaded.merge_and_unload()
print("合并后的模型类型：", type(merged).__name__)

运行后你会看到：gpt2 约 1.24 亿参数里，可训练的 LoRA 只有约 29 万，占比 0.2%。保存到 ./my-lora-adapter 的是几 MB 的小文件，而不是 500MB 的整个模型——这正是 PEFT 的价值所在。

三、练习#

  1. 把 target_modules 换成 ["c_attn"]（只挂一个模块），再看 print_trainable_parameters()，对比参数量的变化，理解"挂载范围"的杠杆作用。
  2. 保持 alpha / r = 2 不变，分别用 (r=8, alpha=16) 和 (r=16, alpha=32) 各跑一次，观察两者可训练参数量和缩放比值的关系。
  3. 保存适配器后，用 PeftModel.from_pretrained 加载到另一个同架构模型上（如 distilgpt2），会发生什么？查文档确认适配器能否跨模型迁移，并解释原因。
  4. 比较 merge_and_unload 前后的模型显存/参数量，总结"可插拔适配器"与"合并部署"各自适合什么场景。
