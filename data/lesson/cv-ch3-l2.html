关键点检测#

实例分割给每个物体画了轮廓，但很多任务关心的是物体上的特定点：人体关节（肩、肘、腕、髋、膝、踝）、人脸五官（眼角、鼻尖、嘴角）、手的骨节点。关键点检测（Keypoint Detection） 就是定位这些有语义的点的坐标，它在姿态估计、动作识别、人脸对齐、手势交互里是基础能力。

这一课讲清一个核心问题：关键点该用"直接回归坐标"还是"预测热图"来表示？ 答案是后者，而"为什么"里藏着关键点检测的全部设计哲学。

一、概念讲解#

1. 任务定义与表示之争#

人体姿态估计的目标是：给定一张含人的图，输出一组关节点的坐标，如 [(x_左肩, y_左肩), (x_左肘, y_左肘), ...]。最直觉的做法是直接回归坐标：网络最后接几个全连接，输出一串 (x, y) 数值。

但直接回归有一个根本问题：坐标是一个"孤立的低维值"，几乎没有空间结构可供卷积网络学习。网络很难从"一个数值"反推"这个点应该出现在肩膀这个局部纹理附近"。更要命的是，真实图片里同一个关节位置往往多模态（被遮挡、有歧义时，一个位置可能有多个合理答案），而回归一个点只能输出一个平均值。

于是主流方法改用热图（heatmap）表示：不为每个关键点输出一个 (x, y)，而是输出一张与输入同尺寸的"概率图"，图上每个像素的值表示"该关键点位于此像素的概率"，真值用一个以标注点为中心的高斯峰来构造。网络的学习目标从"背出一个坐标"变成了"画出一座高斯山"——这是一个逐像素的、有空间结构的监督信号，卷积网络天生擅长。

预测时，对热图取峰值位置（argmax，或更精细的取期望）就得到坐标。热图还有额外好处：它天然携带置信度（峰越高越确定），还能自然地表达多模态（出现多个峰 = 多个可能位置），这些是坐标回归给不了的。

2. 两条技术路线：自顶向下 vs 自底向上#

关键点检测（尤其是多人姿态估计）分两大流派：

  • 自顶向下（top-down）：先用一个人检测器框出每个人，再对每个单人框单独做关键点检测。优点是单人的姿态估计简单、精度高；缺点是速度随人数线性下降，且严重依赖检测器——人没被框到，姿态就丢了；
  • 自底向上（bottom-up）：先检测图中所有人的所有关键点（不管属于谁），再通过关联算法把这些点分组、拼成一个个完整的人。代表是 OpenPose（用"部件亲和场 PAF"学习点与点之间的连接关系）。优点是人数再多也只做一次前向，速度稳定；缺点是多人密集、遮挡时分组容易错。

3. 经典网络演进：精度如何一步步做高#

关键点网络的主线是"如何在高分辨率下保持大感受野"——这其实和分割是同一个矛盾。代表性工作：

  • CPM（卷积姿态机）：用多阶段网络逐步精修热图，后一阶段看前一阶段的输出 + 中间特征，让浅层也能间接获得大感受野；
  • Stacked Hourglass（堆叠沙漏）：把编码器-解码器做成一个"沙漏"单元，再堆叠多个沙漏，反复"下采样提取语义 → 上采样恢复细节 → 中间监督"，是热图法的经典骨架；
  • HRNet：反其道而行，全程保持高分辨率，同时用并行的低分辨率分支交换信息（多分辨率并行 + 反复融合），避免了"先降再升"的信息损失，成为精度标杆。

这条线的共同教训：关键点定位对空间精度极其敏感，任何粗暴的下采样都会直接损伤坐标精度。

4. 评价指标：从像素到 OKS#

  • PCK（Percentage of Correct Keypoints）：预测点与真值的距离小于某阈值（如头部长度的一定比例）即算正确，统计正确率；
  • OKS（Object Keypoint Similarity）：COCO 用的指标，本质是"关键点版的 IoU"。它把每个关键点的距离误差用该点的尺度与标注不确定性加权，再像 mAP 那样对阈值与类别做平均，得到 mAP@OKS。理解 OKS 就是理解"关键点的 mAP"，与第一章的 IoU/mAP 一脉相承。

二、可运行代码示例#

第一段从零生成高斯热图真值（关键点检测的核心监督信号）；第二段用 torchvision 预训练的 Keypoint R-CNN（自顶向下路线）做一次推理。

import torch
import torch.nn.functional as F

# ---------- 1) 从零生成高斯热图真值 ----------
def make_heatmap(h, w, cx, cy, sigma=3.0):
    """在 (h, w) 图上，以 (cx, cy) 为中心画一个高斯峰作为关键点真值"""
    ys = torch.arange(h).float().view(-1, 1)   # (h, 1)
    xs = torch.arange(w).float().view(1, -1)   # (1, w)
    dist2 = (ys - cy) ** 2 + (xs - cx) ** 2    # 到中心的平方距离
    return torch.exp(-dist2 / (2 * sigma ** 2))

h, w = 64, 64
hm = make_heatmap(h, w, cx=32.0, cy=20.0, sigma=3.0)
peak = torch.stack(torch.where(hm == hm.max()), dim=1)   # 找到峰值坐标
print("热图形状：", tuple(hm.shape), " 峰值位置：", peak.tolist())   # 应约等于 (20, 32)
print("热图最大值：", round(hm.max().item(), 4))                     # 应为 1.0

# 一个"多模态"例子：两个峰表示该关键点有两个可能位置
hm2 = make_heatmap(h, w, 20, 20, 3.0) + make_heatmap(h, w, 48, 44, 3.0)
print("双峰热图的最大两个值：", torch.topk(hm2.flatten(), 2).values.tolist())

# ---------- 2) 预训练 Keypoint R-CNN 推理（自顶向下：先检测人再估点） ----------
from torchvision.models.detection import keypointrcnn_resnet50_fpn, KeypointRCNN_ResNet50_FPN_Weights

weights = KeypointRCNN_ResNet50_FPN_Weights.DEFAULT
model = keypointrcnn_resnet50_fpn(weights=weights).eval()

img = torch.rand(3, 480, 640)
with torch.no_grad():
    out = model([img])[0]
print("检测到的人数：", len(out["boxes"]))
if len(out["boxes"]):
    print("关键点坐标形状：", tuple(out["keypoints"][0].shape))      # (17, 3)：17 个 COCO 关键点
    print("关键点分数形状：", tuple(out["keypoint_scores"][0].shape)) # (17,)

第 1 段展示了热图法的本质：真值不是 (32, 20) 这个孤立坐标，而是一张以 (32, 20) 为中心的"高斯山"。网络学会"画山"，推理时"找山顶"，坐标自然就出来了，还顺带拿到了置信度。

三、练习#

  1. 修改 make_heatmap 的 sigma，观察高斯峰"变尖/变胖"；说说 sigma 过大或过小分别会导致网络学出怎样的预测行为（过拟合 vs 过于平滑）。
  2. 实现"从热图取坐标"的两种方式：argmax 取峰值，以及"用热图概率做加权期望"，对比两者在热图不对称时的差异。
  3. 解释自顶向下与自底向上各自的"单点故障"在哪里（一个依赖检测器、一个依赖分组），并举例说明哪种场景该选哪种。
  4. 用 torchvision 的 keypointrcnn_resnet50_fpn 对一张真实照片推理，把关键点画回原图（连接相邻关节画骨架），观察遮挡部位的关键点分数是否明显更低。
