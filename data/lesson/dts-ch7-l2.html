梯度累积与并行的交互、有效 batch 换算#

上一课你把并行度拼成了一张配置表。同一个 effective batch（有效 batch）可以用很多种方式凑出来：改单卡 micro-batch、改梯度累积步数、改 DP 度都行。它们对收敛几乎等价，对通信次数却差好几倍——本课把"凑 batch"从调参动作变成一笔可算的账。

一、概念讲解#

1. 有效 batch 是三个自由度的乘积#

沿用第 5 章的记号，有效 batch 指的是一次参数更新实际吃进的样本序列数：

Beff​=m×A×DP=m×A×TP⋅PP⋅CP⋅EPP​

其中 m 是单卡 micro-batch、A 是梯度累积步数（gradient accumulation steps）、DP 是数据并行度。当 TP/PP/CP 大于 1 时，一个 micro-batch 内部还会被再切开：TP 切它、PP 让它流过流水线、CP 切序列维；所以公式里只出现 DP，而每卡激活峰值正比于 m×s（s 为序列长度）。

DeepSpeed 的配置文档把这条恒等式写成了强制约束：train_batch_size 必须等于 train_micro_batch_size_per_gpu × gradient_accumulation_steps × GPU 数，并建议三个量里只填两个、让框架推第三个。这就是"换算"的全部内容——动一个，另两个就得补偿。

2. 反直觉点：A 变了，通信次数也变了，但梯度并没有变小#

示例 1 用 96 卡、TP=PP=CP=1（即 DP=96）凑 Beff​=1536，给出四种切法：

micro m 累积 A DP Beff​ 每卡激活峰值
1 16 96 1536 最小
4 4 96 1536 中
8 2 96 1536 较大
16 1 96 1536 最大

四种切法的梯度总量一模一样。变的是多少次 AllReduce：若每个 micro-batch 都同步一次梯度，A 次累积就等于 A 次全量 AllReduce。所以"用 A 换 m"买到的是通信频率下降。

3. 代价核算：A 把同步次数放大 A 倍#

以 70B 模型为例：bf16 梯度约 70 GB；DP=8 且组在节点内（示例 β=300 GB/s），ring AllReduce 一次约 408 ms。示例 2 把 A 的影响列全：

A 每步同步次数 每步同步总时间 相比 no_sync 多付
1 1 408.40 ms 0
4 4 1633.61 ms 1225.21 ms
16 16 6534.45 ms 6126.05 ms

这就是 no_sync() 存在的理由：在累积的前 A−1 个 micro-batch 里跳过梯度同步，只在累积边界同步一次。PyTorch DDP 提供 model.no_sync() 上下文管理器，把 forward/backward 包在 with model.no_sync(): 里，只在最后一个 micro-batch 用正常的 loss.backward() 触发 AllReduce；DeepSpeed 则把这件事交给引擎，gradient_accumulation_steps 决定同步粒度。

注意边界：跳过同步意味着各 rank 这段时间"各算各的"，所以每个 rank 必须处理等量的 micro-batch，否则会有 rank 提前进入同步而挂死——这是最经典的 hang 原因之一，第 4 课专讲。

4. 与 PP 的耦合：A 就是流水线里的 micro-batch 数#

当 PP>1 时，一个 micro-batch 要依次穿过 p 个 stage，所以能填满流水线的个数就是 A，气泡重写为 (p−1)/(A+p−1)。示例 3 的表格给出：p=8 时 A=16 的气泡是 30.4%，A=1 时高达 87.5%。

这条耦合带来两个方向的结论：① 开 PP 后，A 不能太小，否则大部分时间 stage 在空转；② 而 A 变大时，梯度同步频率下降、气泡也下降——这就是"累积步数"这个旋钮在 3D 并行里比在纯 DP 里更值钱的原因。

5. 学习率、梯度裁剪与优化器步数#

换了并行度就等于换了有效 batch，学习率必须跟着记账。两种常见缩放（都只是起点，必须实测收敛）：

  • 线性缩放：lr∝Beff​，示例 4 里 512 → 1536 对应 3×10−4→9×10−4；
  • 平方根缩放：lr∝Beff​​，同样区间给出 5.20×10−4。

还有两个容易漏的：warmup 按"优化器步数"计（不是 micro-batch 数），换 A 后 step 数变了，warmup 的绝对 token 量会跟着漂；梯度裁剪作用在累积后的梯度上，阈值语义随 A 变化。ZeRO-1/2 与 FP16 优化下，累积期的 AllReduce 会被框架改写成分段 ReduceScatter，no_sync 语义由框架接管——先看框架文档再手写 no_sync，两者叠加会静默改掉同步时机。

6. 收敛视角：等效但要小心两件事#

梯度累积在数学上等价位一个大 batch（同样本、同求平均），"能不能涨点"通常不是问题。真正会出问题的是两处：① BatchNorm 类统计量按 micro-batch 计算时不等价（LLM 用 LayerNorm/RMSNorm，无此项；换视觉模型要小心）；② Dropout 掩码在不同 micro-batch 上独立，等效 batch 变大后正则被稀释。两点都属于"公式等价、随机性不等价"。

二、可运行代码示例#

四段纯 Python（标准库），把"有效 batch 换算、同步次数、PP 气泡、学习率记账"都变成可打印的数。

# ===== 示例 1：有效 batch 换算的三个自由度 =====
P, TP, PP, CP = 96, 1, 1, 1
DP = P // (TP * PP * CP)
print(f"示例 1：P={P} 卡，TP={TP} PP={PP} CP={CP} → DP={DP}")

def effective_batch(m, a, dp):
    """有效 batch = 单卡 micro-batch × 梯度累积步数 × DP。"""
    return m * a * dp

print("\n同一台 96 卡机器，凑到 effective batch = 1536 的四种切法：")
for m, a in ((1, 16), (4, 4), (8, 2), (16, 1)):
    print(f"  micro={m:<3} accum={a:<3} DP={DP}  →  {effective_batch(m, a, DP):>5}  "
          f"（每卡激活峰值 ∝ micro × s）")

# ===== 示例 2：no_sync 把 a 次梯度 AllReduce 压成 1 次 =====
GB = 1e9
GRAD = 140 * GB / 2                       # 70B 模型 bf16 梯度 ≈ 70 GB
ALPHA, BW_INTRA = 5.0, 300.0              # 示例参数：DP 组在节点内

def ar_ring_ms(bytes_, p, bw=BW_INTRA, alpha=ALPHA):
    """ring AllReduce：2(p-1) 步，每步传 bytes_/p（第 2 章的账）。"""
    return 2 * (p - 1) * (alpha + (bytes_ / p) / (bw * 1e9) * 1e6) / 1e3

print(f"\n示例 2：{GRAD/GB:.0f} GB bf16 梯度的 DP AllReduce（ring，示例 β={BW_INTRA} GB/s）")
for dp, tag in ((8, "DP=8 节点内"),):
    one = ar_ring_ms(GRAD, dp)
    print(f"  {tag}：同步一次 {one:7.2f} ms")
    print("   accum  A  每步同步次数   每步同步总时间    相比 no_sync 多付")
    for a in (1, 2, 4, 8, 16):
        print(f"   {a:>5}  {'1' if a==1 else a:<10} {a:>10}   {one*a:11.2f} ms   {one*(a-1):11.2f} ms")

# ===== 示例 3：PP>1 时 micro-batch 数 = 累积步数 a → 气泡换算 =====
def bubble(p, m):
    return (p - 1) / (m + p - 1)

print("\n示例 3：PP>1 时流水线里的 micro-batch 数就是累积步数 a，气泡占比 (p-1)/(m+p-1)")
print("   p\\a ", "".join(f"{a:>8}" for a in (1, 2, 4, 8, 16, 32)))
for p in (2, 4, 8):
    print(f"  {p:>4} " + "".join(f"{bubble(p, a)*100:7.1f}%" for a in (1, 2, 4, 8, 16, 32)))

# ===== 示例 4：全局 batch 变了，lr / warmup 怎么记账 =====
print("\n示例 4：换并行度后 lr 的两种常见缩放（都只是起点，必须实测收敛）")
base_batch, base_lr = 512, 3e-4
for b in (512, 1536, 6144):
    print(f"  global batch {b:>5} → 线性 {base_lr*b/base_batch:.2e}   平方根 {base_lr*(b/base_batch)**0.5:.2e}")

三、练习#

  1. 实现：写一个函数 split_eff_batch(B_eff, DP, max_micro, max_accum)，枚举所有 (m,A) 组合并返回满足 m×A×DP=Beff​ 的解，按"每步同步次数 = A"升序排列；再用它回答：Beff​=1536、DP=96、m≤8 时最少要同步几次。
  2. 解释：为什么"A 从 1 加到 16"能把同步次数降到 1/16，而"梯度总量"一点没变？用示例 1 的表格与示例 2 的时间列各说一句。
  3. 对比/验证：把示例 2 的 bw 从 300 GB/s 改成 25 GB/s（DP 组跨机）与 600 GB/s（更快的节点内链路），重算 A=1,4,16 三行的总时间，并说明为什么跨机时"减少同步次数"这件事更值钱。
  4. 思考：把 A 从 4 改成 16 后，loss 曲线在同样 token 数下的抖动明显变大而均值几乎不变。列出两种可能的原因（提示：优化器步数、Dropout 随机性），并各设计一个消融实验。
