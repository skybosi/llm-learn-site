融合的收益来源：省带宽、省 kernel 启动、增加复用#

256 MiB 的 fp32 张量过 8 个逐元素算子：逐算子执行要读写 4096 MiB，融成一个内核只要 512 MiB。算子没少、浮点运算没少，省下的是中间张量"写回显存再读出来"的往返。算子融合（operator fusion）就是把这 N 趟访存压成 1 趟；本课把它的收益拆成三笔能逐条核对的账（带宽、启动、片上复用），并给出可跑的核算脚本与真内核实测。

一、概念讲解#

1. 三笔账，各有各的适用区间#

融合不改变算术：y = sigmoid(relu(x@W + b)) 照样要算矩阵乘、加法、relu、sigmoid；它改变的是数据在哪里停留。三笔收益要分开看，否则容易在不适用的场景上期待落空：

收益 机制 什么时候显著 什么时候几乎为零
省带宽 中间张量不落地：N 趟"读 + 写"变成 1 趟 逐元素点链、逐元素 + 归约、逐元素 + epilogue 链条里全是 exp/tanh 这类算力受限算子；张量小到能整块进缓存
省内核启动 N 次内核下发与派发变成 1 次 张量小、算子多、启动开销占比高（小 batch、端侧） 张量很大时启动占比低于 1%，可忽略
增数据复用 中间值留在寄存器/片上，被同一内核里多个表达式共用 归约前先算、epilogue、同一结果被多处引用 复用距离远、同时活着的值太多（第 3 课讲它怎么反噬）

2. 带宽账可以精确算，不需要估#

设张量元素数为 E、每元素 4 字节（fp32），单张量字节数 S=4E。一条由 N 个逐元素算子组成的链：

流量不融合​=i=1∑N​(readi​+writei​)=2NS,流量融合​=2S

比值正好是 N。本课 N=8、S=256 MiB，于是 4096 MiB 对 512 MiB。这里的"不融合"只要求"每算子一趟下发、中间结果落地"：中间结果就算被内存池复用（第 4 章第 3 课），流量也一分不少——复用省的是容量，不是带宽。

3. 启动账：小张量时才重要#

单次执行的时间下界可以写成两项：

t≈Btraffic​+nkernel​⋅L

B 是可达带宽，L 是单次内核启动 + 框架派发的固定开销。取 B=1.5 TB/s、L=5 µs（示例量级参数，非某卡实测）：8 内核 2.90 ms、1 内核 0.36 ms，启动只占 1.4%。工程判据由此而来：只有 N⋅L 与 traffic/B 同量级时，"省启动"才是主要收益——即张量小、算子多的场景（端侧、小 batch）。

4. 复用账：融合给中间值找了个"不必落地"的去处#

中间张量不落地之后，它待在寄存器里，可被同一内核里的多个表达式共用。两类真实优化由此而来：归约前算（把逐元素生产者算进归约循环，如 softmax 的分母）与 epilogue 融合（归约结果后续的逐元素变换接在归约后面，如 sum → ×2 → relu）。对立面是活值数：同时在世的值越多，寄存器越紧张——第 3 课的核心矛盾。

5. 真实编译器里长什么样#

TVM 把 operator fusion 与常量折叠、静态内存规划并列为图级优化三项，其设计文档写到融合流水线（relax.FuseOps + relax.FuseTIR）"把多个连续的张量算子融合成单个 kernel"。Inductor 侧本机实测（见输出）：8 个逐元素算子被合成为一个内核 cpp_fused_add_div_mul_relu_sigmoid_sub_0，只申请一块新缓冲；而 relu(x@w+b) 接 sigmoid、sum 产出两个内核——不透明的 extern_kernels.addmm 一个，其余融成 cpp_fused_relu_sigmoid_sum_0。连续算子确实会被融成一个；外部库实现的矩阵乘是融合边界。

6. 常见坑#

  • 以为融合减少了计算量：减的是访存与下发次数；算力受限的链（exp、大型 tanh）融合后时间几乎不变。
  • 拿小张量的比例外推大张量：启动项占比随张量变大迅速衰减，小张量的 3 倍加速到大张量可能只剩 1.2 倍。
  • 把"复用缓冲"当成"融合"：内存复用不降带宽，只降容量与分配开销；两者常被混为一谈。
  • 忘了不透明边界：调优时先看清生成的内核名里到底融进了哪些算子，再讨论"为什么没更快"。

二、可运行代码示例#

第 1 段是纯 numpy 的核算（无第三方依赖）；第 2 段用 numba 把同一条链手写成 1 / 2 / 8 个内核做对照实测（可选，pip install numba）；第 3 段用 torch.compile 看真实编译器生成的内核名（可选，需 torch）。

# ---- 第 1 课示例：融合省掉的是什么（numpy，本机 python3.10 + numpy 1.26.2 实跑，CPU）----
import numpy as np, time

MB = 1 << 20
SHAPE = (1 << 16, 1 << 10)                 # 65536 x 1024 = 64Mi 个 fp32 = 256 MiB
ELEMS = SHAPE[0] * SHAPE[1]
S_BYTES = ELEMS * 4                        # 单个张量的字节数

# 八个"廉价"逐元素算子：整条链是带宽受限（若含 exp/tanh 这类超越函数就是算力受限，另说）
OPS = [('add',  lambda a, o: np.add(a, 1.0, out=o)),
       ('mul',  lambda a, o: np.multiply(a, 2.0, out=o)),
       ('sub',  lambda a, o: np.subtract(a, 3.0, out=o)),
       ('relu', lambda a, o: np.maximum(a, 0.0, out=o)),
       ('div',  lambda a, o: np.divide(a, 4.0, out=o)),
       ('add5', lambda a, o: np.add(a, 5.0, out=o)),
       ('tanh', lambda a, o: np.tanh(a, out=o)),
       ('half', lambda a, o: np.multiply(a, 0.5, out=o))]
N = len(OPS)

def run_unfused(x):
    """框架逐算子执行：每个算子申请一块新输出，中间张量全部落地再读回。"""
    y = x
    for _, f in OPS:
        o = np.empty_like(x); f(y, o); y = o
    return y

def run_reuse(x):
    """逐算子但复用两块输出缓冲：还是 8 趟访存，省掉的只是分配，流量一分没少。"""
    bufs = [np.empty_like(x), np.empty_like(x)]
    y = x
    for i, (_, f) in enumerate(OPS):
        f(y, bufs[i % 2]); y = bufs[i % 2]
    return y

def run_fused(x, tile_rows):
    """模拟融合内核：一次读进"片上"（这里是一块常驻 tile 缓冲），链内原地推进，一次写回。"""
    out = np.empty_like(x)
    for r in range(0, x.shape[0], tile_rows):
        t = np.array(x[r:r + tile_rows], copy=True)     # 一趟读：DRAM → 片上
        for _, f in OPS:
            f(t, t)                                     # 链内全在片上，不落地
        out[r:r + tile_rows] = t                        # 一趟写：片上 → DRAM
    return out

def bench(fn, *a, repeat=3):
    fn(*a)
    ts = []
    for _ in range(repeat):
        t0 = time.perf_counter(); fn(*a); ts.append(time.perf_counter() - t0)
    return min(ts)

x = np.linspace(-1.0, 1.0, ELEMS, dtype=np.float32).reshape(SHAPE)
traffic = {'逐算子（每步新分配）': 2 * N * S_BYTES, '逐算子（复用两块缓冲）': 2 * N * S_BYTES,
           '模拟融合（分块 + 块内原地）': 2 * S_BYTES}
kernels = {'逐算子（每步新分配）': N, '逐算子（复用两块缓冲）': N, '模拟融合（分块 + 块内原地）': 1}

print(f'=== 1. 场景：{S_BYTES / MB:.0f} MiB 的 fp32 张量过 {N} 个逐元素算子 ===')
print(f'  单个张量读一遍 + 写一遍 = {2 * S_BYTES / MB:.0f} MiB')
for tag in traffic:
    print(f'  {tag:<24} DRAM 流量 {traffic[tag] / MB:>5.0f} MiB  内核数 {kernels[tag]}'
          f'  = {traffic[tag] / (2 * S_BYTES):.0f} 倍单张量读写')

print('\n=== 2. 实测（同一台 CPU 上的相对比较，绝对值随机器变化）===')
for tag, fn, args in [('逐算子（每步新分配）', run_unfused, (x,)),
                      ('逐算子（复用两块缓冲）', run_reuse, (x,)),
                      ('模拟融合（分块 + 块内原地）', run_fused, (x, 256))]:
    print(f'  {tag:<24}{bench(fn, *args) * 1e3:7.1f} ms   账面流量 {traffic[tag] / MB:>4.0f} MiB')
print('  本机只测到 1.3~3 倍的差距，而不是 8 倍：numpy 每个 ufunc 调用有自己的固定开销，')
print('  且 CPU 的缓存层级与 GPU 的寄存器/共享内存不是一回事——numpy 的墙钟时间不能外推到 GPU。')
print('  同一个问题的"真·融合内核"版本见下面 numba / torch 两块（本机均已实跑）。')

print('\n=== 3. 把两笔账换算成时间（参数化模型：带宽 B、单次内核启动 L 自己代入）===')
for B in (1.5e12, 3.0e12):
    L = 5e-6
    t_no = 2 * N * S_BYTES / B + N * L
    t_fu = 2 * S_BYTES / B + L
    print(f'  B={B / 1e12:.1f} TB/s, L={L * 1e6:.0f} us → 不融合 {t_no * 1e3:6.2f} ms'
          f'（启动占 {N * L / t_no * 100:4.1f}%），融合 {t_fu * 1e3:6.2f} ms'
          f'（启动占 {L / t_fu * 100:4.1f}%），比 {t_no / t_fu:4.2f}x')
print('  两笔收益各自成立：流量按"每算子一趟"降到 1 趟，内核数从 N 降到 1；')
print('  张量越小，启动与固定开销占比越高，融合越划算。')

# ---- 可选（pip install numba）：同样 8 个算子，分别写成 1 / 2 / 8 个内核（CPU，本机已实跑）----
import numpy as np, time
from numba import njit, prange
SHAPE = (1 << 16, 1 << 10)                 # 与上面同一个尺度
N = SHAPE[0] * SHAPE[1]

@njit(parallel=True, fastmath=True, cache=False)
def op1(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] + 1.0
@njit(parallel=True, fastmath=True, cache=False)
def op2(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] * 2.0
@njit(parallel=True, fastmath=True, cache=False)
def op3(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] - 3.0
@njit(parallel=True, fastmath=True, cache=False)
def op4(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] if a[i] > 0.0 else 0.0
@njit(parallel=True, fastmath=True, cache=False)
def op5(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] / 4.0
@njit(parallel=True, fastmath=True, cache=False)
def op6(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] + 5.0
@njit(parallel=True, fastmath=True, cache=False)
def op7(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] * a[i]
@njit(parallel=True, fastmath=True, cache=False)
def op8(a, b):
    for i in prange(a.shape[0]): b[i] = a[i] * 0.5

@njit(parallel=True, fastmath=True, cache=False)
def fused8(a, b):
    for i in prange(a.shape[0]):
        v = a[i]
        v = v + 1.0; v = v * 2.0; v = v - 3.0; v = v if v > 0.0 else 0.0
        v = v / 4.0; v = v + 5.0; v = v * v; v = v * 0.5
        b[i] = v

@njit(parallel=True, fastmath=True, cache=False)
def fused4a(a, b):
    for i in prange(a.shape[0]):
        v = a[i]
        v = v + 1.0; v = v * 2.0; v = v - 3.0; v = v if v > 0.0 else 0.0
        b[i] = v
@njit(parallel=True, fastmath=True, cache=False)
def fused4b(a, b):
    for i in prange(a.shape[0]):
        v = a[i]
        v = v / 4.0; v = v + 5.0; v = v * v; v = v * 0.5
        b[i] = v

def eight_passes(x):
    bufs = [np.empty_like(x), np.empty_like(x)]
    y = x
    for i, op in enumerate((op1, op2, op3, op4, op5, op6, op7, op8)):
        op(y.reshape(-1), bufs[i % 2].reshape(-1)); y = bufs[i % 2]
    return y

def two_passes(x):
    bufs = [np.empty_like(x), np.empty_like(x)]
    fused4a(x.reshape(-1), bufs[0].reshape(-1))
    fused4b(bufs[0].reshape(-1), bufs[1].reshape(-1))
    return bufs[1]

def one_pass(x):
    out = np.empty_like(x)
    fused8(x.reshape(-1), out.reshape(-1))
    return out

def bench(fn, x, repeat=5):
    fn(x); ts = []
    for _ in range(repeat):
        t0 = time.perf_counter(); fn(x); ts.append(time.perf_counter() - t0)
    return min(ts)

x = np.linspace(-1.0, 1.0, N, dtype=np.float32).reshape(SHAPE)
print(f'{"实现":<22}{"内核数":>7}{"往返流量 MiB":>13}{"实测 ms":>10}{"相对":>8}')
base = None
for tag, fn, k in (('一个内核融 8 个算子', one_pass, 1),
                   ('切成两个内核各 4 个', two_passes, 2),
                   ('八个内核各 1 个算子', eight_passes, 8)):
    t = bench(fn, x)
    base = t if base is None else base
    print(f'{tag:<22}{k:>7}{2 * k * x.nbytes / 2**20:>13.0f}{t * 1e3:>10.1f}{t / base:>8.2f}')
ref = one_pass(x); got = eight_passes(x)
print(f'两条路径最大绝对差 {np.abs(ref.reshape(-1) - got.reshape(-1)).max():.2e}')

真内核实测（同机，numba 0.60.0，每项取 5 次最小值）：

实现                        内核数     往返流量 MiB     实测 ms      相对
一个内核融 8 个算子                 1          512      12.9    1.00
切成两个内核各 4 个                 2         1024      27.5    2.13
八个内核各 1 个算子                 8         4096      56.6    4.38
两条路径最大绝对差 1.91e-06

计时列在不同负载下会浮动约 ±10%（本课所有实测都是本机一次真实运行、取多次最小值的输出）；流量、内核数、寄存器数、occupancy 这类结构性数字则是确定的。

两处可核对的结论：切一刀就是两倍流量（2 个内核 1024 MiB、实测 2.13x，与账面 2x 吻合）；8 个内核只有 4.38x 而非 8x——内核启动与并行调度有固定开销，幅度会被摊薄，趋势与流量账一致。两条路径结果一致（最大绝对差 1.91e-06）。
