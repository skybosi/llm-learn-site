多路召回#

排序模型再强，也只能在"已经捞出来的几百个候选"里挑。如果候选池里根本没有用户会喜欢的物品，排序再准也白搭。本课回到漏斗的最上游——召回，讲清楚工业界为什么几乎不用"单一路召回"，而是用多路召回拼出一张尽量无死角的候选网。

一、概念讲解#

1. 召回阶段的任务与约束#

召回（recall / matching）的任务是：在毫秒级时延内，从百万甚至上亿的物品池里，快速挑出几百到几千个"可能感兴趣"的候选，交给后面的粗排、精排。它面对两个硬约束：

  • 规模大：不能像精排那样给每个物品都跑一遍重模型，必须用"轻量 + 索引"的方式快速裁剪。
  • 时延低：用户打开 App 到看到推荐，全程只有几百毫秒，召回只能占其中一小部分。

因此召回的核心取舍是：用精度换速度与覆盖面。召回阶段允许"捞进来一些不那么准的"，但绝不能"漏掉真正会点击的"。评判召回好坏，看的不是排序精度，而是召回率（真正感兴趣的物品里，有多少被捞进来了）和覆盖率。

2. 为什么必须"多路"#

如果只用一路召回（比如只做 ItemCF），会有一个致命弱点：每种召回策略都有自己的盲区。举几个典型的"盲区"：

  • ItemCF 协同过滤：只推荐"和用户历史行为共现过的相似物品"，对新用户（没有历史行为）和新物品（没有被共现过）无能为力。
  • 热门召回：能兜底冷启动，但千人一面，没有个性化，长期推荐会造成"信息茧房"。
  • 向量召回：擅长语义泛化，但可能召回"语义相似却已看过"的重复内容，且训练门槛高。

没有任何单一策略能同时解决"个性化、冷启动、多样性、时效性"四个需求。多路召回的思路就是：并行地跑很多路召回，每路负责覆盖一类需求，最后把各路结果合并、去重、截断。这就像用一张"渔网"去捕鱼——单根线有洞，多张网叠在一起才能把鱼兜住。

3. 常见的几路召回#

工业界通常会根据业务需求，组合下面几路：

  • 协同过滤召回：ItemCF / UserCF，利用"物以类聚、人以群分"，是个性化的基本盘（第 2 章学过）。
  • 向量召回（双塔 + ANN）：把用户和物品编码成向量，用近似最近邻检索，能召回"没见过共现但语义相近"的物品，是近年最主流的一路（下一课细讲）。
  • 热门 / 兜底召回：全局热门、类目热门、地域热门，负责新用户和新物品的冷启动。
  • 兴趣标签召回：给用户和物品都打标签（或类目），按标签匹配度召回，可解释性强。
  • 图召回：在"用户-物品"二分图上做随机游走（如 PersonalRank），捕捉多跳关系，能挖出"你朋友也喜欢"这类更远的关联。
  • 时效 / 新鲜度召回：召回新发布的物品，或按时间衰减给近期内容加权，保证推荐流有新鲜血液。

各路召回的量级通常不一样，比如热门召回给 100 个、向量召回给 400 个、ItemCF 给 300 个，合并后大约上千，再截断交给粗排。

4. 合并策略：加权、去重与冷启动保底#

多路召回的合并不是简单拼接，有几个关键动作：

  1. 打分归一化：各路召回的分数量纲不同（ItemCF 是相似度、热门是计数、向量是内积），不能直接相加比较。常见做法是把每路分数做 min-max 归一化，再按一路权重加权融合。
  2. 去重：同一个物品可能被多路召回，合并时按物品 ID 去重，分数可以取各路之和（多路都推荐它，说明它更可信）或取最大。
  3. 配额与保底：给每路一个数量配额，同时保证"冷启动路"（热门/标签）至少占一定比例，避免新物品永远没曝光。

还有一个容易被忽略的点：新物品冷启动。协同过滤和向量召回都偏向"已有历史"的物品，新物品天然吃亏。所以要专门留一路"新物品召回"（按发布时间和类目推送），并在合并时给它保底曝光量，让它积累第一批反馈数据。

二、可运行示例#

示例 1：手写 ItemCF 召回#

先构造用户-物品交互矩阵，算物品间余弦相似度，再为一个用户召回"他喜欢过的物品的相似物品"。

import numpy as np

# 交互矩阵：5 个用户 × 6 个物品，1 表示喜欢/点击
R = np.array([
    [1, 1, 0, 0, 0, 0],   # u0
    [1, 0, 1, 0, 0, 0],   # u1
    [0, 1, 0, 1, 0, 0],   # u2
    [0, 0, 1, 1, 1, 0],   # u3
    [0, 0, 0, 1, 0, 1],   # u4
])

def cosine_sim(A):
    """计算列向量两两之间的余弦相似度。"""
    norm = np.linalg.norm(A, axis=0, keepdims=True) + 1e-9
    A_norm = A / norm
    return A_norm.T @ A_norm   # (n_items, n_items)

item_sim = cosine_sim(R)  # 物品-物品相似度

def itemcf_recall(user_vec, item_sim, top_k=3):
    """ItemCF 召回：用户历史物品的相似物品打分之和，排除已交互过的。"""
    n = len(user_vec)
    scores = np.zeros(n)
    liked = np.where(user_vec > 0)[0]
    for i in liked:
        scores += item_sim[i]                    # 累加相似度
    scores[liked] = -np.inf                      # 排除已经看过/点过的
    return np.argsort(-scores)[:top_k]

user0 = R[0]
rec = itemcf_recall(user0, item_sim, top_k=3)
print("u0 的 ItemCF 召回:", rec.tolist())
print("物品相似度矩阵(取整):\n", np.round(item_sim, 2))

示例 2：多路召回合并（ItemCF + 热门 + 标签）#

实现三路召回，各自打分并归一化，加权合并后去重、截断，展示"多路互补 + 冷启动保底"。

import numpy as np

n_items = 6
# 三路召回的原始分数（不同量纲）
itemcf_scores = np.array([0.8, 0.0, 0.6, 0.0, 0.0, 0.0])   # ItemCF 相似度
hot_scores    = np.array([3, 5, 2, 8, 4, 9])               # 热门计数
tag_scores    = np.array([0.0, 0.0, 0.0, 0.7, 0.0, 0.5])   # 标签匹配度(新物品也在这路)

def minmax(s):
    lo, hi = s.min(), s.max()
    return (s - lo) / (hi - lo + 1e-9) if hi > lo else np.zeros_like(s)

# 加权融合：热门路权重低（兜底）、ItemCF/标签路权重高（个性化）
merged = (0.5 * minmax(itemcf_scores)
          + 0.2 * minmax(hot_scores)
          + 0.3 * minmax(tag_scores))

# 去重 + 截断 topK（这里用分数排序模拟；实际工程按物品 ID 去重）
top_k = 3
top_idx = np.argsort(-merged)[:top_k]
print("各路归一化分数:")
print("  ItemCF:", np.round(minmax(itemcf_scores), 2))
print("  热门  :", np.round(minmax(hot_scores), 2))
print("  标签  :", np.round(minmax(tag_scores), 2))
print("融合分数:", np.round(merged, 2))
print("最终 topK 物品:", top_idx.tolist())

三、练习#

  1. 在示例 1 中，给用户 u0 换成一个"没有任何交互"的新用户，观察 ItemCF 召回会输出什么；解释为什么这路召回避开了冷启动，必须靠热门/标签路兜底。
  2. 修改示例 2 的权重（比如把热门路权重调到 0.8），观察最终 topK 变化，并说明"冷启动保底"和"个性化质量"之间的权衡。
  3. 列举三种"多路召回里需要去重"的场景，并说明去重时"分数求和"与"取最大"分别适合什么情形。
  4. 思考题：为什么向量召回能召回"没见过共现、但语义相近"的物品，而 ItemCF 做不到？这弥补了 ItemCF 的哪一类盲区？
