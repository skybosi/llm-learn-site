时序动作定位与检测：边界回归、提议生成与密集预测#

这一节要解决什么#

上一节的输入边界由数据集给定：一段切好的片段、一个类别。这一节把边界也交给模型：

给定一段未裁剪的长视频，输出一串 (起,止,类别,置信度)。凭什么说一个预测"对"？三条技术路线各自把难度放在了哪里？mAP 这个数字到底在统计什么？

这一节的全部结论如下：

  1. 时序 IoU 是一份精确的误差兑换率，而且容限随时长缩放。 长度相等、起点偏移 δ 时 IoU=(L−δ)/(L+δ)：IoU=0.5 恰好对应 δ=L/3；IoU=0.7 对应 δ=3L/17=0.176471；IoU=0.9 对应 δ=L/19=0.052632。反解容限 dmax​(θ)=L1+θ1−θ​（表 1）。
  2. 同一个绝对误差在不同时长上的判决完全不同。 一律预测 1 秒的检测器：在 5 秒真值上可偏 1.666667 秒仍算 0.5 IoU，在 1 秒真值上只能偏 0.333333 秒。所以 mAP 必须按动作时长分层报（表 1）。
  3. 单帧"提案"有硬上界 1/G。 真值长 G=41 帧时单帧预测的 IoU 上界是 0.024390；要过 IoU=0.5，最小可行扩展是 k=⌈0.5⋅41⌉=21 帧（表 2）。长度超过 2 帧的真值，单帧预测在 tIoU=0.5 下不可能命中——这不是训练问题，是算术问题。
  4. 协议 A（tIoU 匹配 + 全局排序）的 AP 几乎只由置信度靠前的预测决定。 11 条预测的算例里，4 条 IoU=1.000000 的精确命中使 AP 在 θ=0.3/0.5/0.7 下完全不动（都是 0.925743）；而删掉 3 条低分预测、让 recall 到不了 1.0 后，AP 掉到 0.801980（降 13.37%）（表 3）。尾部误报几乎免费，头部误报代价极大——这是"刷 mAP"最常见的着力点。
  5. 近似命中拿满分。 同阈值下 IoU=0.51 与 1.00 的收益完全相同；[205,245] 以 IoU=0.777778 命中真值 [200,240] 就被记成完整的 TP（表 3）。mAP 无法区分"勉强够到"与"分毫不差"，必须另报定位误差分布。
  6. 协议 A 与协议 B 测的不是同一件事，敏感的错误类型相反。 逐帧 AP 对孤立的假阳性脉冲极其敏感（0.949926→0.462833，降 51.28%），而最大区间 IoU 完全不动（0.853659）；反过来，真值长度只对了 70% 时，逐帧 AP 仍有 0.911174，而最大区间 IoU 掉到 0.720930（表 4）。"逐帧 F1 0.9、tIoU-mAP 0.3"可以同时成立。
  7. 三条路线的差异可以各自量成一个"天花板"。 边界回归的天花板是锚覆盖率；提议生成的天花板是提议召回率（算例里 4 个候选只有 2 个够到 0.5，都丢了真值的一端）；密集预测的天花板是 k/G 的算术上界（表 5）。
  8. 检测的统计门槛比分类更严。 视频级伯努利给 sd=p(1−p)/V​：V=10000 时判为有差需 0.013131——1.3 个百分点的 mAP 提升在 10000 段视频上不可分辨；再加上真值数量的泊松波动 1/Vλ​（V=1000,λ=1 时 3.1623%），跨数据集比 mAP 比分类更不可靠（表 6）。

主线一句话：动作识别只有一个口径（top-1），时序定位有三个互不可换算的口径（tIoU-mAP、逐帧 AP/F1、定位误差）；报数时不写清是哪一个，数字就没有意义。

一、任务定义与它的三个子问题#

1.1 输入输出的形状#

时序动作定位（temporal action localization / detection）的一般形式：

输入 x∈RT×H×W×C ⟹ 输出 {(s^i​,e^i​,c^i​,p^​i​)}i=1K​.

和上一节相比，多出来的三个自由度是：

  1. 段数 K 未知：一段视频里可能有零个、一个、多个动作，K 本身要预测；
  2. 边界 (s^,e^) 是连续量：不是类别，而是实数位置；
  3. 同一类别可以出现多次：两个真值之间的匹配是指派问题，不是分类问题。

这三个自由度分别对应三条技术路线的三种"偷懒方式"：

路线 怎么处理 K 怎么处理边界 怎么处理多次出现
边界回归 固定（先给锚） 回归偏移 靠多个锚
提议生成 枚举候选 候选自带边界、只分类/回归 靠候选数量
密集预测 连通域自动定 阈值化 + 平滑 连通域天然多段

1.2 与"动作识别"的边界#

判断一个任务是不是本节的任务，问一个问题：

如果把真值的边界人为移动 10%，任务的正确答案会变吗？

  • 动作识别：不会（标签只看片段里有没有该动作）；
  • 时序定位：会（IoU 直接变）。
  • 动作检测（一段视频多标签）：会（要给出每一段的边界）。

这个判据同时也说明：动作识别的那一套评测（top-1/多裁剪）在时序定位里完全不可用，因为 top-1 对边界移动不敏感，而这正是本节全部难度的来源。

1.3 三个子问题各自的可解性下界#

在谈方法之前，先各自给一个"不算模型也能算出来的界"：

  1. 边界：IoU=0.5 允许的边界误差是时长的 1/3（表 1）。这是误差预算，它决定回归头的精度需求。
  2. 段数：如果一段视频平均有 λ 个真值，随机猜段数的正确率是 1/(λ+2) 量级（含"零段"）。这解释了为什么"段数"通常由阈值/非极大抑制决定，而不是直接回归。
  3. 召回：任何两阶段方法的召回率不可能超过提议生成器的 IoU@阈值召回率（表 5 的注 1）。这个界在调参前就该量出来。

二、时序 IoU：一份精确的误差兑换率#

2.1 定义与闭式#

IoU([se​,ee​],[sp​,ep​])=​[se​,ee​]∪[sp​,ep​]​​[se​,ee​]∩[sp​,ep​]​​.

它在两个区间长度相同时有一个只用偏移表达的闭式。设长度 L、起点偏移 δ（0≤δ≤L）：

IoU(δ)=L+δL−δ​.

为什么这样设计：IoU 同时惩罚"位置错"与"长度错"，且对长度不敏感（比值而非差值）。用比值的好处是尺度不变；代价是容限随时长变化，这一点下面立刻展开。

  • 在 5 秒真值上，起点偏 1.666667 秒仍算 0.5 IoU——蒙对；
  • 在 1 秒真值上，偏 0.333333 秒就刚好落在边界，再偏一点就是 0。

所以"按动作时长分层报 mAP"不是可选项：长短动作的判定难度差一个量级，只报一个总数会把这件事完全抹平。可算判据：如果测试集里最短动作的时长 Lmin​ 满足 Lmin​<3⋅MAE(边界误差)，那么 0.5 阈值下这部分真值基本不可能被命中，它们的 mAP 贡献应当单独统计。

2.3 长度错误：另一条独立的失败通道#

上面的闭式只覆盖"等长 + 平移"。长度错误更狠：设真值长 G、预测长 P=G+Δ 且完全包含真值，则

IoU=G+ΔG​=1+Δ/G1​.

Δ/G=1（长了一倍）⇒IoU=0.5；Δ/G=0.25⇒0.8。

判据：预测长度与真值长度的分布要单独看。一个"总把区间开得很大"的模型可以用高召回骗过逐帧指标，但在区间 IoU 上必然崩——这正是表 4 第 4 行要量化的东西。

三、边界回归 / 提议生成 / 密集预测#

3.1 三条路线的机制#

(a) 边界回归。 先有锚区间 [as​,ae​]，再回归两个偏移：

s^=as​+bs​(ae​−as​),e^=ae​+be​(ae​−as​).

为什么这样设计：把"绝对位置"换成"相对偏移"，回归目标被限制在一个有界区间内，且尺度不变。这个技巧与目标检测里的锚框是同一个想法。

代价：锚一旦没有覆盖真值，真值就不可能被恢复（锚覆盖率 = 召回天花板）；而且单锚结构天生给不出多段。

(b) 提议生成。 先生成 K 个候选区间（滑动窗、分组回归、或学出来的提议网络），再对每个候选做分类 + 边界精修。算例里候选 [10,30],[20,45],[30,55],[45,70] 对真值 [20,60] 的 IoU 分别是 0.200000/0.625000/0.625000/0.300000（表 5）：只有两个够到 0.5，而且各自丢了真值的一端 15–20 帧。

代价（结构性）：没有满分候选时，召回率被提议生成器直接封顶。这不是分类器能补救的——分类器只能决定"用不用这些候选"。

(c) 密集预测。 逐帧二分类（前景/背景概率）→ 阈值 → 取连通区间 → 可选平滑。它的段数由连通域自动决定，结构最简单。

代价：k/G 的算术上界（第三节 4.2 已算：单帧 1/41=0.024390）。所以平滑/包络不是可选项，是必需品。

3.2 单帧提案的硬上界（本节最重要的算术）#

真值长 G 帧时，单帧预测 [t,t+1] 的 IoU：

IoU=G1​(落在真值内),IoU=G+d1​(落在真值外、距边界 d 帧).

IoU=G1​(落在真值内),IoU=G+d1​(落在真值外、距边界 d 帧).

所以上界就是 1/G，与预测得多准无关。 G=41 帧时上界 0.024390；要过 IoU=0.3 需要 G≤3.3333 帧，过 0.5 需要 G≤2.0000 帧。

kmin​=⌈θ⋅G⌉,dmax​=θkmin​​−G.

  1. k=1（纯单帧）时三个阈值全部落在"不能命中"一侧——这不是训练不充分，是算术不允许；
  2. 平滑让 dmax​ 从负数变成正数，即"允许预测稍微超出真值"——这正是平滑在做的事；
  3. dmax​ 只有 0.43–2.33 帧量级，所以平滑的粒度必须是帧级甚至亚帧级，不能用"把区间拉长一倍"这种粗平滑。

四、评测（上）：IoU 阈值与 mAP 的统计含义#

4.1 两种协议#

协议 A（tIoU 匹配 + 全局排序）——时序定位的标准口径：

  1. 所有视频、所有类别的预测排成一条全局置信度降序列表；
  2. 依次取出，与同视频、尚未匹配的真值求 IoU；最高 IoU ≥θ 则记 TP 并锁定该真值，否则记 FP；
  3. 在每个 TP 处算 P=TP/(TP+FP)、R=TP/Npos​，取 precision 的前缀包络（单调化），在 101 个 recall 点上插值求平均。

AP=1011​r∈{0,0.01,…,1}∑​r~≥rmax​P(r~),mAP=C有真值的类​1​c∑​APc​.

AP=1011​r∈{0,0.01,…,1}∑​r~≥rmax​P(r~),mAP=C有真值的类​1​c∑​APc​.

协议 B（逐帧）：把每个帧位置当独立样本，按分数排序算逐帧 PR 曲线面积；或取 maxα​P+R2PR​ 作为"最优 F1"。

四条读法：

  1. 无假阳性时两个口径结论一致（都算不错），但注意区间 IoU 也不是 1.0：平滑的响应阈值化后必然多出几帧——逐帧最优与区间最优不是同一个工作点。
  2. 尾部假阳性把逐帧 AP 从 0.949926 压到 0.462833（降 51.28%）、最优 F1 从 0.921053 压到 0.729167（降 20.83%），而最大区间 IoU 完全不动：总可以选一个更高的阈值把那段假阳性切掉、只留主峰。孤立假阳性对区间指标近乎免费，对逐帧指标致命。
  3. 头部假阳性更难处理（与主峰无法用单一阈值分开），把最大区间 IoU 压到 0.707317。
  4. 长度错误几乎不惩罚逐帧指标：真值长度只对了 70% 时逐帧 AP 仍有 0.911174、最优 F1 仍有 0.837838，而最大区间 IoU 掉到 0.720930。

合起来：逐帧指标敏感于"多标/漏标帧"，区间 IoU 敏感于"长度与边界"。所以 "逐帧 F1 0.9、tIoU-mAP 0.3"可以同时成立，两个数字不可换算、不可互相背书。

  1. 是协议 A 还是协议 B；
  2. 若是 A：阈值集合（0.3–0.7 取平均？单 0.5？）、每视频预测数上限（top-K）、是否按类别平均、Npos​ 的定义；
  3. 若是 B：阈值怎么选——在测试集上扫最优 F1 是有乐观偏差的，要在验证集上定；
  4. 测试视频数 V（下一节的统计门槛）；
  5. 是否按动作时长分层（表 1 的容限差异）。

更糟的是 mAP 是多个阈值的平均，各阈值之间强相关，所以"平均"不能降低方差。报 mAP 必须同时报阈值集合与 V。

5.2 真值数量本身有噪声#

若一段视频的真值数服从泊松 λ，真值总数的相对波动是 1/Vλ​：

V λ 相对波动 绝对波动（个）
1,000 1.0 0.031623 31.62
1,000 3.0 0.018257 54.77
10,000 1.0 0.010000 100.00
10,000 3.0 0.005774 173.21

V=1000,λ=1 时是 3.1623%。如果两批数据用不同标注规范造，这 3% 会直接变成 mAP 的 3 个点。

边界（这一条决定了能不能跨数据集比）：标签规范差异同时改变真值的数量与边界，两者都直接进 mAP。所以时序定位的跨数据集比较比分类更不可靠；只有在同一份真值、同一套阈值、同一个 Npos​ 定义下的比较才是有意义的。

def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1 for ch in s)


def pad(s, w, align=">"):
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2
    return " " * left + s + " " * (gap - left)

def iou(se, ee, sp, ep):
    inter = max(0.0, min(ee, ep) - max(se, sp))
    union = (ee - se) + (ep - sp) - inter
    return inter / union if union > 0 else 0.0

def evaluate_at(theta, preds, gt):
    """协议 A：全局置信度排序 + tIoU 匹配 + 101 点插值 AP。"""
    matched = {v: [False] * len(g) for v, g in gt.items()}
    npos = sum(len(g) for g in gt.values())
    order = sorted(preds, key=lambda x: -x[3])
    tp = fp = 0
    prec, rec, rows = [], [], []
    for (v, s, e, conf) in order:
        best, bi = 0.0, -1
        for i, (gs, ge) in enumerate(gt.get(v, [])):
            if matched[v][i]:
                continue
            o = iou(gs, ge, s, e)
            if o > best:
                best, bi = o, i
        if bi >= 0 and best >= theta:
            matched[v][bi] = True
            tp += 1
            hit = "TP"
        else:
            fp += 1
            hit = "FP"
        p = tp / (tp + fp)
        r = tp / npos
        prec.append(p)
        rec.append(r)
        rows.append((v, f"[{s:g},{e:g}]", f"{conf:.2f}", hit, f"{best:.6f}",
                     f"{p:.6f}", f"{r:.6f}"))
    env = list(prec)
    for i in range(len(env) - 2, -1, -1):
        env[i] = max(env[i], env[i + 1])
    ap = 0.0
    for k in range(101):
        rk = k / 100.0
        pk = max([env[i] for i, r in enumerate(rec) if r >= rk] or [0.0])
        ap += pk / 101.0
    return ap, rows, npos

T = 100
GTS = (20, 61)                      # 真值 [20,60]，半开区间
gt_frames = set(range(*GTS))
N_GT = len(gt_frames)


def make_scores(spikes, sigma=2.0):
    """主峰在真值中心（sigma 很小 -> 阈值化后区间接近真值）；spikes 为假阳性脉冲。"""
    c = 0.5 * (GTS[0] + GTS[1] - 1)
    sc = {t: 0.5 + 0.45 * math.exp(-((t - c) ** 2) / (2 * sigma ** 2)) for t in range(T)}
    for (s0, ln, h) in spikes:
        for t in range(s0, s0 + ln):
            if 0 <= t < T:
                sc[t] = max(sc[t], h)
    return sc


def frame_ap(sc):
    order = sorted(sc, key=lambda t: -sc[t])
    tp = 0
    ap = 0.0
    prev_r = 0.0
    for i, t in enumerate(order, 1):
        if t in gt_frames:
            tp += 1
        p = tp / i
        r = tp / N_GT
        ap += (r - prev_r) * p
        prev_r = r
    return ap


def best_f1(sc):
    best, best_th = 0.0, None
    for th in sorted(set(sc.values()), reverse=True):
        sel = [t for t in sc if sc[t] >= th]
        tp = sum(1 for t in sel if t in gt_frames)
        fp = len(sel) - tp
        p = tp / (tp + fp) if tp + fp else 0.0
        r = tp / N_GT
        f1 = 2 * p * r / (p + r) if p + r else 0.0
        if f1 > best:
            best, best_th = f1, th
    return best, best_th


def intervals_at(sc, th):
    iv, cur = [], None
    for t in range(T):
        if sc[t] >= th:
            cur = [t, t] if cur is None else [cur[0], t]
        else:
            if cur is not None:
                iv.append(tuple(cur))
                cur = None
    if cur is not None:
        iv.append(tuple(cur))
    return [((a, b + 1), iou(GTS[0], GTS[1], a, b + 1)) for (a, b) in iv]


def best_interval_iou(sc):
    best, bestinfo = 0.0, None
    for th in sorted(set(sc.values()), reverse=True):
        for iv, o in intervals_at(sc, th):
            if o > best:
                best, bestinfo = o, iv
    return best, bestinfo

    return {t: 0.5 + 0.45 * math.exp(-((t - c) ** 2) / (2 * 2.0 ** 2)) for t in range(T)}

表 6  检测结果的统计可分辨门槛：视频级指标的方差灾难
====================================================================================================
检测任务的每个样本是**一段视频**，通常每段只有 1-3 个真值。
把「某视频是否被检出」当伯努利变量、检出率 p，视频数 V 时

两次独立评测判为有差需 |p1-p2| > 1.96*sd*sqrt(2)。

10,000         |         0.004737 |           0.009285 |                 0.013131
50,000         |         0.002118 |           0.004152 |                 0.005872
----------------------------------------------------------------------------------------------------
读法：V=10000 时门槛是 0.013131——
**1.3 个百分点的提升在 10000 段视频上不可分辨**。

更糟的是：mAP 是多个 IoU 阈值下的平均，各阈值之间强相关，
所以「平均」并不能降低方差；报 mAP 必须同时报阈值集合与视频数 V。

还有一个只属于检测的坑：**真值数量本身有噪声**。
若一段视频真值数 ~ 泊松(lambda)，则真值总数的相对波动是 1/sqrt(V*lambda)：
V            |         lambda |         真值总数相对波动 |         绝对波动（个）
----------------------------------------------------------------------------------------------------
1,000        |            1.0 |                 0.031623 |                  31.62
1,000        |            3.0 |                 0.018257 |                  54.77
10,000       |            1.0 |                 0.010000 |                 100.00
10,000       |            3.0 |                 0.005774 |                 173.21
----------------------------------------------------------------------------------------------------
读法：lambda=1 时真值总数的相对波动是 1/sqrt(V)，V=1000 时有 3.1623%。
**如果两批数据用不同标注规范造，这 3% 会直接变成 mAP 的 3 个点。**
所以检测的跨数据集比较比分类更不可靠：标签规范差异同时改变真值**数量**与
真值**边界**，而两者都直接进 mAP。

小结#

  • 时序 IoU 是精确的误差兑换率：IoU=(L−δ)/(L+δ)，θ=0.5 恰好对应 δ=L/3，θ=0.7 对应 3L/17=0.176471，θ=0.9 对应 L/19=0.052632。反解容限 dmax​=L(1−θ)/(1+θ)，绝对容限正比于时长。
  • 单帧提案有硬上界 1/G：G=41 帧时上界 0.024390；过 θ=0.5 的最小扩展 k=21 帧、dmax​=1 帧。长度超过 2 帧的真值，单帧预测在 tIoU=0.5 下不可能命中——平滑是必需品。
  • 三条路线各自有一个天花板：边界回归看锚覆盖率，提议生成看提议召回率（算例里 4 个候选只有 2 个够到 0.5），密集预测看 k/G。先量天花板，再谈调参。
  • 协议 A 的 AP 几乎只由置信度靠前的预测决定：11 条预测的算例里 AP 在 θ=0.3/0.5/0.7 下都是 0.925743；删掉 3 条低分预测后掉到 0.801980（降 13.37%）。尾部误报几乎免费，头部误报代价极大。
  • 近似命中拿满分：同阈值下 IoU=0.51 与 1.00 收益相同，所以必须另报定位误差分布。
  • 协议 A 与协议 B 敏感的错误类型相反：孤立假阳性把逐帧 AP 从 0.949926 打到 0.462833（降 51.28%）而最大区间 IoU 不动（0.853659）；长度只对 70% 时逐帧 AP 仍有 0.911174、区间 IoU 掉到 0.720930。两者不可换算。
  • 统计门槛：sd=p(1−p)/V​，V=10000 时判为有差需 0.013131；真值数量的泊松波动 1/Vλ​ 在 V=1000,λ=1 时是 3.1623%。跨数据集比 mAP 比分类更不可靠。
  • 报数五件套：协议（A/B）、阈值集合、每视频 top-K、V、时长分层。
