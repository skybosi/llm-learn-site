预训练任务#

前两课分别讲了 BERT 的填空目标（MLM）与架构。这一课把它们拼起来，看 BERT 在预训练阶段同时做的两件事：掩码语言模型（MLM）与下一句预测（NSP）。我们会讲清 NSP 的设计与争议、预训练的数据与规模，以及预训练完成后如何"接任务头"微调到分类、问答等下游任务——把第 1 章的"范式二"落到 BERT 的具体流程上。

一、概念讲解#

1. 两个预训练任务：MLM + NSP#

BERT 的预训练是多任务的，每个训练样本同时承担两个目标：

  1. 掩码语言模型（MLM）：把 15% 的 token 遮起来预测（第 1 课讲过），负责学"词与词之间的语义关系"；
  2. 下一句预测（Next Sentence Prediction，NSP）：给两句 [CLS] 句A [SEP] 句B [SEP]，让模型判断"句 B 是否是句 A 真正的下一句"，负责学"句子与句子之间的关系"。

为什么需要 NSP？因为很多下游任务依赖句间关系（如问答里的"问题—答案"、自然语言推理里的"前提—假设"）。只靠 MLM，模型学不到"这两句话是否衔接"。NSP 让模型在预训练时就见过"句子对"结构，微调这类任务时更省力。

2. NSP 的样本构造：50/50 正负例#

构造 NSP 样本时，一半是正例、一半是负例：

  • 正例（label=1，IsNext）：句 B 在语料里确实是句 A 的下一句；
  • 负例（label=0，NotNext）：句 B 从语料里随机抽一句（与句 A 无关）。

模型在 [CLS] 位置的输出上接一个二分类头，判断两者是否衔接。[CLS] 表示 + 分段嵌入（句 A 用 0、句 B 用 1）共同为这个判断提供信息。

3. NSP 的争议与 RoBERTa 的取舍#

NSP 后来被证明未必必要。RoBERTa（2019）做了系统的消融实验，发现：

  1. 去掉 NSP 甚至略好：只用 MLM 在部分任务上反而更强；
  2. 数据与训练更重要：更大的语料、更长的训练、更大的 batch、动态掩码，带来的提升远大于 NSP。

于是 RoBERTa 干脆去掉了 NSP，只保留 MLM，并把数据从 BERT 的约 16GB 文本扩到 160GB。这提醒我们：预训练任务的设计要经过实证检验，不是"越多任务越好"。此后 ALBERT 又把 NSP 换成更难的自监督目标 SOP（句子顺序预测），继续探索"怎么让模型学句间关系"。

4. 预训练的数据与规模#

BERT 的预训练语料是 BooksCorpus（8 亿词）+ 英文维基百科（25 亿词），共约 33 亿词。训练细节：base 模型在 512 长度序列上训练约 100 万步，用 Adam 优化器，MLM 与 NSP 损失相加作为总损失。相比今天的 LLM（数万亿 token），这个规模很小，但在 2018 年已是"大规模预训练"的标杆。

5. 预训练之后：微调到下游任务#

预训练得到的是"通用语言表示"，要解决具体任务，就在它上面接一个任务头再微调：

  • 单句分类（情感分析等）：在 [CLS] 输出上接线性分类头；
  • 句子对任务（NLI 等）：同样用 [CLS] 表示，输入两句；
  • 序列标注（命名实体识别）：在每个 token 的输出上接分类头；
  • 抽取式问答（SQuAD）：预测答案在文中的起止位置。

微调时整个模型（含预训练权重）一起用任务数据继续训练，通常只需少量数据就能达到很好的效果。这正是第 1 章"范式二：预训练 + 微调"的完整落地。

二、可运行代码示例#

先手写 NSP 样本构造，看清 50/50 正负例是怎么来的：

import random

def build_nsp_pairs(sentences, rng=None):
    """为每句话构造 (句A, 句B, 是否下一句) 的 NSP 样本，正负各约一半。"""
    rng = rng or random.Random(0)
    pairs = []
    for i, a in enumerate(sentences):
        if rng.random() < 0.5:
            b = sentences[(i + 1) % len(sentences)]   # 正例：真正的下一句
            label = 1
        else:
            choices = [s for j, s in enumerate(sentences) if j != i]
            b = rng.choice(choices)                    # 负例：随机挑一句
            label = 0
        pairs.append((a, b, label))
    return pairs

sents = ["I like apples", "They are sweet", "The car is fast", "Water is wet"]
for a, b, l in build_nsp_pairs(sents):
    print(f"A: {a!r:>20}  B: {b!r:>20}  -> 是否下一句: {l}")

运行后你会看到 1 与 0 大致各半——正例是语料里真正相邻的两句，负例是随机拼凑、语义无关的两句。模型要学的，就是区分这两类。

再演示"预训练底座 + 任务头"的微调：在 [CLS] 上接二分类头做情感分类。

import torch
from transformers import BertForSequenceClassification, BertTokenizer

# num_labels=2：在 BERT 的 [CLS] 输出上接一个二分类头
model = BertForSequenceClassification.from_pretrained(
    "bert-base-uncased", num_labels=2)
tok = BertTokenizer.from_pretrained("bert-base-uncased")

# 玩具数据：6 条短句，1 = 正向情感，0 = 负向情感
texts = ["I love this movie", "this film is amazing",
         "so boring I fell asleep", "worst film ever",
         "absolutely brilliant", "I hate it"]
labels = torch.tensor([1, 1, 0, 0, 1, 0])

enc = tok(texts, padding=True, truncation=True, return_tensors="pt")
optim = torch.optim.AdamW(model.parameters(), lr=1e-5)

model.train()
for epoch in range(3):
    optim.zero_grad()
    loss = model(**enc, labels=labels).loss   # 内部已完成 [CLS] → 分类头 → 交叉熵
    loss.backward()
    optim.step()
    print(f"epoch {epoch}: loss = {loss.item():.4f}")

注意 BertForSequenceClassification 干的事：它在 BERT 的 [CLS] 输出上接了一个线性分类头，前向时自动算好交叉熵损失。这就是"预训练底座 + 任务头 + 微调"的最小完整形态。

三、练习#

  1. 修改 build_nsp_pairs，让正例比例从 0.5 改成 0.9，观察输出中 1 的占比，并解释为什么 BERT 要刻意保持正负平衡（提示：否则模型会学到什么"偷懒"策略）。
  2. 把微调示例的 num_labels 改成 3（三分类），说明 BertForSequenceClassification 内部发生了哪些变化，训练代码又是否需要改动。
  3. 查 RoBERTa 论文，找出"去掉 NSP"之后模型在哪些任务上变好、哪些任务上变化不大，用一句话概括 NSP 的真实价值。
  4. 思考题：为什么 BERT 微调只需要很少的标注数据？结合"预训练已经学到了通用语言知识，微调只是把它迁移到具体任务"来回答。
