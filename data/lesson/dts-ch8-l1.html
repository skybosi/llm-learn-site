三本账：显存 / 通信 / 扩展效率 —— 给定模型就能算出该用哪种组合#

前七章你是"顺推"：给定并行组合，分析它的通信与效率。这一章反过来：给你一个模型和一批机器，先算出该用哪种组合，再动手。做法是把决策拆成三张可以手算、也可以打印的表——显存账本管"装不装得下"、通信账本管"要搬多少字节"、扩展效率账本管"多花的卡值不值"。三张表都只用参数量、字节数和 α-β 三个量。

一、概念讲解#

1. 先定义三本账与输入输出#

显存账本（memory ledger）：把每张卡要放的字节逐项列出来，判断组合是否可行。通信账本（communication ledger）：把一个优化器步里每个 rank 要搬运的字节数与轮数算出来，套 α-β 模型得时间。扩展效率（scaling efficiency）：理想计算时间除以实际单步时间，衡量"加卡带来的收益剩了多少"。

输入只有两组量：模型（层数 L、hidden h、头数 a、词表 V、序列长 s）和机器（卡数 N、每卡显存、峰值、单跳延迟 α、等效带宽 β）。输出是一个并行组合 (TP,PP,DP,ZeRO) 加预算表。参数量的口径先统一：每层注意力 4h2 + MLP 8h2 = 每层 12h2，再加词嵌入 Vh。

2. 第一本账：16 字节/参数的来历#

混合精度 + Adam 训练时，每个参数要占：fp16 权重 2 + fp16 梯度 2 + fp32 主权重 4 + Adam 一阶动量 4 + 二阶方差 4 = 16 字节。这正是 ZeRO 论文的口径：它以 Ψ 表示参数量、K 表示优化器状态乘子（混合精度 Adam 的 K=12），得到总内存 2Ψ+2Ψ+KΨ=16Ψ。

ZeRO（Zero Redundancy Optimizer，零冗余优化器）按"切什么"分三档，每卡模型状态量分别是 4Ψ+12Ψ/Nd​、2Ψ+14Ψ/Nd​、16Ψ/Nd​。论文给出的实例很直观：7.5B 模型、DP 度 64 时，纯 DP 每卡 120 GB，ZeRO-1/2/3 依次降到 31.4 / 16.6 / 1.88 GB。

激活另算。论文脚注给的量级关系是：激活 ∝ 层数 × hidden × batch × 序列长；序列长度还有一块与 a⋅s2 成正比的注意力矩阵，所以长序列时激活会先炸，这也是激活重算（activation recomputation，即梯度检查点）存在的原因。TP 会把大部分激活按 1/TP 摊薄，PP 按层摊薄。

3. 第二本账：通信量的三种来源#

数据并行的每步成本是一次梯度 AllReduce：2Ψ 个元素（fp16 即 4Ψ 字节）；ZeRO-3 因为还要在前后向各 AllGather 一次参数，变成 3Ψ，也就是论文说的"通信量升到 1.5 倍"。ring 算法的每 rank 搬运量与时间在第 2、4 章已经推过：

Vrank​=N2(N−1)​S,Tring​=2(N−1)(α+NβS​)

张量并行（TP）的量在层上：Megatron-LM 的结论是每个 transformer 层的前向只剩 2 次 AllReduce、反向再 2 次（MLP 一次、注意力输出一次），消息大小是 s⋅b⋅h 个元素。流水线并行（PP）只有相邻 stage 的点对点，字节量小，代价在气泡：bubble=(PP−1)/(micro+PP−1)。

4. 第三本账：通信不随卡数下降#

把三本账合成一个单步时间：

Tstep​=Tcmp​⋅(1+bubble)+Tcomm​⋅(1−overlap)

关键在于 Tcomm​ 的带宽项约等于 2S/β，与卡数几乎无关（N/(N−1)→1），而 α 项 2(N−1)α 还随卡数线性增长；只有计算项 ∝1/N 在下降。所以固定全局 batch 地加卡（强扩展）必然撞墙：示例模型从 16 卡的 96.3% 掉到 256 卡的 60.5%。要保住效率，全局 batch 必须随卡数同步放大（弱扩展），示例里 16→256 卡都稳定在 96.1%——代价是 batch 放大本身会影响收敛，这正是第 7 章"有效 batch 换算"要处理的事。

5. 决策顺序（也是第 4 课项目的算法）#

  1. 由模型配置算参数量与单层激活；2. 用显存账本筛出装得下的候选；3. 用通信账本与效率账本给候选排名；4. 用成本账本（下一课）在工期约束下定价；5. 小规模实测校验预测，偏差写进报告。

6. 常见坑#

  • 只按 fp16 权重估显存：漏掉优化器状态，少算 8 倍。
  • 用平均带宽算环时间：环的速率由最慢一跳决定（第 4 章），跨 rail 会腰斩。
  • 按线性扩展报工期：示例里 256 卡强扩展只剩 60%，工期直接差 40%。
  • 忽略 α 项随 N 增长：小消息 + 多卡时，2(N−1)α 才是主角。
  • 把 TP 当万能旋钮：它增加每层集合通信次数，跨节点立刻崩塌。

二、可运行代码示例#

三段纯 numpy/Python，不需要任何 GPU。全部参数都是示例量级（峰值 990 TFLOP/s、α=5μs、等效带宽 200 GB/s、$2/GPU·h），请用 nccl-tests 与你自己机器的实测值替换后再下结论。

import numpy as np

# ===== 示例 1：numpy 模拟 ZeRO-3 参数分片与 AllGather 重建 =====
rng = np.random.default_rng(0)
W = rng.standard_normal((8, 4)).astype(np.float32)   # 用 8x4 张量当"一层权重"的替身
WORLD = 4

def zero3_shard(t, world):
    """ZeRO-3 / FSDP 的切分口径：参数按 rank 连续切块（这里按第 0 维切，便于观察）。"""
    return np.array_split(t, world, axis=0)

shards = zero3_shard(W, WORLD)
print("示例 1：ZeRO-3 分片 + AllGather 重建（world=4）")
for r, s in enumerate(shards):
    print(f"  rank {r}: 持有分片 shape={s.shape}，元素数={s.size}")
gathered = np.concatenate(shards, axis=0)
print(f"  AllGather 重建后与原始张量逐元素相等：{np.array_equal(gathered, W)}")

# ===== 示例 2：numpy 模拟 ring AllReduce（reduce-scatter + all-gather） =====
def ring_allreduce(ranks, alpha_us=5.0, beta_gbps=25.0):
    """每 rank 一份输入；返回 (各 rank 的归约结果, 每 rank 搬运字节, 每 rank 耗时 us)。"""
    n = len(ranks)
    size = ranks[0].size
    chunks = [np.array_split(r.copy(), n) for r in ranks]   # 每 rank 把自己的张量切成 n 块
    for k in range(n - 1):                                  # 阶段一 reduce-scatter：n-1 步
        for r in range(n):
            idx, dst = (r - k) % n, (r + 1) % n
            chunks[dst][idx] = chunks[dst][idx] + chunks[r][idx]
    for k in range(n - 1):                                  # 阶段二 all-gather：n-1 步
        for r in range(n):
            idx, dst = (r + 1 - k) % n, (r + 1) % n          # 阶段一结束后 rank r 拥有第 (r+1)%n 块
            chunks[dst][idx] = chunks[r][idx].copy()
    out = [np.concatenate(c) for c in chunks]
    per_rank_bytes = 2 * (n - 1) * (size / n) * 4            # 2(n-1) 步 × 每步 size/n 个 float32
    per_rank_us = 2 * (n - 1) * (alpha_us + (size / n) * 4 / (beta_gbps * 1e3))
    return out, per_rank_bytes, per_rank_us

N = 4
grads = [np.arange(1, 1025, dtype=np.float32) * (r + 1) for r in range(N)]  # 4 份"梯度"
outs, pb, pt = ring_allreduce(grads)
ref = np.sum(np.stack(grads), axis=0)
theory = 2 * (N - 1) / N * 1024 * 4
print(f"\n示例 2：ring AllReduce（{N} 个 rank，每份 1024 个 float32，alpha=5us、beta=25GB/s 示例参数）")
print(f"  每个 rank 结果都等于 np.sum：{[bool(np.array_equal(o, ref)) for o in outs]}")
print(f"  每 rank 搬运 {pb:.0f} B，理论值 2(n-1)/n*S = {theory:.0f} B，一致：{pb == theory}")
S = 100 * 2**20                                          # 换成一个 100 MiB 的梯度
t_us = 2 * (N - 1) * (5.0 + (S / N) / (25 * 1e3))
print(f"  同一模型放大到 100 MiB 梯度：{t_us/1e3:.2f} ms（上限由 2(n-1) 次 alpha 与带宽项构成）")

# ===== 示例 3：三本账 —— 一个 6.6B 级模型的显存 / 通信 / 扩展效率 =====
CFG = dict(layers=32, hidden=4096, heads=32, vocab=32000, seq=4096)
PEAK, MFU = 990e12, 0.45          # 示例：bf16 稠密峰值 990 TFLOP/s（换成你的卡）
ALPHA_US, BW_BUS_GBPS = 5.0, 200.0  # 示例：单跳延迟 5us，等效总线带宽 200 GB/s（请用 nccl-tests 实测替换）

def params(cfg):
    """口径：每层注意力 4h^2 + MLP 8h^2 = 12h^2，加词嵌入 V*h（忽略 bias 与 LayerNorm）。"""
    L, h, V = cfg["layers"], cfg["hidden"], cfg["vocab"]
    return L * 12 * h * h + V * h

P = params(CFG)
print(f"\n示例 3：模型 {CFG}")
print(f"  参数量 ≈ {P/1e9:.2f} B")
per_layer_params = 12 * CFG["hidden"]**2
print(f"  每层 12h^2 = {per_layer_params/1e6:.1f} M；词嵌入 V*h = {CFG['vocab']*CFG['hidden']/1e6:.1f} M")

def act_per_layer_bytes(cfg, b, tp, recompute=True, st=2):
    """单层激活账本（逐项列出；重算注意力后不再保存 scores 与 softmax 概率两块 s^2 项）。"""
    s, h, a = cfg["seq"], cfg["hidden"], cfg["heads"]
    terms = {"QKV 输出": 3*s*b*h*st, "注意力输出": s*b*h*st,
             "MLP 中间": 2*s*b*4*h*st, "LN/残差": 2*s*b*h*st}
    if not recompute:
        terms["attention scores"] = a*s*s*b*st
        terms["softmax 概率"] = a*s*s*b*st
    return sum(terms.values()) / tp, terms

def mem_gib(P, nd, tp, pp, stage, act_b=0.0, ckpt_b=0.0, opt_b=16):
    """16 字节/参数 = fp16 权重 2 + fp16 梯度 2 + fp32 主权重 4 + Adam m 4 + v 4（混合精度 Adam）。"""
    Psh = P / tp / pp
    model = {0: Psh * opt_b,                    # 纯 DP：全部状态每卡一份
             1: Psh * (4 + 12 / nd),            # ZeRO-1：切优化器状态 12P
             2: Psh * (2 + 14 / nd),            # ZeRO-2：再切梯度 2P
             3: Psh * (16 / nd)}[stage]         # ZeRO-3：连参数 2P 一起切
    return (model + act_b + ckpt_b) / 2**30, model / 2**30

print("\n  第一本账 · 显存（每卡 GiB；microbatch=1、激活层数 / pp、梯度检查点开）")
print(f"    {'TP':>2} {'PP':>2} {'DP':>3} {'总卡':>4} {'ZeRO':>4} {'参数+优化器':>10} {'激活':>7} {'合计':>7}  {'≤80GiB':>6}")
for tp, pp, dp, stage, rc in [(1, 1, 8, 0, True), (1, 1, 8, 1, True), (1, 1, 8, 2, True),
                             (1, 1, 8, 3, True), (1, 1, 8, 3, False), (2, 1, 8, 3, True),
                             (2, 2, 8, 3, True), (4, 2, 16, 3, True)]:
    act, _ = act_per_layer_bytes(CFG, 1, tp, rc)
    act_all = act * CFG["layers"] / pp
    tot, mdl = mem_gib(P, dp, tp, pp, stage, act_b=act_all)
    print(f"    {tp:>2} {pp:>2} {dp:>3} {tp*pp*dp:>4} {'DP' if stage==0 else f'Z{stage}':>4}"
          f" {mdl:>10.1f} {act_all/2**30:>7.1f} {tot:>7.1f}  {'✓' if tot<=80 else '✗':>6}")

def grad_bytes(P, stage, dtype_bytes=2):
    """一个优化器步里梯度通信的总字节（全组视野）：DP/ZeRO-1/2 = 2Ψ 个元素，ZeRO-3 = 3Ψ。"""
    k = 2 if stage < 3 else 3
    return k * P * dtype_bytes

def comm_step(P, cfg, stage, dp, tp, tokens_step, layers_topology="flat"):
    """返回 (每 rank 搬运字节, 通信时间 ms)：梯度 AllReduce + TP 每层两次 AllReduce 的账。"""
    S = grad_bytes(P, stage)                       # 全组梯度字节
    per_rank = 2 * (dp - 1) / dp * S if dp > 1 else 0.0
    t_ms = 2 * (dp - 1) * ALPHA_US / 1e3 if dp > 1 else 0.0
    t_ms += per_rank / (BW_BUS_GBPS * 1e9) * 1e3
    if tp > 1:                                     # TP 通信发生在节点内，按同一等效带宽计
        per_layer_msg = (tokens_step // dp) * cfg["hidden"] * 2          # s·b·h 个 fp16
        tp_bytes = cfg["layers"] * 2 * (2 * (tp - 1) / tp) * per_layer_msg
        per_rank += tp_bytes
        t_ms += cfg["layers"] * 2 * 2 * (tp - 1) * ALPHA_US / 1e3
        t_ms += tp_bytes / (BW_BUS_GBPS * 1e9) * 1e3
    return per_rank, t_ms

def step_time(P, cfg, tokens_step, N, dp, tp, pp, stage, micro=16, overlap=0.85, recompute=True):
    """t_step = 计算 + 气泡 + 未重叠的通信；扩展效率 = 理想计算时间 / 实际单步时间。"""
    flops = 6 * P * tokens_step
    t_cmp = flops / (N * PEAK * MFU) * 1e3                       # ms
    _, t_comm = comm_step(P, cfg, stage, dp, tp, tokens_step)
    bubble = (pp - 1) / (micro + pp - 1)
    t_step = t_cmp * (1 + bubble) + t_comm * (1 - overlap)
    return t_cmp, t_comm, bubble, t_step, t_cmp / t_step * 100

print("\n  第二/三本账 · 通信与扩展效率")
print("  (a) 强扩展：全局 batch 固定 262144 token/步，加卡只缩短计算，不缩短通信")
print(f"    {'总卡':>4} {'TP':>2} {'PP':>2} {'DP':>4} {'计算 ms':>8} {'通信 ms':>8} {'气泡':>6} {'单步 ms':>8} {'扩展效率':>8}")
for Ntot, tp, pp, dp in [(16, 1, 1, 16), (64, 1, 1, 64), (128, 1, 1, 128), (256, 1, 1, 256), (512, 4, 2, 64)]:
    t_cmp, t_comm, bub, t_step, eff = step_time(P, CFG, 262144, Ntot, dp, tp, pp, 3)
    print(f"    {Ntot:>4} {tp:>2} {pp:>2} {dp:>4} {t_cmp:>8.1f} {t_comm:>8.1f} {bub:>6.1%} {t_step:>8.1f} {eff:>7.1f}%")
print("  (b) 弱扩展：全局 batch 随卡数等比放大（每卡 token 数不变）")
print(f"    {'总卡':>4} {'TP':>2} {'PP':>2} {'DP':>4} {'计算 ms':>8} {'通信 ms':>8} {'气泡':>6} {'单步 ms':>8} {'扩展效率':>8}")
for Ntot, tp, pp, dp in [(16, 1, 1, 16), (64, 1, 1, 64), (128, 1, 1, 128), (256, 1, 1, 256), (512, 4, 2, 64)]:
    tokens_step = 4096 * 4 * dp            # 每卡 microbatch=1、seq=4096、累积 4 步
    t_cmp, t_comm, bub, t_step, eff = step_time(P, CFG, tokens_step, Ntot, dp, tp, pp, 3)
    print(f"    {Ntot:>4} {tp:>2} {pp:>2} {dp:>4} {t_cmp:>8.1f} {t_comm:>8.1f} {bub:>6.1%} {t_step:>8.1f} {eff:>7.1f}%")
print("\n  第三本账的结论：通信时间几乎不随卡数下降（带宽项 ~2S/beta 固定，alpha 项还随 dp 线性涨），")
print("  所以强扩展必然撞墙；要让效率维持在 90% 以上，全局 batch 必须随卡数同步放大（弱扩展）。")

三、练习#

  1. 实现：把示例 3 的模型换成你自己的配置（层数、hidden、头数、词表、序列长），只改 CFG，重新打印第一本账与第二/三本账；把每卡显存上限从 80 GiB 改成你机器的实际值，指出哪一个组合最先变得不可行。
  2. 解释：示例 3 里 ZeRO-1（47.7 GiB）和 ZeRO-3（26.2 GiB）差 21.5 GiB，而关闭重算后激活一项就多 64 GiB。用 4Ψ+12Ψ/Nd​ 与 16Ψ/Nd​ 两个公式说明：为什么"先开重算"通常比"从 Z1 换到 Z3"更划算？什么情况下反过来？
  3. 对比/验证：把 step_time 的 overlap 从 0.85 改成 0.0，重跑强扩展表。分别解释 64 卡与 512 卡两行变化的百分比为什么不同（提示：看通信项与计算项的比值）。
  4. 思考：示例 3 里 512 卡 TP4/PP2 的效率只有 41.6%，而 256 卡纯 DP 有 60.5%。若工期要求是 30 天内训完 300B token，你会选哪个组合？用单步时间乘以步数把它算出来，并说明你愿意付的额外成本来自哪一本账。
