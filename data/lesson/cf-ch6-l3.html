指令调度与流水线：延迟隐藏（与 GPU occupancy 同理）#

第 2 课结束时每个值都有了自己的寄存器，但"有寄存器"不等于"跑得快"：指令从发射到结果可用之间隔着若干周期的延迟（latency），顺序发射的机器上，紧接着要用这个结果的指令只能让流水线空转——这几周期叫停顿（stall）。指令调度（instruction scheduling）就是重排顺序、把无关工作塞进停顿槽。本课讲清"需要多少无关工作才够"，并说明它与 GPU occupancy 是同一件事的两个层次。

一、概念讲解#

1. 延迟从哪来#

流水线把指令拆成取指、译码、执行、写回等阶段，因此发射间隔（reciprocal throughput，如每 2 周期一条）与结果可用时间（latency，如 8 周期）是两个不同的数。五级流水线靠"转发"让紧邻的 ALU 依赖不产生气泡，但访存、浮点乘加没那么幸运：凡是 RAW 依赖，要么等，要么让机器先做别的。

2. 依赖 DAG 与表调度#

把指令当节点、RAW 依赖当边得到一张 DAG；节点的高度（height）是从它出发到任一汇点的最长路径（含自身延迟）。表调度（list scheduling）只有两条规则：① 维护"就绪集合"（前驱已发射的指令）；② 每周期从就绪集合里挑高度最大的发射。这是龙书第 10 章的标准启发式——不保证最优（NP-hard），但足够好也足够快。

3. 延迟隐藏的定量：需要多少并行度#

把发射槽看成服务台、在飞指令看成排队人数，可以直接搬小定律（Little's law）的直觉：要让发射槽一直有活干，在飞指令数必须 ≥ 延迟 / 发射间隔——延迟 4 周期、每周期发射 1 条，就需要 ≥ 4 条独立指令同时在飞。本课代码量了这条结论（填隙率 = 指令数 / 发射跨度）：

并行度（独立链数） 发射跨度 完成周期 填隙率
1 29 32 0.28
2 14 17 0.57
4 8 11 1.00
8 8 11 1.00

并行度 1、2 时大量空转，4 条独立链就顶满（填隙率 1.00），再加到 8 条不会再快——够用即可，多出来的并行度是浪费寄存器。

4. 同一批算术，写法不同周期数差一倍#

调度器只能重排已存在的独立工作，变不出并行度；改变并行度得靠中端变换，最典型的是重结合（reassociation）：8 个乘积求和用 1 个累加器是一条 8 层依赖链，拆成 4 个就有 4 路独立工作，最后用归约树合并。本课代码实测（同样延迟 4 周期）：

写法 指令数 程序序 表调度 峰值寄存器
单累加器 8 32 32 2
4 累加器交错 11 19 19 5
4 累加器顺序 11 31 19 5
8 累加器树 15 23 23 9

① 单累加器那 32 周期几乎全是等待，调度器无能为力；② 4 累加器把时间压到 19 周期，代价是峰值寄存器 2 → 5；③ "顺序写"行最能说明调度的价值——同一份代码写成一串是 31 周期，重排后回到 19。再加累加器反而变差（23 周期、9 个寄存器）：归约树自己的延迟成了新瓶颈。并行度不是越多越好，它和寄存器压力一起被约束。

5. 与 GPU occupancy 同理#

GPU 走另一条路。一个 SM 上驻留的 warp 数是硬件层面的并行度，occupancy = 活跃 warp 数 / 最大 warp 数。访存延迟高达数百周期，单线程内的 ILP 远不够，硬件于是在 warp 之间切换：一个等数据，就换另一个上执行单元。

这与编译器做表调度满足的是同一个不等式——在飞工作量要盖住延迟 × 发射率，只是 CPU 侧主要用 ILP、GPU 侧主要用 TLP。代价也同构：本课表里"峰值寄存器 2 → 5"，在 GPU 上就是"每线程寄存器越多 → 驻留 warp 越少 → occupancy 越低"；CUDA 最佳实践文档也提醒，高 occupancy 有助于隐藏延迟，但不必盲目追求最大值。第 2 课的溢出与 GPU 的 occupancy 下降，是同一个资源约束的两套硬件版本。

6. 常见坑#

基本块内调度看不到跨块机会；真实的编译器还有 trace scheduling / 超块与软件流水（让不同迭代的指令重叠）两件武器，都在 LLVM 的"调度与形成"与"SSA 机器码优化"阶段。

  • 调度会拉长活跃范围：提前算"晚用"的指令会让值活得更久，可能把第 2 课的分配逼到溢出；好做法是调度与分配协同（LLVM 的 MachineScheduler 带寄存器压力感知）。
  • 乱动有副作用的指令：访存、可能触发异常的除法不能随意提前或推后；浮点重结合同样不合法（(a+b)+c ≠ a+(b+c)），只在允许不安全优化时才做。
  • 在乱序机器上过度乐观：硬件窗口本身会重排，调度的收益主要在顺序核、DSP、GPU 这类暴露延迟的机器上。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）实现顺序发射模拟 + 表调度，量出上面两张表的每个数。模型是本课自定义的玩具机器：单发射、顺序发射、延迟 4 周期——为看清机制，不是真实 CPU 参数。

# ---- 指令调度：顺序发射 + 停顿 vs 表调度（list scheduling） ----
# 纯 Python，无第三方依赖。
# 玩具机器模型：单发射（1 条/周期）、顺序发射；操作数未就绪就停顿；所有算术指令延迟 4 周期。
LAT = 4

def op(text, dst, srcs):
    return {'t': text, 'd': dst, 's': list(srcs)}

# ---------- 1. 三个程序：8 个乘积求和的三种写法 ----------
def single_acc(n=8):
    """单累加器：一条长依赖链 acc = acc + v[i]*w[i]（SSA 名字，每条指令一个结果）"""
    ops = [op(f'c0 = v0*w0', 'c0', ['v0', 'w0'])]
    for i in range(1, n):
        ops.append(op(f'c{i} = fma(v{i}, w{i}, c{i-1})', f'c{i}', [f'v{i}', f'w{i}', f'c{i-1}']))
    return ops

def multi_acc(n=8, k=4, interleaved=True):
    """k 个累加器：每条链 n/k 个乘积，最后用归约树合并"""
    m = n // k
    chains = []
    for j in range(k):
        ch = [op(f'c{j}_0 = v{j*m}*w{j*m}', f'c{j}_0', [f'v{j*m}', f'w{j*m}'])]
        for i in range(1, m):
            ch.append(op(f'c{j}_{i} = fma(v{j*m+i}, w{j*m+i}, c{j}_{i-1})', f'c{j}_{i}',
                         [f'v{j*m+i}', f'w{j*m+i}', f'c{j}_{i-1}']))
        chains.append(ch)
    ops = []
    if interleaved:
        for step in range(m):
            for j in range(k):
                ops.append(chains[j][step])
    else:
        for ch in chains: ops += ch
    # 归约树
    level, idx = [f'c{j}_{m-1}' for j in range(k)], 0
    while len(level) > 1:
        nxt = []
        for i in range(0, len(level) - 1, 2):
            t = f's{idx}'; idx += 1
            ops.append(op(f'{t} = {level[i]}+{level[i+1]}', t, [level[i], level[i+1]]))
            nxt.append(t)
        if len(level) % 2: nxt.append(level[-1])
        level = nxt
    return ops

def indep_chains(k):
    """k 条互相独立的单指令链：用来量"延迟隐藏需要多少并行度" """
    return [op(f'x{i} = v{i}*w{i}', f'x{i}', [f'v{i}', f'w{i}']) for i in range(k)]

# ---------- 2. 顺序发射模拟（程序序 / 给定顺序） ----------
def simulate(order):
    ready, clock, timeline = {}, 0, []
    for ins in order:
        t = max([ready.get(s, 0) for s in ins['s']] or [0])   # 操作数全部就绪的最早时间
        issue = max(clock, t)                                # 顺序发射：不能越过上一条
        clock = issue + 1
        ready[ins['d']] = issue + LAT
        timeline.append((issue, ins))
    cycles = max(i + LAT for i, _ in timeline)
    return cycles, timeline

# ---------- 3. 表调度：每次从"就绪指令"里挑关键路径最长的那条 ----------
def height_map(ops):
    """height[i] = 从 i 出发到任一汇点的最长路径（含自身延迟）；successor = 消费者"""
    succ = {i: [j for j, o in enumerate(ops) if ops[i]['d'] in o['s']] for i in range(len(ops))}
    h = {}
    for i in range(len(ops) - 1, -1, -1):
        h[i] = LAT + max([h[j] for j in succ[i]] or [0])
    return h, succ

def list_schedule(ops):
    h, succ = height_map(ops)
    preds = {i: [j for j, o in enumerate(ops) if o['d'] in ops[i]['s']] for i in range(len(ops))}
    done, order, clock = set(), [], 0
    while len(done) < len(ops):
        ready = [i for i in range(len(ops)) if i not in done and all(p in done for p in preds[i])]
        if not ready:                       # 全在等结果：空转一个周期
            clock += 1
            continue
        i = max(ready, key=lambda x: (h[x], -x))     # 关键路径最长的先发
        order.append(ops[i]); done.add(i); clock += 1
    return order, simulate(order)

# ---------- 4. 寄存器压力：每个结果从发射到"最后一次被用"都占一个寄存器 ----------
def peak_regs(ops, timeline):
    issue = {ins['d']: c for c, ins in timeline}
    last_use = {}
    for ins in ops:
        for s in ins['s']:
            last_use[s] = max(last_use.get(s, 0), issue[ins['d']])
    ivs = []
    for ins in ops:
        start = issue[ins['d']]
        end = last_use.get(ins['d'], start)
        ivs.append((start, max(end, start)))
    peak = 0
    for c in range(max(e for _, e in ivs) + 1):
        peak = max(peak, sum(1 for a, b in ivs if a <= c <= b))
    return peak

def span(timeline):
    """发射跨度：从第 0 周期到"最后一条指令被发射"，含被迫停顿的周期"""
    return max(c for c, _ in timeline) + 1

def report(label, ops):
    c1, tl1 = simulate(ops)                      # 程序序
    order2, (c2, tl2) = list_schedule(ops)       # 表调度
    s1, s2 = span(tl1), span(tl2)
    print(f'  {label:<22} {len(ops):>3} 条  程序序：跨度 {s1:>2}/填隙 {len(ops)/s1:.2f}'
          f'  完成 {c1:>2} 周期 ｜ list：跨度 {s2:>2}/填隙 {len(ops)/s2:.2f}'
          f'  完成 {c2:>2} 周期  峰值寄存器 {peak_regs(ops, tl2)}')
    return c1, c2

if __name__ == '__main__':
    print('=== 模型：单发射、顺序发射、算术指令延迟 %d 周期 ===' % LAT)
    print('\n=== 写法一：8 个乘积求和的四种写法（同一批算术） ===')
    report('单累加器（依赖链）', single_acc(8))
    report('4 累加器（交错写）', multi_acc(8, 4, True))
    report('4 累加器（顺序写）', multi_acc(8, 4, False))
    report('8 累加器（归约树）', multi_acc(8, 8, True))

    print('\n=== 写法二：k 条互相独立的指令（无依赖，纯看发射是否停顿） ===')
    for k in (1, 2, 4, 8):
        ops = indep_chains(k)
        c2, tl2 = simulate(ops)
        print(f'  {k} 条独立指令：发射跨度 {span(tl2)} 周期，完成 {c2} 周期'
              f'（延迟 {LAT} 只体现为末尾的流水线排空）')

    print('\n=== 写法三：并行度不足会怎样（k 条长度 8 的独立链） ===')
    for k in (1, 2, 4, 8):
        ops, n = [], 8 // k
        for j in range(k):
            ch = single_acc(n)
            ops += [op(o['t'].replace('c', f'k{j}_c'), o['d'].replace('c', f'k{j}_c'),
                       [s.replace('c', f'k{j}_c') for s in o['s']]) for o in ch]
        c1, tl1 = simulate(ops)
        _, (c2, tl2) = list_schedule(ops)
        print(f'  并行度 {k}（{len(ops)} 条）：发射跨度 {span(tl2)}，完成 {c2} 周期，'
              f'填隙率 {len(ops)/span(tl2):.2f}')

    print('\n=== 时间线（4 累加器交错写，list 调度） ===')
    ops = multi_acc(8, 4, True)
    _, (c2, tl2) = list_schedule(ops)
    for c, ins in tl2:
        print(f'  周期 {c:>2}: {ins["t"]:<28} 结果就绪于 {c + LAT}')
    print(f'  合计 {c2} 周期（缺号的周期就是没指令可发的空转周期）')

模型里 FMADD 的延迟是 8 周期、倒数为 0.50（理论吞吐 2 条/周期）。同段代码换成 k = 1 / 2 / 8 条独立链：

1 100 803 0.12

总周期几乎不随 k 变（803→806），因为每条链每 8 周期才能推进一次；k 越大同样周期里塞进的指令越多，IPC 按 k/8 线性上升，到 k = 8 顶到 1.0——正好复现第 3 节的结论：需要"延迟 × 吞吐"量级的独立工作才能填满发射槽。
