FCN 全卷积网络#

上一课留下的矛盾是：分类 CNN 一路下采样，最后靠全连接层"拍平"输出，既丢了空间、又丢了分辨率，没法做逐像素分割。FCN（Fully Convolutional Networks，全卷积网络） 给出了划时代的答案：把全连接层全部换成卷积层，让网络保留空间结构，再自己学会"上采样"把分辨率补回来。

它是现代语义分割的奠基之作。后面几乎所有分割网络（U-Net、DeepLab……）都是它的变体。这一课我们彻底搞懂它"为什么能端到端"。

一、概念讲解#

1. 全连接 → 全卷积：为什么这一步是关键#

回想分类 ResNet 的最后一层：输入是 7×7×2048 的特征图，先被展平成 7×7×2048 = 100352 维向量，再乘一个权重矩阵得到 1000 类分数。问题在于：这个权重矩阵的形状被"7×7"这个具体尺寸焊死了，换了输入尺寸网络就崩溃，而且展平把像素间的空间关系全抹掉了。

FCN 的做法是：把这个全连接层换成 1×1 卷积。数学上，一个 1×1 卷积核在每个空间位置做一次"通道间的线性组合 + 非线性"，其作用等价于"对每个位置的向量做一次全连接"，但它是逐位置共享、保空间的。于是：

  • 输入尺寸不再受限，任何大小的图都能进；
  • 输出不再是一个向量，而是一张保留空间位置的热力图（每个位置输出 K 个通道 = K 个类别的分数）。

这一替换，把"分类网络"变成了"逐像素打分网络"，是分割能端到端的第一块基石。

2. 上采样：把分辨率补回来#

骨干网络下采样 5 次（VGG 里每次 stride=2 的池化），特征图缩到输入的 1/32。要得到逐像素输出，必须把这张小热力图放大 32 倍。FCN 用的是转置卷积（Transposed Convolution，也叫反卷积 / Deconvolution）。

转置卷积的直觉：普通卷积是"多个输入像素加权求和成一个输出像素"（下采样/保尺寸），转置卷积是它的逆方向——"一个输入像素按卷积核权重散布（scatter）到多个输出位置"（上采样）。可以把转置卷积理解成"先对输入插零扩大，再做普通卷积"，因此它的输出尺寸可以用公式反推：

Hout​=(Hin​−1)×stride−2×padding+kernel_size

注意它不是普通卷积的精确逆运算（信息在下采样时已经丢失，无法无损恢复），但它可学习：网络能学会"怎样放大最有利于分割"，这比固定的双线性插值更强。当然，工程上也会直接用双线性插值 + 后续卷积做上采样，更省参数、更稳定。

3. Skip Connection：粗语义 + 细边界 = 更准#

直接 32 倍上采样，得到的是"FCN-32s"——结果很糊，因为下采样 5 次后细节早就没了。FCN 的关键改进是跳跃连接（skip connection）：把浅层的高分辨率特征加到上采样结果上，再继续上采样，形成分阶段恢复：

  • FCN-16s：1/32 特征上采样 2 倍，与第 4 次池化后的 1/16 特征相加，再 16 倍上采样；
  • FCN-8s：进一步叠加第 3 次池化后的 1/8 特征，再 8 倍上采样。

直觉很清楚：深层特征"知道是什么"（语义强、位置粗），浅层特征"知道在哪"（位置准、语义弱）。把两者逐级相加，就是在"是什么"和"在哪里"之间做折中，边界明显更锐利。FCN-8s 的效果显著好于 FCN-32s，确立了"编码器-解码器 + 跳跃连接"这一沿用至今的分割范式。

4. 端到端的含义#

FCN 之前的传统分割方法是一堆手工特征 + 图模型（如条件随机场 CRF 做后处理平滑）的拼装。FCN 第一次让"像素到像素"的映射由一个网络端到端完成：输入 RGB 图，直接输出同尺寸类别图，损失是每个像素的交叉熵，反向传播贯穿整网。没有中间的人工环节，这就是"端到端"的真正价值——也是它能横扫当时各大数据集的根本原因。

二、可运行代码示例#

先从零搭一个迷你 FCN（含转置卷积上采样 + 跳跃连接），验证"任意尺寸进、同尺寸出"；再用 torchvision 的预训练 FCN 看真实输出。

import torch
import torch.nn as nn
import torch.nn.functional as F

# ---------- 1) 迷你 FCN：下采样 + 转置卷积上采样 + 跳跃连接 ----------
class MiniFCN(nn.Module):
    def __init__(self, num_classes=3):
        super().__init__()
        # 编码器：三次下采样（stride=2），通道从 3 -> 32 -> 64 -> 128
        self.enc1 = nn.Sequential(nn.Conv2d(3, 32, 3, padding=1), nn.ReLU(),
                                  nn.Conv2d(32, 32, 3, padding=1), nn.ReLU())
        self.enc2 = nn.Sequential(nn.Conv2d(32, 64, 3, stride=2, padding=1), nn.ReLU())
        self.enc3 = nn.Sequential(nn.Conv2d(64, 128, 3, stride=2, padding=1), nn.ReLU())

        # 解码器：转置卷积逐级上采样
        self.up3 = nn.ConvTranspose2d(128, 64, kernel_size=4, stride=2, padding=1)  # 2x 上采样
        self.up2 = nn.ConvTranspose2d(64, 32, kernel_size=4, stride=2, padding=1)   # 2x 上采样
        self.up1 = nn.ConvTranspose2d(32, num_classes, kernel_size=4, stride=2, padding=1)

    def forward(self, x):
        e1 = self.enc1(x)         # (N, 32, H, W)
        e2 = self.enc2(e1)        # (N, 64, H/2, W/2)
        e3 = self.enc3(e2)        # (N, 128, H/4, W/4)
        d2 = self.up3(e3)         # (N, 64, H/2, W/2)
        d2 = d2 + e2              # 跳跃连接：融合同分辨率的浅层特征
        d1 = self.up2(d2)         # (N, 32, H, W)
        d1 = d1 + e1              # 再一次跳跃连接
        out = self.up1(d1)        # (N, C, 2H, 2W)，最后一步放大到更大尺寸
        return out

model = MiniFCN(num_classes=3)
x = torch.rand(2, 3, 64, 64)      # 任意尺寸输入
out = model(x)
print("输入形状：", tuple(x.shape))
print("输出形状：", tuple(out.shape))   # 期望 (2, 3, 128, 128)，通道数=类别数
print("像素级交叉熵损失示例：", F.cross_entropy(out, torch.randint(0, 3, (2, 128, 128))).item())

注意两点：up2 上采样后直接 d2 + e2，要求两者空间尺寸一致——这是转置卷积 kernel=4, stride=2, padding=1 恰好能 2 倍上采样的原因；最后 out 尺寸（128×128）比输入（64×64）还大，说明网络对输出尺寸有充分自由度，真实 FCN 会精确定制到"与输入同尺寸"。

三、练习#

  1. 用公式验证 kernel_size=4, stride=2, padding=1 的转置卷积确实做 2 倍上采样；再把 up2 换成 kernel=3, stride=2, padding=1，观察尺寸是否对不上并思考为什么跳跃连接会报错。
  2. 给 MiniFCN 加一层 self.up0，让最终输出尺寸恰好等于输入（64×64），并补一次与输入同分辨率没法做的说明（输入是 3 通道 RGB，不是特征）。
  3. 把转置卷积上采样改成 F.interpolate(..., mode="bilinear") + 1×1 卷积 的组合，对比两种方案的可学习参数量与效果差异。
  4. 用 torchvision 的 fcn_resnet50 做推理，观察 aux（辅助分类器）输出与主输出 out 的区别；思考"中间层加辅助监督"对梯度传播的帮助。
