视频表示：从 2D CNN 加时序聚合到视频 Transformer#

这一节要解决什么#

第 1 节把"视频"变成了一组可核对的数：S=fs​LHWC、N=(T/t)(H/p)(W/p)、FLOPsattn​=4N2d。但账只是约束，不是方案。这一节回答一个更具体的问题：

从"把视频当很多张图"到"把视频当一条时空 token 序列"，中间经历了四代表示。每一代是为了修上一代的什么缺陷而出现的？它又付出了什么代价？

四代是：2D CNN + 时序聚合 → 3D CNN → 双流 → 视频 Transformer。注意这不是"越来越好"的线性史，而是每一代把上一代的某个结构性缺陷换成了另一笔代价。本节的核心结论如下：

  1. 第一代的缺陷是代数的，不是容量的。 平均/最大池化对帧序置换不变：把一段 4 帧特征做时间反演，池化输出逐元素完全相同（最大差 0.000000），而一阶时间差分给出符号相反的输出（最大差 8.000000）。信息论上，T 帧有 T! 种排列，T=8 时要 15.299 bit、T=64 时要 295.995 bit 才能区分——池化把这 40320（8!）种排列商成了同一个向量。"开门 / 关门"在第一代下不可分，不是模型不够大，而是聚合算子在数学上丢掉了顺序（表 1）。
  2. 第二代的修法是显式卷积时间维，而它能成立的代数理由是"充气"。 把 2D 核沿时间复制 kt​ 份、每份除以 kt​：W3d​[:,:,t,:,:]=W2d​/kt​。对时间恒定的输入，这个 3D 核的响应与 2D 核在浮点误差内相等（最大误差 8.882×10−16）；不除 kt​ 则整体放大 3.000000 倍。参数量与 FLOPs 同时乘 kt​（表 2）。这条代数事实解释了 I3D 为什么能直接从 ImageNet 权重"充气"出 3D 权重——它把"3D 训练需要海量视频"这个门槛降成了"需要一个静止图像数据集"。
  3. 第二代的真正约束是感受野与时间分辨率的交换。 时间感受野递推 R←R+(kt​−1)J、J←J⋅st​：不做时间下采样时 Rt​=11 帧（0.367 s，Tout​=54 步）；I3D 式后段下采样 Rt​=19 帧（0.633 s，Tout​=6 步）；C3D 式逐段下采样 Rt​=63 帧（2.100 s）但 Tout​=1 步（表 3）。"3D 卷积能建模时序"的真实含义是"建模 0.4–0.6 秒的局部运动"，而更长的依赖必须靠下采样把时间折掉。
  4. 第三代的修法是把运动变成显式输入。 构造一个"类别 =（形状，方向）"的四类问题：只给外观特征可分 2/4（准确率 0.5000），只给运动特征也可分 2/4（0.5000），两者拼接后 4/4（1.0000）（表 4）。双流的动机就是这条"秩相加"：外观与运动在构造上互补。
  5. 第三代最贵的不是光流解算，而是存储与串行化。 粗到细 Lucas–Kanade（L=4、K=3、窗 7）约 4800 FLOP/像素，224² 一帧 0.241 GFLOP；而一个构造的 8 层 3×3 主干单帧是 5.130 GFLOP——变分解算只有主干的 0.0469 倍。真正的代价是：fp16 双通道光流的体积是 RGB uint8 的 1.3333 倍（12.250 MiB / 64 帧），10 万段素材要 1.168 TiB 预计算缓存；若改用 CNN 估流，32 帧 clip 要 31 次主干级前向 =159.030 GFLOP（表 4）。
  6. 第四代把"固定核"换成"内容寻址"，代价是二次项。 联合时空注意力（N=Nt​Ns​）与分解式时空注意力的比值是闭式 1/Nt​+1/Ns​：Nt​=8,Ns​=196 时 0.1301（省 7.69×），Nt​=32 时 0.0364（省 27.51×）（表 5）。但 1/Ns​ 是地板：空间部分仍按 Ns2​ 增长。
  7. token 化的两个旋钮在 N 上等价、在语义上不等价。 p:16→8 与 t:1→4 都让 N 变 4 倍（或 1/4）：T=32 时 per-frame patch 16 是 6272 个 token，tubelet 2×16 是 3136（0.5×），tubelet 4×16 是 1568（0.25×）（表 7）。p 变小是"看更细的空间"，t 变大是"把时间压得更狠"——同一个 N 背后是完全不同的信息取舍。
  8. 位置编码是视频 Transformer 里最容易被忽略、又最容易出错的一环。 联合 3D 学习表参数量 Nt​Ns​（T=64 时 6272 个），分解表 Nt​+Ns​（228 个），比值 27.51×；在 T=8 上预训练的联合表用到 T=64 时 5488/6272=87.5% 的位置没有学到的向量。正弦式编码的判据是点积只依赖位移（数值偏离 1.4×10−14）；而时间子块维度 dt 不能太小：dt=8（4 个频率）时最短码距 0.645292 出现在 Δ=63 上，比相邻位置的 0.964100 还小——位置编码自身把时间轴折叠了（表 6）。

一句话总结这一节的取舍：视频表示的演化史，就是不断把"信息放在哪里"这件事从算子的固定形状（池化 → 卷积核 → 手工光流）搬到数据决定的注意力上；每搬一次，建模能力上升、对数据与算力的要求也上升。

一、第一代：2D CNN + 时序聚合#

1.1 做法#

最直接的做法把视频当成一叠图像：

ft​=CNN(xt​)∈Rd,z=g(f1​,…,fT​),

其中 g 是时序聚合算子，常见的是平均池化、最大池化，或"分段采样 + 段内平均"（TSN 式）。分类头接在 z 上。g 也可以是一层浅 LSTM 或一维卷积，但只要主干逐帧独立，时序建模的能力上限就由 g 决定。

1.2 为什么它会出现在最前面#

不是因为它最好，而是因为它是唯一能直接复用图像预训练权重的形状：

  • 权重可直接加载：主干是标准 2D CNN / ViT，ImageNet 权重逐层可用，不需要任何改动。
  • 成本与帧数成线性：C∝T（第 1 节表 7），没有二次项。T 帧就是 T 次前向。
  • 数据要求最低：逐帧特征 + 全局标签即可训练，不需要时序标注。

1.3 结构性缺陷：聚合算子是置换不变的#

缺陷可以一行写出。若

g(fπ(1)​,…,fπ(T)​)=g(f1​,…,fT​)∀π∈ST​,

则 g 无法区分原序列与它的任何重排，特别地无法区分时间反演 t↦T+1−t。平均池化与最大池化都满足这条性质。表 1 是数值证据：

聚合方式 原序列输出 时间反演后输出 最大差
平均池化 [0.25, 0.50, 0.75, 1.00] [0.25, 0.50, 0.75, 1.00] 0.000000
最大池化 [1.00, 2.00, 3.00, 4.00] [1.00, 2.00, 3.00, 4.00] 0.000000
一阶时间差分 [-1.00, 0.00, 0.00, 4.00] [1.00, 0.00, 0.00, -4.00] 8.000000

顺序信息有多少 bit：T 帧有 T! 种排列，要区分它们至少需要 log2​(T!) bit。

T=8 的 clip 有 40320 种排列，池化把它们全部映射到同一个向量。这正是"开门 / 关门""推 / 拉""上楼梯 / 下楼梯"在第一代下不可分的信息论原因。

怎么做才不算白做：如果必须用第一代（例如算力只够逐帧前向），唯一有效的补救是把顺序信息压进特征本身——例如拼接相邻帧差分 ft​−ft−1​、或使用"帧序回归"这类辅助任务。注意这些做法都相当于在手工设计 g，而不是让模型学。

1.4 边界#

第一代的适用条件可以写成一句话：任务标签本身对时间顺序不敏感。场景识别（"这是厨房"）、物体出现检测（"画面里有没有刀"）属于这一类；动作识别（"切"vs"搅"）不属于。模糊地带是"动作类别主要由出现过的物体决定"的数据集——在这类数据上第一代仍然很强，这正是它至今没被淘汰的原因。判据：如果打乱一个 clip 的帧序而人类标注者仍给出同一标签，那么第一代的下界就是够的。

二、第二代：3D CNN#

2.1 核的形状变了#

把卷积核从 k×k 扩成 kt​×k×k：

yt,i,j​=τ=0∑kt​−1​a∑​b∑​Wτ,a,b​xt+τ,i+a,j+b​.

为什么这修好了第一代的缺陷：卷积在时间维上是有序的、非对称的算子。kt​≥2 时"A 后接 B"与"B 后接 A"给出不同响应——信息不再被置换群商掉。

2.2 充气（inflation）：3D 权重从哪来#

3D 卷积的最大障碍不是计算，而是没有 ImageNet 那样的 3D 预训练权重。I3D 的解法是把 2D 核沿时间膨胀：

W3d​[:,:,t,:,:]=kt​1​W2d​,t=0,…,kt​−1.

为什么必须除以 kt​：对时间恒定的输入 xt+τ,i+a,j+b​=xi+a,j+b​，3D 输出是

y=τ∑​a,b∑​kt​1​Wa,b​xi+a,j+b​=a,b∑​Wa,b​xi+a,j+b​=y2d​.

也就是说，除以 kt​ 让"看到静止画面"的 3D 核与原来的 2D 核给出同一个响应，从而让 ImageNet 上学到的"边缘/纹理/物体"检测器在时间维上被忠实复制。表 2 的数值验证：

量 值
2D 卷积输出（中心像素） 2.9510929572
膨胀 3D 卷积输出（时间中心） 2.9510929572
逐元素最大绝对误差（除以 kt​） 8.882e-16
不除以 kt​ 时的输出/2D 输出比 3.000000（=kt​）

取舍：膨胀只保证"静止输入下等价"，它不保证时间维上学到了有意义的核——时间核的初值全是 W2d​/kt​，需要靠视频数据把"时间上的差异"学出来。所以 I3D 的贡献不是"不用视频数据"，而是把 3D 训练从"从零开始"变成"从一个好的初值开始"。

2.3 代价：参数、FLOPs 与感受野#

同一空间核下，参数量与单帧 FLOPs 同时乘 kt​（表 2）：

kt​ 参数量比 单帧 FLOPs 比 首层时间下采样 输出时间长度（T=64）
1 1× 1× stride 1 64
3 3× 3× stride 1 / 3 64 / 21
5 5× 5× stride 1 / 5 64 / 12
7 7× 7× stride 1 / 7 64 / 9

这就是 3D CNN 必须靠时间下采样控成本的原因：不下采样，kt​ 越大越贵且时间轴越长（token 越多，二次项越贵）；下采样，时间分辨率就掉。

时间感受野的递推是

R←R+(kt​−1)J,J←J⋅st​(初始 R=1,J=1),

Tout​≈⌊(T−R)/J⌋+1。三种典型栈（表 3）：

B I3D 式，后段下采样 19 8 6 0.6333
C C3D 式，逐段下采样 63 32 1 2.1000

2.4 边界：时间下采样是有损的，而且损失在哪里很具体#

  • A 型保住时间分辨率（Tout​=54），但感受野只有 11 帧 =0.367 s——看不到跨秒的过程（"切菜 → 下锅 → 翻炒"）。
  • C 型感受野 63 帧 =2.100 s，但时间轴只剩 1 步：整段视频被压成一个向量，长时信息必须挤进这一个向量。
  • B 型是折中：Rt​=19 帧 =0.633 s，Tout​=6 步，累计 stride 8。

判据：如果任务的判别信号落在"1 秒以上"的时间跨度上（长动作、多步操作），那么 3D CNN 的栈要么感受野不够、要么时间分辨率被下采样吃光。这不是调参能解决的问题，是形状问题——这正是第三代与第四代出场的理由。

三、第三代：双流#

3.1 为什么把运动单独拿出来#

3D 卷积的核长 kt​ 通常只有 3–7（见 2.3），它能表达的"运动"只是局部时空模式。而"挥手 / 挥手反向""推 / 拉"这类判别信号是全局的位移方向，短核需要很多层才能累积出来。双流的做法是：干脆把运动显式算出来，作为第二路输入。

构造一个可算的动机（表 4）：4 个类别 =（形状，方向），

  • 外观特征只编码形状 ⇒ 同形状的两类共享质心，最近质心分类准确率 0.5000；
  • 运动特征只编码方向 ⇒ 同方向的两类共享质心，0.5000；
  • 拼接两路 ⇒ 四个质心互不相同，1.0000。

这是"构造算例"：真实数据上互补性不是二值的，融合收益取决于两条支路的错误是否相关。写成公式，若两支路错误率 p1​,p2​、错误相关系数 ρ，则融合后的错误率下界不是 max(p1​,p2​) 也不是 p1​p2​，而是落在两者之间，由 ρ 决定。报"双流提升了多少"时必须同时报 ρ，否则数字不可解释。

3.2 融合方式#

方式 在哪里融合 代价 失效场景
早融合（early） 输入层拼 RGB + flow 主干输入通道 5，第一层权重无法复用 ImageNet 两路尺度/统计不一致时训练不稳
晚融合（late） 两支路各出一个分数再平均 每路可独立预训练，最省事 无法建模跨路的细粒度交互
慢融合（slow） 中间若干层做 3D 卷积交互 参数与算力介于两者之间 层数/位置要调

为什么晚融合在实践中常被选：两条支路的输入统计差异极大（RGB 三通道 0–255，光流两通道有正负、动态范围大），早融合会让第一层同时适配两种分布；晚融合让每路各自收敛，再把两个标量分数平均，代价是丢掉跨路交互。

3.3 光流的真实代价#

先破除一个常见误判。粗到细 Lucas–Kanade（层数 L=4、迭代 K=3、窗 7）的每像素代价约为

Cpx​≈L⋅K⋅(8w2+8)=4⋅3⋅(8⋅72+8)=4800 FLOP,

于是 224² 一帧 =0.241 GFLOP、64 帧 =15.414 GFLOP。作为对照，一个构造的 8 层 3×3 主干（见代码）单帧 5.130 GFLOP、64 帧 328.320 GFLOP。变分解算只有主干的 0.0469 倍——解算本身不是瓶颈。

真正贵的是三项（表 4 后半）：

  1. 存储与预计算：fp16 双通道光流是 4 B/像素，224² 一帧 200704 B、64 帧片段 12.250 MiB（RGB uint8 是 9.188 MiB，比值 1.3333）。10 万段素材的光流缓存 =1.168 TiB，而且必须一次性预计算完。
  2. 若用 CNN 估流：每对相邻帧要多跑一个主干级网络，32 帧 clip 有 31 对 ⇒ 约 31 次主干单帧 =159.030 GFLOP/clip，与 RGB 支路同量级。
  3. 串行化：光流必须在训练/推理之前算完；在线推理时它是一个额外的前置网络，端到端延迟被拉长。

3.4 边界：光流是手工中间表示#

三条硬边界：

  • 失效模式明确：遮挡边界、无纹理区域、大位移处光流会错，且错误直接进入运动支路（不像学习到的特征那样可以被后续层纠正）。
  • 信息被固定：光流把"运动"固定成 2 通道位移场。模型无法学到"什么样的运动对这个任务有用"——例如"哪部分区域的运动重要""运动的时间导数是否重要"这些都由光流算法替你决定了。
  • 不可微的闭环（当光流用变分法算时）：光流无法与主干联合优化。

这三条合起来就是第四代的动机：既然"把运动交给手工表示"限制了模型，那就让注意力在时空 token 上自己去发现该看哪里、该跨多远看。

四、第四代：视频 Transformer#

4.1 动机：从固定核到内容寻址#

卷积/池化的共同点是权重与位置绑定：第 l 层第 i 个位置永远看同一个邻域。注意力换成了内容寻址：

Attn(Q,K,V)=softmax(d​QK⊤​)V,

任意两个 token 之间都可以直接建连边，连边强度由内容决定。这修好了 2.4 的形状问题：长时依赖不再需要靠层数堆感受野，一层就能跨越整段视频。代价就是第 1 节算过的 4N2d 与 N2 显存。

4.2 token 化：两个旋钮#

token 数是

N=tT​⋅pH​⋅pW​.

p（空间 patch）与 t（时间 tubelet）在 N 上完全对称，但语义不同（表 7，T=32、224 输入）：

配置 N 相对 per-frame 时间步数 时间维如何被建模
patch 16, tubelet 1 6,272 1.0000 32 无（需外接时序模型）
patch 16, tubelet 2 3,136 0.5000 16 卷积核内隐式
patch 16, tubelet 4 1,568 0.2500 8 卷积核内隐式
patch 8, tubelet 1 25,088 4.0000 32 逐帧 token + 时间注意力
patch 8, tubelet 2 12,544 2.0000 16 卷积核内隐式

怎么读：p:16→8 让 N 变 4 倍，是"看更细的空间"；t:1→4 让 N 降 4 倍，是"把时间压得更狠"。第 1 节的 N∗=6d 只看得见 N，看不见这个区别——所以在做容量规划时，必须先固定语义（要空间细节还是时间细节），再用 N 去算账。

取舍：tubelet 是"用一次线性投影换取 t 倍的时间压缩"。它把 t 帧的 patch 压成一个 token，因此该 token 内的时间顺序只能由那个投影表达（等价于一个时间 stride t 的卷积）。想要 fine-grained 时间建模就不能用大 tubelet。

4Nt2​Ns2​d4d(Nt​Ns2​+Ns​Nt2​)​=Nt​1​+Ns​1​.

Ns​=196 时（表 5）：

  1. Nt​ 越大，1/Nt​ 越小，分解式省得越多（Nt​=64 时省 48.25×）。
  2. 但 1/Ns​ 是地板：Ns​=196 时即使 Nt​→∞，比值也只降到 1/196=0.0051。分解注意力并没有消掉空间二次项，它只是把"时空联合二次"换成"每帧空间二次 + 跨帧时间二次"。

代价：分解注意力假设"空间与时间可以分开建模"。对"同一帧内两个物体相撞"这类必须联合的时空事件，分解式会丢信息。这是一条结构性的取舍，不是调参问题。

4.4 位置编码的时空细节#

注意力本身是置换等变的——没有位置编码，打乱 token 顺序结果不变。视频的 token 有三个索引 (t,i,j)，位置编码的设计有三个层次：

（a）联合 3D 学习表。 参数量 Nt​Ns​：T=64（tubelet 2，Nt​=32）时需要 6272 个向量。它是"最好用"的（模型自由学），但：

  • 在 T=8（Nt​=4、784 个位置）上预训练后用到 T=64，5488/6272=87.5% 的位置没有学到的向量，只能插值或重初始化；
  • 参数量随 T 线性增长，与主干参数量同量级时（小时长、小模型）比例可观。

（b）分解表。 空间表 Ns​ 个 + 时间表 Nt​ 个，共 Nt​+Ns​：T=64 时 228 个，是联合表的 1/27.51；从 T=8 扩到 T=64 只需新增 28 个时间向量。

（c）正弦函数式（3D sincos）。 0 参数、可外推，且有一个可验证的好性质：点积只依赖位移。

PE(t)⋅PE(t+Δ)=i∑​cos(Δωi​),ωi​=10000−2i/dt​.

数值核对（dt​=256）：Δ=1,2,4,8 时解析值与数值点积一致，对 t 的最大偏离 1.4×10−14。

时间子块的维度预算是本节最容易被忽略的细节。dt​ 维的正弦码提供 dt​/2 个频率，而频率太少会发生远距碰撞（表 6 末段）：

dt=8 时最短码距 0.645292 出现在 Δ=63 上，比相邻位置的 0.964100 还小：相距 63 帧的两个位置比相邻帧更难区分，位置编码自己把时间轴折叠了。dt≥16 时最短码距恰好落在 Δ=1，局部单调、0..255 内无碰撞。判据：时间维预算不要低于 16 维（8 个频率）；768 维按三轴均分给时间 256 维，余量充足。

4.5 边界#

  • 数据饥渴：注意力没有卷积的局部性/平移等变先验，同样容量需要更多数据或更强预训练。这直接导致第 4 节的自监督成为必需，而不是可选。
  • 二次项：4N2d 与 N2 显存在长视频上不可接受（第 1 节表 2、第 3 节会给反解）。
  • 位置编码外推：上一条已量化——联合学习表在 T 上不可外推，分解表可外推时间维，正弦式可完全外推。
  • 与 3D CNN 的关系不是取代：卷积的局部性先验在小数据、高分辨率、需要精细定位的任务上仍然高效；很多现代结构是"卷积干 + 注意力"的混合，而不是纯注意力。

import math
import unicodedata


def dwidth(s: str) -> int:
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1
               for ch in s)


def pad(s: str, w: int, align: str = ">") -> str:
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2
    return " " * left + s + " " * (gap - left)


def row(cells, widths, aligns=None) -> str:
    aligns = aligns or [">"] * len(cells)
    return " | ".join(pad(c, w, a) for c, w, a in zip(cells, widths, aligns))

def conv2d(x, w):
    H, W = len(x), len(x[0])
    out = [[0.0] * (W - 2) for _ in range(H - 2)]

            for a in range(3):
                for b in range(3):
                    s += x[i + a][j + b] * w[a][b]

    return out


def conv3d(x, w):
    kt = len(w)
    T, H, W = len(x), len(x[0]), len(x[0][0])

                        for b in range(3):
                            s += x[tau + t][i + a][j + b] * w[t][a][b]
                out[tau][i][j] = s
    return out

def stack(name, layers, T=64, fps=30):

    for kt, st in layers:
        R += (kt - 1) * J
        J *= st
    Tout = max(0, (T - R) // J + 1)
    return name, R, J, Tout, R / fps

def centroid_acc(extract):
    cents = [list(extract(c)) for c in CLASSES]
    correct = 0
    for ci, c in enumerate(CLASSES):
        x = list(extract(c))
        best, bd = -1, None
        for cj, cen in enumerate(cents):
            dd = sum((x[k] - cen[k]) ** 2 for k in range(len(x)))
            if bd is None or dd < bd - 1e-12:
                best, bd = cj, dd
        if best == ci:
            correct += 1
    return correct / len(CLASSES)

解算代价（粗到细 Lucas-Kanade，构造参数）：
  每像素每帧 ≈ L*K*(8*w^2+8) = 4*3*(8*7^2+8) = 4,800 FLOP
  224x224 一帧 = 0.241 GFLOP；64 帧片段 = 15.414 GFLOP
  作为对照，一个构造的 2D 主干（下表）单帧前向是：

  变分解算/主干 = 0.0469 倍 —— 解算本身**不是**瓶颈。

真正贵的是另外三项：
  1) 存储：1e5 段 64 帧素材的光流缓存 = 1.168 TiB（fp16），且必须一次性预计算。
  2) 若用 CNN 估光流（而非变分/LK），每对相邻帧要多跑一个主干级网络：
     32 帧 clip 有 31 对相邻帧 -> 约 31x 主干单帧 FLOPs = 159.030 GFLOP/clip，与 RGB 支路同量级。
  3) 串行化：光流必须在训练/推理之前算完，端到端延迟被拉长；
     在线推理时它是一个额外的前置网络。

三条边界：
  1) 光流在遮挡边界、无纹理区域、大位移处失效；错误会直接进入运动支路。
  2) 光流是**外部依赖**：推理时必须先跑一遍光流网络/算法，端到端延迟被拉长。
  3) 光流是**手工中间表示**：它把「运动」固定成 2 通道位移场，
     模型无法学到「什么样的运动对该任务有用」。这是第 3 节要接上的问题。

表 5  联合时空注意力 vs 分解式时空注意力
========================================================================================================
联合注意力：N = Nt * Ns，两个矩阵乘各 2*N^2*d -> 4*N^2*d
分解注意力：先空间（每帧内）Nt * 4*Ns^2*d，再时间（每个空间位置）Ns * 4*Nt^2*d

8        |    1,568 |        7.553 G |          0.983 G |         0.1301 |          7.69x

Nt= 32, Ns=196: 比值 = 1/32 + 1/196 = 0.0364；联合 120.846 GFLOP -> 分解 4.393 GFLOP

两条读法：
  1) Nt 越大，1/Nt 越小，分解式省得越多（Nt=64 时 0.0207，省 48.25x）。
  2) 但 1/Ns 这一项是地板：Ns=196 时即使 Nt 无穷大，比值也只降到 1/196。
     换句话说，分解注意力的**空间部分仍然按 Ns^2 增长**——
     它把长视频的二次项从「时空联合」降成「每帧空间二次 + 跨帧时间二次」。

代价：分解注意力假设「空间与时间可以分开建模」。
对「同一帧内两个物体相撞」这类必须联合的时空事件，分解式会丢信息。

表 7  token 化：tubelet 与 per-frame patch 的等价关系
========================================================================================================
per-frame patch：每帧 (H/p)*(W/p) 个 token，T 帧共 T*Ns 个；
tubelet t x p x p：每 t 帧 (H/p)*(W/p) 个 token，共 (T/t)*Ns 个。
故 tubelet 的 t 等价于「时间 stride t + 一个学出来的时间投影」。

读法：把 p 从 16 降到 8，token 数放大 4 倍；把 t 从 1 提到 4，token 数降 4 倍。
两者在 N 上完全等价，但语义完全不同：p 变小是「看更细的空间」，
t 变大是「把时间压得更狠」。第 1 节的 $N^*=6d$ 只看得见 N，看不见这个区别。

这也是「视频 Transformer」与「逐帧 ViT + 时间注意力」的等价与差别：
  tubelet 2x16 的 N = 3,136；
  逐帧 patch 16（32 帧）N = 6,272，若再对每帧做一次空间注意力，
  空间部分 FLOPs 正比于 32*196^2，而 tubelet 版是 16*196^2 —— 正好 2 倍。

小结#

  • 第一代（2D CNN + 池化）的缺陷是代数的：平均/最大池化置换不变，时间反演下输出完全相同（最大差 0.000000），一阶时间差分给出符号相反的输出（8.000000）。T=8 时 40320 种排列被商成一个向量，顺序信息上界 log2​(T!)=15.299 bit（T=64 时 295.995 bit）（表 1）。
  • 第二代的代数基础是膨胀：W3d​[:,:,t,:,:]=W2d​/kt​，静止输入下与 2D 响应相等（最大误差 8.882×10−16），不除 kt​ 则放大 3.000000 倍；参数量与 FLOPs ×kt​（表 2）。
  • 第二代受限于感受野与时间分辨率的交换：感受野 R←R+(kt​−1)J。A 型 Rt​=11 帧（0.367 s，Tout​=54）、B 型 19 帧（0.633 s，6 步）、C 型 63 帧（2.100 s，1 步）（表 3）。"3D 卷积能建模时序"的真实含义是 0.4–0.6 秒的局部运动。
  • 第三代的动机是互补性：构造四类问题上，外观 0.5000、运动 0.5000、融合 1.0000（表 4）。报告融合收益必须同时报两支路错误的相关性 ρ。
  • 第三代最贵的不是解算而是存储与串行化：变分 LK 约 4800 FLOP/像素 =0.241 GFLOP/帧，是构造主干（5.130 GFLOP/帧）的 0.0469 倍；但 fp16 光流 12.250 MiB/64 帧、10 万段 1.168 TiB；CNN 估流则要 31 次主干级前向 =159.030 GFLOP/clip（表 4）。
  • 光流是手工中间表示：失效区（遮挡/无纹理/大位移）明确，且模型无法学"什么样的运动有用"——这是第四代的动机。
  • token 化的两个旋钮在 N 上对称、语义上不对称：p:16→8 与 t:1→4 都改 4 倍；T=32 时 6272/3136/1568 分别对应 tubelet 1/2/4（p=16）（表 7）。
  • 时空注意力比值的闭式 1/Nt​+1/Ns​：Nt​=8 省 7.69×、Nt​=32 省 27.51×、Nt​=64 省 48.25×；但 1/Ns​ 是地板，空间二次项没被消掉（表 5）。
  • 位置编码三层方案：联合表 Nt​Ns​（T=64 时 6272 个，从 T=8 外推时 87.5% 缺失）、分解表 Nt​+Ns​（228 个，27.51× 更少）、正弦式 0 参数且点积只依赖位移（偏离 1.4×10−14）（表 6）。
  • 时间维位置编码的维度不能太小：dt=8（4 个频率）时最短码距 0.645292 出现在 Δ=63，比相邻码距 0.964100 还小——位置编码自身折叠了时间轴；dt≥16 时最短码距落在 Δ=1（表 6）。
  • 四代不是替代关系：卷积的局部性先验在小数据、高分辨率、精细定位上仍高效；现代结构多为混合。每一代的"代价"列都是结构性的，不可用工程手段消掉。
