Relay / MLIR / StableHLO：三种路线的取舍#

同一段 relu → softmax，Relay、MLIR、StableHLO 都能写出来。表面差别在语法，真正的差别落在三份契约上：类型系统要求写多细、算子集合是否封闭、跨版本是否承诺兼容。选错路线的代价不会在"能不能表示"上暴露，而是在"换个后端要重写多少"和"半年后升级框架还能不能读"上暴露。本课把三种写法塞进同一个验证器，把取舍做成可执行的对比。

一、概念讲解#

1. Relay：为图优化设计的高层 IR#

Relay 是 TVM 的高层图 IR（MAPL'18 论文题目就叫 Relay: A New IR for Machine Learning Frameworks）：函数式、静态类型、支持 let-binding 与代数数据类型（ADT），能表达控制流与复合结构。它的职责很明确：承接前端图、做图级优化（常量折叠、死代码消除、算子融合）与算子分解，把高层算子拆成可调度的原语；再交给 TensorIR 做分块、绑定线程与代码生成。TVM 的 OSDI'18 论文把这条分层讲成"图级 + 算子级两层优化"，配一个学习型代价模型自动搜索低层实现。取舍很清楚：算子集由 TVM 本体定义，扩展要改编译器；好处是分解出的原语一定是后端能调的。

2. MLIR：不是一门 IR，而是造 IR 的框架#

MLIR 里的一等抽象是 operation：它自带名字、操作数、结果、属性，还能挂 region（region 里有 block，block 里有 operation），于是同一套基础设施可以描述从高层张量到循环、到硬件指令的所有层级。命名空间由 dialect 提供，一个 dialect 里的 op 名形如 myml.relu；渐进 lowering 就是指"这一层先降到下一层，剩下的留着"。它的 pass 契约同样硬：一个 pass 只锚定到某个 operation，不得读兄弟 operation、不得改它之外的状态、不得跨调用保存可变数据——为了让 pass 能并行跑在成千上万个函数上。代价是：MLIR 自己不承诺长期兼容（其文档有专门的 Deprecations & Current Refactoring 页），每个 dialect 各自演进；你能扩，但也得自己负责稳定。

3. StableHLO：用封闭算子集换可移植性#

StableHLO 的定位写在规范第一句里：它是 ML 框架与 ML 编译器之间的可移植层（portability layer）——产出 StableHLO 的框架与消费它的编译器（规范点名 XLA、IREE）互不需要知道对方内部结构。做法是三条硬规矩：算子集封闭（不可能随便加 op）、高层算子必须留下可分解定义（composite 带一个 decomposition 字段），必要时才用 custom_call 逃逸；换来的则是：类型里可以写动态维（tensor<?x3xf32>）与量化类型，以及一份带版本日志的规范与"向后兼容"的自我定位。

这里有个容易被忽略的事实：StableHLO 的算子集里根本没有 relu 和 softmax——relu 要写成 maximum(x, 0)，softmax 只能登记成 stablehlo.composite（带 decomposition 字段，语义上可被分解替换）或者直接写分解。代码第 2 段把这条规矩算成数字：一个 composite softmax 展开成 7 条封闭算子（reduce 求 max → broadcast_in_dim → subtract → exponential → reduce 求和 → broadcast_in_dim → divide），与原 composite 的逐元素差是 0.00e+00；而另一个"省掉 max 平移"的分解同样全在算子集内，输入整体加 100 后直接给出 nan。结论很直接：封闭算子集不限制表达能力，但每个高层算子都必须留下数值等价的分解定义。

4. 三条路线怎么选#

维度 Relay MLIR StableHLO
扩展方式 加算子要改 TVM 本体 新 dialect 即可，命名空间隔离 不允许加算子（走 composite / custom_call）
兼容承诺 随 TVM 版本演进 项目明确不承诺稳定，dialect 自管 封闭算子集 + 版本日志，主打向后兼容
动态 shape 支持符号维 由各 dialect 自己定义 ? 直接写进类型
layout 在哪 后端 pass 决定 memref 的 affine map 表达 不进类型
典型消费者 TVM 自己的调度与 codegen IREE、各厂商后端、Triton 生态 XLA、JAX / TF / PyTorch 的导出路径

判据可以浓缩成一句：要"我能加东西"就选 MLIR；要"别人能稳定读我的东西"就选 StableHLO；要"图优化和调度一把抓"就用 Relay 这类自带后端的图 IR。三者在真实系统里常常串联：框架导出 StableHLO → 编译器内部用 MLIR 多级 dialect 做 lowering → 算子级交给 TVM/Triton 风格的调度与代码生成。

5. 常见坑#

  • 把 StableHLO 当"又一个方言"：它有序列化格式与兼容性测试的约束，随便改语义会砸掉整条生态链。
  • 加 dialect 却不写 verifier：非法 IR 一路漂到后端才报错。
  • 以为"能表示"等于"能优化"：自定义 op 没有 lowering 就会卡住；Relay 的算子在 LegalizeOps 之后才有可调度形态。
  • 只在"语法"层面比较三种 IR：契约（类型、算子集、兼容承诺）才是迁移成本所在。

二、可运行代码示例#

纯 Python + numpy，本机 python3.10 + numpy 1.26.2 实跑：一个 MLIR 风格通用算子形式的解析器、三个"方言注册表"、一个最小验证器（SSA 顺序 + 算子集/方言注册 + 显式类型），再加一个 numpy 解释器做数值对拍。

# ---- Relay / MLIR / StableHLO 三条路线：同一段程序过三个"方言注册表"（numpy + 纯 Python 实跑）----
import re
import numpy as np


# ---------- 0. 一段 IR 文本的通用解析：只认 MLIR 风格的通用算子形式 ----------
def split_types(s):
    """按顶层逗号切分类型列表，<> 内部的逗号不算分隔符。"""
    out, depth, cur = [], 0, ''
    for ch in s:
        if ch == '<':
            depth += 1
        elif ch == '>':
            depth -= 1
        if ch == ',' and depth == 0:
            out.append(cur.strip()); cur = ''
        else:
            cur += ch
    return [x for x in [cur.strip()] + out if x]


def parse_type(t):
    """tensor<2x3xf32> → ('tensor', (2, 3), 'f32')；动态维写 ? → None。"""
    m = re.fullmatch(r'tensor<([0-9x?]+)x(\w+)>', t.strip())
    if not m:
        raise ValueError(f'看不懂的类型 {t!r}')
    dims = tuple(None if d == '?' else int(d) for d in m.group(1).split('x'))
    return ('tensor', dims, m.group(2))


OP_RE = re.compile(r'^(?:(\%\w+)\s*=\s*)?"([\w.]+)"\(([^)]*)\)'
                   r'(?:\s*\{([^}]*)\})?\s*:\s*\(([^)]*)\)\s*->\s*\(([^)]*)\)$')


def parse_ops(text):
    ops = []
    for raw in text.strip().splitlines():
        line = raw.strip()
        if not line or line.startswith('//'):
            continue
        m = OP_RE.match(line)
        if not m:
            raise ValueError(f'解析失败：{line}')
        res, name, operand_s, attr_s, in_t, out_t = m.groups()
        attrs = {}
        for kv in [a.strip() for a in (attr_s or '').split(',') if a.strip()]:
            k, v = kv.split('=', 1)
            attrs[k.strip()] = v.strip()
        ops.append({'result': res, 'op': name,
                    'operands': [o.strip() for o in operand_s.split(',') if o.strip()],
                    'attrs': attrs,
                    'in_types': [parse_type(t) for t in split_types(in_t)],
                    'out_types': [parse_type(t) for t in split_types(out_t)]})
    return ops


# ---------- 1. 三条路线的差异落在三处：类型契约 / 算子集合 / 兼容承诺 ----------
REGISTRY = {
    'relay': dict(
        label='relay（TVM 高层图 IR）', types_required=True,
        opset={'relay.nn.relu', 'relay.nn.softmax', 'relay.add', 'relay.multiply',
               'relay.nn.dense'},
        registered_dialects=set(), custom_ops=False,
        promise='算子集由 TVM 本体维护，随版本演进'),
    'mlir': dict(
        label='mlir（多级可扩展 dialect）', types_required=True,
        opset={'myml.relu', 'myml.softmax', 'myml.matmul'},
        registered_dialects={'myml'}, custom_ops=True,
        promise='不承诺跨版本稳定，dialect 各自演进'),
    'stablehlo': dict(
        label='stablehlo（可移植算子集）', types_required=True,
        opset={'stablehlo.constant', 'stablehlo.maximum', 'stablehlo.composite',
               'stablehlo.add', 'stablehlo.reduce', 'stablehlo.subtract',
               'stablehlo.exponential', 'stablehlo.divide',
               'stablehlo.broadcast_in_dim'},
        registered_dialects=set(), custom_ops=False,
        promise='封闭算子集 + 版本日志，主打向后兼容'),
}

# 同一条计算意图：relu → softmax，三种写法（注意 stablehlo 里没有 relu/softmax 这两个算子）
PROGRAMS = {
    'relay': '''
%0 = "relay.nn.relu"(%arg0) : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
%1 = "relay.nn.softmax"(%0) {axis = 1 : i64} : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
''',
    'mlir': '''
%0 = "myml.relu"(%arg0) : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
%1 = "myml.softmax"(%0) {axis = 1 : i64} : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
''',
    'stablehlo': '''
%c = "stablehlo.constant"() {value = 0.0} : () -> (tensor<2x3xf32>)
%0 = "stablehlo.maximum"(%arg0, %c) : (tensor<2x3xf32>, tensor<2x3xf32>) -> (tensor<2x3xf32>)
%1 = "stablehlo.composite"(%0) {name = mynamespace.softmax} : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
''',
    # 一个想融进 attention 的自定义 op：三条路线的命运不同
    'custom': '''
%0 = "myml.fused_attention"(%arg0) : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
''',
}


def verify(ops, dialect, defined=('%arg0',)):
    """最小验证器：SSA 定义先于使用 + 算子集合/方言注册 + 显式类型检查。"""
    cfg = REGISTRY[dialect]
    diags, known = [], set(defined)
    for o in ops:
        for operand in o['operands']:
            if operand not in known:
                diags.append(f"{o['op']}: 使用了未定义的值 {operand}（SSA 顺序违规）")
        if o['op'] not in cfg['opset']:
            prefix = o['op'].split('.')[0]
            if cfg['custom_ops'] and prefix in cfg['registered_dialects']:
                pass                       # 自定义 dialect 已注册 → 合法
            else:
                diags.append(f"{o['op']}: 方言 {prefix} 未注册、不在算子集内")
        if cfg['types_required'] and not o['out_types']:
            diags.append(f"{o['op']}: 缺少显式结果类型")
        if o['result']:
            known.add(o['result'])
    return diags


print('=== 1. 同一段程序过三个方言注册表 ===')
for dialect in ('relay', 'mlir', 'stablehlo'):
    cfg = REGISTRY[dialect]
    print(f"  --- {cfg['label']} ---")
    for tag in ('relay', 'mlir', 'stablehlo', 'custom'):
        ops = parse_ops(PROGRAMS[tag])
        diags = verify(ops, dialect)
        verdict = '通过' if not diags else '拒绝：' + '；'.join(diags)
        print(f'    {tag + " 程序":<14} {verdict}')
    print(f"    （兼容承诺：{cfg['promise']}）")
print(f"  stablehlo 注册表里有 relu / softmax 这种高层算子吗？ "
      f"{'stablehlo.relu' in REGISTRY['stablehlo']['opset'] or 'stablehlo.softmax' in REGISTRY['stablehlo']['opset']}"
      "（规范里确实没有：relu 要写成 maximum(x, 0)，softmax 只能靠 composite 或直接写分解）")

# ---------- 2. StableHLO 的"封闭算子集"怎么容纳 softmax：composite 必须可分解 ----------
SOFTMAX_DECOMP = '''
%1 = "stablehlo.reduce"(%arg0) {kind = max, axis = 1} : (tensor<2x3xf32>) -> (tensor<2xf32>)
%2 = "stablehlo.broadcast_in_dim"(%1) {shape = 2x3} : (tensor<2xf32>) -> (tensor<2x3xf32>)
%3 = "stablehlo.subtract"(%arg0, %2) : (tensor<2x3xf32>, tensor<2x3xf32>) -> (tensor<2x3xf32>)
%4 = "stablehlo.exponential"(%3) : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
%5 = "stablehlo.reduce"(%4) {kind = sum, axis = 1} : (tensor<2x3xf32>) -> (tensor<2xf32>)
%6 = "stablehlo.broadcast_in_dim"(%5) {shape = 2x3} : (tensor<2xf32>) -> (tensor<2x3xf32>)
%7 = "stablehlo.divide"(%4, %6) : (tensor<2x3xf32>, tensor<2x3xf32>) -> (tensor<2x3xf32>)
'''

print('\n=== 2. 一个 composite softmax 展开成 7 条封闭算子（数值对拍）===')
decomp = parse_ops(SOFTMAX_DECOMP)
diags = verify(decomp, 'stablehlo')
print(f'  分解后 {len(decomp)} 条算子，全部在算子集内：{"是" if not diags else diags}')


def numpy_exec(ops, feeds):
    env = dict(feeds)
    for o in ops:
        a = [env[i] for i in o['operands']]
        attrs = o['attrs']
        if o['op'].endswith('composite'):                       # composite 语义 = 它的分解
            m = a[0].max(axis=1, keepdims=True)
            e = np.exp(a[0] - m)
            v = e / e.sum(axis=1, keepdims=True)
        elif o['op'].endswith('constant'):
            v = np.full(o['out_types'][0][1], np.float32(attrs['value']))
        elif o['op'].endswith('maximum'):
            v = np.maximum(a[0], a[1])
        elif o['op'].endswith('subtract'):
            v = a[0] - a[1]
        elif o['op'].endswith('exponential'):
            v = np.exp(a[0])
        elif o['op'].endswith('divide'):
            v = a[0] / a[1]
        elif o['op'].endswith('reduce'):
            axis = int(attrs['axis'].split(':')[0])
            v = a[0].max(axis=axis) if attrs['kind'] == 'max' else a[0].sum(axis=axis)
        elif o['op'].endswith('broadcast_in_dim'):
            v = np.broadcast_to(a[0][:, None], tuple(int(d) for d in attrs['shape'].split('x')))
        else:
            raise ValueError(f"解释器不认 {o['op']}")
        env[o['result']] = v
    return env


rng = np.random.default_rng(0)
x = rng.standard_normal((2, 3)).astype(np.float32) * 3.0
relu = np.maximum(x, np.float32(0))
composite = parse_ops(PROGRAMS['stablehlo'])
y_comp = numpy_exec(composite, {'%arg0': x})['%1']
y_decomp = numpy_exec(decomp, {'%arg0': relu})['%7']
print(f'  composite 版 shape={y_comp.shape} sum={y_comp.sum(axis=1)}')
print(f'  分解版     shape={y_decomp.shape} sum={y_decomp.sum(axis=1)}')
print(f'  两版最大绝对差 = {np.abs(y_comp - y_decomp).max():.2e}（同一套数值稳定写法 → 逐位相同）')

# 反例：不加 max 平移的"分解"，量级一大就溢出 —— 分解必须与 composite 数值等价
NAIVE_DECOMP = '''
%1 = "stablehlo.exponential"(%arg0) : (tensor<2x3xf32>) -> (tensor<2x3xf32>)
%2 = "stablehlo.reduce"(%1) {kind = sum, axis = 1} : (tensor<2x3xf32>) -> (tensor<2xf32>)
%3 = "stablehlo.broadcast_in_dim"(%2) {shape = 2x3} : (tensor<2xf32>) -> (tensor<2x3xf32>)
%4 = "stablehlo.divide"(%1, %3) : (tensor<2x3xf32>, tensor<2x3xf32>) -> (tensor<2x3xf32>)
'''
naive = parse_ops(NAIVE_DECOMP)
print(f'  同一算子集内换个分解（省掉 max 平移）：仍在算子集内 = {not verify(naive, "stablehlo")}')
relu_big = np.maximum((x + np.float32(100)).astype(np.float32), np.float32(0))   # 量级抬到 ~100
y_stable = numpy_exec(decomp, {'%arg0': relu_big})['%7']
with np.errstate(over='ignore', invalid='ignore'):   # 故意制造溢出：关掉 numpy 警告，下面显式统计
    y_naive = numpy_exec(naive, {'%arg0': relu_big})['%4']
print(f'  输入整体 +100 后：稳定版 sum={y_stable.sum(axis=1)}，朴素版 sum={y_naive.sum(axis=1)}')
print(f'  朴素版里 inf 个数 = {int(np.isinf(y_naive).sum())}，nan 个数 = {int(np.isnan(y_naive).sum())}'
      '（exp(100) 约 2.7e43，超出 float32 上界 3.4e38）')
print('  结论：封闭算子集不牺牲表达能力，但每个高层算子必须留下"数值等价"的分解定义')

  结论：封闭算子集不牺牲表达能力，但每个高层算子必须留下"数值等价"的分解定义

=== 3. 类型里到底能写什么（三方言的类型层）===
  shape   | relay: tensor<2x3xf32> 写死 | mlir: tensor<2x3xf32> 写死 | stablehlo: tensor<?x3xf32> 支持动态维
  dtype   | relay: float32/float16/int8 | mlir: 任意 dialect 类型 | stablehlo: 含 f8/bf16/tf32/量化类型
  layout  | relay: 由后端 pass 决定 | mlir: memref 用 affine map 表达 | stablehlo: 不进类型（spec 列为未来工作）
  控制流     | relay: 函数式 + ADT | mlir: region/block 任意嵌套 | stablehlo: 无跳转算子，用 while/if 表达
  自定义 op  | relay: 有限，需改编译器 | mlir: 一等公民（dialect 隔离） | stablehlo: 不允许，必须走 composite
  取舍一句话：可扩展性（MLIR）↔ 生态稳定性（StableHLO）↔ 图优化友好度（Relay）

三、练习#

  1. 实现：给 verify 加一条类型一致性规则——每个算子的操作数类型必须与声明签名一致（提示：stablehlo.add 的两个操作数形状要么相同、要么符合广播规则）。用一段故意写错的 IR 验证你的检查能报出位置。
  2. 解释：为什么 StableHLO 允许 ? 动态维、却把 layout 排除在类型之外？把这两件事和"谁在什么时候知道这些信息"联系起来回答。
  3. 对比/验证：把 PROGRAMS['mlir'] 里的 myml.softmax 换成 myml.custom_fused_softmax，并把它注册进 mlir 注册表——三条路线里谁还能通过验证？由此说明"方言注册"与"算子集封闭"两种扩展代价的差别。
