评价指标（召回/精确/NDCG）#

推荐系统输出的是一个排序列表，而不是一个分类标签。这决定了它的评估和上一门课学的"准确率/精确率"很不一样：用户只关心列表最前面那几条对不对，几乎没人翻到第 500 位。于是推荐领域衍生出一套"截断（@K）"指标——Precision@K、Recall@K、NDCG@K——它们的共同点是在前 K 个位置上算账。这一课把这三个指标的定义、关系、以及 NDCG 里的"折扣"逻辑彻底讲清。

一、概念讲解#

1. 离线评估的基本框架#

在没上线、没有真实用户反馈时，我们用留出法评估：把历史交互按用户切成训练集和测试集，用训练集训练、让模型给每个用户生成一个"候选推荐列表"，再拿测试集里"用户真正交互过的物品"当金标准（ground truth）去核对。

注意一个关键区别：

  • 显式反馈场景（有评分）：常用 RMSE/MAE 衡量"预测评分准不准"；
  • 隐式反馈场景（只有交互与否）：用 Top-K 指标衡量"推荐列表里命中了几个"。

现实以隐式反馈为主，所以 Top-K 指标（召回/精确/命中率/NDCG）是推荐评估的主角。

2. Precision@K 与 Recall@K#

设对用户 u，模型给出的推荐列表为 ranked_u，测试集里 u 真正交互过的物品集合为 relevant_u。只看前 K 个位置：

Precision@K = |ranked_u[:K] ∩ relevant_u| / K
Recall@K    = |ranked_u[:K] ∩ relevant_u| / |relevant_u|
  • Precision@K（精确率）：推荐的 K 条里，有多少是用户真喜欢的。分母是 K，衡量"准不准"。
  • Recall@K（召回率）：用户真正喜欢的物品里，被推荐命中了多少。分母是用户喜欢物品的总数，衡量"全不全"。

两者是一对天生的矛盾：K 变大，Recall 只增不减（能命中的只会更多），但 Precision 通常下降（列表变长，稀释了命中比例）。最终对一个用户群体，通常对每个用户分别算指标再取平均（mean_avg），得到整个模型的 Precision@K 与 Recall@K。

3. 命中率、覆盖率与新颖度（简述）#

  • Hit Rate@K：ranked_u[:K] 里是否至少命中一个真实交互（0/1，再对用户取平均）。比 Precision 更宽松。
  • 覆盖率（Coverage）：所有用户推荐列表的并集占全部物品的比例。衡量长尾——覆盖率越高，冷门物品越有机会露面。
  • 新颖度/惊喜度（Novelty/Serendipity）：衡量推荐是否"意外但合理"，通常用物品的平均流行度倒数等代理量。难以精确度量，常做辅助。

4. NDCG@K：把"位置"也纳入打分#

Precision/Recall 只看"命中没命中"，却不管"命中的那个排在第 1 还是第 100"。但位置极其重要——排第一和排第一百，用户体验天差地别。NDCG（Normalized Discounted Cumulative Gain，归一化折损累积增益） 就是为此设计的，它由三部分组成：

第一步：增益（Gain）。 每个位置赋予一个相关度得分 rel_p（隐式反馈里常简化为：命中=1，未命中=0；显式场景可用真实评分）。

第二步：折损累积（DCG）。 位置越靠后，增益越要"打折"。标准做法是对数折扣：

DCG@K = Σ_{p=1}^{K} rel_p / log₂(p + 1)

p=1 时折扣为 1（不折损），p 越大 log₂(p+1) 越大、折得越狠。

第三步：归一化（N）。 DCG 的绝对大小依赖"相关物品有几个、排得多前"，不同用户之间没法比。于是除以一个理想 DCG（IDCG）——即"相关物品全部排在最前"这个完美排序的 DCG：

NDCG@K = DCG@K / IDCG@K

归一化后 NDCG ∈ [0, 1]，1 表示"排序完美"。这就是 NDCG 里 "N（Normalized）" 的来历。

二、可运行代码示例#

用 NumPy 从零实现 Precision@K、Recall@K、NDCG@K，在一个人工排序列表上跑一遍，体会三者差异。

import numpy as np

def precision_at_k(ranked, relevant, k):
    """前 k 个推荐里命中相关物品的比例。"""
    hits = len(set(ranked[:k]) & set(relevant))
    return hits / k

def recall_at_k(ranked, relevant, k):
    """相关物品被前 k 个推荐命中的比例。"""
    hits = len(set(ranked[:k]) & set(relevant))
    return hits / len(relevant) if relevant else 0.0

def ndcg_at_k(ranked, relevant, k):
    """归一化折损累积增益：位置越靠前权重越高。"""
    dcg = 0.0
    for p, item in enumerate(ranked[:k], start=1):
        rel = 1.0 if item in relevant else 0.0   # 隐式反馈：命中=1，否则=0
        dcg += rel / np.log2(p + 1)              # 对数折扣
    # 理想排序：相关物品全部排在最前，其余位置填 0
    ideal = ([1.0] * len(relevant) + [0.0] * max(k - len(relevant), 0))[:k]
    idcg = sum(r / np.log2(p + 1) for p, r in enumerate(ideal, start=1))
    return dcg / idcg if idcg > 0 else 0.0

# 模型给出的推荐排序（物品编号），以及用户真正喜欢的物品集合
ranked   = [3, 1, 5, 2, 4]
relevant = {1, 3, 5}

print("推荐列表：", ranked, " 真正喜欢：", relevant)
for k in [1, 3, 5]:
    print(f"k={k}: Precision={precision_at_k(ranked, relevant, k):.3f}, "
          f"Recall={recall_at_k(ranked, relevant, k):.3f}, "
          f"NDCG={ndcg_at_k(ranked, relevant, k):.3f}")

观察要点：k 增大时 Recall 单调上升（命中只会变多），而 Precision 可能下降；NDCG 则把"命中的物品是否靠前"也计入了——如果把 ranked 里的 1 和 3 调换位置，Precision/Recall 完全不变，但 NDCG 会下降，这正是它比前两者更"挑剔"的地方。

为什么这样做？——理论推导#

为什么折扣要取 log₂(p+1)，而不是 1/p 或线性#

NDCG 里最"神秘"的一步是那个 1 / log₂(p+1) 折扣。它为什么不是 1/p 或别的？答案来自位置价值的经验分布：用户点击率随排名下降的速度，大致服从一条对数曲线而非线性曲线——排名第 2 的位置和排名第 10 的位置，点击率差距远没有"10 倍"那么大，而是更接近对数尺度上的缓慢衰减。取 log 折扣的直觉是：价值的边际损失随位置递增而递减，前几名每前进一名都极其值钱，而到第 50 名之后，再往后挪一位已经无所谓了。log₂(p+1)（而不是 log p）是为了让 p=1 时分母为 1、折扣为 0，保证"第一名不折损"这个自然约定。

为什么必须归一化（除以 IDCG）#

DCG 有一个致命缺陷：它和"相关物品的个数"强相关。一个用户喜欢 10 个物品，随便排都能拿到高 DCG；另一个用户只喜欢 1 个，即便排到第 1 名 DCG 也低。直接把两个用户的 DCG 相加做平均，等于偷偷给"喜好更多物品"的用户更高权重，这会扭曲结论。除以 IDCG（每个用户自己的"完美排序能达到的上限"）后，NDCG 变成了相对满分的比例，才真正跨用户可比、可平均。这个"除以理论最优"的思路，是很多归一化指标的共同母题。

母原理连接： 从"精确率/召回率"到"NDCG"，指标的演化史就是一场"越来越贴近真实业务"的抽象史——先把分类问题改造为排序问题（@K 截断），再把位置价值编码进去（折扣），最后除以理论最优做归一化。理解每一步的动机，比背公式重要得多。
