序列 / 上下文并行：长文本训练的分割方式#

前面四种并行都没切开序列维：DP 切样本（每个样本仍是完整长序列），TP 切 hidden，PP 切层，EP 切专家。长文本于是撞上两堵墙：激活内存随序列长线性涨、注意力计算随长度平方涨。序列并行（SP）与上下文并行（CP）专门处理这一维。本课讲清三种切法——SP 切逐 token 算子、Ulysses 用 all-to-all 换头、Ring Attention 环传 KV——以及因果掩码的负载不均。

一、概念讲解#

1. 为什么长序列要单独一个并行维#

量 随序列长 s 的量级 谁最受影响
逐 token 激活（LayerNorm/Dropout 的输出） O(s) 显存
注意力分数矩阵 QK⊤ O(s2)（分块后可 O(s⋅block)） 显存 + 计算
K/V 激活 O(s) 显存 + CP 的通信量

这些量都与 s 绑定，前四种并行一项都降不下来。长序列必须新增一维：把 s 个位置切给多个设备。层次有二：只切逐 token 独立算子（SP，省显存），或连注意力一起切（CP）。

2. 序列并行 SP：切逐 token 算子，靠 g/gˉ​ 与 TP 对接#

LayerNorm 与 Dropout 都是逐 token 独立的：第 i 个 token 的输出只依赖第 i 个输入，所以沿序列切开后各 rank 就地计算与单卡完全一致（示例 1 已用 numpy 验证）。

难点在交界处：TP 区（GEMM）要完整序列，SP 区只有 1/P。Megatron-LM 引入一对共轭算子：

算子 前向 反向 作用
g all-gather reduce-scatter 进 TP 区：把序列拼回来
gˉ​ reduce-scatter all-gather 出 TP 区：把梯度/激活切回去

收益有明确数字：激活内存减少 5 倍，激活重计算的时间开销降低 90% 以上；530B 的 GPT-3 风格模型在 2240 张 A100 上 MFU 从 42.1% 提到 54.2%。注意 SP 省的是显存，不减注意力的 O(s2) 计算——那是 CP 的事。

3. 上下文并行 CP 路线一：Ulysses，用 all-to-all 换头#

DeepSpeed-Ulysses 的做法是：先按序列切（每 rank 拿 s/P 个 token），进注意力前做一次 all-to-all，让每个 rank 拿到完整序列、但只拿一部分注意力头；算完再 all-to-all 一次换回序列布局。序列切分与头切分互为对偶，通信只用来切布局。

论文的关键性质是：序列长度与计算设备数按比例增长时，每 rank 通信量保持常数。示例 3 复现了这一点：每 rank 序列长固定 2048，设备数 2→32 时每层发送量只从 48.0 升到 93.0 MiB。论文实测是 4 倍长序列比当时 SOTA 快 2.5 倍。

4. 上下文并行 CP 路线二：Ring Attention，用环传递 KV#

Ring Attention 不复刻整段 K/V，而是让 K/V 块在设备环上流动：每个 rank 算完当前 K/V 块的注意力后把块发给下一个设备，同时接住上游的块继续算。于是峰值显存降到 O(s/P)，且通信与块间注意力计算重叠；论文强调它"不引入近似，也不带来额外的通信与计算开销"。

示例 3 的账本给了一个易被忽略的结论：ring 与"先复制整段 KV 到每个 rank"的每 rank 收发字节完全相同（都是 PP−1​⋅KV）。差别在峰值显存（KV 对 KV/P）与可重叠性（ring 的传输藏在块计算后面，一次性 all-gather 很难重叠）。

5. 因果掩码下的负载不均#

长文本几乎都是因果（causal）注意力：第 q 个查询只能看见前 q+1 个键，于是工作量沿序列呈三角形分布——开头轻、结尾重。若按序列连续切成 P 段，最重的 rank 决定整步：示例 2 用 8 个 rank、每块 256 行算出"连续切分"最大/均值 = 1.875，即整步要按最慢者等近 1.9 倍。

修法是交错分配块：每个 rank 同时拿一个靠前的块和一个靠后的块，两块三角形面积相加为常数，工作量完全相同——示例 2 的"条带配对"最大/均值精确为 1.000。Striped Attention 就是把 token 均匀散布到各设备，A100/TPUv4 上报告最高 1.45 倍加速。

6. 通信账本与选型#

把三条路线的账放在一起：

方案 每层每 rank 通信量 峰值 KV 显存 适用条件
SP（配合 TP） 2 次集合通信（all-gather + reduce-scatter），PP−1​⋅2bsh 量级 激活 1/P 已有 TP，想省激活显存
Ulysses 2 次 all-to-all，每 rank 趋于常数（本地序列固定时） 1/P（但需完整序列的一段头） 头数足够多（≥P），序列与设备同比例增长
Ring Attention PP−1​⋅KV（与全量复制相同） 1/P 超长序列；需处理因果负载均衡

一条通用约束：CP 每层通信量随 s 增长（KV∝s），所以序列越长，CP 组越需要高速链路——长文本 + 跨机 CP 是常见陷阱。

7. 常见坑#

  • 把 SP 当 CP：SP 只切逐 token 算子，注意力的 O(s2) 计算一点没省；要切注意力必须上 CP。
  • CP 组跨慢链路：K/V 块每层都要交换，跨机时通信量随 s 增长，很容易把收益吃光。
  • 连续切分不做因果均衡：示例 2 里相差近 1.9 倍；长序列上这个差距更大。
  • 分块边界与位置编码/mask 对不齐：RoPE 的位置编号、因果 mask 边界必须按全局位置算，否则数值不正确。
  • 头数不足还硬上 Ulysses：头数要能被 CP 度整除（GQA 下注意 KV 头数），否则每 rank 拿不到独占的头。

二、可运行代码示例#

三段纯 numpy：验证 SP 切序列的精确性与显存收益、量化因果负载不均与条带均衡的收益、算清 CP 两条路线的通信与显存账本。

# ===== 示例 1：序列并行：切序列是精确的，激活随之下降 =====
import numpy as np
rng = np.random.default_rng(0)
s, h, P = 2048, 4096, 8
x = rng.normal(size=(s, h)).astype(np.float32)
def ln(v):
    mu = v.mean(-1, keepdims=True); var = v.var(-1, keepdims=True)
    return (v - mu)/np.sqrt(var + 1e-5)
ref = ln(x)
shards = [ln(x[r*s//P:(r+1)*s//P]) for r in range(P)]
print("示例 1：序列并行（SP）按序列维切 LayerNorm 激活")
print(f"  逐 rank 计算后拼接 == 单卡结果：{np.allclose(np.concatenate(shards), ref, atol=1e-5)}")
print(f"  单卡激活 {s*h*2/2**20:.0f} MiB（fp16），每 rank {s*h*2/P/2**20:.0f} MiB，降为 1/{P}")
g_recv = (P-1)/P * s*h*2
print(f"  SP 与 TP 交界处每层 g 算子：把切开的序列 all-gather 回去，每 rank 收 {g_recv/2**20:.0f} MiB")
print(f"  结论：SP 省的是显存（{s*h*2/2**20:.0f} → {s*h*2/P/2**20:.0f} MiB/rank），"
      f"代价是每层多两次集合通信（前向 all-gather、反向 reduce-scatter）。")

# ===== 示例 2：因果注意力的负载不均：朴素切 vs 条带（striped） =====
def block_work(k, c):
    """第 k 个块（覆盖行 k·c..(k+1)·c-1）的因果注意力工作量 = Σ(q+1)。"""
    return c*(k*c + (c+1)/2)
P_, c = 8, 256                                # 8 个 rank，16 个块，每块 256 行
blocks = 2*P_
cont = [block_work(2*r, c) + block_work(2*r+1, c) for r in range(P_)]   # 连续切分
strip = [block_work(r, c) + block_work(blocks-1-r, c) for r in range(P_)]  # 条带配对
print("\n示例 2：因果掩码下的工作量（8 rank × 256 行/块，序列 4096）")
print(f"  连续切分  每 rank 工作量 {[int(w) for w in cont]}")
print(f"            最大/均值 = {max(cont)/np.mean(cont):.3f}（最慢 rank 决定整步）")
print(f"  条带配对  每 rank 工作量 {[int(w) for w in strip]}")
print(f"            最大/均值 = {max(strip)/np.mean(strip):.3f}")
print(f"  均衡带来的收益上限：{(max(cont)/np.mean(cont))/(max(strip)/np.mean(strip)):.2f}x")

# ===== 示例 3：CP 两条路线的账本：同样的字节，不同的显存与重叠 =====
def kv_bytes(s_len, h_dim, dtype=2):
    return 2*s_len*h_dim*dtype                # K 与 V 各一份
s_len, h_dim = 32768, 4096
KV = kv_bytes(s_len, h_dim)
print("\n示例 3：上下文并行（CP）的通信与显存（序列 32768、hidden 4096、fp16）")
print(f"  整段 KV 共 {KV/2**30:.2f} GiB；下面按 rank 数 P 看两种做法的差异")
print("  P    复制整段 KV 的显存/rank   ring 的显存/rank   每 rank 收发字节")
for P in (2, 4, 8, 16, 32):
    vol = (P-1)/P*KV
    print(f"  {P:<4} {KV/2**30:22.2f} GiB {KV/P/2**30:18.2f} GiB {vol/2**30:16.2f} GiB")
print("  注：两种做法的每 rank 收发字节相同（都是 (P-1)/P·KV），差别在峰值显存与调度：")
print("      ring 每 rank 只留 1/P 的 KV，把 K/V 块的传输藏在块间注意力计算后面。")
print("\n  Ulysses 路线：两次 all-to-all（QKV 去、输出回）；固定每 rank 序列长度后，")
print("  设备数与序列长度同比例增长时，每 rank 每层发送量趋于常数：")
print("  P    全局序列长   每 rank 序列长   每 rank 每层发送(MiB)")
for P in (2, 4, 8, 16, 32):
    local_s = 2048
    vol = 2*(P-1)/P*3*local_s*h_dim*2
    print(f"  {P:<4} {local_s*P:12.0f} {local_s:15.0f} {vol/2**20:20.1f}")

三、练习#

  1. 实现：把示例 1 的 ln 换成"LayerNorm + Dropout"两步（Dropout 用固定随机掩码保证各 rank 一致），验证切序列的精确性；说明随机数要怎么对齐才能复现。
  2. 解释：g 与 gˉ​ 为什么互为共轭？用链式法则说明"前向拼序列、反向切梯度"与 all-gather / reduce-scatter 的配对关系。
  3. 对比/验证：把示例 2 的块数从 16 改成 32（每块 128 行），重算两种切分的最大/均值；解释块越细时差距怎么变。
  4. 思考：序列长 131072、hidden 8192、fp16、CP 度 16。用示例 3 的公式算整段 KV 字节数与每 rank 每层的 ring 收发量；若 CP 组跨 25 GB/s 链路、每层还算 8 次块注意力，为什么"CP 组该留在高速域内"？
