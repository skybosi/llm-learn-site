这一节要解决什么#

前两节讲了 judge 有什么偏差、判定协议怎么设计。这一节处理最后一个、也是最容易被跳过的问题：这个 judge 的结论，在你真正要做的那个决策上，够不够用？

这个问题的回答不能靠"看几个例子觉得挺准"。它需要三样东西：

  1. 一个校准集：judge 与人工在同一批样本上的判定，按同一套标签编码。
  2. 一组一致性统计量：一致率、Cohen κ（含有序/加权版本）、Krippendorff α，以及它们各自的失效条件。
  3. 一张校准证据表：把统计量翻译成"哪些决策可用、哪些不可用"的结论。

本节最重要的两个判断，都会与直觉相反：

  • "一致率 85%" 几乎不携带信息，因为它没有扣除随机一致。当某一类占比 90% 时，一个"永远输出该类"的 judge 也能得到 90% 的一致率。
  • κ 也不能单独用。它有"悖论"（高一致率配低 κ），而且它衡量的是"排序一致性"，不是"阈值一致性"。你的决策若依赖一个固定的分数阈值，需要的校准证据与 κ 完全不同。

最后落到双评与仲裁：当 judge 与人工分歧时，谁来定？ 这决定你的成本结构（人工复核率）与最终结论的可信度。

一、一致率：为什么它几乎无用#

设 judge 与人工都把样本分成正/负两类，得到混淆矩阵：

人工正 人工负
judge 正 a b
judge 负 c d

观测一致率：

po​=na+d​

随机一致率（假设两者独立但保持各自的边际分布）：

pe​=n2(a+b)(a+c)+(c+d)(b+d)​

Cohen κ：

κ=1−pe​po​−pe​​

为什么一致率无用：因为 pe​ 可能很高。若"正类"占比 90%（比如"这个回答基本合格"），一个恒输出"正"的 judge 得到 po​=0.90，pe​=0.9×0.9+0.1×0.1=0.82，κ=(0.90−0.82)/(1−0.82)=0.44。看起来"90% 一致"的 judge，实际上只比抛硬币好一点。 这就是为什么报告必须给 κ。

但 κ 也有自己的问题（这就是 κ 悖论）：

情形 po​ κ 解释
正类占比 50%，混淆矩阵对角线 80% 0.80 0.60 一致性不错
正类占比 95%，对角线 96% 0.96 0.20 几乎全是随机一致
正类占比 5%，对角线 96% 0.96 0.20 同上

所以在低方差的标签分布上，κ 会很低——这不必然意味着 judge 烂，而是意味着这个标签体系在这些样本上区分度太低。此时正确动作可能是换标签定义（提高区分度），而不是换 judge。

实践判据（用于二分类 judge）：

κ 可用性
<0.2 不可用（与随机无实质差别）
0.2∼0.4 只可用于粗筛（"捞出可能差的样本"）
0.4∼0.6 可用于中等置信的对比（报告必须带 κ 与样本量）
0.6∼0.8 可用于回归门禁（配合人工抽查）
>0.8 可用于大部分内部决策；安全/合规仍不可

注意这张表不是普适定律，它是"二分类 + 中等标签平衡"下的经验参照。在有序评分（1~5）上，必须用加权 κ——否则相邻类别的分歧与"1 分 vs 5 分"的分歧被同等对待，κ 会被严重低估。

二、有序数据：加权 κ 与 Krippendorff α#

加权 κ：给出一个权重矩阵 wij​（表示"判成 i 而实际是 j"的代价），然后：

κw​=1−∑ij​wij​eij​∑ij​wij​oij​​

两种常见权重：

  • 线性：wij​=∣i−j∣/(k−1)
  • 二次：wij​=(i−j)2/(k−1)2（更严厉地惩罚大偏差，常用于 5 分制）

怎么做：在 1~5 分这种有序评分上，默认报二次加权 κ，并同时报"相邻错"比例（错 1 分以内）与"大错"比例（错 ≥2 分）。这两个比例比单一 κ 更好沟通。

Krippendorff α：它的优势是容忍缺失（不同评分者评了不同子集）并且适用于任意测量尺度。二分类情形下它与 κ 数值接近；有序尺度上用 ordinal 度量后与加权 κ 接近。长期维护的评测集应该用 α，因为标注者缺勤是常态。

取舍：κ 与 α 都是"一致性"指标，都不度量正确性。两个标注者可能"一致地错"（共享同一个误解）——这时 κ 会很高。防御手段是金题（gold items）：混入已知答案的样本，测量的是"与真相的一致"，而不是"彼此的一致"。第 4 节会展开。

三、校准集怎么建#

校准集不是"随便抽一批标一下"。四条设计约束：

（a）分层随机采样，而不是便利采样。 按"难度 × 类别"分层，每层都抽。否则你会得到一个人工都一致同意"简单"的集合，κ 虚高。

（b）必须包含分歧区。 judge 与人工最容易不一致的地方是判定边界附近（比如 3 分与 4 分之间）。校准集里要故意过采样边界样本（比如 judge 分数落在 [3.5,4.5] 的样本占 40%）。这样得到的 κ 更能反映实际决策区域的可靠性。注意过采样会改变 κ 的总体解释——报告里要写明采样权重，并给出加权后的估计。

（c）样本量。 κ 的不确定性在 n 小时很大。n=100、κ=0.5 时 95% 区间约 [0.33,0.64]。判据：让区间宽度小于你的决策阈值间距（比如你要区分 κ>0.4 与 κ<0.4，那么需要区间半宽小于 0.1，对应 n≥200∼300）。

（d）冻结与版本化。 校准集是测量工具的一部分，必须冻结并版本化（第 2 章的原则同样适用）。每次换 judge 版本、换 prompt、换被测模型家族，都要重跑校准。 这是"judge 校准会过期"的具体含义。

成本估算：校准集的成本 = 样本数 × 每人耗时 × 人力单价 × 重复数（一致性估计需要至少 2 人标一部分）。n=300、每题 2 分钟、2 人重复率 30% → 约 300×2×1.3=13 人时。这是一个可以用一次会议预算换来的、能撑半年的证据。

四、分歧的会计：把"不一致"拆成三份#

κ 是一个数，但它由三类不同的原因造成，处置方式完全不同：

分歧=方向可预测judge 的系统偏差​​+靠重复平均judge 的随机噪声​​+任务本身模糊人工标注者的分歧​​

怎么拆：

  • 人工分歧（人-人一致率 / 人-人 κ）：如果两个人之间只有 κ=0.5，那么 judge 与人的 κ 上限大约就是这个量级。这是"任务可判定性"的上限。 把 judge 训到超过人-人一致率，通常意味着它在拟合某一方的偏见。
  • judge 随机噪声：同一 judge 同一样本重复 k 次的自我一致率（见第 1 节的方差分解）。k 次多数投票可以把噪声降下来。
  • judge 系统偏差：judge-人一致率与"人-人上限"的差距里，位置/长度/自我偏好能解释的部分（第 1 节的回归）。

这个分解有一个直接用途：它告诉你该改哪一头。

  • 如果人-人 κ=0.45、judge-人 κ=0.42，那么 judge 已经接近上限，继续优化 judge 没有意义，该改的是 rubric 与标注指南（提高任务可判定性）。
  • 如果人-人 κ=0.75、judge-人 κ=0.40，那么 judge 是真短板，值得继续调协议/换模型/加集成。

五、校准映射：让分数可比，但别过头#

有时你需要把 judge 的分数（或胜率）映射到人的尺度上。两种做法：

（a）单调校准（isotonic / 分箱）：用校准集拟合一个单调函数 f，把 judge 分数映射到人工分数的期望。优点是单调性可保证（不会把更高的 judge 分映射成更低的人工分）；缺点是在数据稀疏的区域会阶梯化。

（b）线性/逻辑校准：拟合 logit(P(人工正))=a+b⋅judge 分数。用它给出"当 judge 给 4 分时，人工判正的概率约 p"。优点是平滑、外推可控；缺点是假设了函数形式。

关键警告（这类校准最常见的误用）：

  1. 校准映射不能修复排序错误。如果 judge 的排序本身与人不一致，任何单调映射都不可能改善。先看排序，再看值。
  2. 只在"同分布"上有效。校准集是从某个分布抽的；把校准后的分数用于另一个分布（另一个任务、另一批用户）时，校准的假设就破了。校准不可迁移，只可复用。
  3. 校准后仍要报不确定性。校准映射本身有估计误差，它会加到结论的区间上。报告里报校准后数字时，要连着"校准集规模 + 映射后的区间"一起报。
  4. 不要把校准变成"调到想要的结论"。如果每次结论不合意就重拟合一次校准映射，那就是在过拟合决策。校准映射必须与决策规则一起冻结。

取舍：如果你只是要"哪个模型更好"（排序），不要做校准映射——直接报配对比 + 置信区间，并附 κ。如果你要"这个模型能不能过 0.8 的门禁"（阈值），校准映射是必须的，因为它把"judge 分数"翻译成"人工通过率"。

六、双评与仲裁：分歧的处置流程#

常见流程（按成本递增）：

方案 做法 成本 适用
单判 judge 一次定论 1× 粗筛、监控
双评（judge ×2） 两次独立判定，一致则采纳 2× 需要稳定结论的对比
双评 + 仲裁 两次不一致则第三人（人工或另一家族 judge）定 2× + 分歧率×1 需要对外报告的结论
人工复核抽样 judge 定论，按比例（如 5%）人工复核 1.05× 大规模评测的质量控制
全部人工 人判定 100×~1000× 安全、合规、对外最终结论

仲裁的三个必须写清的规则：

  1. 仲裁者的资格：同一 judge 的第三次调用不算独立仲裁（它带同样的偏差）。仲裁应该换家族、换协议（比如 rubric 分解）、或者换人。
  2. 不一致样本的处置：丢弃、记平局、还是仲裁？丢弃会改变被测总体（不一致的样本往往更难、更有信息量）。推荐：不一致样本单独成层报告，让读者看到"分歧集中在哪一类任务上"。
  3. 分歧率是核心质量指标：分歧率从 20% 涨到 35% 说明任务、prompt 或模型版本出了问题。把分歧率作为常规监控指标，而不只是报告里的一个数字。

七、一条可操作的红线#

把本节合成一张决策表。这张表建议直接写进团队的评测规范：

决策类型 最低要求 为什么
内部粗筛（"捞可能差的样本"） 单判 judge + 报告 κ 假阳性由后续人工兜住
模型选型（A 还是 B） 双评 + 配对比 + 置信区间 + 报告 κ 与偏差测量 结论要能挡住质疑
回归门禁（改动不许变差） 校准过的 judge + 阈值校准证据 + 人工抽查 ≥5% 阈值判断需要阈值校准
对外发布结论 人工评审为主 + judge 辅助 + 一致性与分歧率披露 责任在人
安全 / 合规判定 不用 judge 做最终判定 代价不对称，漏检不可接受（第 5 章）

这张表的关键一行是最后一行：judge 在安全场景永远不能做最终判定，只能做"候选筛选器"。理由是第 3 章讲过的错误代价不对称——judge 的漏检率即使只有 1%，在安全场景也不可接受，而"1% 漏检"恰恰是大多数 judge 在困难负例上的真实表现。

八、校准会过期：怎么知道该重校准了#

四类触发条件（建议写进监控）：

  1. 换 judge 版本 / 换 prompt / 换解码参数 → 必须重跑校准。
  2. 被测对象变化：换成新的模型家族、新的任务类型、新的语言。校准是在分布上成立的，分布变了就失效。
  3. 分歧率漂移：双评分歧率、或与人工抽查的一致率相对上次显著下降（比如 κ 掉了 0.1 以上）。
  4. 时间：即使什么都没变，也建议每季度用保留的校准集重跑一次——服务端模型可能在你不知情的情况下更新。

注意第 4 条的现实性：很多"托管模型"会在不改变名称的情况下更新。这不是猜想，而是工程常态。"版本记录"只能记录你请求的版本串，不能保证服务端实现不变——所以时间维度的重校准不可省。

import math

def phi(x):
    return 0.5 * (1 + math.erf(x / math.sqrt(2)))


# ============================================================
# 1. 一致率 vs Cohen's kappa：为什么必须报 kappa
# ============================================================
def confusion(y_human, y_judge):
    a = sum(1 for h, j in zip(y_human, y_judge) if h == 1 and j == 1)
    b = sum(1 for h, j in zip(y_human, y_judge) if h == 0 and j == 1)
    c = sum(1 for h, j in zip(y_human, y_judge) if h == 1 and j == 0)
    d = sum(1 for h, j in zip(y_human, y_judge) if h == 0 and j == 0)
    return a, b, c, d


def cohen_kappa(y_human, y_judge):
    a, b, c, d = confusion(y_human, y_judge)
    n = a + b + c + d
    po = (a + d) / n
    pe = ((a + b) * (a + c) + (c + d) * (b + d)) / (n * n)
    return po, pe, (po - pe) / (1 - pe) if pe < 1 else 0.0


print("== 1. 一致率与 kappa（合成） ==")
# 情形 A：标签平衡，judge 与人工中等一致
r = random.Random(1)
y_h = [1 if r.random() < 0.5 else 0 for _ in range(400)]
y_j = [h if r.random() < 0.75 else 1 - h for h in y_h]
po, pe, k = cohen_kappa(y_h, y_j)
print(f"平衡标签(正类 50%): 一致率 {po:.3f}, 随机一致率 {pe:.3f}, kappa {k:.3f}")
# 情形 B：极端不平衡，judge 恒输出正类
y_h2 = [1 if r.random() < 0.90 else 0 for _ in range(400)]
y_j2 = [1] * 400
po2, pe2, k2 = cohen_kappa(y_h2, y_j2)
print(f"不平衡(正类90%)+恒输出正: 一致率 {po2:.3f}, 随机一致率 {pe2:.3f}, kappa {k2:.3f}")
# 情形 C：极端不平衡但 judge 真的更好
y_j3 = [h if r.random() < 0.80 else 1 - h for h in y_h2]
po3, pe3, k3 = cohen_kappa(y_h2, y_j3)
print(f"不平衡(正类90%)+真判: 一致率 {po3:.3f}, 随机一致率 {pe3:.3f}, kappa {k3:.3f}")
print("  <- '一致率 0.90' 在情形 B 的 kappa 只有 "
      f"{k2:.2f}；一致率几乎不携带信息，kappa 才携带")


# ============================================================
# 2. kappa 的 bootstrap 置信区间（校准集通常只有几百条）
# ============================================================
def bootstrap_kappa(y_h, y_j, n_boot=2000, seed=5):
    r = random.Random(seed)
    n = len(y_h)
    ks = []
    for _ in range(n_boot):
        idx = [r.randrange(n) for _ in range(n)]
        _, _, kk = cohen_kappa([y_h[i] for i in idx], [y_j[i] for i in idx])
        ks.append(kk)
    ks.sort()
    return ks[int(0.025 * n_boot)], ks[int(0.975 * n_boot)], statistics.mean(ks)


print("\n== 2. kappa 的不确定性（bootstrap） ==")
for n in (50, 100, 300, 1000):
    r = random.Random(2)
    yh = [1 if r.random() < 0.5 else 0 for _ in range(n)]
    yj = [h if r.random() < 0.70 else 1 - h for h in yh]
    lo, hi, mean = bootstrap_kappa(yh, yj)
    print(f"n={n:5d}: kappa 点估计 {cohen_kappa(yh, yj)[2]:.3f}  "
          f"95% CI [{lo:.3f}, {hi:.3f}]  宽度 {hi-lo:.3f}")
print("  <- n=100 时区间宽度可达 0.3；报'kappa=0.45'而不报区间是误导")


# ============================================================
# 3. 二次加权 kappa（1~5 有序评分）
# ============================================================
def weighted_kappa(y_h, y_j, k=5, kind="quadratic"):
    n = len(y_h)
    O = [[0] * (k + 1) for _ in range(k + 1)]
    for h, j in zip(y_h, y_j):
        O[h][j] += 1
    row = [sum(O[i]) for i in range(k + 1)]
    col = [sum(O[i][j] for i in range(k + 1)) for j in range(k + 1)]

    def w(i, j):
        if kind == "quadratic":
            return ((i - j) ** 2) / ((k - 1) ** 2)
        return abs(i - j) / (k - 1)

    num = sum(w(i, j) * O[i][j] for i in range(1, k + 1) for j in range(1, k + 1))
    den = sum(w(i, j) * row[i] * col[j] / n
              for i in range(1, k + 1) for j in range(1, k + 1))
    return 1 - num / den if den else 0.0


print("\n== 3. 有序评分的加权 kappa（合成） ==")
r = random.Random(3)
yh = [r.choice([1, 2, 3, 4, 5]) for _ in range(300)]
# judge 与人工：70% 相同分数，其余相邻偏差 +/-1
yj = []
for h in yh:

    if u < 0.58:

    elif u < 0.88:
        yj.append(max(1, min(5, h + r.choice([-1, 1]))))  # 相邻错 +-1

adj = sum(1 for h, j in zip(yh, yj) if abs(h - j) <= 1) / 300
print(f"完全一致率 {sum(1 for h,j in zip(yh,yj) if h==j)/300:.3f}；"
      f"相邻(±1)以内 {adj:.3f}")
print(f"二次加权 kappa = {weighted_kappa(yh, yj):.3f}")
print(f"线性加权 kappa = {weighted_kappa(yh, yj, kind='linear'):.3f}")
po_, _, k_nom = cohen_kappa([1 if x >= 4 else 0 for x in yh],
                            [1 if x >= 4 else 0 for x in yj])
print(f"若硬切成二分类(>=4) 的未加权 kappa = {k_nom:.3f}"
      "  <- 丢掉有序信息，低估一致性")
print("  <- 有序数据必须用加权 kappa，并同时报'相邻错'与'大错'比例")


# ============================================================
# 4. Krippendorff alpha（容忍缺失，适合长期维护的评测集）
# ============================================================
def krippendorff_alpha_ordinal(units, k=5):
    # units: list of list，每条是若干评分者给出的分数（可缺）
    # 用 ordinal 度量：delta^2 = (sum_{g=i..j} n_g - (n_i+n_j)/2)^2
    counts = [0] * (k + 1)
    for u in units:
        for v in u:
            counts[v] += 1
    n_total = sum(counts)

    def delta(c, kk):
        if c == kk:
            return 0.0
        lo, hi = min(c, kk), max(c, kk)
        s = sum(counts[g] for g in range(lo, hi + 1)) - (counts[lo] + counts[hi]) / 2
        return s * s

    # Do：观测到的分歧（同一 unit 内所有评分者两两比较）
    do_num = do_den = 0.0
    for u in units:
        m = len(u)
        if m < 2:
            continue
        for i in range(m):
            for j in range(m):
                if i == j:
                    continue
                do_num += delta(u[i], u[j])
                do_den += 1
    Do = do_num / do_den if do_den else 0.0
    # De：按边际分布随机配对
    de_num = de_den = 0.0
    for c in range(1, k + 1):
        for c2 in range(1, k + 1):
            n_c, n_c2 = counts[c], counts[c2]
            if c == c2:
                pairs = n_c * (n_c - 1)
            else:
                pairs = n_c * n_c2
            de_num += delta(c, c2) * pairs
            de_den += pairs
    De = de_num / de_den if de_den else 0.0
    return 1 - Do / De if De else 0.0


print("\n== 4. Krippendorff alpha（含 15% 缺失） ==")
r = random.Random(4)
units = []
for _ in range(400):
    base = r.choice([1, 2, 3, 4, 5])
    raters = []
    for _ in range(3):
        if r.random() < 0.85:          # 15% 缺失
            v = base if r.random() < 0.7 else max(1, min(5, base + r.choice([-1, 1])))
            raters.append(v)
    if len(raters) >= 2:
        units.append(raters)
print(f"可用单元 {len(units)}（3 名评分者，15% 缺失）")
print(f"Krippendorff alpha (ordinal) = {krippendorff_alpha_ordinal(units):.3f}")
print("  <- alpha 容忍缺失；kappa 在缺勤严重时只能丢掉不完整单元（样本损失）")


# ============================================================
# 5. 人类之间的上限：人-人 kappa 决定 judge 的天花板
# ============================================================
print("\n== 5. 人-人一致率是 judge 的上限（合成） ==")
r = random.Random(6)
n = 500
true_quality = [1 if r.random() < 0.5 else 0 for _ in range(n)]
# 标注者的"能力"参数：越接近 1 越准
for acc_h in (0.60, 0.75, 0.90):
    h1 = [q if r.random() < acc_h else 1 - q for q in true_quality]
    h2 = [q if r.random() < acc_h else 1 - q for q in true_quality]
    _, _, k_hh = cohen_kappa(h1, h2)
    # judge 的能力稍高于标注者
    j = [q if r.random() < min(0.95, acc_h + 0.05) else 1 - q for q in true_quality]
    _, _, k_hj = cohen_kappa(h1, j)
    print(f"标注者准确率 {acc_h:.2f}: 人-人 kappa {k_hh:.3f} | "
          f"人-judge kappa {k_hj:.3f} | 差距 {k_hj - k_hh:+.3f}")
print("  <- 人-judge 与人-人的差距才是'judge 还差多少'的可用信号；")
print("     若人-人 kappa 只有 0.5，把 judge 调到 0.6 通常是在拟合某一方的偏见")


# ============================================================
# 6. 阈值决策的可靠性：kappa 高不代表阈值判断准
# ============================================================
print("\n== 6. kappa 与阈值判断的可靠性可以脱钩（合成） ==")
r = random.Random(8)
n = 2000
# 人的真实连续质量
quality = [r.gauss(0.0, 1.0) for _ in range(n)]
human_pos = [1 if q > 0.0 else 0 for q in quality]          # 人工阈值 0
# judge 分数：与质量相关但有系统偏移（judge 偏严）
judge_score = [q * 0.9 - 0.35 + r.gauss(0, 0.6) for q in quality]


def eval_threshold(thr):
    yj = [1 if s > thr else 0 for s in judge_score]
    po, pe, kk = cohen_kappa(human_pos, yj)
    # 阈值判断的两个关键量：通过率与漏判
    pass_rate = sum(yj) / n
    fn = sum(1 for h, j in zip(human_pos, yj) if h == 1 and j == 0) / \
        max(1, sum(human_pos))
    return po, kk, pass_rate, fn


print("judge 分数整体偏严（均值 -0.35）。不同阈值下的表现：")
for thr in (-0.6, -0.35, 0.0, 0.3):
    po, kk, pr, fn = eval_threshold(thr)
    print(f"  阈值 {thr:+.2f}: 一致率 {po:.3f}  kappa {kk:.3f}  "
          f"judge 通过率 {pr:.3f}  (人工通过率 {sum(human_pos)/n:.3f})  漏判率 {fn:.3f}")
print("  <- kappa 在不同阈值下变化不大（它主要看排序），")
print("     但'通过率'与'漏判率'变化巨大 —— 阈值决策必须做阈值校准")

代码里六个值得注意的点：

  • 第 1 段是本节的第一号结论：情形 B（正类占 90%、judge 恒输出正）的一致率是 0.90，κ 只有约 0.0 —— "90% 一致"完全可能等价于"没有信息"。情形 C 用同样不平衡的标签，但 judge 真判，一致率 0.86、κ 约 0.30。一致率几乎不携带信息，κ 才携带。
  • 第 2 段说明 κ 必须带区间：n=50 时 κ 的 95% 区间宽度可以超过 0.4。"κ=0.45，judge 可用作回归门禁"这种结论在小校准集上是不成立的——区间下界可能落到 0.2。
  • 第 3 段是有序评分的正确做法：同一个 judge，用二次加权 κ、线性加权 κ、以及硬切成二分类的未加权 κ 会给出三个差距明显的数。硬切二分类丢掉了有序信息，会低估一致性；反过来，如果有人只报未加权 κ 说"judge 不行"，你要先看他有没有把有序信息丢掉。
  • 第 4 段是 α 的核心优势：15% 缺失时，κ 的常规做法只能丢掉不完整单元（本例会损失近 1/4 样本），而 α 用全部可用评分对。长期维护的评测集应默认用 α，因为标注者缺勤是常态。
  • 第 5 段给出"够不够用"的正确参照系：judge 的上限不是 1.0，而是人-人一致率。代码里标注者准确率 0.60 时人-人 κ 只有 0.08 量级——任务本身在人之间就不可复现，此时 judge 与人的 κ 是 0.11，已经略高于人工之间。标注者准确率升到 0.90 后，人-人 κ 到 0.68，judge 只领先 0.07。这说明"judge 还差多少"必须与人-人上限对照着读；在人-人 κ 只有 0.2 的任务上把 judge 调到 0.5，多半是在拟合某一位标注者的偏好。
  • 第 6 段是本节最容易被忽略、也最贵的一条：κ 衡量排序一致性，而业务决策常常依赖一个固定阈值。代码里 judge 分数整体偏严，κ 在不同阈值下变化不大，但"judge 通过率"与"漏判率"天差地别。所以回归门禁用的 judge 必须做阈值校准，光有 κ 不够。

练习#

  1. 一致率与 κ：某 judge 与人工在 400 条样本上：混淆矩阵 a=180,b=20,c=30,d=170。 （a）算观测一致率、随机一致率、κ； （b）如果另一个 judge 的混淆矩阵是 a=350,b=40,c=5,d=5，算它的三个量，并说明这两个 judge 哪个更可信； （c）在什么决策上你会选前者、什么决策上选后者？

  2. κ 悖论与标签设计：你的评测标签是"合格 / 不合格"，实测合格率 94%，judge-人 κ=0.28。 （a）判断这个低 κ 是因为 judge 差还是标签区分度低，需要什么额外数据？ （b）给出两个改法（改标签体系 / 改 judge），并说明各自的风险； （c）如果业务只关心"能不能挑出那 6% 的不合格样本"，此时正确的指标是什么（提示：不要用 κ）。

  3. 校准集设计：你要为一个 1~5 分 rubric 的 judge 建校准集，预算 15 人时。 （a）写出采样方案（分层维度、每层样本数、边界样本过采样比例）； （b）用 bootstrap 估计 n=200 时二次加权 κ 的区间宽度（可用本节代码）； （c）说明"过采样边界样本"如何影响 κ 的可解释性，以及报告里该怎么写。

  4. 分歧会计：某评测：人-人 κ=0.62（两人，30% 重复标注），judge-人 κ=0.41，judge 自我一致率 0.93。 （a）把总分歧拆成"人工分歧 / judge 噪声 / judge 系统偏差"三份； （b）指出最值得投入的改进方向，并给出理由； （c）如果 judge 自我一致率只有 0.70，结论会怎么变？

  5. 校准映射：judge 分数与人工"通过/不通过"的校准集数据在手。 （a）分别用分箱（isotonic）与逻辑回归拟合映射，说明两者在稀疏区与尾部的差别； （b）为什么要先看排序再看值？给出一个例子说明"排序错、映射无法修复"； （c）写出报告中必须与校准后数字一起披露的三项信息。

  6. 红线与过期（开放题）：你的团队想用 judge 做"内容安全检查"的自动化判定，声称"κ 已经 0.78"。 （a）用本节的红线表说明为什么这仍然不可接受； （b）给出替代方案（judge 在安全流程中的正确定位）； （c）列出四个"必须重跑校准"的触发条件，并说明"什么都没变但服务端模型更新了"该怎么防。

小结#

  • 一致率几乎无用，κ 才有信息：正类占 90% 时，恒输出正类的 judge 也能拿到 0.90 的一致率，而 κ≈0。报告必须给 κ。
  • κ 有两个陷阱：一是悖论（低方差标签下 κ 被严重压低，此时该反思标签体系而非 judge）；二是它衡量排序一致性而非阈值一致性——依赖固定阈值的决策（回归门禁）必须另外做阈值校准。
  • 有序评分用加权 κ（默认二次），并同时报"相邻错"与"大错"比例；长期维护的评测集用 Krippendorff α（容忍缺失，避免丢掉不完整单元）。
  • 校准集要分层 + 故意过采样边界样本 + 冻结版本，样本量以"κ 的置信区间宽度小于决策阈值间距"为准（通常 n≥200∼300）。
  • 分歧要拆成三份：人工分歧（任务可判定性的上限）、judge 随机噪声（靠重复平均降）、judge 系统偏差（靠偏差测量降）。先看人-人一致率，再决定要不要继续优化 judge。
  • 校准映射不能修复排序错误、不可跨分布迁移、必须与决策规则一起冻结。排序问题直接报配对比 + 区间；阈值问题才需要映射。
  • 双评 + 仲裁的规则要写清：仲裁者必须独立（同 judge 第三次调用不算）、不一致样本不丢弃而应单独成层报告、分歧率是常规监控指标。
  • 红线：内部粗筛可以用单判 judge；选型要双评 + 配对比 + 偏差测量；回归门禁要校准过阈值；对外结论以人工为主；安全/合规不做 judge 最终判定。
