训练配置#

数据准备好了，接下来是把"旋钮"调对：学习率、批次大小、预热、调度、显存优化、评估与早停。这些超参数直接决定训练能不能收敛、会不会过拟合、会不会把显存撑爆。本课逐一讲清。

一、概念讲解#

1. 关键超参数#

超参数 含义 微调常见取值
learning_rate 每一步参数更新的步长 1e-5 ~ 5e-5（全参数微调）
per_device_train_batch_size 单卡单步的样本数 1 ~ 8（受显存限制）
gradient_accumulation_steps 梯度累积步数 4 ~ 32（等效扩大 batch）
num_train_epochs 遍历数据集的轮数 1 ~ 3（数据小可稍多）
warmup_ratio 预热阶段占比 0.03 ~ 0.1
lr_scheduler_type 学习率调度曲线 cosine / linear
weight_decay 权重衰减（正则） 0.01 ~ 0.1
max_seq_length 序列最大长度 1024 ~ 8192（看显存）

其中学习率是最敏感的旋钮。太小收敛慢、欠拟合；太大训练不稳定、甚至发散并加重灾难性遗忘。

2. 等效 batch size 与梯度累积#

等效 batch size = per_device_train_batch_size × 梯度累积步数 × 卡数。它决定每轮参数更新用了多少样本，进而影响训练稳定性。显存不够时，不直接加大单步 batch，而是用梯度累积：多个小步只累积梯度、不更新权重，攒够一定步数再统一更新一次。

3. 学习率调度：预热 + 衰减#

  • Warmup：训练初期把学习率从接近 0 线性/线性地爬升到目标值，避免一上来步子太大。
  • 衰减：中后期按余弦或线性降到接近 0，帮助模型稳稳落入极小值。

典型曲线是"先爬升 → 平台 → 余弦下降"。Hugging Face 的 lr_scheduler_type="cosine" 配合 warmup_ratio 就能复现。

4. 显存优化三板斧#

全参数微调最怕显存不够，常用手段：

  • 混合精度（mixed precision）：用 bf16/fp16 存权重和算前向，用 fp32 存优化器状态和关键累积，既省显存又加速。现代 GPU 优先 bf16（动态范围大，不易溢出）。
  • 梯度检查点（gradient checkpointing）：前向时不保存所有中间激活，反向时按需重新计算，用"时间换显存"。省显存但训练变慢。
  • 梯度累积：如前所述，用小 batch + 累积模拟大 batch。

三者常组合使用。此外还有 8-bit 优化器（如 bitsandbytes 的 AdamW8bit）进一步压优化器状态。

5. 评估、早停与检查点#

  • 评估：每个 epoch（或每若干步）在验证集上算 loss / 指标（如准确率、Rouge、或人工抽检），监控是否过拟合。
  • 早停（early stopping）：验证 loss 连续若干个评估周期不再下降就提前停，防止过拟合、省算力。
  • 检查点（checkpoint）：定期保存模型和优化器状态，既能中途恢复，也能事后回滚到验证集上最优的那一版。注意 save_strategy 与 evaluation_strategy 的配合，以及是否要 load_best_model_at_end。

二、可运行代码示例#

下面给出一个完整的 TrainingArguments 配置 + Trainer 训练骨架，覆盖上面讲的旋钮。

from transformers import (
    AutoTokenizer,
    AutoModelForCausalLM,
    Trainer,
    TrainingArguments,
)
from datasets import Dataset

model_name = "Qwen/Qwen2.5-0.5B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token
model = AutoModelForCausalLM.from_pretrained(model_name)

# 打开梯度检查点（省显存），需先对模型启用
model.gradient_checkpointing_enable()

# （省略数据准备，沿用上一课的分词结果，这里用占位 Dataset 示意）
raw = [
    {"instruction": "翻译成英文", "input": "今天天气很好。", "output": "The weather is nice today."},
    {"instruction": "翻译成英文", "input": "我喜欢学习编程。", "output": "I like learning to program."},
]

def tokenize_fn(example):
    messages = [
        {"role": "user", "content": example["instruction"] + "\n" + example["input"]},
        {"role": "assistant", "content": example["output"]},
    ]
    prompt = tokenizer.apply_chat_template(messages[:-1], tokenize=False, add_generation_prompt=True)
    full = tokenizer.apply_chat_template(messages, tokenize=False)
    p_ids = tokenizer(prompt, add_special_tokens=False)["input_ids"]
    f_ids = tokenizer(full, add_special_tokens=False)["input_ids"]
    return {"input_ids": f_ids, "labels": [-100]*len(p_ids) + f_ids[len(p_ids):]}

train_dataset = Dataset.from_list(raw).map(tokenize_fn)
# 验证集通常单独划分，这里为演示复用一小份
eval_dataset = train_dataset

# 训练配置：显存优化 + 学习率调度 + 评估早停
training_args = TrainingArguments(
    output_dir="./ft-config-output",
    # —— 批次与累积 ——
    per_device_train_batch_size=1,
    gradient_accumulation_steps=8,      # 等效 batch = 1 × 8 = 8
    # —— 学习率 ——
    learning_rate=2e-5,
    num_train_epochs=3,
    warmup_ratio=0.1,
    lr_scheduler_type="cosine",
    weight_decay=0.01,
    # —— 显存优化 ——
    bf16=True,                          # 混合精度（无 bf16 支持的卡可改 fp16=True）
    gradient_checkpointing=True,
    # —— 日志/保存/评估 ——
    logging_steps=5,
    save_strategy="epoch",
    evaluation_strategy="epoch",
    load_best_model_at_end=True,        # 训练结束后加载验证集上最优的检查点
    metric_for_best_model="eval_loss",
    report_to="none",
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    tokenizer=tokenizer,
)

trainer.train()
print("\n训练结束，已加载验证集上最优的检查点。")
print("提示：若 bf16 报错，说明当前硬件不支持，可改为 fp16=True 或去掉该行。")

三、练习#

  1. 填空：等效 batch size = ____ × ____ × ____；显存不够时用 ____ 技术模拟大 batch。
  2. 概念辨析：说明 warmup_ratio 和 lr_scheduler_type 各自的作用；为什么"先预热再余弦衰减"是常用组合？
  3. 动手实验：把上面代码的 per_device_train_batch_size 改成 2、gradient_accumulation_steps 改成 4，等效 batch 变了吗？如果再把 learning_rate 改成 1e-4，观察训练曲线（loss）的变化趋势。
  4. 思考题：梯度检查点为什么能省显存却会拖慢训练？"时间换显存"的原理是什么？结合反向传播需要中间激活这一点说明。
