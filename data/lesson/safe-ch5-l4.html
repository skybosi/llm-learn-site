运营期安全：监控信号、收紧与放宽的判据、事故复盘与重测周期#

这一节要解决什么#

上一节的门禁是一次性的。它证明的是：

在 t0​ 这一天，用版本 v 的系统，在某批用例集上，各条判据达标

而系统此后每天都在变：模型换版本、工具集扩张、语料更新、汇点新增、判定器升级、对手变强。所以"上线"不是安全工作的终点，而是漂移检测的起点。

这一节回答运营期的四个问题：

  1. 监控哪些信号？ 每个信号对应第 1 章 R=∑i​Ni​pi​Ei​ci​ 里的哪一项？
  2. 看到什么该收紧、什么该放宽？ 这不是直觉问题，是一个期望损失最小化问题。
  3. 出了事故怎么复盘？ 怎么把"已经改进"变成可检验的断言？
  4. 什么时候必须重测？ 门禁的有效期由什么决定？

把四个问题写成一个持续的控制回路：

§1–§2：ARL 与 MDE测​​→§3：四个动作的期望损失判​​→§4：复盘与闭环改​​→§5：变更影响矩阵再测​​

本节与前三节的差别是时间：前三节都在某个时刻上做决策，这一节处理"决策随时间的更新"。

本节的第一条纪律：

 运营期的目标不是"把风险压到最低"，而是"在不确定下把风险控制在 R∗ 之下，同时保持可用" ​

 运营期的目标不是"把风险压到最低"，而是"在不确定下把风险控制在 R∗ 之下，同时保持可用" ​

因为"压到最低"与"保持可用"在运营期是同一个预算里的两个方向。第 1 节 §4.4 已经算过：在 R∗ 附近，影子价格只有 4995.0 元/万元 —— 继续买安全的边际回报低于它的成本。运营期的每一次"收紧"都要付这笔钱，所以它必须有判据。

⚠️ 本节所有数值均为合成的：CUSUM 参数、事故记录、λ0​/λ1​、成本、变更次数、有效率与检出率都是手写常量或解析计算。§1 的 ARL 是精确解（马尔可夫链 + 高斯消元），不是模拟；§7 的对手能力增长模型在正文与输出里都被明确标注为推测。

一、监控哪些信号：把信号接到 R 的四个因子上#

1.1 为什么按 R 的因子分类#

监控最容易犯的错是"把能采集的数都采集了"。正确的分类依据是这个信号变动时，R 的哪一项在变 —— 因为只有知道它在改哪一项，才知道该动哪一层防护。

信号类 监控什么 变的是 R 的哪一项 对应哪一节的机制
安全信号 违规率、越权调用、汇点未覆盖告警 p（成功率） 第 3 章 εeff​
能力信号 过度拒答率、引用可核验率 E（利用因子） 第 2 章对齐税
成本信号 人工放行量、延迟、熔断误停 c（单次损失） 第 5 章第 2 节的代价项
对手信号 新工具 / 新汇点 / 新语料来源 N（暴露量） 第 1 章威胁模型

注意"能力信号"变的是 E 而不是 p：过度拒答本身不泄漏任何东西，但它会让用户绕过系统（去用没有防护的通道），从而抬高真实场景里的 E。这与第 2 章"过度拒答的净效用为 0 却安全分 1.00"是同一件事。

"对手信号"变的是 N：新接一个语料来源，就等于多了一条可能的注入通路，N 变大。这一类信号最容易被漏掉，因为它不来自运行指标，而来自变更管理。

1.2 每个信号的三个字段#

一个可用的监控信号必须带三个字段，缺任何一个它都无法进入控制回路：

字段 含义 缺失后果
基线 p0​ 正常状态下的分布参数 无法判断"多少算异常"
采样 n 每次观测的样本量 无法算 MDE（§2）
动作 触发后执行什么 告警变成噪声

本节后面集中处理第二与第三个字段：n 决定"能看见多大的漂移"，动作由 §3 的期望损失决定。

1.3 边界#

  1. 信号不是越多越好。每个信号都带一个误报预算（α）；M 个独立监控放在一起，至少一个误报的概率是 1−(1−α)M（第 3 节 §5.1 的 FWER）。M=8,α=0.05 时是 0.336580 —— 监控面板上的假警报会吃掉运维的注意力。
  2. 基线必须随版本更新。模型换版本后 p0​ 会变；不更新基线，监控会在每次发版后连续超标。
  3. "对手信号"没有自然的采样频率，它由变更流程驱动。所以它不能做成"每天一个点"的图，只能做成"每次变更一条记录"。

二、控制图：CUSUM 的精确 ARL 与漂移 MDE#

2.1 为什么需要累计量#

最朴素的监控是每天算一个违规率，超过控制限就报警（Shewhart 图）。它对大漂移有效，对小漂移几乎无效 —— 因为单点的噪声淹没了信号。

CUSUM（累积和）用累计量换取灵敏度。定义：

St​=max(0, St−1​+Xt​−k),St​≥h ⟹ 报警

其中 Xt​ 是第 t 天的违规条数，k 是参考值（通常取 (μ0​+μ1​)/2，μi​ 是两种状态下每天违规数的期望），h 是决策区间。

ARL（平均运行长度）是它的核心指标：

ARL0​=E[报警时间∣未漂移](越大越好),ARL1​=E[报警时间∣已漂移](越小越好)

ARL0​=E[报警时间∣未漂移](越大越好),ARL1​=E[报警时间∣已漂移](越小越好)

本节用的是精确解而不是模拟：把 S 的状态空间（0,…,h−1）写成马尔可夫链，吸收态是"报警"，然后解线性方程组 (I−Q)m=1（高斯消元）。Xt​ 的二项分布在尾部截断并重归一化。

2.2 参数与校准结果#

设定：每天抽 n=200 条人工审计，Xt​∼Binomial(200,p)；p0​=0.010（基线）⇒μ0​=2.0, sd0​=1.41；p1​=0.020（2 倍漂移）⇒μ1​=4.0, sd1​=1.98。

k 取略大于 μ0​：k 太小则 ARL0​ 太短（天天报警），k 太大则 S 贴在 0 上、ARL0​ 变成天文数字。用二分把 ARL0​ 卡到约 365 天：

 更不容易误报=更晚发现 —— 这两个量只能换，不能同时降 ​

这与第 4 章 §6.4 的"告警阈值与 ARL0​"是同一条纪律："持续监控"必须写成"每月多少样本、能看见多大的漂移"，而不是一句"我们在持续监控"。

2.5 失效条件与边界#

  1. p0​ 本身有估计误差。ARL0​ 对 p0​ 极敏感（指数级）；把 ARL0​ 建立在一个点估计上，实际误报率可能差几倍。报告必须带 p0​ 的区间。
  2. "每天审计 n=200 条"是一个昂贵的前提。n 减半会让 μ 与 sd 同时减半，ARL1​ 变差 —— 所以监控的样本量应当按月预算，而不是"能审多少审多少"。
  3. CUSUM 假设观测独立。审计抽样如果是同一批样本被反复看（例如盯着一类请求），相关性会让实际 ARL0​ 明显短于计算值。

误切换/年=365×2(1−Φ(2sd(π)band​))

读数：带宽 0（每天重估、无迟滞）时动作几乎天天翻（365 次/年）；带宽 0.05 把它压到 4.5 次/年，代价是检测延迟从 6.19 天涨到 13.19 天。

"最小驻留"是第二道锁：带宽压的是抖动，驻留压的是抖动与误动作的持续时间。两者的差别在真实系统里很重要 —— 一个抖动 1 天就恢复的收紧，与一个抖动持续 7 天的收紧，业务方的感受完全不同。

3.4 失效条件与边界#

  1. U 与 R 都是估计值，而结论对它们的比值极敏感。"熔断门槛 0.4643"是在 UA3​=60000,RA3​=20000 下算出来的；把 UA3​ 降到 30000，门槛会大幅左移。所以这四个数必须由业务方给并在评审时签字。
  2. π 的估计方法决定了整个回路的质量。本节假设 π 由监控给出（§1–§2 的 CUSUM 是它的一个来源）；如果 π 是拍出来的，那么 §3 的精确分区只是一个精致的假象。π 的区间必须一起报。
  3. ⚠️ 误切换数是解析估计（依赖 sd(π)=0.01 这个合成假设），不是实测。真实抖动必须用历史 π 序列回放，且 sd(π) 本身要估。

4.3 复盘产出的字段（接第 4 章的风险登记册）#

每一条改进项应当写成第 4 章 §4.1 那样的登记册条目，并额外带三个字段：

字段 内容 为什么
绑定的可观测指标 哪个信号、当前值、目标值 判"闭环"的依据
观测窗口 多少天、样本量 判"有效"的依据（§4.2）
反事实 如果当时有哪一层，这次事故会不会被拦住 决定后续预算往哪投

第三条最容易被跳过，但它是最有信息量的：它把一次事故直接接到第 1–2 节的层与预算上。判据可以写成"这次事故的机制属于哪一层/哪几层的覆盖范围，那几层当时的 εeff​ 是多少、为什么没拦住" —— 这个问题的答案经常是共线失效（第 2 节 §7）而不是某层不够强。

4.4 失效条件与边界#

  1. MTTR 会被分母操纵：把容易修的事故先算进去，MTTR 就漂亮。所以 MTTR 必须按类型分别报，不能只报一个总平均（本节的表就是按类型分的）。
  2. 闭环率与复发率必须一起看。闭环率高、复发率也高 = 流程很快但判据太松；闭环率低、复发率低 = 关门很慢但判据很实。只看一个数一定被误导。
  3. "零复发"在小窗口下没有信息量。n=90 天零复发的上界是 0.032738/天（等效间隔 30.55 天）—— 这个结论几乎没有排除任何东西，但它在汇报里看起来非常漂亮。

五、重测周期：变更影响矩阵与有效期#

5.1 门禁有效期取两条约束的较小者#

T=min(T对手增长​, T下一次变更​)

  • T对手增长​：第 3 节 §7 的推测模型，g=0.30,U0​=0.003→U∗=0.01 时是 1674.96 天；
  • T下一次变更​：任何一次可能让某条 gate 结论失效的变更。

合成参数下，工具集每 60.8 天变一次，所以有效期 =60.8 天。

 在合成参数下，变更节奏（30.4 天）比对手增长（1675.0 天）紧得多 ​

所以运营期的重测是"跟着变更走"，不是"跟着日历走"。 这条结论的实践含义是：不要做"每季度全量重测"，而要做"每次变更触发受影响的那几条 gate"。

5.3 失效条件与边界#

  1. 矩阵本身是要评审的。它的每一格都是一个"我认为这个变更会影响这条 gate"的判断；填错的代价是漏测（方向危险），所以默认应当偏保守，再靠 §5.4 的故障注入或历史数据来收窄。
  2. 矩阵会随架构变化而失真。引进了缓存、换了检索器、加了新的模型供应商 —— 这些都可能让某一格的判断变化。所以矩阵要与模型卡/数据卡同版本管理（第 4 章 §1 的可复现性要求）。
  3. 重测次数 115 本身是成本。要把它折成预算：每次重测的成本 ≈ 该 gate 的 n× 单位成本。这个数应当回到第 1 节 §六 的敏感性表里，作为 κ 之外的另一项预算。

XMAX = 20


def binom_pmf(n, p, xmax):
    out = []
    for x in range(xmax + 1):
        out.append(math.comb(n, x) * p ** x * (1 - p) ** (n - x))
    s = sum(out)
    return [v / s for v in out]


def solve(mat, rhs):
    """高斯消元（部分主元）。mat 是 n x n 的列表的列表。"""
    n = len(mat)
    a = [r[:] + [rhs[i]] for i, r in enumerate(mat)]
    for col in range(n):
        piv = max(range(col, n), key=lambda r: abs(a[r][col]))
        a[col], a[piv] = a[piv], a[col]
        d = a[col][col]
        for j in range(col, n + 1):
            a[col][j] /= d
        for r in range(n):
            if r == col:
                continue
            f = a[r][col]
            if f == 0.0:
                continue
            for j in range(col, n + 1):
                a[r][j] -= f * a[col][j]
    return [a[i][n] for i in range(n)]


_ARL_CACHE = {}


def cusum_arl(p, n, k, h, xmax=XMAX):
    """CUSUM: S_t = max(0, S_{t-1} + X_t - k)，S_t >= h 报警。精确 ARL（截断 X）。"""
    key = (round(p, 9), n, k, h, xmax)
    if key in _ARL_CACHE:
        return _ARL_CACHE[key]
    pmf = binom_pmf(n, p, xmax)
    states = h  # 0..h-1 为非吸收态
    trans = [[0.0] * states for _ in range(states)]
    for s in range(states):
        for x, pr in enumerate(pmf):
            if pr == 0.0:
                continue
            t = s + x - k
            if t < 0:
                t = 0
            if t >= h:
                continue
            trans[s][t] += pr
    mat = [[(1.0 if i == j else 0.0) - trans[i][j] for j in range(states)] for i in range(states)]
    m = solve(mat, [1.0] * states)
    _ARL_CACHE[key] = m[0]
    return m[0]


def calibrate_h(p0, n, k, target_arl0, hi=40):
    """ARL_0(h) 单调递增；二分出最小的 h 使 ARL_0 >= target。"""
    lo = 1
    while lo < hi:
        mid = (lo + hi) // 2
        if cusum_arl(p0, n, k, mid) < target_arl0:
            lo = mid + 1
        else:
            hi = mid
    return lo

练习#

  1. （信号与 R 的接口） 用 §1.1 的表： （a）为"能力信号"里的过度拒答率写一条完整的监控定义（基线、采样、动作），并说明它变的是 E 而不是 p 的理由； （b）若新接了一个语料来源（N 变大），说明它应该触发哪几条门禁重测（用 §5.2 的矩阵）； （c）给出一个"c 变了但没有信号"的场景，并说明为什么它是最危险的（提示：第 1 节 §1.2 里 c 由业务方定）； （d）若监控面板上有 8 个独立告警、每个 α=0.05，算出每天"至少一个假警报"的概率，并给出把面板噪声压到 0.05 以下的两种办法。

  2. （CUSUM 的 ARL） 用 §2 的数据： （a）用式 St​=max(0,St−1​+Xt​−k) 与 k=3,h=6 手算：若连续三天 X=(5,6,4)，S 的轨迹是什么？会报警吗？ （b）若把每天审计量从 n=200 提到 n=400（p0​,p1​ 不变，μ 与 sd 都变），定性说明 ARL1​ 会变好还是变差，并解释为什么 k 必须跟着调； （c）解释"ARL0​ 是离散跳变的"（h 取整数），并说明这对"精确设定一年一次误报"意味着什么； （d）若审计抽样存在相关性（同一批样本被重复看），实际 ARL0​ 会比计算值长还是短？为什么？

  3. （漂移 MDE 与预算） 用 §2.4 的表： （a）若业务要求"2 倍漂移必须在一周内检出"，k=3 时 h 最大能取多少？对应的 ARL0​ 是多少？ （b）若把 p0​ 从 0.010 估成 0.015（基线估高了），对同一条 (k,h) 的 ARL0​ 与 MDE 各有什么影响？ （c）在给定"每天审计 n 条"的预算下，推导 ARL1​ 与 n 的关系方向，并说明为什么"样本量翻倍"比"阈值调小"更值得投； （d）给出一条"把 MDE 改善 20%"的技术手段与它的代价。

  4. （收紧/放宽与迟滞） 用 §3 的数据： （a）若 UA3​ 从 60000 降到 30000（熔断变得更便宜），重算 πA2→A3∗​ 并说明分区怎么变； （b）在 π=0.10 时算出四个动作的期望损失，验证"熔断是亏的"； （c）求使 A1（不动）与 A3（熔断）期望损失相等的 π，并说明它为什么落在 A2 的区间之外； （d）若 sd(π)=0.02（估计更不准），重算带宽 0.05 时的误切换频率，并给出一个把成本压回原水平的办法。

  5. （复盘与闭环） 用 §4 的数据： （a）复算闭环率 0.7500 与复发率 0.4444，并说明若把"其它"这一类的 1 起复发判成非复发，两个数各变成多少； （b）"数据外流"这一类 MTTD 11.2 天、MTTR 21.5 天，且 2/2 复发。给出三条具体的机制改进，每条绑定一个可观测指标与观测窗口； （c）用 1−0.051/n 算出"T0​=90 天的机制要证明间隔拉长到 180 天"所需的观测窗口； （d）给"反事实"字段写一个可判定的模板，并用 §2 第 2 节的共线分组解释为什么这个字段经常指向共线失效。

  6. （重测周期） 用 §5.2 的矩阵： （a）若把 G7 那一行的"检索语料"改成 .，裁剪后的重测次数变成多少？节省比例变成多少？ （b）若模型版本从每年 12 次涨到每月 4 次（每年 48 次），重测次数与"最紧的重测间隔"各变成多少？ （c）说明"跟着变更走"与"跟着日历走"在漏测风险上的差别，并给出一个使前者反而更危险的场景； （d）设计一张"变更 → 重测"的自动触发规则（谁在什么时候填什么字段、失败怎么升级），并说明它与第 4 章 §5 的审查 gate 的关系。

  7. （开放题） 为你熟悉的某个 LLM 系统写一份运营期安全回路： （a）列出至少 6 个监控信号，每个给出基线、采样量、动作，并标出它接到 R 的哪一项； （b）选其中最关键的一个信号，写出它的控制图设计（用 CUSUM 还是 Shewhart、k 与 h 怎么定、ARL0​ 目标多少、MDE 多少）； （c）给出该系统的四个"收紧/放宽"动作与它们的 U,R，解出后验概率分区，并说明你打算怎么估 π； （d）给出一条复盘改进项的完整登记（指标、窗口、反事实、owner、deadline），并说明你打算用什么数据在 6 个月后判定它是否有效。

小结#

  • 运营期的目标是在不确定下把风险控制在 R∗ 之下并保持可用，不是"压到最低"。第 1 节的影子价格（4995.0 元/万元 <10000）说明继续买安全的边际回报低于成本，所以每一次收紧都要有判据。
  • 信号按 R 的因子分类：安全信号改 p、能力信号改 E、成本信号改 c、对手信号改 N。每个信号必须带基线、采样量、动作三个字段，缺一个就无法进入控制回路。
  • CUSUM 的 ARL 可以精确算（马尔可夫链 + 高斯消元）：n=200 条/天、k=3,h=6 时 ARL0​=434.95 天、对 2 倍漂移 ARL1​=6.19 天；同样卡在一年一次误报附近，Shewhart 图要 9.2 天。但漂移到 3 倍以上两者趋同（2.59 vs 2.54 天）—— CUSUM 买的是小漂移的灵敏度，代价是参数更多、解释更贵。
  • "持续监控"必须写成"每月多少样本、能看见多大的漂移"：误报预算从 196.84 天一次放宽到 2073.07 天一次，一周内可检出的 MDE 从 0.0181 退到 0.0211。更不容易误报 = 更晚发现。
  • "收紧还是放宽"是一个期望损失最小化问题：四个动作（放宽/不动/收紧/熔断）的后验概率分区阈值是 0.009901/0.062500/0.464286。熔断门槛比收紧门槛高 7.4 倍；在 π=0.1 时"报警就熔断"是亏的（56000.0 vs 15200.0 元/天）。迟滞带宽 0.05 把误切换从 365 次/年压到 4.5 次/年，代价是检测延迟从 6.19 涨到 13.19 天。
  • 复盘的核心量是复发率而不是闭环率：闭环率 0.7500 但复发率 0.4444，说明"闭环"定义太松。闭环的判据是"绑定的可观测指标已经移动"；而"改进有效"的可检验判据是 1−0.051/n —— T0​=90 天的机制要观测 365 天零复发，才能说间隔至少拉长到 122.34 天。这比任何发版周期都长，所以它必须登记成长期跟踪项。
  • 重测周期取 min(T对手增长​,T下一次变更​)：合成参数下 1675.0 天 vs 60.8 天 —— 跟着变更走，不跟着日历走。变更影响矩阵把全量 224 次裁到 115 次（省 48.66%）；G7 那一行全是 x，那必须是一个有意识的决定。
  • 与前四章的逐条呼应是本节（也是全课）的收束：R 的四个因子、对齐税、εeff​、区间与样本量、风险登记册、上线后审计 —— 每一个都要在运营期有一个会动的读数。接不上的那一项，就是这套体系真正会烂掉的地方。
  • 本节交付物四件：① §1.1 的四类信号表（含 R 因子的映射）；② §2 的 CUSUM 参数、ARL0​/ARL1​ 与 MDE 表；③ §3 的四动作期望损失表与后验概率分区 + 迟滞表；④ §4–§5 的复盘四量、1−0.051/n 判据与变更影响矩阵。

下一节：本章到此结束，也是全课的收束 —— 第 5 章的四节把前四章的零件装成了一台机器：第 1 节把 N,p,E,c 变成预算表（R=6057600.0、R∗=800000、等边际解 142.88 万元、影子价格 4995.0 元/万元），第 2 节把它装成一套设计并算出共线失效的 2.2677 倍低估（799938.1→1814046.9 元），第 3 节把它变成一张可执行的门禁表（八个 gate、FWER=0.336580、共线检出率 0.998800、期望损失几乎全由误阻构成），第 4 节把它交给一个会持续更新的控制回路（ARL0​=434.95 天、熔断门槛比收紧高 7.4 倍、复发率 0.4444、变更影响矩阵省 48.66%）。四节串起来一句话：安全设计不是把最强的防护叠起来，而是把每一个判断写成带来源的估计值、带样本量的判据、带代价与失效条件的层，然后在预算与可用性的约束下把它们组合起来、验收、并持续重新验收。 本课到此结束；接下来要做的事只有一件 —— 回到第 1 章的那张表，把每一个还是"估计值"的格子，换成实测。
