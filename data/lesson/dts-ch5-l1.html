数据并行（DP/DDP）：通信量、扩展效率与全局 batch 的限制#

前四章一直在算"一次通信要多久"。从这一课起问题反过来：给定模型和机器，到底该把什么切开？ 最容易想到、也最常用的答案是数据并行（Data Parallelism，DP）：每张卡拿不同的数据算同一个模型，最后把梯度加起来。它看起来几乎免费，却有两笔必须算清的账——每步要搬多少字节，以及全局 batch 变大之后优化上的收益递减。本课把这两笔账都变成可以打印的数字。

一、概念讲解#

1. 数据并行切什么：切样本，不切模型#

DP 的定义只有一句话：P 个 rank 各持一份完整的模型副本，各自吃不同的 mini-batch，反向得到本地梯度 gi​，再 AllReduce 求平均得到 gˉ​=P1​∑i​gi​，然后各 rank 用同一个 gˉ​ 独立更新。由于更新量完全相同，P 卡 DP 的每一步在数学上等价于"用 P 倍大的 batch 做单卡训练"。

这条等价关系决定了 DP 的性质：省的是时间，不省显存——参数、梯度、优化器状态在每个 rank 上全量复制。DeepSpeed 的 ZeRO 教程给过一个清楚的量级：1.5B 参数的 GPT-2，其 Adam 优化器状态就要 18 GB，在 32 GB 的 V100 上不开 ZeRO 直接 OOM（分给 8 个 rank 后降到 2.25 GB）。显存这本账留到第 6 章，此处只记：DP 不解决"装不下"，只解决"算太慢"。

本章要讲的五种切法，先建立一张地图，后面每课讲一种：

策略 切开哪个维度 每层通信模式 主要代价
数据并行 DP 样本（batch） 梯度 AllReduce 全局 batch 变大、优化收益递减
张量并行 TP 层内矩阵（hidden） 每层 4 次 AllReduce 通信在关键路径上，必须高带宽
流水线并行 PP 层（depth） 相邻 stage 点对点 气泡，设备空转
专家并行 EP MoE 的专家 每层 2 次 All2All 负载不均、token 丢弃
序列/上下文并行 SP/CP 序列维（激活、K/V） all-gather / reduce-scatter / ring 长序列的通信与因果负载不均

2. 每步通信量：2(P−1)/P⋅s#

第 2 课已经把 ring AllReduce 的结构拆过：它等于 reduce-scatter（P−1 步）+ all-gather（P−1 步），每步每个 rank 只发 s/P 字节（s 是梯度总字节数）。于是每个 rank 的发送量是

V_{\text{rank}} = 2(P-1)\cdot\frac{s}{P} = \frac{2(P-1)}{P}\,s,\qquad\rV_{\text{total}} = 2(P-1)\,s

代入第 2 课的 α-β 模型，ring AllReduce 的时间是 T≈2(P−1)(α+Pβs​)。注意这两项的命运不同：字节项 P2(P−1)​s 在 P 大时趋近 2s（与卡数无关），而延迟项 2(P−1)α 随 P 线性增长。所以"卡越多通信越贵"这句话，只有在消息小、α 主导时才成立。

用示例参数算一遍（s 取 7B 模型 fp16 梯度 = 14 GB，α=5 μs）：

链路（示例值） 25 GB/s 跨机 300 GB/s 节点内
P=64 的 AllReduce ≈ 1.10 s ≈ 92.5 ms
每 rank 发送量 2⋅63/64×14 GB≈27.6 GB 同左

报数时还要说清口径：nccl-tests 的 algbw 是"消息量/时间"，busbw（总线带宽）按 2(P−1)/P 折算，同一份数据两者相差约 2 倍（P 大时）。

3. 扩展效率：通信能不能被计算盖住#

DP 每卡每步的计算量是 6N⋅(B/P) FLOPs（含前向 2 与反向 4，N 为参数量，B 为全局 batch 的 token 数）；每卡通信字节是 P2(P−1)​⋅2N（fp16 梯度每个参数 2 B）。两者相除得到每个通信字节对应的计算量：

comm bytesFLOPs​=P2(P−1)​⋅2N6NB/P​=P−11.5B​

只有这个比值超过机器的平衡点 F/β（F 为每卡有效算力、β 为链路带宽），DP 才不被通信拖住。示例：每卡 312 TFLOPS 打四折 ≈ 125 TFLOPS，链路 25 GB/s，平衡点 5000 FLOP/B，于是 P≲1+1.5B/5000。全局 batch B=106 token 时上限约 301 卡——DP 的规模上限由 batch 大小决定，而不是由卡数决定。

PyTorch DDP 还会把通信藏进反向传播：内部 Reducer 按 bucket_cap_mb（默认 25 MiB）把梯度分桶，某桶就绪即异步 AllReduce，与仍在进行的反向重叠。这与第 4 课的"通信-计算重叠"是同一手法，也是 DP 比裸算更划算的原因。

4. 第二笔账：全局 batch 的收益递减#

P 卡 DP 把全局 batch 放大到 B=bmicro​×P× 累积步数。batch 变大后，优化上要做两件事：按线性 scaling 规则（Goyal 等，2017）把学习率同步放大，并加 warmup，否则训练初期会发散。但放大 batch 的收益有上限，其阈值由 gradient noise scale Bnoise​ 描述（McCandlish 等，2018）：

  • b≪Bnoise​：梯度噪声随 batch 近似按 1/b​ 下降，加倍 batch 几乎能减半步数，样本效率不变；
  • b≫Bnoise​：梯度已经很准，再加 batch 只是浪费样本，步数几乎不再下降。

示例 3 在合成回归问题上实测了这条曲线：Bnoise​≈32。batch 从 1 加到 8（8 倍），每步损失下降只涨 6.4 倍；加到 1024（1024 倍），只涨 31 倍——每样本收益从 1.00 掉到 0.03。通信账说"batch 越大越划算"，优化账说"大到某个点就白给"，并行方案要同时满足两条。

5. 常见坑#

  • 把"每步时间"当"每样本时间"：加卡后每步变快，但每样本耗时可能反升（通信占比变高）。
  • 只调学习率不加 warmup：线性 scaling 规则必须配 warmup，否则大 batch 初期发散。
  • 梯度累积忘了 no_sync()：PyTorch 里不套 model.no_sync()，每个 micro-step 都会 AllReduce 一次，累积 k 步就等于把通信量乘以 k。
  • 假设 DP 省显存：DP 一份都不省；省显存要靠 ZeRO/FSDP（第 6 章）。
  • 用 nvidia-smi 的理论带宽当 β：有效带宽通常明显更低，且随消息大小变化（第 2 课）。

二、可运行代码示例#

三段代码都不需要 GPU：第一段用 numpy 模拟 ring AllReduce 并核对 2(P−1)/P 的字节账；第二段算 DP 每步的计算/通信两本账；第三段在合成数据上实测 gradient noise scale。

# ===== 示例 1：numpy 模拟 ring AllReduce：数值正确性与通信量 =====
import numpy as np

def ring_allreduce(parts):
    """parts: P 个 rank 各自的完整梯度。返回 (归约结果, 每 rank 发出/收到字节数)。"""
    P = len(parts); n = parts[0].size; chunk = n // P
    assert n % P == 0, "先让元素数能被 P 整除，以便观察 chunk 级流水"
    itemsize = parts[0].itemsize
    sent = [0]*P; recv = [0]*P
    buf = [p.copy() for p in parts]
    for step in range(P - 1):                       # reduce-scatter：P-1 步
        nxt = [b.copy() for b in buf]
        for i in range(P):
            c = (i - step) % P                      # 本步该 rank 负责的 chunk
            dst = (i + 1) % P
            sl = slice(c*chunk, (c+1)*chunk)
            nxt[dst][sl] += buf[i][sl]              # 收到即累加（模拟同拍收发）
            sent[i] += chunk*itemsize; recv[dst] += chunk*itemsize
        buf = nxt
    for step in range(P - 1):                       # all-gather：P-1 步
        nxt = [b.copy() for b in buf]
        for i in range(P):
            c = (i + 1 - step) % P
            dst = (i + 1) % P
            sl = slice(c*chunk, (c+1)*chunk)
            nxt[dst][sl] = buf[i][sl]
            sent[i] += chunk*itemsize; recv[dst] += chunk*itemsize
        buf = nxt
    return buf, sent, recv

rng = np.random.default_rng(0)
P, n = 8, 8*1024                                # 8 个 rank，每份梯度 64 KiB（float64）
parts = [rng.normal(size=n) for _ in range(P)]
result, sent, recv = ring_allreduce(parts)
s_bytes = n*8
print("示例 1：ring AllReduce（P=8，每份梯度 64 KiB）")
print(f"  每 rank 结果一致且等于逐元素求和：{np.allclose(result[3], np.sum(parts, axis=0))}")
print(f"  每 rank 发出 {sent[0]} B = {sent[0]/s_bytes:.4f}·s（理论 2(P-1)/P = {2*(P-1)/P:.4f}）")
print(f"  每 rank 收到 {recv[0]} B = {recv[0]/s_bytes:.4f}·s")
print(f"  全组发送总量 {sum(sent)/s_bytes:.2f}·s（理论 2(P-1) = {2*(P-1)}）")

# ===== 示例 2：DP 一步的账本：通信时间与计算时间的比 =====
def dp_step(params, batch_tokens, P, tflops, beta_gbs, alpha_us=5.0, mfu=0.4):
    """params 单位 B（十亿参数）；按 6·N·tokens FLOPs 计（前向 2 + 反向 4）；
    通信为 fp16 梯度 2 B/参数，ring AllReduce 共 2(P-1) 步、每步 s/P。"""
    comp_ms = 6*params*1e9*(batch_tokens/P)/(tflops*1e12*mfu)*1e3
    s = 2*params*1e9
    comm_ms = 2*(P-1)*(alpha_us + (s/P)/(beta_gbs*1e9)*1e6)/1e3
    return comp_ms, comm_ms

print("\n示例 2：7B 模型的 DP 一步（全局 batch 100 万 token，每卡 312 TFLOPS@40% MFU，α=5 us）")
print("  P    每卡计算(ms)  跨机25GB/s 通信(ms)  节点内300GB/s 通信(ms)  跨机 计算占比")
for P in (8, 16, 32, 64, 128, 256, 512):
    c, m = dp_step(7, 1_000_000, P, 312, 25)
    _, m2 = dp_step(7, 1_000_000, P, 312, 300)
    print(f"  {P:<4} {c:12.2f} {m:21.2f} {m2:22.2f} {c/(c+m):14.1%}")
print(f"  计算/通信字节比 = 6·B/(4·(P-1))；要盖住 25 GB/s 链路（机器平衡点 5000 FLOP/B），"
      f"需 P ≲ {1+6*1_000_000/(4*5000):.0f}")

# ===== 示例 3：全局 batch 的收益递减（实测 gradient noise scale） =====
M, d = 4096, 32
X = rng.normal(size=(M, d)); w_true = rng.normal(size=d); y = X @ w_true
w0 = np.zeros(d)
loss = lambda w: ((X@w - y)**2).mean()
G = 2*X.T@(X@w0 - y)/M                             # 全量梯度
Gs = -2*y[:, None]*X                               # 每样本梯度（在 w0=0 处）
Sig = Gs.T@Gs/M - np.outer(G, G)                   # 每样本梯度协方差
H = 2*X.T@X/M
lmax = np.linalg.eigvalsh(H).max()
B_noise = np.trace(Sig)/(G@G)
print(f"\n示例 3：合成回归问题（{M} 样本、{d} 维）在起点处的 gradient noise scale")
print(f"  B_noise = tr(Σ)/|g|² = {B_noise:.1f}；λmax(H) = {lmax:.1f}")
print("  batch   每步损失下降   每 1k 样本下降   相对 b=1 的每样本收益")
base = None
for b in (1, 8, 32, 64, 128, 256, 512, 1024):
    lr = (1.0/lmax)/(1 + B_noise/b)                # 该 batch 下的最优步长
    drops = []
    for _ in range(400):                           # 400 次单步蒙特卡洛
        idx = rng.integers(0, M, size=b)
        g = 2*X[idx].T@(X[idx]@w0 - y[idx])/b
        drops.append(loss(w0) - loss(w0 - lr*g))
    dL = float(np.mean(drops)); per_k = dL/b*1000
    if base is None: base = per_k
    print(f"  {b:<7} {dL:12.6f} {per_k:15.6f} {per_k/base:17.2f}x")

三、练习#

  1. 实现：给示例 1 的 ring_allreduce 增加"每一步的并发发送字节数"统计，输出 P−1 步的数组；说明为什么前 P−1 步（reduce-scatter）与后 P−1 步（all-gather）的每步字节数相同。
  2. 解释：为什么每 rank 的发送量是 P2(P−1)​s，而不是 (P−1)s？把 P 换成 P2 时这个量怎么变？用它解释"ring AllReduce 的带宽项与卡数无关"。
  3. 对比/验证：把示例 2 的 β 改成 100 GB/s 与 300 GB/s，重算"仍能被计算盖住"的最大 P；再固定 P=256，问全局 batch 至少要多小才会撞上通信墙。
  4. 思考：设梯度累积 k=8、DP 度 P=16、每卡 micro-batch 32 个样本、序列长 4096。写出全局 batch（样本数与 token 数各是多少），并算出每个 optimizer step 的通信字节数与每个 micro-step 的通信字节数（提示：no_sync() 的作用）。
