语法分析：递归下降与 AST 构建#

token 流是平的，但程序的意义是嵌套的：a + b * 4 与 (a + b) * 4 的 token 序列只差一对括号，结构却完全不同。把扁平序列恢复成嵌套结构，是语法分析（parsing）的工作。这一课不讲"编译器前端 40% 的时间花在语法分析上"这类结论，而是给你一套能自己推着写完的方法：先写文法，再让文法逐条变成函数，树就自然长出来了。

一、概念讲解#

1. 上下文无关文法：把"合法结构"写成规则#

上下文无关文法（context-free grammar, CFG）由四部分组成：终结符（token 类型，如 NAME、+）、非终结符（语法范畴，如 expr、stmt）、产生式（一个非终结符如何展开）、开始符号。教科书用 BNF，工程里更常写 EBNF（*、+、?、| 直接进文法）：

program → stmt* EOF
stmt    → "var" NAME "=" expr ";"
        | NAME "=" expr ";"
        | "print" expr ";"
expr    → term (("+" | "-") term)*
term    → factor (("*" | "/") factor)*
factor  → NUM | NAME | "(" expr ")"

关键性质：产生式左边永远只有一个非终结符，怎么展开与"上下文"无关——这就是"上下文无关"的含义。它强到足以描述几乎所有编程语言的语句结构，又弱到能被高效解析。对比一下：第 1 课承认词法只能处理正则语言；这里允许递归（factor 里又能出现 expr），能力刚好覆盖嵌套括号。

2. 递归下降：让每条产生式变成一个函数#

递归下降（recursive descent）是 CFG 最直接的实现方式，映射规则几乎是机械的：

文法写法 代码写法
非终结符 X 函数 parse_X()，返回一个 AST 节点
产生式右侧的终结符 t eat(t)：匹配则前进，不匹配则报错
A B（连接） 顺序调用，前一个的返回值当后一个的输入
A | B（选择） 按当前 token 试分支（靠前瞻一个 token 就能决定）
A* / A+ while 循环
A?（可选） if

代价是：必须保证前瞻一个 token 就能选对分支。这带来三条常见修改——第一，去掉左递归：expr → expr "+" term 直接翻译会无限递归，改写成 expr → term ("+" term)*；第二，提出左公因子，让 A | B 的首 token 不相交；第三，若文法本身不是 LL(1)（比如悬空 else），要么加前瞻，要么改文法。这套"先写文法、再检查能否一遍前瞻"的流程，就是递归下降工程的日常。

3. 优先级与结合性住在文法层次里#

表达式优先级不是解析器里的 if 判断，而是文法分层的副产品：expr → term + term、term → factor * factor，层数越深、绑定越紧。这也解释了为什么"加除法"只要新加一层。

结合性则藏在一个很细的写法里：expr → term ("+" term)* 用循环迭代构建节点，a - b - 1 会依次左折叠成 ((a-b)-1)，是左结合；若把循环改成递归 expr → term "+" expr，同样三个 token 会变成 a-(b-1)，成了右结合。赋值的右结合（a = b = 1）就是后一种写法的真实用途。

4. AST 该长什么样#

抽象语法树（abstract syntax tree, AST）只保留结构、丢掉装饰：括号、分号、print 关键字都不进树，二元运算节点只留运算符与左右子树。与具体语法树（parse tree）的区别正是"抽象"二字——parse tree 忠实复现每个产生式步骤，节点多到没法用；AST 是下游语义分析、IR lowering 真正消费的形态。

节点设计有一条硬约束：一个节点的所有关键信息必须在树里，不能靠"回头再看 token"。比如 var 声明与赋值都写成 NAME "=" expr ";"，AST 必须用 declare 与 assign 两个 kind 区分开，否则语义分析无法判断这是"定义新变量"还是"改已有变量"。

二、可运行代码示例#

把第 1 课的扫描器和这一课的解析器接起来，就是一条最小的完整前端：源码 → token → AST → 求值。

# ---- 例 1：扫描器 + 递归下降解析器 → AST → 求值（纯标准库） ----
import re

TOKEN_RE = re.compile(r'[A-Za-z_]\w*|\d+(?:\.\d+)?|[<>=!]=|[-+*/(){}=;]')

def scan(src):
    tokens, i = [], 0
    while i < len(src):
        c = src[i]
        if c in ' \t\r\n':
            i += 1; continue
        if src[i:i + 2] == '//':                     # 行注释：直接跳到行尾
            i = src.find('\n', i); i = len(src) if i < 0 else i
            continue
        m = TOKEN_RE.match(src, i)
        if not m:
            raise SyntaxError(f'第 {src[:i].count(chr(10)) + 1} 行：非法字符 {c!r}')
        i = m.end(); text = m.group()
        if text.isidentifier():
            tokens.append(('NAME', text))            # 关键字本轮当普通名字处理
        elif text[0].isdigit():
            tokens.append(('NUM', float(text)))
        else:
            tokens.append(('OP', text))
    tokens.append(('EOF', 'EOF'))
    return tokens

class Node:
    def __init__(self, kind, *kids): self.kind, self.kids = kind, kids
    def __repr__(self):
        if not self.kids: return self.kind
        return '%s(%s)' % (self.kind, ', '.join(map(repr, self.kids)))

class Parser:
    """每个文法规则 = 一个函数；每条分支 = 一次 eat()。"""
    def __init__(self, tokens): self.toks, self.pos = tokens, 0

    def peek(self):    return self.toks[self.pos]
    def check(self, kind, value=None):
        k, v = self.peek()
        return k == kind and (value is None or v == value)
    def eat(self, kind, value=None):
        k, v = self.peek()
        if not self.check(kind, value):
            raise SyntaxError(f'期望 {kind}{value or ""}，实际是 {(k, v)}')
        self.pos += 1; return v

    def program(self):
        stmts = []
        while not self.check('EOF'):
            stmts.append(self.stmt())
        return Node('block', *stmts)

    # stmt → "var" NAME "=" expr ";" | "print" expr ";" | NAME "=" expr ";"
    def stmt(self):
        if self.check('NAME', 'var'):
            self.eat('NAME'); name = self.eat('NAME'); self.eat('OP', '=')
            value = self.expr(); self.eat('OP', ';')
            return Node('declare', name, value)
        if self.check('NAME', 'print'):
            self.eat('NAME'); value = self.expr(); self.eat('OP', ';')
            return Node('print', value)
        name = self.eat('NAME'); self.eat('OP', '=')
        value = self.expr(); self.eat('OP', ';')
        return Node('assign', name, value)

    # expr → term (("+"|"-") term)* ；term → factor (("*"|"/") factor)*
    # 循环迭代 = 左结合；若改成递归调用 expr 就变成右结合
    def expr(self):
        node = self.term()
        while self.check('OP', '+') or self.check('OP', '-'):
            op = self.eat('OP'); node = Node('bin', op, node, self.term())
        return node

    def term(self):
        node = self.factor()
        while self.check('OP', '*') or self.check('OP', '/'):
            op = self.eat('OP'); node = Node('bin', op, node, self.factor())
        return node

    # factor → NUM | NAME | "(" expr ")"
    def factor(self):
        if self.check('NUM'):
            return Node('num', self.eat('NUM'))
        if self.check('NAME'):
            return Node('var', self.eat('NAME'))
        if self.check('OP', '('):
            self.eat('OP', '('); node = self.expr(); self.eat('OP', ')'); return node
        raise SyntaxError(f'表达式起始处出现 {self.peek()}')

def evaluate(node, env):
    if node.kind == 'num': return node.kids[0]
    if node.kind == 'var': return env[node.kids[0]]
    if node.kind == 'bin':
        op, l, r = node.kids
        a, b = evaluate(l, env), evaluate(r, env)
        return {'+': a + b, '-': a - b, '*': a * b, '/': a / b}[op]
    if node.kind == 'block':
        for s in node.kids: evaluate(s, env)
        return None
    if node.kind == 'declare':
        env[node.kids[0]] = evaluate(node.kids[1], env); return None
    if node.kind == 'assign':
        env[node.kids[0]] = evaluate(node.kids[1], env); return None
    if node.kind == 'print':
        print('print →', evaluate(node.kids[0], env)); return None
    raise RuntimeError(node.kind)

SRC = '''var a = 2;
var b = 3;
print a + b * 4;      // 优先级：先乘后加
print (a + b) * 4;
c = a - b - 1;        // 左结合：等价于 (a - b) - 1
print c;'''
ast = Parser(scan(SRC)).program()
print('AST:', repr(ast))
evaluate(ast, {})

运行输出：

AST: block(declare('a', num(2.0)), declare('b', num(3.0)),
     print(bin('+', var('a'), bin('*', var('b'), num(4.0)))),
     print(bin('*', bin('+', var('a'), var('b')), num(4.0))),
     assign('c', bin('-', bin('-', var('a'), var('b')), num(1.0))), print(var('c')))
print → 14.0
print → 20.0
print → -2.0

三行输出把两件事同时验证了：a + b * 4 的树里 * 在 + 下面（优先级生效），c = a - b - 1 的树是左折叠（左结合生效）。AST 里没有括号、没有分号——结构已经说明了全部，这正是"抽象"的收益。

代码里有一处为求短小而故意留下的漏洞：扫描器把关键字当普通 NAME，stmt 靠字面值是否等于 var／print 来分支。于是 var var = 1; 会被接受、var = 1; 会被当成声明。真实做法是让扫描器把关键字标成独立类型（第 1 课的 KEYWORDS 表），stmt 只认类型——词法与语法各守各的边界。

三、练习#

  1. 实现：给文法加 if expr { stmt* } else { stmt* }，写出对应产生式并实现 stmt 的新分支。提示：先想清楚 expr 与 { 两个首 token 是否足以一次前瞻选对分支。
  2. 解释：为什么 expr → expr "+" term 这种左递归写法直接翻译成函数会栈溢出？改写成 term ("+" term)* 之后，语义为什么不变？
  3. 对比：把 expr 的循环改写成递归调用（a - b - 1 变成右结合），打印两种 AST 并解释 evaluate 结果差在哪。
  4. 思考：var 与赋值共用 NAME "=" expr ";" 的 token 形状，为什么必须在 AST 层用 declare / assign 区分？如果不区分，后面的作用域与类型检查会出什么问题？
