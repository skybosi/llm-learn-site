一、目标与步骤#

本课要完成的四步，对应最终报告的四块内容：

  1. 特征工程：缩放、编码、构造时间/金额衍生特征。
  2. 基线 + 多模型对比：从 Logistic 回归到 XGBoost/LightGBM，用一致的交叉验证口径打分。
  3. 超参数调优：用 Optuna 对树模型调参，关注"不平衡下的指标选择"。
  4. 阈值与业务换算：把概率转成"可用/不用"的业务决策。

先统一口径：由于正类极稀，所有模型的对比指标都用 AUC-PR 与 AUC-ROC，绝不看 Accuracy。

二、代码骨架与实现指导#

1. 特征工程#

欺诈数据的 28 个 V 特征已经过 PCA 匿名化（近似无量纲），真正需要处理的是 Time 与 Amount：

import numpy as np
import pandas as pd
from sklearn.preprocessing import RobustScaler

def build_features(df):
    """在原始特征上做工程，返回特征矩阵 X 与标签 y。"""
    df = df.copy()

    # 金额：长尾分布，用 RobustScaler 比 StandardScaler 更抗极端大额交易
    df["Amount_scaled"] = RobustScaler().fit_transform(
        df["Amount"].values.reshape(-1, 1)
    )

    # 时间：把秒级时间戳转成"一天内的时刻"，捕捉交易时间规律
    df["hour"] = (df["Time"] // 3600) % 24          # 0~23 点
    df["is_night"] = (df["hour"] >= 0) & (df["hour"] < 6)  # 凌晨交易标志

    # 可选：金额的粗分箱交叉特征（面试时说明"为何构造"即可）
    df["amount_bucket"] = pd.qcut(df["Amount"], 4, labels=False, duplicates="drop")

    feature_cols = [c for c in df.columns if c.startswith("V")]
    feature_cols += ["Amount_scaled", "hour", "is_night", "amount_bucket"]
    X = df[feature_cols]
    y = df["Class"]
    return X, y

说明：匿名特征已标准化，一般不必再整体缩放；但如果想统一量纲，可对 V 列再套一层 StandardScaler。这里的重点不是"堆特征"，而是每一步都有理由——面试时你要能解释为什么对 Amount 用鲁棒缩放。

3. 基线 + 多模型对比#

用一个统一的评分函数，把各模型放进同一口径对比：

from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import roc_auc_score, average_precision_score
import xgboost as xgb
import lightgbm as lgb

def evaluate_cv(model, X, y, cv):
    """用时间序列 CV 计算 AUC-ROC 与 AUC-PR 的均值/标准差。"""
    rocs, prs = [], []
    for tr_idx, va_idx in cv.split(X):
        model.fit(X.iloc[tr_idx], y.iloc[tr_idx])
        proba = model.predict_proba(X.iloc[va_idx])[:, 1]
        rocs.append(roc_auc_score(y.iloc[va_idx], proba))
        prs.append(average_precision_score(y.iloc[va_idx], proba))
    return np.mean(rocs), np.std(rocs), np.mean(prs), np.std(prs)

# 注意：LogisticRegression 对类别不平衡敏感，可加 class_weight='balanced'
models = {
    "LogisticRegression": LogisticRegression(max_iter=1000, class_weight="balanced"),
    "RandomForest": RandomForestClassifier(
        n_estimators=200, class_weight="balanced", n_jobs=-1, random_state=42
    ),
    "XGBoost": xgb.XGBClassifier(
        n_estimators=500, learning_rate=0.1, max_depth=6,
        scale_pos_weight=99,  # 正负样本权重：约 (1-0.0017)/0.0017
        eval_metric="aucpr", tree_method="hist", n_jobs=-1, random_state=42
    ),
    "LightGBM": lgb.LGBMClassifier(
        n_estimators=500, learning_rate=0.1, num_leaves=31,
        scale_pos_weight=99, n_jobs=-1, random_state=42
    ),
}

X, y = build_features(train_df)
for name, model in models.items():
    roc_m, roc_s, pr_m, pr_s = evaluate_cv(model, X, y, tscv)
    print(f"{name:20s} AUC-ROC={roc_m:.4f}(±{roc_s:.4f})  AUC-PR={pr_m:.4f}(±{pr_s:.4f})")

预期结果方向：树模型（XGBoost/LightGBM）显著优于线性基线；随机森林居中。如果你跑出来的顺序不是这样，先查数据泄漏，再谈调参——顺序异常本身就是最该警惕的信号。

4. Optuna 超参数调优#

以 LightGBM 为例，用 Optuna 在验证集上做贝叶斯搜索（比 GridSearch 快一个量级）：

import optuna
from sklearn.metrics import average_precision_score

def objective(trial):
    params = {
        "n_estimators": trial.suggest_int("n_estimators", 200, 1500),
        "learning_rate": trial.suggest_float("learning_rate", 0.01, 0.3, log=True),
        "num_leaves": trial.suggest_int("num_leaves", 8, 128),
        "min_child_samples": trial.suggest_int("min_child_samples", 10, 200),
        "subsample": trial.suggest_float("subsample", 0.5, 1.0),
        "colsample_bytree": trial.suggest_float("colsample_bytree", 0.5, 1.0),
        "scale_pos_weight": trial.suggest_float("scale_pos_weight", 10, 200),
    }
    model = lgb.LGBMClassifier(**params, n_jobs=-1, random_state=42)
    model.fit(X.iloc[tr_idx], y.iloc[tr_idx])
    proba = model.predict_proba(X.iloc[va_idx])[:, 1]
    return average_precision_score(y.iloc[va_idx], proba)  # 用 AUC-PR 作优化目标

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=50, show_progress_bar=True)
print("最优 AUC-PR:", study.best_value)
print("最优参数:", study.best_params)

调参原则：先粗后细。先固定 learning_rate 用少量 n_estimators 快速扫出大致区间，再在最优附近细化。避免一上来就 500 次 trial 烧时间，且容易在验证集上过拟合。

5. 阈值选择与业务换算#

模型输出的是概率，业务要的是"拦还是不拦"。用验证集选阈值：

from sklearn.metrics import precision_recall_curve

proba = best_model.predict_proba(X.iloc[va_idx])[:, 1]
precision, recall, thresholds = precision_recall_curve(y.iloc[va_idx], proba)

# 业务假设：拦一笔真欺诈省 1000 元，误拦一笔正常交易损失 50 元（客服+流失）
# 目标：最大化 收益 = 1000 * TP - 50 * FP，等价于在 PR 曲线上找最优工作点
cost_fp, cost_fn = 50, 1000  # 误报成本、漏报成本
optimal_idx = np.argmax(
    (recall[:-1] * cost_fn * pos_count) - ((1 - precision[:-1]) * cost_fp * neg_count)
)
best_threshold = thresholds[optimal_idx]
print(f"推荐阈值: {best_threshold:.4f}, 对应 Recall={recall[optimal_idx]:.4f}, "
      f"Precision={precision[optimal_idx]:.4f}")

这段是面试的"分水岭"：绝大多数候选人只报 AUC，而你能回答"这个模型上线该用什么阈值、为什么"。

三、验收与复盘#

  1. 口径一致性验收：四个模型是否都用了同一套 CV 划分、同一组 X/y、同两个指标？口径不一，对比表就无意义。
  2. 结果合理性验收：树模型是否明显优于线性基线？AUC-PR 是否远低于 AUC-ROC（这正是"不平衡"的体现，说明指标选对了）？
  3. 可复现验收：固定 random_state 后重跑一遍，结果是否稳定？误差是否在一个可接受区间内？
  4. 复盘提示：把本课的对比表、最优参数、推荐阈值整理进 reports/。下一课将基于这些产出做特征重要性分析与面试话术，本课的每张表都会成为面试时"你做了什么"的证据。
