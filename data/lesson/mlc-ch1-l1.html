框架执行的三个代价：算子边界、内存搬运、动态开销#

编译原理课的经验是"能编译一次，就不要每次解释"。深度学习框架的默认执行恰好相反：y = relu(x * 2 + 2) 被拆成乘、加、relu 三次独立算子调用，每次都要付"框架派发 + 内核下发 + 一份中间张量"。链越长，真正在算的时间占比越低——瓶颈不在单个算子里，而在算子与算子的缝里。这条缝就是本课要拆的三笔账：算子边界、内存搬运、动态开销。

一、概念讲解#

1. 三个代价不是同一件事#

代价 从哪来 何时占主导 修法 后续
算子边界 每次调用的固定成本（派发、形状推导、内核下发） 算子小、算子多 融合、图执行 第 5 章
内存搬运 中间结果写回显存再读出 逐元素、带宽受限算子 融合、布局、复用 第 4、5 章
动态开销 逐条解释与派发、形状检查 算子多而每个都小 捕获成图、编译缓存 第 2、8 章

总账（t_dispatch 派发、t_launch 内核下发，均与大小无关）：

Teager​=i=1∑L​(tdispatch,i​+tlaunch,i​+tkernel,i​),Tfused​≈tdispatch​+tlaunch​+max(Tmem​,Tcompute​)

固定成本从"每算子一份"变成"整条链一份"，这就是融合的收益来源。

2. 代价一：算子边界，与张量大小无关的固定成本#

eager（即时执行）下每次调用至少要：派发到具体实现、校验并推导输出 shape/dtype/device、分配输出张量，GPU 上再加一次 kernel 下发——这些成本与张量大小无关。

推论很直接：当 t_kernel 已与固定成本同量级时，继续打磨内核收益极小，把三个算子合成一个却能省掉两份固定成本。这也解释了一个反直觉现象：合并小算子往往比逐个调优小内核更有效。本课代码把两项成本分开量：张量缩到 1 个元素时，测出的几乎只剩固定成本。

3. 代价二：内存搬运，中间结果写回再读出#

设链上有 L 个逐元素算子、张量 M 个元素、每元素 w 字节：eager 总访存 2LMw，融合后只有 2Mw，比值恰好是 L；而 Tmem​=2Mw/BW。

用 roofline 的话说：算术强度（每搬 1 字节能做多少次浮点运算）决定算子站在带宽一侧还是算力一侧。逐元素算子的强度是个与 M 无关的常数，永远落在带宽一侧——矩阵再大也"在等数据"。归约算子更亏：softmax 要读三遍（求 max、求 exp 与和、再归一化），这正是 CUDA 课里 FlashAttention"在线 softmax + 分块"要解决的账。融合也有前提（依赖结构、归约维度、布局一致），见第 5 章。

4. 代价三：动态开销，热路径上站着一个解释器#

eager 下每写一行算子调用，就要走一遍 Python 字节码、属性查找、参数打包，再进框架的 C++ 派发层做 dtype/device/shape 校验、广播判断、autograd 建图、分配器调用；而模型恰恰由成百上千个小算子组成。

症状是：每个内核都不慢，内核之间却有大段空隙；GPU 利用率低而 CPU 单核跑满（host-bound）。诊断要看时间线上的 gap，不是内核时长。也别全归给"Python 慢"——C++ 派发与分配器占相当比例，换前端语言未必解决；正解是"捕获一次、执行多次"（第 2 章）。

5. 三个代价会互相拉扯#

  • 融合省了边界与搬运，却把多个中间值同时压进寄存器，可能推高寄存器压力与显存峰值（第 5 章）。
  • 捕获成图能消掉动态开销，但捕获不全（图断裂）时只能分段退回 eager，收益按段打折（第 2 章）。

6. 常见坑#

  • 只看内核时长：内核之间的空白同样是你的时间，且往往才是大头。
  • 把"算子少"当"一定快"：大算子也可能纯带宽受限，融合过头还会溢出寄存器。
  • 直接比 wall-clock：不预热、不对齐同步、不固定 dtype 与形状，测到的只是噪声。

二、可运行代码示例#

下面只用 numpy，不需要 GPU、不需要 torch（本机 python 3.10.16 + numpy 1.26.2 实跑）：① 量出一次算子调用的净固定开销；② 量出元素级算子的可持续带宽；③ 按张量大小对照两项成本、找出分界点，再给出链长 L 下 eager 与融合的访存账。

# ===== 第 1 课示例：三个代价的可打印账 + 本机实测"固定开销 vs 访存" =====
# 只用 numpy（本机 python3.10 + numpy 1.26.2 验证），不需要 GPU、不需要 torch。
# 所有计时都取"多次测量中的最小值"（见 best_of）：噪声只会让某次变慢，不会让它变快。
import sys
import time

import numpy as np

print(f"环境：python {sys.version.split()[0]}，numpy {np.__version__}（纯 CPU 即可跑完）")


def best_of(fn, reps, trials=5):
    """取多次测量的最小值：机器噪声只会让某次变慢，不会让它变快，所以 min 更接近真实成本。"""
    best = float('inf')
    for _ in range(trials):
        t0 = time.perf_counter()
        for _ in range(reps):
            fn()
        best = min(best, (time.perf_counter() - t0) / reps)
    return best

# ---------- 1. 实测"一次算子派发"的固定开销 ----------
# size-1 张量做加法：计算量可忽略，测到的几乎全是"派发 + 分配 + 形状检查"的固定成本。
N_REP = 200_000
a1 = np.zeros(1, dtype=np.float32)
b1 = np.zeros(1, dtype=np.float32)
for _ in range(1000):
    a1 + b1

t_disp = best_of(lambda: a1 + b1, N_REP)
t_loop = best_of(lambda: None, N_REP)

print("\n=== 代价一：算子边界的固定开销（实测）===")
print(f"  空循环                 {t_loop * 1e6:6.3f} µs/次")
print(f"  size-1 张量一次加法     {t_disp * 1e6:6.3f} µs/次")
print(f"  → 净固定开销 ≈         {(t_disp - t_loop) * 1e6:6.3f} µs/次（与张量大小无关）")

# ---------- 2. 实测元素级算子的可持续访存带宽 ----------
M_BIG = 16_000_000                  # float32 → 64 MB 张量
x = np.zeros(M_BIG, dtype=np.float32)
for _ in range(3):
    y = x + 1.0                     # 预热

t_add = best_of(lambda: x + 1.0, 5)
bytes_big = 2 * M_BIG * 4           # 读 x 一遍 + 写 y 一遍
bw = bytes_big / t_add

print("\n=== 代价二：元素级算子吃掉的是带宽（实测）===")
print(f"  {M_BIG:,} 元素加法       {t_add * 1e3:6.2f} ms/次")
print(f"  访存量                 读 {M_BIG * 4 / 1e6:.0f} MB + 写 {M_BIG * 4 / 1e6:.0f} MB = {bytes_big / 1e6:.0f} MB")
print(f"  → 可持续有效带宽 ≈      {bw / 1e9:.1f} GB/s（本机实测；机器不同数值就不同）")
print(f"  算术强度 = 2*M FLOPs / {bytes_big / 1e6:.0f} MB = {2 * M_BIG / bytes_big:.2f} FLOP/Byte")
print("  → 这个强度与 M 无关：元素级算子永远站在 roofline 的带宽一侧")

# ---------- 3. 扫张量大小：固定开销什么时候被访存淹没 ----------
print("\n=== 固定开销占比随张量大小变化（实测 + 实测带宽折算）===")
print(f"{'M':>10} {'实测耗时(µs)':>13} {'访存折算(µs)':>13} {'推定固定开销(µs)':>17} {'固定开销占比':>13}")
for m in (1, 10 ** 2, 10 ** 3, 10 ** 4, 10 ** 5, 10 ** 6, 10 ** 7):
    xs = np.zeros(m, dtype=np.float32)
    for _ in range(5):
        ys = xs + 1.0
    reps = max(3, min(200, 2_000_000 // m))
    t_meas = best_of(lambda: xs + 1.0, reps)
    t_mem = (2 * m * 4) / bw                  # 按实测带宽折算的纯访存时间
    fixed = max(t_meas - t_mem, 0.0)
    print(f"{m:>10,} {t_meas * 1e6:>13.3f} {t_mem * 1e6:>13.3f} {fixed * 1e6:>17.3f} {fixed / t_meas:>12.1%}")

m_star = t_disp * bw / 8                      # 解 t_disp = (2*M*4)/bw
print(f"  交叉点：M ≲ {m_star:,.0f} 个元素时，固定开销 ≥ 一次加法的访存时间")
print("  注：上表最后几行的「推定固定开销」被夹到 0 附近（偶发几个百分点残差来自系统噪声），")
print("      不是真的没有开销，而是这些尺寸下实测已经贴住、甚至快过按 16M 元素标定的带宽模型")
print("      （数据进了 cache、分配器复用）。这正是第 6 章要讲的：代价模型永远是近似，")
print("      只能用来给候选排序，不能当绝对值用。")

# ---------- 4. 链式元素级算子：eager 与融合的账 ----------
M_CHAIN = 1_000_000
print(f"\n=== 三个代价合起来：M={M_CHAIN:,} 元素的逐元素算子链，长度 L ===")
print(f"{'L':>3} {'eager kernel':>13} {'eager 访存(MB)':>15} {'融合 kernel':>12} "
      f"{'融合访存(MB)':>13} {'访存比':>7}")
for L in (2, 4, 8, 16):
    eager_b, fused_b = 2 * L * M_CHAIN * 4, 2 * M_CHAIN * 4
    print(f"{L:>3} {L:>13} {eager_b / 1e6:>15.1f} {1:>12} {fused_b / 1e6:>13.1f} {eager_b / fused_b:>7.1f}")

print(f"\n  融合省下的访存时间（按实测 {bw / 1e9:.1f} GB/s 折算，M={M_CHAIN:,}）：")
for L in (2, 4, 8, 16):
    saved = (2 * L * M_CHAIN * 4 - 2 * M_CHAIN * 4) / bw
    print(f"    L={L:>2}：省 {saved * 1e3:6.2f} ms（占原耗时 {1 - 1 / L:6.1%}）")
print(f"  逐元素链的访存随 L 线性增长，融合后与 L 无关：收益上界就是「省掉 L−1 次往返」。")

print("""
读法：
  1) 固定开销与张量大小无关 → 小算子被它主导、大算子被带宽主导，第 3 节那张表把分界点量出来了；
  2) 逐元素链的 kernel 数与访存都随链长 L 线性增长，融合后都变成常数；
  3) 两项占比告诉你该优化哪个：固定占比高 → 先减算子边界（捕获 + 融合 + 图执行）；
     访存占比高 → 先降搬运（融合 + 布局 + 内存复用）。""")

读法：
  1) 固定开销与张量大小无关 → 小算子被它主导、大算子被带宽主导，第 3 节那张表把分界点量出来了；
  2) 逐元素链的 kernel 数与访存都随链长 L 线性增长，融合后都变成常数；
  3) 两项占比告诉你该优化哪个：固定占比高 → 先减算子边界（捕获 + 融合 + 图执行）；
     访存占比高 → 先降搬运（融合 + 布局 + 内存复用）。

三张表对照着读。同一段加法，张量 1 个元素要 0.23 µs、1600 万元素要 4.68 ms：大小差七个数量级，耗时只差四个数量级，差额正是那个与大小无关的固定项。第 3 节把分界点量在不到一千个元素（本次 781）：比它小，固定开销就是全部；比它大，访存说了算。第 4 节则是纯代数账：L 个逐元素算子融合成一次遍历，访存恰好降到 1/L。

三、练习#

  1. 实现：把第 3 节的扫描扩到 M = 10**8，记录每次加法的有效带宽；解释带宽为何随 M 先升后稳，而固定开销占比单调下降。
  2. 解释：为什么净固定开销要用"size-1 耗时 − 空循环耗时"，而不是直接用 size-1 耗时？
  3. 对比/验证：对 L=2..16 假设固定成本 c 为 1 / 5 / 10 µs，算出融合收益里"省边界"与"省搬运"各占多少；何时省边界才是主要收益？
  4. 思考：若模型有 2000 个小算子、每个处理 104 个元素，三个代价里哪个最可能是主瓶颈？把 104 改成 107 后结论怎么变？
