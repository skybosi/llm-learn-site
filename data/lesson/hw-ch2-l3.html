显存层次（HBM/L2/寄存器）#

前面两课都在讲"算"，这一课讲"存"。硬件里有一条残酷的规律：存储越快，离计算越近，容量就越小。GPU 用一层层的存储堆出一个"金字塔"，用容量换速度、用局部性换带宽。理解这个金字塔，是后面判断"推理为什么卡在带宽上"的前提。

一、概念讲解#

1. 存储金字塔#

从快到慢、从小到大，GPU 的存储层次大致是：

  1. 寄存器（Register）：每个线程私有，速度最快、容量最小；
  2. 共享内存 / L1 缓存（Shared Memory / L1）：SM 内共享，片上 SRAM；
  3. L2 缓存：整块芯片所有 SM 共享；
  4. HBM 显存：片外，容量大、带宽高但仍远慢于片上；
  5. 主机内存：通过 PCIe / NVLink 连接，最慢。

2. 各层容量与带宽的量级（以 H100 为例）#

层级 容量（量级） 速度/带宽（量级） 谁在用
寄存器 256 KB / SM 极快（纳秒级、片上） 单个线程的临时变量
共享内存 / L1 约 228 KB / SM 极快（片上，TB/s 级） SM 内线程共享、数据复用
L2 缓存 50 MB 快（数 TB/s） 全芯片共享、跨 SM 复用
HBM 80 GB 3.35 TB/s 权重、激活、KV cache

规律一目了然：离 SM 越近越快越小，离得越远越慢越大。寄存器、共享内存、L2 加起来也就几十 MB 量级，而权重动不动就是几十上百 GB——这就是矛盾所在。

3. 为什么要分层：局部性与复用#

存储分层的依据是程序的两种局部性：

  • 时间局部性：刚用过的数据很快会再用（分块里的矩阵小块）；
  • 空间局部性：相邻的数据会被一起访问（数组顺序读取）。

把热点数据放进片上小存储反复复用，就能大幅减少对慢速 HBM 的访问。上一课讲的 GEMM 分块，正是靠共享内存实现这种复用。

4. 推理的残酷现实：权重放不进片上#

问题来了：大模型的权重是几十上百 GB，任何片上存储都装不下。于是每生成一个 token，权重都要从 HBM 完整读一遍。HBM 的 3.35 TB/s 看起来很大，但除以 140 GB 的权重，也不过每秒 20 多次——这就是大模型推理吞吐的天花板（第 4 章会严格推导）。存储金字塔直接解释了"推理为什么是访存密集"。

5. 容量 vs 带宽：两个不同的瓶颈#

最后务必分清两个概念：

  • 容量决定"能不能装下"：80 GB 的 H100 装不下 175B 的 FP16 模型（350 GB）；
  • 带宽决定"装下后跑多快"：装得下 70B（140 GB），但每秒也只能读 20 多遍。

两者都会卡人，但卡的方式不同。选卡、选精度、做优化，都是在和这两个数打交道。

二、可运行代码示例#

把存储金字塔量化，并亲手算出"读一遍权重要多久"。

# ---- 例 1：H100 存储层次速查表 ----
h100_memory = {
    "寄存器(每SM)":       {"容量": 256e3,    "带宽 TB/s": None,  "位置": "片上/最快"},
    "共享内存+L1(每SM)":  {"容量": 228e3,    "带宽 TB/s": None,  "位置": "片上"},
    "L2 缓存":            {"容量": 50e6,     "带宽 TB/s": 5.5,   "位置": "片上/全芯片共享"},
    "HBM 显存":           {"容量": 80e9,     "带宽 TB/s": 3.35,  "位置": "片外"},
}
for name, spec in h100_memory.items():
    print(f"{name}: 容量 {spec['容量']/1e6:.0f} MB, 带宽 {spec['带宽 TB/s']} TB/s")

# ---- 例 2：读一遍不同大小的模型，要多久 ----
def read_time(bytes_needed, bw_tb_s):
    return bytes_needed / (bw_tb_s * 1e12)

for name, params in {"7B": 7e9, "8B": 8e9, "70B": 70e9}.items():
    weight_bytes = params * 2   # FP16，每参数 2 字节
    t = read_time(weight_bytes, 3.35)
    print(f"模型 {name}（FP16 {weight_bytes/1e9:.0f} GB）在 H100 读完一遍 ≈ {t*1e3:.1f} ms")

# ---- 例 3：容量瓶颈 vs 带宽瓶颈 ----
def capacity_bound(params, bytes_per_param, capacity_gb):
    return params * bytes_per_param <= capacity_gb * 1e9

for name, params in {"70B": 70e9, "175B": 175e9}.items():
    fits = capacity_bound(params, 2, capacity_gb=80)
    print(f"H100 80GB 能否装下 {name} FP16 模型? {'能' if fits else '不能'}")

# ---- 例 4：片上复用 vs 片外访问的差距 ----
# 共享内存/L1 的片上带宽可达 TB/s 级，远快于 HBM。
# 假设片上带宽约 10 TB/s，HBM 3.35 TB/s，做一次"读 1KB"的对比：
def latency_proxy(bw_tb_s):
    return 1024 / (bw_tb_s * 1e12)   # 理想化：读 1KB 的时间下限

print(f"\n读 1KB 的理想下限：片上(10TB/s) ≈ {latency_proxy(10)*1e9:.1f} ns，HBM(3.35TB/s) ≈ {latency_proxy(3.35)*1e9:.1f} ns")

要点：例 2 是本课最重要的一行输出——70B 模型读一遍约 42 毫秒，意味着即便算力无穷大，H100 每秒最多也只能为它服务约 24 次。例 4 强调片上与片外的巨大差距，说明"把数据留在片上复用"是优化的核心手段。

三、练习#

  1. 排序：把寄存器、L2、HBM、主机内存按"带宽从大到小"排序，并说明每层分别解决什么问题。
  2. 计算：H200 的 HBM 带宽是 4.8 TB/s、容量 141 GB。用 read_time 算它读完一个 70B FP16 模型（140 GB）要多久，对比 H100 快了多少。
  3. 判断：一块 24 GB 的显卡能装下 13B 的 FP16 模型吗？装下 13B 的 INT8（每参数 1 字节）模型吗？分别说明是"容量卡住"还是"能装下但带宽受限"。
  4. 思考：为什么权重明明读一遍还要读第二遍（每生成一个 token 都要重读）？如果能把权重常驻在片上，推理速度会怎样变化？结合片上与 HBM 的带宽差说明。
