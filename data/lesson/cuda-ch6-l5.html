算子正确性验收：与参考实现逐元素对齐（容差与随机用例）#

前四课写出来的四类算子都"能跑"，但"能跑"和"算对了"之间隔着一条必须用数字填平的沟：GPU 上的累加顺序与参考实现不同，浮点加法又不满足结合律，所以逐位相等几乎永远不成立。验收的全部技术含量就在于：选对参考实现、选对误差度量、把容差定成有依据的数、再用一组能真正触发 bug 的用例去打它。这一课把这条链做成一个可复用的检查脚本：参考实现、误差度量、容差判定、用例矩阵四步，也是第 8 章项目报告的必备脚手架。

一、概念讲解#

1. 三层参考实现，各有各的"可信度"#

  • 高精度 oracle：把输入提升到 float64 再算一遍，它决定"真值"的可信度；但它自己不是标准答案——被测 kernel 只能用 float32。
  • 独立实现：框架自带算子（A@B 走 BLAS）或另一种算法的实现。它能抓"两边都错得一样"的共模错误。
  • 手算小例子：2×2 矩阵、N=4 的 scan，纸笔算完写进测试。它不管精度，但唯一能定位逻辑错。

三层要一起用：手算例子发现逻辑错，高精度 oracle 定位误差量级，独立实现防共模错误。

2. 误差度量：绝对、相对、ULP#

度量 定义 什么时候用 陷阱
绝对误差 ∣y−y^​∣ 值域已知且同量级（如概率、经过 tanh 的量） 值域大时完全没意义
相对误差 ∣y−y^​∣/∣y∣ 值远离 0 时 分母接近 0 时爆炸
混合准则 ∣y−y^​∣≤atol+rtol⋅∣y^​∣ 工程默认，同时盖住 0 附近与大量级 两个常数都要有依据
ULP 两个 float32 位模式的整数距离 判断"离参考差几个可表示数" 参考值接近 0 时 ULP 会异常大

不要只报最大值：单个离群元素（参考值 10−6 而绝对差 10−4）会把相对误差的 max 抬到 102，制造假警报。下一节的脚本同时报中位数、90 分位与 ">10 ULP 的元素个数"，三者合起来才能区分"整体漂移"与"个别离群"。

3. 误差随 K 增长：容差必须写得出依据#

float32 的机器 epsilon 约 1.19×10−7（2−23）。逐点累加的误差界随项数 K 线性增长（∣err∣≲Kε∑∣ai​bj​∣），成对/树形累加按 log2​K 增长。于是：

  • 同一个 kernel，K=16 时 max 绝对误差 2.1×10−6，K=1024 时涨到 1.3×10−4——容差不能是与 K 无关的常数；
  • Kahan 补偿求和把 K=1024 的中位 ULP 从 6 压到 0，代价是每步多 3 次浮点操作；
  • --use_fast_math 与内建 __expf 类函数会牺牲精度换吞吐：一旦打开，容差必须随之放宽，并写进报告。

4. 为什么"可复现"比"逐位对齐"更重要#

atomicAdd、--use_fast_math、不同 tile 尺寸都会改变加法顺序，因此同一份输入两次运行可能得到不同结果。验收要区分统计复现（误差始终在容差内，默认要求）与逐位复现（两次运行完全相同，只在回归基线/结果审计时需要，手段是固定归约树、禁掉非确定性原子加）。第 5 章"原子操作没有顺序保证"这一条，在这里落成一条具体验收条款。

5. 用例矩阵：别用一个漂亮形状交差#

维度 要覆盖的取值 想抓的 bug
形状 全 1、M=1、N=1、非 2 的幂（17/33/65）、小于一个 tile 边界判断、越界、tile 裁剪
K K=1、K<bk​、K 不是 bk​ 的倍数 尾段处理、MMA 形状约束
数值 全 0、全同一值、含 NaN/Inf、量级悬殊 污染传播、上溢下溢、除零
数据类型 fp32 / fp16 / bf16 输入、fp32 累加 累加器精度不足

污染用例要单独设计：一个 NaN 输入会把整个 K 维输出行变成 NaN（下一节实测 64/4096），随机数据几乎撞不上它。

6. 常见坑#

  • 用 == 比较 GPU 结果与参考：必然失败，且失败与实现质量无关。
  • 容差定成"跑通为止"：会把真实 bug 一起放过（如漏算 1/4 输出列，下面实测违规 25%，应该被抓到）。
  • 只测一个随机形状：随机形状几乎不命中边界分支，覆盖率是假的。
  • 忽略 NaN 检查：np.allclose 默认把 NaN 当不相等（好事），但自己写的"取 max"会被 NaN 静默传染。
  • 参考实现自身有 bug：手算用例是唯一兜底；每个算子至少留一个纸笔可验证的小例子。

二、可运行代码示例#

需要 numpy（本机 python3.10 + numpy 1.26.2 验证）。脚本给出：float32 GEMM 的两种累加顺序、ULP 统计、混合容差判定、边界/污染用例、以及"分段顺序改变 ULP"的实测。

# ===== 本课示例：正确性验收工具 —— float32 参考、ULP 度量、容差判定、边界与污染用例 =====
import numpy as np

# ---------- 1. 误差度量：绝对 / 相对 / ULP ----------
def ulp_diff(a, b):
    """按 IEEE754 位模式的整数距离计算 ULP —— 比相对误差更适合看"差几个可表示数"。"""
    ai = np.asarray(a, np.float32).view(np.int32).astype(np.int64)
    bi = np.asarray(b, np.float32).view(np.int32).astype(np.int64)
    return np.abs(ai - bi)

def report(name, got, ref64):
    got = np.asarray(got, np.float32); ref = ref64.astype(np.float32)
    abs_err = np.abs(got.astype(np.float64) - ref64)
    ulp = ulp_diff(got, ref)
    print(f"  {name:<16} max|Δ|={abs_err.max():.2e}  中位 ULP={int(np.median(ulp))}  "
          f"90 分位 ULP={int(np.percentile(ulp, 90))}  >10 ULP 的元素={int((ulp > 10).sum())}")

# ---------- 2. float32 GEMM：按 (block, thread tile) 的循环序累加，模拟不同实现顺序 ----------
def gemm_f32(A, B, Tb=64, Tt=4, kahan=False):
    M, K = A.shape; N = B.shape[1]
    A = np.asarray(A, np.float32); B = np.asarray(B, np.float32)
    C = np.zeros((M, N), dtype=np.float32)
    for bi in range(0, M, Tb):
        for bj in range(0, N, Tb):
            acc = np.zeros((min(Tb, M-bi), min(Tb, N-bj)), dtype=np.float32)
            comp = np.zeros_like(acc)
            for k in range(K):
                for ti in range(0, acc.shape[0], Tt):
                    for tj in range(0, acc.shape[1], Tt):
                        prod = (A[bi+ti:bi+ti+Tt, k][:, None]
                                * B[k, bj+tj:bj+tj+Tt][None, :]).astype(np.float32)
                        if not kahan:
                            acc[ti:ti+Tt, tj:tj+Tt] += prod
                        else:
                            tgt = acc[ti:ti+Tt, tj:tj+Tt]
                            y = prod - comp[ti:ti+Tt, tj:tj+Tt]
                            t = tgt + y
                            comp[ti:ti+Tt, tj:tj+Tt] = (t - tgt) - y
                            acc[ti:ti+Tt, tj:tj+Tt] = t
            C[bi:bi+Tb, bj:bj+Tb] = acc
    return C

# ---------- 3. K 维长度对误差的影响 ----------
rng = np.random.default_rng(0)
print("=== K 维长度对误差的影响（M=N=64，float32 输入，参考为 float64）===")
for K in (16, 64, 256, 1024):
    A = rng.standard_normal((64, K)).astype(np.float32)
    B = rng.standard_normal((K, 64)).astype(np.float32)
    ref = A.astype(np.float64) @ B.astype(np.float64)
    print(f"K={K}:")
    report("逐点累加", gemm_f32(A, B, Tb=64, Tt=4), ref)
    report("Kahan 补偿", gemm_f32(A, B, Tb=64, Tt=4, kahan=True), ref)

# ---------- 4. 容差判定：混合准则 |got-ref| <= atol + rtol*|ref| ----------
def check(got, ref, atol, rtol):
    got = got.astype(np.float64); ref = ref.astype(np.float64)
    bad = np.abs(got - ref) > atol + rtol * np.abs(ref)
    return bad.mean(), np.abs(got - ref).max()

print("\n=== 容差判定：atol=1e-4 + rtol=1e-3（逐元素混合准则）===")
A = rng.standard_normal((128, 256)).astype(np.float32)
B = rng.standard_normal((256, 128)).astype(np.float32)
ref64 = A.astype(np.float64) @ B.astype(np.float64)
correct = gemm_f32(A, B, Tb=64, Tt=4)
broken = correct.copy(); broken[:, :32] = 0.0        # 故意漏算 1/4 的输出列
for name, got in (("正确实现", correct), ("漏算 1/4 列", broken)):
    frac, mx = check(got, ref64, 1e-4, 1e-3)
    print(f"  {name:<12} 违规元素占比={frac:>6.2%}  max|Δ|={mx:.2e}  判定={'通过' if frac == 0 else '不通过'}")
print("  同一实现换更严的容差：", end="")
for atol, rtol in ((1e-5, 1e-4), (1e-6, 1e-5)):
    frac, _ = check(correct, ref64, atol, rtol)
    print(f"(atol={atol:g}, rtol={rtol:g})→违规 {frac:.2%}", end="  ")
print()

# ---------- 5. 形与边界用例 ----------
print("\n=== 边界用例（只拿一个漂亮的 2 的幂形状交不了差）===")
def gemm_generic(A, B, Tb=64):
    """支持任意形状的版本：block 按实际剩余尺寸裁剪。"""
    M, K = A.shape; N = B.shape[1]
    A = np.asarray(A, np.float32); B = np.asarray(B, np.float32)
    C = np.zeros((M, N), dtype=np.float32)
    for bi in range(0, M, Tb):
        for bj in range(0, N, Tb):
            acc = np.zeros((min(Tb, M-bi), min(Tb, N-bj)), dtype=np.float32)
            for k in range(K):
                acc += A[bi:bi+acc.shape[0], k][:, None] * B[k, bj:bj+acc.shape[1]][None, :]
            C[bi:bi+acc.shape[0], bj:bj+acc.shape[1]] = acc
    return C
for (m, n, k) in ((1, 1, 1), (1, 4096, 512), (4096, 1, 512), (17, 33, 65), (128, 96, 160)):
    A = rng.standard_normal((m, k)).astype(np.float32)
    B = rng.standard_normal((k, n)).astype(np.float32)
    ref = (A.astype(np.float64) @ B.astype(np.float64)).astype(np.float32)
    frac, mx = check(gemm_generic(A, B), ref, 1e-4, 1e-3)
    print(f"  M={m:<5} N={n:<5} K={k:<5} 违规占比={frac:>6.2%} max|Δ|={mx:.2e}")

print("\n=== 污染传播：一个 NaN / Inf 能毁掉多少输出 ===")
A = rng.standard_normal((64, 64)).astype(np.float32); B = rng.standard_normal((64, 64)).astype(np.float32)
for name, val in (("A[0,0]=NaN", np.nan), ("A[0,0]=Inf", np.inf)):
    Am = A.copy(); Am[0, 0] = val
    C = gemm_generic(Am, B)
    bad = int((~np.isfinite(C)).sum())
    print(f"  {name:<12} 非有限输出 = {bad}/{C.size}（占 {bad/C.size:.0%}）：一个输入污染整个第 0 行输出")

# ---------- 6. 为什么"逐位对齐"做不到：累加分段方式改变 ULP ----------
print("\n=== 同一份输入、不同分段顺序的求和：ULP 差多少 ===")
for K in (256, 4096, 65536):
    x = rng.standard_normal(K).astype(np.float32)
    exact64 = float(np.sum(x.astype(np.float64)))
    exact32 = np.float32(exact64)
    for block in (8, 64, 512):
        parts = np.array([np.float32(np.sum(x[i:i+block], dtype=np.float32))
                          for i in range(0, K, block)], dtype=np.float32)
        got = np.float32(np.sum(parts, dtype=np.float32))
        print(f"  K={K:>6} 段长={block:>4} 与 float64 差={abs(float(got)-exact64):.2e}"
              f"  与整体 float32 求和的 ULP 差={int(ulp_diff(got, exact32))}")

四处可核对的结论：误差确实随 K 线性增长（中位 ULP 1→6），而 Kahan 把它压回 0；混合容差能同时抓住"漏算 1/4 列"（违规 25%）与放行正常的浮点差异（违规 0%），但把容差收紧到 atol=1e-6 时正确实现也开始违规（0.54%）——这条边界就是"容差要有依据"的具体含义；一个 NaN 只污染对应的 64 个输出（第 0 行），而不是整块矩阵，这让污染用例可以精确定位；同一份输入换分段顺序，ULP 差在 0~5 之间波动——所以"与参考逐位相等"不该作为验收标准，而"误差在容差内且可复现"才是。
