GPTQ/AWQ/GGUF#

上一课讲了量化的通用公式，这一课讲三个"怎么把量化做得好"的具体方法：GPTQ 用二阶误差补偿把权重逐层量化到 4-bit 且几乎不掉点，AWQ 通过"保护重要通道"来规避离群值破坏，GGUF 则是 llama.cpp 生态里最通用的量化模型文件格式。学完本课，你应当能区分三者的原理定位，并会各写一段加载/量化命令。

一、概念讲解#

1. GPTQ：逐层量化 + 误差补偿#

GPTQ 的名字带 "Q"（quantization），它的目标是在训练后、不用重训的前提下，把模型量化到 3/4-bit 而精度几乎不损失。核心思想有三条：

  • 逐层量化：一层一层地量化，当前层的误差可以在量化后续权重时被"吸收"；
  • 二阶信息（Hessian）：用权重对误差的 Hessian 矩阵来评估"量化哪个权重影响更大"，优先补偿影响大的；
  • 反量化补偿：量化某一列后，立刻把由此引入的误差"摊"到尚未量化的其余列上，让总误差互相抵消。

效果：Llama-7B 用 GPTQ 量化到 4-bit，困惑度（perplexity）相比 FP16 基本持平，而模型体积减半以上。

2. AWQ：激活感知、保护重要通道#

AWQ（Activation-aware Weight Quantization，激活感知权重量化）观察到：不是所有权重都同等重要——那些与"大激活值"相连的权重通道对精度影响最大（约 1% 的显著通道贡献了大部分输出）。上一课我们看到离群值会"绑架" scale，AWQ 的对策是：

  • 用少量校准数据跑一遍，统计每条通道的激活幅度；
  • 给重要通道乘一个更大的 per-channel scale，让它们量化得更精细（等效于"保护"它们）；
  • 不改变权重的实际数值（保护通过 scale 缩放实现，计算时再还原），因此不增加额外训练、无重训成本。

AWQ 4-bit 在多数模型上精度优于朴素的 round-to-nearest 4-bit，且量化过程比 GPTQ 更快。

3. GGUF：一个文件装下模型 + 量化方案#

GGUF 是 llama.cpp 生态的模型文件格式，前身是 GGML。它的特点：

  • 单文件自描述：把权重、词表、超参、量化元数据都装进一个 .gguf 文件，开箱即用；
  • 多种量化档位：提供从 FP16 到 2-bit 的一整套档位（如 Q4_0、Q4_K_M、Q5_K_M、Q8_0），"K-quant"系列是结合了块级混合精度的改良方案；
  • 跨硬件：CPU、CUDA、Metal、Vulkan 后端都能读同一份 GGUF。

GGUF 本身不是一种"量化算法"，而是一种承载量化权重的容器格式——它既可以用简单量化，也可以搭配更精细的量化方案。

二、可运行示例#

1. GPTQ：用 AutoGPTQ 量化/加载#

# -*- coding: utf-8 -*-
# 用 AutoGPTQ 加载一个已量化的 4-bit 模型并推理
from transformers import AutoTokenizer
from auto_gptq import AutoGPTQForCausalLM

model_id = "TheBloke/Llama-2-7B-GPTQ"          # 已量化好的 4-bit GPTQ 模型
tok = AutoTokenizer.from_pretrained(model_id)
model = AutoGPTQForCausalLM.from_quantized(model_id, use_triton=True)

prompt = "用一句话解释 PagedAttention"
inputs = tok(prompt, return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=64)
print(tok.decode(out[0], skip_special_tokens=True))

2. AWQ：用 vLLM 直接加载 4-bit AWQ#

# vLLM 原生支持 AWQ：--quantization awq 即可
python -m vllm.entrypoints.openai.api_server \
    --model TheBloke/Llama-2-7B-AWQ \
    --quantization awq \
    --max-model-len 4096 \
    --port 8000

3. GGUF：用 llama.cpp 转换或直接下载#

# 方式一：直接下载现成 GGUF（如 Q4_K_M 档位）
#   地址形如 https://huggingface.co/TheBloke/Llama-2-7B-GGUF
./llama-cli -m ./llama-2-7b.Q4_K_M.gguf -p "Hello" -n 64

# 方式二：自己把 HF 模型转成 GGUF（需要 llama.cpp 仓库）
python convert_hf_to_gguf.py ./Llama-2-7b-chat-hf --outfile ./llama-2-7b.gguf
./llama-quantize ./llama-2-7b.gguf ./llama-2-7b.Q4_K_M.gguf Q4_K_M

4. 三方法快速对照#

# -*- coding: utf-8 -*-
# 三个量化方案的定位对照

summary = [

    ("AWQ",   "激活感知、保护重要通道",     "精度好、量化快、实现广",   "GPU 服务（vLLM 原生支持）"),
    ("GGUF",  "单文件容器 + 多档位量化",    "跨硬件、开箱即用",         "llama.cpp 本地/边缘"),

三、练习#

  1. 跑 GPTQ：用 AutoGPTQ 加载一个 4-bit GPTQ 模型，记录显存占用，与 FP16 加载对比（FP16 约 2 倍字节），验证"减半"。
  2. 跑 AWQ：用 vLLM --quantization awq 起服务，与不量化（FP16）对比同样显存下的并发数，体会省显存带来的容量提升。
  3. 转 GGUF：用 convert_hf_to_gguf.py 把一个 HF 模型转成 GGUF，再分别 quantize 成 Q4_0 和 Q5_K_M，对比文件大小与生成质量。
  4. 思考：GPTQ 和 AWQ 都属于 PTQ（无需重训），但 AWQ 需要"校准数据"来统计激活分布。为什么说"感知激活"比"只看权重"更聪明？结合上一课的离群值问题回答。
