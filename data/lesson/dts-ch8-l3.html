对照：训练并行 vs 推理并行#

前两课把训练算清了。很多人接着就照搬：训练时 TP=4、PP=2，推理也照配一份——然后发现延迟不达标、并发上不去。原因是训练与推理优化的是两个不同的目标函数：训练要 tokens/秒/成本，可以容忍全局同步与秒级延迟；推理要 TTFT（time to first token，首 token 延迟）与 TPOT（time per output token，每 token 延迟），延迟本身就是 SLA。本课用同一套账本把两者的差异算成数字（只做并行与显存口径的对照，算子与引擎细节留给推理优化课）。

一、概念讲解#

1. 状态不同：大头从优化器状态换成 KV cache#

训练每卡的大头是模型状态：混合精度 Adam 下 16 字节/参数，纯 DP 时 6.57B 模型要 98.0 GiB/卡。推理没有优化器状态、也没有梯度，但要多存 KV cache（注意力 Key/Value 的缓存）：

KV bytes=2(K 与 V)×L×nkv​×dhead​×s×b×dtype

示例模型（32 层、hidden 4096、8 个 KV 头、head_dim 128、fp16）的单 token 单序列 KV 是 128 KiB。代进不同 batch 与序列长：序列 4096、batch 32 时 KV 16.00 GiB，而 fp16 权重只有 12.2 GiB；batch 128 时 KV 64.00 GiB、合计 76.2 GiB；序列拉到 32768、batch 128 就是 512.00 GiB。结论：推理的并发上限由 KV cache 决定，不是权重；训练里 batch 调大要找激活显存的上限，推理里要找 KV cache 的上限。

2. 通信模式不同：训练是少量大消息，推理是海量小消息#

把通信折到"每个 token"同一把尺子上。训练：DP=64、弱扩展下每步梯度 3Ψ 个 fp16 元素（39.4 GB）除以 1,048,576 token/步 = 36.7 KiB/token。推理 decode：每层前向两次 AllReduce（Megatron-LM 的口径：MLP 一次、注意力输出一次），每次 b⋅h 个元素——折下来 TP=2 是 512 KiB/token、TP=4 是 768、TP=8 是 896，是训练的 14~24 倍。

这个数量级差决定了优化方向：训练的一次大 AllReduce 由 β（带宽）主导，靠分桶与重叠能藏进反向计算里；推理的 128 次（2×L）小 AllReduce 由 α（固定延迟）主导，藏不掉——它串在关键路径上。所以第 1 课的 α-β 模型在训练里主要算带宽账，在推理里主要算延迟账。

3. 分片对象不同：切 KV，而不是切权重#

训练分片（ZeRO/FSDP）切的是权重、梯度、优化器状态三件套；推理的权重通常复制（每层都要用全部权重，切了就要在关键路径上 AllGather），真正需要切的是 KV cache：按 KV 头切（GQA 天然支持，8 个头切 4 份每卡 2 个）或按 token 分页切（PagedAttention）。

TP 在推理里的作用是降单流延迟（权重访存按 1/TP 下降），但每层的小集合通信随 logP 上升，于是存在最优点：示例模型单流从 TP=1 的 114 token/s 升到 TP=8 的 331 token/s，TP=16 反而回落到 321 token/s——省下的访存（0.55 ms）已经不够付通信（2.57 ms）。这就是推理 TP 一般不超过单节点内 8 路的原因。DP 副本不降单流延迟，只放大总吞吐。

4. 算术强度不同：decode 是访存瓶颈，prefill 才是算力瓶颈#

batch=1 时每 token 要读 2Ψ 字节权重（26.3 GB）、只做 2Ψ FLOPs（13.1 GFLOP），算术强度 0.50 FLOP/byte，而示例硬件拐点约 990/3≈300 FLOP/byte——差三个数量级，decode 必然是显存带宽瓶颈，这就是低精度权重（fp8/int4）对 decode 立竿见影的原因。

而 prefill 阶段序列长、矩阵乘大，是算力密集、可批处理，引擎会把两者分开调度。把两者平均值当"推理性能"，是这类对照里最常见的错误。

5. 一张对照表#

维度 训练并行 推理并行
目标 tokens/秒/成本，可容忍同步 TTFT 与 TPOT，延迟即 SLA
最大显存项 优化器状态（16 B/参数） KV cache（2Lnkv​dsb 字节）
通信形态 每步一次大 AllReduce（带宽主导） 每 token 每层多次小 AllReduce（延迟主导）
分片对象 权重 / 梯度 / 优化器状态（ZeRO、FSDP） KV cache（按 KV 头或分页）；权重多复制
TP 的作用 装下模型 + 缩短单步 降单流延迟，有 logP 上限
DP 的作用 提升吞吐（需同步梯度） 副本提升总吞吐，不降延迟
并行域 TP/PP 均可能跨节点（PP 天然跨节点） TP 留在节点内，跨节点主要靠副本

6. 常见坑#

  • 照搬训练的 TP/PP：训练为装下模型切 PP，推理却把 PP 用在延迟关键路径上，token 要穿过整条流水线。
  • 用算力估推理延迟：decode 是访存瓶颈，换更快的卡不如换更宽的显存带宽、更窄的权重。
  • 忽略长上下文的量级：KV 随 s 线性涨、注意力计算随 s2 涨，与权重不是同一量级。
  • 把两者平均值当"推理性能"：瓶颈完全不同。
  • 忘记数值口径：训练看 loss 曲线，推理要逐 token 对齐 logits，换并行配置会改数值。

二、可运行代码示例#

一段纯 numpy/Python：算 KV cache 账本、把训练与推理的通信折到每个 token 对比、再算 decode 延迟随 TP 的变化曲线。所有硬件参数（3 TB/s 显存带宽、α=5μs、200 GB/s 互连）都是示例量级，请换成你的卡。

import numpy as np
# ===== 对照：训练并行 vs 推理并行的三笔账 =====
L, H, NKV, DH = 32, 4096, 8, 128          # 示例模型：32 层、hidden 4096、8 个 KV 头、head_dim 128
P = L * 12 * H**2 + 32000 * H
DT = 2                                     # fp16/bf16 2 字节

def kv_bytes(layers, n_kv, d_head, seq, batch, dtype=DT):
    """KV cache = 2（K 与 V）× 层数 × KV 头数 × head_dim × 序列长 × batch × 字节数。"""
    return 2 * layers * n_kv * d_head * seq * batch * dtype

print(f"模型 ≈ {P/1e9:.2f} B")
print("账本一 · 显存：训练的大头是优化器状态，推理的大头是 KV cache")
print(f"  单 token 单序列 KV = 2*{L}*{NKV}*{DH}*{DT} = {kv_bytes(L,NKV,DH,1,1)} B = {kv_bytes(L,NKV,DH,1,1)/1024:.0f} KiB")
print(f"  {'序列长':>6} {'batch':>6} {'KV cache':>10} {'+ 权重(fp16)':>12} {'合计 GiB':>9}")
for s in (4096, 32768):
    for b in (1, 32, 128):
        kv = kv_bytes(L, NKV, DH, s, b)
        tot = (kv + 2 * P) / 2**30
        print(f"  {s:>6} {b:>6} {kv/2**30:>9.2f}G {2*P/2**30:>11.1f}G {tot:>9.1f}")
print(f"  对照训练：优化器状态按 16 B/参数 = {16*P/2**30:.1f} GiB/卡（纯 DP），是权重的 {16*P/(2*P):.0f} 倍")

print("\n  用 numpy 模拟 GQA 的 KV 分片：8 个 KV 头切给 tp=4 个 rank（每 rank 2 个头）")
rng = np.random.default_rng(1)
KV = rng.standard_normal((L, NKV, 128, 64)).astype(np.float32)   # 32 层 × 8 头 × 128 × 64
shards = np.array_split(KV, 4, axis=1)
print(f"  每 rank 持有 shape={shards[0].shape}（{shards[0].nbytes/2**20:.1f} MiB/序列，原为 {KV.nbytes/2**20:.1f} MiB）")
print(f"  按 KV 头拼接可无损还原：{np.array_equal(np.concatenate(shards, axis=1), KV)}")

def training_bytes_per_token(P, tokens_step, stage=3, dtype=DT):
    """训练：一个优化器步的梯度通信总量（全组视野）÷ 该步 token 数。"""
    return (2 if stage < 3 else 3) * P * dtype / tokens_step

def inference_bytes_per_token(L, h, tp, dtype=DT, batch=1):
    """推理 decode：每层前向 2 次 AllReduce（Megatron 的 g 与注意力输出各一次），每次 b*h 个元素。"""
    return 2 * L * (2 * (tp - 1) / tp if tp > 1 else 0.0) * h * batch * dtype

print("\n账本二 · 通信：折到「每个 token」看，推理 decode 比训练高一个量级")
toks = 4096 * 4 * 64
t_tr = training_bytes_per_token(P, toks)
print(f"  训练：梯度 {3*P*DT/1e9:.1f} GB/步 ÷ {toks} token/步 = {t_tr/1024:.1f} KiB/token（DP=64、弱扩展）")
for tp in (2, 4, 8):
    i_inf = inference_bytes_per_token(L, H, tp)
    print(f"  推理 decode：TP={tp} → {i_inf/1024:.0f} KiB/token，是训练的 {i_inf/t_tr:.0f} 倍")

print("\n账本三 · 延迟：decode 由显存带宽决定，TP 的收益到 alpha 项吃掉它为止")
print("  模型口径：每层前向 2 次 AllReduce（Megatron-LM 的 g 与注意力输出各一次）、每次按树形 O(log P) 步计延迟")
BW_B, ALPHA_US, BETA = 3.0e12, 5.0, 200.0      # 示例：3 TB/s 显存带宽、5us、200GB/s 互连
kv_tok = kv_bytes(L, NKV, DH, 1, 1)
print(f"  {'TP':>3} {'权重/卡 GB':>10} {'访存 ms':>8} {'通信 ms':>8} {'合计 ms':>8} {'单流 token/s':>12}")
for tp in (1, 2, 4, 8, 16):
    w = 2 * P * DT / tp
    t_mem = (w + kv_tok * 1) / BW_B * 1e3
    comm_b = 2 * L * (2 * (tp - 1) / tp if tp > 1 else 0.0) * H * DT
    steps = 0 if tp == 1 else 2 * ((tp - 1).bit_length())   # 小消息走树形：每层 2 次 AllReduce，各 O(log P) 步
    t_c = comm_b / (BETA * 1e9) * 1e3 + 2 * L * steps * ALPHA_US / 1e3
    print(f"  {tp:>3} {w/1e9:>10.2f} {t_mem:>8.2f} {t_c:>8.3f} {t_mem+t_c:>8.2f} {1000/(t_mem+t_c):>12.0f}")
P_ = P
print(f"  算术强度：每 token 访存 {2*P_*DT/1e9:.1f} GB、计算 {2*P_/1e9:.1f} GFLOP（batch=1）"
      f" → {(2*P_)/(2*P_*DT):.2f} FLOP/byte；示例硬件拐点 990e12/3e12 ≈ 300 FLOP/byte，差 3 个数量级")

三、练习#

  1. 实现：把 kv_bytes 用于你自己的模型配置（层数、KV 头数、head_dim），算出在"单卡 80 GiB、权重 fp16、留 10 GiB 给激活与框架"时，序列 4096 下最大能跑多大 batch；再把 KV 换成 fp8 算一遍。
  2. 解释：为什么训练里"分桶 + 重叠"能把通信藏起来，推理 decode 里同样的小 AllReduce 却藏不掉？用"关键路径长度"与第 1 课的 α 项回答。
  3. 对比/验证：把账本三的 BETA 从 200 GB/s 改成 25 GB/s（跨机不再 NVLink），重跑 TP 曲线，指出最优点移到哪里；解释为什么推理的 TP 通常不跨节点。
  4. 思考：同一个 6.57B 模型，训练用 DP=64、推理用 TP=8 + 8 个副本。请分别写出两者"每 token 的通信字节"的表达式，并说明为什么两者不能共用一套并行配置。
