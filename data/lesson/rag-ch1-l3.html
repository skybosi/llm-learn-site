稠密双塔：对比学习目标、温度与难负样本的数学#

这一节要解决什么#

稀疏检索的失效一（词汇不匹配）来自一个表示层面的假设："相关"必须伴随"用词重叠"。要打破它，只能换表示 —— 把查询和文档映射到同一个语义空间，让"意思相近"在向量距离上体现，而不是在词表重叠上体现。这就是稠密检索。

"用双塔算 embedding 然后做最近邻"这句话几乎人人会说，但它背后有一串必须回答的问题，而这些问题在教程里通常被含糊过去：

  • 为什么必须是两个编码器（双塔）？ 用一个交叉编码器（把查询和文档拼起来过一遍）明显更强，为什么不用？答案是索引可行性，而且这个约束是硬的 —— 它直接决定了"离线预计算"能不能做。
  • 相似度为什么是内积？ 换成余弦、欧氏距离会怎样？这个选择真的只是"习惯"吗？
  • 对比学习的目标（InfoNCE）里那个温度 τ 在做什么？ 为什么它不能拍一个 0.07 了事？它如何决定梯度在"难样本"与"易样本"上的分配？
  • 批内负样本有什么问题？ "把同一个 batch 里其他样本的文档当负样本"是标准做法，但它的分布不是真实的负样本分布。偏差有多大？什么时候必须纠偏？
  • 难负样本是最有效的，但为什么它也是最危险的？ 假负样本（false negative）会怎样破坏训练？如何检测？

这一节要把这些问题全部算清楚。结论会给出四类可预测的失效，以及一个在工程上极其重要的事实：稠密检索质量下降的原因，有一半不在模型，而在"近似最近邻"这个环节（第 2 章展开）。

一、为什么必须解耦：双塔是索引可行性的产物#

1.1 交叉编码器强在哪里、死在什么地方#

交叉编码器（cross-encoder） 把查询与文档拼接后送进同一个编码器，并在最后一层做交互。它能看到查询词与文档词之间的细粒度对齐（"哪个查询词对应文档里的哪一段"），因此在排序质量上明显优于任何双塔。

形式化对比：

cross-encoder:s(q,d)=fθ​([q;d])（一次前向 = 一个 (q,d) 对的分数）

dual-encoder:s(q,d)=⟨fθ​(q),gϕ​(d)⟩（文档编码可离线预计算）

关键差别只有一个：文档侧的计算能否与查询解耦。 双塔里 gϕ​(d) 不含 q，所以：

交叉编码器 双塔
每个查询要对多少文档做前向 N（全库） 1（只编码查询）
文档侧计算 在线、每查询重复 离线一次，永久复用
单查询在线成本 O(N⋅前向) O(一次前向+一次近邻搜索)
排序质量 高（有词级交互） 较低（把整篇文档压成一个向量）
能否进 ANN 索引 不能（分数不是向量距离） 能（内积/距离）

这不是"质量换速度"的权衡，而是"能不能用"的分界：N=107 文档时，交叉编码器对每个查询要做 107 次前向 —— 即使每次 1 ms，也是 2.8 小时/查询。所以工程上唯一可行的结构是：

双塔（便宜、可索引）负责从 10^7 里取出 100 个候选
交叉编码器（贵、不可索引）只对 100 个候选做精排

这就是"召回-重排"两级架构的全部理由。 记住这个分界，第 4 章的重排就是它的直接推论。

1.2 双塔的代价：一个向量必须装下一整篇文档#

解耦的代价是信息瓶颈：gϕ​(d)∈Rd 要把整篇文档（几千 token）压缩成 d 维（常为 384~1536）的定长向量。用"每条文档最多能保留多少可区分信息"来估：d 维、每维 b bit 精度，可得

I(d)≲d⋅bbit

d=768、b=16（fp16）时上界约 12 Kbit；实际可用的判别信息远低于上界（受训练目标与数据分布限制）。这意味着：

  • 同一篇文章的不同问题，在双塔里可能被压缩到难以区分的表示上（这就是后面失效三"组合性"的根源）；
  • 精确细节（数字、ID、否定）最容易被压掉，因为训练目标关心的是"整体语义匹配"。

所以双塔与稀疏检索不是"新方法取代旧方法"，而是"两种不同损失的信息压缩"：稀疏保留精确词面，稠密保留语义泛化。第 4 节的混合检索正是要让两种损失互补。

1.3 为什么内积：因为要能建索引#

相似度函数的选择，看起来是建模问题，实际是搜索问题。三种常见选择：

相似度 查询时的搜索问题 能否用成熟 ANN 结构
内积 ⟨q,d⟩ 最大内积搜索（MIPS） 能（内积空间有专门的层次化/量化结构）
余弦 cos(q,d) 归一化后的 MIPS 能（把两侧都归一化，退化为 MIPS）
欧氏距离 ∥q−d∥2 最近邻搜索 能（但与非归一化内积不等价）

它们之间有关系，但只有在向量被归一化时才干净地等价：

∥q−d∥2=∥q∥2+∥d∥2−2⟨q,d⟩⟹若 ∥q∥=∥d∥=1, 则 ∥q−d∥2=2−2⟨q,d⟩

这条式子的工程含义很重要：

  • 归一化之后，内积排序 = 余弦排序 = 欧氏距离升序，三者可以互换。大多数稠密检索都归一化，就是为了拿到这个等价性；
  • 不归一化时三者不等价：∥d∥ 大的文档会在内积下占优（相当于一个"文档热度"的隐式偏置）。有时这是想要的（长文档更可能相关），有时是灾难（热门文档压过一切）。这是一个必须显式决定的设计选择，不能靠"忘了归一化"来决定。

一个反直觉的推论：如果训练时用内积、检索时也归一化，但训练时没有把向量约束到单位球面，那么模型会学到用 ∥d∥ 编码"文档质量/长度"这类先验 —— 检索时的归一化会把这个先验抹掉，造成训练-推理不一致。归一化必须在训练目标里体现（或训练也用归一化后的内积），不能只在推理时做。

二、对比学习目标：InfoNCE 与温度的来源#

2.1 从"分类问题"看检索训练#

把"给定查询 q，从候选集中找出正确文档"写成一个分类问题：正确文档是类别 d+，其余是负类。用 softmax 建模：

P(d+∣q)=exp(s(q,d+)/τ)+∑i=1K​exp(s(q,di−​)/τ)exp(s(q,d+)/τ)​

训练目标就是最大化这个概率（等价于最小化负对数似然）：

L=−log∑j∈{+}∪{−}​exp(s(q,dj​)/τ)exp(s(q,d+)/τ)​

这就是 InfoNCE（in-batch / sampled softmax 形式）。

先澄清一个常见误解：InfoNCE 的名字（"对比估计"）暗示它是一个"互信息下界估计器"，在理论上确实可以这样解释（它给出的下界与批大小 K 有关）。但在检索工程里，把它当作"用负采样近似的 softmax 分类损失"更实用 —— 因为这个视角直接告诉你：批内负样本数量 = 分类问题的类别数 = 损失的信息量。K 越大，任务越难，学到的表示区分度越高。这解释了"为什么大家都想加大 batch"。

2.2 温度 τ 到底在做什么：梯度分配的推导#

要看清 τ，就得看梯度。把 sj​=s(q,dj​) 简写，s~j​=sj​/τ，则对正样本的梯度：

∂s+∂L​=−τ1​(1−P(d+∣q))

对某个负样本 di−​：

∂si−​∂L​=τ1​P(di−​∣q)

（两式都会再通过 s=⟨f(q),g(d)⟩ 回传到编码器，这里关心的是"分数上的力度"。）

这两条式子把 τ 的作用说清楚了：

  1. τ 是一个全局的梯度缩放因子 1/τ。 τ 小 → 梯度幅度大。这与"学得更快"有关，但也直接关系到训练稳定性。
  2. τ 决定了 P 分布的"尖锐度"，从而决定梯度被分配给谁。 当 τ→0，softmax 趋于 one-hot：一旦正样本已经排第一，P(d+)→1，正样本梯度 →0，所有容易的样本停止贡献梯度，只有"正样本还没排第一"的困难样本在推动学习。
  3. 当 τ 大，分布趋于均匀：P(d+)≈K+11​，每个样本（无论难易）都得到相近量级的梯度。这相当于把所有负样本同等对待，包括那些显然无关的（"这杯咖啡的做法" 对 "Transformer 的注意力机制"）。

于是 τ 的语义是：

τ 控制"多少注意力放在难样本上"。τ 小 → 集中火力打难样本（对表示质量有要求，但训练更脆）；τ 大 → 平均用力（稳，但容易被大量易负样本稀释）。

τ 与批大小的耦合关系也从此可见：批越大，易负样本越多（一个 batch 里总有大量毫不相关的文档），因此大 batch 通常需要更小的 τ 来把火力压到难样本上。这就是为什么"τ=0.07 配大 batch"是一个常见组合，而批大小从 256 降到 32 时，沿用 0.07 往往会让训练不稳定。

一个可用的诊断：训练时打印每个 batch 的 P(d+) 均值。它长期停在 1/(K+1) 附近（约等于随机猜）说明 τ 太大或表示没有区分度；它在很早的阶段就饱和到 0.99 说明任务太容易（负样本太简单），梯度要枯竭了。

2.3 批内负样本的采样偏差：一个必须量化的问题#

标准做法是"同一个 batch 里，其他样本的正文档当负样本"。这引入三类偏差，每一类都有对应的工程纠正：

(a) 采样分布 ≠ 负样本分布（频次偏差）。

批内负样本的采样概率正比于"该文档在训练对里出现的频率"，而真实检索中，一个文档成为负样本的概率正比于"它出现在检索结果里的频率"。这两者不同：

  • 高频文档（热门、通用）在批内被当成负样本的次数** disproportionately 多** → 模型学会把热门文档推远 → 检索时对热门文档过度惩罚；
  • 修正方法：对负样本按"被采样的概率"做重要性加权（把损失从"均匀对待每个批内负样本"改成"按目标分布加权"）。

(b) 假负样本（false negatives）—— 最危险的一类。

批内其它样本的正文档可能是当前查询的正确答案。例如两个查询"如何回滚部署"与"如何撤销发布"，它们的正文档高度相似；把它们互相当负样本，就是在训练模型不要把正确答案排前面。

设批中每个正文档与当前查询"实际相关"的概率为 ρ（取决于语料的主题集中度），批大小为 K，则一个 batch 里至少含一个假负样本的概率：

P(有假负样本)=1−(1−ρ)K−1

K \ ρ 0.001 0.01 0.05
64 0.06 0.47 0.96
256 0.23 0.92 ≈1
1024 0.64 ≈1 ≈1

读法：在主题集中的语料上（ρ=0.05，即 5% 的文档相互"也算相关"，这对客服 FAQ、法律条文、代码库这类语料很常见），批大小 64 就已经有 96% 的批次含假负样本。这就是"小 batch 训练稠密检索反而更好"这一现象的部分原因 —— 不是小 batch 的梯度更好，而是大 batch 的假负样本更多。

判定与缓解手段：

手段 做法 代价
去重/合并 训练前把"互为近重复"的正文档聚类，同簇内不互相当负样本 需要近重复检测，簇内信息量下降
相似度掩码 计算假负样本与查询的相似度，超过阈值就把它从损失里屏蔽 需要一次额外的前向/缓存；阈值需标定
假负样本鲁棒的损失 用对标签噪声更鲁棒的损失（例如对负样本损失做截断） 引入新的超参数与偏差
更小的批 + 梯度累积 保持有效学习率的同时减少"同批互斥" 训练更慢；梯度累积不改变批内负样本构成（这是关键区别）

⚠️ 必须分清"批大小"与"梯度累积"：梯度累积可以让有效批变大、学习更稳，但它不会增加批内负样本数（每次前向的 batch 仍是那个小批）。所以"我用梯度累积模拟了大 batch"在对比学习里不成立 —— 负样本数量没变。

(c) 负样本的"难度分布"随时间漂移。

训练早期，模型差，批内负样本都算"难"；训练后期，模型已经能轻松分开它们，梯度枯竭。这解释了为什么现代稠密检索训练会显式引入难负样本挖掘（hard negative mining）：定期用当前模型检索，把"排在前面但不是正样本"的文档选出来当负样本。

2.4 难负样本：为什么最有效，也最容易把训练搞坏#

难负样本的收益是在梯度上可解释的：由 2.2 的梯度式，负样本 di−​ 得到的梯度正比于 P(di−​∣q) —— 而 P 又随分数指数增长。分数高的负样本拿到绝大部分负样本梯度，因此"修正它们的排序"是效率最高的更新方向。这正是难负样本挖掘的全部理由。

但难度与噪声是同一枚硬币的两面。把"分数高"当"负样本"的代理，会同时把两类东西引进来：

  1. 真正的难负样本（相似但不相关）→ 有用；
  2. 假负样本（相似且相关）→ 有害，且越难的样本里假负比例越高（因为假负样本天然是"最相似"的一类）。

设挖掘到的候选里假负比例为 ρh​，则"挖掘越深（h 越大），ρh​ 越高"是结构性规律。这不是可以通过调参绕开的，只能通过"挖掘后用判据过滤"来控制：

可用的过滤判据（按成本从低到高）：
  ① 规则：同文档不同段落、同一簇内的近重复 → 直接排除
  ② 相似度：与查询的相似度超过正样本相似度一定比例 → 疑似假负，排除或降权
  ③ 人工/模型复核：对挖掘到的候选做一次标注（最贵，但最可靠；用在小规模高价值场景）

工程上的默认配方（第 4 章会把它落到重排的训练里）：混合负样本 —— 一部分随机/批内（覆盖全局分布、防止表示塌缩），一部分挖掘（提供高信息量梯度），并对挖掘部分施加过滤。纯随机负样本学得慢，纯难负样本学得偏。

2.5 一个更几何的视角：对齐性与均匀性#

上面的分析可以用两个量概括，它们直接对应两类失败：

Lalign​=E(q,d+)​​f(q)−g(d+)​2（正样本要多近）

Luniform​=logEd,d′​[e−2∥g(d)−g(d′)∥2]（向量要多散）

  • 对齐性（alignment） 不好 → 正样本没有靠近 → 召回不到（失效：语义相似但分数低）；
  • 均匀性（uniformity） 不好 → 表示塌缩到一个窄锥里（各向异性）→ 所有文档的相似度都差不多 → 排序失去分辨率。

这两者会互相冲突：把所有文档都映射到同一点，对齐性完美（距离 0），均匀性极差。对比学习目标（InfoNCE）之所以有效，是因为它的分母里那些负样本同时施加了两种力：把正样本拉近、把负样本推开。这也解释了为什么"负样本太少"会塌缩：没有足够的推力，最优解就是所有向量重合。

一个可用的诊断指标：随机采样一批文档向量，计算它们两两余弦相似度的均值与方差。健康状态下均值应明显小于 1（例如 0.1~0.4 量级），方差不能接近 0。若均值接近 0.9+，说明表示几乎塌缩，此时即使 recall@100 看起来还行，Top-5 的排序也会很差（分辨率不够）。

三、稠密检索的四类失效#

现在可以系统列出失效。注意只有第一类与"训练数据/模型"有关，第四类是索引层的问题（这是许多人误判的地方）。

3.1 失效一：领域漂移（domain shift）—— 可预测、可检测#

现象：公开语料上训练的通用双塔模型，在垂直领域（医疗病历、法律条文、工业设备手册、公司内部缩写）上 recall 显著下降。

机制：稠密模型学到的是训练语料的语义分布。"相似"的定义由数据决定 —— 在通用语料里，"内存"和"存储"是近义词；在某个工业语料里，"内存"可能指某个具体型号的缓冲区，与"存储"无关。迁移到新领域时，模型仍按旧分布度量相似性。

判据：领域漂移通常表现为"整体性的分数下移 + 排序仍然大致正确"（因为相对结构还在）。这与"索引近似误差"的表现不同（后者表现为"随机漏掉部分相关文档"），也与"假负样本导致的塌缩"不同（后者表现为"分数区分度消失"）。

对策：领域内继续训练（用领域内的 (query, doc) 对或合成的弱标注对）；或直接改用稀疏检索在该领域打底（如果领域术语密集，稀疏天然强）。注意："换更大的通用模型"通常无效 —— 问题不在模型容量，在训练分布。

3.2 失效二：组合性与多条件查询 —— 结构性#

现象：查询"在 2023 年之后发布、支持中文且延迟低于 50ms 的推理框架"，双塔可能召回的是一篇讲"延迟优化"的文档（只匹配其中一个条件），或一篇泛泛的"框架综述"（语义中心匹配）。

机制：⟨f(q),g(d)⟩ 是一个双线性形式，它没有任何机制表达"必须同时满足 A 且 B 且 C"。文档向量是所有主题的平均，查询向量是所有条件的平均 —— 两个平均值的相似度会偏向"覆盖条件多的文档"，而不是"满足全部条件的文档"。

⟨f(q),g(d)⟩=⟨∣C∣1​c∈C∑​fc​,g(d)⟩=∣C∣1​c∑​单条条件匹配⟨fc​,g(d)⟩​​

读法：多条件查询的分数是各条件的平均匹配度，而不是最小匹配度（AND 语义）。因此"满足两条但缺一条"的文档可能打败"满足全部三条但每条都不算特别强"的文档。这无法通过调参修好，只能靠重排（能建模条件间的交互）、查询分解或结构化过滤。

工程判据：查询里出现明确的枚举式约束（年份、数值范围、版本号、实体组合）时，稠密检索的排序就不可靠 —— 这些约束应该下沉为元数据过滤（filter），而不是指望向量相似度。这也是第 2 章"索引里要带哪些元数据字段"的一个直接输入。

3.3 失效三：精确标识符与罕见串 —— 结构性#

现象：查询"错误码 E1234"、"函数 reset_index 的用法"、"型号 XYZ-200 的规格"，稠密检索召回了大量"语义相关但标识符不同"的文档，而真正含该串的文档没进前列。

机制：这些串在训练语料里出现极少（df 极低），模型几乎没机会学到它们的独立表示；同时分词会把它们切成子词，不同 ID 之间子词重叠（E1234 与 E1235 共享前缀）导致向量高度相似而语义完全不同。这是一个"表示分辨率不足"的问题，而且与 ρ（假负）问题叠加：这些近似 ID 会互相成为假负样本，进一步混淆训练。

对策：这类查询必须由稀疏/精确匹配一路兜底。这是混合检索在后文反复出现的具体理由之一。工程上还有一个便宜的手段：把标识符抽成元数据字段并做结构化过滤/精确匹配，与向量检索并行。

3.4 失效四：近似最近邻的召回损失 —— 与模型无关#

现象：离线用精确内积算出的 recall@100 很高，上线后用 ANN 索引（HNSW/IVF）测出的 recall@100 明显更低，且每次查询漏掉的文档不一样（不稳定）。

机制：ANN 索引用近似搜索代替穷举，"近似"意味着有概率漏掉最近的邻居。这不是模型的问题，而是搜索算法的问题 —— 而且它与模型质量相乘：模型质量决定"正确文档是否在向量空间里排前 100"，索引质量决定"前 100 里有多少被找回来"。

如果把两者写成概率，整个链路的召回上界是：

Rend-to-end​(k)≤正确文档是否在前 kRmodel​(k)​​ × 前 k 是否被找回Rindex​(k)​​

这个分解是整个第 2 章的动机。它也是调试时的第一道分叉：当线上召回差时，先测"精确内积 + 全扫"的 recall，再看 ANN 的 recall —— 两者的差距全部由索引参数负责，与模型无关。不做这个分解，你会在错误的地方花几周时间。

四、稠密检索什么时候不划算#

补齐另一面。稠密检索在下面这些情形里投入产出比很低：

情形 原因
语料以标识符/代码/编号为主 精确匹配信号占主导，稀疏几乎免费且更好
领域极小且术语封闭（几千条） 训练数据不足以学到领域语义分布；直接稀疏即可
查询极短且以实体名为主 双塔对"实体名的字面匹配"没有额外优势，反而可能因泛化而误召
有严格的"必须包含某串"要求 概率性相似度无法提供保证；需要硬过滤
延迟预算极紧且文档量小（<105） 稀疏倒排更快、更省内存（稠密要存 N×d 个浮点）

内存账（这个是硬账，值得算清）：N 篇文档、d 维、fp32：

向量内存=N×d×4 字节

N d=768 fp32 d=768 int8 d=768 二值化（1 bit）
106 ≈ 3.1 GB ≈ 0.77 GB ≈ 96 MB
107 ≈ 31 GB ≈ 7.7 GB ≈ 960 MB
108 ≈ 307 GB ≈ 77 GB ≈ 9.6 GB

读法：107 量级在 fp32 下已经无法常驻单机内存，必须量化或分片（第 2 章的量化误差与索引更新都在这个账本上做）。而稀疏倒排的存储量与"文档总 token 数"成正比、与 d 无关，在"短文档 + 大 N"的场景里常更省。

代码：双塔的对比损失、温度梯度与假负样本诊断#

下面用 numpy 实现一个极简的双塔（真实的编码器是神经网络；这里用线性投影，让对象集中在损失函数与采样上 —— 这两者才是本节的主角）。内容包括：InfoNCE 的实现、温度对梯度分配的影响、批内负样本偏差的数值演示、假负样本概率、以及表示塌缩诊断。

"""
双塔对比学习的核心机制最小实现（只用 numpy）。

设计决策：
  1. 用线性投影代替神经网络编码器：要观察的是"损失与采样"的行为，
     不是"模型容量"；换掉编码器不改变本节任何结论。
  2. 显式实现"相似度掩码"参数 —— 假负样本的处理必须是代码里的第一类公民，
     不能留在数据清洗的注脚里（因为它是批内负采样的固有问题）。
  3. 所有向量归一化，并把这个约束写成注释里的设计理由：
     归一化保证"内积排序 = 余弦排序 = 欧氏距离排序"三者等价。
"""
import numpy as np

RNG = np.random.default_rng(0)


def l2norm(x, eps=1e-9):
    """归一化。设计理由见正文 1.3：让内积/余弦/欧氏三种相似度排序等价。"""
    return x / (np.linalg.norm(x, axis=-1, keepdims=True) + eps)


class TinyTwoTower:
    """
    双塔：f(q)=W_q q（查询塔）、g(d)=W_d d（文档塔），分数为归一化内积。
    两个塔参数不共享 —— 共享会让"查询分布"与"文档分布"被强行对齐，
    在实践中通常更差（除非两塔输入同质，如"问题-问题"匹配）。
    """
    def __init__(self, dim_in: int, dim_out: int):
        self.Wq = RNG.normal(0, 0.1, (dim_out, dim_in))
        self.Wd = RNG.normal(0, 0.1, (dim_out, dim_in))

    def encode_q(self, Q):
        return l2norm(Q @ self.Wq.T)

    def encode_d(self, D):
        return l2norm(D @ self.Wd.T)

    # ------------------------------------------------------------- InfoNCE
    def info_nce(self, Q, D, pos_idx, tau=0.07, mask=None):
        """
        InfoNCE（批内负样本版）。

        Q: (B, d_in) 查询；D: (B, d_in) 每个查询对应的正文档（同序）
        pos_idx: (B,) 第 i 个查询的正文档在 D 中的下标（默认 i 本身）
        mask: (B, B) bool，True 表示"该 (i, j) 对是假负样本，要从损失里屏蔽"

        设计决策：
          · 分数矩阵 S = q_i · d_j，对角线（经 pos_idx 重排后）是正样本；
          · 屏蔽假负样本用"减去一个极大值"实现（不是置零）——置零等于告诉模型
            "这一对的分数应该接近 0"，而屏蔽的语义是"不提供任何梯度"。
        """
        q = self.encode_q(Q)                      # (B, k)
        d = self.encode_d(D)                      # (B, k)
        S = q @ d.T / tau                         # (B, B) 温度缩放后的 logits
        if mask is not None:
            S = np.where(mask, -1e9, S)
        # 数值稳定的 log-softmax
        S = S - S.max(axis=1, keepdims=True)
        logZ = np.log(np.exp(S).sum(axis=1, keepdims=True))
        logp = S - logZ
        loss = -logp[np.arange(len(Q)), pos_idx].mean()
        return loss, S, logp

    def grad_scores(self, logp, pos_idx):
        """
        损失对 logits 的梯度：正样本 −(1−p+)，负样本 +p_i。
        注意这两式的"总量"等于 0（∑p = 1），这正是温度控制梯度分配的数学来源：
          τ 小 → 分布尖 → 大部分梯度集中在少数高分负样本上。
        """
        B = logp.shape[0]
        G = np.exp(logp)                          # p_ij，行和为 1
        G[np.arange(B), pos_idx] -= 1.0           # 正样本项
        return G


# ------------------------------------------------------------ 诊断工具
def temperature_gradient_report(tau_values=(0.05, 0.1, 0.2, 0.5, 1.0),
                                score_scale: float = 0.2):
    """
    温度如何改变梯度分配：对固定的分数分布，看"前 3 个最高分负样本"
    拿走了负样本总梯度的多少比例。

    读法：τ 小 → 比例接近 1（火力集中在少数难样本）；
          τ 大 → 比例下降，趋向"平均用力"（下界约 3/(K−1)）。
    设计决策：score_scale 刻意取小值（0.2），因为余弦相似度的动态范围本来
              就在 0.1~0.3 量级；用 N(0,1) 会让 logits 动态范围过大，
              于是在任何 τ 下都饱和，看不出 τ 的作用。
    """
    out = []
    B, K = 8, 8
    for tau in tau_values:
        S = RNG.normal(0, score_scale, (B, K))
        S[np.arange(B), np.arange(B)] += 1.0      # 正样本略微占优
        S = S / tau
        S = S - S.max(axis=1, keepdims=True)
        P = np.exp(S) / np.exp(S).sum(axis=1, keepdims=True)
        share = []
        for i in range(B):
            row = P[i].copy(); row[i] = 0.0       # 只看负样本
            top3 = np.sort(row)[-3:].sum() / row.sum()
            share.append(top3)
        out.append((tau, float(np.mean(share))))
    return out


def false_negative_probability(K: int, rho: float) -> float:
    """批大小 K、单文档实际相关概率 ρ 时，批内至少一个假负样本的概率。"""
    return 1 - (1 - rho) ** (K - 1)


def collapse_diagnostic(vectors: np.ndarray):
    """
    表示塌缩诊断：随机文档向量两两余弦相似度的均值与标准差。

    判据（量级经验值）：
      · 均值 < 0.4 且标准差 > 0.05 → 表示健康
      · 均值 > 0.8              → 严重塌缩：排序分辨率不足，Top-k 会退化
    注意：这个诊断与 recall@k 是**互补**的 —— 塌缩时 recall 可能还行，
          但"哪一条排第一"已经不可靠。
    """
    V = l2norm(vectors)
    G = V @ V.T
    iu = np.triu_indices(len(V), k=1)
    sims = G[iu]
    return {"余弦均值": round(float(sims.mean()), 3),
            "余弦标准差": round(float(sims.std()), 3),
            "判据": "均值高 + 标准差小 = 塌缩；需要更强/更多的负样本"}


def batch_negative_frequency_bias(doc_freq: np.ndarray, n_samples: int = 200_000):
    """
    批内负样本的频次偏差：批内采样使"热门文档"被当作负样本的次数
    正比于它在训练对里的出现频率，而真实检索里正比于它出现在结果里的频率。

    这里给出两种分布的对比，用于说明"必须做重要性加权"的动机。
    """
    p = doc_freq / doc_freq.sum()
    sampled = RNG.choice(len(p), size=n_samples, p=p)
    # 真实检索分布：近似为 sqrt(频率) 归一化（热门但没那么极端）
    q = np.sqrt(p); q = q / q.sum()
    target = RNG.choice(len(p), size=n_samples, p=q)
    return {"批内负样本Top10%占比": round(float(np.isin(sampled,
             np.argsort(-p)[:max(1, len(p)//10)]).mean()), 3),
            "真实检索Top10%占比": round(float(np.isin(target,
             np.argsort(-p)[:max(1, len(p)//10)]).mean()), 3)}


if __name__ == "__main__":
    print("== 1. 温度如何分配梯度（前 3 难负样本拿走的负样本梯度占比）==")
    for tau, share in temperature_gradient_report():
        print(f"  τ={tau:<5}: 前3难负样本占比 ≈ {share:.3f}")
    print("  说明：τ 越小越集中（τ=0.05 时 97% 的负样本梯度集中在 3 个样本上）；")
    print("        τ 增大向'平均用力'靠拢，但只会渐近地趋向 3/(K−1)=3/7，")
    print("        不会真的达到 —— 因为 softmax 永远不会完全均匀")

    print("\n== 2. 批内假负样本概率 1−(1−ρ)^(K−1) ==")
    for K in (32, 64, 256, 1024):
        row = " ".join(f"ρ={r}: {false_negative_probability(K, r):.3f}"
                       for r in (0.001, 0.01, 0.05))
        print(f"  K={K:<5} {row}")
    print("  说明：主题集中的语料（ρ=0.05）上，K=64 就有 96% 的批次含假负样本")

    print("\n== 3. 批内负样本的频次偏差 ==")
    df = RNG.zipf(1.5, 2000).astype(float)        # 幂律分布，模拟真实文档频率
    print(" ", batch_negative_frequency_bias(df))
    print("  说明：批内采样的热门文档占比高于真实检索分布 → 需要重要性加权")

    print("\n== 4. 表示塌缩诊断（同一批向量，逐步注入共同方向）==")
    healthy = RNG.normal(0, 1, (500, 64))
    shared = RNG.normal(0, 0.1, (1, 64))         # 人为制造的"所有向量共有的方向"
    for alpha in (0.0, 0.5, 0.9):
        V = (1 - alpha) * healthy + alpha * 5.0 * np.ones((500, 1)) * shared
        print(f"  共同方向权重 α={alpha}:", collapse_diagnostic(V))
    print("  说明：α 增大 → 余弦均值趋近 1、标准差趋近 0。")
    print("        此时 recall@k 可能仍然不差（正确答案还在前 k 里），")
    print("        但 Top-1/Top-3 的分辨率已经丧失 → 排序问题而非召回问题")

    print("\n== 5. 一次真实的 InfoNCE 计算（含假负样本掩码）==")
    tt = TinyTwoTower(dim_in=32, dim_out=16)
    Q = RNG.normal(0, 1, (8, 32)); D = RNG.normal(0, 1, (8, 32))
    # 人为制造一对假负样本：文档 3 与查询 0 的正文档几乎相同
    D[3] = D[0] + 0.02 * RNG.normal(0, 1, 32)
    mask = np.zeros((8, 8), dtype=bool); mask[0, 3] = mask[3, 0] = True
    for tau in (0.07, 0.2):
        _, _, lp1 = tt.info_nce(Q, D, np.arange(8), tau=tau)
        _, _, lp2 = tt.info_nce(Q, D, np.arange(8), tau=tau, mask=mask)
        p1, p2 = np.exp(lp1), np.exp(lp2)
        print(f"  τ={tau}: 假负样本被赋予的概率 p(0→3)")
        print(f"          不屏蔽={p1[0,3]:.4f}  屏蔽后={p2[0,3]:.4f}   "
              f"正样本概率 p(0→0): {p1[0,0]:.4f} → {p2[0,0]:.4f}")
    print("  读法：屏蔽之前，模型把相当一部分概率质量分给了这对'互为答案'的样本，")
    print("        于是在梯度里把它当作负样本往下压（∂L/∂s = +p）；")
    print("        屏蔽之后这一项的概率与梯度都归零，正样本获得的相对梯度上升。")
    print("  注意：loss 的绝对值变化方向不确定（取决于该对相似度是否高于正样本），")
    print("        所以验收屏蔽效果要看**概率/梯度的重新分配**，不是看 loss 升降。")

三处关键设计决策：

  1. 用线性投影代替神经网络编码器。这是刻意的：本节要观察的是损失函数与采样分布的行为，换成任意编码器都不改变"温度分配梯度""批内假负样本""塌缩"这三条结论。把复杂度留在无关的地方，会让读者误以为这些现象来自模型结构。
  2. 假负样本掩码用 −109 而不是 0。置零意味着"这一对的分数应该是 0"（会产生梯度），掩码意味着"这一对不参与"（不产生梯度）。两种实现的训练结果完全不同 —— 这是一个具体的、容易写错的设计细节。
  3. collapse_diagnostic 与 recall 并列而非替代。塌缩时 recall@k 可能仍然可观（正确答案还在前 k 里），但排序分辨率已经坏了。把这两个指标分开，才能在出问题时判断"是没召回还是排错了"——这正是第 6 章失效归因的雏形。

练习#

  1. 推温度的梯度效应：从 L=−log∑j​exp(sj​/τ)exp(s+/τ)​ 出发，分别求 ∂L/∂s+ 与 ∂L/∂si−​。验证正文的两个式子。然后回答：当 τ→0 且正样本已经排第一时，∂L/∂s+ 趋于多少？这对应"哪些样本还在提供梯度"？
  2. 算假负样本概率：某代码库语料里 ρ=0.03（3% 的文档互为"近重复/同一文件的不同版本"）。分别算 K=32,128,512 时批内含假负样本的概率。若你只能用 K=32，设计一个基于规则的过滤把有效 ρ 降到 0.001，并估算这需要多少计算量（提示：近重复检测可以用 minhash/SimHash，成本与 token 数成正比）。
  3. 批大小 vs 梯度累积：你只能上 K=16 的批（显存限制），但想"模拟 K=256"。请说明为什么梯度累积不能增加批内负样本数，并给出一个真正能增加负样本数量的替代方案（提示：队列/记忆库式负样本）。然后指出该方案的代价（提示：负样本的"新鲜度"/滞后）。
  4. 设计难负样本流水线：写出一份完整流程：从当前模型检索 → 取 Top-100 中非正样本 → 过滤 → 混入训练批。要求明确：(a) 过滤规则有哪些（至少三条）；(b) 挖掘负样本与随机负样本的比例怎么定（给出理由）；(c) 多久重新挖掘一次（提示：模型在变，挖掘出的"难"样本会变易 —— 给出重挖频率的判据）。
  5. 归一化的三条等价性：证明"归一化后内积排序 = 余弦排序 = 欧氏距离升序"。然后构造一个不归一化的反例：两个文档，一个与查询余弦相似度高但模长小，另一个余弦相似度略低但模长大，使得内积排序与余弦排序相反。说明这个差别在什么业务场景下是"特性"、什么场景下是"bug"。
  6. 端到端召回上界：设模型侧 recall@100 = 0.92，ANN 索引 recall@100 = 0.85（相对精确搜索）。计算端到端 recall@100。若你把 ANN 参数调到 recall@100 = 0.98（但延迟翻倍），端到端提升多少？把这个提升与"把模型侧 recall@100 从 0.92 提到 0.95"的提升做对比，说明哪一个更划算，以及在什么条件下结论会反转。
  7. 失效诊断：线上稠密检索召回下降。请设计一个实验序列，把原因确定地归到四类失效之一： （a）领域漂移；（b）组合性/多条件；（c）精确标识符；（d）ANN 近似损失。 对每一类，写出：你会看的指标、判定阈值、以及确认后的修复动作。
  8. 表示塌缩：用 collapse_diagnostic 观察"负样本数从 7 降到 1"时余弦均值怎么变（提示：自己构造一个只有 2 篇文档的 batch）。解释这个变化与 InfoNCE 分母的关系，并说明为什么"把所有向量映射到同一点"是对齐性最优解、均匀性最差解。

小结#

  • 双塔不是"更弱的交叉编码器"，而是一个索引可行性的产物：只有文档侧编码与查询解耦，才能离线预计算并建 ANN 索引。N=107 时交叉编码器每查询要 107 次前向 —— 这是"能不能用"的分界，不是快慢权衡。
  • 双塔的代价是信息瓶颈：一篇几千 token 的文档被压成 d 维定长向量，精确细节（数字、标识符、否定）最容易被压掉；不同问题指向同一文档时难以区分。这是"稀疏保精确、稠密保泛化"的根源。
  • 相似度用内积是为了能建索引（MIPS）。归一化后内积/余弦/欧氏三者等价；不归一化时不等价，∥d∥ 成为隐式偏置，这个选择必须显式做。归一化要在训练目标里体现，不能只在推理时做。
  • InfoNCE = 用负采样近似的 softmax 分类损失。批内负样本数 K 就是这个分类问题的类别数，K 越大任务越难、表示区分度越高。
  • 温度 τ 控制梯度分配：∂L/∂s+=−τ1​(1−p+)、∂L/∂si−​=τ1​pi​。τ 小 → 分布尖 → 火力集中在难负样本上（大 batch 需要更小的 τ）；τ 大 → 平均用力，被大量易负样本稀释。
  • 批内负样本有三类偏差：频次偏差（热门文档被过度惩罚，需重要性加权）、假负样本（1−(1−ρ)K−1，ρ=0.05 时 K=64 已有 96% 的批次中招）、难度漂移（后期梯度枯竭，需要显式挖掘）。
  • 梯度累积不能替代大 batch —— 它不增加批内负样本数。这是对比学习与普通监督训练的一个关键区别。
  • 难负样本的梯度效率由 pi​ 的指数形式决定，这也是它危险的原因：越难的候选里假负比例越高。默认配方是"混合负样本 + 对挖掘部分过滤"，不是纯难负样本。
  • 几何视角：对齐性（正样本多近，差 → 召不回）与均匀性（向量多散，差 → 各向异性、排序失去分辨率）会互相冲突。诊断量是两两余弦相似度的均值与标准差：均值 > 0.8 就是塌缩信号。
  • 四类失效：领域漂移（可预测、表现为整体分数下移）、组合性/多条件（双线性形式只能表达"平均匹配"，枚举约束必须下沉为元数据过滤）、精确标识符（子词重叠导致近似 ID 互相混淆，必须稀疏兜底）、ANN 近似损失（与模型无关，必须用"精确内积全扫"做对照实验才能分离）。
  • 端到端召回是乘积：Re2e​≤Rmodel​×Rindex​。调试时先做这个分解，否则会在错误的地方花几周。

下一节：稀疏与稠密各有明确的失效，而且它们的失效看起来互不重叠 —— 这暗示了一个结论：把它们合起来会更好。但"看起来互补"不是证明。我们必须给出"混合为何有效"的可推导条件（误差不相关），并对比两条融合路线（加权求和 vs 排名融合）各自在什么假设下成立。
