多头注意力#

上一课的注意力只有一个"头"：整条序列共用一套 QKV 投影，每个词只在一个"关系视角"下看别人。但语言里的关系是多样的——主谓关系、修饰关系、指代关系……一个视角往往顾此失彼。多头注意力（multi-head attention）的解法很直接：并行跑多个头，每个头用不同的投影参数，各自关注不同的关系，最后把结果拼起来。这一课我们把它从头实现一遍。

一、概念讲解#

1. 一个头不够，多来几个#

单一注意力头会把所有信息压进一个"平均"的关系里。例如处理"银行的河流"时，同一个头很难同时既关注"银行"与"河流"的搭配，又关注"河流"与远处某个修饰语的关系——权重一旦被大关系占据，小关系就被稀释。

多头注意力让 h 个头各干各的：每个头有自己独立的 W_q、W_k、W_v 投影，因此每个头学到的"关系子空间"不同。有的头可能专盯邻近词，有的头专盯句法上的远距离搭配，有的头专盯指代。最后把各个头的输出拼接，再经一个线性层融合，得到既丰富又统一的表示。

2. 结构：并行投影 → 各自注意 → 拼接 → 融合#

多头的完整流程：

  1. 把输入分别投影成 h 组 Q、K、V（每组维度 d_head = d_model / h）；
  2. 每个头独立做一次缩放点积注意力，得到 h 个输出（每个 d_head 维）；
  3. 把 h 个头的输出按特征维拼接，回到 d_model 维；
  4. 再过最后一个可学习的线性层 W_o 融合各头信息。

公式写作：

MultiHead(Q, K, V) = Concat(head_1, ..., head_h) W_o
head_i = Attention(Q W_q^i, K W_k^i, V W_v^i)

3. 为什么"切小"而非"加宽"#

多头没有增加总参数量，而是把 d_model 拆成 h 份，每份一个头。这样做的好处是：与其让一个宽头学一个笼统的关系，不如让多个窄头并行探索不同的关系子空间。这正是论文所说的"让模型在不同的表示子空间里联合关注来自不同位置的信息"。

代价是每个头的维度变小（d_head = d_model / h），单头的表达力下降；但多个头互补，整体更强。所以 d_model 通常要被 h 整除，这也成了实现时的第一行断言。

4. 多头后的参数量与计算量#

多头注意力比单头多出的，只有最后的融合层 W_o（还有"分头切分"这个视角带来的组织开销）。总计算量仍与单头同阶，却换来了多视角的表达力——性价比极高。这也是为什么几乎所有后续大模型（BERT、GPT 等）都原封不动沿用多头结构。

二、可运行代码示例#

下面从零实现一个 MultiHeadAttention，用一次前向验证输出形状和"每个头一张注意力图"的结构。

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        assert d_model % num_heads == 0, "d_model 必须能被头数整除"
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_head = d_model // num_heads
        # 三个投影：一次把 d_model 投影成 d_model，再在 forward 里切分成多头
        self.Wq = nn.Linear(d_model, d_model, bias=False)
        self.Wk = nn.Linear(d_model, d_model, bias=False)
        self.Wv = nn.Linear(d_model, d_model, bias=False)
        self.Wo = nn.Linear(d_model, d_model, bias=False)   # 融合各头

    def forward(self, x):
        B, T, _ = x.shape
        # 投影后切成 h 个头，再转成 (B, h, T, d_head) 方便批量算注意力
        Q = self.Wq(x).view(B, T, self.num_heads, self.d_head).transpose(1, 2)
        K = self.Wk(x).view(B, T, self.num_heads, self.d_head).transpose(1, 2)
        V = self.Wv(x).view(B, T, self.num_heads, self.d_head).transpose(1, 2)

        scores = Q @ K.transpose(-2, -1) / (self.d_head ** 0.5)   # (B, h, T, T)
        attn = F.softmax(scores, dim=-1)
        out = attn @ V                                            # (B, h, T, d_head)

        # 把多头拼回：先转回 (B, T, h, d_head)，再拼成 (B, T, d_model)
        out = out.transpose(1, 2).contiguous().view(B, T, self.d_model)
        return self.Wo(out), attn

B, T, d_model = 2, 5, 12
x = torch.randn(B, T, d_model)
mha = MultiHeadAttention(d_model, num_heads=3)
out, attn = mha(x)

print("输出形状:", out.shape)        # (2, 5, 12)，与输入一致
print("注意力矩阵形状:", attn.shape)  # (2, 3, 5, 5)：每个样本每个头一张注意力图
print("每个头的维度:", mha.d_head)    # 12 // 3 = 4
print("参数量:", sum(p.numel() for p in mha.parameters()))

运行后注意两点：

  • out 与输入 x 形状相同，说明多头注意力是一个"保形"的构件，可以像积木一样反复堆叠（这是下一章编码器的前提）；
  • attn 的形状是 (B, h, T, T)，即每个头各自产生一张注意力矩阵。把不同的头打印出来，常能看到它们关注着截然不同的位置——这就是"多视角"的直接证据。

三、练习#

  1. 把 num_heads 改成 1，观察输出形状与参数量；再改成 4，确认参数量几乎不变（只差在 W_o 前的组织方式），理解"多头不靠堆参数取胜"。
  2. 打印同一输入下不同头的注意力矩阵，比较它们关注的差异，体会"不同子空间关注不同关系"。
  3. 在 __init__ 里去掉 assert，用一个不能被整除的组合（如 d_model=10, num_heads=3）跑一遍，观察 view 报什么错，从而理解为什么论文里 d_model 总是 h 的整数倍。
  4. 思考：如果把"拼接后过 W_o"换成"对 h 个头的输出直接求平均"，会损失什么？W_o 在这里承担了什么样的角色？
