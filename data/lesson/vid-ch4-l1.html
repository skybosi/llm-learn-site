长视频处理：分块、滑窗、记忆机制与漂移的可算形式#

这一节要解决什么#

第 1 章与第 2 章的所有结论都建立在一个隐含前提上：你能把要处理的那段视频一次装进模型。第 1 章的采样账、token 账、显存账是在"给定 N 个 token"之后算的；第 2 章的四个任务是在"给定一段裁剪好的片段"或者"给定一条可以逐帧扫过去的序列"之后算的；第 3 章把"预测"换成"生成"时，撞上的是同一面墙。这一章把这个前提撤掉：

视频长度从 10 秒变成 1 小时、10 小时、7×24 小时的连续流之后，什么东西是按长度线性增长的，什么东西是按长度爆炸的，什么东西是按长度累积的？三类机制（分块、滑窗、记忆）各自把哪一笔账换成了哪一笔账？以及——为什么"误差累积"不是一个形容词，而是一个可以解出重锚周期的方程？

这一节的全部结论如下：

  1. 分块不是"近似掉一点点"，它近似掉的是 1−b/N 的全部跨块信息。 块内全注意力的对数保留比例恰好是 b/N：N=65536、b=512 时保留 0.007812、丢弃 0.992188（表 1）。块越大保留越多，但块内二次项代价随之线性上升——这是一个只有一个旋钮的天平，旋钮就是 b。
  2. 滑窗堆层补不回全域感受野，因为感受野线性增长而层数是常数。 stride=1、宽 w 的滑窗 l 层后 RF(l)=1+l(w−1)；要求 RF≥N 需要 l∗=⌈(N−1)/(w−1)⌉ 层：N=65536、w=512 时是 129 层（表 1）。几十层的模型靠滑窗永远看不见第 128 块。
  3. 全局记忆槽位的代价是线性的（N⋅m 对数，不是 N2），但它是一个率受限信道。 容量上界 C=m⋅d⋅bq​：m=64、d=1152、bq​=16 时 C=1179648 bit =1.1796 Mbit。若每帧状态需 r=104 bit，只能携带 117.96 帧（约 3.93 秒 @30 fps）；若要无损存原始像素，只能携带 0.023704 帧（表 2）。"无损长记忆"不是一个待优化的目标，它是一个不存在的东西。
  4. 误差累积有一条闭式解，而且它把"漂移"拆成两个独立参数。 εk​=λεk−1​+ρ 的解是 εK​=λKε0​+ρ(λK−1)/(λ−1)。λ=1,ρ=0：恒为 0.010000；λ=1,ρ=0.005：线性累积到 5.010000（K=1000）；λ=0.98：收敛到 ε∞​=ρ/(1−λ)=0.250000，半衰期 34.3096 块；λ=1.01：翻倍时间 69.6607 块，K=1000 时 ε=10688.669375；λ=1.10：翻倍时间 7.2725 块，K=100 就已经 826.786740（表 3）。λ 只差 0.03，同一个 1000 块之后误差差三个量级。
  5. 只算 λ 不算 ρ 会把安全周期高估 5.8 倍。 λ=1.01、ρ=0.005、容差 εmax​=0.5 时，含 ρ 的 K∗=67.6706 块（重锚周期 68），忽略 ρ 的 K∗=393.1551 块——高估 5.8098 倍（表 6）。λ=0.98 时误差有渐近上界 ε∞​=0.25：容差 0.5 下永远不必重锚，容差 0.2 下每 78 块重锚一次（表 6）。
  6. 检索式 vs 全量是 164.59 倍的算力差、540.00 倍的 KV 差，不是"快一点"。 1 小时 1080p30（108000 帧、2.7648×107 token）上：全量注意力 9.8652×1019 FLOPs（11.42 天）、分块全扫 2.5570×1016（4.26 分钟）、检索式 1.5535×1014（1.55 秒）；KV cache 分别是 3.2444 TiB / 6.1523 GiB（top-200 帧） / 每帧 0.0308 GiB（表 4）。
  7. "检索式便宜"只在事件足够长时成立。 独立帧选择器的帧级召回上界是 Rhit​(p,G)=1−(1−p)G：p=0.02、G=10 时只有 0.182927；要 0.90 召回，G=10 需 p=0.205672（22213 帧）、G=1000 只需 p=0.002300（248 帧）——事件时长缩 100 倍，采样密度要涨 9.0 倍（表 5）。
  8. 三类机制必须一起用，因为它们修的是三种不同的东西：分块修二次项，滑窗修边界断点，记忆修跨块可达性；而 ρ（每块新增误差）与 λ（误差放大）只能靠重锚/重置压，不能靠加宽窗口压。

一、长视频的约束从哪来：三笔账在同一处爆炸#

1.1 先把"长"换算成 token#

沿用第 1 章的 token 账 N=(T/t)(H/p)(W/p)。为了后面所有数字可核对，本节固定一组工程参数（它们是"取量级"的算例参数，不代表任何真实系统的配置）：

符号 值 含义
fs​ 30 fps 帧率
T 3600 s 视频时长（1 小时）
Nf​ 108000 帧数
Nc​ 256 每帧 token 数
d 1152 隐藏维
L 28 层数
s 2 B 每个标量字节（bf16）
nh​ 16 注意力头数
Feff​ 1014 FLOP/s 有效算力（约等于"峰值 × 30% 利用率"的量级）

于是总 token 数

Ntot​=Nf​⋅Nc​=108000×256=2.7648×107

这个数字本身不吓人。吓人的是第 1 章那条单层账 4N2d+24Nd2 里的第一项：

4Ntot2​d=4×(2.7648×107)2×1152≈3.5224×1018 FLOPs /层

乘 28 层，加上第二项，全量双向注意力一共 9.8652×1019 FLOPs（表 4 第 1 行）。按 1014 FLOP/s 折算是 11.42 天——而且这还是"算得动"的部分，同一配置的 KV cache 是

KV=2LNtot​ds=2×28×2.7648×107×1152×2 B=3.2444 TiB

单卡放不下。注意这两笔账的增长阶不同：算力是 O(N2)，显存是 O(N)。所以"把视频变长"这件事，先撞墙的是算力，第二个撞墙的是显存，而这两个墙的位置相差 N 倍——这就决定了长视频的所有工程方案都长成同一个形状：先用一切手段把 N 降下来（降采样/裁剪/合并），再对剩下的 N 做 O(N2) 的事，而跨块的部分用 O(N) 的记忆去接。

1.2 分块：把 N2 换成 N⋅b，代价是 1−b/N#

分块（chunking）的定义很朴素：把序列切成 K=N/b 块，每块内部做全注意力，块与块之间不看。于是对数从 N2 降到

K⋅b2=N⋅b⟹保留比例=N2Nb​=Nb​

为什么这样设计：因为 4N2d 这一项跟 N 是二次关系，而工程上能加的显存是常数。把 N 分段之后，单次前向的 token 数从 N 变成 b，二次项从 4N2d 变成 K⋅4b2d——总二次项代价被压成原来的 b/N，而且这个比例与 N 无关地只跟 b 有关，于是显存峰值与视频长度解耦：这是分块真正买到的东西。表 1 的数字：

N b K 保留对数比 b/N 丢失比例
4096 256 16 0.062500 0.937500
65536 512 128 0.007812 0.992188
1048576 1024 1024 0.000977 0.999023

N=65536、b=512 时保留 0.7812%。这就是"分块近似掉了什么"的准确答案：它不是丢掉了 (0.78%) 的信息，而是丢掉了 (99.22%) 的注意力对。 在注意力是均匀的极端假设下，一个块内 query 能看到的 key 质量只有全量的 b/N——这是理想化下界（真实注意力不是均匀的，长视频里大量 key 的权重确实接近 0，这正是分块在实践中能工作的原因），但它是唯一的、可当场算出来的判据。

边界/取舍：b 是唯一旋钮，而它同时被两个方向夹住：

  • b 太大 → 二次项回来，显存峰值回升，分块的意义消失；
  • b 太小 → 跨块信息被丢得更多，且块边界处出现硬断点（见 1.3）。

一个常见的误判是把 b 说成"超参"，实际上在显存预算 M 给定之后 b 是被解出来的：单块 score 物化 nh​b2s 加上激活 Lcact​bds 必须小于 M。用本节的参数（nh​=16,s=2,L=28,cact​=10,d=1152）：

16b2⋅2+28⋅10⋅b⋅1152⋅2≤M⟹32b2+645120b≤M

16b2⋅2+28⋅10⋅b⋅1152⋅2≤M⟹32b2+645120b≤M

M=40 GiB =4.295×1010 B 时解出 b≤6.63×104——在这个参数下显存根本不是 b 的约束，真正的约束来自 1.4 的时延与精度。这是一个有用的反向结论：多数长视频系统的 b 不是被显存决定的，而是被"每块要覆盖多长的时间"决定的。

1.3 滑窗：为什么"堆层"补不回感受野#

滑窗（sliding window）与分块的对数账完全一样（每个 query 看 w 个 key，共 N⋅w 对），差别在感受野的增长方式。stride=1、宽 w 时，l 层的感受野是

RF(l)=1+l(w−1)

要求 RF(l)≥N，即

l∗(N,w)=⌈w−1N−1​⌉

l∗(N,w)=⌈w−1N−1​⌉

表 1 B 部分：N=65536,w=512⇒l∗=129；N=1048576,w=4096⇒l∗=257。感受野是线性长的，层的数量是常数（几十层），所以滑窗结构性地无法把信息从第 1 块传到第 128 块。这不是训练问题、不是容量问题，是 RF 的算术问题。

为什么还会用滑窗：因为它修的是分块的硬断点。分块里第 k 块的最后 b/2 帧与第 k+1 块的前 b/2 帧之间没有任何连接；滑窗用重叠（stride s<w）让每帧出现在 ⌈w/s⌉ 个窗口里，把断点变成"上下文减半"的渐变。代价是计算量变成 Nw/s 而不是 Nw——重叠是拿算力买连续性的。

怎么做：工程上三者是叠着用的，典型形状是"局部滑窗 + 全局槽位"：

对数=局部N⋅w​​+全局N⋅m​​,N2N(w+m)​=Nw+m​

表 1 C 部分：N=65536,w=512,m=256 时总对数比 0.011719（对比纯分块的 0.007812：多花 0.003906 的比例就买到了"跨块跳数 =1"）。这是全章最划算的一笔交易：全局通路的对数代价是线性的，而且斜率极小。

1.4 记忆机制：它不是缓存，是率受限信道#

记忆机制常见的三种形状（第 1 章已按形状分类，这里只关心容量）：

形状 更新式 跨块可达 代价
池化/压缩 mk​=g(blockk​) 一层 N⋅m 对数 + m 个槽位
注意力记忆 mk​=Attn(q,mk−1​,blockk​) 一层 同上 + 每块一次 O(m2+bm)
状态空间 hk​=Aˉhk−1​+Bˉxk​ 一层 O(bd)，与 m 无关但状态维固定

三者共有的约束被一个不等式锁死：把记忆看成一个率受限信道，m 个 token、每 token d 维、每维 bq​ bit，容量上界

C=m⋅d⋅bq​

（上界：假设完美编码、且不含当前块）。表 2 的核心读数：m=64,d=1152,bq​=16⇒C=1179648 bit=1.1796 Mbit。

  • 若每帧的"状态"只需 r=104 bit（1.25 KiB 的语义内容），可携带 117.96 帧，按 30 fps 是 3.93 秒；
  • 若要求无损保存原始像素（r=49766400 bit/帧），只能携带 0.023704 帧。

为什么这样设计：因为不存在"无损长记忆"这个选项，所有长视频记忆系统做的都是同一件事的变体——选择用什么 r 去换多少秒。把这句话写成预算式：要携带 T 秒历史，每帧可用

bframe​=Tfs​mdbq​​ bit

T=3600 s 时 bframe​=10.92 bit/帧——比"一帧里存一个类别标签"（约 8∼11 bit）还紧；相对原始帧位宽只有 2.194787×10−7。这就是为什么长视频记忆必须是任务相关的：你不可能存下所有东西，只能存下你决定要的东西，而这个决定就是模型的归纳偏置。

取舍/边界：表 2 的 C 是上界，实际有效容量还要打折，打折的两个来源可算：

  • 量化损失：bq​=16 的浮点编码不是均匀码本，相对量化误差上界是 2−8=0.003906（bf16 的 7 位显式尾数，加隐含位共 8 位有效位），叠到 d 维上后槽位的可用分辨率下降；
  • 干扰/串扰：第 1 章那条串扰账 (N−1)/d​ 说的是"d 维能记住 d 项"只是上界。d=1152 时，要区分 N=117.96 帧的状态（每帧 104 bit 挤进 d 维），实际是超载使用，必须靠任务结构（例如只记住"谁在哪里、发生了什么"这类低熵摘要）把 r 压下来。

三、漂移与误差累积的定量形式#

3.1 一阶模型与它的闭式解#

沿块（或沿帧、沿 rollout 步）递推的误差几乎总能用一阶线性模型刻画：

εk​=λεk−1​+ρ,ε0​ 给定

  • λ：误差传递系数（一步把一个误差放大/缩小多少倍）；
  • ρ：每块新增误差（本块的量化、近似、采样、压缩引入）。

解为

εK​=⎩⎨⎧​λKε0​+ρλ−1λK−1​,ε0​+ρK,​λ=1λ=1​

εK​=⎩⎨⎧​λKε0​+ρλ−1λK−1​,ε0​+ρK,​λ=1λ=1​

这条式子是本节的中心。它把"漂移"从形容词变成了两个可以分别测量的数：λ 靠"注入扰动看它几步后剩多少"测，ρ 靠"单块误差底噪"测。表 3 同时用闭式解和逐块递推算了一遍，最大相对偏差 1.887×10−14（双精度舍入），所以这张表的每一格都是可信的。

与第 3 章第 3 节（vid-ch3-l3）的边界与记号对照：同一个递推在生成侧也会出现，那一节写的是 en+1​=ρen​+δn​，本课这里写的是 εk​=λεk−1​+ρ——它们是同一条式子，但字母对调了（生成侧的 ρ 对应本节的 λ，生成侧的 δ 对应本节的 ρ）。读跨章节材料时先对齐字母。分工上：第 3 章管生成侧（自回归 rollout、exposure bias、关键帧锚定的一致性定价），本节管理解侧（双向注意力不可分解、记忆的信道容量、以及"精度容差 → 重锚周期"的工程反解）。机制（分块/滑窗）两边都出现，但失效条件不同：生成侧问"接缝处分布是否连续"，理解侧问"跨块证据是否可达"。

3.3 重锚周期的反解#

λ>1 时，给定容差 εmax​，最长可以连续跑多少块？直接解 εK​=εmax​：

K∗=lnλln(ε0​+ρ/(λ−1)εmax​+ρ/(λ−1)​)​

K∗=lnλln(ε0​+ρ/(λ−1)εmax​+ρ/(λ−1)​)​

表 6 把 λ∈{1.005,1.01,1.02,1.05}、ρ∈{0,0.005,0.02}、εmax​∈{0.1,0.5} 全算了一遍。核心对照：

λ=1.01, ρ=0.005, ε0​=0.01, εmax​=0.5⟹K∗=67.6706 (重锚周期 68)

λ=1.01, ρ=0.005, ε0​=0.01, εmax​=0.5⟹K∗=67.6706 (重锚周期 68)

而只算 λ 的算法 K∗=ln(εmax​/ε0​)/lnλ=393.1551（周期 394）——高估 5.8098 倍。ρ 越大高估越离谱：ρ=0.02、εmax​=0.1 时高估 52.5673 倍。这就是"重锚周期靠经验定"这件事的代价：经验值通常落在"只算 λ"的那一档上。

λ<1 时公式换一个方向（误差有上界）：

ε∞​=1−λρ​,εmax​≥ε∞​⇒永不重锚,εmax​<ε∞​⇒K∗=lnλlnε∞​−ε0​ε∞​−εmax​​​

ε∞​=1−λρ​,εmax​≥ε∞​⇒永不重锚,εmax​<ε∞​⇒K∗=lnλlnε∞​−ε0​ε∞​−εmax​​​

3.4 "漂移"的两种含义必须分开#

中文语境里"漂移"被用在两件完全不同的事上，混用会让讨论失去判据：

含义 可测量 修法
数值/状态漂移 εk​=λεk−1​+ρ 的累积 注入扰动后的衰减曲线 → 拟合 (λ,ρ) 重锚、阻尼、残差连接、降低 ρ
分布漂移 输入分布 pt​(x) 随时间变化 相邻时间窗的特征分布距离（如两窗均值差 / 合并标准差） 在线自适应、滑窗重训、周期性重标定

两者的可算判据不同：前者是时间上的误差递推，后者是分布之间的距离。一个系统可以 λ<1（不累积）而仍然被分布漂移打崩，反之亦然。讨论"长视频模型为什么会退化"时，先说清是哪一个。

四、检索式（先找片段再理解）vs 全量处理#

4.1 两段式：粗排 + 精读#

检索式长视频理解的形状是两段：

全量、线性、便宜便宜特征→粗排​​ ⟶ 少量、二次、贵大模型只读 top-K​​

为什么这样设计：因为"找"和"理解"的代价阶数不同。找是逐帧独立的（每帧一个向量，与查询做点积），代价 O(Ndf​)；理解是帧间耦合的（注意力二次），代价 O(Nc2​d) 级别。表 4 的账：

4.2 召回的可算下界：为什么短事件必须提高采样密度#

把粗排抽象成一个独立帧选择器（每帧以概率 p 被选中，平均间隔 Lˉ=1/p 帧）。一个长度 G 帧的相关事件被"至少选中一帧"的概率是

Rhit​(p,G)=1−(1−p)G

精读成本的线性系数是期望选中帧数 E[选中]=Np。表 5：

4.3 什么时候检索式会输#

三类可算的反例，都可以在动手前用上面的式子判断：

  1. 答案需要跨片段的全局关系（"整个视频里出现了几次同类事件""哪一段最异常"）。这类问题不能用"取 top-K 再读"回答，因为答案不在任何单个片段里。判据：把问题形式化成"需要聚合函数 over 全部片段"时，检索式结构性不适用。
  2. 短事件：G 小时 p∗ 迅速趋向 1（表 5 反解），此时检索式退化成"全量精读"，却还要多付一遍粗排成本。
  3. 粗排与精读的目标不一致：粗排的特征空间是为"帧级相似"训练的，而任务需要"片段级语义"。这个错配无法用加大 K 修，只能换粗排目标。可算的判据是粗排召回率 vs K 的曲线：如果 R@K 在 K=100→1000 只涨几个百分点，说明粗排已经把正确片段排在了很后面，加 K 是浪费。

取舍：检索式与全量不是二选一，而是同一预算下的两种分配。给定 FLOPs 预算 F，你可以把它全给"对每一帧做一次便宜处理"，也可以分一部分给"对少量帧做一次昂贵处理"。分界点在

全量便宜Nccheap​​​=检索式Nccheap​+Kcexp​​​/精度

——即"精度增益是否值得 K⋅cexp​"。这个问题没有通用答案，但表 4 告诉你预算的量级差（164.59 倍），表 5 告诉你精度差的可算下界（Rhit​）。

def eps_closed(K, lam, e0, rho):
    if abs(lam - 1.0) < 1e-15:
        return e0 + rho * K
    lk = K * math.log(lam)
    if lk > 700.0:                      # lam^K 已超出双精度可表示范围
        return float("inf")
    lK = math.exp(lk)
    return lK * e0 + rho * (lK - 1.0) / (lam - 1.0)


def eps_recur(K, lam, e0, rho):
    e = e0
    for _ in range(K):
        e = lam * e + rho
    return e

def solve_K(lam, e0, rho, eps_max):
    if abs(lam - 1.0) < 1e-15:

    return math.log(tgt) / math.log(lam)

小结#

  • 长度把三笔账分开了。 算力 O(N2)、显存 O(N)、误差 O(块数)——先撞算力墙，再撞显存墙，最后被误差累积拖垮。1 小时 1080p30（2.7648×107 token）上全量注意力是 9.8652×1019 FLOPs（11.42 天）与 3.2444 TiB KV。
  • 分块的保留比例恰好是 b/N：N=65536,b=512⇒0.007812。它丢掉的不是 0.78% 的信息，是 99.22% 的注意力对；b 是唯一旋钮，而这个旋钮在多数配置下由"每块覆盖多长时间"决定，不由显存决定。
  • 滑窗的 RF=1+l(w−1) 是线性长的，N=65536,w=512 要 129 层才能全域可见。堆层补不回跨块可达性，必须加全局通路（N⋅m 对数，线性且斜率极小：m=256 只加 0.003906 的比例）。
  • 记忆是率受限信道，容量上界 C=mdbq​：m=64⇒1.1796 Mbit，r=104 bit/帧只能携带 117.96 帧（3.93 秒）。携带 1 小时时每帧只剩 10.92 bit——无损长记忆不存在。
  • 误差累积有闭式解 εK​=λKε0​+ρ(λK−1)/(λ−1)。λ=1 是相变线：0.98 收敛到 0.250000（半衰期 34.3096 块），1.01 翻倍时间 69.6607 块、K=1000 时 10688.669375——λ 差 0.03，误差差四个量级。
  • 重锚周期可反解，而且只算 λ 会高估 5.8098 倍（λ=1.01,ρ=0.005,εmax​=0.5：67.6706 vs 393.1551）。λ<1 时先看 ε∞​=ρ/(1−λ) 是否已达标：已达标就永不重锚。
  • 检索式 vs 全量是 164.59 倍的算力差、540.00 倍的 KV 差（分块全扫 vs 检索式），全量与检索式差 635017.81 倍。瓶颈在便宜特征的质量，不在精读模型。
  • "检索式便宜"以事件时长为条件：Rhit​=1−(1−p)G；要 0.90 召回，G=10 需 p=0.205672（22213 帧）、G=1000 只需 0.002300（248 帧）——事件缩 100 倍，密度涨 9.0 倍。
  • 报数清单：(fs​,T,Nf​,Nc​)、(b,w,stride,m,bq​)、实测 (λ,ρ,ε0​) 与 K∗、(p,Ktop​,Rhit​)、以及 FLOPs/KV/带宽/延迟四笔账。缺任何一格，"长视频方案"就退化成一句口号。
