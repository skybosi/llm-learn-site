项目：给定模型与机器，产出并行方案 + 预算表并实测验证#

前三课给了三块零件：三本账（第 1 课）、成本模型（第 2 课）、训练与推理的对照（第 3 课）。这一课把它们收成一个可交付物：一份报告卡——给定模型与机器，输出并行组合、三本账、预算表、验收门与风险。难点不在跑得快，而在说清为什么选它：每个数字都要能追溯到参数量、字节数或 α-β 里的某一项。没有 GPU 也能完成：预测列全部由账本算出，实测列按下面的可选步骤补，并且明确写出"实测缺失"这一风险。

一、概念讲解#

1. 交付物：一张有字段约束的报告卡#

字段 口径 为什么必须有
模型与机器 L,h,a,V,s；卡数、每卡显存、峰值、α、β、单价 没有它们，后面的数字全都不可复现
方案 (TP,PP,DP,ZeRO 档)、microbatch、累积步数、是否重算 配置是并行方案的一部分，不是实现细节
显存账 参数状态 / 激活 / 预留，逐项加总 判断"装不装得下"的唯一依据
通信账 每卡每步搬运字节、α 次数、重叠比例 解释效率损失来自哪里
效率与预算 单步 ms、扩展效率、GPU·h、$、墙钟天、$/1B token 决策的直接输入
正确性门 与参考实现的逐元素比对 + 单步 loss 对齐 没过门的性能数字无效
实测对照 预测 vs 实测，偏差与归因 账本的可信度靠偏差验证
风险与结论 显存余量、网络假设、依赖项 让评审能反对你的假设

2. 输入与硬约束#

输入：模型配置 + 机器规格。硬约束有三条，任何候选先过它们：① TP 必须整除注意力头数 a（每卡要拿到完整的头）；② PP 不超过层数 L，且每 stage 的层数要能均分；③ TP×PP×DP 等于实际卡数。显存约束是第四条：每卡占用量（参数状态 + 激活 + 预留）不超过每卡显存。

3. 枚举候选而不是拍脑袋#

候选集不用很大，够覆盖三个方向即可：纯 DP（装不下就淘汰）、最小分片代价的 ZeRO 档、以及 TP/PP 组合（用于装不下或缩短关键路径）。示例里 7B 与 65B 各有 8 个候选，全部打印——被淘汰的候选也要给出理由（显存超了、效率低于判据、还是通信量翻倍）。

4. 选型判据：先可行性，再效率，最后单价#

顺序不能反：① 显存装得下；② 扩展效率达到判据（本项目用 ≥85%）；③ 在满足前两条的集合里取 /1B token 最小。示例里 7B 选 TP1 PP1 DP8 Z2（37.0 GiB/卡、效率 97.7%、$50.4/1B）；65B 选 TP4 PP1 DP16 Z3（32.6 GiB/卡、效率 85.7%、$564.7/1B），而 TP1 PP1 DP64 只差一点就装不下（85.1 GiB > 80 GiB）被淘汰——这说明"卡数够"不等于"方案可行"。

5. 实测验证：三个必须量到的数#

预测列由账本给出，实测列至少要量三件事：① 单步时间（热身若干步后取中位数）；② 峰值显存（torch.cuda.max_memory_allocated()）；③ 通信时间占比（nccl-tests 的实测 α、β 或 profiler）。偏差归因分三处查：预测偏低多半是 MFU 估高了（小 microbatch、算子碎片）；预测偏高多半是重叠估低了；显存偏差看激活重算与碎片。

6. 项目验收标准与常见坑#

验收：① 正确性门全过；② 预测与实测的单步时间偏差在 ±20% 内（超过就要归因）；③ 预算表的每个数字都能手算复算；④ 明确写出网络假设（β 取的是哪条链路的实测值）。常见坑：只报表内最优方案而不报淘汰理由；用示例参数冒充实测（表里要把"示例"与"实测"分开标注）；漏掉检查点与故障开销；把 7B 的方案直接套到 65B 上（激活按 a⋅s2 涨，TP 需求完全不同）。

二、可运行代码示例#

一段纯 Python：输入模型与机器，枚举候选、过显存约束、算三本账与预算表、给出选定方案与淘汰理由，最后跑一次 numpy 正确性门。

# ===== 项目：给定模型与机器，产出并行方案 + 预算表 =====
import numpy as np

MODELS = {
    "7B":  dict(layers=32, hidden=4096, heads=32, vocab=32000, seq=4096),
    "65B": dict(layers=80, hidden=8192, heads=64, vocab=32000, seq=4096),
}
MACHINE = dict(mem_gib=80, peak=990e12, mfu0=0.45, alpha_us=5.0, bw_gbps=200.0,
               price_per_gpu_h=2.0, nodes=8, gpus_per_node=8)
TOKENS_TOTAL, MICRO, ACCUM, OVERLAP = 300e9, 1, 4, 0.85

def n_params(c):
    return c["layers"] * 12 * c["hidden"]**2 + c["vocab"] * c["hidden"]

def n_heads_ok(c, tp):
    return c["heads"] % tp == 0 and (c["heads"] // tp) > 0

def act_gib(c, tp, pp, micro=MICRO):
    s, h, a = c["seq"], c["hidden"], c["heads"]
    terms = 3*s*micro*h*2 + s*micro*h*2 + 2*s*micro*4*h*2 + 2*s*micro*h*2   # 已开注意力重算
    return terms / tp * c["layers"] / pp / 2**30

def mem_gib(c, dp, tp, pp, stage):
    P = n_params(c)
    Psh = P / tp / pp
    model = {0: Psh*16, 1: Psh*(4 + 12/dp), 2: Psh*(2 + 14/dp), 3: Psh*(16/dp)}[stage]
    return (model + act_gib(c, tp, pp) * 2**30) / 2**30

def plan(c, N, dp, tp, pp, stage, micro=MICRO):
    P = n_params(c)
    tokens_step = c["seq"] * micro * ACCUM * dp
    t_cmp = 6 * P * tokens_step / (N * MACHINE["peak"] * MACHINE["mfu0"]) * 1e3
    S = (2 if stage < 3 else 3) * P * 2
    per_rank = 2*(dp-1)/dp*S if dp > 1 else 0.0
    t_comm = 2*(dp-1)*MACHINE["alpha_us"]/1e3 if dp > 1 else 0.0
    t_comm += per_rank / (MACHINE["bw_gbps"]*1e9) * 1e3
    if tp > 1:
        msg = (tokens_step // dp) * c["hidden"] * 2
        tp_bytes = c["layers"] * 2 * (2*(tp-1)/tp) * msg
        per_rank += tp_bytes
        t_comm += tp_bytes / (MACHINE["bw_gbps"]*1e9) * 1e3
        t_comm += c["layers"] * 2 * 2 * (tp-1) * MACHINE["alpha_us"] / 1e3
    bubble = (pp-1)/(micro+pp-1)
    t_step = t_cmp*(1+bubble) + t_comm*(1-OVERLAP)
    eff = t_cmp / t_step * 100
    steps = TOKENS_TOTAL / tokens_step
    gpu_h = N * steps * t_step / 1000 / 3600
    mem = mem_gib(c, dp, tp, pp, stage)
    return dict(plan=f"TP{tp} PP{pp} DP{dp} Z{stage}", mem=mem, eff=eff, t_step=t_step,
                days=steps*t_step/86400e3, gpu_h=gpu_h, cost=gpu_h*MACHINE["price_per_gpu_h"],
                usd_per_1b=gpu_h*MACHINE["price_per_gpu_h"]/(TOKENS_TOTAL/1e9),
                per_rank_comm_gb=per_rank/1e9, tokens_step=tokens_step)

CANDS = {
    "7B":  (8,  [(1,1,8,3),(2,1,4,3),(4,1,2,3),(1,2,4,3),(2,2,2,3),(1,1,8,2),(1,1,8,0),(2,1,4,2)]),
    "65B": (64, [(1,1,64,3),(8,1,8,3),(4,1,16,3),(4,2,8,3),(8,2,4,3),(2,4,8,3),(16,1,4,3),(8,1,8,2)]),
}
for name, (N_TOTAL, cands) in CANDS.items():
    c = MODELS[name]
    print(f"\n==== 报告卡：{name}（≈{n_params(c)/1e9:.1f}B，{c['layers']} 层）× 卡池 "
          f"{MACHINE['nodes']}×{MACHINE['gpus_per_node']}={MACHINE['nodes']*MACHINE['gpus_per_node']} 卡"
          f"，本方案用 {N_TOTAL} 卡（每卡 {MACHINE['mem_gib']} GiB）====")
    print(f"  {'方案':<16} {'卡数':>4} {'显存/卡':>8} {'效率':>6} {'单步 ms':>8} {'墙钟天':>7} {'$/1B token':>10} {'可行':>5}")
    rows = []
    for tp, pp, dp, stage in cands:
        N = tp*pp*dp
        if N != N_TOTAL or not n_heads_ok(c, tp) or pp > c["layers"]:
            continue
        r = plan(c, N, dp, tp, pp, stage)
        ok = r["mem"] <= MACHINE["mem_gib"]
        print(f"  {r['plan']:<16} {N:>4} {r['mem']:>8.1f} {r['eff']:>5.1f}% {r['t_step']:>8.1f}"
              f" {r['days']:>7.1f} {r['usd_per_1b']:>10.1f} {'✓' if ok else '✗':>5}")
        if ok:
            rows.append(r)
    cheap = min(rows, key=lambda r: r["usd_per_1b"])
    target = [r for r in rows if r["eff"] >= 85]
    pick = min(target, key=lambda r: r["usd_per_1b"]) if target else cheap
    tag = "满足效率判据(>=85%)" if target else "无方案达到效率判据(>=85%)，取最优可行方案"
    print(f"  选定：{pick['plan']}（显存 {pick['mem']:.1f} GiB/卡、效率 {pick['eff']:.1f}%、{tag}）")
    print(f"  预算表：{TOKENS_TOTAL/1e9:.0f}B token → {pick['gpu_h']:.0f} GPU·h、"
          f"${pick['cost']:.0f}、墙钟 {pick['days']:.1f} 天（示例价 ${MACHINE['price_per_gpu_h']}/GPU·h）")
    print(f"  通信：每卡每步 {pick['per_rank_comm_gb']:.2f} GB；单步 token {pick['tokens_step']:,}")
    if not target:
        print(f"  项目结论：这台机器在这个网络口径下装得下 {name}，但效率只有 {pick['eff']:.1f}%；"
              f"要提效率得加跨机带宽或减少 DP 通信（改 TP/PP 组合），不是加卡。")

# ===== 正确性门：用 numpy 模拟数据并行的梯度 AllReduce，和本地求和逐元素比对 =====
print("\n==== 正确性门（不需要 GPU）：梯度 AllReduce 与本地求和的逐元素比对 ====")
rng = np.random.default_rng(7)
dp = 4
local = [rng.standard_normal(256).astype(np.float32) for _ in range(dp)]
ref = np.sum(np.stack(local), axis=0)
def ring_allreduce(ranks):
    n = len(ranks)
    chunks = [np.array_split(r.copy(), n) for r in ranks]
    for k in range(n-1):
        for r in range(n):
            i, d = (r-k) % n, (r+1) % n
            chunks[d][i] = chunks[d][i] + chunks[r][i]
    for k in range(n-1):
        for r in range(n):
            i, d = (r+1-k) % n, (r+1) % n
            chunks[d][i] = chunks[r][i].copy()
    return [np.concatenate(c) for c in chunks]
outs = ring_allreduce(local)
dev = max(float(np.max(np.abs(o - ref))) for o in outs)
print(f"  dp={dp}，4 个 rank 的 AllReduce 结果与本地求和逐元素比对（atol=1e-5）："
      f"{[bool(np.allclose(o, ref, rtol=0, atol=1e-5)) for o in outs]}")
print(f"  最大逐元素偏差：{dev:.1e} —— 环上归约顺序与 np.sum 的成对求和不同，")
print(f"  所以验收门用容差而不是 bitwise 相等（fp32 累加顺序差异是正常现象）。")

三、练习#

  1. 实现：给 CANDS 加一个新候选（例如 7B 上的 TP2 PP1 DP4 Z1），跑一遍并说明它为什么可行或不可行；再把 MACHINE["mem_gib"] 改成 40，重新给两张报告卡选型。
  2. 解释：65B 的 TP4 PP1 DP16 Z3 效率 85.7% 而 TP8 PP1 DP8 Z3 只有 75.9%，但后者的每卡通信量更小（截面更小）。用第 1 课的 Tcomm​=2(DP−1)(α+S/(DPβ)) 说明为什么效率反而更低。
  3. 对比/验证：把 ACCUM 从 4 改成 16，重跑 7B 报告卡。计算"单步 token 数""单步时间""$/1B token"三项各变了多少，并解释为什么 $/1B token 几乎不变而单步时间线性变长。
  4. 思考：如果机器规格里 β 从 200 GB/s 降到 50 GB/s（跨机链路变差），两张报告卡的选定方案会怎么变？请给出你会优先调整的三个旋钮（DP 度、TP/PP 组合、全局 batch），并说明每个旋钮的代价落在三本账的哪一本上。
