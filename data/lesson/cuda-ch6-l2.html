前缀和（scan）：并行算法的第一个门槛#

归约只要求"最终一个数"，前缀和却要求"每个位置之前所有数的和"——N 个输出之间天然串行相关，看起来毫无并行性。它是并行算法教学里的第一个门槛：绕过去的方法有两种取向相反的树形算法，一个把 work 抬高 logN 倍换来极浅的 depth，另一个用两次树遍历把 work 压回 2N 但 depth 翻倍。这一课把两者与多级扫描（decoupled look-back）的账算清，并用向量化 numpy 把每一步验证到与参考实现逐位一致。

一、概念讲解#

1. 定义：inclusive 与 exclusive#

给定 x0​,…,xN−1​，inclusive scan（包含扫描）输出 yi​=∑j≤i​xj​；exclusive scan（排除扫描）输出 yi​=∑j<i​xj​，即 y0​=0。两者只差"是否包含自己"，但工程上区别很大：exclusive 的 yi​ 直接就是"第 i 个元素之前的历史和"，做区间和 x[l:r) 只要 yr​−yl​；GPU 上的分配/压缩（histogram、stream compaction）几乎都用 exclusive。

扫描的底层结构是树形归约的前缀版本：同一个加法树，把"向上汇总"改成"向上汇总 + 向下传播"。

2. Hillis-Steele：depth 浅，work 高#

最直观的并行扫描：第 d 轮每个位置加上"往前 2d 个位置"的值，共 ⌈log2​N⌉ 轮。

yi(d+1)​=yi(d)​+yi−2d(d)​

depth 只有 log2​N（N=220 时 20 轮），但每轮几乎所有线程都要做一次加法，work 从 N−1 涨到 Nlog2​N：N=220 时是顺序版本的 20 倍。在 GPU 上 work 就是指令数、就是功耗，所以它只在"块内 32~1024 个元素"这种 N 很小的场合划算——那里 log2​N≤10，多做的加法比多轮同步便宜。

3. Blelloch：work 回到 2N，depth 翻倍#

Blelloch 扫描（也叫 up-sweep / down-sweep 扫描）分两趟走同一棵平衡二叉树：

  1. up-sweep（归约趟）：从叶子往上，每个内部节点是它两个孩子的和。做完之后树根就是总和。这一趟做的加法数是 N−1。
  2. down-sweep（传播趟）：从根往下，把"左兄弟的和"沿途传给右孩子，根置 0。这一趟最多再做 N−1 次加法。

两趟合计 work =2N−2，只比顺序多一倍；depth =2log2​N，仍然是对数级。work 与 depth 的取舍是并行算法里最经典的取舍：Hillis-Steele 用 work 换 depth，Blelloch 用 depth 换 work。Blelloch 的 down-sweep 需要原地读写同一片数组并在每轮之间同步，因此块内实现常配 shared memory + __syncthreads()；它的自然输出是 exclusive scan，要 inclusive 时把结果整体平移一位。

4. 多级扫描：把长数组切成块#

N 到百万级时一块放不下。多级扫描（multi-level / chained scan）分三步：

  1. 每个 block 对自己那段做块内扫描，结果先当作"局部前缀和"留着；
  2. 把每块的块和（block aggregate）收集起来，对块和数组做一次扫描得到每块的起始偏移量；
  3. 每个 block 把自己的局部前缀和加上第 2 步算出的偏移量，得到全局结果。

第 2 步对"块数"而不是"元素数"做扫描，N=220、每块 256 个元素时只有 4096 个块和。朴素的实现开两个 kernel（块内扫描 + 块间扫描）；decoupled look-back 把它压成单次 launch：每块先把块和以"聚合值（aggregate）"发布出去，再向前扫描前驱块的状态，等它们陆续发布出"前缀值（prefix）"就累加并自行发布，用一个"已发布"的状态标志保证可见性。

5. 数值稳定性：扫描比归约更容易炸#

扫描的误差会沿前缀链累积：第 i 个输出用了 i 个输入的加法链，误差不再像归约那样只有 logN 级。N=224 的浮点前缀和（尤其在有正有负、量级差异大时）可能整体漂移。工程对策：块内用 Hillis-Steele 的较短链 + 每块起始偏移量单独做一次（更高精度或双精度）的块间扫描；对精度敏感的数据用双精度中间累加，只在最后写回 float32。

6. 常见坑#

  • 原地扫描的读写竞争：Hillis-Steele 每轮必须"整体读旧值、再写新值"。GPU 上同一 warp 内用 __shfl_up_sync 天然满足同步语义；shared memory 写法必须在读写之间加屏障，否则部分线程会读到本轮已更新的值。
  • 把 exclusive 当 inclusive 用：差一位会让所有区间和的边界错开一个元素，且测试数据是随机数时不容易发现（要专门构造非对称用例）。
  • 边界不是 2 的幂：Hillis-Steele 的循环条件要按 N 判，不能假定整除；越界读要显式屏蔽。
  • 块和扫描漏掉第一块：y0​=0，块间扫描必须是 exclusive 的，否则第一块会被加一次自己。
  • 忽略 atomicAdd 的粒度：块间偏移量必须整块发布，不能每个元素各自加，否则顺序不可复现。

二、可运行代码示例#

需要 numpy（本机 python3.10 + numpy 1.26.2 验证）。四段分别做：代价账、向量化 Hillis-Steele 与 cumsum 对拍、inclusive/exclusive 的区间和用法、两级扫描。

# ===== 本课示例：三种前缀和的 work/depth 账 + 向量化验证 + 多级扫描 =====
import numpy as np

# ---------- 1. 顺序、Hillis-Steele、Blelloch 的代价对比 ----------
def costs(n):
    lg = n.bit_length() - 1
    return dict(seq_work=n - 1, seq_depth=n - 1,
                hs_work=n * lg, hs_depth=lg,
                bl_work=2 * (n - 1), bl_depth=2 * lg)

print(f"{'N':>10} {'策略':<14} {'work(加法)':>12} {'depth':>7} {'work/n':>8}")
for n in (1024, 1 << 20):
    c = costs(n)
    print(f"{n:>10,} {'顺序':<14} {c['seq_work']:>12,} {c['seq_depth']:>7,} {c['seq_work']/n:>8.2f}")
    print(f"{'':>10} {'Hillis-Steele':<14} {c['hs_work']:>12,} {c['hs_depth']:>7} {c['hs_work']/n:>8.2f}")
    print(f"{'':>10} {'Blelloch':<14} {c['bl_work']:>12,} {c['bl_depth']:>7} {c['bl_work']/n:>8.2f}")

# ---------- 2. 用 numpy 向量化跑 Hillis-Steele（inclusive scan），与 cumsum 对拍 ----------
def hillis_steele(x):
    y = x.astype(np.float64).copy()
    n = y.size
    step = 1
    while step < n:
        y[step:] = y[step:] + y[:-step]   # 同步语义：整体读旧值、写新值
        step *= 2
    return y

rng = np.random.default_rng(0)
for n in (16, 1000, 4096):
    x = rng.standard_normal(n).astype(np.float32)
    got = hillis_steele(x)
    ref = np.cumsum(x.astype(np.float64))
    print(f"\nn={n:>5} Hillis-Steele 与 cumsum 最大差 = {np.abs(got - ref).max():.2e}")
    if n == 16:
        print("  x    =", np.array2string(x, precision=2, max_line_width=200))
        print("  scan =", np.array2string(got, precision=2, max_line_width=200))

# ---------- 3. 为什么需要"排除性扫描"：inclusive 与 exclusive 的换算 ----------
x = np.array([3., 1., 4., 1., 5., 9., 2., 6.])
inc = hillis_steele(x.astype(np.float32))
exc = np.concatenate(([0.0], inc[:-1]))
print("\ninclusive:", inc)
print("exclusive:", exc, " ← 每个位置的前缀和，不含自己")
print("用 exclusive 做区间和 x[2:6) =", exc[6] - exc[2], "（对照直接求和", x[2:6].sum(), "）")

# ---------- 4. 多级扫描：切块 → 块内扫描 → 块间偏移 ----------
def two_level_scan(x, block=256):
    n = x.size
    pad = (-n) % block
    xp = np.concatenate([x, np.zeros(pad, dtype=x.dtype)]) if pad else x
    blocks = xp.reshape(-1, block)
    local = np.cumsum(blocks, axis=1)              # 块内 inclusive scan
    totals = local[:, -1]                          # 每块的块和
    offsets = np.zeros_like(totals)
    if totals.size > 1:
        offsets[1:] = np.cumsum(totals)[:-1]       # 块间 exclusive scan
    out = (local + offsets[:, None]).reshape(-1)[:n]
    return out, totals, offsets

x = rng.standard_normal(1000).astype(np.float32)
out, totals, offsets = two_level_scan(x)
print(f"\n多级扫描 n=1000, block=256：块数={totals.size}，"
      f"与 cumsum 最大差={np.abs(out - np.cumsum(x.astype(np.float64))).max():.2e}")
print("  每块的块和:", np.array2string(totals, precision=2, max_line_width=200))
print("  块间偏移量:", np.array2string(offsets, precision=2, max_line_width=200))

# ---------- 5. 代价随 N 的增长：扫描没有"又省 work 又省 depth"的选项 ----------
def work_ratio(n):
    lg = n.bit_length() - 1
    return dict(hs=n * lg / (n - 1), depth_gain=(n - 1) / lg)
for n in (1 << 10, 1 << 20, 1 << 24):
    r = work_ratio(n)
    print(f"n={n:>10,}  Hillis-Steele 的 work 是顺序的 {r['hs']:.1f} 倍，"
          f"Blelloch 是 2.0 倍，depth 收益 {r['depth_gain']:.0f}x")

三、练习#

  1. 实现：用纯 Python 实现 Blelloch 的 up-sweep + down-sweep，输出 exclusive scan，在 n=8,16 上与 np.cumsum 对拍；再把 down-sweep 的加法次数单独计数，验证总计是 2N−2。
  2. 解释：为什么 decoupled look-back 里每块要发布"聚合值"和"前缀值"两种状态，只发布一种会退化成什么？用一句话说明它多花在哪里、省在哪里。
  3. 对比/验证：把 two_level_scan 的 block 改为 64、1024，观察与 cumsum 的最大差如何变化；再把块内累加换成 float64，解释差异来源。
  4. 思考：Attention 的 causal mask 需要"第 i 行只对前 i 列做 softmax"。这道题里 scan 能直接帮上忙吗？如果没有 scan，你会怎么用"逐块累加 + 在线更新"替代它（第 4 课展开）？
