图文生成统一#

上一课我们造出了一个"能看图说话"的模型，但它是单向的：输入图像+文本，输出文本。而你在前面章节学的扩散模型又是另一个方向：输入文本，输出图像。一个自然的问题出现了——能不能把"理解"和"生成"塞进同一个模型，让它既能读图、又能画图、还能一边写文章一边插图？这就是"图文生成统一"要回答的问题。本课时梳理它的技术路线，并以 Chameleon 为例讲解"一个 Transformer 通吃图文"的优雅方案。

一、概念讲解#

1. 为什么要"统一"#

  • 交错生成（interleaved）：真实内容往往是图文交织的——一篇教程、一条带表情的聊天记录、一份带示意图的报告。分立的"文生图模型"只能一次性生成单张图，无法在生成文本的中间自然地"插图"。
  • 任意模态到任意模态（any-to-any）：用户可能给出文字要图片，给出图片要描述，给出"图+文字"要修改后的图。每加一种组合就训练一个新模型，工程上不可持续。
  • 一个共享的语义空间：理解与生成本应共享同一套世界知识，分开训练等于把知识重复学两遍。

2. 两条主要技术路线#

把图文统一，业界基本分两派：

路线 A：早融合，统一 token（early fusion / unified token）。 用一个图像 tokenizer 把图片离散化成"图像 token"，和文本 token 放进同一个词表，然后只训练一个 Transformer 做下一 token 预测。代表是 Chameleon、以及更早的 DALL-E（VQ-VAE + 自回归）。它的优点是架构极简、天然的任意模态交错；难点是把连续图像压成离散 token 会损失细节，且长序列训练难。

路线 B：模块化，冻结扩散（modular / frozen diffusion）。 语言模型负责"理解 + 生成文本"，当需要出图时，让 LLM 输出一个文本或嵌入形式的"图描述"，再交给一个冻结的扩散模型（如 Stable Diffusion）去真正画图。代表是 EMU2、GILL。优点是图像质量高（借用了扩散模型的能力）、训练改动小；缺点是交错生成不够"原生"，图文不是在同一套参数里学出来的。

3. Chameleon：一个 Transformer 通吃图文#

Chameleon（Meta, 2024）是路线 A 的代表，值得重点拆解：

  • 统一词表：它有一个图像 tokenizer 把图片切成离散的图像 token，还有一个文本 tokenizer；两者合并成一个共享词表，图像 token 和文字 token 在这个词表里地位完全平等。
  • 一个 Transformer：只有一个标准的 Transformer 做下一 token 预测。输入序列可以是纯文本、纯图像，或"文本-图像-文本"任意交错，模型逐个 token 地预测下一个。
  • 训练稳定的关键技巧：把连续图像离散化、又把图像 token 和文本 token 混在一起训练，数值上极不稳定。Chameleon 用两个技巧压住训练发散：QK-Norm（在注意力计算的 query 和 key 上加 LayerNorm，抑制 logits 尖峰）和 z-loss（一个正则项，把输出 logits 的整体尺度往下拉）。这给"一个 Transformer 训到底"铺平了路。

它的效果证明：统一模型能做图文交错生成（给定文本生成图、看图说话、按图续写文字等），而且规模越大能力越强——这正是"统一"路线的核心吸引力。

4. 扩散与自回归的"握手"#

你可能好奇：前面花三章学的扩散模型在这里扮演什么角色？答案是——它没被抛弃，而是变成了统一生态里的一环：

  • 路线 B 直接把扩散模型当作画图后端：LLM 负责语义理解和编排，扩散模型负责像素级生成。
  • 即便在路线 A 里，"图像 tokenizer + 自回归"也只是图像生成的一种实现；扩散模型仍然是目前单张高保真文生图质量的天花板。
  • 所以一个完整的多模态系统，往往是"LLM 当大脑、扩散模型当画笔"，两者分工协作。

二、可运行代码示例#

示例 1：用 diffusers 完成一次文生图（生成侧）#

先复习你已经熟悉的生成能力，作为统一模型的"画笔"部分。

from diffusers import StableDiffusionPipeline
import torch

# 加载 Stable Diffusion (该模型在第三章已详细介绍)
pipe = StableDiffusionPipeline.from_pretrained(
    "runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16
)
pipe = pipe.to("cuda")

prompt = "a cute corgi wearing a red scarf, cartoon style"
image = pipe(prompt, num_inference_steps=25, guidance_scale=7.5).images[0]
image.save("corgi.png")
print("已生成图片 corgi.png")

示例 2：从零理解"统一 token"的交错生成思路#

下面不加载大模型，用一个极简的张量实验演示 Chameleon 的核心：文字 token 与图像 token 在同一条序列、同一个词表里被预测。

import torch

# 假设我们有一个统一词表:
#   0..999   是文本 token (来自文本 tokenizer)
#   1000..1999 是图像 token (来自图像 tokenizer, 每张图用若干 token 表示)
vocab_size = 2000
n_img_tokens_per_image = 4   # 示意: 每张图离散成 4 个图像 token

# 一个"交错生成"的目标序列:
#   [文本] "下面是一只狗: "  ->  [图像 token x4]  ->  [文本] " 它的毛色是金色。"
# 我们用 token id 拼出这条序列
text_a = [12, 34, 56, 78]                        # "下面是一只狗: " 的 token id
image  = [1000 + i for i in range(n_img_tokens_per_image)]  # 4 个图像 token
text_b = [90, 91, 92, 93, 94]                    # " 它的毛色是金色。" 的 token id

sequence = text_a + image + text_b
print("统一序列的 token id:", sequence)
print("序列里既有文本 token(<1000)也有图像 token(>=1000):",
      any(t >= 1000 for t in sequence) and any(t < 1000 for t in sequence))

# 训练时, 模型对每个位置预测下一个 token; 损失只来自"预测的分布 vs 真实下一 token"
# 例如位置 len(text_a) 处, 模型要预测的是一个"图像 token id", 而不是文本 token
targets = sequence[1:] + [0]   # 右移一位, 0 是填充
print("训练目标(下一 token):", targets)

关键点在第 targets = sequence[1:]：当模型读到文本部分时，它预测的是图像 token id；读到图像部分时又预测文本 token id。因为两者在同一个词表里，损失函数不需要任何特殊处理——这就是"统一"在实现上的极致简洁。

真正的 Chameleon 远比这复杂：图像 tokenizer 用 VQ 量化把连续图像变成离散码本索引，训练还要加 QK-Norm 和 z-loss 稳定数值。但"图文 token 同词表、共用一个自回归目标"这一核心思想，上面的骨架已经完整体现了。

三、练习#

  1. 路线辨析：用自己的话说明"早融合统一 token"与"模块化冻结扩散"两条路线的本质区别，并各举一个代表模型。
  2. 动手实验：在示例 2 中，把序列改造成"图像在前、文本在后"（比如"看图写说明"任务），写出对应的 sequence 与 targets，观察训练目标的变化。
  3. 权衡分析：统一 token 路线要先把图像离散化，这会带来什么信息损失？结合第三章学到的 VAE/潜空间压缩，谈谈扩散模型为什么能规避"离散化损失细节"这个问题。
  4. 思考题：如果让你设计一个"图文交错生成"的聊天应用，你会选路线 A 还是路线 B？从图像质量、交错自然度、工程成本三个角度说明理由。
