视频数据与计算账：时空尺寸、采样策略与成本#

这一节要解决什么#

cv-advanced 结束时，你手上的模型是"一张图进、一个标签出"的。视频只是多了一维，很多教程也因此把它当成"多帧图像"处理。这一节要证明的是：多出来的那一维不是量变，它把三个不同的账同时引爆——存储、时间采样、注意力的二次项，而且这三笔账的货币不一样，不能互相折算。

本节不引入任何网络结构（那是第 2 节的事），只做一件事：把"视频"从一个模糊的模态名词，变成一组可以逐格核对的数。全部结论如下：

  1. 原始像素账是线性的，但基数极大。 一段 60 s、1080p、30 fps 的视频在未压缩下是 T⋅H⋅W⋅3=1800×1080×1920×3=11,197,440,000 B =10.428 GiB，正好是一张同分辨率图像的 1800 倍；把时长拉到 1 小时是 625.706 GiB（表 1）。这意味着视频的"数据集大小"不能像图像那样用张数报——同样 1 万个样本，图像是 1 万张，视频是 1 万段、每段上千帧。
  2. 时间轴上有采样定理，而且它会造出真实不存在的运动。 采样序列满足 cos(2πfn/fs​)=cos(2π(f−kfs​)n/fs​)，k=round(f/fs​)。于是 24 fps 拍 25 Hz 的轮辐，表观频率是 1.00 Hz 且方向反转；15 fps 拍 8 Hz 的手部往复，表观是 7.00 Hz 且反向；10 fps 拍 6 Hz 则变成 4.00 Hz 反向（表 3）。低帧率下的模型看到的不是"少几帧的真相"，而是一段假运动。
  3. 分辨率决定"位移能不能被量化出来"，不决定运动频率上限。 帧间位移 d=2πfA/fs​；缩放到 224 输入后 dnet​=s⋅d。当 dnet​<1 px 时相邻帧在输入分辨率下不可区分，需要 W=1/dnet​ 帧的窗口才累积到 1 px。v=2 px/s 的慢速平移要 72.32 帧（2.41 s）才累积 1 px，而 1 s 的片段只有 30 帧（表 4）——慢动作在短片段里等价于静止。
  4. 等字节预算下，"高帧率低分辨率"与"低帧率高分辨率"不是同一件事。 60 s、426×240、30 fps 与 60 s、1920×1080、1.4667 fps 的字节数分别是 526.520 MiB 与 522.070 MiB，几乎相同；前者保住 4 Hz 运动，后者把 4 Hz 折成 0.40 Hz 反向，且它的帧间隔 0.682 s 已超过 4 Hz 的周期 0.25 s（表 5）。
  5. token 化把像素账换成二次项账。 8 帧 224×224、tubelet 2×16 只有 N=784 个 token，注意力核心 1.888 GFLOP、score 矩阵 0.014 GiB；换成 p=16→8 或 T=8→32，N 变 3136，注意力核心涨到 30.212 GFLOP、占比 40.50%、score 矩阵 0.220 GiB。再往上，512×384×384、tubelet 4×16 给出 N=73,728、注意力核心 16,698.833 GFLOP、占比 94.12%、score 矩阵 121.500 GiB（单层、单样本）（表 2）。
  6. "注意力什么时候开始主导"有一个闭式的交叉点。 单层里注意力核心是 4N2d、投影是 8Nd2、MLP 是 16Nd2；令 4N2d=24Nd2 得 N∗=6d。d=768 时 N∗=4608。N 从 3136 翻到 6272 时，单层总 FLOPs 只涨 2.810 倍，而注意力核心涨 4 倍、占比从 40.50% 升到 57.65%（表 2）。
  7. 片段长度买的是"周期覆盖"，不是"帧数"。 同一段 16 s 素材，稠密 t=2,p=16 要 47,040 个 token；稀疏分段（TSN 式）K=8 只要 1,568 个，少 30.0 倍——但它在 Lf=64 个运动周期里只看了 8 个瞬间的相位（表 6）。省下的 token 正是"动作做到哪一步"这条信息。
  8. 三条采样轴的边际收益/边际成本不同。 以"时间可辨频率上限 fmax​=fs​/2""缩放后可辨位移下限 1 px"为收益代理、以 C∼fs​HWL（CNN）或 C∼N2（注意力）为成本代理：帧率 ×2 的收益/成本是 ×1.00，分辨率边长 ×2 是 ×0.50，片段长 ×2 是 ×1.00（表 7）。这个排序只在"混叠是主瓶颈"时成立，换句话说先修混叠、再修分辨率才是对的顺序。

本节所有数字都能用文末的脚本重算。贯穿全章的方法论是同一句话：任何"这个采样配置够用"的说法，都要先写成一张账，再写成一张有前提的收益/成本表。

一、视频的本体：三个轴与两笔账#

1.1 视频不是"很多张图"，它是四个索引的张量#

一段视频最朴素的表示是一个四维数组

X∈RT×H×W×C,T=fs​⋅L

其中 fs​ 是帧率（frames per second, fps）、L 是时长（秒）、H×W 是空间分辨率、C 是通道数（RGB 时 C=3）。未压缩字节数是

S=T⋅H⋅W⋅C=fs​⋅L⋅H⋅W⋅C.

这个式子是线性的：三个轴各翻一倍，字节数就翻一倍/四倍/一倍。但它的基数极大（表 1）：

分辨率 像素/帧 字节/帧 1 s@30 fps 60 s@30 fps 600 s@30 fps
240p 102,240 306,720 8.775 MiB 526.520 MiB 5.142 GiB
480p 409,920 1,229,760 35.184 MiB 2.062 GiB 20.615 GiB
720p 921,600 2,764,800 79.102 MiB 4.635 GiB 46.349 GiB
1080p 2,073,600 6,220,800 177.979 MiB 10.428 GiB 104.284 GiB
4K 8,294,400 24,883,200 711.914 MiB 41.714 GiB 417.137 GiB

（表 1：以 C=3、uint8 计。）

1.2 为什么"按帧切成独立样本"是错的起点#

上面的账直接推出一个反直觉的结论。1080p、30 fps、60 s 的视频有 1800 帧；如果把它当图像数据集，1800 个样本在 batch=64 下只有 28.125 个 batch——一个 epoch 相当于图像任务里"看了 28 个 batch"。这会诱导两个错误做法：

  1. 把帧数当样本数报。 "我们有 100 万帧"听起来很大，折成 1080p、30 fps 只有 1000000/1800≈556 段 60 s 视频。数据集规模必须同时报段数、段长、帧率、分辨率，缺一项不可比。
  2. 把帧级监督当视频监督。 帧级标签（每帧一个类别）看似信息量更大，但它把一个时序任务降成了图像任务：模型完全可以不看相邻帧。第 4 节会把这个"监督粒度 = 多少 bit"的账算成公式。

为什么视频的数据集总是"更小"：不是标注者懒，而是同一份预算下，视频的边际成本按上式同时乘上了 fs​ 与 L。标注 1 小时的素材，即使标注者只以 5 倍速看一遍，也是 720 s 的纯观看时间——而图像标注 1 万张可能不到 1 小时。

1.3 真正的成本不在存储，而在"进入模型之后"#

存储账只是本体。真正决定可行性的下一笔账发生在 token 化之后。如果把视频切成 t×p×p 的时空管（tubelet），token 数是

N=时间格数tT​​​⋅每帧空间格数pH​⋅pW​​​.

单层自注意力的核心计算量是

FLOPsattn​=4N2d(2N2d 算 QK⊤, 2N2d 算 AV),

而物化出来的 score 矩阵占

Memscore​=B⋅nh​⋅N2⋅s 字节

（B 是 batch，nh​ 是头数，s 是每元素字节数）。N2 的出现意味着：空间分辨率、帧率、片段长度这三条轴在 token 账里被乘进了同一个 N，然后被平方。 表 2 是这句话的数值版本。这一节先把它算清楚；第 3 节会把这个账拆到"显存峰值与反解 Nmax​"。

取舍与边界：S 与 N2 不能互相折算。我们可以用有损压缩把 S 降两个数量级（这是工程上常见做法），但压缩发生在像素域，它对 N 没有任何影响——N 由"你决定送进网络的采样格数"决定。把这两笔账混为一谈，就会出现"我们用了视频压缩所以模型能训长视频"这类错误推理。

二、帧率：时间轴上的采样定理与折叠#

2.1 判据只有一个#

把视频看成对连续运动的采样，时间轴的奈奎斯特判据是

fs​>2fmax​

其中 fmax​ 是画面中最快的周期性运动的频率（Hz）。人类日常动作的往复频率大致在 1–8 Hz（挥手、走路、开合），但工具类动作（击球、搅拌、机械振动）可以更高。注意这个判据里的 f 是运动频率，不是帧率，也不是"物体速度"。

2.2 折叠公式：混叠不是丢帧，是造出假运动#

采样序列的等价关系可以一行推出：

cos(2πffs​n​)=cos(2π(f−kfs​)fs​n​),k∈Z,

因为 2πkn 是 2π 的整数倍。取 k=round(f/fs​) 使 ∣f−kfs​∣ 最小，得到表观频率

f^​=∣f−kfs​∣,方向反转⟺k 为奇数.

k 为奇数时相位整体反转，视觉上就是"运动方向反了"。表 3 给出逐格数值（截取关键列）：

三个必须记住的读数：

  • 24 fps 拍 25 Hz 的轮辐 → 1.00 Hz，k=1（反转）。 这就是电影里车轮倒转的来源；它不是"看不清"，是一个稳定的、慢速的假运动。
  • 15 fps 拍 8 Hz 的手部往复 → 7.00 Hz，k=1（反转）。 表观频率只差 1 Hz，肉眼几乎看不出异常，但方向错了。方向错了对动作识别是致命的：开门/关门、推/拉、上楼梯/下楼梯这几类任务只差一个时间反演。
  • 30 fps 拍 8 Hz → 8.00 Hz（未混叠），因为 8≤15。 这解释了为什么 30 fps 在大多数日常动作上是够的。

2.3 为什么"帧率越高越好"也是错的#

先把两端说清楚。帧率不足的代价是上面那条：混叠 + 方向反转 + 表观频率错位。帧率过高的代价是：

  1. 时间冗余上升。 相邻帧越接近，输入里"新信息"越少。第 4 节会证明这正是视频掩码建模必须用高掩码率的原因之一：低掩码率下，任务可以退化成"从邻帧拷贝"。
  2. 成本线性上涨。 对逐帧 2D 主干 C∝fs​；对时空注意力 C∝N2∝fs2​（表 7）。把 30 fps 换成 60 fps，注意力主干的成本是 4 倍，而可辨频率上限只从 15 Hz 提到 30 Hz。
  3. 拍摄端已经在替你降采样。 曝光时间越长，单帧内的运动模糊越长（表 4c）：v=1000 px/s 在 1/30 s 曝光下拖影 33.33 px，在 1/60 s 下 16.67 px。若相机用 1/30 s 曝光，那么"60 fps 采样"采到的是 30 组几乎相同的模糊帧，多出来的帧没有新的运动信息。

怎么做：把帧率选择写成一个不等式而不是一个常数。给定任务关心到 fmax​，取 fs​≥2fmax​（留 20% 余量取 fs​≥2.4fmax​），并核对曝光时间 τ≲1/(2fmax​)，否则模糊先于采样把信息抹掉了。取舍：fmax​ 不能拍脑袋，它要么来自任务的物理先验（"这是手势"→ 取 8 Hz），要么来自数据的可观测量（相邻帧位移分布的尾部）。

三、分辨率：把运动量化掉的那一刀#

3.1 帧间位移：什么时候"相邻帧看不出来"#

设某点以速度 v（px/s，在原分辨率上）运动，帧间隔 1/fs​，则帧间位移是

d=fs​v​ px;简谐运动 x(t)=Acos(2πft) 的峰值速度 vpeak​=2πfA.

缩放到网络输入分辨率（缩放因子 s）后 dnet​=s⋅d。判据是

dnet​<1 px ⟹ 相邻帧在该分辨率下不可区分, 需 W=dnet​1​ 帧的窗口才累积到 1 px.

表 4b 是慢速平移的读数：

v (px/s) d@30 fps dnet​@224 W（帧） W/30（秒）
2 0.0667 0.0138 72.32 2.4107
10 0.3333 0.0691 14.46 0.4821
50 1.6667 0.3457 2.89 0.0964
200 6.6667 1.3827 0.72 0.0241
1000 33.3333 6.9136 0.14 0.0048

这张表最重要的一行是第一行。 v=2 px/s（相当于"缓慢的云、远处的人、几乎静止的手"）在 224 输入下每帧只移动 0.0138 px，要 72.32 帧（2.41 s）才累积到 1 px。如果片段是 1 s（30 帧），这段运动在网络眼里就是静止。反过来 v=1000 px/s 每帧 6.91 px，在 224 这种小分辨率上已经是很大的位移，会触发光流/局部匹配的"大位移问题"（第 3 节用金字塔解决：L 层金字塔把可测位移上界提到 2L px）。

注意 d 与 f 成正比：高频小幅运动（手指快速抖动）与低频大幅运动（挥手）可以有相同的帧间位移。所以"帧间位移小"不能推出"运动频率低"，混叠判据必须用频率，不能用位移代理。

把表 4a 也放进来对照：

f (Hz) vpeak​ (px/s) d@30 fps dnet​@224 W（帧） 混叠需 fs​>

（A=100 px 原生，缩放到 224 的因子 s=224/1080=0.2074。）

读法：在 A=100 px、1–8 Hz 这个区间，224 输入在 30 fps 下两种失败都不会发生——dnet​ 从 4.344 到 34.751 px，既不需要跨帧累积，也没大到离谱；混叠门槛是 2–16 fps，30 fps 全部满足。所以这一区间的失败几乎总是出在别的地方（片段太短、标签太弱、模型太浅），而不是"像素不够"。 这条结论的价值是负面的：它阻止你把预算花错地方。

怎么做：分辨率的选择应该由"任务需要的最小空间结构"决定（目标检测要细纹理、动作分类不需要），而不是由"别人用了 224"决定。取舍/边界：降低分辨率会同时降低 dnet​（运动更难被量化）和细纹理的可辨性，但它不改变混叠。当混叠存在时，唯一有效的修法是提帧率。

3.3 运动模糊：单帧里的运动信息#

曝光时间 τ 内的拖影长度是

ℓ=v⋅τ,

它与帧率无关（表 4c）：

v (px/s) τ=1/30 s τ=1/60 s τ=1/250 s
50 1.67 px 0.83 px 0.20 px
200 6.67 px 3.33 px 0.80 px
1000 33.33 px 16.67 px 4.00 px
2000 66.67 px 33.33 px 8.00 px

这张表解释了一个常被忽略的事实：运动信息其实"部分地"在单帧里。 模糊方向编码了运动方向，模糊长度编码了速度。这也是两条后续路线的物理根据：光流方法显式估计运动（第 3 节），而双流方法之所以要额外算光流，是因为单帧里的模糊信息与纹理纠缠在一起、且受曝光与景深影响，不如显式估计稳定（第 2 节会给出双流的完整代价账）。

四、片段长度与采样范式#

4.1 片段长度买的是"周期覆盖"#

一个动作要被看见，片段至少要覆盖它一个完整周期：

覆盖周期数=L⋅f,相位采样数=L⋅fs​.

例如 f=4 Hz 的动作，L=1 s 只覆盖 4 个周期、30 个相位；L=16 s 覆盖 64 个周期、480 个相位。"覆盖周期"决定模型能不能看到动作的完整过程，"相位采样"决定它能不能看到细节。 这两者都可以通过延长 L 或提高 fs​ 获得，但成本形状不同（见第六节）。

4.2 稠密采样 vs 稀疏分段：省下的 token 是什么#

两种主流采样范式的 token 账完全不同（表 6）：

  • 稠密采样：保留 T 帧，N=tT​⋅pH​⋅pW​，与 L 成正比。
  • 稀疏分段（TSN 式）：把片段切成 K 段，每段只取 1 帧，N=K⋅pH​⋅pW​，与 L 无关。

同一段 16 s 素材（fs​=30，p=16，Ns​=196）：

方案 N 相对稠密
稠密 t=2,p=16 47,040 1.0×
分段 K=8,p=16 1,568 30.0× 更少
分段 K=32,p=16 6,272 7.5× 更少

为什么分段方案曾经是对的：在 2D CNN + 时序聚合的框架里（第 2 节），每帧独立过主干，K 段就是 K 次前向；把 K 从 480 降到 8，成本降 60 倍，而"这段视频是什么动作"这个 clip 级问题只依赖"出现过哪些外观"，不依赖"顺序"。它买到的正是 clip 级监督所能提供的那点信息。

它丢掉的：在 Lf=64 个运动周期里只看了 8 个瞬间的相位。顺序、方向、节奏这三类信息全部丢失——这正是"开门 vs 关门""推 vs 拉"这类数据集（时序敏感任务）存在的原因。所以分段的边界是：

分段池化 ⇒ 只能学"有没有这个动作"，学不到"动作做到哪一步".

4.3 stride 与样本相关性#

一段 600 s 的视频、片段长 2 s：stride=1 s 得到 599 个片段；stride=0.5 s 得到 1197 个。样本数翻了约 2 倍，但相邻片段的重叠也翻了约 2 倍——它们不是独立样本。这会影响两件事：

  1. 验证集必须按视频划分，不能按片段划分。 同一视频的相邻片段同时出现在训练与验证集里，会让验证指标虚高。写成判据：验证集划分的单位是视频，不是片段。
  2. 有效样本量受时间自相关折损。 若相邻片段的特征相关系数是 ρ，m 个相邻片段的有效样本量约为 m/(1+(m−1)ρ)（与第 4 节 InfoNCE 的有效负样本数是同一类折算）。"我们有 100 万个片段"这句话要和 ρ 一起报。

单层、单样本，B=1。三件事从表里直接读出来：

  1. 第 2 行与第 3 行完全一样。 p 减半（空间 token ×4）与 T 翻两番（时间 token ×4）对 N 的贡献不可区分——因为在 N 的公式里它们只是相乘的两个因子。这解释了为什么"用低分辨率多帧"与"用高分辨率少帧"在 FLOPs 上等价，却在"可辨运动频率"上完全不等价（表 5）。
  2. 占比随 N 单调上升，且上升得很快。 N=6272 时注意力已占 57.65%；N=73728 时占 94.12%——此时主干其余部分（投影 + MLP）几乎可以忽略。
  3. score 矩阵的绝对值在长视频上不可接受。 N=73,728 时单层单样本 121.500 GiB。注意这是物化出来的大小；真实实现靠分块（FlashAttention 类方法）避免物化整个矩阵，但FLOPs 的 4N2d 一分不少——省的是显存，不是计算。

5.2 交叉点 N∗=6d：什么时候该担心二次项#

单层 Transformer 的计算量可以写成

FLOPslayer​=注意力核心4N2d​​+QKV+O 投影8Nd2​​+MLP16Nd2​​=4N2d+24Nd2.

令两者相等：

4N2d=24Nd2 ⟹ N∗=6d.

4N2d=24Nd2 ⟹ N∗=6d.

d=768 时 N∗=4608。这个数的用法是判断当前配置处在哪一侧：

  • N≪N∗（如 N=784，0.17N∗）：算力主要花在投影与 MLP 上，此时"缩短片段/降分辨率"省不了多少。
  • N≫N∗（如 N=73,728，16.00N∗）：几乎全部算力都在二次项上，此时任何与 N 成正比的削减都几乎线性地省算力。

N 翻倍时：总 FLOPs 涨 2.810 倍，注意力核心涨 4 倍，占比从 40.50% 升到 57.65%，score 矩阵从 225.1 MiB 涨到 900.4 MiB。这就是"长视频的第一个墙"：不是存不下，是二次项。

5.3 与存储账的对照：两笔账不能互抵#

把第一节与这里的结论并排：

S=fs​LHWC (线性),FLOPsattn​=4N2d, N=tfs​L​⋅p2HW​ (二次).

S 可以用编解码器压，N 不能——N 由采样策略直接决定。工程上常见的错误是"我们已经把视频压到 1/100 了，所以可以训长视频"：压缩只让数据搬运变便宜，模型看到的 token 数一个不少。

取舍/边界：N∗=6d 这个交叉点只在"标准 pre-LN Transformer、MLP 隐层 4d"的假设下成立；换成 GLU 变体（隐层 8/3d 再乘 2）或 MoE 层，常数会变。用公式定形状、用 profilng 定常数，不要背 4608。

六、三条轴的联合取舍#

6.1 边际收益/边际成本#

定义两个"可分辨性"的代理量（都是下界，不是精度）：

fmax​=2fs​​(时间),dmin​=sscaled​1 px​(空间),

再定义两个成本代理（2D CNN 主干、逐帧前向 C∼fs​HWL；时空注意力主干 C∼N2）。三条轴的边际账是（表 7）：

操作 收益代理 成本代理 (CNN) 收益/成本 成本代理 (注意力)
fs​×2 fmax​×2 C×2 ×1.00 C×4
分辨率边长 ×2 dmin​ 减半 C×4 ×0.50 C×16
片段长 L×2 覆盖周期 ×2 C×2 ×1.00 C×4

6.2 怎么用这张表，以及它什么时候失效#

可核对的组合：配置 a = 帧率 ×2（分辨率不变）收益 2.00×、CNN 成本 1.00×；配置 b = 分辨率 ×2（帧率不变）收益 1.00×、CNN 成本 4.00×。同成本下 a 的收益是 b 的 2 倍——在"运动混叠"是主瓶颈时，加帧率优先于加分辨率；反过来"小物体/细纹理"是主瓶颈时结论相反。

这张表有明确的前提，不满足就失效：

  1. "dmin​ 减半 = 收益 ×2" 只在"物体/位移小于 1 px 是瓶颈"时成立。当瓶颈是混叠时，加分辨率完全不救运动：表 5 里配置 B 的分辨率是 A 的 4.5 倍，4 Hz 运动照样被折成 0.40 Hz 反向。
  2. "覆盖周期 ×2 = 收益 ×2" 只在动作时长本身就是瓶颈时成立。若模型已经用分段池化，加长片段可能只增加冗余——表 6 里分段方案的 N 与 L 无关，加长 L 对它的成本毫无影响，也就谈不上"边际收益"。
  3. 成本代理只算主干，不含解码、光流、数据搬运。真实流水线里解码常常先于 GPU 成为瓶颈——这是第 3 节要算的光流与显存账的一部分。

边界与开放问题：fmax​=fs​/2 是"能表示"的上界，不是"能识别"的上界。真实模型能否用上靠近奈奎斯特的频率，取决于运动的幅度、信噪比与曝光模糊。把 fs​ 定成 2fmax​ 只是必要条件；工程上更稳的做法是先做一张像表 4 那样的位移/模糊表，再定 fs​。

def dwidth(s: str) -> int:
    """显示宽度：CJK 全角记 2 列，其余记 1 列。"""
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1
               for ch in s)


def pad(s: str, w: int, align: str = ">") -> str:
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2
    return " " * left + s + " " * (gap - left)


def row(cells, widths, aligns=None) -> str:
    aligns = aligns or [">"] * len(cells)
    return " | ".join(pad(c, w, a) for c, w, a in zip(cells, widths, aligns))

def hbytes(n: float) -> str:
    for unit in ("B", "KiB", "MiB", "GiB", "TiB"):

    return "?"

  3) 成本代理只算主干，不含光流、解码、数据搬运；真实流水线里解码往往
     先于 GPU 成为瓶颈（第 3 节会给光流与显存的账）。

一个可核对的组合：
  配置 a = fs x2,  分辨率不变 : 收益 2.00x, CNN 成本 1.00x
  配置 b = fs 不变, 分辨率 x2 : 收益 1.00x, CNN 成本 4.00x
  同成本下 a 的收益是 b 的 2 倍——在「运动混叠」是主瓶颈时，加帧率优先
  于加分辨率；反过来在「小物体/细纹理」是主瓶颈时相反。

小结#

  • 视频是 T×H×W×C 的张量，T=fs​L。 未压缩字节 S=fs​LHWC：1080p、30 fps、60 s =11,197,440,000 B =10.428 GiB =1800 张同分辨率图像；1 小时 =625.706 GiB（表 1）。数据集规模必须同时报段数、段长、帧率、分辨率。
  • 混叠公式 f^​=∣f−kfs​∣、k=round(f/fs​)，k 为奇数时方向反转。24 fps 拍 25 Hz 的轮辐 =1.00 Hz 反转；15 fps 拍 8 Hz =7.00 Hz 反转；30 fps 拍 8 Hz 未混叠（8≤15）（表 3）。
  • 混叠不是丢帧，是造出假运动，而且方向反转对"开/关、推/拉、上/下"这类只差时间反演的任务是致命的。
  • 帧率不是越高越好：对逐帧主干成本线性、对注意力成本二次；曝光 τ 下的模糊长度 ℓ=vτ，与帧率无关——τ 太长时提高帧率只是采到更多相同帧（表 4c）。
  • 帧间位移 d=2πfA/fs​（简谐）或 v/fs​（平移），缩放到输入后 dnet​=sd；dnet​<1 px 需要 W=1/dnet​ 帧累积。v=2 px/s 在 224 输入、30 fps 下要 72.32 帧（2.41 s）才累积 1 px（表 4b）。
  • 位移不能代理频率：d∝f，高频小幅与低频大幅可以同位移；混叠判据必须用频率。
  • 等字节对撞：426×240@30 fps 与 1920×1080@1.4667 fps 的 60 s 字节数分别是 526.520 MiB 与 522.070 MiB；前者保住 4 Hz，后者折成 0.40 Hz 反向，且帧间隔 0.682 s 已超过 4 Hz 的周期 0.25 s（表 5）。
  • 稀疏分段省的 token 就是顺序信息：16 s 素材稠密 N=47,040、分段 K=8 时 N=1,568（少 30.0 倍），但 64 个运动周期里只看了 8 个相位（表 6）。
  • token 数 N=(T/t)(H/p)(W/p)；单层 FLOPs=4N2d+24Nd2；交叉点 N∗=6d（d=768→4608）。N 从 3136 翻到 6272，总 FLOPs 涨 2.810 倍而注意力核心涨 4 倍，占比 40.50%→57.65%，score 矩阵 225.1→900.4 MiB（表 2）。
  • score 矩阵显存 =Bnh​N2s：N=73,728 时单层单样本 121.500 GiB、注意力占比 94.12%。分块实现省的是显存，4N2d 的 FLOPs 一分不少。
