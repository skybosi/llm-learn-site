Megatron / DeepSpeed 的并行组合与配置要点#

前六章你分别拿到了 DP、TP、PP、EP、CP 与 ZeRO 的"单件账本"。真到开训时它们必须同时出现：一台 64 卡机器上，你得说清 TP 放在哪几条卡上、PP 切成几段、DP 组跨不跨机、EP 组和谁重合。这一课把这些"旋钮"变成一张可校验的配置表：总卡数是乘积，切分必须整除，组合有硬性要求，而每种组合的通信代价都能用前几章的 α-β 账算出来。

一、概念讲解#

1. 总卡数是乘积，不是加法#

Megatron Core 的并行指南给出一条可以直接进配置校验脚本的恒等式：

Total GPUs=TP×PP×CP×EP×DP

五个维度各管一件事，官方口径是：DP 切 batch、TP 切层内张量（适合大 hidden）、PP 切模型深度（适合 50+ 层）、CP 切序列（8K+ token）、EP 切 MoE 专家。指南在同一页给出参考配置，本课的校验器直接拿它们当测试用例：LLaMA-3 70B 用 64 卡（TP4/PP4/CP2/DP2）、LLaMA-3.1 405B 用 1024 卡（TP8/PP8/CP2/DP8）、DeepSeek-V3 671B 用 1024 卡（TP2/PP16/CP1/EP64）。

乘积式有个直接推论：任何一个维度翻倍，总卡数就翻倍，而"每份计算"只变小一部分——这正是第 8 章"三本账"要解决的取舍。

2. 硬约束一：切分必须整除，否则根本跑不起来#

两类整除约束：

切谁 必须能被谁整除 不满足时的现象
attention heads、hidden TP 初始化即报错，或头被切开后数值错
层数 PP 各 stage 层数不均 → 慢 stage 拖住整条流水线
专家数 EP 专家槽位对不齐，路由越界或负载严重倾斜

这让 TP 成了一个离散选择：hidden=8192、heads=64 时 TP 只能取 2、4、8、16、32、64，TP=3 非法（示例 1 会打印）。工程顺序因此是"先枚举合法 TP，再挑其他维度"，而不是先定总卡数反推。

3. 硬约束二：TP 与 EP 组合时建议开序列并行#

Megatron Core 指南明确写着：TP + EP 组合时必须启用序列并行（--sequence-parallel），它把 LayerNorm / Dropout 的激活按序列维分片，消掉 TP 各 rank 上重复的激活。指南同时说"用 TP 就该常开"——这是激活账本里最便宜的一刀。

另一条与网络有关：EP 的路由通信（All2All）往往比 DP 的梯度 AllReduce 更敏感，所以 MoE 配置倾向把 EP 组压在节点内、让 DP 组跨机；TP 恰好相反——它的 AllReduce 次数最多、单次消息最小，必须待在节点内。这两条方向相反的偏好，就是"组合"最反直觉的地方。

4. PP 的隐藏税：气泡随段数上升#

PP 把层分到 p 个 stage 上，但同一时刻只有部分 stage 有活干。1F1B（一前一后交替）调度下，气泡占比为

bubble(p,m)=m+p−1p−1​

m 是在流水线里流动的 micro-batch 数。示例 2 把表打全：p=4 时 m=4 要付 42.9% 的气泡，m=16 降到 15.8%。这就是"PP 省显存但要交时间税"的定量版本，而 m 由谁决定、怎么加，是下一课的主题。

5. 反直觉点：PP 与 DP 之间存在"等价条款"#

先看两个旋钮各自做了什么。PP 把 80 层切成 4 段：每卡只存 20 层的参数、梯度和优化器状态，代价是气泡。DP 不减免任何模型状态，但可以让 ZeRO-1 把优化器状态按 DP 组切分：DP=8 时每卡只存 1/8 的优化器状态，代价是 optimizer step 后要 AllGather 参数、以及一次 ReduceScatter。

两者都在对付同一件事——模型状态冗余。所以当某个 PP 度的显存收益已能被 ZeRO-1 用更小的通信代价换到时，加 PP 就不划算。这也是 Megatron 对所有多卡训练都推荐 --use-distributed-optimizer（把优化器状态按 DP 切分）的原因：它是"零气泡版"的那一半。

6. 配置表：六个旋钮、三处陷阱、一条自检#

旋钮 典型取值 先问自己
TP 1/2/4/8 hidden、heads 整除吗？TP 组在节点内吗？
PP 1/2/4/8/16 层数整除吗？m 够大吗（气泡 < 20%）？
CP 1/2/4 序列够长吗（8K+ 才有明确收益）？
EP 1/专家数 整除吗？路由通信在节点内吗？
DP P/(TP⋅PP⋅CP⋅EP) 梯度 AllReduce 跨了几台机？
ZeRO/FSDP off / 1 / 2 / 3 优化器状态、梯度、参数分别要不要切？

三处最常见的陷阱：① 拿总卡数去反推维度（应先枚举合法 TP）；② 以为 PP 一定比 ZeRO 省（两者可互换，先算通信账）；③ 让 TP 组跨机（示例 3 显示单步从 18.70 ms 涨到 215.55 ms）。自检只有一条：写下每个 rank 的坐标 (tp, pp, cp, ep, dp)，确认它与邻居的通信落在预期链路上。

二、可运行代码示例#

三段纯 Python（标准库），把"组合合法性、PP 气泡、TP 通信"变成可打印的数字。带宽、延迟、层配置都是示例参数，请用 nvidia-smi topo -m 与 nccl-tests 实测值替换。

# ===== 示例 1：并行组合的合法性校验 + 总卡数 =====
ATTN_HEADS, HIDDEN, NUM_LAYERS = 64, 8192, 80

def check(tp, pp, cp, ep, dp, heads=ATTN_HEADS, hidden=HIDDEN, layers=NUM_LAYERS, experts=None):
    """返回 (总卡数, 违反的约束)。约束都来自"切分必须整除"与"组合必须成组"。"""
    bad = []
    if heads % tp:  bad.append(f"attention heads={heads} 不能被 TP={tp} 整除")
    if hidden % tp: bad.append(f"hidden={hidden} 不能被 TP={tp} 整除")
    if layers % pp: bad.append(f"layers={layers} 不能被 PP={pp} 整除 → 各 stage 层数不均")
    if ep > 1 and tp == 1: bad.append("EP>1 与 TP 组合时需开序列并行（只上 EP 时先确认实现）")
    if experts is not None and experts % ep:
        bad.append(f"experts={experts} 不能被 EP={ep} 整除")
    return tp * pp * cp * ep * dp, bad

print("示例 1：并行组合校验（总卡数 = TP×PP×CP×EP×DP）")
cfgs = [("纯 DP（起步配置）",       1, 1, 1, 1, 8,  None),
        ("TP+DP",                   8, 1, 1, 1, 2,  None),
        ("LLaMA-3 70B 参考配置",    4, 4, 2, 1, 2,  None),
        ("LLaMA-3.1 405B 参考配置", 8, 8, 2, 1, 8,  None),
        ("DeepSeek-V3 MoE 参考",    2, 16, 1, 64, 1, 256),
        ("非法：TP=3",              3, 1, 1, 1, 2,  None)]
for name, tp, pp, cp, ep, dp, ne in cfgs:
    n, bad = check(tp, pp, cp, ep, dp, experts=ne)
    print(f"  [{'OK ' if not bad else 'BAD'}] {name:<22} TP{tp} PP{pp} CP{cp} EP{ep} DP{dp} = {n:>5} 卡")
    for b in bad: print(f"          └─ {b}")

# ===== 示例 2：PP 气泡 —— 为什么 micro-batch 数 m 至少要到 4p =====
def bubble(p, m):
    return (p - 1) / (m + p - 1)

ms = (1, 2, 4, 8, 16, 32)
print("\n示例 2：1F1B 的气泡占比 (p-1)/(m+p-1)")
print("   p\\m ", "".join(f"{m:>8}" for m in ms))
for p in (2, 4, 8, 16):
    print(f"  {p:>4} " + "".join(f"{bubble(p, m)*100:7.1f}%" for m in ms))

# ===== 示例 3：TP 组放节点内还是跨节点（α-β 模型；每 rank 体积含 batch×seq/tp） =====
ALPHA, BW_INTRA, BW_INTER = 5.0, 300.0, 25.0       # 全部为示例参数

def tp_step_ms(tp, hidden, b, s, layers, bw, alpha=ALPHA):
    """TP 每层 2 次 AllReduce；每 rank 体积 = b*s*hidden*2B/tp。"""
    vol = b * s * hidden * 2 / tp
    per_call = alpha + (vol / (bw * 1e9) * 1e6)     # us
    return layers * 2 * per_call / 1e3, vol

print("\n示例 3：TP 通信时间（示例参数：hidden=8192, b=1, s=8192, layers=80, α=5 μs）")
for tp, bw, tag in ((4, BW_INTRA, "TP=4 节点内"), (4, BW_INTER, "TP=4 跨节点"),
                    (8, BW_INTRA, "TP=8 节点内"), (8, BW_INTER, "TP=8 跨节点")):
    ms, vol = tp_step_ms(tp, 8192, 1, 8192, 80, bw)
    print(f"  {tag:<12} 每 rank 每次 {vol/2**20:6.1f} MiB  单步 {ms:8.2f} ms（160 次 AllReduce）")

示例 3 里有个易被忽略的换算：TP 从 4 加到 8，每 rank 体积减半（32 → 16 MiB），单步通信时间也减半；但 TP 组越大，能同时容纳的 DP 越少——TP 是在拿 DP 并行度换单层显存。

三、练习#

  1. 实现：给示例 1 的 check() 加上"DP 组是否跨机"的判断（输入节点数与每节点卡数，返回 DP 组的跨机跳数），并用它扫描 LLaMA-3 70B 参考配置的 rank 布局，指出哪些 rank 对之间的 TP 通信会跨机。
  2. 解释：为什么 p=16 时即使 m=32，气泡仍有 31.9%，而 p=2 时 m=4 就只有 20.0%？用 m+p−1p−1​ 的分子分母各说明一次。
  3. 对比/验证：把示例 3 的 bw 换成你自己机器上 nvidia-smi topo -m 显示的两类链路实测值（节点内一类、跨节点一类），重算四行，并回答：TP 从 4 提到 8，收益在节点内还是跨节点更大？
  4. 思考：某团队把 80 层模型按 TP8/PP8 切到 64 卡上，单步比 TP4/PP4 慢了 40%。请列出至少三条互斥的候选原因，并各给一个只用日志或 nccl-tests 就能证伪的实验。
