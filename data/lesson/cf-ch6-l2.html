寄存器分配：图着色、溢出与重写#

第 4 课强调过：IR 的临时名"要多少有多少"。到了目标机上这种奢侈立刻破产——AArch64 只有 31 个通用寄存器，一部分还被调用约定与栈指针占着。把几百个虚拟值塞进几十个物理寄存器，塞不下的怎么办？这就是寄存器分配（register allocation）：表面是安排寄存器，本质是两道题——一个 NP-完全的图着色，一个"塞不下时如何改程序"。

一、概念讲解#

1. 这一步在做什么#

LLVM 的目标无关代码生成文档把这一步定义为：把 SSA 形式下"无限虚拟寄存器文件"的代码，转换成目标机具体寄存器文件上的代码；这个阶段引入溢出代码（spill code），并消除程序里所有虚拟寄存器引用。前半句是约束，后半句是验收标准。

2. 活跃范围与干扰图#

活跃范围（live range）是一个值"从被定义到最后一次被使用"的区间。两个值的活跃范围有重叠就不能共用寄存器——这条关系写成图就是干扰图（interference graph）：节点是值，边表示"不能同色"。

构造规则只有一句（Chaitin 的写法）：对每条指令，它定义的值 d 与"该指令之后仍然活着的每个值"之间连一条边——直线代码里任意两个重叠的活跃范围，重叠区间内必有一个定义点，边就在那里被加上。图 1 是本课示例第一轮的干扰图（把示例跑一遍即可逐边核对）。

分配于是变成"给图着色，颜色 = 寄存器"；判定"K 个颜色够不够"在 K ≥ 3 时是 NP-完全的。Chaitin 等人把它引入编译器，不是因为它容易，而是因为它有好的启发式。

3. simplify / select：Chaitin 式启发式#

Chaitin 的算法靠一个栈完成：simplify 反复找出"度数 < K"的节点，从图上摘掉并压栈（邻居少于 K 个，等邻居都定色后总能挑到一个颜色）；select 反向弹栈，给每个节点挑一个邻居没用过的颜色。

图摘到某一刻一定会卡住（剩余节点度数都 ≥ K），此时必须挑一个节点当溢出候选（spill candidate），压栈并标记"可能溢出"。挑谁按"溢出代价最小"：代价近似为 (使用次数 + 定义次数) / 度数。

4. 乐观着色与溢出重写#

卡住就直接判溢出太悲观：图摘到后面会变小，高风险节点可能刚好能落位。乐观着色（optimistic coloring，Briggs 等人的改进）把候选也压栈，只有弹栈时真的找不到颜色才算实际溢出——本课代码实现的正是这一版。

真的溢出意味着这个值必须走内存：在栈帧上开一个槽（spill slot），使用处之前插 ld（装进短命临时名）、定义处之后插 st，这就是 Chaitin 的 spill everywhere。重写之后必须重建干扰图、重新分配（程序变了、活跃范围就变了，可能迭代多轮）；本课代码还做了一个改良——定义来自 load 的值可以从内存重算（rematerialization），于是删掉那条 load、改在使用处重装，省掉一次没必要的 store。

5. 复写合并：让 copy 消失#

IR 里有大量 r = mov t3 这样的复制。让它的两端同色（共用寄存器），那条 copy 就变成"自己搬自己"，可以直接删掉：建图时不给复写对连边，着色时优先让它们同色。这不是白拿的——合并可能造出度数更高的节点反而不可着色，所以实践里用保守合并（如 Briggs 测试、George 测试）。

6. 溢出代价：把寄存器留给热点#

溢出选择对性能影响很大：一条"多一次访存"的指令放进循环体，代价被放大成千上万倍，所以经典启发式按循环深度加权（深度 d 的权常见取 10^d）。本课代码用同一份程序跑了两遍：权重全为 1 时溢出 d，把 d 标成循环体内（权重 10）后改溢 c——"热点值优先留在寄存器里"就是这个意思。

7. 工程现实与常见坑#

真实的分配器要在编译时间与代码质量之间取舍：

方案 思路 适用
图着色（Chaitin / Briggs） 全局看冲突，能合并与拆分 追求代码质量的 AOT
线性扫描（Poletto & Sarkar） 按顺序扫一遍活跃范围 JIT、编译速度优先
LLVM 的 greedy allocator 逐个活跃范围贪心、必要时拆分 LLVM 默认（另有 basic / fast / PBQP）
  • 把分配当纯图着色：固定寄存器与调用约定是硬约束，必须一起进模型；只看冲突数、不看代价也不行，循环体内的活跃范围要优先保住。
  • 忘了重写后重新分配：溢出改变了活跃范围，图不作废就会得到错误的着色。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）把"活跃变量分析 → 干扰图 → simplify/select → 溢出重写 → 再分配"跑通。示例是能手工核对的直线代码：8 条指令、8 个值、9 条边，K = 3。

# ---- 寄存器分配：Chaitin 式图着色（simplify / select）+ 溢出重写 ----
# 纯 Python，无第三方依赖。示例是一段直线代码，活跃变量分析与干扰图都能手算核对。

K = 3                          # 可用的物理寄存器数
REGS = ['x1', 'x2', 'x3']

# ---------- 1. 待分配的线性程序（寄存器数不限的 IR） ----------
#   指令 = (格式串, 定义, 使用列表, 权重, 是否 copy)；格式串里 {d} 是定义，{u0}{u1} 是操作数
def I(fmt, d, uses, w=1, cp=False):
    return {'fmt': fmt, 'def': d, 'uses': list(uses), 'w': w, 'cp': cp}

def T(ins):
    return ins['fmt'].format(d=ins['def'] or '-',
                             **{f'u{k}': v for k, v in enumerate(ins['uses'])})

def program():
    return [
        I('ld   {d}, [x_a]',          'a',  []),
        I('ld   {d}, [x_b]',          'b',  []),
        I('ld   {d}, [x_c]',          'c',  []),
        I('ld   {d}, [x_d]',          'd',  []),
        I('{d} = {u0} + {u1}',        't1', ['a', 'b']),
        I('{d} = {u0} + {u1}',        't2', ['c', 'd']),
        I('{d} = {u0} + {u1}',        't3', ['t1', 't2']),
        I('{d} = mov {u0}',           'r',  ['t3'], cp=True),   # copy：可与 t3 共用寄存器
    ]

# ---------- 2. 活跃变量分析（直线代码：live_out[i] = live_in[i+1]） ----------
def liveness(prog):
    li = [set()] * len(prog)
    for i in range(len(prog) - 1, -1, -1):
        out = li[i + 1] if i + 1 < len(prog) else set()
        li[i] = set(prog[i]['uses']) | (out - {prog[i]['def']})
    return li

def live_out(prog, li, i):
    return li[i + 1] if i + 1 < len(prog) else set()

# ---------- 3. 干扰图：定义 d 与"该点之后仍然活着"的每个值互斥 ----------
#    copy 指令的定义-使用对不连边（它们允许共用一个寄存器 = 复写合并）
def build_ig(prog):
    nodes = set()
    for ins in prog:
        if ins['def']: nodes.add(ins['def'])
        nodes.update(ins['uses'])
    adj = {v: set() for v in nodes}
    li = liveness(prog)
    for i, ins in enumerate(prog):
        d = ins['def']
        if not d: continue
        for v in live_out(prog, li, i):
            if v == d: continue
            if ins['cp'] and v in ins['uses']: continue       # 复写对：不互斥
            adj[d].add(v); adj[v].add(d)
    return adj, li

# ---------- 4. simplify / select（乐观着色：spill 候选也压栈，真没色了才算溢出） ----------
def allocate(adj, K, spill_cost, partner_map=None):
    work = {v: set(adj[v]) for v in adj}
    stack = []
    while work:
        low = [v for v in work if len(work[v] & work.keys()) < K]
        if low:                                     # 度数 < K：一定能着色
            v = min(low, key=lambda x: (len(work[x] & work.keys()), x))
            stack.append((v, False))
        else:                                       # 度数 >= K：先当"潜在溢出"
            v = max(work, key=lambda x: (len(work[x] & work.keys()), -spill_cost.get(x, 0), x))
            stack.append((v, True))
        for s in work.values(): s.discard(v)
        del work[v]
    color, spilled = {}, []
    for v, potential in reversed(stack):
        used = {color[n] for n in adj[v] if n in color}
        partner = (partner_map or {}).get(v)
        free = [c for c in range(K) if c not in used]
        if partner in color and color[partner] not in used:
            color[v] = color[partner]                # 复写合并：跟 copy 伙伴同色
        elif free:
            color[v] = free[0]
        else:
            spilled.append(v)
    return color, spilled, stack

# ---------- 5. 溢出重写 ----------
#   定义来自 load 的值：删掉那条 load，改用在使用处重装（rematerialization）
#   其余值：溢写到栈——定义后立即 store，每个使用前 load 成短命临时名
def rewrite(prog, spills):
    out, slots, addr, removable = [], {}, {}, set()
    for ins in prog:
        if ins['def'] in spills and not ins['uses'] and 'ld ' in ins['fmt']:
            removable.add(ins['def'])
            addr[ins['def']] = ins['fmt'].split('[')[1].split(']')[0]
    for i, ins in enumerate(prog):
        if ins['def'] in removable: continue          # 该 load 被删掉
        uses = list(ins['uses'])
        for k, v in enumerate(uses):
            if v not in spills: continue
            tmp = f'{v}${i}'
            if v in removable:
                out.append(I('ld   {d}, [' + addr[v] + ']', tmp, []))
            else:
                slots.setdefault(v, f'[spill_{v}]')
                out.append(I('ld   {d}, ' + slots[v], tmp, []))
            uses[k] = tmp
        out.append(I(ins['fmt'], ins['def'], uses, ins['w'], ins['cp']))
        if ins['def'] in spills and ins['def'] not in removable:
            slots.setdefault(ins['def'], f'[spill_{ins["def"]}]')
            out.append(I('st   {u0}, ' + slots[ins['def']], None, [ins['def']]))
    return out

def show(prog, li=None, indent='  '):
    for i, ins in enumerate(prog):
        extra = ''
        if li is not None:
            extra = '   live_out={' + ','.join(sorted(live_out(prog, li, i))) + '}'
        print(f'{indent}{i:>2}: {T(ins):<22} def={str(ins["def"]):<5} use={ins["uses"]}{extra}')

def spill_cost(prog, weights=None):
    c = {}
    for ins in prog:
        w = (weights or {}).get(ins['def'], ins['w'])
        for v in ([ins['def']] if ins['def'] else []) + ins['uses']:
            c[v] = c.get(v, 0) + w
    return c

if __name__ == '__main__':
    base = program()
    print('=== 待分配的程序（K = %d 个寄存器：%s） ===' % (K, ' '.join(REGS)))
    show(base)

    prog, round_no = base, 0
    while round_no < 5:
        round_no += 1
        adj, _ = build_ig(prog)
        li = liveness(prog)
        print(f'\n=== 第 {round_no} 轮：{len(prog)} 条指令，{len(adj)} 个值，'
              f'{sum(len(s) for s in adj.values()) // 2} 条干扰边 ===')
        show(prog, li)
        print('  干扰边：', ' '.join(sorted({'-'.join(sorted((u, v))) for u in adj for v in adj[u]})))
        cost = spill_cost(prog)
        partner = {i['def']: i['uses'][0] for i in prog if i['cp'] and i['uses']}
        color, spilled, stack = allocate(adj, K, cost, partner)
        print('  simplify 栈：', ' '.join(f'{v}{"?" if p else ""}' for v, p in stack), '（? = 潜在溢出）')
        print('  select 着色：', ' '.join(f'{v}={REGS[c]}' for v, c in sorted(color.items())))
        print('  实际溢出：', spilled if spilled else '无')
        if not spilled:
            copies = [p for p in prog if p['cp'] and color.get(p['def']) == color.get(p['uses'][0])]
            print(f'\n  分配完成：{len(prog)} 条指令（原始 {len(base)} 条），溢出 {round_no - 1} 个值')
            show(prog)
            print(f'  copy 与源同色、可直接删除：{len(copies)} 条'
                  f'{"（" + ", ".join(T(p) for p in copies) + "）" if copies else ""}')
            break
        prog = rewrite(prog, set(spilled))
        print(f'  溢出重写后（{len(prog)} 条指令）：')
        show(prog)

    print('\n=== 对照：溢出代价启发式的影响（同样 K=3，只改权重） ===')
    for label, w in (('所有值权重 = 1', {}), ('d 在循环体内（权重 10）', {'d': 10})):
        adj, _ = build_ig(base)
        cost = spill_cost(base, w)
        _, spilled, _ = allocate(adj, K, cost)
        print(f'  {label:<22} 代价表 {dict(sorted(cost.items()))} → 溢出 {spilled}')

  d 在循环体内（权重 10）         代价表 {'a': 2, 'b': 2, 'c': 2, 'd': 11, 'r': 1, 't1': 2, 't2': 2, 't3': 2} → 溢出 ['c']

三件值得盯住的事：

  1. 第 1 轮就撞上 K=3 的硬墙：a、b、c、d 在指令 3 处同时活着、两两相连（a-b a-c a-d b-c b-d c-d），凑成 4-团——3 种颜色染不了 4 个两两冲突的节点，必然溢出。
  2. 溢出重写没有让程序变长：d 的定义是一条 load，"删掉 load、在使用处重装"之后仍是 8 条；经典 spill everywhere 会多出一条 st d, [spill_d]。
  3. 第 2 轮干扰边从 9 条降到 7 条，着色一次成功；t3 与 r 同为 x1，那条 r = mov t3 可直接删。对照实验再看启发式：d 的权重调成 10 后代价从 2 变 11，分配器就改溢 c——"保谁"由启发式决定。

三、练习#

  1. 实现：把 K 改成 4 再跑一遍，验证"4 色够染 4-团"。
  2. 解释：为什么"定义点与 live-out 连边"这一条规则就够？举一个漏边导致同色的例子。
  3. 对比/验证：把 rewrite() 改成经典 spill everywhere（load 型定义也插 st），比较两版的指令数与第 2 轮干扰边数。
