TensorRT-LLM 与 llama.cpp#

vLLM 是"高吞吐 GPU 服务"的通用解，但推理引擎的世界远不止这一种：NVIDIA 的 TensorRT-LLM 走的是"针对自家 GPU 深度编译优化"的极致性能路线；llama.cpp 走的是"CPU / 消费级设备也能跑大模型"的轻量通用路线。学完本课，你应当能说清三者的定位差异，并会写各自的启动/编译命令。

一、概念讲解#

1. TensorRT-LLM：为 NVIDIA GPU 深度定制的编译器#

TensorRT-LLM 是 NVIDIA 官方的 LLM 推理框架，本质是一个编译型引擎。它的核心是：先把模型"编译"成针对目标 GPU 高度优化的 TensorRT engine（引擎），再运行。编译过程做图优化、算子融合、kernel 自动调优（autotuning），因此单卡峰值性能往往极高。

特点：

  • 编译期优化：使用前要先 build engine（耗时几分钟到更久），换来运行时的高性能；
  • in-flight batching：即第 1 章的 continuous batching 的 NVIDIA 实现；
  • 强量化支持：原生支持 FP8、INT8、INT4 AWQ 等，FP8 在 H100 上有明显加速；
  • 多卡并行：张量并行 + 流水线并行，适合超大模型。

代价是：绑定 NVIDIA 生态、上手门槛高、编译流程繁琐，且新模型需要额外写转换脚本。

2. llama.cpp：让大模型跑在 CPU 和消费级设备上#

llama.cpp 是一个用 C/C++ 写的极轻量推理实现，最初目标是在 Mac 上跑 LLaMA，后来演变成"任何有内存的设备都能跑量化模型"的通用工具。它依赖 GGUF 格式（第 4 章会详讲）的量化权重。

特点：

  • 几乎零依赖：编译成单个可执行文件，CPU 就能跑，也有 CUDA / Metal / Vulkan 后端加速；
  • 极致量化：支持从 FP16 到 2-bit 的多种量化档位，4-bit 模型只需几 GB 内存就能跑 7B；
  • 本地/边缘优先：适合个人电脑、手机、嵌入式设备，不适合高并发在线服务。

代价是：吞吐不如 GPU 服务引擎（CPU 上跑大模型访存受限），功能聚焦于"能跑起来"而非"榨干吞吐"。

3. 三者定位一句话#

引擎 定位 强项 典型场景
vLLM 通用高吞吐 GPU 服务 易用、生态好、吞吐高 在线 API、批量评测
TensorRT-LLM NVIDIA 极致性能 编译优化、FP8、超大模型多卡 生产级 GPU 集群、低延迟
llama.cpp 轻量通用 CPU/消费级、量化灵活 本地跑模型、边缘设备

二、可运行示例#

1. TensorRT-LLM：编译并运行（示意）#

# 1) 安装（NVIDIA 提供 docker 镜像，最省事）
docker pull nvcr.io/nvidia/tensorrt-llm/release:latest

# 2) 把 Hugging Face 模型转换成 TRT-LLM 格式并编译 engine（以 Llama-2-7B 为例）
python convert_checkpoint.py --model_dir ./Llama-2-7b-chat-hf \
    --dtype float16 --output_dir ./trt_ckpt
trtllm-build --checkpoint_dir ./trt_ckpt \
    --gemm_plugin float16 --max_batch_size 64 --max_input_len 1024 \
    --max_output_len 512 --output_dir ./engine

# 3) 用 in-flight batching 启动服务
python run.py --engine_dir ./engine --max_output_len 512 --port 8000

2. llama.cpp：下载量化模型并推理#

# 1) 编译 llama.cpp（以 CPU 为例；有 CUDA 可加 -DGGML_CUDA=ON）
git clone https://github.com/ggerganov/llama.cpp && cd llama.cpp
cmake -B build && cmake --build build --config Release -j

# 2) 下载一个 4-bit GGUF 模型（如 Llama-3-8B Q4_K_M）
#    然后交互式推理，-ngl 999 表示尽量把层卸载到 GPU（若有）
./build/bin/llama-cli -m ./llama-3-8b-q4_k_m.gguf \
    -p "用一句话解释 KV Cache" -n 128 -ngl 999

# 3) 或启动一个兼容 OpenAI 的本地服务
./build/bin/llama-server -m ./llama-3-8b-q4_k_m.gguf --port 8080

3. 用一个 Python 表格帮选型#

# -*- coding: utf-8 -*-
# 简易选型：根据你的硬件与场景，推荐推理引擎

def recommend(has_nvidia_gpu, is_production, need_cpu_only):
    if need_cpu_only:
        return "llama.cpp（CPU/边缘，量化模型）"
    if has_nvidia_gpu and is_production:
        return "TensorRT-LLM（编译优化，极致性能）或 vLLM（易用高吞吐）"
    if has_nvidia_gpu:
        return "vLLM（开箱即用的高吞吐服务）"
    return "llama.cpp（本地消费级设备）"

for gpu, prod, cpu in [(True, True, False), (True, False, False),
                       (False, False, True), (False, False, False)]:
    print(f"GPU={gpu} 生产={prod} 仅CPU={cpu} -> {recommend(gpu, prod, cpu)}")

三、练习#

  1. 看差异：对比 TensorRT-LLM 的"先编译 engine"与 vLLM 的"直接加载权重"，思考：为什么 TensorRT-LLM 换模型更麻烦，但单卡峰值性能常更高？
  2. CPU 跑模型：用 llama.cpp 在本地 CPU 上跑一个 4-bit 量化模型，记录生成速度（tokens/s），再对照第 1 章 decode"访存密集"的结论，解释为什么 CPU 上很慢。
  3. 加 GPU 卸载：llama.cpp 启动时把 -ngl 从 0 改到 999，观察速度变化，理解"层卸载到 GPU"的作用。
  4. 思考：一个边缘设备（无 GPU、内存 16GB）要跑 7B 模型，只能选哪个引擎？为什么 vLLM 和 TensorRT-LLM 都不可行？
