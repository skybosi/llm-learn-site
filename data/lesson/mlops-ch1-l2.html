数据 / 模型 / 代码的版本与血缘：为什么"模型版本"单独不够#

这一节要解决什么#

线上模型的回答质量掉了。你打开模型仓库，手上有：

model_v7.pt        2026-08-14      87 MB
model_v8.pt        2026-09-02      87 MB     ← 现在线上跑的

现在开始问问题：

  • 为什么 v8 比 v7 差？ 是数据变了、代码变了、超参变了，还是环境变了？版本号回答不了 —— 它只标识输出，不标识输入。
  • v7 的训练数据还在吗？ 训练数据存在 data/all.jsonl，而这个文件在过去两个月里被追加过 6 次、被一次清洗脚本就地重写过 1 次。所以"还在"这个说法没有意义：它已经不是当时那份了。
  • 这份数据里发现了 PII，要撤销，哪些模型受影响？ 这要求你从数据出发，沿"谁用了它 → 产出了什么 → 谁又用了那个产物"一路走到底。
  • 能不能把 v7 重新训出来？ 需要数据、代码、超参、环境、种子五样同时可定位。

这四个问题的共同点是：它们的答案不在"模型"这个对象里，而在"模型与其它制品的关系"里。这一节就是把这层关系工程化：制品（artifact）的版本化 + 血缘（lineage）图。

先把结论写出来，后面所有设计都在为它服务：

可归因⟺∃ 两个版本的变更集 Δ=(A2​∖A1​)∪(A1​∖A2​) 且 Δ 可分解到 (D,C,H,E,Σ)

版本号不是变更集。 只知道 v7 → v8，你拥有的只是一个名字的变化；只有知道"这两次运行之间，哪 3 个制品换了"，归因才是可计算的。

一、为什么"模型版本"单独不够#

1.1 模型是函数，版本号只描述值域#

把训练看成一个确定的映射（第三/四节会讨论它其实不完全确定）：

M=Train(D,C,H,E,Σ),D=数据, C=代码, H=超参, E=环境, Σ=随机性

model_v8.pt 是 M 的一个取值。可以从 M 读出很多观测（参数量、层数），但读不出自变量。于是：

你想做的推理 只给版本号时 需要变更集时
解释分数差异 "v8 就是差一些" "v8 换了 v3 数据（去重后样本少 4%）且 warmup 从 2000 提到 5000"
决定下一步实验 盲目试 沿差异最大的那一项做消融
评估风险 无法 "这次改动同时动了 tokenizer，风险等级高"

1.2 一个更隐蔽的问题：三个"版本"命名空间被混用#

在真实团队里，"版本"这个词至少指三件不同的事，而它们update 的节奏与不可变性完全不同：

命名空间 例子 谁在推进 不可变？
内容版本（artifact revision） sha256:3db6…（一份确切字节） 内容变化时自动 必须不可变
逻辑版本（dataset/model release） dataset:train-v3、model:chat-v7 人/流程显式发布 发布后不可变，改就发 v4/v8
指针 / 别名（pointer / alias） prod、latest、champion 上线流程 可变，且每次移动都要审计

事故几乎全部发生在这三者的边界上。最常见的一种：

清理脚本发现 data/all.jsonl 里有重复样本，就地重写了这个文件。指向它的 tag 还是 v3，但字节已经变了。

于是三个灾难同时发生：历史 run 记录的 data_ref 指向的字节找不回来了；用 v3 训练的两个模型其实用了不同数据，却因为同名而被当成可比较；"复现 v7"变成不可能。

纪律（本节的第一条）：

内容不可变；逻辑版本只追加；指针移动必须留审计记录​

任何"更新一个已发布版本"的操作，实质都是"发布一个新版本 + 移动指针"，必须被表示为两次操作而不是一次覆盖。

1.3 内容寻址解决了什么、没解决什么#

三层结构要分清：

[ 不可变内容层 ]   blob / shard 的 sha256        ← 只增不改
        ↑ 引用
[ 逻辑版本层 ]     manifest（有序的 (路径, hash, 大小) 列表）  ← 一次发布一个
        ↑ 别名
[ 指针层 ]         train-v3 / prod / champion      ← 可变，有审计

内容寻址解决的是"同一性判定"：两个制品是不是同一份，比哈希即可，不需要读内容、不需要信命名。

它没有解决三件事：

  1. "同一份"的粒度：把一亿条样本打包成一个文件求哈希，任何一条变化都让哈希变，你无法知道"变了 30 条还是全变了" → 需要分片 + Merkle（见 2.3）。
  2. 语义同一性：字节相同但读取顺序不同、预处理代码不同，训练结果可以不同。所以数据版本必须和"读取与预处理代码"一起版本化。
  3. 外部性：第三方模型 API、上游数据库、用户实时产生的日志，不受你控制，内容寻址只能记录"当时看到的是什么"（把它冻结成一个制品）。

二、数据版本化：版本化的是"查询结果"#

2.1 数据不是一份文件，是一次选择#

所谓"训练集"其实是一个产物，由一串变换决定：

D=Tokenize(Dedup(Filter(Join(Sources))))

这里面每一个括号里的东西都会变：源数据在增长、过滤器阈值被调过、去重算法换过、tokenizer 升过版。所以：

数据版本的语义="在这个变换链下，此刻选出的这一组字节"

把数据版本化为"给文件打标签"之所以失败，是因为文件是变换链的输出，而不是变换链本身。 正确的最小定义是一个显式的清单（manifest）：

dataset_release: train-v3
code_ref: git:9f2c1a7            # ★ 生成这份清单的 pipeline 代码
parents: [train-v2]
transform:
  filters: {min_len: 32, lang: ["zh", "en"], dedup: "minhash:0.8"}
  tokenizer: sha256:b1e2…        # 制品 id，不是名字
shards:                          # ★ 分片级内容寻址
  - {path: "part-000.parquet", sha256: "aa11…", bytes: 104857600, rows: 50000, t_start: "2026-01-01", t_end: "2026-06-30"}
  - {path: "part-001.parquet", sha256: "bb22…", bytes: 104857600, rows: 50000, t_start: "2026-07-01", t_end: "2026-08-31"}
merkle_root: "9f3c…"             # ★ 清单自身的指纹，见 2.3

三个字段值得强调：code_ref（变换链的代码）、tokenizer（下游预处理的关键依赖）、t_start/t_end（时间切分，防止用未来数据训练）。

2.2 三条实现路径与它们的代价#

方案 机制 优点 代价 适用
全量快照 每次发布复制一份（或硬链接） 简单、无歧义 存储 × 版本数；大文件复制慢 中小规模（TB 以下）
时间旅行表 表自带快照 id / 版本列（SCD-2） 省空间、SQL 直接查历史 绑定存储引擎；跨系统难移植 已有数仓（Iceberg/Delta 类）
manifest + 内容寻址分片 只存分片哈希，物理文件按哈希去重 增量、可校验、可跨系统 要写 pipeline 集成；需 GC 推荐给自建管线

第三种的增量能力来自一个简单事实：两次发布之间只改了几个分片，就只上传那几个分片。

写放大=全量字节变更分片字节​,读放大=定位一个样本需要读的分片元数据

2.3 Merkle 树：把"变了多少"变成可计算的#

分片哈希表本身已经够用，但要高效地证明"两份清单相同"与"定位差异"，用 Merkle 结构：

hleaf​(i)=H(shardi​),hnode​=H(hleft​∥hright​),root=唯一的 hroot​

三条性质，每条都有直接工程后果：

  1. 相等判定 O(1)：两个 manifest 的 root 相同 ⟺（在抗碰撞假设下）分片集合相同。注意是"集合"：若分片顺序在语义上重要（例如课程式训练的顺序），顺序必须进入哈希输入，否则"集合相同"≠"训练相同"。
  2. 差异定位 O(klogn)：k 个分片变化时，只需比较路径上的节点，不必逐个分片读。104 个分片下，定位 3 个变化的分片只需读约 3×14 个哈希。
  3. 可验证的局部读取：给定可信 root，客户端可以只下载一个分片并验证它属于这份清单（Merkle proof），无需下载全部。

定位差异的读取量=O(klogn),朴素的逐分片比较=O(n)

2.4 数据的"删除"是一个与不可变性冲突的动作#

不可变存储遇到"删除某条数据"（隐私撤回、许可到期、脏数据）会立刻冲突。必须先承认三件事：

  1. 物理删除要重写所有含它的分片 → 分片哈希全变 → 严格说，这是一次新的数据集版本，而不是对旧版本的编辑；
  2. 已经训练过的模型无法"取消训练" → 删除数据不会让模型遗忘它（成员推断攻击仍然有效）。所以"撤销数据"的真实含义是重训决策；
  3. 下游有余量：日志、缓存、评测报告、向量库索引里可能也有这份数据。

因此正确的表示是墓碑（tombstone）事件 + 影响面计算，而不是假装数据被抹掉了：

delete_event {artifact: "aa11…", reason: "PII", at: "...", scope: "shard"}
  → 受影响数据集版本 = {v ∈ releases : shard ∈ v.shards}
  → 受影响模型      = descendants(受影响数据集版本) ∩ kind == "model"
  → 决策：重训 / 接受风险并记录 / 下线

"撤销数据"在工程上从来不是一个删除操作，而是一次血缘查询 + 一个重训预算决定。

三、模型版本化：权重只是其中一个制品#

3.1 三种"模型制品"不能混为一谈#

制品 内容 谁用 更换频率 哈希变了意味着
checkpoint 权重 + 优化器状态 + step + RNG 状态 恢复训练 高（每 N 步） 训练进度不同
weights 纯权重（可加载推理） 评测、微调、导出 中（每次发布） 模型不同
engine 量化/编译后的可执行件（与硬件、算子库绑定） 线上服务 与硬件绑定 可能只是换了编译目标，权重未必变

把三者都叫"模型 v8"会造成两类事故：拿 engine 去继续训练（缺优化器状态）、或者以为 engine 变了就是权重变了（实际只是换了一张卡重编译）。每个制品必须有 kind，且血缘边要区分"派生"与"重新打包"。

3.2 LLM 特有：改变输出 ≠ 改变权重#

这是 LLM 版本管理区别于传统 ML 的关键点。以下五样东西都能显著改变输出，却不改变任何权重字节：

输出=fweights​(tokenize(x; tokenizer), prompt_template, decode_params)

变更 是否改权重 是否必须版本化 为什么
tokenizer 词表升版 否 是 同一文本切成不同 id，输出直接变
system prompt / chat 模板 否 是 改一个词就能让评测动几个点
解码参数（temperature/top_p/max_tokens） 否 是 同一权重下分布完全不同
后处理（引用抽取、拒答逻辑） 否 是 只影响"看起来对不对"
推理引擎版本 否 是 数值实现不同（第 3 节）

所以线上真正需要版本化的是一个推理单元：

InferenceUnit=(weights, tokenizer, prompt_template, decode_params, engine, postprocess)

把它整体做成一个内容寻址的制品清单，这就是第 2 章灰度与回滚的最小可回滚单元 —— 少一个部件都可能导致"回滚了权重但没回滚 prompt"的经典事故。

3.3 模型卡片要做成可查询的结构，不是一篇文档#

模型卡片（model card）如果只是一篇 Markdown，它会在三个月内过时且没人查。把它做成结构化元数据，字段要能支撑查询：

model: chat-v7
weights:   {artifact: "3db6…", kind: weights}
training:  {dataset: train-v3, code: "git:9f2c1a7", run: "1c1455b9e5ca8c1b-42"}
eval:      [{metric: accuracy, dataset: eval-frozen-v2, fn: acc_v2, value: 0.874,
             n_seeds: 3, ci95: [0.862, 0.886]}]
limits:    ["超过 8k 上下文质量下降", "对 2026-06 之后的事实无覆盖"]
license:   internal-only

注意 eval 里必须带 dataset 与 fn 引用（第 1 节的三元组），并且带种子数与置信区间（第 4 节会用到）。一个模型卡片如果能自动回答"哪些模型在 eval-frozen-v2 上超过 0.87 且训练数据不含 shard aa11"，它就活了；否则它只是装饰。

3.4 别名是指针，不是版本#

prod、champion、latest 必须实现为指向逻辑版本的指针，并且：

  • 每次移动写一条审计记录：谁 / 何时 / 从哪个版本到哪个版本 / 为什么（关联的变更单）；
  • 支持"按时间点解析"：resolve("prod", at="2026-08-14T09:00Z") → chat-v7。这是事故复盘的基础设施：复盘时第一个问题往往是"当时线上到底跑的哪个版本？"

四、血缘：从制品到图#

4.1 节点、边与一个必要的修正#

定义有向图 G=(A,E)，A 是制品集合，边 e=(u→v,run,kind,t) 表示"制品 v 由 u 通过 run 派生而来"。

纯 DAG 是不够的，真实图有三种"反 DAG"现象，必须建模：

  1. 重训：同一个数据集被反复用来训模型，边很多 → 无所谓，多重边（用 run 区分）；
  2. 互引：微调模型 A 生成数据，数据训出模型 B，B 又生成数据训 A 的新版本 → 时间上无环，但去掉时间戳后成环。所以边必须带时间戳，查询时要能限定"只看某个时刻之前的祖先"；
  3. 人：有些结点是人（上传的第三方权重、手工标注的评测集）。它们不可自动追踪，但必须显式存在，标为 external 类型并记录获取方式与日期。

4.2 四类查询及它们的用途#

查询 图上的操作 用途
正向影响面 从节点出发的可达集 数据撤销 / 某依赖升级后要重跑什么
反向归因 到节点的可达集（限时间） 模型出问题，上游哪些变更可能相关
最早引入点 两条路径的最短差分 / 自底向上的共同祖先 "v7→v8 之间，最早改变的是哪一步"
变更集 两次 run 的输入/输出对称差 消融实验的设计输入

"最早引入点"值得单说：当两个产物的指标出现差异时，不要从最新的一步开始猜。做法是从两条血缘链的最近共同祖先开始，向下逐段比较输入哈希：

分歧点=在两条链上，第一个输入集合不同的 run

由于每个 run 都记了输入的制品 id，这个比较是纯集合运算，不需要重跑任何训练。这正是第 1 节把 run_artifacts(role=input) 记全的回报。

4.3 断链：血缘必然不完整，关键是显式#

血缘图在现实中一定有断点：

  • 第三方模型 API（gpt-*@2026-06 这种版本号随时可能被供应商改）；
  • 手工上传的权重（有人从别处下载了一个 checkpoint）；
  • 通过共享盘/邮件传递的数据；
  • 数据源本身（上游业务库的变更没有通知）。

处理方式不是"想办法全都自动捕获"（做不到），而是把断点变成显式的 external 节点，并绑定你能固定的信息：

external {kind: model_api, provider: "…", model_id: "…", pinned_date: "2026-06-01",
          snapshot_of_behavior: eval_report_id, note: "供应商未提供权重哈希"}

为什么这比"留空"好：留空会让下游查询静默返回不完整答案（以为影响面就这么大）；显式的 external 节点让查询可以说"影响面包含 2 个不可控依赖"。

4.4 影响面不只是一个集合，还是一笔钱#

撤销一份数据时，真正决定决策的是重训代价：

重训代价=r∈descendants(d)∩train-runs∑​(GPU 时×单价+评测与发布成本)

边权要按动作类型区分：train 边很贵，eval 边便宜（可以重跑），export 边几乎免费。所以血缘边必须带 kind，否则"影响面 47 个制品"这句话没法转成任何预算。

五、取舍#

决策 一侧 另一侧 判据
内容寻址 vs 递增版本号 同一性可判定、天然去重 人类不可读、需要别名层 两者都要：内容层寻址，逻辑层编号，别名层指针
全量快照 vs manifest 增量 简单、无歧义 省存储、快 数据 > TB 或更新频繁 ⇒ manifest；否则全量快照更省心
血缘自动采集 vs 手工登记 不漏（在框架覆盖范围内） 能表达"人做的事" 训练框架内自动；人做的步骤必须走一个"登记制品"的入口，否则就是断链
中心 registry vs 分散存储 可查询、可审计 无单点、团队自治 制品元数据集中，字节可以分散（URI 指向对象存储）
删除 vs 墓碑 满足合规的字面要求 保历史可复现 先墓碑 + 影响面，物理删除是另一个流程（且要记录它破坏了哪些历史版本）
血缘粒度 每条 run 都连（全） 只连跨阶段的关键制品（少） 边太多会淹没；规则是"下游需要用于复现的输入都连"，其余记在 run 元数据里

代码：内容寻址制品库 + Merkle 清单 + 血缘图#

下面的代码实现三件事：(1) 内容寻址的金库与按分片的 Merkle 清单（能定位"变了哪几片"）；(2) 逻辑版本与可变指针的分离（演示"就地重写同一版本"如何被检测出来）；(3) 血缘图与"撤销一份数据要重训哪些模型 + 花多少钱"。只用标准库。

"""
mlops-ch1-l2：制品库 + Merkle 数据集清单 + 血缘图。

三个设计决策（★）：
  ① 内容不可变、逻辑版本只追加、指针移动有审计 —— 三层分离
  ② 数据集用"分片清单 + Merkle root"，让"变了多少"可计算
  ③ 血缘边带 kind 与时间戳 —— 让影响面能换算成重训预算
运行：python3 mlops_ch1_l2.py
"""
from __future__ import annotations

import hashlib
import json
from bisect import bisect_right
from collections import deque


def H(*parts: bytes) -> str:
    h = hashlib.sha256()
    for p in parts:
        h.update(p)
    return h.hexdigest()[:16]


def content_id(data: bytes) -> str:
    """全局唯一的内容哈希命名空间：blob 与数据集分片共用它。

    ★ 为什么共用一个命名空间：如果"金库的键"与"清单里的 sha256"是两套算法，
      校验时就得再来一次映射，而任何一次映射不一致都会让"验证通过"变成假的。
    """
    return H(b"blob:", data)


# ============================================================ ① 不可变金库
class BlobStore:
    """内容寻址：id = content_id(内容)。天然去重、不可变、可校验。"""

    def __init__(self):
        self.blobs: dict[str, bytes] = {}
        self.put_calls = 0

    def put(self, data: bytes) -> str:
        self.put_calls += 1
        bid = content_id(data)
        if bid not in self.blobs:          # ★ 同一份数据只存一次
            self.blobs[bid] = data
        return bid

    def get(self, bid: str) -> bytes:
        return self.blobs[bid]


# ============================================================ ② Merkle 清单
class DatasetRelease:
    """一次数据集发布 = 有序分片清单 + Merkle root。

    ★ 决策②：分片顺序进入哈希输入。若训练对样本顺序敏感（课程式训练），
      "集合相同"不等于"训练相同"，顺序必须被版本化。
    """

    def __init__(self, name: str, code_ref: str, shards: list[tuple[str, bytes]],
                 parents: list[str] | None = None, transform: dict | None = None):
        self.name = name
        self.code_ref = code_ref
        self.parents = parents or []
        self.transform = transform or {}
        self.shards = [(path, content_id(data), len(data)) for path, data in shards]
        self.leaves = [H(b"leaf:", s.encode()) for _, s, _ in self.shards]
        self.root = self._merkle(self.leaves)
        self.manifest_id = H(json.dumps(self.to_dict(), sort_keys=True).encode())

    @staticmethod
    def _merkle(leaves: list[str]) -> str:
        if not leaves:
            return H(b"empty")
        level = list(leaves)
        while len(level) > 1:
            nxt = []
            for i in range(0, len(level) - 1, 2):
                nxt.append(H(b"node:", level[i].encode(), level[i + 1].encode()))
            if len(level) % 2:                     # 奇数节点上提（不复制）
                nxt.append(level[-1])
            level = nxt
        return level[0]

    def diff(self, other: "DatasetRelease", store: BlobStore) -> dict:
        """定位差异：只比较分片哈希表（真实系统可走 Merkle 路径，O(k log n)）。"""
        a = {p: (s, n) for p, s, n in self.shards}
        b = {p: (s, n) for p, s, n in other.shards}
        return {
            "added": sorted(b.keys() - a.keys()),
            "removed": sorted(a.keys() - b.keys()),
            "changed": sorted(p for p in a.keys() & b.keys() if a[p][0] != b[p][0]),
            "same_root": self.root == other.root,
        }

    def verify(self, store: BlobStore) -> bool:
        """任何人拿到清单都能验证字节没被篡改（前提：root 可信）。

        ★ 两步：先验证每个分片字节的哈希与清单一致，再用同样的 Merkle 规则重算 root。
          只验其中一步都不够：只验字节 → 清单可以被换掉；只验 root → 不知道字节在不在。
        """
        for path, sha, n in self.shards:
            data = store.blobs.get(sha)
            if data is None or content_id(data) != sha or len(data) != n:
                return False
        return DatasetRelease._merkle(self.leaves) == self.root

    def to_dict(self) -> dict:
        return {"name": self.name, "code_ref": self.code_ref, "parents": self.parents,
                "transform": self.transform, "root": self.root,
                "shards": [{"path": p, "sha256": s, "bytes": n} for p, s, n in self.shards]}


# ============================================================ 逻辑版本 + 指针
class Registry:
    """★ 决策①：三层分离。

    releases: 逻辑版本 -> 不可变的 manifest（只追加）
    pointers: 别名 -> [(时间, 目标)]（可变，但每次移动留审计）
    """

    def __init__(self):
        self.releases: dict[str, dict] = {}
        self.pointers: dict[str, list[tuple[str, str, str]]] = {}
        self.incidents: list[str] = []

    def publish(self, name: str, manifest: dict):
        if name in self.releases:
            old = self.releases[name]["manifest_id"]
            if old != manifest["manifest_id"]:
                # ★ 就地覆盖同一发布名 —— 这是最危险的操作，必须被检测并拒绝
                self.incidents.append(
                    f"拒绝覆盖已发布版本 {name}（旧 {old} → 新 {manifest['manifest_id']}）；"
                    f"正确做法：发布 {name[:-1]}{int(name[-1])+1}")
                raise ValueError(self.incidents[-1])
        self.releases[name] = manifest

    def move_pointer(self, alias: str, target: str, at: str, reason: str, who: str):
        self.pointers.setdefault(alias, []).append((at, target, f"{who}:{reason}"))

    def resolve(self, alias: str, at: str) -> str | None:
        """按时间点解析别名 —— 复盘时回答"当时线上是什么"。"""
        hist = self.pointers.get(alias, [])
        times = [t for t, _, _ in hist]
        i = bisect_right(times, at) - 1
        return hist[i][1] if i >= 0 else None


# ============================================================ ③ 血缘图
TRAIN_COST_HOURS = {"train": 40.0, "finetune": 12.0, "quantize": 1.0,
                    "eval": 0.2, "export": 0.05, "prompt": 0.0}
GPU_PRICE = 2.5  # $/GPU·h


class Lineage:
    """边 = (parent, child, run, kind, at)。kind 决定重训代价，at 支持"只看当时"。"""

    def __init__(self):
        self.edges: list[tuple[str, str, str, str, str]] = []
        self.kind: dict[str, str] = {}

    def register(self, aid: str, kind: str):
        self.kind[aid] = kind

    def add(self, parent: str, child: str, run: str, kind: str, at: str):
        self.edges.append((parent, child, run, kind, at))

    def _adj(self, before: str | None = None):
        fwd, bwd = {}, {}
        for p, c, r, k, t in self.edges:
            if before and t > before:
                continue
            fwd.setdefault(p, []).append((c, k, r))
            bwd.setdefault(c, []).append((p, k, r))
        return fwd, bwd

    def descendants(self, root: str, before: str | None = None) -> dict[str, str]:
        """正向影响面：child -> **把它产出来的那条边的 kind**（用于预算）。

        ★ 语义必须是"这个制品由哪类动作产出"，而不是"路径上最贵的边"：
          否则一条 train 边的代价会沿链传播，把便宜的 eval/export 也记成 40 GPU 时。
        """
        fwd, _ = self._adj(before)
        seen: dict[str, str] = {}
        q = deque([root])
        while q:
            cur = q.popleft()
            for child, kind, _run in fwd.get(cur, []):
                if (child not in seen
                        or TRAIN_COST_HOURS.get(kind, 0) > TRAIN_COST_HOURS.get(seen[child], 0)):
                    seen[child] = kind
                    q.append(child)
        return seen

    def ancestors(self, node: str, before: str | None = None) -> dict[str, str]:
        _, bwd = self._adj(before)
        seen: dict[str, str] = {}
        q = deque([node])
        while q:
            cur = q.popleft()
            for parent, kind, _run in bwd.get(cur, []):
                if parent not in seen:
                    seen[parent] = kind
                    q.append(parent)
        return seen

    def divergence_point(self, a: str, b: str) -> dict:
        """两条血缘链的最近共同祖先 + 第一个输入不同的 run（归因的起点）。"""
        anc_a, anc_b = self.ancestors(a), self.ancestors(b)
        common = set(anc_a) & set(anc_b)
        return {"common_ancestors": sorted(common), "n_a": len(anc_a), "n_b": len(anc_b)}

    def retrain_plan(self, revoked: str, before: str | None = None) -> dict:
        """撤销一份数据要重训什么、花多少钱。"""
        desc = self.descendants(revoked, before)
        jobs = [(aid, kind) for aid, kind in desc.items()
                if kind in ("train", "finetune", "quantize")]
        hours = sum(TRAIN_COST_HOURS.get(k, 0) for _, k in jobs)
        # eval / export 也要重跑，但便宜得多，单独列
        cheap = [aid for aid, kind in desc.items() if kind in ("eval", "export")]
        return {"affected_models": sorted(a for a, _ in jobs),
                "n_models": len(jobs), "gpu_hours": hours,
                "cost_usd": round(hours * GPU_PRICE, 2),
                "cheap_reruns": len(cheap)}

八处关键设计决策：

  1. BlobStore.put 幂等：同一份数据被 30 个 run 引用只存一份，且 id 不可变。演示里 8 片 v2 + 9 片 v3 共 put 17 次，实际只存了 10 个 blob —— 内容寻址自带去重。
  2. DatasetRelease 把分片顺序放进哈希输入：顺序敏感的语料（课程式训练、SFT 拼接顺序）如果只做集合版本化，"集合相同"会被误判为"训练相同"。另外叶子节点做了一次域分离（H(b"leaf:", sha)），让"叶子哈希"与"内部节点哈希"属于不同空间 —— 否则攻击者可以用一个内部节点的值冒充叶子，构造出两份不同清单却同 root 的碰撞。
  3. diff 是哈希表比较，真实系统可换成 Merkle 路径比较得到 O(klogn)；关键是"变了多少"必须可计算，否则无法判断一次数据更新是小修还是大改。
  4. verify 不需要可信中心：清单 + 任意副本即可校验字节。这让"数据被就地改过"这件事可被发现 —— 第 4 节会把这条接进 CI。
  5. Registry.publish 对同名不同内容直接抛错，并把事故写进 incidents。这条约束是本节的核心纪律：内容不可变、逻辑版本只追加。错误信息里直接给出正确做法（发 v4），让纠错路径比违规路径更短。
  6. move_pointer 记录 (时间, 目标, 谁:为什么)，resolve(alias, at) 按时间点解析。复盘时"当时线上跑的是哪个版本"这个问题由此变成一个查表操作。
  7. Lineage.add 强制带 kind 与 at：kind 决定重训代价（train 40 小时 vs eval 0.2 小时），at 让互引（模型生成数据、数据再训模型）仍然可做因果查询 —— 演示第 6 段里，限定时间点后 m-v8 的祖先不再包含未来才出现的 m-v9。
  8. retrain_plan 把影响面换算成 GPU 时与美元。这是"撤销数据"从道德讨论变成工程决策的一步：你无法取消训练，只能支付重训；而重训的前提是这条链上的每个环节都能原样重放。

小结#

  • 模型是函数，版本号只是它的一个取值。 可归因的前提是有变更集 Δ 且能分解到 (D,C,H,E,Σ)；只知道 v7→v8 等于什么都不知道。
  • 三个命名空间必须分开：不可变的内容层（内容寻址）、只追加的逻辑版本层（一次发布一个 manifest）、可变的指针层（prod/champion，每次移动留审计并按时间可解析）。事故几乎都发生在这三层的边界上，最典型的是就地重写已发布版本。
  • 数据版本化的是"查询结果"而不是"文件"：正确的对象是一个含 code_ref、transform、tokenizer、分片哈希与 t_start/t_end 的 manifest；实现路径有全量快照 / 时间旅行表 / 内容寻址分片三种，按规模与引擎选。
  • Merkle 让"变了多少"可计算：相等判定 O(1)、差异定位 O(klogn)、可局部验证；但分片顺序若语义重要，必须进入哈希。
  • 数据删除与不可变性冲突：物理删除会改变分片哈希，本质是发布新版本；且删除不会让模型遗忘。正确表示是墓碑事件 + 血缘影响面 + 重训预算：$ \text{重训代价}=\sum_{\text{train-runs}} (\text{GPU 时}\times\text{单价}+\text{评测发布成本})$。
  • 模型侧要版本化的是一个"推理单元"：权重、tokenizer、prompt 模板、解码参数、引擎、后处理。改变输出但不改变权重的部件，恰恰是最常被漏记的，也是"回滚了权重却没回滚 prompt"这类事故的来源。
  • 血缘图的边必须带 kind 与时间戳：kind 让影响面换算成预算，时间戳让"模型生成数据、数据再训模型"的互引仍然可做因果查询。断链不可避免，但必须显式化为 external 节点，让查询能诚实地报告"这里有不可控依赖"。
  • 最有用的归因操作是"找分歧点"：两条血缘链上第一个输入集合不同的 run。它是纯集合运算，不需要重跑任何训练 —— 这正是第 1 节把输入制品记全的回报。

下一节：到这里，所有该记的东西都记了，所有引用关系也都连上了。但哈希对得上不等于数值对得上 —— 换一张卡、换一个 cuDNN 版本，同一份数据与代码会算出不同的数。第 3 节要处理环境的确定性：种子到底能固定什么、浮点为什么不可结合、以及"bitwise 复现"与"统计等价"之间那条真实的取舍线。
