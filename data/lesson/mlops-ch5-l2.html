预算与告警：把「别超支」写成可计算的控制器#

这一节要解决什么#

第 1 节把成本拆成了单位经济：每千请求 0.4286 元（分配口径）、每千 token 0.000230 元（消耗口径）。但有了尺子不等于有了闸门 —— 一个团队可以在三月把单位成本降到 0.0002，同时把总量翻三倍，账单照样涨。这一节处理的是总量这一侧：

  1. 谁有权花多少？ 预算不是财务的一个数，而是组织树上的一组约束：子节点配额之和加父节点预留不得超过父节点配额。本节算例里这棵树是超配的：33,500+2,000=35,500>30,000（超 18.3%）。
  2. 什么时候该响？ "花到 90% 再告警"是一个直觉，不是一个判据。本节把阈值写成代价模型的解，回测 4000 个月后最优阈值 τ∗=28,800 元（预算的 0.960 倍），此时误报率 38.25%、漏报率 8.48%。
  3. 为什么要提前买容量？买多少？ 这是报童问题：承诺 1.80 元/GPU·h、按需 2.50，最优承诺量 Q∗=883.43 GPU·h —— 低于需求的均值 1000。少买一单位只多付 0.70，多买一单位白付 1.80，所以最优解必然落在均值以下。
  4. 超支风险要预留多少？ 三种规则给出的数差 2 倍以上：均值 19,130.67 元、p95 21,351.42 元、历史最大值 37,713.60 元，而剩余预算只有 14,296.55 元。用最大值做预留会得到"永远不批"的结论。
  5. 真的超了，先动什么？ 软限制阶段的可逆动作排序（缓存/批处理/路由），以及哪些动作只允许出现在硬限制。

一句话：第 1 节给的是尺子，这一节给的是恒温器 —— 测量、比较、执行、再测量。

一、概念：预算是一组约束，不是一个数#

1.1 三层预算#

层 含义 谁的决策 时间尺度
承诺（committed） 已签的预留容量、包年包月、预留实例 采购/财务 月 ~ 年
额度（quota） 分给团队/项目/租户的可花上限 平台/技术负责人 周 ~ 月
实际（actual） 已发生的可归因消耗 系统自动计量 天 ~ 小时

三层的口径必须与第 1 节对齐：承诺层看分配口径，额度层通常看分配口径（否则额度之和小于账单，没人负责那部分），而优化决策看消耗口径。混用会得到"预算内却超支"的怪事：

归因口径租户∑​cused​​​≤B且账单口径calloc​​​>B

归因口径租户∑​cused​​​≤B且账单口径calloc​​​>B

这在数学上完全可能，因为 calloc​=cused​+(1−ρ)calloc​，空闲部分不属于任何租户。预算约束必须写明它约束的是哪个口径，否则第一次月末对账就是一场互相指责。

1.2 预算树的守恒约束#

预算天然是树：组织 → 团队 → 项目 → 实验。一条硬约束：

i∈children(v)∑​Qi​+Rv​≤Qv​∀v

其中 Rv​ 是父节点给自己留的机动（应急、跨团队共享池）。这不是形式主义：违反它意味着有人可以在不超自己额度的情况下让组织超支。本节算例的检测输出：

超配 org: 子节点合计 33,500 + 预留 2,000 = 35,500 > 配额 30,000（超 18.3%）
修正：把 ads 压到 3,500 元，或把 org 配额提到 35,500 元

两类修法对应两种组织选择：压子节点（承认总量封顶，让团队竞争）或抬父节点（承认业务需要，向上升级预算）。平台不该替组织做这个选择，但必须让这个选择无法被跳过 —— 这就是"守恒约束要在配置校验期报错，而不是在月末报错"。

二、为什么这样设计#

2.1 预算控制的目标不是"不超支"#

如果目标是不超支，最优策略是"什么都不批"，代价是业务停摆。真正的目标是以最小代价满足需求，也就是在"超支损失"与"过度保守的损失"之间取最小点。这就是为什么第 3 节把阈值写成代价模型，而不是写成"预算的 90%"。

形式化：设 C 是月末真实花费，C^ 是第 15 天的预测，B 是预算，

cost(τ)=Cfa​误报P(C^>τ,C≤B)​​+漏报E[(C−B)+1{C^≤τ}]​​+(1−r)告警但残余E[(C−B)+1{C^>τ}]​​

cost(τ)=Cfa​误报P(C^>τ,C≤B)​​+漏报E[(C−B)+1{C^≤τ}]​​+(1−r)告警但残余E[(C−B)+1{C^>τ}]​​

其中 Cfa​ 是一次误报的代价（人时 + 上下文切换），r 是提前告警能挽回的比例。这个式子里没有"预算的百分之几"这种参数 —— 阈值的位置由 Cfa​、r 与预测误差的联合分布共同决定。

2.2 为什么必须"预测"而不能只"对账"#

对账是月末动作，控制必须发生在月中。区别在于：

  • 对账回答"花了多少"（事后、精确、不可行动）；
  • 预测回答"还会花多少"（事前、有误差、可行动）。

工程上两者都需要，但告警只能挂在预测上。这带来一个不可避免的代价：预测有误差，于是阈值问题必然是一个两类错误问题，而不是一个"设定正确值"问题。实测的分布（回测 4000 个月）：P(超支)=67.77%，E[超支额]=4,653.40 元。

2.3 为什么点预测不够：预测误差比真值本身的方差还大#

先看四个点预测在同一份数据上的表现（第 15 天，真值 32,794.43）：

方法 月末预测 误差 第 15 天告警 首次告警 告警天数
均值外推 31,406.90 −4.23% 是 d8 23
EWMA 水平 31,393.25 −4.27% 是 d8 23
Holt 线性 29,087.61 −11.30% 否 d5 20
OLS 趋势 34,834.12 +6.22% 是 d8 23

四个方法之间的差就有 17.5% 的真值。更值得看的是方法越"高级"误差越大这件事：Holt 是唯一说"不会超支"的，而真相是超支 9.3%。原因在斜率估计：

  • OLS 斜率 +15.23（真值 +12.5），标准误 26.03 → ∣t∣=0.59；
  • 但理论标准误（用已知 σ=90）只有 5.38；
  • 一个 1555 元的尖峰（d8）把残差平方和抬高，于是标准误被抬到 26.03；
  • 对这份数据做鲁棒化（中位数 893，3⋅MAD=82 截尾）后：斜率 +11.72、标准误 5.16、∣t∣=2.27。

同一份数据，"趋势显著吗"有两个答案（0.59 vs 2.27）。 这不是统计学的花边，而是预算预测的第一个工程结论：异常值处理方式决定了你的趋势结论，而趋势结论决定了你要不要现在动手。 第 1 章的"追踪 schema"与第 3 章的"阈值对噪声的敏感性"在这里以同一个结构第三次出现。

三、怎么做#

3.1 四个预测器与它们各自的失效#

设观测到的日成本为 c1​..ct​：

  • 均值外推 C^=N⋅St​/t：无偏但方差大，且把一次性尖峰当成常态（本节算例的第 8 天尖峰被它线性放大到整月）；
  • EWMA 水平 ℓt​=αct​+(1−α)ℓt−1​，C^=St​+ℓt​(N−t)：抗单点尖峰，但完全看不见趋势；
  • Holt 线性 ℓt​=αct​+(1−α)(ℓt−1​+bt−1​)，bt​=β(ℓt​−ℓt−1​)+(1−β)bt−1​，C^=St​+∑h=1N−t​(ℓt​+hbt​)：跟趋势，但趋势项的方差被异常值放大，且外推 h 步会把斜率误差放大 h 倍；
  • OLS 趋势：等价于最小二乘拟合一条直线再外推，可给出斜率的标准误（这是它比前三个更有用的地方）。

选择规则可以写成一个可算的判据：

若 SE(β^​1​)∣β^​1​∣​<2 且异常值未被处理⇒不要用趋势外推，退回“均值 + 分布”

本节算例正是这个情形（∣t∣=0.59），而鲁棒化之后 ∣t∣=2.27。先做异常值判定，再选预测器，这个顺序不能反。

3.2 从点预测到分布：回测#

点预测只给一个数，而阈值决策需要 P(C^>τ) 与 P(C>B)。获得这两个量的唯一可靠办法是回测：从同一数据生成过程（或历史同期）模拟 M 个月，每个月中用同样的预测流程，得到 M 对 (C^,C)。

P^(超支)=M1​m=1∑M​1{Cm​>B},E^[(C−B)+]=M1​m∑​(Cm​−B)+

P^(超支)=M1​m=1∑M​1{Cm​>B},E^[(C−B)+]=M1​m∑​(Cm​−B)+

实测（M=4000）：67.77% 与 4,653.40 元。回测还顺手给出一个常被忽略的数：预测误差本身有多大。本例第 15 天的点预测误差在 −11.30% 到 +6.22% 之间 —— 也就是说，任何"精确到几百元"的月末预测都是幻觉。

3.4 承诺容量：一个标准报童问题#

C(Q)=ccom​Q+cod​E[(D−Q)+]

其中 μ^​future​ 由趋势拟合外推得到。三种 α 的实测：

三条规则都指向"现在就要动作"，但量级差 2 倍。 用最大值那条会得出一个数学上无法满足的要求，其组织后果是"预算控制退化为什么都不批" —— 这是预算体系最常见的自毁方式：把风险厌恶推到极致，就等于把决策权交给默认值。 可执行的做法是明示 α（例如 p95），并规定"当 p95 预留也不足时，触发软限制动作而不是拒绝新申请"。

  • "生效天数"是第二维：压缩 max_tokens 的收益/风险最低，但它 0.5 天就能生效 —— 它属于止损档（硬限制前的最后手段），不属于优化档；
  • 不可逆动作只留给硬限制。把"拒绝流量"放进软限制的候选集，等于允许一次误判直接造成用户可见的损失。

四、取舍与边界#

4.1 预算 ≠ 成本#

预算是对分配口径的约束，而真正的浪费常常藏在消耗口径里：一个团队可能用满了预算却只跑了 40% 的有效利用率（第 3 节的主题）。反过来，把预算当成本会奖励"把资源占住不用"的人 —— 因为占用本身不消耗预算。两个口径必须同时公开，一个用于约束，一个用于激励。

4.2 公共地悲剧与借用-归还#

共享集群上，"每个人都不超自己额度"不等于"总量不超"。两条可执行的机制：

  1. 借用登记：A 借用 B 的闲置配额必须显式记录，且 B 在需要时有权抢占（第 3 节的抢占判据）；
  2. 借用计价：借来的配额按略高于自身的价格计费（例如 1.2 倍），使"自己优化"永远比"借"便宜。

4.3 告警疲劳是被算出来的，不是被忍出来的#

本节算例里最优阈值下的误报率是 38.25% —— 听起来很高。但如果一个月只发一次告警，38% 的误报率意味着一个月大约 0.4 次误报，是可接受的；如果每天检查一次而每次都独立，就是 12 次误报。所以检查频次与阈值必须一起定（第 3 章第 3 节的响应率模型 R0​/(1+m/K) 在这里直接适用）。

4.4 跨期结转与承诺期锁定#

  • 不允许结转 → 月末突击花钱（可预测的浪费）；
  • 允许无限结转 → 预算失去约束力；
  • 承诺期越长折扣越大，但需求预测的不确定性随时间增长（σ∝T​），两者相乘给出一个最优承诺期限的存在性：本例 Q∗ 随 σ 上升而下降，所以"承诺一年"在 σ=400 的构型下比"承诺一月"要少买 13%。

4.5 边界：本节不做的事#

  • 不做采购谈判（ccom​ 是外生参数）；
  • 不判断模型质量（降级动作的质量风险必须由第 3 章的护栏指标验证，否则"路由到小模型"只是一个未经检验的省钱动作）；
  • 不处理多币种/税率/摊销会计（那是财务口径，与工程口径是两条线）。

"""
mlops-ch5-l2：预算与告警 —— 把「别超支」写成可计算的控制器。

⑧ 软限制动作的顺序表（单位收益 / 质量风险 / 生效时间 / 可逆性）

运行：python3 /tmp/mlops_ch5_l2.py
⚠️ 全部为合成数据（random，固定种子）。价格与代价参数是显式假设，不是实测值。

P_SPIKE = 2                # 每月两次事故/大实验尖峰（日期与幅度随机）
CUT_DAY = 15               # 在第 15 天做预测

C_FA = 2500.0              # 一次误报的代价（人时 + 上下文切换）
RECOVER = 0.80             # 真超支且提前告警时能挽回的比例
BOOT = 4000                # 回测月数

C_ONDEMAND = 2.50          # 按需价

ACTIONS = [                # (名字, 能省的比例, 质量风险 0-1, 生效天数, 可逆?)
    ("前缀/结果缓存", 0.09, 0.02, 1.0, True),

def norm_pdf(x: float) -> float:
    return math.exp(-0.5 * x * x) / math.sqrt(2.0 * math.pi)


def norm_cdf(x: float) -> float:
    return 0.5 * (1.0 + math.erf(x / math.sqrt(2.0)))


def norm_ppf(p: float) -> float:
    lo, hi = -40.0, 40.0
    for _ in range(200):
        mid = (lo + hi) / 2.0
        if norm_cdf(mid) < p:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2.0


def cost_newsvendor(q: float, mu: float, sd: float) -> tuple[float, float]:
    """C(q) = c_com·q + c_od·E[(D-q)^+]，返回 (期望成本, 期望缺口)。"""
    z = (q - mu) / sd
    gap = sd * norm_pdf(z) + (mu - q) * (1.0 - norm_cdf(z))
    return C_COMMIT * q + C_ONDEMAND * gap, gap


# ==================================================================== [0] 自检
def self_check() -> None:
    for p in (0.001, 0.28, 0.5, 0.9, 0.999):
        assert abs(norm_cdf(norm_ppf(p)) - p) < 1e-12
    cu, co = C_ONDEMAND - C_COMMIT, C_COMMIT
    q_star = MU_D + SD_D * norm_ppf(cu / (cu + co))
    best = min(((cost_newsvendor(q, MU_D, SD_D)[0], q) for q in
                [500.0 + 0.001 * i for i in range(1_100_001)]))
    assert abs(best[1] - q_star) < 0.5, (best[1], q_star)
    g0 = cost_newsvendor(MU_D, MU_D, SD_D)[1]
    assert abs(g0 - SD_D * norm_pdf(0.0)) < 1e-9
    print("[0] 自检：norm_ppf/norm_cdf 互逆 ✅｜报童数值最优 == 解析解 ✅"
          f"（q*={q_star:.2f}，网格最优 {best[1]:.2f}）")
    print(f"    临界分位 Cu/(Cu+Co) = {cu:.2f}/({cu:.2f}+{co:.2f}) = {cu/(cu+co):.4f}"
          f" → z*={norm_ppf(cu/(cu+co)):+.4f}（< 0，所以最优承诺量低于均值）")
    print(f"    缺口恒等式：E[(D-μ)^+] = σ·φ(0) = {g0:.4f} GPU·h ✅")


# ==================================================================== [1] 日成本
def gen_days(rng: random.Random) -> tuple[list[float], dict]:
    """月与月之间的差别来自三处：基线水平、增长斜率、两次随机尖峰。"""
    base = rng.gauss(BASE, 180.0)
    trend = rng.gauss(TREND, 9.0)
    spikes: dict[int, float] = {}
    for _ in range(P_SPIKE):
        day = rng.randint(5, DAYS - 2)
        spikes[day] = spikes.get(day, 0.0) + abs(rng.gauss(1800.0, 600.0))
    days = [round(max(0.0, base + trend * t + rng.gauss(0.0, SIGMA)
                      + spikes.get(t, 0.0)), 2) for t in range(1, DAYS + 1)]
    return days, {"base": base, "trend": trend, "spikes": spikes}


# ==================================================================== [2] 预测器
def forecast(obs: list[float], n_total: int = DAYS) -> dict[str, float]:
    d = len(obs)
    spent = sum(obs)
    out = {}
    out["均值外推"] = spent / d * n_total
    a = 0.3
    lvl = obs[0]
    for x in obs[1:]:
        lvl = a * x + (1 - a) * lvl
    out["EWMA 水平"] = spent + lvl * (n_total - d)
    a, b = 0.4, 0.2
    lvl, tr = obs[0], obs[1] - obs[0]
    for x in obs[1:]:
        prev = lvl
        lvl = a * x + (1 - a) * (lvl + tr)
        tr = b * (lvl - prev) + (1 - b) * tr
    out["Holt 线性"] = spent + sum(lvl + h * tr for h in range(1, n_total - d + 1))
    b0, b1 = ols(obs)
    out["OLS 趋势"] = spent + sum(b0 + b1 * t for t in range(d + 1, n_total + 1))
    return out


def ols(obs: list[float]) -> tuple[float, float]:
    d = len(obs)
    xs = list(range(1, d + 1))
    mx, my = sum(xs) / d, sum(obs) / d
    sxx = sum((x - mx) ** 2 for x in xs)
    b1 = sum((x - mx) * (y - my) for x, y in zip(xs, obs)) / sxx
    return my - b1 * mx, b1


def alert_profile(days: list[float], budget: float) -> dict[str, dict]:
    """每种方法：首次告警日 / 告警天数 / 第 15 天后是否仍告警。"""
    keys = ("均值外推", "EWMA 水平", "Holt 线性", "OLS 趋势")
    prof = {k: {"first": 0, "n": 0, "late": False} for k in keys}
    prof["剩余天数法"] = {"first": 0, "n": 0, "late": False}
    for d in range(5, DAYS + 1):
        f = forecast(days[:d])
        for k in keys:
            if f[k] > budget:
                prof[k]["n"] += 1
                if prof[k]["first"] == 0:
                    prof[k]["first"] = d
                if d >= CUT_DAY:
                    prof[k]["late"] = True
        spent = sum(days[:d])
        burn = spent / d
        if (budget - spent) / burn < DAYS - d:
            prof["剩余天数法"]["n"] += 1
            if prof["剩余天数法"]["first"] == 0:
                prof["剩余天数法"]["first"] = d
            if d >= CUT_DAY:
                prof["剩余天数法"]["late"] = True
    return prof


# ==================================================================== [3] 阈值
def backtest_pairs(predictor: str, m: int = BOOT, seed: int = SEED + 1) -> list[tuple[float, float]]:
    """从同一数据生成过程回测 m 个月，得到 (真实月末总额, 第 15 天预测) 对。"""
    rng = random.Random(seed)
    pairs = []
    for _ in range(m):
        days, _ = gen_days(rng)
        pairs.append((sum(days), forecast(days[:CUT_DAY])[predictor]))
    return pairs


def threshold_search(pairs: list[tuple[float, float]], budget: float) -> dict:
    def cost(tau: float) -> float:
        c = 0.0
        for truth, fc in pairs:
            if fc > tau and truth <= budget:
                c += C_FA
            elif fc <= tau and truth > budget:
                c += truth - budget
            elif fc > tau and truth > budget:
                c += (1.0 - RECOVER) * (truth - budget)
        return c / len(pairs)

    grid = [budget * (0.70 + 0.01 * i) for i in range(61)]
    best = min(((cost(t), t) for t in grid))
    rows = []
    sel = sorted(set([grid[0], budget * 0.85, budget * 0.90, budget * 0.95, budget,
                      budget * 1.05, budget * 1.10, grid[-1], best[1]]))
    for tau in sel:
        fa = sum(1 for tr, fc in pairs if fc > tau and tr <= budget)
        miss = sum(1 for tr, fc in pairs if fc <= tau and tr > budget)
        hit = sum(1 for tr, fc in pairs if fc > tau and tr > budget)
        n_safe = sum(1 for tr, _ in pairs if tr <= budget)
        n_over = len(pairs) - n_safe
        rows.append((tau, cost(tau), fa / max(1, n_safe), miss / max(1, n_over),
                     hit / max(1, fa + hit)))
    rows.sort()
    return {"best": best,
            "p_over": sum(1 for tr, _ in pairs if tr > budget) / len(pairs),
            "e_over": sum(max(0.0, tr - budget) for tr, _ in pairs) / len(pairs),
            "rows": rows}


# ==================================================================== [4] 配额
def quota_audit(nodes: dict[str, dict], root: str = "org") -> list[str]:
    msgs = []

    def walk(name: str) -> float:
        nd = nodes[name]
        used = nd["quota"] if not nd["children"] else sum(walk(c) for c in nd["children"])
        if nd["children"] and used + nd["reserve"] > nd["quota"] + 1e-9:
            msgs.append(f"  超配 {name}: 子节点合计 {used:,.0f} + 预留 {nd['reserve']:,.0f}"
                        f" = {used+nd['reserve']:,.0f} > 配额 {nd['quota']:,.0f}"
                        f"（超 {(used+nd['reserve']-nd['quota'])/nd['quota']*100:.1f}%）")
        return used
    walk(root)
    return msgs

小结#

  • 预算是一组约束，不是财政的一个数：三层（承诺/额度/实际）+ 树的守恒约束 ∑Qi​+Rv​≤Qv​。本节算例超配 18.3%（35,500>30,000），必须在配置校验期报错。
  • 预算约束必须写明口径：∑cused​≤B 与 calloc​≤B 是两条不同的约束，混用会导致"预算内却超支"。
  • 告警只能挂在预测上，而预测必然有误差，因此阈值问题是一个两类错误问题：回测 4000 个月，P(超支)=67.77%，E[超支额]=4,653.40 元。
  • 点预测会骗人，且方法越复杂不一定越好：四法差 17.5%；Holt 是唯一说"不超支"的（29,087.61），真值 32,794.43。
  • 异常值决定趋势结论：非鲁棒 ∣t∣=0.59 vs 鲁棒 ∣t∣=2.27（中位数 893，3⋅MAD=82 截尾）。先判定异常值，再选预测器。
  • 阈值是代价模型的解：τ∗=28,800 元 =0.960B，α=38.25%、β=8.48%、代价 1,319.71 元；曲线在最优附近很平（0.95B∼1.00B 只差 2.6%）。
  • d∗ 判据不需要模型：d∗=(B−St​)/bt​=13.66<15 天。它应该与预测型告警并联，因为它的失效方式不同。
  • 承诺容量是报童问题：F(Q∗)=Cu​/(Cu​+Co​)=0.2800 → Q∗=883.43<μ=1000。多承诺一单位白付 1.80，缺一单位只多付 0.70；σ 翻倍 → Q∗ 降到 766.86。

  • 预留必须对着分位数：均值 19,130.67、p95 21,351.42、最大值 37,713.60 元，而剩余预算 14,296.55 元。用最大值等于"什么都不批"。
