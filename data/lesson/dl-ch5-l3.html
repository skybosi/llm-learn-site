序列模型应用#

掌握了 RNN、LSTM、GRU 之后，这一课我们把视角拉高，俯瞰序列模型到底能解决哪些问题，以及解决它们时有哪些"套路"。你会看到：千变万化的 NLP 任务，其实都可以归结为几种标准的输入输出结构。理解了这几种结构，后面做实战就有了地图。

一、概念讲解#

1. 四类典型任务#

按照"输入是序列、输出是什么"，序列任务大致分成四类：

  1. 序列分类（sequence classification）：输入一条序列，输出一个类别。典型：情感分析、垃圾邮件识别、新闻分类。对应"多对一"结构。
  2. 序列标注（sequence labeling）：输入一条序列，输出同样长度的一串标签。典型：分词、词性标注、命名实体识别（NER）。对应"多对多等长"结构。
  3. 序列生成（sequence generation）：给定一个起点，逐字逐词地生成新序列。典型：文本续写、音乐生成、聊天回复。对应"一对多"或自回归结构。
  4. 序列到序列（sequence-to-sequence, seq2seq）：输入一条序列，输出另一条长度可能不同的序列。典型：机器翻译、文本摘要、问答。对应 encoder-decoder 结构。

2. 双向 RNN：让模型"看到后面"#

普通 RNN 只能从左往右读，判断某个词时看不到它后面的内容。但很多任务里，后面的信息同样重要——比如判断"苹果"是水果还是公司，要看后面是不是出现了"发布手机"。

双向 RNN（Bidirectional RNN）解决这个问题：用两条独立的循环网络，一条从左到右读、一条从右到左读，然后把每个时间步的两个隐藏状态拼起来。这样第 t 步的输出既包含上文也包含下文。它在序列分类和序列标注里几乎是标配。PyTorch 里给 nn.LSTM/nn.GRU 加 bidirectional=True 即可，注意此时输出的隐藏维度会翻倍。

3. Encoder–Decoder 架构#

当输入和输出长度不一时（如翻译），单条 RNN 不够用，需要拆成两段：

  • 编码器（Encoder）：把整条输入序列读进去，压缩成一个固定长度的"语义向量"（通常取最后一步的隐藏状态）；
  • 解码器（Decoder）：以这个语义向量为起点，一步步生成输出序列，每生成一个词，又把它当作下一步的输入。

这就是 seq2seq 的基本骨架，机器翻译、摘要、对话系统都建立在它之上。它的局限是"固定长度语义向量"会成为信息瓶颈——输入很长时，一个向量装不下所有信息，于是后来引入了注意力机制（Attention），让解码器在每步都能"回看"编码器的所有位置，动态挑选该关注的部分。注意力机制是 Transformer 的前身，我们会在后续课程里专门展开。

4. 结构选择的速查表#

面对一个新任务，可以先问自己三个问题：输入是序列吗？输出是序列吗？输入输出等长吗？ 然后对号入座：

  • 输入是序列、输出是类别 → 序列分类（RNN + 全连接，常配双向）；
  • 输入是序列、输出等长标签 → 序列标注（双向 RNN，逐时间步分类）；
  • 输出是序列、输入很短 → 序列生成（自回归解码）；
  • 输入输出都是序列且不等长 → seq2seq（Encoder–Decoder）。

这套"对号入座"的能力，比背任何单个网络细节都更有用。

二、可运行代码示例#

下面用 PyTorch 把"双向 LSTM 做序列标注"完整实现一遍：给定一句用数字拼成的"句子"，预测每个位置的词性标签。我们用随机数据演示结构和训练流程，重点是让你看清双向 + 逐时间步分类是怎么搭起来的。

import torch
import torch.nn as nn

torch.manual_seed(0)

vocab_size, tag_size, hidden = 20, 4, 8   # 词表 20、标签 4 类、隐藏维 8

class BiLSTM_Tagger(nn.Module):
    def __init__(self):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, 6)
        # 双向 LSTM：输出隐藏维度会翻倍成 hidden * 2
        self.lstm = nn.LSTM(6, hidden, batch_first=True, bidirectional=True)
        self.fc = nn.Linear(hidden * 2, tag_size)   # 注意 *2

    def forward(self, x):
        out, _ = self.lstm(self.embed(x))   # (batch, seq_len, hidden*2)
        return self.fc(out)                 # 逐时间步打标签 (batch, seq_len, tag_size)

model = BiLSTM_Tagger()
loss_fn = nn.CrossEntropyLoss()
opt = torch.optim.Adam(model.parameters(), lr=0.01)

# 随机构造训练数据：8 条长度 6 的"句子"，每个位置随机打一个标签
x = torch.randint(0, vocab_size, (8, 6))
y = torch.randint(0, tag_size, (8, 6))

for step in range(400):
    logits = model(x)                     # (8, 6, 4)
    loss = loss_fn(logits.reshape(-1, tag_size), y.reshape(-1))
    opt.zero_grad()
    loss.backward()
    opt.step()

with torch.no_grad():
    pred = model(x).argmax(-1)
    acc = (pred == y).float().mean().item()

print(f"最终损失：{loss.item():.4f}，逐位置准确率：{acc:.3f}")
print("预测标签（前 3 条）：\n", pred[:3].tolist())
print("真实标签（前 3 条）：\n", y[:3].tolist())

运行后你会发现模型很快就能"背下"这些随机标签——因为数据是随机造的，没有规律可学，模型只是强行记忆。这正好提醒我们：能跑通结构只是第一步，真实效果要靠有规律的真实数据来检验。下一章我们会用真实的中文/英文情感数据，把这里学到的结构真正派上用场。

三、练习#

  1. 把 bidirectional=True 改成 False，注意 self.fc 的输入维度要从 hidden * 2 改成 hidden，然后重新训练，观察准确率是否变化，并说说双向带来的代价。
  2. 把 LSTM 换成 GRU，实现一个双向 GRU 标注器，比较参数量和训练速度。
  3. 思考：序列标注任务的损失函数为什么要对每个时间步都计算交叉熵？如果只对最后一步算，会变成什么任务？
  4. 用自己的话解释：为什么 encoder-decoder 的"固定长度语义向量"会成为一个瓶颈？注意力机制是如何缓解这个瓶颈的？
