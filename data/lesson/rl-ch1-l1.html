智能体与环境#

你在《机器学习基础》里学过的监督学习，回答的是"给定输入，输出是什么"；而强化学习（Reinforcement Learning, RL）回答的是一个完全不同的问题："在一连串的决策里，我现在该做什么，才能让长期累积的好处最大？" 它不给你标准答案，只给你一个评价信号——"做得好/做得差"。这一课我们不碰任何算法，先把强化学习最基本的一台"机器"——智能体与环境——拆开看清楚。后面所有的价值函数、贝尔曼方程、动态规划，都建立在这台机器之上。

一、概念讲解#

1. 一台不断"对话"的机器：交互循环#

强化学习的主角有两个：智能体（agent） 和 环境（environment）。它们在离散的时间步（time step） t = 0, 1, 2, … 上反复进行一场对话：

  1. 智能体观察环境当前所处的状态 S_t；
  2. 智能体据此选择一个动作 A_t；
  3. 环境收到动作后，转移到一个新状态 S_{t+1}，并返回一个奖励 R_{t+1}；
  4. 时间步推进，回到第 1 步。

这一轮交互产生的序列叫轨迹（trajectory）：

S₀, A₀, R₁, S₁, A₁, R₂, S₂, A₂, R₃, …

注意下标的约定：动作 A_t 是在状态 S_t 处做出的决策；它的"后果"是下一个时间步的奖励 R_{t+1} 和状态 S_{t+1}。这个 t+1 不是笔误，而是全书的统一记号——奖励和下一状态，都是动作的延迟结果。

2. 三个信号：状态、动作、奖励#

把这场对话里的信息流拆成三个角色各异的信号，是理解强化学习的第一块敲门砖：

信号 谁来发出 含义 类比
状态 S_t 环境 环境此刻的"处境快照" 棋盘上当前所有棋子的位置
动作 A_t 智能体 智能体此刻的选择 我走哪一步棋
奖励 R_{t+1} 环境 对上一个动作的即时打分 走完这步后局面变好还是变坏

关键区别在于：状态和动作是"描述"，奖励才是"评价"。环境告诉你"现在是什么样"（状态）、"你选了啥"（动作的反馈），但只有奖励告诉你"你选得对不对"。智能体的唯一目标，就是让这条奖励之流在长期上尽可能大——智能体不知道正确动作是什么，只知道它做得好不好。这恰恰是强化学习与监督学习的本质分野：监督学习给你"标签"（正确答案），强化学习只给你"打分"（好坏程度）。

3. 环境是"黑箱"：智能体唯一能控制的是动作#

对智能体而言，环境是一个黑箱：它无法直接决定环境跳转到哪个状态，也无法规定环境给多少奖励——它只能决定"我选哪个动作"。环境如何响应，由环境自己的动力学决定。这种"你只能控制自己的选择，后果由外部规律决定"的结构，正是现实中几乎所有决策问题的共同骨架：

  • 下棋：你是智能体，棋盘规则是对手是环境，输赢是奖励；
  • 自动驾驶：车辆是智能体，道路与其他车辆是环境，安全到达是奖励；
  • 推荐系统：算法是智能体，用户是环境，点击/停留时长是奖励。

理解"我只能控制动作"这一点，能让你在后续看到价值函数、策略这些概念时，始终清楚它们的出发点：在"不能控制环境"的约束下，如何选择动作序列以最大化长期奖励。

4. 探索与利用：强化学习独有的两难#

因为智能体拿不到标准答案，它必须自己试。这就引出一个监督学习里没有的经典矛盾——探索（exploration）与利用（exploitation）：

  • 利用：选择当前已知的、回报最好的动作，落袋为安；
  • 探索：去尝试那些还没试过、或信息不足的动作，以期发现更好的选择。

只利用不探索，会卡在局部最优；只探索不利用，则永远拿不到实际回报。这个权衡贯穿全部强化学习算法（从贪心策略到 epsilon-greedy 再到上置信界 UCB），第 5 章讲 Q-learning 时会正式处理它。现在你只需要记住这句话：探索-利用权衡，是"靠试错学习"这件事与生俱来的代价。

5. 与监督学习、无监督学习的并排对照#

为了把强化学习的位置钉死，把三种学习范式放在一起：

范式 数据形态 学什么 反馈时机
监督学习 (输入, 标签) 成对给出 从输入到标签的映射 每个样本即时反馈
无监督学习 只有输入，无标签 数据内在结构（聚类、降维） 无外部评价
强化学习 交互产生的 (状态, 动作, 奖励) 流 在状态下选动作的策略 延迟、且只给好坏打分

强化学习最独特的两点：反馈是延迟的（这一手棋的后果可能几十步后才显现），以及反馈是评价性的而非指导性的（只说"总分 -5"，不说"这步该走马"）。

6. 预告：用一个五元组把这一切说精确#

上面全是直觉。但"知其所以然"需要把"环境黑箱"变成一个可计算的对象。第 3 课会引入马尔可夫决策过程（MDP），用一个五元组 (S, A, P, R, γ) 精确刻画环境：S 是状态集、A 是动作集、P 是"给定状态和动作后下一状态与奖励的概率分布"、R 是奖励、γ 是折扣因子。有了这个五元组，第 2 章的贝尔曼方程才能成立。本课你先记住它的存在即可。

二、可运行代码示例#

下面用 NumPy 亲手搭一个"最小环境"——一条有 5 个格子的一维线世界，并让一个随机智能体在上面跑出一条轨迹，把"状态 → 动作 → 奖励 → 新状态"的循环直接打印出来看。

import numpy as np

rng = np.random.default_rng(0)

class LineWorld:
    """一维线世界环境：5 个格子 0..4，最右端 4 是目标。

    智能体每步可选 left(-1) 或 right(+1)。到达目标得 +1 并终止；
    其余移动得 0；撞到左边界(0)仍停留原地、得 0。"""
    def __init__(self):
        self.goal = 4          # 目标格
        self.n_states = 5

    def reset(self):
        """环境回到起点（格子 0），返回初始状态。"""
        return 0

    def step(self, state, action):
        """执行动作，返回 (下一状态, 奖励, 是否终止)。

        action = -1 表示向左，+1 表示向右。"""
        # 动作 -> 位移：这里直接约定 -1/+1
        next_state = state + action
        # 边界处理：不能越出 [0, 4]
        next_state = max(0, min(self.n_states - 1, next_state))
        # 到达目标：+1 并终止；否则 0 且继续
        if next_state == self.goal:
            return next_state, 1.0, True
        return next_state, 0.0, False

def random_agent(state, env):
    """随机策略：向左/向右各 50% 概率，是"只会试错"的最朴素智能体。"""
    return int(rng.choice([-1, 1]))

# 交互循环：把第 1 节讲的状态/动作/奖励/新状态跑出来
env = LineWorld()
state = env.reset()
trajectory = []                      # 记录 (S_t, A_t, R_{t+1}, S_{t+1})
done = False
max_steps = 20                       # 防呆：最多走 20 步

for t in range(max_steps):
    action = random_agent(state, env)         # 智能体选动作 A_t
    next_state, reward, done = env.step(state, action)  # 环境给出 R_{t+1}, S_{t+1}
    trajectory.append((state, action, reward, next_state))
    state = next_state
    if done:
        break

# 打印轨迹，注意下标约定：R 和 S' 都是动作 A 的"下一时刻"结果
print(" t |  S_t  A_t   R_{t+1}  S_{t+1}")
print("---|--------------------------")
for t, (s, a, r, s_next) in enumerate(trajectory):
    print(f" {t} |   {s}   {a:+d}    {r:.0f}      {s_next}")
print(f"\n总步数 = {len(trajectory)}，最终状态 = {state}")

一次典型运行会输出类似：

 t |  S_t  A_t   R_{t+1}  S_{t+1}
---|--------------------------
 0 |   0   +1    0      1
 1 |   1   +1    0      2
 2 |   2   -1    0      1
 3 |   1   -1    0      0
 4 |   0   +1    0      1
 5 |   1   +1    0      2
 6 |   2   +1    0      3
 7 |   3   +1    1      4

总步数 = 8，最终状态 = 4

盯着这张表看三个要点：① R_{t+1} 和 S_{t+1} 总是由上一行的 A_t 决定；② 奖励 0 占了绝大多数，只有踩到目标那一刻才是 1——这就是"延迟奖励"的直观体现；③ 随机智能体走了 8 步才碰运气到终点，这暴露了它"只会试错、不会学习"的局限，也正是后面所有算法要解决的问题。

三、练习#

  1. 把 random_agent 改成一个"贪心向右"的智能体（永远返回 +1）。它从格子 0 出发，几步能到目标？这种纯利用的策略在这个环境里为什么反而最优？在什么环境下它会栽跟头？
  2. 把 LineWorld 的目标格改到格子 1，重跑随机智能体。轨迹长度是变长还是变短？这说明了"目标位置"如何改变了任务的难度。
  3. 给 step 加一点随机性：以 10% 概率无视动作、随机左移或右移（模拟"打滑"）。再跑轨迹，观察"同样的动作不再有同样的后果"，说说这为什么对应现实中"环境不可完全控制"。
  4. 思考题：在监督学习中，"标签"和强化学习中的"奖励"都来自外部。为什么说它们是两类根本不同的信号？请各用一句话概括两者在"告诉学习者什么信息"上的差异。
