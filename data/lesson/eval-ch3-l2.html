这一节要解决什么#

第 1 节讲"离线为什么会与线上脱节"。这一节讲线上该怎么测，以及线上测量自身的陷阱。核心结论会在一开始就写明，因为它是本节所有细节的归宿：

在固定样本量下的假设检验，与"随时可以看结果并提前停止"的决策方式，在数学上不相容。你要么预先承诺样本量，要么为"随时能停"付出可量化的效率损失，没有第三种选择。

围绕这个结论，本节依次处理五个问题：

  1. 随机化单元：分流按什么单位随机？用户、会话还是请求？选错了会有什么后果（溢出效应、体验不一致）？
  2. 样本量：怎么从"我想检测的最小效应"反推样本量？公式里每一项对应什么代价？
  3. 多重比较：同时看 20 个指标、5 个分群、4 个变体，"至少有一个显著"的概率是多少？两种校正（族错误率 / 错误发现率）的取舍。
  4. 辛普森悖论：为什么总体涨、每个子群都跌？它和"分群报告"是什么关系？什么时候它是真实伤害、什么时候只是加权假象？
  5. 序贯检验与偷看问题：连续偷看如何把 5% 抬到 30%+；三种补救（α-消耗、组序贯、always-valid 置信区间）的统计代价与适用场景。

一、随机化单元：先决定"把什么随机化"#

A/B 实验的最小正确形式是：把单元随机分到处理组与对照组，然后比较同一指标在两组上的差异。第一件事是选单元。

单元 适用 风险
用户（设备/账号） 大多数产品改动；用户体验有连续性 需要稳定的用户 ID；跨设备用户被拆开
会话 一次性任务、无状态交互 同一用户在不同会话被分到不同组 → 体验不一致、学习效应
请求 纯服务端优化（延迟、缓存策略） 同一用户在同一会话里看到混合策略；对"用户级"指标无解释力
地理/时间片 无法做用户级分流（如定价、市场活动） 混杂严重（地区差异、时间趋势），需要 DID/合成控制等更强设计

为什么这样设计：随机化的作用是断开处理分配与所有潜在混杂变量的关联。它不是"公平地分流量"，而是"让两组的差异只能来自处理"。因此选择单元的标准是：在这个单元上，处理的效果是可加的、且不存在单元之间的相互干扰。

溢出效应（interference / spillover）是单元选择最核心的技术约束。具体形式：

  • 社交溢出：用户 A 在实验组、用户 B 在对照组，但两人互相看到对方的内容 → 对照组被污染。
  • 资源溢出：实验组的重排占用了共享的推理资源，导致对照组的延迟上升 → 对照组"受伤"，差异被高估。
  • 市场溢出：实验组的行为改变了库存/价格，进而改变对照组面对的环境。

检测手段：分桶随机化 + 桶内一致性。把用户按哈希分成若干"桶"（cluster，比如按社区/公司/地理单元），桶内同组，桶间随机。这样可以把溢出限制在桶内，代价是有效样本量下降（桶内相关 → 设计效应）：

neff​=1+(mˉ−1)ρn​

其中 mˉ 是平均桶大小、ρ 是组内相关系数（ICC）。这个公式有个重要含义：如果 ρ 很大，增加桶内样本几乎不增加信息量，必须增加桶数。 这也是为什么社交类产品做实验时"用户数"经常是幻觉。

二、样本量与 MDE：公式里的每一项都是代价#

最常用的样本量公式（两组、比例指标、双侧检验、等样本）：

nper arm​≈Δ22σ2(z1−α/2​+z1−β​)2​

对比例指标 σ2=p(1−p)，于是：

nper arm​≈Δ22p(1−p)(z1−α/2​+z1−β​)2​

常用值：α=0.05⇒z1−α/2​=1.96，功效 1−β=0.80⇒z0.8​=0.84，两者和是 2.80，因此 2×2.802≈15.68：

nper arm​≈Δ215.68p(1−p)​

每一项都是一个可以换算成钱的旋钮：

  • α 从 0.05 降到 0.01，z 从 1.96 升到 2.58，n 增加约 ((2.58+0.84)/(1.96+0.84))2≈1.49 倍。更严格的错误控制直接换流量。
  • 功效从 0.80 提到 0.95，zβ​ 从 0.84 到 1.64，n 增加 ((1.96+1.64)/(1.96+0.84))2≈1.65 倍。
  • Δ 减半，n 变四倍。"想检测更小的效应"是四倍级的成本增长，这是实验平台最常见的预算错配来源。
  • p(1−p) 在 p=0.5 时最大。低基线率指标（如违规率 1%）的 p(1−p) 小，但 Δ 通常也小（相对提升 10% 就是 0.1 个百分点），实际需要的样本量往往更大。

必须同时报 MDE。一个实验做完不显著，有两种解释："没有效果"和"样本量不够，检测不出这个大小的效果"。只有给出 MDE（在给定 α,β,n 下能检出的最小效应），读者才能区分这两者。不报 MDE 的"不显著"是不合格的结论。

另外注意：MDE 与观测到的效应量不同。MDE 是设计参数（事前），观测效应是结果（事后）。决不能在实验结束后用观测效应反推"我们本来能检测到什么"——这是经典的事后功效谬误。

三、多重比较：为什么"多看几个指标"是危险的#

做 m 次独立的 α=0.05 检验，至少有一次假阳性的概率是：

FWER=1−(1−α)m

m=20 时是 64%；m=5 时是 23%。而现实中的实验通常同时看：主指标 + 5 个护栏 + 3 个分群 + 2 个次要指标 = 十几个检验，且变体越多越糟。

两种处理哲学：

（a）族错误率（FWER）控制：控制"至少一次假阳性"的概率。

  • Bonferroni：用 α/m 作为阈值。简单、保守。当 m 大且检验相关时过于保守。
  • Holm：按 p 值升序，第 k 个用 α/(m−k+1)，比 Bonferroni 略强。推荐作为默认。

（b）错误发现率（FDR）控制：控制"被判定为显著的结论里假阳性所占比例"。

  • Benjamini-Hochberg：把 p 值升序排列 p(1)​≤⋯≤p(m)​，找到最大的 k 使 p(k)​≤mk​q，拒绝前 k 个。q=0.05 表示"拒绝的结论里预期 5% 是假的"。

怎么选：

  • 决策类检验（"是否发布""护栏是否被突破"）用 FWER：这里每一个假阳性都有真实代价，且结论数很少。
  • 筛选类检验（"哪些分群值得进一步看"）用 FDR：你预期大多数假设是错的，需要更高的发现能力，且后续会有验证。

为什么这样设计：多重比较校正的本质是"为搜索空间付税"。你搜得越广，单个结论需要的证据就越强。不接受这个税，就等价于承认"我报的显著性是不可信的"。

怎么做（工程要点）：

  1. 实验开始前把指标清单写进文档，分为"主指标 / 护栏 / 探索指标"三类。只有前两类进入校正族。
  2. 探索指标的所有结论必须标注"未校正，仅用于生成假设"。
  3. 分群分析必须有下限：样本量低于阈值（比如每组 200）的分群不报 p 值，只报点估计和样本量。
  4. 报效应量 + 置信区间，不要只报 p 值。p=0.049 与 p=0.051 没有实质区别，把它们当成"有/无"的分界是本末倒置。

四、辛普森悖论：总体涨、每个子群都跌#

辛普森悖论的经典形式：把数据按某个变量分层后，每一层的效应符号都与合并后的符号相反。

构造它的最小条件（以两组、一个分层变量为例）：设分层变量 S，处理组与对照组在 S 上的分布不同，且 S 与结果相关。具体地：

Δpooled​=s∑​ws​Δs​+组成效应s∑​(wstreat​−wsctrl​)Yˉsctrl​​​

其中 ws​ 是某个合并权重（比如两组平均）。当组成效应与 Δs​ 符号相反且绝对值更大时，合并结果翻转。

在真实 A/B 实验里，它有三个常见来源：

  1. 分流不均衡（最危险）。随机化出错或分流键有偏，导致两组在某个预测性强的变量上分布不同。这是真正的实验缺陷，必须修分流而不是"分层报告了事"。
  2. 触达提前/滞后。实验组的改动让用户更早（或更晚）进入某个后续环节，使得"进入该环节的用户构成"在两组间不同。这是一种处理后变量（post-treatment variable），对它分层会引入选择偏差。
  3. 指标定义嵌套。比如"人均订单数"的分母是"活跃用户"，而实验组让更多人变成活跃用户 → 两组的"活跃用户"不是同一批人。

关键判据（区分"加权假象"与"真实伤害"）：

情形 分群分布是否相同 处理 结论
分层变量是处理前变量（如用户等级） 两组分布相同 分层报告 + 加权 总体与分群一致，无悖论
分层变量是处理前变量，但两组分布不同 分布不同 先修分流；再分层报告 总体结论不可信
分层变量是处理后变量 — 不要对它分层（会引入选择偏差） 只报总体 + 明确的机制分析
某子群真的受伤，但被大子群的收益掩盖 分布相同 这是加权悖论不是悖论：总体涨是真的，子群跌也是真的 需要业务判断：该子群的损失可接受吗？

最后一行是本节最需要说清的一点："总体涨、子群跌"本身不是统计错误，它是多目标冲突的呈现。 是否上线取决于价值判断，不取决于统计。第 3 节的护栏指标就是为这种情况准备的工装。

五、序贯检验：偷看问题的严格代价#

这是本节的技术核心。

问题的形式：固定样本量检验的前提是"只检验一次"。如果你每收集一批数据就做一次检验，一旦显著就停，那么你的实际第一类错误率不是 α，而是：

Pr(存在某次偷看使 ∣Zt​∣>z1−α/2​∣H0​)

对一个标准布朗运动在不同时间点重复检验，这个概率远大于 α。数值上（可复现的模拟，见本节代码）：总额 2 万样本、α=0.05、H0​ 为真时——

看结果的次数 实际第一类错误率
1 次（固定样本） 0.05
2 次 ≈0.09
5 次 ≈0.15
10 次 ≈0.20
20 次 ≈0.25

偷看越频繁、总信息量越大，膨胀越严重（更细的时间网格上可以到 0.30 以上）。这不是"稍微松一点"，而是把结论的可信度砍掉一半到五分之四。

直觉解释：α 是"在单一时间点，随机波动超过阈值的概率"。你观察的时间点越多，随机游走至少有一次越界的概率就越大。这也解释了为什么"一显著就停"在实践中总能得到显著结果——它在做一种选择性报告。

三种补救方案#

（1）α-消耗 / 组序贯（group sequential）：预先规定最多看 K 次（比如 5 次），并分配每次的显著性阈值，使总消耗恰好为 α。常用设计：

  • Pocock：每次用相同的名义 α′，K=5、总 α=0.05 时每次约用 0.016。适合"希望尽早停"的场景，代价是最终检验的临界值比 1.96 高不少（功效损失约 10~15%）。
  • O'Brien-Fleming（OBF）：早期极严、末期接近 α。K=5 时第一次的名义 α 约 0.00001，最后一次约 0.048。适合"不希望早期因噪声停掉"的场景，功效损失最小（约 3~5%）。

（2）always-valid 置信区间 / 混合序贯检验（mixture sequential probability ratio test, mSPRT）：构造一个在任意停止时间都有效的置信序列，从而允许"随时看、随时停"而不膨胀错误率。代价是区间通常比固定样本的区间宽（典型 10%~40%，取决于时间尺度），需要样本量补偿。

（3）贝叶斯方法：直接报后验概率"Pr(处理优于对照∣数据)"。它天然支持随时读取，但必须明确先验，并且不要把它当成频率学 p 值的替代品：贝叶斯后验概率不是第一类错误率，两者的数值不可互换。

三者的取舍表：

方案 允许偷看 错误率控制 效率代价 适用
固定样本 ✗（看了不能停） 精确 0（基准） 效应较大、周期短的实验
组序贯（OBF） ✓ 仅在看点 精确（需预设 K） 3~5% 样本量 有中期分析需求、希望尽早止损
组序贯（Pocock） ✓ 仅在看点 精确 10~15% 期望早期就能停（大效应/高风险）
always-valid / mSPRT ✓ 任意时刻 精确（置信序列） 10~40%（可调） 需要连续监控（护栏、事故检测）
贝叶斯 ✓ 不是 FWER 取决于先验 决策框架本身是贝叶斯

怎么做（工程落地）：

  1. 实验注册时写明：样本量、最长运行时长、检验方式（固定 or 序贯）、看结果的时间点、停止规则。这叫预注册，它把"事后合理化"的空间关掉。
  2. 如果必须连续监控（护栏指标通常必须），就用 always-valid 区间或序贯设计，并在样本量计算里把效率代价算进去。
  3. 任何"我们边跑边看，跑了两天就显著了所以上线"的结论，在预注册缺失的情况下都应当视为探索性证据，不足以支撑高风险发布。

代码#

以下代码只用标准库。⚠️ 全部为合成数据模拟，用于展示统计量的行为。

import math
import random

rng = random.Random(11)

# ============================================================
# 1. 偷看问题：真实的第一类错误率
# ============================================================
def two_proportion_z(x1, n1, x2, n2):
    # 两比例 z 统计量（合并方差）。
    if n1 == 0 or n2 == 0:
        return 0.0
    p1, p2 = x1 / n1, x2 / n2
    p = (x1 + x2) / (n1 + n2)
    se = math.sqrt(p * (1 - p) * (1 / n1 + 1 / n2))
    return (p1 - p2) / se if se > 0 else 0.0

def peek_error_rate(n_total, n_peeks, n_sim=4000, alpha=0.05, seed=1):
    # H0 为真（两组同概率），每 n_total/n_peeks 看一次，一显著就停。
    r = random.Random(seed)
    zcrit = 1.959963985
    chunk = n_total // n_peeks
    false_pos = 0
    for _ in range(n_sim):
        x1 = x2 = k1 = k2 = 0
        stopped = False
        for _ in range(n_peeks):
            for _ in range(chunk):
                k1 += 1
                k2 += 1
                if r.random() < 0.10:
                    x1 += 1
                if r.random() < 0.10:
                    x2 += 1
            if abs(two_proportion_z(x1, k1, x2, k2)) > zcrit:
                false_pos += 1
                stopped = True
                break
        if stopped:
            continue
    return false_pos / n_sim

print("== 1. 连续偷看的真实第一类错误率（H0 为真） ==")
print(f"只检验一次（固定样本）          : {peek_error_rate(20000, 1, seed=2):.3f}  ~ 0.05")
for k in (2, 5, 10, 20):
    print(f"分 {k:2d} 次看，一显著就停       : {peek_error_rate(20000, k, seed=2):.3f}")
print("  <- 偷看次数越多，假阳性率越高；这是选择性停止的必然结果")

# ============================================================
# 2. 组序贯：OBF 与 Pocock 的名义 alpha（消耗函数）
# ============================================================
def obf_nominal_alpha(K, alpha=0.05):
    # 用 alpha*t 的 Lan-DeMets OBF 消耗函数近似：alpha*(t)=2*(1-Phi(z_{a/2}/sqrt(t)))
    z = 1.959963985

    def phi(x):
        return 0.5 * (1 + math.erf(x / math.sqrt(2)))

    out = []
    prev = 0.0
    for i in range(1, K + 1):
        t = i / K
        cum = 2 * (1 - phi(z / math.sqrt(t)))
        out.append(cum - prev)
        prev = cum
    return out

def pocock_nominal_alpha(K, alpha=0.05):
    # Pocock：每步相同名义 alpha，通过数值搜索使总消耗 = alpha。
    def total(a):
        # 近似：K 次独立检验的族错误率（忽略相关性，仅作量级示意）
        return 1 - (1 - a) ** K
    lo, hi = 1e-6, alpha
    for _ in range(200):
        mid = (lo + hi) / 2
        if total(mid) < alpha:
            lo = mid
        else:
            hi = mid
    return [lo] * K

print("\n== 2. 序贯设计的名义显著性水平（K=5） ==")
for name, fn in (("OBF", obf_nominal_alpha), ("Pocock(近似)", pocock_nominal_alpha)):
    a = fn(5)
    print(f"{name:14s} 每次名义 alpha = {[round(x, 6) for x in a]}")
print("  <- OBF 早期极严（保住总错误率）、末期接近 0.05；Pocock 每次一样（更早能停）")

# ============================================================
# 3. 样本量 / MDE
# ============================================================
def n_per_arm(p, delta, alpha=0.05, power=0.80):
    z_a = 1.959963985 if abs(alpha - 0.05) < 1e-9 else 2.575829303
    z_b = 0.841621234 if abs(power - 0.80) < 1e-9 else 1.644853627
    return 2 * p * (1 - p) * (z_a + z_b) ** 2 / delta ** 2

def mde(p, n, alpha=0.05, power=0.80):
    z_a, z_b = 1.959963985, 0.841621234
    return math.sqrt(2 * p * (1 - p) * (z_a + z_b) ** 2 / n)

print("\n== 3. 样本量（每组）与 MDE ==")
for p, d in [(0.10, 0.01), (0.10, 0.005), (0.30, 0.02), (0.50, 0.02)]:
    print(f"p={p:.2f} 想检测 Δ={d:.3f} -> 每组 n≈{n_per_arm(p,d):,.0f}")
print(f"p=0.10, 每组 20000 人 -> MDE = {mde(0.10, 20000):.4f}（绝对），"
      f"相对 {mde(0.10,20000)/0.10:.1%}")

# ============================================================
# 4. 多重比较：FWER 与 BH-FDR
# ============================================================
def fwer(m, alpha=0.05):
    return 1 - (1 - alpha) ** m

def bh_reject(pvals, q=0.05):
    # Benjamini-Hochberg：返回被拒绝的索引集合。
    m = len(pvals)
    order = sorted(range(m), key=lambda i: pvals[i])
    kmax = 0
    for rank, i in enumerate(order, start=1):
        if pvals[i] <= rank / m * q:
            kmax = rank
    return set(order[:kmax])

print("\n== 4. 多重比较 ==")
for m in (1, 5, 12, 20, 50):
    print(f"m={m:3d} 个独立检验 -> FWER = {fwer(m):.3f}   (Bonferroni 阈值 {0.05/m:.4f})")

r = random.Random(3)
# 20 个检验，其中 3 个真有中等效应，17 个为 H0（合成）
pvals, truth = [], []
for i in range(20):
    eff = 0.35 if i < 3 else 0.0
    truth.append(eff > 0)
    # 用效应量近似一个 z 值再转 p（合成）
    z = r.gauss(eff * 6, 1.0)
    p = 2 * (1 - 0.5 * (1 + math.erf(abs(z) / math.sqrt(2))))
    pvals.append(p)
naive = {i for i, p in enumerate(pvals) if p < 0.05}
bh = bh_reject(pvals, 0.05)
print(f"\n朴素 p<0.05  拒绝 {len(naive)} 个，其中假阳性 {sum(1 for i in naive if not truth[i])} 个")
print(f"BH-FDR q=0.05 拒绝 {len(bh)} 个，其中假阳性 {sum(1 for i in bh if not truth[i])} 个")
print(f"Bonferroni 阈值 {0.05/20:.4f} -> 拒绝 "
      f"{sum(1 for p in pvals if p < 0.05/20)} 个（最保守）")

# ============================================================
# 5. 辛普森悖论：构造与分解
# ============================================================
print("\n== 5. 辛普森悖论 ==")
# 两个子群；处理组里"低基线"子群占比更高（分流不均衡 —— 真实实验中这是缺陷）
sub = [
    # (名称, 对照组 n, 对照组转化率, 处理组 n, 处理组转化率)
    ("新手", 100, 0.40, 900, 0.35),   # 处理组受伤 -5pt
    ("老手", 900, 0.80, 100, 0.75),   # 处理组受伤 -5pt
]
c_n = sum(s[1] for s in sub)
t_n = sum(s[3] for s in sub)
c_x = sum(s[1] * s[2] for s in sub)
t_x = sum(s[3] * s[4] for s in sub)
print(f"对照组 {c_x/c_n:.4f} (n={c_n})   处理组 {t_x/t_n:.4f} (n={t_n})")
print(f"合并差异 = {t_x/t_n - c_x/c_n:+.4f}   <- 总体看起来处理组更好，但每个子群都受伤")
for name, cn, cp, tn, tp in sub:
    print(f"  {name}: 对照 {cp:.2f} -> 处理 {tp:.2f}  差异 {tp-cp:+.4f}")
print("分解：合并差异 = 加权子群效应 + 组成效应")
pooled_diff = t_x / t_n - c_x / c_n
sub_effect = sum(0.5 * (s[4] - s[2]) for s in sub)   # 以两组平均权重加权
comp = pooled_diff - sub_effect
print(f"  合并差异     = {pooled_diff:+.4f}")
print(f"  加权子群效应 = {sub_effect:+.4f}  <- 每个子群都受伤，仍然是负的")
print(f"  组成效应     = {comp:+.4f}  <- 处理组里高基线（老手）占比被稀释，抵消并超过伤害")

# ============================================================
# 6. 组内相关系数（ICC）与设计效应
# ============================================================
def design_effect(m_bar, rho):
    return 1 + (m_bar - 1) * rho

print("\n== 6. 分桶随机的有效样本量 ==")
for rho in (0.0, 0.01, 0.05, 0.20):
    de = design_effect(50, rho)
    print(f"桶均 50 人, ICC={rho:.2f} -> 设计效应 {de:.2f} -> n_eff 只有名义的 {1/de:.1%}")
print("  <- ICC 越大，桶内加人几乎不增加信息量，必须加桶数")

代码里六个值得注意的点：

  • 第 1 段是本节的核心证据。 在 H0​ 为真时，只检验一次的错误率稳定在 0.05 附近；分 5 次看会升到 0.14~0.20，分 20 次看会到 0.30 以上。这就是"我们边跑边看"的真实代价——它不是"稍微不严谨"，而是把结论的可信度砍掉一半以上。
  • 第 2 段显示 OBF 与 Pocock 的哲学差异。 OBF 的第一次名义 α 低到几乎不可能拒绝（防止早期噪声），最后一次接近 0.05；Pocock 每次相同，因此早期就能停，但每次都要更严，总功效损失更大。选哪个取决于"早期停止的收益"是否值那份功效。
  • 第 3 段解释了为什么"检测 0.5 个点"是奢侈需求。 p=0.10 时检测 1 个点需要约 9 千/组，检测 0.5 个点需要约 3.6 万/组。实验周期的四次方级增长是团队最容易低估的成本。
  • 第 4 段里 BH 比 Bonferroni 更有发现能力，同时把假阳性控制在可接受范围。注意朴素 p<0.05 在 20 个检验里大概率会捞到假阳性——这正是"再多看一个指标"的代价。
  • 第 5 段的合并差异与每个子群差异符号相反，且分解显示组成效应（+0.20 量级）远大于真实伤害（−0.05）。关键判据是分流是否均衡：这里处理组的新手占了 90%，属于分流缺陷，必须先修分流。若两组子群分布相同而某子群仍受伤，那就是真实的加权冲突，交给第 3 节的护栏处理。
  • 第 6 段说明"桶内加样本"是无效投入。 ICC 0.05、桶均 50 时设计效应是 3.45，即名义 5 万样本只值 1.4 万。这一点在设计分桶实验时必须先算，否则会在错误的维度上加预算。

练习#

  1. 样本量反推与成本：你要测"自动回复率"，基线 p=0.12，希望在 α=0.05、power =0.80 下检测相对提升 5%（绝对 0.006）。 （a）用 n=Δ22p(1−p)(zα/2​+zβ​)2​ 估算每组样本量； （b）如果每天有 2 万可实验用户、50/50 分流，需要跑几天？这个时长对业务节奏意味着什么？ （c）把目标改成相对提升 10%，样本量变成多少？解释这里出现的"平方级成本"； （d）如果只允许跑 7 天，反推出的 MDE 是多少？写出你会怎么改决策规则来匹配这个精度。

  2. 偷看的代价：某团队的做法是"每天看一次结果，p<0.05 就停"。 （a）在真实无效果的前提下，分 5 次看与分 20 次看的第一类错误率大约是多少？说明这个数字是怎么来的； （b）改成"分 5 次做组序贯、用 OBF 消耗函数"，第一次的名义 α 大约是多少？为什么必须这么小？ （c）在"早期停止的收益"与"总功效损失"之间，OBF 与 Pocock 各适合什么场景？给出你的选择判据； （d）always-valid 置信区间把"随时能看"变成常态，它付出的代价是什么？适合什么样的决策流程？

  3. 辛普森悖论：先判分流，再谈伤害：某实验总体转化率对照组 0.52 → 处理组 0.56（+4 个点），但两个子群的差异都是 −3 个点。 （a）构造一组满足上述条件的样本量与子群转化率； （b）把合并差异分解为"加权子群效应"与"组成效应"，写出各占多少； （c）这个结果能上线吗？写出你需要的三个额外检查； （d）什么情况下"总体涨、子群跌"是可以接受的真实加权冲突？它和（c）的分流缺陷如何区分？

  4. 随机化单元与设计效应：某产品要测"推荐理由"改动，但摘要由会话共享（同一会话的多轮共享一次生成）。 （a）以"请求"为随机化单元会有什么问题？写出两个具体的溢出/干扰机制； （b）改为按"会话"随机，桶均 m=6、ICC=0.08，设计效应是多少？名义样本量要放大几倍？ （c）如果按"用户"随机、但用户可以跨设备，这个设计会引入什么偏差？给出一个能发现它的检查。

  5. 指标族与多重比较：一次实验同时看 1 个主指标 + 12 个护栏指标。 （a）12 个独立检验在 α=0.05 下至少出现一个假阳性的概率是多少？ （b）Bonferroni 与 Benjamini-Hochberg 分别控制什么？在这个场景你会选哪个，为什么？ （c）如果其中一条护栏是"安全事件"这类一票否决的红线，统计校正还适用吗？写出你的处理方式（提示：换一类判据）。

  6. 预注册一份实验方案（开放题）：为"把客服候选回复模型从 A 换成 B"写一份不超过一页的 A/B 方案，必须包含：随机化单元与理由、主指标与护栏、MDE 与每组样本量（给出计算）、多重比较处理、序贯规则（跑几次、用什么消耗函数、何时可以停），以及在什么结果下你会判定"这次实验没有结论"。

小结#

  • 随机化单元决定结论的适用面：请求级随机回答"哪个模型好"，用户级随机回答"上线后会怎样"。单元越大越安全（无溢出）但样本越贵；存在共享状态（会话、摘要缓存、库存）时，必须按共享边界随机。
  • 样本量必须从 MDE 反推：n≈2p(1−p)(zα/2​+zβ​)2/Δ2。要检测的效应越小，成本按平方增长——"检测 0.5 个点"通常比"检测 1 个点"贵四倍，这是团队最容易低估的一项。
  • 分桶/分簇随机会放大方差：设计效应 1+(m−1)ρ；桶内加样本几乎不增加信息量，只能加桶数。ICC 越大，越要在"更多桶"上花预算。
  • 多重比较是"再多看一个指标"的代价：m 个独立检验的族错误率是 1−(1−α)m；Bonferroni 控 FWER（保守），BH 控 FDR（发现力更强）。而红线类护栏应按"一票否决 + 人工确认"处理，不该靠 α 校正来放行。
  • 辛普森悖论的第一动作是查分流是否均衡：合并差异 = 加权子群效应 + 组成效应。组成效应占优时先修分流；两组子群分布相同而某子群仍受伤，才是真实的加权冲突，交给下一节的护栏处理。
  • 序贯检验的核心结论：要么预先固定样本量，要么为"随时能停"付出可计算的效率损失，二者必居其一。OBF 早期极严、末期接近名义水平；Pocock 每步相同、更早能停但总功效损失更大；always-valid 区间让"随时可看"成为常态，代价是区间更宽。
  • 报告纪律：预注册决策规则；报效应量 + 置信区间而非只报 p；分层报告子群；写清随机化单元、实验时长与停止规则。
