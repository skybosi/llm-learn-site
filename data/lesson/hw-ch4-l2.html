Roofline 曲线#

上一课我们用一个 ridge 数做"二分类"。这一课把它升级成一张图——Roofline 曲线。它把"算力上限"和"带宽上限"同时画出来，让你一眼看出任意一个算子能跑到多快、卡在哪。这是性能分析里最实用的一张图，也是本课程"算清楚"的工具箱里最锋利的一件。

一、概念讲解#

1. Roofline 模型的两条"屋顶"#

横轴是算术强度（FLOP/byte），纵轴是可达到的性能（FLOP/s）。一台机器有两个硬上限：

  • 算力上限：无论强度多高，性能不可能超过峰值算力 Ppeak​，是一条水平线；
  • 带宽上限：性能 = 强度 × 带宽，是一条过原点、斜率为带宽的斜线。

实际性能 G 被两者同时卡住：

G≤min(Ppeak​, AI×BW)

把这两条线画出来，像给性能盖了一个"屋顶（roofline）"，模型由此得名。

2. 拐点（ridge point）：两条屋顶的交界#

水平线与斜线的交点就是拐点：

ridge=BWPpeak​​

  • 算子强度 小于 ridge → 落在斜线上，受带宽限制；
  • 算子强度 大于 ridge → 落在水平线上，受算力限制。

H100 的 ridge ≈ 295，A100 ≈ 156。带宽越高，斜线越陡，拐点越靠左，意味着"访存密集"的区间更小、同样强度下能跑得更高。

3. 怎么用这张图#

把你要分析的算子算一个强度，标到横轴对应位置，再看它落在哪条线上：

  1. 落在斜线上 → 访存密集，能达到的性能 = 强度 × 带宽，优化方向是"提高强度或减字节"；
  2. 落在水平线上 → 计算密集，优化方向是"提高算力利用率"。

一个算子实际性能远低于它所在的那条线，说明还有大量优化空间（延迟、利用率、访存模式不佳等）；贴着线，说明已经接近理论极限。

4. 注意它的假设#

Roofline 是第一性估算模型，默认带宽是唯一访存瓶颈、计算与访存可完美重叠、忽略延迟与缓存命中差异。真实世界更复杂，但作为"先算个量级、找对方向"的工具，它极其好用——本课程所有"能不能跑、跑多快"的估算，本质都是 Roofline 的简化版。

二、可运行代码示例#

用 matplotlib 亲手画出 H100 与 A100 的 Roofline 曲线，并把几个算子标上去。

import numpy as np
import matplotlib.pyplot as plt

def draw_roofline(ax, peak_tflops, bw_tb_s, label, color):
    peak = peak_tflops * 1e12          # 换算成 FLOP/s
    bw = bw_tb_s * 1e12                # 换算成 B/s
    ridge = peak / bw
    ai = np.logspace(-1, 4, 300)       # 算术强度从 0.1 到 10000
    attainable = np.minimum(peak, bw * ai)
    ax.loglog(ai, attainable, color=color, label=f"{label} (ridge≈{ridge:.0f})")
    return ridge, peak, bw

fig, ax = plt.subplots(figsize=(8, 5))

ridge_h, peak_h, bw_h = draw_roofline(ax, 989.0, 3.35, "H100 SXM", "#1f77b4")
ridge_a, _, _        = draw_roofline(ax, 312.0, 2.0,  "A100 SXM", "#ff7f0e")

# 标出几个算子的强度落点
ops = {
    "逐元素 ReLU":       0.25,
    "矩阵×向量":         1.0,
    "中小 GEMM":         50.0,
    "大 GEMM(4096^3)":   1400.0,
}
for name, ai in ops.items():
    # 该算子在 H100 上能达到的性能上限
    perf = min(peak_h, bw_h * ai)
    ax.plot(ai, perf, "o", markersize=7)
    ax.annotate(name, (ai, perf), textcoords="offset points",
                xytext=(8, 6), fontsize=9)

ax.set_xlabel("算术强度 AI (FLOP/byte)")
ax.set_ylabel("可达到性能 (FLOP/s)")
ax.set_title("Roofline 模型：H100 vs A100")
ax.legend()
ax.grid(True, which="both", ls="--", alpha=0.4)
plt.tight_layout()
plt.savefig("roofline.png", dpi=150)
print("已保存 roofline.png")
print(f"H100 ridge ≈ {ridge_h:.0f} FLOP/byte，A100 ridge ≈ {ridge_a:.0f} FLOP/byte")

要点：曲线左半段是斜线（带宽限制），右半段是水平线（算力限制）。你标上去的"逐元素 ReLU""矩阵×向量"落在斜线上，是访存密集；"大 GEMM"落在水平线上，是计算密集。换一台带宽更高的机器，斜线变陡、拐点左移，同样的算子可能从"访存密集"变成"计算密集"——这就是 Roofline 想让你看清的动态关系。

三、练习#

  1. 画图：把 H200（989 TFLOPS、4.8 TB/s）加到同一张图上，观察它的斜线是否更陡、拐点是否更靠左，并解释原因。
  2. 定位：一个强度为 100 FLOP/byte 的算子，在 H100 上能达到的性能上限是多少 FLOP/s？它落在斜线还是水平线？写出计算过程。
  3. 对比：分别用 FP16（989 TFLOPS）和 FP8（1979 TFLOPS）作为 H100 的算力上限画 Roofline，观察拐点如何变化。这对"低精度推理"意味着什么？
  4. 思考：如果一个算子实际测得的性能远低于 Roofline 预测的那条线，可能是什么原因？列举至少两种（提示：延迟、访存模式、利用率）。
