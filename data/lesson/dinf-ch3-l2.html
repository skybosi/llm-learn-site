集合通信在推理中的角色：TP 的 all-reduce 频率、EP 的 all-to-all 与重叠条件#

这一节要解决什么#

上一节算清了单次集合通信的成本。但推理里通信从来不是单次事件 —— 它是按频率重复的：

TP：每个 token 的每一层要付 2 次 all-reduce（Megatron-LM 口径）
    → L=32、环形 N=8 时是 896 条消息（不是 8 条）
EP：每一层要付 dispatch + combine 两次 all-to-all
    → 每次的字节数是 t_k·H·σ 的 batch 倍（不是 H·σ）

第 1 章把这些账压成了一个量 c=2L⋅2(N−1)α，直接进了 N∗=A/c​。这一节要把 c 拆开，因为它里面有两个自变量完全不同的因子：

频率：由 L,N,算法决定2L⋅2(N−1)​​⋅单次成本：由链路决定α​​

把这两者混在一起谈，就会出现下面这类无法回答的争论：

"通信占了多少时间？" —— 占 12.57 ms（环形 N=8）还是 2.31 ms（树形 N=8）还是 0.13 ms（N=2）？取决于哪个自变量，差 100 倍。

这一节给出四样东西：

  1. 频率的公式：2L⋅步数 条消息/token，以及为什么"延迟的乘数是条数，不是字节数"。
  2. 精确的重叠模型：通信能否被藏住不是"乘一个系数"，而是逐层的

T=L⋅(max(访存,FLOP)窗口​​+max(0,Tcomm​−η⋅窗口))

由此得到阈值 Nhide​ 与"拆到第几张卡开始有净损失"。 3. 流水线并行的判据：ηTcomp​≥Tcomm​⟺κ≥1/η。这条式子有一个反直觉性质：两边的 (P−1) 会消掉，判据与流水线段数无关。 4. EP 的 all-to-all 完整账：容量因子 ceff​ 同时决定丢包率与载荷比，而这两者的边际收益方向相反（ceff​ 从 1.6 降到 1.0，丢包率涨 6.5 个数量级，载荷比只涨 1.6 倍）。

一、频率：一个 token 里有几条消息#

1.1 TP 的 2L 从哪来#

Megatron-LM 的张量并行把每一层切成两处通信：

层内第 1 处：MLP 的第二个线性层（行并行）输出后 → all-reduce
层内第 2 处：注意力输出投影（行并行）后       → all-reduce
（第一个线性层是列并行，输出按列切开，不需要通信）

所以每层 2 次、L 层共 2L 次。这个 2L 与 N 无关，与消息大小无关，是模型结构的常数。 而每次 all-reduce 的步数取决于算法（环形 2(N−1) / 树形 2⌈log2​N⌉）。两者相乘就是条数：

条数/token=结构2L​​×算法步数(N,algo)​​​

1.2 为什么"延迟的乘数是条数"#

把单次成本写成两项：

TAR​=延迟2(N−1)α​​+带宽2NN−1​βS​​​

在 decode（S=8 KiB、域内 β=450 GB/s）下：

Tbw​Tlat​​=0.03214.00​≈440

所以每次通信的成本 ≈ 延迟项，而延迟项与 S 无关。于是每 token 的通信时间就是

Tcomm/token​=条数×2(N−1)α=2L⋅2(N−1)⋅α​单次​

在延迟主宰区，Tcomm​ 与消息大小无关，只与条数×α 有关​

这条推论有一个很实用的形式：

要降 Tcomm​，只有三个旋钮：降 L（模型，不可动）、降步数（换算法）、降 α（换链路）

注意"降 N"也在这三个里（N 通过步数进入）。但"把消息合并成大包"不在其中 —— 那是训练侧的常规优化，在 decode 上无效。上一节的交叉点 S∗=Nαβ 就是这条判据的定量边界。

⚠️ prefill 是相反的。 b=32,s=2048 时 S=512 MiB，Tlat​/Tbw​≈0.0067，带宽项主导。这时"合并消息"有效，而"换算法"几乎无效（步数不变、每步更大）。同一个引擎要在两种形态下切换策略。

二、单层 roofline 账：窗口由谁定#

现在把"通信能否被藏住"这个问题形式化。能用来掩盖通信的只有那一层的计算时间，而单层计算时间由 roofline 决定：

窗口(N,b,s)=max​权重访存N⋅B12H2σ​​​,FLOPN⋅C2⋅12H2bs+4bs2H​​​​

这个"窗口"取 max 而不是相加，也不是取较小者：

  • 取 max 是因为真实执行里两条流水线并行（访存与计算），谁长谁定；
  • 不能取"整模型权重 / L" —— decode 是逐层流式读取，能掩盖第 k 层通信的只有第 k 层那点访存时间。用整模型账会高估可重叠窗口 L 倍（这是本节最容易犯的错）。

⚠️ 这里有一个容易写错的口径：Iprefill​ 随 bs 线性增长，而它与 N 无关（N 只在窗口的 1/N 里）。所以"prefill 的窗口是 FLOP"这件事由 bs 决定，不由并行度决定 —— 加大 N 不会把窗口从 FLOP 变回访存。

此处最容易犯的错：把 decode 的窗口公式（I=b）直接套到 prefill 上，或反过来。两者的 I 差 bs 倍（本例 65536 倍），于是"通信能不能藏住"的结论完全相反：

I vs 拐点 295 窗口 N=8 环形的 η∗ 结论
decode b=1 1 1/295 访存 1.87 藏不住，必须减步数
prefill b=32,s=2048 65536 222× FLOP 1.16 也藏不住（消息太大）
prefill + 树形 65536 222× FLOP 0.58 藏得住

所以"prefill 能重叠、decode 不能"这个常见说法也不准确 —— prefill 的 512 MiB 消息把环形通信推到 4.204 ms，而单层窗口只有 3.613 ms，η∗=1.16>1，环形下 prefill 也藏不住。只有换成树形（2.100 ms）才降到 0.58。

三、精确的重叠模型#

3.1 公式与阈值#

把"重叠"写成逐层的三项，而不是乘一个系数：

T(N)=L⋅(窗口(N)+max(0,Tcomm​(N)−η⋅窗口(N)))​

第二项 max(0,⋅) 是溢出的通信（藏不住的那部分）。定义两个阈值：

Nhide​(η)=max{N:Tcomm​(N)≤η⋅窗口(N)}η∗(N)=窗口(N)Tcomm​(N)​

这两个是同一个条件的两种读法：N≤Nhide​ 等价于 η≥η∗。当 N≤Nhide​ 时，T(N)=L⋅窗口(N)∝1/N —— 拆卡是纯收益，通信完全不参与。

四、流水线并行：κ≥1/η 与"P 会消掉"#

4.1 判据的推导#

上一节的重叠模型是"层内重叠"。流水线并行是另一种重叠，它的判据不同，而且有一个非常反直觉的性质。

模型：P 级流水线，每级的每微批要付 Tcomm​（级间传激活）与 Tcomp​（本级计算）。计算能掩盖通信的比例是 η（0≤η≤1）。把流水线按相邻微批对配对，第 i 级的计算要掩盖第 i+1 级的通信：

可用的掩盖相邻对∑​(ηTcomp​)​​=η(P−1)Tcomp​≥(P−1)Tcomm​∑(通信)​​=(P−1)Tcomm​

ηTcomp​≥Tcomm​⟺κ:=Tcomm​Tcomp​​≥η1​​

(P−1) 在两边消掉了。 这是本节最反直觉的结论，值得单独强调：

"能不能藏住通信"与"几段流水线"无关，只与"单微批的算力够不够长"有关​

P 买到的是吞吐摊销（把权重分到 P 张卡上，每卡只算 1/P 的层），不是可重叠性。

4.2 为什么 η∗ 比"提速倍数"更本质#

同样的信息，两种说法：

说法 B：树形把 η∗ 从 1.87 降到 0.80

说法 B 更有用，因为 η∗ 可以直接与"你的引擎实测重叠率"比较：

引擎实测 η 环形可行？ 树形可行？
0.3（保守，粗粒度 kernel） ✗（需 1.87） ✗（需 0.80）

0.95（prefill 式大 kernel） ✗ ✓

所以"我的引擎能不能藏住 TP 通信"这个问题，答案取决于 η 与 η∗ 的比较，而 η∗ 是算出来的、η 是测出来的。 这就是本节的方法论：把可算的与可测的分开。

4.3 取舍：为什么推理的 PP 与训练不同#

训练 PP 推理 PP

五、EP 的 all-to-all：容量便宜，但 S 大且窗口是访存#

5.1 字节账#

一个 MoE 层要付两次 all-to-all：

dispatch：把每个 token 的激活送到它选中的 t_k 个专家所在的 rank
combine ：把专家输出送回来

每 rank 每次发送的字节数：

Sa2a​=b⋅tk​⋅H⋅σ​

b=256、tk​=2、H=4096、σ=2 时：

Sa2a​=256×2×4096×2=4 MiB

比 TP 的 8 KiB 大 512 倍。 这就是 EP 通信贵的真正原因 —— 不是每字节单价（上一节证明 AllToAll 的容量只有 AllReduce 的一半），而是 S。

5.2 窗口：MoE 的算术强度#

MoE 的单层窗口同样是 roofline，但有效权重只有 tk​/E：

权重访存=NE​⋅12H2σ/B,FLOP=N2⋅12H2⋅btk​​/C

⟹IMoE​=Nσ2btk​​

b=256、tk​=2、N=8、σ=2 时 I=64 FLOP/byte，远低于拐点 295 —— 所以

MoE 的 decode 窗口是权重访存，与稠密层同类型，但原因不同​

稠密层由权重总量定；MoE 由"每次只激活 tk​/E 的权重"定。这条区分在选型时很关键：MoE 省的是 FLOP，不省访存。

5.3 容量因子：同一个旋钮的"丢包率"与"载荷比"#

EP 路由不可能完美均衡 —— 每个专家收到的 token 数服从 (btk​,1/E) 的二项分布。容量因子 ceff​ 决定给每个专家预留多少槽位：

cap=⌊ceff​⋅Ebtk​​⌋,poverflow​=Pr[Binom(btk​,1/E)>cap]

而预留的槽位里没用上的部分就是浪费：

载荷比=E⋅capbtk​​=ceff​1​  (ceff​ 不整除时略高)

注意这两个量的方向完全相反：ceff​↑ → 丢包率 ↓（好）但载荷比 ↓（坏）。

5.4 模型的边界#

这个二项分布模型有三个不成立的地方，用之前必须知道：

  1. 独立性。真实路由的相关性来自输入本身（同一批请求主题相近 → 选中同一专家）与路由函数的确定性（相同 token → 相同专家）。相关性会让尾部更厚，所以二项模型给的是乐观下界。
  2. token 不可丢。真实 MoE 通常不是"丢 token"而是"溢出到 CPU / 丢弃并让该 token 只走部分专家" —— 后者的质量损失不是"少 1 个 token"而是"该 token 的输出被截断"。所以 poverflow​ 应该与"质量退化"而不是"请求失败"挂钩。
  3. 容量是整数。⌊ceff​⋅btk​/E⌋ 的台阶会让小 batch 下的丢包率非单调。程序里 b=256 的台阶是 5.12%（E/btk​=1/64），所以 ceff​ 的步长应该取 1/64 的整数倍，而不是 0.1。

代码：TP 频率、roofline 窗口、重叠阈值与 EP 容量因子#

脚本只用标准库，做八件事：(1) 算条数；(2)(3) 算 decode/prefill 的单层 roofline 窗口；(4) 精确重叠模型与数值最优 N；(5) Nhide​ 表；(6) 流水线判据；(7)(8) EP 的 all-to-all 与容量因子。

"""
集合通信在推理中的角色与代价：TP 的 all-reduce 频率、EP 的 all-to-all、
以及"通信与计算重叠"的收益条件（只用 Python 标准库）。

设计决策：
  1. **频率与单次成本分开算**。所有"通信够不够快"的争论最终归结为
     「一个 token 里有几次集合通信」×「每次多少 µs」。两者自变量完全不同
     （前者是 L、s、b、并行策略；后者是 α、β、S、N）。
  2. **可重叠窗口用 roofline 单层下限**：max(单层权重访存, 单层 FLOP/算力)。
     不是"整模型权重 / L"（高估 L 倍），也不是"算力项"（在 batch=1 时低估 10 倍）。
     这一项的量级直接决定"decode 能否重叠"这个全节最关键的结论（正文 §2）。
  3. **重叠写成 max(0, T_comm − η·窗口)**，不写成"乘一个系数"——
     因为"新增的那部分通信能不能藏住"取决于当前 N（阈值 N_hide）。
     写成乘法会丢掉阈值，从而丢掉本节最有用的判据。
  4. 二项分布尾部不用 comb()：comb(512,64) 是 10^100 量级，转 float 直接
     OverflowError。本课用正态近似（含连续性修正），并在小 λ 时退回泊松递推。
"""
from math import ceil, log2, exp, sqrt, erfc

# ==================== 全课统一口径 ====================
DT = 2                          # fp16 每元素 2 字节
L, H = 32, 4096                 # 层数、隐藏维
B_HBM = 3.35e12                 # HBM3e 单向带宽（H100 SXM）
C_BF16 = 989e12                 # bf16 稠密算力
A_DOM, B_DOM = 1.0e-6, 450e9    # 域内：NVLink/NVSwitch α、单向 β
A_NET, B_NET = 2.0e-6, 50e9     # 跨机：NDR InfiniBand α、单向 β


# ==================== (1) 集合通信的调用频率 ====================
def ar_steps(N, algo):
    """一次全归约的步数：环形 2(N−1)，树形 2⌈log2 N⌉。"""
    if N <= 1:
        return 0
    return 2 * (N - 1) if algo == "ring" else 2 * int(ceil(log2(N)))


def tp_messages_per_token(N, algo, layers=L, ars_per_layer=2):
    """一个 token 在 TP 下的全归约**消息条数** = ars_per_layer · L · 步数。"""
    steps = ar_steps(N, algo)
    return ars_per_layer * layers * steps, steps


# ==================== (2) 单次集合通信的 α-β 成本 ====================
def ring_ar(N, S, alpha, beta):
    """环形全归约：2(N−1) 步，每卡发 2(N−1)/N·S 字节（RS + AG 各一半）。"""
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * (N - 1)
    nbytes = 2 * (N - 1) / N * S
    lat, bw = steps * alpha, nbytes / beta
    return lat + bw, lat, bw, steps


def tree_ar(N, S, alpha, beta):
    """递归倍增全归约：2⌈log2 N⌉ 步，容量按紧下界 (N−1)/N·S 记账。"""
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * int(ceil(log2(N)))
    lat, bw = steps * alpha, (N - 1) / N * S / beta
    return lat + bw, lat, bw, steps


def ar_cost(N, S, alpha, beta, algo="ring"):
    return (ring_ar if algo == "ring" else tree_ar)(N, S, alpha, beta)


# ==================== (3) 单层的 roofline 下限 ====================
def layer_weight_bytes(H_=H, dtype=DT):
    """单层权重字节数（12·H² 个参数 × dtype）——decode 逐层的访存下限。"""
    return 12 * H_ * H_ * dtype


def layer_flops(H_=H, batch=1, seq=1):
    """
    单层浮点运算量：主项 2·12·H²·b·s，注意力项 4·b·s²·H。
    b·s² 项在长序列下反超——这正是 prefill 与 decode 的分界（第 1 章 §1.2）。
    """
    return 2 * 12 * H_ * H_ * batch * seq + 4 * batch * seq * seq * H_


def layer_times(N, batch, seq, dtype=DT, alpha=A_DOM, beta=B_DOM, algo="ring",
                ars_per_layer=2, b_hbm=B_HBM, c_flop=C_BF16, H_=H):
    """
    单层的 (T_comm, T_mem, T_flop, S)。
      T_comm = ars_per_layer × 单次 all-reduce
      T_mem  = 单层权重字节 / N / HBM 带宽
      T_flop = 单层 FLOP / N / 算力
    可重叠窗口 = max(T_mem, T_flop)，由调用方取（真实执行是"谁长谁定"）。
    """
    S = batch * seq * H_ * dtype
    t_ar, lat, bw, steps = ar_cost(N, S, alpha, beta, algo)
    return (ars_per_layer * t_ar,
            layer_weight_bytes(H_, dtype) / N / b_hbm,
            layer_flops(H_, batch, seq) / N / c_flop,
            S)


# ==================== (4) 精确的可重叠模型 ====================
def total_time_overlap(N, batch, seq, eta, dtype=DT, alpha=A_DOM, beta=B_DOM,
                       algo="ring", layers=L, H_=H):
    """
    T(N) = L·(窗口(N) + max(0, T_comm(N) − η·窗口(N)))
      —— 窗口是"当前这层的 roofline 下限"。
    这样写有个重要的结构后果：只要 T_comm(N) ≤ η·窗口(N)，T 就精确等于 L·窗口(N)，
    于是"拆卡收益"完全由窗口的 1/N 决定 —— 通信不参与，N 越大越好。
    """
    if N <= 1:
        w = max(layer_weight_bytes(H_, dtype) / B_HBM,
                layer_flops(H_, batch, seq) / C_BF16)
        return {"T": layers * w, "window": layers * w, "T_comm": 0.0,
                "overflow": 0.0, "S": batch * seq * H_ * dtype, "steps": 0}
    T_comm, T_mem, T_flop, S = layer_times(N, batch, seq, dtype, alpha, beta, algo,
                                           H_=H_)
    win = max(T_mem, T_flop)
    overflow = max(0.0, T_comm - eta * win)
    return {"T": layers * (win + overflow), "window": layers * win,
            "T_comm": layers * T_comm, "overflow": layers * overflow, "S": S,
            "steps": ar_steps(N, algo)}


def n_hide(batch, seq, eta, alpha=A_DOM, beta=B_DOM, algo="ring", layers=L, H_=H,
           limit=4096):
    """
    阈值：T_comm(N) ≤ η·窗口(N) 的最大 N。此后通信被完全藏住，拆卡是纯收益。
    台阶由 ⌈log2 N⌉ 与 N 的奇偶带来，所以数值扫描比闭式解诚实。
    """
    best = 1
    for N in range(2, limit + 1):
        T_comm, T_mem, T_flop, S = layer_times(N, batch, seq, alpha=alpha, beta=beta,
                                               algo=algo, H_=H_)
        if T_comm <= eta * max(T_mem, T_flop):
            best = N
        else:
            break
    return best


def best_N_overlap(batch, seq, eta, algo="ring", layers=L, H_=H, alpha=A_DOM,
                   beta=B_DOM, limit=64):
    """数值最优 N（不做闭式解）；返回 (N, T)。"""
    best, bestT = 1, float("inf")
    for N in range(1, limit + 1):   # 必须覆盖到 64：极值常落在 N=4~8
        r = total_time_overlap(N, batch, seq, eta, algo=algo, layers=layers, H_=H_,
                               alpha=alpha, beta=beta)
        if r["T"] < bestT:
            best, bestT = N, r["T"]
    return best, bestT


# ==================== (5) 流水线：通信能否被计算藏住 ====================
def pp_overlap_condition(T_comm, T_comp, eta):
    """
    1F1B 稳态下"通信被计算藏住"的判据。
    逐对推导：把流水线按相邻微批配对，i 级的计算必须覆盖 i+1 级的通信：
        (P−1)·T_comm ≤ (P−1)·η·T_comp
    **两边的 (P−1) 消掉**，只剩：
        η·T_comp ≥ T_comm   ⇔   κ = T_comp/T_comm ≥ 1/η
    这是一个反直觉但正确的结论：能不能藏通信与"几段流水线"无关，
    只与"单微批的算力时间够不够长"有关。P 只影响**吞吐摊销**，不影响可重叠性。
    返回 (是否满足, κ, 所需最小 η* = 1/κ)。
    """
    kappa = T_comp / T_comm if T_comm else float("inf")
    # 相对容差：κ 是浮点比值，"刚好相等"必须算满足（否则边界结论随舍入翻转）
    ok = kappa >= (1.0 / eta) * (1 - 1e-12)
    return ok, kappa, (1.0 / kappa if kappa else float("inf"))


def pp_latency_P(P, T_comm, T_comp):
    """推理 PP 的延迟乘数：一个 token 必须顺序穿过全部 P 级。"""
    return P * (T_comm + T_comp)


# ==================== (6) EP 的 all-to-all 与容量因子 ====================
def ep_a2a_bytes(batch, top_k, H_=H, dtype=DT):
    """dispatch 阶段每个 rank 发出的字节 = batch·top_k·H·dtype（seq=1）。"""
    return batch * top_k * H_ * dtype


def ring_a2a(N, S, alpha=A_NET, beta=B_NET):
    """环形全交换：N−1 步直发（无归约阶段），每卡发 (N−1)/N·S。"""
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = N - 1
    nbytes = (N - 1) / N * S
    lat, bw = steps * alpha, nbytes / beta
    return lat + bw, lat, bw, steps


def binom_drop(batch, top_k, E, c_eff):
    """
    单专家容量 = ⌊c_eff·batch·top_k/E⌋；溢出概率 = P(Binom(batch·top_k, 1/E) > cap)。
    λ = batch·top_k/E 很大时用正态近似（含连续性修正），小 λ 用泊松。
    """
    n, p = batch * top_k, 1.0 / E
    cap = int(c_eff * batch * top_k / E)
    lam = n * p
    if lam < 30:
        cdf, term = 0.0, exp(-lam)
        for k in range(0, min(cap, n) + 1):
            cdf += term
            term *= lam / (k + 1)
        return max(0.0, 1.0 - cdf), cap
    # 正态近似：P(X > cap) ≈ ½·erfc((cap + 0.5 − λ)/√(2λ(1−p)))
    z = (cap + 0.5 - lam) / sqrt(2 * lam * (1 - p))
    return 0.5 * erfc(z), cap


def ep_layer(N, batch, top_k, E, c_eff, H_=H, dtype=DT, alpha=A_NET, beta=B_NET,
             c_flop=C_BF16, b_hbm=B_HBM, eta=0.8):
    """
    一个 MoE 层的账。
      通信：dispatch + combine 各一次全交换；每 rank 每次发 S = batch·top_k·H·dtype
            （这是**本 rank 要送出去的** token 激活，不是总量）
      窗口：roofline 单层下限 = max(权重访存, 专家 FLOP)
            权重访存 = (E/N)·12H²·dtype / B_HBM   ← 本 rank 持有的专家权重
            专家 FLOP = 2·12H²·batch·top_k / (N·C) ← 本 rank 上被激活的 token-expert 对
      **关键**：MoE 的算术强度 = 2·batch·top_k/(N·dtype)，与 batch 成正比。
      它远低于 roofline 拐点 C/B（本例 295 FLOP/byte），所以 MoE 的 decode
      窗口是**访存**而不是 FLOP —— 这一点与稠密层相同，但原因不同（稠密层由
      权重总量定，MoE 由"每次只激活 t_k/E 的权重"定）。
    """
    S = ep_a2a_bytes(batch, top_k, H_, dtype)
    t1, lat, bw, steps = ring_a2a(N, S, alpha, beta)
    flops = 2 * 12 * H_ * H_ * batch * top_k / N
    T_flop = flops / c_flop
    T_mem = (E / N) * layer_weight_bytes(H_, dtype) / b_hbm
    win = max(T_flop, T_mem)
    intensity = flops / ((E / N) * layer_weight_bytes(H_, dtype))
    drop, cap = binom_drop(batch, top_k, E, c_eff)
    payload = (batch * top_k) / (E * cap) if cap else float("inf")
    overflow = max(0.0, t1 - eta * win)
    return {"t_one": t1, "t_two": 2 * t1, "S": S, "steps": steps, "lat": lat,
            "bw": bw, "T_flop": T_flop, "T_mem": T_mem, "window": win,
            "intensity": intensity, "drop": drop, "cap": cap, "payload": payload,
            "overflow2": 2 * overflow, "dom": "FLOP" if T_flop >= T_mem else "访存"}

四处关键设计决策：

  1. 窗口取 max(T_mem, T_flop) 而不是 T_flop 或"整模型账"。这是本节所有结论的支点：decode 下 Tmem​ 是 Tflop​ 的 295 倍，取错就得到"decode 通信能被轻松藏住"的相反结论。
  2. 重叠写成 max(0, T_comm - eta * win) 而不是 (1-eta) * T_comm。前者会自动产生阈值（Tcomm​≤ηW 时溢出为 0），后者永远给出"重叠总有效"的假象。这个差别决定了能不能算出 Nhide​。
  3. pp_overlap_condition 里加了 10−12 的相对容差。因为 κ=1.2492 与 1/0.8=1.25 的"相等"是浮点比较 —— 不加容差，边界结论会随舍入随机翻转（本次运行就出现过）。
  4. binom_drop 用正态近似而不是精确 comb()。(64512​)∼10100，转 float 直接 OverflowError。这不是精度问题，是能不能跑起来的问题 —— 而丢包率的量级判断（10−7 还是 0.47）用正态近似完全够。

小结#

  • 通信成本的乘数是"条数"，不是"字节"：条数=2L×步数(N,algo)。L=32、N=8 环形是 896 条/token，换成树形 384 条（2.33×）。在延迟主宰区（decode），Tcomm​ 与消息大小无关。
  • 可重叠窗口必须用单层 roofline 下限：max(12H2σ/(NB),FLOP/(NC))。不能用"整模型权重/L"（高估 L 倍），也不能只用 FLOP 项（decode 下低估 295 倍）。decode 的窗口恒为访存（I=1 FLOP/byte），prefill 的翻转为 FLOP（I=2bs/σ）。
  • 重叠要写成 T=L(窗口+max(0,Tcomm​−η窗口))，不能写成乘系数。前者自动给出阈值 Nhide​=max{N:Tcomm​≤ηW}∝η​，后者永远掩盖"溢出"这一项。
  • Nhide​ 只随 η​ 增长：η 从 0.3 到 1.0（3.3 倍）只让 Nhide​ 从 3 到 5（1.8 倍）。重叠不是通往大 N 的路。
  • decode 的 N 有上界、prefill 的没有：decode 在 N=32 环形时 T/T(1)=1.038>1（比不拆还慢）；prefill 大 batch 在 N=32 时 T/T(1)=0.170（继续跌）。
  • 流水线判据是 κ≥1/η（κ= 窗口/通信），与段数 P 无关 —— (P−1) 在两边消掉。P 买的是吞吐摊销，不是可重叠性。decode 环形 η∗=1.87（不可能）、树形 0.80（临界）；prefill 环形 1.16（也过不了），"prefill 一定能重叠"是错的。
  • EP 的贵不在单价而在 S：Sa2a​=btk​Hσ（b=256 时 4 MiB，比 TP 的 8 KiB 大 512 倍），而 AllToAll 的容量只有 AllReduce 的一半。
  • MoE 的 decode 窗口是访存（IMoE​=2btk​/(Nσ)，b≤1024 时低于拐点 295）。"MoE 省 FLOP 不省访存"，所以它不能像"算力密集"那样把通信藏住：b 越大 S 越大而窗口不变，通信/窗口从 0.27 涨到 2.85。
  • 容量因子是"丢包率 vs 载荷比"同一个旋钮的两端：ceff​ 从 1.0 到 1.6，丢包率从 0.47 降到 1.3×10−7（6.5 个数量级），载荷比只从 1.000 降到 0.627（1.6 倍）。边际收益极不对称 —— 应该取到"丢包率刚低于 SLO 容忍"的点。
  • 一句话："通信贵不贵"要先回答三个问题：几条消息、每条多大、那一层有多少计算能藏住它；三个答案里任何一个答错，结论都会反号。
