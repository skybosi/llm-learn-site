ItemCF：基于物品的协同过滤#

上一课的 UserCF 是从"人"出发：找相似的人。ItemCF（Item-based Collaborative Filtering） 换了个视角：找相似的物品。它的思想是——"你喜欢《星际穿越》，而《星际穿越》和《盗梦空间》经常被同一批用户同时喜欢，那不妨把《盗梦空间》推荐给你"。电商里那句经典的"买了这个的人也买了…"，就是 ItemCF。这一课把 ItemCF 的公式、它与 UserCF 的本质差异、以及"为什么工业界更偏爱它"讲透。

一、概念讲解#

1. 核心思想：物品相似由"被谁喜欢"定义#

ItemCF 同样只看评分矩阵 R，但相似度的对象从"用户"换成了"物品"：两个物品相似，当且仅当它们被同一批用户以相近的方式喜欢。判定"物品 i 与 j 相似"，看的是矩阵里这两列打分向量的夹角——这正好把上一课 UserCF 的"行向量"逻辑转置成了"列向量"逻辑。

2. 算法三步走（与 UserCF 完美对偶）#

  1. 算物品相似度：对每对物品 (i, j)，用"同时给两者打过分的用户"那部分打分算相似度 sim(i, j)。
  2. 找邻居：对目标用户 u 已经打过高分的每个物品 j，找出与 j 最相似的一批物品 i。
  3. 加权预测：用 u 对"已评物品"的打分，按物品相似度加权，预测 u 对未评物品 i 的评分：
R̂[u, i] = Σ_{j ∈ N(u) ∩ S(i)} sim(i, j) · R[u, j] / Σ_{j ∈ N(u) ∩ S(i)} |sim(i, j)|

其中 N(u) 是 u 评过分的物品集合，S(i) 是 i 的相似物品集合。直观读法："你给 j 打了多少分，乘以 j 和 i 有多像，再加总"。

3. ItemCF 为什么在工业界更吃香#

理论上 UserCF 和 ItemCF 是对偶的，但工程实践强烈偏爱 ItemCF，原因有三：

  1. 物品数量通常远小于用户数量：物品相似度矩阵比用户相似度矩阵小得多，计算与存储都便宜。
  2. 物品相似度更稳定：一个物品"像什么"变化缓慢，可以离线预计算并存起来，推荐时只做查表 + 加权；而用户的兴趣随时在变，UserCF 的用户相似度要频繁重算。
  3. 可解释性更自然："因为你买了 A，而 A 和 B 相似"比"因为某个和你相似的人也买了 B"更容易被用户接受，也更好做成"看了又看"这类推荐位。

一个经典的认知误区是"ItemCF 是内容推荐"。不是。 ItemCF 的相似度完全由用户行为决定，跟物品的文字/图像内容毫无关系——两个内容完全不同的物品（比如一把伞和一本书）也可能因"经常被一起购买"而高度相似。这正是协同过滤与基于内容推荐的根本分野。

4. UserCF 与 ItemCF 的对照#

维度 UserCF ItemCF
相似度对象 用户（行向量） 物品（列向量）
相似度稳定性 低（兴趣易变） 高（物品属性稳定）
可否离线预计算 难 易
适用场景 用户少、物品多、需社交化解释 用户多、物品少、需"看了又看"
冷启动敏感点 新用户 新物品

二、可运行代码示例#

用 NumPy 从零实现 ItemCF，与上一课 UserCF 形成对照：核心变化只是"把矩阵转置，相似度改在物品上算"。

import numpy as np

# 用户-物品评分矩阵：0 表示未评分
R = np.array([
    [5, 3, 0, 1],
    [4, 0, 0, 1],
    [1, 1, 0, 5],
    [1, 0, 0, 4],
    [0, 1, 5, 4],
], dtype=float)

def item_cosine(R, i, j):
    """物品 i 与 j 的余弦相似度：只看同时给两者打分的用户。"""
    col_i, col_j = R[:, i], R[:, j]
    mask = (col_i > 0) & (col_j > 0)      # 同时评过两者的用户
    if mask.sum() == 0:
        return 0.0
    a, b = col_i[mask], col_j[mask]
    denom = np.linalg.norm(a) * np.linalg.norm(b)
    return float(a @ b / denom) if denom > 0 else 0.0

# 1) 计算物品-物品相似度矩阵
n_users, n_items = R.shape
sim = np.zeros((n_items, n_items))
for i in range(n_items):
    for j in range(n_items):
        sim[i, j] = 1.0 if i == j else item_cosine(R, i, j)
print("物品相似度矩阵：\n", np.round(sim, 3))

def predict(R, sim, user, item, k=2):
    """用 user 已评分物品中、与 item 最相似的 k 个，加权预测评分。"""
    rated = [j for j in np.where(R[user] > 0)[0] if j != item]  # 用户评过分的物品
    if not rated:
        return float(R[user][R[user] > 0].mean())               # 无历史时退回用户均值
    top_k = sorted(rated, key=lambda j: -sim[item, j])[:k]      # 与 item 最像的 k 个
    num = sum(sim[item, j] * R[user, j] for j in top_k)         # 物品相似度加权分子
    den = sum(abs(sim[item, j]) for j in top_k)                 # 归一化分母
    return float(num / den) if den > 0 else float(R[user][R[user] > 0].mean())

# 2) 预测：用户 0 对物品 2（原本未知）的评分
print("预测 用户0 对 物品2 的评分 =", round(predict(R, sim, user=0, item=2, k=2), 3))

# 3) 给用户 0 生成推荐
def recommend(R, sim, user, k=2, top_n=2):
    unrated = [i for i in range(n_items) if R[user, i] == 0]
    scores = [(i, predict(R, sim, user, i, k)) for i in unrated]
    scores.sort(key=lambda x: -x[1])
    return [(i, round(s, 3)) for i, s in scores[:top_n]]

print("给用户 0 的推荐（物品, 预测分）：", recommend(R, sim, user=0, k=2))

观察要点：对比上一课 UserCF 对同一矩阵的结果，你会发现两者的推荐倾向可能不同——UserCF 靠"相似用户"带路，ItemCF 靠"相似物品"带路，它们抓住的是矩阵里两种不同结构的信号。真实系统里两者常被组合使用。

三、练习#

  1. 把 k 从 2 改成 3，观察 ItemCF 预测变化；当"相似物品"变多时，预测是更平滑还是更振荡？为什么？
  2. 实现均值修正版 ItemCF：预测时先减用户均值，R̂[u,i] = r̄_u + Σ sim·(R[u,j] − r̄_u) / Σ|sim|，思考这里减的是"用户均值"还是"物品均值"，为什么。
  3. 造一个"热门物品陷阱"的矩阵：某个物品被几乎所有用户打高分，观察它是否会被 ItemCF 推荐给所有人；联系第 1 章的"长尾/热度偏差"，说明热门物品如何通过高相似度"污染"推荐。
  4. 思考：ItemCF 对"新物品冷启动"为什么无能为力，但对"新用户"却相对友好？结合"物品相似度可离线算、用户只需一次即时加权"这一点写下一两句话。

为什么这样做？——理论推导#

ItemCF 与 UserCF 是"转置"下的同一个算法#

把评分矩阵 R（行=用户，列=物品）转置成 Rᵀ（行=物品，列=用户），在 Rᵀ 上跑 UserCF 的"找相似行、加权预测"，得到的正是 ItemCF。这个对偶性说明：UserCF 和 ItemCF 没有本质优劣，只是把"相似"这个先验分别施加在行空间和列空间。工程上选谁，完全由"哪一边的数量更少、更稳定、更能离线预计算"决定——这是算法理论之外、却决定落地成败的关键考量。

加权平均同样是加权最小二乘#

上一课我们证明过"相似度加权平均 = 加权最小二乘闭式解"。ItemCF 的公式只是把那个结论里的"邻居"从用户换成物品：把 sim(i, j) 解释为"物品 j 的评分作为物品 i 真实评分的一个可信观测"，其噪声方差与 1/sim(i,j) 成正比，那么最小化 Σ_j sim(i,j)(ŷ − R[u,j])² 得到的 ŷ 就是 ItemCF 的加权平均公式。同一个母原理，换一对下标就得到两个算法。

为什么"被同一批用户喜欢"能定义物品相似#

这是协同过滤最深刻、也最容易被问倒的一点：凭什么"共同被喜欢"意味着"相似"？其依据是共现（co-occurrence）作为潜在属性的代理。物品的"真实属性"（风格、用途、价位）不可直接观测，但两个物品如果反复出现在同一批用户的购物篮里，说明它们背后共享了某个未被观测到的共同原因（比如"都适合下雨天通勤"）。统计学上，这是"潜在变量导致的可观测共现"：共享的隐藏属性越多，共现频率越高。ItemCF 用"打分向量的相似度"去逼近这个隐藏属性，本质上是在用行为数据反推物品的隐空间结构——这一思想，正是第 3 章矩阵分解（隐语义模型）的直接前奏。

母原理连接： ItemCF 的"物品相似度"是"潜在变量 → 可观测共现"这条因果链的一次朴素近似；矩阵分解则把这条链升级为显式的低维向量——两者是同一思想由浅入深的两个版本。
