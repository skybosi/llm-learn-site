其他高效微调#

LoRA 是目前最流行的高效微调方法，但它不是唯一解。PEFT 库背后站着一整个方法家族：Adapter、Prefix-tuning、Prompt tuning、IA3、AdaLoRA……它们的共同目标都是"冻结基座、只训一小撮参数"，差异在于把可训练参数放在哪里、长什么样。这一课我们把这个家族梳理一遍，搞懂每种方法的"插入位置"和取舍，建立选型的判断力。

一、概念讲解#

1. 一条主线：可训练模块插在哪#

所有方法都可以用一句话概括——在模型里找一块地方插入可训练参数：

  • 插入层之间：Adapter（瓶颈层）、AdapterFusion；
  • 插入输入序列：Prompt tuning、Prefix-tuning（软提示/软前缀）；
  • 改造已有权重：LoRA（低秩增量）、AdaLoRA（自适应秩）、IA3（缩放向量）。

记住这个分类，方法再多也不乱。

2. Adapter：塞进 Transformer 的瓶颈层#

Adapter 在每个 Transformer 子层（如注意力之后、FFN 之后）插入一个小的下采样—非线性—上采样瓶颈模块：先 d → m 降维，再 m → d 升维（m << d），外带残差连接。训练时只更新 adapter，基座冻结。它的缺点是增加了推理时的串行计算，latency 会上升；但优点是表达能力可控、可叠加多任务（AdapterFusion 进一步学习"怎么组合多个 adapter"）。

3. Prefix-tuning / Prompt tuning：把可训练参数放进"提示"#

这两类方法不碰权重，而是在输入侧加可训练的虚拟 token：

  • Prompt tuning：只在输入最前面加一小串可训练的软提示向量，参数极少（只有 prompt 长度 × 维度），但对小模型效果不稳定；
  • Prefix-tuning：在每一层的键/值上各加一串可训练前缀，相当于每一层都有自己的"提示"，表达能力更强，参数也比 prompt tuning 多。

它们的软提示向量是连续的、不可读的，与人类写出的离散 prompt 不是一回事，本质是把"怎么提示模型"这件事交给梯度去学。

4. IA3：三个缩放向量#

IA3（Infused Adapter by Inhibiting and Amplifying Inner Activations）思路极简：在键、值、FFN 中间激活上各乘一个可训练缩放向量，通过放大/抑制内部激活来改变模型行为。它每层只加 3 个向量，参数比 LoRA 还少一个量级，却在 T0 基准上表现强劲。代价是它在某些任务上不如 LoRA 稳定，社区接受度也较低。

5. AdaLoRA：让秩自适应#

LoRA 给所有层用同一个固定秩 r，但不同层的重要性其实不同。AdaLoRA 把增量矩阵参数化为"奇异值分解"形式，并在训练中动态裁剪不重要的奇异值，让重要层获得更高秩、次要层降低秩。它在参数量预算相同的情况下往往优于固定秩的 LoRA，但实现复杂、超参更多，实践者通常先跑稳 LoRA 再考虑它。

6. 怎么选：一张选型速查#

  • 默认首选 LoRA/QLoRA：实现成熟、显存省、可插拔，社区生态最全；
  • 追求极致参数量：IA3；
  • 固定预算下榨性能：AdaLoRA；
  • 需要软提示风格 / 研究多任务组合：Adapter、AdapterFusion；
  • 研究"连续提示"本身：Prefix-tuning、Prompt tuning。

工程上几乎可以无脑从 LoRA 起步，遇到瓶颈再按上表换方法——因为 PEFT 的统一 API 让切换成本极低。

二、可运行代码示例#

PEFT 把切换方法变成"换一个 Config"。下面用同一个小模型，分别注入 IA3 和 Prefix-tuning，对比可训练参数量。依赖 transformers、peft。

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import IA3Config, PrefixTuningConfig, get_peft_model

model_id = "gpt2"
tokenizer = AutoTokenizer.from_pretrained(model_id)
tokenizer.pad_token = tokenizer.eos_token

# 1) IA3：在键/值/FFN 上各加一个缩放向量
ia3_config = IA3Config(
    target_modules=["c_attn", "c_proj", "mlp.c_fc"],  # GPT-2 的注意力与 FFN 层
    feedforward_modules=["mlp.c_fc"],                  # 标记哪些是 FFN 模块
    task_type="CAUSAL_LM",
)
base1 = AutoModelForCausalLM.from_pretrained(model_id)
ia3_model = get_peft_model(base1, ia3_config)
print("=== IA3 ===")
ia3_model.print_trainable_parameters()

# 2) Prefix-tuning：在每一层的键/值上各加一串可训练前缀
prefix_config = PrefixTuningConfig(
    task_type="CAUSAL_LM",
    num_virtual_tokens=20,        # 每层可训练的虚拟前缀 token 数
    encoder_hidden_size=64,       # 前缀编码器的小隐藏层
    prefix_projection=True,       # 用投影层稳定高维前缀的学习
)
base2 = AutoModelForCausalLM.from_pretrained(model_id)
prefix_model = get_peft_model(base2, prefix_config)
print("=== Prefix-tuning ===")
prefix_model.print_trainable_parameters()

# 3) 走一步前向，确认两种模型都能正常输出 logits
for name, m in [("IA3", ia3_model), ("Prefix", prefix_model)]:
    inputs = tokenizer("你好", return_tensors="pt")
    with torch.no_grad():
        logits = m(**inputs).logits
    print(f"{name} 输出形状：{tuple(logits.shape)}")

运行后你会看到：IA3 的可训练参数占比往往不到 0.1%（比 LoRA 还小），Prefix-tuning 则主要取决于 num_virtual_tokens。两者都能正常前向、产出 logits，但后续的保存、加载、合并流程与上一课的 LoRA 完全一致——这就是 PEFT 统一抽象带来的便利。

三、练习#

  1. 增大 num_virtual_tokens（如 20 → 100），观察 Prefix-tuning 可训练参数量的变化，思考前缀长度与显存、表达能力的关系。
  2. 用 IA3Config 和 LoraConfig 各注入一次 gpt2，对比两者的 trainable%，验证"IA3 参数比 LoRA 更少"。
  3. 查 PEFT 文档，找到 AdaLoraConfig 的可用参数（如 init_r、target_r），尝试注入并观察它与 LoraConfig 的差异。
  4. 用一个表格整理本课五种方法（Adapter / Prefix-tuning / Prompt tuning / IA3 / AdaLoRA）的"插入位置、可训练参数规模、主要优缺点"，作为你自己的选型备忘。
