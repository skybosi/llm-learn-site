Swin Transformer 等分层架构#

前两课我们看到 ViT 的两个先天短板：一是自注意力的平方复杂度，分辨率一高就算不动；二是全程保持单一尺度的特征（从第一层到最后一层都是 196 个 token、同一个分辨率），而检测、分割这些你熟悉的密集预测任务，恰恰需要"金字塔式"的多尺度特征——大物体看高层粗特征，小物体看低层细特征。Swin Transformer 的贡献，就是给 Transformer 装回了 CNN 那套"分层 + 多尺度"的骨架，同时用一个巧妙的"移位窗口"把注意力复杂度从平方降到线性。这一课我们重点讲 Swin，再顺带认识几个同族的分层架构，看清这条演进路线。

一、概念讲解#

1. 分层 + 多尺度：把"金字塔"还给 Transformer#

回顾 Mask R-CNN 里的 FPN：骨干网输出 C2/C3/C4/C5 多个尺度的特征图，供检测头在不同尺度上找目标。ViT 做不到这一点，它的输出从头到尾是同一分辨率。Swin 的做法是模仿 CNN 的"特征金字塔"：

  1. Patch Partition + Linear Embedding：先把图切成 4×4 的小补丁，投影到 C 维。
  2. 分阶段下采样：整个网络分 4 个 Stage。每进入下一个 Stage，就用 Patch Merging 把相邻 2×2 的补丁合并成一个，通道数翻倍（C → 2C → 4C → 8C），token 数量变为原来的 1/4。这等价于 CNN 里的"池化 + 通道翻倍"。

于是特征图从高分辨率小通道，逐步变成低分辨率大通道，形成四个尺度的金字塔。下游的检测/分割头（如 Mask R-CNN 的 RPN 与 FPN）可以直接挂在上面，几乎不改动就能复用——这正是 Swin 能迅速成为检测分割骨干网（Swin-T/S/B/L）的原因。

2. 窗口注意力：把平方降成线性#

全局注意力是 O(N²)。Swin 的解法是窗口（window）注意力：把特征图划分成不重叠的局部窗口（默认 7×7），注意力只在窗口内部计算。这样每个 token 只和同窗口的其余 token 交互，复杂度从 O(N²) 降为 O(N·W²)，W 是窗口边长，与全图尺寸无关，因此对分辨率是线性的。

但纯窗口注意力带来一个新问题：窗口之间互不相通，长距离依赖被切断了。于是有了 Swin 的点睛之笔——移位窗口（Shifted Window）：

  • 第 1 个 block 用普通窗口划分（W-MSA）；
  • 第 2 个 block 把窗口整体沿对角线方向偏移 (⌊W/2⌋, ⌊W/2⌋) 再划分（SW-MSA）。

两个 block 交替，上一层的窗口边界和下一层的错开，信息就能跨窗口流动。移位后窗口数量变多、大小不一，Swin 用循环移位（cyclic shift）+ 掩码注意力（masked attention）的工程技巧，在不真的拆散窗口的前提下完成高效计算。

3. 相对位置偏置：比绝对位置编码更稳#

第 1 课讲过，ViT 用绝对位置编码，一换分辨率就要插值，很脆弱。Swin 改用相对位置偏置：在注意力得分上，额外加一个只与"两个 token 在窗口内的相对偏移 (Δx, Δy)"有关的偏置项。因为相对位置的范围是有限的（窗口 7×7 内 Δx, Δy ∈ [-6, 6]），这张偏置表尺寸固定，与输入分辨率无关，天然支持任意分辨率输入。这个细节是 Swin 能在下游任务上平滑迁移的关键之一。

4. 同族的分层架构一览#

Swin 不是孤例，它代表了一条"给 Transformer 找回 CNN 结构"的主线，值得一起放进你的工具箱：

  • PVT（Pyramid Vision Transformer）：用空间缩减注意力（先把 K、V 做空间下采样再算注意力）来降复杂度，同样形成金字塔特征，是更早的"分层 ViT"之一。
  • DeiT：本身不分层，但用蒸馏（distillation）把 CNN 老师（如 RegNet）的知识喂给 ViT，让 ViT 在 ImageNet-1k 这种小数据上也能训好，破解了"ViT 必须海量数据"的魔咒。
  • CvT / Twins / CrossFormer：各自在"卷积 + 注意力混合""分组/局部注意力"上做文章，核心都是降低复杂度、引入多尺度。
  • ConvNeXt：反向的启示——按 Swin 的宏观设计（分层、窗口化、LayerNorm、GELU）反过来纯用卷积搭网络，发现也能追平 Swin。它提醒我们：很多时候提升来自结构设计，而不是"卷积 vs 注意力"的派别之争。

理解这条主线后你会发现，现代骨干网的竞争早已不是"卷积 vs Transformer"的二元对立，而是"如何用最合理的结构，拿到最强的多尺度表征"。

二、可运行代码示例#

先实现一个"窗口划分"函数，直观体会普通窗口和移位窗口的区别，再演示窗口注意力如何把复杂度降下来。

import torch
import torch.nn.functional as F


def window_partition(x, window_size):
    """把特征图划分成 window_size×window_size 的不重叠窗口。"""
    B, H, W, C = x.shape
    # 重塑成 (B, H//ws, ws, W//ws, ws, C)
    x = x.view(B, H // window_size, window_size, W // window_size, window_size, C)
    # 调换维度后合并：每个窗口变成一个独立的 token 序列
    windows = x.permute(0, 1, 3, 2, 4, 5).contiguous().view(-1, window_size * window_size, C)
    return windows  # (B * num_windows, ws*ws, C)


x = torch.randn(1, 8, 8, 4)          # 一个 8x8、4 通道的特征图
w = window_partition(x, window_size=4)
print("普通窗口划分后:", w.shape)      # (1*4, 16, 4) —— 4 个窗口，每个 4x4=16 个 token

接下来对比"全局注意力 vs 窗口注意力"的相似度矩阵尺寸，直观看到复杂度的下降：

def attention_scores(q, k):
    return q @ k.transpose(-1, -2)

N, C = 64, 16                        # 64 个 token，16 维
q = k = torch.randn(1, N, C)

# 全局注意力：每个 token 对全体 token 算相似度
scores_global = attention_scores(q, k)
print("全局注意力相似度矩阵:", scores_global.shape)   # (1, 64, 64)

# 窗口注意力：分成 4 个窗口，每个窗口 4x4=16 个 token，窗口内互相关注
windows = q.view(1, 4, 16, C)        # (1, 4 个窗口, 16 token, C)
scores_win = windows @ windows.transpose(-1, -2)
print("窗口注意力相似度矩阵:", scores_win.shape)     # (1, 4, 16, 16)

# 直观比较总的"注意力对"数量
print("全局注意力对:", N * N)                       # 64*64 = 4096
print("窗口注意力对:", 4 * 16 * 16)                 # 4 个窗口 * 256 = 1024

当 token 数量从 64 涨到 4096（比如大图 + 小补丁），全局注意力的代价是 4096²，而窗口注意力只按 窗口数 × 窗口大小² 线性增长——这就是 Swin 敢在高分辨率上跑检测分割的根本原因。

最后用 timm 一句话加载 Swin 骨干网，看看它作为下游骨干的接入方式：

import timm

# 加载 Swin-Tiny；features_only=True 会返回 4 个 Stage 的多尺度特征
model = timm.create_model("swin_tiny_patch4_window7_224", pretrained=False, features_only=True)
feats = model(torch.randn(1, 3, 224, 224))
print("Stage 数量:", len(feats))
for i, f in enumerate(feats):
    print(f"Stage {i} 特征形状:", f.shape)

运行后你会看到四个 Stage 的特征从 (1, 56, 56, 96) 一路降到 (1, 7, 7, 768)，通道数翻倍、分辨率减半，正是"特征金字塔"的形状——和 FPN 需要的多尺度输入严丝合缝。

  2. 用 timm 分别加载 vit_base_patch16_224 与 swin_tiny_patch4_window7_224，比较两者第一层 token 数量与一个 Stage 结束后的 token 数量，解释为什么 Swin 更适合作为检测分割的骨干网。
