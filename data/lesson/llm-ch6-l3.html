缓解方法#

幻觉无法被彻底根除，但可以大幅压制。本课讲几类最实用的缓解手段：检索增强生成（RAG）给模型"外挂事实"、约束提示让它学会说"不知道"、推理与验证让它自我纠错、以及解码与对齐层面的兜底。学完本课，你会拥有一套可落地的"防幻觉"工具箱。

一、概念讲解#

1. 检索增强生成（RAG）：先查再答#

幻觉的一大根源是模型"凭记忆硬编"。RAG（Retrieval-Augmented Generation）的思路很直接：不依赖模型的记忆，先从外部知识库检索相关文档，再把文档塞进提示里，让模型基于检索到的内容作答。

流程分三步：

  1. 建库：把权威文档切块、向量化，存入向量库。
  2. 检索：把用户问题也向量化，召回最相关的若干片段。
  3. 生成：把召回片段拼进提示，要求模型"仅依据这些资料回答"。

因为答案被锚定在检索到的真实文本上，模型"编"的空间被大大压缩。

2. 约束提示：允许模型"不知道"#

很多时候幻觉源于模型不愿承认自己不会。通过提示工程可以直接改善：

  • 明示"如果你不确定，请直接说'我不知道'，不要猜测"。
  • 要求"只依据给定材料回答，材料里没有的信息一律不说"。
  • 要求"给出依据/引用来源"，让编造无处遁形。

这类约束成本极低，应作为第一道防线。

3. 推理与验证：让它自己纠错#

  • 思维链 + 自一致性：多采样几条推理路径，投票筛掉少数错误路径（第 5 章已讲）。
  • 自我验证（self-verification）：让模型先作答，再让它扮演审查员检查答案的事实与逻辑，或要求它"反向推导验证"。
  • 外部工具：让模型调用计算器、代码执行器、搜索引擎，把"纯靠嘴算/嘴记"的部分交给可靠工具。

4. 解码与训练层面的兜底#

  • 降低 temperature：生成事实类内容时用低温（甚至贪心）解码，减少随机 token 带来的编造。
  • 训练层面：用 RLHF 对齐"诚实"（奖励"承认不知道"）、用更干净的数据、加入事实性偏好对，从源头降低幻觉倾向。
  • 事实性评估：用 TruthfulQA 等基准持续监控，量化缓解效果。

二、可运行示例#

下面实现一个迷你 RAG 系统：建库 → 检索 → 约束生成，再对比"不接地"与"接地"两种作答。

import re

# —— 1. 建库：权威文档切块（每块一段） ——
docs = [
    "水的沸点在标准大气压下是 100 摄氏度。",
    "北京是中华人民共和国的首都。",
    "太阳是太阳系的恒星，地球绕太阳公转。",
    "光速在真空中约为每秒 30 万公里。",
]

# —— 2. 检索：按关键词重叠召回最相关的片段 ——
def retrieve(question, top_k=1):
    q_words = set(re.findall(r"[\u4e00-\u9fffA-Za-z0-9]+", question))
    scored = []
    for d in docs:
        d_words = set(re.findall(r"[\u4e00-\u9fffA-Za-z0-9]+", d))
        scored.append((len(q_words & d_words), d))  # 简单共现打分
    scored.sort(reverse=True)
    return [d for _, d in scored[:top_k]]

# —— 3. 生成：mock 模型，grounded=True 时只用检索到的资料作答 ——
def mock_generate(question, use_rag):
    if not use_rag:
        return "水的沸点是 120 摄氏度。"          # 未接地：凭"记忆"硬编
    context = retrieve(question, top_k=1)[0]
    # 接地的模型：只从召回文档里提取答案，找不到就承认不知道
    m = re.search(r"是\s*(\d+\s*摄氏度)", context)
    answer = m.group(1) if m else "无法确定，我不知道。"
    return f"依据资料：{context}\n回答：{answer}"

question = "水的沸点是多少？"
print("【不接地】", mock_generate(question, use_rag=False))
print()
print("【RAG 接地】")
print(mock_generate(question, use_rag=True))

运行后对比鲜明：不接地的模型脱口而出"120 摄氏度"（幻觉）；RAG 接地的模型先召回"标准大气压下是 100 摄氏度"，再据此作答，并明确给出依据。真实 RAG 的差异只在检索用向量相似度、生成用真 LLM，"先查再答、答案有据"这个骨架完全一致。

三、练习#

  1. 换问题：把 question 换成"北京是哪个国家的首都？"和"太阳是什么？"，跑通 RAG 流程，确认检索能否正确召回对应文档。
  2. 改检索：retrieve 用词重叠打分太粗糙，改进它——例如同时统计重叠词数并除以问题长度做归一化，观察召回排序是否更准。
  3. 加"不知道"约束：为 mock_generate 增加一个分支：当召回文档与问题无关（重叠得分为 0）时返回"我不知道"，而不是硬答。
  4. 设计验证步骤：在 RAG 之后再加一步"自我验证"——让模型检查回答是否真的出现在召回文档里，输出"可信/存疑"。
  5. 组合拳：为一款"医疗问答助手"设计一套防幻觉方案，综合运用 RAG、低温解码、"不知道"约束与外部工具，说明每层各防住哪类幻觉。
