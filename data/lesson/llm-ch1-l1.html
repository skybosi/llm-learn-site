什么是 LLM#

学完注意力与 Transformer 之后，你已经掌握了注意力打分、QKV、多头、编码器解码器这些积木。这一课要回答一个"全景"问题：把这些积木堆大、堆多、再喂进海量文本，会得到什么？ 答案就是大语言模型（Large Language Model，LLM）。我们先从"语言模型"这个老概念讲起，再解释"大"究竟大在哪，以及它为什么突然展现出让人意外的能力。

一、概念讲解#

1. 语言模型：一台"预测下一个词"的概率机器#

语言模型（Language Model，LM）的定义其实很朴素：它给任意一段文本赋予一个概率，或者说，给定前面已经出现的 token 序列，预测下一个 token 的分布：

P(x_1, x_2, ..., x_n) = P(x_1) · P(x_2 | x_1) · P(x_3 | x_1, x_2) · ... · P(x_n | x_1, ..., x_{n-1})

这就是概率的链式法则。语言模型的核心，就是学习右边那一串"条件概率" P(x_t | x_<t)。你只要会"根据上文猜下一个词"，就能给整段文本打分，也能逐词地生成文本。

在神经网络之前，经典的 n-gram 模型用马尔可夫假设偷懒：下一个词只依赖前面 n-1 个词。它统计词频就能做，但 n 一大就面临组合爆炸，也记不住长距离的上下文。后来的 RNN 用隐状态把历史压缩成一个向量，第一次让模型"记住"整个前缀；但它串行计算、难以并行，长序列里梯度也容易出问题。最终，Transformer 的自注意力让每个位置都能直接"看向"所有历史位置，又完全可并行，成了现代语言模型的标准骨架——这些你在上一门课已经亲手实现过。

2. 加一个"大"字：规模是量变，也是质变#

大语言模型并没有发明什么全新的训练目标——它训练时做的事，和几十年前的 n-gram 本质一样，还是预测下一个 token。真正改变一切的是"大"，具体体现在三个维度：

  • 参数规模大：GPT-3 有约 1750 亿个参数，是 GPT-1（1.17 亿）的 1500 倍；
  • 训练数据大：语料从几亿 token 涨到数万亿 token，覆盖网页、书籍、代码、对话等；
  • 计算量大：训练一次动辄用数千块 GPU 跑数月，FLOPs 以 10^23 级别计。

同样的目标、同样的 Transformer 结构，只是把层数、宽度、数据量按数量级放大，模型就涌现出小模型完全没有的能力。这正是本章第 3 课要展开的"缩放定律"与"涌现能力"。

3. 为什么是"解码器"式的 Transformer#

现代 LLM 几乎都是仅解码器（decoder-only）架构，比如 GPT 系列。原因很直观：

  1. 因果掩码天然契合生成：每个 token 只能看到它自己之前的内容，这正好对应"根据上文猜下文"的自回归方式，训练与推理的设定一致；
  2. 结构简单、可扩展性强：没有编码器—解码器之间的交叉注意力，直接堆叠更多层、加宽即可，工程上容易规模化；
  3. 与"预测下一个词"的目标完美匹配：一个统一的目标，覆盖了几乎所有文本任务。

BERT 那一类仅编码器（encoder-only）模型则适合"读懂"整句（双向看上下文），更适合分类、抽取式问答等判别式任务——第 3 章会详细对比。

4. 一个目标，多种能力：LLM 的"意外"之处#

LLM 最反直觉的一点是：训练时它只学了一件事——预测下一个 token——但训练完成后，它却能翻译、问答、写代码、做摘要、甚至逐步推理。学界对此的解释主要有两点：

  • 上下文学习（in-context learning）：GPT-3 发现，只要在提示里给几个示例，模型不用改任何参数就能完成新任务（下一课的"第三范式"）；
  • 涌现能力（emergent abilities）：某些能力（如多步推理、指令跟随）在模型规模小于某个阈值时几乎没有，一旦跨过阈值就突然出现（第 3 课展开）。

5. "大"的三个支柱是相互制约的#

参数、数据、算力三者不是各涨各的：模型太大数据太少会过拟合、浪费参数；数据太多模型太小会"吃不下去"。它们之间的最优配比，正是 Chinchilla 缩放定律要回答的问题（详见本章第 3 课）。理解这一点，你就能看懂各家模型"为什么是这个尺寸"。

二、可运行代码示例#

先看最朴素的"语言模型"到底在算什么：用一段小语料手工统计"下一个字符"的概率。

from collections import defaultdict, Counter

# 一段很小的语料，纯粹为了讲清楚"语言模型 = 预测下一个 token"
corpus = "the cat sat on the mat. the dog sat on the log."
tokens = list(corpus)  # 简化：按字符切分；真实 LLM 用子词 token

# 1) 统计每个字符后面跟着的下一个字符，建立条件频数表
next_count = defaultdict(Counter)
for a, b in zip(tokens[:-1], tokens[1:]):
    next_count[a][b] += 1

# 2) 给定当前字符，返回下一个字符的概率分布
def next_char_dist(ch):
    c = next_count[ch]
    total = sum(c.values())
    return {b: cnt / total for b, cnt in sorted(c.items(), key=lambda kv: -kv[1])}

print("字符 't' 之后最可能出现的字符（概率）:")
for ch, p in next_char_dist('t').items():
    print(f"  {repr(ch)}: {p:.3f}")

运行后你会看到 't' 后面大概率是 'h' 或 'e'（来自 "the"），概率分布可解释、可生成。这就是语言模型的最小原型：一张"当前 token → 下一个 token 概率"的表。

真正的 LLM 把这件"猜下一个词"的事，交给了上千亿参数的神经网络：

import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

# 一个极小的 GPT-2，便于本地演示（首次运行会联网下载权重）
name = "sshleifer/tiny-gpt2"
tokenizer = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name)

prefix = "The capital of France is"
inputs = tokenizer(prefix, return_tensors="pt")

with torch.no_grad():
    logits = model(**inputs).logits        # [1, 序列长, 词表大小]
    next_logits = logits[0, -1, :]         # 只取最后一个位置的"下一个词"打分
    probs = torch.softmax(next_logits, dim=-1)  # 转成概率分布

# 打印概率最高的 5 个候选 token
topk = torch.topk(probs, k=5)
print(f"\n给定前缀 {prefix!r}，模型预测的下一个 token：")
for i, p in zip(topk.indices.tolist(), topk.values.tolist()):
    print(f"  {tokenizer.decode([i])!r}: {p:.4f}")

注意：代码里那句 next_logits = logits[0, -1, :] 与上面 bigram 里"查 't' 那一行"是同一件事——都是"给定上文，给出下一个 token 的分布"。差别只在：bigram 的表只有几十个字符，而 tiny-gpt2 要在一两万个词的词表上打分，GPT-3 则在 5 万多个 token 的词表、1750 亿参数上打分。

三、练习#

  1. 修改 bigram 代码，统计语料中 'a' 之后最可能的字符，并解释这个概率为什么"准"或"不准"（提示：语料太小、字符粒度太粗）。
  2. 加载 tiny-gpt2，把前缀换成 "Once upon a time"、"The result of 2 + 2 is"，观察 top-5 候选的变化，体会"下一个词预测"如何催生出叙事、计算等看似不同的能力。
  3. 用代码统计 tiny-gpt2 的参数量（sum(p.numel() for p in model.parameters())），对比课本中 GPT-3 的 1750 亿，体会"大"意味着什么。
  4. 思考题：为什么"预测下一个 token"这一个简单目标，能同时催生翻译、问答、代码生成？把你的想法写下来，学完本章第 2、3 课后再回来对照。
