参数对比#

LoRA 到底省了多少？本课把 LoRA 和全参数微调、其他 PEFT 方法放在一起，从可训练参数量、显存、速度、效果、存储几个维度做量化对比，并引入 QLoRA，帮你选型。

一、概念讲解#

1. 可训练参数量对比#

可训练参数量直接决定显存和优化器开销。以 70 亿参数（7B）模型为例，不同方法的可训练参数量级大致如下：

方法 可训练参数占比 7B 模型可训练参数量级
全参数微调 100% 70 亿
Adapter ~1%–5% 千万～数亿
LoRA（r=8） ~0.1%–0.5% 数百万
Prefix/Prompt Tuning <0.1% 数十万

LoRA 的参数量主要由 r × (d+k) × 挂载层数 决定。r 越大、挂的模块越多，参数越多、表达力越强，但收益递减。

2. 显存对比#

显存节省是 LoRA 最大的工程收益。全参数微调要为每个参数存梯度 + Adam 状态（fp32 下动量和方差各 4 字节），而 LoRA 只为 A、B 这些少量参数存这些。结论：

  • 训练显存：LoRA 相比全参数微调，通常能省下 60%–80% 的显存，让原本需要多卡的模型在单卡上可训。
  • 推理显存：合并后推理显存与基座模型一致；不合并则多出极少量旁路参数。

3. 速度与效果对比#

  • 训练速度：LoRA 单步计算量略增（多了低秩旁路），但省下的显存允许更大 batch，整体吞吐常常不降反升；反向传播只为少量参数算梯度，速度也更快。
  • 效果：在多数 SFT 任务上，LoRA 的效果能逼近甚至持平全参数微调，尤其在数据量中等、任务与预训练分布差距不悬殊时。当领域差距特别大、或数据极多时，全参数微调仍有优势上限。

4. LoRA vs QLoRA#

QLoRA 在 LoRA 基础上进一步量化：把冻结的基座权重量化到 4-bit（NF4），并配合双重量化、分页优化器（paged optimizer）等技巧，把显存压到极致。它让在单张消费级显卡（如 24GB）上微调 7B 甚至更大模型成为可能，是 LoRA 的"穷人版加强版"。

代价是：4-bit 量化会带来轻微精度损失、训练稍慢，且需要 bitsandbytes 支持。多数资源受限场景，QLoRA 是首选。

5. 存储与工程对比#

维度 全参数微调 LoRA QLoRA
每任务存储 一份完整模型（数 GB~数十 GB） 一份适配器（几 MB~几十 MB） 同 LoRA
任务切换 换整份权重 换适配器，共用一个基座 同 LoRA
训练硬件门槛 高（多卡） 中（单卡） 低（消费级单卡）
灾难性遗忘风险 较高 低 低
效果上限 高 接近 略低于 LoRA（量化损失）

6. 选型建议#

  • 追求极限效果、算力充足、任务单一 → 全参数微调。
  • 单卡、多任务并行、快速迭代、预算有限 → LoRA / QLoRA。
  • 资源极度受限、任务简单 → 可尝试 Prompt/Prefix Tuning，或直接用提示工程。

一句话总结：LoRA 以约 1% 的可训练参数和更低的显存门槛，换来了接近全参数微调的效果，是当前性价比最高的微调路线；QLoRA 进一步把门槛降到消费级硬件。

二、可运行代码示例#

下面用代码量化对比"全参数微调 vs LoRA"的可训练参数与训练显存估算。

from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

model_name = "Qwen/Qwen2.5-0.5B"     # 0.5B 模型，便于快速统计
base = AutoModelForCausalLM.from_pretrained(model_name)

# 全参数微调：所有参数都可训练
total_params = sum(p.numel() for p in base.parameters())
print(f"模型总参数量: {total_params/1e6:.1f} M")
print(f"全参数微调可训练参数: {total_params/1e6:.1f} M（100%）")

# LoRA：只训练低秩增量 A、B
lora_model = get_peft_model(
    base,
    LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"], task_type="CAUSAL_LM"),
)
trainable = sum(p.numel() for p in lora_model.parameters() if p.requires_grad)
print(f"LoRA(r=8) 可训练参数: {trainable/1e6:.2f} M（{trainable/total_params*100:.2f}%）")

再估算训练时的显存差异。这里用一个简化的经验模型：全参数微调需要为每个参数存梯度 + 两份 Adam 状态，而 LoRA 只为少量可训练参数存这些。

def estimate_training_memory(total_params, trainable_params, bytes_per_weight=2, bytes_per_state=4):
    """粗略估算训练显存（忽略激活值）：权重 + 梯度 + 优化器状态"""
    # 权重：bf16 存全部参数
    # 梯度：只对可训练参数存
    # Adam 状态（动量 + 方差）：只对可训练参数存，各 fp32
    mem_weight = total_params * bytes_per_weight
    mem_grad = trainable_params * bytes_per_weight
    mem_adam = trainable_params * bytes_per_state * 2   # m + v
    return (mem_weight + mem_grad + mem_adam) / 1e9     # 转 GB

full_mem = estimate_training_memory(total_params, total_params)
lora_mem = estimate_training_memory(total_params, trainable)
print("\n训练显存估算（不含激活值，单位 GB）：")
print(f"  全参数微调: {full_mem:.2f} GB")
print(f"  LoRA(r=8):  {lora_mem:.2f} GB")
print(f"  节省比例:   {(1 - lora_mem/full_mem)*100:.0f}%")
print("\n（真实值还需加上激活值、量化等；此估算只用于展示差距的量级）")

三、练习#

  1. 填空：QLoRA 在 LoRA 基础上把冻结的基座权重量化到 ____ 位（NF4），从而把训练门槛降到 ____ 级显卡；代价是轻微的 ____ 损失。
  2. 判断：下列说法是否正确？
    • (a) LoRA 的可训练参数越多（r 越大、挂载模块越多），效果一定越好。
    • (b) LoRA 合并后，推理显存与基座模型一致。
    • (c) 全参数微调在每个任务上的效果都必然优于 LoRA。
  3. 动手实验：把上面代码里 LoRA 的 r 依次改成 4、16、64，记录可训练参数量；再把 target_modules 加上 "k_proj", "o_proj"，观察参数如何变化。体会"r 和挂载范围"如何影响成本。
  4. 思考题：为什么 QLoRA 能在 24GB 显卡上微调 7B 模型，而全参数微调做不到？结合"冻结权重 + 4bit 量化 + 只训练低秩增量"三点说明。
