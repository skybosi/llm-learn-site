核心实现（RAG 问答系统）#

本课实现 RAG 的四段核心管线：文档切块 → 向量化 → 检索 → LLM 生成。每一步都不止"能跑"，而要能解释"为什么这么选"，并预留可对比的开关，供下一课做实验评估。

一、目标与步骤#

  1. 文档切块：实现可配置的大小/重叠切分，理解切块对检索的影响。
  2. 向量化：把文本块编码成向量，说明 embedding 选型。
  3. 检索：实现相似度检索与 MMR 去重，输出带来源的片段。
  4. LLM 生成：写一个"强制引用"的提示词模板，让答案逐句有据可查。

二、代码骨架与实现指导#

1. 文档切块（chunking）#

切块是 RAG 最容易被忽略、却影响最大的环节。核心权衡：块太大→上下文噪声多、embedding 语义被稀释；块太小→信息断裂、一条事实被切散。中文文档建议从 chunk_size=512、overlap=64 起步：

from llama_index.core.node_parser import SentenceSplitter
from llama_index.core import SimpleDirectoryReader

documents = SimpleDirectoryReader("data/docs", recursive=True).load_data()

def chunk_documents(documents, chunk_size=512, overlap=64):
    """按字符切块，块间重叠 overlap 以避免把关键句从中间切断。"""
    parser = SentenceSplitter(chunk_size=chunk_size, chunk_overlap=overlap)
    nodes = parser.get_nodes_from_documents(documents)
    # 每个节点携带来源元数据（文件名/页码），供"引用"使用
    for n in nodes:
        n.metadata.setdefault("source", n.metadata.get("file_name", "unknown"))
    return nodes

nodes = chunk_documents(documents)
print(f"共 {len(nodes)} 个节点；平均长度 {sum(len(n.text) for n in nodes)/len(nodes):.0f} 字符")

# 直观检查切块质量：打印一个节点，确认它语义完整、没有把标题孤零零切出去
print("示例节点:\n", nodes[5].text[:200])

面试要点：能说出"我用 512/64 是因为中文平均一段话的语义单元大约在这个量级，且 overlap 保证跨块断点不被切断"。下一课会做 256/512/1024 的对比实验来验证这个选择，而不是拍脑袋。

2. 向量化#

from llama_index.embeddings.huggingface import HuggingFaceEmbedding

# 中文开源 embedding：bge 系列在中文检索评测中表现好，且可本地部署
embed_model = HuggingFaceEmbedding(
    model_name="BAAI/bge-small-zh-v1.5",
    # 若显存/内存紧张可换成 bge-small；追求效果换 bge-base/large
)
# 对 query 与 document 是否用不同前缀：bge 系列建议 query 加 "为这个句子生成表示"
# （通过 query_instruction 传入，部分封装已内置，务必查你的版本是否自动处理）

选型理由要落在"中文 + 本地 + 效果/成本平衡"三点上；如果项目跑在服务器、预算充足，可换 bge-large-zh-v1.5 或 API embedding，并说明换了会带来什么收益。

3. 构建索引与检索#

from llama_index.core import VectorStoreIndex, StorageContext
from llama_index.vector_stores.chroma import ChromaVectorStore
import chromadb

# 建索引并持久化（lesson-01 已给过，这里补充"可复现"细节）
db = chromadb.PersistentClient(path="data/chroma_db")
collection = db.get_or_create_collection("rag_docs")
vector_store = ChromaVectorStore(chroma_collection=collection)
index = VectorStoreIndex(nodes, embed_model=embed_model,
                         storage_context=StorageContext.from_defaults(vector_store=vector_store))

# 检索器：similarity_top_k 控制召回数量，决定后续生成看到的上下文量
retriever = index.as_retriever(similarity_top_k=5)

# MMR 检索：在相似度之外加入"多样性"，避免返回 5 个几乎重复的片段
from llama_index.core.retrievers import VectorIndexRetriever
from llama_index.core.postprocessor import SimilarityPostprocessor

mmr_retriever = VectorIndexRetriever(
    index=index, similarity_top_k=10,  # 先多召回
)
# 后处理：相似度阈值过滤 + （可选）重排序
postprocessor = SimilarityPostprocessor(similarity_cutoff=0.3)

检索质量是 RAG 的天花板：生成再强，也救不回检索错的内容。所以这里多召回（top-k=10）再过滤/重排，比"只取 3 个最相似"更稳。

4. LLM 生成（带引用的提示词）#

核心是让模型只能依据检索片段回答，并逐条标注来源编号：

from llama_index.core import get_response_synthesizer
from llama_index.core.prompts import PromptTemplate

# 自定义提示词：强制"逐句引用"，回答不了就明说，不许编造
QA_TEMPLATE = """你是一名严谨的文档问答助手。请仅依据下面提供的【参考资料】回答问题。

规则：
1. 只使用参考资料中的信息，禁止使用你的先验知识补充或猜测。
2. 每个关键结论后面用 [来源N] 标注出处，N 对应参考资料编号。
3. 如果资料不足以回答，直接说"根据现有资料无法确定"，不要编造。

【参考资料】
{context_str}

【问题】
{query_str}

【回答】"""

qa_prompt = PromptTemplate(QA_TEMPLATE)
synth = get_response_synthesizer(text_qa_template=qa_prompt)

def answer(query):
    """检索 + 生成，返回带引用的回答与命中的来源片段。"""
    retrieved = mmr_retriever.retrieve(query)
    # 拼上下文时带上编号，供引用标注对齐
    context = "\n\n".join(
        f"[来源{i+1}] {n.text}" for i, n in enumerate(retrieved)
    )
    response = synth.synthesize(query, retrieved)
    return {
        "answer": str(response),
        "sources": [n.metadata.get("source") for n in retrieved],
        "context": context,
    }

result = answer("框架里如何自定义一个检索器？")
print("回答:\n", result["answer"])
print("来源:", result["sources"])

若生成端想换成 API（OpenAI 兼容），只需替换 LLM 对象；若用本地 Qwen，用 HuggingFaceLLM 加载 7B 模型。生成端的选择独立于检索端，这正是 RAG 可插拔的工程价值。

5. 组装成可演示的接口#

# 一个极简的查询入口，便于在终端/前端演示
if __name__ == "__main__":
    while True:
        q = input("\n请输入问题（q 退出）: ").strip()
        if q.lower() in {"q", "quit", "退出"}:
            break
        out = answer(q)
        print("\n" + out["answer"])
        print("\n--- 引用来源 ---")
        for s in out["sources"]:
            print(" *", s)

三、验收与复盘#

  1. 切块质量验收：抽查 5 个节点，确认每个节点语义完整、来源元数据正确。
  2. 检索 smoke test：拿 3 个已知答案的问题测检索，肉眼判断 top-5 里是否包含答案片段。
  3. 引用对齐验收：随机看 3 个回答，确认每个 [来源N] 都真实对应一条检索片段，且内容支持结论。
  4. 可对比性验收：切块大小、top-k、是否 MMR 都已做成参数，便于下一课跑对比实验。
  5. 复盘提示：记录你发现并修复的第一个问题（例如"默认切块把表格切散了""MMR 后命中率反而不如纯相似度"），这些"踩坑记录"是面试最真实的素材。
