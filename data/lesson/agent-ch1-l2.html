误差累积与目标漂移：为什么"让模型自己循环"会放大错误#

这一节要解决什么#

上一节把 LLM 看成一个随机的纯函数，并指出 Agent 是"在模型外补上循环与状态"。于是所有人都想做同一件事：把它循环起来 —— 让模型自己决定下一步、自己调工具、自己判断做完没有。

循环确实是 Agent 的定义性特征，但循环有一个坏的数学性质：它把每一步的错误乘起来。这一节要把这件事算清楚，而不是停留在"闭环会放大误差"这种口号上。具体要回答：

  1. 误差到底是怎么累积的？能不能给出一个可算的表达式，而不是一句"越跑越偏"？
  2. "失败"和"漂移"为什么是两类不同的问题？为什么后者更难？
  3. 哪些工程手段能改变这个乘积，哪些只是心理安慰？
  4. 在什么条件下"误差累积"这个悲观结论不成立（也就是：什么时候循环其实很安全）？

这是本章第一个难点。之所以要写得长，是因为后面所有章节的"为什么"都挂在这里：终止条件（第 2 章）、幂等与补偿（第 3 章）、状态显式化与重放（第 4 章）、回退粒度（第 5 章）、失效归因（第 7 章），全部是在和这一节的乘积搏斗。

一、先把"一步"定义清楚#

"单步正确率 p" 这个说法在工程上太含糊 —— 含糊的度量会导出错误的结论。先把一步拆开：

一步（step）由四件事组成：

感知：把工具结果 / 环境反馈转成模型可读的输入      → 可能失真（截断、格式转换丢了字段）
决策：模型选择下一个动作（调哪个工具、传什么参）    → 可能选错
执行：真正调用工具并得到结果                      → 可能失败（超时、限流、5xx）
解释：模型读懂结果，决定下一步                     → 可能误读

于是"这一步正确"其实是一个复合事件：

p=p感知​⋅p决策∣感知​⋅p执行​⋅p解释∣结果​

第一个反直觉的结论：单步正确率往往被执行和感知这两个"非模型"环节拖累，而不是被模型拖累。一个 p决策​=0.98 的模型，如果工具超时率 5%、结果截断导致 4% 的关键字段丢失，实际单步正确率是：

0.96×0.98×0.95×1.0≈0.894

比模型的"智力水平"低了近 9 个百分点。这解释了一个常见现象：换更强的模型没救活这个 Agent，但把工具超时重试做对，救活了。 因为瓶颈不在决策环节。

⚠️ 常见的错误归因：把"Agent 不靠谱"一律归结为"模型不够强"。用上面的乘积拆一次，就能知道该往哪儿投工程预算 —— 这也是第 7 章"失效归因四象限"要系统化的东西。

二、误差累积：一条轨迹的成功率#

设轨迹长度为 n（模型做了 n 次决策），每步独立地以概率 p 正确。那么"整条轨迹每一步都正确"的概率是

Pn​=pn

这就是上一节给出的式子。现在把它算透，而不是只看三行表。

2.1 指数衰减的"半衰期"#

对 Pn​=pn 取对数，得到期望的正确决策步数（average correct horizon）：

n1/2​=lnpln0.5​

单步正确率 p 半衰期 n1/2​（步） 20 步全对 50 步全对
0.90 6.6 0.12 0.005
0.95 13.5 0.36 0.077
0.97 22.8 0.54 0.22
0.99 69.0 0.82 0.61
0.995 138.3 0.90 0.78

这张表比"pn 很小"有力得多，它给了一个设计尺子：如果你的任务天然需要 20 步，那么 p=0.95 的系统半衰期只有 13.5 步 —— 任务长度已经超过系统的半衰期，它在结构上就不可能可靠，无论你怎么调提示词。此时唯一有效的方向是：把 p 推到 0.99 以上（半衰期 69 步），或把任务切成几段各自重置。

2.2 为什么"提升单步质量"的收益是超线性的#

对 lnp 在 p=1 附近展开：lnp≈−(1−p)−2(1−p)2​−⋯，于是

lnPn​=nlnp≈−n(1−p)(1+21−p​)

也就是说，成功率对错误率 e=1−p 是近似指数敏感的：

Pn​≈e−ne

任务步数 n e=0.05 e=0.03 e=0.01
10 0.61 0.74 0.90
20 0.37 0.55 0.82
50 0.08 0.22 0.61

把错误率从 5% 压到 1%（5×），在 20 步任务上成功率从 37% 提到 82%（2.2×）—— 收益被步数放大。这给了工程上一个明确的杠杆排序：

杠杆 作用对象 典型手段 代价
降 e 单步 工具契约清晰、参数校验、结果结构化、少歧义指令 设计成本；有时要牺牲灵活性
降 n 轨迹 任务分解、并行子任务、一次性批量取回上下文 分解本身会引入协调误差
破坏乘性 整个乘积 检查点、重试、回退、幂等 成本与状态管理复杂度

2.3 这个模型什么时候过于悲观#

Pn​=pn 的假设是每步独立、错误不可恢复、错误必然致命。三条都不成立时它会严重低估真实成功率。逐条拆：

  1. 错误可检测。如果某一步的错误会立刻表现为工具报错或格式不合法，那么它不会污染后续步骤，而是触发重试。设错误的可检测率为 d，重试次数为 k，则单步有效错误率变为

eeff​=e(1−d)k

此时 Pn​≈e−ne(1−d)k。注意 (1−d)k 是乘性的：d=0.9 时重试 2 次就把它压到 10−2 量级。这就是"检查点比聪明更重要"的数学依据。

  1. 错误不必然致命。很多任务允许多条正确路径（p 实际上是"走向某个可接受状态"的概率，不是"唯一正确动作"的概率）。此时正确的建模是吸收马尔可夫链：状态空间里有一个"目标集合"，Pn​ 应换成"n 步内命中目标集合的概率"，它会显著高于 pn。

  2. 错误是相关的，不是独立的。模型在同一上下文里犯的错往往同源（同一个误解、同一段被截断的文档），此时独立性假设失效，误差可能成串出现，累积比 pn 更快。这是下一节"漂移"要处理的。

所以正确的态度是：pn 是量级估算与设计尺子，不是预测器。 它的价值在于告诉你"任务长度和单步质量必须匹配"，以及"哪一类手段真正改变了乘积"。

三、目标漂移：不报错的失败#

pn 描述的是"某一步错了"，但真实的 Agent 更常死于另一种模式：每一步都在合法地做某件事，但整条轨迹已经偏离了原始目标，而且没有任何一步报错。

这就是目标漂移。它与"失败"的区别是本质性的：

失败（failure） 漂移（drift）
表现 报错、异常、无法继续 一切正常，继续执行
可检测性 高（有信号） 低（无信号，需外部判据）
归因 局部（找到那一步） 全局（要对比目标与当前状态）
处置 重试 / 换工具 重新对齐目标 / 回滚到分叉点
成本 一次重试 可能要走完剩余步数才发现白干

3.1 为什么会出现漂移：三个机制#

机制一：子目标置换（subgoal substitution）。 模型把"达成目标的某个手段"当成了目标本身。典型表现：

原始目标：把这份报告发给客户
第 2 步：发现报告文件格式是 .docx，需要转 PDF
第 3 步：本机没有转换工具
第 4 步：开始研究如何安装 LibreOffice     ← 漂移发生在这里，且没有任何报错
第 9 步：成功装好了转换工具 —— 任务"完成"，但报告始终没发出去

每一步都正确（p 很高），整条轨迹"成功"了，但目标是错的那个。这是 pn 模型完全看不见的失败模式。

机制二：局部最优吸引子。 如果循环里有"反思/自评"环节，模型倾向于选择容易做对的事而不是该做的事。这有一个可控性上的后果：自评打分 s^ 与真实进展 s 之间有偏差，循环会朝 s^ 增大的方向走 —— 而 s^ 的最大值点未必是任务的完成点。可以写出一个漂移动力学：

θt+1​=θt​−η∇θ​s^(θt​)

其中 θ 表示"任务状态的语义坐标"（当前在做的事在语义上离目标的距离）。s^ 是模型自评，它与真实目标函数 s 的偏差 ϵ(θ)=s^−s 会把不动点从 s 的最优点推到 s^ 的最优点。只要 s^ 系统性地偏好某类"看起来像进展"的动作（重写总结、反复读文件、格式美化），循环就会稳定停在那儿。

机制三：误差进入状态并自我强化。 这是最隐蔽的一种，因为它有一个可推导的下界。设状态向量 xt​ 的更新为

xt+1​=f(xt​,at​)+ξt​

其中 ξt​ 是每步的行动/解释误差。若 f 的 Lipschitz 常数 L>1（迭代映射在放大差异），则误差被放大：

∥δxt+1​∥≈∥Jf​δxt​∥≤L∥δxt​∥⟹∥δxt​∥≤Lt∥δx0​∥

指数放大。而若 L<1（收缩映射，如带裁剪的归一化状态），误差会被自然阻尼，漂移有界：

∥δx∥∞​≤1−Lsupt​∥ξt​∥​

这是本节最重要的设计结论之一：漂移是否失控，取决于状态更新映射是扩张还是收缩。Agent 设计里因此有两条对立的策略：

  • 让状态收缩：结构化状态（受限字段、枚举、归一化数值）、每步重写摘要而不是追加。
  • 让状态可追溯：完整追加日志、可重放。它本身是扩张的（历史只会增长），所以必须额外配一个"当前状态"的收缩视图。

这也是第 4 章"工作记忆 vs 长期记忆"分离的数学动机：一个扩张的审计日志 + 一个收缩的工作状态。

3.2 漂移的度量：怎么把"偏了多少"变成数#

漂移不是可观测信号，所以必须人为构造一个判据。三种可用的度量：

(a) 语义距离。 令 g 为原始目标的嵌入向量，g^​t​ 为"当前计划/当前状态"的嵌入，则

driftt​=1−cos(g,g^​t​)

在无纠偏的随机游走假设下，E[driftt​]≈1−e−t/τ，τ 由每步的语义扰动幅度决定 —— 即漂移随时间趋于饱和，这符合直觉（走远到一定程度就完全无关了）。

(b) 约束违反计数。 把目标的硬约束列成可检查的谓词集合 C={c1​,…,cm​}（"必须包含 X 字段"、"不得修改 Y 表"、"总花费 ≤ Z"）。定义

violationst​=j=1∑m​1[¬cj​(xt​)]

这是工程上最实用的漂移度量，因为它可执行、无歧义、可以每一步检查。语义距离只能给趋势，约束谓词能在违规的当步就报警。

(c) 进展速率。 定义每步的进展 Δt​=s(xt+1​)−s(xt​)。若连续 w 步 Δt​≤0，判定为停滞（stall）：

stall⟺i=t−w+1∑t​Δi​≤0

停滞检测比"看是否完成"更早给出信号：漂移的典型征兆不是变慢，是原地空转。

度量 能发现什么 代价 什么时候失效
语义距离 方向性偏离 需嵌入模型 + 目标嵌入 目标本身模糊时无意义
约束谓词 硬性越界 需把目标写成可执行约束 约束写不全 → 假安全感
进展速率 空转 / 死循环 需一个可算的进展函数 进展函数本身容易被模型"刷分"

⚠️ 三者的共同陷阱：它们都是你在循环外定义的。一旦你把其中任何一个交回给模型自评（"你觉得你偏离目标了吗？"），它就退化成机制二里的 s^，会被局部最优吸引子俘获。判据必须在循环外。

四、把两者接起来：失败与漂移的联合失效模型#

真实 Agent 同时受两者影响。定义整条轨迹的"可接受"概率：

Pok​=pnP(无致命错误)​​×driftn​<δP(无致命漂移)​​

第二项在约束谓词模型下可以用一个粗略的存活模型估计。设每步违反任一硬约束的概率为 q（且违反即不可接受），则

Pok​≈(1−q)npn=(p(1−q))n

这个式子的意义：漂移的风险与错误的风险在指数上相加。如果每步有 2% 的概率产生"合法但越界"的偏离，那么在 20 步任务上它单独就把成功率压到 0.9820=0.67 —— 和单步错误率的杀伤力同量级。而它更危险的地方在于：漂移不报错，所以你不会去修它。

现象 归因 该改什么
Agent 20 步任务成功率只有三成 误差累积 降 e、降 n、加检查点与重试
Agent 跑完了但结果不对，日志里没错误 目标漂移 加外部判据（约束谓词）、加目标对齐检查点、缩短单段轨迹
同一个任务重跑两次结果差很多 高方差（p 不稳定） 减少歧义、固定解码、结构化输出

第三行值得单独说：方差. 上表里 p 一直被当成常数，但真实系统的 p 是一个随机变量。成功率的一阶矩相同不代表可用性相同 —— 一个"平均 80%、但分布从 50% 到 95%"的系统，比一个"稳定 80%"的系统难运维得多，因为你无法通过重试获得确定性，也无法给出 SLA。这直接引出第 4 节的"可靠性 = 成功率 + 方差"这条度量定义。

五、工程上真正能改变乘积的五件事#

把上面的数学翻译成可执行的设计。按"性价比"排序：

① 让错误变可检测（提高 d）。 这是最便宜的杠杆。手段：工具返回结构化错误码而不是散文；参数在执行前 schema 校验；关键步骤要求模型输出可验证的断言（"我确认文件已写入，路径是 X"——然后你去 stat 这个路径）。检测率的每一分提升都被 k 次重试以 (1−d)k 放大。

② 缩短单段轨迹（降 n）。 任何需要 50 步的任务，都应该被切成 5 段各 10 步，段间加显式检查点。注意这里有个真实的取舍：分段会引入段间接口误差（子任务的输入输出约定可能失真），所以分段不是免费的 —— 段太长则累积，段太短则接口成本占比过高。经验判据：让每段的 n 不超过系统半衰期的 1/3。

③ 加外部判据（对付漂移）。 把目标的硬约束写成可执行谓词，每一步都检查，违反即中断（而不是继续跑完再看）。这一步没有任何模型参与，因此免疫局部最优吸引子。

④ 让状态更新收缩（对付机制三）。 工作状态用受限结构（字段固定、枚举、归一化），而不是自由文本不断追加。审计日志可以扩张，但决策只看收缩视图。

⑤ 让动作可撤销（破坏不可逆性）。 这是第 3 章幂等 / 第 5 章回退的动机：如果每个高副作用动作都有补偿操作，那么"错误已进入状态"就从不可逆变成可逆，Lt 的指数放大就被截断在一次补偿之内。可回滚是唯一能从根上打断漂移指数放大的手段。

反过来，没有用的三件事（避免在这上面浪费预算）：

  • 把提示词写得更长更啰嗦：可能降低 e，但只要它同时增加了上下文歧义，p 不一定升。
  • 让模型"再想一遍"：若自评 s^ 有偏，这会加剧机制二（局部最优吸引子）。
  • 单纯加大步数预算：n 的上限提高必然降低 (p(1−q))n。除非同时引入检查点，否则"给它更多步"就是"给它更多机会跑偏"。

六、一个反直觉的结论：短暂停机的 Agent 更可靠#

由第三节的机制三出发可以得到一个略微反直觉的设计原则：允许 Agent 暂停并向外部（人 / 校验器）查询，会同时改善 p 和漂移。

设每次"询问外部"以概率 r 打断漂移（把状态重置回最后一个已验证检查点），代价是 c 的额外延迟/成本。修后的有效错误率变为 e′=e(1−r)，轨迹长度有效值变为 n′=n(1−ρr)（ρ 为漂移导致的无效步数占比）。于是

Pok′​≈e−n(1−ρr)⋅e(1−r)

它在 r 上的导数为正直到某个点 —— 即存在一个最优的"外部求助率"，既不是 0（完全不问）也不是 1（每步都问）。这个最优点就是第 4 节"可靠性 vs 成本可控"冲突的具体形态：多问一次更稳，但更贵。

代码：把上两节的量算出来（可运行）#

下面的代码不调用任何 API，只做两件事：把误差累积/漂移的乘积算出来，并给出一个"这套系统在这个任务长度上还能不能用"的判据。注意每一处注释标注的是设计决策，不是实现细节。

import math
from dataclasses import dataclass

@dataclass
class StepModel:
    """把'单步正确率'拆成四个环节 —— 这是归因的前提（见第 7 章四象限）。"""
    p_perceive: float = 0.97   # 感知：结果结构化/截断是否会丢字段
    p_decide:   float = 0.98   # 决策：模型选对动作
    p_execute:  float = 0.99   # 执行：工具成功返回
    p_interpret:float = 1.00   # 解释：读懂结果

    @property
    def p(self) -> float:
        return self.p_perceive * self.p_decide * self.p_execute * self.p_interpret

    def bottleneck(self) -> str:
        """瓶颈定位：最小的那一环才是该投工程的地方。"""
        pairs = {"感知": self.p_perceive, "决策": self.p_decide,
                 "执行": self.p_execute, "解释": self.p_interpret}
        return min(pairs, key=pairs.get)

def half_life(p: float) -> float:
    """半衰期：任务长度超过它，系统结构上就不可靠（ln0.5/ln p）。"""
    return math.log(0.5) / math.log(p)

def success_rate(p: float, n: int, detect: float = 0.0, retries: int = 0,
                 q_drift: float = 0.0) -> float:
    """
    P_ok ≈ (p * (1-d)^k * (1-q))^n
      detect/retries：错误可检测 + 重试 → 把错误率乘性压低
      q_drift       ：每步'合法但越界'的概率 —— 漂移风险与错误风险在指数上相加
    设计决策：把漂移显式建模进来，因为它在真实系统里不报错、最容易被忽略。
    """
    e_eff = (1 - p) * (1 - detect) ** retries
    p_step = (1 - e_eff) * (1 - q_drift)
    return p_step ** n

def design_check(p: float, n: int, n_segments: int = 1) -> dict:
    """
    判据：单段长度不应超过半衰期的 1/3。
    分段会引入段间接口误差（这里用 0.98 的固定损耗近似），所以要给出净收益。
    """
    seg_len = n / n_segments
    h = half_life(p)
    iface_loss = 0.98 ** n_segments           # 段间接口误差（近似）
    return {
        "单段长度": seg_len,
        "半衰期": round(h, 1),
        "单段是否过长": seg_len > h / 3,
        "不分段成功率": round(p ** n, 4),
        "分段后成功率": round((p ** seg_len * iface_loss), 4),
        "建议": "分段" if (p ** seg_len * iface_loss) > p ** n else "不分段",
    }

if __name__ == "__main__":
    m = StepModel()
    print(f"实际单步正确率 p = {m.p:.4f}，瓶颈环节 = {m.bottleneck()}")
    print(f"半衰期 = {half_life(m.p):.1f} 步")

    for n in (10, 20, 50):
        base = success_rate(m.p, n)
        fixed = success_rate(m.p, n, detect=0.9, retries=2)   # 只有'可检测+重试'
        drift = success_rate(m.p, n, detect=0.9, retries=2, q_drift=0.02)  # 再加漂移
        print(f"n={n:>3}  裸跑 {base:.3f}  加检测重试 {fixed:.3f}  再加漂移 {drift:.3f}")

    print(design_check(m.p, n=30, n_segments=3))

这段代码想让你看到的三件事（而不是让你抄）：

  1. StepModel 把 p 拆开，是为了让"该修哪个环节"变成一个可计算的问题 —— bottleneck() 直接给答案。
  2. success_rate 里的 (1-detect)**retries 与 (1-q_drift) 是两类不同的杠杆：前者作用于错误率，后者作用于漂移。把它们写在一起，是为了让"只修了一类"的后果在数字上可见。
  3. design_check 里特意让分段带一个接口损耗。不做这件事的分段建议是耍流氓 —— 真实的分段永远有代价。

练习#

  1. 半衰期对齐：你的 Agent 单步正确率 0.94，任务是"读完 12 个文件、抽取字段、写一份汇总"。估算它需要多少步？算出半衰期，判断这个任务在结构上做不做得成。若做不成，给出两条不同方向的修复方案（一条降 e，一条降 n），并说明各自要付出什么代价。
  2. 归因练习：某 Agent 线上成功率从 82% 掉到 61%，日志里没有一条异常。给出三个互斥的假设（分别对应：p 下降、q 上升、p 的方差上升），并设计一个能区分它们的最小实验（提示：要控制变量，不能只看总成功率）。
  3. 推导：证明当 p→1 时 Pn​=pn≈e−n(1−p)，并说明这个近似在 p=0.9、n=20 时的相对误差是多少。这个误差说明"用 e−ne 做设计估算"什么时候安全、什么时候会误导。
  4. 漂移的可检测性：为"给客户发送报价单"这个任务写出至少 5 条可执行的硬约束谓词（形如 assert ...），要求每条都能在轨迹的某一步被机械检查。然后回答：这 5 条里哪几条能拦住"子目标置换"型漂移？哪几条拦不住？为什么？
  5. 反例：构造一个任务，使得"分段执行"（把 30 步切成 3 段）反而降低成功率。给出对应的参数（p、段间接口误差），并用 design_check 的公式算出交叉点。

小结#

  • 单步正确率是四个环节的乘积（感知 × 决策 × 执行 × 解释），瓶颈常在"非模型"环节 —— 所以"换个更强的模型"经常不是正确的修复。
  • 误差累积 Pn​=pn≈e−ne：提升单步质量的收益与任务长度相乘地被放大，半衰期 n1/2​=ln0.5/lnp 是判断"任务长度与系统质量是否匹配"的尺子。
  • pn 是量级估算：错误可检测（(1−d)k）、多路径可接受、错误相关，这三件事都会让真实成功率高于（或低于）它。
  • 目标漂移是不报错的失败：三个机制 = 子目标置换、自评吸引子、误差经 L>1 的状态映射指数放大。对应三个对策 = 外部判据、收缩视图、可回滚。
  • 漂移与错误在指数上相加：Pok​≈(p(1−q))n。漂移更危险，因为它没有错误信号。
  • 真正改变乘积的五件事：提高可检测率、缩短单段轨迹、加外部硬约束、让状态更新收缩、让动作可撤销。"加更多步数预算"不在其中 —— 它是在放大风险。
  • 存在一个最优的外部求助率：完全不问和每步都问都不是最优 —— 这就是下一节"五个设计目标互相冲突"的第一个具体实例。
