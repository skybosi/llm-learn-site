项目规划#

学完了经典模型（ARIMA、Prophet）和深度学习模型（LSTM、TCN、Transformer、Informer），现在是时候把它们组装成一个真实的预测项目。但动手写代码之前，最容易被忽略、也最容易翻车的环节是规划：问题定义不清、评价指标选错、数据没对齐、基线没搭，后面做再多也是白费。这一课我们把一个预测项目开工前要想清楚的事全部摊开——这是第六章"实战"的施工蓝图。

一、概念讲解#

1. 定义问题：先把"要预测什么"钉死#

预测项目的第一句话永远是回答四个问题：

  • 目标变量：预测什么？（销量、负荷、流量、价格……）
  • 预测粒度：在什么时间分辨率上预测？（分钟、小时、天、周……）
  • 预测步长（horizon）：预测未来多远？（下一时刻、未来 7 天、未来 24 小时……）
  • 更新频率：模型多久重新预测/重训一次？（实时、每小时、每天……）

这四个答案决定了后面的一切技术选择。例如"预测未来 5 分钟的股价"和"预测未来 1 个月的销量"，数据量、模型复杂度、不确定性完全不同。切忌"先拿个 LSTM 跑起来再说"——问题没定义清，跑出来的结果无法评估、无法落地。

2. 明确数据：可得性决定方案上限#

模型的上限由数据决定。规划阶段要问：

  • 历史数据多长、多密？ 深度学习模型需要大量样本，只有几百个点的序列很难喂饱 Transformer；
  • 有没有缺失、异常、时间戳错乱？ 数据清洗的成本往往超过建模本身；
  • 有没有可用的协变量？ 日历特征、天气、促销计划等能显著提升精度；
  • 能否实时获取？ 这决定模型是离线批预测还是在线滚动预测。

先盘点数据，再决定模型。数据稀疏时，一个简单的指数平滑可能比复杂模型更靠谱；数据丰富时，深度学习才有用武之地。

3. 选评价指标：先定"什么叫好"#

不同业务在乎的"好"不一样，指标要在建模前定好，而不是做完再挑一个好看的。常用指标（下一课会有代码）：

  • MAE（平均绝对误差）：误差的绝对值的平均，量纲与目标一致，直觉清晰；
  • RMSE（均方根误差）：放大误差，对"大的错误"惩罚更重，适合"大偏差代价高"的场景；
  • MAPE / sMAPE（百分比误差）：相对误差，量纲无关，便于跨序列比较，但对接近 0 的目标不稳；
  • 业务指标：最终要落到业务上，比如"缺货率""预测偏差带来的成本"。技术指标是代理，业务指标才是终点。

还要选好对比基线：一个天真的"用昨天当今天"（naive）或简单移动平均，是一切复杂模型的照妖镜。复杂模型若打不过基线，就没有存在价值。

4. 划分数据：时间序列的特殊切法#

时间序列的 train/val/test 不能随机打乱（会泄露未来），必须按时间顺序切：早期做训练、中期做验证、近期做测试。这一步常被新手忽略，导致"看起来精度很高，上线就崩"。更严谨的是回测（backtesting）——用滚动窗口反复"用过去预测未来"，模拟真实部署。

5. 排期与风险：先跑通端到端的最小闭环#

规划的最后一步是排一个最小可行闭环（MVP）：先搭一个能从头跑到尾的简单版本（哪怕用 naive 基线），验证数据管道、评估脚本、部署路径都通，再逐步替换成复杂模型。这能避免"花了三周调模型，最后发现数据管道根本没搭对"的悲剧。同时要识别风险：数据获取延迟、概念漂移（数据分布随时间变化）、模型上线后的监控与重训。

二、可运行代码示例#

规划阶段的"代码"，更多是数据体检与基线搭建的脚手架。下面用一段代码，对一份模拟的日销量序列做三件事：数据质量体检、按时间切分、建立 naive 基线。这三件事是任何预测项目开工前的必修课。

import numpy as np
import pandas as pd

np.random.seed(0)

# 1) 模拟一份"日销量"数据：趋势 + 周周期 + 噪声，并故意插入缺失和异常
dates = pd.date_range("2022-01-01", periods=730, freq="D")
trend = np.linspace(0, 30, 730)
weekly = 8 * np.sin(np.arange(730) * 2 * np.pi / 7)
noise = np.random.randn(730) * 3
sales = trend + weekly + noise
sales[100] = 200                     # 异常值（尖峰）
sales[300:310] = np.nan              # 连续缺失 10 天

df = pd.DataFrame({"date": dates, "sales": sales})

# 2) 数据体检：缺失、异常、基本统计
print("=== 数据体检 ===")
print("缺失值数量:", df["sales"].isna().sum())
print("异常值（|z|>3）数量:", (np.abs((df["sales"] - df["sales"].mean()) / df["sales"].std()) > 3).sum())
print(df["sales"].describe())

# 3) 缺失值处理：前向填充（简单场景可用，复杂场景应结合业务）
df["sales"] = df["sales"].ffill()

# 4) 按时间顺序切分：80% 训练 / 10% 验证 / 10% 测试（绝不能随机打乱）
n = len(df)
tr_end = int(n * 0.8)
va_end = int(n * 0.9)
train, val, test = df.iloc[:tr_end], df.iloc[tr_end:va_end], df.iloc[va_end:]
print(f"\n=== 数据切分 ===\n训练 {len(train)} 天 / 验证 {len(val)} 天 / 测试 {len(test)} 天")

# 5) Naive 基线：用"昨天"预测"今天"（复杂模型的照妖镜）
def naive_forecast(series, horizon=1):
    return series.shift(horizon)      # 预测值 = horizon 天前的真实值

pred = naive_forecast(df["sales"], horizon=7)   # 用 7 天前预测今天（周周期基线）
from sklearn.metrics import mean_absolute_error, mean_squared_error
mask = pred.notna() & df["sales"].notna()
mae = mean_absolute_error(df["sales"][mask], pred[mask])
rmse = np.sqrt(mean_squared_error(df["sales"][mask], pred[mask]))
print(f"\n=== Naive 基线（用 7 天前预测今天）===\nMAE={mae:.3f}  RMSE={rmse:.3f}")
print("任何复杂模型若不能显著优于这个基线，就没有上线的价值。")

运行后体会几点：

  • 体检先行：缺失 10 天、异常尖峰一眼可见，这些不处理，模型会学到假信号；
  • 顺序切分：train/val/test 按时间先后，保证测试集是"模型从未见过的未来"；
  • 基线是底线：周周期数据用"7 天前"做 naive 基线 MAE 很小，这提醒我们——先想想数据本身有没有简单的周期规律可以利用。

三、练习#

  1. 把 naive 基线的 horizon 改成 1 和 7，比较 MAE。为什么周周期数据里 horizon=7 的基线反而很强？这提示你在正式建模前应先做什么分析？
  2. 为一份"分钟级股价"数据设计问题定义四要素（目标变量、粒度、步长、更新频率），并说明每个选择如何影响模型选型。
  3. 思考：如果业务方说"预测要尽量准"，但没给任何业务指标，你会追问哪些问题来把"准"翻译成可量化的技术指标？
  4. 用你自己的一段数据，跑一遍"体检 → 切分 → 基线"，并把发现写成一段简短的开工报告。这是进入下一课"完整预测流程"前的入场券。
