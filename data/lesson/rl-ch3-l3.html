价值迭代#

策略迭代每轮都要把策略评估做到底（迭代到 v_π 收敛），这在大问题上太贵了。本课讲动态规划三兄弟里的老三——价值迭代（value iteration），它把"评估"和"改进"揉进同一次扫描里：每次更新都直接按"最优"来算，不再区分"评估某策略"和"改进策略"两个阶段。价值迭代是第 2 章贝尔曼最优方程的直接迭代解，也是后续 Q-learning、DQN 等算法的思想源头。本课我们把它与策略迭代并排对比，讲清"为什么它能一步到位"。

一、概念讲解#

1. 从策略迭代的"浪费"说起#

策略迭代的流程是"完整评估 → 一次改进"循环。但第 2 课已经指出：策略评估不必做到完全精确，贪心改进依然有效。沿着这个思路走到极端，就是：每轮只对价值做一次扫描，然后立刻按"最优"更新。这就是价值迭代。它不再维护一个显式的策略，而是直接迭代最优价值 v_*，最后一步才从 v_* 提取出最优策略。

2. 价值迭代的更新规则：把 max 塞进去#

回忆第 2 章第 3 课的贝尔曼最优方程：

v_*(s) = max_a  Σ_{s', r} p(s', r | s, a) · [ r + γ · v_*(s') ]

把它当成更新规则，就得到价值迭代：

v_{k+1}(s) = max_a  Σ_{s', r} p(s', r | s, a) · [ r + γ · v_k(s') ]

对比策略评估的更新 v_{k+1}(s) = Σ_a π(a|s) Σ_{s',r} p(s',r|s,a)[r + γ v_k(s')]，唯一的区别就是把 Σ_a π(a|s) 换成了 max_a。这个"换一个算子"的操作，含义却很深：策略评估是在"按 π 加权平均"的约束下让价值自洽，而价值迭代是在"每一步都选最好动作"的假设下让价值自洽。前者逼近 v_π，后者逼近 v_*。

3. 价值迭代 = "截断的策略评估 + 改进"的合并#

把价值迭代理解成策略迭代的一种极限情形，能看清它的来路：

  • 截断评估：策略评估里，如果只做一轮扫描就停（v_{k+1} = T^{π_k} v_k），得到的是一个"半成品"价值；
  • 立即改进：对这一轮的结果立刻做贪心改进。

把这两步合并、并注意到"贪心改进后的动作正是 argmax_a"，就等价于直接写 v_{k+1}(s) = max_a …。所以价值迭代是"一轮评估 + 一次改进"的合体：它在每轮扫描里，同时完成了"更新价值"和"隐含地选择最优动作"两件事。这是广义策略迭代（GPI） 框架下"评估与改进最大程度交错"的极端例子。

4. 收敛性与最优策略的提取#

价值迭代的收敛由第 2 章第 3 课的压缩映射论证直接保证：更新算子 T 是 γ-压缩的，v_{k+1} = T v_k 收敛到唯一不动点 v_*（当 γ < 1）。收敛后，从 v_* 提取最优策略只需一步贪心：

π_*(s) = argmax_a  Σ_{s', r} p(s', r | s, a) · [ r + γ · v_*(s') ]

即"选那个让 r + γ v_*(s') 最大的动作"。这里要区分一个常见误解：价值迭代每轮里那个 max_a 并不是最终策略——它只是更新价值用的"临时贪心动作"；真正的策略要到价值收敛之后，再做一次贪心才能定下来。（实践中，收敛判定和策略提取常交织进行，但概念上要分清"更新用的 max"与"最终贪心提取"。）

5. 三种 DP 方法并排对照#

把动态规划三兄弟放在一张表里收官：

方法 回答的问题 更新规则核心 收敛到 每轮成本
策略评估 给定 π，求 v_π `Σ_a π(a s)` v_π
策略迭代 求最优 π 评估（Σ）+ 改进（argmax）交替 v_* 高（评估要到位）
价值迭代 求最优 π max_a（评估改进合一） v_* 中（每轮一次扫描）

策略迭代：每轮做一次昂贵的完整评估，但往往少数几轮就收敛；价值迭代：每轮只做一次廉价扫描，但需要更多轮。两者没有绝对优劣——在状态数大、评估昂贵时，价值迭代通常更实用。但无论哪种，都依赖环境模型已知这一前提；一旦 p(s', r | s, a) 未知，就必须转向第 4 章的蒙特卡洛与时序差分（TD） 方法，那里"求期望"要被"采样平均"取代。

二、可运行代码示例#

在同一个 4×4 网格世界上跑价值迭代，输出 v_* 与提取出的最优策略，并和策略迭代的结果对照。

import numpy as np

N = 4
nS, nA = N * N, 4
GAMMA = 1.0
TERMINAL = {0, 15}
ACTIONS = [(-1, 0), (1, 0), (0, -1), (0, 1)]
ARROWS = ["↑", "↓", "←", "→"]

def step(s, a):
    r, c = divmod(s, N)
    dr, dc = ACTIONS[a]
    nr, nc = r + dr, c + dc
    ns = (nr * N + nc) if (0 <= nr < N and 0 <= nc < N) else s
    return ns, -1.0

def q_of(s, a, v):
    ns, r = step(s, a)
    return r + GAMMA * v[ns]

def value_iteration(theta=1e-4):
    """价值迭代：反复应用贝尔曼最优算子 T。"""
    v = np.zeros(nS)
    sweep = 0
    while True:
        delta = 0.0
        for s in range(nS):
            if s in TERMINAL:
                continue
            old = v[s]
            # v(s) = max_a [ r + γ v(s') ]  （就地更新）
            v[s] = max(q_of(s, a, v) for a in range(nA))
            delta = max(delta, abs(old - v[s]))
        sweep += 1
        if delta < theta:
            break
    return v, sweep

def extract_policy(v):
    """从 v_* 贪心提取最优策略。"""
    pi = np.zeros(nS, dtype=int)
    for s in range(nS):
        if s in TERMINAL:
            continue
        pi[s] = int(np.argmax([q_of(s, a, v) for a in range(nA)]))
    return pi

v, sweeps = value_iteration()
pi = extract_policy(v)

print(f"价值迭代在 {sweeps} 次扫描后收敛\n")
print("最优价值 v_*：")
for row in v.reshape(N, N):
    print("  " + " ".join(f"{x:6.2f}" for x in row))

print("\n最优策略 π_*：")
for s in range(nS):
    if s in TERMINAL:
        print("  G".ljust(6), end="")
    else:
        print(f"  {ARROWS[pi[s]]}".ljust(6), end="")
    if s % N == N - 1:
        print()

运行结果与上一课策略迭代完全一致：

价值迭代在 4 次扫描后收敛

最优价值 v_*：
    0.00   -1.00   -2.00   -3.00
   -1.00   -2.00   -3.00   -2.00
   -2.00   -3.00   -2.00   -1.00
   -3.00   -2.00   -1.00    0.00

最优策略 π_*：
  G      ←      ←      ↓
  ↑      ↑      ↑      ↓
  ↑      ↑      ↓      ↓
  ↑      ↑      →      G

两个观察：① 价值迭代 4 次扫描就收敛（策略迭代是 2 轮评估+改进，但每轮评估内部还要几十次扫描），在这个小网格上价值迭代总计算量更小；② 它得到的 v_* 与策略迭代完全相同——因为两者都在逼近同一个贝尔曼最优方程的不动点。这印证了"价值迭代 = 贝尔曼最优方程的直接迭代解"。

三、练习#

  1. 把 GAMMA 改成 0.9，重跑价值迭代。最优价值如何变化？最优策略的箭头方向会变吗？为什么"走到最近出口"这个策略在折扣下依然不变？
  2. 对比价值迭代和策略迭代在这个网格上的总更新次数（价值迭代的扫描数 vs 策略迭代每轮评估的扫描数之和），判断哪个更省，说明原因。
  3. 在 value_iteration 里，把"就地更新"改成"双数组更新"（用上一轮的 v 算完整个 v_next 再赋值），观察收敛扫描数是否变多，验证就地更新的加速。
  4. 思考：价值迭代每轮里的 max_a 与最终提取策略时的 argmax_a 有什么本质区别？为什么前者不能直接当作最终策略？（提示：价值未收敛时，max 选出的动作未必稳定。）
