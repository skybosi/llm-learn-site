自动调优的成本：搜索预算、缓存与可复现性#

第 3 课的代价模型能把候选排对顺序，却不回答一个工程问题：这次调优值多少钱、多久回本。三组数据构成本课骨架：预算从 5 条加到 72 条时，"落在最优 2% 以内"的比例从 1/12 升到 12/12，但机上耗时从 0.06 秒涨到 0.86 秒；测量噪声从 σ=0 涨到 0.20 时，同一策略的命中率从 10/10 掉到 5/10；把 72 条候选 × 3 次样本的一次性成本（864 ms）用缓存摊掉后，后续同 shape 调用只花查表时间。自动调优不是"搜得越久越好"，而是"在预算内买到足够好的调度，并且不再重复付钱"。

一、概念讲解#

1. 三笔成本：搜索、测量、重编译#

一次调优的开销分三块。搜索成本 = 候选数 × 每条候选的样本数（本课 repeats=3，72 条即 216 次真测）。测量成本 = 单次编译 + 运行时间，决定"能搜多大"；第 3 课的代价模型把多数候选的评估降级为预测，正是为压这一项。重编译成本最易被忽略：调优结果绑定在特定 shape、dtype 与设备上，新 shape 到来就要重编译甚至重调优——第 2 章讲动态 shape 时的编译键，在调优语境下就是缓存键。

2. 搜索预算的收益递减#

第 3 节给出典型曲线：预算 5 条命中 1/12，10 条仍 1/12，20 条 3/12，36 条 6/12，72 条 12/12。前两档几乎无差别（好区域抽不到），20 条起改善，36→72 才跨过"基本稳"的门槛。这条 S 形曲线说明：早期投入买不到什么，中段见效，之后饱和。正确做法是先估饱和点、把预算定在附近，而不是"调到不动为止"。

3. 噪声：为什么不能只信单次冠军#

第 3 节显示 σ=0 时 10/10 落在最优 2% 以内，σ=0.10 与 0.20 时降到 9/10 与 5/10，最差一次比最优差 60%。原因是好调度之间的差距与单次测量的抖动同一量级。三条对策：每条候选测多次取中位数（statistics.median）；计时前先 warmup（第一次调用含编译与冷启动，必须剔除）；对最终选中的少数几条重复测，用置信区间而非单点值决策。

4. 缓存：把一次性成本摊成零#

调优结果要落成 key → 调度参数表，key 至少含：算子/子图标识、输入 shape 与 dtype、目标设备、编译选项。第 5 节给出它的真实形态（JSON：tile、order、vec、unroll、候选数、样本数）。缓存命中率是这套系统最重要的运营指标之一：本课 4 次同 key 调用全部命中，真测次数保持 216 不变——冷启动 864 ms 之后，每次调用只花查表时间。反过来，缓存键漏字段（把 batch 写进 key 却不写 shape）会造成"看着命中了、结果算错了"，比不命中更危险。

5. 可复现性：日志里少一项，别人就复现不出#

调优结果是基于测量做出的决策，必须成套记录：硬件标识（型号 + 驱动 / CUDA 版本）、编译器与库版本、精度模式（fp32 / tf32 / fp16 累加规则不同）、输入 shape 与布局、搜索算法与随机种子、每条候选的样本统计。少一项，换台机器就可能选出另一条调度；"快了 N 倍"没有这套记录也无法验证。结论的不确定性本身就是结果的一部分。

6. 常见坑#

  • 不设预算上限：先定"最多多少 GPU 小时 / 多少次真测"，否则搜索不收敛。
  • 拿单次测量当结论：σ=0.10 时单次冠军有相当概率不是最优。
  • 缓存键漏字段：漏 dtype 或 shape 会让不同问题撞进同一个键；漏设备会把一台卡的结论搬到别处用。
  • 调优记录不落盘：进程退出即丢失，下次冷启动重付代价。
  • 忽略回归：硬件或库升级后先跑回归，确认旧 key 的结果仍成立再决定是否保留缓存。

二、可运行代码示例#

# ---- 第 4 课：自动调优的成本账（纯 Python，无第三方依赖）----
import itertools, json, random, statistics

TILES = [(1, 1, 1), (8, 8, 1), (16, 16, 1), (32, 32, 1), (64, 64, 1), (128, 64, 8)]
ORDERS = [('i', 'j', 'k'), ('j', 'i', 'k')]
VECS = [1, 4]
UNROLLS = [1, 4, 8]


def space():
    for t, o, v, u in itertools.product(TILES, ORDERS, VECS, UNROLLS):
        yield dict(tiles=t, order=o, vec=v, unroll=u, parallel=('i', 'j'))


def truth(s):
    """"真机"：本课用第 2/3 课那种解析模型扮演；调优程序只能通过 measure() 看它。
    最优点在 tile 面积 64×64、unroll=4、次序 i 优先、向量化 4 —— 由模型结构决定，不是硬编码。"""
    area = s['tiles'][0] * s['tiles'][1]
    e = 1.0
    e += 2.0 * abs(area - 4096) / 4096                  # 面积偏离 64×64 就变差
    e += 0.8 * abs(s['unroll'] - 4) / 4                 # unroll 4 最好，1/8 都差
    e += 0.2 if s['order'][0] != 'i' else 0.0
    return e * (1.0 + 0.15 * (1 if s['vec'] == 1 else 0))


class Tuner:
    """调优器：对每条候选真测 k 次，按统计量挑一条，并把"成本账"记全。"""

    def __init__(self, noise=0.05, k=3, seed=0, measure_ms=4.0):
        self.noise, self.k, self.measure_ms = noise, k, measure_ms
        self.rng, self.trials, self.hits, self.cache = random.Random(seed), 0, 0, {}

    def measure(self, s):
        """一次"真测"：返回 k 个带测量噪声的样本。"""
        self.trials += 1
        base = truth(s)
        return [base * (1.0 + self.rng.gauss(0, self.noise)) for _ in range(self.k)]

    def tune(self, key, budget=None):
        cands = list(space())
        if budget and budget < len(cands):
            cands = self.rng.sample(cands, budget)
        best, best_stat = None, float('inf')
        for s in cands:
            stat = statistics.median(self.measure(s))
            if stat < best_stat:
                best, best_stat = s, stat
        self.cache[key] = dict(tiles=best['tiles'], order=''.join(best['order']), vec=best['vec'],
                               unroll=best['unroll'], candidates=len(cands), repeats=self.k,
                               samples=len(cands) * self.k)
        return best, len(cands)

    def call(self, key):
        """同一 shape 再跑：查缓存命中就不付搜索成本。"""
        if key in self.cache:
            self.hits += 1
            return self.cache[key]
        return None


if __name__ == '__main__':
    pool = list(space())
    oracle = min(truth(s) for s in pool)
    print(f'=== 1. 空间 {len(pool)} 条；真值最优 {oracle:.4f} —— 调优要逼近它，'
          f'但只能靠带噪声的实测 ===')

    print('\n=== 2. 每条候选测 k 次：成本随 k 线性涨，准确度不必线性涨 ===')
    print(f"{'k':>3}{'候选数':>8}{'实测样本数':>12}{'机上耗时(ms)':>14}{'选中真值':>12}")
    for budget, k in ((12, 1), (12, 3), (12, 10), (72, 3)):
        t = Tuner(noise=0.05, k=k, seed=1)
        s, n = t.tune(f'k{k}_{budget}', budget=budget)
        print(f'{k:>3}{n:>8}{n * k:>12}{n * k * t.measure_ms:>14.0f}{truth(s):>12.4f}')

    print('\n=== 3. 搜索预算的收益递减：12 次调优里有多少次落在最优 2% 以内 ===')
    print(f"{'budget':>8}{'每次真测次数':>14}{'总机上耗时(秒)':>16}{'落在最优2%':>12}")
    for budget in (5, 10, 20, 36, len(pool)):
        near = 0
        for trial in range(12):
            t = Tuner(noise=0.02, k=3, seed=500 + trial)
            s, _ = t.tune(f'b{budget}_{trial}', budget=budget)
            near += truth(s) <= oracle * 1.02
        print(f'{budget:>8}{budget * 3:>14}{budget * 3 * 4.0 / 1000:>16.2f}{f"{near}/12":>12}')

    print('\n=== 4. 测量噪声：预算拉满（72 条全测、k=3），噪声如何淹没差距 ===')
    print(f"{'每点噪声σ':>10}{'落最优2%':>10}{'中位真值':>10}{'最差真值':>10}")
    for noise in (0.0, 0.02, 0.05, 0.10, 0.20):
        picks = []
        for trial in range(10):
            t = Tuner(noise=noise, k=3, seed=1700 + trial)
            s, _ = t.tune(f'n{noise}_{trial}')
            picks.append(truth(s))
        near = sum(1 for v in picks if v <= oracle * 1.02)
        print(f'{noise:>10.2f}{f"{near}/10":>10}{statistics.median(picks):>10.4f}{max(picks):>10.4f}')
    print('  好调度之间的差距只有百分之几，而一次实测的抖动可能有几个百分点 —— '
          '这就是"必须多次测量 + 不能只信单次冠军"的原因')

    print('\n=== 5. 缓存与可复现性：调优结果是一张 key → 调度表 ===')
    t = Tuner(noise=0.03, k=3, seed=5)
    key = 'matmul_1024_1024_1024_f32_cuda'
    s, n = t.tune(key)
    print(f'  冷启动 key={key}')
    print(f'    → {json.dumps(t.cache[key], ensure_ascii=False)}')
    for _ in range(4):
        t.call(key)
    print(f'  同一 key 再跑 4 次：缓存命中 {t.hits} 次；累计候选 {t.trials} 条、'
          f'实测样本 {t.trials * t.k} 个')
    print(f'  一次性成本 = {t.trials} 条候选 × {t.k} 次样本 = {t.trials * t.k} 次真测，'
          f'约 {t.trials * t.k * t.measure_ms:.0f} ms；命中缓存后每次只花查表时间')
    print('  可复现性清单：硬件标识 + 驱动/编译器版本 + 精度 + 搜索种子 + 输入 shape，'
          '缺任何一项都复现不出同一条调度')

四处可核对的结论：成本随样本数线性涨（12 条候选 × 1/3/10 次样本 → 48/144/480 ms），而结果并不随样本数线性变好（1.84 → 1.80 → 1.80），说明多测几次前要先确认目标还值得测；预算收益是 S 形（5 条命中 1/12，36 条 6/12，72 条 12/12）；噪声会吞掉好调度之间的差距（σ=0.20 时只有 5/10 落在最优 2% 以内，最差一次挑到 1.60 倍）；缓存把一次性成本摊零（一次 216 次真测 ≈ 864 ms，之后 4 次同 key 调用全部命中）。

三、练习#

  1. 实现：给 Tuner 加 budget_s（秒）与 deadline 检查：时间耗尽即停止遍历、返回当前最优，并记录"实际测了几条、因超时跳过几条"；用 measure_ms=4 验证它真会在预算处停下。
  2. 解释：为什么第 2 节里 k 从 1 加到 10 只把结果从 1.84 降到 1.80，而 12 条候选扩到 72 条却从 1.80 降到 1.00？提示：前者改的是估计精度，后者改的是覆盖区域。
  3. 对比/验证：把 Tuner.cache 的 key 改成只含 tile 不含 shape，用两个不同 shape 调用，观察第二个是否"错误命中"第一个的结果；再修正 key，并写出你认为必须进 key 的字段清单。
  4. 思考：本课的"真测"是解析模型加噪声。换成真实 GPU 后噪声来源会变成什么（时钟频率、缓存状态、其他进程、功耗墙）？哪些能靠测量方法消除，哪些只能靠记录与统计处理？
