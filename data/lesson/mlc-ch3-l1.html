张量 IR 的要素：shape / dtype / layout / 依赖#

同一段 y = relu(x + 0)，在框架里是两次算子调用（add 与 relu），在 IR 里则只是三个带类型的值加两个节点。实质差别是：IR 不允许先算着看——每个值在编译期就必须回答四件事：形状是什么、元素类型是什么、内存地址怎么算、它依赖谁。四件事凑齐，常量折叠、布局变换、生命周期复用才谈得上；缺一件，后面的 pass 就只能保守。本课用两百行 numpy 把 shape 推导、stride 计算、依赖拓扑序与动态 shape 的编译键全部跑出来。

一、概念讲解#

1. 一个值 = 类型 + 地址公式#

术语先定死：shape（形状，各维大小）、dtype（元素类型）、layout（布局，逻辑索引到物理偏移的映射，行优先布局下就是一组 stride）、stride（步长，每沿该维走一格地址前进多少元素）。地址公式只有一行：

\text{offset}(i_0,\dots,i_{R-1}) = \sum_{k} i_k \cdot s_k,\qquad\rs_k = \prod_{j>k} d_j \text{（行优先）}

R 是 rank（秩），dk​ 是第 k 维大小。字节数 = ∏k​dk​×sizeof(dtype)。四者的分工是由谁决定、变了会怎样：

要素 谁决定 变了会怎样
shape 前端图 + 推导规则 决定 buffer 大小、kernel 形状、是否要重编译
dtype 前端 + 计算图 决定指令、寄存器占用、是否走 Tensor Core 路径
layout 后端在编译期选 不改语义，只改地址公式，但直接决定访存效率
依赖 图的连边 决定拓扑序、生命周期、能否融合、谁是死代码

本课代码第一段给出真实数字：(1,3,224,224) 共 150528 个 float32，占 602112 字节，行优先 strides 是 (150528, 50176, 224, 1)；换成 NHWC 写法后，形状的元素数一个没变，strides 变成 (150528, 672, 3, 1)。同一个张量，两套地址公式——这就是为什么"类型"里必须说清 layout 归谁管。

2. shape 有三种确定程度，动态维会污染 stride#

静态维（2）、动态维（StableHLO 写作 tensor<?x3xf32>）、以及"运行期才知道"的完全未知维。StableHLO 规范里 shape 可以部分或完全未知，但不允许 unranked：秩必须先确定。动态维出现的位置决定代价：它落在最外维时，后面几维的 stride 仍是常量（代码输出里 (None, 3) 的 strides 是 (3, 1)）；一旦落到更内层，stride 只能写成符号表达式（(2, None) 的 strides 是 '1*S'），连"下一个元素在哪"都要运行期算。

这份代价换来的收益是可以量化的。代码第 5 节用同一张图跑三次调用（batch=2、7、2）：把未知维写成符号，三次调用只产生 1 个编译键；把每一维都特化成实际值，就产生 2 个编译键（batch=2 命中两次、batch=7 触发一次新编译）。TorchInductor 走的正是第一条路：用 SymPy 符号表达形状，只在必要时插 guard，guard 失败才重编译——用轻微的运行期计算换掉整次编译。

3. dtype：位宽之外的语义#

dtype 不只是"几字节"，它决定指令选择与累加精度。量化又把 dtype 拆成两层：storage type（真正存的整数，如 i8）与 expressed type（它代表的浮点，如 f32），二者靠 scale 与 zero_point 换算，StableHLO 规范用 !quant.uniform 把这对参数写进类型，还支持 per-axis（每个切片一组 scale）。常见坑有两个：一是隐式类型提升，np.result_type(f32, f64) 会把整条链拉成双精度，性能与数值一起变；二是把"输入精度"和"累加器精度"混为一谈——低精度输入配 fp32 累加是常规做法，反过来才是事故。

4. layout：语义之外的另一半#

代码第 3 段是最小证据：同一个逻辑索引 (1, 2)，在 strides (4, 1) 下行优先偏移是 6，在 (1, 2) 下是 5。值一样，落在内存里的位置不一样。三条路线对 layout 的处置不同：StableHLO 的类型里没有 layout（规范明确把 layout 列为未来工作），MLIR 用 memref 的 affine/strided map 表达，TVM 则把 operator layout alteration 直接列为一类标准 pass。为什么要争这一件事？因为同一个 warp 里 32 个线程的地址是否连续，只由 stride 决定，与 shape 无关——这是前一门课访存合并分析的全部前提。

5. 依赖：图能被优化的前提#

MLIR 对值的定义很硬：一个 Value 要么是块参数，要么是"恰好一个 Operation 的结果"。于是每个操作数都是一条有向边，图必然是 DAG，def-use 链一次性买来四件事：拓扑序（代码输出的实际顺序是 mm → bias_b → sum → act → out，与书写顺序无关）、执行顺序的自由度（互不依赖的节点可重排）、生命周期（最后一次使用之后即可复用 buffer）、以及优化判据（没有使用者的节点是死代码，单使用者的相邻点链可以融合）。广播是唯一的特例：stride 为 0 的视图让 broadcast 不搬一个字节，但拿这组 stride 去估显存峰值就会低估。

6. 常见坑#

  • 把 strides 当 shape、按"占内存"估广播：同一个 shape 可对应多组 stride（切片、转置视图）；broadcast_to 的中间张量常常是零拷贝视图。
  • 动态维放在内层还想常量折叠：stride 成了符号，折叠机会直接消失。
  • 只推 shape 不推 dtype：kernel 签名对不上，只能回退到 eager。
  • 忽略 np.result_type 的提升：链尾多出一个 fp64 转换节点，白付带宽。

二、可运行代码示例#

纯 Python + numpy，本机 python3.10 + numpy 1.26.2 实跑，无需 GPU。五段分别对应上面五节：形状/地址、推导与拓扑序、两种 layout 的偏移、逐元素对拍、动态 shape 的编译键。

# ---- 最小张量 IR：shape / dtype / layout（strides）/ 依赖（numpy，本机 python3.10 + numpy 1.26.2 实跑）----
import numpy as np

# ---------- 1. shape 与 dtype：IR 里张量值的"类型" ----------
def numel(shape):
    n = 1
    for d in shape:
        n *= d
    return n


def row_major_strides(shape):
    """行优先（C 序）布局：strides[i] = 后面所有维度大小的乘积。
    维度为 None（动态）时，stride 可能是符号表达式 —— 静态维才能折成常量。"""
    st = [None] * len(shape)
    acc = 1
    for i in range(len(shape) - 1, -1, -1):
        st[i] = acc
        d = 'S' if shape[i] is None else shape[i]
        acc = acc * d if isinstance(acc, int) and isinstance(d, int) else f'{acc}*{d}'
    return tuple(st)


def offset(strides, idx):
    """地址公式 offset = Σ idx_i · strides_i；这就是 layout 的全部作用。"""
    return sum(i * s for i, s in zip(idx, strides))


print('=== 1. shape / dtype / layout 三者的分工 ===')
for shape in [(2, 3), (1, 3, 224, 224)]:
    st = row_major_strides(shape)
    print(f'  shape={shape}  元素数={numel(shape):>8}  dtype=float32  '
          f'行优先 strides={st}  字节={numel(shape) * 4}')
n = (1, 3, 224, 224)
print('  同一个逻辑张量，两种物理排布：')
print(f'    NCHW {n}          strides={row_major_strides(n)}')
print(f'    NHWC {(1, 224, 224, 3)}  strides={row_major_strides((1, 224, 224, 3))}')
print(f'  动态维让 stride 变成符号：shape=(2, None) → strides={row_major_strides((2, None))}')

# ---------- 2. 一个可执行的小图 IR：节点 + 输入 + shape/dtype 推导 ----------
class Node:
    def __init__(self, name, op, inputs=(), attrs=None):
        self.name, self.op, self.inputs, self.attrs = name, op, tuple(inputs), attrs or {}


class Graph:
    def __init__(self, nodes, inputs):
        self.nodes = {n.name: n for n in nodes}
        self.inputs = inputs                      # name -> (shape, dtype)
        self.shape, self.dtype, self.layout = {}, {}, {}

    def infer(self):
        for name, (sh, dt) in self.inputs.items():
            self.shape[name], self.dtype[name] = tuple(sh), dt
            self.layout[name] = ('row_major', row_major_strides(sh))
        for n in self.order():
            sh, dt = self._infer_node(n)
            self.shape[n.name], self.dtype[n.name] = sh, dt
        return self

    def _infer_node(self, n):
        S = [self.shape[i] for i in n.inputs]
        D = [self.dtype[i] for i in n.inputs]
        if n.op == 'matmul':
            (m, k), (k2, nn) = S
            assert k == k2, f'{n.name}: matmul K 维不匹配 {k} vs {k2}'
            assert D[0] == D[1], f'{n.name}: matmul 两侧 dtype 不同'
            return (m, nn), D[0]
        if n.op == 'add':                          # numpy 式双向广播；None = 动态维
            out = []
            for dims in zip(*[s[::-1] for s in S]):
                sizes = {d for d in dims if d != 1 and d is not None}
                if len(sizes) > 1:
                    raise ValueError(f'{n.name}: 广播失败 {S}')
                if sizes:
                    out.append(sizes.pop())
                else:
                    out.append(1 if all(d == 1 for d in dims) else None)
            return tuple(out[::-1]), np.result_type(*D)
        if n.op == 'relu':
            return S[0], D[0]
        if n.op == 'transpose':
            return tuple(S[0][p] for p in n.attrs['perm']), D[0]
        if n.op == 'broadcast_to':
            return tuple(n.attrs['shape']), D[0]
        raise ValueError(f'未知算子 {n.op}')

    def order(self):
        """依赖 → 拓扑序：值依赖（SSA）就是有向边，必须无环。"""
        producers = {name: [] for name in self.inputs}
        producers.update({n.name: list(n.inputs) for n in self.nodes.values()})
        for n in self.nodes.values():
            for i in n.inputs:
                if i not in producers:
                    raise ValueError(f'{n.name} 引用了不存在的值 {i}')
        indeg = {k: len([i for i in v if i in self.nodes]) for k, v in producers.items()}
        ready = [k for k, d in indeg.items() if d == 0]
        out = []
        while ready:
            k = ready.pop(0)
            if k in self.nodes:
                out.append(self.nodes[k])
            for m, deps in producers.items():
                if k in deps:
                    indeg[m] -= 1
                    if indeg[m] == 0:
                        ready.append(m)
        if len(out) != len(self.nodes):
            raise ValueError('图里有环：值依赖必须是 DAG')
        return out


def nodes_static():
    """out = relu(transpose(matmul(A, B) + bias, (1, 0)))"""
    return [Node('mm', 'matmul', ('A', 'B')),
            Node('bias_b', 'broadcast_to', ('bias',), {'shape': (2, 4)}),
            Node('sum', 'add', ('mm', 'bias_b')),
            Node('act', 'relu', ('sum',)),
            Node('out', 'transpose', ('act',), {'perm': (1, 0)})]


g = Graph(nodes_static(), {'A': ((2, 3), np.float32), 'B': ((3, 4), np.float32),
                           'bias': ((4,), np.float32)}).infer()
print('\n=== 2. shape 推导 + 依赖拓扑序（值 → 类型在编译期就算清）===')
for n in g.order():
    print(f'  {n.name:<7} {n.op:<12} {str(g.shape[n.name]):<10} '
          f'{np.dtype(g.dtype[n.name]).name:<8} 依赖={list(n.inputs)}')
print('  每个节点的 shape/dtype 都在执行前确定；这决定了 buffer 大小与 kernel 签名')

# ---------- 3. layout 是"怎么放"，不是"是什么"：同一逻辑张量两种排布 ----------
print('\n=== 3. layout：逻辑形状相同，物理地址公式不同 ===')
for tag, st, idx in [('行优先 strides=(4,1)', (4, 1), (1, 2)),
                     ('列优先 strides=(1,2)', (1, 2), (1, 2))]:
    print(f'  {tag:<22} 逻辑索引 {idx} → 偏移 {offset(st, idx):>2}')
print('  偏移 6 vs 5：值一样，落在内存里的位置不一样 —— layout 由后端在编译期定')

# ---------- 4. 执行 + 对拍：验证 shape/dtype 推导没有说谎 ----------
def run(graph, feeds):
    env = dict(feeds)
    for n in graph.order():
        a = [env[i] for i in n.inputs]
        if n.op == 'matmul':
            v = a[0] @ a[1]
        elif n.op == 'add':
            v = a[0] + a[1]
        elif n.op == 'relu':
            v = np.maximum(a[0], np.float32(0))
        elif n.op == 'transpose':
            v = np.transpose(a[0], n.attrs['perm'])
        elif n.op == 'broadcast_to':
            v = np.broadcast_to(a[0], n.attrs['shape'])
        env[n.name] = v
    return env


rng = np.random.default_rng(0)
A = rng.integers(-5, 5, (2, 3)).astype(np.float32)
B = rng.integers(-5, 5, (3, 4)).astype(np.float32)
bias = np.array([1, -2, 3, -4], dtype=np.float32)
env = run(g, {'A': A, 'B': B, 'bias': bias})
ref = np.maximum(A @ B + bias, 0).T
print('\n=== 4. 逐元素对拍（IR 执行 vs numpy 参考实现）===')
print(f'  编译期推得 out.shape={g.shape["out"]} 实际={env["out"].shape} '
      f'一致={g.shape["out"] == env["out"].shape}')
print(f'  编译期推得 out.dtype={np.dtype(g.dtype["out"]).name} 实际={env["out"].dtype} '
      f'一致={np.dtype(g.dtype["out"]) == env["out"].dtype}')
print(f'  最大绝对差 = {np.abs(env["out"] - ref).max()}')
print('  执行顺序：' + ' → '.join(n.name for n in g.order()))

# ---------- 5. 动态 shape：符号维 vs 特化维，决定"一个图编译几次" ----------
print('\n=== 5. 动态 shape：编译键（guard）决定复用还是重编译 ===')
g_dyn = Graph([Node('mm', 'matmul', ('A', 'B')),
               Node('bias_b', 'broadcast_to', ('bias',), {'shape': (None, 4)}),
               Node('sum', 'add', ('mm', 'bias_b')),
               Node('act', 'relu', ('sum',)),
               Node('out', 'transpose', ('act',), {'perm': (1, 0)})],
              {'A': ((None, 3), np.float32), 'B': ((3, 4), np.float32),
               'bias': ((4,), np.float32)}).infer()
print(f'  动态图：A.shape={g_dyn.shape["A"]}，A.layout.strides={g_dyn.layout["A"][1]}'
      '（首维还没进 stride，所以后面几维的 stride 仍是常量）')


def shape_key(graph, feeds, specialize=False):
    """把每维转成"键里的一格"：特化模式写实际值，动态模式写符号。"""
    key = []
    for name, (sh, _) in graph.inputs.items():
        dims = []
        for i, d in enumerate(sh):
            actual = feeds[name].shape[i]
            if d is not None:
                dims.append(d)
            else:
                dims.append(actual if specialize else f'S{name}{i}')
        key.append((name, tuple(dims)))
    return tuple(key)


for specialize in (False, True):
    seen = {}
    for batch in (2, 7, 2):
        feeds = {'A': rng.integers(-5, 5, (batch, 3)).astype(np.float32),
                 'B': B, 'bias': bias}
        k = shape_key(g_dyn, feeds, specialize)
        seen.setdefault(k, 0)
        seen[k] += 1
    tag = '特化：每维写实际值' if specialize else '动态：未知维写符号 S'
    print(f'  {tag}：3 次调用（batch=2,7,2）→ {len(seen)} 个编译键')
    for k, cnt in seen.items():
        print(f'    键={k}  命中 {cnt} 次')
print('  特化模式把 batch 折成常量、能多做常量折叠，但每个新 shape 都要重编译；')
print('  动态模式一个键覆盖所有 batch —— 这正是 TorchInductor 用 SymPy 符号 + guard 的取舍')

三、练习#

  1. 实现：给 Graph._infer_node 增加 reshape 与 slice 两个算子，让它们在存在动态维时推导出符号 stride；再用输入形状 (None, 4, None) 验证你的 stride 表达式。
  2. 解释：为什么 (None, 3) 的 strides 还是 (3, 1)，而 (2, None) 的 strides 成了 '1*S'？由此解释"动态维越靠内，编译期能做的越少"。
  3. 对比/验证：把第 5 节的 specialize 反向扩展——让 B 的 K 维也写成符号（(None, 4)），3 次调用（batch=2,7,2）会产生几个编译键？什么样的符号化是白拿收益、什么只是把编译推迟到运行期？
  4. 思考：如果 layout 不进类型（StableHLO 的选择），谁来保证"同一个值在两处被假设成同一种排布"？反过来，把 layout 写进类型，会付出什么代价（考虑两个后端、两个版本之间的互操作）？
