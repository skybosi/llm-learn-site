语音-文本联合建模：离散语音 token、统一词表与流式取舍#

这一节要解决什么#

上一节把账算清了：端到端的结构优势是"少乘一个因子"，代价是语音表示把序列拉长了 12.5 倍（50 token/s vs 4 字/s），于是算力、延迟、数据全面吃亏。这一节要处理的就是把这 12.5 倍压回去的核心机制：离散语音 token。

问题可以这样写：语音是连续信号，每秒 16000 个样本；文本是离散符号，每秒约 4 个。要让一个 Transformer 同时处理两者，必须先把语音也离散化——用什么码本、多少比特、每秒多少个 token。这三个数不是独立的：它们的乘积就是码率。

R=r⋅b(bps),b=log2​K (K 为码本大小)

本节要回答三个问题，每个都给可算判据：

  1. 码本与残差 VQ：一级量化为什么不够？多级叠加的收益怎么衰减？"码本坍缩"怎么用量出来的数诊断？
  2. 统一词表与对齐：把语音 token 和文本 token 放进一个模型，参数量上几乎免费——那真正的代价在哪？对齐是显式给（CTC/时长）还是当隐变量（交错 + 交叉熵）？
  3. 流式与双向：右上下文要多少？为什么最优值一定落在一个很窄的窗口里？块状注意力到底省了什么、没省什么？

这三问合起来是一条主线：离散化的每一个选择都在"信息量、序列长度、可控性"三者之间换。

 语音 token 化的取舍=率-失真（压多狠）×序列长度（多难算）×对齐方式（多可控） ​

一、离散语音 token：码本、比特与下界#

1.1 率-失真：压缩有硬下限#

把语音的连续表征（潜向量）量化成 K 个码字之一，等价于在码率 R 下做有损压缩。在高码率、均方失真、高斯源的近似下，信息论给出的下界是

D(R)=σ2⋅2−2R/Deff​

其中 σ2 是源方差、Deff​ 是有效维数（源在感知度量下真正占据的自由度）。把它写成"每加 1 bit 失真乘多少"：

D(R)D(R+b)​=2−2b/Deff​

Deff​=10（构造值）时，每加 1 bit 失真只降

2−2/10=0.8706(降 13.0%)

要把失真降一半，需要多加 log2​2⋅Deff​/2=5.00 bit。 这就是"离散 token 压缩有硬下限"的算术形式：不是工程做得不好，而是每一比特买到的东西随比特数递减。表 2 列出 b=2,4,…,20 时的理论失真与对应信噪比。

R=r⋅b 固定时（表 3 用 R=1000 bps），有两条极端路线：

配置 token 率 r b/token 60 s 序列长 问题

关键观察：在信息论下界上，这几种花法是等价的（同样的 R 就是同样的 D）。差别全在工程侧：注意力算力按序列长度的平方增长，所以"深码本 + 低率"看起来极度有利（1500 vs 12000 是 1.56% 的注意力算力）——但它被码本的可实现性封死了。真实系统只能用 K=210∼213 的码本，于是配置被迫落在 r=25∼100 token/s 的窄带里。

 实际配置的窄带=注意力算力∩码本可实现性, 不是审美选择 ​

1.3 残差 VQ：用多级逼近一级#

既然大码本不可实现，就用多个小码本逐级逼近：第 1 级量化 x，第 2 级量化残差 x−x^1​，第 3 级再量化新的残差，依此类推。第 m 级的目标是

{cj(m)​}min​x∑​​(x−i<m∑​c^(i))−c(m)​2

（这正是 k-means 的目标函数，逐级独立求解。）三个可算的理由说明为什么这样做：

  1. 查表/存储成本：单级 K=2b 的码本需要 K⋅d 的存储与查表；切成 n 级后是 ∑i​Ki​⋅d。本节合成算例里 4 级共 15 bit（等效 32768 个码字），单级成本 32768d、RVQ 成本 64d，小 512 倍。
  2. 层次结构：粗层可以单独用于低延迟场景，细层只用于质量——同一套 token 天然支持多种码率。
  3. 训练稳定性：每级只拟合残差，梯度尺度更可控。

代价是逐级收益递减，而且在合成算例里还出现了码本利用率问题：第 3 级只用掉 3/16 个码字（37.5%）。

1.4 码本坍缩：一个可以量出来的故障#

"码本坍缩"（codebook collapse）指模型把绝大多数输入都映射到少数几个码字上——等价于名义码率被浪费。它有一个直接读数：

困惑度=2H,H=−k∑​pk​log2​pk​ (pk​ 为第 k 个码字的分配比例)

  • 困惑度 =K 表示码字被均匀使用（信息量吃满）；
  • 困惑度 =6.39（表 10 的"早期"）表示平均只在 6.39 个码字里选，等效码率只有 log2​6.39/log2​64=44.6%——名义 6 bit，实际 2.67 bit。

等效码率占比=log2​Klog2​(困惑度)​=log2​KH​

判据：若困惑度 /K<0.1（表 10 的早期阶段），说明容量过剩或更新机制有问题；此时正确动作是缩小码本或提高 token 率，而不是继续加训练步数。修复手段（码本重置、EMA 更新、commitment 项）都是"救活死码"，但前提是先把死码率量出来。

二、语音-文本联合建模：统一词表与对齐#

2.1 统一词表的参数账：几乎免费#

把语音码字当成额外的 token 加进词表（"扁平化"），参数量几乎不变：d=4096 时，+64 个 token 只增加 0.5 M 参数（0.1%）。所以"要不要统一词表"在参数量上不是一个问题。真正的差别在输出分布的结构：

方案 词表 V 嵌入参数 单次归一化
纯文本 100000 409.6 M 100000 个 logits
文本 + 扁平语音 id 100064 409.9 M 100064 个 logits，一次
文本 + 4 个独立码本头 100000 409.6 M 各约 25000 个 logits，4 次

扁平能表达任意联合分布（同一级与跨级的依赖都能建模）；分层式各头独立归一化，计算量小但不能表达"第 2 级码字依赖第 1 级码字"这种级间依赖。取舍点是一个可以量出来的量：给定前一级码字后、当前级码字的条件互信息。若这个量接近 0（各级近似独立），分层式几乎无损；若它显著（协同发音正是如此），只有扁平/自回归式能表达。

2.2 交错序列的长度账#

统一词表最自然的训练目标是交错（interleaving）：把文本 token 与语音 token 放在同一条序列里，用同一个"预测下一个 token"的目标训练。代价是序列长度：

表示 token/s 60 s 序列长 注意力 FLOPs 倍数
纯文本 4 240 1.0×
语音 1 级 50 3000 156.2×
语音 4 级（扁平） 200 12000 2500.0×
语音 4 级 + 文本（交错） 204 12240 2601.0×

注意力 FLOPs 随序列长度平方增长，所以 4 级扁平交错把 60 s 的注意力算力抬到 2601 倍。这直接解释了 1.2 节的结论：宁可"低 token 率 + 大码本"，也不要把多级码本扁平交错成一个长序列——把 200/s 压回 50/s，注意力立刻省 16 倍，代价是量化失真，两者可以在等码率曲线（表 3）上直接比。

2.3 对齐：三条路线，差别在"把什么当隐变量"#

路线 监督信号 需要配对数据 流式友好 主要失效模式
交错 + 交叉熵 下一 token 是 是 文本/语音速率耦合错位
对比对齐 句级相似度 是（弱） 否（要整句） 细粒度信息被句向量压掉
显式时长 / CTC 帧级对齐 是（需时长） 是 对齐错误传播到声学

三条路线的差异不在"谁的模型更强"，而在监督信号把哪一部分当成隐变量：

  • 交错 + 交叉熵把"文本与语音的速率比"当隐变量——模型自己学"什么时候说多少话"。这最灵活，也最难训（速率耦合会漂移）。
  • CTC / 显式时长把它显式给出——可控、可流式，但需要标注，且第 3 章算过：对齐错误会传播到声学。
  • 对比对齐把它整体丢掉——最省标注，也最不可控（句向量压掉了细粒度信息）。

可算判据（针对交错路线）：在一个 batch 里统计"每单位文本 token 对应的语音 token 数"，其方差应稳定在期望速率比附近；方差过大说明速率耦合没有学到。这个判据不需要任何外部基准，只需要训练日志。

三、流式与双向：上下文、延迟与算力#

3.1 块状注意力：省了什么、没省什么#

为了让编码器可流式，常把序列切成块、每块只与自身及左侧块做注意力。设块长 W 帧（帧移 20 ms）、总长 T 帧：

右上下文=W×20 ms,全注意力 FLOPs块状注意力 FLOPs​=(nW)2nW2​=TW​

表 7 用 T=3000 帧（60 s）算：W=25 帧给 500 ms 右上下文、算力降到 0.0083；W=1000 帧给 20 s 右上下文、算力 0.3333。但KV cache 一点没省：

KV cache=n⋅W⋅d⋅2⋅bytes=T⋅d⋅2⋅bytes

它只与 T 成正比，与块长无关（表 7 里恒为 6.14 MB）。所以

 块状注意力牺牲的是跨块建模，不是 KV cache；真正省算力的手段是降 token 率 ​

3.2 右上下文的最优值：收益指数衰减 vs 代价线性增长#

把"能看到多少未来帧"折成相对质量，一个合理的构造模型是

q(c)=1−e−c/c0​,延迟=c×20 ms

（c0​=20 帧为构造值，代表语音的局部时间尺度。）表 8 给出 c=0,2,5,10,20,40,80,200 的结果：c=20 时质量已达 0.6321（延迟 400 ms），c=200 时才到 ≈1（延迟 4000 ms）。收益指数衰减、代价线性增长，所以最优 c 一定很小——这解释了为什么流式系统的右上下文普遍落在 300∼600 ms 这个窄窗口里。

⚠️ 指数饱和的形状是结构性的（收益递减），但 c0​ 的数值是构造值，真实的饱和点必须由实验定。任何一个具体系统声称的"300 ms 足够"都是它自己语料上的经验值，不能直接搬。

3.3 双向与流式的真正差别#

双向（全注意力）能看到整句，流式看不到；这个差别不只是"质量换延迟"，而是改变模型能学到什么：

  • 双向可以学"回声"式的依赖（后面的词决定前面的音）；流式不能。
  • 双向可以做全局归一化（例如整句的音高基线）；流式只能做局部归一化，容易产生段间不一致（第 3 节的说话人一致性就是它的一个实例）。
  • 双向的推理成本与序列长度平方相关；流式是线性的（但 KV cache 仍是线性的，见 3.1）。

四、取舍与边界#

把本节的三个机制放回上一节的三笔账，结论是：

  1. 降 token 率是唯一同时省算力、省延迟、省存储的手段，但它被码本可实现性封在 r≥25 token/s 附近（表 3）。
  2. 多级 RVQ 是"用多级换单级"的标准做法，代价是逐级收益递减（合成算例里 82.4%→56.7%→…）与码本利用率下降（表 4 的第 3 级只用 3/16）。
  3. 对齐方式决定了可控性：显式时长/CTC 最可控但需标注；交错 + 交叉熵最灵活但速率耦合不可控；对比对齐最省标注但细粒度信息被压掉。这不是"哪个更先进"，而是"你把哪一部分交给模型自己学"。
  4. 流式的延迟地板是右上下文，它与"块状注意力省了多少算力"无关（KV cache 不省）。若要压延迟，唯一有效的是压 token 率或压块长——前者已在 3.1 封死，后者直接牺牲跨块建模。

⚠️ 关于"现在哪条路线更好"：本节不给结论。目前公开讨论里三条路线都有支持者，而它们各自的失效模式（速率耦合漂移 / 对齐错误传播 / 细粒度信息丢失）都能用本节的判据定位。任何"某路线已胜出"的说法都应当被要求给出三样东西：同一批测试集上的效应量与置信区间、码本利用率/困惑度、以及速率比方差。这三样本节都给了可算形式。

def make_data():
    """8 组 x 4 变体，8 维；确定性生成（不用随机数，保证任何环境一致）。"""
    centers = []
    for i in range(8):
        # 组中心：一圈 + 一维偏移，避免重合
        th = 2.0 * math.pi * i / 8.0
        c = [1.0 * math.cos(th), 1.0 * math.sin(th), 0.0, 0.0,
             0.5 * math.cos(2 * th), 0.5 * math.sin(2 * th), 0.0, 0.0]
        centers.append(c)
    pts = []
    for i, c in enumerate(centers):
        for j in range(4):
            v = list(c)
            v[2] += 0.22 * (j - 1.5)          # 组内第 1 个方向
            v[3] += 0.15 * ((j % 2) * 2 - 1)  # 组内第 2 个方向
            v[6] += 0.10 * (j - 1.5)
            v[7] += 0.08 * ((j % 2) * 2 - 1)
            pts.append(v)
    return centers, pts


def dist2(a, b):
    return sum((x - y) ** 2 for x, y in zip(a, b))


def kmeans(pts, K, iters=60, spread=0.35):
    """确定性 k-means：初始中心在数据主方向上等距铺开（不用随机数）。"""
    d = len(pts[0])
    mean = [sum(p[k] for p in pts) / len(pts) for k in range(d)]
    # 主方向取数据方差最大的两维（确定性）
    var = [sum((p[k] - mean[k]) ** 2 for p in pts) / len(pts) for k in range(d)]
    order = sorted(range(d), key=lambda k: (-var[k], k))
    a, b = order[0], order[1]
    umin, umax = min(p[a] for p in pts), max(p[a] for p in pts)
    vmin, vmax = min(p[b] for p in pts), max(p[b] for p in pts)
    cent = []
    for i in range(K):
        t = 0.5 if K == 1 else i / (K - 1.0)
        cc = list(mean)
        cc[a] = umin + (umax - umin) * t
        cc[b] = vmin + (vmax - vmin) * (1.0 - t)
        cc[a] += spread * (0.5 - (i % 3)) / 3.0
        cc[b] += spread * (0.5 - ((i + 1) % 3)) / 3.0
        cent.append(cc)
    for _ in range(iters):
        asg = []
        for p in pts:
            best, bi = None, 0
            for j, c in enumerate(cent):
                v = dist2(p, c)
                if best is None or v < best:
                    best, bi = v, j
            asg.append(bi)
        new = [[0.0] * d for _ in range(K)]
        cnt = [0] * K
        for p, j in zip(pts, asg):
            cnt[j] += 1
            for k in range(d):
                new[j][k] += p[k]
        for j in range(K):
            if cnt[j]:
                cent[j] = [x / cnt[j] for x in new[j]]
    return cent, asg

def hist_entropy(counts):
    tot = sum(counts)
    H = 0.0
    for c in counts:
        if c:
            p = c / tot
            H -= p * math.log2(p)
    return H

小结#

  • 码率是三个数的乘积：R=r⋅b，b=log2​K。50 token/s + K=1024（10 bit）=500 bps =512:1 压缩。
  • 率-失真下界 D(R)=σ22−2R/Deff​：Deff​=10 时每加 1 bit 失真只乘 0.8706（降 13.0%），把失真降一半需要 +5.00 bit。压缩有硬下限。
  • 等码率下有两种花法：R=1000 bps 时，"深码本 + 低率"（25×40，60 s 序列 1500）与"浅码本 + 高率"（200×5，序列 12000）在信息论上等价，注意力算力差 (1/8)2=1.56%——但前者被码本可实现性封死。实际配置的窄带 r=25∼100、K=210∼213 是两条约束的交集。
  • 残差 VQ 用多级换单级：合成算例里 4 级共 15 bit（32768 个码字），存储/查表成本 64d vs 单级 32768d，小 512 倍；代价是逐级收益递减（第 1 级降 82.4% 的 MSE）与利用率下降（第 3 级只用 3/16）。
  • 码本坍缩的可算读数：困惑度 =2H，等效码率占比 =H/log2​K。表 10 的三阶段是 6.39/50.63/63.34，对应等效码率 44.6%/94.4%/99.8%。困惑度太低不是"训练不够"，而是"容量过剩"。
  • 统一词表的参数几乎免费：+64 个 token 只增 0.5 M 参数（d=4096）。真正的差别在输出结构：扁平一次归一化、能表达跨级依赖；分层四次归一化、更省但不能表达级间依赖。判据是"给定前一级后的条件互信息"。
  • 交错序列的长度账：语音 1 级 50/s、4 级扁平 200/s、加文本 204/s；60 s 序列 3000/12000/12240，注意力 FLOPs 倍数 156.2/2500.0/2601.0。这是"低 token 率 + 大码本"的量化理由。
  • 三条对齐路线的差别在"把什么当隐变量"：交错 + 交叉熵（速率比）、对比对齐（整体丢掉）、显式时长/CTC（显式给出，但错误会传播）。判据是"速率比的条件方差"。
  • 块状注意力省二次项、不省 KV cache：KV cache=T⋅d⋅2⋅bytes（表 7 恒为 6.14 MB），右上下文 =W×20 ms，算力占比 =W/T。
  • 右上下文最优值很小：q(c)=1−e−c/c0​，c=20 帧给 0.6321 质量/400 ms 延迟，c=200 才到 ≈1/4000 ms。收益指数衰减、代价线性增长——这是流式系统普遍取 300∼600 ms 的原因。
  • ⚠️ 外部成绩保守表述：本节没有引用任何具体系统的实测数字。三条路线"谁更好"属于未收敛的讨论（C 级推测），判定它需要三样东西：同一测试集上的效应量与置信区间、码本困惑度、速率比方差。
