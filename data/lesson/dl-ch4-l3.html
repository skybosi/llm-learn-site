训练问题#

RNN 结构看起来很优雅，但真训练起来，会撞上一个出了名的大坑：梯度消失和梯度爆炸。这俩问题让普通 RNN 记不住长序列里的早期信息，也就处理不好"长距离依赖"。这一课我们把 RNN 的反向传播（BPTT）拆开看，搞懂坑是怎么来的、怎么缓解，为下一章 LSTM/GRU 的登场铺路。

一、概念讲解#

1. BPTT：沿时间反向传播#

RNN 的反向传播有个专门的名字——随时间反向传播（Backpropagation Through Time, BPTT）。它的思路并不神秘：把 RNN 沿时间轴展开成一条链后，它就像一层层堆叠的网络，梯度从最后一个时间步，顺着链一步步往回传。

因为每一步都复用同一个权重 Wₕₕ，所以 Wₕₕ 的梯度是所有时间步贡献的累加。具体来说，损失对早期隐藏状态 hₜ 的梯度，会经过一连串 Wₕₕ 的连乘才能传到更早的 h₀。问题就出在这个连乘上。

2. 梯度消失与梯度爆炸：连乘的代价#

粗略地说，误差从时间步 T 传到时间步 1，中间要乘上 T-1 次 Wₕₕ 相关的项。假设每一步的放大倍数约为 λ，那么梯度就大致按 λ^(T-1) 缩放：

  • 若 λ < 1：λ^(T-1) 随序列变长指数级趋近 0 → 梯度消失。早期时间步几乎收不到更新信号，网络"记不住"很久以前的信息。
  • 若 λ > 1：λ^(T-1) 指数级爆炸 → 梯度爆炸。参数更新一步蹿得老远，损失变成 NaN，训练直接崩溃。

梯度爆炸很好识别——损失曲线突然飙到 inf/NaN；梯度消失则更隐蔽——损失下降得特别慢，甚至看起来"学不动了"，但模型其实在偷懒，只会利用最近几步的信息。

3. 缓解手段#

针对这两个问题，工程上有几招标准应对：

  • 梯度裁剪（gradient clipping）：对付爆炸最直接有效。每次反向传播后，检查整个模型梯度的范数，若超过阈值，就按比例把梯度整体缩回去，方向不变、只限步长。PyTorch 里一行 torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm) 就搞定。
  • 更好的激活与初始化：用 ReLU 族激活、合理的权重初始化（如 Xavier），能减轻梯度消失，但治标不治本。
  • 换门控结构：这是治本的方向。LSTM、GRU 通过"门"让信息可以在长时间里近乎无损地传递，从根本上绕过连乘消失的问题——这正是下一章的主角。
  • 截断 BPTT：训练超长序列时，只往回传播固定的若干步（比如 50 步），既省显存又避免梯度在超长链上失控。

4. 为什么"记不住"是致命伤#

试想一个句子："我把昨天买的、放在厨房柜子上的那本书，送给了朋友。" 当模型读到句尾要判断"送"的对象时，需要追溯到开头的"我"。普通 RNN 的梯度经过这么长的链早就衰减没了，模型学不到这种跨越几十步的依赖，只能靠猜。语言里这种"长距离依赖"俯拾皆是，所以 RNN 很快就被 LSTM/GRU 取代了——但理解了 RNN 的坑，你才能真正体会门控结构的价值。

二、可运行代码示例#

下面用一个字符级 RNN 训练小任务，直观演示两件事：① 梯度范数会如何随训练波动，② 加梯度裁剪后训练更稳。我们用 RNN 预测一个简单周期序列的下一个字符，重点观察"梯度"与"损失"的数值，而非追求精度。

import torch
import torch.nn as nn
from torch.nn.utils import clip_grad_norm_

torch.manual_seed(0)

# 造一个确定性的小语料：反复重复 "abc"
text = "abc" * 200
chars = sorted(set(text))               # 只有 'a','b','c'
char2idx = {c: i for i, c in enumerate(chars)}
data = torch.tensor([char2idx[c] for c in text])

class CharRNN(nn.Module):
    def __init__(self, vocab_size, hidden_size):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, 8)
        self.rnn = nn.RNN(8, hidden_size, batch_first=True)
        self.fc = nn.Linear(hidden_size, vocab_size)

    def forward(self, x):
        # x: (batch, seq_len) -> embed -> (batch, seq_len, 8)
        out, _ = self.rnn(self.embed(x))
        # 每个时间步都预测"下一个字符"，取全部时间步输出
        return self.fc(out)             # (batch, seq_len, vocab_size)

def make_batches(data, batch_size, seq_len):
    """把一维语料切成 (batch, seq_len) 的输入和错开一位的目标。"""
    inputs, targets = [], []
    for i in range(0, len(data) - seq_len, seq_len):
        inputs.append(data[i:i + seq_len])
        targets.append(data[i + 1:i + seq_len + 1])
        if len(inputs) == batch_size:
            break
    return torch.stack(inputs), torch.stack(targets)

model = CharRNN(len(chars), hidden_size=16)
loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)

# 对比：是否开启梯度裁剪
for use_clip in [False, True]:
    torch.manual_seed(0)
    model = CharRNN(len(chars), 16)
    optimizer = torch.optim.Adam(model.parameters(), lr=0.01)
    print(f"\n=== 梯度裁剪: {use_clip} ===")
    for step in range(300):
        x, y = make_batches(data, batch_size=8, seq_len=16)
        logits = model(x)                       # (8, 16, 3)
        loss = loss_fn(logits.reshape(-1, len(chars)), y.reshape(-1))
        optimizer.zero_grad()
        loss.backward()

        if use_clip:
            clip_grad_norm_(model.parameters(), max_norm=1.0)   # 裁剪梯度

        # 统计当前梯度的总范数（只看第一个参数的梯度，作为示意）
        grad_norm = model.rnn.weight_ih_l0.grad.norm().item()
        optimizer.step()

        if step % 100 == 0:
            print(f"step {step:3d} | loss={loss.item():.4f} | grad_norm={grad_norm:.4f}")

运行后你会看到：不裁剪时 grad_norm 可能在某些步明显偏大（本例序列短，未必爆炸，但能观察到范数波动）；开启裁剪后，范数被牢牢压在 max_norm=1.0 以内，更新更稳。把这个小例子换成更长的序列、更深的网络，裁剪的价值会更明显。

三、练习#

  1. 把 max_norm 改成 0.1 和 10.0，观察 grad_norm 的上限和损失下降速度分别怎么变化，说说阈值设太小会怎样。
  2. 把序列长度 seq_len 从 16 逐步加大到 64、128，观察不做裁剪时的 grad_norm 如何变化，并解释原因。
  3. 试着故意调大学习率（如 lr=1.0）且不裁剪，运行几次，看损失会不会出现 NaN；再开启裁剪对比。
  4. 思考：梯度裁剪为什么能压住爆炸却救不了消失？梯度消失的"症状"在损失曲线上通常长什么样？
