多步任务的预算与剪枝#

这一节要解决什么#

第 2 章给过"三把闸"：步数、预算、置信度。那是定性的说法 —— 知道要有闸门，但不知道闸门该设多少、什么时候该主动放弃、剩余的钱够不够走完。这一节把它算成数。

多步任务有一个残酷的数学事实：

P(全部成功)=i=1∏N​pi​⟹P≈pN

单步成功率 0.95、20 步，端到端只有 0.9520≈0.36。也就是说"任务失败"在多步场景里是常态而不是异常。于是 Agent 的核心工程问题从"怎么写计划"变成了：

在哪一步之前必须放弃？以及哪些分支根本不该展开？

这两个问题的答案分别叫最优停止（事中剪枝）与分支定界（事前剪枝）。它们不是工程经验，是两个可以推导的规则。

学完这一节你应该能回答：

  • 为什么"预算"不能只是"步数上限"？哪几个维度不可互相换算？
  • "还要花多少"怎么估？低估与高估各自的代价是什么？
  • 多步成功率真的按 pN 衰减吗？什么条件下这个模型过于悲观？
  • 事前剪枝和事中剪枝分别剪什么？下界（lower bound）为什么必须"绝不会高估成本"？
  • 最优停止的判据是什么？为什么已投入成本不能进入判据，而"剩余预算"要以机会成本形式进入？
  • 有 k 个候选解法时，预算该"先广后深"还是"先深后广"？能算吗？

一、预算不是"步数上限"#

1.1 多维预算向量#

一个真实 Agent 的预算是六维的，而且这些维度不能互相换算：

B=(Bstep​, Btoken​, Bmoney​, Btime​, Bcall​, Beffect​)

维度 为什么不能省 耗尽的后果 闸门类型
步数 防死循环（第 2 章的终止条件） 无限循环 硬闸
token 上下文与输出都按 token 计价，是主要成本驱动因子 成本爆炸、上下文超窗 软闸（可压缩上下文续命）
金额 外部 API 与人工审批的真金白银 直接成本超支 硬闸
墙钟时间 交互式场景的人等待阈值 用户流失 硬闸（对交互）/ 软闸（对批处理）
工具调用次数 有些工具按次计费或有配额 配额耗尽 硬闸
副作用次数 不可逆动作做多了不可撤销 现实世界被改坏 硬闸，且不可续

"不可互相换算"的含义要具体化：

token→时间(并行/流式可改变比例),钱→副作用次数(免费的工具也可能不可逆)

所以工程上必须逐维检查，而且要知道"哪个维度先耗尽"只有运行时才知道：

耗尽时刻=argd∈Bmin​rd​Bdrest​​(rd​=该维度的消耗速率)

这给出一个有用的运行策略：定期重算"按当前速率，哪个维度最先见底"，并在它见底前 ~20% 就触发降级（第 4.4 节）。这就是"预算看板"的算法内容。

1.2 硬闸与软闸#

不是所有维度都该用同一种方式拦：

类型 行为 例子 为什么
硬闸 到达即终止（或强制升级给人） 金额、不可逆副作用次数、交互式场景的墙钟 越界是不可接受的，不是"贵一点"
软闸 到达即降级策略，不终止 token（压缩上下文）、时间（批处理） 越界可以接受，只是变差

把软闸当硬闸是常见的过度保守：上下文快满就终止任务，而正确的动作是剪裁/摘要（第 4 章）后继续。反过来，把硬闸当软闸是最危险的：副作用次数超标时"再试一次"，而每一次都是不可逆的现实改动。

1.3 剩余成本估计#

要知道"还能不能走完"，必须估计剩余成本。计划里通常只有先验（写计划时估的每步成本），而执行中有实测。最简单的估计是"未完步骤的先验之和"：

C^restprior​=i∈todo∑​c^i​

但它有一个系统性偏差：先验通常是乐观的（模型估成本倾向于低估外部调用的延迟与失败重试）。所以要用实测修正。两种常用形式：

（a）乘性修正（简单、稳健，推荐作为默认）：

C^rest​=∑i∈done​c^i​∑i∈done​cireal​​⋅i∈todo∑​c^i​=ρ⋅C^restprior​,ρ=先验实测​​done​

（b）加权混合（样本少时向先验收缩）：

C^rest​=w⋅C^restprior​+(1−w)⋅ρ⋅C^restprior​,w=n0​+ndone​n0​​

其中 n0​ 是"先验可信度"（等价于几个观测），ndone​ 是已完成步数。w 的形式说明一件事：刚开始执行时相信先验，执行得越多越相信实测。 这是贝叶斯式收缩的最简形态。

两个方向的估计偏差各有代价：

偏差 后果 缓解
低估（以为还够） 越界：硬闸触发时任务半途而废，已投入的成本沉没，还可能留下需要补偿的副作用 用悲观分位（如 P80​）而不是均值做硬闸判断
高估（以为不够） 过早放弃：本来能成的任务被停掉 用乐观分位做"是否值得继续"的判断，同时保留软闸降级

硬闸判断用悲观估计（防越界）;继续判断用乐观估计（防误杀）

这条"不对称"是本节最实用的一条工程规则。

1.4 成功率衰减：pN 什么时候过于悲观#

P=∏i​pi​ 假设独立性且一步失败即整体失败。两个假设都常常不成立：

  1. 可恢复性：失败的动作可以重试/换路径（第 3 节），于是它不必然杀死任务。引进"可恢复系数"：

Peff​=i∏​(1−(1−pi​)(1−ri​))

其中 ri​ 是第 i 步失败后能被恢复的概率。当 ri​ 高时，任务成功率远高于 pN —— 这就是"重试与回退是可靠性投资"的量化含义。 2. 错误相关性：同一个模型在同一上下文里的错误是相关的（第 1 章的误差累积），所以 ∏pi​ 既可能高估也可能低估，取决于错误是否同源。同源错误（同一个理解偏差）会让实际成功率低于乘积预测。 3. 判定噪声：pi​ 本身是估计值，N 大时乘积对 p 的敏感性极高：

∂lnp∂lnP​=N⟹单步 5% 的误差，20 步后被放大成约 100%

推论：不要相信精确的 P 值，只用它做量级判断（"这个任务需要几步"比"成功率是 0.36 还是 0.41"重要得多）。

二、剪枝：事前的分支定界#

2.1 剪枝的两种形态#

形态 时机 剪什么 需要什么
事前剪枝 计划阶段（第 2 节的 L4） 不可行/不划算的分支 成本下界 + 收益上界
事中剪枝 执行阶段 不再划算的进行中任务 剩余成本估计 + 剩余成功概率（最优停止）

2.2 分支定界：下界为什么必须"绝不低估成本"#

设节点的成本下界 LB(v)（走完这个分支至少要花多少）与收益上界 UB(v)（走完最多能得到多少价值）。剪枝规则：

剪掉 v⟺UB(v)−LB(v)≤0⟺LB(v)≥UB(v)

下界的正确性是全部安全性的来源：LB 必须满足

∀从 v 出发的完整解 s:LB(v)≤cost(s)

即绝不能高估成本下限。如果 LB 高估了，你会剪掉一个其实便宜的分支 —— 这不是"效率损失"，而是丢掉正确答案（剪枝是不可逆的信息损失）。

一个反直觉推论：LB 与 UB 都可以很粗糙，只要它们方向正确。

  • LB 取"剩余步骤数 × 最小单步成本" —— 虽然松，但绝不高估，安全。
  • UB 取"全部收益之和"（完全不考虑冲突） —— 虽然松，但绝不低于真实收益，安全。

剪枝的价值=被剪掉的节点数×每节点成本,剪枝的风险=P(LB 被高估)×C丢解​

工程上因此有一条倾向：宁可少剪，不可剪错。松的下界剪得少但永远安全；"聪明"的下界剪得多但一旦错就丢解。

2.3 三类安全的剪枝依据#

依据 剪什么 判据
可行性 违反硬约束的分支 前置必不成立（第 2 节 L3）、权限不足、被否决的路径
预算 走完必然越界的分支 LB(v)>Brest​（用悲观估计）
占优 严格更差的分支 存在 v′ 使得 cost(v′)≤cost(v) 且 goal(v′)⊇goal(v)（穷尽同样目标却更便宜）

第三条（占优剪枝）是最有价值的，因为它能剪掉大量"看起来不同但实质等价"的候选 —— 而这正是 LLM 生成多个计划时的典型形态：三个计划措辞不同、结构相同。判定占优需要一个计划的结构指纹（第 3 节的 plan_signature 就是这个东西）。

2.4 探索与利用：k 个候选解法怎么分预算#

当有 k 个候选解法（不同工具、不同数据源、不同分解方式）时，预算分配是一个两难：

先深后广：把预算全押在一个候选上 → 若它错，全部沉没
先广后深：先给每个候选一小笔"探针预算" → 用结果淘汰差的，再在好的上深投

"先广后深"在什么条件下严格更优？ 设候选 j 的成功概率为 pj​（未知），探针花费 cprobe​，探针能正确识别"这个候选能不能成"的概率为 q。两阶段策略的期望：

Ptwo-stage​≈1−j=1∏k​(1−qpj​) （至少一个候选通过探针）  然后深投最优候选

深投单候选的期望=pj​(随机选一个的话是 pˉ​)

于是"先广后深"的收益正比于候选之间的差异度：如果所有候选的 pj​ 都相同，探针不提供信息，纯浪费；如果差异大（有的 0.1、有的 0.8），探针的收益极大。

探针值得⟺Var(pj​) 大∧cprobe​≪cdeep​

工程形式（可实现的规则）：

cprobe​≤k1​⋅Brest​且cprobe​≤0.1⋅Brest​

即"探针预算占总量的一小部分，且每个候选至少能拿到一次探针"。这同时避免了两个极端：不探测（赌运气）与过度探测（把预算全花在比较上）。

三、事中剪枝：最优停止#

3.1 判据的推导#

到了某一步，问题是：继续投入，还是停下？用期望值写：

继续⟺期望收益Prest​⋅V​​>剩余成本Crest​​​+机会成本Copp​​​

其中：

  • Prest​：从当前状态走完并成功的概率（可用 ∏i∈todo​pieff​ 估计）。
  • V：成功的价值（要显式定义！"任务完成"的货币化或效用化）。
  • Crest​：剩余成本（1.3 的估计）。
  • Copp​：机会成本 —— 这条预算如果用在别的任务上能产生的价值。这是最容易被漏掉的一项。

"沉没成本不进判据"是硬要求：已投入的 Cspent​ 不出现在不等式的任何一边。理由：

继续⟺E[未来净收益]>0与过去的支出无关（过去不可改变）

但"剩余预算"要以机会成本形式进入：如果 Brest​−Crest​=0，那么继续就意味着"没有余量应对任何意外"，这个约束会抬高 Copp​：

Copp​≈λ⋅Brest​Crest​​⋅V(λ∈[0.1,0.5] 为风险厌恶系数)

形式不重要，重要的定性结论：预算越紧，同等收益下越应该早停 —— 因为余量本身就是一种价值（应对不确定性）。

3.2 边际形式：什么时候"再试一次"是负期望#

把判据写成边际形式更可操作。设第 n 次尝试的边际成功概率为 ΔPn​=Pn​−Pn−1​，单次成本为 c：

再试一次⟺ΔPn​⋅V>c+cdup​⋅P(重复副作用)

当边际成功概率递减时（通常如此），存在唯一的停止次数：

n∗=max{n:ΔPn​>Vc​}

n∗=max{n:ΔPn​>Vc​}

反直觉推论一：边际成功概率低于 c/V 时，无论已经失败多少次都应该停。直觉会说"都试了 5 次了，再试一次说不定就成" —— 这是沉没成本谬误。数学上每一次尝试都是独立决策。

反直觉推论二：提高 V 会让最优停止次数上升（更愿意试），而提高 c 会下降。所以"贵任务多做几次、便宜任务少做几次"这个直觉是反的 —— 正确的是"高价值任务多做几次、低价值任务少做几次"、"贵的尝试少做、便宜的尝试多做"。

3.3 与"时机"的关系#

最优停止还有一个时间维度：越早停越好（剩余成本越小）。所以判据应当在每个可能的停止点都重算一次，而不是只在失败后算：

在每个步骤边界重新评估：E[继续] vs E[停止]

这一条的实践含义是：停止不是"出错时才考虑"的异常路径，而是循环的常规分支之一。实现上它应该和"继续"在同一个 switch 里，共享同一份预算与概率估计。

3.4 降级：比"继续/停止"更好的第三选项#

真实系统里通常存在第三选项：降级交付。它把"全成或全败"的二值结果变成三值：

选项 条件 交付物
继续 E[继续]>E[降级] 完整结果
降级 剩余预算能覆盖降级路径，且降级产物 ≥ 最低验收线 部分结果 + 明确的"未完成项"
停止/升级 连降级都不可行，或降级产物低于最低验收线 结构化放弃报告（第 3 节）

降级的三种形态：缩范围（少做几个子目标）、降质量（用更便宜的模型/更少验证）、转人工（把剩余部分交给人）。选择依据是"哪种降级路径的成本最低且产物仍在验收线之上"。

降级可行⟺∃ 降级路径 d: Cd​≤Brest​ ∧ Quality(d)≥最低验收线

最后这个"最低验收线"必须是外部定义的（业务给的），不能由 Agent 自己判断 —— 否则它会为了"任务成功"而悄悄降低标准，这是最隐蔽的失效形态之一。

代码：多维预算 + 剩余成本估计 + 分支定界 + 最优停止#

下面的代码实现：(1) 多维预算闸门；(2) 剩余成本估计（先验 + 实测修正 + 乐观/悲观区间）；(3) 分支定界剪枝（安全的 LB + 占优剪枝）；(4) 最优停止判据（含沉没成本不进判据的验证）；(5) 探针预算分配对比。

"""
ch5-l4：多维预算闸门 + 剩余成本估计 + 分支定界剪枝 + 最优停止。

设计目标：把"该不该继续"从感觉变成可算的边际判据，
并保证剪枝的下界方向正确（宁可不剪，不可剪错）。
"""
from dataclasses import dataclass, field
from itertools import product


# ==================== (1) 多维预算 ====================
DIMS = ("step", "token", "money", "time", "call", "effect")


@dataclass
class Budget:
    """六维预算。

    ★ 设计决策：维度刻意不可换算（DIMS 之间没有汇率）。
      因为它们对应四种不可替代的稀缺：计算、钱、人的耐心、现实世界的不可逆改动。
      effect 维（副作用次数）尤其不能与 money 互换 —— 免费的工具也可能不可逆。
    """
    total: dict[str, float]
    used: dict[str, float] = field(default_factory=dict)

    def charge(self, **kw: float) -> None:
        for k, v in kw.items():
            assert k in DIMS, f"未知预算维度 {k}"
            self.used[k] = self.used.get(k, 0.0) + v

    def remaining(self) -> dict[str, float]:
        return {d: self.total.get(d, float("inf")) - self.used.get(d, 0.0) for d in DIMS}

    def first_exhausted(self) -> tuple[str, float] | None:
        """哪个维度先见底（剩余最少的绝对量）。"""
        rem = {d: v for d, v in self.remaining().items() if v != float("inf")}
        if not rem:
            return None
        d = min(rem, key=lambda k: rem[k])
        return (d, rem[d]) if rem[d] <= 0 else None

    def tightest(self) -> tuple[str, float]:
        rem = {d: v for d, v in self.remaining().items() if v != float("inf")}
        d = min(rem, key=lambda k: rem[k])
        return d, rem[d]

    def burns_at(self, rate: dict[str, float]) -> tuple[str, float]:
        """按当前消耗速率，哪个维度最先耗尽、还剩几轮（1.1 的看板算法）。"""
        best, best_rounds = None, float("inf")
        for d, r in rate.items():
            if r <= 0:
                continue
            rem = self.remaining().get(d, float("inf"))
            if rem == float("inf"):
                continue
            rounds = rem / r
            if rounds < best_rounds:
                best, best_rounds = d, rounds
        return best or "none", best_rounds


HARD_DIMS = {"money", "time", "effect"}
SOFT_DIMS = {"token", "call", "step"}


def gate(budget: Budget) -> dict:
    """★ 设计决策：硬闸/软闸分开处置（1.2）。

    硬闸越界 → 终止或升级；软闸越界 → 降级策略（压缩上下文、减少调用）后继续。
    把软闸当硬闸 = 过度保守（本来能压缩后继续）；把硬闸当软闸 = 灾难（副作用超标还再试）。
    """
    out = {"exhausted_hard": [], "exhausted_soft": [], "action": "continue"}
    for d, rem in budget.remaining().items():
        if rem != float("inf") and rem <= 0:
            (out["exhausted_hard"] if d in HARD_DIMS else out["exhausted_soft"]).append(d)
    if out["exhausted_hard"]:
        out["action"] = "terminate_or_escalate"
    elif out["exhausted_soft"]:
        out["action"] = "degrade_and_continue"
    return out


# ==================== (2) 剩余成本估计 ====================
def estimate_remaining(prior: dict[str, float], real: dict[str, float],
                       todo: list[str], n0: float = 3.0) -> dict:
    """先验 + 实测修正 + 收缩（1.3）。

    ★ 设计决策：返回乐观/悲观区间而不是单点估计 —— 因为两个方向的误差代价不对称：
      硬闸判断要用悲观分位（防越界），继续判断要用乐观分位（防误杀）。
    """
    done = [k for k in real if k in prior]
    prior_rest = sum(prior[k] for k in todo if k in prior)
    if not done:
        return {"rest": prior_rest, "optimistic": prior_rest * 0.8,
                "pessimistic": prior_rest * 1.6, "rho": 1.0, "w": 1.0,
                "note": "无实测样本：完全相信先验"}
    rho = sum(real[k] for k in done) / max(1e-9, sum(prior[k] for k in done))
    w = n0 / (n0 + len(done))                    # 样本少 → 向先验收缩
    blended = (w + (1 - w) * rho) * prior_rest
    return {"rest": round(blended, 2), "optimistic": round(blended * 0.85, 2),
            "pessimistic": round(blended * 1.5, 2),
            "rho": round(rho, 3), "w": round(w, 3),
            "note": f"实测/先验 = {rho:.2f}（{'先验偏乐观' if rho > 1 else '先验偏保守'}）"}


def success_prob(todo: list[str], p: dict[str, float],
                 recoverable: dict[str, float] | None = None) -> float:
    """1.4 的修正形式：P_eff = Π (1 - (1-p_i)(1-r_i))。

    ★ 设计决策：默认不给 r（不可恢复）会得到 p^N —— 悲观基线。
      给出 r 之后才能体现"重试与回退是可靠性投资"。
    """
    r = recoverable or {}
    out = 1.0
    for k in todo:
        pi = p.get(k, 0.9)
        ri = r.get(k, 0.0)
        out *= (1 - (1 - pi) * (1 - ri))
    return out


# ==================== (3) 分支定界剪枝 ====================
@dataclass
class Branch:
    name: str
    todo: list[str]
    goal: frozenset[str]
    cost_prior: dict[str, float]
    value: float                       # 收益上界（UB 的输入）


def lower_bound(b: Branch, min_cost: float) -> float:
    """成本下界 = 剩余步骤数 × 全局最小单步成本。

    ★ 设计决策：刻意取一个"松但绝不高估"的下界（2.2）。
      高估的下界会剪掉真实存在且便宜的可行解 —— 那是丢解，比少剪严重得多。
    """
    return len(b.todo) * min_cost


def prune(branches: list[Branch], budget_rest: float,
          min_cost: float) -> tuple[list[Branch], list[str], dict]:
    """三类安全剪枝：可行性（此处由 goal 为空表示）/ 预算 / 占优。"""
    kept: list[Branch] = []
    log: list[str] = []
    dominated: list[str] = []
    saved = 0.0

    for b in branches:
        if not b.goal:
            log.append(f"✗ 可行性：{b.name} 不产生任何目标事实")
            continue
        lb = lower_bound(b, min_cost)
        if lb > budget_rest:
            log.append(f"✗ 预算：{b.name} 下界 {lb:.1f} > 剩余 {budget_rest:.1f}")
            continue
        if b.value - lb <= 0:
            log.append(f"✗ 收益：{b.name} 价值上界 {b.value} ≤ 成本下界 {lb:.1f}")
            continue
        kept.append(b)

    # 占优剪枝：目标集更全 + 成本不更高的分支才保留（2.3 第三条）
    final: list[Branch] = []
    for i, a in enumerate(kept):
        is_dominated = False
        for j, c in enumerate(kept):
            if i == j:
                continue
            cost_a = sum(a.cost_prior.get(k, 1.0) for k in a.todo)
            cost_c = sum(c.cost_prior.get(k, 1.0) for k in c.todo)
            if a.goal <= c.goal and cost_c <= cost_a and (a.goal, cost_a) != (c.goal, cost_c):
                is_dominated = True
                dominated.append(f"{a.name} 被 {c.name} 占优")
                break
        if not is_dominated:
            final.append(a)
        else:
            saved += sum(a.cost_prior.get(k, 1.0) for k in a.todo)
    log.extend(f"✗ 占优：{d}" for d in dominated)
    return final, log, {"剪掉分支数": len(branches) - len(final),
                        "省下的预算估计": round(saved, 2)}


# ==================== (4) 最优停止 ====================
def should_continue(p_rest: float, value: float, cost_rest: float,
                    budget_rest: float, lam: float = 0.3) -> dict:
    """3.1 的判据。

    ★ 设计决策：接受 spent 参数吗？**不接受** —— 沉没成本绝不能进入判据。
      这是刻意的 API 设计：把 spent 从签名里拿掉，代码就不可能误用它。
      机会成本 C_opp 则显式进入：预算越紧，同等收益下越应早停。
    """
    c_opp = lam * (cost_rest / max(budget_rest, 1e-9)) * value
    ev_continue = p_rest * value - cost_rest - c_opp
    ev_stop = 0.0
    return {"期望继续": round(ev_continue, 3), "期望停止": ev_stop,
            "机会成本": round(c_opp, 3),
            "决策": "continue" if ev_continue > ev_stop else "stop"}


def marginal_stop(n: int, p_try: float, value: float, cost: float,
                  p_dup: float = 0.0, c_dup: float = 0.0) -> dict:
    """3.2 的边际形式：第 n 次尝试是否值得（ΔP_n · V > c + c_dup·P(dup)）。"""
    before = 1 - (1 - p_try) ** (n - 1)
    after = 1 - (1 - p_try) ** n
    delta = after - before
    threshold = (cost + c_dup * p_dup) / value
    return {"第 n 次": n, "ΔP": round(delta, 4), "阈值 c/V": round(threshold, 4),
            "值得": delta > threshold}


def n_star(p_try: float, value: float, cost: float) -> int:
    n = 0
    while marginal_stop(n + 1, p_try, value, cost)["值得"] and n < 100:
        n += 1
    return n


# ==================== (5) 探针预算分配 ====================
def probe_vs_deep(p_list: list[float], budget: float, deep_cost: float,
                  probe_cost: float, q: float = 0.85) -> dict:
    """2.4：先广后深 vs 直接深投的期望成功率对比（只做一次深投）。

    ★ 设计决策：这里把探针简化成"以概率 q 正确挑出最好的候选"，
      故意不建模误报（把差候选判为好）—— 因为本函数的目的是展示
      "候选差异度（方差）决定探针价值"这一**结构性结论**，
      而不是给出一个精确的成功率预测。真实系统里必须把误报率算进去，
      否则会高估先广后深的收益。
    """
    k = len(p_list)
    p_base = sum(p_list) / k                        # 基线：随机挑一个候选深投
    budget_after_probe = budget - k * probe_cost
    if budget_after_probe < deep_cost:
        return {"可行": False, "原因": "探针后预算不足一次深投"}
    p_best = max(p_list)
    exp_two = q * p_best + (1 - q) * p_base         # 挑对了→最好候选；挑错→随机水平
    return {"可行": True, "候选数 k": k, "候选成功率": p_list,
            "直接深投期望": round(p_base, 4),
            "先探后深期望": round(exp_two, 4),
            "候选方差": round(sum((p - p_base) ** 2 for p in p_list) / k, 4),
            "探针总花费": round(k * probe_cost, 2),
            "深投可用预算": round(budget_after_probe, 2),
            "结论": ("先广后深更优" if exp_two > p_base * 1.05 else "差异不大：探针不值")}

八处关键设计决策：

  1. DIMS 六维不可换算，且 charge 断言维度合法。这是 1.1 那条"钱 ≠ 副作用次数"的结构化表达 —— effect 维尤其不能与 money 互换，因为免费的工具也可能不可逆。
  2. gate() 把硬闸与软闸分开返回（HARD_DIMS / SOFT_DIMS）。把软闸当硬闸是过度保守（token 快满就终止，而正确动作是压缩后继续），把硬闸当软闸是灾难（副作用超标还"再试一次"，每次都是不可逆的现实改动）。
  3. burns_at() 实现"按当前速率哪个维度最先见底"。它的用途不是拒绝执行，而是在见底前约 20% 触发降级 —— 这是"预算看板"的全部算法内容。
  4. estimate_remaining 返回乐观/悲观区间而不是单点值，并在文档里明确"硬闸用悲观、继续判断用乐观"这条不对称规则。单点估计会逼你做一个隐含的对称假设，而两个方向的误差代价根本不对称。
  5. success_prob 实现了 1.4 的修正形式 Peff​=∏(1−(1−pi​)(1−ri​))，演示里把 20 步任务的成功率从 pN=0.359 提到 0.668（r=0.6）—— 这就是"重试与回退是可靠性投资"的量化形态。默认 r=0 得到悲观基线，避免夸大战绩。同一个演示还暴露了 1.4 的敏感性结论：单步 p 从 0.95 降到 0.90（只差 5.3%），20 步端到端从 0.359 掉到 0.122（相对 −66%）—— 所以 P 只能做量级判断。
  6. lower_bound 刻意用最松的下界（剩余步数 × 最小单步成本），注释写明理由是"高估的下界会剪掉真实存在的可行解，那是丢解，比少剪严重得多"。prune 里的占优剪枝则用"目标集更全且成本不更高"来剪掉 LLM 最常生成的"措辞不同、结构相同"的候选（演示里 plan-B 占优 plan-A）。
  7. should_continue 的签名里没有 spent 参数。这是刻意的 API 设计而不是文档约定：把沉没成本从签名里拿掉，代码就不可能误用它。机会成本 Copp​ 则显式进入，表达式 λ⋅(Crest​/Brest​)⋅V 体现"预算越紧越应早停"。
  8. marginal_stop / n_star 把 3.2 的边际判据做成可算的函数，演示刻意输出两组对比来暴露那个反直觉结论：V 上升 n∗ 上升（高价值任务值得多试），c 上升 n∗ 下降（贵的尝试少做）—— 与"贵任务多试几次"的日常直觉相反。

  6. 沉没成本：某任务已花 12 元（预算 15 元），剩余步骤的成功概率 0.2，剩余成本估计 4 元（悲观 6 元），成功价值 50 元，λ=0.3。请分别用"已花 12 元"与"已花 2 元"两种情形做判断，验证结论是否相同。然后回答：如果结论相同，为什么"已花的钱"在实际决策中会感觉上影响判断？这种感受在工程上叫什么谬误？

  7. 降级交付：某调研 Agent 预算 10 元，已完成 6 元的工作，剩余路线的期望：完整路线还需 6 元、质量 1.0；缩范围还需 2.5 元、质量 0.65；转人工 0.5 元、质量 0.4。最低验收线是 0.6。请选出最优选项并给出期望净收益计算。然后回答：如果 Agent 自己判断"质量 0.4 也算完成"，会发生什么？为什么最低验收线必须外部定义？

  8. 设计题：为一个"自动处理 50 条退款申请"的批处理 Agent 设计预算与剪枝策略。要求：(a) 六维预算的具体数值与理由；(b) 逐条退款的"继续/降级/放弃"判据（要写出 Prest​、V、Crest​ 的来源）；(c) 哪些剪枝可以事前做（例如"金额低于 5 元的申请不值得走完整流程"）；(d) 整体预算与单条预算的关系（提示：需要"逐条分配 + 全局看板"两层，否则一条卡住会吃掉所有预算）。最后说明：为什么在批处理场景里，"逐条预算上限"比"全局预算上限"更能防止一条拖垮全部？

小结#

  • 预算是六维向量 (Bstep​,Btoken​,Bmoney​,Btime​,Bcall​,Beffect​)，维度之间不可换算：token ≠ 时间（并行/流式改变比例）、钱 ≠ 副作用次数（免费工具也可能不可逆）。必须逐维检查，且"哪个维度先耗尽"只有运行时按速率 Bdrest​/rd​ 才能算出来。
  • 硬闸与软闸必须分开：硬闸（金额、时间、副作用次数）到达即终止或升级；软闸（token、调用次数）到达即降级后续命。把软闸当硬闸是过度保守，把硬闸当软闸是灾难。
  • 剩余成本估计要"先验 + 实测修正 + 收缩"：C^rest​=∑c^∑creal​​done​⋅C^restprior​，样本少时向先验收缩（w=n0​/(n0​+n)）。两个方向的偏差代价不对称：硬闸判断用悲观分位（防越界），继续判断用乐观分位（防误杀）。
  • P=∏pi​ 常常过于悲观，因为失败未必杀死任务。修正形式 Peff​=∏i​(1−(1−pi​)(1−ri​))，ri​ 是"失败后可恢复的概率" —— 这就是"重试与回退是可靠性投资"的量化含义。同时注意敏感性：∂lnP/∂lnp=N，单步 5% 的估计误差在 20 步后被放大成量级错误，所以 P 只能做量级判断。
  • 剪枝分两种：事前（分支定界：LB(v)≥UB(v) 即剪）与事中（最优停止）。下界绝不能高估成本，否则会剪掉真实存在的可行解 —— 那是丢解，比少剪严重得多，且不可逆。因此宁可取松的下界（剩余步数 × 最小单步成本）。
  • 三类安全剪枝：可行性、预算、占优（目标集更全且成本不更高）。占优剪枝专门对付 LLM 生成的"措辞不同、结构相同"的候选。
  • 最优停止判据：继续 ⟺Prest​⋅V>Crest​+Copp​。沉没成本绝不能进入判据（本节的实现方式是把 spent 从函数签名里删掉），而剩余预算要以机会成本形式进入（预算越紧越应早停）。边际形式：再试一次 ⟺ΔPn​⋅V>c+cdup​P(dup)，反直觉推论是高价值任务多做几次、贵的尝试少做。
  • 停止是循环的常规分支，不是异常路径：每个步骤边界都该重算一次。而且真实系统通常有第三个选项 —— 降级交付（缩范围 / 降质量 / 转人工），判据是 Cd​≤Brest​ 且 Quality(d)≥ 外部定义的最低验收线。让 Agent 自己定验收线，它会为了"成功"悄悄降低标准。
