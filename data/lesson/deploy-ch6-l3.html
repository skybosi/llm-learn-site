验收与总结#

服务跑起来了不算完，通过验收才算交付。这一课做三件事：用脚本把上一课的 SLO 逐条验收、做一次故障演练看服务扛不扛得住、最后把整门课程串成一张知识地图，给你一条清晰的收尾与进阶路径。

一、概念讲解#

1. 验收要验三样东西#

  • 性能达标：压测结果满足 SLO（P99 TTFT、吞吐、可用性）；
  • 正确性可用：真实业务样例能给出正确、格式合规的回答；
  • 稳定性扛得住：故障演练——把组件杀掉、把显存打满，看服务能否自愈或至少不"静默崩溃"。

三者缺一不可：只压测不看正确性，可能"又快又错"；只看正确性不演练，可能"平时好、出事就瘫"。

2. 验收脚本怎么写#

验收脚本和普通压测的区别在于它自己会下结论：跑完样本后计算分位数，再用 assert 对照 SLO 判断通过/失败。这样验收结果可复现、可写进交付文档，也方便日后回归。

3. 故障演练的价值#

演练不是制造事故，而是提前暴露单点。典型动作：docker compose kill vllm 观察健康检查与重启；把 gpu_memory_utilization 临时调到 0.98 制造 OOM；断开监控看告警是否触发。练一次，比上线后半夜被电话叫醒强一百倍。

二、可运行示例#

示例 1：验收压测脚本（断言 P99 TTFT）#

# -*- coding: utf-8 -*-
# 验收脚本：走网关压测，断言 P99 TTFT 达标
import time, asyncio, aiohttp

BASE = "http://localhost:8080/v1/chat/completions"   # 走网关
MODEL = "support-assistant"

async def measure_ttft(session):
    payload = {
        "model": MODEL,
        "messages": [{"role": "user", "content": "我的订单什么时候发货？"}],
        "max_tokens": 100, "stream": True,           # 流式才能测 TTFT
    }
    t0 = time.perf_counter()
    ttft = None
    async with session.post(BASE, json=payload) as r:
        async for line in r.content:                 # 逐行读 SSE
            if line.startswith(b"data: [DONE]"):
                break
            if line.startswith(b"data: ") and ttft is None:
                ttft = time.perf_counter() - t0      # 首个内容分片即 TTFT
    return ttft or (time.perf_counter() - t0)

async def run(n_req=100, concurrency=10):
    sem = asyncio.Semaphore(concurrency)
    async with aiohttp.ClientSession() as sess:
        async def one():
            async with sem:
                return await measure_ttft(sess)
        return await asyncio.gather(*[one() for _ in range(n_req)])

ttfts = asyncio.run(run())
ttfts.sort()
p99 = ttfts[int(len(ttfts) * 0.99)]
print(f"样本 {len(ttfts)} 个，P99 TTFT = {p99*1000:.0f} ms")
assert p99 <= 1.5, f"SLO 不达标：P99 TTFT 超过 1.5s（实测 {p99:.2f}s）"
print("✅ 验收通过：P99 TTFT ≤ 1.5s")

示例 2：正确性冒烟样例#

# -*- coding: utf-8 -*-
# 用几条真实业务样例，检查回答是否可解析、非空、含关键信息
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/v1", api_key="EMPTY")
cases = [
    "我的订单什么时候发货？",
    "如何申请退货？",
    "你们的客服电话是多少？",
]
for q in cases:
    r = client.chat.completions.create(
        model="support-assistant",
        messages=[{"role": "user", "content": q}],
        max_tokens=100,
    )
    answer = r.choices[0].message.content
    ok = bool(answer and answer.strip())
    print(f"[{'PASS' if ok else 'FAIL'}] {q} -> {answer[:30]}...")

三、练习#

  1. 用示例 1 的脚本，把并发从 10 提到 40 重跑，观察 P99 TTFT 是否仍达标；若失败，回到第 5 章 l2 的思路找出甜点并发并写进交付文档。
  2. 给示例 2 增加一条"输入为空"的边界用例，看服务是友好返回还是崩溃，说明边界测试的必要性。
  3. 执行示例 3 的"杀容器"演练，记录从 kill 到服务恢复的耗时，评估它是否落在你的可用性 SLO 预算内。
