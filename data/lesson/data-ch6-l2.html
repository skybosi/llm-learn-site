数据契约：管线与下游之间唯一可执行的接口#

这一节要解决什么#

第 1 节冻结了配方，但它冻结的是上游（数据怎么被造出来）。管线与下游之间还缺一份东西：下游凭什么相信这批数据能用？

现实里这件事通常靠三种方式"解决"：口头同步（"字段没变"）、文档（一份 README）、或者干脆什么都不做（"反正都是我们自己在用"）。这三种方式在数据没坏的时候都能用，问题在于它们在数据坏的时候全都不会响。第 1 章把这种错误叫静默错误；这一节要给的，是让静默错误变成响亮的拒绝的那份接口。

它要回答四个具体问题：

  1. 契约该管什么？ 9 个字段、6 类判据（类型 / 空值率 / 取值域 / 词表 / 唯一率 / 分布）。本节实测六种故障全部被拒，并补上两种只有唯一性与分布判据能抓的故障：50% 复制率的批在逐行取值判据下全部通过，但 text 唯一率掉到 0.5000。
  2. 判据的严格程度怎么定？ 判据写成"T>τ 就拒收"，两个错误是弃真（好批被拒）与取伪（坏批被收）。最优 τ 由两者的似然比与成本比共同决定：实测 τ∗=0.02439，在该点上 P(拒∣好)=0.1007、P(收∣坏)=5×10−4。把 τ 挪到 0.0300（+23%），期望成本从 0.006534 涨到 0.068587（涨 10 倍）。
  3. 同时查很多个字段会怎样？ 9 个字段各用 α=0.001 单测，每批至少一次误报的概率（FWER）是 1−(1−α)m=0.00896（0.896%）；Bonferroni 校正后 0.00100（0.100%）。按每天 30 批算，误报从 0.27 次/天降到 0.03 次/天。
  4. 告警要不要"连续两个批次都越线"？ 本节给出一条硬约束：如果真实漂移只落在一个字段上，要求 k 个字段同时越线就等于检不出来（P(检出)=sk，s=0.7 时 k=2 只剩 0.490）。因此工程上用的是同一字段连续 k 个批次越线，而它的最优 k 是成本比的函数：Cslip​/Calert​ 从 1 涨到 5，k∗ 就从 2 掉回 1。

一、契约是什么，以及为什么它必须是可执行的#

1.1 概念：契约是一组「不满足就拒绝」的谓词#

一份数据契约包含三样东西：

Contract=(字段与类型F​​, 逐字段谓词P​​, 批级与时效约束B​​)

本节代码里 F 有 9 个字段，P 有 6 类谓词（type / null_max / min,max 或 enum / len_min,len_max / unique / uniq_min / ks_max），B 有 3 条批级约束 + 2 条时效约束。

与"文档"的关键差别是：谓词有返回值。文档能说的最硬的话是"quality 应当在 [0,1]"，谓词能说的是"这一批里有 4000 行 quality > 1，所以拒收"。

1.2 为什么契约要「拒收」而不是「修正」#

一个自然的疑问：既然能检测出空值率超标，为什么不顺手把它修掉？

因为修正会把一个可检测的故障变成一个不可检测的故障。第 3 节会实测这件事的一个近亲：埋点丢失后用默认值补齐，均值只从 0.8499 变到 0.8000，但标准差从 0.05037 塌缩到 0.0000 —— 而如果下游根本不知道上游补过值，它连"该去看标准差"这件事都不会想到。

契约的语义应当是二值的：满足则放行，不满足则停止并交给人。修正只能发生在明确声明过的位置（例如"缺失值填充"是契约里一个显式字段，而不是解析器的默认行为）。

1.3 判据清单：六类谓词各自管什么#

判据 写法 管什么 漏掉它会怎样
type 逐值类型检查 类型漂移（float→str） 下游算术静默产生 NaN 或字符串拼接
null_max 空值率上界 上游字段消失 / 解析失败 缺失被"看起来正常"的默认值填满
min,max / enum 取值域或词表 单位变化、枚举扩展 单位从 % 变小数，分布整体位移
len_min,len_max 字符串长度域 截断、拼接错误 长文档被截半，训练时静默丢信息
unique / uniq_min 主键唯一性、唯一率 重复灌入、连接错误 复制率上升，等价于隐式加权采样
ks_max 与参考分布的 KS 上界 分布漂移（非逐值） 无法被任何逐值判据发现

这张表的下一节（第 3 节）会把最后一行的 KS 判据换成更可解释的 PSI 与 AUC，但在契约层，KS 的价值在于它自带零分布：可以直接把"离参考多远算远"换算成显著性水平，从而定价。

1.4 为什么契约要参与版本#

代码实测：9 处候选变异全部换了版本：

  删掉 source 列               是         拒收整批
  新增一列 note                 是         放行（前向兼容）
  quality 由 float 变 str     是         拒收（破坏契约）
  lang 词表新增 ja              是         需评审后换版本
  ks_max 0.020 -> 0.025     是         放行但换版本
  批最小行数 1e6 -> 5e5          是         合规章限，拒收
  license 去掉 cc0            是         拒收（合规）

注意这 7 行里契约层的动作是不同的：删列是拒收、新增列是放行、词表扩展要评审、阈值放松放行但换版本。这是契约与普通校验脚本的另一个差别：契约不仅回答"合不合法"，还回答"该怎么处理"。

"新增一列放行（前向兼容）"是一条重要的设计选择：只增字段不改语义是兼容的，因为下游可以忽略不认识的列。反过来，删列、改类型、改语义是不兼容的，必须走版本递增 + 下游确认。

1.5 取舍与边界#

  • 契约越严，弃真越多。 一个把所有字段都设成 null_max=0、enum 穷举的契约会把大量合法数据挡在门外。严格程度必须与"误收一个坏批要付多少钱"挂钩 —— 这是 §3 全部的内容。
  • 契约不能代替监控。 契约在入口检查，监控在运行中检查。一个批可以在入口完全合法、在三次转换之后变得不可用。两者的关系是"入口 + 出口"，不是替代。
  • 契约也不能代替纪律。 例如"这批数据只用一次、不许回流到训练集"这种约束无法写成逐值谓词，只能写成流程规定（第 4 章的反向去污染）。

二、六种故障与逐条判据的实测#

2.1 概念：故障要能被"定位到字段"#

一个好的契约不只说"这批不合格"，还要说"是哪个字段的哪条判据不合格"。本节代码的 check_batch 返回一个列表，每项形如 quality:类型(str) 或 lang:空值率0.3333>0.0100。

实测六种故障（⚠️ 合成批，20 万行）：

  故障          被拒      触发的判据
  缺列          是       source:缺列
  类型漂移        是       quality:类型(str)
  空值潮         是       lang:空值率0.3333>0.0100
  词表漂移        是       lang:词表外
  主键重复        是       doc_id:主键重复
  取值越界        是       quality:高于上界
  干净批是否被拒：否（这是弃真率的分母）

最后一行是本节的对照臂：一个抓不出干净批的契约是坏的。任何契约上线前，第一件事都是拿一份已知干净的数据跑一遍，把"弃真率的分母"测出来。这一步看起来多余，但它能抓住最常见的一类错误：判据写得比数据严（例如把 float 的整数取值也当类型错误）。

2.2 为什么每种故障都只在一个字段上留痕#

实测的六种故障里，每一种都只触发一个字段上的判据。这说明两件事：

  1. 定位是容易的（只要契约覆盖了那个字段）；
  2. 覆盖是全部。如果监控词表里没有那个字段，故障就完全没有声音 —— 这正是 §7 的静默失效。

2.3 只有唯一性与分布判据能抓的故障#

六种故障都是"逐值可判"的。再看两种逐值不可判的：

  50% 复制率的批：text 唯一率 = 0.5000（契约 >= 0.995）-> 报警
                    doc_id 唯一率 = 0.5000（契约 unique）-> 报警
  而逐行取值判据（type/min/max/enum）全部通过 —— 唯一性判据是独立的第二道网。

一个 50% 复制率的批，每个值都合法、类型都对、词表都在、范围都合规。只有唯一率与分布这两类判据能发现它。这解释了一个常见的疑惑："我们的校验很全，为什么重复率还是上去了？"——因为"全"指的是逐值判据全，而重复是集合级性质。

第 2 章的内容指纹（MinHash / 后缀数组）解决的正是这一类问题，而这一节要补的是：契约里必须有一条集合级判据，哪怕它只是一个粗粒度的唯一率下界。

2.4 怎么做：判据的四个实现细节#

  1. 空值率要用"整批"做分母，而不是"非空值"做分母。null_max=0 的语义是"一个空值都不许有"，用非空做分母会让它永远成立。
  2. 范围判据必须先过滤类型。本节代码第一次写的时候就在 type(str) 的值上直接比大小，抛了 TypeError。正确的顺序是：先类型判据、再范围判据，且范围判据只在类型合格的值上执行。
  3. 布尔类型要单独挡。Python 里 isinstance(True, int) 为 True，所以 doc_id 是 int 时一个 True 会通过类型检查。契约实现里必须显式排除 bool。
  4. 唯一率要有明确的口径：len(set(values))/len(values) 是"去重后的比例"，与"重复率"互为补数。写进契约时要写清是哪一个。

三、判据的定价：弃真 vs 取伪#

3.1 概念：判据是一个假设检验#

把判据统一写成：

拒收⟺T>τ

其中 T 是统计量（本节用两样本 KS），τ 是门槛。两个错误：

α(τ)=弃真：好批被拒P(T>τ∣H0​)​​,β(τ)=取伪：坏批被收P(T≤τ∣H1​)​​

α(τ)=弃真：好批被拒P(T>τ∣H0​)​​,β(τ)=取伪：坏批被收P(T≤τ∣H1​)​​

这里 H0​ 是"这批与参考同分布"，H1​ 是"这批漂移了 δ"。门槛的期望成本：

C(τ)=Crej​⋅α(τ)+Cpass​⋅β(τ)

Crej​ 是拒收一个好批的代价（重新检查、人工确认、延迟），Cpass​ 是放进一个坏批的代价（坏数据流到下游并造成损失）。本节取 Crej​=0.05、Cpass​=3.00 人周，成本比 60:1。

3.2 为什么 Cpass​/Crej​ 是唯一真正要商量的量#

C(τ) 的最小值由两件事决定：α 与 β 的似然比（统计性质）和两个成本（组织性质）。前者只能靠数据算，后者只能靠商量。而后者往往被跳过，导致门槛被"经验值"占位（"KS 超过 0.05 就报警"）。

本节的实测把这件事变得可读：

    C_pass/C_rej=     1 -> tau*=0.03020  P(拒|好)=2.046e-02  P(收|坏)=2.300e-02  成本=0.002173
    C_pass/C_rej=     5 -> tau*=0.02679  P(拒|好)=5.431e-02  P(收|坏)=7.000e-03  成本=0.004466
    C_pass/C_rej=    20 -> tau*=0.02439  P(拒|好)=1.007e-01  P(收|坏)=5.000e-04  成本=0.005534
    C_pass/C_rej=    60 -> tau*=0.02439  P(拒|好)=1.007e-01  P(收|坏)=5.000e-04  成本=0.006534
    C_pass/C_rej=   300 -> tau*=0.02439  P(拒|好)=1.007e-01  P(收|坏)=5.000e-04  成本=0.012534

读法：当 Cpass​/Crej​ 从 1 涨到 300，τ∗ 从 0.03020 收紧到 0.02439（用更多误报换更少误收）；而 τ∗ 在 20 以上不再变化，因为 β 已经撞到蒙特卡洛的下限（β=5×10−4 就是 1/2000，即 2000 次模拟里只有一次没被检出）。最后一行说明：继续加大成本比不会让你更安全，只会更贵 —— 想更安全必须改判据（例如换统计量或加大样本量），不是改门槛。

3.3 怎么做：α 用解析、β 必须用模拟#

本节代码把两件事分开：

  • α(τ) 用 Kolmogorov 分布的 Γ 近似（解析）：

α(τ)≈2k=1∑∞​(−1)k−1exp(−2k2(ne​​+0.12+0.11/ne​​)2τ2),ne​=n+mnm​

  • β(τ) 用2000 次蒙特卡洛的备择样本经验 CDF。

为什么要分开？因为非中心 KS 分布没有可靠的闭式。本节先试了渐近式，结果在 ne​=2500、δ=0.10σ（DS=5.0）这种量级上，它给出的取伪率恒为 1，完全失真。代码里把这句话写进了输出，作为给读者的警告：

  ⚠️ 这一步是唯一必须靠模拟的地方：非中心 KS 分布没有可靠的闭式，先试过渐近式，在 DS=5.0 这种量级上它给出的取伪率恒为 1，完全失真。

3.4 怎么做：最优门槛与平坦区#

实测最优值 τ∗=0.02439：

  最优门槛 tau* = 0.02439，期望成本 = 0.006534 人周（P(拒|好)=1.007e-01, P(收|坏)=5.000e-04）
  平坦区（成本在最小值 5% 以内）：tau in [0.02414, 0.02439]（宽度 0.00025）；
  把 tau 从 0.02439 挪到 0.0300（+23%），成本从 0.006534 涨到 0.068587（涨 10 倍）

两个读法：

  • 平坦区很窄（宽度 0.00025），说明门槛对 τ 比较敏感，不能随手取整。
  • 往严的一侧挪的代价远大于往松的一侧：τ 从 0.02439 提到 0.0300 只动了 23%，成本涨 10 倍。这是成本比 60:1 的直接后果。

3.5 边界一：门槛必须对着"最小要抓的漂移"定#

同一个门槛在两个漂移幅度下的取伪率：

    delta=0.10 tau=0.04 -> P(收|坏)=0.2005
    delta=0.15 tau=0.04 -> P(收|坏)=0.0020
    delta=0.10 tau=0.06 -> P(收|坏)=0.9155

τ=0.06 对 δ=0.15 是够用的（取伪 0.2290），对 δ=0.10 就几乎完全看不见（0.9155）。所以"门槛定在 0.06"这句话没有意义，必须补一句"针对多大的漂移"。工程上的写法是：先定"必须抓住的最小漂移"，再解出让取伪率可接受的门槛。

3.6 边界二：τ 低于某个值时，检查本身就是主要成本#

  边界：tau 低于 0.0271 时弃真成本单项就超过 0.300 人周，检查本身会把好批挡在门外

τ=0.0271 是"α(τ)×Crej​=0.300 人周"的位置。越过它之后，弃真成本本身就和"一次坏批"同量级了 —— 那时候的问题不再是"检测够不够灵敏"，而是"这个检查是不是在制造问题"。

四、空值率阈值与多重比较#

4.1 概念：空值率阈值随「坏批先验」收缩#

空值率判据看似简单，但它的合理阈值随场景变化一个量级。本节模型：

  • 好批自身的空值率 pgood​=0.0005（10 万行里约 50 次）—— 注意不是 0；
  • 坏批的空值率 pbad​ 是场景相关的先验；
  • 判据是"空值数 ≤k 就放行"。

实测四档：

  坏批真实空值率                       最优 k    阈值(空值率)     P(拒|好)     P(收|坏)     
  新源（无历史，暂取 0.50）               109     0.00109     0.000e+00  0.000e+00  
  同族新源（历史 0.05）                 109     0.00109     0.000e+00  0.000e+00  
  已知源小版本（历史 0.01）               109     0.00109     0.000e+00  1.042e-176 
  已知源补丁（历史 0.001）               66      0.00066     9.797e-03  3.348e-04

同一个字段，"新源"的阈值 k∗=109（空值率 0.1090%）与"已知源补丁"的阈值 k∗=66（0.0660%）差 2 倍。这不是拍脑袋的差异，是坏批先验的差异：当坏批的空值率可能高达 50% 时，把 k 设得大一点几乎没有取伪风险；当坏批的空值率只有 0.1% 时，k 必须收紧才有分辨力。

4.2 怎么做：用解析上界代替模拟#

极端情形 pbad​=0.5 有一个干净的上界（Chernoff 型）：

P(空值数≤k∣p=0.5)≤2−(k+1)

实测：

    k= 5 -> 漏检率上界 1.562e-02
    k=10 -> 漏检率上界 4.883e-04
    k=17 -> 漏检率上界 3.815e-06
    k=20 -> 漏检率上界 4.768e-07
    k=30 -> 漏检率上界 4.657e-10

k 每加 1，上界减半。这条式子给了"要多少行才能把漏检率压到 10−6"的直接答案：k=20 就够（4.768×10−7），对应阈值 20/105=2×10−4。

4.3 概念：多重比较为什么必须处理#

9 个字段各用 α=0.001 单测，每批至少一次误报的概率是：

FWER=1−(1−α)m=1−0.9999=0.00896

实测每天 30 批 → 约 0.27 次/天误报。Bonferroni 校正 α/m=0.000111 之后 FWER 降到 0.00100，每天约 0.03 次：

  多重比较（Gamma 近似下的算术）：9 个字段各用 alpha=0.001 -> FWER = 0.00896（0.896%）
    Bonferroni alpha/m = 0.000111 -> FWER = 0.00100（0.100%）；每天 30 批 0.27 次 vs 0.03 次误报

Bonferroni 的代价是每个字段的灵敏度下降（α 变小，τ 变大）。对 m=9 这个规模它是可接受的；如果 m 到几百，就要用 max-statistic 置换检验或 FDR 控制，否则 Bonferroni 会把灵敏度压到没有。

4.4 怎么做：验证 Γ 近似准不准#

解析式有一个前提：样本量足够大。本节用 2000 次蒙特卡洛实测：

  n       tau(Gamma)      tau(经验分位数)        Gamma 的实测弃真率  经验门槛的弃真率      
  200     0.13405         0.13000           0.0495        0.0495        
  1000    0.06040         0.06000           0.0480        0.0500        
  5000    0.02710         0.02700           0.0490        0.0490

在 α=0.05 这个档上，Γ 近似在小样本上也能用（实测弃真率与名义值同量级）。但换到尾部：

  回到 alpha=0.001、n=5000（同一个 Gamma 近似）：tau(Gamma)=0.03889，2000 次零分布样本的 99.9% 经验分位 = 0.04080
    Gamma 门槛上的实测弃真率 = 0.00200（名义 0.001 的 2.0 倍）-> 尾部偏乐观
    delta=0.10 时：Gamma 门槛检出率 0.9820，经验门槛检出率 0.9780（差 0.0040）
    delta=0.15 时：Gamma 门槛检出率 1.0000，经验门槛检出率 1.0000（差 0.0000）

α=0.001 时实测弃真率是名义值的 2.0 倍。方向要说清：Γ 门槛比经验门槛更松（0.03889<0.04080），所以它既多放进一点漂移、也多放进 0.20% 的好批。收紧到经验门槛，δ=0.10 的检出率只掉 0.0040。

结论：判据表里必须有一条"门槛上线前用实测零分布分位数复核"。这不是学究气：2 倍的弃真率差异，在每天 30 批的规模上就是"每月多几次无谓的停线"。

4.5 边界：告警规则的硬约束#

一个自然的想法是"要求 k 个字段同时越线才算真事故"。本节实测一条硬约束：

  先看一条硬约束：如果真实漂移只落在一个指标上，要求 k 个指标同时越线
  就等于检不出来 —— P(检出|d=1) = s^k，灵敏度 0.7 时 k=2 就只剩 0.490。

如果一个事故的表现是"只有 quality 漂移"，那么 k=2 时检出率只剩 0.490，而 k=3 时是 0.343。所以工程上不能用"多字段同时越线"，只能用同一字段连续 k 个批次越线：

  基线（C_alert=1.0, C_slip=60.0, q=0.02, 单指标灵敏度 0.7, 单批 FWER=0.00896）：
    k=1: 每批误报率=8.964e-03  检出率=0.7000  期望成本=0.3688 人周
    k=2: 每批误报率=8.035e-05  检出率=0.4900  期望成本=0.6121 人周
    k=3: 每批误报率=7.203e-07  检出率=0.3430  期望成本=0.7884 人周
    k=4: 每批误报率=6.457e-09  检出率=0.2401  期望成本=0.9119 人周

而 k∗ 是成本比的函数：

    C_slip/C_alert=  1.0 -> k*=2（成本 0.0103 人周，检出率 0.4900）
    C_slip/C_alert=  5.0 -> k*=1（成本 0.0388 人周，检出率 0.7000）
    C_slip/C_alert= 20.0 -> k*=1（成本 0.1288 人周，检出率 0.7000）
    C_slip/C_alert= 60.0 -> k*=1（成本 0.3688 人周，检出率 0.7000）

Cslip​/Calert​=1 时"两次连续越线"最优；一旦漏检比误报贵 5 倍以上，k=1 立刻变成最优。所以"连续两个批次确认"不是一条通用纪律，而是一个由成本比决定的参数。

4.6 取舍与边界#

  • FWER 与灵敏度是一对交换。 本节用 Bonferroni 把 FWER 从 0.896% 压到 0.100%，代价是每个字段的门槛变严。m 越大这个代价越难接受。
  • ks_max 判据对重复不敏感（见 §5），所以它不能单独用。
  • 门槛必须与"必须抓住的最小漂移"一起写。 只写门槛的判据表是半成品。

五、一处边界：近重复批会让分布判据失去分辨力#

5.1 实测：复制会稀释 KS#

  用 n=20000 校准出的门槛 tau=0.01947 做判决：
    同分布对照                    KS = 0.01090 -> 放行
    纯漂移 delta=0.05           KS = 0.02575 -> 拒收
    50% 近重复 + 50% 漂移         KS = 0.01540 -> 放行

一个"50% 是漂移样本、50% 是从参考批逐字节复制的样本"的批，KS 从 0.02575 掉回 0.01540，落到门槛之下被放行。原因是分布统计量看的是整体形状：复制进来的那半与参考完全一致，把差异"稀释"了一半。

5.2 为什么这件事必须写在契约判据旁边#

因为近重复是数据管线里最常见的故障之一（采集重复、重跑重复灌入、上游分发错误），而它恰好是分布判据最不敏感的一类。这解释了第 2 章的内容指纹为什么不能省：

内容指纹（集合级）与契约判据（分布级 + 逐值级）必须并联。前者抓重复，后者抓类型/范围/分布；它们各自都有对方抓不到的东西。

5.3 取舍与边界#

  • 并联不是"都上"。 每一项判据都有成本（计算 + 维护 + 弃真）。并联的原则是"覆盖对方的盲区"，而不是"越多越好"。
  • 内容指纹也有盲区：它是逐字节的，抓不住"改了一个标点"的语义重复 —— 这一类要靠 MinHash / LSH 的近似重复检测（第 2 章）。
  • 近重复的代价是非线性的：它不只是"浪费存储"，它等价于对那部分样本的隐式加权，会改变配比的真实含义（第 3 章）。

六、契约与监控的分工#

把这一节的结论与第 3 节的分工提前写清楚，避免后面重复：

维度 契约（本节） 监控（下一节）
位置 入口 / 出口的批 运行中的时间序列
对象 一批数据的静态性质 多个批之间的变化
判据 谓词（真/假） 统计量 + 门槛 + 趋势
典型故障 缺列、类型漂移、越界 慢漂移、埋点丢失、指标塌缩
失败模式 误收坏批 / 误拒好批 告警疲劳 / 漏报
定价方式 弃真 vs 取伪（本节） 期望损失 + 到检延迟（下一节）

两者共用同一套成本语言（人周），这是它们能被统一决策的前提。

def check_batch(c, batch):
    bad = []
    for name, spec in c["fields"].items():
        if name not in batch:
            bad.append("%s:缺列" % name)
            continue
        col = batch[name]
        n = len(col)
        nn = [v for v in col if v is not None]
        nullr = 1 - len(nn) / n
        if nullr > spec.get("null_max", 1.0) + 1e-12:
            bad.append("%s:空值率%.4f>%.4f" % (name, nullr, spec["null_max"]))
            continue
        t = spec["type"]

        def ok(v, t=t):
            if t == "bool":
                return isinstance(v, bool)
            if t == "int":
                return isinstance(v, int) and not isinstance(v, bool)
            if t == "float":
                return isinstance(v, float) and not isinstance(v, bool)
            return isinstance(v, str)

        badtype = [v for v in nn if not ok(v)]
        if badtype:
            bad.append("%s:类型(%s)" % (name, type(badtype[0]).__name__))
        typed = [v for v in nn if ok(v)]
        if "enum" in spec and any(v not in spec["enum"] for v in typed):
            bad.append("%s:词表外" % name)
        if t in ("int", "float"):
            if "min" in spec and any(v < spec["min"] - 1e-12 for v in typed):
                bad.append("%s:低于下界" % name)
            if "max" in spec and any(v > spec["max"] + 1e-12 for v in typed):
                bad.append("%s:高于上界" % name)
        if t == "str":
            if "len_min" in spec and any(len(v) < spec["len_min"] for v in typed):
                bad.append("%s:过短" % name)
            if "len_max" in spec and any(len(v) > spec["len_max"] for v in typed):
                bad.append("%s:过长" % name)
        if spec.get("unique") and len(set(nn)) != len(nn):

                bad.append("%s:唯一率%.4f<%.4f" % (name, u, spec["uniq_min"]))
    return (len(bad) > 0, bad)

def ks_sf(x, ne):
    """KS 统计量的上尾 P(KS>x | H0)：Kolmogorov 分布的 Gamma 近似（含有限样本修正）。"""
    if x <= 0:
        return 1.0
    t = (math.sqrt(ne) + 0.12 + 0.11 / math.sqrt(ne)) * x
    s, sign, k = 0.0, 1.0, 1
    while True:
        term = sign * math.exp(-2.0 * k * k * t * t)
        s += term
        if abs(term) < 1e-18 or k > 200:
            break
        sign = -sign
        k += 1
    return max(0.0, min(1.0, 2.0 * s))

def ks_stat(a, b):
    a, b = sorted(a), sorted(b)
    i = j = 0
    d = 0.0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            x = a[i]; i += 1
        else:
            x = b[j]; j += 1
        while i < len(a) and a[i] == x:
            i += 1
        while j < len(b) and b[j] == x:
            j += 1
        d = max(d, abs(i / len(a) - j / len(b)))
    return d

def crit_gamma(n, alpha):
    """由 Gamma 近似反解临界值 tau：P(KS>tau)=alpha。"""
    ne = n * n / (2.0 * n)
    lo, hi = 1e-9, 0.4
    for _ in range(80):
        mid = (lo + hi) / 2
        if ks_sf(mid, ne) > alpha:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2

def crit_gamma(n, alpha):
    """由 Gamma 近似反解临界值：P(KS>tau)=alpha（ne = n/2 的两样本等量情形）。"""
    ne = n * n / (2.0 * n)
    lo, hi = 1e-9, 0.4
    for _ in range(80):
        mid = (lo + hi) / 2
        if ks_sf(mid, ne) > alpha:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2

def mc_null(n, reps, seed):
    rng = random.Random(seed)
    return sorted(ks_stat([rng.gauss(0, 1) for _ in range(n)],
                          [rng.gauss(0, 1) for _ in range(n)]) for _ in range(reps))

def mc_alt(n, delta, reps, seed):
    rng = random.Random(seed)
    return [ks_stat([rng.gauss(0, 1) for _ in range(n)],
                    [rng.gauss(delta, 1) for _ in range(n)]) for _ in range(reps)]

def upper_frac(arr, tau):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= tau:
            lo = mid + 1
        else:
            hi = mid
    return (len(arr) - lo) / len(arr)

=== 5. 蒙特卡洛：Gamma 近似在什么规模上失效 ===
  固定 alpha=0.05，比较 Gamma 近似临界值与经验分位数（每格 2000 次重复，⚠️ 合成抽样）
  n       tau(Gamma)      tau(经验分位数)        Gamma 的实测弃真率  经验门槛的弃真率      
  200     0.13405         0.13000           0.0495        0.0495        
  1000    0.06040         0.06000           0.0480        0.0500        
  5000    0.02710         0.02700           0.0490        0.0490        
  -> 在 alpha=0.05 这个档上，Gamma 近似在小样本上也能用（实测弃真率与名义值同量级）；
     但下面会看到：同一近似在 alpha=0.001 的尾部开始偏乐观。
     判据表因此有一条：门槛上线前必须用实测零分布分位数复核一次。
  回到 alpha=0.001、n=5000（同一个 Gamma 近似）：tau(Gamma)=0.03889，2000 次零分布样本的 99.9% 经验分位 = 0.04080
    Gamma 门槛上的实测弃真率 = 0.00200（名义 0.001 的 2.0 倍）-> 尾部偏乐观
    delta=0.10 时：Gamma 门槛检出率 0.9820，经验门槛检出率 0.9780（差 0.0040）
    delta=0.15 时：Gamma 门槛检出率 1.0000，经验门槛检出率 1.0000（差 0.0000）
  方向要说清：Gamma 门槛比经验门槛更松（0.03889 < 0.04080），于是实测弃真率是名义值的 2.0 倍。
  收紧到经验门槛，delta=0.10 的检出率只掉 0.0040（0.9820 -> 0.9780）——
  这就是为什么第 3 节的门槛 tau* 一定要拿实测零分布复核，而不是照抄渐近式。

  先看一条硬约束：如果真实漂移只落在一个指标上，要求 k 个指标同时越线
  就等于检不出来 —— P(检出|d=1) = s^k，灵敏度 0.7 时 k=2 就只剩 0.490。

  所以工程上用的是「同一指标连续 k 个批次越线」（consecutive-window 规则）：
  成本参数：一次误报 C_alert=1.0 人周；一次漏检 C_slip=60.0 人周
  基线（C_alert=1.0, C_slip=60.0, q=0.02, 单指标灵敏度 0.7, 单批 FWER=0.00896）：
    k=1: 每批误报率=8.964e-03  检出率=0.7000  期望成本=0.3688 人周
    k=2: 每批误报率=8.035e-05  检出率=0.4900  期望成本=0.6121 人周
    k=3: 每批误报率=7.203e-07  检出率=0.3430  期望成本=0.7884 人周
    k=4: 每批误报率=6.457e-09  检出率=0.2401  期望成本=0.9119 人周
  -> 在 C_alert << C_slip 的组织里，k=1 最优；把 k 提到 2 只省下 8.884e-03 的误报成本，
     却把检出率从 0.700 砍到 0.490。k* 是成本比的函数，不是越多越好。
  成本比扫描（C_slip/C_alert 越大越倾向 k=1）：
    C_slip/C_alert=  1.0 -> k*=2（成本 0.0103 人周，检出率 0.4900）
    C_slip/C_alert=  5.0 -> k*=1（成本 0.0388 人周，检出率 0.7000）
    C_slip/C_alert= 20.0 -> k*=1（成本 0.1288 人周，检出率 0.7000）
    C_slip/C_alert= 60.0 -> k*=1（成本 0.3688 人周，检出率 0.7000）

练习#

  1. 给你的表写一份契约。 从 §1.3 的六类判据里选出你实际会用的，逐条写出：字段名、判据、阈值、阈值是怎么定出来的（成本比？合规？历史分布？）。写不出"怎么定出来"的判据，标成"待定价"。
  2. 测一次弃真率。 拿一份已知干净的数据跑契约，记录被拒的比例。如果不是 0，逐条定位是哪个判据误伤，并回答：是判据太严，还是数据本身就该被拒？
  3. 算一次成本比。 用你项目的数字估 Cextrej​ 与 Cextpass​。然后回答：在 Cextpass​/Cextrej​ 下，你现有的阈值是偏松还是偏严？偏多少？
  4. 构造一个"逐值全过、集合级被抓"的故障（类似 §2.3 的 50% 复制率），验证你的契约里至少有一条集合级判据能抓住它。抓不住的话，说明缺哪一类判据。
  5. 复核一个门槛。 选你契约里一条分布判据（KS 或 PSI），用实测零分布的 99.9% 分位复核解析门槛。两者差多少？换算成"每月多几次误报"是多少？
  6. 做一次多重比较的账。 你有多少个字段在做单测？把 α 统一到多少才能让 FWER 落在你能接受的水平？为此每个字段的灵敏度会掉多少（用 δ=0.10 的取伪率估）？
  7. 设计一个告警规则并定价。 给出 Cextalert​ 与 Cextslip​ 的估计，算出 k∗。如果你的组织实际用的是 k=2，请说明你们的成本比隐含是多少；如果这个隐含值与你估的差很远，说明规则需要改，还是你的成本估计需要改？

小结#

  • 契约是一组"不满足就拒绝"的谓词，不是文档。它与文档的差别在于谓词有返回值，能指出"是哪个字段的哪条判据"不合格。
  • 拒收而不是修正：修正会把可检测的故障变成不可检测的故障（第 3 节的方差塌缩是同一件事的近亲）。
  • 六类判据各有盲区，必须并联：逐值判据抓类型/范围/词表，唯一率与分布判据抓重复与漂移。50% 复制率的批在逐值判据下全部通过，只有唯一率能抓。
  • 门槛是内点解：$ au^*=0.02439$，由 Cextpass​/Cextrej​ 与似然比共同决定。$ au$ 往严的一侧挪 23%，成本涨 10 倍。门槛必须与"最小要抓的漂移"一起写。
  • 取伪率只能靠模拟：非中心 KS 分布没有可靠的闭式，渐近式在大非中心参数下给出恒为 1 的取伪率。α 可以解析算，β 必须抽样。
  • 多重比较必须处理：9 个字段 α=0.001 时 FWER =0.896%（每天 0.27 次误报），Bonferroni 后 0.100%（0.03 次）。
  • 解析门槛要复核：α=0.001 时 Γ 近似的实测弃真率是名义值的 2.0 倍（0.03889 vs 经验分位 0.04080）。收紧到经验门槛，检出率只掉 0.0040。
  • "多字段同时越线"是错的规则：漂移只落在一个字段上时 P(ext检出)=sk（s=0.7、k=2 → 0.490）。要用"同一字段连续 k 个批次"，而 k∗ 由 Cextslip​/Cextalert​ 决定。
  • 近重复会稀释分布判据：KS 从 0.02575 掉回 0.01540 就放行了。内容指纹（集合级）与契约判据必须并联。
