项目：三个 kernel 的实现与报告#

前两课给了方法与衔接面，但方法只有在别人能复核时才算成立。本项目交三件东西：三个代表不同瓶颈类型的 kernel（带宽/流式/算力受限各一）、一个验收/计时 harness、以及每份都回答"为什么快 / 瓶颈在哪 / 还剩什么没榨出来"的报告。下面的 harness 可照抄：它自己测量屋顶、用容差门挡住错误实现，并给报告打分——不合格会被退回。

一、概念讲解#

1. 交付物与验收标准#

三个 kernel 要覆盖三种瓶颈：

kernel 瓶颈类型 关键量 优化主线
softmax（4096²） 超越函数 + 带宽 每个元素一次 exp 行分块 + in-place，第二遍触碰收进 L2
reduction（16M） 纯带宽 只读一遍 分块两级归约，与库实现对齐
GEMM（512³） 算力 2N3 FLOPs tiling 提升复用（第 4 章）

每个 kernel 交朴素版 + 优化版，且要过四道门：正确性门（与参考实现逐元素对齐并给容差）、计时门（预热后多次取最小值）、搬运账（报字节，不只报时长）、屋顶对照（声明适用屋顶并算出 SOL 与剩余空间）。这与第 1 课的"三问法"是同一件事，只是把口头三问变成了必填字段。

2. 三问怎么落到数字上#

为什么快只能用一个对照回答：同一问题的朴素实现与优化实现的时间比。"5.10 ms → 0.195 ms，26.2x，因为搬运算降了 32 倍"才算答案。注意提速与搬运降幅不必相等：本次 GEMM 搬运降 64 倍、时间只快 51.9 倍，差额来自分块自身的循环开销。

瓶颈在哪要写"卡在哪一类屋顶"。做法是把每类屋顶的地板时间都算出来取最大者：

tfloor​=max(BWroof​bytes​, Froof​FLOPs​, Sroof​exp 次数​)

binding 的那项就是瓶颈，headroom=t实测​/tfloor​ 就是"还剩多少"。算力屋顶不能套到只做加法的 kernel 上，故每个 kernel 要显式声明适用屋顶——这也是报告卡的硬条件之一。

还剩什么要给下一步的具体动作："分块已把第二遍触碰收进 L2，但第一遍仍要全量读输入，再压只能融合上游算子"——它指向具体改动，并说明当前方案为什么到头了。

3. 屋顶为什么必须实测，而且不止"一个数"#

规格书峰值假设满占用、理想访存、无降频，而同机三种风格测出的数字差别就很大：本次运行测得纯拷贝带宽 100.0 GB/s、库实现 fp32 算力 0.30 TFLOP/s、in-place exp 吞吐 739.5 Melem/s。而且屋顶本身也是测量值：连测三次，带宽在 92～103 GB/s、库算力在 0.23～0.31 TFLOP/s 间浮动，报告该写区间而非单点。

更关键的是选错屋顶会得出荒谬结论。softmax 的字节账只有 2 个数组大小（各 64 MiB），只按带宽算地板是 1.34 ms，而实际耗时 33.3 ms，会得到"还剩 24.8 倍空间"的假结论；把 exp 吞吐算进屋顶后（4096² 次 exp ÷ 739.5 Melem/s ≈ 22.7 ms），SOL 是 68.1%、"还剩 1.47x"才可信。低 SOL 不等于有空间，也可能只是还没测到真正 binding 的资源。

工程做法：三类屋顶都用与目标 kernel 同量级、同访问风格的参照来测（见下方 harness），并在报告里写明参照——换机器方法照样成立。

4. 报告卡：把"写得好不好"变成可执行的检查#

报告卡由七条硬条件组成：正确性门、计时方式、搬运账、屋顶对照、片上预算、瓶颈判定、剩余空间说明。其中"片上预算"最容易漏也最致命：分块的前提是 tile 装得进目标存储层，声称 64 MiB 的 tile 落在 8 MiB 预算里，方案就不成立——代码里的反例自检演示了它被退回。

把验收写成代码有两个好处：人不会漏项（跑一次就知道缺哪条），产出变成机器可读的 report.json，可进 CI、可做前后对比，也可把"还剩 3.45x"当下一轮基线。

5. 常见坑#

  • 只交优化版：没有朴素版就没有"为什么快"，第一问无法回答。
  • 容差给得太松：atol=1e-1 能放过任何错误实现；容差要按 dtype 与累加长度选。
  • 计时不带预热：首次调用含惰性初始化与 autotune，测到的是编译时间。
  • 拿单次测量当结论：取最小值是为了排噪声，但要同时报波动。
  • 把"库实现"当绝对上限：它也可能没打满硬件，SOL 只作方向判断。

二、可运行代码示例#

下面的 harness 用 numpy 实现三个 kernel 的 CPU 参照版（GPU 上把实现换成 CUDA kernel，结构不变），完成：实测三类屋顶 → 正确性门 → 计时 → 搬运账 → 屋顶对照 → 报告卡校验 → 反例自检 → 落盘 report.json。

# ===== 本课示例：三个 kernel 的验收 + 报告卡流水线（numpy，无 GPU 可完整跑通）=====
# 报告卡回答三问：为什么快 / 瓶颈在哪 / 还剩什么没榨出来。
# 关键设计：屋顶不抄规格书，而是在同一台机器上实测三类屋顶——带宽 / 算力 / 超越函数吞吐。
import json
import time

import numpy as np

WARMUP, REPEAT = 2, 5

def bench(fn, *args):
    """预热 WARMUP 次，取 REPEAT 次里的最小值（最小值最接近真实能力，受噪声干扰最小）。"""
    for _ in range(WARMUP):
        fn(*args)
    ts = []
    for _ in range(REPEAT):
        t0 = time.perf_counter()
        fn(*args)
        ts.append(time.perf_counter() - t0)
    return min(ts), ts

# ---------- 0. 实测本机三类屋顶：代替「规格书里的峰值」 ----------
big_src = np.random.default_rng(0).standard_normal(32 * 1024 * 1024).astype(np.float32)
big_dst = np.empty_like(big_src)
copy_s, _ = bench(lambda: np.copyto(big_dst, big_src))
ROOF_GBS = 2 * big_src.nbytes / copy_s / 1e9           # 读+写都算，所以乘 2

mm_a = np.random.default_rng(1).standard_normal((1024, 1024)).astype(np.float32)
mm_b = np.random.default_rng(2).standard_normal((1024, 1024)).astype(np.float32)
mm_c = np.empty_like(mm_a)
gemm_s, _ = bench(lambda: np.matmul(mm_a, mm_b, out=mm_c))
ROOF_TFLOPS = 2 * 1024 ** 3 / gemm_s / 1e12

exp_src = np.random.default_rng(7).standard_normal(1 << 24).astype(np.float32)
exp_dst = np.empty_like(exp_src)
exp_s, _ = bench(lambda: np.exp(exp_src, out=exp_dst))
ROOF_MELEM_S = exp_src.size / exp_s / 1e6              # 超越函数吞吐（百万元素/秒）

ROOFS = {"带宽": ROOF_GBS, "算力": ROOF_TFLOPS, "超越函数": ROOF_MELEM_S}
print("=" * 82)
print("[屋顶] 同机实测，不用规格书数字：")
print(f"  带宽      {ROOF_GBS:8.1f} GB/s    （{big_src.nbytes/2**20:.0f} MiB 数组拷贝，读+写计数）")
print(f"  算力      {ROOF_TFLOPS:8.2f} TFLOP/s  （1024^3 fp32 matmul 的库实现）")
print(f"  超越函数  {ROOF_MELEM_S:8.1f} Melem/s （2^24 个 fp32 的 np.exp，in-place）")
print("=" * 82)

# ---------- 1. 三个 kernel：每个都给「朴素版 + 优化版」，好回答「为什么快」 ----------
N1 = 4096                                   # 4096x4096 fp32 = 64 MiB
X = np.random.default_rng(3).standard_normal((N1, N1)).astype(np.float32)

def softmax_naive(x):
    """两遍读 x，且两次分配全尺寸临时缓冲区（e 与 e/s 各 64 MiB）。"""
    m = x.max(axis=1, keepdims=True)
    e = np.exp(x - m)
    return e / e.sum(axis=1, keepdims=True)

def softmax_blocked(x, RB=256):
    """按行分块：一块只有 RB×N 的 4 MiB，第二遍触碰落在 L2 而不是 DRAM（第 4 章 tiling 的整算子版）。"""
    out = np.empty_like(x)
    for i in range(0, x.shape[0], RB):
        blk = x[i:i + RB]
        m = blk.max(axis=1, keepdims=True)
        o = out[i:i + RB]
        np.subtract(blk, m, out=o)          # 全部 in-place：不再分配临时大数组
        np.exp(o, out=o)
        np.divide(o, o.sum(axis=1, keepdims=True), out=o)
    return out

N2 = 16 * 1024 * 1024
V = np.random.default_rng(4).standard_normal(N2).astype(np.float32)

def reduce_lib(x):
    """交给库：numpy 内部已是分块/树形归约。"""
    return np.add.reduce(x)

def reduce_manual(x):
    """手写两级归约：先分块各自求和，再对块和求和。搬运量与朴素版完全相同。"""
    CH = 1 << 16
    part = np.array([x[i:i + CH].sum() for i in range(0, x.size, CH)], dtype=np.float32)
    return float(part.sum())

N3 = 512
A = np.random.default_rng(5).standard_normal((N3, N3)).astype(np.float32)
B = np.random.default_rng(6).standard_normal((N3, N3)).astype(np.float32)

def gemm_lib(a, b):
    return a @ b

def gemm_naive(a, b):
    """逐输出元素写：每个 C[i][j] 都去读一整行 A 和一整列 B（第 4 章算过这笔搬运账）。"""
    out = np.empty((a.shape[0], b.shape[1]), dtype=np.float32)
    for i in range(a.shape[0]):
        for j in range(b.shape[1]):
            out[i, j] = a[i, :] @ b[:, j]
    return out

def gemm_tiled(a, b, T=64):
    """分块：一次搬入、T 次复用（第 4 章的 blocked_gemm，简化为固定 T 且整除）。"""
    M, K = a.shape
    N = b.shape[1]
    out = np.zeros((M, N), dtype=np.float32)
    for i in range(0, M, T):
        for j in range(0, N, T):
            for k in range(0, K, T):
                out[i:i + T, j:j + T] += a[i:i + T, k:k + T] @ b[k:k + T, j:j + T]
    return out

# ---------- 2. 报告条目：正确性门 + 计时 + 搬运账 + 明确声明用哪几个屋顶 ----------
KERNELS = [
    dict(name="softmax",
         naive=("两遍读 + 临时数组", lambda: softmax_naive(X)),
         opt=("行分块 RB=256", lambda: softmax_blocked(X)),
         reference=lambda: softmax_naive(X),
         bytes_opt=2 * X.nbytes, flops=5 * N1 * N1, sfus=N1 * N1,   # 每个元素一次 exp
         roofs=("带宽", "超越函数"),
         budget=8 * 2 ** 20,                                       # 行块 4 MiB，按 L2 量级留余量
         residual="分块把第二遍触碰收进 L2，但第一遍仍要全量读 x；再压只能融合上游生产 x 的算子"),
    dict(name="reduce_sum",
         naive=("库 add.reduce", lambda: reduce_lib(V)),
         opt=("手写两级归约", lambda: reduce_manual(V)),
         reference=lambda: np.add.reduce(V),
         bytes_opt=V.nbytes, flops=V.size, sfus=0,
         roofs=("带宽",),
         budget=1 << 16,                                           # 单块的局部和，64 KiB
         residual="纯带宽受限且只读一遍；numpy 归约是单线程，实测到三成带宽就是它自己的上限"),
    dict(name="gemm",
         naive=("逐元素写", lambda: gemm_naive(A, B)),
         opt=("分块 T=64", lambda: gemm_tiled(A, B)),
         reference=lambda: gemm_lib(A, B),
         bytes_opt=(2 * N3 ** 3 * 4 // 64 + N3 * N3 * 4), flops=2 * N3 ** 3, sfus=0,
         roofs=("带宽", "算力"),
         budget=3 * N3 * N3 * 4,
         residual="分块把搬运降 64 倍后仍未到库的算力屋顶，差距在 warp/thread 级 tile 与指令级并行"),
]
QTY = {"带宽": lambda k: (k["bytes_opt"], ROOF_GBS * 1e9),
       "算力": lambda k: (k["flops"], ROOF_TFLOPS * 1e12),
       "超越函数": lambda k: (k["sfus"], ROOF_MELEM_S * 1e6)}

def verify(got, ref, rtol=1e-5, atol=1e-4):
    g = np.asarray(got, dtype=np.float64).ravel()
    r = np.asarray(ref, dtype=np.float64).ravel()
    denom = np.maximum(np.abs(r), 1e-12)
    max_rel = float(np.max(np.abs(g - r) / denom))
    max_abs = float(np.max(np.abs(g - r)))
    return (max_rel <= rtol or max_abs <= atol), max_rel, max_abs

rows, gates = [], []
for k in KERNELS:
    ok_n, rel_n, abs_n = verify(k["naive"][1](), k["reference"]())
    ok_o, rel_o, abs_o = verify(k["opt"][1](), k["reference"]())
    t_n, _ = bench(k["naive"][1])
    t_o, _ = bench(k["opt"][1])
    floors = {name: QTY[name](k)[0] / QTY[name](k)[1] for name in k["roofs"]}
    binding = max(floors, key=floors.get)
    sol = {name: 100 * floors[name] / t_o for name in k["roofs"]}
    rows.append(dict(kernel=k["name"], ok=ok_n and ok_o, speedup=t_n / t_o,
                     t_naive_ms=t_n * 1e3, t_opt_ms=t_o * 1e3,
                     gbs=k["bytes_opt"] / t_o / 1e9,
                     floors_ms={n: v * 1e3 for n, v in floors.items()},
                     sol={n: round(v, 1) for n, v in sol.items()},
                     binding=binding, binding_sol=round(sol[binding], 1),
                     headroom_x=t_o / floors[binding],
                     budget_ok=k["budget"] <= 8 * 2 ** 20,
                     residual=k["residual"],
                     tol=f"rel {max(rel_n, rel_o):.1e} / abs {max(abs_n, abs_o):.1e}"))

print(f"\n{'kernel':<10}{'正确':>6}{'朴素ms':>10}{'优化ms':>10}{'提速':>9}{'GB/s':>7}"
      f"{'带宽SOL':>10}{'算力SOL':>10}{'expSOL':>9}{'卡在哪':>10}{'还剩':>8}")
print("-" * 106)
for r in rows:
    s = r["sol"]
    print(f"{r['kernel']:<10}{('PASS' if r['ok'] else 'FAIL'):>6}{r['t_naive_ms']:>10.3f}"
          f"{r['t_opt_ms']:>10.3f}{r['speedup']:>8.2f}x{r['gbs']:>7.1f}"
          f"{s.get('带宽', 0):>9.1f}%{s.get('算力', 0):>9.1f}%{s.get('超越函数', 0):>8.1f}%"
          f"{r['binding']:>10}{r['headroom_x']:>7.2f}x")

# ---------- 3. 报告卡验收：报告里缺证据就不通过 ----------
REQUIRED = {"correctness": "正确性门（与参考实现逐元素对齐 + 容差）",
            "timing": "计时（预热 + 多次取最小值）",
            "traffic": "搬运账（字节数，而不是只报时长）",
            "roof": "屋顶对照（且声明了用哪几个屋顶）",
            "budget": "片上预算（tile 必须装得下，否则分块方案不成立）",
            "verdict": "瓶颈判定（写明卡在哪一类屋顶）",
            "residual": "还剩什么没榨出来的具体说明"}
print("\n[报告卡验收] 每条都是缺了就退回的硬条件")
for r in rows:
    checks = {
        "correctness": r["ok"],
        "timing": REPEAT >= 5 and WARMUP >= 1,
        "traffic": r["gbs"] > 0,
        "roof": bool(r["sol"]) and r["binding_sol"] > 0,
        "budget": r["budget_ok"],
        "verdict": r["binding"] in ROOFS,
        "residual": len(r["residual"]) >= 15,
    }
    missing = [REQUIRED[c] for c, v in checks.items() if not v]
    gates.append((r["kernel"], not missing))
    print(f"  {r['kernel']:<11} {'通过' if not missing else '退回：' + '；'.join(missing)}")

# ---------- 4. 反例自检：声称的 tile 装不下时必须被退回 ----------
print("\n[反例自检] 把 reduce_sum 的片上预算谎报成 64 MiB（真值 64 KiB）：")
bogus = {"budget_ok": V.nbytes <= 8 * 2 ** 20}
print(f"  reduce_sum    {'通过' if bogus['budget_ok'] else '退回：' + REQUIRED['budget']}")
assert not bogus["budget_ok"], "反例自检失效：预算检查没有拦住装不下的 tile"

print("\n[三问] 逐 kernel 的回答必须落到数字上：")
for r in rows:
    print(f"  {r['kernel']}: 为什么快 = 提速 {r['speedup']:.2f}x"
          f"（{r['t_naive_ms']:.2f} ms -> {r['t_opt_ms']:.2f} ms）；"
          f"瓶颈在 {r['binding']}（SOL {r['binding_sol']}%）；还剩 {r['headroom_x']:.2f}x")

report = {"roofs": ROOFS, "kernels": rows}
open("report.json", "w", encoding="utf-8").write(json.dumps(report, ensure_ascii=False, indent=2))
print(f"\n报告已落盘 report.json（{len(rows)} 个 kernel，"
      f"{sum(1 for _, ok in gates if ok)}/{len(gates)} 过验收）")

三、练习#

  1. 实现：给 harness 加第四个 kernel（如 LayerNorm），判断它属于哪类瓶颈、声明适用屋顶、填齐七条字段并让报告卡通过。
  2. 解释：reduce_sum 的优化版比朴素版慢（0.86x），报告卡却仍通过。为什么"提速 < 1"不妨碍验收？这份报告的价值落在哪一行数字上？
  3. 对比/验证：把 REPEAT 改成 1，看 SOL 与 headroom 波动多大；再把 softmax 的 RB 改成 4096（行块 64 MiB，超出 L2），解释提速为什么消失。
  4. 思考：为什么"实测屋顶"比"抄规格书峰值"更适合放进报告？规格书偏高、偏低各会导致什么错误结论，会以什么形式在报告卡里暴露？
