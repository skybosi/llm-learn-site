预训练#

现代大语言模型通常按"预训练 → 指令微调 → RLHF 对齐"三个阶段训练。预训练（pretraining）是第一阶段，也是最昂贵的一步：把模型放到海量文本上，让它学会"语言本身"——语法、常识、推理的统计规律。学完本课，你应当能说清预训练的优化目标是什么、数据从哪来、为什么它如此烧钱，以及它产出的"基座模型"能做什么、不能做什么。

一、概念讲解#

1. 预训练的目标：预测下一个词#

预训练的核心是一个看似简单的任务——自回归语言建模（autoregressive language modeling）：给定一段前文，预测下一个 token 最可能是什么。对句子 深度学习大语言模型，模型依次学习：

  • 看到 深度，预测 学
  • 看到 深度学，预测 习
  • ……

形式化地，一段文本 x1​,…,xT​ 的建模概率被分解为连乘：

P(x1:T​)=t=1∏T​P(xt​∣x<t​)

训练目标就是最大化对数似然，等价于最小化逐 token 的交叉熵损失（负对数似然，NLL）。平均 NLL 取指数，得到常用指标困惑度（perplexity, PPL）：

PPL=exp(−T1​t∑​logP(xt​∣x<t​))

PPL 越低，说明模型对语言越"熟悉"，预测越有把握。PPL = 20 大致可理解为"平均每个位置要在 20 个候选里犹豫"。

2. 预训练的数据：越大、越杂、越干净越好#

预训练语料来自全网：网页、书籍、维基百科、代码仓库、论文等，规模以"万亿 token"计。数据处理的重点不是精挑细选，而是三件事：

  • 去重：互联网文本大量重复，重复样本会浪费算力、加剧过拟合。
  • 过滤：去掉低质、有害、模板化的内容，保留多样且信息密度高的文本。
  • 配比：按一定比例混合不同来源（如代码占比提升推理能力），并做tokenize把文本切成词表内的 token。

正是"海量、多样、干净"的数据，让模型得以在训练中"见多识广"。

3. 预训练为什么这么贵#

预训练的算力成本与模型参数量 × 训练 token 数大致成正比。一个百亿参数模型训练 1 万亿 token，需要成千上万张 GPU 跑数月。这背后是缩放定律（scaling laws）：在足够宽的范围内，模型参数量、数据量、算力同步放大，测试损失会按幂律稳定下降，而且这种下降是可预测的——这正是各家敢在训练前就押注大算力的底气。

4. 预训练产出什么：基座模型#

预训练结束后得到的模型叫基座模型（base model）。它的能力边界很清晰：

  • 会：流利续写、补全代码、做类比、背出训练语料里的常识。
  • 不会：听不懂"指令"。你问它"把这句话翻译成英文"，它不会去翻译，而是顺着往下续写，因为它只学过"预测下一个词"，从没学过"回答用户"。

让基座模型学会"听话"，正是下一课指令微调要做的事。

二、可运行示例#

下面用一个字符级的极小模型，完整走一遍"预测下一个字符"的预训练：构造样本、逐 token 算交叉熵、训练、最后用它续写。

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# —— 极简语料：把每个字符当作一个 token ——
corpus = "深度学习大语言模型预训练预训练很贵"
vocab = sorted(set(corpus))                 # 去重得到"词表"
char2id = {c: i for i, c in enumerate(vocab)}
id2char = {i: c for c, i in char2id.items()}
V = len(vocab)

# —— 构造训练样本：用前文（窗口=2）预测下一个字符 ——
def build_samples(text, ctx=2):
    xs, ys = [], []
    for i in range(ctx, len(text)):
        window = [char2id[c] for c in text[i - ctx:i]]  # 前文
        xs.append(window)
        ys.append(char2id[text[i]])                     # 要预测的下一个字符
    return torch.tensor(xs), torch.tensor(ys)

X, Y = build_samples(corpus, ctx=2)
print("词表大小 V =", V, "，训练样本数 =", len(X))

# —— 一个极简的"下一字符"模型：窗口字符嵌入拼接 -> 线性 -> 输出各字符 logits ——
class TinyLM(nn.Module):
    def __init__(self, V, d=16):
        super().__init__()
        self.emb = nn.Embedding(V, d)   # 字符嵌入表
        self.fc = nn.Linear(d * 2, V)   # 2 个字符拼起来预测下一个字符
    def forward(self, x):               # x: [N, ctx]
        e = self.emb(x).view(x.size(0), -1)  # 展平为 [N, d*ctx]
        return self.fc(e)                    # [N, V] 每个字符的 logits

model = TinyLM(V)
opt = torch.optim.Adam(model.parameters(), lr=0.01)
loss_fn = nn.CrossEntropyLoss()          # 逐 token 的交叉熵，正是预训练目标

for epoch in range(200):
    logits = model(X)                    # 对每个样本预测下一个字符
    loss = loss_fn(logits, Y)            # 负对数似然
    opt.zero_grad()
    loss.backward()
    opt.step()
    if epoch % 50 == 0 or epoch == 199:
        ppl = torch.exp(loss).item()     # 困惑度 = exp(平均 NLL)
        print(f"epoch {epoch:3d}  loss={loss.item():.4f}  perplexity={ppl:.2f}")

# —— 用训练好的模型"续写"：给定前缀，逐步采样下一个字符 ——
def generate(prefix, n=8):
    out = prefix
    for _ in range(n):
        window = [char2id[c] for c in out[-2:]]
        with torch.no_grad():
            logits = model(torch.tensor([window]))
        probs = F.softmax(logits, dim=-1)          # logits -> 概率分布
        nxt = id2char[torch.multinomial(probs, 1).item()]
        out += nxt
    return out

print("续写结果：", generate("预训练"))

运行时你会发现困惑度从几十一路降到接近 1——模型把这句"课本"背下来了，这正是预训练在极小语料上的缩影。真实预训练唯一不同的是：语料是万亿 token、模型是千亿参数。

三、练习#

  1. 手算困惑度：设某位置模型预测正确的 token 概率为 0.2，该位置的 NLL 是多少？若三个位置的正确概率分别为 0.5、0.25、0.1，平均困惑度是多少？
  2. 改窗口：把 build_samples 的 ctx 改成 1 和 3，观察损失下降速度和最终困惑度的差异，思考"更多上下文"为什么通常有助于预测。
  3. 改模型：把 TinyLM 里的 fc 换成两层 Linear(64)，中间加 ReLU，观察收敛更快还是更慢，为什么？
  4. 采样温度：在 generate 里给 softmax 前先除以温度 T（logits / T），分别试 T=0.1 和 T=10，观察续写结果更"死板"还是更"随机"。
  5. 思考：为什么预训练只用"预测下一个词"这一种任务，就能让模型学会语法、常识甚至少量推理？这和"多任务学习"有什么关系？
