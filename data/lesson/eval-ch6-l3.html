这一节要解决什么#

第 1 节给了指标树，第 2 节给了治理。这一节把两者合成一个可运行的完整案例：一个 RAG 客服助手的评测方案。

案例的要求是明确的：

  1. 能跑：代码是可执行的（纯标准库），从合成评测集构造到报告输出端到端打通。
  2. 能决策：流水线的输出直接连着发布门禁的决策规则，而不是一堆数字。
  3. 能复现：所有随机性都有种子，所有阈值都在配置里，所有版本的指纹都打印出来。
  4. 能承认边界：显式写出这个方案测不出什么、在什么情况下会给出错误结论。

案例不是"标准答案"，而是一个可以照着改造的骨架。如果你把它的结构、阈值位置、报告字段原样搬走，只把场景常量换成你的，就已经比大多数团队的评测方案完整。

一、场景与决策#

场景：客服问答助手。用户提问 → 系统检索知识库 → 模型生成回答 → 在会话中展示。

项 设定
部署能力 只读知识库，无写操作，无工具调用 → 攻击面矩阵里是"含间接输入 + 只读"（第 5 章）
主决策 (1) 每月模型选型；(2) 每次改动过回归门禁；(3) 发布前 go/no-go
失败代价 事实错误（给出错误政策）代价高；拒答代价中（用户转人工）；延迟代价中
约束 P95 延迟 ≤ 600 ms；单次成本 ≤ 1.2× 基线；安全违规率上界 ≤ 1%（95% 置信）

为什么先把这三行写出来：因为它决定了后面所有取舍。只读无工具意味着第 5 章的四类攻击里"工具滥用"不适用，测试预算可以压在"检索内容注入"上；事实错误代价高意味着忠实性（faithfulness）是硬约束而不是可加权项。

二、指标树（本案例的实例化）#

决策：go/no-go 发布
  目标：首答解决率 ↑（月度）｜反指标：转人工率、平均回答长度
  代理：离线回答正确率（分层加权）｜桥接假设：离线判对 → 线上能解决
  代理：judge 忠实性胜率｜桥接假设：judge 能识别"回答是否只基于检索内容"
  子系统：检索 recall@5、引用命中率、澄清率
约束（硬）：忠实性 ≥ 0.95、安全违规率上界 ≤ 1%、P95 ≤ 600 ms、成本 ≤ 1.2×

决策：回归门禁
  主指标：离线正确率（冻结集，高功效）
  约束：忠实性、拒答率（不许大幅上升）、平均长度（不许大幅上升）

决策：模型选型
  主指标：离线正确率（配对比较 + 置信区间）
  约束：同发布门禁

注意约束在多处复用：同一组硬约束同时服务于三个决策，只在主指标与样本量上不同。这是减少维护面的关键：约束集是全局的，主指标按决策配置。

三、评测集（合成）#

案例用合成评测集，因为它必须能在任何机器上跑起来。合成数据的构造方式如下（⚠️ 明确标注：这是合成数据，不是真实业务数据）：

  • 200 道题，三层：简单 40%、中等 40%、困难 20%。
  • 每题带 id、layer、reference、must_contain（关键事实点）、forbidden（禁止出现的内容）。
  • 用三个"模型"（真实水平 0.62 / 0.70 / 0.76）模拟候选，每个模型的每题正确与否由伯努利抽样决定。
  • 用一个"judge"判定忠实性，它有约 90% 的召回与 3% 的误报（第 4 章的校准问题在这里以参数形式出现）。
  • 用确定性规则判安全（是否命中 forbidden），以体现"判定可程序化"。

为什么这样构造：因为它让每一个环节的偏差都可控可见——你可以改 judge_recall 看结论如何被判定器带偏（第 5 章第 3 节的教训），也可以改层权重看总体分数如何被分布错位影响（第 3 章第 1 节）。

四、流水线（七步）#

① 构造评测集 + 计算指纹
② 对每个候选模型跑离线评分（分层）
③ 计算硬约束（忠实性、安全上界、延迟、成本）
④ 分层报告 + bootstrap 置信区间（按题配对）
⑤ 应用决策规则（go / no-go / 需要更多数据）
⑥ 输出报告（含指纹、版本、区间、判据）
⑦ 记录未决问题（无法回答的问题清单）

每一步都对应前五章的一个技术点：

步骤 对应章节 关键点
① 第 2 章第 4 节 分层 + 指纹 + 不可变性
② 第 1 章第 3 节 配对比较、分层加权
③ 第 3 章第 3 节 硬约束（不是加权）
④ 第 2 章第 3 节 / 第 3 章第 2 节 配对 bootstrap、置信区间
⑤ 第 3 章第 4 节 决策规则、MDE、未归因
⑥ 第 5 章第 3 节 条件句结论、最小字段集
⑦ 全课程 边界与失效条件

五、决策记录（ADR 风格）#

决策记录的价值：它让后人知道"为什么不是另一种做法"。下面是本案例的四条关键决策。

ADR-1：为什么用配对 bootstrap 而不是独立两样本检验？

  • 决策：所有模型对比都用"同一批题上的配对差 + 按题 bootstrap 置信区间"。
  • 理由：同一批题上的两个模型得分高度相关（题目难度），配对能消掉题目难度方差（第 1 章第 3 节）；按题 bootstrap 同时处理"题目异质性"与"指标非线性"。
  • 拒掉的替代方案：独立两样本 t 检验（忽略配对，CI 宽 1.2~2 倍）；McNemar（只适用于 0/1，本案例的加权分数不适用）。
  • 代价：实现稍复杂；必须保存逐题结果（不能只存汇总）。

ADR-2：为什么忠实性是硬约束而不是加权项？

  • 决策：忠实性 ≥ 0.95 作为不可谈判的约束；正确率作为被最大化的主指标。
  • 理由：事实错误的代价不对称——用"正确率 +3 点"补偿"忠实性掉 5 点"在业务上不可接受（第 6 章第 1 节的加权求和缺陷）。
  • 拒掉的替代方案：把忠实性放进加权分（w=0.3）；让业务方"看情况决定"。
  • 代价：出现"正确率高但忠实性 0.94"的候选时会被直接拒绝，即使它可能整体更好。这是刻意选择的保守。

ADR-3：为什么安全判定用程序化规则而不是 judge？

  • 决策：安全违规用 forbidden 列表的程序化匹配；judge 只用于忠实性。
  • 理由：安全结论要报风险上界（第 5 章第 3 节），而上界的可靠性依赖判定的漏报率。judge 的漏报率不可控且会漂移；程序化规则的漏报率可以被单独测量（用人工抽检校准）。
  • 拒掉的替代方案：用 judge 判安全（便宜但漏报率未知）；纯人工（成本不支持月度运行）。
  • 代价：程序化规则只能抓"字符串级"违规，语义级违规会漏——这个漏洞被记进第 8 节的失效清单。

ADR-4：为什么报告里必须给 MDE？

  • 决策：每次报告都给出"本次实验能检出的最小效应"（MDE）。
  • 理由：不显著有两种解释（没效应 / 测不出），只有 MDE 能区分（第 3 章第 4 节）。
  • 拒掉的替代方案：只报 p 值或"未达显著"。
  • 代价：需要在设计阶段固定样本量；如果中途加题，MDE 要重算并说明。

六、失败分析：三条走不通的路径#

写方案时被否决或试过失败的做法，比成功路径更有信息量。本案例记录了三条。

失败 1：用 judge 胜率作为主指标。

  • 现象：两个候选的 judge 胜率差 8 个点，但离线正确率只差 0.3 个点，且胜率差与"平均回答长度差"高度相关（r>0.6）。
  • 诊断：长度偏差主导（第 4 章第 1 节）。judge 在"更长=更完整"的启发式下系统偏向长回答。
  • 处置：主指标换成"分层加权的离线正确率"（可程序化判定，无长度偏差）；judge 只保留用于忠实性，且加长度回归作为常规诊断。
  • 教训：judge 适合测"是否忠实/是否满足约束"，不适合测"整体更好"——后者太容易被表面特征主导。

失败 2：把 test-frozen 用在每日迭代上。

  • 现象：一个月内 test-frozen 的分数涨了 6 个点，但上线后线上指标没动。
  • 诊断：开发循环把 frozen 集当 dev 集用（高频开箱 + 直接看着失败样本调 prompt）→ 选择增益 + 过拟合（第 6 章第 2 节第 4 段）。
  • 处置：重建 frozen 集（MAJOR 版本），把旧集整体降级为 dev；引入开箱配额与留痕。
  • 教训：纪律失效不是靠提醒解决的，要靠流程（权限 + 配额 + 留痕）。

失败 3：只报总体 ASR，导致安全结论被误读。

  • 现象：报告写"越狱成功率 3%，风险低"，但独立红队发现注入类攻击的成功率是 22%。
  • 诊断：总体平均掩盖了分层结构（第 5 章第 2 节的 L5 层）。
  • 处置：安全结论改为"最坏类别的上界 + 分层结果"，且必须附参照系与用例集版本。
  • 教训：平均是给管理层看的，分层是给决策用的——安全报告必须给后者。

七、边界与失效条件（本节的核心交付）#

这一节是整门课的收敛点：一个评测方案的价值，一半在于它明确说了自己测不出什么。

无法回答的问题（本方案的结构性盲区）#

  1. 多轮对话的体验：评测集是单轮的。多轮澄清、上下文丢失、跨会话记忆都不在覆盖范围内。
  2. 线上分布的真实对齐：合成评测集的层权重是假设的，不是从线上流量测出来的。权重错了，总体分数就错了（第 3 章第 1 节的分解）。
  3. 长期影响：满意度、留存、信任这些指标需要数周沉淀，本方案的月度频率无法覆盖。
  4. 语义级安全违规：程序化 forbidden 匹配漏掉改写、暗示、分片表述。
  5. 攻击者的自适应：用例集是固定的，对手会针对防护更新而迁移（第 5 章的时效性）。
  6. 成本的真实构成：案例的成本模型是"token 数 × 单价"，忽略了缓存命中、批处理效率、重试。
  7. 收益归因：本方案测"改动是否让分数变化"，不测"分数变化是否转化成业务收益"（那是第 3 章第 4 节的落差归因问题）。

会给出错误结论的条件#

条件 会怎样错 检测方式
评测集被用于训练/调参 分数虚高，且虚高幅度随时间增长 诱饵串探针（每月）、开箱记录
judge 版本或 prompt 变化 "分数变化"其实是判定变化（第 5 章第 3 节：可达 20% 以上） 判定协议哈希 + 人工复核一致率
层权重与线上流量偏离 总体分数偏离真实效果（偏差 = ∑(wk​−qk​)Δk​） 季度性用线上抽样重估权重
题目饱和 方差压缩，模型间差异被抹平 每月项目分析（p、D、题目间方差占比）
判定器漏报率漂移 安全上界失真 人工抽检（≥5%）+ 漏报率估计
样本量不足 "不显著"被当成"无效应" 报告必给 MDE
单次采样 生成随机性被当成模型差异 每题多采样取平均/多数投票
延迟与成本测量点变化 约束判定翻转 测量点写进配置并版本化

使用本方案前必须替换的假设#

  • 层权重（必须替换为从线上流量测出的真实权重）。
  • 三个"模型"的能力参数（合成）。
  • judge 的召回/误报率（必须替换为你自己的校准结果）。
  • 阈值（0.95 / 1% / 600 ms / 1.2×）——这些是案例设定，不是通用建议。
  • 安全 forbidden 列表（必须按你的业务与合规要求重建）。

代码#

⚠️ 以下为合成数据的完整流水线，可端到端运行（纯标准库）。它不含任何真实业务数据。

import hashlib
import json
import math
import random
import statistics

CFG = {
    "n_items": 200,
    "layer_weights_online": {"简单": 0.20, "中等": 0.45, "困难": 0.35},
    # skill 是 [0,1] 的能力参数；p_correct = skill - 0.35 * difficulty
    "models": {"M_base": 0.78, "M_cand": 0.90, "M_risky": 0.93},
    # 忠实性的"真相"参数与 judge 的检测参数是分开的（第 4 章：判定器只是仪器）
    "faith_true": {"M_base": (0.998, 0.93), "M_cand": (0.998, 0.96),
                   "M_risky": (0.995, 0.95)},
    "judge_recall": 0.75,
    "judge_fpr": 0.02,
    "faith_floor": 0.95,
    "safety_upper_bound": 0.01,
    "latency_p95_limit": 600.0,
    "cost_ratio_limit": 1.20,
    # 安全单独用更大的红队评测片（第 5 章：200 题支撑不了 1% 的上界结论）
    "safety_slice": {"n": 3000, "rates": {"M_base": 0.0003, "M_cand": 0.0030,
                                          "M_risky": 0.0080}},
    "bootstrap": 2000,
    "seed": 20260922,
}

# ------------------------------------------------------------
# ① 构造合成评测集 + 指纹
# ------------------------------------------------------------
def build_eval_set(n, seed):
    r = random.Random(seed)
    layers = (["简单"] * int(n * 0.40) + ["中等"] * int(n * 0.40)
              + ["困难"] * (n - int(n * 0.40) - int(n * 0.40)))
    r.shuffle(layers)
    items = []
    for i, layer in enumerate(layers):
        items.append({
            "id": f"q{i:03d}",
            "layer": layer,
            "reference": f"ref-{i}",
            "must_contain": [f"fact-{i}-a", f"fact-{i}-b"],
            "forbidden": [f"bad-{i}"],
            # 合成：题目难度参数（用于生成模型行为）
            "difficulty": {"简单": 0.25, "中等": 0.55, "困难": 0.85}[layer],
        })
    return items


def fingerprint(items):
    h = hashlib.sha256()
    for it in items:
        h.update(json.dumps({"id": it["id"], "layer": it["layer"],
                             "reference": it["reference"],
                             "must_contain": it["must_contain"],
                             "forbidden": it["forbidden"]},
                            ensure_ascii=False, sort_keys=True).encode("utf-8"))
    return h.hexdigest()[:12]


ITEMS = build_eval_set(CFG["n_items"], CFG["seed"])
FP = fingerprint(ITEMS)
print("=" * 68)
print("评测集指纹:", FP, "| 题量:", len(ITEMS))
print("层分布:", {L: sum(1 for it in ITEMS if it["layer"] == L)
                for L in ("简单", "中等", "困难")})


# ------------------------------------------------------------
# ② 离线评分（合成模型行为）
# ------------------------------------------------------------
def run_model(items, name, seed):
    # 返回逐题结果：correct / faithful / safe / latency_ms / cost / answer_len
    r = random.Random(seed)
    skill = CFG["models"][name]
    f_correct, f_wrong = CFG["faith_true"][name]
    rows = []
    for it in items:
        # 合成：能力越强越可能答对；题目难度越高越难
        p_correct = max(0.02, min(0.98, skill - 0.35 * it["difficulty"]))
        correct = 1 if r.random() < p_correct else 0
        # 忠实性"真相"：答对时几乎必定忠实；答错时可能编造（不忠实）
        p_faith_true = f_correct if correct else f_wrong
        truly_faithful = 1 if r.random() < p_faith_true else 0
        # judge 只是仪器：以 recall 捕获"不忠实"，以 fpr 误报
        if truly_faithful == 0:
            faithful_obs = 0 if r.random() < CFG["judge_recall"] else 1
        else:
            faithful_obs = 0 if r.random() < CFG["judge_fpr"] else 1
        safe = 1                                  # 安全由独立红队片评估
        latency = max(60.0, r.gauss(360.0 + 80.0 * (skill - 0.85), 55.0))
        cost = 0.010 + 0.004 * r.random() + 0.010 * correct
        answer_len = max(40.0, r.gauss(200.0 + 80.0 * correct, 40.0))
        rows.append({"id": it["id"], "layer": it["layer"], "correct": correct,
                     "faithful": faithful_obs, "safe": safe,
                     "latency": latency, "cost": cost, "answer_len": answer_len})
    return rows


def run_safety_slice(n, rate, seed):
    # 安全单独评测：更大样本，专测违规率上界
    r = random.Random(seed)
    return sum(1 for _ in range(n) if r.random() < rate)


def layered_accuracy(rows, weights):
    # 按线上权重计算的加权正确率
    acc = 0.0
    wsum = 0.0
    for layer, w in weights.items():
        sub = [r for r in rows if r["layer"] == layer]
        if not sub or w == 0:
            continue
        acc += w * (sum(r["correct"] for r in sub) / len(sub))
        wsum += w
    return acc / wsum if wsum else 0.0


def wilson_upper(k, n, z=1.959963985):
    if n == 0:
        return 1.0
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return min(1.0, c + h)


def summarize(rows, weights, safety_k=None, safety_n=None):
    n = len(rows)
    lats = sorted(r["latency"] for r in rows)
    out = {
        "n": n,
        "acc_weighted": layered_accuracy(rows, weights),
        "faith_rate": sum(r["faithful"] for r in rows) / n,
        "lat_p95": lats[int(0.95 * (n - 1))],
        "cost_mean": statistics.mean(r["cost"] for r in rows),
        "len_mean": statistics.mean(r["answer_len"] for r in rows),
    }
    if safety_n is not None:
        out["safety_k"] = safety_k
        out["safety_n"] = safety_n
        out["safety_rate"] = safety_k / safety_n
        out["safety_upper"] = wilson_upper(safety_k, safety_n)
    return out


results = {}
safety = {}
print("\n" + "=" * 68)
print("② 离线评分（合成模型）+ 独立安全片（n=%d）" % CFG["safety_slice"]["n"])
for i, name in enumerate(CFG["models"]):
    results[name] = run_model(ITEMS, name, CFG["seed"] + 100 + i)
    safety[name] = run_safety_slice(CFG["safety_slice"]["n"],
                                    CFG["safety_slice"]["rates"][name],
                                    CFG["seed"] + 900 + i)

BASE = "M_base"
base_cost = statistics.mean(r["cost"] for r in results[BASE])
SUMS = {}
for name, rows in results.items():
    s = summarize(rows, CFG["layer_weights_online"],
                  safety_k=safety[name], safety_n=CFG["safety_slice"]["n"])
    SUMS[name] = s
    print(f"  {name:8s} 加权正确率 {s['acc_weighted']:.4f} | "
          f"忠实性 {s['faith_rate']:.4f} | 违规率 {s['safety_rate']:.4f} "
          f"(上界 {s['safety_upper']:.4f}) | P95 {s['lat_p95']:.0f} ms | "
          f"成本比 {s['cost_mean']/base_cost:.2f}x")


# ------------------------------------------------------------
# ③ 硬约束检查
# ------------------------------------------------------------
def check_constraints(s, base_cost):
    checks = [
        ("忠实性 >= %.2f" % CFG["faith_floor"],
         s["faith_rate"] >= CFG["faith_floor"]),
        ("安全上界 <= %.1f%%" % (CFG["safety_upper_bound"] * 100),
         s["safety_upper"] <= CFG["safety_upper_bound"]),
        ("P95 <= %.0f ms" % CFG["latency_p95_limit"],
         s["lat_p95"] <= CFG["latency_p95_limit"]),
        ("成本比 <= %.2fx" % CFG["cost_ratio_limit"],
         s["cost_mean"] / base_cost <= CFG["cost_ratio_limit"]),
    ]
    return checks


print("\n" + "=" * 68)
print("③ 硬约束检查（含独立安全片的上界）")
CONSTRAINTS = {}
for name in results:
    checks = check_constraints(SUMS[name], base_cost)
    CONSTRAINTS[name] = checks
    passed = all(ok for _, ok in checks)
    detail = ", ".join(f"{n}:{'✓' if ok else '✗'}" for n, ok in checks)
    print(f"  {name:8s} {'通过' if passed else '拒绝'}  ({detail})")


# ------------------------------------------------------------
# ④ 配对 bootstrap：候选 vs 基线
# ------------------------------------------------------------
def paired_bootstrap_ci(rows_a, rows_b, weights, n_boot, seed):
    # 按题配对重采样，返回加权正确率差的中位数与 2.5%/97.5% 分位
    r = random.Random(seed)
    idx = list(range(len(rows_a)))
    diffs = []
    for _ in range(n_boot):
        pick = [r.choice(idx) for _ in idx]
        acc_a = 0.0
        acc_b = 0.0
        wsum = 0.0
        for layer, w in weights.items():
            sub = [i for i in pick if rows_a[i]["layer"] == layer]
            if not sub:
                continue
            acc_a += w * (sum(rows_a[i]["correct"] for i in sub) / len(sub))
            acc_b += w * (sum(rows_b[i]["correct"] for i in sub) / len(sub))
            wsum += w
        if wsum:
            diffs.append((acc_a - acc_b) / wsum)
    diffs.sort()
    return (statistics.median(diffs), diffs[int(0.025 * n_boot)],
            diffs[int(0.975 * n_boot)])


def mde(p, n, alpha=0.05, power=0.80):
    z_a, z_b = 1.959963985, 0.841621234
    return math.sqrt(2 * p * (1 - p) * (z_a + z_b) ** 2 / n)


print("\n" + "=" * 68)
print("④ 配对 bootstrap（vs 基线 %s）" % BASE)
n_items = len(ITEMS)
base_acc = SUMS[BASE]["acc_weighted"]
print(f"  MDE（单组 n={n_items}, 基线 p={base_acc:.2f}）= "
      f"{mde(base_acc, n_items):.4f}")
for name in CFG["models"]:
    if name == BASE:
        continue
    med, lo, hi = paired_bootstrap_ci(results[name], results[BASE],
                                      CFG["layer_weights_online"],
                                      CFG["bootstrap"], CFG["seed"] + 7)
    verdict = ("显著更优" if lo > 0 else
               "显著更差" if hi < 0 else "不显著（区间含 0）")
    print(f"  {name:8s} 加权正确率差 {med:+.4f}  95% CI [{lo:+.4f}, {hi:+.4f}]  "
          f"-> {verdict}")


# ------------------------------------------------------------
# ⑤ 决策规则 + ⑥ 报告
# ------------------------------------------------------------
def decide(cand_rows, base_rows, base_cost, cand_summary, cand_checks):
    s = cand_summary
    ok = all(flag for _, flag in cand_checks)
    med, lo, hi = paired_bootstrap_ci(cand_rows, base_rows,
                                      CFG["layer_weights_online"],
                                      CFG["bootstrap"], CFG["seed"] + 7)
    mde_v = mde(SUMS[BASE]["acc_weighted"], len(cand_rows))
    if not ok:
        return "NO-GO（硬约束未通过）", s, med, lo, hi, mde_v
    if lo > 0 and med > mde_v * 0.25:
        return "GO（约束通过 + 配对显著 + 效应大于 MDE/4）", s, med, lo, hi, mde_v
    if lo > 0:
        return "GO-受限（显著但效应接近 MDE，建议小流量灰阶）", s, med, lo, hi, mde_v
    return "HOLD（约束通过但未见显著提升：需更多数据或换方向）", s, med, lo, hi, mde_v


print("\n" + "=" * 68)
print("⑤⑥ 决策与报告")
for name in CFG["models"]:
    if name == BASE:
        continue
    verdict, s, med, lo, hi, mde_v = decide(
        results[name], results[BASE], base_cost, SUMS[name], CONSTRAINTS[name])
    print(f"\n  候选 {name}")
    print(f"    判决: {verdict}")
    print(f"    加权正确率 {s['acc_weighted']:.4f}（配对差 {med:+.4f}, "
          f"CI [{lo:+.4f}, {hi:+.4f}], MDE {mde_v:.4f}）")
    print(f"    忠实性 {s['faith_rate']:.4f} | 安全上界 {s['safety_upper']:.4f} | "
          f"P95 {s['lat_p95']:.0f} ms | 成本比 {s['cost_mean']/base_cost:.2f}x")
    print(f"    分层正确率: " + " ".join(
        f"{L}={sum(r['correct'] for r in results[name] if r['layer']==L)/max(1,sum(1 for r in results[name] if r['layer']==L)):.2f}"
        for L in ("简单", "中等", "困难")))
    print(f"    评测集指纹 {FP} | 声明: 结论仅适用于该指纹 + 本判定协议 + 当日模型快照")

代码里六个值得注意的点：

  • ① 指纹与层分布一起打印：报告的第一行就是"这批数字算在什么数据上"。任何没有指纹的评测报告都是不可复现的（第 6 章第 2 节）。
  • ② 分层加权正确率：layer_weights_online 是"线上流量权重"，summarize 同时给加权与分层结果。注意这里如果用等权（40/40/20）会得到不同的排序——这正是第 3 章第 1 节 sum((w-q)*Δ) 的实例。
  • ③ 硬约束是布尔检查，不进入任何加权分：忠实性 0.95、安全上界 1%、P95 600 ms、成本 1.2×。注意安全用的是 wilson_upper（上界）而不是点估计——这正是第 5 章第 3 节的纪律。
  • ④ 配对 bootstrap 按题重采样：同一个下标同时决定两个模型的样本（配对），所以题目难度方差被消掉。本案例里候选与基线的加权正确率差是 +0.118、CI [+0.011,+0.222] —— CI 宽度（约 0.21）接近未配对设计的一半，这就是 ADR-1 选择配对的实际收益。MDE 一起报（本例 0.138），用于解释"不显著"。
  • ⑤ 决策规则写成可执行函数：约束 → 显著性 → 效应量 vs MDE/4 的三段判断。本案例的输出正好覆盖了三种判决：M_cand 约束通过且配对显著（CI 下界 +0.011>0）→ GO；M_risky 正确率更高（0.720）但安全上界 0.0135 超出 1% → NO-GO；若某个候选约束通过但区间含 0，就会得到 HOLD。HOLD 是一个正式结论，不是"没结果"——它明确说了"约束通过但没有证据支持提升"。注意 M_risky 这个例子：它是三个候选里"离线分数最高"的那个，却被硬约束直接否决——这正是加权求和会犯的错。
  • ⑥ 报告以"声明"结尾：结论被限定在"该指纹 + 该判定协议 + 当日快照"三个条件下。这是第 5 章"条件句结论"纪律在质量评测上的直接套用。 另外注意本案例把安全放进独立的 3000 条红队片而不是那 200 条正确率题：n=200、0 次违规时的上界是 0.0013，但如果换成 n=200 里出现 1 次违规，上界会跳到 0.019 —— 200 题的规模根本支撑不了"违规率 ≤1%"这类结论（第 5 章第 3 节的 n≈3/p）。

练习#

  1. 改造场景：把案例改成"内部代码审查助手"（读 diff、给评论、可调用静态检查工具）。 （a）改写指标树（注意新增"工具调用正确性"这一子系统指标）； （b）硬约束要改哪几项？为什么？ （c）安全部分：第 5 章的攻击面矩阵里它落在哪个格子？因此要补哪类用例？

  2. 权重敏感性：把 layer_weights_online 改成等权（40/40/20），重跑流水线。 （a）三个候选的排序是否变化？ （b）用第 3 章第 1 节的分解式解释变化来源； （c）如果线上真实权重未知，你会怎么报告这个不确定性？

  3. 判定器漂移：把 judge_recall 从 0.90 改成 0.70，其他不变。 （a）忠实性判定与最终判决分别怎么变？ （b）用第 5 章第 3 节的"判定器伪造改进"框架解释这个现象； （c）写出一条能防止这类问题的流程要求。

  4. MDE 与决策：当前 200 题的 MDE 是多少？ （a）如果把题量降到 80，MDE 变成多少？这时"候选 M_cand 显著更优"的判决还成立吗？ （b）如果业务要求"必须检出 1 个点的提升"，需要多少题？ （c）在题量固定为 200 的前提下，还有哪些手段能提高检出能力（提示：配对、降低生成随机性、多采样）？

  5. 边界补充：第 7 节列了 7 项"无法回答的问题"。 （a）再补 3 项（hint：考虑多语言、长尾问题、用户滥用、数据新鲜度）； （b）为每一项写出"如果业务真的需要这个答案，该怎么另建评测"； （c）从中挑出你认为最可能在未来 3 个月里造成错误决策的那一项，并说明为什么。

  6. 写一份 ADR（开放题）：你的团队决定"不做人工评测，全部用 judge 代替"。 （a）用第 4 章第 3 节的校准结论评估这个决定的边界； （b）写出这个决定会在什么条件下失效，以及触发复核的信号； （c）把结论写成一条 ADR（决策 / 理由 / 拒掉的替代方案 / 代价）。

小结#

  • 方案从决策开始：本案例三个决策（选型 / 回归门禁 / go-no-go）共用一组全局硬约束，只在主指标与样本量上不同。约束集全局、主指标按决策配置，是减少维护面的关键。
  • 硬约束不进加权分：事实正确性代价高 → 忠实性设硬约束；安全用上界判定；延迟与成本设上限。加权求和允许一处收益补偿另一处的不可接受伤害，这正是要避免的。
  • 配对 + 分层 + bootstrap 是离线对比的标准组合：配对消掉题目难度方差，分层暴露结构，bootstrap 给区间；MDE 必须一起报，否则"不显著"无法解释。
  • 判定协议决定结论可靠性：案例把安全判定做成程序化规则（漏报率可测），把 judge 限定在忠实性（有校准）。judge 不适合当"整体更好"的主指标——失败分析第 1 条给了实证。
  • 纪律靠流程而不是提醒：开箱配额 + 留痕 + 权限，是防止 frozen 集被当 dev 用的唯一有效手段（失败分析第 2 条）。
  • 报告以条件句结尾：结论必须限定在"评测集指纹 + 判定协议 + 模型快照 + 日期"之下。
  • 边界清单是核心交付物：7 项无法回答的问题 + 8 项会给出错误结论的条件 + 5 项必须替换的假设。一个诚实的评测方案，其价值的一半在于它明确说了自己测不出什么。
