这一节要解决什么#

第 1 节产出了指标树。指标树要落地，必须落在一份具体的评测集上。而评测集是长期资产：它会被使用几个月到几年，会经历模型更替、标注规则修订、题目饱和与污染。没有治理的评测集会在半年内变成"一组没人敢改、也没人敢信的数字"。

这一节把第 2 章第 4 节（自建评测集）与第 5 章的对抗视角合起来，专门讲治理：让评测集像软件一样被版本化、被测试、被审计、被淘汰。

内容分五块：

  1. 数据契约：一条样本里到底有哪些字段、哪些是不可变的、哪些可以被修订。
  2. 版本策略：什么改动是补丁、什么是不兼容变更；语义化版本对评测集怎么定义。
  3. 三集方案与开箱纪律：dev / test-frozen / test-live 的规模、更新频率、锚题比例。
  4. 权限与防污染：谁能读、谁能改、怎么检测"评测集被用于训练"。
  5. 生命周期：饱和检测、退役规则、以及"评测集换掉了怎么保证可比"。

一、数据契约：样本的字段与不可变性#

一条评测样本不只是"输入 + 答案"。把它的字段定清楚，是治理的第一步：

字段 是否可变 说明
id 不可变 全局唯一，跨版本稳定；退役也不复用
input 不可变（修订=新 id） 改动输入等于换了一道题，必须新 id
reference / rubric 可修订（记版本） 标准答案会随业务规则变化
layer / tags 可修订 分层标签（任务类型、难度、风险等级）
provenance 不可变 来源（真实流量 / 专家构造 / 合成）、采集时间、脱敏方式
license / consent 不可变 数据可用范围与合规依据
added_in 不可变 加入的评测集版本
retired_in 不可变 退役的版本（空=在用）
gold 可修订 是否金题（用于质检，不影响计分）
weight 可修订（记版本） 若做加权评分，权重必须版本化

三条不可变性铁律：

  1. id 永不复用。 退役的题目的 id 不能给新题目用——否则历史报告无法解读。
  2. 改动 input 必须新 id。 否则"同一道题"在不同版本上不可比。
  3. reference/rubric 可以改，但必须记版本并触发基线重跑。 因为改了评分标准，之前的分数不再可比。

为什么这样设计：因为评测集的可比性来自"同一批 id 上的分数"。任何让 id 与内容脱钩的操作（复用 id、就地改输入）都会破坏这个基础，而且破坏是延迟发现的——通常在你需要拿一年前的数字做趋势分析时才发现。

二、版本策略：什么算不兼容变更#

对评测集采用语义化版本 MAJOR.MINOR.PATCH，但定义要贴合评测场景：

版本位 触发条件 后果
PATCH 修 typo、补 rubric 措辞（不改判定边界）、补 tags 无需重跑基线；分数应几乎不变（可抽检证明）
MINOR 新增题目、新增分层、退役明确失效的题目 必须重跑全部基线；新旧分数不可直接比较，需锚题等值
MAJOR 改评分函数、改判定协议、大规模替换题目、改标签体系 历史分数作废；只能在同一 MAJOR 内比较

判断 MINOR 与 MAJOR 的分界线：问一个问题——"分数变了，是模型变了还是评测集变了？" 如果无法用锚题等值把两者分开，那就是 MAJOR。

锚题（anchor items）的作用在这里变得具体：跨 MINOR 版本保留一批未被修改的题目（通常 15%~25%），用它们在两个版本上的分数差估计"版本难度差"，从而对总分做等值校正。没有锚题的版本升级，等于把趋势线砍断。

怎么做（升级流程）：

  1. 新版本在一个分支上构建，冻结旧版本（不再修改）。
  2. 候选改动先过影响评估：抽 30~50 题跑新旧两个版本，估分数偏移与方差。
  3. 若偏移超出阈值（比如 >1 个点）→ 判定为 MINOR 或 MAJOR，而非 PATCH。
  4. 更新 CHANGELOG（含每题的增删改），打 tag。
  5. 用新版本重跑全部在用模型，把结果写进基线表。
  6. 在报告里同时给出新旧对齐关系（锚题校正系数）。

取舍：不兼容变更越少越好（减少重跑成本），但把该升级的改动当 PATCH 发布，会让趋势线悄悄失真。默认从严：拿不准就按 MINOR 处理。

三、三集方案与开箱纪律#

第 2 章给过三集方案，这里给出治理视角的版本：

集 规模占比 用途 可见性 更新频率
dev 50%~60% 日常迭代、调参、快速反馈 对开发者完全可见 随时（可过拟合）
test-frozen 20%~30% 发布门禁、对外报告 只有评测负责人可见；题目内容限制访问 按版本（MINOR 级别）
test-live 20%~30% 监控漂移、发现新失败模式 定期轮换 持续（月度轮换）

开箱纪律（四条，必须写进流程）：

  1. test-frozen 的题目内容不对模型开发团队全员开放（至少不开放答案与 rubric 细节）。实践做法：只开放聚合结果与失败聚类，题目正文按需申请、留痕。
  2. 每个模型对 test-frozen 的开箱次数有限（比如每季度 3 次）。每次开箱记录：时间、模型版本、结果、决策。这是防止"反复选择"（第 3 章的选择增益）的唯一有效手段。
  3. 一旦某集被用于调参或训练，立即降级为 dev 集（永久，不可逆）。
  4. test-live 只用于监控，不用于发布决策（因为它在轮换，跨期不可比）。

锚题比例怎么定：取决于两个因素——版本升级的频率与分数波动的量级。经验规则：如果每次 MINOR 升级的难度漂移预期在 1~2 个点，而你要检测的效应也是 2 个点，那么锚题比例要让难度差的估计标准误（约 1/nanchor​​ 量级）显著小于 1 个点 → nanchor​ 通常需要占总量的 15% 以上。比例过低时，等值校正本身引入的噪声会大于要校正的偏差。

四、权限与防污染#

污染（contamination） 在治理层面有两个来源：外部（模型训练数据里包含公开基准）与内部（团队把评测集内容用于训练/调参）。

内部防污染的四道闸：

  1. 访问控制：test-frozen 单独仓库或目录，读写权限最小化；读操作也留痕（否则无法追责）。
  2. 水印/诱饵（canary strings）：在题目文本里嵌入不影响语义的唯一字符串；定期用成员推断或生成式探测检查模型是否"见过"这些串。这是第 2 章污染检测方法在内部治理上的应用。
  3. 数据血缘：训练/微调数据集的构建流程中，加一道黑名单过滤（把评测集指纹纳入拦截列表），并保留过滤日志。
  4. 流程隔离：评测集维护者与训练数据维护者不应当是同一人（组织性措施，比技术措施更可靠）。

外部污染的检测（第 2 章讲过方法，这里只补治理动作）：对每个公开基准，记录首次使用时间与模型训练截止时间的关系；对时间窗可疑的基准，改用私有变体（同构但内容不同的题）做交叉验证。

取舍：防污染的每一道闸都增加摩擦（申请、留痕、隔离）。摩擦必须花在 test-frozen 上，不要花在 dev 上——dev 集的设计目的就是被榨干。

五、生命周期：饱和、退役与换代#

饱和检测：如果某套题的通过率长期高于 90%（或低于 10%），它对区分模型的贡献接近于零（第 2 章的项目分析）。两个可用信号：

  • 区分度 D：高分组与低分组的通过率差；D≈0 的题目在选型场景中没有价值。
  • 方差的来源：如果题目间方差占总方差的比例持续下降（第 4 章的方差分解），说明题目不再能区分模型。

退役规则（写进文档）：

条件 动作
通过率 > 0.95 且 D<0.1（连续两个版本） 标记为"饱和"，从选型集移除；保留在回归门禁集（防退化仍有用）
题目被证明有歧义/无可判定标准 退役（记 retired_in），并在 CHANGELOG 说明
题目被用于训练（确认污染） 立即退役 + 重估历史报告（哪些结论受了影响）
通过率 < 0.05（对所有在用模型） 复核是否题面错误；若是，退役；若否，保留为"能力边界"题

换代（把评测集整体替换）：这是最贵的动作，因为历史趋势会断。做法：

  1. 重叠期：新旧两套同时跑至少一个季度，用重叠部分的题目做等值。
  2. 双报告期：报告同时给新旧分数与对齐说明。
  3. 切换点明确记录：在时间序列图上标注断点，禁止跨断点直接比较。

一条纪律：评测集的"变好"从来不是目标。 目标是"它能改变正确的决策"。一套一直不涨的分数也可能是健康的（说明模型没变、题目没饱和、流程稳定）。

六、把治理变成常规动作#

治理不是一次性文件，是四条周期性动作：

频率 动作 产物
每次改动 影响评估（抽 30~50 题跑新旧） 版本归类（PATCH/MINOR/MAJOR）
每月 项目分析（难度/区分度）、污染抽检 饱和清单、污染告警
每季度 test-live 轮换、锚题复核、开箱配额结算 轮换记录、配额使用情况
每半年 评测集健康报告（覆盖度、一致性、成本、决策贡献） 是否换代/补题的决策

"决策贡献"这一项最容易被忽略，也最重要：统计过去半年里，这套评测集实际改变了多少次决策。如果答案是 0，那么问题不在评测集的质量，而在它没有连着一个决策（回到第 1 节）。

import hashlib
import json

# ============================================================
# 1. 数据集指纹：规范化哈希（顺序无关 + 内容敏感）
# ============================================================
def canonical_item(item):
    # 只把"影响分数"的字段纳入指纹；元数据（备注、创建时间）不纳入
    return json.dumps(
        {k: item[k] for k in ("id", "input", "reference", "rubric_version")},
        ensure_ascii=False, sort_keys=True)


def dataset_fingerprint(items):
    h = hashlib.sha256()
    for line in sorted(canonical_item(it) for it in items):
        h.update(line.encode("utf-8"))
        h.update(b"\n")
    return h.hexdigest()[:16]


base_items = [
    {"id": "q001", "input": "退货政策是什么", "reference": "7 天无理由",
     "rubric_version": "r1", "layer": "简单", "note": "初版"},
    {"id": "q002", "input": "如何修改发票抬头", "reference": "在订单页修改",
     "rubric_version": "r1", "layer": "中等", "note": ""},
    {"id": "q003", "input": "跨境订单多久到", "reference": "7-15 个工作日",
     "rubric_version": "r1", "layer": "中等", "note": ""},
]
fp1 = dataset_fingerprint(base_items)

# 改动 1：只改备注（不应改变指纹）
mod_meta = [dict(it, note="补了说明") for it in base_items]
# 改动 2：改参考答案（应改变指纹）
mod_ref = [dict(base_items[0], reference="15 天无理由")] + base_items[1:]
# 改动 3：调换顺序（不应改变指纹）
mod_order = list(reversed(base_items))

print("== 1. 数据集指纹（规范化哈希） ==")
print(f"原始指纹            : {fp1}")
print(f"只改备注（元数据）  : {dataset_fingerprint(mod_meta)}  "
      f"{'不变 ✓' if dataset_fingerprint(mod_meta) == fp1 else '变了 ✗'}")
print(f"调换顺序            : {dataset_fingerprint(mod_order)}  "
      f"{'不变 ✓' if dataset_fingerprint(mod_order) == fp1 else '变了 ✗'}")
print(f"改参考答案          : {dataset_fingerprint(mod_ref)}  "
      f"{'变了 ✓' if dataset_fingerprint(mod_ref) != fp1 else '不变 ✗'}")
print("  <- 指纹要满足两个性质：顺序无关、内容敏感；")
print("     只把影响分数的字段纳入哈希，否则每次补备注都要重跑基线")


# ============================================================
# 2. 版本归类：用抽样影响评估决定 PATCH / MINOR / MAJOR
# ============================================================
def version_bump(score_shift, mdd=0.01):
    # score_shift：抽 30~50 题上新旧版本的分数差（绝对值）
    if score_shift > 2 * mdd:
        return "MAJOR（评分标准或题目体系变了）"
    if score_shift > 0.3 * mdd:
        return "MINOR（需要重跑基线 + 锚题等值）"
    return "PATCH（无需重跑；仍应抽检证明）"


print("\n== 2. 版本归类：抽样影响评估 ==")
for shift, desc in ((0.001, "修 typo"), (0.004, "补 rubric 措辞"),
                    (0.012, "新增 20 题 + 退役 5 题"),
                    (0.035, "把评分从二分类改为三分制")):
    print(f"  分数偏移 {shift:.3f} ({desc:18s}) -> {version_bump(shift)}")
print("  <- 阈值要写成明文规则（本例 MDD=1pt）；拿不准就从严重一侧处理")


# ============================================================
# 3. 锚题等值：跨 MINOR 版本对齐趋势
# ============================================================
def equate(score_new_full, anchor_new, anchor_old):
    # 一维等值：用锚题上的差校正新版本全集分数
    drift = anchor_new - anchor_old          # 锚题上的难度漂移
    return score_new_full - drift, drift


print("\n== 3. 锚题等值：让新旧版本可比（合成） ==")
print("  场景：v1.2 -> v1.3，新版本削弱了部分简单题（整体变难）")
for s_full, a_new, a_old in [(0.712, 0.640, 0.700), (0.712, 0.700, 0.700),
                             (0.688, 0.700, 0.700)]:
    adj, drift = equate(s_full, a_new, a_old)
    tag = ("新版本更难，原始分数被低估" if drift < -0.005 else
           "难度相当" if abs(drift) <= 0.005 else
           "新版本更容易，原始分数被高估")
    print(f"  全集 {s_full:.3f} | 锚题 新 {a_new:.3f} / 旧 {a_old:.3f} "
          f"-> 漂移 {drift:+.3f} 校正后 {adj:.3f}   ({tag})")
print("  <- 没有锚题等值，'v1.3 分数掉了 2 个点'无法区分模型退化与题目变难")


# ============================================================
# 4. 开箱配额：选择增益随开箱次数增长
# ============================================================
def selection_gain(n_candidates_per_open, n_opens, n_items=300,
                   true_p=0.70, seed=5):
    # 每次开箱从 n_candidates_per_open 个模型里挑最好的；返回累计最大分
    r = random.Random(seed)
    best_all = 0.0
    history = []
    for _ in range(n_opens):
        scores = []
        for _ in range(n_candidates_per_open):
            hits = sum(1 for _ in range(n_items) if r.random() < true_p)
            scores.append(hits / n_items)
        best_all = max(best_all, max(scores))
        history.append(best_all)
    return history


print("\n== 4. 开箱配额：反复开箱会累积选择增益（合成，真实能力都是 0.70） ==")
h = selection_gain(5, 10)
for i, v in enumerate(h, 1):
    print(f"  第 {i:2d} 次开箱后，历史最高分 = {v:.4f}  (真实 {0.70})")
print("  <- 10 次开箱后'最高分'比真实能力高 3 个点以上，全部来自噪声；")
print("     这就是为什么 test-frozen 必须限制开箱次数并留痕")


# ============================================================
# 5. 饱和检测：区分度 D 与方差占比
# ============================================================
def item_stats(n_high, n_low, p_high, p_low, seed):
    # 按上下 27% 分组计算区分度 D
    r = random.Random(seed)
    hh = sum(1 for _ in range(n_high) if r.random() < p_high) / n_high
    ll = sum(1 for _ in range(n_low) if r.random() < p_low) / n_low
    return hh, ll, hh - ll


print("\n== 5. 饱和检测：难度 p 与区分度 D（合成） ==")
items = [
    ("q011", 0.97, 0.96), ("q012", 0.95, 0.94), ("q013", 0.55, 0.20),
    ("q014", 0.60, 0.25), ("q015", 0.28, 0.38),
]
print(f"{'题':>6}{'高分组':>8}{'低分组':>8}{'难度p':>8}{'区分度D':>9}  处置")
for qid, ph, pl in items:
    hh, ll, D = item_stats(60, 60, ph, pl, seed=hash(qid) % 1000)
    p = (hh + ll) / 2
    if p > 0.95 and D < 0.10:
        act = "饱和：移出选型集，留在门禁集"
    elif D < 0.05:
        act = "区分度极低：复核题面是否歧义"
    elif p < 0.10:
        act = "过难：复核是否题面错误"
    else:
        act = "保留"
    print(f"{qid:>6}{hh:>8.2f}{ll:>8.2f}{p:>8.2f}{D:>9.2f}  {act}")
print("  <- 饱和题对'选型'无用，但对'回归门禁'仍然有价值（防退化）；")
print("     区分度接近 0 或为负的题（q015 这类）几乎总意味着题面/rubric 有歧义")

代码里六个值得注意的点：

  • 第 1 段给出指纹的两个必备性质：顺序无关（同一批样本换个顺序指纹不变）与内容敏感（改参考答案就变）。关键设计是只把影响分数的字段纳入哈希——如果把备注、创建时间也纳入，那么每次补个说明都要重跑基线。这是"评测集治理"和"普通数据管理"的分界线。
  • 第 2 段把版本归类变成可执行规则：偏移 < 0.3×MDD 算 PATCH，0.3~2×MDD 算 MINOR，超过 2×MDD 算 MAJOR。规则要事先写成数字，否则每次升级都会变成"这次就算 PATCH 吧"的政治协商。
  • 第 3 段是锚题等值的最小实现：锚题上的漂移 −0.060 说明新版本更难，于是全集的 0.712 校正到 0.772。没有这一步，"v1.3 掉了 2 个点"无法区分模型退化与题目变难——而这两种情况的应对完全相反。
  • 第 4 段量化了开箱配额的必需性：5 个候选、真实能力全为 0.70，反复开箱 10 次后"历史最高分"比真实能力高 3 个点以上。这 3 个点会全部进入发布决策的收益叙事。 限制开箱次数 + 留痕是唯一有效的对抗手段。
  • 第 5 段把饱和检测落到具体动作：p>0.95 且 D<0.10 的题从选型集移除但保留在门禁集；D 接近 0 或为负的题必须复核题面（负区分度几乎总意味着歧义）。注意这里是"移出某个集"而不是"退役"——同一道题对不同决策的价值不同。
  • 第 6 段给出内部污染探针的最简形式：诱饵串命中是"启动调查"的触发器，不是结论。它便宜、可自动化，适合每月跑一次；确认污染还需要人工判断与更大的检测组合（第 2 章的成员推断方法）。

练习#

  1. 数据契约：为"用户问客服机器人"的评测样本写一份字段表。 （a）区分可变/不可变字段，并说明每个字段的作用； （b）如果你的 reference 需要随业务政策变化（退货期从 7 天改为 15 天），写出修订流程（哪些记录要改、哪些基线要重跑）； （c）设计一个能自动发现"id 被复用"的校验。

  2. 版本归类：你做了四处改动：（a）修正 3 道题的错别字；（b）新增 25 道题；（c）把评分从"对/错"改为"对/部分对/错"；（d）给 10 道题补了分层标签。 （a）为每处改动判定 PATCH/MINOR/MAJOR，并说明理由； （b）如果这四处一起发布，整体应归为哪一版？ （c）写出发布检查清单（至少 6 项）。

  3. 锚题等值：v2.0 与 v2.1 之间有 60 道锚题。v2.1 上模型 A 全集 0.681、锚题 0.650；v2.0 上锚题 0.700。 （a）算漂移与校正后分数； （b）判断模型是进步还是退步； （c）如果锚题本身的难度也变了（因为业务规则更新，部分锚题的参考答案改了），这个校正会偏哪个方向？你会怎么防护？

  4. 开箱纪律：你的团队每两周做一次模型选型，候选 6~10 个，每次都跑 test-frozen。 （a）用第 4 段的模型估算一年（26 次）后的累计选择增益； （b）设计一个替代方案，让"频繁选型"不污染发布决策（提示：分层使用 dev 与 frozen）； （c）写出开箱记录必须包含的字段。

  5. 污染响应：诱饵串探针在三个方式中有两个命中。 （a）列出至少四种"非污染"的可能解释； （b）设计一个能区分"见过"与"泛化"的验证实验； （c）如果确认污染，写出处置流程（评测集、历史报告、训练流程分别怎么改）。

  6. 生命周期决策（开放题）：你的评测集用了 9 个月，指标：题目间方差占比从 0.65 降到 0.38，40% 的题目通过率 > 0.95，两名维护者都换过人。 （a）列出一份健康检查清单（至少 8 项）； （b）给出你的处置建议（补题/退役/换代）与成本估算； （c）写出给管理层的汇报要点（必须包含"这次治理的收益如何度量"）。

小结#

  • 评测样本是带契约的数据对象：id/input/provenance 不可变，reference/rubric/weight 可修订但要记版本。三条铁律：id 永不复用、改 input 必须新 id、改评分标准必须重跑基线。
  • 版本策略要写成明文规则：PATCH（修 typo，无需重跑）、MINOR（增删题目，需重跑 + 锚题等值）、MAJOR（改评分/判定/体系，历史分数作废）。分界线的判据是"能否用锚题把模型变化与评测集变化分开"。
  • 锚题是趋势线的接续件：比例通常 ≥15%，低了会让等值校正自身引入的噪声大于要校正的偏差；没有锚题的版本升级等于砍断趋势线。
  • 三集 + 四条开箱纪律：dev（可过拟合）/ test-frozen（门禁，限次开箱 + 留痕）/ test-live（监控，定期轮换，不用于发布决策）。一旦某集被用于训练或调参，永久降级为 dev。
  • 防污染要四道闸：访问控制与读留痕、诱饵串探针、训练数据黑名单过滤、人员/流程隔离。摩擦花在 test-frozen 上，不要花在 dev 上。
  • 饱和题"移出某个集"而不是"退役"：同一道题对选型无用、对回归门禁仍有用；负区分度几乎总是题面歧义。
  • 治理是周期性动作：每次改动做影响评估、每月做项目分析与污染抽检、每季度轮换与配额结算、每半年做健康报告（含"这套评测集实际改变了多少次决策"——如果答案是 0，问题不在评测集质量，而在它没有连着决策）。
