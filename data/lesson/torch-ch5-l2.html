评估#

上一课我们让损失一路下降，但训练损失低不等于模型好——它可能只是在验证集上"死记硬背"训练数据。判断模型真正好不好，必须在它从没见过的验证集/测试集上测一遍。这一课讲清楚：怎么正确、公平地评估一个模型。

一、概念讲解#

1. 为什么要单独评估#

训练时模型在"开卷考试"：它反复看同一批数据并照着答案改。损失下降只能说明"它把训练集背下来了"，不代表它面对新数据还能答对。评估就是用一份模型没参与训练的数据来测"真实水平"，暴露过拟合：

  • 训练损失持续下降，验证损失却开始上升 → 过拟合；
  • 两者一起下降 → 学习健康。

2. 评估时的关键动作#

评估和训练很像，但有四处必须不同：

  1. model.eval()：关闭 Dropout 的随机丢弃、固定 BatchNorm 的统计量；
  2. torch.no_grad()：不求梯度、不建计算图，省内存、加速；
  3. 不打乱数据：DataLoader 用 shuffle=False；
  4. 不调用 optimizer.step() / backward()：只前向计算，不更新参数。

这四个动作合起来，保证评估结果稳定、可复现、不被随机性污染。

3. 常用评估指标#

  • 回归：均方误差 MSE、平均绝对误差 MAE——和训练损失一致即可；
  • 分类：准确率（accuracy） 最直观，即"预测正确的样本数 ÷ 总样本数"。

分类准确率的计算套路：取模型输出在类别维上的最大值下标作为预测类别，再和真实标签比较：

pred = output.argmax(dim=1)           # (batch,) 每个样本的预测类别
correct = (pred == target).sum().item()  # 正确个数
accuracy = correct / target.size(0)   # 正确率

二、可运行代码示例#

用一个三分类的小模型演示"训练 + 每个 epoch 后评估"的完整写法。数据用随机生成的三簇点，代码直接在 CPU 上跑，重点看评估函数 evaluate 怎么写、以及准确率如何随训练上升。

import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset


# 1) 构造三分类数据：三簇点，各自带标签 0/1/2
torch.manual_seed(0)
def make_cluster(center, n=300):
    return center + torch.randn(n, 2) * 0.5

x0 = make_cluster(torch.tensor([-3.0, -3.0])); y0 = torch.zeros(300, dtype=torch.long)
x1 = make_cluster(torch.tensor([3.0, -3.0]));  y1 = torch.ones(300, dtype=torch.long)
x2 = make_cluster(torch.tensor([0.0, 3.0]));   y2 = torch.full((300,), 2, dtype=torch.long)

X = torch.cat([x0, x1, x2])
Y = torch.cat([y0, y1, y2])

# 拆成训练集（80%）和验证集（20%）
n = X.size(0)
idx = torch.randperm(n)
train_idx, val_idx = idx[: int(n * 0.8)], idx[int(n * 0.8):]
train_loader = DataLoader(TensorDataset(X[train_idx], Y[train_idx]), batch_size=32, shuffle=True)
val_loader = DataLoader(TensorDataset(X[val_idx], Y[val_idx]), batch_size=32, shuffle=False)

# 2) 模型与训练配置
model = nn.Sequential(nn.Linear(2, 16), nn.ReLU(), nn.Linear(16, 3))
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.02)


# 3) 评估函数：只前向、不求梯度
def evaluate(model, loader):
    model.eval()              # 评估模式
    correct = 0
    total = 0
    with torch.no_grad():     # 关闭自动微分
        for xb, yb in loader:
            out = model(xb)                  # 前向
            pred = out.argmax(dim=1)         # 取概率最大的类别
            correct += (pred == yb).sum().item()
            total += yb.size(0)
    return correct / total


# 4) 训练循环 + 每个 epoch 末评估
for epoch in range(1, 16):
    model.train()   # 切回训练模式
    for xb, yb in train_loader:
        optimizer.zero_grad()
        loss = criterion(model(xb), yb)
        loss.backward()
        optimizer.step()

    acc = evaluate(model, val_loader)   # 每个 epoch 后在验证集上评估
    print(f"epoch {epoch:2d}  验证准确率 = {acc:.3f}")

运行后你会看到类似：

epoch  1  验证准确率 = 0.756
epoch  2  验证准确率 = 0.911
epoch  3  验证准确率 = 0.967
...
epoch 15  验证准确率 = 0.994

准确率从 0.75 一路涨到 0.99 以上，说明模型真学会了区分三簇点，而不只是背训练数据。注意 evaluate 里 model.eval() 和 torch.no_grad() 两个细节：漏掉任何一个，评估都可能不准确、还白白浪费显存。

三、练习#

  1. 在 evaluate 里补上"平均损失"的计算，让函数同时返回 (准确率, 平均损失)，并打印每个 epoch 的验证损失。
  2. 把训练 epoch 加到 40，观察验证准确率是否开始"震荡甚至下降"，体会过拟合的苗头。
  3. 故意把 model.eval() 从 evaluate 里删掉，对比结果；再思考：本例没用 Dropout，为什么结果可能没变化？换个带 Dropout 的模型会怎样？
  4. 给模型加一层 nn.Dropout(0.5)，比较 eval() 调用与否对验证准确率的影响。
