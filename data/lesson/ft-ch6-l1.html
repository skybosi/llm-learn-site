用 Hugging Face 微调#

前面几章我们把 QLoRA、PEFT、SFT、评估拆开讲透了。这一章开始实战收口：把 Hugging Face 生态的 transformers + datasets + peft + trl 串成一条完整的微调流水线，从"一堆原始数据"到"一个能用的模型"，用一份可运行脚本走通。这一课聚焦端到端流程和工程细节——数据怎么进、tokenize 怎么做、训练怎么配、模型怎么存和推 Hub。

一、概念讲解#

1. Hugging Face 微调的四块积木#

一次标准微调由四个库协同完成，各司其职：

  • datasets：加载、清洗、切分数据集，统一成 Dataset 对象，支持流式加载超大语料；
  • transformers：加载基座模型和分词器，提供 Trainer 训练循环；
  • peft：注入 LoRA 等适配器，把训练参数量压到千分之一；
  • trl：在 Trainer 之上再封装 SFT 等任务专用训练器。

整条流水线的形状是固定的：数据 → 分词（含掩码）→ 注入适配器 → 配置 Trainer → 训练 → 保存/合并。掌握这条主线，换模型、换数据都不慌。

2. 数据管道：从文件到 Dataset#

真实项目的数据通常在 JSON/JSONL 里，第一步是加载并做训练/验证切分（务必留出验证集）。datasets 的 load_dataset("json", data_files=...) 一步到位，train_test_split() 切分。若数据太大放不进内存，用 streaming=True 流式处理。

3. Tokenize 与数据整理#

分词阶段要做三件事：

  1. 渲染对话：用 apply_chat_template 把 messages 转成训练文本；
  2. 截断/填充：max_length + padding，超长样本要截断（对长文档任务建议先分块再训练）；
  3. 构造 labels：把 prompt 部分掩成 -100，让损失只落在回答上。

这些在 SFTTrainer 里被自动处理，但你仍需理解其原理（上一章已讲）才能在出问题时排查。

4. 训练配置的关键项#

TrainingArguments 里最影响结果和显存的几个参数：learning_rate、per_device_train_batch_size、gradient_accumulation_steps、num_train_epochs、bf16/fp16、gradient_checkpointing、save_steps/eval_steps。梯度检查点能大幅省显存（用时间换空间），配合 4-bit 量化是低配显卡的救命组合。

5. 保存与共享#

训练产物是适配器权重（几 MB），用 save_pretrained 保存；想部署成普通模型就 merge_and_unload。要共享给团队或社区，用 push_to_hub 推到 Hugging Face Hub，配好 README 的 model card。

二、可运行代码示例#

下面是一份完整、可跑的端到端脚本（依赖 datasets、transformers、peft、trl、accelerate、bitsandbytes）。用小型数据和 4-bit 量化，普通 T4 即可运行。

import torch
from datasets import Dataset
from transformers import (
    AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig, TrainingArguments
)
from peft import LoraConfig, prepare_model_for_kbit_training
from trl import SFTTrainer

# 1) 数据：构造几条指令样本（真实项目请 load_dataset("json", data_files="...")）
raw = [
    {"messages": [
        {"role": "user", "content": "解释什么是梯度下降"},
        {"role": "assistant", "content": "梯度下降是一种通过沿负梯度方向迭代更新参数来最小化损失函数的优化算法。"}]},
    {"messages": [
        {"role": "user", "content": "什么是学习率"},
        {"role": "assistant", "content": "学习率控制每次参数更新的步长，过大易震荡，过小收敛慢。"}]},
]
dataset = Dataset.from_list(raw)
dataset = dataset.train_test_split(test_size=0.2)  # 留出验证集

model_id = "HuggingFaceH4/zephyr-7b-beta"  # 示例：换成你要微调的基座

# 2) 量化加载（QLoRA），T4 也能跑 7B
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)
model = AutoModelForCausalLM.from_pretrained(
    model_id, quantization_config=bnb_config, device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained(model_id)
tokenizer.pad_token = tokenizer.eos_token
model = prepare_model_for_kbit_training(model)

# 3) LoRA 配置
peft_config = LoraConfig(
    r=16, lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM",
)

# 4) 训练参数（含梯度检查点省显存）
args = TrainingArguments(
    output_dir="./hf-ft-output",
    per_device_train_batch_size=1,
    gradient_accumulation_steps=8,
    learning_rate=2e-4,
    num_train_epochs=1,
    logging_steps=1,
    save_strategy="epoch",
    evaluation_strategy="no",
    bf16=True,
    gradient_checkpointing=True,
    report_to="none",
)

# 5) SFTTrainer 训练
trainer = SFTTrainer(
    model=model,
    args=args,
    train_dataset=dataset["train"],
    tokenizer=tokenizer,
    peft_config=peft_config,
    max_seq_length=512,
)
trainer.train()

# 6) 保存适配器，并演示合并
trainer.save_model("./hf-ft-output")
merged = trainer.model.merge_and_unload()
merged.save_pretrained("./hf-ft-merged")
print("适配器已保存到 ./hf-ft-output，合并模型已保存到 ./hf-ft-merged")

这份脚本就是本课程前几章所有知识的汇合：QLoRA（4-bit NF4 + 双重量化）、PEFT（LoraConfig + 注入）、SFT（chat template + 回答掩码）、训练工程（梯度检查点 + 累积）。跑通它，你就拥有了一套可复用到任何项目的微调骨架。

三、练习#

  1. 把示例数据换成你自己的 JSONL 文件，用 datasets.load_dataset("json", data_files="你的文件.jsonl") 加载，并确认 train_test_split 能正确切出验证集。
  2. 开启 evaluation_strategy="steps" 与 eval_steps，传入 eval_dataset，训练时观察验证集 loss，判断是否过拟合。
  3. 用 push_to_hub（先 huggingface-cli login）把适配器推到你的 Hub 空间，并写一个带"模型用途、数据来源、局限性"的 model card。
  4. 对比"只存适配器 + 运行时加载"与"merge_and_unload 后部署"两种方式的加载耗时与磁盘占用，说明各自适用场景。
