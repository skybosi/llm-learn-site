bitsandbytes 与部署#

量化家族里还有一个"平民英雄"——bitsandbytes。它让任何人在一块普通显卡（甚至消费级卡）上，用几行代码就把一个大模型以 4-bit 或 8-bit 载入显存，是 Hugging Face transformers 生态里最省事的量化入口。学完本课，你应当能用 bitsandbytes 载入一个 4-bit 模型跑推理，并理解 NF4、双量化、QLoRA 这三个关键词，最后串起一条完整的量化部署流程。

一、概念讲解#

1. bitsandbytes 是什么#

bitsandbytes 是一个 CUDA 量化库，提供 INT8 与 4-bit 的运行时量化。它最大的便利在于：你不需要预先准备量化好的模型文件，直接在 from_pretrained 时加上量化参数，就能边加载边量化，几行代码搞定。

from transformers import AutoModelForCausalLM, BitsAndBytesConfig

nf4_config = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4")
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf",
                                             quantization_config=nf4_config)

2. NF4：更适合权重的 4-bit 表示#

普通 INT4 是均匀地把浮点区间切成 16 份。但权重值的分布通常接近正态——中间多、两头少。均匀切割会浪费格子。

NF4（4-bit NormalFloat） 是一种非均匀的 4-bit 数据类型：它的 16 个取值点按照标准正态分布的分位数来放置，让格子密集地落在权重最常出现的区域，从而在同样 4-bit 下获得更小的量化误差。经验上，NF4 比均匀 INT4 精度更好，是 bitsandbytes 4-bit 的默认选择。

3. 双量化（double quantization）#

4-bit 量化还需要为每个块存一个 FP32 的 scale 因子，这些 scale 本身也要占内存。双量化就是"连 scale 也再做一次量化"（把 scale 也压成 8-bit），进一步省下可观的显存——对一个 7B 模型，双量化通常能再省约 0.4GB 左右。损失极小，性价比很高。

4. QLoRA：在 4-bit 基座上微调#

QLoRA 是 bitsandbytes 生态里最重要的衍生成果：它在4-bit NF4 量化模型之上叠加低秩适配器（LoRA）做微调，让"在一块 24GB 卡上微调 65B 模型"成为可能。核心是"量化主权重 + 只训练一小撮 LoRA 参数 + 双量化省显存"。推理部署时，LoRA 可合并回量化权重或单独加载。

5. 一条完整部署流程#

从零到"跑起来的 4-bit 服务"，通常是这几步：

  1. 选量化方案：GPU 在线服务优先 AWQ/GPTQ（vLLM 原生）；本地/边缘用 GGUF；图省事用 bitsandbytes；
  2. 载入模型：用 bitsandbytes 或 vLLM 按目标精度载入；
  3. 压测：测显存、吞吐、TTFT/TPOT，确认满足目标；
  4. 上线：封装成 OpenAI 兼容服务，配置并发与显存利用率。

二、可运行示例#

1. bitsandbytes 载入 4-bit 模型推理#

# -*- coding: utf-8 -*-
# 用 bitsandbytes 以 4-bit NF4 载入模型并推理（需 GPU + bitsandbytes）
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig

bnb = BitsAndBytesConfig(
    load_in_4bit=True,                  # 启用 4-bit
    bnb_4bit_quant_type="nf4",          # NF4 非均匀量化
    bnb_4bit_use_double_quant=True,     # 双量化，再省显存
    bnb_4bit_compute_dtype=torch.float16,
)
model_id = "meta-llama/Llama-2-7b-hf"
tok = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id,
                                             quantization_config=bnb,
                                             device_map="auto")

prompt = "用一句话解释量化为什么能提速 decode"
inputs = tok(prompt, return_tensors="pt").to("cuda")
out = model.generate(**inputs, max_new_tokens=64)
print(tok.decode(out[0], skip_special_tokens=True))

# 打印量化后模型占用的显存（应远小于 FP16 的 ~14GB）
print(f"显存占用约 {model.get_memory_footprint()/1024**3:.1f} GB")

2. 对照 INT8 与 FP16 的显存#

# -*- coding: utf-8 -*-
# 估算不同量化精度下 7B 模型权重的显存占用
def weight_gb(params_billion, bytes_per_param):
    return params_billion * 1e9 * bytes_per_param / 1024**3

for name, bpp in [("FP16", 2), ("INT8", 1), ("INT4/NF4", 0.5),
                  ("INT4+双量化", 0.5)]:   # 双量化主要省 scale，权重仍 0.5
    print(f"7B {name:>12}：权重约 {weight_gb(7, bpp):.1f} GB")
print("\n注：双量化额外省下的是 scale 因子占用的显存，7B 约 0.4GB。")

3. 部署检查清单（伪代码）#

# -*- coding: utf-8 -*-
# 量化部署上线前的检查清单

def deploy_check(engine, quant, vram_gb, tpot_ms, ttft_ms):
    checks = {
        "引擎就绪": engine in {"vLLM", "TensorRT-LLM", "SGLang", "llama.cpp"},
        "量化生效": quant is not None,
        "显存不超预算": vram_gb < 40,
        "TPOT 达标": tpot_ms < 50,
        "TTFT 达标": ttft_ms < 1000,
    }
    failed = [k for k, v in checks.items() if not v]
    return "通过" if not failed else f"未通过：{failed}"

print(deploy_check("vLLM", "awq", vram_gb=12, tpot_ms=25, ttft_ms=300))

三、练习#

  1. 跑 4-bit：在有 GPU 的环境里运行示例 1，对比 get_memory_footprint() 与 FP16 的 ~14GB，验证 4-bit 的显存减半。
  2. 关双量化：把 bnb_4bit_use_double_quant 改成 False，观察显存与生成速度的微小差异，理解双量化"省的是 scale"。
  3. 换 INT8：改用 BitsAndBytesConfig(load_in_8bit=True) 载入，对比 8-bit 与 4-bit 的显存和输出质量，体会精度与省内存的权衡。
  4. 思考：QLoRA 为什么能让"微调大模型"的门槛大幅降低？把"量化主权重 + LoRA + 双量化"三者各自的作用写清楚。
