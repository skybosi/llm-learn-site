领域适配#

通用基座模型懂很多，但在垂直领域（医疗、法律、金融、代码、某个企业内部知识）常常"看似会答、实则外行"。领域适配（Domain Adaptation） 就是让通用模型真正掌握某个领域的知识、术语与规范。这一课的关键认知是：领域适配不只是"喂指令数据"，它往往需要两条腿走路——先用领域语料做继续预训练补知识，再用指令数据做 SFT 补行为。我们讲清两条路线的分工，以及怎么在预算有限时取舍。

一、概念讲解#

1. 领域适配的两个维度#

通用模型在垂直领域会暴露两类短板：

  • 知识缺：不懂领域专有名词、实体、事实（如"依那西普"、"Ⅲ期临床试验"）；
  • 行为偏：不熟悉领域的任务格式、输出规范、行文风格（如病历结构化、法律文书格式）。

对应两条适配路线：

  • 继续预训练（CPT, Continual Pre-Training）：在领域原始语料上继续做自回归语言建模，补知识；
  • 指令微调（SFT）：在领域指令—回答对上做监督微调，补行为/格式。

两者的目标、数据、损失都不同，不能互相替代。

2. CPT：给模型"读"领域书#

CPT 数据是领域原始文本（论文、病历、合同、代码库），不需要人工标注问答，来源充足。损失和预训练一样——预测下一个 token。它让模型的词表、内部表示"长出"领域概念，是最扎实的知识注入方式。

CPT 的坑在于灾难性遗忘：如果只喂领域文本，模型会慢慢忘掉通用能力。缓解办法：

  • 混入通用语料（领域:通用 常见 1:1 或按需调节）；
  • 低学习率、少轮数（CPT 通常 1~2 个 epoch，学习率远低于预训练）；
  • 重放（replay）：训练数据里保留一部分通用样本。

3. SFT：教模型"按领域规矩办事"#

SFT 数据是领域任务的指令—回答对，比如"根据这份病历摘要生成结构化记录"。它教的是行为规范和格式，但无法凭空注入模型没见过的知识——所以对一个完全陌生的领域，纯 SFT 常出现"一本正经地胡说八道"。

4. 混合策略：先 CPT 后 SFT#

实践中最有效的配方通常是两段式：

  1. 先 CPT：用大量领域语料（混一点通用语料）让模型补上领域知识；
  2. 再 SFT：用精心构造的领域指令数据，把"有知识"的模型调成"会按要求办事"的助手。

预算有限时，可按数据可得性取舍：领域语料多且标注难 → 侧重 CPT；已有高质量标注问答 → 侧重 SFT；两者都有 → 两段式效果最佳。此外，RAG（检索增强） 是"不微调"的轻量替代——把领域知识放进向量库按需检索，适合知识高频更新的场景。

5. 领域数据从哪来#

  • 领域语料：公开论文、行业标准、内部文档（注意版权与隐私合规）；
  • 指令数据：专家标注最贵，可先用 LLM 辅助生成草稿再由专家审核（"合成 + 人工校验"），或用 RAG 检索到的事实去约束生成，降低幻觉。

二、可运行代码示例#

下面演示 CPT 的最小实现——用 Trainer 在领域文本上做自回归继续预训练，并与前面 SFT 脚本形成对照。依赖 transformers、datasets、peft。

from datasets import Dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, Trainer, TrainingArguments
from peft import LoraConfig, get_peft_model

model_id = "gpt2"  # 演示用小模型，真实项目换成领域基座

# 1) 领域语料（原始文本，无需标注）：这里混入一句通用语料防遗忘
domain_texts = [
    "依那西普是一种 TNF 抑制剂，用于治疗类风湿关节炎。",
    "本项研究为随机、双盲、安慰剂对照的 III 期临床试验。",
    "机器学习是人工智能的一个分支，关注从数据中学习规律。",  # 通用语料，防止灾难性遗忘
]
dataset = Dataset.from_dict({"text": domain_texts})

tokenizer = AutoTokenizer.from_pretrained(model_id)
tokenizer.pad_token = tokenizer.eos_token

# 2) 把文本 tokenize 成"自回归"形式：labels = input_ids
def tokenize(ex):
    enc = tokenizer(ex["text"], truncation=True, max_length=128)
    enc["labels"] = enc["input_ids"].copy()  # CPT 对全部 token 算 loss（与 SFT 掩码不同！）
    return enc

dataset = dataset.map(tokenize, remove_columns=["text"])

# 3) 注入 LoRA，继续预训练也只训低秩增量
model = AutoModelForCausalLM.from_pretrained(model_id)
model = get_peft_model(model, LoraConfig(
    r=8, lora_alpha=16, target_modules=["c_attn", "c_proj"],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM",
))

# 4) 用通用 Trainer 跑 CPT
args = TrainingArguments(
    output_dir="./cpt-output",
    per_device_train_batch_size=2,
    learning_rate=5e-5,          # CPT 学习率要低
    num_train_epochs=2,          # 轮数要少，防遗忘
    logging_steps=1,
    report_to="none",
)
trainer = Trainer(model=model, args=args, train_dataset=dataset)
trainer.train()
trainer.save_model("./cpt-output")
print("CPT 完成，适配器已保存到 ./cpt-output")

注意第 2 步与 SFT 的关键差异：CPT 的 labels = input_ids，即对每一个 token 都算损失，因为它的目标是"学习领域文本的语言规律"，而不是"只学回答部分"。这正是 CPT 与 SFT 在实现层面最直观的区别。

三、练习#

  1. 把 CPT 脚本里的领域语料去掉那句通用语料，多训几轮后，用一个通用问题（如"写一首诗"）测试模型，观察是否出现灾难性遗忘的迹象。
  2. 用你自己领域的 20 条文本，分别做 CPT 和 SFT，然后各问一个领域问题，对比"懂不懂知识"和"会不会按格式答"两方面的差异。
  3. 实现一个"两段式"小流程：先跑 CPT 得到适配器，再把它作为基座接 SFT，观察最终模型在领域问答上的表现是否优于单独 CPT 或单独 SFT。
