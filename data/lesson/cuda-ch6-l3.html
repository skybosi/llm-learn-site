矩阵乘：naive → tiling → 双缓冲 → Tensor Core 路径#

第 4 课已经把 naive GEMM 的账算死：算术强度 0.25 FLOP/Byte，无论矩阵多大都在等显存。这一课把它的账真正算成 kernel——不是一次写完，而是分四步走，每一步只解决一个瓶颈，并且每一步都留下可核对的数字：tiling 降 HBM 搬运、thread tile 降 shared memory 流量、双缓冲藏延迟、Tensor Core 之外还要解决"喂不进 MMA 的形状"与 bank 冲突。这也是本章最后一课（正确性验收）的对照基准。

一、概念讲解#

1. 第一层：block tile 决定 HBM 搬运量#

把输出切成 bm​×bn​ 的块，K 维切成 bk​ 段；每段把 bm​×bk​ 的 A 条带与 bk​×bn​ 的 B 条带搬进 shared memory，块内所有线程共享。搬运量：

HBM 元素数=bm​M​⋅bn​N​⋅bk​K​(bm​bk​+bk​bn​)

M=N=K=4096、float32 时：(64,64,8) 要搬 8 GiB，算术强度 16 FLOP/Byte；(256,128,16) 只要 3 GiB，强度升到 42.7。块越大，HBM 越省，但 shared memory 与寄存器越紧——第 4 课的 occupancy 权衡在这里开始生效。

2. 第二层：warp tile 与 thread tile#

shared memory 不是免费的：块内每个线程都去读同一份 A/B 条带，读多了 shared memory 带宽也会成为瓶颈。于是有第二层分块：warp tile（每个 warp 负责 w×w 的输出子块）与 thread tile（每个线程负责 t×t 的输出）。

关键手法是寄存器分块（register blocking）：线程把 A 的一段 t 个值放进寄存器，把 B 的一段 t 个值放进寄存器，做 t2 次乘加——寄存器复用把 shared memory 读取量降低 t 倍。代价是累加器占寄存器：t=4 要 16 个，t=8 要 64 个。累加器 + A 片 + B 片合计 24（t=4）到 80（t=8）个寄存器，还要给地址、索引、流水线留出余量。"线程块越大越好"在这里第一次撞墙：t=8 时单线程就吃掉 80 个寄存器，occupancy 会被压下来。一个具体的对比：每个线程只算 1 个输出时，做 bm​bn​bk​ 次乘加要读 2bm​bn​bk​ 个 shared memory 元素（每次乘加两个操作数都从 shared 取）；改成 t×t 的 thread tile 后，每个线程用 2t 个寄存器读数做 t2 次乘加，shared memory 读取量降为原来的 1/t。

3. 第三层：双缓冲把"等"藏起来#

把 shared memory 分成两份缓冲：计算第 i 段的同时，把第 i+1 段的数据搬进来（第 4 课的 cp.async / TMA）。流水线深度为 S 时，稳态下每次循环只等"最慢的一环"，而不是"搬运 + 计算"之和。工程判据：只要搬运时间 ≤ 计算时间，就实现了完全重叠；反过来，如果 shared memory 里装不下 S 段数据，就只能降 S 或降 tile 尺寸。注意分工：cp.async/TMA 解决的是 HBM → shared memory 这一段，寄存器分块解决的是 shared memory → 寄存器 这一段，两者不能互相替代。

4. 第四层：Tensor Core 路径#

Tensor Core 把 D=A×B+C 的固定小形状指令化（MMA，matrix multiply-accumulate）。典型形状（PTX ISA 的 mma.sync 家族）：FP16 输入的 m16n8k16、TF32 输入的 m16n8k8、FP64 的 m16n8k4。走这条路要改三件事：

事项 具体约束
分块尺寸 bk​ 必须是 MMA 的 k 的整数倍（m16n8k16 时 16），否则最后一段喂不进指令
数据布局 操作数要按 MMA 期望的 fragment 布局排（WMMA API 的 fragment 是不透明类型，布局由架构决定，不能在代码里假定）
shared memory MMA 对 shared memory 的访问方式固定，必须用 padding 或 XOR swizzle 消除 bank 冲突

精度上要分清三种"半精度"：FP16 输入 + FP32 累加、TF32（fp32 输入、10 位显式尾数，由 MMA 内部截断）、以及 BF16（8 位尾数、动态范围与 fp32 相同）。累加器与输入的精度是两件事：输入截断会带来系统性误差，累加器用 fp32 只是防止加法链上的精度爆炸。是否可接受，取决于第 5 课的对齐容差。

5. 常见坑#

  • 只做 block tile，不做 thread tile：HBM 省了，shared memory 却成了新瓶颈，典型的"优化了一半"。
  • 把累加器写回 shared memory：k 段之间累加器必须留在寄存器里，每段写一次 shared 会把收益全抹掉。
  • b_k 不是 MMA 的 k 的倍数：编译器可能悄悄退化成 SIMT 路径，也可能直接编不过；显式检查余数。
  • 忽略 bank 冲突：行宽 32、按列读 8 行的最坏情况是 8-way 冲突；+1 padding（行宽 33）或 XOR swizzle 都能降到 1-way。
  • C 的初始化：MMA 的 C 是累加输入，必须显式清零或从已有值加载，否则读到未初始化寄存器。

二、可运行代码示例#

需要 numpy（本机 python3.10 + numpy 1.26.2 验证）。五段分别给出：搬运账、寄存器账、thread tile 的正确性对拍、Tensor Core 分块约束检查、bank 冲突的三种布局对照。

# ===== 本课示例：GEMM 三层复用账 + 寄存器账 + thread tile 验证 + Tensor Core 约束 =====
import numpy as np

# ---------- 1. 三层复用：block tile / warp tile / thread tile 的搬运账 ----------
def traffic(M, N, K, bm, bn, bk, warp, Tt=1, elemsize=4):
    """返回 HBM 字节、shared→reg 元素数、每线程寄存器需求（thread tile 为 Tt×Tt）。"""
    hbm = (M // bm) * (N // bn) * (K // bk) * (bm * bk + bk * bn) * elemsize
    # 每个 warp 负责 warp×warp 一格；格内每个线程算 Tt×Tt 个输出，
    # 每次 k 迭代需要 A 的 Tt 个值与 B 的 Tt 个值 → 每线程读 2·Tt 个，共 (warp/Tt)² 个线程
    warps = (bm // warp) * (bn // warp)
    threads_per_warp = (warp // Tt) ** 2
    shm = (M // bm) * (N // bn) * (K // bk) * warps * threads_per_warp * (2 * bk * Tt)
    regs = Tt * Tt + 2 * Tt
    return hbm, shm, regs

M = N = K = 4096
flops = 2 * M * N * K
print(f"=== M=N=K={M}，float32：block tile 定 HBM，thread tile 定 shared→reg ===")
print(f"{'block(bm,bn,bk) warp Tt':<28} {'HBM(MB)':>8} {'算术强度':>9} {'shared→reg(百万元素)':>20} {'寄存器/线程':>11}")
for (bm, bn, bk, warp, Tt) in ((64, 64, 8, 32, 1), (64, 64, 8, 32, 4), (64, 64, 8, 32, 8),
                               (128, 128, 8, 64, 4), (256, 128, 16, 64, 4)):
    hbm, shm, regs = traffic(M, N, K, bm, bn, bk, warp, Tt)
    label = f"{str((bm,bn,bk))} w{warp} t{Tt}"
    print(f"{label:<28} {hbm/2**20:>8.2f} {flops/hbm:>9.1f} {shm/1e6:>20.1f} {regs:>11}")
print("（naive 版本的算术强度是 0.25 FLOP/Byte，对照第 4 课）")

# ---------- 2. 每线程的寄存器账：累加器 + A 片 + B 片 ----------
print("\n=== thread tile 的寄存器预算（float32，一个寄存器 4 字节）===")
for Tt in (4, 8):
    acc, a_frag, b_frag = Tt * Tt, Tt, Tt
    print(f"thread tile {Tt}x{Tt}：累加器 {acc:>3} + A 片 {a_frag:>2} + B 片 {b_frag:>2}"
          f" = {acc + a_frag + b_frag:>3} 个寄存器（另有地址/索引/流水线缓冲，通常还要再留 30%~50%）")

# ---------- 3. thread tile GEMM 的正确性：numpy 手工分块 vs A@B ----------
def thread_tiled_gemm(A, B, Tb=8):
    """最小可运行的 thread tile 版本：每个 Tb×Tb 输出块独立累加，k 维逐点（即 k 段长为 1）。"""
    M, K = A.shape; N = B.shape[1]
    C = np.zeros((M, N), dtype=np.float64)
    for bi in range(0, M, Tb):
        for bj in range(0, N, Tb):
            block = np.zeros((min(Tb, M - bi), min(Tb, N - bj)))
            for k in range(K):
                block += A[bi:bi+Tb, k][:, None] * B[k, bj:bj+Tb][None, :]
            C[bi:bi+Tb, bj:bj+Tb] = block
    return C

rng = np.random.default_rng(0)
print("\n=== thread tile 与参考实现的逐元素对拍 ===")
for (m, n, k) in ((64, 64, 64), (128, 96, 160)):
    A = rng.standard_normal((m, k)).astype(np.float32)
    B = rng.standard_normal((k, n)).astype(np.float32)
    C = thread_tiled_gemm(A, B, Tb=8)
    ref = A.astype(np.float64) @ B.astype(np.float64)
    print(f"  {m}x{n}x{k}: 最大差 {np.abs(C - ref).max():.2e}，"
          f"相对误差 {np.abs(C - ref).max() / np.abs(ref).max():.2e}")

# ---------- 4. Tensor Core 路径的分块约束：K 维步长必须是 MMA 形状的倍数 ----------
print("\n=== Tensor Core 分块约束（以 m16n8k16 形状为例）===")
def check_tc(M, N, K, bm, bn, bk, mma=(16, 8, 16)):
    m, n_, k_ = mma
    ok = (bm % m == 0) and (bn % n_ == 0) and (bk % k_ == 0)
    return ok, (K % bk, N % bn, M % bm)
for (m, n, k, bm, bn, bk) in ((4096, 4096, 4096, 128, 128, 32),
                              (4096, 4096, 4096, 128, 128, 24),
                              (1000, 1000, 1000, 128, 128, 32)):
    ok, tail = check_tc(m, n, k, bm, bn, bk)
    print(f"  M{m} N{n} K{k} block({bm},{bn},{bk})：形状可整除={ok}，"
          f"余数(K%bk,N%bn,M%bm)={tail}" + ("" if ok else "   ← bk 不是 16 的倍数，mma 直接吃不下"))

# ---------- 5. 为什么 Tensor Core 要求 shared memory swizzle ----------
print("\n=== shared memory bank 视角（32 个 bank、每 bank 4 字节）===")
def bank_conflict(addr_of, rows=8, cols=8):
    """addr_of(i,j) 给出元素地址；统计"一次 warp 读不同行同一列"时的最大 bank 冲突。"""
    worst = 0
    for j in range(cols):
        banks = [addr_of(i, j) % 32 for i in range(rows)]
        worst = max(worst, max(banks.count(b) for b in set(banks)))
    return worst
plain = lambda i, j: i * 32 + j            # 行宽 32，无填充
padded = lambda i, j: i * 33 + j           # 行宽 33（+1 padding）
swizzled = lambda i, j: i * 32 + (j ^ i)   # XOR swizzle：行内列号与行号异或
for name, f in (("行宽 32（无填充）", plain), ("行宽 33（+1 padding）", padded),
                ("行宽 32 + XOR swizzle", swizzled)):
    print(f"  {name:<22} 逐列读 8 行的最大 bank 冲突 = {bank_conflict(f)}-way")

  M4096 N4096 K4096 block(128,128,24)：形状可整除=False，余数(K%bk,N%bn,M%bm)=(16, 0, 0)   ← bk 不是 16 的倍数，mma 直接吃不下
  M1000 N1000 K1000 block(128,128,32)：形状可整除=True，余数(K%bk,N%bn,M%bm)=(8, 104, 104)

=== shared memory bank 视角（32 个 bank、每 bank 4 字节）===
  行宽 32（无填充）             逐列读 8 行的最大 bank 冲突 = 8-way
  行宽 33（+1 padding）      逐列读 8 行的最大 bank 冲突 = 1-way
  行宽 32 + XOR swizzle    逐列读 8 行的最大 bank 冲突 = 1-way

四处可核对的结论：HBM 搬运只随 block tile 变（8192 → 4096 → 3072 MB，算术强度 16 → 42.7）；shared→reg 流量随 thread tile 成比例下降（137439 → 34360 → 17180 百万元素，恰好是 1/t），而 HBM 一字未动——这就是"两层复用各管一段"的直接证据；thread tile 的相对误差在 10−8 量级，差异只来自 float32 累加顺序；b_k=24 这种"看着接近 32"的取值直接不可用，K%bk​=16 说明最后一段喂不进 m16n8k16。最后一张表是 Tensor Core 路径最容易被忽略的一环：同一段数据，布局不同，bank 冲突 8-way vs 1-way。
