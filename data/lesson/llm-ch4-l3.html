RLHF 对齐#

指令微调让模型"听话"，但"听话"不等于"有用、诚实、无害"。面对同一个问题，模型可以给出冗长啰嗦、含糊其辞甚至带偏见有害的回答，而这些"好不好"的细微差别很难写进标准答案里。RLHF（基于人类反馈的强化学习，Reinforcement Learning from Human Feedback）就是训练三阶段的最后一步：让模型的输出对齐（align）人类偏好。本课讲清它为什么需要、三阶段怎么串起来、奖励模型如何从"两两比较"中学习，以及 DPO 这类替代方案。

一、概念讲解#

1. 对齐问题：光会答不够#

对齐追求三个 H：有帮助（Helpful）、诚实（Honest）、无害（Harmless）。SFT 之后模型会答题了，但还可能：编造事实（不诚实）、输出攻击性内容（有害）、答非所问（不有帮助）。这些问题是"回答质量"问题，靠逐字标准答案很难监督——因为同一个问题往往没有唯一正确答案，只有"哪个更好"。

2. RLHF 的三阶段#

InstructGPT 把对齐分成三步，RLHF 通常指后两步，但一般把 SFT 也算进来构成完整流程：

  1. SFT：先用（指令，回答）微调出会答题的策略（上一课内容）。
  2. 训练奖励模型（Reward Model, RM）：对同一个 prompt 生成多个回答，让人排序"谁更好"；RM 学习给"更好的回答"打更高分。
  3. PPO 强化学习：用 RM 当奖励信号，继续优化策略，让模型输出得分更高的回答，同时约束它别偏离 SFT 太远。

3. 奖励模型与 Bradley-Terry 偏好模型#

RM 不直接预测"绝对分数"，而是从两两比较中学习相对偏好。给定同一个 prompt 的两个回答 A、B，若标注员认为 A 更好（A ≻ B），则希望 RM 给 A 的分数 rA​ 高于 B 的分数 rB​。常用 Bradley-Terry 模型建模"A 胜过 B"的概率：

P(A≻B)=σ(rA​−rB​)=1+e−(rA​−rB​)1​

训练 RM 就是最大化这个概率的对数，等价于一个二分类交叉熵损失：把"更优回答"当正类，让分数差 rA​−rB​ 越大越好。这就是 RM 的完整学习信号。

4. PPO 阶段：用奖励做强化学习#

有了 RM，就能对任意回答打分。PPO 把语言模型当作策略，每次让它生成回答，用 RM 打分当奖励，再用策略梯度更新参数，使高奖励回答更可能被生成。为了防止模型"钻空子"（输出迎合 RM 但不自然的话），损失里通常加一项 KL 惩罚，约束新策略不要离 SFT 策略太远。

5. DPO：绕过 RM 与 RL 的替代方案#

RLHF 要训 RM、还要跑 RL，工程复杂且不稳定。DPO（Direct Preference Optimization）发现：可以直接用偏好对优化策略，无需单独训 RM，也无需强化学习。它把"偏好"直接写进一个可微分的损失，在数学上与 RLHF 的最优解有对应关系，实现起来简单得多，现已成为开源社区的主流对齐方法。

二、可运行示例#

下面用合成偏好对，完整演示"奖励模型训练"：给若干（更优回答分数，较差回答分数）的样本，用 Bradley-Terry 损失训一个小 RM，看它如何学会拉开好坏回答的分数差。

import torch
import torch.nn as nn

torch.manual_seed(0)

# —— 合成偏好数据：每条记录是 (r_a, r_b)，含义为 "回答 a 优于回答 b" ——
# 真实世界中，r 由 RM 模型输出；这里用标量直接示意训练信号。
prefs = [
    (2.0, 1.0),   # a 比 b 好，差距较小
    (3.0, 1.0),   # a 比 b 好，差距较大
    (4.0, 2.0),
    (1.0, 2.0),   # 这条表示 b 更好（反向偏好）
    (5.0, 3.0),
]
prefs = torch.tensor(prefs, dtype=torch.float32)
r_a, r_b = prefs[:, 0], prefs[:, 1]

# —— 一个极简奖励模型：把某个"回答"编码成标量分数 ——
# 这里为演示，让模型学两个可调参数 w，代表两个回答的分数。
w = nn.Parameter(torch.tensor([0.0, 0.0]))   # w[0] 对应回答 a 的分数，w[1] 对应回答 b
opt = torch.optim.Adam([w], lr=0.1)

def bradley_terry_loss(r_a_hat, r_b_hat):
    # P(a ≻ b) = sigmoid(r_a - r_b)，最大化其对数值 = 最小化负对数
    return -torch.log(torch.sigmoid(r_a_hat - r_b_hat)).mean()

for step in range(100):
    score_a = w[0].expand_as(r_a)   # 回答 a 的分数
    score_b = w[1].expand_as(r_b)   # 回答 b 的分数
    loss = bradley_terry_loss(score_a, score_b)
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 20 == 0 or step == 99:
        print(f"step {step:3d}  loss={loss.item():.4f}  "
              f"score_a={w[0].item():.3f}  score_b={w[1].item():.3f}  "
              f"差值={w[0].item() - w[1].item():.3f}")

print("结论：训练后 score_a 显著高于 score_b，")
print("即 RM 学会了把'更好的回答'打更高分——这正是 RLHF 中奖励模型的核心能力。")

注意这里的 RM 是刻意简化到两个标量参数的示意，真实 RM 是拿整个 SFT 模型当主干、在最后接一个线性头输出标量；训练数据也不是"两个标量"，而是"同一 prompt 下的多份回答及其排序"。但损失函数——Bradley-Terry 偏好损失——和这里完全同构。

三、练习#

  1. 手推梯度：对损失 L=−logσ(ra​−rb​)，分别对 ra​、rb​ 求偏导，说明梯度方向为什么是"抬升好回答、压低差回答"。
  2. 加反向样本：在 prefs 里多加几条"b 更好"的样本，观察两个分数会怎样靠近或翻转，理解偏好数据"一致性"的重要性。
  3. 理解 KL 约束：为什么 PPO 阶段要加 KL 惩罚、别让策略离 SFT 太远？如果完全没有 KL 约束，模型可能为了刷高奖励做什么事？
  4. 对比 DPO：DPO 省掉了 RM 和 RL，为什么还需要"偏好对"数据？它和 SFT 用的"标准答案"数据在性质上有何不同？
  5. 思考局限：RLHF 让输出更符合人类偏好，但人类偏好本身可能有偏见。举一个"对齐到有偏好的标注"会带来的风险。
