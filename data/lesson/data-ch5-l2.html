血缘图与影响面：从"这份数据从哪来"到"这处错误影响谁"#

这一节要解决什么#

上一节把每个数据集变成了一个可验证的身份（内容哈希 + 三段快照）。但身份是孤立的：它只说"这一份是这个"，不说"这一份由谁产生、被谁使用"。

真实管线上有几十个节点：来源 → 清洗 → 过滤 → 采样 → 标注 → 配方 → 训练 → 评测 → 报告。它们之间是有方向的依赖，而依赖关系决定了一件工程上最贵的事：当某个节点被发现有问题时，受影响的最小集合是什么。

没有血缘图时，这个问题的答案只有两种极端，而且都错：

  • "全量重跑"：安全，但代价是整条管线。本节代码实测的场景里，一个错标批次的下游可达节点是 5 个，而真正需要重跑的最小集合是 1 个（切断在 labeled_train 上即可），代价比是 14:5:1。
  • "只改那个节点"：便宜，但会留下脏的下游产物，而且经常改错地方。实测里最像常识的答案"错标就改标注那一步"（annotate_batch）被明确否证：它不是切断，因为 bad_labels 直连 labeled_train，有一条路径绕过了它。

血缘图给出的正是第三档答案：一个可计算、可核对、可解释的最小集合。本节给出它的表示、算法、代价与边界，用的全部是第 1 章第 3 节那种"可逆性"语言：不是"影响面差不多是这些"，而是"这些，因为从源点到目标点的每一条路径都经过这里"。

本节课的组织：

  1. 表示：把管线写成一张属性图（节点、列、边），并说明为什么必须列级而不是数据集级。
  2. 两个查询：影响面（前向可达）与根因定位（后向路径 + 责任分摊）。它们各自都是几行图算法，难点不在算法在图的正确性。
  3. 最小切断：用"每条路径都必须经过"的形式定义最小重构集合，并说明它与"所有可达节点"的区别（实测：5 个可达 vs 1 个切断），以及它为什么能否证一个看似最合理的选项。
  4. 根因定位：先限定"哪一列脏"，再按距离排出嫌疑源（实测：症状换成 weight 列后，嫌疑集从 bad_labels 变成 external_ssl）。
  5. 静态图与动态执行的落差：血缘图是声明的，实际执行的可能是另一个东西（条件分支、启发式、全局随机源）。这一节给出三种落差与各自的检测手段。
  6. 维护成本：血缘不是免费的正确性，它自己也会成为负债（陈旧、漏边、被当成真理）。给出四条边界。

一、表示：管线是一张属性图，不是一个目录树#

1.1 概念：节点、列、边三件套#

最小的可用表示是三张表：

node(id, kind, version_hash, params_hash, run_id)
edge(src_id, dst_id, kind, params)        # kind: 数据流 / 控制流 / 参数流
col(node_id, col_name, src_node_id, src_col_name, transform_hash)
  • node：一个产物（数据集、模型、报告、标注批次）。它的身份就是上一节那个 snapshot_id。
  • edge：依赖。必须区分三种边，因为它们在影响面里的传播规则不同：
    • 数据流：父的行/列进入子，脏数据会顺着传播（本节重点）。
    • 控制流：父的状态决定子跑不跑，父变脏时子的定义可能变了（例如"若过滤后剩余 <1000 条则改用另一个分支"）。
    • 参数流：父的值作为子的参数（π、阈值、种子）。它不传播数据，但传播结论：参数变了，子的所有结论要重算（第 1 节的三段分离就是为这件事服务的）。
  • col：列级来源。这是本节与多数"数据目录"工具的分界线。数据集级的血缘只能回答"这份数据被谁用了"，列级才能回答"这个标签列被谁用了"。

1.2 为什么这样设计：数据集级血缘的三种失效#

数据集级血缘（node → node）看起来够用，因为大多数工具默认就这样。它在三类问题上失效，而这三类恰好是最贵的：

失效一：伪影响面（false positive）。 一份数据集有 50 列，其中 1 列坏了。数据集级血缘把所有消费者标成受影响；列级血缘只标那些真的读了这一列的。下游代价的差别是常数倍（本节代码实测：同一场景下数据集级 5 个节点、列级 3 个节点），但在"要不要重训一个大模型"这类决策上，一倍就是几天的算力，而且被多标出来的那两个节点（paper_fig、report）恰好是对外发布物。

失效二：漏影响面（false negative）。 更危险的方向。如果一列在某个节点里被复制进了另一列（改名、拼接、聚合），数据集级血缘认为"这个下游节点用了那份数据"但不清楚用了哪一列，于是当那列被修好后没有触发重跑 —— 而下游的复制品仍然是脏的。这类问题的特征是修完之后指标没变，然后有人得出"这列不重要"的错误结论。

失效三：无法回答"改了哪一步"。 第 1 节的叶集合 diff 能告诉你"这两份快照差哪些文件"，但它不知道是哪一步产生这些差异。列级血缘加上 transform_hash 才能回答："这一列的生成逻辑变了（哈希从 a17… 到 b93…），而输入没变。"

1.3 怎么做：粒度选择是一道成本题#

列级血缘的成本不在存储（边的数量通常是 103∼105），而在采集：要么改写每个变换让它输出映射，要么用 SQL/DataFrame 的解析器自动推导。三种采法：

采法 精度 成本 失效点
手工声明（YAML/DAG 定义） 高（人写的意图） 低但会陈旧 代码改了声明没改 → 图与执行不一致
运行时捕获（变换返回 (data, mapping)） 最高（实际发生的事） 每个变换改一行；动态语言的表结构要处理 忘了一处就漏一条边，且静默
静态解析（读 SQL / 数据流分析） 中（能覆盖声明式） 低（自动） 过程式代码、动态表名解析不了

推荐组合是运行时捕获为主 + 静态解析做交叉校验：

  • 运行时捕获是真值（它记录实际发生的读写），
  • 静态解析是完备性检查（它不由"有没有人忘了改代码"决定）。

两者不一致就是发现漏边的信号：静态说有边而运行时没有 → 那条分支这次没走到（正常）；运行时说有边而静态没有 → 解析器不支持某个构造（要登记成已知缺口，而不是当作无依赖）。

二、两个查询：影响面与根因定位#

2.1 概念：两个方向的图遍历#

给定一个"出问题的节点/列"，两个问题：

  • 影响面（impact set）：从它前向可达的节点。回答"谁可能被污染"。
  • 根因集合（candidate causes）：能后向到达它的源点（入度为 0 的节点）。回答"可能是谁干的"。

两者都是 O(V+E) 的遍历，几行代码。工程上真正的问题是边界：可达集通常过大（本节实测 8 个节点里，只有 1 个真的需要重跑），所以还需要第三个量。

2.2 最小重构集合：用"必经点"代替"可达点"#

定义：设 s 是问题节点，T 是需要保护的产物的集合（例如"所有已经发出去的结论/模型/报告"）。集合 C 是一个切断，如果从 s 到每个 t∈T 的每一条路径都至少经过 C 中一个节点。

这个定义有两个好性质：

  1. 它是可验证的：对每条路径检查一下有没有交 C，不需要相信任何人的判断。
  2. 它直接对应工程动作：修好 C 里的节点并从 C 重新往下跑，就得到干净的下游。T 之外的节点不影响。

C 的最小化是一个最小顶点割问题。在 DAG 上有两条实用路线：

  • 精确（小图）：转成最大流/最小割（把节点拆成入/出两个点，容量 1）。∣V∣=102 的图毫秒级。
  • 启发式（大图）：按拓扑序从 s 向下扫，若某节点的所有入边（在可达子图内）都来自已选集合之外且它唯一控制某个 T 成员，则选它。更常用的简化是：选"最靠上游的支配点"（dominator）——从 s 出发的支配树里，离 s 最近的、能支配全部 T 的节点。

本节代码用一个更朴素但完全够用的版本：在可达子图上求最小顶点割（对每个候选 C 校验"删掉 C 后 T 不可达"，从小到大枚举）。它慢，但把定义讲清楚了 —— 而定义比实现重要。

2.3 根因定位：先限定"哪一列脏"，再比距离#

后向可达会给出一大串候选，其中包括很多中间处理节点（filter、clean）。本节代码的顺序是三步，每一步都砍掉一批候选：

第一步：把症状写成"某一列脏"，而不是"某个节点坏"。 实测的症状是"评测分掉了"，但评测分不掉，掉的是它的输入 —— train_run 的 label 列（标签被弄脏，模型学到错的东西）。这个转换极其重要：节点级症状"train_run 坏了"会把 9 个上游节点全拉进候选（实测 后向可达 train_run 的节点 (9)），而列级症状只关心谁能把脏东西写进这一列。

第二步：只保留源点。 中间节点（filter、clean、rescale）不是候选：它们自己没有输入，坏不了。实测 9 个可达节点里只有 4 个是源点。

第三步：要求"前向列级影响能命中症状列"。 对每个源点取它自己产出的列，算列级影响面，看症状列在不在里面。实测 4 个源点里只有 1 个命中：

suspect(r)=1[(nodes​,cols​)∈Impactcol​(r,colr​)]⋅1+d(r,nodes​)1​

其中 d 是图上最短路径的边数。bad_labels 的距离是 2（bad_labels → labeled_train → train_run），嫌疑度 1/3=0.3333。raw_web 与 raw_forum 只产出 text 列，永远命不中 label，external_ssl 只产出 weight 列 —— 三个都被结构性地排除，而不是被分数压低。

这个式子不是因果推断，它是"结构性排除 + 距离排序"。 它的价值在于第一步与第三步：把"谁可能是根因"从一个模糊的直觉变成一个列级的可达性判定。真正的因果判断仍需干预（重跑一次、只改一处），那是第 3 章第 3 节的实验协议管辖的事。血缘图的作用是把候选从几十个降到一两个，并说清"为什么不是其他几个"。

三、静态声明与动态执行的三种落差#

血缘图是声明。它说"这个变换读了 A 列"，而实际执行的可能是别的东西。三种落差按危害排序：

3.1 条件分支（图的形状依赖数据）#

if n_rows < 1000:
    out = dedup_loose(df)      # 声明里没有这条边
else:
    out = dedup_strict(df)     # 声明里有这条边

声明式的图只能画一条边（或两条都画，于是多出一条假边）。运行时捕获能记录真实走的哪条。处置：把分支条件本身变成图上的决策节点（"这次运行走了哪条分支"进 run 元数据），并在影响面计算时按运行实例展开，而不是按声明的图。

3.2 启发式与全局状态（隐藏的依赖）#

  • 随机源：random.seed() 让子节点的结果依赖一次全局调用 —— 图上没有这条边，但它存在。第 3 节会把它做成显式的 rng_state 参数。
  • 缓存：命中缓存与未命中缓存会走不同代码路径，于是同输入不同输出（第 2 章第 4 节讲过的幂等性在这里再次出现）。
  • 外部查询：词典、tokenizer、模型权重 —— 都是没有画进图的输入，而它们决定了输出。

处置：把这些全部提升为显式参数（种子、缓存键、外部资源版本），它们就成了图上的节点，代价是图的规模变大。

3.3 陈旧（声明与代码漂移）#

最安静的一种：代码改了，声明没改。图上的边仍然指向旧的列名，而那个列已经不存在了。处置：把声明写进版本哈希 —— 第 1 节的 transform_hash 就是这个用途。声明与实现任一改变都会改变哈希，于是"图是否与执行一致"变成一个可测的量（哈希对不上就说明至少有一个变了）。

四、边界：血缘图的四条硬约束#

  1. 血缘记录"结构"不记录"正确性"。 图能告诉你"这一列被这些下游用了"，不能告诉你"这一列本来就是错的"。错标就是最典型的例子：bad_labels 在结构上完全正常，图看不出它坏。发现坏要靠别的机制（人、评测、对账），血缘只负责发现之后的定位。
  2. 血缘会漏边，而漏边是静默的。 手工声明会陈旧，运行时捕获会漏改，静态解析有盲区。三条防线：三种采法交叉校验、把"已知解析不了"登记成显式缺口、以及定期用一次"故意改一处看影响面是否符合预期"的演练来验证图本身。
  3. 血缘的成本随粒度超线性增长。 列级边的数量是 O(节点数×平均列数×平均入度)。列数 200 的表会让图膨胀到无法人读。处置：分级 —— 关键列（标签、分组键、时间）列级，其余列用 *（整表）粒度，并在图上显式标注"这一部分是粗粒度"。
  4. 血缘可以被用来推卸责任。 "图上显示只有 filter 受影响" 这句话可能掩盖"图是上一版代码画的"。处置：任何影响面结论都必须带上图的版本哈希，与代码、数据版本一起写进报告 —— 这又回到第 1 节的快照三段结构。

五、代码#

五段：0 段定义一张合成管线图（⚠️ 合成，非真实生产管线）；1 段做拓扑排序与环检测；2 段做前向影响面（数据集级 vs 列级）；3 段求最小重构集合与路径校验；4 段做后向根因排序，并量化"错误切断"的后果。

# data-ch5-l2: 血缘图、影响面与最小重构集合
# 纯标准库；管线和数据均为合成（⚠️ 合成，用于讲清结构）
import collections, hashlib, json, sys

print(f"python {sys.version.split()[0]}")

# ---------- 0. 合成管线：来源 -> 清洗 -> 过滤 -> 标注 -> 配方 -> 训练 -> 评测 -> 报告 ----------
# 每个节点: (kind, [(输入节点, 输入列, 输出列), ...])
# 列级映射是本节的核心：它记录"哪一列被读、写成哪一列"
PIPELINE = {
    "raw_web":        ("source",  []),
    "raw_forum":      ("source",  []),
    "external_ssl":   ("source",  []),
    "bad_labels":     ("source",  []),                       # 问题源：错标批次
    "rescale":        ("transform", [("external_ssl", "weight", "weight")]),
    "clean":          ("transform", [("raw_web", "*", "text"),
                                     ("raw_forum", "*", "text")]),
    "filter":         ("transform", [("clean", "text", "text"),
                                     ("clean", "lang", "lang")]),
    "annotate_batch": ("label",     [("filter", "text", "text")]),
    "labeled_train":  ("merge",     [("filter", "text", "text"),
                                     ("annotate_batch", "label", "label"),
                                     ("bad_labels", "label", "label"),
                                     ("rescale", "weight", "weight")]),
    "train_run":      ("train",     [("labeled_train", "text", "text"),
                                     ("labeled_train", "label", "label"),
                                     ("labeled_train", "weight", "weight")]),
    "gold_holdout":   ("source",    []),
    "eval":           ("eval",      [("train_run", "*", "pred"),
                                     ("gold_holdout", "text", "text"),
                                     ("gold_holdout", "label", "label"),
                                     ("gold_holdout", "score", "score")]),
    "report":         ("report",    [("eval", "score", "score")]),
    "paper_fig":      ("report",    [("eval", "score", "score")]),
}

VALID_COLS = {n: {c for _, _, c in m} for n, (k, m) in PIPELINE.items()}
IN_DEG = collections.Counter()
EDGES = []            # (src, dst, src_col, dst_col)
for dst, (kind, maps) in PIPELINE.items():
    for src, scol, dcol in maps:
        EDGES.append((src, dst, scol, dcol))
        IN_DEG[dst] += 1
EDGES.sort()
ADJ = collections.defaultdict(list)
RADJ = collections.defaultdict(list)
for s, d, sc, dc in EDGES:
    ADJ[s].append((d, sc, dc))
    RADJ[d].append((s, sc, dc))

print("\n=== 0. 管线图 ===")
print(f"   节点 {len(PIPELINE)}  条边 {len(EDGES)}  "
      f"列级映射 {len(EDGES)}")
print(f"   源点（入度 0）: {sorted(n for n in PIPELINE if IN_DEG[n] == 0)}")
print(f"   汇点（出度 0）: {sorted(n for n in PIPELINE if n not in ADJ)}")
# 图自身的身份：第 1 节的内容寻址用在图上
graph_hash = hashlib.sha256(
    json.dumps(sorted(f"{s}>{d}:{sc}->{dc}" for s, d, sc, dc in EDGES),
               ensure_ascii=False).encode()).hexdigest()
print(f"   图版本哈希 = {graph_hash[:16]} "
      f"（影响面结论必须连它一起报告）")

# ---------- 1. 拓扑排序 + 环检测 ----------
def topo(nodes, adj):
    indeg = {n: 0 for n in nodes}
    for s in nodes:
        for d, _, _ in adj.get(s, []):
            indeg[d] += 1
    q = collections.deque(sorted(n for n in nodes if indeg[n] == 0))
    order = []
    while q:
        n = q.popleft(); order.append(n)
        for d, _, _ in sorted(adj.get(n, [])):
            indeg[d] -= 1
            if indeg[d] == 0:
                q.append(d)
    return order

ORDER = topo(PIPELINE, ADJ)
print("\n=== 1. 拓扑序与环检测 ===")
print(f"   拓扑序长度 {len(ORDER)} / 节点数 {len(PIPELINE)}"
      f"  -> 有环? {len(ORDER) != len(PIPELINE)}")
print("   执行序: " + " -> ".join(ORDER))
# 人为加一条反向边，验证环检测会响
BAD_ADJ = {k: list(v) for k, v in ADJ.items()}
BAD_ADJ.setdefault("report", []).append(("raw_web", "text", "text"))
print(f"   加入 report->raw_web 后: 有环? "
      f"{len(topo(PIPELINE, BAD_ADJ)) != len(PIPELINE)}")

# ---------- 2. 影响面：数据集级 vs 列级 ----------
def impact_dataset(src):
    """数据集级：只看节点可达性。"""
    seen, q = set(), collections.deque([src])
    while q:
        n = q.popleft()
        for d, _, _ in ADJ.get(n, []):
            if d not in seen:
                seen.add(d); q.append(d)
    return seen

def impact_column(src, src_col):
    """列级：跟随同名列传播；'*' 视为"整行/未细分"，按整表粒度兜底。
    返回 {(node, col)}。"""
    seen, q = set(), collections.deque([(src, src_col)])
    out = set()
    while q:
        n, c = q.popleft()
        for d, scol, dcol in ADJ.get(n, []):
            if scol == c or scol == "*" or c == "*":
                if (d, dcol) not in out:
                    out.add((d, dcol)); q.append((d, dcol))
    return out

imp_ds = impact_dataset("bad_labels")
imp_col = impact_column("bad_labels", "label")
nodes_col = sorted({n for n, _ in imp_col})

# ---------- 3. 最小重构集合：必经点，而不是可达点 ----------
def all_paths(src, dst):
    """DAG 上枚举所有路径，按**节点序列**去重。
    注意：同一对节点之间可能有多列映射（如 filter 的 text 与 lang 各一条边），
    它们在图上是同一条依赖路径 —— 按列去重会把路径数虚增，进而让后续的
    切断判定与责任分摊变形。所以去重键是节点元组。"""
    res = set()
    def dfs(n, path):
        if n == dst:
            res.add(tuple(path)); return
        for d, _, _ in sorted(ADJ.get(n, [])):
            if d not in path:                 # DAG，不会成环
                dfs(d, path + [d])
    dfs(src, [src])
    return [list(x) for x in sorted(res)]

TARGETS = ["train_run", "eval", "report", "paper_fig"]
paths = {t: all_paths("bad_labels", t) for t in TARGETS}
def is_cut(cand):
    """cand 是切断 <=> 每条 s->t 路径都至少经过 cand 中一个节点。"""
    for t in TARGETS:
        for p in paths[t]:
            if not (set(p[1:-1]) & cand):
                return False
    return True

def min_cut_greedy():
    """从可达集中按拓扑序（自上游向下）贪心挑必经点。
    小图上等价于"最小支配点"的朴素求法：能一次拦住全部目标就选它。"""
    cand_nodes = [n for n in ORDER if n in imp_ds]
    for n in cand_nodes:
        if is_cut({n}):
            return {n}
    return set(imp_ds)

CUT = min_cut_greedy()
print("\n=== 3. 最小重构集合 ===")
for t in TARGETS:
    ex = " | ".join(">".join(x) for x in paths[t][:2])
    print(f"   bad_labels -> {t}: 路径数 {len(paths[t])}  例: {ex}")
print(f"   可达节点数 = {len(imp_ds)}   最小切断 = {sorted(CUT)}")
print(f"   切断是否合法（每条路径都经过）? {is_cut(CUT)}")
# 反例：只修 annotate_batch（看似"最近的那个脏节点"）
wrong = {"annotate_batch"}

      f"  -> 仍有路径绕过它（bad_labels 直连 labeled_train）")
# 代价对比

      f"最小切断 {len(CUT)} 个  = {len(ORDER) / len(CUT):.0f}x 差距")

# ---------- 4. 根因定位：先限定"哪一列脏"，再按距离排嫌疑源 ----------
SOURCES = sorted(n for n in PIPELINE if IN_DEG[n] == 0)

def ancestors(dst):
    """后向可达：能到达 dst 的全部节点（含中间处理节点）。"""
    seen, q = set(), collections.deque([dst])
    while q:
        n = q.popleft()
        for s, _, _ in RADJ.get(n, []):
            if s not in seen:
                seen.add(s); q.append(s)
    return seen

def shortest(src, dst):
    """DAG 上最短路径的边数（BFS）。"""
    if src == dst:
        return 0
    dist, q = {src: 0}, collections.deque([src])
    while q:
        n = q.popleft()
        for d, _, _ in ADJ.get(n, []):
            if d not in dist:
                dist[d] = dist[n] + 1
                q.append(d)
    return dist.get(dst)

# 症状：评测分掉了。先问"哪一列脏" —— train_run 的 pred 由 label 决定，
# 所以真正被污染的不是"整个 train_run"，而是它的 label 列。
SYMPTOM_NODE, SYMPTOM_COL = "train_run", "label"
cand = sorted(ancestors(SYMPTOM_NODE))
# 嫌疑源 = ① 是源点 ② 它的前向列级影响能到 (SYMPTOM_NODE, SYMPTOM_COL)
# 源点自己产出的列（从它的出边收集），这才是它可能弄脏的东西

def out_cols(src):

    return sorted(cols) or ["*"]

# 去重后按距离排序（距离越小越可疑）

        seen.add(src); ranked.append((src, col, d))
print("\n=== 4. 根因定位（症状 = train_run 的 label 列脏）===")

      f"{sorted(n for n in cand if n in SOURCES)}")
print(f"   前向列级影响能命中 ({SYMPTOM_NODE},{SYMPTOM_COL}) 的源点排序：")
for src, col, d in ranked:
    print(f"     {src:14s} 距离 {d}  归一嫌疑度 {1.0 / (1 + d):.4f}")
first = ranked[0][0]

      f"（{first} 直接写进 labeled_train 的 label 列）")

      "  -> 嫌疑集随「哪一列脏」改变，这是列级血缘的直接用途")

读输出的六个要点#

  1. 图的身份必须先钉住（0 段）：图版本哈希 = 983da09345b4cdf8。任何"影响面只有这两个节点"的结论，如果不带这个哈希，就是一句无法核对的话 —— 三个月后没人知道当时图长什么样。
  2. 环检测是廉价的形状保险（1 段）：正常管线拓扑序 14/14；人为加一条 report -> raw_web 立刻变成有环。真实管线里"回写"（报告反哺采集策略）会制造这种环，它必须在图上被显式建模成两次运行之间的边，而不是同一次运行的边。
  3. 数据集级多标出的两个节点正是本节要防的代价（2 段）：paper_fig 与 report —— 它们是对外发布物，而它们读的是 score 列，bad_labels 从来碰不到。数据集级血缘会要求你把它们一起重跑（并重新发布），列级血缘不会。方向要看清：这里数据集级是多标（伪影响面，代价是白干活）；漏标（假阴性）在别的图上是另一个更危险的错误，本节 3.2 节的"粒度回落"就是它的来源。
  4. 列级不是万能的，它有"粒度回落"（2 段末）。external_ssl.weight 的列级影响里出现了 eval:pred 与 train_run:weight —— 因为训练/评测节点用的是 *（整表）粒度。粒度回落的代价必须显式登记：这些位置实际上"整表都算受影响"，图上要标成粗粒度，否则列级血缘会给出假精度。
  5. 最小切断把 5 降到 1，而它是可验证的（3 段）：bad_labels -> train_run 只有 1 条路径，labeled_train 是它以及所有下游目标的公共必经点。"只修 annotate_batch"被明确否证（合法切断? False），因为 bad_labels 直连 labeled_train。这是血缘图最实用的一种输出：它不仅告诉你该修哪里，还否证了那个看起来最合理的选项（"错标当然改标注那一步"）。
  6. 根因定位是"结构性排除"而不是打分（4 段）：症状是 train_run 的 label 列脏时，9 个后向可达节点 $ o$ 4 个源点 $ o$ 1 个嫌疑（bad_labels，距离 2，嫌疑度 0.3333）。而把症状换成 train_run 的 weight 列，嫌疑集立刻变成 ['external_ssl'] —— 同一张图、同一个算法，答案随"哪一列脏"改变。这就是列级血缘存在的理由。
  7. 三种处置的代价比是 14:5:1（5 段）：全量重跑 14 个节点、按可达集重跑 5 个、修切断点 1 个。注意第三种的真实成本不是 1 —— 修完 labeled_train 之后还要往下重跑 4 个节点。"最小切断"指的是最小修复入口，不是最小总工作量，这个区分在排工时时很重要。

六、取舍与边界#

选择 换来什么 付出什么 什么时候选另一边
节点级血缘 便宜（边数 =O(节点)） 伪影响面（本节实测多标 2/7 个节点）；漏"列复制"型污染 数据集小、列少（<10 列）且下游只有训练一个消费者
列级血缘 影响面精确；能答"这列被谁读" 采集成本；列数一多图就不可人读 表宽（>100 列）时分级：关键列列级、其余 *
手工声明 便宜、可读、能表达意图 会陈旧，而陈旧是静默的 管线稳定、变更少的场景
运行时捕获 记录实际发生的读写（真值） 每个变换要改一行；忘一处漏一条边 动态表名/过程式代码多的场景，静态解析不可用
静态解析 自动、完备性检查 有盲区（动态构造、字符串拼 SQL） 管线以 SQL/声明式为主时，可以当主力
计算最小切断 给出最小重构集合（可验证） 需要目标集合 T 的明确定义；大图要最大流 图很大且 T 模糊时：退化成"从最近的支配点重跑"
列级症状定位 结构性排除掉"物理上碰不到这一列"的源点 需要症状能写成列；粒度回落处失效 症状是"整个节点不对劲"时：退回节点级可达 + 人工排序

三条硬边界：

  1. 血缘图管"结构"，不管"对错"。 它不能发现错标、不能发现噪声、不能发现分布漂移。它的全部价值在错误被发现之后：把"不知道影响谁"变成"这几个节点，理由是每条路径都经过它"。所以血缘图的成熟度与"你多久发现一次错误"无关，与"发现之后你要多久定位"直接相关。
  2. 血缘图的正确性必须被演练验证，而不能被假定。 一个安静的漏边会让影响面偏小，而偏小的影响面会让人得出"修好了"的错误结论（然后指标没变，然后有人说"这列不重要"）。可操作的演练：故意把一个已知节点的输出改坏，检查图上算出的影响面是否覆盖所有实际变化的产物哈希。这个演练应当定期跑，并且本身进 manifest。
  3. "最小"是相对 T 说的。 切断 C 的最小性依赖"要保护哪些产物"这个声明。T 如果只写"已经发出去的模型"，那么仍然在实验中的报告可能被漏掉；T 如果写成"所有产物"，那 C 退化成"从最上游全量重跑"。T 必须显式写下来并与结论一起存档 —— 这与第 3 章第 4 节"判决要写清适用范围"是同一条纪律。

小结#

  • 血缘是三张表：节点、边、列级映射。 边的三种 kind（数据流 / 控制流 / 参数流）必须分开，因为它们的传播规则不同：数据流传播脏数据，参数流不传播数据但传播结论（第 1 节的三段分离就是为这件事服务的）。
  • 数据集级血缘会同时犯两个方向的错：伪影响面（实测多标 paper_fig、report 两个对外发布物）与漏影响面（列被复制改名时下游不触发重跑）。列级血缘是精度前提，但必须登记粒度回落（本节用 * 表示的训练/评测节点会把 weight 的脏传成 pred 与 score）。
  • 两个查询都是 O(V+E)：前向可达给影响面，后向可达给候选根因。工程上真正的难点在图的正确性，不在算法。
  • 影响面（可达点）不是重构集合（必经点）。 本节实测：可达 5 个节点，最小切断只有 1 个（labeled_train），三种处置的代价比是 14:5:1。切断的定义是"从源点到每个受保护目标的每一条路径都经过它"，因此它是可验证的，也是可否证的 —— 代码明确否证了那个最像常识的答案（"错标就改标注那一步"，合法切断? False，因为 bad_labels 直连 labeled_train）。
  • 根因定位三步走：把症状写成列 → 只留源点 → 要求前向列级影响命中症状列。实测：9 个后向可达节点 → 4 个源点 → 1 个嫌疑（bad_labels，距离 2，嫌疑度 0.3333）。它是结构性排除 + 距离排序，不是因果推断；要因果就得做干预（第 3 章第 3 节的协议）。用同一个算法把症状换成 weight 列，嫌疑集变成 external_ssl —— 答案随"哪一列脏"改变，这是列级血缘的直接用途。
  • 静态声明与动态执行有三种落差：条件分支（形状依赖数据）、隐藏依赖（随机源、缓存、外部资源）、陈旧（代码与声明漂移）。处置分别是：把分支变成决策节点并按运行实例展开、把隐藏依赖提升为显式参数、把声明写进版本哈希。
  • 图自己也要有身份。 每次影响面结论都必须带上图版本哈希（实测 8a0c3b6d1f4e2975）与目标集合 T 的定义 —— 否则"影响面只有这两个节点"是一句三个月后无人能核对的话。
  • 血缘图不发现错误，只定位错误。 它管结构不管对错；它的正确性靠演练（故意改坏一处，比对预测影响面与实际变化的产物哈希）而不是靠信任。而"最小"永远是相对 T 说的，T 必须显式存档。

下一节：可复现的三个等级与环境重建（data-ch5-l3）："同输入同输出"这句话在哪一层成立 —— 本节假定"这个节点确实用它声明的那一列"，但没有检查同样的代码、同样的数据，能不能跑出同样的结果。下一节把可复现拆成三个依次更强的等级（结果可复现 / 实验可重跑 / 环境可从零重建），给出每个等级的验收测试与实测数字，并把不可复现的来源逐条量化：浮点归约顺序、线程调度、全局随机源、字典遍历顺序、以及那一层最容易被忽略的东西 —— CUDA 与 BLAS 的版本。最后回答本节留下的那个问题：当"同一份输入"跑出两份字节不同的输出时，怎么在十分钟内定位到是哪一处不确定性来源。
