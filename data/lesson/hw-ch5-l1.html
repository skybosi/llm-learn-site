权重的显存占用#

一张 GPU 能不能跑起某个模型，第一道门槛就是"权重装不装得下"。权重是模型学到的参数本身，推理时它们要常驻显存，从头到尾占着位置不动。学完本课，你应当能手算出任意模型在任意精度下权重要占多少显存，并判断它能否装进一张给定容量的卡。

一、概念讲解#

1. 权重就是参数，参数就是数#

神经网络里所有需要学习的数字统称参数（parameter），在推理场景下通常就叫权重（weight）。一个 Transformer 大模型里，权重集中在几个大矩阵上：词嵌入表、每一层的注意力投影（Q/K/V/O）、前馈网络的升维/降维矩阵、输出层的分类头，等等。模型"有多大"，通常就用参数量来描述，单位是 B（Billion，十亿），例如 "7B" 就是约 70 亿个参数。

2. 精度决定每个参数占几字节#

权重显存的大小只由两件事决定：有多少个参数，以及每个参数用几个字节存。字节数由数值精度决定：

精度 每参数字节数 说明
FP32 4 单精度浮点，训练和部分推理的"标准"精度
FP16 / BF16 2 半精度，推理主流，显存减半
INT8 1 8 位整数量化，再减半
INT4 0.5 4 位量化，权重缩到原来的 1/8

于是有核心公式：

权重显存=参数量×每参数字节数

一个非常实用的经验法则：每 10 亿（1B）参数在 FP16 下约占 2 GiB，FP32 下约占 4 GiB。7B 模型在 FP16 下大约 14 GiB，就是这么来的。

3. 权重是"一次性"开销，与上下文无关#

这是权重的关键性质：它跟批量大小（batch）和上下文长度（sequence length）都无关。无论你一次让模型回答 1 个词还是 1 万个词，权重占用的显存都是固定的。真正随上下文变化而膨胀的是下一课要讲的 KV cache。所以可以这样切分：权重是"入场费"，先交掉这部分，剩下的显存才拿去做真正的计算。

4. 量化：用精度换空间#

既然字节数由精度决定，最直接的省显存手段就是量化（quantization）——把 FP16 权重转成 INT8 或 INT4。INT8 让权重减半，INT4 缩到 1/4。代价是精度损失，可能影响回答质量；但对很多场景，收益（能让模型塞进更小的卡）远大于损失。注意：量化主要压缩的是权重这部分，而 KV cache、激活往往仍保持较高精度，这个差别在后续课程里会反复出现。

二、可运行示例#

下面用纯 Python 手算几款常见模型的权重显存，并判断它们能不能装进不同容量的卡。

# -*- coding: utf-8 -*-
# 权重显存 = 参数量 × 每参数字节数，全部手算，不依赖任何框架。

def weight_memory_gb(num_params, bytes_per_param):
    """计算权重占用显存（GiB）。

    参数量 num_params 的单位是"个"（例如 7B = 7e9），
    bytes_per_param 是每个参数的字节数（FP32=4、FP16=2、INT8=1、INT4=0.5）。
    """
    total_bytes = num_params * bytes_per_param
    return total_bytes / (1024 ** 3)   # 除以 1024^3 换算成 GiB

# 各精度的每参数字节数
PRECISION_BYTES = {
    "FP32": 4,
    "FP16": 2,
    "BF16": 2,
    "INT8": 1,
    "INT4": 0.5,
}

# 常见开源模型的大致参数量（个）
models = {
    "LLaMA-2 7B": 6.74e9,
    "Mistral 7B": 7.30e9,
    "LLaMA-3 8B": 8.00e9,
    "LLaMA-2 13B": 13.0e9,
    "LLaMA-2 70B": 69.0e9,
    "GPT-3 175B": 175.0e9,
}

print("模型权重显存占用（GiB）：")
print(f"{'模型':<14} {'FP32':>7} {'FP16':>7} {'INT8':>7} {'INT4':>7}")
for name, n in models.items():
    row = [f"{weight_memory_gb(n, PRECISION_BYTES[p]):>7.1f}"
           for p in ("FP32", "FP16", "INT8", "INT4")]
    print(f"{name:<14} {' '.join(row)}")

# 判断：权重能否装进给定显存的卡？这里给"框架开销"留 2 GiB 余量。
def can_fit_weights(model_fp16_gb, vram_gb, reserve_gb=2.0):
    """权重 + 预留开销 <= 显存容量，才算装得下。"""
    return model_fp16_gb + reserve_gb <= vram_gb

print("\nFP16 权重能否装进常见卡（预留 2 GiB 开销）：")
cards = {"RTX 4090": 24, "A100 40G": 40, "A100 80G": 80, "H100 80G": 80}
for name, n in models.items():
    gb = weight_memory_gb(n, PRECISION_BYTES["FP16"])
    fits = [c for c, v in cards.items() if can_fit_weights(gb, v)]
    print(f"  {name:<14} FP16={gb:>6.1f} GiB -> 能装进：{', '.join(fits) if fits else '（无，需量化或分卡）'}")

运行这段代码，你会得到一张清晰的对照表：7B 模型在 FP16 下约 13～16 GiB，一张 24 GiB 的消费级卡能装下；而 70B 模型约 140 GiB，单卡根本装不下，必须量化、或用多卡做张量并行、或换更大显存的数据中心卡。

三、练习#

  1. 手算：一个 13B 模型，用 INT8 量化，权重显存是多少 GiB？用 INT4 呢？（用上面的经验法则心算，再写代码验证）
  2. 补精度：PRECISION_BYTES 里没有 FP8。若 FP8 每参数占 1 字节，计算 70B 模型在 FP8 下的权重显存，并与 INT8 对比，说说为什么两者数值一样。
  3. 余量：把 reserve_gb 从 2.0 改成 0 和 4.0，观察 can_fit_weights 的判断结果有哪些变化，说明"预留开销"为什么不能省略。
  4. 加模型：往 models 里加一个 72B 的 Qwen 模型和 110B 的模型，重新跑一遍，看看哪些卡"出局"了。
  5. 思考：为什么权重显存与 batch 和上下文长度无关？如果下一课讲的 KV cache 随上下文线性增长，那么当上下文非常长时，权重和 KV cache 谁可能成为更大的显存开销？
