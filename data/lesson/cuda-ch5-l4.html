多 GPU 视角：从单卡内存模型到集合通信的前置直觉#

单卡上你已经建立三样东西：作用域、内存序、"搬运是一笔要算清楚的账"。从 1 张卡到 8 张，三样全部保留，只是参数恶化一到两个数量级：作用域要放大到 system，搬运要过 NVLink 或 PCIe，而"一次交换"的固定成本开始和带宽一样重要。本课只补"从 kernel 作者视角看多卡"这一层。

一、概念讲解#

1. 单卡的那套规则怎么延伸到多卡#

第 2 课作用域表里的 cuda::thread_scope_system 覆盖"整机，含 CPU 与其它 GPU"。官方要求：跨设备并发的线程要建立顺序，必须用 system 作用域的同步操作——第 2 课的 litmus test 在多卡上仍成立，只需把作用域那一格换成 system。

能否直接解引用另一张卡上的指针，取决于四件事：

机制 入口 要点
peer 访问可用性 cudaDeviceCanAccessPeer(&ok, dev, peer) 是否支持由 PCIe/NVLink 拓扑决定
开启 peer 访问 cudaDeviceEnablePeerAccess(peer, 0) 非 NVSwitch 系统上每设备最多 8 条 peer 连接
跨设备拷贝 cudaMemcpyPeer / cudaMemcpyPeerAsync 未开启 peer 时会被迫绕道主机（慢得多）
坑：cudaDeviceEnablePeerAccess() 全局生效，会给该 peer 上后续所有分配加开销；更可控的做法是用 VMM API 只对需要的区域声明。

2. 把"搬运账"升级成 α-β 模型#

第 4 章算字节数，多卡要算时间。一次通信的成本是：

T=α+βs​

s 是消息字节数，α 是固定延迟项，β 是带宽项，取法就是 ping-pong 实测：小消息测到 α，大消息的斜率是 1/β。模型立刻给出判断：小消息永远被 α 支配。用示例参数（P=8、α=5 μs、β≈300 GB/s）算 ring AllReduce：

消息大小 总时间 纯带宽项 延迟占比
4 KiB 70.2 μs 0.19 μs 99.7%
256 KiB 82.2 μs 12.23 μs 85.1%
16 MiB 852.9 μs 782.94 μs 8.2%

"梯度分桶"（把小梯度合成大消息再发）的收益就在这一列：不改变带宽项，但把次数降下来，把 α 摊薄。

3. ring AllReduce：为什么是 2(p-1) 步#

集合通信里最值得从 kernel 层理解的算法是 ring AllReduce：

  1. reduce-scatter（p−1 步）：rank r 只持有全局 chunk (r+1)modp；第 k 步从左邻居收到 chunk (r−k−1)modp 的部分和并累加，同时把 chunk (r−k)modp 的部分和发给右邻居。走完 p−1 步，rank r 手里有一个完整 chunk。
  2. allgather（p−1 步）：把这些完整 chunk 沿同一个环传一圈，每步发一个、收一个。

合计 2(p−1) 步、每步每 rank 只发 s 字节——这是 ring 在带宽账上最优的原因（总传输量 2s(p−1)/p<2s），代价是延迟项要付 2(p−1) 次。示例代码用 8 个 numpy 向量跑遍全部 rank：14 步、结果与参考求和一致。

4. 时间账：什么时候换算法#

沿用 2(p−1)(α+s/β)，对 100 MiB 梯度算三种情形（同一规模的通信时间）：

场景 α β 时间
同机 8 卡，PCIe 级链路 5 μs ≈25 GB/s 58.79 ms
同机 8 卡，NVLink 级链路 5 μs ≈300 GB/s 4.96 ms
4 节点 × 2 卡（节点内快、跨节点 NIC 25 GB/s） 5 μs 两级 12.80 ms

（α、β 是示例参数，请用自己硬件的实测值替换：nvidia-smi topo -m 看拓扑，nccl-tests 量带宽与延迟。）

三条结论：

  • 链路带宽决定量级：同一算法与规模，25 GB/s 与 300 GB/s 差一个数量级。
  • 跨节点就换算法层次：先节点内合并、再让节点代表跨节点，4 节点时从 58.79 ms 降到 12.80 ms；涨到 8 节点又回到 58.79 ms——瓶颈转到 NIC。
  • 带宽最优 ≠ 最快：小消息下 ring 的 2(p−1) 次 α 是纯亏，树形/二分只要 O(logp) 步。用 2(p−1)α≈2log2​p⋅(α+s/β) 找交叉点，p=8 时在几十到几百 KiB 量级。

5. 从两个点反解 α 与 β#

α、β 不用查表，两个点就能解：由 t1​=α+s1​/β、t2​=α+s2​/β 相减得

β=t2​−t1​s2​−s1​​,α=t1​−βs1​​

这正是 nccl-tests 输出表格的读法；示例代码先用模型造数据、再反解回参数。

6. 常见坑#

  • 用 device 作用域等另一张卡：作用域不够，行为未定义。
  • 假设 peer 访问一定可用：不支持时 cudaMemcpyPeer 退回经主机中转，带宽掉到主机内存量级。
  • 通信与计算串行排：不重叠时总时间是两者之和。
  • 拿 ring 到处用：小消息下延迟主导，树形等步数更少的算法更快。
  • 用"理论带宽"当预期：有效带宽按第 3 课口径核对，实测通常低于峰值。

7. 这一课到哪里为止#

本课只到"前置直觉"：多卡一致性、访问路径、把通信算成一笔时间账。算法层的完整推导（三种 AllReduce 的步数、ReduceScatter/AllGather 角色、拓扑感知、NCCL 调参）在分布式训练系统课第 1–4 章。

二、可运行代码示例#

第一段纯 Python/numpy（无 GPU）：把 8 个 rank 抄成 8 个向量本地跑一遍 ring AllReduce，再用 α-β 模型算时间账；第二段给出多卡一致性的最小 CUDA 写法。

# ===== 示例 1：无 GPU 也能验证的 ring AllReduce（8 个 rank = 8 个 numpy 向量） =====
import numpy as np

def ring_allreduce(inputs):
    """标准 ring AllReduce：rank r 初始只持有全局 chunk (r+1)%P。
    reduce-scatter P-1 步：第 k 步收到全局 chunk (r-k-1)%P 并累加；
    allgather P-1 步：把已完整的 chunk 沿环传一圈。返回 (各 rank 结果, 步数)。"""
    P = len(inputs); n = inputs[0].size
    assert n % P == 0
    b = [v.reshape(P, n // P).copy() for v in inputs]
    for k in range(P - 1):                       # reduce-scatter
        nxt = [c.copy() for c in b]
        for r in range(P):
            c = (r - k - 1) % P
            nxt[r][c] = b[r][c] + b[(r - 1) % P][c]
        b = nxt
    for k in range(P - 1):                       # allgather
        nxt = [c.copy() for c in b]
        for r in range(P):
            c = (r - k) % P
            nxt[r][c] = b[(r - 1) % P][c]
        b = nxt
    return [c.reshape(n) for c in b], 2 * (P - 1)

P = 8
inputs = [np.arange(8192, dtype=np.float64) + r for r in range(P)]
outs, steps = ring_allreduce(inputs)
expect = np.sum(inputs, axis=0)
err = max(float(np.abs(o - expect).max()) for o in outs)
print(f"ring AllReduce：{P} 个 rank，每个 rank 一份 8192 元素（切成 {P} 块）")
print(f"  通信步数 = {steps}（公式 2×(P-1) = {2*(P-1)}）")
print(f"  8 个 rank 的结果与逐元素参考求和的最大偏差 = {err:.1e}")

# ===== 示例 2：α-β 模型 —— 通信时间随消息大小与链路带宽的变化 =====
def ring_time(nbytes, P, alpha_us, beta_gbps):
    """ring AllReduce：2(P-1) 步，每步 α + s/β。返回微秒。"""
    return 2 * (P - 1) * (alpha_us + nbytes / (beta_gbps * 1e9) * 1e6)

def two_level_time(nbytes, P, alpha_us, beta_gbps, nodes, nic_gbps):
    """两级 ring：节点内先在快链路上把同号 chunk 合并，再让节点代表走 NIC 跨节点。"""
    per_node = P // nodes
    inner = 2 * (per_node - 1) * (alpha_us + (nbytes / nodes) / (beta_gbps * 1e9) * 1e6)
    outer = 2 * (nodes - 1) * (alpha_us + (nbytes / per_node) / (nic_gbps * 1e9) * 1e6)
    return inner + outer

grad = 100 * 2**20          # 100 MiB 梯度
print("\n100 MiB AllReduce（P=8，α=5 μs）：")
for beta, tag in ((25.0, "β≈25 GB/s  PCIe 级"), (300.0, "β≈300 GB/s NVLink 级")):
    print(f"  {tag:<22} 单层 ring = {ring_time(grad,8,5.0,beta)/1e3:7.2f} ms")
print("  跨节点（节点内 β≈300 GB/s、跨节点 NIC β≈25 GB/s）：")
for nodes in (2, 4, 8):
    t = two_level_time(grad, 8, 5.0, 300.0, nodes, 25.0)
    print(f"    {nodes} 个节点  两级 ring = {t/1e3:7.2f} ms")

print("\n小消息时延迟项主导（P=8，α=5 μs，β=300 GB/s）：")
for kb in (4, 256, 16384):
    s = kb * 1024
    t = ring_time(s, 8, 5.0, 300.0)
    bw = 2 * 7 * s / (300e9) * 1e6
    print(f"  {kb:>6} KiB：总 {t:>8.1f} μs  纯带宽项 {bw:>7.2f} μs  延迟占比 {(t-bw)/t:6.1%}")

# ===== 示例 3：两个数据点反解 α 与 β（拿到实测数据后的第一步） =====
def fit_alpha_beta(sizes_bytes, times_us):
    """由 t = α + s/β：两点相减得 β = (s2-s1)/(t2-t1)，回代得 α。"""
    (s1, t1), (s2, t2) = list(zip(sizes_bytes, times_us))
    beta = (s2 - s1) / ((t2 - t1) * 1e-6) / 1e9
    return t1 - s1 / (beta * 1e9) * 1e6, beta

print("\n反解流程自检（先用模型造数据，再反解回参数）：")
for alpha, beta in ((5.0, 300.0), (3.0, 25.0)):
    sizes = [1 << 20, 64 << 20]
    times = [alpha + s / (beta * 1e9) * 1e6 for s in sizes]
    a, b = fit_alpha_beta(sizes, times)
    print(f"  模型 α={alpha:>4.1f} μs, β={beta:>5.1f} GB/s → 反解 α={a:.3f} μs, β={b:.3f} GB/s")

下面是把多卡一致性写对的最小 CUDA 片段（跨设备必须 system 作用域）：

#include <cuda/atomic>

// 设备 0 上：写数据，再用 system 作用域的 release 发布标志
__global__ void publishFrom0(int* d_data, cuda::atomic<int, cuda::thread_scope_system>* flag) {
    if (threadIdx.x == 0) {
        *d_data = 42;                                        // 数据写在设备 0 的内存里
        flag->store(1, cuda::memory_order_release);           // system 作用域：跨设备可见
    }
}

// 设备 1 上（需先 cudaDeviceEnablePeerAccess(0, 0)）：acquire 后再读
__global__ void consumeOn1(const int* d_data,
                           cuda::atomic<int, cuda::thread_scope_system>* flag, int* ok) {
    while (flag->load(cuda::memory_order_acquire) != 1) { }   // 作用域必须匹配
    if (threadIdx.x == 0) *ok = (*d_data == 42);
}

// 主机侧：查询可用性并开启 peer 访问（非 NVSwitch 系统每设备最多 8 条连接）
int ok = 0;
cudaDeviceCanAccessPeer(&ok, 1, 0);
if (ok) { cudaSetDevice(1); cudaDeviceEnablePeerAccess(0, 0); }
