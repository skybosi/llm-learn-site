通信下界与"为什么不能更快"的直觉#

把 AllReduce 从 8 卡扩到 64 卡，通信时间不会停在原地，也不会线性变差——它总撞在一堵墙上。提前算出这堵墙在哪，就等于拿到了判断依据：实测远高于下界，说明还有优化空间；已经贴着下界，再调调度就是白费力气。本课把轮数下界、带宽下界与端到端下界算清楚，并指明这些下界在什么模型下成立、又被什么硬件打破。

一、概念讲解#

1. 先说清模型，再谈下界#

下界只在自己的模型里成立，讨论前必须固定三件事：

模型要素 两种典型取值 影响
每节点每轮能收几条消息 1 条（全双工端口）／只能与一个伙伴交换（半双工） 每轮"已知信息"能涨几倍
网络设备能否参与归约 不能（纯点对点）／能（交换机内归约） 中转字节是否被重复搬运
消息能否多播 不能／能 全网流量与每节点接收量的差距

所以下界永远是"在某某模型下"的结论。本课先给纯点对点模型的下界（它解释了 ring 的地位），再看硬件怎么打破它。

2. 轮数下界：信息每轮最多翻一倍#

把每个节点"已掌握哪些节点的贡献"记成集合：第 0 轮是 {自己}，大小 1。若一轮里最多接收一条消息，而该消息最多携带发送方上一轮的全部知识，则第 k 轮集合大小

Mk​≤2Mk−1​,Mk​≤2k⟹k≥⌈log2​p⌉

这就是轮数下界：延迟项至少要付 ⌈log2​p⌉ 次（ring 要付 2(p−1) 次，第 2 章会看到这正是它小消息吃亏的原因）。它紧不紧取决于模型：示例代码穷举了所有通信方案，全双工下 p=2,3,4 的最少轮数是 1、2、2，正好等于下界；换成半双工，p=3 要 3 轮、p=5 要 4 轮，下界不再紧。引用下界必须连同模型一起报。

3. 带宽下界：每个节点必须收到多少字节#

AllReduce 结束时每个节点都持有 S 字节结果，而它本地只有 S/p，剩下

pp−1​S （每节点）,(p−1)S （全网接收量合计）

必须来自外部。这是信息量下界，与算法无关：结果不可压缩。ring 的实际账本是每节点 2pp−1​S、全网 2(p−1)S：

p 每节点接收 全网接收量 下界 (p−1)S ring / 下界
2 1024.0 MiB 2.00 GiB 1.00 GiB 2.000×
8 1792.0 MiB 14.00 GiB 7.00 GiB 2.000×
64 2016.0 MiB 126.00 GiB 63.00 GiB 2.000×
4096 2047.5 MiB 8190.00 GiB 4095.00 GiB 2.000×

（S=1 GiB。）比值恒为 2、与 p 无关——这就是"ring 是 bandwidth-optimal"的准确含义：在纯点对点模型下最多差 2 倍，而不是"已经最优"。

4. 多出来的 1 倍是谁，谁能让它消失#

多出的一倍来自 reduce-scatter 阶段的中转：部分和被中间节点收下、累加、再转发，同一份数据投递了两遍。要消掉它，得让归约发生在数据不必落在 GPU 上的地方：

  • 交换机内归约：NVSwitch 的 NVLink SHARP（NCCL 里由 NCCL_NVLS_ENABLE 控制）与 InfiniBand SHARP，交换芯片求和后再交付 GPU，省掉 reduce-scatter 那一遍投递。
  • 多播／广播：一份数据只发一次，由网络复制给多个目的端。
  • 提高每轮能合并的消息数：一轮内并行收 m 条，等价于把"每轮翻倍"改成"每轮乘 (m+1)"，轮数下界随之下降。这正是 NCCL 把一个集合通信切成多个 channel 并发收发的动机之一。

同时认清口径陷阱：nccl-tests 的 busbw 已按算法结构折算（AllReduce：busbw=algbw×p2(p−1)​），因而可能"超过"链路峰值带宽；拿它与物理带宽直接比较是常见误判。

5. 端到端下界：重叠决定天花板#

一个训练步的时间有两条下界：

Tstep​≥max(T计算​,T通信​) (完全重叠),Tstep​≥T计算​+T通信​ (不重叠)

真实系统落在两者之间。若通信占串行总时间的比例是 f，即使通信被完全藏起来，加速上限也只有 1/(1−f)——Amdahl 的通信版。f=16.7% 对应上限 1.20×：这就是"通信占两成、优化它最多快 20%"的严格含义，也解释了为什么工程上要把通信塞进反向传播的空隙（梯度分桶、多流、分块流水，第 4 章展开）。

6. 常见坑#

  • 把下界当当前性能：贴着下界就该换维度（换拓扑、换精度、换并行策略），而不是继续调调度。
  • 跨模型引用下界：半双工的轮数结论套到全双工，或把点对点下界套到带交换机内归约的机器上。
  • 只算通信不算等待：同步点上的 straggler（最慢那张卡）会让实测高于下界——第 7 章排障会再遇到。

7. 本章小结#

三课合起来是一套提问顺序：work 多少、depth 多长（第 1 课）→ 通信付几次 α、搬多少字节（第 2 课）→ 这两项的下界在哪、模型假设是什么（第 3 课）。下一章把同一套账套到具体算法上：ring、tree、recursive-doubling 的步数与通信量。

二、可运行代码示例#

三段纯 Python（标准库）：穷举所有通信方案求轮数下界的可达性、构造"偏移翻倍"方案达到 ⌈log2​p⌉ 轮、ring 带宽账本与下界的比值。

# ===== 示例 1：轮数下界与它何时可达 =====
import math

def matchings(nodes):
    """半双工：一轮只能和一个伙伴双向交换（其余节点闲置）。"""
    if not nodes:
        yield []
        return
    first, rest = nodes[0], nodes[1:]
    for m in matchings(rest):
        yield m
    for i, other in enumerate(rest):
        for m in matchings(rest[:i] + rest[i + 1:]):
            yield [(first, other)] + m

def injections(p):
    """全双工：一轮里每个节点最多发一条、最多收一条（收方互不重复）。"""
    def rec(i, used_src, pairs):
        if i == p:
            yield list(pairs); return
        for _ in rec(i + 1, used_src, pairs):
            yield _                              # i 不参与收发
        for src in range(p):
            if src in used_src or src == i:
                continue
            pairs.append((i, src))               # i 收 src 的贡献
            for _ in rec(i + 1, used_src | {src}, pairs):
                yield _
            pairs.pop()
    yield from rec(0, set(), [])

def min_rounds(p, plan):
    """BFS：状态 = 每个节点已合并了哪些节点的贡献；目标 = 人人知道全部 p 份。"""
    start = tuple(frozenset([i]) for i in range(p))
    goal = frozenset(range(p))
    frontier, seen, rounds = {start}, {start}, 0
    while frontier:
        rounds += 1
        nxt = set()
        for state in frontier:
            for pairs in plan:
                new = list(state)
                for dst, src in pairs:
                    new[dst] = new[dst] | state[src]
                t = tuple(new)
                if t not in seen:
                    seen.add(t); nxt.add(t)
        for t in nxt:
            if all(s == goal for s in t):
                return rounds
        frontier = nxt
    return -1

def hd_plan(p):
    """半双工：一轮里每对伙伴双向交换，节点只能属于一对。"""
    plans = []
    for m in matchings(list(range(p))):
        pairs = []
        for (u, v) in m:
            pairs += [(u, v), (v, u)]
        plans.append(pairs)
    return plans

print("全双工（每轮每节点最多发一条、收一条）的穷举最少轮数：")
for p in (2, 3, 4):
    fd = min_rounds(p, list(injections(p)))
    print(f"  p={p}: {fd} 轮（计数下界 ⌈log2 p⌉ = {math.ceil(math.log2(p))}）")
print("半双工（一轮只能和同一个伙伴双向交换）的穷举最少轮数：")
for p in (2, 3, 4, 5):
    hd = min_rounds(p, hd_plan(p))
    print(f"  p={p}: {hd} 轮（计数下界 ⌈log2 p⌉ = {math.ceil(math.log2(p))}）")

# ===== 示例 2：偏移 1,2,4,… 的交换方案，k = ⌈log2 p⌉ 轮后人人知全局 =====
def doubling_allreduce(p):
    know = [frozenset([i]) for i in range(p)]
    rounds = math.ceil(math.log2(p))
    for j in range(rounds):
        off = 1 << j
        nxt = [know[i] | know[(i - off) % p] for i in range(p)]   # 每人收左邻居 off 距离的贡献
        know = nxt
    return rounds, all(len(s) == p for s in know)

print("\np        轮数（偏移 1,2,4,…）   k = ⌈log2 p⌉   人人知全局")
for p in (2, 3, 5, 8, 33, 1024):
    r, ok = doubling_allreduce(p)
    print(f"{p:<8} {r:<24} {math.ceil(math.log2(p)):<14} {ok}")

# ===== 示例 3：带宽账本 —— ring 的全网接收量 vs 信息论下界 =====
def ring_receive_bytes_per_node(S, P):
    """ring AllReduce：reduce-scatter 与 allgather 各 P-1 步，每步收 S/P 字节。"""
    return 2 * (P - 1) * (S // P)

print("\nS = 1 GiB 梯度，ring 的 2(P-1)·S/P 记账：")
S = 1 << 30
print("P        每节点接收      全网接收总量      下界 (P-1)·S     ring / 下界")
for P in (2, 8, 64, 512, 4096):
    per = ring_receive_bytes_per_node(S, P)
    total, lower = per * P, (P - 1) * S
    print(f"{P:<8} {per / 2**20:>10.1f} MiB {total / 2**30:>15.2f} GiB {lower / 2**30:>15.2f} GiB {total / lower:>12.3f}×")

# ===== 示例 4：通信与计算重叠与否，决定端到端时间 =====
t_compute, t_comm = 100.0, 20.0
total_serial = t_compute + t_comm
f = t_comm / total_serial
print(f"\n单步时间（计算 {t_compute:.0f} ms、通信 {t_comm:.0f} ms）：")
print(f"  通信在串行总时间中的占比 f = {f:.1%} → 完全重叠的加速上限 1/(1-f) = {1 / (1 - f):.2f}×")
for tag, t in (("不重叠（串行）", total_serial), ("一半重叠", t_compute + t_comm / 2), ("完全重叠", max(t_compute, t_comm))):
    print(f"  {tag:<14} {t:6.1f} ms   相对串行加速 {total_serial / t:4.2f}×")

三、练习#

  1. 实现：给示例 2 加参数 m（每轮并行收 m 条消息），把轮数改成"每轮乘 (m+1)"，对 p=1024、m=1,2,4 打印所需轮数；说明它在 NCCL 里对应什么。
  2. 解释：为什么每节点接收量下界 pp−1​S 与算法无关？用"结果不可压缩""本地只有 S/p"两句话论证，再说明交换机内归约为何能逼近它、而 ring 固定在 2 倍。
  3. 对比/验证：取 S=128 MiB、P=8/16/64 验证"ring / 下界 = 2.000"不随 P、S 变化；再用 α=5 μs、β=25 GB/s 算 P=64、S=128 MiB 时 ring 的通信时间（2(P−1) 步），与纯带宽项比较，给出延迟项占比。
  4. 思考：一个训练步计算 100 ms、通信 20 ms，其中 8 ms 落在同步点上无法重叠。端到端时间多少？把可重叠部分换算成"藏住它需要多大 β"，你会先动哪一环？
