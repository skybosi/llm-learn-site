全参数微调原理#

全参数微调（Full Fine-Tuning）是最"朴素"的微调方式：把预训练权重当作起点，用任务数据继续做梯度下降，更新模型里的每一个参数。本章先讲清它背后的计算原理和成本来源，后面两课再讲数据准备与训练配置。

一、概念讲解#

1. 全参数微调到底改了什么#

预训练结束后，模型有了一组权重 θ₀。全参数微调做的事情是：

θ_t+1 = θ_t - η · ∇L(θ_t)

以 θ₀ 为初始值，在任务数据上最小化损失 L（对因果语言模型来说，通常仍是下一个 token 的交叉熵损失），逐步把所有权重 θ 更新到 θ*。这里"全参数"的含义是：梯度 ∇L 会回传到模型的每一个可训练参数上，包括注意力层的 Q/K/V/O 投影、FFN 的两层、词嵌入和输出层等。

它和预训练的唯一区别在于起点不同、数据不同、步数不同：预训练从随机初始化出发、跑海量通用语料；微调从预训练权重出发、跑少量任务数据。因此微调通常能用很小的学习率和很少的步数就收敛。

2. 损失函数与梯度回传#

对"指令微调"这类典型的全参数微调任务，每个样本被组织成一段对话文本，模型的目标仍然是最大化目标回答部分 token 的概率。损失函数写作：

L = -Σ_{t} log P(y_t | y_<t, x)     （只对"回答"部分的 token 求和）

实现上，通常对 prompt 部分的标签位置做掩码（把 label 设成 -100 忽略掉），只计算回答部分的交叉熵。这样模型学到的是"给定指令，如何生成期望回答"，而不是浪费算力去预测指令本身。

反向传播时，梯度从损失出发，沿计算图一路回传到嵌入层。所有参数的梯度都要被计算、累积、再用于更新——这正是全参数微调算力和显存开销的根本来源。

3. 优化器：AdamW 与显存开销#

全参数微调几乎都用 AdamW（带权重衰减的 Adam）。它的显存消耗比"只存权重"大得多，因为每个参数还要额外存两份状态：

内容 数量级（以 bf16 权重、参数量 P 计）
模型权重 2P 字节（bf16）
梯度 2P 字节
Adam 一阶动量 m 2P 字节（通常 fp32，4P）
Adam 二阶动量 v 2P 字节（通常 fp32，4P）

一个粗略经验值是：全参数微调的显存需求大约是推理的 4–6 倍（权重 + 梯度 + 优化器状态，还要算上激活值）。这也解释了为什么 70 亿参数的模型，用 bf16 全参数微调时，即便激活值做了检查点优化，通常也需要多张 80GB 显卡或一张 H100 级别的卡——这也是第 3 章 LoRA 要解决的痛点。

4. 学习率与调度#

全参数微调对学习率很敏感：

  • 学习率要远小于预训练：预训练可能用 1e-4 量级，微调通常用 1e-5 ~ 5e-5，因为模型已经"接近好位置"，步子太大会破坏已有能力。
  • Warmup（预热）：训练初期用极小学习率线性爬升，避免一开始梯度方向不稳定时"冲出去"。
  • 衰减（Decay）：中后期用余弦或线性衰减把学习率降下来，帮助收敛到更稳的极小值。

5. 灾难性遗忘#

全参数微调最大的风险是灾难性遗忘（catastrophic forgetting）：因为所有参数都在改，如果任务数据分布太窄、或学习率太大、或训练步数过多，模型会"过度贴合"任务数据，丢掉预训练阶段学到的通用能力（常识、推理、多语言等）。

常见缓解手段：控制学习率和步数、混合通用数据（数据配比）、使用 LoRA 这类只改少量参数的方法（对原权重的扰动更小）。这是第 3 章 LoRA 受欢迎的另一个原因。

一句话总结：全参数微调 = 从预训练权重出发，用任务数据对所有参数做小步长的梯度下降；它效果好但显存/算力成本高，且有过拟合和遗忘风险。

二、可运行代码示例#

下面用 Hugging Face Trainer 走一遍极简的全参数微调：在一个玩具数据集上，把一个小型因果模型的所有参数都纳入训练。

from transformers import (
    AutoTokenizer,
    AutoModelForCausalLM,
    Trainer,
    TrainingArguments,
)
from datasets import Dataset

# 1) 加载一个小型基座模型，全参数微调的起点
model_name = "Qwen/Qwen2.5-0.5B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
# pad_token 需要显式设置，避免右对齐时出错
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

model = AutoModelForCausalLM.from_pretrained(model_name)

# 2) 构造一个极小的指令微调玩具数据（仅演示流程）
raw = [
    {"instruction": "把下面的句子翻译成英文", "input": "今天天气很好。", "output": "The weather is nice today."},
    {"instruction": "把下面的句子翻译成英文", "input": "我喜欢学习编程。", "output": "I like learning to program."},
    {"instruction": "总结下面这句话", "input": "模型在大量文本上预训练后，再用任务数据微调。", "output": "预训练后再微调。"},
]

def format_and_tokenize(example):
    """拼成 chat 模板文本，并对 prompt 部分做 label 掩码"""
    messages = [
        {"role": "user", "content": example["instruction"] + "\n" + example["input"]},
        {"role": "assistant", "content": example["output"]},
    ]
    prompt_text = tokenizer.apply_chat_template(
        [messages[0]], tokenize=False, add_generation_prompt=True
    )
    full_text = tokenizer.apply_chat_template(messages, tokenize=False)

    prompt_ids = tokenizer(prompt_text)["input_ids"]
    full_ids = tokenizer(full_text)["input_ids"]
    # prompt 部分对应 label 置为 -100，训练时不计算损失
    labels = [-100] * len(prompt_ids) + full_ids[len(prompt_ids):]

    return {"input_ids": full_ids, "labels": labels}

dataset = Dataset.from_list(raw).map(format_and_tokenize)

# 3) 训练配置：小学习率、小步数，体现"从预训练权重出发做小幅修正"
training_args = TrainingArguments(
    output_dir="./ft-output",
    per_device_train_batch_size=1,
    gradient_accumulation_steps=4,   # 等效 batch size = 4
    learning_rate=2e-5,              # 远小于预训练学习率
    num_train_epochs=2,
    warmup_ratio=0.1,                # 前 10% 步数做预热
    lr_scheduler_type="cosine",      # 余弦衰减
    weight_decay=0.01,
    logging_steps=1,
    report_to="none",                # 演示时不接 wandb
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    tokenizer=tokenizer,
)

# 4) 开始训练：这里会更新模型的所有参数
trainer.train()

print("\n全参数微调完成。训练过程中，模型的每一个参数都参与了梯度更新。")
print("（数据量极小，仅用于演示流程，不具备实际效果。）")

说明：真实全参数微调通常需要 GPU 和足够的显存。上面的玩具数据只有 3 条，只用于演示"全参数"意味着什么；若要真正训练，请准备更大规模的数据（下一课讲数据准备）。

三、练习#

  1. 填空：全参数微调以 ____ 权重为初始值，用任务数据最小化 ____ 损失（对因果语言模型而言），并把梯度回传到 ____ 参数上。
  2. 显存估算：设模型参数量为 P，用 bf16 存储权重、fp32 存储 Adam 状态。请列出全参数微调需要驻留显存的主要项，并说明为什么它大约是推理显存的 4–6 倍。
  3. 动手实验：把上面代码里的 learning_rate 从 2e-5 改成 1e-3，观察训练 loss 是否发散或剧烈震荡。结合"预训练权重已经很接近好位置"解释你看到的现象。
  4. 思考题：为什么微调的学习率要远小于预训练？如果学习率设置得太大，可能引发什么后果（结合灾难性遗忘）？
