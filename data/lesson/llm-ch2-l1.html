自回归生成#

从这一课开始，我们进入 GPT 系列。GPT 的"G"是 Generative（生成式），它生成文本的方式叫自回归（autoregressive）：一个 token 一个 token 地吐出来，每吐一个，就把它接在上文后面，再喂回去预测下一个。这听起来简单，但"怎么从概率分布里挑出下一个 token"大有讲究——贪心、温度、top-k、top-p 这些采样策略，直接决定了模型输出是"呆板"还是"有灵气"。本课先讲清自回归的数学本质与因果约束，再亲手实现四种采样。

一、概念讲解#

1. 自回归：把联合概率拆成一串条件概率#

自回归生成的理论基础，正是第 1 章第 1 课见过的链式法则。模型不直接"一口气"生成整句，而是把整句的联合概率分解成一步步的条件概率：

P(x_1, ..., x_n) = ∏_{t=1}^{n} P(x_t | x_1, ..., x_{t-1})

生成时就是反复做同一件事：

  1. 拿当前已生成的序列 x_1...x_{t-1} 当输入；
  2. 模型输出"下一个 token"的概率分布 P(x_t | x_<t)；
  3. 从这个分布里采样出一个 token 拼到末尾；
  4. 回到第 1 步，直到生成结束符或达到长度上限。

因为第 t 步的结果会成为第 t+1 步的输入，所以叫"自回归"——序列依赖它自己过去生成的内容。

2. 因果掩码：只允许"回头看"#

自回归要求第 t 步只能依赖"过去"（x_<t），绝不能偷看未来。在 Transformer 里，这靠因果掩码（causal mask）实现：注意力打分时，把位置 i 对位置 j（j > i）的注意力权重压成负无穷，softmax 之后权重归零。这样每个位置只能 attend 到自己和更早的位置。

上一门课你已经写过掩码注意力（decoder 里就用到）。这里强调的是：因果掩码是"训练目标 = 生成方式"的桥梁——训练时预测下一个词，推理时也预测下一个词，二者设定完全一致，模型不需要切换行为。

3. 训练与推理的差异：Teacher Forcing vs 自由采样#

  • 训练时用 Teacher Forcing：每一步都把"正确答案"（ground truth）喂给模型，让模型预测下一个 token 并算交叉熵损失。好处是训练稳定、可并行（一次性算出整条序列每个位置的损失），坏处是模型训练时看到的都是"正确上文"，推理时却要面对"自己可能生成的错误上文"，两者有偏差（exposure bias）。
  • 推理时是自由采样：模型只能看到自己之前生成的 token，一个错可能"滚雪球"放大。

理解这个差异，是理解后续"为什么生成质量要专门调"的前提。

4. 四种采样策略：从"确定"到"随机"#

模型每一步输出的是一个概率分布，怎么把它变成一个具体 token，就是采样策略：

  • 贪心（greedy）：永远选概率最大的 token。结果确定但容易重复、呆板，一旦选错没有回头路。
  • 温度采样（temperature）：先 logits / T 再 softmax，T 越大分布越平滑、越随机；T 越小越接近贪心。T < 1 会让高峰更尖，T > 1 让低概率 token 也获得机会。
  • Top-k：只保留概率最高的 k 个 token，其余置零，再重新归一化采样。砍掉尾部噪声，避免选到很离谱的词。
  • Top-p（核采样 / nucleus）：按概率从高到低累加，只保留"累计概率刚达到 p"的那一小撮 token，再归一化采样。相比 top-k，它能自适应候选集大小——分布集中时候选少，分布分散时候选多。

实践中常组合使用（如"温度 + top-p"），在"确定性"与"多样性"之间找平衡。

二、可运行代码示例#

先手写四种采样，作用在同一个"下一个 token 打分向量"上，看它们各自怎么挑词。

import torch
import torch.nn.functional as F

# 模拟模型对 8 个候选 token 的 logits（打分越高越可能被选）
logits = torch.tensor([1.0, 2.5, 2.3, 0.2, 0.8, 2.9, 1.7, 0.4])

def greedy(logits):
    """贪心：直接取概率最大的 token。"""
    return torch.argmax(logits)

def temperature_sample(logits, t=1.0):
    """温度采样：logits 除以温度 t 后再 softmax、多项式采样。"""
    probs = F.softmax(logits / t, dim=-1)
    return torch.multinomial(probs, 1).item()

def top_k_sample(logits, k=3):
    """Top-k：只保留打分最高的 k 个，其余置 -inf。"""
    topk = torch.topk(logits, k)
    filtered = torch.full_like(logits, float('-inf'))
    filtered[topk.indices] = topk.values
    return torch.multinomial(F.softmax(filtered, dim=-1), 1).item()

def top_p_sample(logits, p=0.9):
    """Top-p：保留累计概率刚达到 p 的最小候选集，再采样。"""
    sorted_logits, sorted_idx = torch.sort(logits, descending=True)
    probs = F.softmax(sorted_logits, dim=-1)
    cum = torch.cumsum(probs, dim=-1)
    keep = (cum - probs) < p            # 累计之前 < p 的 token 才保留
    filtered = torch.where(keep, sorted_logits,
                           torch.full_like(sorted_logits, float('-inf')))
    sampled = torch.multinomial(F.softmax(filtered, dim=-1), 1)
    return sorted_idx[sampled].item()

print("贪心选中的 token 下标:", greedy(logits).item())
print("温度 T=0.5 采样 5 次:", [temperature_sample(logits, 0.5) for _ in range(5)])
print("温度 T=1.5 采样 5 次:", [temperature_sample(logits, 1.5) for _ in range(5)])
print("top-k (k=3) 采样 5 次:", [top_k_sample(logits, 3) for _ in range(5)])
print("top-p (p=0.9) 采样 5 次:", [top_p_sample(logits, 0.9) for _ in range(5)])

观察输出：贪心永远给同一个下标；温度越低越"稳"（几乎总选高分者），温度越高越"飘"；top-k 与 top-p 则把候选锁定在一个高质量子集里随机。这就是不同采样策略的直观差别。

再把这套东西接到真实模型上，看生成效果：

from transformers import pipeline, set_seed

gen = pipeline("text-generation", model="sshleifer/tiny-gpt2")
prefix = "The future of AI is"

# 贪心：重复、保守
set_seed(0)
print("贪心:", gen(prefix, max_new_tokens=20, do_sample=False)[0]["generated_text"])

# 温度 + top-p：更丰富，但可能跑偏
set_seed(0)
print("采样:", gen(prefix, max_new_tokens=20, do_sample=True,
                  temperature=0.8, top_p=0.9)[0]["generated_text"])

三、练习#

  1. 修改 temperature_sample，令 t → 0⁺ 与 t → +∞，观察采样结果分别趋近什么（提示：与贪心、均匀分布的关系）。
  2. 对同一组 logits，分别用 top_k_sample(k=1)、top_k_sample(k=8)、top_p_sample(p=1.0)，解释三者分别退化成了哪种策略。
  3. 用 tiny-gpt2 固定同一个 seed，比较 temperature=0.2 与 temperature=1.5 生成的文本，用你自己的话描述"温度"对多样性与连贯性的影响。
  4. 思考题：Teacher Forcing 训练 + 自由采样推理之间的"exposure bias"，在长文本生成中为什么会被放大？可以结合"一个错误 token 会成为下一步输入"来回答。

为什么这样做？——理论推导#

自回归生成不是工程上的"土办法"，而是概率论链式法则的直接推论。这一节把它一步步推出来。

第一步：直接建模联合分布不可行#

一段文本是 T 个 token 的序列 x1​,x2​,…,xT​，每个 xt​ 取自大小为 ∣V∣ 的词表。若想"一口气"建模整句的联合分布 P(x1​,…,xT​)，它一共有 ∣V∣T 种取值。对 T=50、∣V∣=50000，这个数是 5000050——远超宇宙原子数，任何数据集都不可能覆盖。直接建模联合分布，是一条死路。

第二步：链式法则给出一个"恰好等价"的分解#

概率论里有一条恒等式——链式法则：

P(x1​,…,xT​)=P(x1​)P(x2​∣x1​)P(x3​∣x1​,x2​)⋯P(xT​∣x1​,…,xT−1​)

写成连乘，就是本课开头的形式：

P(x1​,…,xT​)=t=1∏T​P(xt​∣x<t​)

关键在"恒等"二字：这不是近似，而是对任意序列都严格成立。也就是说，只要我们把 T 个条件分布 P(xt​∣x<t​) 各自建模正确，联合分布就自动正确——不需要任何额外假设。

第三步：分解后问题塌缩成"预测下一个 token"#

分解带来了质变：原来要拟合 ∣V∣T 种取值，现在只需拟合 T 个条件分布，而每个条件分布都只是词表上的一个分类分布（∣V∣ 个概率）。更妙的是，这 T 个分布的结构完全一样——都是"给定前缀，输出下一个 token 的概率"。因此可以用同一个函数（参数共享）来完成：

fθ​(x<t​)≈P(⋅∣x<t​)

这就是"语言模型 = 逐步预测下一个 token"的由来：一个网络，反复干同一件"看前缀、猜下一个"的事，就建模了整段文本的联合分布。

第四步：生成 = 反复采样这个条件分布#

联合分布被拆成一串条件分布后，生成就水到渠成：先采样 x1​∼P(⋅)，把 x1​ 拼进前缀，再采样 x2​∼P(⋅∣x1​)，依此类推。每一步的输出都成为下一步的输入，序列"依赖自己过去生成的内容"——这正是"自回归"名称的字面含义。因为第 t 步只被允许依赖 x<t​，因果掩码（不偷看未来）正是为了让模型在每一步都恰好只学到它该学的那一项条件分布，从而保证"训练目标 = 生成方式"严格一致。

母原理连接：链式法则是"把大问题拆成小问题"这一母原理（分治）在概率论中的化身。它把一个指数级的联合分布，塌缩成线性级的一串条件分布，让"预测下一个"这个局部动作逐步累积出完整序列——和动态规划"分解子问题再拼装"、马尔可夫链"下一步只依赖当前"共享同一条思想脉络。
