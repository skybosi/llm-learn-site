项目规划（RAG 问答系统）#

第二个项目是 RAG（检索增强生成）问答系统：做一个"能基于私有文档回答、并给出引用来源"的问答应用。你已经学完 LLM 原理（生成、上下文、幻觉的成因），本课不重复概念，而是带你规划一个能写进简历、能演示、能在面试里被追问的完整 RAG 项目。

一、目标与步骤#

1. 项目目标：做一个"可验证"的私有文档问答系统#

RAG 的核心价值是：让大模型基于"检索到的真实片段"回答，而不是靠记忆胡编。本项目要交付的不是"能聊天"，而是三件可验证的东西：

  • 回答 + 引用：每个答案附上它依据的文档片段来源。
  • 可评估：能定量回答"引用准不准、答案忠不忠实"。
  • 可调优：能对比不同切块策略、检索策略的效果差异。

一句话验收："给定一份私有文档集，系统能在多数问题上给出正确且有据可查的答案，并量化其引用准确率。"

2. 数据来源（真实公开文档）#

选一套有明确事实、适合抽问题验证的公开文档作为私有语料，推荐以下任一：

语料 说明 获取方式
某开源框架官方文档（如 LangChain / LlamaIndex 文档） 结构清晰、有章节、事实性强，适合做引用验证 官网下载 PDF/HTML，或直接爬取 docs 站点
一份公开年报 / 财报 PDF 数字密集，适合考"精确数值引用" 上市公司官网投资者关系页
一份法律法规文本（如《个人信息保护法》） 条款化，容易构造"哪一条规定什么"的问题 政府官网公开文本

建议选 50~200 页、中文为主的文档，规模足够暴露"切块/检索"的真实问题，又不至于让本地向量库与 embedding 太慢。本课后续以"一份框架文档 + 若干 PDF"为例。

3. 技术选型：LangChain vs LlamaIndex#

两个框架都能做 RAG，选型要落在"你的项目需要什么"上：

维度 LangChain LlamaIndex
定位 通用 LLM 应用编排（链、Agent、工具） 面向"数据/索引/检索"的 RAG 专用框架
文档加载与切块 有，但更偏编排 强项：Loader、NodeParser、各类切分
检索与索引 需多手动拼装 强项：VectorStoreIndex、检索器、Rerank 集成
Agent / 多步流程 强 较弱（也有，但非核心）
学习曲线 概念多（Chain/LCEL） 上手快，围绕"文档→索引→查询"

本项目建议：核心管线用 LlamaIndex（文档切块、索引、检索更省事），embedding 与向量库选开源方案；如果你目标是"展示 Agent/编排能力"，则换 LangChain 亦可。关键在于说出你为何选它——这是面试必问。

技术栈汇总：

环节 选型 说明
文档解析 PyPDF / unstructured 解析 PDF、DOCX、HTML
切块 LlamaIndex SentenceSplitter 大小/重叠可调，便于做对比实验
Embedding 开源 embedding（如 BAAI/bge-small-zh-v1.5） 中文效果好、可本地跑
向量库 Chroma（本地）或 FAISS 轻量、可持久化
生成 本地 Qwen 或 API（如 OpenAI/智谱） 生成最终答案
评估 RAGAS + 自建引用核对 定量评估忠实度与引用准确性

4. 验收标准（先定指标）#

指标 含义 验收线（自定）
命中率 Hit Rate@k 检索出的 top-k 片段中是否包含"金标准答案" top-5 命中率 ≥ 0.8
引用准确率 答案的每个引用片段是否真的支持该结论 抽样人工核对 ≥ 0.9
忠实度 Faithfulness 答案是否全部可由检索片段推出（不幻觉） RAGAS 忠实度 ≥ 0.8
回答正确率 抽取 50 个事实问题人工判分 ≥ 0.8

5. 里程碑#

步骤 产出物
1. 文档加载与解析 干净文本 + 元数据（来源页/标题）
2. 切块策略 大小/重叠参数与理由
3. 向量化与索引 向量库构建脚本
4. 检索 + 生成 带引用的问答函数
5. 评估 命中率、忠实度、引用准确率
6. 复盘与话术 对比实验表 + 面试问答

二、代码骨架（本节先搭框架）#

先立起项目结构与环境，验证"能加载文档、能连 embedding、能建索引"这条最小通路：

pip install llama-index-core llama-index-embeddings-huggingface \
            llama-index-vector-stores-chroma chromadb pypdf sentence-transformers
# rag-project/
# ├── data/docs/              # 放入你的 PDF/文档
# ├── src/
# │   ├── ingest.py           # 文档加载 -> 切块 -> 向量化 -> 建索引
# │   ├── query.py            # 检索 -> 生成（带引用）
# │   └── evaluate.py         # 命中率/忠实度/引用核对
# └── reports/

from llama_index.core import SimpleDirectoryReader, VectorStoreIndex
from llama_index.core.node_parser import SentenceSplitter
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.chroma import ChromaVectorStore
import chromadb

# 1) 文档加载：递归读取 data/docs 下的 PDF，自动抽取每段文本与页码等元数据
documents = SimpleDirectoryReader("data/docs", recursive=True).load_data()
print(f"加载文档 {len(documents)} 篇")

# 2) 切块：中文场景建议 chunk_size=512、overlap=64（理由见第 2 课）
parser = SentenceSplitter(chunk_size=512, chunk_overlap=64)
nodes = parser.get_nodes_from_documents(documents)
print(f"切块后节点 {len(nodes)} 个")

# 3) 向量化与索引：本地中文 embedding + Chroma 持久化
embed_model = HuggingFaceEmbedding(model_name="BAAI/bge-small-zh-v1.5")
db = chromadb.PersistentClient(path="data/chroma_db")
collection = db.get_or_create_collection("rag_docs")
vector_store = ChromaVectorStore(chroma_collection=collection)
index = VectorStoreIndex(nodes, embed_model=embed_model, vector_store=vector_store)
index.storage_context.persist()
print("索引构建完成")

最小通路的目标是"跑通一遍"，不是"一步到位"。跑通后再回来做切块对比与检索调优。若本地无 GPU，bge-small-zh-v1.5 在 CPU 上也能跑，只是慢一些。

三、验收与复盘（规划视角）#

  1. 选型能自圆其说：你能在 30 秒内讲清"为什么用 LlamaIndex 而非 LangChain（或反之）"。
  2. 指标先于实现：确认第 4 节的四个验收指标已写下来，而不是等做出系统再定。
  3. 最小通路已跑通：索引构建完成、能打印出节点数，且向量库已持久化。
  4. 简历一句话初稿："Built a citation-grounded RAG QA system over 100+ pages of private docs using LlamaIndex + BGE embeddings + Chroma, with Hit@5 0.85 and faithfulness 0.82."（数字后续补全）
