3. 误差分析#

只看整体指标不够，要拆开看"错在哪"：

# 3.1 找到"高置信却判错"的样本（模型最该改进的地方）
proba = best_model.predict_proba(X.iloc[va_idx])[:, 1]
y_true = y.iloc[va_idx].values
fp_mask = (proba > 0.9) & (y_true == 0)   # 高置信误报（正常交易被拦）
fn_mask = (proba < 0.1) & (y_true == 1)   # 高置信漏报（真欺诈被放行）
print(f"高置信误报 {fp_mask.sum()} 笔, 高置信漏报 {fn_mask.sum()} 笔")

# 3.2 分桶看：不同金额区间的召回率是否差异巨大（常见盲区）
df_val = val_df.copy()
df_val["proba"] = proba
df_val["amount_bucket"] = pd.qcut(df_val["Amount"], 5, labels=False, duplicates="drop")
recall_by_bucket = df_val[df_val["Class"] == 1].groupby("amount_bucket").apply(
    lambda g: (g["proba"] >= best_threshold).mean()
)
print("各金额分桶的召回率:\n", recall_by_bucket)

误差分析要能得出一个明确的下一步结论，例如："小额欺诈召回明显偏低，下一步应针对小额交易补充采样或调整 scale_pos_weight。"没有结论的误差分析等于没做。

三、面试话术#

面试官会问什么、怎么答#

Q1：为什么用 AUC-PR 而不是 Accuracy？ 答：欺诈正类只有约 0.17%，就算把全部交易判为正常，Accuracy 也有 99.8%，但一个欺诈都没抓到，模型毫无价值。所以我用 AUC-PR 作为主指标，它专门衡量"少数类在排序上的表现"；同时用 AUC-ROC 做参照，并在业务层面把假阳率换算成误拦成本。

Q2：数据不平衡你是怎么处理的？ 答：分三层。第一是指标层，换掉 Accuracy 用 AUC-PR；第二是算法层，给树模型设 scale_pos_weight（约等于负/正样本比）；第三是决策层，不直接取 0.5，而是用 PR 曲线 + 业务成本（误拦 50 元 vs 漏报 1000 元）选出最优阈值。我没有盲目上 SMOTE 过采样，因为树模型 + 权重已经足够，过采样还会放大噪声、拖慢训练。

Q3：你怎么防止数据泄漏？ 答：两点。一是按时间切分而不是随机切分——随机切分会把"未来"的交易混进训练集，虚高指标；二是 PCA 特征来自全量数据，我始终只用训练集算统计量（比如 Amount 的 RobustScaler 先 fit 训练集再 transform 验证集），避免 fit_transform 全程导致信息泄漏。

Q4：上线时模型输出概率还是标签？ 答：输出概率，再由业务阈值转标签。因为最优阈值会随业务成本变化，把决策权留给业务方；我还做了金额分桶的召回分析，发现小额欺诈是短板，会作为迭代方向。

四、常见坑（复盘清单）#

  1. 用 Accuracy 当主指标：在不平衡数据上等于自欺欺人。
  2. 随机切分导致泄漏：让指标虚高，面试被追问即露馅。
  3. 全程 fit_transform：把验证集统计量泄漏进模型，CV 分数不可信。
  4. 只看整体指标不拆桶：掩盖了小额欺诈这类关键短板。
  5. 无脑过采样 SMOTE：在树模型上收益有限还引入噪声；先试权重，再谈采样。
  6. 调参无目标：拿 Accuracy 或交叉熵乱调，最终得到"指标好看、业务没用"的模型。
