结果评估与复盘#

上一课我们把模型训出来了。但"训练完成"只是中途站，不是终点。模型到底好不好、哪里好、哪里差，必须靠严谨的评估和复盘来回答。这一课是本课程的收官之课，我们要做三件事：算对指标、做透误差分析、写出一份能指导下一步的复盘结论。学完这一课，你不只是会"训模型"，而是具备了把一个 CV 项目闭环交付的完整能力。

一、概念讲解#

1. 先算对指标：IoU、AP、mAP#

检测分割的评估指标，本质都是在回答"预测和真值有多吻合"。几个核心概念必须分清：

  • IoU（交并比）：预测框/掩码与真值框/掩码的"交集面积 ÷ 并集面积"。它是判断"是否算预测对了"的底层标准。一般 IoU ≥ 0.5 视为命中（也可用 0.75 做更严格标准）。
  • Precision / Recall：在某个 IoU 阈值和置信度阈值下，统计预测对的（TP）、预测错的（FP）、漏掉的（FN），得到精确率和召回率。二者是跷跷板——阈值调高，精确率升、召回率降。
  • AP（平均精确率）：把置信度阈值从高到低扫一遍，画出 Precision-Recall 曲线，曲线下面积就是 AP。它综合了"找得全不全"和"找得准不准"。
  • mAP：所有类别的 AP 取平均。mAP@0.5:0.95 是 COCO 的标准主指标，即在多个 IoU 阈值（0.5 到 0.95 步长 0.05）上取平均，最严格也最常用。

2. 误差分析：不要只看一个数字#

mAP 是一个"总账"，但复盘要靠"分账"。一个好的误差分析会把 mAP 拆开，回答"模型具体在哪类目标、哪种场景上失败"：

  • 按类别拆：哪几类的 AP 明显低？是类别混淆（把 A 认成 B），还是根本检测不到？
  • 按目标大小拆：小目标（面积 < 32² 像素）的 AP 通常远低于大目标。如果你的场景小目标多，这会是主要瓶颈。
  • 按错误类型拆：漏检（FN）多还是误检（FP）多？定位不准（框偏了）还是分类错？不同错误类型的对策完全不同——漏检多要提召回（降阈值、加强 RPN），误检多要压误报（难负样本挖掘）。
  • 可视化检查：把预测结果画到图上，找出最差的一批样本人工看，往往能发现"脏数据、标注错误、特定光照"等指标里看不见的问题。

3. 超参与消融：改进要"有据可查"#

复盘时如果做了改进（换骨干、加增强、调损失权重），要用消融实验（ablation）证明每项改动都有贡献，而不是凭感觉。消融的原则是一次只变一个变量：

配置 mAP@0.5:0.95 说明
基线 ResNet50 0.52 起点
+ 强数据增强 0.56 增强带来 +4 点
+ Swin 骨干 0.60 换骨干 +4 点
+ 自监督预训练 0.63 少标签场景收益明显

这张表才是复盘的"证据链"：每一项收益都量化、可追溯。

4. 部署视角：精度之外的"及格线"#

一个只讲精度、不讲落地的项目是不完整的。复盘时还要从部署角度审视：

  • 推理速度（FPS / 延迟）：mAP 高了 2 点但延迟翻倍，对实时场景可能得不偿失；
  • 模型体积与量化：转 ONNX、TensorRT 或 INT8 量化后精度掉多少、速度提多少；
  • 鲁棒性：换了光照、分辨率、新一批数据后，指标是否稳定。

把精度、速度、体积、鲁棒性一起纳入复盘，你交付的才是一个"能上线"的项目，而不是一个"只在测试集上好看"的模型。

二、可运行代码示例#

先实现最核心的 IoU 计算，理解这个"命中判断"是怎么来的：

import torch


def box_iou(boxes1, boxes2):
    """计算两组边界框的 IoU。box 格式 (N,4)，每行为 (x1,y1,x2,y2)。"""
    # 计算交集的左上/右下坐标
    lt = torch.max(boxes1[:, None, :2], boxes2[:, :2])   # (N, M, 2)
    rb = torch.min(boxes1[:, None, 2:], boxes2[:, 2:])   # (N, M, 2)
    wh = (rb - lt).clamp(min=0)                          # 交集宽高，负的截成 0
    inter = wh[:, :, 0] * wh[:, :, 1]                    # 交集面积

    area1 = (boxes1[:, 2] - boxes1[:, 0]) * (boxes1[:, 3] - boxes1[:, 1])
    area2 = (boxes2[:, 2] - boxes2[:, 0]) * (boxes2[:, 3] - boxes2[:, 1])
    union = area1[:, None] + area2 - inter
    return inter / union


pred = torch.tensor([[0, 0, 10, 10], [5, 5, 15, 15]])   # 两个预测框
gt = torch.tensor([[0, 0, 10, 10]])                     # 一个真值框
print("IoU 矩阵:\n", box_iou(pred, gt))                 # 第一个框完美重合 IoU=1

再看一段 mAP 的"手动简化版"——不调库，走一遍"按置信度排序 → 算 P/R → 曲线下面积"的过程，把 mAP 的直觉建立起来：

def simple_ap(confidences, is_tp, num_gt):
    """简化 AP 计算：按置信度降序，逐步统计 P/R，用数值积分求曲线下面积。"""
    order = torch.argsort(confidences, descending=True)
    is_tp = is_tp[order].float()
    tp = torch.cumsum(is_tp, dim=0)                 # 累计真阳性
    fp = torch.cumsum(1 - is_tp, dim=0)             # 累计假阳性
    precision = tp / (tp + fp + 1e-8)
    recall = tp / num_gt
    # 在 recall 上插值，保证 PR 曲线单调递减，再求面积
    ap = 0.0
    prev_recall = 0.0
    for p, r in zip(precision.tolist(), recall.tolist()):
        ap += p * (r - prev_recall)
        prev_recall = r
    return ap


# 假数据：8 个预测，置信度 + 是否命中真值（TP=1/FP=0），真值共 3 个目标
conf = torch.tensor([0.9, 0.8, 0.7, 0.6, 0.5, 0.4, 0.3, 0.2])
is_tp = torch.tensor([1, 1, 0, 1, 0, 0, 1, 0])
print("简化 AP:", simple_ap(conf, is_tp, num_gt=3))

最后，写一个把"预测画到图上"的可视化辅助函数，用于误差分析时人工检查最差样本：

import torchvision
import torchvision.transforms.functional as TF
from PIL import Image, ImageDraw


def draw_boxes(image_path, boxes, labels, colors):
    """在图上画出预测框和标签，用于人工误差分析。"""
    img = Image.open(image_path).convert("RGB")
    draw = ImageDraw.Draw(img)
    for box, label in zip(boxes, labels):
        x1, y1, x2, y2 = box
        draw.rectangle([x1, y1, x2, y2], outline=colors.get(label, "red"), width=3)
        draw.text((x1, y1), str(label), fill=colors.get(label, "red"))
    return img


# 示意：画两个框（现实中 boxes/labels 来自预测或真值）
demo = draw_boxes(
    image_path=None,  # 传你的真实图片路径
    boxes=[[10, 10, 100, 100], [120, 30, 200, 160]],
    labels=["缺陷A", "缺陷B"],
    colors={"缺陷A": "red", "缺陷B": "blue"},
)
print("可视化函数已就绪，将预测框/真值框叠加到原图即可人工核对。")

这三个工具——IoU、AP、可视化——组合起来，就是一套不依赖任何库也能上手的评估与误差分析工具链。工业界实际会用 COCO 官方的 pycocotools 或 detectron2 内置评估器，但底层逻辑和上面这段代码是一致的。

三、练习#

  1. 用 pycocotools 在你的检测结果上跑一次完整 COCO 评估，打印每类的 AP、mAP@0.5 和 mAP@0.5:0.95，找出 AP 最低的两个类别，并结合可视化分析原因。
  2. 把上面 simple_ap 里的置信度排序打乱后再算一次 AP，验证 AP 对"置信度排序质量"的敏感性，说明为什么"校准置信度"对检测器很重要。
  3. 做一次消融实验：在 detectron2 上分别训练"基线 / 基线+强增强 / 基线+强增强+Swin骨干"三个配置，用表格列出 mAP、训练时间、显存，判断哪项改动的性价比最高。
  4. 从部署视角复盘你的模型：测量单张推理延迟，尝试 ONNX 导出（或 INT8 量化），记录精度损失和速度提升，写一段三句话的"落地可行性"结论。
