威胁建模：资产、对手、能力假设与信任边界#

这一节要解决什么#

先看两个句子：

甲：这套系统的越狱成功率是 5%，风险很高。 乙：这套系统的越狱成功率是 5%，年化期望损失 5000 元；同一个人在另一套能执行写操作的部署上能达到 6×105 元 —— 后者优先。

两句里的"越狱成功率"是同一个数。差别只在它有没有分母。甲句无法被检验、无法被排序、无法被修复：不知道对手是谁、被攻破的东西值多少钱、攻破之后他能拿走多少。乙句可以被反驳 —— 你可以质疑 106 这个暴露量、质疑 0.01 这个利用因子、质疑损失曲线，然后我们把数改掉、把结论重算。

本章、乃至整门课要反复回到的一件事就是：安全的断言必须能被算出来，否则它只是修辞。 而"能不能被算出来"取决于一个前置工作 —— 你先把威胁模型写下来了没有。

这一节先把这个前置工作做成一个可核对的结构，而不是一段"我们很重视安全"的说明。具体要解决四个问题：

  1. "资产"到底是什么？ 为什么"数据泄露"这四个字在没有单位和量级时无法定价？单次损失 c 为什么必须拆成 cdirect​+cthird​+cremedy​（本节算例里 cremedy​ 占 480/900=53.3%）？
  2. "对手"怎么刻画？ 为什么"黑盒/灰盒/白盒"这个三档划分不够用？用哪四个正交维度（可查询 / 可改提示 / 可写被读内容 / 可引副作用）才能把 LLM 系统的对手刻画清楚？
  3. "信任边界"画在哪？ 在一条典型的"检索 + 工具调用"链路上，同一个数据对象穿过不同边界时的风险为什么不一样？为什么"不要相信用户输入"这条老规则在这里会失效？
  4. "失效条件"怎么写？ 每一层防护都要写清"它在什么情况下整体不成立"，否则防护会被误当成保证。

这一节的产出必须是一张表，后面每一章都要往这张表里填一列：第 2 章填"注入面"，第 3 章填"泄露通路"，第 4 章填"对齐失败的类型"，第 6 章填"防护覆盖率与残余风险"。

本节的核心算式只有一条，但它的每一个因子都值得单独讨论：

R=i∈通路∑​Ni​pi​Ei​ci​

其中 Ni​ 是年暴露量（一年有多少次机会）、pi​ 是单次成功概率（对手在这一次机会里得手的概率）、Ei​ 是利用因子（得手一次能从该资产上真正拿走多少比例）、ci​ 是该资产被完整拿走一次的单次损失。pi​ 就是平时大家说的"攻击成功率"；它只是 R 里的一个因子。

一、为什么"没有威胁模型的讨论都是空的"#

1.1 一句反例：同一个 p，三种部署#

先把结论摆出来。同一份模型权重、同一个 p=0.05 的越狱成功率，只改部署形态：

部署 年暴露量 N 成功率 p 单次损失 c 利用因子 E 年化风险 R 相对
公开问答机器人 106 0.05 10 元 0.01 5000 元 1.000
企业内部问答 5×103 0.05 900 元 0.30 67500 元 13.500
受控运维助手 103 0.05 20000 元 0.60 6×105 元 120.000

p 完全相同，R 差 120 倍。这三个场景里的技术手段差别不大（都是提示注入 + 越狱），差别在于对手能碰到什么、碰到之后能做什么。所以：

"这个模型安全吗？"这个问题在语法上就是不完整的。 完整的问题是"在这个部署里、对这类对手、通过这条通路，年化风险是多少？"

1.2 威胁模型的五个槽位#

一个能用的威胁模型必须回答五个问题。缺任何一个，后面四个都会失去参照：

T=(A, O, B, H, F)

槽 符号 问题 写不出来时的后果
资产 A 被拿走/被篡改的东西是什么？单位是什么？量级多少？值多少？ ci​ 无法估，R 没有量纲
对手 O 谁在打？他有几个正交的能力维度？ pi​ 没有分母，"难不难"不可比
边界 B 数据的每一段在进入模型前后分别由谁控制？ "注入"无法定义
通路 H 从对手能力到资产损失，中间经过哪些环节？ Ni​、Ei​ 无从写起
失效 F 每条防护在什么条件下整体不成立？ 防护被当成保证

这五个槽位之间的关系是单向依赖的：O 决定 H 有哪些（没有写被读内容的能力，间接注入这条通路根本不存在）；H 结合 A 才有 R；F 是 H 上"我们以为被切断但其实没断"的那些边。所以顺序不能颠倒 —— 先写清对手，再谈攻击面。

1.3 "为什么没有威胁模型的讨论都是空的"：三个可操作的判定问句#

下面三个问句可以当场把一段空泛的安全性表述问崩。它们的共同点是：每一个都要求给数或给结构，而不是给形容词。

问句 1（分母）："你说的这个成功率，是在多少次暴露上测的？每次暴露能拿到什么？拿到之后值多少钱？"

如果回答不出 N、E、c，那么这句话不能进风险表，最多只能进"待定"。p=0.05 在 N=106,E=0.01,c=10 时值 5000 元，在 N=103,E=0.6,c=2×104 时值 6×105 元。

问句 2（能力档）："这个攻击者能查询模型吗？能改我们给他的提示吗？能让我们读到他自己写的内容吗？能让我们执行一个副作用吗？"

四个问题对应四个正交维度（见 §三）。只要第四个问题的答案是"能"，整张风险表的量级就会变 —— 因为 E 从"读到一段文字"变成"执行一条写操作"，c 的量级也从信息损失跳到运营损失。

问句 3（边界）："这段文本在进入上下文之前，最后一次被谁写过？我们做了什么校验，校验的是格式还是语义？"

这个问题的杀伤力在于：检索出来的文档、工具返回的 JSON、别人写的 issue，在传统安全模型里都属于"我们自己的数据"，但在 LLM 的上下文里它们和系统提示同权。如果答案里只有"格式校验"（schema、长度、类型），那就等于没做语义层的信任分级 —— 而注入正是语义层的攻击。

1.4 一个具体的失衡：为什么"模型越狱率"这个词会误导人#

把 R 取对数看它的敏感性：

∂lnp∂lnR​=1,∂lnN∂lnR​=1,∂lnc∂lnR​=1,∂lnE∂lnR​=1

四个弹性都是 1 —— 也就是说，把 p 从 0.05 压到 0.005（十倍努力）与把 E 从 0.60 压到 0.06（同样的收益）在 R 上是等价的。但工程上这两件事的成本往往差很远：前者要重新做一轮对齐训练 + 红队，后者可能只需要把写操作的工具从模型的可调用列表里拿掉。

这不是说 p 不重要，而是说：只看 p 的团队会系统性低估"结构改动"的收益。 本章后面的缓解措施排序（§七）就是把这个直觉算成数字。

二、资产清单：从"数据泄露"到可定价的对象#

2.1 资产的四要素#

每一项资产必须写成四要素，缺一个都不可计算：

资产=(u, 单位, n, c)

  • u：名称，必须具体到能被清点（"企业知识库"可以，"敏感信息"不行）；
  • 单位：条 / 会话 / 个 / 份 —— 没有单位就无法把 n 和 E 乘起来；
  • n：量级（数量级即可，但要有）；
  • c：完整拿走一个单位的单次损失（元）。注意是"完整拿走一个单位"，不是"泄露一点点" —— 后者由 E 承担。

本节算例的清单（合成数据 ⚠️）：

资产 单位 数量 n 单次损失 c（元）
企业知识库 条 120000 2000
用户会话历史 会话 40000 900
运维凭据 个 12 480000
模型权重 份 1 3000000
训练语料中的逐字串 条 8000 150

两个立刻可读的结论：

  1. c 的跨度是 20000 倍（3000000/150）。这意味着"泄露了多少条"这个指标在不同资产之间不可加。把"泄露 100 条知识库条目"和"泄露 100 条逐字串"写成同一个数，是把 20000 倍的差距抹掉了。
  2. 数量最多的资产不是最贵的资产。条数合计 168013，但风险排序由 c（以及后面的 E 与 p）决定，不由条数决定。

2.2 为什么 c 必须拆成三项#

单次损失最常见的估计错误是只算直接损失。完整的 c 至少有三项：

c=直接损失cdirect​​​+第三方损失cthird​​​+处置成本cremedy​​​

算例（合成 ⚠️）：

资产 cdirect​ cthird​ cremedy​ 合计
会话历史泄露 120 300 480 900
运维凭据泄露 50000 120000 310000 480000
逐字串复现 20 60 70 150

读数：处置成本常常大于直接损失。 会话历史那一行里 cremedy​/c=480/900=53.3%；运维凭据那一行是 310000/480000=64.6%。只算 cdirect​ 会把风险系统性低估 2 倍以上。这个偏差在排序上更危险：如果两类资产的 cremedy​/c 比例不同（凭据类偏高、逐字串类偏低），只算直接损失会把凭据类排低。

为什么这样设计（拆三项）： 因为三项的归属方不同。cdirect​ 由受害者承担、cthird​ 由第三方（用户、合作方）承担、cremedy​ 由运营方承担。归谁承担决定了"谁有动机修"，这一点在合规与责任边界上（本课最后一章）会重新出现。

2.3 资产建模的三个常见失误#

失误 1：把"模型"当成一项资产。 模型权重、模型行为、模型输出是三项不同的资产：权重泄露是知识产权损失（c 由重训成本 + 法务估），行为可被操纵是完整性损失（c 由错误决策的后果估），输出被滥用是责任损失。三者的 N、E、c 完全不同。

失误 2：把"数据"当成一个同质的池子。 训练语料、检索语料、会话历史、日志、遥测 —— 它们的可访问范围与保留期不同，因此 E 不同。第 3 章会把"训练语料里的逐字串"单列，因为它的泄露机制（记忆化）与其他几类完全不同。

失误 3：忘记"模型的输出本身"是资产。 在 Agent 形态里，输出会变成动作（发信、写库、下单）。这时资产的单位是"动作"，c 是"一个错误动作的后果"。这正是 §一 里那张表第三行的来源。

三、对手能力档：四个正交维度#

3.1 为什么"黑盒/灰盒/白盒"不够#

这个三档划分来自密码学与经典 ML 安全，它刻画的是对手对模型内部知道多少。它有用，但对 LLM 系统远远不够，因为它没有刻画对手对输入通道的控制，而 LLM 系统的主要攻击面恰恰在输入通道上。

考虑两个"黑盒"对手：

  • 对手 A：只有查询接口，能发提示，能看到回答。
  • 对手 B：不能查询模型，但可以在一个会被检索的公开页面上写一段字。

两者都是黑盒，但他们的攻击完全不是一回事：A 需要绕过安全约束（越狱），B 只需要让内容被读进上下文（间接注入）。用同一个"黑盒"标签覆盖他们，会让"黑盒越狱率"这种指标失去意义。

3.2 四个正交维度#

能力档=(Q, P, W, S)

维 含义 它决定什么
Q 可查询模型并观察输出 p 能否被迭代优化（有反馈 → 可自动化搜索）
P 可控制进入上下文的提示文本 直接注入/越狱的前提
W 可写入"会被读进上下文"的外部内容 间接注入的前提；不需要接触模型
S 可引发副作用（写库/发信/下单/执行代码） E 与 c 的量级

算例里的五档（合成 ⚠️）：

档位 Q P W S
A · 纯外呼黑盒 True False False False
B · 提权黑盒 True True False False
C · 间接注入者 False False True False
D · 工具链内鬼 True True True True
E · 白盒对手 True True True True

C 档最值得注意：它不可查询、不可改提示，只靠别人把内容读进上下文。传统威胁建模里这种对手常常被漏掉，因为"他连接口都没有"。但 LLM 系统的默认行为是把上下文里的一切都当指令读，所以"内容被读到"本身就构成一次控制机会。

为什么这样设计（正交而不是分级）： 因为四个维度不构成全序。C 档与 B 档无法比较谁"更强" —— B 能迭代但他写不进任何被检索的位置，C 写得起但他不知道自己的哪一段起了作用。用分级（弱/中/强）会强迫建模者做出一个没有依据的比较，而用四维布尔向量则保留了"哪些通路对谁开放"这个真正有用的信息。

3.3 从能力档到通路：N、p、E 怎么填#

有了资产（A）与对手（O），通路就是两者之间的一条边：

通路：(a∈A, o∈O) ⟼ (N,p,E)

  • N 是年暴露量：这条通路一年被触发多少次。它由业务量决定，不由安全团队决定。注意"暴露"的定义要写清楚（一次查询？一次会话？一条被索引的文档被读到的次数？）。定义不同，N 可以差几个数量级。
  • p 是单次成功率：一次暴露里对手得手的概率。它才是各种"越狱率/注入率"指标落脚的地方。
  • E 是利用因子：得手一次能拿走该资产的多少比例（0∼1）。它由系统的结构决定：能不能批量读取、输出有没有长度上限、取走的内容能不能被带出（比如只能看到一段摘要 vs 能下载整个文件）。

这里有一个必须在正文里说清的边界：上表的 p 是互不独立的估计（同一个模型、同一批防护），把它们当成独立事件相加会低估联合风险。R=∑i​Ni​pi​Ei​ci​ 是期望值可加（期望的线性性总是成立），但如果要问"一年内至少发生一次的概率"，就必须建联合分布 —— 那是更重的工作，本节不做。可加的是期望损失，不是事件概率。

四、信任边界：把"谁控制这段数据"画出来#

4.1 经典信任边界与它在 LLM 上的失效#

经典 Web 安全的信任边界画在请求体上：

[不可信] 请求体 ──校验/转义──> [可信] 应用逻辑 ──> [可信] 数据库

这个模型能成立，靠的是一条假设：数据在"被解析"之后就不再是指令。SQL 注入能被参数化查询挡住，正是因为参数永远走数据通道。

LLM 系统没有这条通道分离。系统提示、用户输入、检索文档、工具返回的 JSON —— 全部被拼成同一个词元序列，由同一个注意力机制处理。所以：

在 LLM 的上下文里，"数据"与"指令"是同一种东西。

这不是实现缺陷，而是自回归语言模型的定义性后果（第 2 节会把它形式化）。它的直接推论是：经典信任边界必须重新画，而且要画在"这段文本是怎么进入上下文的"这条链路上，而不是画在"它是用户输入还是数据库记录"这个来源上。

4.2 一条典型链路的边界图#

考虑一个"检索 + 工具调用"的助手：

① 终端用户 ──[B1]──> ② 提示拼装 ──[B2]──> ③ 检索/工具
                          ↑                        │
                          └──────[B3]──────────────┘
   ④ 外部内容源（网页/issue/邮件/PDF）──[B4]──> ③
   ③ ──[B5]──> ⑤ 模型上下文 ──[B6]──> ⑥ 输出/动作
边界 谁在这条边上写数据 必须回答的问题 常见错误
B1 终端用户 用户能否改变系统提示？能改多少？ 把用户输入直接拼进模板而不设字数与结构
B2 应用 提示模板里有哪些槽位是变量？ 槽位无上限 → 用户可以把整段"指令"塞进一个槽
B3 检索/工具 工具返回的内容是否原样进上下文？ 认为"工具返回是可信的"
B4 外部写者 谁能让内容出现在被检索的位置？ 完全没建模这条边
B5 上下文管理器 拼接顺序是什么？谁在前谁在后？ 把外部内容放在系统提示之后且无标记
B6 模型 输出被直接执行还是经过审批？ 把"模型说要写"当成"可以写"

B4 是 LLM 系统特有的、也最容易被忽略的一条。 它把攻击面从"能接触模型的人"扩展到"能往任何被检索位置写字的人"。这条边上的对手就是 §3.2 里的 C 档：不可查询、不可改提示、只需要写。

4.3 边界上的三种检查，以及为什么只有第三种有用#

每条边界上通常有三种检查：

  1. 格式检查：类型对不对、长度超不超、编码是不是 UTF-8。它能挡住崩溃，挡不住攻击。
  2. 来源检查：这段内容来自哪个数据源？有没有签名？它能缩小攻击面，但不能缩小到零 —— 因为"可信数据源"这个概念在 LLM 上退化了：一个内部 Wiki 页面也是人写的。
  3. 语义检查：这段内容里有没有"试图改变任务"的成分？

第三种是唯一直接针对注入的检查，但它有一个结构性困难：判据本身要靠模型来读，于是它自己也可能被注入。这就是"过滤器的自我指涉问题"（第 2 节与第 6 节会展开）。本节只把它记成一个边界属性：B3/B4/B5 上的语义检查都不是可靠的单点防护，只能作为纵深的一层。

4.4 边界的"宽度"：一个可算的判据#

边界不是布尔量，它有宽度：一段数据在穿过边界时，有多少比例是攻击者可控的？定义可控词元占比：

ρ=总词元数攻击者可直接或间接写入上下文的词元数​

ρ 是可算的，也是第 2 节可利用性判据的第一项。它的意义在于：

  • 系统提示里没有变量 → ρ 只来自检索/工具内容；
  • 用户输入占满一个槽位 → ρ 可能到 0.2∼0.4；
  • 外部文档原样拼接 → ρ 可能超过 0.9。

ρ 大不必然危险，ρ=0 也不必然安全：如果 ρ>0 的文本对输出没有因果影响（比如它只被存进日志、永不进上下文），那它不构成注入面。第 2 节会把这两项合成一个判据：

可利用⟺ρ>0 ∧ 对输出的干预效应=0

本节只要把它记进威胁模型表的"边界"列：每条边界上写下 ρ 的估计与它的计算方式。

五、失效条件：每条防护都要写"它在什么情况下整体不成立"#

5.1 为什么"失效条件"是威胁模型的必要成分#

工程上最常见的沟通事故是这样发生的：

安全团队：我们加了输入过滤，注入风险已缓解。 三个月后：攻击者用 base64 编码绕过了过滤。

问题不在"过滤被绕过"（这是必然的），问题在于"已缓解"这个词被听成了"已消除"。避免这种事故的唯一办法是：每条防护在写下的同时，写下它的失效条件。

防护=(作用对象, 拦截判据, 削减比例, 失效条件)

5.2 失效条件的四种类型#

类型 含义 例子
覆盖失效 判据没覆盖到的输入形态 输入过滤只查明文关键词 → 编码/多语言/同义词绕过
判据失效 判据本身依赖被攻击的对象 用模型判断"这段是不是注入" → 判断器自己可被注入
结构失效 依赖的前提被系统改动破坏 会话隔离依赖"每会话独立缓存" → 引入前缀共享缓存后失效
人的失效 依赖人的持续注意力 写操作人工审批 → 审批疲劳后变成橡皮图章

这四类不是并列的修辞，而是可以直接转成数字的：覆盖失效影响 p（成功率上升），结构失效影响 E（一旦绕过就等于全开），人的失效影响 phuman​ 的时间衰减。

5.3 把失效条件写成可算的残余风险#

一条削减比例为 κ 的防护，它的残余风险不是 1−κ，而是：

Rres​=R⋅(1−κ)+R⋅κ⋅qbypass​=R⋅(1−κ(1−qbypass​))

其中 qbypass​ 是该防护在其失效条件被满足时的绕过率。

算例：输入过滤的 κ=0.60，但对编码绕过几乎无效 —— 设编码类请求占 3%、这类请求里 qbypass​=0.90。取总风险中与输入过滤相关的那一份（算例里"企业知识库/C 档"的 R=60000 元）：

Rres​=60000×(1−0.60×(1−0.90))=60000×0.94=56400 元

也就是说，"削减 60%"在有明确绕过面时只剩 6% 的有效削减。这个数字看起来悲观，但它是可改进的：只要把编码类请求也纳入判据（κ 在编码子集上从 0.10 提到 0.5），残余就明显下降。失效条件写出来，才有优化目标。

六、年化风险 R=∑i​Ni​pi​Ei​ci​：算法、假设与陷阱#

6.1 算式与它的三个假设#

R=i∑​Ni​pi​Ei​ci​

要让这个式子成立，需要三个假设，每一个都可能不成立，必须写下来：

  1. 期望可加：R 是期望损失，期望的线性性无条件成立 —— 这一条总是成立，不用假设。
  2. 单次损失与频次独立：即 ci​ 不随 Ni​ 变化。这一条常常不成立：泄露 1 条与泄露 104 条的单位处置成本不同（规模效应、监管关注阈值）。
  3. 参数存在且稳定：pi​ 有意义（对手没有每天都在进化）。这一条最脆弱：对手的行为是适应性的，p 会随防守变化。

所以 R 的正确用法是排序与量级判断，不是"精确预测"。把它当成精确值会得出荒谬的结论（比如"我们今年的安全预算是 6172000 元"）。

6.2 陷阱一：稀有事件的重尾#

p 很小的通路（比如"模型权重被白盒对手拿走"的 p=0.20、N=5）在点估计上很稳，但它的不确定度极大。对一条通路的风险取对数正态：

Ri​∼Lognormal(μ,σ2),μ=lnRi​−2σ2​

（μ 这样取是为了让 E[Ri​]=Ri​，即点估计仍然是均值。）算例对第 1 名通路（R=3×106）给出：

σ 中位数 90% 区间 区间比值 蒙特卡洛复核
0.5 2647491 [1163212, 6025733] 5.18 倍 [1163967, 6038009]
1.0 1819592 [351256, 9425944] 26.84 倍 [352558, 9497891]
1.5 973957 [82606, 11483288] 139.01 倍 [83426, 11550158]

读数：σ=1.5 时，90% 区间的上界是中位数的 36.3 倍。 用中位数或点估计来排序会把长尾项排低 —— 而安全事件恰恰以长尾为主。所以：

排序时不能只看 R，要看 R 的区间。 两条通路的点估计接近时（比如 3000000 与 2880000），决定优先级的是不确定度，不是第三位有效数字。

6.3 陷阱二：参数误差的传导#

lnR 对四个参数都是线性的，所以同向的百分比误差会相加。如果 N 与 c 都被低估 f 倍（常见于"我没算过"），R 被低估 f2 倍：

  • f=2 → R 放大 4 倍；
  • f=5 → R 放大 25 倍。

更重要的一条：全局同向误差不改变排序，局部误差才改变排序。算例：把原第 3 名通路（用户会话历史/B 档）的 N 单独放大 100 倍，它直接升到第 1 名。所以：

估参必须按通路逐条做。 "我们整体上乐观了 2 倍"这种调整对决策没用；"这条通路的 N 我们其实没数过"才是要命的地方。

6.4 陷阱三：N 的重复计数#

同一个事件往往可以归到多条通路（一次成功注入既读了知识库又读了会话历史）。把它们相加会重复计算同一份损失。处理方式有两种：

  • 保守法：把所有通路合并成"一次事件"来估，c 用事件的总损失；
  • 标签法：给每条通路的损失打标签（哪些资产受影响），求和时对同一事件只计一次主导损失。

本节算例用的是保守法（把两条通路当成可以分别发生的事件），所以 6172000 元应当读作上界。这一点必须写进交付物：R 的绝对值不可信，它的排序可信。

七、缓解措施：按边际收益排序#

7.1 算式#

一条缓解措施的价值是它削减的期望损失除以它的年化成本：

ROIj​=costj​ΔRj​​,ΔRj​=Ri(j)​⋅κj​

算例（合成 ⚠️）：

措施 通路 削减 κ 年化成本 ΔR ROI
工具写操作人工审批 运维凭据 / D 95% 120000 2736000 22.80
会话隔离与缓存分区 用户会话历史 / B 80% 90000 108000 1.20
降低知识库检索广度 企业知识库 / A 40% 20000 16000 0.80
输出侧 PII 检测 用户会话历史 / B 70% 260000 94500 0.36
输入侧注入过滤 企业知识库 / C 60% 180000 36000 0.20
逐字串训练侧去重 训练语料中的逐字串 / A 50% 400000 750 0.00

排序：工具写操作人工审批（22.80）> 会话隔离（1.20）> 降低检索广度（0.80）> 输出侧 PII（0.36）> 输入侧过滤（0.20）> 训练侧去重（0.00）。

7.2 三个立刻可读的结论#

结论 1：最优措施不是"安全措施"，是权限设计。 第 1 名的 ROI 比第 2 名高 19 倍，而它的本质是把 E 从 1.0 压下来（写操作要人批）。这与 §1.4 的弹性分析一致：E 是一个被系统性低估的杠杆。

结论 2：最"正统"的安全措施排名很低。 输入侧注入过滤（ROI 0.20）与训练侧去重（ROI 0.00）在直觉上最像"安全投入"，但它们的 ROI 低，原因是它们作用的通路本身 R 不大（60000 与 1500）。这不是说它们不该做，而是说：在预算有限时，它们不该排在第一。 训练侧去重更值得注意 —— 它的成本最高（400000）而作用通路的 R 只有 1500，在本节算例里 ROI 近于 0。第 3 章会说明为什么它仍然要做（合规与下游用途），但在本节的威胁模型里它排最后。

结论 3：ROI 会因为重复计算而虚高。 当多条措施作用于同一条通路时，线性相加会超过 1。算例：通路"用户会话历史/B"上同时有输出侧 PII（0.70）与会话隔离（0.80），真实削减是

1−(1−0.70)(1−0.80)=0.94,

而线性相加给出 1.50。所以：

Rres​=Rj∈同通路∏​(1−κj​(1−qbypass(j)​))

这条式子是本节最实用的一个工具：它说明"堆措施"的边际收益递减，也说明为什么第一条措施最值钱。

7.3 取舍：什么时候不该用 R 排序#

  • 当 c 的量纲不可比时（合规罚款 vs 声誉损失 vs 用户伤害）。R 把它们都折算成元，而有些东西折算本身就是错的。这时的正确做法是分列约束（"这一条的容忍度是零"），而不是塞进 R 里比较。
  • 当对手是适应性的。p 会随防守变化，一次排序的结论不能管一年。这时的正确做法是定期重估，并监控 p 的变化（红队，第 6 章）。
  • 当决策是 0/1 时（做或不做某功能）。R 排序只回答"先做哪个"，不回答"该不该做这个功能"。后者要用"残余风险是否在容忍度内"来判，是一个阈值判断，不是一个排序判断。

八、边界与开放问题#

  1. 本节没有给出 p 的测量方法。 §三 里所有 p 都是合成常数。真实的 p 怎么测 —— 红队的样本量与置信区间、自动化攻击的成功率曲线 —— 是第 2 章与第 6 章的内容。
  2. 本节没有处理多步攻击。 真实攻击常常是链式的（先注入拿到凭据，再用凭据扩权）。链式攻击的 p 是各步 p 的乘积（若独立），但也可能因为一步成功而改变后续步骤的可行性（条件依赖）。这是攻击图（attack graph）的领域，本节只做单边估计。
  3. 资产的 c 里有一项在本节被刻意回避了：用户伤害。它难以货币化，而把它压成一个数会掩盖伦理判断。本课最后一章会回到"哪些风险不该被折算"。
  4. "暴露量 N"的定义依赖业务口径，而安全团队通常不掌握业务口径。这是一个组织问题，不是技术问题 —— 但它决定了整张表能不能算。

def lognormal_ci(mean, sigma, z=1.6448536269514722):
    """对数正态：给定均值 mean 与对数标准差 sigma，返回 (中位数, 5%, 95%)。"""
    mu = math.log(mean) - sigma * sigma / 2.0
    return math.exp(mu), math.exp(mu - z * sigma), math.exp(mu + z * sigma)

小结#

  • 一句没有分母的安全断言不可检验、不可排序、不可修复。 同一个 p=0.05，在公开问答、企业内部问答、受控运维助手三档部署下的年化风险是 5000、67500、600000 元 —— 差 120 倍，而"越狱率"一模一样。所以风险必须写成 R=∑i​Ni​pi​Ei​ci​，四个因子缺一不可。
  • 威胁模型有五个必须写出来的槽位：资产 A、对手 O、边界 B、通路 H、失效 F。它们单向依赖：O 决定有哪些 H，H×A 才有 R，F 是"以为切断了其实没断"的那些边。顺序颠倒会得到一张好看但无法执行的表。
  • 把"这是不是一个真的风险"问成三个可操作的问题：分母是多少（N、E、c）？对手有哪四个能力（Q、P、W、S）？每段文本最后一次被谁写过、检查的是格式还是语义？第三个问题的杀伤力最大 —— 它直接暴露"没做语义层信任分级"这件事。
  • "黑盒/灰盒/白盒"不够用：四维能力向量才能刻画 LLM 系统的对手，因为 C 档（不可查询、不可改提示、只可写被检索内容）在旧分级里根本不存在。四维不构成全序，所以不能用"弱/中/强"代替。
  • 资产必须带单位与量级，c 必须拆三项。 算例里 c 的跨度是 20000 倍，处置成本占 53.3% / 64.6% —— 只算 cdirect​ 会把风险低估 2 倍以上，而且会改变排序。
  • 信任边界要画在"这段文本怎么进入上下文"的链路上，其中 B4（外部写者 → 被检索位置）是 LLM 系统特有的、也最常被漏掉的一条；边界有"宽度"，用可控词元占比 ρ 度量（算例 0.1111∼0.2161）。
  • 每条防护必须写失效条件（覆盖失效 / 判据失效 / 结构失效 / 人的失效），并把残余风险算成 Rres​=R⋅(1−κ(1−qbypass​))。算例：名义削减 60% 的输入过滤，在编码绕过面前只剩 6% 的有效削减（Rres​=56400 元）。
  • R 的绝对值不可信，它的排序可信。 σ=1.5 时第 1 名通路的 90% 区间上界是中位数的 36.3 倍；全局同向误差不改排序，局部误差才改排序（把第 3 名的 N 放大 100 倍它直接升到第 1）—— 所以估参必须逐条做。
  • 缓解措施要按边际收益排序，而不是按"听起来重要"排序：算例里 ROI 最高的是"工具写操作人工审批"（22.80，本质是把 E 从 1.0 压下来），最低的是"逐字串训练侧去重"（0.00）。多条措施作用于同一条通路时不能线性相加：真实削减是 1−(1−0.70)(1−0.80)=0.94，线性相加会算成 1.50。
  • 取舍：c 量纲不可比时不该塞进 R（要用分列约束）；对手是适应性的时候排序一年就过期；R 只回答"先做哪个"，不回答"该不该做这个功能"。

下一节：威胁模型表写完之后，最上面那两条通路（模型权重 3000000 元、运维凭据 2880000 元）还只是两个数字 —— 我们并不知道对手怎么走到那一步。第 2 节要解决的问题正是这一点：为什么"把数据当指令执行"不是实现缺陷而是自回归语言模型的结构性后果；如何用可控词元占比 ρ 与对输出的干预效应写出可利用性判据（而不是招式清单）；间接注入为什么把攻击面从"能接触模型的人"扩展到"能往被检索位置写字的人"（即本节的 C 档对手）；以及多轮绕过里约束为什么会衰减 —— 并给出 KL(pfree​∥pguard​) 这个把"安全约束压掉了多少"变成数字的量。
