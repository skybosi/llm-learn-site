与框架衔接：自定义算子、CUDA Graphs、动态 shape#

一个在微基准里快 3 倍的 kernel，接进训练脚本后可能一点都不快——甚至更慢。原因通常不在 kernel 内部，而在衔接面：框架不认识它（编译器把它当黑盒或直接报错）、每次迭代要发射几十个 kernel（CPU 发射成瓶颈）、输入的序列长度一直在变（刚实例化的图就失效）。本课把这三件事拆成注册、调度、形状三层，逐层给出可运行的判据。

一、概念讲解#

1. 三层衔接面#

层 要解决的问题 框架侧的手段
注册 让框架知道这个算子，且能推导形状、能求导 torch.library.custom_op + fake kernel + autograd
调度 用很少的 CPU 开销把整段工作交给 GPU CUDA Graphs（stream capture / Graph API）
形状 让上面两件事在 shape 变化时仍然成立 分桶（bucketing）+ 按桶各持一张图

三层是依赖顺序：注册没做对，后面的图与分桶无从谈起。

2. 自定义算子：schema 与 fake kernel 不是形式主义#

PyTorch 官方指南把三件事列为自定义算子的必备项：稳定的 schema 与变异/别名契约、用 torch.library.opcheck 校验、返回张量时必须提供 fake kernel（否则 torch.compile 与 torch.export 用不了）。torch.compile 要先把图 trace 出来而不真正执行，需要"只算形状不算数"的 fake 实现推导输出元信息；schema 里的 mutates_args 告诉编译器这次调用会不会改写输入——声明错了，编译器可能合并两次调用或错误复用缓冲区。

注册形态是 @torch.library.custom_op("lib::name", mutates_args=()) 加一个 @op.register_fake；较新版本还有 torch.library.triton_op/wrap_triton 专门包 Triton kernel。更早的写法 torch.library.Library("lib","DEF").define(schema) + impl(...) + impl_abstract(...) 语义相同；示例代码两条路都实现并运行时探测（本机 2.3.1 走旧路径）。

3. CUDA Graphs：把 N 次发射压成 1 次#

官方把建图分成 定义 → 实例化 → 执行 三阶段：定义时描述节点与依赖，实例化时"对图模板做快照、校验，并完成大部分初始化工作"，之后可执行图（executable graph）能被反复发射而不必重新实例化。理由就是 CPU 发射成本：向流里放 kernel 时驱动要做一连串准备，这笔开销每个 kernel 都要付一次，"对执行时间很短的 kernel，可能占端到端时间的很大比例"。

建图有两条路：Graph API（cudaGraphCreate() + cudaGraphAddNode()，后者统一了早期按类型分的 cudaGraphAddKernelNode() 之类）与 stream capture（cudaStreamBeginCapture()/cudaStreamEndCapture() 把已有流式代码括起来，捕获期间的工作只被记录、不执行）。硬约束：legacy default stream（NULL stream）不可捕获（per-thread stream 可以）；捕获中的流与捕获事件不能同步、不能查询状态，cudaMemcpy() 这类会同步的 API 在捕获期间无效；跨流依赖要用 cudaEventRecord/cudaStreamWaitEvent 表达，参与捕获的流最后都要 rejoin 回 origin stream。

参数变化时不必重建图：cudaGraphExecUpdate(hGraphExec, hGraph, &resultInfo) 用新图的节点参数更新已实例化图，前提是两张图拓扑相同（"topologically identical"），否则返回更新失败。另有 cudaGraphInstantiateFlagAutoFreeOnLaunch（每次发射自动释放未释放的分配）与 cudaGraphUpload()（预先上传可执行图）。

PyTorch 把它包成 torch.cuda.CUDAGraph、torch.cuda.graph、torch.cuda.make_graphed_callables（官方标注 beta）：捕获前在 side stream 上预热；每次重放读写同一批内存地址，输入/输出张量须长期持有；换数据就拷进捕获时的输入张量再 replay()。

4. 动态 shape：不是优化技巧，而是前置条件#

PyTorch 文档在"会静默出错或未定义行为"一档里明确写着：Dynamic shapes are prohibited——图假定捕获序列里每个张量在每次重放的尺寸与布局都一致。于是"处理动态 shape"变成三种工程选择：

策略 图的数量 计算浪费 适用
pad 到全局最大 1 最大（长尾下可达数倍） 长度分布集中且浪费可接受
定宽分桶（如 128 一档） 中 小 想精确控制浪费
2 的幂分桶 少 中 最常用的折中：图数是个位数
逐 shape 各一张图 极多 0 只在长度取值很少时可行

判据不是"哪个浪费最少"，而是总成本 = 填充后 token 数 × 单位成本 + 图数量 × 实例化成本；示例 A 把这张表算成数字。

5. 常见坑#

  • 在 forward 里直接调 CUDA 扩展：能跑，但编译器看不到契约，会被当图断点。
  • 忘了 fake kernel：eager 正常、torch.compile 报错，且报错不指向根因。
  • 捕获前不预热：首次调用的惰性初始化（内存池、cuBLAS 句柄、autotune）会被录进图或让捕获失败。
  • mutates_args 声明错：编译器做出错误的复用/合并决策，症状是数值悄悄错。
  • 捕获区域里有 .item()：捕获期间禁止 CPU-GPU 同步，直接报错。
  • 指望 cudaGraphExecUpdate 改形状：它要求拓扑相同；换 bucket 应每桶各实例化一张图。

二、可运行代码示例#

示例 A：graph 盈亏平衡点 + 动态 shape 分桶账（纯 numpy）#

# ===== 本课示例 A：graph 的盈亏平衡点 + 动态 shape 的分桶账（纯 numpy，无 GPU）=====
import numpy as np

# ---------- 1. 流式提交 vs graph 重放：什么时候 graph 才划算 ----------
# 参数都是"待实测"的占位值：用 nsys 量你自己的 CPU 发射耗时与 kernel 时长再替换。
LAUNCH_US = 8.0    # 每个 kernel 的 CPU 发射开销（示例占位）
EXEC_US = 3.0      # 每个 kernel 的 GPU 执行时间（示例占位）
N_OPS = 40         # 一次迭代里有几个 kernel
INSTANTIATE_US = 2000.0   # 一次 cudaGraphInstantiate 的一次性成本（示例占位）
GRAPH_LAUNCH_US = 10.0    # 一次整图 cudaGraphLaunch 的 CPU 开销（示例占位）

def t_stream(iters):
    return iters * N_OPS * max(LAUNCH_US, EXEC_US)   # CPU 发射成为瓶颈则等 CPU

def t_graph(iters):
    return INSTANTIATE_US + iters * (N_OPS * EXEC_US + GRAPH_LAUNCH_US)

denom = N_OPS * (LAUNCH_US - EXEC_US) - GRAPH_LAUNCH_US
breakeven = INSTANTIATE_US / denom if denom > 0 else float("inf")
print(f"设置：{N_OPS} 个 kernel/迭代；发射 {LAUNCH_US} us，执行 {EXEC_US} us"
      f" -> {'CPU 发射是瓶颈' if LAUNCH_US > EXEC_US else 'GPU 执行是瓶颈'}")
print(f"盈亏平衡迭代数 = 实例化成本 / 每迭代省下的时间 = {breakeven:.1f} 次\n")
print(f"{'迭代次数':>8}{'流式总时长(ms)':>16}{'graph 总时长(ms)':>18}{'加速比':>9}")
for it in (1, 10, 50, 100, 1000):
    a, b = t_stream(it) / 1000, t_graph(it) / 1000
    print(f"{it:>8}{a:>16.3f}{b:>18.3f}{a/b:>8.2f}x")
print(f"判读：图把每迭代的 CPU 开销从 {N_OPS} 次发射压成 1 次；迭代次数低于平衡点时"
      "实例化成本收不回来 —— 这就是「短命 workload 别上 graph」的量化依据。")

# ---------- 2. 动态 shape：分桶的浪费 vs 重新实例化的次数 ----------
rng = np.random.default_rng(0)
lens = np.clip(rng.lognormal(mean=5.5, sigma=0.9, size=512).astype(int), 16, 4096)
MAXLEN = int(lens.max())

def bucket_pow2(n):
    b = 16
    while b < n:
        b *= 2
    return b

def bucket_fixed(n, width=128):
    return int(np.ceil(n / width) * width)

strategies = {
    "pad 到全局最大": np.full_like(lens, MAXLEN),
    "2 的幂分桶": np.array([bucket_pow2(n) for n in lens]),
    "定宽 128 分桶": np.array([bucket_fixed(n) for n in lens]),
    "不定桶（逐 shape）": lens.copy(),
}
PER_TOKEN_US = 0.02   # 每个（填充后）token 的计算成本占位值
print(f"\n请求数 {len(lens)}，长度 min={lens.min()} max={MAXLEN} "
      f"mean={lens.mean():.0f}；实际 token {lens.sum():,}")
print(f"{'策略':<20}{'填充后 token':>14}{'浪费':>9}{'不同 shape 数':>14}"
      f"{'实例化成本(ms)':>15}{'总成本(ms)':>12}")
for name, padded in strategies.items():
    waste = padded.sum() / lens.sum() - 1
    n_shapes = len(np.unique(padded))
    inst = n_shapes * INSTANTIATE_US / 1000
    total = padded.sum() * PER_TOKEN_US / 1000 + inst
    print(f"{name:<20}{padded.sum():>14,}{waste:>8.0%}{n_shapes:>14}{inst:>15.1f}{total:>12.1f}")
n_exact = len(np.unique(lens))
print(f"判读：不定桶浪费 0%，但要维护 {n_exact} 张图，实例化成本压倒一切；")
print("      2 的幂分桶把图的数量压到个位数、浪费仍在可接受范围 —— 这才是工程选择。")
print("      注意：CUDA Graphs / torch.cuda.graph 明确要求静态 shape，"
      "所以「分桶」不是优化技巧而是前置条件。")

示例 B：注册成框架算子 + graph 安全体检（torch，CPU）#

# ===== 本课示例 B：把 kernel 注册成框架算子 + graph 安全体检 =====
# 依赖 torch（CPU 即可，无需 GPU）。真实 kernel 换成 C++/CUDA 实现，注册协议完全相同。
import torch

SCHEMA = "fused_scale_bias(Tensor x, Tensor scale, Tensor bias) -> Tensor"

def _impl(x, scale, bias):
    """占位实现：真实现是 CUDA kernel；这里保持数值语义一致以便验收。"""
    return x * scale + bias

def _abstract(x, scale, bias):
    return torch.empty_like(x)

if hasattr(torch.library, "custom_op"):                 # 新路径：较新版本才有（本机 2.3.1 无）
    @torch.library.custom_op("gck::fused_scale_bias", mutates_args=())
    def fused_scale_bias(x: torch.Tensor, scale: torch.Tensor, bias: torch.Tensor) -> torch.Tensor:
        return _impl(x, scale, bias)

    @fused_scale_bias.register_fake
    def _(x, scale, bias):
        return _abstract(x, scale, bias)

    op, path = torch.ops.gck.fused_scale_bias, "torch.library.custom_op + register_fake"
else:                                                    # 旧路径：更早版本
    _lib = torch.library.Library("gck", "DEF")
    _lib.define(SCHEMA)
    _lib.impl("fused_scale_bias", _impl, "CPU")
    _lib.impl("fused_scale_bias", _abstract, "Meta")     # Meta 实现 = fake kernel
    op, path = torch.ops.gck.fused_scale_bias, "torch.library.Library(define/impl/impl_abstract)"

print(f"torch {torch.__version__}；注册路径：{path}")
print(f"算子 schema：{op.default._schema}\n")

# ---------- 正确性验收：必须与参考实现逐元素对齐 ----------
torch.manual_seed(0)
x = torch.randn(4, 8)
s, b = torch.tensor(2.0), torch.tensor(-0.5)
got, ref = op(x, s, b), x * s + b
print(f"[正确性] shape={tuple(got.shape)} dtype={got.dtype} "
      f"max|got-ref|={float((got - ref).abs().max()):.1e} "
      f"-> {'PASS' if torch.allclose(got, ref, atol=1e-6) else 'FAIL'}")

# ---------- opcheck：框架侧的契约体检 ----------
if hasattr(torch.library, "opcheck"):
    res = torch.library.opcheck(op, (x, s, b))
    print(f"[opcheck] {sum(1 for v in res.values() if v == 'PASS')}/{len(res)} 项通过")
else:
    print("[opcheck] 本机 torch 无 torch.library.opcheck（较新版本才有，2.3.1 无），"
          "跳过；你的版本若有该 API，务必跑一次。")

# ---------- graph 安全体检：按 CUDA Graphs 的硬约束逐条查 ----------
RULES = [
    ("capture_on_side_stream", "捕获必须在非默认流上（默认流不可捕获）"),
    ("no_host_sync", "禁止任何 CPU-GPU 同步（.item()/print 张量/隐式搬运）"),
    ("static_shape", "禁止动态 shape：每次重放张量尺寸与布局必须一致"),
    ("static_control_flow", "禁止动态控制流（除非用 torch.cond 之类的图内算子）"),
    ("no_alloc_in_capture", "捕获期间不要临时分配（用 graph 私有内存池/预分配输出）"),
    ("single_capture", "同一进程同一时刻只允许一次捕获进行中"),
]
OPS = [  # 一个假想的 fused attention 前向链（示例数据）
    ("embedding", dict(capture_on_side_stream=True, no_host_sync=True, static_shape=True,
                       static_control_flow=True, no_alloc_in_capture=True, single_capture=True)),
    ("shape_dispatch", dict(capture_on_side_stream=True, no_host_sync=True, static_shape=False,
                            static_control_flow=True, no_alloc_in_capture=True, single_capture=True)),
    ("top_p_filter", dict(capture_on_side_stream=True, no_host_sync=False, static_shape=False,
                          static_control_flow=False, no_alloc_in_capture=True, single_capture=True)),
    ("fused_scale_bias", dict(capture_on_side_stream=True, no_host_sync=True, static_shape=True,
                              static_control_flow=True, no_alloc_in_capture=False, single_capture=True)),
]
print("\n[graph 体检] 逐算子对照硬约束（同一时刻只允许一次捕获：全局约束，逐算子默认满足）")
bad_total = 0
for name, flags in OPS:
    bad = [(k, why) for k, why in RULES if not flags.get(k, True)]
    bad_total += len(bad)
    print(f"  {name:<18} {'可捕获' if not bad else f'不可捕获（{len(bad)} 条违规）'}")
    for k, why in bad:
        print(f"      - 违反 {k}：{why}")
print(f"\n判读：一个 capture 区域里只要有 1 个算子违规，整段就不可捕获 —— "
      f"共发现 {bad_total} 条违规，需要先把它们移出 capture 或改写成图内算子。")

三、练习#

  1. 实现：给示例 B 的 fused_scale_bias 加 out= 版本（写入传入的输出缓冲），把 mutates_args 改成 {"out"}，并说明为什么声明成"不改输入"会让编译器做出错误假设。
  2. 解释：示例 A 中 1000 次迭代的加速比 2.42x，忽略实例化成本的理论上限是 40×8/(40×3+10)≈2.46。这 0.04x 从哪来？
