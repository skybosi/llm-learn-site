三地址码：为什么几乎所有优化都建在它上面#

打开任何一个真实编译器，你会发现绝大多数优化 pass 都不读语法树：LLVM 的 opt 只吃 IR，GCC 的优化跑在 GIMPLE 上。为什么大家宁愿先花力气"翻译"一遍，也不直接在 AST 上做优化？答案有一部分是数据结构选择：三地址码（three-address code，TAC）。这一课要说清它的准确形状，以及它凭什么让常量折叠、公共子表达式消除、死代码消除都愿意建在它上面。

一、概念讲解#

1. 一个 IR 要满足哪四个条件，才配被反复优化#

优化 pass 的本质是"在某种表示上做模式匹配，再改写"。要让这件事成立，表示必须同时满足四条：

  1. 每条指令职责单一：一行只做一个运算，pass 才能用有限的模式枚举它。
  2. 定义与使用显式：t1 = a + b 直接说明 t1 由谁算出、a、b 被谁使用，不必穿过父节点找依赖。
  3. 顺序显式：程序点可比较，"第几条指令"即执行顺序的近似（有跳转时换成 CFG）。
  4. 名字可再生：临时名要多少有多少；IR 阶段故意用得很奢侈，把"名字不够"留给后端。

AST 有三条不达标：它是嵌套的（条件 1、3 不满足）；同一子表达式在树里是两棵独立子树，"它们同值"只能靠子树同构去判；想在中间插入临时结果，还得改父节点。

2. 三地址码的定义与指令种类#

三地址码是"每条指令最多一个运算符、最多三个地址"的 IR，典型形式 x = y op z；x、y、z 都是名字——源程序变量、常量，或编译器生成的临时名（temporary）。这套记法出自龙书《Compilers: Principles, Techniques, and Tools》§6.2.3。

类别 形式 说明
复制 x = y 赋值、参数搬运、退出 SSA 后的产物
二元运算 x = y op z 算术与位运算
无条件跳转 goto L 标签由 lowering 生成
条件跳转 if x relop y goto L 比较与跳转合成一条
过程调用 param x；call p, n 参数传递与调用分开，n 是参数个数
索引与指针 x = y[i]、x[i] = y、x = &y、x = *y 数组访问与取地址

同一套指令有三种等价记法：四元式（(op, arg1, arg2, result) 四元组）、三元式（省略 result，用"第几条指令"引用结果）、间接三元式（三元式加一个指令指针数组，移动指令时不必重编号）。本课用四元式，调试时最好读。

3. 一段例子：AST 怎么变成 TAC#

源码 d = (a + b) * c; e = (a + b) / c;。后序遍历下降（先子后父）之后是 6 条指令：t1 = a + b、t2 = t1 * c、d = t2、t3 = a + b、t4 = t3 / c、e = t4。

关键观察：同一个式子 a + b 出现两次，naive 下降就算了两遍，而第二次 add 是多余的——值编号（value numbering）发现 t3 与 t1 右值相同，换成 t3 = copy t1，一次加法消失。"右值相同"在 TAC 里就是两个可直接比较的元组，在 AST 里却是子树同构判定。

4. 为什么几乎所有优化都建在它上面#

优化 在 TAC 上的样子 依赖哪条性质
常量折叠 两个操作数都是常量 → 直接算出结果 指令职责单一
公共子表达式消除 右值相同的指令只留一条，其余改 copy 名字可再生
到达定值 / 活跃变量 逐条求 def/use 集合，在图上迭代到不动点 def/use 显式
死代码消除 结果无 use 且无副作用 → 删除 副作用可枚举
强度削减 x * 2 → x + x 指令种类少
循环不变量外提 同一条指令搬到循环外 顺序显式 + 可移动

最后一行背后的东西尤其重要：这些 pass 都不需要知道源语言长什么样，只认指令形状与数据流事实——这正是 LLVM 用同一套优化服务 C、C++、Rust、Swift 的原因。

5. TAC 不是唯一选择：四种 IR 风格#

Crafting Interpreters 第 2 章 §2.1.4 列出的 IR 风格检索词正是 control flow graph、static single-assignment、continuation-passing style 与 three-address code。

形式 值放在哪 例子
名字式三地址码 有名字的临时量 本课的 (add, a, b, t1)
栈式字节码 隐式操作数栈 CPython 的 LOAD_FAST / BINARY_ADD
SSA 每个名字只被赋值一次 LLVM IR 的 %x = add i32 %a, %b（第 3 课）
图 IR 节点=运算，边=数据依赖 AST、DAG、数据流图

本课站在最基础的那一格：LLVM IR 可以看作"类型化 + SSA 化 + 名字化"的三地址码，CPython 字节码则是"栈式"的三地址码。

6. 常见坑#

  • 把 TAC 当可执行代码：它没有寄存器、栈帧与调用约定，那些全是后端的事。
  • 忽略名字重定义：sum = sum + i 两边是两个不同的值，值编号时必须让旧编号失效；本课示例假设块内每个变量只定义一次，SSA 把这条假设变成制度（第 3 课）。
  • 把有副作用的指令当纯表达式：过程调用与数组写不能因结果没人用就删。
  • 用局部冒充全局：值编号只在块内成立，跨块要 CFG + 数据流（下一课）。
  • 让短路被优化掉：if (a != 0 && b / a > 0) 不能降成"先算 b / a 再合并"——短路是语义。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）把"表达式 → 四元式 → 局部值编号"走通，并打印每条指令的 def/use 集合——后者正是第 5 章数据流分析的原料。

# ---- 三地址码生成 + 局部值编号（纯 Python，无第三方依赖）----
import re

TOKEN = re.compile(r'\s*(?:(\d+)|([a-zA-Z_]\w*)|([-+*/()=;]))')

def tokenize(src):
    """词法分析：字符流 → token 流（只认数字、标识符、运算符与分号）"""
    out, i = [], 0
    while i < len(src):
        m = TOKEN.match(src, i)
        if not m:
            raise SyntaxError(f'非法字符 {src[i]!r} at {i}')
        i = m.end()
        num, name, op = m.groups()
        if num:    out.append(('NUM', int(num)))
        elif name: out.append(('NAME', name))
        else:      out.append(('OP', op))
    return out

def parse(tokens):
    """语法分析：只处理 '名字 = 表达式 ;' 的直线序列（控制流留到下一课）"""
    pos = 0
    def peek(): return tokens[pos] if pos < len(tokens) else (None, None)
    def eat(kind, value=None):
        nonlocal pos
        k, v = peek()
        if k != kind or (value is not None and v != value):
            raise SyntaxError(f'期望 {kind}{value or ""}，得到 {(k, v)}')
        pos += 1
        return v
    def expr():
        node = term()
        while peek() in (('OP', '+'), ('OP', '-')):
            node = ('bin', eat('OP'), node, term())
        return node
    def term():
        node = atom()
        while peek() in (('OP', '*'), ('OP', '/')):
            node = ('bin', eat('OP'), node, atom())
        return node
    def atom():
        k, v = peek()
        if k == 'NUM':  eat('NUM');  return ('num', v)
        if k == 'NAME': eat('NAME'); return ('var', v)
        if (k, v) == ('OP', '('):
            eat('OP', '('); node = expr(); eat('OP', ')'); return node
        raise SyntaxError(f'表达式起始处意外 token {(k, v)}')
    prog = []
    while pos < len(tokens):
        name = eat('NAME'); eat('OP', '=')
        prog.append(('assign', name, expr())); eat('OP', ';')
    return prog

OPNAME = {'+': 'add', '-': 'sub', '*': 'mul', '/': 'div'}

class TACGen:
    """三地址码：四元式 (op, arg1, arg2, result)，每条指令最多一个运算"""
    def __init__(self):
        self.code, self.n = [], 0
    def tmp(self):
        self.n += 1
        return f't{self.n}'
    def emit(self, op, a1, a2, res):
        self.code.append((op, a1, a2, res))
    def gen(self, node):
        k = node[0]
        if k == 'num': return ('const', node[1])
        if k == 'var': return ('name', node[1])
        _, op, l, r = node
        a1, a2 = self.gen(l), self.gen(r)      # 先子后父 = 后序遍历
        res = self.tmp()                       # 名字可再生：临时名要多少有多少
        self.emit(OPNAME[op], a1, a2, res)
        return ('name', res)
    def program(self, prog):
        for _, name, e in prog:
            self.emit('copy', self.gen(e), None, name)
        return self.code

def def_use(instr):
    """每条指令的 (定义, 使用集合) —— 数据流分析的基本原料"""
    op, a1, a2, res = instr
    uses = [x[1] for x in (a1, a2) if x and x[0] == 'name']
    return res, uses

def local_cse(code):
    """局部值编号：块内相同右值只算一次，后续重算改成 copy。
    注意：假设每个变量在块内只定义一次（否则旧的右值编号必须失效）。"""
    vnum, out = {}, []
    for op, a1, a2, res in code:
        if op == 'copy':
            key = ('copy', a1, a2)
            if key in vnum:
                out.append(('copy', ('name', vnum[key]), None, res))
            else:
                vnum[key] = res
                out.append((op, a1, a2, res))
            continue
        key = (op, a1, a2)
        if key in vnum:
            out.append(('copy', ('name', vnum[key]), None, res))   # 复用已有结果
        else:
            vnum[key] = res
            out.append((op, a1, a2, res))
    return out

def show(code, title):
    print(f'--- {title}（{len(code)} 条）---')
    for i, (op, a1, a2, res) in enumerate(code):
        def fmt(x): return '-' if x is None else (str(x[1]) if x[0] == 'name' else f'#{x[1]}')
        d, u = def_use((op, a1, a2, res))
        print(f'{i:>2}: {res:<4} = {op:<4} {fmt(a1):<4} {fmt(a2):<4}  def={d} use={u}')

def arith(code):
    return sum(1 for i in code if i[0] in OPNAME.values())

def copies(code):
    return sum(1 for i in code if i[0] == 'copy')

src = 'd = (a + b) * c; e = (a + b) / c;'
tac = TACGen().program(parse(tokenize(src)))
after = local_cse(tac)
show(tac, 'lowering 后的三地址码')
show(after, '值编号/公共子表达式消除后')
print(f'\n算术指令：{arith(tac)} → {arith(after)}；copy 指令：{copies(tac)} → {copies(after)}')

运行结果（每条指令后面直接列出 def/use，便于人工核对）：

--- lowering 后的三地址码（6 条）---
 0: t1   = add  a    b     def=t1 use=['a', 'b']
 1: t2   = mul  t1   c     def=t2 use=['t1', 'c']
 2: d    = copy t2   -     def=d use=['t2']
 3: t3   = add  a    b     def=t3 use=['a', 'b']
 4: t4   = div  t3   c     def=t4 use=['t3', 'c']
 5: e    = copy t4   -     def=e use=['t4']
--- 值编号/公共子表达式消除后（6 条）---
 0: t1   = add  a    b     def=t1 use=['a', 'b']
 1: t2   = mul  t1   c     def=t2 use=['t1', 'c']
 2: d    = copy t2   -     def=d use=['t2']
 3: t3   = copy t1   -     def=t3 use=['t1']
 4: t4   = div  t3   c     def=t4 use=['t3', 'c']
 5: e    = copy t4   -     def=e use=['t4']

算术指令：4 → 3；copy 指令：2 → 3

指令条数没变（6 → 6），但算术指令从 4 条降到 3 条，多出来的那条是廉价的 copy。这一点很重要：优化 pass 的收益要按"贵指令减少、便宜指令增加"来算，而不是按总条数。

三、练习#

  1. 实现：给 local_cse 增加常量折叠——两个操作数都是常量时直接算出结果、改成 copy #值；用 d = (2 + 3) * c; 验证。
  2. 解释：为什么三地址码要限制"每条指令最多一个运算符"？允许 t = a + b * c 会让 pass 在哪些地方变复杂？
  3. 对比/验证：把例 1 的 TAC 与 clang -O0 -emit-llvm 对同一段 C 代码的 IR 并排比较，列出三点差异（提示：类型、alloca/load/store、SSA 名字）并解释来源。
  4. 思考：临时名"无限供应"为什么对后端重要？若 IR 只允许 8 个名字，编译器被迫在什么时候做寄存器分配，代价是什么？
