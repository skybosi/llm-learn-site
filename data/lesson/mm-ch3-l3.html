采样与加速#

文生图模型"质量高"和"采样慢"是一体两面：第 2 章的 DDPM 要跑 T=1000 步，每步都过一次 U-Net，慢得难以商用。这一课解决这个问题——在几乎不损失质量的前提下，把采样步数从上千步压到几十步甚至个位数。核心是三件事：更聪明的采样调度器、确定性去噪（DDIM）带来的跳步能力，以及蒸馏等工程加速手段。

一、概念讲解#

1. 采样调度器：决定"怎么一步步去噪"#

调度器（scheduler）是去噪循环的"步进策略"，决定每步减多少噪声、注不注入随机噪声。不同调度器的数学形式不同，但都围绕第 2 课的骨架变形：

  • DDPM 调度器：第 2 课的原版，随机采样，需 T 步，最慢但理论最正；
  • DDIM 调度器：把采样改成确定性过程，允许跳步（如每 50 步取 1 步），几十步即可；
  • PNDM / Euler / DPM-Solver：高阶数值求解器，用更少步逼近更优解，是 diffusers 的常见默认。

2. DDIM：确定性 + 跳步是"加速"的钥匙#

DDIM 的关键洞见：采样不必严格沿马尔可夫链一步一步走。它把 DDPM 的随机采样改写成确定性映射，于是可以只选子序列 {t_1, t_2, ...} 采样——1000 步缩到 50 步甚至 20 步，质量仍保持很好。直觉上，"去噪"是一个平滑过程，相邻两步高度冗余，跳着走损失很小。

代价是：确定性采样牺牲了随机多样性（同一个噪声种子永远出同一张图），且步数过低时质量仍会明显下滑。但对"快"的需求来说，这笔交易非常划算。

3. 从潜变量到图像：解码也是成本#

别忘了 Stable Diffusion 的流水线末端还有一步：VAE 解码器把潜变量放大 8 倍成像素。它只跑一次前向，通常远快于去噪循环，但在极速场景（个位数采样步）里占比会凸显。整体耗时 = 去噪步数 × U-Net 单步耗时 + VAE 解码耗时，加速要同时盯着这两项。

4. 工程与算法层面的更多加速#

  • 蒸馏：把"50 步的模型"蒸馏成"1~4 步的学生模型"。代表有 LCM（Latent Consistency Models）、Turbo/SDXL-Turbo，能在极少步数内逼近原质量；
  • 精度与量化：fp16/bf16、INT8 量化，降低单步算力；
  • 缓存与算子：缓存文本嵌入、VAE 结果；用 TensorRT、xFormers（省显存注意力）等加速算子；
  • 换小模型：SD 1.5 / SDXL / SD 2.1 参数量差异大，选小模型本身就是最直接的加速。

5. 质量—速度的权衡总结#

方法 典型步数 质量 特点
DDPM 1000 高 理论正、最慢
DDIM 20~50 高 确定性、可跳步
DPM-Solver / PNDM 20~50 很高 高阶求解、默认首选
LCM / Turbo（蒸馏） 1~4 较高 极快、适合实时

结论一句话：默认用 DPM-Solver 类调度器跑 25 步；追求极致速度上蒸馏模型；追求最大多样性用 DDPM。 选型本质是在"步数、质量、多样性"三者间找平衡。

二、可运行代码示例#

用 diffusers 在同一句 prompt 下切换调度器与步数，直接对比效果。首次运行会下载权重。

from diffusers import (
    StableDiffusionPipeline,
    DDIMScheduler,
    DPMSolverMultistepScheduler,
)
import torch

pipe = StableDiffusionPipeline.from_pretrained(
    "runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16
).to("cuda")

prompt = "a red panda reading a book, studio light"

# 1) 默认调度器（PNDM），25 步
img1 = pipe(prompt, num_inference_steps=25).images[0]
img1.save("pndm_25.png")

# 2) 换成 DDIM，15 步（确定性、更快，质量略降）
pipe.scheduler = DDIMScheduler.from_config(pipe.scheduler.config)
img2 = pipe(prompt, num_inference_steps=15).images[0]
img2.save("ddim_15.png")

# 3) 换成 DPM-Solver 多步，25 步（高阶求解，通常质量更高）
pipe.scheduler = DPMSolverMultistepScheduler.from_config(pipe.scheduler.config)
img3 = pipe(prompt, num_inference_steps=25).images[0]
img3.save("dpm_25.png")

print("已生成 pndm_25.png / ddim_15.png / dpm_25.png")

再体验一下蒸馏加速的威力（LCM，个位数步数）：

from diffusers import DiffusionPipeline
import torch

# —— LCM 蒸馏版：1~4 步即可出图，实时生成 ——
pipe = DiffusionPipeline.from_pretrained(
    "SimianLuo/LCM_Dreamshaper_v7", torch_dtype=torch.float16
).to("cuda")

prompt = "a red panda reading a book, studio light"
image = pipe(prompt, num_inference_steps=4, guidance_scale=8.0).images[0]
image.save("lcm_4.png")
print("已生成 lcm_4.png（仅 4 步）")

对比 ddim_15.png（15 步）与 lcm_4.png（4 步）：后者用不到三分之一的时间，画质却接近。这就是"蒸馏把几十步的知识压进几步"的直观效果。

三、练习#

  1. 固定 prompt，用同一调度器把 num_inference_steps 依次设为 5、10、25、50，逐张比较质量与耗时，画出"步数—质量"的经验曲线。
  2. 手推 DDIM 与 DDPM 的关键差异：说明 DDIM 去掉随机噪声项后为何变成确定性映射，以及"确定性"如何换来"可跳步"。
  3. 在代码里把调度器换成 EulerDiscreteScheduler 再跑 25 步，与 DPM-Solver 对比，说说不同高阶求解器之间的观感差异。
  4. 思考题：为什么"蒸馏"能让学生在 4 步内逼近教师 50 步的效果？从"蒸馏让学生直接学教师的多步映射结果"这个角度说明。
  5. 调研题：查阅 LCM（Latent Consistency Models）论文，了解"一致性模型"如何把多步采样压缩成极少数步，写一段 200 字以内的总结。
