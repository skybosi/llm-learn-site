控制流图（CFG）与基本块#

上一课得到的三地址码是一条直线序列，看起来"上一条指令就是前驱"。但只要出现一个 goto 或 if ... goto，这个直觉就崩了：第 7 条指令的前驱可能是第 4 条，也可能是第 20 条。偏偏"活跃变量""到达定值""可用表达式"这些分析全都定义在前驱 / 后继上。所以我们必须把线性序列重新组织成一张图：先切出基本块（basic block），再连成控制流图（control-flow graph，CFG）。

一、概念讲解#

1. 基本块：唯一入口，唯一出口#

基本块是一段连续的三地址码，满足两条约束：① 控制流只能从第一条指令进入；② 只能从最后一条指令离开。换句话说，块内没有跳转进出，块内指令严格顺序执行。

这两条约束看着朴素，却是"局部优化"的全部合法性来源：只要在块内，上一课的值编号、常量折叠就可以放心地做，因为没有任何一条路径能"绕过"或"插进"中间。

2. 怎么切：三条 leader 规则#

切块算法来自龙书 §8.4.1，只需两步：

  1. 找出所有 leader：第一条指令；任何跳转（goto、if ... goto）的目标；任何跳转的下一条指令。
  2. 从一个 leader 到下个 leader 之前，就是一个基本块。

第二条 leader 规则容易被忽略，但它决定了 CFG 的连通性：if 语句的 else 分支入口，正是"条件跳转的下一条指令"。

3. CFG：节点、边与两个虚拟节点#

CFG 中，节点是基本块，有向边 p → q 表示"执行完 p 可能接着执行 q"。边的来源只有两种：跳转指令显式给出的目标，以及条件跳转的顺序落下（fall-through）。为此通常额外加两个虚拟节点：entry（唯一入口）与 exit（唯一出口），让"有多个出口的函数"也满足单入口单出口的图论性质。

读论文常用的三个术语：入度 ≥ 2 的块是汇合块（join）；出度 ≥ 2 的块是分支块（branch）；存在一条能回到自己的路径的块叫循环头（loop header），那条边叫回边（back edge）。

4. 三种典型结构与一段真实代码#

结构 CFG 形状 关键位置
if (c) s1 else s2 菱形：条件块分出 then/else，再汇合 汇合块是 φ 的落点（下一课）
while (c) s 条件块在前，循环体末尾 goto 回条件块 回边落在条件块上
do s while (c) 循环体在前，条件块在末尾 回边落在条件块，体至少执行一次

把 if (a < b) x = 1; else x = 2; y = x + 1; 降级，得到：

cmp t1 = a < b; if t1 goto L1; goto L2; L1: x = 1; goto L3; L2: x = 2; goto L3; L3: y = x + 1

按 leader 规则切，得到 5 个块，其中 B2 只含一条 goto L2——它是"条件为假"的落点，却被 if 与 goto 夹成了一个独立块。这是"教科书算法 + naive lowering"的典型产物：块数不等于源码里的分支数。这类只含跳转的块在后续的块合并 pass 里会被清掉；但在做数据流分析时它们无害，只是多几轮迭代。

5. 为什么说 CFG 是"几乎所有优化"的地基#

有了 CFG，优化被分成两层：局部优化（块内，例如上一课的值编号）与全局优化（跨块，需要先知道"某个程序点上哪些事实一定成立"）。后者的统一做法是：给每个块设 in/out 两个集合，沿前驱／后继传播，迭代到不动点为止。第 5 章的数据流分析框架就是这套模板。

于是 CFG 的真正价值浮现出来：它把"程序"变成了一个有限的、可以求不动点的数据流问题。这是常量传播、死代码消除、循环不变量外提能够"跨块"工作的共同前提。

6. 常见坑#

  • 漏掉 fall-through 边：只把 goto 当边，条件为假的那条路径就丢了，CFG 会断开。
  • 把"标签"当成"块"：多个标签可以落在同一个块里，标签是名字，块是区间。
  • 不先清理不可达块：分析照样收敛，但算的是没人执行到的代码，结果没有意义。
  • 忽略间接控制流：函数指针调用、异常、longjmp 会让 CFG 缺边——这就是"保守分析"的来源。
  • 把块内指令当无序集合：x = 1; y = x 与 y = x; x = 1 不等价，块内顺序即语义。

二、可运行代码示例#

下面的纯 Python 代码（无第三方依赖）实现 leader 规则、切块、连边，并顺手算出前驱表、汇合块与可达性——这三样是数据流分析的直接输入。

# ---- 从三地址码切基本块并建 CFG（纯 Python，无第三方依赖）----
# 等价源码：if (a < b) x = 1; else x = 2;  y = x + 1;
N, C = 'name', 'const'
PROG = [
    ('cmp',    '<', (N, 'a'), (N, 'b'), 't1'),   # 0
    ('ifgoto', (N, 't1'), 'L1'),                 # 1  真 → L1
    ('goto',   'L2'),                            # 2  假 → L2
    ('label',  'L1'),                            # 3
    ('copy',   (C, 1), 'x'),                     # 4
    ('goto',   'L3'),                            # 5
    ('label',  'L2'),                            # 6
    ('copy',   (C, 2), 'x'),                     # 7
    ('goto',   'L3'),                            # 8
    ('label',  'L3'),                            # 9
    ('add',    (N, 'x'), (C, 1), 'y'),           # 10
    ('ret',    (N, 'y')),                        # 11
]
OPSYM = {'add': '+', 'sub': '-', 'mul': '*', 'div': '/'}

def val(x): return str(x[1]) if x[0] == 'name' else str(x[1])

def fmt(ins):
    t = ins[0]
    if t == 'copy':   return f'{ins[2]} = {val(ins[1])}'
    if t in OPSYM:    return f'{ins[3]} = {val(ins[1])} {OPSYM[t]} {val(ins[2])}'
    if t == 'cmp':    return f'{ins[4]} = {val(ins[2])} {ins[1]} {val(ins[3])}'
    if t == 'goto':   return f'goto {ins[1]}'
    if t == 'ifgoto': return f'if {val(ins[1])} goto {ins[2]}'
    if t == 'ret':    return f'return {val(ins[1])}'
    return str(ins)

def label_index(prog, name):
    return next(i for i, x in enumerate(prog) if x[0] == 'label' and x[1] == name)

def leaders(prog):
    """龙书 §8.4.1 的三条规则：① 首条指令 ② 跳转目标 ③ 跳转的下一条"""
    lead = {0}
    for i, ins in enumerate(prog):
        if ins[0] == 'goto':
            lead.add(i + 1); lead.add(label_index(prog, ins[1]))
        elif ins[0] == 'ifgoto':
            lead.add(i + 1); lead.add(label_index(prog, ins[2]))
    return sorted(i for i in lead if i < len(prog))

def split_blocks(prog, lead):
    blocks, label2block, names = [], {}, []
    for k, start in enumerate(lead):
        end = lead[k + 1] if k + 1 < len(lead) else len(prog)
        bid = f'B{k+1}'
        for ins in prog[start:end]:
            if ins[0] == 'label': label2block[ins[1]] = bid
        blocks.append((bid, [ins for ins in prog[start:end] if ins[0] != 'label']))
        names.append(bid)
    return blocks, label2block, names

def build_cfg(blocks, label2block, names):
    """后继由块的最后一条指令决定；边带一个来源标签，便于人核对"""
    succ, edges = {}, []
    order = {b: i for i, b in enumerate(names)}
    for bid, body in blocks:
        last = body[-1] if body else None
        fall = names[order[bid] + 1] if order[bid] + 1 < len(names) else None
        if last and last[0] == 'goto':
            succ[bid] = [(label2block[last[1]], '无条件')]
        elif last and last[0] == 'ifgoto':
            succ[bid] = [(label2block[last[2]], '条件为真')]
            if fall: succ[bid].append((fall, '条件为假'))
        elif last and last[0] == 'ret':
            succ[bid] = []
        else:
            succ[bid] = [(fall, '顺序')] if fall else []
        edges += [(bid, t, why) for t, why in succ[bid]]
    return succ, edges

def reachable(succ, entry):
    seen, stack = {entry}, [entry]
    while stack:
        for s, _ in succ[stack.pop()]:
            if s not in seen:
                seen.add(s); stack.append(s)
    return seen

blocks, label2block, names = split_blocks(PROG, leaders(PROG))
succ, edges = build_cfg(blocks, label2block, names)
preds = {b: [p for p in names if b in [t for t, _ in succ[p]]] for b in names}

print('基本块（leader =', leaders(PROG), '）:')
for bid, body in blocks:
    print(f'  {bid}: ' + '；'.join(fmt(i) for i in body))
print('\nCFG 边:')
for a, b, why in edges:
    print(f'  {a} → {b}   （{why}）')
print('\n前驱表:', {b: preds[b] for b in names})
print('汇合块（入度 ≥ 2）:', [b for b in names if len(preds[b]) >= 2])
r = reachable(succ, names[0])
print('可达块:', sorted(r), '｜ 不可达块:', sorted(set(names) - r) or '无')

运行结果：leader 落在下标 [0, 2, 3, 6, 9]，切出 5 个块，B2 是个只含跳转的"空转块"。

基本块（leader = [0, 2, 3, 6, 9] ）:
  B1: t1 = a < b；if t1 goto L1
  B2: goto L2
  B3: x = 1；goto L3
  B4: x = 2；goto L3
  B5: y = x + 1；return y

CFG 边:
  B1 → B3   （条件为真）
  B1 → B2   （条件为假）
  B2 → B4   （无条件）
  B3 → B5   （无条件）
  B4 → B5   （无条件）

前驱表: {'B1': [], 'B2': ['B1'], 'B3': ['B1'], 'B4': ['B2'], 'B5': ['B3', 'B4']}
汇合块（入度 ≥ 2）: ['B5']
可达块: ['B1', 'B2', 'B3', 'B4', 'B5'] ｜ 不可达块: 无

三个可直接核对的事实：B5 是唯一的汇合块（所以它会是下一课 φ 函数的落点）；所有块可达；B2 的出现说明"块数"由 lowering 的形态决定，而非源码的语法结构。

三、练习#

  1. 实现：给 leaders 补一条规则——ret 的下一条指令也是 leader（理由是什么？），并用一段含 return 的 TAC 验证你的实现。
  2. 解释：为什么基本块要求"唯一入口"？如果允许跳到块中间，上一课的值编号与第 5 章的活跃变量分析分别会怎样失效？
  3. 对比/验证：手写 do { s } while (c) 与 while (c) { s } 的两段 TAC，切块后比较两者的边数、回边位置与循环体入口块编号。
  4. 思考：异常（try/catch）与函数指针调用会怎样破坏"基本块只有唯一出口"的假设？编译器的 CFG 该怎样建模才既不漏边、又不至于把所有代码都连成一片？
