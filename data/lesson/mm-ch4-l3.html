零样本能力#

前两课我们建立了 CLIP 的对齐机制。现在到了收获的时刻：CLIP 最令人震撼的能力——零样本（zero-shot）分类。一个从未在 ImageNet 上训练过的模型，凭什么能在 ImageNet 的 1000 个类别上做到和有监督 ResNet-50 相当甚至更好的准确率？这一课就把它的原理、实现和边界彻底讲清楚。

一、概念讲解#

1. 什么是零样本：不训练，直接"读标签"#

传统分类模型要识别"斑马"，必须先见过几千张标注为"斑马"的图片。零样本的意思是：模型没见过任何一张标注了"斑马"的训练图，却能识别斑马。CLIP 之所以能做到，是因为它学到的不是"图 → 1000 个类别编号"的分类器，而是"图 ↔ 文本"的双向对齐。识别一个新类别时，你只需要做一件事——把这个类别的名字写成一句话，然后看哪句话和图片最匹配。

2. 零样本分类的完整流程#

给定一张待分类的图 x，和 K 个候选类别 {c₁, …, c_K}：

  1. 构造文本：把每个类别名填入一个 prompt 模板，例如 "a photo of a {class}"，得到 K 个句子。
  2. 文本编码：用文本编码器把 K 个句子编码成 K 个归一化向量 t₁…t_K。
  3. 图像编码：用图像编码器把 x 编码成归一化向量 i。
  4. 算相似度：计算 i 与每个 t_k 的余弦相似度。
  5. 归一化输出：对 K 个相似度做 softmax，取概率最大的类别作为预测。

整个过程没有任何训练、没有梯度更新，模型完全复用预训练时学到的对齐。你只需要决定"用什么话描述这个类别"。

3. prompt 模板与 prompt ensembling：措辞很关键#

零样本效果对措辞极其敏感。原论文发现，同样的类别，用 "a photo of a {class}" 和直接写 "{class}" 分类准确率能差好几个百分点。更妙的是，把多个模板的结果取平均（prompt ensembling）还能进一步稳定提升。

原论文为 ImageNet 准备了约 80 个模板，覆盖多种表达方式：

  • "a photo of a {class}, a type of {something}."
  • "a blurry photo of a {class}."
  • "a good photo of the {class}."
  • "an origami {class}."

做法是：每个模板各编码一次，把同一类别的所有模板向量先取平均得到该类的代表向量，再与图像向量算相似度。这样能降低单个模板措辞带来的偶然偏差，让分类更稳健。

这也引出了后来被广泛研究的"prompt 工程"方向：既然措辞如此重要，与其手工写模板，不如让模型学习最优模板（Context Optimization / CoOp）或让软提示在视觉侧工作。CLIP 是这一切的起点。

4. 为什么零样本真的有效#

零样本能力不是魔法，它来自三件事的叠加：

  1. 监督信号是语言：语言天然覆盖了远超任何单一数据集的类别空间。"斑马""斑马线""斑马纹蛋糕"这些概念在文本里都出现过，模型在预训练时就已经见过它们的语言侧，只是从没把它们和特定图片绑定成分类任务。
  2. 学习的是表征而非分类头：分类器会把表征"烧死"在固定类别上；对比学习保留了一个通用的语义空间，任何能写进模板的概念都可以即插即用。
  3. 规模带来的鲁棒性：4 亿对数据的多样分布让模型对图像风格、背景、视角的偏移更不敏感，因此在分布偏移严重的测试集（如 ImageNet 的素描版、对抗版）上，零样本 CLIP 的相对优势比标准 ImageNet 上更明显。

5. 零样本的短板：诚实看待边界#

零样本并非万能，原论文也明确列出了失败案例，理解它们同样重要：

  • 细粒度与计数：区分"哈士奇 vs 阿拉斯加"、数出图片里有几只羊，CLIP 表现平平。
  • 结构化与空间关系："红球在蓝球左边"这类需要精确几何推理的任务，纯双塔结构吃力。
  • 离分布概念：对某些特定数据集（如 MNIST 手写数字）CLIP 的零样本准确率很低，因为它预训练数据里几乎没有这种风格。
  • 对模板的依赖：同一个类别换种说法结果就变，说明对齐还不够"确定"，仍依赖语言侧的措辞。

这些短板，恰恰是第五章多模态大模型（LLaVA 等）要解决的问题——用大语言模型的推理能力去补 CLIP 不擅长的部分。

二、可运行代码示例#

示例 1：零样本图像分类#

下面用 CLIP 对一张图做零样本分类，完整复现上面的流程。

from transformers import CLIPProcessor, CLIPModel
from PIL import Image
import torch

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

# 候选类别——模型从未针对这些类做过分类训练
classes = ["cat", "dog", "car", "airplane", "banana"]
template = "a photo of a {}"          # prompt 模板
texts = [template.format(c) for c in classes]

# 用一张占位图演示; 实际替换为你的图片路径
image = Image.new("RGB", (224, 224), color=(100, 90, 80))

inputs = processor(text=texts, images=image, return_tensors="pt", padding=True)
with torch.no_grad():
    out = model(**inputs)

# 图像向量与各类文本向量的余弦相似度
logits = out.image_embeds @ out.text_embeds.T   # (1, K)
probs = logits.softmax(dim=-1)[0]

# 按概率从高到低打印结果
for c, p in sorted(zip(classes, probs.tolist()), key=lambda t: -t[1]):
    print(f"{c:10s} {p:.4f}")
print("预测类别：", classes[torch.argmax(probs).item()])

示例 2：prompt ensembling 提升稳定性#

我们用多个模板对同一组类别编码，并对比"单模板"与"多模板平均"的差异。

from transformers import CLIPProcessor, CLIPModel
from PIL import Image
import torch

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

classes = ["cat", "dog", "car"]
templates = [
    "a photo of a {}.",
    "a blurry photo of a {}.",
    "a good photo of the {}.",
    "an origami {}.",
]
image = Image.new("RGB", (224, 224), color=(110, 100, 90))

# 图像向量只需算一次
img_inputs = processor(images=image, return_tensors="pt")
with torch.no_grad():
    img_emb = model.get_image_features(**img_inputs)
    img_emb = img_emb / img_emb.norm(dim=-1, keepdim=True)

# 单模板结果
single_texts = [templates[0].format(c) for c in classes]
with torch.no_grad():
    single_emb = model.get_text_features(**processor(text=single_texts, return_tensors="pt", padding=True))
    single_emb = single_emb / single_emb.norm(dim=-1, keepdim=True)
single_probs = (img_emb @ single_emb.T).softmax(dim=-1)[0]

# 多模板平均: 对每个类别, 把所有模板的文本向量取平均
all_emb = []
for c in classes:
    per_template = [t.format(c) for t in templates]
    with torch.no_grad():
        emb = model.get_text_features(**processor(text=per_template, return_tensors="pt", padding=True))
        emb = emb / emb.norm(dim=-1, keepdim=True)
    all_emb.append(emb.mean(dim=0, keepdim=True))   # 同类多模板取平均
mean_emb = torch.cat(all_emb, dim=0)

mean_probs = (img_emb @ mean_emb.T).softmax(dim=-1)[0]

print("单模板概率：", dict(zip(classes, single_probs.tolist())))
print("多模板平均概率：", dict(zip(classes, mean_probs.tolist())))

emb.mean(dim=0) 那一行是 ensembling 的核心：多个措辞在嵌入空间里"投票"，平均后的类代表向量更接近该类的语义中心，受单个模板措辞偏差的影响更小。

三、练习#

  1. 流程复述：不看代码，用自己的话写出零样本分类的 5 个步骤，并标出每一步用到了 CLIP 的哪个组件。
  2. 动手实验：在示例 1 中加入一个与图片无关但措辞相近的类别（例如把 "banana" 换成 "banana peel"），观察概率分布如何变化，并解释为什么措辞如此重要。
  3. 动手实验：把示例 2 的模板数量从 4 个扩展到 10 个（自行编写措辞），记录平均概率的变化。模板越多，结果一定越好吗？可能存在什么反例？
  4. 思考题：为什么 CLIP 在"分布偏移的 ImageNet 变体"上相对有监督模型的优势更明显？结合前两课学到的"通用表征 vs 固定分类器"来解释。
