为什么需要位置#

你已经知道，Transformer 去掉了循环神经网络（RNN）那种"一个 token 接一个 token"的串行处理，改成一整条序列同时并行计算。并行带来的效率是巨大的，但它也丢掉了一件 RNN 天然拥有的东西——顺序。RNN 是按时间步读入序列的，"第一个词"和"第二个词"这个先后关系被硬编码进了它的计算过程；而 Transformer 的自注意力把所有位置当成了一个集合来对待。这一课就从一个尖锐的问题开始：如果把注意力直接作用在词向量上，模型真的能区分"我打你"和"你打我"吗？答案是不能。我们要先把这个"位置盲"讲透，才能理解第 2、3 课为什么要给每个位置补一个向量。

一、概念讲解#

1. RNN 有顺序，Transformer 没有#

RNN 每读入一个 token，就更新一次隐藏状态，再把状态传给下一个时间步：

h_t = f(W_h · h_{t-1} + W_x · x_t)

因为 h_t 依赖 h_{t-1}，token 的先后关系被自然地编码进了状态里。交换两个 token 的位置，整条状态链会完全不同。

Transformer 的自注意力则完全不同。对每个位置，它先算 Query、Key、Value，然后用 Query 去和所有位置的 Key 做点积，得到权重，再对 Value 加权求和。注意这里的措辞——"所有位置"。计算第 3 个位置的输出时，模型会同时看向第 1、第 2、第 4 个位置，而它没有任何机制去记录"第 3 个"这个身份本身。它只知道"有一堆向量，我要按相似度加权它们"。

2. 自注意力是"置换等变"的#

这是理解本课最关键的一个性质。所谓置换等变（permutation equivariance），意思是：如果把输入的 token 换一种顺序，那么输出的向量也只会跟着换同样的顺序，内容本身不变。

换句话说，注意力把输入序列当作一个"袋子里的一堆词"（bag of tokens）来处理。对第 i 个位置的输出而言，它只是"输入向量的一个加权平均"，而权重由 Query 与各个 Key 的相似度决定。相似度和"谁排在第几位"毫无关系，只和"这些向量本身长什么样"有关。

于是出现一个尴尬的结论：句子 ["我", "打", "你"] 和句子 ["你", "打", "我"]，经过同一个自注意力层之后，得到的输出向量集合是完全相同的一组向量（只是顺序对调了）。模型根本无法凭注意力本身知道，谁是主语、谁是宾语。

3. 为什么不能靠"顺序遍历"来救#

有人会问：既然并行是问题，那让模型仍然按顺序一个一个算不就行了？这就回到了 RNN 的老路上——串行意味着无法并行训练，长序列的效率会急剧下降。Transformer 的设计初衷就是用并行换速度，因此它选择了一个折中：并行计算，同时显式地把位置信息"注入"输入。

这个"注入"就是位置编码（positional encoding）的由来：在把 token 的 embedding 送进自注意力之前，先给它加上一个只与位置有关、与内容无关的向量。这样，"我"在位置 0 和"我"在位置 2 得到的输入向量就不同了，注意力层才有机会把它们区分开。

带位置的输入 = token_embedding + position_encoding(position)

4. 位置编码需要满足什么#

一个合格的位置编码，至少要有两个特点：

  1. 唯一且有序：不同位置得到不同的向量，且这个向量能反映先后顺序，让模型能算出"谁在前、谁在后、隔了多远"。
  2. 可加性：它以"加法"的方式和 token embedding 结合，且维度必须与 d_model 一致，不破坏后面的矩阵运算。

至于这个向量是固定公式算出来的（第 2 课的正弦编码），还是当作参数训练出来的（第 3 课的可学习编码），就构成了两种主流方案。在动手实现它们之前，先亲眼确认一下"位置盲"到底有多彻底。

二、可运行代码示例#

下面写一个最简的缩放点积自注意力，输入三个随机向量，然后交换前两个 token，观察输出发生了怎样的变化。

import torch
import torch.nn.functional as F

torch.manual_seed(0)

def self_attention(X):
    # X: (seq_len, d_model)，自注意力中 Q、K、V 都来自 X
    d = X.shape[-1]
    Q = K = V = X
    scores = Q @ K.T / (d ** 0.5)      # (seq_len, seq_len) 的相似度矩阵
    weights = F.softmax(scores, dim=-1) # 每一行是"该位置对全体位置的关注分布"
    return weights @ V, weights

# 三个 token 的 embedding，顺序为 [A, B, C]
X = torch.randn(3, 4)
out_abc, _ = self_attention(X)

# 交换前两个 token，顺序变为 [B, A, C]
X_swap = X[[1, 0, 2]]
out_swap, _ = self_attention(X_swap)

print("原始顺序输出:\n", out_abc)
print("交换后输出:\n", out_swap)
print()
# 关键验证：交换输入只是把输出也换了位置，向量内容一个都没变
print("原始第0行(A) 等于 交换后第1行:", torch.allclose(out_abc[0], out_swap[1]))
print("原始第1行(B) 等于 交换后第0行:", torch.allclose(out_abc[1], out_swap[0]))
print("原始第2行(C) 等于 交换后第2行:", torch.allclose(out_abc[2], out_swap[2]))

运行后三个 allclose 都会输出 True。这直观地说明：自注意力只关心"这些向量彼此多相似"，完全不关心"它们各自站在哪个位置"。如果把 A、B、C 换成真实词向量，"我打你"和"你打我"就会得到同一组输出——位置信息在这里彻底丢失了。

再看一个更贴近真实 Transformer 的例子：加上位置编码后，交换 token 就不再"等价"了。

# 一个简单的"可学习位置编码"雏形：每个位置一个独立的向量
pos_encoding = torch.randn(3, 4)          # 位置 0/1/2 各有一个 4 维向量

X_pos = X + pos_encoding                  # token embedding + 位置编码
out_pos = self_attention(X_pos)[0]

X_pos_swap = X[[1, 0, 2]] + pos_encoding  # 注意：token 换了，但位置编码按位置不变
out_pos_swap = self_attention(X_pos_swap)[0]

# 这次输出不再是简单换位，说明位置信息已经进入了计算
print("加位置编码后，交换输出是否还只是换位:",
      torch.allclose(out_pos[0], out_pos_swap[1]) and torch.allclose(out_pos[1], out_pos_swap[0]))

这一次结果为 False：位置向量打破了置换等变，模型终于有能力"看见"顺序了。剩下的问题只是——这个 pos_encoding 该怎么设计，是固定的还是学出来的。这就是后两课的内容。

三、练习#

  1. 把上面的 self_attention 改成多头的版本（把 d_model 拆成几个头分别算再拼起来），确认"置换等变"这个性质对多头注意力是否依然成立，并解释为什么。
  2. 构造两句话 ["我", "爱", "你"] 与 ["你", "爱", "我"]，各用随机 embedding 表示，计算它们自注意力输出（不加位置编码），验证两组输出只是顺序对调。这说明不加位置编码的 Transformer 会犯什么具体的语言理解错误？
  3. 思考：为什么位置编码要"加"在输入上，而不是"拼接"（concatenate）在输入后面？两种做法在维度、参数量、以及后续线性层的处理上各有什么代价？
  4. 位置编码要不要参与梯度更新？如果参与，它和"把位置当作普通可训练参数"有什么区别？带着这个问题进入第 3 课。
