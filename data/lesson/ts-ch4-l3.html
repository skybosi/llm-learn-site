序列到序列预测#

前两课我们做的都是多对一：读入一个窗口，输出一个值，再用自回归方式逐点外推。这种"滚雪球"有一个系统性问题——误差逐步累积，每预测一步都要把上一步的（可能不准的）结果当作输入，越滚越偏。序列到序列（Sequence-to-Sequence，seq2seq）换了一种思路：读入一段历史，一次性输出整段未来，让模型直接学会"从历史分布跳到未来分布"的映射，而不是一步步地凑。这一课我们讲 seq2seq 的结构、训练技巧，以及它留下的那个著名瓶颈——它正是下一章 Transformer 登场的理由。

一、概念讲解#

1. 从"多对一"到"多对多"#

把预测问题抽象成映射的形状：

  • 多对一：[x_{t-L+1}, ..., x_t] → ŷ_{t+1}，上一课的做法；
  • 多对多：[x_{t-L+1}, ..., x_t] → [ŷ_{t+1}, ..., ŷ_{t+H}]，一次输出未来 H 步。

seq2seq 属于后者。它由两部分组成：编码器（Encoder）把整段历史读进去，压缩成若干个隐藏状态；解码器（Decoder）再从这个压缩表示出发，逐步生成未来的每一个值。编码器和解码器都可以是 LSTM、GRU 或 TCN，最经典的是 LSTM。

2. 编码器-解码器的分工#

编码器逐时间步读入历史窗口 [x_{t-L+1}, ..., x_t]，最后一步的隐藏状态 h_t（和细胞状态 c_t）作为整段历史的摘要，是解码器的初始状态。解码器用这个摘要启动，再逐时间步生成 ŷ_{t+1}, ŷ_{t+2}, ...。

这就是"先理解，再生成"的分工：编码器负责"看懂了什么"，解码器负责"据此说出未来"。这套结构最早用于机器翻译（编码器读一句外语，解码器译成中文），搬到时间序列上天然合适——因为预测本质也是一种"序列翻译"：把过去翻译成未来。

3. Teacher Forcing：训练与推断的不一致#

训练解码器时有一个关键技巧叫 Teacher Forcing（教师强制）：训练时，解码器每一步的输入不是"上一步的预测"，而是上一步的真实标签 y_{t+k}。这样模型始终在"正确答案"的基础上继续生成，训练又快又稳，误差不会在训练中累积。

但它埋下一个隐患：训练和推断不一致。推断时没有真实标签，只能用上一步的预测，一旦某一步预测偏了，后续输入都建立在这个偏差上。这个"训练-推断鸿沟"是 seq2seq 的一个经典问题。缓解办法之一是计划采样（scheduled sampling）：训练过程中按一定概率随机用预测值替换真实值，让模型逐渐适应"吃自己的预测"。

4. 固定长度瓶颈：一切问题的根源#

编码器把整段历史压成最后一步的隐藏状态，无论历史多长，都只能装进一个固定大小的向量。历史越长，被"挤"丢的信息越多；解码器生成未来第 k 步时，也只能依靠这同一个摘要，无法区分"此刻我该参考历史的哪一段"。这正是我们第一章（注意力机制课程）反复强调的瓶颈，也是为什么 seq2seq 之后人们发明了注意力——让解码器每一步都能回头从编码器各时间步里按需取用。下一章 Transformer 会把这个思路推到极致。

二、可运行代码示例#

下面实现一个 LSTM 编码器-解码器，读入 60 步历史、一次性输出未来 20 步。训练用 Teacher Forcing，推断用自回归逐点生成。

import torch
import torch.nn as nn
import numpy as np
import matplotlib.pyplot as plt

torch.manual_seed(0)
np.random.seed(0)

# 1) 生成序列
t = np.arange(0, 800)
series = 0.02 * t + 5 * np.sin(t / 12.0) + np.random.randn(800) * 0.3

# 2) 构造样本：输入 60 步，输出未来 20 步
ENC_LEN, DEC_LEN = 60, 20
def make_dataset(series, in_len, out_len):
    X, y = [], []
    for i in range(len(series) - in_len - out_len):
        X.append(series[i:i + in_len])
        y.append(series[i + in_len:i + in_len + out_len])
    return (torch.tensor(X, dtype=torch.float32).unsqueeze(-1),
            torch.tensor(y, dtype=torch.float32).unsqueeze(-1))

X, y = make_dataset(series, ENC_LEN, DEC_LEN)
print("X 形状:", X.shape, " y 形状:", y.shape)   # (样本, 60, 1) 与 (样本, 20, 1)

class Seq2Seq(nn.Module):
    def __init__(self, input_size=1, hidden_size=32):
        super().__init__()
        self.encoder = nn.LSTM(input_size, hidden_size, batch_first=True)
        self.decoder = nn.LSTM(input_size, hidden_size, batch_first=True)
        self.fc = nn.Linear(hidden_size, 1)

    def forward(self, src, trg=None, teacher_forcing_ratio=0.5):
        # 编码：读完整段历史，取最后一步的 (h, c) 作为解码器初始状态
        _, (h, c) = self.encoder(src)

        dec_input = src[:, -1:, :]          # 解码器第一个输入：历史的最后一个点
        outputs = []
        for k in range(DEC_LEN):
            out, (h, c) = self.decoder(dec_input, (h, c))
            pred = self.fc(out)             # (batch, 1, 1)
            outputs.append(pred)
            # 决定下一步输入：teacher forcing 用真实值，否则用上一步预测
            if trg is not None and torch.rand(1).item() < teacher_forcing_ratio:
                dec_input = trg[:, k:k+1, :]
            else:
                dec_input = pred
        return torch.cat(outputs, dim=1)    # (batch, DEC_LEN, 1)

model = Seq2Seq()
criterion = nn.MSELoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

# 3) 训练：teacher forcing 概率 0.5
model.train()
for epoch in range(400):
    optimizer.zero_grad()
    pred = model(X, trg=y, teacher_forcing_ratio=0.5)
    loss = criterion(pred, y)
    loss.backward()
    optimizer.step()
    if (epoch + 1) % 50 == 0:
        print(f"epoch {epoch+1:3d}  loss={loss.item():.4f}")

# 4) 推断：不传 trg，纯自回归生成未来 20 步
model.eval()
with torch.no_grad():
    src = torch.tensor(series[-ENC_LEN:], dtype=torch.float32).reshape(1, ENC_LEN, 1)
    pred = model(src, trg=None)            # 全自回归

plt.figure(figsize=(9, 3.5))
plt.plot(range(-ENC_LEN, 0), series[-ENC_LEN:], label="历史")
true_future = series[-ENC_LEN - DEC_LEN: -ENC_LEN] if len(series) > ENC_LEN + DEC_LEN else None
plt.plot(range(0, DEC_LEN), pred[0, :, 0].numpy(), label="预测", linestyle="--")
plt.legend(); plt.title("seq2seq 一次预测未来 20 步")
plt.show()

几个要点：

  • encoder 返回的 (h, c) 就是"历史摘要"，直接作为 decoder 的初始状态，这正是编码器-解码器的连接点；
  • Teacher Forcing 的概率是个超参：1.0 训练最稳但推断漂移大，0.0 最难收敛，工程上常取 0.5 折中；
  • 推断阶段 trg=None，模型完全靠自己的预测滚动 20 步——注意即使这样，误差累积也远小于"多对一 + 滚动 20 次"，因为模型被显式训练过"看到历史就说出整段未来"。

三、练习#

  1. 把 teacher_forcing_ratio 分别设为 0.0、0.5、1.0 训练三个模型，比较推断阶段的误差。为什么 1.0 训练时的 loss 最低，推断却不一定最好？
  2. 把 DEC_LEN 从 20 加到 60，观察长序列生成质量如何下降。结合"固定长度瓶颈"，解释为什么输出越长越难。
  3. 把编码器换成本章上一课的 TCN，解码器保留 LSTM，体会"编码器/解码器可插拔"的灵活性。
  4. 思考：解码器每一步都只能依赖同一个初始状态 (h, c)，它无法在生成第 15 步时"回头精确参考历史第 3 步"。这个缺陷提示我们需要引入什么机制？（提示：下一章的主题。）
