视频问答与视频-语言：对齐、时序引用与评测陷阱#

这一节要解决什么#

前两节的输出都是闭集：一个类别、一个区间。这一节把输出换成开放的语言：

给定视频（和一段文本），输出一段文本或一个被文本指称的时间段。视频与文本怎么对齐？对齐到什么程度算"用上了视频"？为什么 BLEU/ROUGE 这类指标会骗人，怎么用可算的判据把它钉住？

这一节的结论如下：

  1. 对比式对齐的全部信号是"对角与非对角的间隔"，与相似度绝对尺度无关。 τ 只影响 softmax 温度，不影响"谁最大"。完全无信息时 L=logB 精确成立（B=8 时 2.079442，与理论值完全相等）（表 1）。
  2. loss 与检索指标会脱钩。 对角间隔 2→6 时 L 从 0.874872 降到 0.030421（降 96.52%），而对角 top-1 已经饱和在 1.000000、对角平均概率只有 0.970293。"loss 降了就有提升"在对比学习里不成立（表 1）。
  3. 重复文本让"唯一正确答案"失效，而且只能从数据侧解决。 把两条文本换成同一条后，对角平均概率从 0.970293 掉到 0.944918，分掉的那部分概率全部变成假负例（表 1）。这是第 1 章第 4 节"假负例 E=(B−1)q"在数据侧的对应物。
  4. 生成式对齐可以在同一份数据上给出完全不同的序列。 反例中贪心序列的累计对数似然是 −8.900000，束宽 k=2 的序列是 −1.200000——相差 7.700000，而两条序列一个 token 都不同。束搜索优化的是逐 token 对数似然而非词面指标，两者方向不一致（表 2）。
  5. 时序引用有两条互相拉扯的约束。 窗口长 w、真值长 G：要过 IoU=0.5 必须 w≥⌈0.5G⌉；而随机基线 ≈(G+w)/T 随 w 上升。T=3600 帧、G=90 帧时，w=45 的随机基线是 0.037500、w=900 时升到 0.333333（表 3、表 6）。报 R@1 必须同时报随机基线。
  6. 词面指标奖励"像"不奖励"对"。 参考"他打开冰箱拿出牛奶"（8 字）：「打开冰箱」BLEU-4 =0.286505；而物体错了的「他打开冰箱拿出苹果」BLEU-4 =0.725980——错得更多反而分更高（表 4）。
  7. 长度惩罚是双刃的。 短答案被 BP 压（"打开冰箱"的 BP=0.367879），长答案完全不受惩罚：啰嗦但正确的「他打开冰箱拿出牛奶然后关门」BLEU-4 是 0.647912。一个啰嗦的模型可以靠多写字白拿分（表 4）。
  8. "猜最高频答案"是一条极强的免费基线。 100 题、最高频答案占 76% 的构造里，一个完全不看视频的常数回答器观测准确率 0.760000，与真读视频的模型只差 8.00 个百分点（表 5）。
  9. 反事实复核是最便宜的照妖镜。 把最高频答案换成最低频答案后重算：不看视频的模型掉到 0.000000，真读视频的模型仍有 0.210000（表 5）。这个落差就是"视频被用上了"的可操作证据，且不需要重训。

主线一句话：视频-语言的任务定义是开放的，所以它的评测是本章最容易作弊的一节；把作弊空间关掉的办法不是换指标，而是加"反事实"这一列。

一、任务谱系：从"选"到"写"到"指"#

1.1 五种输出形态#

1.2 两个共同的结构问题#

无论哪种形态，视频-语言都有两个绕不开的结构问题：

  1. 时长不匹配：视频有成千上万帧，文本只有几十个词。对齐必须做时间池化或注意力，而这一步会丢信息（第 1 章第 2 节的置换不变性在这里再次出现）。
  2. 弱监督：训练用的视频-文本对大多是网络爬取的，文本只描述大概发生了什么，不指认具体时间（第 1 章第 4 节算过：W=30 s 窗口的定位不确定度 9.813781 bit，超过类别熵）。

所以视频-语言的方法论可以概括成一句话：用弱对齐训练一个能强定位的模型，中间靠结构假设（注意力、稀疏、对比）把弱信号收紧。

二、对比式对齐：把两个模态压到同一个空间#

2.1 目标函数#

设 batch 内 B 个视频、B 个文本，相似度 Sij​=vi⊤​tj​/τ。对称 InfoNCE：

L=21​[B1​i∑​−log∑j​eSij​eSii​​+B1​j∑​−log∑i​eSij​eSjj​​].

L=21​[B1​i∑​−log∑j​eSij​eSii​​+B1​j∑​−log∑i​eSij​eSjj​​].

为什么是"对称"的：单向目标只保证"视频能找到文本"，不保证"文本能找到视频"。检索方向有两个，训练目标就该有两个。这个细节在报数时很重要——R@1（视频→文本）与 R@1（文本→视频）通常差几个点。

2.2 完全无信息时 L=logB：一个精确的锚#

S 全零时，L=21​[B1​∑i​logB+B1​∑j​logB]=logB。表 1 的第一行验证了这一点：B=8 时 L=2.079442，与 log8=2.079442 完全相等。

它的用处：这是判别"训练是否在学东西"的第一条线。如果 L 停在 logB 附近不降，说明模型没学到跨模态对应，而不是"任务难"。而且它随 batch 对数增长（B=32768 时 10.397208），所以跨 batch 比 loss 无意义。

2.3 信号是间隔，不是尺度#

相似度构造 L 视频→文本 top-1 文本→视频 top-1 对角平均概率
完全无信息（截断为 0） 2.079442 0.125000 0.125000 0.125000
弱对齐（对角 +2） 0.874872 0.875000 0.875000 0.467549

三条读法：

  1. 只在对角加一个常数，top-1 从 0.125000 跳到 0.875000，而相似度的绝对尺度完全没变（都加了同一个数）。对比学习只关心相对间隔。
  2. 间隔从 2 提到 6：L 降 96.52%，但 top-1 已经饱和。loss 还在降、指标已经不涨——这是对比学习实验里最常见的误读。
  3. 对角平均概率告诉我另一件事：0.970293 意味着仍有约 3% 的概率质量落在错误配对上。检索 top-1 是"冠军是谁"，概率质量是"冠军有多稳"——两个都要报。

2.4 重复样本：只能从数据侧解决#

把两条文本换成同一条（两者对角得分都是 5.0）：

  • 对角平均概率从 0.970293 掉到 0.944918；
  • 分掉的那部分概率全部化成假负例（同一条文本被当成两个不同的负样本）。

为什么调 loss 救不了：目标函数里"正样本只有一个"是前提，重复样本破坏的是前提本身。可用的处置只有三种：

  1. 去重（句面级：去掉近似重复的文本）；
  2. 跨视频采样（降低同一条文本出现在多个视频下的概率）；
  3. 用监督标签挖掉同类负例——但这把"自监督"的便宜又还了回去。

三、生成式对齐：自回归与解码#

3.1 目标函数与它的两个性质#

Lgen​=−N1​n=1∑N​logp(yn​∣y<n​,v).

两个性质直接决定了它的行为：

  1. 每个 token 都在贡献一项负值，所以长答案的对数似然天然更低；
  2. 它衡量的是"逐 token 有多可能"，不是"整句有多对"——一句语义完全正确但用词不同的答案，对数似然可能很低。

3.3 解码与评测的错位#

这是本节第一个"指标会骗人"的点：

  • 束搜索优化对数似然；
  • 评测算的是 n-gram 重叠（BLEU/ROUGE/CIDEr）。

两者方向不一致的显式证据在表 4：把答案从"他打开冰箱拿出牛奶"扩展成"他打开冰箱拿出牛奶然后关门"（语义仍然完全正确），BLEU-4 却是 0.647912，低于错误答案"他打开冰箱拿出苹果"的 0.725980。解码器优化的目标是"更像参考"，而"更对"并不保证"更像"。

判据：任何报告必须写清解码参数——贪心/束搜索/采样、束宽、长度惩罚、是否对同一输入多次采样取最好。不同的解码参数下 BLEU 动辄差几个点，比大多数方法改进都大。

四、时序定位引用：把语言钉到时间轴上#

4.1 任务与判据#

时序定位引用（moment retrieval / temporal grounding）：给定查询句，输出视频里的一个区间 [s,e]。评测用 R@n,IoU=m（前 n 个预测里有一个 IoU≥m 即命中）。

三条读法：

  1. 窗口越短越准，但短到一定程度永远过不了阈值：w=1 时上界 0.011111。这是和第二节单帧提案同一个算术。
  2. 随机基线随 G/T 线性增长：T=3600、G=900 帧（30 秒）时随机 R@1 上界已达 0.375000——这时候"20% 的 R@1"没有任何说服力。
  3. 拉长窗口提高召回，代价是 IoU 下降。两个约束把 w 夹在 w≥⌈mG⌉ 附近的一个窄区间里。

五、评测陷阱：词面指标为什么会骗人#

5.1 BLEU 的两个机制#

BLEU-N=BP⋅exp(N1​n=1∑N​logpn​),pn​=候选的 n-gram 数截断匹配的 n-gram 数​,

BLEU-N=BP⋅exp(N1​n=1∑N​logpn​),pn​=候选的 n-gram 数截断匹配的 n-gram 数​,

BP={1,e1−∣ref∣/∣hyp∣,​∣hyp∣>∣ref∣否则​

两个机制各自会骗人：

  1. n-gram 精度奖励"用词相似"。参考"他打开冰箱拿出牛奶"（8 字）时：
候选输出 字数 BLEU-1 BLEU-4 ROUGE-L 完全匹配 人工判断
打开冰箱 4 0.286505 0.286505 0.615385 0.000000 错（漏了两件事）
他打开冰箱拿出牛奶 9 1.000000 1.000000 1.000000 1.000000 对
他打开冰箱拿出苹果 9 0.777778 0.725980 0.777778 0.000000 错（物体错）
他打开冰箱拿出牛奶然后关门 13 0.692308 0.647912 0.818182 0.000000 对（稍啰嗦）
冰箱牛奶 4 0.286505 0.000000 0.615385 0.000000 错

第 3 行与第 4 行是本节最重要的两格：错得更多反而分更高（0.725980>0.647912），因为前者的 n-gram 与参考更接近。词面指标奖励"像"，不奖励"对"。

  1. 长度惩罚（BP）只罚短、不罚长：短答案"打开冰箱"的 BP=e1−8/4=0.367879；而 13 字的啰嗦答案 BP=1。一个啰嗦的模型可以靠多写字白拿分。这与生成式训练里"长答案对数似然天然更低"的方向正好相反——训练与评测对长度的偏好相反，是生成式视频-语言里一个结构性错位。

5.2 完全匹配：无偏但丢信息#

EM 对每个字严格，因此无偏；代价是它把"打开冰箱"与"冰箱牛奶"都记成 0.000000，丢掉了"部分正确"。所以 EM 与词面指标是互补的，不是替代关系。

5.3 答案先验：一条免费的强基线#

100 题、8 个候选答案（最高频占 76%）、三个模型（全部为确定性构造）：

模型 观测准确率 句均 BLEU-1 句均 BLEU-2 ROUGE-L 反事实准确率
A 真读视频（80% 题答对） 0.840000 0.920000 0.840000 0.920000 0.210000
B 不看视频（恒答最高频） 0.760000 0.880000 0.760000 0.880000 0.000000
C 真读视频（65% 题答对） 0.610000 0.805000 0.610000 0.805000 0.200000

四条读法：

  1. 模型 B 一眼都没看视频，观测准确率 0.760000——它用了 0 bit 的视频信息，只比真读视频的 A 低 8.00 个百分点。任何视频问答的准确率都要先减去这条基线再看。
  2. 反事实复核把两者分开了：把所有最高频答案换成最低频答案后重算，B 掉到 0.000000（它的输出根本没变），A 仍有 0.210000。这个落差就是"视频被用上了"的可操作证据，且只需重算一次指标、不需重训。
  3. 单 token 答案上的 BLEU-1 只是准确率的另一种写法（三者都等于准确率），对"为什么对"零信息。词面指标在短答案上完全退化；真实系统的答案是多 token 的（含物体、数量、时序词），这时 BLEU-2 及以上才开始有分辨力。
  4. 反事实准确率只由"有多少题原本就答成了最高频答案"决定，与 O(1/N) 量级的采样噪声同阶（N=100 时 sd≈0.04）。量它的意义在于：它随真实能力单调，却对答案先验免疫。

5.4 最小可用的评测清单#

判据（任一视频问答/描述的结果表至少要有这五列）：

  1. 词面指标（BLEU/ROUGE/CIDEr，注明版本、平滑、是否句均或语料级）——用于和历史工作可比；
  2. 完全匹配——无偏的那一列；
  3. 最高频基线（常数回答器的成绩）——把"免费分"显式化；
  4. 反事实/扰动准确率——把"是否真的用了视频"显式化；
  5. 解码参数（贪心/束搜索/采样，束宽，长度惩罚）。

再加两条边界：

  • 多选与开放不该比：多选的随机基线是 1/K（可算），开放任务没有可算的随机基线，只有第 3 列那条先验基线。
  • 人工评估不能省：表 4 的第 3 行（物体错）在 BLEU-4 上高于第 4 行（语义对但啰嗦），任何自动指标都复现不了这个区别。

def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1 for ch in s)


def pad(s, w, align=">"):

class LCG:
    def __init__(self, seed=20260926):
        self.s = seed & 0xFFFFFFFFFFFFFFFF

    def u(self):
        self.s = (6364136223846793005 * self.s + 1442695040888963407) & 0xFFFFFFFFFFFFFFFF
        return (self.s >> 11) / float(1 << 53)

    def n(self):
        u1 = max(self.u(), 1e-12)
        u2 = self.u()
        return math.sqrt(-2.0 * math.log(u1)) * math.cos(2.0 * math.pi * u2)


def iou(se, ee, sp, ep):
    inter = max(0.0, min(ee, ep) - max(se, sp))
    union = (ee - se) + (ep - sp) - inter
    return inter / union if union > 0 else 0.0

def infonce(S):
    """对称 InfoNCE：两个方向各取均值。"""
    l1, l2 = [], []
    for i in range(B):
        mx = max(S[i])
        ex = [math.exp(v - mx) for v in S[i]]
        Z = sum(ex)
        l1.append(-math.log(ex[i] / Z))
    for j in range(B):
        col = [S[i][j] for i in range(B)]
        mx = max(col)
        ex = [math.exp(v - mx) for v in col]
        Z = sum(ex)
        l2.append(-math.log(ex[j] / Z))
    return 0.5 * (sum(l1) / B + sum(l2) / B)


def diag_acc(S):
    a = sum(1 for i in range(B) if S[i].index(max(S[i])) == i)
    b = sum(1 for j in range(B)
            if [S[i][j] for i in range(B)].index(max([S[i][j] for i in range(B)])) == j)
    return a / B, b / B


def diag_prob(S):
    """对角线上的平均 softmax 概率（两个方向的均值）。"""
    tot = 0.0
    for i in range(B):
        ex = [math.exp(v - max(S[i])) for v in S[i]]
        tot += ex[i] / sum(ex)
    for j in range(B):
        col = [S[i][j] for i in range(B)]
        ex = [math.exp(v - max(col)) for v in col]
        tot += ex[j] / sum(ex)
    return tot / (2 * B)

def ngrams(seq, n):
    return [tuple(seq[i:i+n]) for i in range(len(seq) - n + 1)] if len(seq) >= n else []


def bleu(hyp, ref, N=4):
    hyp, ref = list(hyp), list(ref)
    logs = []
    for n in range(1, N + 1):
        h = ngrams(hyp, n)
        r = ngrams(ref, n)
        if not h:
            return 0.0
        cnt = {}
        for g in r:
            cnt[g] = cnt.get(g, 0) + 1
        clip = 0
        for g in h:
            if cnt.get(g, 0) > 0:
                cnt[g] -= 1
                clip += 1
        p = clip / len(h)
        if p == 0.0:
            return 0.0
        logs.append(math.log(p))
    bp = 1.0 if len(hyp) > len(ref) else math.exp(1 - len(ref) / len(hyp))
    return bp * math.exp(sum(logs) / N)


def lcs_len(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            dp[i][j] = dp[i-1][j-1] + 1 if a[i-1] == b[j-1] else max(dp[i-1][j], dp[i][j-1])
    return dp[len(a)][len(b)]


def rouge_l(hyp, ref):
    l = lcs_len(list(hyp), list(ref))
    p = l / len(hyp) if hyp else 0.0
    r = l / len(ref) if ref else 0.0
    return 2 * p * r / (p + r) if p + r else 0.0

     O((G/T)^n)——**n=3 时随机基线几乎为 0**，所以密集描述的指标不易被先验注水，
     但也意味着它比单段引用**难得多**，两个任务的分不能直接比。

练习#

  1. InfoNCE 的锚：把表 1 的 B 改成 4、16、64，验证"完全无信息"一行精确等于 logB。再用第 1 章第 4 节的公式算出 B=32768 时该值，并解释为什么"跨 batch 比 loss"没有意义。
  2. 间隔与饱和：在表 1 的构造上把对角间隔从 6 提到 12。预测对角平均概率会到多少（用 1+(B−1)e−Δ1​ 估算，Δ 为间隔），并与 Δ=6 的 0.970293 比较。说明这条曲线为什么决定了"对比学习后期该不该继续加算力"。
  3. 生成式的长度错位：用表 4 的 BLEU 实现，构造一对答案：A（长、语义正确）与 B（短、语义错误），使得 BLEU-4(A)<BLEU-4(B)。写出你构造的两个串与两个分数，并指出是 BP 起作用还是 pn​ 起作用。
  4. 随机基线：T=2000 帧、G=60 帧。分别算出 w=15,30,60,120 时的随机 R@1 上界与 IoU 上界，并指出哪个 w 使"过 IoU=0.5"与"随机基线最小"同时成立。若真值是 G=600 帧呢？
  5. 反事实的设计：对表 5 的构造，设计一个除了最高频答案之外的扰动（例如把"蓝色"全部换成"黄色"，蓝色占 12%）。预测三个模型在该扰动下的准确率，并说明为什么这个扰动比"换最高频"更能分辨 A 与 C。
  6. 解码与指标的错位：在表 2 的反例里，把两条序列各当成一个"候选答案"、把对数似然更高的那条当"参考"。用 BLEU-1 计算两条序列互为参考时的分数，解释为什么"优化对数似然"与"优化 BLEU"在长序列上会分歧。
  7. 设计题：为一个"视频问答"产品设计评测方案。要求给出：题量与答案空间大小、三条基线（随机、最高频、只用问题不看视频）、两个防作弊指标、以及一个可分辨门槛（用第 2 章的 sd=p(1−p)/V​ 算）。

小结#

  • 对比式对齐的目标是间隔：完全无信息时 L=logB 精确成立（B=8→2.079442）；对角 +2 使 top-1 从 0.125000 升到 0.875000；间隔 2→6 使 L 降 96.52% 而 top-1 已饱和。loss 与指标会脱钩。
  • 重复文本破坏"正样本唯一"这个前提：对角平均概率 0.970293→0.944918，分掉的概率全成假负例，只能靠去重/跨视频采样解决。
  • 生成式对齐的解码与评测错位：束搜索优化对数似然（反例里比贪心高 7.700000），而评测数 n-gram；表 4 里语义正确的长答案 BLEU-4（0.647912）低于物体错的答案（0.725980）。
  • 时序引用的两条约束互相拉扯：w≥⌈mG⌉（过阈值）与 Prandom​≈(G+w)/T（基线）。T=3600,G=90 时 w=45→ 基线 0.037500，w=900→0.333333。报 R@1 必须报随机基线。
  • 词面指标奖励"像"不奖励"对"，且长度惩罚只罚短不罚长：8 字参考下，错的 9 字答案 0.725980 > 对的 13 字答案 0.647912；"打开冰箱"的 BP=0.367879。
  • "猜最高频"是免费基线：不看视频的常数回答器准确率 0.760000，只比真读视频的模型低 8.00 个百分点；反事实复核把两者分开（0.000000 vs 0.210000）。
  • 最小评测清单（五列）：词面指标 + 完全匹配 + 最高频基线 + 反事实/扰动准确率 + 解码参数。再多选与开放不可比、人工评估不可省。
