项目：把同一模型编译到多个后端，给出性能与收益归因报告#

前三课给了三块零件：运行时（第 1 课）、缓存与多设备（第 2 课）、引擎里的位置与 roofline 归因（第 3 课）。这一课把它们收成一个可交付物：同一张计算图、多个后端、一张报告卡。难点不在跑得快，而在说清为什么快——把"融合省字节""回放省下发""权重变窄省带宽"分别量化，并诚实写出没生效的那部分。没有 GPU 也能完成：把计数与模型算清楚，真机只用来替换实测列。

一、概念讲解#

1. 项目定义与交付物#

输入：一个确定的模型（本课用两层 MLP）、固定的输入分布与 batch、一份后端清单。输出：一张报告卡：

字段 口径 为什么必须有
后端与配置 融合边界、分块、是否图回放 无配置的性能数字不可比
正确性门 与基准逐元素对比的 max|Δ| 没过门不许进性能表
计时 热身后取最小值 + 报极差 抗抖动，并可判断可信度
计数 kernel 数、中间张量、MACs、搬运字节 与硬件无关，跨机可比
模型时间 搬运/带宽、下发次数×单次开销 解释实测数字来自哪一层
归因 消融得到的每一步贡献 报告的核心结论
端到端换算 Amdahl 折成整体收益 防止把局部加速当结论

2. 三个后端的最小定义#

  • B0 逐算子：每算子一次 kernel、一个中间张量，即"回退到 eager"的形态。
  • B1 融合：matmul+bias+relu 与 matmul+bias 各融成一个 kernel，中间张量与 kernel 数都减少。
  • B2 融合+分块：把 batch 按 BM 行分块，让激活块有机会留在片上；代价是权重按块重读。

B2 的取舍是真问题：块越小权重重读越多（本例权重 360 MB，BM=1 时搬运翻到 2885.9 MB）；块越大，激活块超过片上容量才付写回代价。分块不是无条件更优。

3. 归因方法：三本账 + 消融 + Amdahl#

三本账：算子时间（MACs/有效算力）、下发时间（kernel 数×单次下发）、搬运时间（字节/带宽），统一到毫秒才可相加。消融：逐个打开后端特性，每步差分就是该特性的贡献（与第 3 课同法）。Amdahl：段内提速要除以覆盖率才是端到端收益，段内 2.00x 在覆盖率 30% 时只剩 1.176x。

4. 无 GPU 也能完成：可打印的模拟#

代码做四件事：跑通四个后端并过正确性门、统计搬运字节与 kernel 数、把流量模型放大到真实尺寸、按 Amdahl 折成端到端。真实尺寸那节只做计数与换算（权重 360.7 MB、激活 344 KiB/张量、假设带宽 2000 GB/s）：这正是无 GPU 时最值得练的部分——把归因写成公式。有 GPU 时只替换实测列，方法不变。

5. 报告卡的四条纪律#

  1. 写负结果：本例激活侧融合只省 0.7 MB（362.4→361.7 MB），"分块"更是负收益。只报赢的结果，报告没有参考价值。
  2. 报噪声：第 1 部分四个后端的最大差 0.14 ms，而单后端重复测量的极差最大 0.45 ms——差异被噪声淹没，此时不许下"谁更快"的结论。
  3. 标口径：实测、计数、模型三列分别标来源；混着写就无法判断哪条能复现。
  4. 可复现：随机种子、输入分布、热身次数与取值口径，都要写进报告。

6. 常见坑#

  • 不做正确性门就比性能：融合会改变算子顺序，浮点结果有差异；门不过，性能数字毫无意义。
  • 只测一次：单次测量把冷启动、GC、邻进程影响全算进来；至少热身 2 次、测量 9 次以上。
  • 把模型时间当预测：模型时间只说明"哪一层主导"，不能替代实测；B3 的 1.999x 只是流量模型结论。
  • 忘记端到端：段内 2x 很容易让人兴奋，覆盖率一折算就打回原形。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）就是项目本身：四个后端共用一个驱动，先过正确性门，再输出四部分报告卡。计时真实（热身 2 次、测量 10 次取最小值并报极差），搬运字节与 kernel 数精确计数，带宽/下发/片上容量为显式假设参数。

# ---- 第 4 课示例：把同一模型编译到多个"后端"，产出性能与收益归因报告卡 ----
# 纯 Python、无第三方依赖。计时是真实测量；搬运字节与算子数是精确计数；
# 带宽/下发开销/片上容量是**显式假设的模型参数**（不是任何真实设备的实测值）。
import time, math, random

B, I, H, O = 32, 48, 48, 48          # batch、输入维、隐藏维、输出维（纯 Python 可跑的尺寸）
F32 = 4
BW_GBPS, LAUNCH_US = 2000.0, 3.0     # 假设：带宽 2000 GB/s、单次下发 3 µs
CACHE_BYTES = 256 * 1024             # 假设：片上能留住的激活块上限 256 KiB

def newc(): return {'launches': 0, 'temps': 0, 'reads': 0, 'writes': 0, 'macs': 0}

def eager(X, W1, b1, W2, b2, c):
    """后端 0：逐算子。3 个 kernel，中间张量各读写一遍。"""
    t1 = [0.0] * (B * H); c['launches'] += 1; c['temps'] += 1
    for i in range(B):
        for j in range(H):
            s = b1[j]
            for t in range(I): s += X[i*I+t] * W1[t*H+j]
            t1[i*H+j] = s
    c['macs'] += B*I*H; c['writes'] += B*H*F32; c['reads'] += (B*I + I*H)*F32
    t2 = [0.0] * (B * H); c['launches'] += 1; c['temps'] += 1
    for k in range(B * H): t2[k] = max(t1[k], 0.0)
    c['writes'] += B*H*F32; c['reads'] += B*H*F32
    y = [0.0] * (B * O); c['launches'] += 1; c['temps'] += 1
    for i in range(B):
        for j in range(O):
            s = b2[j]
            for t in range(H): s += t2[i*H+t] * W2[t*O+j]
            y[i*O+j] = s
    c['macs'] += B*H*O; c['writes'] += B*O*F32; c['reads'] += (B*H + H*O)*F32
    return y

def fused(X, W1, b1, W2, b2, c):
    """后端 1：把 matmul+bias+relu 与 matmul+bias 各融成 1 个 kernel（2 个 kernel、1 个中间张量）。"""
    h = [0.0] * (B * H); c['launches'] += 1; c['temps'] += 1
    for i in range(B):
        for j in range(H):
            s = b1[j]
            for t in range(I): s += X[i*I+t] * W1[t*H+j]
            h[i*H+j] = s if s > 0.0 else 0.0
    c['macs'] += B*I*H; c['writes'] += B*H*F32; c['reads'] += (B*I + I*H)*F32
    y = [0.0] * (B * O); c['launches'] += 1
    for i in range(B):
        for j in range(O):
            s = b2[j]
            for t in range(H): s += h[i*H+t] * W2[t*O+j]
            y[i*O+j] = s
    c['macs'] += B*H*O; c['writes'] += B*O*F32; c['reads'] += (B*H + H*O)*F32
    return y

def blocked(X, W1, b1, W2, b2, c, BM):
    """后端 2：再按 BM 行分块，让激活块有机会留在片上；代价是权重按块重读。"""
    h = [0.0] * (B * H); c['temps'] += 1
    nblk = math.ceil(B / BM); c['launches'] += 2 * nblk
    for i in range(B):
        for j in range(H):
            s = b1[j]
            for t in range(I): s += X[i*I+t] * W1[t*H+j]
            h[i*H+j] = s if s > 0.0 else 0.0
    y = [0.0] * (B * O)
    for i in range(B):
        for j in range(O):
            s = b2[j]
            for t in range(H): s += h[i*H+t] * W2[t*O+j]
            y[i*O+j] = s
    c['macs'] += B*I*H + B*H*O
    # 流量模型：X 读一次；权重按块重读；激活只在块超出片上容量时才写回并再读
    X_b, W_b, Y_b, Act_b = B*I*F32, (I*H + H*O)*F32, B*O*F32, B*H*F32
    spill = 2 * Act_b if BM*H*F32 > CACHE_BYTES else 0
    c['reads'] += X_b + nblk * W_b + spill // 2
    c['writes'] += Y_b + spill // 2
    return y

def bench(fn, reps=10):
    """返回 (输出, 计数, 最小耗时 ms, 极差 ms)。热身 2 次且丢掉第 1 个计时样本，
    让解释器/分配器的冷启动效应出局；极差说明这行实测有多可信。"""
    fn(newc()); fn(newc())
    times, out, c = [], None, None
    for _ in range(reps):
        c = newc(); t0 = time.perf_counter(); out = fn(c); times.append((time.perf_counter() - t0) * 1e3)
    times = times[1:]
    return out, c, min(times), max(times) - min(times)

def scale(B2, I2, H2, O2, BM, wbytes=F32):
    """放大到真实尺寸：只算流量模型（不做真实计算）。wbytes = 权重每元素字节数。"""
    X_b, W_b, Y_b, Act_b = B2*I2*F32, (I2*H2 + H2*O2)*wbytes, B2*O2*F32, B2*H2*F32
    nblk = math.ceil(B2 / BM)
    spill = 2 * Act_b if BM*H2*F32 > CACHE_BYTES else 0
    return {'B0 eager 逐算子':   X_b + W_b + 4*Act_b + Y_b,
            'B1 融合(2 kernel)': X_b + W_b + 2*Act_b + Y_b,
            f'B2 融合+分块 BM={BM}': X_b + nblk*W_b + Y_b + spill,
            'B3 融合+权重 int8': X_b + W_b/2 + 2*Act_b + Y_b}

if __name__ == '__main__':
    rnd = random.Random(7)
    X = [rnd.uniform(-1, 1) for _ in range(B*I)]
    W1 = [rnd.uniform(-1, 1) for _ in range(I*H)]; b1 = [rnd.uniform(-1, 1) for _ in range(H)]
    W2 = [rnd.uniform(-1, 1) for _ in range(H*O)]; b2 = [rnd.uniform(-1, 1) for _ in range(O)]
    ref = None; rows = []
    for name, fn in (('B0 eager 逐算子', lambda c: eager(X, W1, b1, W2, b2, c)),
                     ('B1 融合(2 kernel)', lambda c: fused(X, W1, b1, W2, b2, c)),
                     ('B2 融合+分块 BM=8', lambda c: blocked(X, W1, b1, W2, b2, c, 8)),
                     ('B2 融合+分块 BM=32', lambda c: blocked(X, W1, b1, W2, b2, c, 32))):
        out, c, ms, sp = bench(fn)
        if ref is None: ref = out
        rows.append((name, out, c, ms, sp))

    print(f'=== 报告卡（第 1 部分）：实测与计数（B={B} I={I} H={H} O={O}，fp32，纯 Python）===')
    print(f'  {"后端":<22}{"kernel":>7}{"中间张量":>9}{"MACs":>10}{"搬运字节":>11}{"实测(min9)":>12}{"极差":>9}{"正确性":>8}')
    ok = True
    for name, out, c, ms, sp in rows:
        d = max(abs(a - b) for a, b in zip(out, ref)); ok &= (d == 0.0)
        print(f'  {name:<22}{c["launches"]:>7}{c["temps"]:>9}{c["macs"]:>10,}'
              f'{(c["reads"]+c["writes"])/1024:>10.1f}K{ms:>11.2f}ms{sp:>8.2f}ms{("通过" if d == 0 else "不通过"):>8}')
    print(f'  正确性门：四个后端与 B0 逐元素完全相同（同一累加顺序）→ {"通过" if ok else "不通过 ← 有 bug"}')
    dmax = max(r[3] for r in rows) - min(r[3] for r in rows)
    spmax = max(r[4] for r in rows)
    print(f'  后端之间的最大差 {dmax:.2f} ms，而单后端重复测量的极差最大 {spmax:.2f} ms —— '
          f'{"差异被噪声淹没，本行不出性能结论" if dmax < spmax else "差异超出噪声，可作初步观察"}')
    print(f'  同时 B2(BM=8) 的搬运字节 {((rows[2][2]["reads"]+rows[2][2]["writes"])/1024):.1f}K '
          f'高于 B1 的 {((rows[1][2]["reads"]+rows[1][2]["writes"])/1024):.1f}K：'
          f'计数与实测指向不同结论，报告必须分别标注口径')

    print('\n=== 报告卡（第 2 部分）：放大到真实尺寸的流量模型（B=8,I=4096,H=11008,O=4096）===')
    print(f'  假设带宽 {BW_GBPS:.0f} GB/s；激活侧 {8*11008*F32/1024:.0f} KiB/张量，权重侧 '
          f'{(4096*11008 + 11008*4096)*F32/1e6:.1f} MB')
    M = scale(8, 4096, 11008, 4096, 8)
    base = M['B0 eager 逐算子']
    print(f'  {"后端":<24}{"搬运":>11}{"模型内存时间":>14}{"相对 B0":>10}')
    for k, v in M.items():
        print(f'  {k:<24}{v/1e6:>9.1f}MB{v/(BW_GBPS*1e9)*1e3:>13.4f}ms{base/v:>9.3f}x')
    print(f'  结论：该形状下激活侧融合只省 {(base-M["B1 融合(2 kernel)"])/1e6:.1f} MB；'
          f'真正的大杠杆是权重字节数（int8 后可到 {base/M["B3 融合+权重 int8"]:.2f}x）')

    print('\n=== 报告卡（第 3 部分）：分块大小 BM 的取舍 ===')
    for BM in (1, 2, 4, 8):
        v = scale(8, 4096, 11008, 4096, BM)[f'B2 融合+分块 BM={BM}']
        print(f'  BM={BM:<2} 块数 {math.ceil(8/BM):<2} 权重重读 {math.ceil(8/BM):<2} 次  '
              f'搬运 {v/1e6:>8.1f} MB  模型内存时间 {v/(BW_GBPS*1e9)*1e3:>8.4f} ms')
    print('  读法：块越小权重重读越多；块越大，激活块超出片上容量才付写回代价。')
    print('  本例权重 360 MB 主导，分块不划算 —— 报告卡必须把负结果如实写出来，而不是只报赢的')

    print('\n=== 报告卡（第 4 部分）：换算成端到端收益（Amdahl）===')
    for share in (0.3, 0.65):
        k = base / M['B3 融合+权重 int8']
        print(f'  若该段占端到端 {share:.0%}、段内提速 {k:.2f}x → 端到端 {1/((1-share)+share/k):.3f}x')
    print('  报告卡的最后一栏必须是端到端换算：段内 2x 在覆盖率 30% 时只剩约 1.2x')

三、练习#

  1. 实现：加后端 B4：融合 + 把权重转置成访存友好的布局（一次 layout 变换）。它不减少字节，但改变"能否向量化"——为它补一个 eff（有效算力比例）参数，把结论写进报告卡。
  2. 解释：第 1 部分里 B2(BM=8) 的 kernel 数是 8、搬运 84.0K，而 B1 是 2 和 42.0K。为什么 B2 在计数上更差？若换成权重只有 2 MB 的小模型（批量 32），B2 的排名会怎么变？提示：先看 nblk * W_b 与 Act_b 的量级。
  3. 对比/验证：把 CACHE_BYTES 从 256 KiB 调到 8 KiB，重跑第 3 部分，记录 spill 从哪档 BM 开始出现；再调到 4 MiB，说明结论怎么变、为什么"片上容量"这个假设必须写进报告。
  4. 思考：若 vLLM 打开 -O3 后吞吐提升 15%，用哪几步把收益拆成"编译覆盖""内核选择""图回放""调度"四份？每一份需要什么证据？
