InfiniBand / RoCE / GPUDirect RDMA：跨机通信路径#

域内再快也出不了机箱。一旦 rank 分布到两台机器上，数据必须穿过网卡——而 GPU 不能被别的节点直接寻址，所以"跨机"这两个字换来的是一条固定路径：GPU → PCIe → NIC → 线缆 → 对端 NIC → PCIe → 对端 GPU。本课把这条路径拆成三段可算的账，并给出一个反直觉的结论：有时候瓶颈不是网络，而是 PCIe。

一、概念讲解#

1. 跨机只有一扇门：网卡#

节点之间的通信必须经过 NIC（host channel adapter）。这带来两个直接后果：

  • 节点出口带宽 = 各 NIC 端口之和，而不是 NVLink 域带宽。8 卡机每卡一条 400 Gb/s 的 IB 口时，出口是 8×50 = 400 GB/s 单向；只有 2 条口时出口仅 100 GB/s。
  • 门到门的距离要付钱：数据在 GPU 与 NIC 之间还得过一次 PCIe。这一步是否多余，就是 GPUDirect RDMA 要回答的问题。

2. InfiniBand 与 RoCE：同一套 verbs，两种网络#

按 IBTA 规范，InfiniBand 每端口单向带宽（Gb/s ÷ 8 得 GB/s）：

代际 每端口速率 单向 说明
EDR 100 Gb/s 12.5 GB/s —
HDR 200 Gb/s 25 GB/s —
NDR 400 Gb/s 50 GB/s 已给出最终物理规范
XDR 800 Gb/s 100 GB/s 每通道 SerDes 200 Gb/s；交换机间可到 1.6 Tb/s

InfiniBand 是一套独立的网络架构（有自己的子网管理器与链路层），设计上原生无损、延迟低。RoCE 是"RDMA over Converged Ethernet"：把 RDMA 语义跑在以太网上（RoCEv2 用 UDP 封装），能用便宜的以太网交换机组网，但因为以太网默认有丢包，需要 PFC/ECN 一类的拥塞控制把网络做成"无损或近无损"，否则重传会把吞吐打下来。

对上层来说两者是同一套 verbs，所以 NCCL 只认一个 IB 传输层（可用 NCCL_IB_DISABLE 关闭、或 NCCL_NET=Socket 强制走 TCP 回退——回退后性能掉一个量级，属于排障手段而非常态）。RoCE 相关参数也在 NCCL 环境变量里：NCCL_IB_GID_INDEX 指定 RoCE 的 GID 索引，NCCL_IB_ROCE_VERSION_NUM 指定 RoCE 版本（默认 2）。

3. GPUDirect RDMA：省掉的那次主机中转#

没有 GPUDirect RDMA（GDR）时，路径是"GPU 显存 → 主机 bounce buffer → NIC"，payload 在 PCIe 上要走两遍（先写进主机内存，NIC 再读走）。GDR 让 NIC 通过 PCIe BAR 直接读写真显存，把这一步变成一遍。

官方文档给出的硬条件很值得记：两个设备必须共享同一个上游 PCIe root complex，所以"能不能用 GDR"本质是一个拓扑问题，不是开关问题。NCCL 默认在拓扑允许时启用，并用 NCCL_NET_GDR_LEVEL 按 GPU–NIC 的拓扑距离设置门槛：LOC（永不用）、PIX（同一 PCIe 交换机）、PXB（多个 PCIe 交换机）、PHB（同一 NUMA 节点、流量过 CPU）、SYS（跨 NUMA 也启用）。另有 NCCL_DMABUF_ENABLE 用 Linux dma-buf 子系统做显存注册（默认为 1，内核或驱动不支持时自动关闭）。

4. 路径账本：Σα+max(s/β)#

一段多跳路径要按流水线算：延迟项逐段相加，带宽项取最慢的一段（不是相加，也不是取最快）：

T(s)=i∑​αi​+imax​βi​s​

这是本课最有用的一条式。它在示例 2 里直接给出答案（4 KiB / 1 MiB / 256 MiB，PCIe 4.0 与 5.0 两种机器）：

机器 4 KiB 1 MiB 256 MiB 瓶颈
PCIe 4.0 x16（31.5 GB/s）+ NDR 6.4 μs 39.6 μs 8.53 ms 本地 PCIe
PCIe 5.0 x16（63.0 GB/s）+ NDR 6.4 μs 27.3 μs 5.38 ms 本地 NIC

反直觉的地方：NDR 单口单向 50 GB/s，比 PCIe 4.0 x16 的 31.5 GB/s 还宽。也就是说，在 PCIe 4.0 的机器上插一张 NDR 网卡，网卡永远吃不饱——PCIe 才是瓶颈。换到 PCIe 5.0 x16（63 GB/s），瓶颈才回到网卡。先算清哪一段最慢，再谈调优。

5. 从节点出口看 ring：跨机那一跳有多贵#

把上面两段合起来：8 张卡、每卡一条 NDR 口，用示例 3 的模型算 1 GiB 梯度的 ring AllReduce（每步每条环边传 s=S/p，共 2(p−1) 步）：

规模 单向 β 预测时间
1 节点 × 8 卡 450 GB/s（NVLink） 4.25 ms
2 节点 × 8 卡 50 GB/s（NDR） 40.42 ms
8 节点 × 8 卡 50 GB/s 42.91 ms
32 节点 × 8 卡 50 GB/s 45.33 ms

从 1 台机器加到 2 台，时间涨了约 9.5 倍——几乎全部来自链路从 NVLink 换成 NDR（450 → 50 GB/s）这一次性跳变。之后继续从 2 节点加到 32 节点，时间只从 40.4 ms 缓慢涨到 45.3 ms：ring 里每个 rank 要搬的总字节数约等于 2S，与 p 无关，随 p 增长的只有 2(p−1) 次 α。所以跨机的代价是"换链路"的跳变，而不是"加节点"的线性恶化——前提是每张卡都能独占一条 rail 口；如果 8 张卡共享 2 条口，β 就被分摊，时间会成倍上涨。

这也是后面所有并行策略的动机：要压的不是节点数，而是"多少字节必须出门"。

6. 常见坑#

  • Gb/s 当 GB/s 用：把 400 Gb/s 当 400 GB/s，预算会差 8 倍。
  • 只看端口速率，不看 NIC 与 GPU 的亲和性：NIC 挂在别的 PCIe 交换机或别的 NUMA 节点时，GDR 可能被 NCCL_NET_GDR_LEVEL 挡在 PHB/SYS，路径上多绕一跳。
  • 在 RoCE 上忽略无损配置：没有 PFC/ECN 的以太网遇到拥塞会丢包重传，吞吐可能塌到与 TCP 同级。
  • 以为 GDR 一定可用：需要共享上游 root complex；虚拟化与 IOMMU 配置也会影响。
  • 把 Socket 回退当成正常结果：NCCL_NET=Socket/NCCL_IB_DISABLE=1 是排障手段，性能量级不同。

7. 这一课到哪里为止#

这里假设了"任意两台机器之间的路径等价"。真实集群不是这样：它按 rail 与 spine 分层，跨层的那条路会骤降。下一课专门讲这件事。

二、可运行代码示例#

三段纯 Python（只用标准库）：先把 IB 端口速率换成 GB/s，再用流水线账本比较 GDR 与 bounce buffer，最后把跨机规模扫一遍。

# ===== 示例 1：InfiniBand 各代端口速率（Gb/s 换 GB/s 要除以 8） =====
IB = [("EDR", 100), ("HDR", 200), ("NDR", 400), ("XDR", 800)]      # Gb/s per port
print("InfiniBand 单口速率（IBTA 规范给出的量级）：")
for gen, gbps in IB:
    print(f"  {gen:<4} {gbps:4d} Gb/s/口 → 单向 {gbps / 8:6.1f} GB/s")
print(f"  8 口 NDR 的节点出口合计：单向 {8 * 400 / 8:.0f} GB/s")


# ===== 示例 2：跨机路径账本 T = Σα + max(s/β)（流水线下延迟相加、带宽取最慢一段） =====
def pipelined_us(s, hops):
    """hops = [(段名, α_μs, β_GB/s)]；返回这一段路径的传输时间（微秒）。"""
    return sum(a for _, a, _ in hops) + max(s / (b * 1e9) * 1e6 for _, _, b in hops)


def hops(s, pcie_bw, gdr):
    """gdr=True：GPU 与 NIC 之间 payload 只过一次 PCIe；
    gdr=False：payload 先在 PCIe 上写进主机 bounce buffer，NIC 再读一遍 → PCIe 段承载两倍字节。"""
    eff = pcie_bw if gdr else pcie_bw / 2
    return [("本地 PCIe", 1.5, eff), ("本地 NIC", 1.0, 50.0),
            ("IB 链路", 1.3, 50.0), ("对端 NIC", 1.0, 50.0), ("对端 PCIe", 1.5, eff)]


def bottleneck(hops_):
    return max(hops_, key=lambda h: 1.0 / h[2])[0]


for pcie, tag in ((31.5, "PCIe 4.0 x16"), (63.0, "PCIe 5.0 x16")):
    print(f"\n{pcie:.1f} GB/s 的 {tag} + 单口 NDR 400 Gb/s：")
    for kib in (4, 1024, 262144):
        s = kib * 1024
        t_gdr = pipelined_us(s, hops(s, pcie, True))
        t_buf = pipelined_us(s, hops(s, pcie, False))
        print(f"  {kib:>6} KiB：GDR {t_gdr:9.1f} μs（瓶颈 {bottleneck(hops(s, pcie, True))}）"
              f"   bounce {t_buf:9.1f} μs   比值 {t_buf / t_gdr:4.2f}×")


# ===== 示例 3：8 卡 ring AllReduce 跨机（每个 rank 独占一条 rail NIC） =====
def ring_ms(total_bytes, P, alpha_us, beta_gbps):
    """ring AllReduce：每步每条环边只传 s = total/P，共 2(P-1) 步。"""
    lat = 2 * (P - 1) * alpha_us
    bw = 2 * (P - 1) / P * total_bytes / (beta_gbps * 1e9) * 1e6
    return (lat + bw) / 1e3


grad = 1 * 2**30                                    # 1 GiB 梯度
print(f"\n{grad / 2**30:.0f} GiB AllReduce，每 rank 一条 NDR 口（单向 50 GB/s），α=5 μs：")
for nodes in (1, 2, 4, 8, 16, 32):
    P = 8 * nodes
    beta = 450.0 if nodes == 1 else 50.0            # 单机走 NVLink，跨机走 rail NIC
    print(f"  {nodes:>2} 节点 × 8 卡 = {P:>3} rank   ring = {ring_ms(grad, P, 5.0, beta):8.2f} ms")

  2. 解释：为什么"延迟相加、带宽取最慢"是对多跳流水线的正确近似？请画一条 3 跳的时间轴（每跳 αi​ 与 s/βi​）说明。
