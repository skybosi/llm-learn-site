张量并行#

前几章我们把单卡上的优化手段——KV Cache、PagedAttention、量化——讲了一遍。但当模型大到一张卡装不下，或者我们想用多张卡同时加速同一份请求时，单卡思路就走到头了。从这一章起进入分布式推理：把模型和计算拆到多张 GPU 上协同工作。这一课先讲最贴近矩阵运算本质的一种拆分方式——张量并行（Tensor Parallelism，TP）：不按"层"切，而是把单个权重矩阵本身切成几块，让一次矩阵乘法由多张卡分摊完成。

一、概念讲解#

1. 为什么需要把"一个矩阵"切开#

LLM 的主体是堆叠的 Transformer 层，每层里最重的计算是 Y = X @ W 形式的线性变换。假设某层权重 W 的 shape 是 [4096, 4096]（单精度约 64 MB），输入 X 是 [seq, 4096]。一张 24 GB 的卡要放权重的几十亿参数尚且吃力，再加上 KV Cache、激活值、优化器状态，就彻底超了。

更关键的是：张量并行同时解决"装不下"和"算得慢"两个问题。把 W 按列切成两份 W1、W2（各 [4096, 2048]），分别放到 GPU0、GPU1，两张卡各自算自己的那一半矩阵乘法，最后把结果拼起来——显存占用减半，计算量也减半，理想情况下延迟接近单卡的一半。这就是张量并行的核心直觉：把一次大矩阵乘法变成多张卡上并行的小矩阵乘法。

2. 列并行与行并行：Transformer 的两类切法#

Megatron-LM 最早把 Transformer 的 FFN 和注意力层规范化成两种标准切法。

列并行（Column Parallel）：把权重按列切。线性层 Y = X @ W + b，W 切成 [W1 | W2]，偏置 b 也对应切。每张卡持有完整输入 X，算出各自的 Y_i = X @ W_i + b_i，最后把输出在列维度拼接。它适合放在层的前半段，因为切分后每张卡的输出只有原来的一半宽，下游接着切就行。

行并行（Row Parallel）：把权重按行切。W 切成 [W1; W2]（上下叠放），此时要求输入 X 也按列切成 [X1 | X2]，两张卡分别算 Y_i = X_i @ W_i，最后把结果做一次 AllReduce 求和得到完整 Y。它天然接在列并行之后，用来把"被切开的中间表示"重新合拢回完整维度。

一个标准 Transformer FFN 的排布是：[列并行 up/gate 投影] → 激活函数 → [行并行 down 投影]。注意力层的 Q/K/V 投影同理可以用列并行，输出投影 O 用行并行。两次列并行之间只传"半个向量"，中间激活函数和 dropout 都只在本地半张上做，通信只在边界发生。

3. 通信是怎么发生的#

列并行最后一步是拼接，行并行最后一步是求和，两者都归结为集合通信原语：

  • AllGather：把各卡的半张输出凑成完整张量（列并行拼接的推广）；
  • ReduceScatter / AllReduce：把各卡的部分结果求和并广播/分发（行并行求和的推广）。

张量并行的代价主要就是这些通信：每经过一个"行并行 → 列并行"的边界就要来回同步一次。这也解释了为什么 TP 对卡间带宽极其敏感——两张卡若只靠慢速 PCIe 互联，通信时间会吃掉并行省下的计算时间。因此 TP 通常只部署在单机内的多卡（NVLink/NVSwitch 高速互联）之间，跨机器做 TP 通信代价太高。

4. 注意力头的并行与 KV 的配合#

对多头注意力，一个更直观的切法是把注意力头分给不同卡：每张卡持有若干个头的 Q/K/V/O 权重，各自算完 softmax 后，O 投影的结果再做一次 AllReduce。配合 MQA/GQA（若干查询头共享同一组 KV 头），KV Cache 还能按"KV 头"切到不同卡上，进一步降低单卡显存压力。vLLM、TensorRT-LLM 等引擎在底层就是把张量并行 + 头并行 + KV 切分打包成 tensor_parallel_size 一个参数暴露给你。

二、可运行代码示例#

示例 1：用 torch 手写一个简化版张量并行 FFN#

下面这段代码演示列并行 + 行并行的核心逻辑。为了在单机不依赖多卡也能理解，我们用"显式切分权重"来模拟两块 GPU 的分工，注释标出每一步在真实多卡里对应哪张卡、哪次通信。

import torch

torch.manual_seed(0)

d_model, d_ff = 8, 16        # 隐藏维 8，FFN 中间维 16（故意取小便于打印）
seq = 3                       # 3 个 token

# 模拟"完整"的 up 投影与 down 投影权重
W_up = torch.randn(d_model, d_ff)   # [8, 16]
W_down = torch.randn(d_ff, d_model) # [16, 8]
x = torch.randn(seq, d_model)       # 输入 [3, 8]

# ---- 单卡基线（结果参考）----
y_ref = (x @ W_up).relu() @ W_down

# ---- 张量并行：按列切成两块，分到 GPU0 / GPU1 ----
tp = 2
W_up0, W_up1 = W_up.chunk(tp, dim=1)       # 各 [8, 8]   （列并行：每卡持半列）
W_down0, W_down1 = W_down.chunk(tp, dim=0) # 各 [8, 8]   （行并行：每卡持半行）

# GPU0 的本地计算：x 完整可见，算半段中间表示
h0 = (x @ W_up0).relu()          # [3, 8]
# GPU1 的本地计算
h1 = (x @ W_up1).relu()          # [3, 8]

# 行并行要求输入按列切分——列并行后中间表示 h 正是 [h0 | h1]，天然满足
y0 = h0 @ W_down0                # [3, 8]   GPU0 的部分和
y1 = h1 @ W_down1                # [3, 8]   GPU1 的部分和

# 行并行的收尾：AllReduce 求和（真实多卡用 torch.distributed.all_reduce）
y_tp = y0 + y1

print("与单卡结果的最大误差:", (y_tp - y_ref).abs().max().item())  # 应为 0

输出 0，说明切开再拼回的数学结果与单卡完全一致——张量并行是数值等价的拆分，只是把计算与存储摊到了多张卡上。

示例 2：用 vLLM 一行开启张量并行#

真实部署不需要手写切分，交给引擎即可。以 vLLM 为例，tensor_parallel_size 就是 TP 卡数：

# 用 4 张卡做张量并行，serving 一个 70B 模型
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --tensor-parallel-size 4 \
    --dtype bfloat16
# 客户端照常请求，引擎内部已把权重与 KV 切到 4 张卡
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
resp = client.chat.completions.create(
    model="meta-llama/Llama-3.1-70B-Instruct",
    messages=[{"role": "user", "content": "一句话解释张量并行"}],
)
print(resp.choices[0].message.content)

注意两点：tensor_parallel_size 一般取 2 的幂且不超过单机 GPU 数（TP 依赖高速 NVLink）；切得越细，通信占比越高，所以不是越大越快，要根据卡间带宽实测。

三、练习#

  1. 把示例 1 改成 tp=4 的切分，验证结果仍与单卡一致；再思考：切到 4 份后，行并行收尾需要几次 AllReduce？
  2. 用 torch.distributed 的 all_reduce 把示例 1 的 y0 + y1 改写成真实的两进程通信版本，在两张卡或两个进程上跑通。
  3. 手算一个 [d_model, d_ff] 的权重按列并行切 2 份后，每张卡的显存与计算量分别是原来的几分之几；说明为什么"通信开销"会随 TP 卡数增加而恶化。
  4. 若在单机上用 2×A100（NVLink 互联）跑 tensor_parallel_size=2，对比 =1 时 TTFT 的变化，解释增益与通信开销的来源。
