数据准备#

微调效果的上限，很大程度由数据决定——"垃圾进，垃圾出"在微调里体现得尤其明显。本课讲清指令微调（SFT）数据的格式、质量、清洗与分词这一整套准备流程。

一、概念讲解#

1. SFT 数据长什么样#

指令微调数据最常见的结构是"指令 + 输入 + 输出"三元组：

instruction（指令）: 让模型做什么
input（输入）:       可选的任务上下文
output（输出）:      期望的参考答案

一个典型样本：

字段 内容
instruction 把下面的句子翻译成英文
input 今天天气很好。
output The weather is nice today.

在训练时，这些字段会被拼成一段对话（chat）格式文本，并用 chat template 编码，再按"只对回答部分算损失"的方式做标签掩码（上一课已讲）。字段本身不必拘泥于这三个名字，核心是"给模型一段上下文，教它输出什么"。

2. 数据质量比数据量更重要#

一个常见的误区是"数据越多越好"。对 SFT 而言，几千到几万条高质量、多样、覆盖目标分布的样本，往往比几十万条低质量样本更有效。质量维度包括：

  • 正确性：参考答案本身要准确，否则模型会学到错误行为。
  • 格式一致：同类任务输出格式要统一（例如都用 JSON、都用"结论 + 理由"）。
  • 多样性：覆盖不同的指令类型、表达方式、难度，避免模型过拟合单一模板。
  • 与目标一致：答案要符合你期望的语气、长度、风格。
  • 无泄露/无污染：剔除与评测集重复的样本，避免"背答案"假象。

3. 数据清洗流水线#

拿到原始数据后，一般按顺序做：

  1. 去重：按文本相似度去重，去掉重复样本（重复会放大某些模式、导致过拟合）。
  2. 长度过滤：过滤过长/过短样本，避免超长序列浪费显存、过短样本无信息量。
  3. 语言/格式过滤：剔除乱码、非目标语言、HTML 标签残留等。
  4. 规则过滤：按业务规则剔除不合规内容（隐私、敏感词等）。
  5. 质量打分：用规则或模型对样本打分，保留高分样本（例如用大模型评估"回答是否优质"）。
  6. 去污染：与评测集做 n-gram 重叠检测，去掉重复的污染样本。

4. 数据配比与混合#

如果数据来自多个任务/领域，需要控制配比。例如：70% 主任务 + 20% 通用对话 + 10% 其他任务。混入少量通用数据能缓解灾难性遗忘；给核心任务更高权重能保证重点能力。配比是"调出来的"，通常要配合在验证集上的评测来迭代。

5. 训练/验证划分与分词#

  • 划分：留出一部分数据做验证集（如 5%–10%），用于监控过拟合、选超参数和早停。划分时注意不要让验证集和训练集有内容重叠。
  • 分词与 chat template：用模型对应的 apply_chat_template 把样本转成模型训练时看到的文本格式，再 tokenize。不同模型的 chat template 不同，必须用配套的模板，否则格式错配会显著损害效果。
  • padding/截断：batch 内 padding 到最大长度，超长序列按 truncation 截断；label 中对 padding 位置同样置 -100。

二、可运行代码示例#

下面演示一个完整的"从原始三元组到可分词的 Dataset"流程。

from datasets import Dataset
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B")
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

# 1) 原始 SFT 数据（instruction / input / output）
raw = [
    {"instruction": "把下面的句子翻译成英文", "input": "今天天气很好。", "output": "The weather is nice today."},
    {"instruction": "把下面的句子翻译成英文", "input": "我喜欢学习编程。", "output": "I like learning to program."},
    {"instruction": "总结下面这句话", "input": "模型在大量文本上预训练后，再用任务数据微调。", "output": "预训练后再微调。"},
    {"instruction": "总结下面这句话", "input": "下雨天道路湿滑，请减速慢行。", "output": "雨天路滑，注意减速。"},
]

def build_messages(example):
    """把三元组转成 chat 消息列表"""
    return {
        "messages": [
            {"role": "user", "content": example["instruction"] + "\n" + example["input"]},
            {"role": "assistant", "content": example["output"]},
        ]
    }

dataset = Dataset.from_list(raw).map(build_messages)

# 2) 用 chat template 拼接 + 分词，并构造 label 掩码
def tokenize_fn(example):
    # prompt 部分：只有 user 消息，末尾加生成提示
    prompt_text = tokenizer.apply_chat_template(
        example["messages"][:-1], tokenize=False, add_generation_prompt=True
    )
    # 完整对话：user + assistant
    full_text = tokenizer.apply_chat_template(example["messages"], tokenize=False)

    prompt_ids = tokenizer(prompt_text, add_special_tokens=False)["input_ids"]
    full_ids = tokenizer(full_text, add_special_tokens=False)["input_ids"]

    # prompt 部分不计算损失，置为 -100
    labels = [-100] * len(prompt_ids) + full_ids[len(prompt_ids):]
    return {"input_ids": full_ids, "labels": labels}

tokenized = dataset.map(tokenize_fn, remove_columns=["messages", "instruction", "input", "output"])
print("分词后的第一条样本：")
print("  input_ids 长度:", len(tokenized[0]["input_ids"]))
print("  前几个 label:", tokenized[0]["labels"][:5], "（-100 表示 prompt 部分不参与损失）")

再演示两个数据准备中的常见操作：去重 和 长度过滤。

# 3) 去重：按 instruction 文本去重（真实场景可用语义相似度）
def dedup(rows):
    seen, kept = set(), []
    for r in rows:
        key = r["instruction"].strip()
        if key not in seen:
            seen.add(key)
            kept.append(r)
    return kept

raw_dup = raw + [raw[0]]   # 故意加入一条重复样本
print("\n去重前样本数:", len(raw_dup), " 去重后样本数:", len(dedup(raw_dup)))

# 4) 长度过滤：过滤输出过短或过长的样本（阈值按业务定）
def length_ok(example, min_len=4, max_len=256):
    n = len(example["output"])
    return min_len <= n <= max_len

filtered = [r for r in raw if length_ok(r)]
print("长度过滤后样本数:", len(filtered))

三、练习#

  1. 填空：SFT 数据最常见的三元组结构是 、、____；训练时用 ____ 把样本拼成对话文本，并对 ____ 部分做 label 掩码（置 -100）。
  2. 判断：下列说法是否正确？为什么？
    • (a) 数据越多，微调效果一定越好。
    • (b) 只要参考答案正确，输出格式不一致也没关系。
    • (c) 验证集可以和训练集有部分重叠，只要比例不高。
  3. 动手实验：给上面的 raw 增加一条格式不一致的样本（例如"总结"任务的 output 写成一整段冗长的话），思考：这种不一致会对模型学习产生什么影响？
  4. 思考题：为什么"去污染"（剔除与评测集重复的样本）很重要？如果不做，会出现什么评估假象？
