专家并行（EP）与 MoE 负载均衡#

前面三种并行都在"切同一个稠密模型"。混合专家（Mixture-of-Experts，MoE）换了思路：模型里有 N 个专家子网络，每个 token 只被路由到其中少数几个，于是参数量可以涨很多倍而每个 token 的计算量不变。代价是路由：谁来决定 token 去哪、怎么保证每个专家都忙、以及 token 在设备之间怎么交换。本课把专家并行（Expert Parallelism，EP）的通信量和负载均衡问题都算成可打印的数。

一、概念讲解#

1. MoE 切什么：切专家，换一次 all-to-all#

MoE 层把标准 FFN 换成 N 个并行专家 FFN，外加一个 router（门控网络）；每个 token 按 router 概率被送往 top-k 个专家，输出按门控值加权求和。因为每个 token 只走 k 个专家，计算量与稠密模型同量级，参数量却是 N 倍——Switch Transformer 的口径是：top-1 路由同时压低了 router 计算、专家容量（每个 token 只去一个专家，容量至少可减半）与通信成本，相同算力下取得最高 7 倍预训练加速。

专家并行（EP）就是把 N 个专家分布到多张卡上（每卡放 N/P 个专家），token 通过 all-to-all 送到专家所在的设备，算完再送回来。DeepSpeed-MoE 论文把这个前提写得很直白：专家并行要求所有专家并行设备之间做 all-to-all 通信——通信模式与前三种并行完全不同，它是"全交换"，而不是规约。

2. 每个 MoE 层两次 all-to-all，通信量与 k 成正比#

一个 MoE 层的通信是两个方向各一轮：

阶段 方向 传什么
dispatch token → 专家所在设备 每个 token 的隐状态，按 router 结果重排
combine 专家 → token 原设备 专家输出，按原位置还原并加权

每 rank 单轮发出的字节数（T 为每 rank 本地 token 数、h 为 hidden、k 为 top-k、fp16）：

Vrank​=k⋅T⋅h⋅2⋅PP−1​（单轮）,Vtotal​=2kTh⋅2⋅PP−1​（dispatch + combine）

两个直接结论：通信量与 k 成正比（top-2 是 top-1 的两倍），每 rank 发送量随 P 增大趋近常数 kTh⋅2——并非越小越便宜；真正的代价是延迟项：all-to-all 要跨 P−1 个 peer，α 项随 P 线性增长，参与 rank 越多、慢节点拖累概率越高。示例 3：同一份专家计算量，NVLink 域内通信占比 0.9%3.8%，换成 25 GB/s 跨机就升到 9.3%18.0%。

3. 容量因子与丢 token#

专家是静态分配的：为了让形状固定、kernel 好写，每个专家每步只处理固定数量的 token：

expert capacity=(number of expertstokens per batch​)×capacity factor

如果路由不均，某个专家的 token 数超过容量，超出的 token 会被跳过该层（Switch 论文原话：these tokens not being processed by this layer）。容量因子 cf 是那把双刃的旋钮：

  • cf 太小 → 丢 token 多，模型质量受损（尤其对稀疏模型 scaling 不利）；
  • cf 太大 → padding 槽位多，算力和通信被浪费。

Switch 论文的实测是：在实验里 token 丢弃率通常低于 1%，前提是辅助损失系数足够大、负载足够均衡。示例 1/2 用 4096 个 token、8 个专家复现了这个现象：均衡 router 下 cf=1.0 丢 1.8%、cf≥1.25 不丢但空槽位涨到 20%~50%；而一个偏斜的 router 在同样 cf=1.0 下直接丢掉 45.8%。顺序很重要：先用辅助损失把负载调平，再调容量因子。

4. 辅助损失：把"均衡"写进目标函数#

要让 router 自己学会均衡，Switch 论文在一个 Switch 层上加入可微的辅助损失：

lossaux​=α⋅N⋅i=1∑N​fi​⋅Pi​

其中 fi​ 是分给专家 i 的 token 比例（由 argmax 计数得到），Pi​ 是 router 分配给专家 i 的概率比例（可微）。当 fi​=Pi​=1/N 时 ∑fi​Pi​=1/N，于是 lossaux​=α——这就是它的下界。示例 1 的实测：均衡 router 的辅助损失正好是 1.000，偏斜 router 涨到 2.025，而同一个偏斜 router 的丢 token 率是 45.8%。辅助损失就是"负载不均"的可微代理指标。

5. EP 与其他并行怎么组合#

真实 MoE 训练是组合出来的：attention 部分用 TP（或 DP），MoE 层把专家摊到 EP 组上，外层再叠 DP/ZeRO。DeepSpeed-MoE 的官方口径是：它通过灵活组合张量切片、数据并行、ZeRO 数据并行与专家并行，支持最高 8 倍大的模型，并用这套组合训练了 10B 参数的多任务多语言 MoE 模型（比同等质量的稠密模型少 5 倍训练时间）。更早的 GShard 则用 2048 块 TPU v3 在 4 天内训练了超过 600B 参数的稀疏 MoE 翻译模型。

一条工程约束：EP 的 all-to-all 是"全交换"，跨机时每一跳都变慢且互相干扰，所以 EP 组通常限制在高速域内（节点内或同一 rail/fabric）；这与 TP 的"别跨机"同类，但更严格，因为它的通信是全对全而非规约。

6. 常见坑#

  • 只调容量因子不看丢 token：丢 token 不报错，只是悄悄少算了些 token，质量下降很难归因。
  • 辅助损失系数过大：均衡目标会与语言建模目标冲突，质量反而变差；系数是超参，不是越大越好。
  • EP 组跨越慢链路：示例 3 的 18% 只是示例参数下的乐观估计，真实拥塞与尾延迟会让 all-to-all 更贵。
  • 以为 top-k 免费：k 从 1 加到 2，通信与专家计算都翻倍，容量因子也要重算。
  • 忽略弹性容量：按实际路由结果动态分配（DeepSpeed-MoE 一类做法）可免去丢 token，但调度复杂度上升——按训练稳定性权衡。

二、可运行代码示例#

第一段用 numpy 模拟 top-1 路由，看负载、丢 token 与辅助损失；第二段扫容量因子；第三段算 EP 每层的通信账本。全部不需要 GPU。

# ===== 示例 1：MoE 路由：负载不均与丢 token =====
import numpy as np
rng = np.random.default_rng(0)

def route(logits, k):
    return np.argsort(-logits, axis=1)[:, :k]        # top-k 路由

def stats(logits, k=1, cf=1.0):
    T, N = logits.shape
    idx = route(logits, k)
    load = np.bincount(idx.ravel(), minlength=N)
    cap = int(T/N*cf)
    dropped = int(sum(max(0, l - cap) for l in load))
    p = np.exp(logits - logits.max(1, keepdims=True)); p /= p.sum(1, keepdims=True)
    f = load/k/T                                        # 分给专家 i 的 token 比例
    P = p.mean(0)                                       # 路由概率分配给专家 i 的比例
    aux = N*np.sum(f*P)                                 # Switch 式辅助损失（未乘 α）
    return load, dropped, cap, aux

T, N, k = 4096, 8, 1
uniform = rng.normal(size=(T, N))                       # 均衡 router
skew = uniform.copy(); skew[:, 0] += 1.5; skew[:, 7] -= 1.5   # 偏斜 router
print("示例 1：MoE 路由（4096 个 token、8 个专家、top-1）")
for name, lg in (("均衡", uniform), ("偏斜", skew)):
    load, dropped, cap, aux = stats(lg, k, cf=1.0)
    print(f"  {name}：每专家负载 {load.tolist()}")
    print(f"        最大/均值 = {load.max()/load.mean():.2f}，容量因子 1.0 下丢 token {dropped} 个"
          f"（{dropped/T:.1%}），辅助损失 {aux:.3f}")

# ===== 示例 2：容量因子扫一遍：丢 token 与 padding 浪费 =====
print("\n示例 2：容量因子 cf 的取舍（expert capacity = (T/N)·cf；均衡 router）")
print("  cf     每专家容量   丢 token   丢 token 占比   空槽位占比(padding)")
for cf in (0.5, 0.75, 1.0, 1.25, 1.5, 2.0):
    load, dropped, cap, aux = stats(uniform, k, cf)
    used = sum(min(l, cap) for l in load)
    waste = (N*cap - used)/(N*cap)
    print(f"  {cf:<6} {cap:11d} {dropped:10d} {dropped/T:14.1%} {waste:18.1%}")
load, dropped, cap, aux = stats(skew, k, cf=1.0)
print(f"  对照：同一个 cf=1.0，偏斜 router 丢 {dropped} 个 token（{dropped/T:.1%}）——"
      "所以先看辅助损失，再调容量因子。")

# ===== 示例 3：EP 的 all-to-all 账本：dispatch + combine =====
def ep_layer_ms(local_tokens, P, k, h, tflops, beta_gbs, alpha_us=5.0, mfu=0.35, h_e=14336):
    """每 rank 固定 local_tokens 个 token；dispatch 与 combine 各一轮 all-to-all。
    通信用 α·(P-1) + s/β 的简化模型，s 为每 rank 单轮发出的字节。"""
    s = k*local_tokens*h*2*(P-1)/P                     # 发往其他 rank 的激活字节
    comm = 2*((P-1)*alpha_us + s/(beta_gbs*1e9)*1e6)/1e3
    comp = k*6*h*h_e*local_tokens/(tflops*1e12*mfu)*1e3 # 每 token 过 k 个专家的 FFN
    return comm, comp, s

print("\n示例 3：EP 每层账本（每 rank 2048 token、hidden 4096、专家中间维 14336、top-2、"
      "每卡 312 TFLOPS@35% MFU、α=5 us）")
print("  EP 度  单轮发送(MiB)  NVLink300 通信(ms)  跨机25 通信(ms)  专家计算(ms)  NVLink 通信占比")
for P in (2, 4, 8, 16, 32):
    c1, comp, sb = ep_layer_ms(2048, P, 2, 4096, 312, 300)
    c2, _, _ = ep_layer_ms(2048, P, 2, 4096, 312, 25)
    print(f"  {P:<6} {sb/2**20:12.1f} {c1:20.3f} {c2:18.3f} {comp:14.2f} {c1/(c1+comp):15.1%}")
for P in (2, 8, 32):
    c1, comp, _ = ep_layer_ms(2048, P, 2, 4096, 312, 300)
    c2, _, _ = ep_layer_ms(2048, P, 2, 4096, 312, 25)
    print(f"  通信占比：EP={P:<2} NVLink {c1/(c1+comp):5.1%} / 跨机25 {c2/(c2+comp):5.1%}")
print("  注：每 rank 发送量趋近上限 k·tokens·h·2 B（与 P 无关），但往返时延项 (P-1)·α 随 EP 度增长；")
print("      跨机链路上每一项都慢一个量级，且 EP 度越大，参与 all-to-all 的 rank 越多、慢节点概率越高。")

三、练习#

  1. 实现：把示例 1 的 router 改成 top-2，重算负载分布、丢 token（注意每个 token 占两个专家的槽位）与辅助损失；说明为什么 top-2 的容量因子通常要单独调。
  2. 解释：为什么辅助损失在 fi​=Pi​=1/N 时取最小值 1？如果某个 expert 分到 3 倍于平均的 token，而 router 概率仍均匀，辅助损失大约变成多少？
  3. 对比/验证：把示例 3 的 k 从 2 改成 1，重算每 rank 发送量与通信占比；讨论"top-1 省通信但可能掉质量"怎么权衡。
  4. 思考：8 个专家、EP 度 4、每 rank 本地 4096 token、hidden 4096、top-2、fp16。算出每层 dispatch + combine 的总通信字节数（全组与每 rank 各是多少），并给出跨 25 GB/s 链路的每层通信时间量级。
