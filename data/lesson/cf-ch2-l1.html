词法分析：token 化与手写扫描器#

第一课我们用正则切过词，那只是玩具。真实扫描器要回答的问题具体得多：if 为什么是关键字而 iffy 是标识符？a---b 该切成什么？字符串里的 \n 是反斜杠加 n 还是换行？这些判断有确定的规则，而规则一旦定错，后面的语法分析再正确也没用。这一课把"切词"从直觉变成一份可实现的规范。

一、概念讲解#

1. 为什么切词要独立成一个阶段#

词法结构是正则的（能用有限状态机描述），语法结构不是（括号配对需要计数）。把两层混在一起写，递归下降的每个函数都要重新处理空白、注释、数字格式，代码会迅速失控。分开的收益是可检验的：

  • 扫描器只需一遍、无回溯，O(n) 处理字符流；
  • 语法分析看到的输入是有类型的短列表，线性扫描即可，不必反复做字符判断；
  • 同一份扫描器能被格式化工具、语法高亮、IDE 补全复用——它们都只需要 token 流。

2. 一个 token 由哪些字段构成#

字段 含义 例（源码 count = 42; 里的 42）
type（类型） 词法类别，语法分析只看它 NUMBER
lexeme（原词） 源码里原始切片，报错时回显用 "42"
literal（字面值） 解释后的值，避免下游重复解析 42.0
line（行号） 出错定位 1

关键设计：数字与字符串的"值"在扫描阶段就算好（value() 顺带解析），把一处只做一次的活儿做完，语法分析只做结构。

3. 最长匹配（maximal munch）与前瞻#

规则只有两条：从当前位置起贪心吃最长的合法词；只有贪心没路可走时才退回一步。于是：

输入 切法 依据
a---b a - - - b - 是左结合减号，-- 不是本语言词法单元
a <= b a <= b <= 比 < 长，优先匹配
iffy 标识符 iffy 判关键字靠整个词相等，不做前缀匹配
1..2 若语言有 .. 则 1 .. 2 长度优先

= 与 == 这种"一条边对应两种规则"的情况，实现手法是先吃下第一个字符，再前瞻一个字符决定是否吞第二个。前瞻只做一次，不需要回溯整个 token。

4. 关键字是个"查表"问题，不是词法问题#

朴素做法是给每个关键字写一条规则、各自一个 token 类型。工业做法更省：把关键字当标识符扫，扫完后拿 lexeme 去哈希表查，命中就把类型从 IDENTIFIER 换成对应关键字类型（查表 O(1)，表在编译期就是常量）。

识别规则本身也是可列举的：标识符允许首字符为字母或下划线、其后为字母/数字/下划线；多数工业语言只接受 ASCII 字母数字，个别语言（如 Java）允许 Unicode 标识符。这些细节必须写进规范，否则 变量 这样的名字在不同实现上行为不一致。

5. 扫描器内部其实是个小状态机#

一个手写扫描器可以写成两层：外层跳过空白与注释并循环，内层按当前字符分派到 identifier、number、string、scan_token 四个分支。Crafting Interpreters 第 4 章就是这套结构，它和下一课的自动机没有本质差别——区别只在"转移表是手写的还是自动生成的"。

二、可运行代码示例#

下面这个扫描器支持注释、关键字表、==/!=/<=/>= 双字符运算符、带小数的数字、带转义与行号统计的字符串。

# ---- 例 1：手写扫描器（纯标准库，直接 python3 运行）----
KEYWORDS = {
    'if': 'IF', 'else': 'ELSE', 'while': 'WHILE', 'for': 'FOR',
    'var': 'VAR', 'print': 'PRINT', 'true': 'TRUE', 'false': 'FALSE',
    'and': 'AND', 'or': 'OR', 'nil': 'NIL',
}

class Token:
    __slots__ = ('type', 'lexeme', 'literal', 'line')
    def __init__(self, type_, lexeme, literal=None, line=1):
        self.type, self.lexeme, self.literal, self.line = type_, lexeme, literal, line
    def __repr__(self):
        return f'{self.type:<6} {self.lexeme!r:<12} line {self.line}'

class ScannerError(Exception):
    pass

class Scanner:
    def __init__(self, src):
        self.src, self.start, self.cur, self.line = src, 0, 0, 1
        self.tokens = []

    # --- 字符流工具 ---
    def at_end(self):   return self.cur >= len(self.src)
    def advance(self):
        ch = self.src[self.cur]; self.cur += 1; return ch
    def peek(self, k=0):
        i = self.cur + k
        return self.src[i] if i < len(self.src) else '\0'
    def match(self, expect):
        if self.at_end() or self.src[self.cur] != expect: return False
        self.cur += 1; return True

    def add(self, type_, literal=None):
        self.tokens.append(Token(type_, self.src[self.start:self.cur], literal, self.line))

    # --- 主循环：跳过空白/注释，再分派 ---
    def scan(self):
        while not self.at_end():
            self.start = self.cur
            self.scan_token()
        self.tokens.append(Token('EOF', '', None, self.line))
        return self.tokens

    def scan_token(self):
        c = self.advance()
        if c in ' \t\r':                       # 空白直接丢
            return
        if c == '\n':
            self.line += 1; return
        if c == '/' and self.match('/'):       # 行注释丢到行尾
            while self.peek() != '\n' and not self.at_end():
                self.advance()
            return
        if c == '(': return self.add('LEFT_PAREN')
        if c == ')': return self.add('RIGHT_PAREN')
        if c == '{': return self.add('LEFT_BRACE')
        if c == '}': return self.add('RIGHT_BRACE')
        if c == ';': return self.add('SEMICOLON')
        if c == '+': return self.add('PLUS')
        if c == '-': return self.add('MINUS')
        if c == '*': return self.add('STAR')
        if c == '/': return self.add('SLASH')
        if c == '=': return self.add('EQUAL_EQUAL' if self.match('=') else 'EQUAL')
        if c == '!': return self.add('BANG_EQUAL' if self.match('=') else 'BANG')
        if c == '<': return self.add('LESS_EQUAL' if self.match('=') else 'LESS')
        if c == '>': return self.add('GREATER_EQUAL' if self.match('=') else 'GREATER')
        if c == '"': return self.string()
        if c.isdigit(): return self.number()
        if c.isalpha() or c == '_': return self.identifier()
        raise ScannerError(f'第 {self.line} 行：非法字符 {c!r}')

    def string(self):
        buf = []
        while self.peek() != '"':
            if self.at_end():                      # 明确报错，而不是切出一个残缺 token
                raise ScannerError(f'第 {self.line} 行：未闭合的字符串')
            if self.peek() == '\n':
                self.line += 1
            c = self.advance()
            if c == '\\':                          # 转义：这里只示范 \\n 与 \\"
                nxt = self.advance()
                buf.append({'n': '\n', 't': '\t', '"': '"', '\\': '\\'}.get(nxt, nxt))
            else:
                buf.append(c)
        self.advance()                             # 吃掉收尾的 "
        self.add('STRING', ''.join(buf))

    def number(self):
        while self.peek().isdigit():
            self.advance()
        if self.peek() == '.' and self.peek(1).isdigit():
            self.advance()
            while self.peek().isdigit():
                self.advance()
        self.add('NUMBER', float(self.src[self.start:self.cur]))

    def identifier(self):
        while self.peek().isalnum() or self.peek() == '_':
            self.advance()
        text = self.src[self.start:self.cur]
        kind = KEYWORDS.get(text)                  # 关键字 = 查表，不做前缀匹配
        self.add(kind or 'IDENTIFIER')

SRC = '''var total = 0;      // 一只累加器
while total <= 10 and total != 3 {
  total = total + 2 * 1.5;
}
print "sum = \\n" ;'''

for tok in Scanner(SRC).scan():
    print(tok)

运行输出（节选，type / lexeme / line；数字与字符串的 literal 已在扫描期解析完毕）：

VAR    'var'        line 1
IDENTIFIER 'total'      line 1
EQUAL  '='          line 1
NUMBER '0'          line 1
SEMICOLON ';'          line 1
WHILE  'while'      line 2
IDENTIFIER 'total'      line 2
LESS_EQUAL '<='         line 2
NUMBER '10'         line 2
...
STRING '"sum = \\n"' line 5
EOF    ''           line 5

注意 if 只出现在关键字表里、iffy 落在 IDENTIFIER；// 一只累加器 整段消失但 line 照常前进——行号必须在丢注释时也维护，否则后面所有报错定位都会偏。

三、练习#

  1. 实现：给例 1 加 <=、>= 的位置记录（起始列号），让报错能输出 第 2 行第 11 列。再补一条 /* 块注释 */：注意未闭合块注释要报错而不是静默到文件尾。
  2. 解释：为什么关键字用"先当标识符、再查表"实现，比给每个关键字写独立词法规则更好？从表的大小、代码量与可维护性两方面回答。
  3. 对比：a---b、1..2、x=y==z 三段在"最长匹配"下分别切成什么？如果语言里有 .. 却没有 --，这会影响切法吗？
  4. 思考：扫描器只能识别正则语言。给出一个"看起来像词法问题、其实不是"的例子（提示：C 的 >> 在模板 vector<vector<int>> 里该不该切开），并说明为什么这个判断被推迟到了语法分析。
