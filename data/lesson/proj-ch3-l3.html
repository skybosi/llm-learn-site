结果与复盘（LLM 领域微调）#

微调项目最难的不是"跑通训练"，而是证明这次微调是值得的。本课把结果落成三样东西：微调前后对比、rank/alpha 选择实验、以及一套能顶住面试追问的话术。做完本课，你手里是"可复现的效果证据 + 可对答的工程决策"。

一、目标与步骤#

  1. 微调前后对比：同一测试集的基座 vs 微调分数与样例对比。
  2. rank/alpha 选择实验：用数据说明"为什么用 r=8/alpha=16"。
  3. 成本与效果复盘：显存、时间、可训练参数占比。
  4. 面试话术：预演高频追问，特别是"为什么 LoRA 不用全参微调"。

二、代码骨架与实现指导#

1. 微调前后对比表#

把第 2 课的评估函数跑在基座与微调模型上，汇总成报告表：

import pandas as pd

汇报要点：不要只报"准确率涨了"，要分项说明——格式遵循率大涨，证明 LoRA 把"按 JSON 输出"烧进了权重；领域准确率提升，证明领域知识/习惯被注入。若领域准确率提升有限，也如实说明，并给出"数据量不足/知识更适合 RAG"的结论，这比虚报更专业。

3. rank/alpha 选择实验#

回答"r 取多少"的最好方式不是背结论，而是小规模实验：

# 用同一份数据、同一超参，只改 r，训少量步数后在验证集打分
import itertools
grid = [(8, 16), (16, 32), (64, 128)]   # (r, alpha)
for r, alpha in grid:
    cfg = LoraConfig(r=r, lora_alpha=alpha, lora_dropout=0.05,
                     target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
                     task_type=TaskType.CAUSAL_LM)
    # 训练 0.5~1 epoch，记录验证 loss 与格式遵循率，以及可训练参数数
    print(f"r={r}, alpha={alpha}, 可训练参数占比={pct:.3%}, val_loss={vloss:.4f}")

预期方向：r 过小（如 4）表达力不足、指标偏低；r 过大（如 64）参数更多但收益边际递减、且更易过拟合；r=8~16 在领域任务上常是性价比拐点。结论必须来自你的数据，这张"拐点表"就是你 rank 选择的证据。

三、面试话术#

Q1：为什么用 LoRA 而不是全参数微调？ 答：全参数微调 7B 需要约 112GB 显存，个人根本负担不起；LoRA 冻结原权重、只训练低秩增量，把显存降到 18GB，可训练参数占比约 0.3%，单卡 2 小时就能出结果。更重要的是，LoRA 的增量权重是独立可插拔的——我可以在同一个基座上保存多个领域的 adapter，部署时按需挂载，比每个领域存一份全量模型更经济、更易维护。

Q2：r 和 alpha 你是怎么选的？ 答：r 决定低秩增量的表达力，alpha 是与 r 挂钩的缩放系数，一般取 r 的 1~2 倍。我做了 r=8/16/64 的小规模对比，发现 r=8 已经接近性能拐点，r=64 收益边际递减还更容易过拟合，所以选了 r=8、alpha=16。结论来自我的验证集实验，不是抄默认值。

Q3：微调会不会"灾难性遗忘"基座能力？ 答：LoRA 冻结原权重、只加低秩增量，天然缓解遗忘；我再加了两道保险——控制 epoch 数（3 个）、用 warmup + 余弦学习率，并在评估时同时看领域指标与通用格式指标。如果发现通用能力下降，我会降学习率或减少 epoch，而不是硬训。

Q4：你怎么保证微调数据质量？ 答：三步——去空去重、统一成 messages 格式套 chat template、人工抽检 100 条。微调是"垃圾进垃圾出"，我在数据清洗上花的时间不比训练少；另外我坚持"少量高质量"而不是"海量噪声"，3k 条就够见效果。

Q5：如果效果不达预期，你怎么排查？ 答：按顺序看——先看训练 loss 是否下降（不降查学习率与 chat template），再看验证集是否过拟合（涨了减 epoch/加 dropout），最后看评估指标（loss 低不等于答得好，必须上格式遵循率与领域准确率）。我踩过"没套 chat template 导致模型输出错乱"的坑，也踩过"学习率照搬全参微调导致 loss 震荡"的坑，现在都有固定的排查顺序。

Q6：微调和 RAG 在这个场景怎么权衡？ 答：如果领域知识频繁更新、且要可追溯，我会选 RAG；如果是"格式稳定 + 领域说话习惯 + 长期复现某种行为"，我选微调。这个项目选微调，是因为我要求模型稳定输出结构化 JSON 且带领域术语，这是提示词和 RAG 都难以稳定复现的。

四、常见坑（复盘清单）#

  1. 只报 loss：loss 低不代表答案好，必须上任务级指标（格式遵循率、领域准确率）。
  2. 没套 chat template：手动拼字符串导致训练数据与推理格式不一致，模型输出错乱。
  3. 学习率照搬全参微调：LoRA 该用更高的 2e-4 量级，用 1e-5 会几乎学不动。
  4. 数据没清洗：重复、空输出、格式错乱直接喂进去，白烧显存还学坏。
  5. r 拍脑袋且无实验：说不出 r 的依据，面试一问就露怯。
  6. 忽略遗忘风险：只看领域指标涨，不检查通用能力是否退化。
