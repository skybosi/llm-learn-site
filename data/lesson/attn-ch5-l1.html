掩码注意力#

进入编解码器细节的第一课，我们要解决一个"作弊"问题。Transformer 的解码器在训练时是一次看到整条目标序列的，但它要完成的任务是逐个生成：预测下一个 token 时，只能依赖"已经生成的部分"，绝不能偷看未来。如果不加约束，位置 t 的自注意力会顺手把 t+1、t+2 的信息也平均进来，训练时看起来很好，一到推理就崩盘——因为推理时未来根本还不存在。掩码注意力（masked attention）就是用一张"禁止未来"的掩码矩阵，把这种偷看堵死。这一课先讲清掩码的动机与结构，再讲它在代码里怎么实现，最后区分一下它和"padding 掩码"这两个容易混淆的概念。

一、概念讲解#

1. 解码器的任务天然是"因果"的#

解码器的使命是自回归生成：已知 y_1 ... y_{t-1}，预测 y_t。这意味着位置 t 只能"看见"位置 1 到 t（含自己），不能看见 t+1 及以后。我们把这种"只能看向过去、不能看向未来"的约束叫做因果约束（causal constraint），对应的掩码叫因果掩码，也叫前瞻掩码（look-ahead mask）。

为什么训练时也要戴上这副"眼罩"？因为训练用的 teacher forcing 策略（第 3 课细讲）要求：喂进去的是真实的、但右移了一位的目标序列，模型预测的每一个位置，都应该恰好等于"只凭历史能算出的那个答案"。如果允许偷看未来，模型会学到一个在训练数据上完美、在真实生成时完全不存在的捷径。

2. 掩码是怎么"堵"住的#

回忆注意力分数的计算：

scores = Q @ K^T / sqrt(d_k)         # (T, T)
weights = softmax(scores)            # 每行归一化为一个概率分布
output  = weights @ V

要让位置 t 完全不关注位置 j > t，最直接的办法是：把 scores[t][j] 设成负无穷。经过 softmax 后，exp(-inf) = 0，对应权重变成精确的 0。于是整张掩码矩阵长这样：

        j=0  j=1  j=2  j=3
  i=0 [  0, -inf, -inf, -inf ]
  i=1 [  0,   0,  -inf, -inf ]
  i=2 [  0,   0,   0,   -inf ]
  i=3 [  0,   0,   0,    0  ]

这是一个下三角矩阵：对角线及以下为 0（允许关注），以上为 −inf（禁止）。把这张掩码逐元素加到 scores 上，再 softmax，就得到每行和仍为 1、但上半区全为 0 的注意力权重矩阵。

3. 编码器为什么不需要因果掩码#

对比一下编码器和解码器的自注意力：

  • 编码器自注意力是双向的：翻译时，理解源句子里的一个词，完全可以参考它前面和后面的词（"bank" 是"银行"还是"河岸"，要看上下文）。所以编码器不加因果掩码，只可能加 padding 掩码。
  • 解码器自注意力是单向（因果）的：只能看过去。它必须加因果掩码。

注意，这两者都在解码器内部吗？不是——编码器里只有"编码器自注意力"，解码器里先有"解码器自注意力（因果）"，之后还有一层"交叉注意力"（第 2 课）。交叉注意力要看的是编码器的输出，那里不存在"未来偷看"的问题，所以它也不需要因果掩码。

4. 因果掩码 vs padding 掩码#

这是最容易混的两个概念，务必分清：

因果掩码（causal / look-ahead mask） padding 掩码（padding mask）
目的 禁止看未来位置 禁止看填充位 <pad>
形状 (T, T) 方阵，按位置关系决定 通常是 (batch, T) 的布尔序列
填充值 上三角 −inf 被 pad 的位置 −inf
用在哪 解码器自注意力 编码器和解码器都可能用（可变长序列）

一句话总结：因果掩码是"顺序约束"，padding 掩码是"长度约束"。两者经常同时出现：一个变长 batch 的解码器，既要按位置屏蔽未来，又要按内容屏蔽 pad。

二、可运行代码示例#

先用最原始的方式手工构造因果掩码，看它如何把 softmax 的未来权重压成 0。

import torch
import torch.nn.functional as F

def causal_mask(seq_len):
    """返回 (seq_len, seq_len) 的因果掩码：下三角为 0，上三角为 -inf"""
    # torch.triu 取上三角，diagonal=1 表示不含主对角线
    return torch.triu(torch.full((seq_len, seq_len), float("-inf")), diagonal=1)

T = 5
mask = causal_mask(T)
print("因果掩码矩阵:\n", mask)

# 模拟一组随机的 Q、K，计算注意力权重
d = 4
Q = torch.randn(T, d)
K = torch.randn(T, d)
scores = Q @ K.T / (d ** 0.5)

weights_masked = F.softmax(scores + mask, dim=-1)   # 关键：把掩码加到分数上
print("掩码后的注意力权重（每行和=1，上三角=0）:\n", weights_masked)
print("每行权重之和:", weights_masked.sum(dim=-1))   # 全为 1

# 验证未来位置确实被屏蔽：第 2 行只看 0,1,2 三个位置
print("第2行对未来位置(3,4)的权重:", weights_masked[2, 3:].tolist())  # [0, 0]

运行后可以看到，softmax 把 −inf 位置压成了 0，每一行仍是一个合法的概率分布。这就是因果约束的全部机制。

接着演示 padding 掩码，并说明两者如何叠加使用：

def padding_mask(lengths, max_len):
    """返回 (batch, max_len) 的布尔掩码：True 表示是 pad，需要屏蔽"""
    batch = len(lengths)
    idx = torch.arange(max_len).unsqueeze(0).expand(batch, max_len)
    return idx >= torch.tensor(lengths).unsqueeze(1)   # 超出真实长度的位置为 True

lengths = [3, 5]          # 两条序列：真实长度分别是 3 和 5
pad = padding_mask(lengths, max_len=5)
print("padding 掩码（True 为 pad）:\n", pad)

# 把 padding 掩码也转成可加到 scores 上的形式（示意）：
# 对每个 pad 位置，把对应整行/整列的分数设为 -inf，即可让其不参与注意力
scores = torch.randn(2, 5, 5)                        # (batch, T, T)
scores_pad = scores.masked_fill(pad.unsqueeze(1), float("-inf"))  # pad 作为 key 被屏蔽
print("叠加 padding 后第 0 条序列第 0 行:", scores_pad[0, 0])       # 位置 3、4 为 -inf
