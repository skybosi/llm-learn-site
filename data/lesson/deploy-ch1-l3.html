技术选型决策树#

前两课解决了"要什么"，这一课解决"选什么"。LLM 部署的技术栈现在非常多——vLLM、TensorRT-LLM、SGLang、llama.cpp、TGI，量化有 GPTQ/AWQ/FP8/GGUF，硬件从 L4 到 H100。选型没有万能答案，只有"在约束下最划算"的答案。本课给你一棵决策树，把需求输入进去，输出一套"引擎 + 量化 + 硬件"的组合。学完本课，你应当能解释每个分支的判断依据，并为一组真实需求给出可辩护的选型。

一、概念讲解#

1. 主流推理引擎速览#

引擎 强项 适用场景 备注
vLLM PagedAttention、continuous batching、OpenAI 兼容、生态好、上手快 在线服务、通用首选 社区活跃，文档全
SGLang RadixAttention（前缀缓存）、结构化输出、长序列 prefill 快 RAG、多轮、Agent、长上下文 与 vLLM 定位接近，增长快
TensorRT-LLM NVIDIA 官方、算子深度优化、低延迟高吞吐 追求极致性能、NVIDIA 全家桶 编译/部署流程较重
llama.cpp / Ollama GGUF 量化、纯 CPU/端侧、零依赖 端侧、边缘、CPU 推理、本地小模型 吞吐不及 GPU 引擎
TGI（HF Text Generation Inference） Hugging Face 出品、与 HF 生态集成 HF Hub 模型快速上线 功能与 vLLM 重叠

2. 量化方案怎么选#

上一门课学过原理，这里给选型结论：

  • AWQ / GPTQ：4-bit 权重量化，显存约为 FP16 的 1/4，精度损失小，GPU 推理主流；
  • FP8：8-bit，需 H100/Ada 等支持 FP8 的硬件，吞吐高、精度几乎无损；
  • GGUF（Q4_K_M 等）：llama.cpp 生态，支持 CPU + 混合 GPU，端侧/边缘首选；
  • bitsandbytes：8-bit/4-bit，主要用于加载显存不够时的权宜之计，生产吞吐一般。

经验：GPU 在线服务优先 AWQ（4-bit 或 8-bit）；有 FP8 硬件优先 FP8；端侧只能 GGUF。

3. 硬件怎么选#

按"模型参数 × 精度"估算权重大小（FP16 约 2 字节/参数，INT4 约 0.5 字节/参数 + 开销），再对照卡显存：

GPU 显存 适合（FP16） 适合（INT4/AWQ）
L4 24GB ≤ 7B ≤ 13B
A10 24GB ≤ 7B ≤ 13B
A100 40/80GB ≤ 30B / ≤ 70B ≤ 70B / 更大
H100 80GB ≤ 70B 70B+ 或需 FP8 提速

注意：显存还要留出 KV Cache 和激活，所以"权重大小 ≤ 显存"只是必要条件，不是充分条件。

4. 决策树主线#

把选择流程写成一条主线（下面示例会代码化）：

  1. 先定位场景：端侧？→ llama.cpp + GGUF；在线/离线 GPU？→ 继续；
  2. 看延迟敏感：在线延迟敏感 → vLLM / SGLang / TensorRT-LLM；离线批处理 → vLLM 打满吞吐即可；
  3. 看特殊需求：RAG/长前缀 → SGLang（前缀缓存）；极致性能 + NVIDIA 栈 → TensorRT-LLM；快速上线 → vLLM；
  4. 定量化：有 FP8 硬件 → FP8；否则 GPU 上 AWQ（4-bit）平衡精度与显存；
  5. 定硬件：按"权重 + KV Cache"估显存，选刚好装下、再留 20–30% 余量的卡；单卡装不下 → 下一章的多卡张量并行。

二、可运行示例#

下面的脚本把决策树实现为函数：输入场景特征，输出推荐引擎、量化与硬件。

# -*- coding: utf-8 -*-
# 技术选型决策树：需求特征 -> 推荐(引擎, 量化, 硬件)

def select_engine(edge: bool, latency_sensitive: bool, long_prefix: bool,
                  nvidia_stack: bool) -> str:
    if edge:
        return "llama.cpp"
    if latency_sensitive and long_prefix:
        return "SGLang（前缀缓存优先）"
    if latency_sensitive and nvidia_stack:
        return "TensorRT-LLM"
    return "vLLM"

def select_quant(fp8_hw: bool, edge: bool) -> str:
    if edge:
        return "GGUF Q4_K_M"
    return "FP8" if fp8_hw else "AWQ 4-bit"

def select_gpu(params_b: float, quant: str, kv_overhead_ratio: float = 0.3) -> str:
    # 权重字节估算：FP16≈2B/参, INT4≈0.5B/参, FP8≈1B/参
    bytes_per_param = {"GGUF Q4_K_M": 0.55, "AWQ 4-bit": 0.55,
                       "FP8": 1.05, "FP16": 2.0}[quant]
    weight_gb = params_b * bytes_per_param
    need_gb = weight_gb * (1 + kv_overhead_ratio)  # 留 KV Cache/激活余量
    # 常见卡显存，按从小到大选第一张够用的
    for gpu, mem in [("L4", 24), ("A10", 24), ("A100-40G", 40),
                     ("A100-80G", 80), ("H100-80G", 80)]:
        if need_gb <= mem * 0.85:   # 再留 15% 碎片余量
            return f"{gpu}（需显存约 {need_gb:.0f}GB）"
    return "单卡装不下 -> 下一章多卡张量并行"

cases = [
    ("手机离线翻译(0.5B)",  dict(edge=True,  latency_sensitive=True,  long_prefix=False, nvidia_stack=False, fp8_hw=False, params_b=0.5)),
    ("客服机器人(7B)",      dict(edge=False, latency_sensitive=True,  long_prefix=False, nvidia_stack=False, fp8_hw=False, params_b=7.0)),
    ("RAG 文档问答(8B)",    dict(edge=False, latency_sensitive=True,  long_prefix=True,  nvidia_stack=False, fp8_hw=True,  params_b=8.0)),
    ("离线批量生成(70B)",   dict(edge=False, latency_sensitive=False, long_prefix=False, nvidia_stack=False, fp8_hw=False, params_b=70.0)),
]
for name, f in cases:
    eng = select_engine(f["edge"], f["latency_sensitive"], f["long_prefix"], f["nvidia_stack"])
    q = select_quant(f["fp8_hw"], f["edge"])
    gpu = select_gpu(f["params_b"], q)
    print(f"{name} -> 引擎：{eng} ｜ 量化：{q} ｜ 硬件：{gpu}")

运行后你会看到四个需求各自得到一套有依据的组合，尤其注意 70B 用 AWQ 4-bit（权重约 38GB）在 A100-80G 上"单卡刚能装、但很紧"，实战里通常直接上双卡——这正是下一章的起点。

三、练习#

  1. 补分支：给决策树增加"是否需要 OpenAI 兼容 API"这一问，说明它对 vLLM 与 TensorRT-LLM 选择的影响。
  2. 精度敏感场景：如果一个医疗/法律场景对量化精度极敏感（拒绝 4-bit 损失），把 select_quant 改成"优先 FP8，无 FP8 硬件时用 FP16"，重跑 70B 案例，观察硬件选择如何变化。
  3. 查成本：为"客服机器人(7B)"案例，分别用 A10 与 A100-40G 估算月成本（假设单价 1.2 与 3.0 美元/小时），说明"刚好够用"的卡为何往往更划算。
  4. 验证决策树：写一个你设想的新需求（含端侧/延迟/长前缀/FP8 四类特征），走一遍决策树，并口头解释每一步为什么这么选。
