SIMT 与线程层次（thread / warp / block / grid）#

写第一个 kernel 时，我们都会看到 kernel<<<grid, block>>>(...) 这种写法，并且很快记住"线程数 = grid × block"。但 GPU 内部从来没有这么多独立的执行单元：硬件把连续的 32 个线程编成一个 warp，同一 warp 共享一个取指单元。这一课要把四层结构（grid / block / warp / thread）、索引线性化公式，以及"block 之间没有任何顺序保证"这条硬约束讲清楚——第 2、3 课的发散、同步与 occupancy 全都建立在这上面。

一、概念讲解#

1. SIMT：32 个线程共用一个取指单元#

SIMT 全称 Single-Instruction Multiple-Threads（单指令多线程）。CUDA C++ Programming Guide 的编程模型一章给出的定义是：一个 thread block 内的线程会被组织成每组 32 个线程的 warp，warp 以 SIMT 范式执行 kernel 代码；warp 内的所有线程执行同一段代码，但每个线程可以走不同的分支。同一处在 SIMT 模型下还强调：warp 内的线程以 lock step（锁步）方式推进。

对照 SIMD（Single-Instruction Multiple-Data）就好理解：SIMD 由程序员显式操作向量；SIMT 是一条指令让 32 个 lane 干同一件事，但你写的是标量代码，lane 由硬件分组。代价是分组由硬件定：只想让 16 个线程干活时，另外 16 个 lane 也不能去干别的（第 2 课讲发散）。

这一点很关键：warp 里 32 个线程各有自己的寄存器副本与程序计数器视图，所以同一句 x = x + 1 在不同线程里算出不同结果。

2. 四层结构：谁可见、谁对应什么硬件#

层级 你在代码里怎么拿到 数量与范围 硬件对应 顺序能不能依赖
grid gridDim（dim3） 一次 launch 的全部 block 整个 GPU（可能有几十到几百个 SM） ❌ block 之间无顺序保证
block blockIdx、blockDim 一个 block 的线程，blockDim.x*y*z ≤ 1024 一个 SM；"全部线程由同一个 SM 执行，且通常在该 SM 上跑到结束" ❌ 靠 __syncthreads 只能同步块内
warp 无内置变量，需自己算 32 个线程，块内按线性号连续编组 调度器（warp scheduler）的发射单位 ❌ 不应依赖 warp 间的相对进度
thread threadIdx 一个执行流 每线程一份寄存器 + 一个 lane —

表里"block 全在同一 SM 上跑完"这句来自官方编程模型一章；同一段还写明 block 的调度没有保证——一个 block 依赖另一个 block 的结果就可能永远等不到（后者也许直到前者结束都没被调度）。官方把它总结成更强的约束：CUDA 编程模型要求 block"可以以任意顺序、并行或串行地执行"。

这条约束管三件事：① 不能写"block 0 先算好、其他 block 后读"的代码；② 需要全 grid 同步时，要么拆成两次 launch，要么用 cooperative groups（第 3 课）；③ 结果是确定性的前提是"每个输出只由自己那个线程写"。

3. 索引怎么算：线性化与 warp/lane#

一维 launch 最简单：全局线性号 gid = blockIdx.x * blockDim.x + threadIdx.x。二维/三维时，x 是最快变化的维度，线性化公式是：

gid = ((blockIdx.z * gridDim.y + blockIdx.y) * gridDim.x + blockIdx.x)
      * (blockDim.x * blockDim.y * blockDim.z)
      + (threadIdx.z * blockDim.y + threadIdx.y) * blockDim.x + threadIdx.x

符号含义：blockIdx/gridDim 是 block 在 grid 里的坐标与尺寸，threadIdx/blockDim 是线程在 block 内的坐标与尺寸；乘出来 gid 恰是 [0, gridDim.x*y*z × blockDim.x*y*z) 的一个排列。

warp 的划分发生在 block 内部：块内线性线程号 local 满足 warp_in_block = local / 32、lane = local % 32。注意 block 基址不参与 warp 编号，于是有：当 blockDim 不是 32 的倍数时，每个 block 的最后一个 warp 会有一部分 lane 是空的。blockDim = 48 时，每块 2 个 warp，其中第 2 个 warp 只有 16 个活跃 lane，硬件照样按 64 个 lane 的位置分配资源。

4. grid-stride loop：不要用元素数反推线程数#

常见写法是"n 个元素就 launch n 个线程"。问题是：n 远超 GPU 能同时容纳的线程数时，多出来的线程只是排队；n 小于一个 block 时，块里大半线程被边界判断掩掉。

工程上的默认做法是 grid-stride loop：launch 一个固定的、约等于"能同时驻留的线程数"的规模，然后让每个线程跨步循环：

for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += gridDim.x * blockDim.x) {
    out[i] = a[i] + b[i];       // 步长 = 本次 launch 的线程总数
}

好处有三：边界保护从"每线程一次判断"变成循环条件；同一份代码在 40 个 SM 与 140 个 SM 的卡上都能跑满；调 block 大小只改 launch 参数。

5. 常见坑#

  • 把 threadIdx.x 当全局下标：只有单 block 时二者才相等；多 block 必须加 blockIdx.x * blockDim.x。
  • 默认 blockDim 是 32 的倍数：48、96、100 这类值会让每个 block 的尾部 warp 半空；实在需要非整倍，也要知道损失了多少 lane。
  • 用 __syncthreads() 妄想同步整个 grid：它的作用域只有当前 block，跨 block 用它是错的（第 3 课）。
  • 依赖 block 的执行顺序做累加：例如让每个 block 去读别的 block 写好的中间结果，是模型层面禁止的。
  • 维度顺序记反：threadIdx.x 变化最快，二维 block 里 x 是列方向，写内存时它与合并访存直接相关（第 3 章）。

二、可运行代码示例#

没有 GPU 也能把上面的结构算清楚：下面这段纯 Python（只依赖 numpy）模拟一次 <<<grid, block>>>，打印索引映射、warp/lane 占用，并用 grid-stride 循环真正执行一遍 a + b 与 numpy 向量化结果对照。

# ---- 无 GPU 模拟 SIMT 线程层次（纯 Python + numpy，可直接运行）----
import numpy as np

WARP = 32                      # 官方定义：一个 warp = 32 个线程


def launch_map(block_dim, grid_dim):
    """模拟 <<<grid_dim, block_dim>>>：算清每个线程的 (block, 块内线程, warp, lane)。"""
    rows = []
    for b in range(grid_dim):
        for t in range(block_dim):
            rows.append({
                'block': b,                 # blockIdx.x
                'tin': t,                   # threadIdx.x（块内线性号）
                'gid': b * block_dim + t,   # 设备内全局线性号
                'warp': t // WARP,          # warp 是**块内**划分：threadIdx / 32
                'lane': t % WARP,           # 块内线程号对 32 取模
            })
    return rows


def show_index_table(block_dim, grid_dim, limit=6):
    rows = launch_map(block_dim, grid_dim)
    print(f'--- blockDim={block_dim}, gridDim={grid_dim}：前 {limit} 个线程 ---')
    print(f'{"block":>5} {"tin":>4} {"gid":>5} {"warp":>5} {"lane":>5}')
    for r in rows[:limit]:
        print(f'{r["block"]:>5} {r["tin"]:>4} {r["gid"]:>5} {r["warp"]:>5} {r["lane"]:>5}')
    lanes = {}
    for r in rows:
        lanes[(r['block'], r['warp'])] = lanes.get((r['block'], r['warp']), 0) + 1
    warps = max(r['warp'] for r in rows) + 1
    print(f'每块 warp 数 = {warps}；每块实际线程 {block_dim}，'
          f'而硬件按 {warps * WARP} 个 lane 分配')
    print('未满 32 的 warp 及其 lane 占用：',
          {f'blk{k[0]}warp{k[1]}': f'{v}/32' for k, v in lanes.items()
           if v < WARP} or '全部满 32')


def grid_stride_add(a, b, n, block_dim, grid_dim):
    """按 grid-stride 循环真正地"逐线程"执行 a+b，返回结果与统计。"""
    total = block_dim * grid_dim          # 一次 launch 的线程总数
    out = np.zeros(n, dtype=a.dtype)
    max_iter = 0
    for r in launch_map(block_dim, grid_dim):
        i, it = r['gid'], 0
        while i < n:                      # 边界保护靠循环条件，而不是靠 tid < n
            out[i] = a[i] + b[i]
            i += total
            it += 1
        max_iter = max(max_iter, it)
    return out, total, max_iter


rng = np.random.default_rng(0)
show_index_table(block_dim=48, grid_dim=2)
show_index_table(block_dim=256, grid_dim=3, limit=3)

for n_case, blk, grd in ((1000, 256, 4), (100000, 256, 8)):
    a2, b2 = rng.integers(0, 100, n_case), rng.integers(0, 100, n_case)
    out, total, max_iter = grid_stride_add(a2, b2, n_case, blk, grd)
    useful = min(n_case, total)
    print(f'\nn={n_case}, launch <<<{grd}, {blk}>>> → 线程总数 {total}；'
          f'每线程最多循环 {max_iter} 次')
    print('  与 numpy 向量化结果一致：', bool(np.array_equal(out, a2 + b2)))
    print(f'  线程利用率（有效线程/总线程）= {useful}/{total} = {useful / total:.3f}')
    print(f'  边界外被掩掉（masked off）的线程数 = {max(total - n_case, 0)}')

# 2D 索引：行主序线性化公式与 numpy 的 flatten 对齐
bd = (4, 8)          # blockDim = (x=4, y=8)
gd = (2, 3)          # gridDim  = (x=2, y=3)
ids = np.array([((by * gd[0] + bx) * bd[1] + ty) * bd[0] + tx
                for by in range(gd[1]) for bx in range(gd[0])
                for ty in range(bd[1]) for tx in range(bd[0])])
print(f'\n2D launch <<<{gd}, {bd}>>>：线性化公式得到 {len(ids)} 个 id，'
      f'是否恰为 0..{len(ids) - 1} 的排列：{bool(np.array_equal(ids, np.arange(len(ids))))}')
