重排的必要性：为什么向量相似度不等于相关性#

这一节要解决什么#

第 1 章推导了双塔检索为什么有效，第 2 章推导了索引的近似代价。两章都用同一个指标衡量成功：召回（recall@k） —— 正确答案有没有出现在候选池里。

但真实系统里最常见的一类抱怨与召回无关：

"文档明明检索到了，就在第 4 条，可模型用了第 1 条不相关的内容。"
"把候选池从 10 条扩到 50 条，召回率涨了 12 个点，但答案正确率没动。"
"这些文档在向量空间里几乎一模一样，可只有一个能回答问题。"

这三句话指向同一个事实：候选池里的顺序本身就是系统质量的一部分，而顺序由打分函数决定。于是本节要回答四个问题：

  1. 双塔打分函数到底能表达什么、不能表达什么？ 这不是"模型学得不够好"，而是"独立编码 + 单个内积"这个架构的数学后果。要把它推导出来，才能知道哪些失效是结构性的。
  2. 为什么在真实嵌入上，这个缺陷会被放大？ 各向异性（第 1 章 2.5 节）不是无关的工程细节 —— 它直接把"相关与不相关的分数差"（margin）压到与打分噪声同量级。
  3. "相似度不等于相关性"具体有几种可分离的失效模式？ 混在一起谈会导致错误的处方：词汇相似型失效该用重排，语义改写型失效恰恰是稠密检索的强项（别把它当成缺陷去"修"），而跨文档聚合型失效重排永远修不了。
  4. 怎么在不训练任何模型的前提下，测出"排序侧损失了多少"？ 这是本节的核心产出：一组能在部署前跑、且能区分"召回问题"与"排序问题"的判据。

结论先放在这里：

双塔把相关性假设成了一个双线性函数 ⟨f(q),g(d)⟩。这个假设是为了"文档侧可以离线预计算"而必须付的代价。它带来的失效是可分的三类：一类靠重排能修，一类本来就不是缺陷，一类谁都修不了（需要改任务表达或改架构）。把三类分清，才知道算力该花在哪。

一、双塔的表示能力约束：一个内积能表达多少交互#

1.1 打分函数的三种形式#

先把"相关性打分"写成一个一般函数 s(q,d)，然后看三种架构分别能表达它的哪个子集：

架构 形式 交互发生在哪 doc 侧能否离线
稀疏检索（BM25） ∑t​wt​⋅tf 型 词项集合的交集 ✅ 完全离线（词频预统计）
双塔（bi-encoder） ⟨f(q),g(d)⟩ 两个向量的内积 ✅ 完全离线（g(d) 预算）
late interaction ∑i∈q​maxj∈d​⟨Eq​[i],Ed​[j]⟩ 查询 token 与文档 token 的逐对相似度取 max ✅ token 向量离线，在线只做 MaxSim
cross-encoder h([q;d]) 每一层注意力都对 q、d 双方可见 ❌ 完全不能（必须联合前向）

这张表的读法：从上到下，"交互的粒度"越来越细，"可预计算的东西"越来越少。效率的来源是"把与查询无关的计算搬到线下" —— 而"与查询无关"这个条件，只有在 q 与 d 不交互时才成立。这就是本章全部取舍的根源。

1.2 双塔的能力上界：它是一个双线性函数#

设 f(q)∈Rd、g(d)∈Rd。那么双塔打分是

sbi​(q,d)=⟨f(q),g(d)⟩=f(q)⊤g(d)

把 g(d) 的每一维看作一个"特征"，那么 sbi​ 是这些特征的一个线性函数，系数由 f(q) 给出。也就是说：

双塔只能表达"文档特征的加权和"，权重随查询变化，但"特征"本身必须是与查询无关的固定编码。

对比一个真正的一般函数 s(q,d)：它可以让"文档里是否有否定词"这个特征的权重，取决于"查询里是否在问'哪些方法不需要 X'"。这在 sbi​ 里做不到 —— 因为这种依赖是乘性的、逐特征的，而 sbi​ 的权重 f(q) 是整个向量一次性给齐的，没有任何机制把 q 的某一部分与 d 的某一部分对齐。

形式化地说：令 F 为所有 f,g∈Rd 能表达的函数族。F 是"秩不超过 d 的双线性函数"的一个子集。而真实的相关性函数在词项/实体对齐上需要更高阶的交互（"查询中的实体 A 与文档中的实体 A 是同一个"这类配对判断，本质上是 O(∣V∣2) 量级的自由度）。固定 d（768 或 1024）意味着这个配对空间被压缩到一个低维投影里 —— 压缩必然丢信息，问题只是丢了多少。

这不是"训练不够充分"：即使 f,g 是任意可测函数、训练数据无限多，只要它们各自只能看到一侧，输出就只能通过 d 维内积组合。这解释了为什么"换个更强的嵌入模型"往往只能拿到有限的改善（下一节会量化）。

1.3 一个具体的最小反例#

考虑三份文档与一个查询（⚠️ 构造的例子，但结构在真实语料里极常见）：

q:  "哪些检索方法不需要训练即可使用？"

d1: "BM25 不需要训练即可使用，它是无参数的词频方法。……"          ← 真相关
d2: "向量检索方法（如 DPR）需要训练一个双塔模型。……"              ← 词汇高度重叠，不相关
d3: "模型训练需要大量标注数据，训练成本很高。……"                  ← 主题词重叠，不相关
  • 词项层面：d2​,d3​ 与 q 共享 检索/方法/训练/使用 等词；d1​ 共享 不需要训练/使用。BM25 未必能救得了 —— 但至少它在"不需要"这个否定词上有信号（如果分词保留它）。
  • 向量层面：d1​,d2​,d3​ 的主题（检索、训练）都很接近，句向量的方向差很小。而 d1​ 与 d2​ 的区别恰恰在于"需要 / 不需要"这一处否定，以及"BM25 / DPR"这一处实体替换 —— 这两处都只占几十个 token 中的两三个，句向量的池化（mean 或 CLS）几乎把它们平均掉。
  • cross-encoder 层面：q 中的"不需要"会与 d2​ 中的"需要"形成直接的注意力对照，q 中的"方法"会与 d2​ 中的"检索方法"对齐而同时注意到"DPR/双塔"这个实体 —— 判断"这不匹配"对它来说是局部 token 对齐问题，而不是一个全局向量方向问题。

结论：双塔的失效不是随机的，它集中在"少数 token 决定相关性"的查询上。这个观察是可测的：统计"把文档中关键 token 置换后打分变化幅度"的分布，双塔的敏感度远低于 cross-encoder（本节代码实测这一点）。

二、各向异性如何把 margin 压到噪声量级#

2.1 margin 的定义#

排序能否做对，取决于分数之间差多少，而不是分数本身。定义

Δ=s(q,d+)−d−∈N(q)max​s(q,d−)

其中 d+ 是相关文档，N(q) 是候选池里的不相关文档。Δ 就是"正确答案比最强的干扰项高多少"。Δ>0 时排序正确，Δ<0 时排序错误。

2.2 各向异性如何压缩 Δ#

第 1 章讲过：真实句向量集中在表示空间的一个窄锥内，即对任意两句 x,y，cos(x,y) 的分布集中在较高的值上（而非各向同性的均值 0）。

设双塔打分用余弦（等价于归一化后的内积），并利用一个一阶展开。把每个向量写成"共享方向 c + 残差"：x=αx​c+rx​，其中 ∥c∥=1、rx​⊥c、∥rx​∥≪αx​（这正是"窄锥"的形式化）。则

cos(x,y)=αx2​+∥rx​∥2​αy2​+∥ry​∥2​αx​αy​+⟨rx​,ry​⟩​≈1−21​​αx​rx​​−αy​ry​​​2

关键一步：cos 关于残差的偏离是二阶小量。也就是说，两个向量在"有意义的残差方向"上差得很远，余弦距离却只差一点。

把这代回 margin：

Δ≈21​(​r^d−​​2−​r^d+​​2),r^x​=rx​/αx​

其中 r^x​=rx​/αx​ 是"去掉共享方向后的残差"。共享方向 c 的贡献在两两相减时被完全消掉 —— 它对所有候选都一样，是中性的。真正携带相关性信息的量被压缩进了 ∥r^∥ 的平方差里，而"窄锥"意味着 ∥r^∥≪1，于是这个平方差是双重的二阶小量。

这是两条不同的机制，不要混（本节代码实验只测第二条）：

机制 数学位置 后果 处方
各向异性：共享方向占主体 ∥r^∥≪1，且 cos 对残差是二阶 相关/不相关的分数差被压缩 换表示（白化、对比学习目标）、或加重排
池化折叠：决定性 token 被平均掉 均值池化把"哪些 token 在"折成"几个 token 在" 信息在编码阶段就丢了，任何后处理都拿不回 只能换交互方式（late interaction / cross-encoder）

第二条更致命：第一条只是让信号变小（还能放大），第二条是让信号消失（放大也没用）。本节代码用"主题 token vs 内容 token"把这个区别做成了可操纵的开关（实验二）。

2.3 与打分噪声合起来：一个可算的误排概率#

现在给打分加上噪声。噪声至少有三个来源：量化误差（第 2 章 4.4 节的 ε）、批处理/精度带来的数值抖动、以及模型对不同难度的候选本身的不确定性。把它们近似成一个标准差为 σ 的零均值扰动。

若把 Δ 也近似看成来自某分布（在候选池内的随机波动），则一个粗略但有用的判据是

P(Top-1 误排)≳Φ(−σ2​Δ​)

其中 Φ 是标准正态 CDF。（推导：若正确与最强干扰的打分各带噪声 N(0,σ2)，两者之差的噪声方差是 2σ2；真实间距为 Δ 时误排概率就是"噪声超过 Δ"的尾概率。）

这张对照表说明一切：

Δ/σ 误排概率上界（约） 读数
5.0 2×10−4 排序几乎必然正确
2.0 0.079 约 8% 的查询会排错 Top-1
1.0 0.24 四分之一错
0.5 0.36 排序基本不可信
0.1 0.47 与随机猜无异

于是问题变成：真实系统里 Δ/σ 落在哪一档？ 第 2 章实测过量化误差 ε≈0.079，而真实分数相邻间距中位数是 0.0012 —— 比值约 66。那是 PQ 量化的场景（σ 被量化放大）。纯 fp32 余弦下 σ 小得多，但各向异性压缩了 Δ，两者是同一个方向的作用。

所以判据必须同时测两个量：Δ（真实分数间距，由嵌入各向异性决定）与 σ（你的打分链路上的噪声，由量化、精度、索引近似决定）。只看其中一个都会得出错误的优化方向：

  • Δ 小、σ 小 → 排序脆弱的根因在表示（该换模型 / 加重排）；
  • Δ 小、σ 大 → 根因在打分精度（该降量化强度 / 全精度重排，回指第 2 章 4.5）；
  • Δ 大 → 排序没问题，别再往这里投算力（问题在召回或生成）。

三、三类失效模式，以及它们为什么必须分开处理#

把"相似度不等于相关性"当成一个笼统的问题，处方必然是错的。下面三类失效的判别信号和正确处方完全不同。

3.1 失效一：词汇相似但语义不相关（可重排修复）#

成因：双塔只能通过全局向量交互，于是"主题相同但论断不同/相反"的文档会被排到前面。典型形态：

  • 模板文档（同一套模板生成的项目说明、API 文档），彼此向量极近，但只有一份讲的是目标接口；
  • 近似重复（同一内容的多个版本），会挤占名次（这是第 3 节的"近重复偏置"）；
  • 否定与条件反转（"支持 X" vs "不支持 X"）；
  • 实体替换（"用 A 方法" vs "用 B 方法"，表述结构相同）。

判别信号：把候选池里的文档两两算余弦 —— 若第 1 名与第 2 名的相似度高于第 1 名与查询的"应有水平"，说明池内高度同质，此时排序区分度必然低。一个更直接的量：池内候选的平均两两相似度（池内一致性）。

正确处方：重排（cross-encoder）。它对"少数 token 决定相关性"的情形最敏感，正是这类失效的对手。

3.2 失效二：语义相关但词汇不相似（这不是缺陷）#

成因：用户用词与文档用词不同（改写、同义、跨语言、术语口语化）。

这一条是稠密检索相对 BM25 的强项，不是它的失效。 把它和失效一混在一起谈，会导致一种常见的错误结论 —— "稠密检索不可靠，还是回到 BM25"。正确说法是：两路误差不相关（第 1 章 4 节已证明），所以混合检索有效。

判别信号：用"查询改写后的 recall 变化"来分离 —— 若把查询改写成文档用词后 recall 显著上升，说明瓶颈在词汇缺口（该上第 4 章的改写/扩展，而不是重排）；若改写后 recall 不变而重排能提升，说明瓶颈在排序。

正确处方：查询侧改写/扩展 + 混合检索。不要用重排去修它：重排的候选池是召回给的，候选池里根本没有的文档，重排无能为力。

3.3 失效三：需要聚合、比较或约束判断（结构性不可解）#

成因：有一类问题的答案不存在于任何单个文档里，而存在于文档之间的关系中：

"这三份方案里，唯一没有提到容量上限的是哪一个？"     ← 需要全集 + 否定
"A 的开销比 B 高多少？"                              ← 需要两个数值 + 算术
"哪些文档的说法互相矛盾？"                            ← 需要跨文档一致性判断
"总结所有文档里出现过的三种共识做法"                   ← 需要跨文档聚合 + 去重

对这类问题，"给单个 (q,d) 对打分并排序"这个动作在结构上无法产生正确答案 —— 因为正确答案不是"某个 d 的得分高"，而是"某个集合的某种关系"。

判别信号：标注一小批查询，问标注者"回答这个问题需要几个不同文档？"。若"需要 ≥2 个文档"的比例显著（例如 >15%），说明你的任务里存在这一类。

正确处方：改任务表达或改架构 —— 多跳/迭代检索（第 4 章 2 节）、集合级打分（对候选集合而非单个候选打分）、或把"比较/聚合"显式分解成子查询（第 4 章 1 节）。重排永远修不了它 —— 这一点必须在架构评审时说清楚，否则团队会一直加大重排池，而指标纹丝不动。

3.4 三类的汇总表#

失效一：词汇相似语义不同 失效二：语义相关词汇不同 失效三：聚合/比较/约束
瓶颈层 排序 召回（查询侧） 任务表达
判别信号 池内两两相似度高、Δ 小 改写后 recall 显著上升 需要 ≥2 文档的比例高
处方 cross-encoder 重排 查询改写 + 混合检索 多跳 / 集合打分 / 分解
调参能修吗 不能（换打分函数） 不适用 不能（换架构）
加重排池有效吗 有效但很快饱和 无效 完全无效

四、把排序侧的损失测出来：三个可在部署前跑的判据#

本节的工程产出是这三个判据。它们的共同点：不需要训练新模型、不需要标注（除了少量人工核对），只用你现有的日志与语料。

判据 A：把 recall 拆成"模型上界"与"索引实际"#

全量精确检索Rexact​​​≥你的近似索引Rindex​​​≥最终进上下文的Rranked@k​​​

  • Rexact​−Rindex​：索引近似造成的损失（第 2 章的战场）；
  • Rindex​−Rranked@k​：排序造成的损失（本节的战场）。

做法：在语料的一个子集（例如 5%，或者用一台机器能全扫的规模）上做精确全扫，得到 Rexact​；用近似索引得到 Rindex​；用真实流水线得到 Rranked@k​。

这个判据不能证明什么：它把"排序损失"与"切分/表示损失"混在了一起 —— 如果正确答案所在的 chunk 根本没被切出来，三个量会一起低，看不出区别。

判据 B：margin / 噪声判据（Δ/σ）#

按 2.2 与 2.3 节的做法实测两个量：

① 在一批查询上，取"真值相关文档"与"最强干扰文档"的分数，算 Δ 的分布
   （没有标注时用"两路检索的交集/差集"近似：只被一路排第一的候选当作准相关候选）
② 用同一批候选，算"你的打分链路"与"全精度精确打分"的差，取标准差 σ
③ 计算 Δ_median / σ：
     > 3   → 排序稳，别动
     1~3   → 有损失，重排可能有收益
     < 1   → 排序不可信，先降 σ（量化/精度）还是先换打分函数要分开测

这个判据不能证明什么：Δ 用近似真值估计时有偏（特别是稀有实体类查询），所以它只能作为排序风险的指示器，不能当作精确的损失值。

判据 C：扩池回升实验（区分召回与排序）#

这是最直接、最可靠的一条：

① 用当前流水线取 Top-k（例如 k=10），记录答案正确率 A(10)
② 同一次检索取 Top-k'=50，用**精确打分 + cross-encoder** 重排后取 Top-10，记录 A(50→10)
③ 比较：
   A(50→10) ≫ A(10)  → 排序损失显著：正确答案在池子里但被排下去了 → 上重排
   A(50→10) ≈ A(10)  → 排序不是瓶颈：候选池里没有更好的东西 → 去修召回/切分/查询
   两者都低且 A(50) 也低 → 召回问题（连池子里都没有）

这个判据不能证明什么：它不能告诉你"排序损失有多少是重排无法修复的"（失效三那类）。要把失效三分离出来，需要按"回答需要几个文档"给查询分层，看扩池回升只在 =1 文档的那层发生。

4.4 判据的执行顺序（为什么是这个顺序）#

① 先做判据 C（最便宜、最直接）：确定瓶颈是不是排序
② 若是排序，再做判据 B：区分"Δ 本身小"（表示问题）还是"σ 大"（精度问题）
③ 只有当"表示问题"被确认，才考虑换嵌入模型或加重排
④ 若判据 C 显示不是排序问题，就别在本节的内容上花任何预算

顺序的理由：判据 C 的结论是决策性的（做不做），判据 B 的结论是方向性的（做哪一件）。把方向性判据放在决策性判据之前，会得到一堆"哪个参数都可以调"的结论 —— 这正是很多团队在重排上投入大量算力却收效甚微的原因。

代码：双塔 vs 联合打分的对照实验#

下面的脚本用合成数据把这一节的三个论断全部测出来：(1) 双塔对"少数关键 token 决定相关性"的文档不敏感；(2) margin 被各向异性压缩后，Δ/σ 判据能预测误排；(3) 干扰强度上升时双塔的 Top-1 准确率崩得比联合打分快得多。

"""
双塔（独立编码 + 内积）vs 联合打分（cross-encoder 代理）的对照实验。

设计决策（三处，都直接对应正文的论断）：
  1. 文本 = "主题 token（多数、决定向量方向）+ 内容 token（少数、决定相关性）"。
     相关性是**合取结构**：查询的两个必要内容 token 必须**都**在文档里。
     这个两层结构是正文 1.3 节最小反例的可测版本：主题 token 让"向量相似度"
     保持很高（词汇/主题相近），而判据只落在少数内容 token 上。
  2. 两个打分器共享同一张固定随机嵌入表，差别只在"如何从 token 集合得到分数"：
       bi   ：两侧各自**均值池化**成一个向量，再取余弦（低秩双线性交互）
       joint：q 与 d 的 token 逐对交互，按查询侧取"每个查询 token 的最佳对齐"
              的乘积（可表达合取）
     两者都**不训练** —— 于是性能差只能归因于结构，而不是优化质量。
     （关键的对照控制：不排除"只是双塔没训好"这个解释，实验就没有说服力。）
  3. 输出 margin Δ、打分抖动 σ、Δ/σ，并检验正文 2.3 节的高斯判据能否预测误排。
     判据必须被检验，否则只是装饰；同时明确它是"上界式粗估"。
"""
import numpy as np

EMB, N_TOK = 16, 64


def make_embedding(seed=0):
    """固定随机嵌入表：token id → 单位向量（所有打分器共用，保证公平）。"""
    rng = np.random.default_rng(seed)
    E = rng.normal(0, 1, (N_TOK, EMB))
    return E / np.linalg.norm(E, axis=1, keepdims=True)


def make_dataset(E, n_q=300, n_list=40, n_topic=6, key_overlap=0.5, seed=2,
                 align_noise=0.15, easy_ratio=0.35):
    """
    ⚠️ 合成数据。构造规则（下面所有 id 都是 token 下标）：
      查询  : [topic] + [k1, k2]                              （3 个 token）
      正例  : [topic] + [k1, k2] + n_topic 个 [topic]           （内容全中）
      难干扰: [topic] + [k1, x] 或 [x, k2] + n_topic 个 [topic]  （只中一个内容，x≠缺失者）
      易干扰: [other] + 两个无关 token + n_topic 个 [other]      （主题不同的负例）
      key_overlap : 难干扰里"共享一个内容 token"的概率（词汇重叠强度）
      align_noise : 正例内容 token 的对齐噪声（真实世界不会完美对齐）
    """
    rng = np.random.default_rng(seed)
    queries, poss, negss = [], [], []
    for _ in range(n_q):
        topic = int(rng.integers(0, N_TOK))
        k1, k2 = (int(t) for t in rng.choice(N_TOK, 2, replace=False))
        q = np.vstack([E[topic], E[k1], E[k2]])
        queries.append(q + rng.normal(0, align_noise, q.shape))
        p = np.vstack([E[topic], E[k1], E[k2]] + [E[topic]] * n_topic)
        poss.append(p + rng.normal(0, align_noise, p.shape))

        negs = []
        for _ in range(n_list):
            if rng.random() < easy_ratio:            # 易干扰：主题不同
                other = int(rng.integers(0, N_TOK))
                while other == topic:
                    other = int(rng.integers(0, N_TOK))
                ids = [t for t in range(N_TOK) if t not in (k1, k2)]
                x, y = (int(t) for t in rng.choice(ids, 2, replace=False))
                negs.append(np.vstack([E[other], E[x], E[y]]
                                      + [E[other]] * n_topic))
            elif rng.random() < key_overlap:         # 难干扰：共享一个内容 token
                keep, miss = (k1, k2) if rng.random() < 0.5 else (k2, k1)
                cand = [t for t in range(N_TOK) if t != miss]
                x = int(rng.choice(cand))
                order = (keep, x) if rng.random() < 0.5 else (x, keep)
                negs.append(np.vstack([E[topic], E[order[0]], E[order[1]]]
                                      + [E[topic]] * n_topic))
            else:                                    # 难干扰但不共享内容 token
                ids = [t for t in range(N_TOK) if t not in (k1, k2)]
                x, y = (int(t) for t in rng.choice(ids, 2, replace=False))
                negs.append(np.vstack([E[topic], E[x], E[y]]
                                      + [E[topic]] * n_topic))
        negss.append(negs)
    return queries, poss, negss


def score_bi(q, d):
    """双塔代理：两侧**均值池化**成一个向量后取余弦（低秩双线性交互）。
    均值池化是句向量 mean pooling 的直接类比，也是它的结构性弱点。"""
    qv, dv = q.mean(0), d.mean(0)
    return float(qv @ dv / (np.linalg.norm(qv) * np.linalg.norm(dv)))


def score_joint(q, d):
    """联合打分代理（cross-encoder 的替身）：
    ① 逐对交互得到相似度矩阵；② 文档侧取 max（每个查询 token 找最佳对齐）；
    ③ 查询侧取乘积 —— 表达"每个必要 token 都要找到对齐"的合取结构。
    完全不训练：它能赢 bi，赢的就是"逐对交互 + 查询侧合取聚合"这个结构。"""
    S = q @ d.T
    return float(np.prod(np.clip(S.max(axis=1), 0.0, None)))


SCORERS = {"bi（均值池化 + 余弦）": score_bi, "joint（逐对交互 + 合取）": score_joint}


def evaluate(scorer, queries, poss, negss, hard_only=False, easy_ratio=0.35):
    """hard_only=True 时只保留"难干扰"（共享一个内容 token 的那些）作为竞争项。"""
    top1, margins = 0, []
    for q, p, ds in zip(queries, poss, negss):
        if hard_only:
            n_hard = int(len(ds) * (1 - easy_ratio))
            ds = ds[len(ds) - n_hard:] if n_hard else ds
        sp = scorer(q, p)
        sn = [scorer(q, d) for d in ds]
        margins.append(sp - max(sn))
        top1 += int(sp > max(sn))
    margins = np.array(margins)
    rng = np.random.default_rng(99)
    noise = [np.std([scorer(q, p + rng.normal(0, 1e-3, p.shape)) for _ in range(5)])
             for q, p in list(zip(queries, poss))[:80]]
    sigma = float(np.mean(noise)) + 1e-12
    ratio = margins / sigma
    from math import erf
    return {"top1": top1 / len(queries),
            "delta_median": float(np.median(margins)),
            "sigma": sigma,
            "ratio_median": float(np.median(ratio)),
            "pred_err": float(np.mean([0.5 * (1 - erf(r / 2)) for r in ratio])),
            "actual_err": 1 - top1 / len(queries)}


def token_swap_sensitivity(scorer, q, d, E_ALT):
    """把文档的**内容 token**（第 1、2 个）换成无关 token，看打分的相对变化：
    '少数 token 决定相关性'时打分器敏感度的直接度量。"""
    base = scorer(q, d)
    out = []
    for pos in (1, 2):
        alt = d.copy()
        alt[pos] = E_ALT[pos]
        out.append(abs(scorer(q, alt) - base) / (abs(base) + 1e-9))
    return float(np.median(out))

（∣V∣=64、难干扰约 26 条、其中一半把随机 token 放在缺失位置上。）实测的 0.433 与"1−0.34 量级"吻合。这个数字不是算法缺陷，而是数据分布的估计误差 —— 但它的含义仍然成立：当相关性是"哪些 token 在"而不是"有几个 token 在"时，池化表达在信息上就不足以分辨。

三处关键设计决策：

  1. 联合打分器完全不训练。这是本节最重要的一处控制：如果它赢了双塔，赢的东西只能是"q 与 d 的 token 能逐对交互"这个结构差异，与优化无关。如果不做这个控制，读者无法排除"只是因为双塔没训好"这个解释 —— 而排除竞争解释正是实验设计的全部意义。（代价是：joint 在这个合成任务上接近满分，不能读成"真实 cross-encoder 能到 0.99"。合成数据的相关性规则与 joint 的归纳偏置恰好同形。真实重排的收益远小于此，必须用自己的验证集测。）
  2. 数据刻意做成"主题 token + 内容 token"两层。主题 token 决定向量方向（双塔能编码），内容 token 决定相关性（池化会稀释它）。把两层显式分开之后，"双塔看不见什么"就变成了可测量的量（实验二、三），而不是一句断言。
  3. 把 Δ/σ 判据本身也当作被测对象（实验四）。一个判据如果不被检验，就只是装饰。这里让它与实测误排率对照，并明确指出它依赖 σ 的定义 —— 给出判据的适用边界和给出判据同等重要。

练习#

  1. 推导双塔的表达上界：设 f,g:RL→Rd，s(q,d)=⟨f(q),g(d)⟩。(a) 证明 s 对 d 是线性的（固定 q）、对 q 也是线性的（固定 d）；(b) 构造一个真实相关性函数（例如"q 中的实体与 d 中的实体相同且 q 含否定词时返回负分"），证明它不能被任何 d 维双线性形式精确表达（提示：考虑该函数在实体配对上的取值矩阵的秩）；(c) 由此说明为什么"换成 d=4096 的嵌入模型"只是把秩提高，而不是消除限制。

  6. 池内一致性作为判据：对每个查询计算候选池的"平均两两余弦"，并把查询分成"池内一致性高/低"两组，比较两组的 Top-1 准确率与 margin 中位数。回答：这个不需要标注的判据能否替代 Δ 的测量？它在什么情况下会给出错误信号（提示：当整个语料都是同主题时）？

  7. 判据的执行顺序：假设你接手一个系统，报告说"答案正确率 61%，重排池从 20 加到 200 没变化"。请按本节 4.4 节的顺序，写出你要依次跑的三个实验、每个实验的预期读数，以及每种读数对应的下一步动作。要求明确写出：在什么读数下你会否决"加重排"这个方案。

  8. 代价对比（跨节）：已知换一个更强的嵌入模型需要重新编码全量语料（N=2×106 篇、平均 8 个 chunk）并重建索引，而加一层 cross-encoder 重排（池 = 100）只需在线算力。请用可估的量（离线编码时长、索引重建时长、在线 P99 延迟增量）建立一个粗略的成本对比，并给出"在什么排序损失幅度下换模型才划算"的判据。

小结#

  • 双塔的能力约束是结构性的：s=⟨f(q),g(d)⟩ 只能表达"与查询无关的文档特征的加权和"，无法表达词项/实体的逐对对齐。这不是训练不足 —— 是"文档侧必须离线预计算"这个效率目标的数学代价。效率的来源恰恰是"与查询无关"，而"与查询无关"就是表达力的上界。
  • 各向异性把 margin 压到噪声量级：真实句向量集中在窄锥内时，余弦对"有意义残差"的偏离是二阶小量，共享方向在两两相减中互相抵消。于是排序可靠性的关键量是 Δ/σ：Δ 由表示决定，σ 由量化/精度/近似决定。只测一个会给出错误的优化方向。
  • 误排概率的经验判据 P≳Φ(−Δ/(σ2​))：Δ/σ=2 时约 8% 的查询会排错 Top-1，Δ/σ=1 时约 24%，Δ/σ=0.5 时排序基本不可信。这个公式是粗估，但量级正确，且可以被实测检验。
  • 三类失效必须分开处理：① 词汇相似语义不同（池内一致性高、Δ 小）→ 重排；② 语义相关词汇不同 → 这是稠密检索的强项，该上查询改写；③ 聚合/比较/约束 → 结构性不可解，重排永远修不了，只能改任务表达或架构。把三类混谈是实现层面最常见的浪费来源。
  • 三个部署前判据：A 拆解 recall（精确 vs 索引 vs 排序后）；B 测 Δ/σ；C 扩池回升实验。执行顺序不能反：C 是决策性的（做不做重排），B 是方向性的（换表示还是降噪声）。先做 B 会得出"什么都能调"的结论。
  • 每个判据都有它不能证明的东西（判据 A 混淆切分损失、判据 B 的近似真值有偏、判据 C 分不出失效三）。写下边界与给出判据同等重要 —— 否则判据会被当成万能的，然后在第一次失效时被整体抛弃。
  • 一句话：向量相似度是一个"全局方向"的度量，而相关性常常取决于"少数 token 的对齐"。重排存在的理由，就是把那部分不可离线预计算的依查询交互，搬回在线算。
