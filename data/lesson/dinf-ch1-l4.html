专家并行：all-to-all 字节账、容量因子与负载不均衡的代价#

这一节要解决什么#

TP 切层内的矩阵，PP 切层，EP（Expert Parallelism）切的是专家。它的通信原语既不是 AllReduce 也不是 P2P，而是 All-to-All —— 因为要交换的是"token 去哪、结果回哪"，这是一个置换（permutation），而不是归约。

推理侧的 EP 有它自己的三个硬问题，前两个在训练课里出现过但没有作为约束来讨论：

  1. all-to-all 的字节账怎么算？ 它的延迟项与带宽项在 decode 下的比例是多少？（这个比值决定了"合包"有没有用。）
  2. 容量因子 C 与丢包率的定量关系：训练里丢包只是"这个 token 少走一个专家"，推理里丢包意味着这一层少了一部分计算，直接反映在输出质量上。C 取多少？它与 batch 大小是什么关系？
  3. 负载不均衡如何变成尾延迟：从 Binomial(Tk,1/E) 出发，最热专家的期望超出均值多少？这个超出如何变成 EP 的效率上限？

先给本节最重要的一条结论，它把 EP 与 TP 区分开：

A2A 的 α 项与 batch 无关，但 β 项 ∝b⟹batch 越大，EP 越划算（与 TP 相反）​

A2A 的 α 项与 batch 无关，但 β 项 ∝b⟹batch 越大，EP 越划算（与 TP 相反）​

一、EP 切什么，以及它与 TP/PP 的结构差别#

1.1 MoE 层与前向的两段 all-to-all#

MoE（Mixture of Experts）层把 FFN 换成 E 个并联的专家加一个路由器：

x [tokens, h]
 ├─ Router:  g = softmax(x · W_r)        # [T, E] 路由分数
 │            选出 top-K 个专家
 ├─ Dispatch   (All-to-All #1): 把每个 token 的表示发到 K 个专家所在的 rank
 ├─ Experts    每 rank 只算本地专家持有的那部分 token（K·(T/E)·... 的批量）
 └─ Combine    (All-to-All #2): 把每个专家的输出按 g 加权求和后送回原 rank
y [tokens, h] = Σ_{k∈topK} g_k · Expert_k(x)

每层两次 all-to-all，与 TP 的"每层两次 AllReduce"在结构上对称 —— 但代价完全不同：

TP 的两次 AllReduce EP 的两次 All-to-All
交换的是什么 部分和（每个 rank 的贡献要相加） token 的表示（每个 token 去一个 rank、再回来）
数据量 b⋅h（与 N 无关） K⋅(N−1)/N⋅b⋅h（与 K 和 N 都有关）
延迟项 2(N−1)α / 次 (N−1)α / 次（单向转发）
是否需要对称 是（所有 rank 得到同样结果） 否（置换，收发可以不同）
batch 增大时的行为 延迟项不变（与 b 无关） 延迟项不变，带宽项 ∝b

最后一行是本节的分水岭：TP 的每 token 通信时间 ≈cN 与 b 完全无关，所以加大 batch 不能摊薄 TP 的通信；而 EP 的延迟项是每层一次的固定转发成本，加大 batch 时它被 b 个 token 摊薄。所以 EP 与"大 batch"是互补的，TP 与"大 batch"是互相抵消的。

1.2 每层的字节账#

设每 token 的隐藏向量 h 个元素、每元素 σ 字节（fp16 时 2）、top-K 路由、N 个 EP rank。Dispatch 阶段：每个 token 要发给 K 个专家，这些专家均匀落在 N 个 rank 上，所以每个 rank 要发给其他 rank 的总量是

bytesdispatch, per rank, per layer​=NN−1​⋅Kbhσ

Combine 阶段把结果送回，量相同。所以每层每 rank：

bytesEP​=2⋅NN−1​Kbhσ​

数值（K=2、h=4096、σ=2、b=1）：

N 每层每 rank 每 token 全模型（L=32） 带宽时间 延迟时间 延迟/带宽
2 16 KiB 1.00 MiB 0.0023 ms 0.320 ms 137
4 48 KiB 3.00 MiB 0.0070 ms 0.960 ms 137
8 112 KiB 7.00 MiB 0.0163 ms 2.240 ms 137
16 240 KiB 15.00 MiB 0.0350 ms 4.800 ms 137

decode 的单 token EP 通信被 α 项主导约 102 倍​

与 TP 完全同构的结论，但数值更大：TP 是 140 μs/层（N=8，环形两步归约），EP 是 70 μs/层（N=8，单向转发）。"延迟/带宽 = 137"这个比值与 N 无关，因为它只由 α、β、消息大小决定：

带宽延迟​=(N−1)Kbhσ/β(N−1)α​=Kbhσαβ​

读法：这个比值是一个"硬件 × 负载"的常数。要它变小，只能增大 b（或 K、h）。所以 "增大 batch" 是 EP 唯一能改善通信效率的手段 —— 这与上一节 PP 靠"增大并发"填气泡是同一件事的两个面。

1.3 batch 把 EP 从延迟主导推向带宽主导#

N=8 带宽项 延迟项 延迟/带宽
b=1 0.016 ms 2.240 ms 137
b=16 0.261 ms 2.240 ms 8.6
b=64 1.044 ms 2.240 ms 2.1
b=256 4.176 ms 2.240 ms 0.5

转折点在 b=αβ/(Khσ)≈123（N=8、K=2、h=4096、fp16）。越过它，带宽成为主导，这时"消息压缩、低精度 A2A、按专家分桶合并"才真正有用。

与"容量因子"的关系在下一节 —— 但这里可以先记住一个矛盾：

提高 batch 摊薄 EP 通信⟺提高 batch 加剧专家负载波动（容量因子要更大）

而这个矛盾有一个出路：把 batch 换成本地 token 数（每 rank 增加专家数）而不是全局 token 数

二、负载不均衡：从二项分布到容量因子#

2.1 每专家负载的分布#

设一次前向里有 T 个 token 参与路由（T=b⋅s，decode 下 T=b），每 token 独立均匀地选 K 个专家（这是理想路由器的假设）。对某个固定专家 e：

Le​∼Binomial(TK, E1​),μ=E[Le​]=ETK​,σ2=TK⋅E1​(1−E1​)

Le​∼Binomial(TK, E1​),μ=E[Le​]=ETK​,σ2=TK⋅E1​(1−E1​)

为什么要用这个分布而不是"μ 就够"：因为最慢的那个专家决定这一层的耗时。这是本节与训练课最大的区别 —— 训练里你是把所有专家的计算加起来看总 FLOPs，推理里你要看 maxe​Le​。

2.2 容量因子：一个推理侧才成为约束的量#

工程实现不能为每个专家预留无限缓冲，于是设

capacity(e)=C⋅μ,C≥1

超出容量的 token 被丢弃（该 token 在这一层跳过这个专家）。训练里丢包通常可容忍（还有别的层、还有梯度）；推理里丢包直接改输出，所以"C 取多少"是一个质量-延迟决策，不是工程细节。

用精确二项分布算出（E=64、K=2）：

T C=1.0 C=1.1 C=1.2 C=1.25 C=1.3 C=1.5
512 67.97% 56.43% 33.76% 24.32% 24.32% 4.24%
1024 70.10% 45.34% 23.43% 13.34% 9.72% 0.58%
2048 71.57% 36.71% 11.80% 4.30% 1.79% 0.013%
4096 72.60% 24.90% 2.64% 0.51% 0.099% ~0
K=1（T=1024） 43.40% 33.99% 18.61% 13.01% 13.01% 2.14%

（注意 T=512 的那一行里 C=1.25 与 C=1.3 的丢包率完全相同：因为容量被取整到 token 数后两者都是 40 —— 这是"容量是整数"这个事实的直接后果，也是"把 C 当连续变量调"会踩的坑。）

四处必须读懂的地方：

  1. C=1.0 时的丢包率是 70%+，不是"接近 0"。因为 P(Le​>μ) 对每个专家约 45%，而 top-K 的 token 有 K 个机会被丢（1−(1−p)K）。这是"容量就是均值"这个直觉最贵的错误。
  2. 丢包率随 T 迅速下降（大数定律）：T 从 512 到 4096（8 倍），C=1.2 时的丢包从 33.8% 掉到 2.64%。所以"容量因子要取 1.25"这句话是负载相关的，不是常数。
  3. C=1.25 是常见的默认值，对应 T=1024 的 13.3% 丢包 —— 这个数字在"追求质量"的场景里高得不可接受，所以真实系统还会配合别的机制（见 2.4）。
  4. 增大 E 反而使丢包率上升（同样的 T、C）：因为 σ/μ=(1−1/E)/(TK/E)​∝E/(TK)​，专家越多，相对波动越大。这与"专家越多越好"的直觉相反 —— MoE 的粒度受统计波动限制。

2.3 最热专家与 EP 的效率上限#

即使不设容量上限（无丢包），最慢专家的耗时也会拖住整层。用极值统计的经典近似（E 个近似独立的同分布变量）：

E[emax​Le​]≈μ+2lnE​σ

⟹μE[maxe​Le​]​≈1+TK/E2lnE(1−1/E)​​

⟹μE[maxe​Le​]​≈1+TK/E2lnE(1−1/E)​​

EP 效率上限≈1+2lnE(1−1/E)E/(TK)​1​​

数值：

T E K 最热专家 / 均值 EP 效率上限
256 64 2 1+1.012 49.7%
1024 64 2 1+0.506 66.4%
4096 64 2 1+0.253 79.8%
16384 64 2 1+0.126 88.8%
1024 64 1 1+0.715 58.3%
1024 64 4 1+0.358 73.7%

这张表解释了 MoE 推理的两个真实现象：

  • 小 batch 的 MoE 推理效率极低（T=256 时上限只有 49.7%）—— 不是因为算力不够，而是因为统计波动让一半的专家在等。
  • top-K 越大，波动越小（K 从 1 到 4，效率上限从 58.3% 升到 73.7%），因为每个 token 的选择被平均了。但 K 越大激活参数越多（更贵），所以这里有一个 K 的取舍。

⚠️ 这个"效率上限"的含义要说清：它是负载均衡假设下的极限，前提是"路由器真的近似均匀 + 各专家耗时相近"。真实系统里路由器会因为训练数据偏置产生系统性热点（某些专家永远更热），那时 σ 不是全部故事 —— 实际不均衡 = 统计波动 + 系统性偏置。后者必须靠辅助损失（load balancing loss）或无辅助损失的偏置调整来治，不是靠加大 batch 能解决的（加大 batch 只能压统计波动那一项）。

2.4 推理侧的四种处置#

手段 治哪一项 代价
增大 T（batch / 分块预填充） 统计波动 σ 延迟上升、KV 显存上升
增大容量因子 C 丢包率 每 rank 显存与算力要按 Cμ 预留 → 利用率下降
复制热专家（expert replication） 系统性偏置 显存 ∝ 副本数；需要知道哪些专家热
无辅助损失的偏置调整 系统性偏置 训练侧改动；推理侧只读取偏置
丢弃 + 残差兜底 兜底 质量损失（必须量化评估，不能默认可接受）

为什么"C 与利用率"是一对张力：若每 rank 按 Cμ 预留算力与显存，而实际平均负载是 μ，那么稳态利用率是

U=Cμμ​=C1​

C=1.25 意味着 80% 的专家算力利用率上限 —— 这是 MoE 推理里一笔常被忽略的固定税。它解释了为什么"MoE 稀疏度越高越省"在推理上会打折：稀疏省的是权重访存（激活参数少），但 EP 的容量预留与 A2A 会把省下的部分吃掉。

三、把 EP 的账并进前几节的框架#

3.1 三层并行在 MoE 模型上的分工#

MoE 模型的显存被两部分占据，需要分别处理：

每 token 都用注意力权重（每层 4H2）​​vs只有被路由到的才用专家权重（E×3Hdff​）​​

示例（L=32、H=4096、E=8、每专家 dff​=16384、top-2）：

量 数值
总参数 53.69 B
激活参数 15.03 B（稀疏比 3.57×）
fp16 总权重 100.00 GiB
fp16 激活权重 28.00 GiB
单卡权重访存（decode） 10.02 ms/token

分工：

并行 切什么 在这个模型上治什么
TP 注意力与每个专家内部的矩阵 降注意力部分的访存；不解决"放不下全部专家"
EP 专家（不同专家在不同 rank） 专家权重的显存 ∝1/N；这是 EP 的主要价值
PP 层 所有权重（注意力 + 专家）∝1/P

关键判断：如果一个 MoE 模型装不下，EP 与 PP 都能治，但：

EP 的代价=2L 次 A2A×(N−1)αvsPP 的代价=L 次 P2P×α

N=8 时 EP 是 2×7=14 个 α/层，PP 是 1 个 α/层 —— 差 14 倍。所以：

能用 PP 解决的显存问题，不要用 EP 解决​

EP 的正当理由只有一个：专家权重太大，PP 分段后仍装不下任何一段（单层专家权重 >1 张卡）。

3.2 与 TP 的 batch 行为对比（本节的收束）#

TP（N=8，环形） EP（N=8，K=2）
每 token 通信 cN，与 b 无关 2⋅NN−1​Kbhσ/β+2L(N−1)α
延迟项随 b 不变 不变（可摊薄）
带宽项随 b 不变 ∝b
b 增大 每 token 时间不变 → 收益不变 每 token 时间下降 → 收益上升
b=64 时的每层通信 140 μs（≈ 固定） 2.240 ms（延迟）+ 1.044 ms（带宽）
有效吞吐上限（示例） 1/5.03ms=199 tok/s（单请求） —
结论 大 batch 越用越不划算 大 batch 越用越划算

读法：这张表是"为什么 MoE 推理偏爱大 batch、而 dense 模型的大 batch 会把 TP 的收益吃掉"的统一解释。两者都源于同一个事实：

通信的"固定"部分（α 项）能被 batch 摊薄，∝N 的部分不能。

TP 的 α 项是 2(N−1)α 每次消息数固定（2L 次），所以总延迟 ∝LαN，与 b 无关；EP 的 α 项也是 2L(N−1)α，同样与 b 无关 —— 两者都能被 batch 摊薄？

⚠️ 这里必须小心，否则会得出错误结论。正确的区分是：

TP 摊薄的是"每次归约的 b⋅h 字节"，EP 摊薄的是"每层 A2A 的固定 (N−1)α"

两者都摊薄，但摊薄后的极限不同：TP 的每 token 通信 ≈2L⋅2(N−1)α 已经是"每 token"口径（因为每次归约服务的是整个 batch 的所有 token，而那个 α 是每次归约付一次、服务 b 个 token）：

Tcomm, per tokenTP​=b2L⋅2(N−1)α​（若按"每次归约服务整个 batch"计）

但真实的 TP 实现里，AllReduce 是每一步 decode 都要做的，每步处理的是"上一步刚生成的 b 个 token"，所以 b 越大，每次归约的消息越大（b⋅h），而归约次数不变（仍 2L 次/步）。所以

Tcomm, per stepTP​=2L⋅(2(N−1)α+2NN−1​βbhσ​)

⟹Tcomm, per tokenTP​=b2L⋅2(N−1)α​+Nβ2L⋅2(N−1)hσ​

第一项（延迟）∝1/b，第二项（带宽）与 b 无关。 在 decode 下第一项主导（137×），所以只要能加大 batch，TP 的每 token 通信也会下降 —— 这正是"batch 是 TP 的替代品"（第 2 节 3.4）的机制来源。

\boxed{\text{统一结论：}T_{\text{comm/token}} = \frac{A_{\alpha}}{b} + A_{\beta},\quad\rA_\alpha \text{ 是"每步的固定延迟开销"、}A_\beta\text{ 是"每 token 的带宽税"}}

\boxed{\text{统一结论：}T_{\text{comm/token}} = \frac{A_{\alpha}}{b} + A_{\beta},\quad\rA_\alpha \text{ 是"每步的固定延迟开销"、}A_\beta\text{ 是"每 token 的带宽税"}}

TP 的 Aα​=4L(N−1)α、Aβ​=4LNN−1​hσ/β；EP 的 Aα​=2L(N−1)α、Aβ​=2LNN−1​Khσ/β。

所以两者的差别不在"能不能摊薄"，而在 Aβ​ 的大小：

AβTP​AβEP​​=2K​

在 K=2 时两者相等（本节代码实测：都是 0.0020 ms/token），K=4 时 EP 贵一倍，K=1 时 EP 便宜一半。 这句话修正了本节开头那条 boxed 结论的表述：EP 与 TP 的 α 项都能被 batch 摊薄，EP 真正的额外成本是"K 倍的带宽税"（每个 token 要发 K 份表示、收 K 份结果）。这个修正很重要 —— 它说明"MoE 推理更适合大 batch"的理由是统计波动（2.3 节：T 越大最热专家问题越小），而不是"通信只能靠 batch 摊薄"。

代码：EP 的 A2A 账、容量因子与效率上限#

脚本做四件事：(1) 打印每层 A2A 的字节与延迟/带宽拆解，并指出 b 的转折点；(2) 用精确二项分布算"容量因子 → 丢包率"表（数值稳定实现）；(3) 算最热专家与 EP 效率上限；(4) 把 TP 与 EP 的 Aα​/Aβ​ 放在同一张表里对比。

"""
专家并行的通信账、容量因子与负载不均衡（只用标准库）。

设计决策：
  1. A2A 的延迟项按「每层一次单向转发 × (N-1) 步」建模，与 TP 的环形归约
     （2(N-1) 步）区分开。两者的差别直接决定"每层通信预算"（正文 1.1）。
  2. 丢包率用**精确二项分布**（lgamma 实现的数值稳定版本），不用正态近似。
     原因：C 接近 1 时正态近似误差可达数个百分点，而结论正是"C=1 附近最危险"（正文 2.2）。
  3. 「最热专家」用极值统计近似 E[max] ≈ μ + sqrt(2 ln E)·σ。它是 EP 效率上限的
     来源，也是 MoE 推理"小 batch 效率低"的定量解释（正文 2.3）。
  4. 最后把 TP 与 EP 的通信写成 A_α/b + A_β 的统一形式，因为这是判断
     "batch 能否救这个配置"的唯一口径（正文 3.2）。
"""
import math
from math import ceil, lgamma, log, log1p, exp, sqrt

# ==================== 口径 ====================
L, H = 32, 4096
E_EXPERTS, TOPK = 8, 2
D_FF_EXP = 4 * H                       # 每个专家的中间维
HBM, FLOPS, LINK, ALPHA = 3.0e12, 989e12, 450e9, 5e-6
DTYPE = 2                              # fp16/bf16


def moe_params(L=L, H=H, E=E_EXPERTS, d_ff=D_FF_EXP, topk=TOPK):
    """返回（总参数, 激活参数）。注意力 4H² 每层都算；专家只算 top-K。"""
    attn = 4 * H * H
    per_expert = 3 * H * d_ff          # gate + up + down
    total = L * (attn + E * per_expert)
    active = L * (attn + topk * per_expert)
    return total, active


# ==================== (1) A2A 字节账 ====================
def a2a_bytes(N, b, topk=TOPK, h=H, dtype=DTYPE, layers=L):
    """
    返回 dict：每层每 rank 字节、每 token 全模型字节、带宽时间、延迟时间。
    模型：dispatch 与 combine 各一次；每 rank 要发给其他 N-1 个 rank。
    """
    per_layer = (N - 1) * topk * b * h * dtype       # 每 rank 每层发出
    total = 2 * layers * per_layer                   # ×2（disp+comb），×L 层
    t_bw = total / LINK
    steps_per_a2a = N - 1
    t_lat = 2 * layers * steps_per_a2a * ALPHA
    return {"per_layer": per_layer, "total": total, "T_bw": t_bw, "T_lat": t_lat,
            "ratio": t_lat / t_bw if t_bw else float("inf")}


def crossover_batch(N, topk=TOPK, h=H, dtype=DTYPE):
    """延迟项 = 带宽项 的 batch：b* = α·β/(K·h·σ)（与 N、L 都无关）。"""
    return ALPHA * LINK / (topk * h * dtype)


# ==================== (2) 容量因子与丢包率 ====================
def binom_pmf_log(n, k, p):
    return (lgamma(n + 1) - lgamma(k + 1) - lgamma(n - k + 1)
            + k * log(p) + (n - k) * log1p(-p))


def binom_sf(n, p, c):
    """P(X > c)，数值稳定（lgamma + exp）。"""
    c = int(math.floor(c))
    if c >= n:
        return 0.0
    return sum(exp(binom_pmf_log(n, j, p)) for j in range(c + 1, n + 1))


def drop_rate(T, E, topk, C):
    """
    丢包率 ≈ 1 - (1-p)^K，p = P(某专家的负载 > C·μ)。
    ★ 注意 p ≠ 0 即使 C 略大于 1（C=1 时 p≈0.45）—— 这是"容量取均值"的代价。
    """
    n, p = T * topk, 1.0 / E
    mu = T * topk / E
    pe = binom_sf(n, p, C * mu)
    return 1.0 - (1.0 - pe) ** topk, pe, mu


# ==================== (3) 最热专家与效率上限 ====================
def hottest(T, E, topk):
    """E[max_e L_e] ≈ μ + sqrt(2 ln E)·σ；返回（比值, 效率上限）。"""
    mu = T * topk / E
    sd = sqrt(T * topk * (1 / E) * (1 - 1 / E))
    ratio = 1 + sqrt(2 * log(E)) * sd / mu
    return ratio, 1.0 / ratio


# ==================== (4) TP 与 EP 的统一通信口径 ====================
def comm_coeffs(N, topk=TOPK, h=H, dtype=DTYPE, layers=L):
    """
    返回 (A_alpha, A_beta)：T_comm/token = A_alpha/b + A_beta。
      TP：每层 2 次全归约，环形 2(N-1) 步 → A_alpha = L·2·2(N-1)α
      EP：每层 2 次 A2A，各 (N-1) 步      → A_alpha = L·2·(N-1)α
    """
    a_alpha_tp = layers * 2 * (2 * (N - 1)) * ALPHA
    a_beta_tp = layers * 2 * (2 * (N - 1) / N) * h * dtype / LINK
    a_alpha_ep = layers * 2 * (N - 1) * ALPHA
    a_beta_ep = layers * 2 * ((N - 1) / N) * topk * h * dtype / LINK
    return {"TP": (a_alpha_tp, a_beta_tp), "EP": (a_alpha_ep, a_beta_ep)}

五处关键设计决策：

  1. binom_sf 用 lgamma + exp 而不是 math.comb。comb(2048, 32) 会溢出（整数转浮点失败），而教材里"C=1.0 时丢包到底多少"正是最需要看清的一段。数值实现的选择在这里是结论正确性问题。
  2. crossover_batch 与 a2a_bytes 分开。前者是闭式（b∗=αβ/(Khσ)，与 N、L 无关），后者是完整账；两者并列才能看出"转折点其实与几个因素无关"这个反直觉事实。
  3. hottest 用 μ+2lnE​σ 而不是实测最大值。这是刻意的：极值统计近似给出的是分布性质，与你的具体实现无关，所以它可以用来预判"这个 MoE 配置在多大 batch 下才有效率"。实测最大值受路由器训练状态影响，两者不等（正文 2.3 的 ⚠️）。
  4. comm_coeffs 把 TP 与 EP 写成同一个形式。这是本节最后一段的收束：两种并行的 α 项都能被 batch 摊薄，差别在 β 项的 K/2 倍 —— 不写成同一形式，这个结论看不出来。
  5. 第 (4) 段保留 (1024, 256, 2) 这一行。E 从 64 涨到 256 时效率上限反而从 66.4% 掉到 46.0%（因为 σ/μ∝E/(TK)​ 上升而 2lnE​ 只涨一点），用数据而不是断言呈现"专家数不是越多越好"。

小结#

  • EP 每层两次 all-to-all（dispatch + combine），与 TP 的两次 AllReduce 结构对称，但交换的是token 表示（置换）而不是部分和（归约）。每层每 rank 的字节是 2NN−1​Kbhσ。
  • A2A 在 decode 下同样是延迟主导：N=8、K=2、b=1 时延迟项 2.240 ms vs 带宽项 0.016 ms，比值 ≈137。这个比值 =αβ/(Khσ)，与 N、L 无关 —— 它是"硬件 × 负载"的常数。
  • 转折点在 b∗=αβ/(Khσ)≈123（示例口径）。越过它，带宽主导，"低精度 A2A / 按专家分桶合并"才开始有用。
  • 容量因子的真相：C=1.0 时丢包率是 40%~70%，不是接近 0（因为 P(Le​>μ)≈0.45，且 top-K 有 K 个被丢的机会）。C=1.25、T=1024、E=64、K=2 → 丢包 13.3%；T 涨到 4096 才降到 0.51%。所以"容量因子取多少"是负载相关的，不是常数。
  • 容量因子是一笔固定税：每 rank 按 Cμ 预留资源，稳态利用率上限只有 1/C。C=1.25 → 80%。这是 MoE 稀疏化收益在推理侧被打折的一个常被忽略的原因。
  • 最热专家决定整层耗时：E[maxe​Le​]≈μ+2lnE​σ，于是 EP 效率上限 ≈1/(1+2lnE(1−1/E)E/(TK)​)。T=256 时只有 49.7%，T=16384 时 88.8%。"MoE 推理需要大 batch"的定量理由在这里，不在通信。
  • 专家数不是越多越好：σ/μ∝E/(TK)​，E 大则相对波动大。MoE 的粒度受统计波动限制。
  • EP 与 TP 的统一口径：Tcomm/token​=Aα​/b+Aβ​。两者的 Aα​ 都能被 batch 摊薄；真正的差别是 EP 的 Aβ​ 是 TP 的 K/2 倍（每个 token 要发 K 份、收 K 份）。
  • "能用 PP 解决的显存问题不要用 EP"：N=8 时 EP 每层 14 个 α、PP 每层 1 个 α，差 14 倍。EP 的正当理由只有一个：单层专家权重超过一张卡。
  • 一句话：EP 用"每层两次 A2A（K 倍带宽税）"买"专家权重的显存分摊"，它的真实瓶颈不是通信而是「统计波动 + 容量预留」—— 这两者都要求大 batch，而大 batch 又会加剧波动，唯一的出路是容量因子与专家复制。

下一章：本章算的是并行拆分的静态账（给定模型与硬件，拆几张、怎么拆）。但真实服务的输入是流：请求陆续到达、长度不同、KV 不断涨落。同一个并行配置在"低并发短请求"与"高并发长请求"下的表现可以差一个数量级。第 2 章进入调度与 KV 管理：连续批处理如何把固定成本摊到更多 token 上、分块预填充的最优块大小、抢占时"重算还是换出"的分界、以及 KV 分页与前缀共享的显存账。
