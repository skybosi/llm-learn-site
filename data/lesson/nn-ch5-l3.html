学习率与调参#

优化器决定"往哪个方向、用什么步法走"，而学习率（learning rate, η）决定"每一步迈多大"。它是所有超参数里最敏感、最值得先调的一个：太大，训练直接发散；太小，训练慢到天荒地老。本课讲学习率的正确取值、随训练动态调整的学习率调度，以及一些实用的调参经验。

一、概念讲解#

1. 学习率的三张"脸"#

参数更新 θ ← θ − η·g 中，η 控制步长，它的取值会带来三种典型结果：

  • 过大：一步跨过最优点，甚至越走越远，损失震荡或直接变成 NaN（发散）。
  • 过小：每步只挪一点点，收敛极慢，还可能陷在局部极小值或平坦区出不来。
  • 合适：损失平稳下降，最终收敛到一个较低的值。

一个实用的经验起点：Adam 用 1e-3，SGD 用 0.01，然后在对数尺度上（如 1e-4、1e-3、1e-2、0.1）粗扫一遍。

2. 为什么要"动态调整"学习率#

训练早期，参数离最优很远，可以用较大的学习率快速下降；训练后期，参数逼近最优，需要较小的学习率精细收敛。固定学习率很难两头兼顾——大了后期震荡、小了前期太慢。学习率调度（scheduler）就是让 η 随训练进程逐步减小：

  • StepLR：每过固定步数，把学习率乘以一个衰减因子（如每 30 轮 ×0.5）。
  • ExponentialLR：每步都按指数 η ← η·γ 衰减。
  • CosineAnnealingLR：学习率沿余弦曲线平滑地从初始值降到最低，是现在大模型最常用的方式。

3. 学习率热身（warmup）#

如果一开始就用很大的学习率，模型还没"站稳"就被巨大的步子打乱。warmup 的思路是：前若干步把学习率从很小线性升到目标值，再开始正常调度。这在训练 Transformer 等大模型时几乎是标配，能显著提升早期稳定性。

4. 学习率与 batch size 的关系#

增大 batch size 会让每步的梯度更"准"（噪声更小），理论上可以同步放大学习率。一个经验法则是线性缩放：batch size 翻倍、学习率也翻倍。不过这条法则在 batch size 极大时（如上万）会失效，需要配合 warmup 等技巧。日常调参时，记住"改了 batch size，最好重新审视学习率"即可。

5. 调参实战经验#

  • 先粗扫，再细调：先在对数尺度 [1e-4, 1e-3, 1e-2, 1e-1] 上各跑几轮，看损失曲线哪个区间能平稳下降，再在该区间附近加密。
  • 看曲线，而不是看最终数字：损失震荡→学习率偏大；损失几乎不动→学习率偏小或梯度消失。
  • 别让学习率"一刀切"：配合 Adam 时学习率不用太纠结；配合 SGD 时学习率 + 调度 + 动量三者要一起调。

二、可运行示例#

下面用一个三层 MLP 拟合带噪声的正弦函数，展示不同学习率的三种结局，以及调度器的效果。

import torch
import torch.nn as nn
import torch.optim.lr_scheduler as lr_scheduler

torch.manual_seed(0)

# —— 构造数据：带噪声的 sin 曲线 ——
x = torch.linspace(-3, 3, 200).view(-1, 1)
y = torch.sin(x) + 0.1 * torch.randn_like(x)

def make_net():
    return nn.Sequential(
        nn.Linear(1, 64), nn.ReLU(),
        nn.Linear(64, 64), nn.ReLU(),
        nn.Linear(64, 1),
    )

def train(lr, use_scheduler=None, epochs=100):
    net = make_net()
    opt = torch.optim.SGD(net.parameters(), lr=lr, momentum=0.9)
    sched = None
    if use_scheduler == "step":
        sched = lr_scheduler.StepLR(opt, step_size=30, gamma=0.5)
    elif use_scheduler == "cosine":
        sched = lr_scheduler.CosineAnnealingLR(opt, T_max=epochs)
    loss_fn = nn.MSELoss()
    for epoch in range(epochs):
        opt.zero_grad()
        loss = loss_fn(net(x), y)
        if not torch.isfinite(loss):      # 发散则提前终止
            return f"epoch {epoch:3d} 发散，loss={loss.item()}"
        loss.backward()
        opt.step()
        if sched:
            sched.step()
    with torch.no_grad():
        final = loss_fn(net(x), y).item()
    return f"最终 loss = {final:.4f}"

# 1. 学习率过大 -> 发散
print("lr=1.0   :", train(lr=1.0))
# 2. 学习率过大 -> 剧烈震荡，无法收敛
print("lr=0.5   :", train(lr=0.5))
# 3. 学习率合适 -> 平稳下降
print("lr=0.05  :", train(lr=0.05))
# 4. 学习率过小 -> 几乎学不动
print("lr=1e-5  :", train(lr=1e-5))
# 5. 初始较大 + StepLR 调度 -> 前期快、后期稳
print("lr=0.5+StepLR :", train(lr=0.5, use_scheduler="step"))
# 6. 初始较大 + 余弦调度 -> 平滑下降
print("lr=0.5+Cosine :", train(lr=0.5, use_scheduler="cosine"))

可以看到：lr=0.5 单用会震荡发散，但配上 StepLR/余弦调度后，前期的大步子能快速下降、后期自动缩小步子，最终也能收敛得很好——这就是"动态调整学习率"的价值。

三、练习#

  1. 找临界值：把示例里的 lr 在 0.05 到 0.5 之间多试几个值（如 0.1、0.2、0.3），找出"刚好开始震荡"的临界学习率，观察损失曲线如何随 lr 增大而恶化。
  2. 手算衰减：设初始学习率 0.1、StepLR(step_size=10, gamma=0.1)，写出第 1、10、11、20、21 步时的学习率分别是多少。
  3. 加 warmup：自己实现一个简单的 warmup——前 10 步把学习率从 0 线性升到 0.5，之后用余弦衰减，替换示例中的固定初始学习率，观察前期损失是否更平稳。
  4. 思考：为什么学习率调度要在每个 epoch 之后 scheduler.step()，而不是每个 batch 之后？如果每个 batch 都衰减会发生什么？
  5. 拓展：把优化器换成 Adam，把初始学习率设为 1e-3，去掉调度器再跑一遍，对比它和学习率调度下的 SGD 谁更省心、谁最终损失更低。
