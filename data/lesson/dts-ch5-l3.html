流水线并行（PP）：气泡与 1F1B / 交错调度#

张量并行把矩阵切开，代价是每一层都要 AllReduce；流水线并行（Pipeline Parallelism，PP）走另一条路：按层把模型切成几段，每个设备只放一段，设备之间只传边界上的激活，通信退化成便宜的点对点。代价换了地方——设备会等待。本课把这份等待（气泡）算成一个可打印的公式，并比较 GPipe、1F1B 与交错调度三种排法。

一、概念讲解#

1. PP 切什么：切层，通信变成点对点#

把 L 层切成 p 段，第 i 个设备放第 i 段（L/p 层），每次只把边界激活发给下一段。于是通信模式从 TP 的 AllReduce 变成相邻设备之间的 send/recv：Megatron-LM 的系统论文明确指出，PP 的点对点通信便宜得多、可以跨节点而不会成为瓶颈，而 TP 的 all-reduce 昂贵、应限制在节点内。

mini-batch（全局 batch）会被切成 m 个微批（microbatch），让流水线里同时有多个微批在飞。m 的大小是本课的主角。

2. 气泡从哪来：为保住"严格的优化器语义"#

如果让每个微批各自往前冲，同一个权重在不同微批的前向与反向里会看到不同版本（前向用旧权重、反向梯度对应新权重）。要保住"每步所有设备用同一份权重同步更新"的语义，就必须在 batch 边界做流水线刷新（flush）：batch 开始与结束时设备只能空转，这段空转就是气泡（bubble）。

Megatron-LM 论文把气泡量化得很干净。设每个微批在一个 stage 上的前向时间为 tf​、反向为 tb​，段数为 p、每 batch 微批数为 m：

  • 气泡时长：tpb​=(p−1)(tf​+tb​)（开头 p−1 次前向 + 结尾 p−1 次反向都是等在等）
  • 理想计算时长：tid​=m(tf​+tb​)
  • 气泡占比：tid​tpb​​=mp−1​，总时长 (m+p−1)(tf​+tb​)

结论只有一句：要让气泡小，就必须 m≫p。

3. GPipe 与 1F1B：气泡一样，显存差一个量级#

两种经典排法：

  • GPipe：先把 m 个微批的前向全部做完，再做全部反向。为了让反向能用上前向的中间结果，需为 m 个微批缓存激活。
  • 1F1B（PipeDream-Flush）：先做 p−1 个前向进入稳态，之后每个设备"一次前向、一次反向"交替，最后排空。1F1B 气泡时间与 GPipe 完全相同，但在飞的微批数被限制在流水线深度以内，只需缓存不超过 p 份激活（GPipe 要 m 份）。

示例 1 用离散时间片模拟验证了这一点：p=4,m=8 时两种排法总时长都是 22 片、气泡都是 6 片（占比 37.5%，与公式 3/8 一致），但需缓存激活的微批份数是 m=8 对 p=4。

4. 交错调度：把气泡再除以 v#

1F1B 的气泡 =(p−1)/m 只跟"段数"和"微批数"有关。若让每个设备持有 v 个模型块（model chunk）而不是一段连续的层，气泡可以进一步缩小：

tpbint.​=v(p−1)(tf​+tb​)​,气泡占比=v1​⋅mp−1​

代价也很清楚：设备之间的通信量增加 v 倍（每层边界都要传 v 次），而且交错调度要求"每个 batch 的微批数是流水线并行度的整数倍"。Megatron-LM 论文的实测是：交错调度最多带来 10% 以上的吞吐提升，显存与原有方案相当——前提是配合 scatter/gather 之类的通信优化。

5. 三种并行怎么组合#

p⋅t⋅d=n（n 为 GPU 总数，p 流水、t 张量、d 数据），每 batch 的微批数 m=b1​⋅dB​（b 微批大小、B 全局 batch）。把气泡写成这些量的函数（取 t=1）：

mp−1​=b′/dn/d−1​=b′n−d​,b′=B/b

这条式子里有个反直觉的结论：数据并行度 d 越大，气泡越小——气泡 =(n−d)/b′ 随 d 单调下降（d 变大时 p=n/d 与 m=b′/d 同时变小，而分子 n−d 减得更快），前提当然是显存装得下。论文的实测规模是：1 万亿参数模型、3072 张 GPU、502 PFLOP/s 聚合吞吐（每卡达理论峰值的 52%）；此时流水线通信的有效对分带宽 892 GB/s，数据并行的通信量则达到 13 TB/s。

6. 微批大小 b 的两难#

  • b 太小：每个微批的算子规模小、算术强度低，GPU 利用率被固定开销吃掉（tf​(b) 里的常数项占比高）；
  • b 太大：m=B/b 变小，气泡占比 (p−1)/m 变大。

论文把这两项写成一个可优化的式子：总时间 ∝(b′/b+p−1)⋅(tf​(b)+tb​(b))，并指出最优微批大小依模型而异（他们的实验里最优值带来的吞吐差异可达 15%）。示例 3 用示例参数扫了一遍，最优 b∗=64。

7. 常见坑#

  • m 不是 p 的整数倍就用交错调度：论文明确要求 batch 内微批数是流水线并行度的整数倍，否则会出问题。
  • 层数不能被 p 整除：各 stage 负载不均，整条流水线按最慢的段跑。
  • 以为 PP 只省显存不花时间：气泡 =(p−1)/m 就是它的时间代价，m 不够大时非常贵（示例 2 里 p=8,m=8 时气泡占 87.5%）。
  • 拿微批数去堆显存：m 大是好事，但 GPipe 排法要缓存 m 份激活，必须换 1F1B。
  • 忽略优化器语义：异步流水线（PipeDream 类）去掉刷新、消除气泡，但放宽了权重版本语义；要严格同步就用刷新。

二、可运行代码示例#

第一段用离散时间片模拟 GPipe 与 1F1B：数出总时长、气泡，并与公式对照；第二段扫 (p,m)；第三段算微批大小的最优值。

# ===== 示例 1：离散时间片模拟 GPipe 与 1F1B：气泡相同，激活占用不同 =====
def simulate(p, m, policy):
    """p 段流水、m 个微批；t_f = t_b = 1 个时间片，跨设备消息次片可用。
    policy: 'gpipe' 先做完全部前向；'1f1b' 在飞超过 p-1 就先做反向。"""
    fwd = [[None]*m for _ in range(p)]; bwd = [[None]*m for _ in range(p)]
    t = 0
    while any(bwd[i][j] is None for i in range(p) for j in range(m)):
        plan = [None]*p
        for i in range(p):
            outstanding = sum(1 for j in range(m) if fwd[i][j] is not None and bwd[i][j] is None)
            cF = next((j for j in range(m) if fwd[i][j] is None and
                       (i == 0 or fwd[i-1][j] is not None)), None)
            cB = next((j for j in range(m) if fwd[i][j] is not None and bwd[i][j] is None and
                       (i == p-1 or bwd[i+1][j] is not None)), None)
            order = ("F", "B") if policy == "gpipe" else \
                    (("B", "F") if outstanding >= p-1 else ("F", "B"))
            for want in order:
                if want == "F" and cF is not None:
                    plan[i] = ("F", cF); break
                if want == "B" and cB is not None:
                    plan[i] = ("B", cB); break
        for i in range(p):
            if plan[i]:
                op, j = plan[i]
                (fwd if op == "F" else bwd)[i][j] = t
        t += 1
        if t > 5000: break
    return t, t - m*2                      # 总时长、气泡时长（理想 = m·(t_f+t_b) = 2m）

p, m = 4, 8
print("示例 1：两种调度的总时长与气泡（p=4 段、m=8 微批；t_f=t_b=1，理想时长 = 2m = 16）")
for pol in ("gpipe", "1f1b"):
    total, bubble = simulate(p, m, pol)
    print(f"  {pol:<6} 总时长 {total:3d}  气泡 {bubble:3d}  气泡占比 {bubble/(2*m):6.1%}"
          f"（公式 (p-1)/m = {(p-1)/m:6.1%}）")
print(f"  单设备需缓存激活的微批份数（论文口径）：GPipe 为 m = {m}，1F1B 为 p = {p}")

print("\n示例 2：把 (p, m) 扫一遍：总时长 = (m+p-1)·(t_f+t_b)，气泡占比 = (p-1)/m")
print("  p    m    总时长   实测气泡占比   公式 (p-1)/m")
for p_, m_ in ((2, 8), (4, 8), (8, 8), (8, 16), (8, 64), (16, 64), (16, 256)):
    total, bubble = simulate(p_, m_, "1f1b")
    print(f"  {p_:<4} {m_:<4} {total:7d} {bubble/(2*m_):14.1%} {(p_-1)/m_:15.1%}")

# ===== 示例 3：微批大小 b 的两难（计算效率 vs 气泡） =====
def batch_time(B, p, b, a=2.0, c=0.05):
    """t_f(b) = a + c·b（示例：固定开销 a + 随样本线性增长的 c）。
    Z = B 个样本；每步时间 = (B/b + p - 1)·(t_f + t_b)，t_b = 2·t_f。"""
    tf = a + c*b
    return (B/b + p - 1)*(tf + 2*tf)
B, p_ = 1024, 8
print(f"\n示例 3：固定 {B} 样本、{p_} 段流水，微批 b 的取舍（t_f(b) = 2.0 + 0.05b ms）")
print("  b      每步时间(ms)   其中气泡占比      每样本时间(ms)")
best = None
for b in (1, 2, 4, 8, 16, 32, 64, 128):
    T = batch_time(B, p_, b)
    bubble_share = (p_ - 1)*(b) / (B + (p_ - 1)*b)   # 气泡时间 / 总时间
    if best is None or T < best[1]: best = (b, T)
    print(f"  {b:<6} {T:12.2f} {bubble_share:16.1%} {T/B:15.4f}")
print(f"  最优微批（示例参数）b* = {best[0]}，每步 {best[1]:.2f} ms；"
      "b 太小被固定开销吃，b 太大被气泡吃。")

三、练习#

  1. 实现：把示例 1 的 simulate 改成记录"每个时间片每个设备在做什么"，打印一张 p× 时间 的调度表（F/B/空）；用这张表数出气泡时长并与 (p−1)(tf​+tb​) 对照。
  2. 解释：为什么 1F1B 与 GPipe 的气泡时间相同、激活占用却从 m 降到 p？用"反向需要哪些前向结果还在手里"回答。
  3. 对比/验证：按论文公式计算交错调度 v=2,4 时 p=8,m=64 的气泡占比，并说明通信量为什么增加 v 倍；给出一个"交错不值"的场景。
  4. 思考：n=64、t=8、p=4、d=2、全局 batch B=1024 样本、微批 b=16。算出每 batch 的微批数 m 与气泡占比；若把 d 提到 8（p=1），气泡是多少？这解释了论文里哪条结论？
