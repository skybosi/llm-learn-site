结果评估与复盘#

推荐系统上线不是终点，而是迭代的起点。怎么判断它"好不好"？离线指标、在线指标、以及上线后的复盘，是三个不同层次的问题。本课讲清楚它们分别衡量什么、各自会骗你在哪里，以及一次上线之后该如何复盘、找到下一步该优化什么。

一、概念讲解#

1. 离线评估：快，但只是"入场券"#

离线评估在历史数据上跑，优点是快、可反复、可对比。排序模型最常用的离线指标是 AUC；推荐列表则常用 topK 指标：

  • AUC：正样本得分高于负样本的概率，衡量排序模型对"点 vs 不点"的区分能力。GAUC（按用户分组算 AUC 再平均）更贴近推荐场景，因为它衡量的是"同一个用户内部排序对不对"，而不是"用户之间比高低"。
  • Precision@K / Recall@K：推荐 topK 里有多少是用户真的感兴趣的 / 用户所有感兴趣物品里被推荐出了多少。
  • NDCG@K：考虑排序位置——排得越靠前的命中权重越高，适合衡量"排序质量"而非只衡量"有没有命中"。
  • 覆盖率 / 多样性 / 新颖性：推荐列表覆盖了多少物品、类目是否多样、是否推荐了用户没见过的内容。这些是"体验指标"，和准确率往往要权衡。

离线指标最大的问题是会骗人：离线 AUC 高，线上可能毫无起色。原因主要有两个：

  • 线上线下一一致性（第 4 章讲过）：训练特征与线上特征口径不一致，离线评估用的是"理想数据"，线上拿不到。
  • 反馈偏差：离线数据是"旧策略推荐后用户的选择"，天然受位置偏差（排前面天然更容易被点）和曝光偏差（只记录了被曝光物品的反馈，没曝光过的物品是缺失数据）污染。离线 AUC 衡量的是"在旧策略曝光过的物品里谁好"，而不是"所有物品里谁好"。

所以离线指标的正确用法是：当"快速筛选候选模型的入场券"，而不是"最终裁判"。它能把明显更差的模型挡在门外，但最终效果必须靠线上验证。

2. 在线评估：AB 实验是唯一裁判#

在线评估用 AB 实验：把用户随机分成对照组（旧策略）和实验组（新策略），在相同时间段对比真实指标——CTR、转化率、人均时长、次日留存等。AB 实验的三个关键点：

  • 随机分流：用户要随机分到两组，消除"两组用户本来就不一样"的干扰。
  • 只看核心指标 + 显著性检验：指标涨跌可能是随机波动，要用统计检验（如 z 检验）判断差异是否显著，样本量要足够大。
  • 警惕新奇效应：新策略刚上线，用户会因为"新鲜感"短期多点击，过一周回落；评估要看稳定期的数据。

在线指标的选择要和业务目标一致（第 1 课定下的指标）：目标是 GMV 就看转化和客单价，目标是留存就看次日/7 日留存，而不是盯着 CTR 一个数。

3. 复盘：从"效果怎么样"到"下一步做什么"#

一次 AB 实验结束，无论成败都要复盘。复盘不是看一个总分，而是拆解：

  • 按人群拆：新用户、老用户、重度/轻度用户，各自的指标如何？也许整体没涨，但新用户涨了，说明新策略对冷启动有效。
  • 按物品/类目拆：哪些类目涨、哪些跌？跌的是不是被多样性打散牺牲了？
  • 按漏斗拆：是召回没捞到好物品（召回率低），还是排序排错了（AUC 没涨），还是重排把好物品打散了？
  • Bad Case 分析：人工抽查几组"应该推但没推""推了但明显不相关"的 case，往往能一眼看出问题出在哪一层。

复盘的产出物，应该是一份带优先级的下一步行动清单：比如"新用户冷启动召回命中率低 → 加强标签/热门路兜底""长尾物品曝光不足 → 加一路长尾召回"。这样评估才真正闭环到迭代。

二、可运行示例#

示例 1：计算推荐列表的 Precision@K / Recall@K / NDCG@K#

import numpy as np

def precision_at_k(rec, relevant, k):
    rec_k = rec[:k]
    return len(set(rec_k) & set(relevant)) / k

def recall_at_k(rec, relevant, k):
    rec_k = rec[:k]
    return len(set(rec_k) & set(relevant)) / len(relevant) if relevant else 0.0

def dcg_at_k(rec, relevant, k):
    """折损累积增益：命中越靠前，增益越大。"""
    gains = [1.0 if i in set(relevant) else 0.0 for i in rec[:k]]
    return sum(g / np.log2(idx + 2) for idx, g in enumerate(gains))  # idx 从 0 起，+2 保证分母从 log2(2)=1 起

def ndcg_at_k(rec, relevant, k):
    ideal = sorted([1.0] * min(len(relevant), k) + [0.0] * max(0, k - len(relevant)), reverse=True)
    idcg = sum(g / np.log2(idx + 2) for idx, g in enumerate(ideal))
    return dcg_at_k(rec, relevant, k) / idcg if idcg else 0.0

# 一个用户：真实感兴趣 5 个物品，推荐列表 10 个
relevant = {3, 7, 15, 22, 40}
rec_list = [7, 3, 50, 22, 1, 40, 99, 15, 8, 2]

for k in [5, 10]:
    print(f"k={k}: Precision={precision_at_k(rec_list, relevant, k):.3f}, "
          f"Recall={recall_at_k(rec_list, relevant, k):.3f}, "
          f"NDCG={ndcg_at_k(rec_list, relevant, k):.3f}")

示例 2：位置偏差演示——为什么"曝光 = 正样本"会骗人#

构造一个简单场景：物品的真实吸引力一样，但因为排位靠前获得更多曝光和点击。演示"用点击率排序"会被位置偏差误导。

import numpy as np

np.random.seed(0)
n_items = 100
true_ctr = np.random.uniform(0.02, 0.05, n_items)   # 每个物品的真实点击率(有细微差异)

# 模拟两种曝光策略下观测到的点击率
def observed_ctr(true_ctr, position_weight):
    """position_weight[i] 是物品 i 因排位获得的曝光放大倍数。"""
    # 位置越靠前，曝光越多，观测到的点击率越被放大（假设点击率本身不变）
    exposures = position_weight
    clicks = np.random.binomial(exposures, true_ctr)
    return clicks / exposures

# 策略 A：物品按编号顺序排，前 10 个获得 10 倍曝光（排位优势）
pos_weight = np.ones(n_items)
pos_weight[:10] = 10.0
obs_a = observed_ctr(true_ctr, pos_weight)

# 策略 B：随机排，曝光均匀
pos_weight_b = np.ones(n_items)
obs_b = observed_ctr(true_ctr, pos_weight_b)

# 用观测 CTR 排 top5，看是否被位置偏差带偏
top5_by_obs = np.argsort(-obs_a)[:5]
top5_true = np.argsort(-true_ctr)[:5]
print("真实 CTR 最高的 top5:", top5_true.tolist())
print("策略 A 观测 CTR 最高的 top5:", top5_by_obs.tolist())
print("被位置偏差误选进 top 的物品数:", len(set(top5_by_obs) - set(top5_true)))

示例 3：离线 AUC 高、线上却失效的演示#

展示一个"训练时用了未来特征（时序穿越）"的模型，离线 AUC 虚高，但线上拿到的是"未来"信息，必然失效。

import numpy as np
from sklearn.metrics import roc_auc_score

np.random.seed(1)
n = 5000
x = np.random.randn(n, 5)
# 真实标签只依赖前 3 个特征
logit = 0.5 * x[:, 0] + 0.3 * x[:, 1] - 0.4 * x[:, 2]
y = (np.random.rand(n) < 1 / (1 + np.exp(-logit))).astype(int)

# 泄漏特征：把"标签本身"当作第 6 个特征（模拟训练时用了未来信息）
x_leak = np.hstack([x, y.reshape(-1, 1)])

def fit_auc(features):
    """用一个简单的线性打分 + 阈值，返回 AUC（用 sklearn 的逻辑回归思路简化）。"""
    # 直接用 logit 近似：这里简化为用特征的加权和预测
    w = np.linalg.lstsq(features, y, rcond=None)[0]
    score = features @ w
    return roc_auc_score(y, score)

print("无泄漏特征的离线 AUC:", round(fit_auc(x), 4))
print("含泄漏特征的离线 AUC:", round(fit_auc(x_leak), 4), "  <- 虚高")
print("说明：线上拿不到'标签'这个未来特征，虚高的 AUC 一到线上就塌。")

三、练习#

  1. 在示例 1 中，把推荐列表改成"5 个命中物品全部排在最末尾"，观察 NDCG@10 相比"命中物品排最前"时的变化，说明 NDCG 为什么比 Recall 更能衡量排序质量。
  2. 说明位置偏差和曝光偏差的区别：为什么"只看点击率"会把"位置靠前"误当成"物品本身好"？举例说明如何缓解。
  3. 设计一个 AB 实验：你要验证"新的召回策略能提升 CTR"，写出对照组/实验组、核心指标、以及判断"显著"所需注意的样本量和时间长度。
  4. 思考题：GAUC 和 AUC 在什么场景下会给出相反的结论？为什么推荐场景更常用 GAUC？
