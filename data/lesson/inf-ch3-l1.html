vLLM#

前两章讲的 PagedAttention 与 continuous batching，最终都要落到一个能直接拿来部署的引擎上。vLLM 就是把这两项技术产品化的代表作，也是目前开源社区使用最广的高吞吐 LLM 推理框架之一。学完本课，你应当能用 vLLM 起一个服务、用 OpenAI 兼容接口调用它，并说出它的几个关键参数的含义。

一、概念讲解#

1. vLLM 是什么#

vLLM 是一个面向 GPU 的高吞吐 LLM 推理与 serving 引擎，由加州大学伯克利分校团队开发。它的立身之本是两件事：

  • PagedAttention（第 2 章）：块状 KV Cache 管理，消除碎片、支持共享，把并发数提高 2–4 倍；
  • continuous batching（第 1 章）：迭代级调度，让 GPU 不空转。

在此之上，vLLM 还提供了 OpenAI 兼容 API（/v1/completions、/v1/chat/completions），意味着你原来调 OpenAI 的代码，把 base_url 改成 vLLM 的地址就能用——迁移成本极低。

2. 为什么它吞吐高#

除了 PagedAttention 和 continuous batching，vLLM 还叠加了多项优化：

  • CUDA kernel 优化：针对注意力、融合算子做高效 kernel，减少 kernel 启动开销；
  • 张量并行 / 流水线并行：大模型可拆到多卡（第 5 章会专门讲张量并行）；
  • 量化支持：支持 AWQ、GPTQ、FP8、INT8 等（第 4 章）；
  • 前缀缓存（automatic prefix caching）：自动复用相同 prompt 前缀的 KV，进一步省算力。

3. 关键启动参数#

  • --model：模型路径或 Hugging Face 模型 id；
  • --max-model-len：最大序列长度，直接决定 KV Cache 预算；
  • --gpu-memory-utilization：允许 vLLM 占用的显存比例（默认 0.9）；
  • --tensor-parallel-size：张量并行卡数；
  • --max-num-seqs：最多同时服务的序列数（并发上限）；
  • --quantization：量化方式（如 awq、gptq、fp8）。

二、可运行示例#

1. 安装与启动服务#

# 用 pip 安装（需要 CUDA 环境）
pip install vllm

# 启动一个 OpenAI 兼容服务，监听 8000 端口
# 显存利用率 0.85，最大序列长度 4096，张量并行 1 卡
python -m vllm.entrypoints.openai.api_server \
    --model meta-llama/Llama-2-7b-chat-hf \
    --max-model-len 4096 \
    --gpu-memory-utilization 0.85 \
    --tensor-parallel-size 1 \
    --port 8000

2. 用 OpenAI SDK 调用#

# -*- coding: utf-8 -*-
# 用 OpenAI SDK 调用本地 vLLM 服务（base_url 指向本地）
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")

resp = client.chat.completions.create(
    model="meta-llama/Llama-2-7b-chat-hf",
    messages=[{"role": "user", "content": "用一句话解释 KV Cache"}],
    max_tokens=128,
    temperature=0.7,
)
print(resp.choices[0].message.content)

3. 离线批处理（不经 HTTP）#

# -*- coding: utf-8 -*-
# vLLM 离线推理：适合批量评测，不经 HTTP 服务
from vllm import LLM, SamplingParams

llm = LLM(model="meta-llama/Llama-2-7b-chat-hf", max_model_len=4096)
prompts = ["什么是 TTFT？", "什么是 continuous batching？"]
sampling = SamplingParams(temperature=0.8, max_tokens=128)

outputs = llm.generate(prompts, sampling)
for p, o in zip(prompts, outputs):
    print(f"Q: {p}\nA: {o.outputs[0].text}\n")

三、练习#

  1. 起服务：在本地（或一台有 GPU 的机器）按示例 1 启动 vLLM，用 curl http://localhost:8000/v1/models 确认服务就绪。
  2. 改并发：启动时改 --max-num-seqs（如 16、64、256），用压测工具（如 vllm bench serve 或自己写并发请求）观察吞吐与延迟的变化，验证第 1 章"吞吐 vs 延迟"的结论。
  3. 调显存：把 --gpu-memory-utilization 从 0.9 改成 0.6，观察是否 OOM 或并发下降，说明该参数如何影响 KV Cache 预算。
  4. 换模型：把模型换成一个 GQA 模型（如 Llama-3-8B），保持其它参数不变，观察同等显存下能服务的请求数是否更多（对照第 2 章的 KV 公式）。
