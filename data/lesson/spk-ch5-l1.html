从级联到端到端：延迟账、误差账与数据算力账#

这一节要解决什么#

前三章分别造好了三个零件：一个把波形变成文本的识别器（第 2 章）、一个把文本变成文本的对话模型（外部课程 llm-foundations）、一个把文本变成波形的合成器（第 3 章）。把它们串起来，就得到一个能听会说的系统——级联系统。这个串法看起来只是"把三个已经能用的东西接起来"，但在过去的系统演进里，它被一整类新架构取代：端到端语音大模型。

这一节要回答的是：为什么？ 而且不接受"端到端更自然"这种答案。我们把"为什么"拆成三笔可以算的账：

  1. 延迟账：级联的延迟是"可加的"，端到端省掉的到底是什么？为什么"端到端一定更快"这句话是错的？
  2. 误差账：级联的正确率是"相乘的"，这个乘法结构在什么条件下不可接受？而端到端换来的"少乘一个因子"值多少钱？
  3. 数据与算力账：端到端要什么数据、什么算力？把"要 100 万小时"翻译成卡·天，再翻译成"上限能不能更低"。

三笔账算完之后，本节的结论不是"应该用端到端"，而是一条判据：

 要不要端到端={现在谁更好谁的下限更低​不构成判据才是判据​ ​

这句话的含义在第五节会用一个可解的交叉点说明：如果端到端的渐近下限真的更低，数据量很快就能兑现；如果它的渐近下限更高，数据再多也追不上。 换句话说，架构选择的真正依据是"极限"，而不是"当前排行榜"。

⚠️ 本节的代码与全部数字都是构造配置：配置的形态（有哪些项、哪一项是固定的、哪一项随长度线性增长）来自系统结构，而具体数值是本节假定的。改一个常数，表里的结论就会变——这正是本节想说的事：架构争论之所以吵不完，往往是因为双方用的常数不同，而不是因为道理不同。

一、级联的延迟结构：可加性就是它的形状#

1.1 把延迟拆成"固定项 + 线性项"#

设用户说完一句话，系统要在 L 个输出字之后把最后一个字说出口。级联的三段各贡献一部分延迟：

C(L)​=端点判决 + 尾块S​​+LLM 逐 tokenL⋅τllm​​​+流式编码L⋅τasr​​​+TTS 首块T1​​​+波形生成L⋅τtts​​​=(S+T1​)+L⋅(τllm​+τasr​+τtts​)​

C(L)​=端点判决 + 尾块S​​+LLM 逐 tokenL⋅τllm​​​+流式编码L⋅τasr​​​+TTS 首块T1​​​+波形生成L⋅τtts​​​=(S+T1​)+L⋅(τllm​+τasr​+τtts​)​

这里 S 是端点判决（endpointing）：系统必须先相信"用户说完了"，才敢把这一句交给 LLM。这一项的物理来源不是算力，而是人的停顿习惯。端到端模型的延迟结构不同——它省掉 S 与 T1​，但要多付两项：

E(L)=右上下文，不可压缩K​​+收尾T0​​​+L⋅每步：1 文本 token + R 语音 token(gτllm​+Rτvoc​)​​

K 是联合模型必须看到的右侧上下文（右上下文），g 是端到端每步解码成本相对级联 LLM 每 token 成本的倍数——它就是"端到端的模型比级联的 LLM 大多少（或慢多少）"。

1.2 端点判决的代价：一个由"人的停顿"决定的地板#

S 里最大的一块是等多久才判定"说完了"。设句间停顿服从参数为 λ 的指数分布（λ 是平均停顿秒数的倒数），系统在静音超过 τ 秒后断句。则

P(误切)=1−e−λτ,C(τ)=误切代价(1−e−λτ)⋅C重说​​​+等待代价（ms）τ⋅1000​​

对 τ 求导置零：

dτdC​=λC重说​e−λτ−1000=0⟹τ∗=λln(λC重说​/1000)​

dτdC​=λC重说​e−λτ−1000=0⟹τ∗=λln(λC重说​/1000)​

取 C重说​=3000 ms（构造值）时 τ∗=ln(3λ)/λ。本节表 2 算出 λ=0.5,1,2,4 时 τ∗=0.811,1.099,0.896,0.621 秒。这个数由人的停顿分布与"重说一句有多贵"共同决定，与模型算力无关——它是端到端在短句上必胜的那部分（约 S=900 ms 量级）。

1.3 TTS 首块：第二个固定项#

TTS 的第一块音频要等声学前端与声码器的流水线填充完毕。第 3 章算过并行声码器的感受野时间；把它落到级联的延迟账上，就是 T1​（首块就绪时间，构造值 150 ms）。它同样不随输出长度变化，所以它在短句上占比高、在长句上被摊薄。

1.4 一个常被忽略的账：端点判决不是唯一的固定项#

级联还有两项固定开销容易被漏掉：（a）每个模块的批处理排队——LLM 解码 25 ms/token 是"含排队"的构造值，单请求会更快、但吞吐会崩；（b）跨模块的数据搬运与序列化——转写文本要真正生成出来才能交给 TTS。第 (b) 项在并发下会变成主要的抖动来源。所以级联的延迟不是一个数，而是一个分布：S 的方差决定了 P99 延迟，而 P99 才是对话体验的实际约束。

二、误差账：级联的乘法结构#

2.1 正确率相乘#

设 ASR 的词错率为 W、每句需要命中的实体槽有 Nent​ 个、下游 LLM 在实体正确时仍有 δ 的残余错误率（常识、推理、格式）。则级联的任务成功率

Pcasc​=实体全对(1−W)Nent​​​⋅(1−δ)

这是乘法结构：每一段的正确率相乘，所以"每段都不错"并不等于"结果不错"。把 W 从 0.05 提到 0.10、Nent​=3 时，P 从 0.8574 掉到 0.7290（相对掉 15.0%）；Nent​=6 时从 0.7351 掉到 0.5314（相对掉 27.7%）。实体越多，WER 的边际代价越大——因为 (1−W)N 对 W 的敏感度随 N 放大：

∂W∂lnP​=−1−WNent​​⟹PΔP​≈−1−WNent​​ΔW

Nent​=6、W=0.05 时，WER 每升 1 个百分点，任务成功率相对降 6.3%。

2.2 端到端的结构优势：少乘一个因子#

端到端把"音频 → 文本 → 答案"变成"音频 → 答案"，于是被乘掉的因子少了一个。在本节的构造假设里（同样的 W 作用在实体上、但不再经过"ASR 文本 → LLM 重读"这一层，残余错误率按半），相对改善是一个常数 2.6%。这个常数说明一件重要的事：

端到端的优势不是"模型更强"，而是结构上少了一层信息瓶颈。它的大小由"那一层瓶颈损失了多少语义"决定，而不是由模型规模决定。

因此"端到端能提升多少"这个问题没有普适答案——它取决于你的任务里"文本接口够不够用"。如果任务的关键信息全在文本里（订票、查询），瓶颈损失接近 0，端到端的结构优势也接近 0；如果关键信息有一部分在文本之外（语气、情绪、重叠说话、非语言声音），瓶颈损失可能是主要的，级联的上限被结构性封死。

2.3 误差链的另一个价值：可归因#

级联还有一个端到端没有的性质——误差可以分摊到可单独替换的部件上：

  • 换 oracle 转写后成功率从 p1​ 升到 p2​ ⇒ ASR 贡献的损失 =p2​−p1​；
  • 换 oracle 文本给 TTS 后成功率不变 ⇒ TTS 不贡献语义损失。

端到端没有这个自由度：它只有一个"错"的输出。这条性质在工程上的价值是可以量化的：可归因意味着"修哪一段"是可决策的，而不可归因意味着只能整体重训。第 3 节的表 10 把这条性质写成了年迭代成本的账（Ce2e​<3Cm​ 才值得放弃可替换性）。

三、数据账：名义小时数不是有效小时数#

3.1 为什么"端到端需要更多数据"这句话不精确#

端到端的监督信号是"音频 + 文本"的配对数据，而级联的三段可以各吃各的：ASR 能吃海量无标注音频（自监督预训练）、LLM 能吃海量纯文本、TTS 能吃"文本 + 少量录音"。所以端到端的约束不是"总小时数"，而是有效小时数

Heff​=i∑​wi​Hi​

其中 wi​ 是每个数据源与目标域的距离的权重。本节表 5 的构造赋值下，名义 501200 小时只有 Heff​=65200 小时，有效占比 13.01%。反过来读这张表：若端到端的数据效率与级联相同，它需要的小时数要乘 1/0.13=7.67 倍才等价。

3.2 标注粒度的第二重成本#

配对数据还有一重成本：端到端要同时监督"听"和"说"两条链，而"说"这一侧需要更细的标注（时长、韵律、说话人）。第 1 章算过标注边界误差如何传播——σ=15 ms 的边界误差会让一半的边界错位一个帧。这些误差在级联里可以在模块边界处"截断"（ASR 只关心词、TTS 只关心音素时长），而在端到端里会直接进梯度。

四、算力账：把小时数换成卡·天#

4.1 训练#

r 是语音 token 率、Nparam​ 是激活参数量。代入 H100 bf16 峰值 9.89×1014 FLOP/s、MFU =0.40：

卡⋅天=9.89×1014×0.40×864006Nparam​Ntoken​​

本节表 6 的结果：1000 万小时、7B 激活参数的全参训练是 2211.83 卡·天，在 64 卡上约 829 天。这条账把"数据量"直接换成"卡·天"，没有任何主观项——它是"端到端要什么算力"的可核对答案。

4.2 推理：把两种模态放到同一把尺子上#

自回归的墙上时间正比于步数。语音 token 率 50/s、文本 token 率约 4/s（4 字/秒），所以同样一分钟的内容：

文本 token 数语音 token 数​=2403000​=12.5

语音表示把序列拉长了 12.5 倍。 这就是第 2 节要解决的核心问题：token 率不降下来，端到端在算力上永远吃亏。

4.3 存储账的两个不同口径#

必须区分字节数与步数：

表示 每小时 压缩比 序列长度（60 s）
原始 PCM（16 kHz/16 bit） 115.2 MB 1:1 960000
离散 token（50/s、11 bit） 247.5 KB 465.5:1 3000
纯文本（4 字/s、UTF-8） 43.2 KB 2666.7:1 240

离散 token 把波形压了 465.5 倍——压缩确实有效；但对纯文本仍大 5.73 倍，而自回归的步数差 12.5 倍。两个比值的差异来自"每 token 多少比特"与"每秒多少 token"是两笔独立的账。第 2 节会在等码率曲线上把这两笔账合并。

五、取舍与边界：判据是"下限"，不是"现状"#

5.1 延迟的交叉点#

把 C(L)=E(L) 解出来：

L∗=gτllm​−τllm​−250RTFenc​−250RTFvoc​S+T1​−K​=25g−35850​

L∗=gτllm​−τllm​−250RTFenc​−250RTFvoc​S+T1​−K​=25g−35850​

（S=900、T1​=150、K=200、τllm​=25 ms、RTFenc​=0.02、RTFvoc​=20。）判据是：

  • L<L∗：端到端更快；
  • L>L∗：级联更快。

表 9 给出 g=1.5,2,3,4,8 时 L∗=340.0,56.7,21.2,13.1,5.2 字。关键观察：g 只要超过阈值——也就是端到端每步成本超过级联每字成本（35 ms）——长回答上级联就会反超。g=2 时每步 62.5 ms，交叉点在 56.7 字（约 14 秒的回答）。

 端到端在延迟上省的是固定开销，代价是每步成本；两者谁大取决于 g ​

这解释了一个常见的工程形态：用小的端到端模型做"快通道"处理短交互，用级联做"慢通道"处理长回答与合规请求。这不是折中主义，而是上式的直接推论。

5.2 可替换性：年迭代成本#

若一年升级 k 次、级联每次只重训一段（成本 Cm​，三段可各自升级）、端到端每次要重训整体（成本 Ce2e​），则

k⋅3Cm​vsk⋅Ce2e​⟹端到端更省⟺Ce2e​<3Cm​

表 10 的构造值（Cm​=200、Ce2e​=2000 卡·天）下，级联年成本 3600 卡·天、端到端 12000 卡·天。但这条账有前提：级联的三段必须能各自升级而不互相拖累。一旦目标包含副语言信息，"文本"这个接口就装不下它，可替换性优势立刻归零。

5.3 最重要的判据：下限，而不是现状#

设错误率随数据量的幂律

E(H)=E∞​+aH−α,α=0.3

级联 E∞(c)​=0.02,ac​=0.03；端到端 E∞(e)​=0.04,ae​=0.06（即在同样的数据量下更差、但假设下限更低）。两条曲线交叉于

H∗=(E∞(e)​−E∞(c)​ae​−ac​​)1/α=(0.020.03​)1/0.3=3.86 小时

H∗=(E∞(e)​−E∞(c)​ae​−ac​​)1/α=(0.020.03​)1/0.3=3.86 小时

表 11 同时给出反向情形：若 E∞(e)​=0.05>E∞(c)​=0.02，则无论 H 多大，差值 Ee​−Ec​→0.03>0，永不交叉。

 两种架构之争的本质是"极限之争"，而不是"当前分数之争" ​

这条判据的工程含义很直接：因为 E∞​ 无法先验知道，应该同时保留两条路——用级联保底，用端到端试探下限，并且定期用同一批测试集重测两者的差距随数据量的变化趋势。如果差距在收窄，继续投端到端；如果差距不随数据量变化，说明端到端的下限并不更低，继续投就是浪费。

    asr_stream = L / CHARS_PER_SEC * 1000.0 * RTF_ENC   # 流式编码与整句同时推进
    llm = L * T_LLM_MS                     # 逐 token 自回归
    tts_first = T_TTS_FIRST                # 首块音频就绪（固定项）
    tts_rest = max(0.0, L / CHARS_PER_SEC * 1000.0 - 100.0) * (RTF_VOC / 1000.0)
    # 级联的「逐段交接」：每 chunk_chars 个字要做一次 TTS 请求/合成边界
    n_chunks = math.ceil(L / chunk_chars)
    tts_handoff = 0.0
    total = asr_tail + asr_stream + llm + tts_first + tts_rest + tts_handoff
    return dict(asr_tail=asr_tail, asr_stream=asr_stream, llm=llm,
                tts_first=tts_first, tts_rest=tts_rest,
                handoff=tts_handoff, total=total, n_chunks=n_chunks)


def e2e_latency(L, g=1.0):
    """端到端：一次前向产生「文本 token + 语音 token」的交错流。
    g: 端到端每步的解码成本相对级联 LLM 每 token 成本的倍数（模型的相对大小）。
    末尾只需把已产出的语音 token 转波形（按 RTF 摊薄），最后一块是固定右上下文。
    """
    per_step = g * T_LLM_MS + SPEECH_PER_TEXT * T_VOC_TOKEN
    t_ar = L * per_step
    t_voc_tail = 100.0                     # 最后 100 ms 波形的收尾
    total = L * per_step + K_E2E + t_voc_tail
    return dict(steps=L, per_step=per_step, t_ar=t_ar,
                lookahead=K_E2E, t_voc=t_voc_tail, total=total)

def cascade_answer(W, N_ent, residual=0.05):
    """级联：实体全对概率 (1-W)^N_ent，再乘下游 LLM 的残余错误。"""
    p_ent = (1.0 - W) ** N_ent
    return p_ent, p_ent * (1.0 - residual)


def e2e_answer(W, N_ent, residual=0.025):
    """端到端：同样的 W 直接作用在实体上，少了「ASR 文本 -> LLM 重读」一层，
    残余错误率按半（构造假设，用来演示结构差异而非断言真实数值）。"""
    return (1.0 - W) ** N_ent * (1.0 - residual)

小结#

  • 级联的延迟是可加结构：C(L)=(S+T1​)+L(τllm​+τasr​+τtts​)。S 是端点判决（构造值 900 ms）、T1​ 是 TTS 首块（150 ms），两者不随输出长度变化——这就是端到端在短句上必胜的部分。
  • 端点判决的地板由人决定：P(误切)=1−e−λτ，最优 τ∗=ln(λC重说​/1000)/λ；λ=0.5/1/2/4 时 τ∗=0.811/1.099/0.896/0.621 秒。算力再强也压不下去。
  • 端到端的延迟结构：E(L)=K+T0​+L(gτllm​+Rτvoc​)。交叉字数 L∗=(S+T1​−K)/(25g−35)：g=2 时 L∗=56.7 字，g=3 时 21.2 字。L<L∗ 端到端更快，反之级联更快——"端到端一定更快"是错的。
  • 级联的误差是乘法：Pcasc​=(1−W)Nent​(1−δ)。W 从 0.05 到 0.10、Nent​=3 时 P 从 0.8574 到 0.7290（−15.0%）；Nent​=6 时从 0.7351 到 0.5314（−27.7%）。敏感度 ∂lnP/∂W=−Nent​/(1−W)。
  • 端到端的结构优势是"少乘一个因子"，因此它的大小取决于"文本接口的瓶颈损失"，不取决于模型规模。关键信息全在文本里的任务（订票、查询）优势接近 0；含副语言信息的任务，级联的上限被结构性封死。
  • 可归因是级联独有：换 oracle 转写可测出 ASR 的损失份额（p2​−p1​）。这条性质对应年迭代成本 k⋅3Cm​ vs k⋅Ce2e​，判据 Ce2e​<3Cm​=600 卡·天。
  • 数据账：Heff​=∑i​wi​Hi​，本表名义 501200 小时只有 65200 有效（13.01%）；等价换算需要 7.67 倍。端到端的约束是配对数据，不是总小时数。
  • 算力账：C≈6Nparam​Ntoken​，Ntoken​=Thour​×3600×r。100 万小时 + 7B 激活参数 =221.18 卡·天（MFU 0.40、64 卡约 82.9 天）；1000 万小时 =2211.83 卡·天（约 829.4 天）。
  • 两种压缩口径不能混用：离散 token 相对波形压 465.5 倍（字节数），但对文本仍大 5.73 倍；自回归的步数差 12.5 倍。
  • 最重要的判据：E(H)=E∞​+aH−α。若端到端的 E∞​ 更低，交叉点 H∗=3.86 小时（本构造值）量级就能兑现；若 E∞​ 更高（情形 B：0.05 vs 0.02），差值趋于 0.03>0，永不交叉。所以"现在谁更好"不是判据，"谁的下限更低"才是——工程上因此应该"级联保底 + 端到端试探下限"。
