Softmax 与 Attention：FlashAttention 的实现层#

Attention 的计算量比同尺寸 GEMM 小，显存占用却是它的平方级：N×N 的注意力矩阵必须被写出来、再读回去做 softmax。FlashAttention 的核心不是"更快的数学"，而是把这块 N2 中间量彻底取消——用逐块流式更新的在线 softmax，让每个 query 行只保留三个running 状态。这一课把"朴素 softmax 会炸 → max 平移 → 在线 rescale → 分块 Attention"这条链推完，并用纯 numpy 把算法与 IO 账都验证一遍。

一、概念讲解#

1. 朴素 softmax 会炸：exp 的溢出#

softmax(x)i​=∑j​exj​exi​​

exp 在 float32 下的溢出阈值约 88.7（ln(2128)≈88.7，expf 到 FLT_MAX 附近即 Inf）。Attention 的 logits 是 QK⊤/d​，只要有一列内积偏大，N 个 logit 里就会出现超过阈值的项，exi​ 直接 Inf，整行结果变成 Inf/Inf = NaN。这不是精度问题，是数值范围问题，随机数据缩放系数一大就必然触发（下一节实测 scale=200 时朴素版全行失效）。

2. 稳定版：减去行最大值#

softmax(x)i​=∑j​exj​−mexi​−m​,m=jmax​xj​

减去同一个常数不改变结果（分子分母同乘 e−m），却保证最大的指数是 e0=1，其余项都 ≤1，彻底避开上溢。代价是必须先扫一遍这一行拿到 m——这正是"要么两遍读写、要么在线更新"的分叉点。

3. 在线 softmax：不保存整行，只维护 (m,l)#

把行切成块，逐块到达。维护 running max m 与 running sum l；新块带来更大的 m′ 时，历史累加值整体乘一个修正因子：

α=em−m′,l←l⋅α+j∈新块∑​exj​−m′,m←m′

关键性质：结果与"先看完整行再算"完全一致（只有浮点舍入差异），但内存从 O(N) 降到 O(1)。这也是 FlashAttention 能在片上完成 softmax 的前提。

4. FlashAttention：把 (m,l,O) 一起在线更新#

设 S=QK⊤/d​、P=softmax(S)。把 K/V 按列切成块（Bc​），对每个 query 块（Br​）：

  1. 算 Sij​=Qi​Kj⊤​/d​（一个 Br​×Bc​ 的子块）；
  2. 用在线 softmax 更新 mi​,li​ 与缩放因子 αi​；
  3. 把输出也一起 rescale：Oi​←Oi​⋅αi​+P~ij​Vj​，其中 P~ij​=eSij​−mi′​ 是未归一化的。

循环结束时 Oi​/li​ 就是精确结果。三个状态（m,l,O）都是每行 O(1) 或 O(d) 量级，N2 的 P 从未被写进 HBM。原始论文把它写成 IO-aware 的分块算法：标准 attention 的 HBM 访问是 O(N2) 量级，FlashAttention 是 O(N2d2M−1) 量级（M 为片上缓存大小），后者在长序列下小一到两个数量级。

一个容易被忽略的工程点：分块只是省了中间量，块内还是要搬 K/V。N 个 query 行都会读一遍完整的 K/V，所以 K/V 的 HBM 读取量是 N⋅2Nd 而不是 2Nd——这层重读在高带宽 GPU 上通常比 N2 中间量便宜得多，但序列很长、d 很大时它也会变成新的上限，这也是 FlashAttention 系列把 KV 分块与 query 并行（而非只按 KV 串行）的原因。

5. 掩码与重算：两个实现层的坑#

  • causal 掩码：j>i 的位置要屏蔽。用 −∞ 会让"整块全被屏蔽"的行出现 −∞−(−∞)=NaN，因此工程实现用足够大的有限负数（如 -1e30）：e−1e30−m→0，既屏蔽又不产生 NaN。
  • 重算（recomputation）：反向传播需要 P，但前向没保存它。FlashAttention 的选择是用保存下来的 (m,l) 从 Q/K/V 重新算出 P，用一次额外的计算换掉 O(N2) 的显存读写——这正是"用算力换带宽"的教科书案例。
  • 块大小不是越大越好：Bc​ 变大要更多 shared memory 放 K/V 块；Br​ 变大要更多寄存器放 O 与累加器。真实实现里这两个值由片上容量与寄存器预算反推，而不是拍脑袋。

6. 常见坑#

  • 拿朴素 softmax 做基线：它在大 logits 下直接失效，会让"优化前后数值不一致"的锅甩给新算法。
  • 在线更新漏乘 α：O 与 l 必须同时乘以同一个 α，只更新其中一个结果会偏。
  • 把 −∞ 塞进分块路径：见上，NaN 会污染整行，且只在特定行形（整块被屏蔽）出现，随机用例很难覆盖。
  • 忘记 1/d​ 的放置：缩放放在 S 或放在 Q 上都可以，但两处都放会让结果差 1/d。
  • 只看 FLOPs 评估收益：FlashAttention 的算力用量并不比标准实现少（甚至因重算更多），收益全在 HBM 流量。

二、可运行代码示例#

需要 numpy（本机 python3.10 + numpy 1.26.2 验证）。五段分别：朴素 softmax 的失效点、在线 softmax 与参考一致、逐块 FlashAttention 对拍、掩码的 NaN 陷阱、IO 账。

# ===== 本课示例：softmax 的三代写法 + 逐块 FlashAttention + IO 账 =====
import numpy as np

# ---------- 1. 朴素 softmax 什么时候会炸 ----------
rng = np.random.default_rng(0)
with np.errstate(over='ignore', invalid='ignore'):
    for scale in (1.0, 20.0, 200.0):
        x = (rng.standard_normal(4096) * scale).astype(np.float32)
        e = np.exp(x)
        naive = e / e.sum()
        m = x.max()
        st = np.exp(x - m); st = st / st.sum()
        print(f"scale={scale:>6}: max(x)={x.max():>8.2f} 朴素结果出现 NaN/Inf={bool(~np.isfinite(naive).all())}"
              f"  稳定版和={st.sum():.8f}  两者最大差={np.nanmax(np.abs(np.nan_to_num(naive) - st)):.2e}")

# ---------- 2. 在线 softmax：分块流式更新 (m, l)，不保存整行 exp ----------
def softmax_reference(x):
    m = x.max(); e = np.exp(x - m); return e / e.sum()

def online_softmax(x, block=256):
    """只维护 running max m 与 running sum l，每来一块就用 alpha 把历史值整体缩放。"""
    m, l, parts = -np.inf, 0.0, []
    for s in range(0, x.size, block):
        xs = x[s:s + block]
        m_new = max(m, xs.max())
        alpha = np.exp(m - m_new)                    # 历史部分的缩放因子
        parts = [p * alpha for p in parts]
        parts.append(np.exp(xs - m_new))
        l = l * alpha + parts[-1].sum()
        m = m_new
    return np.concatenate(parts) / l

x = (rng.standard_normal(4096) * 8).astype(np.float32)
ref = softmax_reference(x)
got = online_softmax(x, block=256)
print(f"\n在线 softmax（block=256）：与参考最大差 = {np.abs(got - ref).max():.2e}")

# ---------- 3. 逐块 FlashAttention：把 (m, l, O) 一起在线更新 ----------
def attention_reference(Q, K, V, causal=True):
    d = Q.shape[1]; S = Q @ K.T / np.sqrt(d)
    if causal:
        S = np.where(np.triu(np.ones(S.shape, bool), 1), -1e30, S)
    P = np.exp(S - S.max(axis=1, keepdims=True)); P = P / P.sum(axis=1, keepdims=True)
    return P @ V

def flash_attention(Q, K, V, block=64, causal=True):
    """按 KV 分块：每块更新 running max m、running sum l、未归一化输出 O。"""
    n, d = Q.shape
    O = np.zeros((n, d)); m = np.full(n, -np.inf); l = np.zeros(n)
    for s in range(0, K.shape[0], block):
        Kb, Vb = K[s:s + block], V[s:s + block]
        S = Q @ Kb.T / np.sqrt(d)
        if causal:
            rows = np.arange(n)[:, None]
            cols = np.arange(s, s + Kb.shape[0])[None, :]
            S = np.where(cols > rows, -1e30, S)      # 用大负数而不是 -inf
        m_new = np.maximum(m, S.max(axis=1))
        p = np.exp(S - m_new[:, None])
        alpha = np.exp(m - m_new)                    # 历史 O 与 l 的缩放因子
        l = l * alpha + p.sum(axis=1)
        O = O * alpha[:, None] + p @ Vb
        m = m_new
    return O / l[:, None]

rng = np.random.default_rng(1)
n, d = 128, 16
Q = rng.standard_normal((n, d)).astype(np.float32)
K = rng.standard_normal((n, d)).astype(np.float32)
V = rng.standard_normal((n, d)).astype(np.float32)
ref_o = attention_reference(Q, K, V, causal=True)
print("\n逐块 FlashAttention 与「一次算完」的参考实现对比：")
for block in (16, 64, 128):
    got_o = flash_attention(Q, K, V, block=block, causal=True)
    print(f"  KV block={block:>3}：最大差={np.abs(got_o - ref_o).max():.2e}"
          f"  相对误差={np.abs(got_o - ref_o).max() / np.abs(ref_o).max():.2e}")

# ---------- 4. 掩码的数值陷阱：整块被 mask 掉时 exp(-inf - -inf) = NaN ----------
print("\n整块被 mask 掉（causal 下第一块只有第 0 行有效）时的两种写法：")
masked = np.array([[-1e30, -1e30], [0.5, -1e30]])
print(f"  用 -1e30 作掩码：逐行 max = {masked.max(axis=1)}，exp(0)=1，可正常归一化")
with np.errstate(invalid='ignore'):
    p_inf = np.exp(masked - np.full(2, -np.inf)[:, None])
print(f"  用 -inf   作掩码：p 里 NaN/Inf 个数 = {int((~np.isfinite(p_inf)).sum())}"
      f" → 整行算废（-inf 与 -inf 相减）")

# ---------- 5. IO 账：标准 attention 与 FlashAttention 的 HBM 流量量级 ----------
def io_bytes(N, d, elem=2):
    """标准：S 写一遍 + P 读一遍（N²×4 字节各一次）；分块：Q/K/V 各读一遍 + O 写一遍。"""
    return N * N * 4 * 2, (N * d * 3 + N * d) * elem
print("\nHBM 流量量级（近似，只算一次读写，单位 MB）：")
print(f"{'N':>7} {'d':>4} {'标准(写S+读P)':>14} {'FlashAttention':>15} {'倍数':>7}")
for N_, d_ in ((1024, 64), (4096, 64), (8192, 128)):
    s, f = io_bytes(N_, d_)
    print(f"{N_:>7} {d_:>4} {s/2**20:>14.1f} {f/2**20:>15.1f} {s/f:>6.1f}x")
print("标准版本还要让 N×N 的中间量驻留或落 HBM；分块版本把它换成 block×d 的片上缓冲。")

标准版本还要让 N×N 的中间量驻留或落 HBM；分块版本把它换成 block×d 的片上缓冲。

三处值得盯住的对照：scale=200 时朴素 softmax 整行失效而稳定版和仍是 1.00000000；逐块结果与"一次算完"的相对误差 1.66×10−7 且三个 block 尺寸完全一致——说明在线 rescale 是代数恒等变换，block 只影响访存效率、不影响结果；N 越大 HBM 流量倍数越大（1024 时 16 倍、8192 时 64 倍），这正是 FlashAttention 在长序列上收益更明显的原因。

三、练习#

  1. 实现：把 flash_attention 的 block 改成 8 与 256，验证结果不变；再给 -1e30 换成 -1e20、-1e10，观察相对误差何时开始劣化（提示：e−1e10 与 float32 的下溢边界）。
  2. 解释：为什么在线 softmax 里 l 与 O 必须乘同一个 α？如果只把 O 乘 α 而不动 l，最终结果会偏大还是偏小？
  3. 对比/验证：把 causal 掩码去掉（causal=False），两个实现的误差量级是否变化？再解释为什么 causal 情形下 FlashAttention 的实际计算量约为非 causal 的一半。
  4. 思考：反向传播需要 P。如果选择把 P 存下来（N2 显存）而不是重算，前向会更快还是更慢？在什么序列长度下这个选择会翻转？
