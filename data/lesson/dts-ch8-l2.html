成本模型：从"能跑"到"单位成本最优"#

上一课能回答"哪种组合装得下、效率多少"，但预算表要回答的是另一件事：这笔钱值不值。最常见的误解是"卡越多越快越省钱"——算完你会看到，加卡买的是墙钟时间，不是单价；真正把单位成本拉开一倍的，是 MFU（Model FLOPs Utilization，模型浮点算力利用率）和通信重叠。这一课把成本写成可求导、可扫参、可打印的式子。

一、概念讲解#

1. 成本只有三个乘数，但分母是有效吞吐#

一次训练的账单是 Cost=N×Ssteps​×Tstep​×p，其中 N 是卡数、Ssteps​ 是优化器步数、Tstep​ 是单步墙钟时间、p 是每 GPU·小时单价。把 Ssteps​=Ttokens​/Bstep​（Bstep​ 是每步处理的 token 数）代进去，就得到单位成本的解析式：

109 tokenCost​=MFUeff​⋅Peak6P​×p,MFUeff​=Tstep​Tcmp​​⋅MFU

6P 是每个 token 的前向+反向 FLOPs（2P 前向、4P 反向），所以单位成本与卡数无关，只由"有效 MFU × 峰值 × 单价"决定。这也解释了为什么下面扫卡数时单价几乎不动。

2. 加卡买的是时间，不是钱#

示例模型 6.57B、训练 300B token、示例价 $2/GPU·h：4 卡 $50.7/1B token、256 卡 51.2/1Btoken（贵1%），但墙钟从79.2天缩到1.2天。所以"单位成本最优"的正确提法不是"最少钱"，而是∗∗在工期与显存两条约束下的最少钱∗∗：不设工期时最小可行卡数最便宜（示例是4卡，但要79天）；加上"14天内完成"就落到32卡（10.0天、51.1/1B token）。工期是决策变量，成本是它的函数。

3. 真正拉开单价的三个旋钮#

同一 64 卡方案下：MFU 从 0.30 提到 0.60，单价 $75.8→$38.9/1B（差近一倍）；重叠率从 0 提到 0.85，$62.4→$51.2/1B；而分片档位从 ZeRO-1 换到 ZeRO-3 只从 $50.5 涨到 $51.2（多出的是那次参数 AllGather）。顺序很重要：先榨 MFU，再榨重叠，最后才纠结分片档位。

4. 分片与切模型：显存能装下时别乱切#

固定 64 卡、同一模型，纯粹 DP 要 112.0 GiB/卡（装不下），ZeRO-1 只要 39.6 GiB 且单价最低；TP4/PP2 虽然显存只用 3.3 GiB，却因为每层集合通信与流水线气泡把单价推到 $90.5/1B。结论：TP/PP 是为"装不下"和"缩墙钟"付的钱，能靠 ZeRO 装下就别切模型；只有在长序列（激活按 a⋅s2 涨）或需要跨节点缩短关键路径时才值得动 TP/PP。

5. 四个容易漏掉的成本项#

  • 检查点（checkpoint）写读：state 体积按 14 字节/参数（bf16 权重 2 + fp32 优化器状态与主副本 12，与第 7 章的检查点体积口径一致；示例模型 ≈92 GB），写一次的固定成本 Cwrite​ 除以间隔就是摊销；间隔太长则故障后要重算。最优间隔有解析解 I∗=2Cwrite​⋅MTBF​：示例 MTBF 48 h、写 4.6 s，得 I∗≈1261 s ≈ 21 min，此时合计开销最低（0.84% 量级）。
  • 故障重算：期望损失随间隔线性上升，所以写太勤反而亏；上表 300 s 间隔合计开销 1.69% 高于 900 s 的 0.84%。
  • 抢占式（spot）实例：盈亏平衡价 =1/(1+每次损失/平均无抢占时长)。示例每 6 h 被抢一次、每次损失 0.55 h，spot 价必须低于 on-demand 的 91.6% 才划算；若损失翻倍到 1.10 h，门槛收紧到 84.5%——便宜的 spot 也要算"重跑账"。
  • 数据与存储 I/O、以及"能跑但不是最优"：前者常被算进 MFU 的隐性损失里，后者才是最大的浪费——用 TP8 换来的 3% 墙钟，付出 33% 单价。

6. 常见坑#

  • 用"单卡峰值 × 卡数"当吞吐估预算：忽略扩展效率，示例低估 4%～40%（取决于是否强扩展）。
  • 只比 $/GPU·h 不比有效 MFU：两家云单价差 20%，MFU 差 40%，便宜的反而贵。
  • 忘记检查点与故障开销：长跑里它们是 1%～5% 的稳定损耗。
  • 把 spot 当纯折扣：不估"每次损失多少小时"就无法判断是否真便宜。
  • 用一次性报价拍板：单价、MFU、工期三者必须一起写进报告卡的同一张表。

二、可运行代码示例#

一段纯 Python：把上一课的三本账接到钱上，扫卡数、比组合、做敏感性分析，再算检查点间隔与抢占平衡点。价格、MTBF、写带宽都标了"示例"，请换成你自己云上的数字。

# ===== 成本账本：从"能跑"到"单位成本最优" =====
CFG = dict(layers=32, hidden=4096, heads=32, vocab=32000, seq=4096)
P = CFG["layers"] * 12 * CFG["hidden"]**2 + CFG["vocab"] * CFG["hidden"]
PEAK, MFU0, PRICE = 990e12, 0.45, 2.0     # 示例：峰值 990 TFLOP/s、MFU 0.45、$2/GPU·h
ALPHA_US, BW, OVERLAP = 5.0, 200.0, 0.85  # 示例：α=5us、等效带宽 200 GB/s、重叠 85%
SEQ, MICRO, ACCUM = 4096, 1, 4
TOKENS_TOTAL, DEADLINE_DAYS = 300e9, 14.0

def step_model(N, dp, tp, pp, stage, tokens_step, micro=MICRO, overlap=OVERLAP, mfu=MFU0):
    """三本账合成一个单步时间：计算 + 气泡 + 未重叠的通信。"""
    t_cmp = 6 * P * tokens_step / (N * PEAK * mfu) * 1e3
    S = (2 if stage < 3 else 3) * P * 2                       # 梯度通信总字节（fp16）
    per_rank = 2 * (dp - 1) / dp * S if dp > 1 else 0.0
    t_comm = 2 * (dp - 1) * ALPHA_US / 1e3 if dp > 1 else 0.0
    t_comm += per_rank / (BW * 1e9) * 1e3
    if tp > 1:                                                # TP：每层两次 AllReduce
        msg = (tokens_step // dp) * CFG["hidden"] * 2
        tp_bytes = CFG["layers"] * 2 * (2 * (tp - 1) / tp) * msg
        per_rank += tp_bytes
        t_comm += tp_bytes / (BW * 1e9) * 1e3 + CFG["layers"] * 2 * 2 * (tp - 1) * ALPHA_US / 1e3
    bubble = (pp - 1) / (micro + pp - 1)
    exposed = t_comm * (1 - overlap)
    t_step = t_cmp * (1 + bubble) + exposed
    return t_cmp, exposed, bubble, t_step, per_rank / 1e9

def budget(N, dp, tp, pp, stage, tokens_step, mfu=MFU0, overlap=OVERLAP):
    t_cmp, exposed, bubble, t_step, comm_gb = step_model(N, dp, tp, pp, stage, tokens_step,
                                                         overlap=overlap, mfu=mfu)
    steps = TOKENS_TOTAL / tokens_step
    gpu_h = N * steps * t_step / 1000 / 3600
    return dict(t_step=t_step, eff=t_cmp / t_step * 100, days=steps * t_step / 86400e3,
                gpu_h=gpu_h, cost=gpu_h * PRICE, usd_1b=gpu_h * PRICE / (TOKENS_TOTAL / 1e9),
                comm_gb=comm_gb)

def mem_gib(dp, tp, pp, stage, micro=MICRO):
    s, h, a = CFG["seq"], CFG["hidden"], CFG["heads"]
    terms = 3*s*micro*h*2 + s*micro*h*2 + 2*s*micro*4*h*2 + 2*s*micro*h*2
    act = terms / tp * CFG["layers"] / pp
    Psh = P / tp / pp
    model = {0: Psh*16, 1: Psh*(4 + 12/dp), 2: Psh*(2 + 14/dp), 3: Psh*(16/dp)}[stage]
    return (model + act) / 2**30

print(f"模型 {P/1e9:.2f} B；训练 {TOKENS_TOTAL/1e9:.0f}B token；示例价 ${PRICE}/GPU·h；工期上限 {DEADLINE_DAYS:.0f} 天")
print("\n(a) 扫卡数（Z3、TP=PP=1，全局 batch 随卡数放大）：成本几乎不变，墙钟线性变短")
print(f"  {'总卡':>4} {'显存/卡':>8} {'单步 ms':>8} {'效率':>6} {'墙钟天':>7} {'GPU·h':>9} {'$':>9} {'$/1B':>7}")
for N in (4, 8, 16, 32, 64, 128, 256):
    st = SEQ * MICRO * ACCUM * N
    b, m = budget(N, N, 1, 1, 3, st), mem_gib(N, 1, 1, 3)
    print(f"  {N:>4} {m:>8.1f} {b['t_step']:>8.1f} {b['eff']:>5.1f}% {b['days']:>7.1f}"
          f" {b['gpu_h']:>9.0f} {b['cost']:>9.0f} {b['usd_1b']:>7.1f}")
fits = [(N, budget(N, N, 1, 1, 3, SEQ*MICRO*ACCUM*N)) for N in (4, 8, 16, 32, 64, 128, 256)
        if mem_gib(N, 1, 1, 3) <= 80]
feasible = [x for x in fits if x[1]["days"] <= DEADLINE_DAYS]
N_min = min(feasible, key=lambda x: x[1]["usd_1b"])
ideal_1b = 6 * P * 1e9 / (PEAK * MFU0) / 3600 * PRICE
print(f"  不设工期约束：显存装得下的最小卡数 N={fits[0][0]} 最便宜（${fits[0][1]['usd_1b']:.1f}/1B，但要 {fits[0][1]['days']:.0f} 天）")
print(f"  加 {DEADLINE_DAYS:.0f} 天工期约束后：N={N_min[0]}（{N_min[1]['days']:.1f} 天、"
      f"${N_min[1]['usd_1b']:.1f}/1B）")
print(f"  若按「效率 100%」粗估：${ideal_1b:.1f}/1B —— 实际比它高 "
      f"{(N_min[1]['usd_1b']/ideal_1b - 1)*100:.0f}%，这就是账本存在的意义")

print("\n(b) 固定 64 卡比并行组合：并行度不是越大越好，分片代价要算进单价")
print(f"  {'方案':<14} {'显存/卡':>8} {'效率':>6} {'单步 ms':>8} {'每卡通信 GB':>11} {'$/1B':>7} {'可行':>5}")
for tag, tp, pp, dp, stage in [("Z1 TP1 PP1", 1, 1, 64, 1), ("Z2 TP1 PP1", 1, 1, 64, 2),
                               ("Z3 TP1 PP1", 1, 1, 64, 3), ("Z3 TP4 PP2", 4, 2, 8, 3),
                               ("Z3 TP8 PP1", 8, 1, 8, 3), ("DP  TP1 PP1", 1, 1, 64, 0)]:
    N, st = tp * pp * dp, SEQ * MICRO * ACCUM * dp
    b, m = budget(N, dp, tp, pp, stage, st), mem_gib(dp, tp, pp, stage)
    print(f"  {tag:<14} {m:>8.1f} {b['eff']:>5.1f}% {b['t_step']:>8.1f} {b['comm_gb']:>11.2f}"
          f" {b['usd_1b']:>7.1f} {'✓' if m <= 80 else '✗':>5}")

print("\n(c) 敏感性：同一方案（64 卡 Z3）下，谁在真正决定单价")
N, st = 64, SEQ * MICRO * ACCUM * 64
for mfu in (0.30, 0.45, 0.60):
    b = budget(N, N, 1, 1, 3, st, mfu=mfu)
    print(f"  MFU {mfu:.2f} → 单步 {b['t_step']:>7.1f} ms、{b['usd_1b']:>5.1f} $/1B")
for ov in (0.0, 0.5, 0.85):
    b = budget(N, N, 1, 1, 3, st, overlap=ov)
    print(f"  重叠 {ov:.2f} → 单步 {b['t_step']:>7.1f} ms、{b['usd_1b']:>5.1f} $/1B")

print("\n(d) 检查点间隔：写开销与故障重算的权衡（示例：state ≈92 GB（14 B/参数）、聚合写 20 GB/s、MTBF 48 h）")
import math
STATE, WRITE_BW, MTBF_H, RESTART_S = 14 * P, 20e9, 48.0, 120.0
C_write = STATE / WRITE_BW
print(f"  一次写检查点 {C_write:.1f} s")
print(f"  {'间隔':>7} {'写开销':>8} {'故障损失':>9} {'合计':>8}")
for itv in (300, 900, 1800, 3600, 7200, 14400):
    o = C_write / itv + (itv / 2 + RESTART_S) / (MTBF_H * 3600)
    print(f"  {itv:>6}s {C_write/itv:>7.2%} {(itv/2+RESTART_S)/(MTBF_H*3600):>9.2%} {o:>8.2%}")
itv_opt = math.sqrt(2 * C_write * MTBF_H * 3600)
print(f"  解析最优 I* = sqrt(2*C_write*MTBF) = {itv_opt:.0f} s ≈ {itv_opt/60:.0f} min")

print("\n(e) 抢占式实例的盈亏平衡：spot 价必须低于 on-demand 的 1/(1+每次损失/平均无抢占时长)")
for mtbf_p, lost_h in ((6.0, 0.55), (12.0, 0.55), (6.0, 1.10)):
    print(f"  平均 {mtbf_p:>4.1f} h 被抢一次、每次损失 {lost_h:>4.2f} h → 临界价 {1/(1+lost_h/mtbf_p):.1%}")

三、练习#

  1. 实现：把示例价从 $2 改成你自己云上的价格（含网络与存储摊销的粗口径），重跑 (a)(b)，指出"14 天约束下最优卡数"是否变化，并说明为什么。
  2. 解释：用 Cost/109token=6P/(MFUeff​⋅Peak)×p 说明：为什么 (a) 里 4 卡与 256 卡的单价只差 1%，而 (c) 里 MFU 从 0.30 到 0.60 能让单价腰斩？两者的"分母"有什么本质不同？
  3. 对比/验证：把 (d) 的 WRITE_BW 从 20 GB/s 改成 5 GB/s（例如共享存储拥塞），重算最优间隔 I∗ 与最低开销，并解释它与 (e) 的 spot 平衡点会怎样相互影响。
  4. 思考：一次 30 天的训练，若 spot 价是 on-demand 的 60%、平均每 8 h 被抢一次，你会怎么选？把"每次损失小时数"拆成"自上次检查点的工作量 + 重启加载时间"两项，说明检查点间隔如何同时决定这个平衡点。
