并行算法基础：work–depth、reduction / scan#

8 张卡把同一份梯度加起来，理论上该比 1 张卡快 8 倍，但现实里常见的是 5 倍上下。想判断"少掉的那部分该怪谁"，不能靠猜，得先把并行程序拆成两笔性质完全不同的账：总共要做多少活（work）与最短必须串多久（depth）。本课用归约（reduction）与前缀和（scan）这两个最小例子把这两笔账建起来——后面所有关于通信量、扩展效率、"为什么不能更快"的说法，最后都会落回这两个量。

一、概念讲解#

1. work 与 depth 是两笔独立的账#

给出两个定义，配两个记号：

量 记号 定义 极端情形
总工作量 W 算法要执行的操作总数，与有多少处理器无关 单处理器时间 T1​=W
关键路径长度 D 依赖关系图上最长链的操作数（也叫 depth / span） 无限处理器时的时间 T∞​=D

W 回答"总共多少活"，D 回答"这活最早什么时候能完"。两者的比值 W/D 就是平均可用并行度。对 n=220 的求和：串行累加 W=D=n−1=1048575；树形成对归约同样 W=1048575，但 D=⌈log2​n⌉=20——同一个 work，depth 差了五万倍。这就是并行算法设计的全部空间：W 往往改不动，能改的是 D。

2. Brent 定理：加卡加到多少就白加#

并行时间有两条硬边界：

max(pW​,D)≤Tp​≤pW​+D

右半边是 Brent 定理（存在这样的贪心调度），左半边是显然的：p 个处理器做 W 个操作至少要 W/p，而依赖链至少要 D。工程含义比定理本身更重要——当 p>W/D 时，W/p 已经小于 D，再加处理器只会把时间压在 D 上不动。对上述 220 求和，饱和点是 p∗=W/D≈5.24×104：在这之前时间随 p 线性下降（p=1024 时下界 1024 步），过了 65536 就恒为 20 步。判断"该不该加卡"的第一步，就是算出 W/D。

3. 归约：W 有下界，D 可以压到 logn#

归约（reduction）把 n 个数合成一个数。两种做法的账：

做法 W D 说明
串行累加 n−1 n−1 一个累加器，完全串行
树形成对归约 n−1 ⌈log2​n⌉ 每层相邻部分和两两相加
warp shuffle + 块内树 + 跨块原子（GPU 常见） n−1 logn 量级 换的是"每步的代价"，不是 work

W≥n−1 不是经验之谈，而是计数论证：每个元素至少要被读一次，而一次加法最多把两份部分和合并成一份，所以要把 n 份并成 1 份至少需要 n−1 次加法。这套"每次操作最多合并两份"的计数法，正是第 3 课推导通信轮数下界时用的同一种工具。

4. 扫描：work-efficient 与 depth-efficient 的取舍#

扫描（scan，前缀和）给出 yi​=∑j≤i​xj​，输出是 n 个数而不是 1 个，因此它比归约贵，但仍是并行的经典样板：

算法 W D 直觉
Hillis–Steele（含前缀和） n⌈log2​n⌉−(n−1) ⌈log2​n⌉ 每层 stride 翻倍，全部元素同时更新；depth 最优但 work 多了个 logn
Blelloch（up-sweep + down-sweep，不含前缀和） 2n−2 2⌈log2​n⌉ 先建归约树再往下推，work 最优、depth 多一倍

n=65536 时两者的 work 分别是 983041 与 131070（相差 7.5 倍），depth 分别是 16 与 32。"哪个更好"没有统一答案：算力紧张选 Blelloch，延迟紧张选 Hillis–Steele。这一对取舍在训练系统里有直接对应物——优化器状态分片的偏移计算、序列并行里的位置索引、检查点切分，都是扫描；而"梯度求和"是归约。

5. 常见坑#

  • 把 work 当 depth 用：以为"总操作数除以 p"就是时间，于是给一个 D 很大的算法堆处理器。
  • 拿 work-inefficient 算法做通信预算：Hillis–Steele 的 work 比 Blelloch 大 n/logn 倍，换算成通信量就是实打实多搬数据。
  • 假设浮点加法满足结合律：不同的归约树给出不同的浮点结果（这不是 bug）。第 2 章的"数值确定性"讨论从这里开始。
  • 只算 depth 不算每一步的代价：depth 里每一步都要付通信延迟 α，下一课把它变成时间。

6. 这一课到哪里为止#

本课只立"算法侧"的两个坐标。把 W、D 换算成秒需要通信模型（第 2 课），把 D 与带宽变成下界在第 3 课，集合通信的具体算法在第 2 章。

二、可运行代码示例#

三段纯 Python（标准库，无需 GPU、无需 numpy）：树形归约与串行累加的账本核对、Brent 下界的数值、两种扫描的 work/depth 实测。

# ===== 示例 1：work 与 depth 是两个不同的量 =====
import math, random

def seq_sum(xs):
    """串行累加：work = n-1，depth = n-1。"""
    acc, ops = float(xs[0]), 0
    for v in xs[1:]:
        acc += v; ops += 1
    return acc, ops

def tree_reduce(xs):
    """成对归约：每层把相邻部分和相加；work = n-1，depth = ceil(log2 n)。"""
    layer, depth, ops = [float(v) for v in xs], 0, 0
    while len(layer) > 1:
        nxt = []
        for i in range(0, len(layer) - 1, 2):
            nxt.append(layer[i] + layer[i + 1]); ops += 1
        if len(layer) % 2:
            nxt.append(layer[-1])          # 落单的元素直接晋级，不产生加法
        layer, depth = nxt, depth + 1
    return layer[0], ops, depth

rng = random.Random(0)
print("n        串行 work  树形 work  树形 depth  ceil(log2 n)  结果一致")
for n in (16, 1024, 1 << 20):
    xs = [rng.uniform(-1, 1) for _ in range(n)]
    s, ws = seq_sum(xs)
    t, wt, d = tree_reduce(xs)
    print(f"{n:<9}{ws:<11}{wt:<11}{d:<12}{math.ceil(math.log2(n)):<14}"
          f"{abs(s - t) < 1e-6 * max(1.0, abs(s))}")

# ===== 示例 2：Brent 定理给出的"处理器数-时间"下界 =====
def brent_lower_bound(W, D, p):
    return max(math.ceil(W / p), D)

W, D = (1 << 20) - 1, 20
print(f"\nn = 2^20 的树形归约（W = {W}, D = {D}）：")
for p in (1, 8, 64, 1024, 65536, 1 << 20):
    print(f"  p = {p:>8}：T >= max(W/p, D) = {brent_lower_bound(W, D, p):>8} 步")
print(f"  饱和点 p* = W/D ≈ {W // D}：再多的处理器也压不动最长依赖链")

# ===== 示例 3：Hillis-Steele 与 Blelloch 扫描的 work / depth =====
def hillis_steele(a):                      # 含前缀和（inclusive）
    x = list(a); n = len(x); d, ops, depth = 1, 0, 0
    while d < n:
        prev = x[:]
        for i in range(n):
            if i >= d:
                x[i] = prev[i] + prev[i - d]; ops += 1
        d *= 2; depth += 1
    return x, ops, depth

def blelloch_exclusive(a):                 # 不含前缀和（exclusive），n 为 2 的幂
    n = len(a); x = list(a); ops, d, depth = 0, 1, 0
    while d < n:                           # up-sweep
        for i in range(2 * d - 1, n, 2 * d):
            x[i] = x[i] + x[i - d]; ops += 1
        d *= 2; depth += 1
    x[n - 1] = 0.0                         # 根清零
    d = n // 2
    while d >= 1:                          # down-sweep
        for i in range(2 * d - 1, n, 2 * d):
            t = x[i - d]; x[i - d] = x[i]; x[i] = t + x[i]; ops += 1
        d //= 2; depth += 1
    return x, ops, depth

print("\nn       HS work    HS depth   n·log2n-(n-1)   Blelloch work  深度 2·log2n   两法都正确")
for n in (64, 4096, 1 << 16):
    xs = [rng.randint(-9, 9) for _ in range(n)]
    ref, acc = [], 0
    for v in xs:                            # 不含前缀和参考值
        ref.append(acc); acc += v
    hi, wig, hd = hillis_steele(xs)
    be, wob, bd = blelloch_exclusive(xs)
    k = int(math.log2(n))
    ok = (hi[n - 1] == sum(xs)) and (be == ref)
    print(f"{n:<8}{wig:<11}{hd:<11}{n * k - (n - 1):<17}{wob:<16}{bd:<15}{ok}")

三张表各自是一个可验证产出：第一张证明"同 work、不同 depth"；第二张是 Brent 下界（注意 65536 与 1048576 两行都是 20 步，加卡失效）；第三张同时核对了两种扫描的 work 公式与正确性（与串行参考值逐元素相等，用整数避免浮点干扰）。把 tree_reduce 换成任意归约顺序、把扫描换成别的 stride，这两张账都能独立复算。

三、练习#

  1. 实现：把 tree_reduce 改成 k 叉（每层每 k 个一组相加），对 n=220、k=2,4,8 打印 work 与 depth，并用 Brent 公式算出 p=1024 时的时间下界；解释为什么 k 变大时 depth 变小而 work 不变。
  2. 解释：用"每个元素至少读一次"与"一次加法最多合并两份部分和"两句话，证明归约的 W≥n−1；再说清这套论证为什么能直接搬到第 3 课的通信轮数下界上。
  3. 对比/验证：把示例 3 的 n 换成 64、4096、65536，验证 Blelloch 的 work 恒为 2n−2、depth 恒为 2log2​n；再把 Hillis–Steele 的 work 与 nlog2​n−(n−1) 对齐。
  4. 思考：数据并行的"全局 batch"就是把 p 个 micro-batch 的梯度相加。若 p=1024、梯度 1 GiB，所有卡读一遍共多少字节？其中必须跨卡搬运的那部分是多少？先写下你的估计，第 2、3 课会用 α-β 模型把它算成时间。
