与推理引擎的关系：TensorRT-LLM / vLLM 里编译器的位置#

前七章讲"编译器内部怎么做"。到了线上，编译器只是引擎里的一个零件：批怎么组、KV cache 怎么分页、attention 用哪个 kernel，都由引擎决定；编译器只负责把剩下的算子段变成高效的 kernel 与执行计划。位置找错就会误判——把端到端没变快归咎于"编译器不行"，而真正的瓶颈根本不在编译器能碰的那部分。本课用 roofline 加覆盖率消融把这件事算成一张表。

一、概念讲解#

1. 引擎的四层，编译器只在其中一层#

层 职责 是否属于编译器
调度 连续批处理、请求进出、优先级 否
KV cache 管理 分页/块管理、复用与驱逐 否
算子实现 attention / MoE / 量化 kernel，多为手写 部分（编译器生成或调库）
执行器 走表、内存池、图回放 是（编译产物在此落地）

本课不重复推理优化课：只回答"编译器的输出在引擎里被谁消费、边界在哪"。记住边界的形状：编译器覆盖"能用图表达的稠密算子段"，而 attention 这类带状态、带动态索引的算子常被引擎用自定义算子（custom op）实现，并成为编译图的边界。

2. vLLM：分段编译 + 自定义算子当边界#

vLLM 的 torch.compile 集成文档的章节结构本身就说明了接入方式：编译缓存、动态形状与 guard 剔除、计算图处理与编译、CUDA Graph 捕获、自定义算子、优化级别、融合 pass。连起来是一条流水线：自定义算子把整图切成若干段 → 每段交给 torch.compile 编译 → 每段再被 CUDA Graph 捕获成可回放的片段（piecewise）。好处是 attention/MoE 这类手写 kernel 不必被编译器"理解"，代价是跨边界可能有额外调度与拷贝——边界画在哪本身就是性能决策。第 2 课的缓存与 guard 问题在这里同样是真问题：请求形状在变，guard 剔除做得好坏直接决定重编频率。

3. TensorRT-LLM：AOT 构建 engine 与动态形状 profile#

另一边是离线构建：build 阶段一次性完成 kernel 选择、层融合、量化与插件绑定，产出可直接加载的 engine，运行时不再需要 Python 与框架。动态形状靠 optimization profile 表达——为每个输入张量声明 min / opt / max 三档维度，构建时按档位优化，运行期按实际 shape 选已编译的实现。工程含义很直接：声明得窄编译更充分但可能选不中，声明得宽命中率高但单档优化被稀释——这与第 2 课"键的粒度"是同一件事。

4. 两条路线的取舍#

维度 JIT（框架内编译，如 Inductor / XLA） AOT（引擎构建，如 TensorRT engine）
编译时机 首次执行触发，按 guard 重编 交付前一次性构建
产物形态 内存中 kernel + 执行计划，随进程消失 落盘 engine，可脱离 Python
形状处理 符号形状 + guard，或逐 shape 特化 optimization profile（min/opt/max）
设备绑定 绑定编译栈版本与设备 绑定目标设备与 profile，跨代需重建
失败回退 易退回 eager 逐算子执行 构建失败即无产物，粒度粗
更新代价 服务端热更新 构建产物需重新生成并分发

5. 为什么同一模型常要"两套 profile"#

代码第 1 节的两行：decode 单 token 每层算力 0.004 ms、带宽 0.206 ms，卡在带宽；prefill 512 token 时每层算力时间 2.105 ms、带宽 0.224 ms，卡在算力。瓶颈不同，最优 tile、并行度与融合策略就不同，"一个模型两份配置"成了常态。这也解释了第 3 节的消融：prefill 上把 MLP 与投影交给编译器拿到 1.64x（算力利用率从假设的 60% 提到 100%），decode 上同样操作只有 1.08x——带宽受限时算得再快也超不过权重读取；decode 上真正有效的是图回放（少下发 13 个算子/层），一步贡献 8.4%。

6. 常见坑#

  • 只看局部提速：把"这段 kernel 快 3 倍"当端到端结论；必须同时报覆盖率（第 4 节：decode 覆盖 92.1% 只换来 1.078x）。
  • 把 engine 当好缓存：engine 与设备、profile、量化配置强绑定，跨机型直接复用是事故来源。
  • 边界画得太多：每多一个自定义算子边界就多一次调度与潜在拷贝，融合机会也被切碎。
  • 忽略 fallback：回退到 eager 后性能与显存行为完全不同，压测必须覆盖回退路径。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）用 roofline + 覆盖率消融算"编译器能贡献多少"：先判每个阶段的瓶颈，再按段归属统计耗时占比，最后用 Amdahl 把局部提速换算成端到端收益并对账；机器参数与效率系数都是显式假设值。

# ---- 第 3 课示例：推理引擎里的编译器位置 + roofline + 覆盖率归因 ----
# 无 GPU、无第三方依赖。下面每个常量都是**显式假设的模型参数**，不是任何真实设备的实测值。
H, L, F16 = 4096, 32, 2          # 隐藏维、层数、fp16 字节数
VOCAB = 25600                    # 词表大小（lm_head 只在最后做一次）
PEAK_TFLOPS, BW_GBPS = 100.0, 2000.0
LAUNCH_US, REPLAY_US = 3.0, 5.0
EAGER_EFF, ENGINE_EFF = 0.60, 0.90   # 假设：未融合路径 / 手写 kernel 能跑到的峰值比例

def segs(s, ctx):
    """一层的四段：(名字, 归属, FLOPs, 权重字节, 理想激活字节, eager 激活字节, eager 算子数)。
    s = 本批 token 数；ctx = 参与计算的上下文长度（decode 时 s=1 但仍要读完整 KV）。"""
    kv = 2 * H * F16 * ctx
    return [
        ('qkv_proj',  'compiled', 2*3*H*H*s, 3*H*H*F16, 3*H*s*F16, 6*H*s*F16, 3),
        ('attention', 'engine',   2*2*s*ctx*H, 0,        kv + 4*H*s*F16, kv + 6*H*s*F16, 4),
        ('o_proj',    'compiled', 2*H*H*s,   H*H*F16,   H*s*F16,   2*H*s*F16, 1),
        ('mlp',       'compiled', 2*8*H*H*s, 8*H*H*F16, H*s*F16,   6*H*s*F16, 5),
    ]

def head(s):
    return ('lm_head', 'engine', 2*H*VOCAB*s, H*VOCAB*F16, VOCAB*s*F16, VOCAB*s*F16, 1)

def t_one(seg, compiled, graph, bw, peak):
    name, host, flops, wb, a_min, a_eager, ops_eager = seg
    act = a_min if compiled else a_eager
    ops = 1 if compiled else ops_eager
    eff = (1.0 if compiled else EAGER_EFF) if host == 'compiled' else ENGINE_EFF
    t_comp = flops / (peak * eff * 1e12) * 1e3     # ms
    t_mem = (wb + act) / (bw * 1e9) * 1e3          # ms
    t = max(t_comp, t_mem) + (0 if graph else ops * LAUNCH_US / 1e3)
    return t, ('算力' if t_comp >= t_mem else '带宽')

def latency(s, ctx, v, graph=False):
    per_layer, detail = 0.0, []
    for seg in segs(s, ctx):
        compiled = seg[0] in v
        t, bound = t_one(seg, compiled, graph, BW_GBPS, PEAK_TFLOPS)
        per_layer += t; detail.append((seg[0], seg[1], t, bound, compiled))
    th, bound = t_one(head(s), False, graph, BW_GBPS, PEAK_TFLOPS)
    detail.append((head(s)[0], head(s)[1], th, bound, False))
    tot = per_layer * L + th + (REPLAY_US / 1e3 if graph else 0)
    return tot, detail

VARIANTS = [('V0 全 eager 回退', set(), False), ('V1 只编译 MLP', {'mlp'}, False),
            ('V2 编译 MLP+三个投影', {'mlp', 'qkv_proj', 'o_proj'}, False),
            ('V3 V2 + 图回放', {'mlp', 'qkv_proj', 'o_proj'}, True)]
PHASES = ((1, 512, 'decode 1 token(ctx512)'), (512, 512, 'prefill 512'), (4096, 4096, 'prefill 4096'))

if __name__ == '__main__':
    print(f'假设机器：峰值 {PEAK_TFLOPS:.0f} TFLOP/s、带宽 {BW_GBPS:.0f} GB/s；模型 {L} 层 × 隐藏维 {H}、fp16，'
          f'权重合计 {L*12*H*H*F16/1e9:.1f} GB')
    print(f'假设效率：完全融合 {1.0:.0%}、手写 kernel {ENGINE_EFF:.0%}、未融合 eager {EAGER_EFF:.0%} 峰值；'
          f'下发 {LAUNCH_US} µs/次，回放 {REPLAY_US} µs/阶段 —— 均为模型参数')

    print('\n=== 1. roofline：prefill 与 decode 是两种完全不同的瓶颈 ===')
    print(f'  {"阶段":<24}{"FLOPs/层":>15}{"搬运字节/层":>15}{"算力时间":>10}{"带宽时间":>10}{"瓶颈":>7}{"端到端":>11}')
    for s, ctx, nm in PHASES:
        per = segs(s, ctx); fl = sum(x[2] for x in per); by = sum(x[3] + x[4] for x in per)
        tc, tm = fl/(PEAK_TFLOPS*1e12)*1e3, by/(BW_GBPS*1e9)*1e3
        tot, _ = latency(s, ctx, set())
        print(f'  {nm:<24}{fl:>15,}{by:>15,}{tc:>9.3f}ms{tm:>9.3f}ms{"  算力" if tc>=tm else "  带宽":>8}{tot:>10.1f}ms')
    print('  读法：decode 每 token 都要把全部权重读一遍 → 带宽天花板；prefill 相反 → 算力天花板')

    print('\n=== 2. 段归属与耗时（V0 未编译口径；lm_head 只算一次）===')
    for s, ctx, nm in PHASES[:2]:
        _, det = latency(s, ctx, set())
        layer_tot = sum(d[2] for d in det[:4]) * L; tot = layer_tot + det[4][2]
        print(f'  -- {nm}（一层 {layer_tot/L:.3f} ms，端到端 {tot:.1f} ms）')
        for name, host, t, bound, comp in det[:4]:
            print(f'     {name:<10}{host:<9}{t:>8.3f} ms/层  占比 {t*L/tot*100:>5.1f}%  瓶颈 {bound}')
        print(f'     {"lm_head":<10}{det[4][1]:<9}{det[4][2]:>8.3f} ms    占比 {det[4][2]/tot*100:>5.1f}%  瓶颈 {det[4][3]}')
    print('  编译器能动的只有 compiled 段；attention 与 lm_head 是引擎手写 kernel 的地盘')

    print('\n=== 3. 覆盖率消融：每一步各自贡献多少 ===')
    for s, ctx, nm in PHASES[:2]:
        print(f'  -- {nm}')
        base, prev = None, None
        for vname, v, graph in VARIANTS:
            t, _ = latency(s, ctx, v, graph=graph)
            if base is None:
                base = t; print(f'     {vname:<22}{t:>9.2f} ms   基准')
            else:
                print(f'     {vname:<22}{t:>9.2f} ms   累计 {base/t:>5.2f}x   本步贡献 {(prev-t)/base*100:>6.1f}%')
            prev = t

    print('\n=== 4. Amdahl 对账：覆盖率 × 局部提速 → 端到端 ===')
    COV = {'mlp', 'qkv_proj', 'o_proj'}
    for s, ctx, nm in PHASES[:2]:
        t0, d0 = latency(s, ctx, set()); t2, d2 = latency(s, ctx, COV)
        e0 = sum(d[2] for d in d0[:4] if d[0] in COV) * L      # 可编译段的基准耗时
        e2 = sum(d[2] for d in d2[:4] if d[0] in COV) * L      # 可编译段的编译后耗时
        c, k = e0 / t0, e0 / e2
        pred = 1 / ((1 - c) + c / k)
        print(f'  {nm}: 可编译段占基准 {c*100:>5.1f}%，局部提速 {k:.2f}x → 预测 {pred:.3f}x，'
              f'实测 {t0/t2:.3f}x  {"一致" if abs(pred-t0/t2) < 1e-9 else "不一致 ← 归因写错了"}')
    print('  读法：局部提速再漂亮，覆盖率低就被 Amdahl 按住 —— 报告必须同时给出这两个数')

实际运行结果（Python 3.14，无第三方依赖）：

假设机器：峰值 100 TFLOP/s、带宽 2000 GB/s；模型 32 层 × 隐藏维 4096、fp16，权重合计 12.9 GB
假设效率：完全融合 100%、手写 kernel 90%、未融合 eager 60% 峰值；下发 3.0 µs/次，回放 5.0 µs/阶段 —— 均为模型参数

=== 1. roofline：prefill 与 decode 是两种完全不同的瓶颈 ===
  阶段                              FLOPs/层         搬运字节/层      算力时间      带宽时间     瓶颈        端到端
  decode 1 token(ctx512)      411,041,792    411,115,520    0.004ms    0.206ms      带宽       7.9ms
  prefill 512             210,453,397,504    448,790,528    2.105ms    0.224ms      算力     113.9ms
  prefill 4096            1,924,145,348,608    771,751,936   19.241ms    0.386ms      算力     988.1ms
  读法：decode 每 token 都要把全部权重读一遍 → 带宽天花板；prefill 相反 → 算力天花板

=== 2. 段归属与耗时（V0 未编译口径；lm_head 只算一次）===
  -- decode 1 token(ctx512)（一层 0.245 ms，端到端 7.9 ms）
     qkv_proj  compiled    0.059 ms/层  占比  23.9%  瓶颈 带宽
     attention engine      0.016 ms/层  占比   6.5%  瓶颈 带宽
     o_proj    compiled    0.020 ms/层  占比   8.0%  瓶颈 带宽
     mlp       compiled    0.149 ms/层  占比  60.2%  瓶颈 带宽
     lm_head   engine      0.108 ms    占比   1.4%  瓶颈 带宽
  -- prefill 512（一层 3.523 ms，端到端 113.9 ms）
     qkv_proj  compiled    0.868 ms/层  占比  24.4%  瓶颈 算力
     attention engine      0.060 ms/层  占比   1.7%  瓶颈 算力
     o_proj    compiled    0.289 ms/层  占比   8.1%  瓶颈 算力
     mlp       compiled    2.306 ms/层  占比  64.8%  瓶颈 算力
     lm_head   engine      1.196 ms    占比   1.0%  瓶颈 算力
  编译器能动的只有 compiled 段；attention 与 lm_head 是引擎手写 kernel 的地盘

=== 3. 覆盖率消融：每一步各自贡献多少 ===
  -- decode 1 token(ctx512)
     V0 全 eager 回退              7.94 ms   基准
     V1 只编译 MLP                 7.55 ms   累计  1.05x   本步贡献    4.8%
     V2 编译 MLP+三个投影             7.36 ms   累计  1.08x   本步贡献    2.4%
     V3 V2 + 图回放                6.69 ms   累计  1.19x   本步贡献    8.4%
  -- prefill 512
     V0 全 eager 回退            113.92 ms   基准
     V1 只编译 MLP                84.22 ms   累计  1.35x   本步贡献   26.1%
     V2 编译 MLP+三个投影            69.37 ms   累计  1.64x   本步贡献   13.0%
     V3 V2 + 图回放               68.70 ms   累计  1.66x   本步贡献    0.6%

=== 4. Amdahl 对账：覆盖率 × 局部提速 → 端到端 ===
  decode 1 token(ctx512): 可编译段占基准  92.1%，局部提速 1.09x → 预测 1.078x，实测 1.078x  一致
  prefill 512: 可编译段占基准  97.3%，局部提速 1.67x → 预测 1.642x，实测 1.642x  一致
  读法：局部提速再漂亮，覆盖率低就被 Amdahl 按住 —— 报告必须同时给出这两个数

四处可核对结论：瓶颈随阶段反转（decode 带宽 0.206 ms 远超算力 0.004 ms，prefill 相反）；编译器只作用于 compiled 段（prefill 里约 97%，attention 仅 1.7%），覆盖率就是收益上限；局部提速 ≠ 端到端提速（decode 覆盖 92.1%、局部 1.09x、端到端 1.078x）；归因要能对上账（两次 Amdahl 预测与实测完全一致，对不上说明漏了收益或把不可编译段算进分母）。

三、练习#

  1. 实现：把 ENGINE_EFF 改成 0.60（假装 attention 也没写好），重跑第 4 节，看 attention 占比抬升后收益怎么变——"优化手写 kernel"与"提升编译覆盖率"哪个更值？
  2. 解释：decode 的 ctx 从 512 改到 4096 重跑第 1 节，看 attention 搬运字节增长几倍，瓶颈是否从"权重"转成"KV"。
  3. 对比/验证：加一个 V4：编译覆盖 qkv/o_proj/mlp 但去掉 attention 段（模拟引擎没提供该 kernel）。比较 V4 与 V3，解释为什么"覆盖率"与"段数"不是一回事。
  4. 思考：TensorRT 的 optimization profile 要求人工声明 min/opt/max。若某个线上服务的形状分布是长尾的，你会怎么选这三档？提示：把第 2 课的"键爆炸"与本题的"单档优化被稀释"放在同一张权衡表上。
