QKV 与缩放点积#

上一课的自注意力直接让 Q=K=V=x，没有任何可学习参数——它只是"照原样"融合信息。真实的 Transformer 不是这样：它先用三个可学习的线性投影把输入分别变成 Query、Key、Value，再算注意力。这一课补上这块拼图，并讲清楚一个看似不起眼、却至关重要的细节：为什么点积要除以 sqrt(d_k)。

一、概念讲解#

1. 为什么要投影出 Q、K、V#

直接让 Q=K=V=x 的问题是：Query 和 Key 用同一套向量，"谁在问、谁在被问"没有分工，模型学不到"如何提问、如何作答"。引入三个线性层后：

Q = x W_q,   K = x W_k,   V = x W_v
  • W_q 学会把输入变换成"我想找什么"的查询表示；
  • W_k 学会变换成"我这里有什么"的键表示；
  • W_v 学会变换成"我真正贡献什么"的值表示。

三者各司其职，参数可学习。注意力先算 Q 与 K 的相似度（它们被投影到同一个子空间才好比），再用权重对 V 加权。Q、K 的维度记为 d_k，V 的维度记为 d_v，二者可以不同。

2. 缩放点积注意力的完整公式#

把投影、打分、归一化、加权串起来，就是论文里的缩放点积注意力（scaled dot-product attention）：

Attention(Q, K, V) = softmax(Q Kᵀ / √d_k) V

与上一课的区别只有两处：Q、K、V 先各自投影；点积之后除以 √d_k。这个除法就是"缩放"二字的由来。

3. 为什么要除以 √d_k#

这是理解 Transformer 的一个经典细节。假设 Q、K 的每个分量都是独立同分布、均值 0、方差 1 的随机量，那么点积 q·k 是 d_k 个乘积之和：

  • 它的均值是 0；
  • 它的方差是 d_k（每个乘积方差为 1，共 d_k 项）。

于是 d_k 越大，点积的绝对值越容易很大。而 softmax 对很大或很负的输入会"饱和"——梯度趋近 0，模型几乎学不动。除以 √d_k 恰好把点积的方差拉回 1，让分数落在一个"温和"的区间，softmax 保持平滑、梯度健康。

这就是"缩放"的全部意义：不是魔法，只是把数值的方差稳定住，防止 softmax 进入饱和区。

4. 加性注意力为什么不需要缩放#

第一章的加性注意力用 vᵀ tanh(W_q q + W_k k) 打分，其中 tanh 已经把数值压进 (-1, 1)，v 再投影成一个量级受控的标量，天然不会随维度膨胀。所以缩放是点积类打分的专属需求——点积没有这种内建的数值约束，才需要手动除 √d_k。

5. 计算复杂度：为什么点积 + 缩放是首选#

相比加性注意力的多层投影，点积注意力可以用高度优化的矩阵乘法实现，在 GPU 上快得多。而"除以 √d_k"几乎零开销，却能补上点积唯一的短板。于是"点积 + 缩放"成了在表达力、速度、数值稳定三者上的最优平衡，这也是 Transformer 作者选择它的理由。

二、可运行代码示例#

下面实现带 QKV 投影的缩放点积注意力，并单独演示"维度膨胀 → softmax 饱和 → 缩放缓解"这条因果链。

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

seq, d = 4, 6
x = torch.randn(seq, d)

# 1) 三个可学习投影，把 x 分别投影成 Q、K、V
class QKVProjection(nn.Module):
    def __init__(self, d, dk, dv):
        super().__init__()
        self.Wq = nn.Linear(d, dk, bias=False)
        self.Wk = nn.Linear(d, dk, bias=False)
        self.Wv = nn.Linear(d, dv, bias=False)

    def forward(self, x):
        return self.Wq(x), self.Wk(x), self.Wv(x)

dk, dv = 8, 8
proj = QKVProjection(d, dk, dv)
Q, K, V = proj(x)
print("Q 形状:", Q.shape, " K 形状:", K.shape, " V 形状:", V.shape)

# 2) 缩放点积注意力：QK^T / sqrt(dk) → softmax → 乘 V
scores = Q @ K.T / (dk ** 0.5)
attn = F.softmax(scores, dim=-1)
out = attn @ V
print("输出形状:", out.shape)          # (4, 8)

# 3) 为什么除以 sqrt(dk)：维度大时点积方差膨胀，softmax 饱和
big = torch.randn(2, 64)               # 高维向量
dots = big @ big.T                     # 点积数值明显变大
print("高维点积:\n", dots)
print("不缩放 softmax（接近 one-hot，梯度趋近 0）:\n", F.softmax(dots, dim=-1))
print("缩放后 softmax（更平滑）:\n", F.softmax(dots / (64 ** 0.5), dim=-1))

运行后重点观察最后两组输出：

  • 不缩放时，softmax 几乎把权重全给了最大值，其它位置趋近 0——这就是"饱和"；
  • 除以 √64 = 8 后，权重被明显"摊开"，分布更平滑。

前者在训练里意味着梯度消失，后者才是我们想要的健康状态。一个除法，决定了注意力能不能被稳定地训练。

三、练习#

  1. 把 dk 和 dv 设成不同的值（如 dk=8, dv=4），确认代码仍能正常运行、输出形状是 (4, 4)，从而理解 Q/K 与 V 的维度可以独立。
  2. 打印 Q @ K.T 不除 √dk 和除以 √dk 两种情况下 scores 的标准差，用 torch.std 验证"缩放把标准差压回接近 1"。
  3. 给 QKVProjection 加一个 d=64 的更大输入，观察不缩放的 softmax 是否更接近 one-hot，进一步体会维度对饱和程度的影响。
  4. 思考：如果 d_k 特别小（如 1），√d_k 会放大点积，这是否也会带来问题？什么时候"缩放"可能反而是有害的？
