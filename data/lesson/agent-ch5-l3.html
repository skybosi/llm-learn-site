失败回退与重规划（回退粒度：动作 / 子目标 / 整体）#

这一节要解决什么#

第 2 节把计划变成了可验证的对象，于是执行前的缺陷可以拦下来。但真实世界继续给你三种东西：前提被证伪（库存其实不够）、工具超时（不知道有没有成功）、连续失败（这条路走不通）。这时候循环必须回答一个第 2 章没有回答的问题：

失败了，退到哪一层？
  A. 重试这个动作（换参数、退避后再试）
  B. 换一个子目标的实现路径（保留已完成的其它部分）
  C. 推翻整个计划，重新规划
  D. 放弃，把控制交回给人

四种选择的差别不是"保守与激进"，而是成本与覆盖率的取舍：粒度越细，代价越小、能救的场景越少；粒度越粗，能救的场景越多、扔掉的已做工作与重复副作用越多。选错的两种典型后果都很难看：

  • 粒度太细：在一个本质上走不通的子目标上反复重试。日志里是"第 3 步失败 → 重试 → 失败 → 重试"，十几轮之后预算耗尽，而真正的信息是"这个子目标在当前前提下无解"。
  • 粒度太粗：一遇到瞬时超时就推翻整个计划重来。于是已完成的那 8 步白做，而且已经发生的不可逆副作用会被重复触发（第 3 章的幂等键在这里是唯一的安全网）。

这一节要把"退到哪"变成一个可以按量选择的决策，并明确两个前提条件：

回退粒度≤第 3 章：副作用可补偿的边界​​∩第 1 节：结构依赖图给出的作废集合​​

也就是说，回退粒度不是自由选择的：不可逆副作用把"退回上一步"变成物理上不可能（邮件已经发出去了），依赖图把"只退回一步"变成不完整（下游产物已经基于错误事实生成了）。

学完这一节你应该能回答：

  • 失败分成哪四类？每类的判据（可观测证据）是什么？
  • 什么情况下"重试动作"是错的？为什么"重试 N 次"不能用一个固定常数？
  • 回退到子目标级时，哪些已完成的产物必须作废？这个集合怎么算？
  • 为什么"每次都重新规划"通常比"不规划"更差？重规划震荡的机制是什么？
  • 什么情况下放弃优于继续尝试？放弃时要交出什么？
  • "计划版本树"解决什么问题？它和"重规划预算"是什么关系？

一、失败分类：回退粒度的前提#

1.1 四类失败与它们的判据#

回退决策的第一个输入不是"失败了"，而是"哪一类失败"。四类的划分依据是一个很实际的问题：这个失败是否改变了"可行性"这个判断。

类别 定义 可观测证据 默认处置
可重试（RETRYABLE） 失败是瞬时的、且重试不改变世界（幂等安全） 超时、连接错误、限流（429）、明确的临时错误码 退避后重试同一动作
可替换（REPLACEABLE） 同一子目标存在另一条实现路径 确定性失败（4xx 参数错、工具明确不支持该操作）、"这个数据源没有该字段" 换工具/换参数/换数据源，保留子目标
可补偿（COMPENSABLE） 已发生的副作用可被撤销或对账 有对应的补偿动作（退款、撤回、删除）；或可事后对账修正 先补偿，再回退到该子目标的起点
不可恢复（UNRECOVERABLE） 前提永久失效，或副作用不可逆且目标已不可能达成 前置被权威证据证伪（"该客户已注销"）、不可逆动作已完成而后续必需前提永久缺失 立即放弃并升级

最容易误判的是第一条与第二条的分界：

超时⇒可重试当且仅当该动作幂等（或可去重）

一个"创建订单"的超时不是可重试失败 —— 它是结果未知，必须先查订单是否存在（第 3 章的未知区间）。把未知当"没发生"来重试，就是重复下单。所以分类器的输入必须是结构化错误 + 幂等声明，不能只看错误码。

1.2 "重试 N 次"为什么不能是常数#

设单次尝试的成功概率为 p（独立近似），重试 k 次的成功率为

Pk​=1−(1−p)k

表面上"k=3 就够"，但这个式子里的 p 对不同动作差了几个数量级（网络抖动 p≈0.9，被限流的 API p≈0.3），而且重试本身有成本与风险：

重试的期望成本=k⋅cstep​+幂等没做对时这一项爆炸P(重复副作用)⋅C重复​​​

更重要的是，同一个失败重复出现时，p 会变——不是变小（不是运气问题），而是这个失败根本不是随机的。所以工程上的正确规则是：

重试⟺失败类别是可重试 ∧ 同因失败次数<kmax​(动作) ∧ 预算足够

kmax​=min(kpolicy​, ⌊cstep​Brest​−Cmin​​⌋)

第二条是关键：重试次数必须同时受"策略上限"和"预算还能撑几次"约束。一个只剩 3 次调用预算的循环去重试一个需要 5 次才能碰运气的操作，是在用剩余预算赌博。

同因失败的检测是重试逻辑的核心：把每次失败的 (动作, 归一化错误签名) 记账，同一个签名连续出现就必须升级（换类别处置），而不是继续重试。

升级条件:sig(e1​)=sig(e2​)=⋯=sig(en​), n≥nescalate​

1.3 分类错误的代价#

真实类别 被误判为 后果
可替换（这条路走不通） 可重试 死循环重试到预算耗尽（最常见）
不可恢复（前提已失效） 可补偿 付出补偿成本去救一个救不回来的目标
可重试（瞬时故障） 不可恢复 过早放弃，任务成功率无谓下降
结果未知（超时但幂等没保证） 可重试 重复副作用（最贵）

这四行里第一行和第四行是绝大多数生产事故的形态，而它们的共同点是：分类器缺少必要输入（要么没有"同因失败计数"，要么没有"幂等声明"）。

二、回退粒度：一个可计算的决策#

2.1 三种粒度的语义#

粒度 退回位置 保留什么 必须作废 典型触发
动作级 当前动作 全部已完成步骤 无（或只有该动作的部分产物） 可重试；参数可修正
子目标级 某个子目标的起点 其它子目标的产物 该节点的传递后继（第 1 节的反向可达） 可替换；该路径被证伪
整体级 计划起点 只保留"已验证事实集" 全部中间产物 关键前提被证伪；计划结构性错误
放弃 交回控制权 全部已完成产物 + 不可逆动作清单 无 不可恢复；预算耗尽

"保留已验证事实集"是整体级回退的关键设计。如果整体重规划把一切都忘掉，它会重复已经踩过的坑（例如又选了那个走不通的数据源）。所以在重规划时，第 4 章的"已确认事实"必须作为硬约束传进新计划的生成上下文：

新计划←generate(目标, 已确认事实, 已否决的路径∗)

新计划←generate(目标, 已确认事实, 已否决的路径∗)

∗ 尤其是"已否决的路径"这一项最容易被漏掉 —— 它正是防止重规划震荡的材料（见 2.4）。

2.2 回退粒度判定表#

把 1.1 的失败类别与几个可测量的量合起来，得到一张可以直接实现的判定表：

失败类别 副作用可补偿 下游失效范围 已投入成本 / 剩余预算 决策
可重试 — 无 剩余预算 ≥cstep​ 动作级：退避重试（同因超限则升级）
可重试 — 无 剩余预算不足 放弃（附"预算耗尽"原因）
可替换 无关 仅该分支 换路径成本 ≤ 剩余预算 子目标级：换实现路径
可替换 无关 仅该分支 换路径成本 > 剩余预算 整体级重规划（找更便宜的整体路线）或放弃
可补偿 ✓ 有补偿动作 该节点后继 补偿成本 ≤ 已投入成本 子目标级 + 先补偿
可补偿 ✓ 全部 补偿成本 > 已投入成本 继续向前（补偿不划算）或降级交付
— ✗ 不可逆 任意 — 不能回退：只能继续向前或放弃
不可恢复 — — — 放弃并升级（不论预算）

表里第七行是全部设计的价值所在：只要链路上有不可逆副作用，回退粒度在那个点之后就被锁定为"只能向前"。这就是第 1 章"可回滚"目标在规划层的落点 —— 它不是"随时能撤"，而是"撤销的代价决定你能退多远"。

2.3 作废集合的计算（接第 1 节）#

子目标级回退的正确性完全依赖"作废集合算得对"。算法就是依赖图的传递后继：

invalidate(v)={u∣v⇝u},保留=V∖(invalidate(v)∪{v})

但有三个实践细节必须处理：

  1. 跨分支的隐式依赖：如果两个子目标通过一个共享黑板（第 6 章）交换过信息，那么"图上的后继"不完整。所以依赖图必须是运行时更新的（每次读写都记一条边），而不是只在计划时画一次。
  2. 外部世界已改变：某些"中间产物"其实是外部的（下过的单、发过的消息）。作废集合里的这类条目不是"删除"而是"需要补偿"，必须分流处理。
  3. 成本 sunk 的部分：作废不等于白花。已投入成本是沉没成本（第 4 节会再强调），它不该影响"该不该继续"，但必须记入"这次回退的代价"用于事后归因（第 7 章）。

2.4 重规划：触发条件与震荡抑制#

重规划不是免费的重来，它的成本是：重新生成计划的模型调用 + 丢失的上下文 + 重复已做过的工作 + 重复副作用的期望风险。所以必须给它设闸门。

触发条件（满足任一即允许）：

条件 判据 为什么需要
前提被证伪 第 2 节的某个"待验证假设"被执行时否定 计划的结构基础没了
同因失败超限 sig 相同且次数 ≥nescalate​ 说明不是运气问题
预算偏离 C已花​>α⋅C^计划​（如 α=1.5） 计划对成本的估计系统性错了
观测与预期矛盾 执行结果与后置条件冲突（第 2 节 L3 的执行时版本） 计划对世界的模型错了
目标被更新 用户/上游改了目标 目标变了，计划必须变

震荡（thrashing） 是重规划特有的失效模式：系统反复生成不同的计划，每次都跑一小段就发现不行，日志里是"计划 A → 计划 B → 计划 C → 计划 A′"。它的机制有三：

震荡⟺每次重规划都没有携带"已被否决的路径"信息⟹搜索空间没有被真正缩小

抑制手段（按有效性排序）：

  1. 计划版本树 + 否决记录：每次重规划都必须显式说明"上一个计划在哪一步、因为什么被否决"，并把该路径标记为不可用。这样第 n 次重规划的候选空间是单调缩小的。
  2. 变更预算：限制重规划次数 nreplan​≤2∼3，超过就放弃或升级给人。这是一个硬闸，因为它防止无界优化。
  3. 要求新计划证明更优：新计划必须给出"为什么能避开上一个的失败点"的具体机制（而不是"这次我换个思路"）。这一条对 LLM 生成的计划特别重要 —— 模型很容易生成一个措辞不同但结构相同的计划。
  4. 单调进展要求：要求每次重规划后已验证事实集必须严格增大。没有新事实的重规划 = 原地打转。

重规划被接受⟺Δ(已验证事实)>0 ∨ 失败点被结构性规避（有机制说明）

2.5 放弃：为什么它是必须实现的能力#

工程系统里最容易被忽视、但在生产中最重要的一条：及时失败。它的价值可以算：

继续的期望收益=P(剩余可救)⋅V成功​−C剩余​

放弃的收益=−C补偿​−C人工​

当 P(剩余可救) 已经很低（例如前提被永久证伪），继续尝试的期望收益为负，此时每多试一次就多亏一次。继续尝试的动机通常不是收益，而是沉没成本谬误与"不愿承认失败"的默认设置。所以放弃不是"没有策略"，放弃是一个需要主动实现的策略。

放弃时必须交出什么（这是接口设计，缺什么就会导致人工接手时重复劳动或重复副作用）：

结构化放弃报告：
  · 目标与验收标准的原文（人需要知道原定要什么）
  · 已完成的步骤与**产物位置**（句柄，不是描述）
  · ★ 已发生的不可逆动作清单（含幂等键）—— 防止人工重复执行
  · 未完成的部分与"卡在哪一步、为什么"
  · 已证伪的假设与已否决的路径（避免人工走同一条死路）
  · 已花费的预算与剩余预算
  · 建议的下一步（交给谁的哪个动作 / 需要什么新信息）

第二、三条是全部价值所在：不可逆动作清单是人工接手时唯一能避免重复付款/重复发信的依据。

代码：失败分类器 + 回退决策器 + 重规划护栏#

下面的代码实现：(1) 失败分类器；(2) 回退粒度决策器（含用反向可达算作废集合）；(3) 重规划护栏（同因失败计数 + 震荡抑制 + 变更预算）；(4) 放弃报告。

"""
ch5-l3：失败分类器 + 回退决策器 + 重规划护栏。

设计目标：把"退到哪一层"从直觉变成判定表，并把"不要每次都重规划"做成硬闸。
"""
from dataclasses import dataclass, field


# ==================== 数据结构 ====================
@dataclass
class Step:
    index: int
    name: str
    subgoal: str
    cost: float = 1.0
    side_effect: str = "none"        # none | reversible | irreversible
    idempotent: bool = True
    compensable: bool = False        # 是否有可用的补偿动作
    depends_on: list[int] = field(default_factory=list)


@dataclass
class Failure:
    step: int
    error_code: str                  # timeout | rate_limit | bad_args | not_supported | ...
    message: str = ""
    precondition_disproved: bool = False   # 第 2 节的"待验证假设"被否证
    result_unknown: bool = False           # 超时后不知道有没有生效

    def signature(self) -> str:
        """归一化错误签名：用于检测"同因失败"（1.2）。

        ★ 设计决策：签名刻意不含 message 的原文与时间戳。
          因为它们每次都不同，含进去就永远检测不到"同一个原因在重复"。
        """
        return f"{self.error_code}:{self.precondition_disproved}"


# ==================== (1) 失败分类器 ====================
def classify_failure(f: Failure, step: Step) -> tuple[str, str]:
    """返回 (类别, 理由)。四类见 1.1。

    ★ 设计决策：分类器的输入必须包含"幂等声明"与"是否可补偿"——
      只看错误码会犯两类最贵的误判：把'结果未知'当可重试（重复副作用），
      把'这条路走不通'当可重试（死循环重试）。
    """
    if f.precondition_disproved:
        return "UNRECOVERABLE", "前提被权威证据证伪：计划的结构基础已不存在"
    if f.result_unknown and not step.idempotent:
        return "COMPENSABLE" if step.compensable else "UNRECOVERABLE", (
            "超时且结果未知、动作不幂等：必须先查证/对账，不能直接重试")
    if f.error_code in ("timeout", "rate_limit", "connection_reset", "5xx"):
        if step.idempotent:
            return "RETRYABLE", "瞬时失败 + 动作幂等安全：可重试"
        return "COMPENSABLE" if step.compensable else "UNRECOVERABLE", (
            "瞬时失败但动作不幂等：重试有重复副作用风险")
    if f.error_code in ("bad_args", "not_supported", "no_such_field", "permission_denied"):
        return "REPLACEABLE", "确定性失败：同一步骤重试不会变好，需要换实现路径"
    if step.side_effect == "irreversible":
        return "UNRECOVERABLE", "不可逆动作失败且无补偿路径"
    return "REPLACEABLE", f"未知错误码 {f.error_code!r}：按确定性失败处置（保守）"


# ==================== (2) 回退决策器 ====================
@dataclass
class Rollback:
    granularity: str                 # action | subgoal | whole | abort
    target_step: int | None
    invalidate: set[int] = field(default_factory=set)
    compensate: list[int] = field(default_factory=list)
    reason: str = ""


class FallbackPolicy:
    def __init__(self, steps: list[Step], budget: float):
        self.steps = {s.index: s for s in steps}
        self.budget = budget
        self.spent = 0.0
        self.same_cause: dict[str, int] = {}
        self.verified_facts: set[str] = set()          # 已验证事实集（重规划时必须携带）
        self.rejected_paths: list[str] = []            # ★ 已否决路径（防震荡）
        self.replan_count = 0
        self.max_replan = 2
        self.escalate_after = 2                         # 同因失败多少次就升级

    # ---- 反向可达：作废集合（2.3）----
    def downstream(self, step: int) -> set[int]:
        adj: dict[int, list[int]] = {i: [] for i in self.steps}
        for s in self.steps.values():
            for d in s.depends_on:
                adj.setdefault(d, []).append(s.index)
        out, stack = set(), [step]
        while stack:
            u = stack.pop()
            for v in adj.get(u, []):
                if v not in out:
                    out.add(v)
                    stack.append(v)
        return out

    def irreversible_before(self, step: int) -> list[int]:
        """该步之前已经发生的不可逆动作 —— 它们锁定了回退上界。"""
        return [i for i, s in sorted(self.steps.items())
                if i < step and s.side_effect == "irreversible"]

    def decide(self, f: Failure, kind: str, remaining_budget: float) -> Rollback:
        step = self.steps[f.step]
        sig = f.signature()
        self.same_cause[sig] = self.same_cause.get(sig, 0) + 1
        repeated = self.same_cause[sig]
        irrev = self.irreversible_before(f.step)

        # 同因失败升级：这是"可重试→可替换"的自动切换（1.2）
        if kind == "RETRYABLE" and repeated > self.escalate_after:
            kind = "REPLACEABLE"
            reason_upgrade = (f"同因失败 {repeated} 次（sig={sig}）：不是运气问题，"
                              f"升级为换实现路径")
        else:
            reason_upgrade = ""

        if kind == "UNRECOVERABLE":
            return Rollback("abort", None, set(), [],
                            reason_upgrade or "不可恢复：继续尝试的期望收益为负")

        if kind == "RETRYABLE":
            if remaining_budget < step.cost:
                return Rollback("abort", None, set(), [],
                                f"剩余预算 {remaining_budget:.1f} < 单步成本 {step.cost:.1f}")
            return Rollback("action", f.step, set(), [], reason_upgrade or "瞬时失败：退避后重试")

        if kind == "REPLACEABLE":
            if irrev and f.step > max(irrev):
                # ★ 不可逆动作之后：回退会把"已发生的副作用"再触发一次
                return Rollback("whole", 0, set(range(1, max(self.steps) + 1)),
                                [i for i in irrev if self.steps[i].compensable],
                                f"{reason_upgrade or '需要换路径'}；但 step{irrev} 已是不可逆，"
                                f"只能整体重规划并保留已验证事实集")
            downstream = self.downstream(f.step)
            return Rollback("subgoal", f.step, downstream, [],
                            reason_upgrade or
                            f"换该子目标的实现路径；作废下游 {sorted(downstream)}")

        if kind == "COMPENSABLE":
            return Rollback("subgoal", f.step, self.downstream(f.step),
                            [f.step] if step.side_effect != "none" else [],
                            "先补偿已发生的副作用，再回退该子目标")

        return Rollback("abort", None, set(), [], "未覆盖的失败类别（不应发生）")


# ==================== (3) 重规划护栏 ====================
@dataclass
class ReplanRequest:
    plan_signature: str              # 计划的结构指纹（去掉措辞差异）
    mechanism: str                   # "为什么这次能避开上一个失败点"的机制说明
    new_facts: set[str]              # 本次重规划带来的新已验证事实


def replan_guard(req: ReplanRequest, policy: FallbackPolicy) -> tuple[bool, str]:
    """决定是否允许重规划（2.4 的四条抑制）。

    ★ 设计决策：三条闸门各自针对一种失败模式：
      · 变更预算     → 防止无界优化（钱与时间）
      · 计划签名去重 → 防止"换个措辞再来一次"（模型最常见的震荡形态）
      · 单调进展要求 → 防止原地打转（每次都必须有新事实或结构性规避）
    """
    if policy.replan_count >= policy.max_replan:
        return False, f"变更预算用尽（{policy.replan_count}/{policy.max_replan}）：放弃或升级给人"
    if req.plan_signature in policy.rejected_paths:
        return False, f"该计划结构已被否决过（{req.plan_signature}）：拒绝重复尝试"
    if not req.new_facts and "避开" not in req.mechanism:
        return False, "既没有新已验证事实，也没有说明如何结构性规避失败点：疑似震荡"
    if len(req.mechanism) < 8:
        return False, "机制说明过于笼统（'换个思路'不算机制）：要求指出具体规避方式"
    return True, f"允许重规划（第 {policy.replan_count + 1} 次）"


def commit_replan(req: ReplanRequest, policy: FallbackPolicy) -> None:
    policy.replan_count += 1
    policy.rejected_paths.append(req.plan_signature)
    policy.verified_facts |= req.new_facts


# ==================== (4) 放弃报告 ====================
def abort_report(policy: FallbackPolicy, done: list[int], failed_step: int,
                 reason: str) -> dict:
    """★ 设计决策：报告里必须含"不可逆动作清单 + 幂等键"。

    这是人工接手时唯一能避免重复付款/重复发信的依据 —— 缺了它，
    人只能凭描述猜，而"猜错了就重复执行"。
    """
    irrev = [{"step": i, "name": policy.steps[i].name, "idem_key": f"run:step{i}"}
             for i, s in sorted(policy.steps.items()) if s.side_effect == "irreversible"
             and i in done]
    return {
        "状态": "aborted",
        "原因": reason,
        "已完成步骤": done,
        "卡住步骤": failed_step,
        "★ 已发生的不可逆动作": irrev,
        "已验证事实": sorted(policy.verified_facts),
        "已否决路径": policy.rejected_paths,
        "预算": {"已花": round(policy.spent, 2), "总额": policy.budget},
        "需要人工提供的信息": ["该客户是否已注销的权威确认"] if failed_step == 3 else [],
    }

七处关键设计决策：

  1. Failure.signature() 刻意不含 message 原文与时间戳。这是 1.2 里"同因失败检测"能工作的前提：如果把每次都不同的文本含进签名，就永远检测不到"同一个原因在重复"，于是重试永远不会升级。
  2. classify_failure 的输入包含 step.idempotent 与 step.compensable，而不只是错误码。这是为了拦住四类误判里最贵的两类：result_unknown and not idempotent 被显式判为"不能直接重试"（否则重复副作用），确定性错误码被显式判为 REPLACEABLE（否则死循环重试）。
  3. decide 里有一个自动升级：RETRYABLE 且同因次数超过阈值时改判为 REPLACEABLE。这实现了 1.2 的结论 —— 同一个失败重复出现说明它不是随机的，继续重试是拿预算赌博。
  4. irreversible_before() + 场景 4 的判定是"回退粒度被副作用锁定"的代码形态：一旦 step3（冻结额度）不可逆地发生了，后续失败就不能简单退到 step4 —— 只能整体重规划并把不可逆动作列进"需补偿"，或继续向前。这就是 2.2 判定表第七行。
  5. replan_guard 的三条闸门各自针对一种失效模式：变更预算防无界优化、计划签名去重防"换个措辞再来一次"（模型最常见的震荡形态）、单调进展要求防原地打转。演示里前三次请求全被拒绝，第四次因为给出了具体机制 + 新事实才通过 —— 这正是 2.4 想要的判别力。
  6. commit_replan 把被否的计划签名写进 rejected_paths，并累加 verified_facts。这两个字段就是"重规划必须携带信息"的实现，它们让第 n 次重规划的候选空间单调缩小 —— 没有它们，重规划就是随机游走。
  7. abort_report 的 ★ 已发生的不可逆动作 字段带幂等键。这是全节最"便宜"也最"救命"的一条设计：人工接手时最危险的动作是重复执行已完成的不可逆操作，而唯一的防线就是交出这份清单。

练习#

  1. 失败分类：下面六个失败分别属于哪一类，处置是什么？如果分类需要额外信息，指出你需要什么： （a）调用只读搜索 API 超时； （b）调用"创建订单"API 超时； （c）调用"发送短信"返回 400 invalid_phone； （d）第 2 节预演的"待验证假设：用户有退款权限"被工具拒绝证伪； （e）连续 5 次都是 rate_limit，退避后依然如此； （f）写文件返回 disk full。

  2. 同因失败阈值：设某动作单次成功率 p=0.5（独立），重试成本 c=2，重复副作用的期望损失 Cdup​=100（当动作不幂等且未去重时每 k 次重试有 1 次概率触发）。用 Pk​=1−(1−p)k 与期望成本公式，算出 k=1,2,3 时的净收益（设成功价值 V=20），并说明为什么"重试到成功为止"在这个设定下是负期望。

  3. 作废集合：用场景 3 的依赖图，手工验证 downstream(2) = {3,4,5,6}。然后回答：如果 step6（通知客户）依赖的其实不是 step5 的输出，而是 step1 的客户联系方式，作废集合应该变吗？为什么？（提示：依赖图里边的方向代表"数据来源"，step6 只依赖 step1 时它不该被作废 —— 这暴露了"依赖图画得太粗"的问题。）

  4. 重规划震荡：给"场景 5"的第 3 次请求写一条合规的机制说明，使它应该被允许通过。然后回答：如果模型连续 5 次都给出"机制说明"文字不同但实际规避方式相同的计划，你的护栏能拦住吗？如果不能，需要补什么检查？（提示：把机制说明结构化，例如要求指出"新计划里哪个步骤的哪个前置与旧计划不同"。）

小结#

  • 回退决策的第一个输入是失败类别，不是"失败了"。四类：可重试（瞬时 + 幂等安全）、可替换（确定性失败，同一步骤重试不会变好）、可补偿（副作用可撤销/对账）、不可恢复（前提永久失效或副作用不可逆）。最贵的两个误判是把"结果未知且不幂等"当可重试（重复副作用），以及把"这条路走不通"当可重试（死循环重试）。
  • "重试 N 次"不能是常数：Pk​=1−(1−p)k 里的 p 因动作而异，而且必须同时受策略上限与预算还能撑几次约束：kmax​=min(kpolicy​,⌊(Brest​−Cmin​)/cstep​⌋)。同因失败计数是重试逻辑的核心：同一签名连续出现就必须升级处置。
  • 回退粒度被两个东西锁定：粒度≤可补偿边界∩依赖图的作废集合。不可逆副作用把"退回上一步"变成物理不可能；依赖图把"只退一步"变成不完整（下游产物基于错误事实）。
  • 作废集合 = 失败节点的传递后继（第 1 节的反向可达），但有三个实践细节：跨分支的隐式依赖要求依赖图运行时更新；外部世界的产物要分流到"补偿"而不是"删除"；沉没成本要记账但不影响决策。
  • 整体级回退必须携带三样东西：目标、已验证事实集、已否决的路径。第二样防止重复踩坑，第三样防止重规划震荡。
  • 重规划要有闸门：触发条件（前提被证伪 / 同因失败超限 / 预算偏离 / 观测与预期矛盾 / 目标更新）与抑制作用（计划版本树 + 否决记录、变更预算 n≤2∼3、要求机制说明、单调进展要求 Δ(已验证事实)>0）。震荡的根因是"每次重规划都没有携带曾被否决的路径"，于是搜索空间没有缩小。
  • 放弃是一个必须主动实现的策略，不是"没有策略"。当 P(剩余可救) 很低时继续尝试的期望收益为负；继续的动机通常是沉没成本谬误。放弃报告必须含已发生的不可逆动作清单（带幂等键）—— 这是人工接手时唯一能避免重复付款/重复发信的依据。

下一节：回退有成本、重试有成本、补偿也有成本 —— 这些成本都要从同一个池子里扣。第 4 节把"预算"做成多维闸门，给出剩余成本估计、两种剪枝、以及最优停止规则：多步任务的核心工程问题不是"怎么写计划"，而是"在哪一步之前必须放弃"。
