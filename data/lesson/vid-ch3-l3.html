长时一致性与显存：漂移机制、分块滑窗与关键帧#

这一节要解决什么#

第 1 节给了漂移的现象学公式 D(n)=ϵdnα，第 2 节给了噪声与时间轴的关系。但两节都回避了同一个问题：α 为什么是那个值？ 把每步误差写成加性扰动只是记账方式，不是机制。这一节把机制补上，并把它接到工程上真正会撞的那堵墙——显存：

  1. 漂移的第一判据不是时长，是推理时的自回归系数 ρ。 递推 en+1​=ρen​+δn​ 的闭式解 en​=∑i<n​ρn−1−iδi​ 给出三种命运：ρ=0.90 时误差上界 ϵ/(1−ρ)=0.001000（n=1000 时已达上界）；ρ=1.00 时线性无界（0.1000，是前者的 100 倍）；ρ=1.02 时指数发散（1,991,323.2533）（表 1）。"长视频会不会崩"先问 ρ，再问时长。
  2. exposure bias 是"训练看真值、推理看自己"的分布偏移，它的破坏力有上界。 用二次多项式在 [0,1]2 均匀分布上拟合一个收缩的非线性动力学，再自由运行 400 步：单步误差 0.185479，n≥50 之后误差在 0.344241∼0.364823 之间振荡不再增长，放大倍数 1.4254（表 2）。沿轨迹的雅可比谱半径最小 0.028298、平均 0.309537、最大 0.353659——只要模型自身的动力学是收缩的，暴露偏差就会被限制在一个常数里。
  3. 分块/滑窗的取舍有一条干净的不等式。 overlap 的代价是线性的 1/(1−o)，加块长的代价是二次的 (B/16)2：B:16→128 让块内注意力涨 64 倍、显存同步涨 64 倍，而 o:0→0.5 只让注意力倍率从 1.0000 涨到 2.0000（表 3）。"滑窗还是加块长"的答案由此确定：能靠 overlap 补回接缝质量，就不要加块长。
  4. 三笔显存账的缩放律不同，所以"先优化哪一笔"是一个可判定的问题。 score 物化 ∼N2、训练激活 ∼N、推理缓存 ∼N。20 秒视频：score 57,840.2500 GiB、激活 225.4688 GiB、缓存 28.1836 GiB——差三个数量级，但都超预算；分块把 score 压到 0.0587 GiB（不动另外两笔），梯度检查点把激活压 7.1111 倍（不动另外两笔）（表 4、表 6）。
  5. 按预算反解是闭式的。 b=s(cact​d+2nh​)=10,272 B/token/层，Nmax​=M/(Lb)：8 GiB 给 5.6712 s、24 GiB 给 17.0135 s、80 GiB 给 56.7117 s（表 4）。这一行数字可以直接写进设计文档的预算表。
  6. 一致性的每一分都能定价。 关键帧锚定把 1920 帧的平均漂移从 14.0217 压到 0.763398（K=8，约 7.75 倍），代价是锚点数 4→240、锚点信息量涨 60 倍、接缝数涨 60 倍（表 5）。"更一致"从来不是免费的：它的价格写在接缝数与条件 bit 数上。

本节的主线：长时一致性是一个"误差在递推里的衰减率"问题，而它的工程解法（分块、滑窗、关键帧、检查点）各自只动三笔账里的一笔——先认清是哪一笔超预算，再选旋钮。

一、漂移的机制：误差在递推里怎么走#

1.1 把生成写成递推#

自回归（或分块、或带状态缓存）的生成在时间方向是一条递推。把误差在时间方向上的分量投影成一个标量（这一步是量级判据，不是完整模型）：

en+1​=ρen​+δn​,e0​=0 ⟹ en​=i=0∑n−1​ρn−1−iδi​.

en+1​=ρen​+δn​,e0​=0 ⟹ en​=i=0∑n−1​ρn−1−iδi​.

（式 1）这个闭式解是所有后续讨论的出发点。逐项看：

  • ρ<1（收缩）：历史误差按几何级数衰减，en​ 有界。两种常见情形：
    • δ 无偏（均值 0、标准差 ϵ）：Een2​=ϵ21−ρ21−ρ2n​，上界 ϵ/1−ρ2​；
    • δ 每步同向（都等于 ϵ）：en​=ϵ1−ρ1−ρn​，上界 ϵ/(1−ρ)。
  • ρ=1（临界）：en​=∑i​δi​，误差直接把每步的偏差加起来，en​∝n。这对应第 1 节的 α=1。
  • ρ>1（发散）：en​ 按 ρn 指数增长——这时"长视频"根本不可用，与模型质量无关。

表 1 的算例（ϵ=10−4）：

这张表最该记住的是"0.001000 那一列"：它说明收缩系统的误差在 n≈50 之后就饱和了——加长视频不会让误差等比增长，除非 ρ≥1。所以"长视频一定会漂移"这个说法是不完整的：真正决定它的是 ρ 的符号位置。

1.2 为什么 ρ 与 α 是同一个量#

第 1 节的 D(n)=ϵdnα 与式 1 描述同一段误差的两种读法：

  • ρ<1 的有界误差在短窗口上拟合出的 α 会偏小（看起来像 0.5 甚至更小），因为在观测窗口内它还没饱和；
  • ρ→1 时 en​≈ϵn，拟合出的 α→1；
  • ρ>1 时拟合出的 α 会大于 1（第 1 节构造的 α=1.5 就是这一类）。

（式 2）因此"这个模型的漂移指数是多少"必须与"观测窗口多长"一起报，这与第 1 节表 3 的教训（口径与时长必须同时报）是同一件事。

1.3 ρ 从哪里来：exposure bias 的定量形态#

ρ 不是超参，它由两件事共同决定：

  1. 模型自身的动力学：把模型在状态 z 处的雅可比 J(z) 的谱半径记为 ρmodel​(z)。若处处 <1，误差在传播中衰减。
  2. 分布偏移：训练时输入来自真值分布 Dtrain​，推理时输入来自模型自己产生的分布。两者的差就是 exposure bias。

表 2 用可复算的构造把这件事量化：目标动力学 f(z)=frac(μ+0.35sin(2πMz))，训练分布是 [0,1]2 均匀，模型族是二次多项式（6 个特征：1,z0​,z1​,z02​,z0​z1​,z12​），在训练分布上最小二乘。结果：

1 0.185479 是 1.0000
2 0.460226 是 2.4813

10 0.246445 是 1.3287
100 0.344241 是 1.8560
400 0.264383 是 1.4254

沿自由运行轨迹的雅可比谱半径：最小 0.028298、平均 0.309537、最大 0.353659。

读法：单步误差 0.185479（模型在训练分布内的误差）已经是主要项；自由运行 400 步之后误差 0.264383，放大 1.4254 倍——没有被无限放大。原因是平均谱半径 0.309537<1，对应表 1 的 ρ<1 那一列。所以：

exposure bias 的破坏力 = 单步误差 × 一个由 ρmodel​ 决定的常数因子。把 ρmodel​ 压到 1 以下，是比"把单步误差压到零"更容易达到、也更关键的目标。

边界：这是一个 2 维、6 特征、4000 样本的构造，量化的是机制不是真实模型的常数。真实视频模型的 ρmodel​ 需要实测（方法见练习 2），而且它可能随状态变化（非一致收缩）。

二、三种一致性机制：分块、滑窗、关键帧#

2.1 分块与滑窗：线性换二次#

分块生成：每块 B 帧，相邻块重叠 oB 帧。于是每块产出 B(1−o) 个新帧，单位新帧的注意力成本倍率是

mult(o)=1−o1​,而块内注意力的绝对成本∝B2.

结论是一条不等式：要让"块内可及时间"翻倍，加块长要付 4 倍注意力 + 4 倍显存；用 overlap 只要付 1/(1−o)——把 o 从 0 提到 0.5 是 2 倍。所以只要"接缝质量"能靠 overlap 补回来，就永远不加块长。 这条判据的边界是接缝质量：overlap 只能让条件更充分，不能修复"块内模型本身不擅长长程运动"的问题；当失效来自后者时，加块长是唯一选择（并且必须同时接受 B2 的代价）。

  • 如果超预算的是 score → 分块（N/(2dhead​) 倍，20 秒时 985,088.0000 倍）；

  • 如果超预算的是推理缓存 → 流式/滑窗推理（丢弃窗口外的历史），代价是长程一致性（第 1 节的记忆容量账）。

3.5 本节的三条边界#

  1. 漂移的第一判据是 ρ 而不是时长（表 1）：ρ<1 时误差饱和（ϵ/(1−ρ)），ρ=1 时线性无界，ρ>1 时指数发散。ρ 由模型自身动力学（表 2 的雅可比谱半径，平均 0.309537）与分布偏移共同决定。
  2. 一致性机制各自只动一笔账（表 3、表 5、表 6）：滑窗是线性代价、加块长是二次代价；关键帧锚定的价格是锚点 bit 数（6.67%→400% 的那一列）与接缝数。
  3. 显存可以闭式反解（式 8）：Nmax​=M/(Lb)，b=10,272 B/token/层，24 GiB 对应 17.0135 s。先把这三个数写进设计文档，再谈架构选择。

#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""第 3 章 第 3 节 数值脚本（正文表 1~表 6）。"""
import math
import unicodedata


def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1
               for ch in s)


def pad(s, w, align=">"):
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2
    return " " * left + s + " " * (gap - left)


def row(cells, widths, aligns=None):
    aligns = aligns or [">"] * len(cells)
    return " | ".join(pad(c, w, a) for c, w, a in zip(cells, widths, aligns))


def rule(t, w=112):
    print("=" * w)
    print(t)
    print("=" * w)


def gib(x):
    return x / 2 ** 30


class LCG:
    def __init__(self, seed=20260923):
        self.s = seed & 0xFFFFFFFFFFFFFFFF

    def u(self):
        self.s = (6364136223846793005 * self.s + 1442695040888963407) \
            & 0xFFFFFFFFFFFFFFFF
        return (self.s >> 11) / float(1 << 53)

    def n(self):
        u1 = max(self.u(), 1e-12)
        u2 = self.u()
        return math.sqrt(-2.0 * math.log(u1)) * math.cos(2.0 * math.pi * u2)

    def uni(self):
        return self.u()

def fit_quad(n_pair, seed):
    r = LCG(seed)
    k = len(FEATS)
    X, Y = [], []
    for _ in range(n_pair):
        z = (r.uni(), r.uni())
        X.append(feats(z))
        Y.append(target(z))
    # 正规方程 (X^T X) w = X^T y，两分量各解一次；用高斯消元（6x6）。
    XtX = [[sum(X[n][i] * X[n][j] for n in range(n_pair)) for j in range(k)]
           for i in range(k)]
    Xty = [[sum(X[n][i] * Y[n][c] for n in range(n_pair)) for c in range(2)]
           for i in range(k)]

    def solve(Amat, bvec):
        A = [rowA[:] + [bvec[i]] for i, rowA in enumerate(Amat)]
        n = len(A)
        for col in range(n):
            piv = max(range(col, n), key=lambda r_: abs(A[r_][col]))
            A[col], A[piv] = A[piv], A[col]
            pv = A[col][col]
            for j in range(col, n + 1):
                A[col][j] /= pv
            for r_ in range(n):
                if r_ != col and A[r_][col] != 0.0:
                    f = A[r_][col]
                    for j in range(col, n + 1):
                        A[r_][j] -= f * A[col][j]
        return [A[i][n] for i in range(n)]
    w = [solve(XtX, [Xty[i][c] for i in range(k)]) for c in range(2)]
    return w

    tr = J[0][0] + J[1][1]

    disc = tr * tr / 4 - det

    return math.hypot(tr / 2, math.sqrt(-disc))

  (b) 每步同向偏差（delta = eps 常数）：误差有界，上界 eps/(1-rho)
  (c) rho > 1：误差按 rho^n 指数发散

  · rho=1.00（临界，即第 1 节的 alpha=1）：误差线性无界，n=1000 时 0.1000，

  · rho=1.02：指数发散，n=1000 时 1,991,323.3 —— 这是「长视频直接崩」的算术形态。

所以「长视频会不会漂移」的第一判据不是时长，而是推理时的时间自回归系数
rho 是否小于 1。rho 由两件事决定：模型在训练分布上的单步误差（下一张表），
以及离开训练分布后误差如何增长（exposure bias）。

  沿自由运行轨迹的谱半径：最小 0.028298、平均 0.309537、最大 0.353659
  平均谱半径 < 1 -> 对应表 1 的 rho<1 列：误差有界、漂移由「模型与真值的
  系统性差」主导，而不是误差自我放大。这正是 exposure bias 的破坏力上限。
它与第 1 节的 alpha 是同一个量的两个视角：alpha 描述漂移随 n 的幂律，
rho 描述同一段误差在一步内的衰减率。

小结#

  • 漂移的机制是递推 en+1​=ρen​+δn​，闭式解 en​=∑i<n​ρn−1−iδi​（式 1）。ρ=0.90 误差上界 0.001000（n=1000 已达上界）；ρ=1.00 线性无界（0.1000，100 倍）；ρ=1.02 指数发散（1,991,323.2533）。
  • ρ 与第 1 节的 α 是同一量的两种读法（式 2）：观测窗口内 ρ<1 拟合出偏小的 α，ρ→1 给 α→1，ρ>1 给 α>1。报 α 必须同时报窗口长度。
  • exposure bias 的破坏力有上界：单步误差 0.185479，自由运行 400 步误差 0.264383（放大 1.4254 倍），n≥50 后在 0.344241∼0.364823 间振荡；原因是平均雅可比谱半径 0.309537<1（最小 0.028298、最大 0.353659）。
  • 分块/滑窗的代价是线性、加块长是二次（式 3）：B:16→128 使块内注意力涨 64 倍；o:0→0.5 只让注意力倍率从 1.0000 到 2.0000。能靠 overlap 补接缝，就不要加块长。
  • 关键帧锚定的定价（式 4、表 5）：K:480→8 把平均漂移从 4.833899 降到 0.763398（6.33 倍），代价是锚点 4→240、锚点信息量占总内容熵 0.208333%→12.500000%、接缝 3→239。
  • 三笔显存账的缩放律不同（式 5）：20 秒时 score 57,840.2500 GiB、激活 225.4688 GiB、缓存 28.1836 GiB；分块把 score 压 985,088.0000 倍但不动另两笔，检查点把激活压 7.1111 倍但不动另两笔（式 6：L+cact​−1Lcact​​）。
  • 预算反解是闭式的（式 7、式 8）：b=s(cact​d+2nh​)=10,272 B/token/层，Nmax​=M/(Lb)；8/24/80 GiB 对应 5.6712/17.0135/56.7117 s。
  • 没有一条优化能同时改善三笔账：分块牺牲并行度（延迟）、检查点牺牲计算（+33% 前向）、滑窗推理牺牲长程一致性。"长视频"没有统一解法的算术原因在此。
