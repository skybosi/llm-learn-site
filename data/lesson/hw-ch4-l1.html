计算密集 vs 访存密集#

上一课引入了算术强度，这一课把它用到实处：把形形色色的算子分成两大类——计算密集（compute-bound） 和 访存密集（memory-bound）。分类不是贴标签，而是决定"该往哪个方向优化"。方向错了，力气全白费。

一、概念讲解#

1. 两类算子的定义#

用算术强度 AI=FLOPs/字节数 作标尺：

  • 计算密集：强度高，算得多、搬得少。瓶颈在算力，机器在"满负荷做运算"。典型：大矩阵乘、卷积。
  • 访存密集：强度低，搬得多、算得少。瓶颈在带宽，机器在"干等数据到货"。典型：逐元素激活、归一化、矩阵乘向量。

2. 一个直觉：搬运是"开销"，计算是"产出"#

把每次访存都当成一次开销：如果搬 1 字节能做几百次运算（大 GEMM），开销就被摊薄了，产出受算力限制；如果搬 1 字节只能做 0.2 次运算（逐元素加法），那绝大部分时间都花在搬数据上，算力再多也闲着。这就是两类算子的本质区别。

3. 常见算子的强度速查#

算子 强度（量级） 类型
大矩阵乘 GEMM 几十～几百 FLOP/byte 计算密集
卷积（大 kernel、大通道） 较高 计算密集
逐元素激活/加法 ~0.2 访存密集
LayerNorm / RMSNorm 很低 访存密集
Softmax / 注意力分数 很低 访存密集
矩阵 × 向量（瘦长矩阵） ~1 访存密集

特别注意最后一行：矩阵乘不一定是计算密集的。当矩阵"瘦长"到接近向量时，强度骤降到 1 附近——而 LLM 推理 decode 阶段每生成一个 token，本质上就是一堆"矩阵 × 向量"。

4. 分类决定优化方向#

  • 计算密集算子：优化方向是榨干算力——用 Tensor Core、对齐维度、提高算术强度、让分块更高效；
  • 访存密集算子：优化方向是减少搬运——算子融合（把多个逐元素 op 合成一个 kernel，中间结果不落显存）、低精度量化（字节数减半）、增大 batch（一次读权重服务更多 token）。

如果方向搞反——比如给一个访存密集的 layernorm 疯狂优化计算——收益几乎为零，因为它根本不卡在计算上。

5. 判断工具：和机器的 ridge 比#

一个算子是"计算密集"还是"访存密集"，还要看它跑在哪台机器上。判据就是上一课的 ridge：

  • 算子强度 > 机器 ridge → 计算密集（机器算力是瓶颈）；
  • 算子强度 < 机器 ridge → 访存密集（机器带宽是瓶颈）。

H100 的 ridge ≈ 295，所以强度 500 的 GEMM 是计算密集，强度 1 的矩阵乘向量是访存密集。同一个算子，换到 ridge 更高的机器上，结论可能反转。

二、可运行代码示例#

给几个算子算强度，并和 H100 的 ridge 比较，输出"密集类型"判断。

# ---- 例 1：机器 ridge 与算子强度 ----
H100_RIDGE = 989.0 * 1e12 / (3.35 * 1e12)   # ≈ 295 FLOP/byte

def classify(flops, bytes_moved, name, ridge=H100_RIDGE):
    ai = flops / bytes_moved
    kind = "计算密集" if ai > ridge else "访存密集"
    print(f"{name}: 强度={ai:8.1f} FLOP/byte -> {kind}")
    return ai

# ---- 例 2：逐个判断 ----
# 大 GEMM 4096^3（FP16，近似搬 3 个矩阵）
n = 4096
classify(2*n**3, 3*n*n*2, "大 GEMM(4096^3)")

# 逐元素 ReLU：读 1、写 1，每个元素 1 次运算
classify(1, 2*2, "逐元素 ReLU(FP16)")

# LayerNorm：读 1 写 1，每个元素约 3 次运算（减均值、除标准差、乘 gamma）
classify(3, 2*2, "LayerNorm(FP16)")

# 矩阵乘向量：m=1, k=n=4096（decode 的一个投影）
classify(2*1*4096*4096, (1*4096 + 4096*4096)*2, "矩阵×向量(1×4096×4096)")

# ---- 例 3：优化方向检查 ----
def optimize_advice(kind):
    if kind == "计算密集":
        return "榨干算力：Tensor Core / 对齐维度 / 提高强度"
    return "减少搬运：算子融合 / 低精度量化 / 增大 batch"

for ai in [500.0, 0.25]:
    kind = "计算密集" if ai > H100_RIDGE else "访存密集"
    print(f"强度 {ai} 的算子 -> 建议：{optimize_advice(kind)}")

要点：同一个 classify 函数，把不同算子的强度算出来一对比，立刻看出大 GEMM（几百）和逐元素/归一化（0.x）的天壤之别。例 3 是"分类"的最终目的——不同瓶颈，优化动作完全不同。

三、练习#

  1. 判断：softmax 需要读入一段向量、求出最大值与和、再做逐元素指数与除法。估算它的算术强度（读 1 写 1，每元素约 4 次运算），判断它在 H100 上属于哪一类。
  2. 计算：注意力分数矩阵 QKT 是一个 N×N 的矩阵乘（N 为序列长度）。当 N=2048 时它偏哪一类？当 N=128 时呢？（提示：用 GEMM 强度 ∝N 的结论。）
  3. 验证：把 H100 换成 A100（ridge ≈ 156），例 2 里的哪些判断会改变？
  4. 思考：为什么"算子融合"能加速访存密集算子？它减少的到底是什么？（提示：中间结果不落显存，省的是什么？）
