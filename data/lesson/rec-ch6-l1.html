项目规划#

前面五章把推荐系统的每个组件都拆开讲了一遍。从本课开始，我们把它们拼成一个可落地的小项目。动手写代码前，先做项目规划：明确业务目标、盘点数据、确定技术选型与评估体系。规划想不清楚，后面的代码写得再漂亮也会跑偏。

一、概念讲解#

1. 从业务目标到可优化指标#

推荐系统项目的起点不是一个算法，而是一个业务问题："我们想让用户多点什么？"业务目标常见有这几类，且它们会直接决定你优化哪个指标：

  • 提升点击 → 优化 CTR（点击率），模型学 pCTR。
  • 提升转化/成交 → 优化 CVR、GMV（成交额），需要建模点击后的转化。
  • 提升停留/留存 → 优化时长、次日留存，需要把"消费深度"纳入打分，而非只看点没点。

规划的第一步，是把一个模糊的业务诉求，翻译成一个清晰、可离线评估、可线上验证的指标。例如"提升推荐质量"太虚，"把推荐流的 CTR 从 3.2% 提升到 3.5%"才是可执行的。指标定下来后，整条链路的每个组件都朝它对齐——召回想多捞"会点击"的物品，粗排精排按 pCTR 排序，重排在保证 CTR 的同时兼顾多样性。

2. 数据盘点：你手里有什么、缺什么#

推荐系统是数据驱动的，规划时必须先清点三类数据：

  • 行为日志：用户的曝光、点击、收藏、购买、停留时长。这是训练排序模型和监督召回的核心信号。要特别关注负样本（曝光了但没点）是否被完整记录——没有负样本，模型就只能学"喜欢什么"，学不会"不喜欢什么"。
  • 物品库：物品的类目、标签、价格、作者、发布时间、内容描述。它决定物品侧特征能做多细。
  • 用户画像：年龄、性别、地域、兴趣标签。它决定用户侧特征的丰富度。

还要诚实面对冷启动：新用户没有行为、新物品没有曝光，这两类在数据里是"空"的。规划时要明确用哪一路召回兜底（热门、标签、新物品保底），否则上线第一天就会"新用户看到一片空白"。

3. 技术选型：离线、在线与存储#

一个最小可用的推荐系统，技术选型大致分三块：

  • 离线：数据仓库存日志，用 Python（NumPy/Pandas/scikit-learn/PyTorch）做模型训练、特征计算、向量生成。
  • 在线：服务端在用户请求时实时跑"召回 → 粗排 → 精排 → 重排"。向量召回需要一个 ANN 检索引擎（如 Faiss/Milvus），物品向量和相似度索引要能快速读。
  • 存储：物品向量、画像、模型参数放 KV 缓存或内存，保证毫秒级读取。

对个人学习项目来说，一个务实的 MVP（最小可行产品） 策略是：先用离线脚本把整条链路在内存里跑通（本课程第 2 课就是这么做的），验证效果后再逐步工程化（向量入库、服务化、增量更新）。不要一上来就追求分布式和微服务，先证明"推荐流程本身有价值"。

4. 评估体系：离线与在线分开设计#

规划阶段就要把"怎么算好、怎么算差"定下来，否则迭代无从下手：

  • 离线评估：在历史数据上，用 AUC、GAUC、Precision@K、Recall@K、NDCG@K 等指标衡量模型（第 3 课细讲）。特点是快、可反复跑，但不代表线上真实效果。
  • 在线评估：通过 AB 实验，把用户随机分到对照组（旧策略）和实验组（新策略），对比 CTR、转化、留存等真实指标，并做显著性检验确认差异不是随机波动。

规划时要预留 AB 实验的埋点和分流能力，并明确"离线指标只是入场券，线上指标才是最终裁判"这个基本态度。

二、可运行示例#

示例 1：定义项目指标与漏斗量级#

先写一个"规划脚本"，把业务目标、漏斗各层的候选量级、以及核心指标的定义固定下来，作为后续两课共用的基准。

# 项目规划：推荐系统 MVP 的指标与漏斗定义
PROJECT = {
    "business_goal": "提升推荐流点击率 CTR",
    "target_metric": "ctr",                 # 全链路统一优化的指标
    "funnel": {                             # 漏斗各层候选量级（示例规模）
        "item_pool": 100_000,               # 物品池
        "recall": 2_000,                    # 召回后候选
        "coarse": 300,                      # 粗排后候选
        "fine": 50,                         # 精排后候选
        "final": 10,                        # 最终展示条数
    },
}

def funnel_reduction(funnel):
    """打印漏斗每一层的候选缩减倍数，直观感受'用精度换速度'。"""
    keys = ["item_pool", "recall", "coarse", "fine", "final"]
    for i in range(1, len(keys)):
        prev, cur = funnel[keys[i - 1]], funnel[keys[i]]
        print(f"{keys[i-1]:>9} -> {keys[i]:<6} : {prev:,} -> {cur:,}  (缩减 {prev/cur:.1f} 倍)")

def ctr(predictions, labels):
    """CTR：被预测为正的样本中，真实为正的比例（在线常用点击/曝光近似）。"""
    clicks = sum(1 for p, y in zip(predictions, labels) if p >= 0.5 and y == 1)
    shows = sum(1 for p in predictions if p >= 0.5)
    return clicks / shows if shows else 0.0

funnel_reduction(PROJECT["funnel"])
# 演示 CTR 计算：8 次曝光，3 次真实点击
preds, labels = [0.9, 0.8, 0.7, 0.6, 0.3, 0.2, 0.1, 0.05], [1, 1, 0, 1, 0, 0, 1, 0]
print("示例 CTR =", round(ctr(preds, labels), 3))

示例 2：生成后续课时共用的模拟数据集#

为第 2、3 课准备一份模拟的"用户-物品交互 + 物品画像"数据，固定随机种子保证可复现。

import numpy as np

np.random.seed(42)
n_users, n_items = 500, 800

# 用户兴趣：每个用户偏好 1~2 个主题（共 8 个主题）
n_topics = 8
user_topics = np.array([np.random.choice(n_topics, size=np.random.randint(1, 3), replace=False)
                        for _ in range(n_users)], dtype=object)
# 物品主题：每个物品 1 个主题
item_topics = np.random.randint(0, n_topics, size=n_items)

# 生成交互：用户更容易点击"自己偏好主题"的物品
interactions = []   # (user, item, label)
for u in range(n_users):
    n_cand = np.random.randint(20, 80)
    for _ in range(n_cand):
        i = np.random.randint(0, n_items)
        base = 0.05
        boost = 0.6 if item_topics[i] in user_topics[u] else 0.0
        label = 1 if np.random.rand() < base + boost else 0
        interactions.append((u, i, label))

print("交互样本数:", len(interactions))
print("正样本比例:", round(np.mean([y for _, _, y in interactions]), 3))
print("示例交互:", interactions[:3])

三、练习#

  1. 把示例 1 里的业务目标改成"提升成交额 GMV"，说说你会把全链路统一优化的指标换成什么，召回和精排的目标要随之怎么调整。
  2. 盘点一下：如果你要给自己常用的一款内容 App 做推荐，它有哪些行为日志、物品画像、用户画像数据？哪些数据最容易缺？
  3. 解释"负样本（曝光未点击）"对排序模型的重要性：如果日志里只记录了点击、没有曝光，会发生什么？
  4. 思考题：为什么离线 AUC 高不等于线上效果好？结合"线上线下一一致性"和"反馈偏差"各举一个原因。
