工具链实践：IR 打印、汇编查看、调试一个 pass#

前两课建立了"四层形态"的心智模型。这一课把它变成可操作的能力：拿到一个文件，你能打印出它每一层的表示、能对比优化前后的差异、能定位"是哪个 pass 改坏了我的代码"。

环境说明：本课命令以 LLVM 工具链为例。没有安装 LLVM 也能学完——例 2、例 3 用我们自带的 Python 迷你编译器完成同样的观察动作；装 LLVM 的步骤见例 4 的注释（macOS brew install llvm、Ubuntu apt install llvm clang、Windows 建议 WSL）。

一、概念讲解#

1. 一次编译里，中间产物到底有哪些#

源码.c ──clang -S -emit-llvm──▶ 源码.ll（LLVM IR，人类可读）
       ──opt -passes=... ─────▶ 优化后的 IR（.ll 或 .bc 字节码）
       ──llc ─────────────────▶ 源码.s（目标汇编）
       ──as / ld ─────────────▶ 可执行文件
       └─ lli 直接解释执行 IR（跳过汇编与链接，便于验证语义）
工具 作用 本课用它做什么
clang -S -emit-llvm 前端 → LLVM IR（文本） 看"源码→IR"这一步
clang -S 一路到汇编 看"IR→汇编"这一步
opt -passes=<…> 只跑指定优化 pass 逐个开关，看每个 pass 的效果
llc IR → 汇编 观察后端指令选择
lli 直接执行 IR 验证"优化没改语义"
objdump（Linux）/ otool -tvV（macOS） 反汇编可执行文件 对照最终机器码

2. 为什么要"逐个 pass"看，而不是只看 -O2#

-O2 是一个包含几十个 pass 的管线。当优化后行为出错，直接面对 -O2 是无从下手的；而有三个可以立刻用上的方法：

  1. 对照法：-O0 与 -O2 的 IR 差异，就是"被优化掉/改写了什么"的清单。
  2. 逐 pass 打印：opt -print-after-all 会把每个 pass 之后的 IR 全部打印出来，定位"从哪一步开始变坏"。
  3. 二分法：把 pass 管线拆成两半，先跑前半——如果坏在前半，就继续二分前半。这是编译器调试的通用手法。

3. 验证"优化没改语义"的基本功#

优化的定义是"换成语义等价但更快的程序"。因此每次优化的验收都应该是行为等价，而不是"看起来更快"：

  • 用 lli 或编译后执行，对同一组输入比较输出；
  • 边界输入必测（0、负数、极大值、空输入）；
  • 浮点要明确容差（-ffast-math 之类的松弛是另一回事，别混进等价性判断）。

这条纪律在后面的 GPU/编译器课程里会反复出现：先证明正确，再谈快。

二、可运行代码示例#

# ---- 例 1：一个给"迷你编译器"用的 IR 观察器 ----
# 目标：在自己的 pass 上做"前后对比"，与 LLVM 的 -print-after-all 是同一种动作

def show(ir, title):
    print(f'--- {title} ---')
    for ins in ir: print('   ', ins)

before = [('t1', '+', ('name','min'), ('name','max')),
          ('t2', '/', ('name','t1'),  ('const',2)),
          ('avg', '=', ('name','t2'), None)]
show(before, '优化前')

def constfold(ir):
    """一个真正的优化 pass：把"两个操作数都是常量"的运算直接算掉"""
    env = {}          # 临时名 → 常量值
    out = []
    for dst, op, a, b in ir:
        def val(x):
            k, v = x
            return env.get(v, v) if k == 'name' else v
        if a[0] == 'const' and b and b[0] == 'const' and op in '+-*/':
            r = eval(f'{a[1]} {op} {b[1]}')   # 演示用；真实编译器用常量求值器
            env[dst] = r
            out.append((dst, 'const', r, None))
        else:
            out.append((dst, op, a, b))
    return out

show(constfold(before), '常量折叠后')
print('→ 与 LLVM `opt -passes=constprop` 的动作同类：能算的提前算掉。')
# ---- 例 2：把"逐个 pass"的思路落到自己的编译器上（可复现、无依赖）----
PASSES = [('常量折叠', constfold)]

def run_pipeline(ir, passes=PASSES):
    """每跑一个 pass 就打印一次 —— 相当于 opt -print-after-all 的教学版"""
    cur = ir
    for name, fn in passes:
        cur = fn(cur)
        print(f'== after {name} ==')
        for ins in cur: print('   ', ins)
    return cur

final = run_pipeline(before)
print('最终 IR 行数:', len(final))
# ---- 例 3：一个可复用的观察脚本（存成 observe.sh）----
#!/usr/bin/env bash
set -euo pipefail
SRC="${1:?用法: ./observe.sh demo.c}"
BASE="${SRC%.*}"
clang -O0 -S -emit-llvm "$SRC" -o "$BASE.O0.ll"
clang -O2 -S -emit-llvm "$SRC" -o "$BASE.O2.ll"
echo "== IR 行数：O0 vs O2 =="
wc -l "$BASE.O0.ll" "$BASE.O2.ll"
echo "== 只看指令（去掉注释与空行）后的差异摘要 =="
diff <(grep -cE '^\s+[a-z]' "$BASE.O0.ll") <(grep -cE '^\s+[a-z]' "$BASE.O2.ll") || true
echo "== 逐 pass 打印（只看前 80 行，避免刷屏）=="
opt -O2 -print-after-all -S "$BASE.O0.ll" -o /dev/null 2>&1 | head -80
# ---- 例 4：安装 LLVM（按平台）----
# macOS:  brew install llvm   （可执行文件在 $(brew --prefix llvm)/bin）
# Ubuntu: sudo apt update && sudo apt install -y llvm clang
# Windows: 建议用 WSL 后按 Ubuntu 安装；或用 https://releases.llvm.org/ 的预编译包
# 验证：clang --version && opt --version && lli --version

三、练习#

  1. 动手：写一个 C 函数 int f(int a, int b) { int s = a + b; return s * s; }，分别导出 -O0 与 -O2 的 IR，列出 O2 至少三处改动并解释每一处的目的。
  2. 调试：用 opt -print-after-all 找到"把 alloca 变成 SSA 寄存器"的那个 pass，并说明它为什么必须早于大多数算术优化。
  3. 验证：给例 1 的 constfold 补一个"死代码消除"pass（删除结果从未被使用的指令），并用两组输入验证改造前后程序输出一致。
  4. 思考：为什么"优化后更快"不能作为正确性证据？举一个"优化破坏了语义但基准测试更快"的例子（提示：浮点重结合、整数溢出）。
