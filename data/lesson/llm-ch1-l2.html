三大范式#

上一课我们知道了 LLM 的"大"与"预测下一个词"。这一课把镜头拉远，看 NLP 在近十年里做任务的思路发生了怎样的根本转变。业界普遍把这段历史概括为三大范式：① 全监督学习、② 预训练 + 微调、③ 预训练 + 提示 + 预测。理解这个演进，你才能看懂 GPT、BERT 各处在哪个位置，以及为什么 ChatGPT 能"一个模型打天下"。

一、概念讲解#

1. 范式一：一个任务，一个模型，一批标注#

深度学习普及之前（以及早期的神经网络时代），做 NLP 任务的标准流程是全监督学习：为每个任务单独收集标注数据，单独训练一个模型。做情感分类就标几万条正负样本练一个分类器，做命名实体识别就再标一批、再练一个模型。

这种方式的问题很直接：标注昂贵、模型无法复用、数据不足时容易过拟合。每个任务都从零开始，模型学到的"语言知识"被锁死在单个任务里，换一个任务就作废。这一时期，模型与任务是一对一的。

2. 范式二：预训练 + 微调（Pretrain + Fine-tune）#

范式二的核心思想是先学通用语言，再适配具体任务，分两步：

  1. 预训练（pre-train）：在海量无标注文本上，用一个自监督目标训练一个"通用语言模型"。目标不需要人工标注——GPT 用"预测下一个词"，BERT 用"挖掉词再填空"（第 3 章会细讲掩码语言模型）。
  2. 微调（fine-tune）：把预训练好的模型作为起点，接上一个任务相关的输出头，再用少量任务标注数据继续训练整个模型（或部分参数）。

这样，语言知识只学一次，之后每个任务只需很少的标注数据就能快速适配。BERT（2018）与 GPT-1（2018）把这条路线带火：BERT 在分类、问答、命名实体识别等任务上刷新榜单，靠的就是"一个预训练模型 + 各任务一个微调头"。模型与任务的关系，从"一对一"变成"一对多"（一个底座、多个副本）。

3. 范式三：预训练 + 提示 + 预测（Pretrain + Prompt + Predict）#

范式二仍有痛点：每个下游任务还是要收集标注数据、还是要微调出一份独立的模型副本。GPT-3（2020）展示了第三条路：模型足够大之后，根本不用改参数，只要在输入里用提示（prompt）把任务"说"出来，模型就能直接完成：

  • 零样本（zero-shot）：只给任务描述，如 "把这句话翻译成英文：今天天气很好"；
  • 少样本（few-shot）：再附上几个"输入 → 输出"示例，模型照葫芦画瓢，如给两三条翻译示例后直接问新的句子。

这被称为上下文学习（in-context learning）：模型在推理时"临时"从提示里的示例学习，参数一动不动。至此，模型与任务的关系变成"一个模型，多种任务"，任务从"训练目标"变成了"自然语言描述"。这也正是 ChatGPT 等对话模型的工作方式——你用提示词指挥同一个模型做翻译、写作、编程、分析。

4. 三大范式的关键区别#

维度 范式一：全监督 范式二：预训练 + 微调 范式三：预训练 + 提示
是否需要大规模标注 每个任务都要 只需少量微调数据 几乎不需要
模型与任务的关系 一任务一模型 一底座多副本 一模型多任务
调整模型参数？ 从头训练 微调 不调整
代表 传统 SVM/RNN 分类器 BERT、GPT-1 GPT-3、ChatGPT

需要强调的是，三种范式不是"新范式完全取代旧范式"：范式二至今仍是 BERT 类判别式任务的主流做法，范式三在生成式大模型上大放异彩，二者长期并存，各有适用场景。

5. 为什么"提示"能成立：规模是关键前提#

范式三能成立，前提是模型足够大。小模型里的 few-shot 提示往往不如微调；只有当参数、数据达到一定规模后，模型才学会"把示例当作临时任务指令"来执行。这也是为什么 GPT-2 尝试零样本迁移效果平平，而 GPT-3 用 1750 亿参数才把 few-shot 推上舞台中央。规模、范式、能力三者，在第 3 课的缩放定律里会被串成一条完整的因果链。

二、可运行代码示例#

用 Hugging Face 分别演示三种范式，体会"任务是怎么被交给模型"的变化。

from transformers import pipeline

# —— 范式一/二：一个已经为某个任务"微调好"的模型，直接接任务 ——
# 这个 sentiment-analysis 管道，内部是一个在情感分类数据上微调过的模型
classifier = pipeline("sentiment-analysis")
print("范式二（微调好的模型，固定任务）:")
print(classifier("I absolutely love this course!"))
print(classifier("This is the worst experience ever."))

上面这段背后是范式二：一个预训练底座 + 一个情感分类头，微调之后专门做"正/负情感"这一件事。换一个任务，就得换一个微调好的模型。

from transformers import pipeline

# —— 范式三：同一个生成模型，用提示词"现场"换任务，参数不动 ——
generator = pipeline("text-generation", model="sshleifer/tiny-gpt2")

# 零样本：只给任务描述，不给示例
zero_shot = generator("Translate to English: 猫在垫子上\n", max_new_tokens=20)
print("范式三（零样本提示）:")
print(zero_shot[0]["generated_text"])

# 少样本：先给几条"输入 -> 输出"示例，再问新问题
few_shot_prompt = (
    "Translate Chinese to English.\n"
    "狗 -> dog\n"
    "猫 -> cat\n"
    "房子 ->"
)
few_shot = generator(few_shot_prompt, max_new_tokens=10)
print("\n范式三（少样本提示）:")
print(few_shot[0]["generated_text"])

关键区别一目了然：范式二里，任务是被"微调"固化进权重的，同一个模型只能做它被训练的那件事；范式三里，同一个生成模型只是换了提示词，就能尝试翻译、续写等不同任务，模型参数一次都没动。当然 tiny-gpt2 很小，效果不稳定，这恰恰印证了"范式三依赖规模"。

三、练习#

  1. 把上面 zero-shot 的提示词改成 "Summarize: <一段英文>"，观察 tiny-gpt2 的输出，解释为什么小模型做不好这件事，而 GPT-3 级别的大模型可以。
  2. 用 sentiment-analysis 管道测试三条中文句子，观察它的表现，并思考：这个模型的"能力边界"是谁决定的（预训练语料？微调数据？）。
  3. 手写一个 build_few_shot_prompt(examples, query) 函数，把"示例列表 + 新问题"拼成范式三的提示文本，要求示例和问题都带清晰的"输入 -> 输出"格式。
  4. 思考题：如果你的任务有 10 万条标注数据，你会选范式二还是范式三？如果只有 50 条呢？说明理由。
