多机故障与降级：慢节点、链路抖动、超时重试与 SLO 概率模型#

这一节要解决什么#

前三节的所有量 —— α、β、ρ、sbw​、Unet​ —— 都是期望值。但多机系统的真实体验由尾部决定：

一次 all-reduce 的期望耗时 14 µs，但 N=1024 个 rank 的同步屏障要等最慢的那个：
  每 rank 服务时间：中位 1 ms、p99 5 ms
  → E[max] = 9.76 ms（N=1024），白丢 89.8% 吞吐
一次跨机消息的期望延迟 2 µs，但重尾分布下 p99 可能是 5 ms：
  → 一个 token 要穿过 4096 条通信链路，任一跳超时就算违反 TPOT
  → 单跳 1% 的违反率，整 token 的违反率 = 1-(1-0.01)^4096 ≈ 1

这两条是本节的全部内容。 它们有一个共同的结构：单点的"小概率"会被"数量"放大成"必然"。

本节的四件事：

  1. 慢节点 = 次序统计量。同步算法的耗时是 maxi​Ti​，所以要用 E[maxi​Ti​] 而不是 E[T]。给出对数正态下的完整数值、可复核的近似式，以及"N 翻倍时 max 涨多少"的答案。
  2. 链路抖动的两种尾部。对数正态（指数尾）与 Pareto（幂律尾）在同一个 q(5ms)=1% 起点下，要满足同一个 1% 的端到端目标，所需 τ 差 19.5 倍（62.57 ms vs 1.220 s）。重尾让你无法用超时买确定性。
  3. 超时与重试的两条账。P(违反)=1−(1−q)n（消息条数 n 是放大器）与"额外重试流量 ≤ 容量余量"（重试风暴的判据）。
  4. 冗余、故障域与降级。独立假设下 R=3 是 10−6/请求，但 30% 相关故障域把它顶到 0.30；降级后每副本负载 ρ′=λ/((R−1)μ) —— ρ′>1 时降级不是变慢，是排队发散。

一、慢节点：同步屏障下的次序统计量#

1.1 为什么必须用 E[max] 而不是 E[T]#

环形全归约的每一步都要等所有参与的 rank。所以单步耗时是

Tstep​=i=1..Nmax​(αhop(i)​+βhop(i)​S/N​+ϵi​)

其中 ϵi​ 是每个 rank 的抖动（kernel 启动、NUMA、邻居干扰、其他租户）。关键结构：max 不是平均，而是极值统计。对 N 个独立同分布样本：

Fmax​(x)=F(x)N ⟹ xp​(max)=F−1(p1/N)

这一个式子就是"慢节点"的全部数学。 它告诉我们三件事：

  1. max 的分布只由 F 的尾部与 N 决定，与 F 的主体无关。
  2. 中位数 max 满足 F(x0.5​)=0.51/N —— 即"单个 rank 的 0.51/N 分位"。N 越大，这个分位越靠尾部。
  3. 绝对增长取决于尾部的陡峭度：尾部越重（σ 越大），max 涨得越快。

median(max)≈exp(μ+σ2lnN​),E[max]≈exp(μ+2σ2​+σ2lnN​)

重尾分布下，"最大值随 logN 增长"是错的；正确的是 exp(σ2lnN​)​

为什么这条区分重要：如果按"logN 增长"估，N 从 1024 涨到 106 只会让 max 涨 2 倍（lnN 涨约 2 倍）；按 exp(σ2lnN​) 估则会涨 e0.69×(27.6​−13.9​)=e0.69×1.53=2.9 倍。后者才对，而随着 σ 增大（集群越不均匀）差距继续拉大。

两处关键结论：

  1. 相对伤害恒为 s（不随 N 变），但绝对伤害 ∝(N−1)。所以：
    • 对延迟（步骤更少的树形/递归倍增），慢节点的伤害小 O(N/logN) 倍；
    • 对吞吐（同步屏障），慢节点的伤害与步数无关，直接是 1/s。
  2. 这解释了一个常见工程现象：换树形算法后"慢节点的问题变轻了" —— 不是因为慢节点变快了，而是因为它被等的次数少了（2(N−1)→2⌈log2​N⌉）。

治理慢节点有两条路：把 max 变小（s↓），或把max 被等的次数变少（步数↓）​

第二条路更便宜：不需要换硬件，只需要换算法（NCCL_ALGO=Tree）或分层。

1.4 边界：什么时候这个模型不成立#

假设 什么时候不成立 后果
各 rank 独立 同一机架/同一交换机/同一供电的 rank 相关 max 的尾部更厚（相关时有效 N 变小但尾部更重）
抖动是静态的 抖动来自邻居租户，随时间变化 单次测量无代表性，需要时间序列
同步屏障 用异步/冗余策略 max 被 logN 阶的"最快 K 个"取代
服务时间同分布 异构集群（新老卡混布） 引入一个确定性的偏移，max 直接由最慢型号决定

最后一行是最常见的真实情形：异构集群里 max 不是统计问题，而是"哪张卡是最老的那张"。判据：如果 σ型号间​>σ抖动​，那么先解决型号混布（把同型号聚在一起），再谈统计。

二、链路抖动：两种尾部，两个世界#

2.1 为什么要区分尾型#

单次跨机消息的延迟分布不是一个"均值 + 方差"就够的。同一份数据在不同假设下会给出完全不同的超时设计。用两个族：

对数正态:Pr[X>τ]=1−Φ(σlnτ−μ​)(指数尾)

Pareto:Pr[X>τ]=(τxm​​)α(幂律尾)

两种尾的物理来源不同：

尾型 来源 例子
指数尾（对数正态） 多个独立小因素相乘 排队延迟、kernel 抖动、NUMA
幂律尾（Pareto） 偶发的大事件、重试链、拥塞崩溃 交换机微突发、ECN 触发、路由震荡

2.3 端到端：n 条链路把 1% 放大成必然#

一个 token 要穿过很多条通信链路。任一跳超时，这个 token 就违反 TPOT（工程上更常见的是"整批被拖慢"）：

P(违反)=1−(1−q(τ))n​

n 是消息条数（第 2 节的 2L× 步数），不是"层数"。程序输出（Pareto α=1.4）：

在 n 条链路的串联里，单跳的慢改善会被 n 完全吃掉：必须把 q 按数量级降，而不是按倍数降​

2.4 边界：τ 不能无限大#

τ 越大，SLO 越好，但有两个代价：

  1. 故障检测变慢：τ 是"判定某跳坏了"的阈值。τ=1.2 s 意味着一个坏节点要 1.2 秒才被发现，期间的请求全部踩在它上面。
  2. 重试风暴：这是下节的主题。τ 长 → 单次尝试占用时间变长 → 同一时刻在飞的请求变多 → 容量被吃掉。

最优 τ:负（τ 大更好）∂τ∂​[P(违反)]​​ + 正（τ 大更差）∂τ∂​[超时占用的容量]​​=0

这个平衡点通常不能闭式解，只能数值扫（这也是为什么真实系统用"τ + 自适应"而不是固定值）。

三、超时与重试的两条账#

3.1 第一条账：重试的期望尝试次数#

设每次尝试独立地以 pfail​ 失败，允许最多 k 次重试。期望总尝试次数：

E[attempts]=i=0∑k​pfaili​=1−pfail​1−pfailk+1​​

放大系数是它减去 1（第一次尝试本来就要发）：

额外流量比例=pfail​+pfail2​+⋯+pfailk​/ 1

pfail​=0.05、k=4 时：

E[attempts]=1+0.05+0.0025+⋯≈1.0526 ⟹ 额外 5.26%

注意这个数字与"pfail​=5%、允许 4 次重试"的直觉不同：不是 5%×4=20%，而是 5.26%。因为高次重试的贡献是几何衰减的。

3.2 第二条账：重试安全判据#

重试安全⟺额外尝试率λ⋅(E[attempts]−1)​​ ≤ 容量余量λ⋅βmargin​​​​

  2. k 从 1 涨到 4，额外流量只从 5.00% 涨到 5.26%。 所以"允许更多重试"几乎不增加流量 —— 因为 pfail2​ 已经很小。真正的风险不在重试次数，而在 pfail​ 本身。
  3. pfail​ 的上界由余量反解：余量 5% 时 pfailmax​≈4.76%（k=4），余量 30% 时是 23.13%。这是"τ 能取多小"的直接约束 —— 因为 pfail​ 就是"被超时误判的比例"：

pfail​≈q(τ)⋅n(小 q) ⟹ τ 的下界由余量决定

  1. 重试风暴的临界形态：一旦额外流量超过余量，队列开始积压 → 延迟上升 → 更多超时 → 更多重试 → 正反馈。这就是"重试风暴"的数学形式：

∂τ∂λretry​​<0,∂λtotal​∂q​>0 ⟹ 两个负反馈耦合出正反馈

唯一的工程解法是"重试预算"（retry budget / circuit breaker）：限制重试流量占总流量的比例（比如 10%），超出就停止重试并直接失败。概率模型给的是这个预算的数值，不是"要不要限"的判断。

四、冗余、故障域与降级#

4.1 冗余的错误算法与正确算法#

错误算法（独立假设）：

pfail​(R)=punitR​

punit​=1%、R=3 → 10−6/请求。这个数字是错的，因为它假设三个副本的故障独立。真实故障域是共享的：

正确算法（带相关故障域）：

pfail​(R)=(1−c)⋅punitR​+c​

其中 c 是"故障域事件"（整机架掉电、交换机重启、K8s 节点驱逐）发生的概率 —— 这种情况下所有副本一起失效，与 R 无关。

4.2 降级：必须走排队模型#

"降级"不是"少做点事"，而是"把负载转移到更少的资源上"。 所以判据不是可用性，而是排队稳定性：

ρ=Rμλ​ （正常态）,ρ′=(R−1)μλ​ （降级态）

ρ′≥1⟺λ≥(R−1)μ⟺降级后排队发散（不是变慢，是崩）​

多机故障与降级：慢节点、链路抖动、超时与重试、冗余/降级对 SLO 的影响
（只用 Python 标准库）。

设计决策：
  1. **同步算法的耗时由最慢的参与者决定**，这是一切故障分析的起点。
     "平均带宽掉了 10%"这类指标对环形/树形集合通信是**无关**的；
     相关的是 max(rank) 的分布，也就是次序统计量（正文 §1）。
  2. **超时与重试不是两个参数，而是一条曲线上的两个点**：
     超时短 → 尾部被砍掉（SLO 好），但误判多 → 重试流量涨 → 容量被吃掉。
     判定"重试是否安全"必须与容量余量挂钩（不等式 extra ≤ margin）。
  3. **冗余的概率模型要带相关性**：独立假设下 3 副本的失败概率是 10⁻⁶，
     真实故障域（同机架/同交换机/同供电）把它拉到 10⁻¹ 量级。
     这一节的算例就是为了让"独立"这个假设的代价可见（正文 §4.1）。
  4. **降级不是"少做点事"，而是把负载转移到更少的资源上**，
     因此必须用排队模型判断"降级后还能不能进 SLO"——这是本节与
     单纯"可靠性计算"的分界（正文 §4.2）。
"""
from math import sqrt, exp, log, ceil, erf

SEC_PER_MONTH = 30 * 24 * 3600
SEC_PER_YEAR = 365 * 24 * 3600


# ==================== (1) 指数/对数正态/帕累托的尾部 ====================
def norm_cdf(x):
    return 0.5 * (1.0 + erf(x / sqrt(2.0)))


def norm_ppf(p):
    """标准正态分位函数（Acklam 有理逼近 + 一次 Halley 修正，误差 <1e-9）。"""
    if p <= 0.0:
        return float("-inf")
    if p >= 1.0:
        return float("inf")
    a = [-3.969683028665376e+01, 2.209460984245205e+02, -2.759285104469687e+02,
         1.383577518672690e+02, -3.066479806614716e+01, 2.506628277459239e+00]
    b = [-5.447609879822406e+01, 1.615858368580409e+02, -1.556989798598866e+02,
         6.680131188771972e+01, -1.328068155288572e+01]
    c = [-7.784894002430293e-03, -3.223964580411365e-01, -2.400758277161838e+00,
         -2.549732539343734e+00, 4.374664141464968e+00, 2.938163982698783e+00]
    d = [7.784695709041462e-03, 3.224671290700398e-01, 2.445134137142996e+00,
         3.754408661907416e+00]
    plow, phigh = 0.02425, 1 - 0.02425
    if p < plow:
        q = sqrt(-2 * log(p))
        x = (((((c[0]*q+c[1])*q+c[2])*q+c[3])*q+c[4])*q+c[5]) / \
            ((((d[0]*q+d[1])*q+d[2])*q+d[3])*q+1)
    elif p > phigh:
        q = sqrt(-2 * log(1 - p))
        x = -(((((c[0]*q+c[1])*q+c[2])*q+c[3])*q+c[4])*q+c[5]) / \
            ((((d[0]*q+d[1])*q+d[2])*q+d[3])*q+1)
    else:
        q = p - 0.5
        r = q * q
        x = (((((a[0]*r+a[1])*r+a[2])*r+a[3])*r+a[4])*r+a[5])*q / \
            (((((b[0]*r+b[1])*r+b[2])*r+b[3])*r+b[4])*r+1)
    e = norm_cdf(x) - p
    u = e * sqrt(2 * 3.141592653589793) * exp(x * x / 2)
    return x - u / (1 + x * u / 2)


def pareto_tail(x, x_m, alpha):
    """Pareto(x_m, α)：P(X > x) = (x_m/x)^α（x ≥ x_m）。重尾，α 越小越重。"""
    if x <= x_m:
        return 1.0
    return (x_m / x) ** alpha


def lognormal_tail(x, mu, sigma):
    """对数正态：P(X > x) = 1 − Φ((ln x − μ)/σ)。"""
    if x <= 0:
        return 1.0
    return 1.0 - norm_cdf((log(x) - mu) / sigma)


def lognormal_params_from_median_p99(median, p99):
    """由"中位数 + p99 两个观测量"反解 (μ, σ) —— 这是唯一可测的口径。"""
    mu = log(median)
    sigma = (log(p99) - mu) / norm_ppf(0.99)
    return mu, sigma


# ==================== (2) 慢节点：同步屏障下的吞吐损失 ====================
def max_order_statistic(n, cdf_inv, p):
    """
    n 个独立同分布样本的最大值的 p 分位：F_max(x)=F(x)^n ⇒ x = F⁻¹(p^{1/n})。
    cdf_inv 是分位函数。这一个式子就是"慢节点"的全部数学。
    """
    return cdf_inv(p ** (1.0 / n))


def lognormal_ppf_factory(mu, sigma):
    return lambda p: exp(mu + sigma * norm_ppf(p))


def expected_max_lognormal(n, mu, sigma):
    """
    E[max] 的数值积分：对分位函数在 (0,1) 上取 2000 个中点求和。
    比解析近似 μ+σ√(2 ln n) 更可靠 —— 那个近似在 σ 较大时高估明显。
    """
    tot = 0.0
    K = 2000
    for i in range(K):
        p = (i + 0.5) / K
        tot += max_order_statistic(n, lognormal_ppf_factory(mu, sigma), p)
    return tot / K


# ==================== (3) 超时、重试与重试风暴 ====================
def slo_violation_chain(n_hops, tail_fn, tau):
    """
    一个 token 要穿过 n_hops 条链路；任一跳 > τ 就算违反 TPOT。
      单跳 q(τ) = tail_fn(τ)；整 token P = 1 − (1−q)^n_hops
    """
    q = tail_fn(tau)
    return q, 1.0 - (1.0 - q) ** n_hops


def tau_for_target(n_hops, tail_fn, target, lo=1e-9, hi=60.0, iters=300):
    """二分求满足 P(违反) ≤ target 的最小 τ（上界给到 60 s，避免击穿）。"""
    for _ in range(iters):
        mid = (lo + hi) / 2
        _, P = slo_violation_chain(n_hops, tail_fn, mid)
        if P > target:
            lo = mid
        else:
            hi = mid
    return hi


def retry_load(attempts_per_sec, p_fail, max_retries):
    """
    允许 max_retries 次重试时的**额外尝试率**与总尝试率放大系数。
      期望总尝试次数 = Σ_{i=0}^{max} p_fail^i = (1−p^{k+1})/(1−p)
    """
    e_attempts = sum(p_fail ** i for i in range(max_retries + 1))
    return attempts_per_sec * (e_attempts - 1), e_attempts


def retry_storm_safe(attempts_per_sec, p_fail, max_retries, capacity_margin_frac):
    """
    重试安全判据：额外尝试率 ≤ 容量余量。
    返回 (是否安全, 额外尝试率, 余量, 允许的最大 p_fail, 放大系数)。
    """
    extra, amp = retry_load(attempts_per_sec, p_fail, max_retries)
    margin = attempts_per_sec * capacity_margin_frac
    lo, hi = 0.0, 1.0
    for _ in range(200):
        mid = (lo + hi) / 2
        e = sum(mid ** i for i in range(max_retries + 1)) - 1
        if e * attempts_per_sec > margin:
            hi = mid
        else:
            lo = mid
    return extra <= margin, extra, margin, lo, amp


# ==================== (4) 冗余、故障域与降级 ====================
def redundancy_fail(R, p_fail_unit, independent=True, correlated_frac=0.0):
    """
    - 独立：一个请求失败 ⇔ R 个副本全失败 → p^R
    - 相关：以 correlated_frac 的概率发生"故障域事件"（整机架/交换机）
            此时该域内所有副本一起失效 → p = c + (1−c)·p^R
    返回 (每请求失败概率, 折算的年不可用秒数)。
    """
    if independent or correlated_frac <= 0.0:
        p = p_fail_unit ** R
    else:
        p = correlated_frac + (1.0 - correlated_frac) * p_fail_unit ** R
    return p, p * SEC_PER_YEAR


def failover_capacity(lam, mu, R, rho_target=0.6, rho_max=0.9):
    """
    降级可行性：正常态每副本 ρ = λ/(Rμ)；一个副本失效后每副本 ρ' = λ/((R−1)μ)。
    返回 (ρ, ρ', 降级后是否还能进延迟 SLO)。
    """
    rho = lam / (R * mu)
    rho_deg = lam / ((R - 1) * mu) if R > 1 else float("inf")
    return rho, rho_deg, rho_deg <= rho_max


def mm1_tail(base_service_s, rho, q=0.99):
    """
    M/M/1 的 q 分位延迟：−ln(1−q)·(1/μ)/(1−ρ)（指数服务 + FIFO）。
    ρ → 1 时发散 —— 这就是"降级后为什么进不了 SLO"的全部原因。
    """
    if rho >= 1.0:
        return float("inf")
    return -log(1 - q) * base_service_s / (1.0 - rho)


def replicas_for_availability(lam, mu, rho_target=0.6, failures=1):
    """
    要扛住 `failures` 个副本同时失效，最少需要几个副本（容量判据）：
        R ≥ ⌈λ/(μ·ρ_target)⌉ + f
    """
    return int(ceil(lam / (mu * rho_target) + failures))

四处关键设计决策：

  1. lognormal_params_from_median_p99 是唯一合理的参数化方式。对数正态的 (μ,σ) 不可直接测，但"中位数 + p99"两个观测量可以（nccl-tests 的 -c 1 模式给的就是这两个量级的统计）。用一个不可测的参数去建模，是这类分析最常见的失败。
  2. expected_max_lognormal 用数值积分而不是闭式近似。经典近似 μ+σ2lnn​ 在 σ=0.69 时高估（给 13.1× 而实际 5.59×）。报告数字时要用积分值。
  3. slo_violation_chain 返回 (q, P) 两个量。只返回 P 会掩盖"P 里有 n 倍放大"这个结构 —— 而治理手段（减 n vs 降 q）完全不同。
  4. redundancy_fail 的 correlated_frac 是加法项而不是乘法项。因为故障域事件是"要么发生要么不发生"的单一事件，不是每个副本独立经历一次。把它写成乘法（c⋅pR）会完全抹掉它的危害。

小结#

  • 同步算法的耗时由 maxi​Ti​ 决定，所以必须用次序统计量：xp​(max)=F−1(p1/N)。"平均带宽掉了 10%"对环形/树形集合通信是无关指标。
  • 重尾下"最大值随 logN 增长"是错的：对数正态的 E[max]≈exp(μ+σ2lnN​)。N=2→1024 时 E[max] 涨 5.59 倍（1.75→9.76 ms），同步屏障吞吐损失从 42.7% 涨到 89.8%。
  • 慢化乘在步数上，相对伤害恒为 s、绝对伤害 ∝(N−1)。治理有两条路：把 max 变小（硬件/隔离），或把它被等的次数变少（树形 2(N−1)→2⌈log2​N⌉）。后者更便宜。
  • 尾型决定超时能不能救：同样 q(5ms)=1% 起点，同一个 1% 端到端目标，对数正态要 τ=62.57 ms、Pareto(α=1.4) 要 1.220 s（19.5 倍）。幂律尾下每 10 倍 τ 只换 10α 倍改善。
  • n 条链路把单跳概率放大成必然：P(违反)=1−(1−q)n。q=1%、n=4096 时 P≈1；τ 提到 20 ms 仍有 94.52%。4096 条消息/token（L=32、环形 N=8）下"靠超时保住尾部"不可行 —— 必须减 n。
  • 重试的期望额外流量是几何小量：pfail​=5%、允许 4 次重试只有 +5.26%（不是 20%）。风险不在重试次数，而在 pfail​ 本身；安全判据是 λ(E[attempts]−1)≤λβmargin​，反解给出 pfail​ 上界（余量 10%、k=4 时 9.09%）——这就是"重试预算"的数值。
  • 冗余必须带相关故障域：pfail​(R)=(1−c)punitR​+c。c=30% 时 R 从 1 加到 5 只把失败率从 0.307 降到 0.300 —— 相关性的下界比副本数的指数更硬，它只能靠故障域隔离（多机架/多 AZ）降低。
  • 降级必须走排队模型：ρ′=λ/((R−1)μ)，ρ′≥1 时降级不是变慢而是排队发散。λ=15000、μ=6000、R=3 时 ρ′=1.25>1 → 降级不可用（而 λ=9000、R=3 时 ρ′=0.75，p99 放大 4 倍但仍可降）。
  • 冗余的边际成本随负载下降：λ/μ=1 时加一个容错副本是 +50% 成本，λ/μ=10 时是 +6%。低利用率的服务做容错极贵。
  • 唯一能改变尾型的手段是冗余计算（hedged request）：P(min>t)=P(X>t)2，把重尾的伤害"开平方"，代价是流量翻倍 —— 判据是第 3 节的 Unet​<0.5。
  • 一句话：多机系统的可用性不是"每个部件都不坏"的乘积，而是"最慢/最坏那个"的极值；把 max、q(τ)、ρ′ 三个量算出来，SLO 就从一句承诺变成一组可验证的不等式。

本章把"网络侧"的账算完了：拓扑的层级（第 1 节）、通信的频率与重叠（第 2 节）、瓶颈的判据与放置（第 3 节）、尾部与故障的概率（第 4 节）。剩下的问题是把这些输入变成钱与容量计划：给定 SLA 与单位 token 成本，选哪一档网络、留多少冗余、把 SLO 定在哪。那属于成本核算与容量规划 —— 它需要本章的三个输入：ρ⋅sbw​（该不该扩带宽）、Nhide​（能拆到几张卡）、ρ′（降级后还进不进 SLO）。
