GPU 加速#

前面所有例子都在 CPU 上跑，规模小还能忍受。一旦模型变大、数据变多，CPU 就会慢得让人抓狂。深度学习能火起来，一大功臣就是 GPU——它有成百上千个计算核心，特别擅长做张量的并行矩阵运算。这一课教你如何在 PyTorch 里把计算搬到 GPU 上，并写出有 GPU 用 GPU、没 GPU 也能跑的代码。

一、概念讲解#

1. 为什么 GPU 更快#

神经网络里最重的计算是矩阵乘法（前向和反向传播都是它）。CPU 核心少、擅长处理复杂但串行的任务；GPU 核心极多、擅长把一个大矩阵运算拆成成千上万个简单运算同时做。训练一个中等规模的 CNN，GPU 往往能比 CPU 快几十到上百倍。

2. 设备：CPU 与 GPU 是"两片不同的土地"#

PyTorch 里，张量和模型都必须显式地放在某个设备上。CPU 和 GPU 上的张量不能直接混着运算：

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
  • torch.cuda.is_available()：判断当前机器有没有可用的 CUDA GPU；
  • torch.device("cuda") / torch.device("cpu")：表示一个设备。

判断出设备后，要做的事就三件：

  1. 模型搬过去：model = model.to(device)；
  2. 数据搬过去：x = x.to(device)、y = y.to(device)（每一批都要搬）；
  3. 模型和数据在同一个设备上，才能前向计算。

3. 加载跨设备保存的模型#

没有 GPU 的机器上加载在 GPU 上保存的权重，会报设备不匹配。解决办法是在 load_state_dict 时指定映射到 CPU：

model.load_state_dict(torch.load("model.pt", map_location="cpu"))

4. 一个通用模板#

把设备判断写进脚本开头，后面全部用 .to(device)，就能做到"同一份代码，GPU 机器上快、CPU 机器上也能跑"。这正是生产代码的标准写法。

二、可运行代码示例#

下面的脚本会在"有 GPU 用 GPU、没 GPU 用 CPU"的前提下，跑一个稍大点的矩阵运算对比。如果没有 GPU，它会明确告诉你当前在 CPU 上运行——这样代码在任何环境都不报错。

import time
import torch
import torch.nn as nn


# 1) 选择设备：有 GPU 用 GPU，没有就退回 CPU
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print("当前使用设备：", device)
if device.type == "cuda":
    print("GPU 名称：", torch.cuda.get_device_name(0))


# 2) 一个稍大的模型，搬到设备上
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(1024, 2048),
            nn.ReLU(),
            nn.Linear(2048, 1024),
            nn.ReLU(),
            nn.Linear(1024, 10),
        )

    def forward(self, x):
        return self.net(x)


model = MLP().to(device)   # 模型搬到设备

# 3) 造一批输入，也搬到设备（注意：每批数据都要 .to(device)）
x = torch.randn(256, 1024, device=device)
y = torch.randint(0, 10, (256,), device=device)

criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)


# 4) 跑几步前向+反向，记录耗时
start = time.time()
for _ in range(5):
    optimizer.zero_grad()
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
elapsed = time.time() - start
print(f"\n5 步训练耗时：{elapsed:.3f} 秒（设备：{device}）")

# 5) 验证：模型参数确实在目标设备上
print("第一层权重所在设备：", model.net[0].weight.device)
print("输入张量所在设备：", x.device)

在 GPU 机器上你会看到类似：

当前使用设备： cuda
GPU 名称： NVIDIA GeForce RTX 3060
5 步训练耗时：0.012 秒（设备：cuda）
第一层权重所在设备： cuda:0
输入张量所在设备： cuda:0

在没 GPU 的机器上则是：

当前使用设备： cpu
5 步训练耗时：0.214 秒（设备：cpu）
第一层权重所在设备： cpu
输入张量所在设备： cpu

注意两个细节：模型 model.to(device) 只需搬一次，而数据 x、y 每一批都要 .to(device)；判断 device.type == "cuda" 才调用 GPU 专属的 torch.cuda.get_device_name，避免在 CPU 机器上报错。

三、练习#

  1. 把输入 x 故意留在 CPU（device="cpu"）、模型搬到 GPU，尝试前向计算，观察报错信息，理解"设备必须一致"。
  2. 在有 GPU 的环境下，把 batch 大小从 256 逐步加到 4096，观察耗时变化；再试试 torch.set_default_device 的用法（新版 PyTorch）。
  3. 写一个函数 load_for_inference(path)，用 map_location 参数把一个 GPU 上保存的权重加载到 CPU，并打印加载成功信息。
  4. 想一想：为什么 model.to(device) 不需要写回 model = model.to(device) 也能生效（提示：nn.Module.to 是原地修改并返回自身）？而 x.to(device) 通常需要重新赋值？
