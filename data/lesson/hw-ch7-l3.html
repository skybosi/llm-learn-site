成本估算与选型决策#

规格看懂了、方案也知道了，最后一步是把所有东西换算成同一个尺度——钱，再做决定。学完本课，你应当能估算"每百万 token 的成本"，算出"买设备 vs 租云"的盈亏平衡点，并掌握一套可复用的选型决策框架。

一、概念讲解#

1. 统一的成本尺度：每百万 token#

模型服务最实用的成本单位是每百万 token 的成本（元或美元）。它把硬件、电费、租金统统折算到"生成 100 万 token 花多少钱"，让不同方案可以直接比较。核心换算链是：

每小时成本÷(每秒 token×3600)×106=每百万 token 成本

其中"每小时成本"可以是云租金，也可以是自购设备的折旧 + 电费 + 运维。

2. 租云的成本#

租云最简单：查实例每小时单价，再结合实测或估算的吞吐（tokens/s），套上面的公式即可。注意几个影响价格的因素：

  • 按需 vs 竞价（spot）：竞价可便宜一半甚至更多，但有被回收风险；
  • 利用率：租了 8 卡却只用到 2 卡，等于给闲置卡白付钱；
  • 吞吐与批量的关系：批量越大吞吐越高（单位成本越低），但要牺牲延迟。

3. 自购的总拥有成本（TCO）#

自购一台设备，成本不是"卡价"那么简单，还要摊进：

  • 硬件折旧：把整机价格平摊到使用寿命（如 3 年）；
  • 电费：GPU 满载功耗 × 运行时长 × 电价；
  • 运维：机房/散热/人工，个人场景可忽略。

自购的隐性收益是：没有每小时租金，设备闲着不花钱，长期高频使用能大幅摊薄单位成本。

4. 盈亏平衡点#

"买"和"租"谁划算，取决于你有多久、多频繁地用。设云时价 $c/小时，自购设备总价 $P、寿命 T 小时，忽略电费运维，则自购等效每小时成本为 P/T。两者相等时的总使用时长就是盈亏平衡点：

t∗=cP​

t∗=cP​

用得比 t∗ 久，买更划算；用得少，租更划算。再加上电费、设备贬值、算力迭代等因素，实际决策还要再打些余量。

二、可运行示例#

用纯 Python 做三件事：算每百万 token 成本、算盈亏平衡点、按"使用时长"给出选型建议。

# -*- coding: utf-8 -*-
# 成本估算与选型决策：统一折算到"每百万 token 成本"

def cost_per_million_tokens(hourly_cost, tokens_per_sec):
    """每小时成本 / 每秒token / 3600 × 1e6 = 每百万 token 成本。"""
    return hourly_cost / (tokens_per_sec * 3600) * 1e6

def decode_throughput(bandwidth_gb_s, params, bytes_per_param=2):
    """访存密集近似：吞吐 ≈ 带宽 / 每 token 需读权重字节数。"""
    return bandwidth_gb_s * 1e9 / (params * bytes_per_param)

# —— 方案 A：租云（按需 H100，参考价 $2.5/h，跑 7B）——
tps_cloud = decode_throughput(3350, 7e9)
cost_cloud = cost_per_million_tokens(2.5, tps_cloud)
print(f"方案 A 租 H100 跑 7B：吞吐 {tps_cloud:.0f} tok/s，成本 ${cost_cloud:.2f}/百万token")

# —— 方案 B：自购 Mac（约 $4000，3 年折旧 + 电费估算）——
mac_price = 4000.0
mac_life_hours = 3 * 365 * 24
mac_power_w = 200                # 满载约 200W（估）
mac_elec_price = 0.15            # 美元/度
mac_hourly = mac_price / mac_life_hours + mac_power_w / 1000 * mac_elec_price
tps_mac = decode_throughput(800, 7e9)
cost_mac = cost_per_million_tokens(mac_hourly, tps_mac)
print(f"方案 B 自购 Mac（约$4000）跑 7B：吞吐 {tps_mac:.0f} tok/s，成本 ${cost_mac:.2f}/百万token")

# —— 盈亏平衡：自购 Mac vs 租 H100，用多久回本？——
print("\n盈亏平衡分析（自购 Mac vs 租 H100）：")
# 每月的使用小时数从少到多扫描
monthly_hours = [10, 40, 100, 200, 400, 730]
for h in monthly_hours:
    cloud_month = 2.5 * h                       # 云：按小时付
    mac_month = (mac_price / (3 * 12)) + (mac_power_w / 1000 * mac_elec_price) * h  # Mac：折旧 + 电费
    verdict = "自购划算" if mac_month < cloud_month else "租云划算"
    print(f"  每月用 {h:>3} 小时：云 ${cloud_month:>6.0f} vs Mac ${mac_month:>6.0f} -> {verdict}")

# —— 决策建议函数 ——
def decide(monthly_hours, cloud_hourly=2.5, device_price=4000, life_months=36, power_w=200, elec=0.15):
    """按月使用时长给出建议。"""
    cloud_month = cloud_hourly * monthly_hours
    device_month = device_price / life_months + (power_w / 1000 * elec) * monthly_hours
    return ("自购", device_month) if device_month < cloud_month else ("租云", cloud_month)

print("\n选型建议汇总：")
for h in (20, 80, 300, 720):
    pick, cost = decide(h)
    print(f"  月使用 {h:>3} 小时 -> 建议「{pick}」，月成本约 ${cost:.0f}")

运行后你会发现：用得越久、越频繁，"自购"的优势越大；偶尔用一下，"租云"更省心省钱。这就是"买还是租"背后的量化逻辑。

三、练习#

  1. 手算成本：云实例 $2/小时、吞吐 100 token/s，每百万 token 成本是多少美元？
  2. 改吞吐：把云实例吞吐从 480 提到 960 token/s（比如批量化），重算每百万 token 成本，体会"吞吐翻倍、成本减半"。
  3. 加电费：把 Mac 的 mac_power_w 从 200 改成 400（或电价翻倍），观察盈亏平衡点移动，说明高电价对自购方案的影响。
  4. 换设备：把设备价改成 8000 美元、寿命改成 2 年，重跑盈亏平衡，看看"更贵的卡、更短的生命周期"会让自购变得多不划算。
  5. 思考：除了价格，选型还要考虑哪些"非金钱"因素？结合第 6 章的互连和第 5 章的显存，写一份你自己的三句话选型清单。
