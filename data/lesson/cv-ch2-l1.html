语义分割任务#

目标检测回答的是"物体在哪个框里、是什么"。但很多场景需要的不是框，而是精确到每一个像素的答案：自动驾驶要知道"路面的边界到底画在哪一条像素线上"，医学影像要标出"病灶覆盖了哪些像素"。这就是语义分割（Semantic Segmentation）。

这一课先建立任务认知：分割到底要输出什么、怎么评价、以及为什么现成的分类 CNN 不能直接拿来用——这个"为什么不能"，正是下一课 FCN 的出发点。

一、概念讲解#

1. 任务定义：给每个像素一个类别#

语义分割的输入是一张图，输出是一张同样尺寸的"类别图"——每个像素都被赋予一个类别标签（如背景、道路、行人、车辆）。注意它只管"类别"，不管"个体"：画面里有两个人站在一起，分割会把两人都标成"人"，但不区分这是两个人——区分个体那是实例分割（第三章）的事。

关键差异在于输出粒度：

  • 分类：整图 → 1 个标签；
  • 检测：整图 → 若干个框 + 标签；
  • 分割：整图 → 每个像素 1 个标签（输出尺寸与输入相同）。

2. 为什么分类 CNN 不能直接做分割#

你手上的 ResNet 是分类器：它一路卷积、池化，把空间尺寸越压越小，最后接全连接层输出类别。它天然不适合分割，原因有两个，且都致命：

  1. 全连接层破坏了空间结构：FC 把特征图"拍扁"成一个向量，空间位置信息被抹掉，而分割恰恰需要"第 (i, j) 个像素属于什么"；
  2. 下采样丢失了分辨率：VGG/ResNet 经过多次 stride=2 的池化或卷积，最终特征图可能只有输入的 1/32 大小，上面每个点对应原图 32×32 的区域——这个粒度离"逐像素"差得太远。

所以分割的核心矛盾是：既要大的感受野（靠下采样获得，用来理解"这是什么"），又要高的空间分辨率（靠上采样恢复，用来定位"在哪里"）。解决这个矛盾，就是分割网络的中心任务。

3. 评价指标：从 mAP 到 mIoU#

分割不再用框的 IoU/mAP，而是像素级的指标：

  • 像素准确率（Pixel Accuracy）：分类正确的像素占总像素的比例。它有个著名缺陷——类别极度不平衡时（背景占了 90%），全预测成背景也能拿高分；
  • mIoU（mean Intersection over Union）：对每一类分别算"预测该类与真值该类像素集合的交并比"，再对所有类取平均。它惩罚"大面积类别把小类别淹没"，是分割领域最主流的指标。

mIoU 对每一类 c 的定义：

IoUc​=预测为 c 或真值为 c 的像素数预测为 c 且真值为 c 的像素数​,mIoU=K1​c=1∑K​IoUc​

分母正是"并集"的像素版，分子是"交集"，和检测里的 IoU 是同一个思想的连续推广。

4. 常用数据集与任务的难度来源#

  • PASCAL VOC：20 类（含背景 21 类），语义分割的经典入门基准；
  • Cityscapes：城市街景，30 类（训练常用 19 类），自动驾驶领域的事实标准，标注极其精细；
  • COCO-Stuff：COCO 的"全像素标注"版本，类别更多、场景更杂。

分割的难度来自三重：逐像素的精细标注成本极高（一张 Cityscapes 图的人工标注以小时计）；类别不平衡普遍存在；边界像素天然模糊（物体边缘一个像素属于哪类，人自己都常犹豫）。

二、可运行代码示例#

下面两段代码：先从零实现 mIoU（含混淆矩阵思路），再用 torchvision 预训练的分割模型做一次推理，直观看到"逐像素输出"长什么样。

import torch
import torch.nn.functional as F

# ---------- 1) 从零实现 mIoU ----------
def mean_iou(pred, target, num_classes):
    """
    pred: (H, W) 预测类别图（整数索引）
    target: (H, W) 真值类别图
    思路：先构造混淆矩阵，矩阵元素 c[i, j] = 真值为 i 且预测为 j 的像素数。
    """
    mask = (target >= 0) & (target < num_classes)   # 忽略无效标签（如 255）
    pred = pred[mask]
    target = target[mask]
    # 把 (target, pred) 配对编码成唯一 id，再统计出现次数
    idx = target * num_classes + pred
    conf = torch.bincount(idx, minlength=num_classes * num_classes)
    conf = conf.reshape(num_classes, num_classes).float()   # 混淆矩阵
    ious = []
    for c in range(num_classes):
        tp = conf[c, c]                                    # 交集
        fn_fp = conf[c].sum() + conf[:, c].sum() - tp      # 并集 = 行和 + 列和 - 交集
        ious.append((tp / fn_fp) if fn_fp > 0 else float("nan"))
    ious = torch.tensor(ious)
    return ious.nanmean().item() if ious.numel() else 0.0   # 忽略无样本的类

torch.manual_seed(0)
H, W, K = 10, 10, 3
target = torch.randint(0, K, (H, W))      # 随机真值
pred = target.clone()
pred[0:2, 0:2] = (target[0:2, 0:2] + 1) % K   # 故意在一小块区域预测错
print(f"该示例 mIoU = {mean_iou(pred, target, K):.4f}")

# ---------- 2) 预训练分割模型推理（需 pip install torchvision） ----------
from torchvision.models.segmentation import fcn_resnet50, FCN_ResNet50_Weights

weights = FCN_ResNet50_Weights.DEFAULT
model = fcn_resnet50(weights=weights).eval()

img = torch.rand(3, 520, 520)             # 真实使用时换成 PIL 图并走 weights.transforms()
with torch.no_grad():
    out = model(img.unsqueeze(0))["out"]   # (1, 21, 520, 520)，21 是 VOC 类别数
pred_map = out.argmax(1).squeeze(0)        # 逐像素取最大概率类别
print("输出逐像素类别图形状：", tuple(pred_map.shape))
print("唯一类别数（理论上应覆盖多个类）：", pred_map.unique().numel())

第 1 段代码里"混淆矩阵"是理解 mIoU 的钥匙：矩阵第 c 行第 c 列是"预测对的像素"，行和是"真值为 c 的像素"，列和是"预测为 c 的像素"，并集就是行和 + 列和 − 对角线。

三、练习#

  1. 把 mean_iou 里的 nanmean 换成"无样本的类直接忽略并只在有样本的类上平均"，说说这两种处理在语义上的差别，以及何时会引发争议。
  2. 自己构造一个"全预测成背景"的极端例子，分别计算像素准确率和 mIoU，验证"像素准确率高但 mIoU 低"这一陷阱。
  3. 用 fcn_resnet50 对一张真实照片推理，把 pred_map 按颜色映射成一张彩色图（用 weights.meta["categories"] 的调色板），直观观察分割边界。
  4. 用一段话解释：为什么"下采样获得大感受野"与"逐像素高分辨率输出"是一对矛盾，并预判分割网络会用什么手段同时满足两者。
