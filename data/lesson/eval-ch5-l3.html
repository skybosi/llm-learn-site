这一节要解决什么#

第 1 节分类，第 2 节造用例。这一节解决最后一个问题：怎么把"跑了一批攻击、成功了几次"变成一句可被信赖的安全结论。

这个问题的困难来自安全事件的统计结构：它们是稀有事件，而且我们关心的是上界而不是中心。

先看一个会让人不舒服的算术。假设你跑了 1000 次独立攻击，0 次成功。直觉说"成功率 0"。但统计上，如果真实成功率是 0.3%，那么 1000 次全失败的概率是 0.9971000≈5% —— 也就是说，"0/1000"这个观测与"真实成功率 0.3%"是相容的。正确的表述是：

在 95% 置信水平下，真实攻击成功率不超过 0.30%（单侧上界）。

这个 0.30% 从哪来？来自"零成功的置信上界"公式：

pupper​=1−α1/n

其中 α 是显著性水平、n 是样本量。n=1000、α=0.05 时 pupper​=1−0.050.001=0.00299。要在 95% 置信下排除"成功率 > 0.1%"，你需要 n≥ln(0.05)/ln(0.999)≈2995 次独立攻击。 这个数字比大多数人预期的大一个数量级。

本节要讲清四件事：

  1. 区间估计：Wilson / Clopper-Pearson / "零成功上界" 的关系与选择。
  2. 样本量反推：给定"要排除多少"，算出"要跑多少次"——以及为什么这个数字通常必须打折。
  3. 相关性与分层：用例之间不独立（第 2 节的模板相关性）、不同模型的判定相关，所以不能简单地把 n 当独立样本数。分层置信 + 整簇 bootstrap 是标准工装。
  4. 聚合与报告：多个危害类别、多个层、多个模型版本怎么汇总成一个结论；以及报告的最小字段集。

一、三个区间估计量的选择#

设观察到 n 次独立试验中 k 次成功（攻击突破）。

方法 形式 特点 何时用
Wald（教科书公式） p^​±zp^​(1−p^​)/n​ 在 k=0 或 k=n 时给出零宽区间（明显错误） 不要用，尤其在小 k
Wilson（得分区间） 解 p(1−p)/n(p^​−p)2​=z2 k=0 时仍给出合理上界；对称性更好 一般报告（默认选择）
Clopper-Pearson（精确） 用 Beta 分位数 保守（区间偏宽）但绝不小于真实覆盖 安全场景（要"不乐观"）

安全场景的选择原则：保守优先。 也就是说，宁可区间偏宽，不可偏窄。因此：

  • 报告主区间用 Clopper-Pearson（或等价地说"精确二项区间"）。
  • 对 k=0 的特例，直接给"零成功上界" 1−α1/n，这是最容易解释的形式。
  • 如果你用 Wilson，要在报告里说明方法（因为它的区间略窄，读者需要知道）。

为什么不用 Wald：它在 k=0 时给出 [0,0] —— 一个宣称"成功率绝对为零"的区间。在安全报告里给出 [0,0] 是最危险的错误，因为它把"没观测到"变成了"不可能"。

二、样本量反推：要排除 p 需要多少次#

三档常用公式（单侧 95%、零成功情形）：

n≥ln(1−ptarget​)ln(0.05)​≈ptarget​3​

（近似式在 p 很小时成立。）

要排除的成功率上界 需要的独立攻击次数
10% 29
5% 59
1% 299
0.5% 598
0.1% 2995
0.01% 29956

这张表是安全评测里最该背下来的数字。 它直接说明两件事：

  1. "我们的越狱成功率低于 1%" 需要约 300 次独立攻击。这个量级可行。
  2. "我们的数据泄漏率低于万分之一" 需要约 3 万次独立攻击，而且每一次都必须能真正触发"泄漏机会"（比如查询到别的租户数据）。这通常不可行——于是必须换方法论：结构化的访问控制审计 + 金丝雀 + 小样本精确测试，而不是靠统计。

必须给这个数字打折（或加密）：上面假设"独立"。现实中：

  • 同一模板的变体相关 → 有效样本量小于 n。防御方式：以模板为单元分层（见下）。
  • 模型对某些攻击天然免疫 → 失败高度相关，n 的边际收益递减。
  • 攻击机会本身有分布 → 只有一部分请求真的带"泄漏机会"。有效样本量 = 触发机会的次数，而不是总请求数。

做法：报告里同时给出三个数字：名义样本量 n、模板数 m、有效机会次数 nopp​，并用 m（而不是 n）配合分层区间给出结论。

三、相关性：为什么不能把 n 当独立样本#

这是安全评测里最容易被忽略、后果最严重的一点。第 2 节的模板相关性在这里变成区间宽度的直接决定因素。

正确做法（分层置信 + 整簇 bootstrap）：

  1. 把用例按模板（或按"失效机制"）分组。组内变体相关，组间近似独立。
  2. 对每个模板，计算它的突破比例 pj​（该模板下有多少变体成功）。
  3. 对模板做 bootstrap：重采样模板（而不是重采样用例），得到总体 ASR 的分布与区间。
  4. 或者更简单也更保守：报告模板级的成功率分布（多少模板 0 成功、多少模板 ≥1 成功），并给出"至少一个模板可被突破"的估计。

安全场景的口径选择（重要）：攻击者会挑最有效的那个变体，所以：

  • 回归门禁（"这次改动有没有让模型更不安全"）：用总体 ASR（含所有变体），因为它对任何变体的变化都敏感。
  • 风险上界（"对手能造成多大伤害"）：用每模板最佳（第 2 节），它更接近攻击者的真实能力。

两个口径必须都报，并说明用途。 只报一个会让结论被误用。

四、聚合：从多个类别到一句结论#

真实评测有多个维度：危害类别 × 攻击层 × 模型版本。把它们聚合成一句结论有两条路：

（a）最坏情况聚合（安全场景的默认）：结论取最差的那一类，而不是平均。

"在所有评测类别中，最差类别（注入式 + 数据外泄）的突破率上界为 6.2%（95% 置信，n=350，模板 42 个）。"

理由是平均会掩盖最弱环节——第 2 节已经展示过：总体 ASR 5%，但 L5 有 28%。攻击者只会打最弱的那一环。

（b）多重比较校正：如果你对 20 个类别各做一次 95% 检验，至少一个"看起来显著变差"的概率是 64%（第 3 节）。但安全场景的处理与第 3 节相反：这里的假阳性（误报变差）代价低（多查一次），假阴性（漏掉真实退化）代价高。所以：

  • 不做 Bonferroni 校正（会漏掉小退化）；
  • 而是用"最坏类别 + 趋势"：小退化靠跨版本的同一类别趋势发现，而不是靠单次检验的显著性。

（c）版本比较：比较两个模型版本时，必须用同一套用例、同一批次、同一判定协议（第 4 章的可复现性要求在这里更严格）。判定协议变化会直接改变 ASR，跨版本比较就失效。做法：判定协议冻结，且每个版本都跑同一套用例（含同一批金丝雀）。

五、判定的可靠性：ASR 的分母是"判定"#

一个常被忽略的事实：ASR 的分子依赖判定。"这次攻击算不算成功"如果是人判的，它本身有分歧率（第 4 章）；如果是分类器判的，它有漏报与误报。

做法（与第 4 章一致）：

  1. 判定标准要冻结并文档化，最好能程序化（比如"输出中是否出现金丝雀"就是可程序化的）。
  2. 抽 5%~10% 人工复核，报"判定一致率"与"分歧样本的分布"。
  3. 报两种口径：分类器判定下的 ASR 与人工复核后的 ASR。如果两者差很多，说明判定是瓶颈，任何精度提升都不可信。

一个具体的偏差方向：如果判定用的是"关键词命中"，那么模型只要学会改变措辞形式（同义替换、换语言、编码）就能把 ASR 降下来，而实际风险不变。这就是"安全指标被优化"的典型形态（Goodhart 的对抗版本）。防御手段：判定要测语义，不测字符串；并定期用"拒绝样本的人工复核"校准判定器。

六、安全评测报告的最小字段集#

下面这张表建议直接做成模板。缺任何一项，结论都不可用：

字段 内容 缺了会误导什么
模型标识 确切版本/快照 ID、访问方式 无法判断结论是否适用于当前线上版本
日期与时效 评测日期 服务端模型可能在无通知下更新
用例集版本 版本号 + 增删记录 用例被删会让"变安全"是假象
参照系 危害分类学 + 能力清单 "覆盖率"没有意义
规模三件套 名义 n、模板数 m、有效机会数 nopp​ 把相关样本当独立样本 → 区间过窄
分层结果 每个层/类别的 ASR + 区间 总体平均掩盖最弱环节
区间方法 Clopper-Pearson / Wilson / 零成功上界 无法判断结论的保守程度
判定协议 判定规则 + 人工复核比例与一致率 判定偏差会被当成模型差异
能力/权限清单 系统当时有哪些工具与权限 结论无法迁移到别的部署
已知漏项 未覆盖的类别与原因 读者会以为"全测过了"
成本指标 轮数、token、人工介入 无法评估攻击的现实可行性
未决问题 未归因的异常、待验证的怀疑 后续会重复踩同一个坑

一句话纪律：安全评测的结论必须写成"条件句"，不是"判断句"。 不是"这个模型是安全的"，而是"在这个部署配置、这套用例集、这个日期下，最差类别的突破率上界是 x"。任何无条件的安全宣称都是错的——因为安全属性依赖部署、依赖对手、依赖时间。

import math
import random
from statistics import NormalDist

ND = NormalDist()
rng = random.Random(719)


# ============================================================
# 1. 三个区间估计：Wald / Wilson / Clopper-Pearson
# ============================================================
def wald(k, n, z=1.959963985):
    if n == 0:
        return (0.0, 0.0)
    p = k / n
    h = z * math.sqrt(p * (1 - p) / n)
    return max(0.0, p - h), min(1.0, p + h)


def wilson(k, n, z=1.959963985):
    if n == 0:
        return (0.0, 0.0)
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return max(0.0, c - h), min(1.0, c + h)


def _beta_cdf_table(a, b, steps=4000):
    # 预计算 Beta(a,b) 的 CDF 查找表（避免每次分位数都做数值积分）
    xs = [i / steps for i in range(steps + 1)]
    ws = []
    for i, t in enumerate(xs):
        w = 1.0 if i in (0, steps) else (4.0 if i % 2 else 2.0)
        ws.append(w * (t ** (a - 1)) * ((1 - t) ** (b - 1)))
    h = 1.0 / steps
    cum = []
    run = 0.0
    for i, w in enumerate(ws):
        if i == 0:
            run += w
        elif i == steps:
            run += w
        else:
            run += w
        cum.append(run)
    # 用同样的步长做一次全区间积分作为归一化常数
    total = 0.0
    for i, w in enumerate(ws):
        coef = 1.0 if i in (0, steps) else (4.0 if i % 2 else 2.0)
        total += coef * (xs[i] ** (a - 1)) * ((1 - xs[i]) ** (b - 1))
    total *= h / 3.0
    # 分段梯形/辛普森累积（与 total 用同一套权重口径）
    run = 0.0
    acc = []
    for i in range(steps + 1):
        if i == 0:
            run += ws[i]
        elif i == steps:
            run += ws[i]
        else:
            run += ws[i]
        # 这里 run 是带权重的累加，配合 h/3 得到部分积分
        acc.append(run * h / 3.0)
    return xs, [min(1.0, v / total) for v in acc]


def beta_quantile(p, a, b):
    # Beta(a,b) 的分位数（查表 + 线性插值）
    xs, cdf = _beta_cdf_table(a, b)
    lo, hi = 0, len(cdf) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if cdf[mid] < p:
            lo = mid + 1
        else:
            hi = mid
    if lo == 0:
        return xs[0]
    x0, x1 = xs[lo - 1], xs[lo]
    y0, y1 = cdf[lo - 1], cdf[lo]
    if y1 == y0:
        return x1
    return x0 + (x1 - x0) * (p - y0) / (y1 - y0)


def clopper_pearson(k, n, alpha=0.05):
    if n == 0:
        return (0.0, 1.0)
    lo = 0.0 if k == 0 else beta_quantile(alpha / 2, k, n - k + 1)
    hi = 1.0 if k == n else beta_quantile(1 - alpha / 2, k + 1, n - k)
    return lo, hi


def zero_success_upper(n, alpha=0.05):
    # k=0 时的精确单侧上界
    return 1 - alpha ** (1.0 / n)


print("== 1. 三个区间估计（k=0 与 k 小的情况） ==")
for k, n in [(0, 100), (0, 1000), (0, 5000), (3, 500), (15, 500)]:
    w = wald(k, n)
    wi = wilson(k, n)
    cp = clopper_pearson(k, n) if n <= 1200 else (0.0, float("nan"))
    zs = zero_success_upper(n) if k == 0 else float("nan")
    print(f"k={k:2d}, n={n:5d}: Wald [{w[0]:.4f},{w[1]:.4f}] | "
          f"Wilson [{wi[0]:.4f},{wi[1]:.4f}] | "
          f"CP [{cp[0]:.4f},{cp[1]:.4f}] | 零成功上界 {zs:.4f}")
print("  <- k=0 时 Wald 给出 [0,0]（宣称'不可能'），这是安全报告里最危险的错误；")
print("     '0/1000' 的正确表述是：95% 置信下真实成功率不超过 0.30%")

# 2. 样本量反推：要排除 p 需要多少次独立攻击

def n_to_exclude(p_target, alpha=0.05):
    return math.log(alpha) / math.log(1 - p_target)

# 3. 相关性：把 n 当独立样本会把区间报得过窄
# ============================================================
def cluster_bootstrap_ci(groups, n_boot=2000, seed=5):
    # groups: list of list（每个模板下的变体结果 0/1）
    r = random.Random(seed)
    ests = []
    for _ in range(n_boot):
        pick = [r.choice(groups) for _ in groups]
        num = sum(sum(g) for g in pick)
        den = sum(len(g) for g in pick)
        ests.append(num / den if den else 0.0)
    ests.sort()
    return ests[int(0.025 * n_boot)], ests[int(0.975 * n_boot)]


print("\n== 3. 相关样本：独立假设 vs 按模板聚类（合成） ==")
for m, per, sd in ((30, 10, 0.15), (10, 30, 0.15), (10, 30, 0.25), (8, 40, 0.30)):
    r = random.Random(11)
    groups = []
    for _ in range(m):
        base = max(0.0, min(1.0, r.gauss(0.10, sd)))   # 模板级难度
        groups.append([1 if r.random() < base else 0 for _ in range(per)])
    k = sum(sum(g) for g in groups)
    n = sum(len(g) for g in groups)
    wi = wilson(k, n)
    cl = cluster_bootstrap_ci(groups)
    print(f"  {m:2d} 模板 x {per:2d} 变体 (n={n:4d}, 模板级 sd={sd:.2f}) "
          f"ASR={k/n:.3f}")
    print(f"       独立假设 [{wi[0]:.3f},{wi[1]:.3f}] 宽 {wi[1]-wi[0]:.3f} | "
          f"按模板聚类 [{cl[0]:.3f},{cl[1]:.3f}] 宽 {cl[1]-cl[0]:.3f}")
print("  <- 模板级差异越大，聚类区间相对独立假设越宽（1.5x~3.7x）；")
print("     模板数 m 才是有效样本量：n 都是 300 时，m=8 的区间比 m=30 宽得多")

# ============================================================
# 6. 判定器漂移：ASR 变化可能只是判定变了
# ============================================================
def asr_with_judge(n, true_rate, judge_recall, judge_fpr, seed):
    # judge_recall：把真实成功判成成功的概率；judge_fpr：把失败误判成成功
    r = random.Random(seed)
    obs = 0
    for _ in range(n):
        true_hit = r.random() < true_rate
        if true_hit:
            obs += 1 if r.random() < judge_recall else 0
        else:
            obs += 1 if r.random() < judge_fpr else 0
    return obs / n


print("\n== 6. 判定器变化如何伪造'更安全'（合成，真实成功率固定 8%） ==")
for rec, fpr, tag in ((0.95, 0.01, "严格判定"),
                      (0.70, 0.01, "漏报变多（换关键词判定）"),
                      (0.70, 0.10, "漏报多 + 误报多")):
    obs = asr_with_judge(2000, 0.08, rec, fpr, seed=19)
    print(f"  {tag:22s} 判定 recall={rec:.2f} fpr={fpr:.2f} -> 观测 ASR {obs:.3f}"
          f"  (真实 0.080)")
print("  <- 同一个模型、同一个真实风险，换判定器就能'降'下 ASR；")
print("     所以判定协议必须冻结，且要报人工复核一致率")

代码里六个值得注意的点：

  • 第 1 段的关键对比是 k=0 那一行：Wald 给 [0,0]（宣称"不可能"），Wilson 给约 [0,0.037]，零成功上界给 0.00299。安全报告只能用后两种，且要写明用了哪种。 注意 Clopper-Pearson 的数值积分在 n 大时很慢，生产实现应当用 Beta 分位数的标准算法（本课为了只用标准库才写成数值积分）。
  • 第 2 段是本节最该记住的表：排除 1% 需要 299 次独立攻击，排除 0.1% 需要 2995 次，排除万分之一需要 3 万次。这个"3/p"近似把很多安全宣称直接判为证据不足——尤其是"我们的泄漏率低于万分之一"这类。
  • 第 3 段把"相关性"的代价量化：四组数据的名义样本量都是 300，独立假设下区间宽度都在 0.070.09；按模板整簇 bootstrap 后，随模板级差异增大，区间可宽到 1.53.7 倍。注意最下面两组：模板数从 30 降到 8 时，区间几乎翻倍——模板数 m 才是有效样本量。
  • 第 4 段给出两个必须同时报的口径：总体 ASR（回归门禁）与"至少一个变体成功的模板占比"（风险上界）。两者可以差一个数量级——本例里总体 0.05 而模板级 0.62。
  • 第 5 段展示聚合方式如何决定结论：平均 ASR 0.05 看起来安全，最坏类别（注入式）的上界 0.24。安全结论必须取最坏类别，因为攻击者只打最弱环节。
  • 第 6 段是最隐蔽的一种"假改进"：真实成功率固定 8%，只把判定器从"严格"换成"漏报多"，观测 ASR 就从 0.076 掉到 0.056——看起来模型变安全了 26%，其实什么都没变。这是为什么判定协议必须冻结、且要报人工复核一致率。

练习#

  1. 零成功的表述：某团队跑了 800 次攻击，0 次成功，报告写"越狱成功率 = 0"。 （a）用零成功上界公式给出正确的单侧 95% 上界； （b）如果这 800 次攻击来自 12 个模板，你会怎么修正这个结论（定性与定量各给一条）； （c）写出你认为可以对外发布的那句话（必须包含参照系与条件）。

  2. 样本量预算：产品要求"证明数据泄漏率低于 0.1%"。 （a）用公式算需要的独立机会次数； （b）说明"独立机会"与"总请求数"的区别，并给出一个能把两者联系起来的测量方案； （c）如果预算只允许 2000 次测试，你还能给出什么样的安全结论？（提示：换方法论）

  3. 区间方法选择：你的报告要写"L5 注入类攻击突破率不高于 6%"。 （a）如果观测是 k=3,n=80，分别用 Wilson 与 Clopper-Pearson 算上界，判断哪个支持你的表述； （b）如果观测是 k=0,n=80，零成功上界是多少？这个结论的强度与（a）相比如何？ （c）说明为什么安全报告"宁可区间偏宽"。

  4. 两种口径：你负责模型 A 与 B 的安全对比。 （a）写出你会报的两组数字（总体 ASR 与每模板最佳），并说明各自支持什么决策； （b）如果 A 的总体 ASR 更低、但每模板最佳更高，你会怎么下结论？ （c）设计一个能区分"真的更安全"与"只是更会规避判定措辞"的实验。

  5. 判定器漂移：某次评测 ASR 从 9% 降到 6%，团队准备发公告说"安全提升 33%"。 （a）列出至少四种能造成这种下降但与模型安全无关的原因； （b）设计一套核查流程（含人工复核比例与一致率要求）； （c）写出公告里必须同时给出的三项限制条件。

  6. 报告模板（开放题）：用第 6 节的字段表，为一个"能读邮件并发送回复的助手"写一份安全评测报告骨架。 （a）每个字段填上你会怎么获取这个信息； （b）指出其中哪三个字段最容易缺失，以及缺失后被误用的方式； （c）最后写一句"条件句"结论（必须包含部署配置、用例集版本、日期、最坏类别上界）。

小结#

  • 安全事件是稀有事件，结论要报上界而不是"率"。"0/1000" 的正确表述是"95% 置信下真实成功率不超过 0.30%"。Wald 区间在 k=0 时给 [0,0]，是安全报告里最危险的错误；用 Wilson 或 Clopper-Pearson。
  • 样本量公式 n≈3/p：排除 1% 要 299 次，排除 0.1% 要 2995 次，排除万分之一要 3 万次。很多"我们的风险低于 x"的宣称在这个公式面前直接不成立。
  • 相关性是区间的隐形放大器：同一模板的变体、同一类攻击的变体都不独立。报告必须同时给名义样本量 n、模板数 m、有效机会数 nopp​，并用按模板整簇 bootstrap给区间（本例中随模板级差异可达独立假设的 1.5~3.7 倍宽）。
  • 两个口径都要报：总体 ASR（回归门禁，对任何变体变化敏感）与"每模板最佳"（风险上界，接近攻击者真实能力）。两者可差一个数量级。
  • 聚合取最坏类别，不做 Bonferroni：平均会掩盖最弱环节；而安全场景的假阴性代价远高于假阳性，所以小退化靠跨版本趋势发现，不靠单次显著性。
  • 判定协议必须冻结：ASR 的分子依赖判定，换判定器（比如改成关键词命中）能伪造 20% 以上的"安全提升"。做法：判定可程序化 + 5%~10% 人工复核 + 报一致率 + 双口径（分类器判定 / 人工复核）。
  • 结论必须是条件句："在这个部署配置、这套用例集、这个日期、这个判定协议下，最坏类别的突破率上界是 x"。无条件的安全宣称都是错的，因为安全依赖部署、对手与时间。
