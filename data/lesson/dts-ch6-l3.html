混合精度 / FP8 训练：数值与工程要点#

上一课的两笔账（显存、算力）里，最省事的杠杆其实是"每个数用几个字节"。把 fp32 换成 16 位，显存与带宽立刻减半，矩阵乘的吞吐也往往翻倍——听起来是纯赚。但真实训练里，这一半的收益经常被两个小问题吃掉：小梯度在低精度格式里下溢成 0，以及参数更新量被低精度的尾数舍掉，训练于是静默地不再前进。这一课把这两件事的判据变成可算的数字。

一、概念讲解#

1. 两种 16 位格式：范围与精度是两笔不同的账#

计算机里的浮点数由「指数位决定范围、尾数位决定精度」两部分构成。两种 16 位格式把 16 个比特分配得完全不同：

格式 指数位 尾数位 最小规格化数 最小次正规数 机器 epsilon 有效十进制位
fp16 5 10 6.1×10−5 6.0×10−8 9.8×10−4 ≈3.0
bf16 8 7 1.2×10−38 — 7.8×10−3 ≈2.1

读法：fp16 精度高、范围窄（下限 6×10−5 量级、上限 65504）；bf16 范围与 fp32 相同（8 位指数），代价是相对精度只有 2−8≈0.4%。这也解释了为什么 bf16 训练几乎不需要损失缩放，而 fp16 不加就要崩。

2. fp16 的下溢与动态损失缩放#

若某次反向产生梯度 10−9，它在 fp16 里连最小次正规数（6.0×10−8）都不到，直接变成 0。损失缩放的机制是：把 loss 乘上 S，反向得到的梯度就整体放大 S 倍，更新前再除以 S。对 10−9 的梯度：S=28 后是 2.56×10−7（可表示），S=216 后是 6.55×10−5（落在规格化区间）。但 S 不能一味调大：fp16 上限是 65504，梯度过大时会被推成 inf。所以工程上用的是动态损失缩放——先试一个 S，一旦出现 inf/NaN 就跳过该步并把 S 减半，连续若干步无异常再把 S 翻倍。

3. 主权重（master weight）为什么必须是 fp32#

第二个陷阱更隐蔽。假设权重 w=0.1，单步更新量是 10−5：Δw 在 w 上属于第 5~6 位有效数字，而 bf16 只有约 2.1 位十进制有效数字。用"该精度下 w 附近的绝对分辨率"衡量：

  • bf16：0.1×2−7≈7.8×10−4
  • fp16：0.1×2−10≈9.8×10−5

两者都大于 10−5 的更新量——也就是说，直接把权重存在 16 位格式里，更新会被整个舍掉。混合精度的标准做法因此是：保留一份 fp32 主权重，优化器更新只作用在 fp32 副本上，每次前向再把 fp32 权重量化成 bf16/fp16 供矩阵乘使用。这就是 ZeRO 账本里那 4 B/参数"主权重"的来历。

4. 一次迭代里各张量该用什么精度#

张量 / 操作 精度 理由
前向/反向的矩阵乘输入 fp16 / bf16 吞吐与带宽的主要收益来源
矩阵乘的累加器 fp32 低精度累加会放大舍入误差
权重主副本、优化器状态（m、v） fp32 更新量比权重小好几个数量级
梯度（AllReduce 前） fp16 / bf16 通信字节数减半：第 1 课那条 2Ψ 账直接减半
归一化（LayerNorm/RMSNorm）与 loss fp32 数值敏感，低精度容易炸

注意第 4 行：混合精度同时是通信优化——梯度换成 16 位后，AllReduce 的字节数直接减半。

5. FP8：把一个张量拆成"值 + 缩放因子"#

FP8 只有 8 个比特，主流两种格式是 E4M3（4 位指数、3 位尾数，范围小而精度相对好）与 E5M2（5 位指数、2 位尾数，范围大而精度差）。8 个比特意味着单独一个数无法同时容纳大范围与小精度，所以 FP8 训练的核心工程是缩放（scaling）：per-tensor scaling（整个张量共用一个因子，实现最简单）与 per-block / per-channel scaling（张量切块、每块自己的因子，能适配"同一张量里不同通道量级差很多"）。与损失缩放同理，FP8 的缩放因子也必须动态维护，否则同样会下溢或溢出；另外梯度要用高精度累加，主权重仍留高精度，FP8 只用在张量乘的输入上。

6. 常见坑#

  • bf16 与 fp16 混着换：bf16 通常不需损失缩放，fp16 需要；混用会出现"本来好好的突然全 NaN"。
  • 关掉动态缩放只留固定 S：loss 尺度一变就溢出或下溢。
  • 在低精度里做归约/累加：AllReduce 用 fp16 传输可以，但累加要用 fp32，否则小梯度被大梯度吃掉。
  • 只看吞吐不看收敛：换 FP8 后必须对照 loss 曲线，否则可能只是"更快地训练坏了"。
  • 忽略软硬件支持前提：FP8 需要相应代际的 GPU 与框架/库支持，不具备时退到 bf16。

二、可运行代码示例#

纯 Python，不需要 GPU。第一段把两种 16 位格式的范围与损失缩放的算术打印出来，第二段说明"更新被吃掉"。

# ===== 示例：bf16 / fp16 的范围、损失缩放与更新被"吃掉"的问题 =====
print("两种 16 位格式（IEEE 754 二进制）：")
print(f"  {'格式':<6}{'指数位':>6}{'尾数位':>6}{'最小规格化数':>14}{'最小次正规数':>14}{'机器 epsilon':>14}")
for n, (e, m) in (("fp16", (5, 10)), ("bf16", (8, 7))):
    mn = 2.0 ** (1 - (2 ** (e - 1) - 1))
    print(f"  {n:<6}{e:>6}{m:>6}{mn:>14.3e}{mn * 2.0 ** -m:>14.3e}{2.0 ** (-m):>14.3e}")

def fp16_ok(x):
    """fp16 的下限取最小次正规数（6e-8 量级），上限 65504。"""
    return 6.0e-8 <= abs(x) <= 65504.0

print("\n损失缩放：loss 乘 S → 反向梯度整体放大 S 倍 → 更新前再除回 S")
g = 1e-9
for expo in (0, 8, 16, 24):
    S = 2 ** expo
    print(f"  S=2^{expo:<3} 缩放后梯度 {g*S:9.3e}  "
          f"{'可表示' if fp16_ok(g * S) else '下溢为 0'}")
print("  另一头：缩放也会把大梯度推到溢出（fp16 上限 65504），所以 S 必须动态调")

print("\n为什么 bf16 通常不需要缩放：它的指数范围与 fp32 一致（8 位指数）")
for v in (1e-30, 1e-9, 1e5, 1e30):
    print(f"  {v:>9.0e}   fp16 {'可表示' if fp16_ok(v) else '不可表示':<10}  bf16 可表示（1.2e-38 ~ 3.4e+38）")

print("\n低精度存权重时更新会被吃掉：绝对分辨率 vs 单步更新量")
for mant_bits, name in ((7, "bf16"), (10, "fp16")):
    for w, upd in ((0.1, 1e-5), (0.1, 1e-3), (1.0, 1e-4)):
        res = w * 2.0 ** (-mant_bits)
        verdict = "更新被舍掉" if res > upd else "还能表示，但有量化噪声"
        print(f"  {name:<5} w={w:<5} 单步更新 {upd:.0e}：分辨率 {res:.2e} → {verdict}")
print("  主权重留 fp32 的意义就在这里：更新量发生在 fp32 里，再量化到 bf16 做前向")

两个可以直接拿去用的判据：梯度小于 6×10−8 时 fp16 会归零（需要缩放），bf16 不需要；权重附近的绝对分辨率一旦大于单步更新量，那一维就再也学不动了（所以必须留 fp32 主权重）。

# ===== 补充：FP8 缩放的粒度与梯度累加精度（纯 Python 数值演示） =====
import math
def e4m3_round(a):
    """模拟 E4M3：尾数 3 位 → [1,2) 区间 8 个格点，可表示上限约 448。"""
    if a == 0: return 0.0
    if abs(a) > 448: a = math.copysign(448, a)
    e = math.floor(math.log2(abs(a)))
    step = 2.0 ** (e - 3)
    return math.copysign(round(abs(a) / step) * step, a)

# 一个张量里两组通道量级差 100 倍：per-tensor 缩放 vs 按块缩放
vals = []
for i in range(2048):
    scale = 1e-2 if (i // 128) % 2 == 0 else 1e-4
    vals.append(scale * (1.0 + 0.5 * ((i * 37) % 11) / 11))

def rel_err(chunk, s):
    q = [e4m3_round(v / s) * s for v in chunk]
    rms = math.sqrt(sum((a - b) ** 2 for a, b in zip(chunk, q)) / len(chunk))
    ref = math.sqrt(sum(v * v for v in chunk) / len(chunk))
    return rms / ref

print("张量内两组通道量级差 100:1，E4M3 量化后的相对误差：")
gt = max(abs(v) for v in vals)                       # per-tensor 用全局最大值
errs = [rel_err(vals[i:i + 128], gt) for i in range(0, len(vals), 128)]
print(f"  per-tensor 缩放：小通道 {sum(errs[1::2])/len(errs[1::2]):.3e}，"
      f"大通道 {sum(errs[0::2])/len(errs[0::2]):.3e}")
for blk in (128, 32):
    errs = []
    for i in range(0, len(vals), 128):
        ch = vals[i:i + 128]
        for j in range(0, len(ch), blk):
            errs.append(rel_err(ch[j:j + blk], max(abs(v) for v in ch[j:j + blk])))
    print(f"  每 {blk:>3} 元素一块：小通道 {sum(errs[1::2])/len(errs[1::2]):.3e}，"
          f"大通道 {sum(errs[0::2])/len(errs[0::2]):.3e}")

print("\n梯度累加：1000 个贡献（1 个 1.0 + 999 个 1e-5）")
contribs = [1.0] + [1e-5] * 999
print(f"  Python float（fp64 展示）：{sum(contribs):.6f}（真值 {1.0 + 999*1e-5:.6f}）")
print("  低精度累加的病根：循环里每次只加 1e-5，一旦累加器量级到 1，"
      "相对精度 0.4%（bf16）就足以把这些增量全部舍掉")

注意第二段的读数：per-block 缩放把小通道的误差从 2.66×10−2 降到 2.48×10−2——收益不大，因为 E4M3 的 3 位尾数本身就把相对误差钉在 3% 量级。这提示 FP8 精度的真正瓶颈是尾数位宽，而不是缩放粒度；缩放解决的是范围问题（溢出/下溢），不是精度问题。

三、练习#

  1. 实现：写一个函数，给定梯度幅值分布（例如对数正态取样 10 万个值），计算"需要多大的 S 才能让 99% 的梯度在 fp16 里可表示但不过 65504"，并说明为什么这个 S 只能靠动态调整。
  2. 解释：为什么 bf16 不需要损失缩放，却仍需要 fp32 主权重？分别从"指数位决定范围"与"尾数位决定精度"两条线回答。
  3. 对比/验证：把示例里的 w=0.1、更新量 10−5 换成 w=1、更新量 10−3，重新判断 bf16 与 fp16 是否"能学到"；再算一下 Adam 的一阶/二阶动量若存成 bf16 会怎样。
  4. 思考：把梯度 AllReduce 从 fp32 换成 bf16，第 1 课里的 2Ψ 通信账会变成多少？若精度带来的收益不稳定，列出两个必须做的对照实验。
