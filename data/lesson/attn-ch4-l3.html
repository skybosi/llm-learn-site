可学习位置编码#

正弦位置编码是固定的、零参数的，但它不一定是最优的——它只是论文作者选的一个"合理先验"。另一种思路彻底放开手脚：把每个位置当成一个可训练参数，让模型自己学。这就是可学习位置编码（learned positional embedding），BERT、GPT 等模型普遍采用它。这一课我们用 nn.Embedding 把它实现出来，和正弦编码做一次正面比较，并顺带看一看它的两个"升级方向"：相对位置编码和旋转位置编码（RoPE）。

一、概念讲解#

1. 把"位置"当成一张查表#

可学习位置编码的本质极其简单：准备一个形状为 (max_len, d_model) 的参数矩阵，第 pos 行就是位置 pos 的编码向量。forward 时，根据序列长度取前 seq_len 行，逐元素加到 token embedding 上。

在 PyTorch 里，这个矩阵正好就是 nn.Embedding(max_len, d_model)：nn.Embedding 内部就是一张可训练的权重表，输入位置序号就取出对应行。它和词嵌入共享同一种机制，只不过索引从"词 id"换成了"位置 id"。

带位置的输入 = token_embedding(token_ids) + pos_embedding(0, 1, ..., seq_len-1)

2. 和正弦编码的正面比较#

维度 正弦位置编码 可学习位置编码
参数 0（纯公式） max_len × d_model
是否训练 否 是，随任务端到端学习
外推能力 可外推到任意长度（公式可续算） 受 max_len 上限限制，超长会报错
相对位置 天然带"距离"信号 需靠数据学出，不保证
适配性 通用、与任务无关 能贴合具体数据分布
代表模型 原始 Transformer BERT、GPT、ViT 等

核心取舍是：正弦编码"免费"提供了外推能力和相对位置先验，但它是任务无关的固定形式；可学习编码更灵活、能拟合训练分布，但把位置信息完全交给数据，并且被 max_len 卡死。实践中，如果序列长度固定且数据充足（如 BERT 的 512 上限），可学习编码往往表现略好；如果要求处理任意长序列，正弦编码或其变体更稳妥。

3. 为什么"加法"而不是"拼接"#

和上一课练习里埋下的问题呼应：位置信息通常用加法注入，而不是把位置向量拼接在词向量后面。原因有三：

  1. 维度稳定：加法不改变 d_model，后续所有层的维度都不用动；拼接会让输入维度翻倍，第一层线性层参数随之翻倍。
  2. 信息混合由网络完成：加法的结果是"词义 + 位置"的叠加，网络靠训练学会从中分离两者；拼接则把两者硬分开，反而不利于后续交互。
  3. 惯例与兼容：加法让位置编码成为可插拔模块，换编码方案时不用改下游结构。

4. 两个升级方向（了解即可）#

  • 相对位置编码：不再给每个绝对位置一个向量，而是直接在注意力分数里加一个"只依赖相对距离 i−j"的偏置项。它天然适合长度外推，代表性工作是 Transformer-XL 与 T5 的相对位置偏置。
  • 旋转位置编码（RoPE）：把位置信息以"旋转矩阵"作用在 Query/Key 上，位置差 k 恰好对应旋转角 kθ。它既保留了正弦编码的"相对位置可线性表示"，又避免显式相加，是如今 LLM（如 LLaMA）的主流选择。可以把它理解成"正弦编码思想 + 可学习式的融合升级"。

二、可运行代码示例#

先实现一个标准的可学习位置编码，并演示它如何与词嵌入相加。

import torch
import torch.nn as nn

class LearnedPositionalEncoding(nn.Module):
    def __init__(self, max_len, d_model):
        super().__init__()
        # 一张 (max_len, d_model) 的可训练表，第 pos 行是位置 pos 的编码
        self.pos_embedding = nn.Embedding(max_len, d_model)

    def forward(self, x):
        # x: (seq_len, batch, d_model)，与 torch.nn.Transformer 的默认形状一致
        seq_len = x.shape[0]
        positions = torch.arange(seq_len, device=x.device)   # 0, 1, ..., seq_len-1
        pos = self.pos_embedding(positions)                  # (seq_len, d_model)
        return x + pos.unsqueeze(1)                          # 广播加到每个 batch 上

d_model = 16
token_emb = nn.Embedding(100, d_model)      # 词表 100 的词嵌入
pos_enc = LearnedPositionalEncoding(max_len=128, d_model=d_model)

# 一条长度为 10 的序列，batch=2
ids = torch.randint(0, 100, (10, 2))
x = token_emb(ids)                           # (10, 2, 16)
y = pos_enc(x)                               # (10, 2, 16)
print("输出形状:", y.shape)                  # torch.Size([10, 2, 16])
print("位置编码是否可训练:", pos_enc.pos_embedding.weight.requires_grad)  # True
print("参数量:", pos_enc.pos_embedding.weight.numel())  # 128 * 16 = 2048

接着把上一课的正弦编码也拿过来，和"初始化后尚未训练"的可学习编码放在一起对比热力图。你会发现：可学习编码初始是随机噪声，训练后才会呈现出某种结构。

import math
import matplotlib.pyplot as plt

def sinusoidal_pe(max_len, d_model):
    pe = torch.zeros(max_len, d_model)
    pos = torch.arange(max_len).unsqueeze(1).float()
    div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
    pe[:, 0::2] = torch.sin(pos * div)
    pe[:, 1::2] = torch.cos(pos * div)
    return pe

sin_pe = sinusoidal_pe(64, d_model)
lrn_pe = pos_enc.pos_embedding.weight[:64].detach()   # 未训练，仍是随机初始化

fig, axes = plt.subplots(1, 2, figsize=(12, 4))
axes[0].imshow(sin_pe.numpy(), aspect="auto", cmap="viridis")
axes[0].set_title("正弦位置编码（固定、有结构）")
axes[1].imshow(lrn_pe.numpy(), aspect="auto", cmap="viridis")
axes[1].set_title("可学习位置编码（随机初始化）")
for ax in axes:
    ax.set_xlabel("维度")
    ax.set_ylabel("位置 pos")
plt.tight_layout()
plt.show()

最后演示一个"外推"上的差别：把序列加长到超过 max_len，可学习编码会直接报错，而正弦编码仍能继续算。

# 可学习编码：序列长度超过 max_len=128 时会越界
try:
    x_long = token_emb(torch.randint(0, 100, (200, 2)))
    pos_enc(x_long)
except Exception as e:
    print("可学习编码超长报错:", type(e).__name__)   # IndexError

# 正弦编码：任何长度都能算
print("正弦编码在长度 200 时仍可计算:", sinusoidal_pe(200, d_model).shape)  # (200, 16)

  2. 把 max_len 设成 32，然后输入长度 40 的序列，确认 nn.Embedding 会抛 IndexError。思考：在真实产品里，超过位置上限通常有哪些处理办法（截断、滑窗、相对位置……）？
