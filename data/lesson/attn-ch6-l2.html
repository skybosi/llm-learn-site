一个小任务#

上一课我们从零拼出了 Transformer，但还没让它真正"学会"任何东西。这一课跑通一个完整的训练闭环。任务选一个经典的合成小任务——序列反转：模型读入一串数字 token，必须原样、倒序地把它吐出来。反转任务看起来简单，却正好考验 Transformer 的两项核心能力——编码器要理解输入，解码器要按正确顺序、逐 token 生成，交叉注意力还必须学会"对着源序列找对应位置"。为了把重心放在训练流程上，这一课改用 PyTorch 官方封装 nn.Transformer（它和上一课手写的骨架功能等价），完整走一遍：造数据 → 建模型 → 训练 → 评估。

一、概念讲解#

1. 为什么选"序列反转"当入门任务#

  • 数据无限、零成本：随机整数序列要多少有多少，不用下载、不用清洗。
  • 目标明确、可验证：输出必须严格等于输入的反转，对了就是对了，一眼就能判定。
  • 恰好锻炼关键机制：解码器位置 i 要输出源序列的倒数第 i 个 token，这意味着交叉注意力里"目标位置 ↔ 源位置"会形成一条反对角线对齐。这个性质正是第 3 课可视化注意力的看点。

当然，反转只是热身。理解了流程后，你可以把同样的骨架换成复制任务、排序任务、甚至一个小型机器翻译。

2. 训练闭环的四块积木#

任何有监督训练都绕不开这四步，本课代码也严格对应：

  1. 数据：构造 (源序列, 解码器输入, 目标输出) 三元组。解码器输入 = 目标右移一位（teacher forcing，见第 5 章第 3 课）。
  2. 模型：nn.Transformer 骨架 + token 嵌入 + 位置编码 + 输出投影。
  3. 损失与优化器：CrossEntropyLoss 在所有位置上求平均，Adam 更新参数。
  4. 评估：用自回归贪婪解码生成整句，和期望输出逐 token 比对。

3. 词表设计与"右移一位"#

反转任务的词表很简单：0 = <bos>（起始符）、1 = <eos>（结束符）、2 ~ 11 是十个"数字"token。设源序列为 [a, b, c, d, e, f]，那么：

源序列:      [a, b, c, d, e, f]
解码器输入:  [<bos>, f, e, d, c, b, a]   ← 反转结果整体右移一位
目标输出:    [f, e, d, c, b, a, <eos>]   ← 每个位置预测"下一个"真实 token

decoder_input[i] 预测 decoder_output[i]。这样训练时一次前向就能同时监督 7 个位置，效率拉满。

4. 评估时为什么要"贪心解码"#

训练用 teacher forcing，评估则必须自回归：从 <bos> 开始，每步取 logits 最大的 token，拼回输入再走下一步，直到遇到 <eos> 或达到长度上限。这就是第 5 章讲过的"训练与推理差异"在代码里的落地。

二、可运行代码示例#

import math
import torch
import torch.nn as nn

torch.manual_seed(0)

VOCAB = 12                 # 0:<bos> 1:<eos> 2~11: 十个数字 token
BOS, EOS = 0, 1

# 位置编码（与上一课一致，batch_first 形式）
class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=200):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        pos = torch.arange(max_len).unsqueeze(1).float()
        div = torch.exp(torch.arange(0, d_model, 2).float()
                        * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(pos * div)
        pe[:, 1::2] = torch.cos(pos * div)
        self.register_buffer("pe", pe.unsqueeze(0))
    def forward(self, x):
        return x + self.pe[:, :x.size(1)]

# 序列反转任务的 Transformer
class Reverser(nn.Module):
    def __init__(self, vocab, d_model=32, n_heads=4, n_layers=2, dim_ff=64):
        super().__init__()
        self.d_model = d_model
        self.embed = nn.Embedding(vocab, d_model)
        self.pos = PositionalEncoding(d_model)
        # 官方封装：encoder 和 decoder 各 n_layers 层
        self.transformer = nn.Transformer(d_model, n_heads, n_layers, n_layers,
                                          dim_ff, batch_first=True)
        self.proj = nn.Linear(d_model, vocab)

    def forward(self, src, tgt):
        src_emb = self.pos(self.embed(src) * math.sqrt(self.d_model))
        tgt_emb = self.pos(self.embed(tgt) * math.sqrt(self.d_model))
        # 因果掩码：保证解码器不偷看未来
        tgt_mask = nn.Transformer.generate_square_subsequent_mask(tgt.size(1), device=tgt.device)
        out = self.transformer(src_emb, tgt_emb, tgt_mask=tgt_mask)
        return self.proj(out)

def make_batch(batch_size, seq_len):
    src = torch.randint(2, VOCAB, (batch_size, seq_len))       # 源：随机数字
    rev = src.flip(1)                                          # 反转
    dec_in = torch.cat([torch.full((batch_size, 1), BOS), rev], dim=1)   # 右移一位
    dec_out = torch.cat([rev, torch.full((batch_size, 1), EOS)], dim=1)  # 目标
    return src, dec_in, dec_out

# ---------- 训练 ----------
model = Reverser(VOCAB)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()

losses = []
for epoch in range(1, 301):
    model.train()
    src, dec_in, dec_out = make_batch(32, 6)          # 每轮随机造 32 条长度 6 的序列
    logits = model(src, dec_in)                       # (32, 7, VOCAB)
    loss = loss_fn(logits.reshape(-1, VOCAB), dec_out.reshape(-1))
    opt.zero_grad(); loss.backward(); opt.step()
    losses.append(loss.item())
    if epoch % 50 == 0:
        print(f"epoch {epoch:>3}  loss {loss.item():.4f}")

如果设备是 CPU，几百个 epoch 通常几十秒内能跑完；loss 会从接近 ln(VOCAB) 的随机水平一路降下来。接着做评估——自回归贪心解码，并和期望输出比对：

@torch.no_grad()
def greedy_decode(model, src, max_len=8):
    model.eval()
    generated = torch.full((1, 1), BOS, dtype=torch.long)
    for _ in range(max_len):
        logits = model(src, generated)               # 教学版：每次重算整个前缀
        nxt = logits[0, -1].argmax().item()          # 取最后一个位置的预测
        generated = torch.cat([generated, torch.tensor([[nxt]])], dim=1)
        if nxt == EOS:
            break
    return generated[0, 1:].tolist()                 # 去掉开头的 <bos>

# 拿 5 条新鲜序列测试
model.eval()
correct = 0
for _ in range(5):
    src = torch.randint(2, VOCAB, (1, 6))
    pred = greedy_decode(model, src)
    target = src.flip(1).tolist()[0] + [EOS]
    ok = (pred == target)
    correct += ok
    print(f"源 {src.tolist()[0]} -> 预测 {pred}  期望 {target}  {'✓' if ok else '✗'}")
print("5 条中正确:", correct)

# 画出 loss 曲线（可选）
import matplotlib.pyplot as plt
plt.plot(losses)
plt.xlabel("epoch"); plt.ylabel("loss")
plt.title("序列反转任务的训练 loss")
plt.show()

提示：这里的 greedy_decode 每次调用 model 都重算了整个前缀，是为清晰而牺牲效率的写法。工程上会配合 KV cache（第 5 章第 3 课）避免重复计算。

三、练习#

  1. 把源序列长度从 6 增加到 12，重新训练。观察 loss 收敛是否变慢、准确率是否下降，思考长序列反转为什么更难。
  2. 把任务从"反转"改成"复制"（输出等于输入），训练后比较两者收敛速度。哪个更难？为什么？
  3. 把 greedy_decode 里"每次重算整个前缀"改成"缓存编码器输出，只重算解码器"的版本，对比相同长度下两种写法的耗时差异。
  4. 引入 <pad> 与变长序列：造一个 batch 内长度不等的反转数据，用 src_key_padding_mask / tgt_key_padding_mask 处理，观察掩码对训练是否必要。
