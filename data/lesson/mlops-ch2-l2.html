评测门禁：阈值怎么定、误拦与漏放的成本比、多重比较与序贯判据#

这一节要解决什么#

上一节把脏数据挡在了门外，流水线上还剩最后一道、也是最像"技术活"的门：离线评测门禁。它要回答的问题每天都有人问错：

候选模型在评测集上比线上模型高了 1.2 个点，能发吗？

三种典型回答都是错的：

回答 错在哪
"p < 0.05，显著，发" 显著性只说明"不像噪声"，不说明"够大"、也不说明"别的指标没坏"
"涨了就是涨了，发" 涨幅本身是随机变量；如果这个候选是从 k 个候选里挑出来的，它还系统性虚高（winner's curse）
"让评测团队再看看" 把统计问题变成人力问题：没有样本量、没有阈值、没有决策规则，"再看看"必然演化成"看到通过为止"

本节要把"发不发"写成一个可复算的决策。四个组成部分缺一不可：

  1. 一个假设：把"候选不比线上差"写成 H0​/H1​，于是"通过"= 拒绝 H0​；
  2. 一个规模：最小可分辨效应（MDE）与样本量 n —— 没有它，"没看出来"会被当成"没问题"；
  3. 一个成本比：误拦（好模型被拒）与漏放（差模型上线）的代价差两三个数量级，最优阈值由它们的比值决定，不由p值决定；
  4. 一个多重性方案：一次发布要看的指标有 m 个（主指标 + 护栏），各指标之间还会被反复看 —— 族错误率 1−(1−α)m 的增长速度会让"单指标 0.05"这个约定失效。

一句话给出本节的结论：门禁的阈值不是"0.05"，而是"使得 αC拦​+βC放​ 最小的那个 α"；门禁的通过条件不是一个 p 值，而是"主指标显著改善 + 所有护栏非劣"这两条同时成立。

一、把发布决策写成可复算的判据#

1.1 四个要素的形式化#

设评测指标为错误率（越小越好），线上模型为基线 pbase​，候选为 pcand​，观测到 p^​。门禁要检验的是"候选更好"：

H0​: pcand​≥pbase​vsH1​: pcand​<pbase​

z=p^​(1−p^​)(nbase​1​+ncand​1​)​p^​base​−p^​cand​​,拒绝 H0​⟺z>z1−α​

但"拒绝 H0​"只解决了第一层。真正要发布的判据是三条同时成立：

① 主指标显著改善z主​>z1−α主​​​​∧② 护栏非劣∀g∈护栏: p^​cand,g​−p^​base,g​<δg(劣化上限)​​​∧③ 效应量够大Δ^主​≥Δmin​​​

第 ③ 条是本节最容易被跳过、也最贵的一条。用本节代码里的一个极端算例：n=50000（本来就很大）时，即使真实改善只有 0.01 个百分点，也能得到 p≈10−50 —— "显著"在 n 足够大时是免费获得的，它回答的是"有没有差异"，不是"差异值不值得发"。所以 Δmin​ 必须先于实验确定（用业务损失算），否则事后总能挑一个"显著"的指标来发。

1.2 为什么两边的成本差这么远#

把两个错误的代价摊开：

错误 名字 后果 典型量级
误拦（拒了真更好的模型） 第一类错误，率 α 研发等待一个周期、评测算力、团队士气 工时 × 单价 + 一次失效的迭代
漏放（放了真更差的模型） 第二类错误，率 β 线上事故、回滚、用户流失、信任损失 事故代价（常含不可逆部分）

C拦​C放​​≈10∼103

这个比值直接决定门禁该"严"还是"松"：C放​/C拦​ 越大，越应该把 α 放大（宁可多拦几次，也不要漏放），也越应该把资源投在提高检出率（更贴近线上的评测集、更多样本）而不是"把 p 值阈值调小"。

1.3 判据的四条纪律#

  1. 判据必须在看到结果之前写下来。包括：主指标是哪个、护栏有哪些、δg​ 多少、Δmin​ 多少、样本量多少、看几次。事后改判据 = 把门禁变成橡皮图章。
  2. 每个数字带它的不确定性（点估计 + 区间 + n）。"错误率 9.2%"不是结论，"9.2% [8.6%, 9.8%]，n=104"才是。
  3. 主指标与护栏分开对待：主指标要"更好"，护栏只要"不更差超过 δg​"（非劣检验）。把护栏也要求"更好"会使得几乎任何发布都通不过（护栏之间互相冲突）。
  4. 判据要能复算：给定 manifest（ch1-l2）+ 评测集版本 + 判据文件，任何人都能算出同一个通过/不通过。

二、样本量与 MDE：门禁的分辨率#

2.1 公式与数值算例#

两比例、等额分配的每组样本量（正态近似）：

n≈(p0​−p1​)2(z1−α​2pˉ​(1−pˉ​)​+z1−β​p0​(1−p0​)+p1​(1−p1​)​)2​,pˉ​=2p0​+p1​​

本节代码取 p0​=0.10、α=0.05、1−β=0.80，实测结果（z0.95​=1.6449、z0.80​=0.8416）：

δ（要检出的绝对改善） 每组 n 总请求（两组）
0.2pp 275738 551476
0.5pp 43521 87042
1.0pp 10630 21260
2.0pp 2531 5061
5.0pp 342 684

这张表的读法是本节最重要的一条工程直觉：n∝1/δ2。要把可分辨的改善减半，样本量要翻两番。所以"我想验证 0.1 个点的提升"这句话的真实含义是"我需要 106 量级的评测样本" —— 大多数团队的评测集根本没有这个规模，于是他们报告的"0.1 个点提升"实际上是样本量不足下的噪声。

反过来，这个公式给出给定评测集的 MDE：

MDE≈(z1−α​+z1−β​)n2p0​(1−p0​)​​

代码实测（p0​=0.10）：

      n/组  x_base  x_cand       z      单侧 p   α=.05  Bonf20  MDE(pp)
     2000     200     184   0.859   0.19524     不通过     不通过     2.36
     5000     500     460   1.358   0.08726     不通过     不通过     1.49
    10000    1000     920   1.920   0.02741      通过     不通过     1.05
    20000    2000    1840   2.716   0.00331      通过     不通过     0.75

同一个观测到的改善（恒为 0.8pp：10.0% → 9.2%），在 n=2000 时不显著，在 n=10000 时显著。 翻转的不是数据，是样本量。这张表同时暴露了两个日常错误：

  • 用 n=2000 评测后说"没提升"——其实 MDE 是 2.36pp，0.8pp 的提升原理上不可能被检出；
  • 用 n=20000 评测后说"提升 0.8pp，很稳"——这句话没有说明"这个 0.8pp 是不是选出来的"（第三节）。

2.2 MDE 的三种用法#

  1. 事前：给定评测集规模，算出 MDE。若 MDE 大于业务关心的 Δmin​，就不要用这个评测集做发布决策 —— 先去扩样本或改用更低方差的指标。
  2. 事中：把 MDE 作为"最少要看多少"的门槛。样本量不足时门禁应输出"证据不足"，而不是"通过"。
  3. 事后：报告任何"不显著"的结论时，必须同时报告 MDE。否则"没发现差异"会被误读为"等价"。严格的等价结论要用 TOST（两个单侧检验），H1​:∣Δ∣<Δm​。

三、选出来的冠军：winner's curse#

3.1 机制#

如果候选是从 k 个里挑出来的（"我们试了 20 组超参，最好的一组涨了 1.2 个点"），那么被报道的那个 Δ^ 是一个极值统计量：

E[i≤kmax​Δ^i​]=Δtrue​+σ⋅E[i≤kmax​Zi​]≈Δtrue​+σ2lnk​

（σ 是单次评测的标准误，Zi​ 是标准正态。）代码实测（n=104、SE=0.424pp）：

k（候选数） E[maxZ] 观测值虚高
1 0.000 0.000pp
5 1.794 0.761pp
20 2.448 1.038pp
100 3.035 1.288pp

从 20 个候选中挑出的冠军，报告的提升要减掉约 1.0 个点才是无偏估计。 这与评测集大小无关 —— 它来自选择，不是来自测量误差。处置有三条：

  1. 留出确认集：在挑选用的数据之外，用一份没被挑过的数据重新评测冠军，用它做门禁判据；
  2. 扣减：报告 Δ^−σ^2lnk​（重选择偏差校正），并把扣减量写进判据；
  3. 减少选择：把"20 组都试"改成"预先指定 1 组 + 少量备选"，从源头降低 k —— 这也是 ch1-l4 的配额与命名规范要解决的问题。

3.2 与多重比较的关系#

winner's curse 是选择带来的偏差（点估计偏高），多重比较是检验次数带来的错误率膨胀（假阳性变多）。两者常同时出现但机制不同：

  • 20 组里挑最好的 1 组 → 点估计虚高（winner's curse）；
  • 20 组各自做一次显著性检验、只要有一个显著就发布 → 族错误率 1−(1−α)20（多重比较）。

四、多重比较：m 个指标怎么办#

4.1 族错误率#

m 个都为 null 的独立检验，各自用 α，至少出现一个假阳性的概率：

FWER=1−(1−α)m

代码实测：

m FWER（α=0.05） Holm 最小阈值 α/m
1 0.050000 0.050000
5 0.226219 0.010000
20 0.641514 0.002500
50 0.923055 0.001000
200 0.999965 0.000250

20 个指标的流水线，如果每个都用 0.05，出现假阳性的概率是 64%。 这就是"发布门禁越来越松"的最常见机制：指标越加越多，判据却从没跟着改。

4.2 两套校正：FWER 与 FDR#

Holm-Bonferroni（控制 FWER，强于 Bonferroni）：把 p 值升序排 p(1)​≤⋯≤p(m)​，从最小的开始逐个与 α/(m−i+1) 比较，遇到第一个不满足就停止（后面的全部不拒绝）。

Benjamini-Hochberg（控制 FDR =E[假阳性/总阳性]）：找最大的 k 使 p(k)​≤mk​α，拒绝前 k 个。代码实测（m=20）：

  Bonferroni 阈值=0.002500 → 通过 3 个
  BH 最大阈值=0.012500 → 通过 5 个（前 5 小的 p 值）
  BH 比 Bonferroni 多救回 2 个

怎么选：

场景 用哪个 理由
发布门禁的主指标 不校正，但唯一且事前指定 只检验一个假设，没有多重性
发布门禁的护栏 Bonferroni/Holm 护栏是"必须都不坏"，要控制"误拦并放行"的族错误率
探索性的离线对比（几十个切片/指标） BH 目标是"找出值得深挖的方向"，允许少量假阳性

一条反直觉但重要的推论：指标越多，越应该区分"决策性指标"和"探索性指标"。把所有指标塞进同一个门禁，等价于用 Bonferroni 校正一切 —— 最后每道门的阈值都小到无法通过，团队就会开始"绕过门禁"而不是"改进模型"。

五、序贯与多查看：为什么不能"看到通过为止"#

5.1 多查看的代价#

流水线上真实的行为是：评测分批回来，每回来一批就看一眼。k 次查看、每次都用 α 的代价是 FWER 膨胀到 1−(1−α)k。等额 α 花费方案（每次用 α/k）代码实测：

查看次数 k 每次阈值 α/k z 边界 FWER 上界
1 0.05000 1.6449 0.05000
2 0.02500 1.9600 0.04938
4 0.01250 2.2414 0.04907
10 0.00500 2.5758 0.04889

FWER 没有膨胀（这是 α/k 的作用），代价是每次都更难显著：k=4 时 z 要从 1.64 提到 2.24，等价于样本量增加 (2.2414/1.6449)2≈1.86 倍。

5.2 代码里的两看设计（可手算复核）#

设计：δ=1pp、α=0.05、power 0.80、看 2 次、每次 α/2=0.025：

FWER=1−(1−0.025)2=0.049375≤0.05

    单看：n/arm=10630；两看：最终 n/arm=13495，中间看 n/arm=6747，每次用 z>1.9600
    FWER(2 看) = 1-(1-0.025)^2 = 0.0494 ≤ 0.05
    看到 n=6747: xb=674 xc=607 z=1.9677 p=0.024551 → 停：判候选更好
    看到 n=13495: xb=1349 xc=1214 z=2.8030 p=0.002531 → 停：判候选更好

注意两看设计的最坏样本量比单看多（13495 vs 10630，多 27%）：多看的代价是"必须把 α 分开花"，好处是允许提前停。本例中间看就跨过了边界，省下了后半段 —— 但这是数据决定的，不是可以承诺的。

5.3 SPRT：理论边界与实测校准#

序贯概率比检验（SPRT）把每一条观测都转成对数似然比增量 ln[P(x∣H1​)/P(x∣H0​)]，并在两个边界之间游走：

A=lnα1−β​,B=ln1−αβ​,累积 Λn​≥A⇒判"更好";Λn​≤B⇒判"不更好"

本节代码用 p0​=0.20（不更好）对 p1​=0.10（更好 10pp），A=2.7726、B=−1.5581，单步增量：出错 ln(p1​/p0​)=−0.6931、不出错 ln1−p0​1−p1​​=+0.1178。两档效应的实测（每档 4000 条确定性路径）：

       p0→p1  E[inc|p0]  E[inc|p1]    固定 n/arm    序贯 E[n] p0    序贯 E[n] p1     α 实测      功效
  0.20→0.10  -0.044403  +0.036690         157            36            57   0.0478  0.8395
  0.20→0.19  -0.000321  +0.000317       19410          4217          5981   0.0535  0.8105

三个关键读法：

  1. E[Λ] 的符号决定一切：E[增量∣p0​]<0（漂向下界 = 判"不更好"），E[增量∣p1​]>0（漂向上界 = 判"更好"）。差值就是每样本信息量，它决定了序贯要跑多久。
  2. 效应越小，序贯越省（相对固定样本）：p0​→p1​=0.19 时固定样本要 19410 个样本，序贯平均只要 4217/5981（两种真值）；而 0.20→0.10 的大效应下，序贯的 E[n]=36/57，固定样本 n=157 —— 两者都不差，但序贯的边界需要实测校准。
  3. Wald 恒等式只是近似：当 E[增量] 只有 10−4 量级时（小效应），overshoot 不可忽略，实际 α 与功效会偏离设计值（本节实测 α=0.0535、功效 0.8105，尚可接受；效应更小就会崩）。生产里必须用模拟校准边界，而不是照抄公式。

六、把决策写成一张卡#

把前面所有东西压成一页可评审的门禁卡（这张卡是本节的可交付物）：

[发布门禁卡]  manifest=<cand-hash>  评测集=<eval-v1.3>  比照基线=<prod-hash>

① 主指标（唯一，事前指定）：错误率
   判据：z > z_{1-α}，α 由成本比定（默认 0.05）
   样本量：每组 n ≥ 10630（对应 MDE = 1.0pp @ p0=0.10）
   效应门槛：Δ̂ ≥ Δ_min = 0.5pp（由业务损失倒推）
   选择偏差：若候选来自 k 组挑 1，则 Δ̂_adj = Δ̂ − σ√(2 ln k) ≥ Δ_min

② 护栏（m 个，非劣检验 + Bonferroni）
   延迟 p99 ≤ 1.10 × 基线；拒答率 ≤ 基线 + 1pp；单请求成本 ≤ 基线 × 1.05
   判据：每个护栏的单侧 p < 0.05/m，且点估计不超过 δ_g

③ 多重性与序贯
   查看次数 k ≤ 2，每次 α/k；或使用 SPRT 并在上线前用模拟校准边界
   禁止：反复查看直到显著（peeking）

④ 证据不足的处置
   若 MDE > Δ_min：结论写"无法判定"，不放行也不判负，先扩充评测集

代码#

本节代码只用标准库。包含：样本量/MDE、两比例检验、Wilson 区间、成本最优 α、FWER 与 BH、winner's curse、序贯多查看、SPRT 的边界与实测校准。合成数据与模拟 ⚠️ 均已标注（固定种子，可逐字节复现）。

"""第 2 章第 2 节：发布门禁 —— 样本量 / MDE / 多重比较 / 序贯检验 / 成本最优 α。

只用标准库（random 用于统计量的蒙特卡洛核对）。合成数据 ⚠️。
"""
import math
import random

# ------------------------------------------------------------------ 正态工具
def phi(x):
    return 0.5 * (1.0 + math.erf(x / math.sqrt(2.0)))


def z_quantile(p, lo=-40.0, hi=40.0):
    for _ in range(200):
        mid = (lo + hi) / 2
        if phi(mid) < p:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2


# ---------------------------------------------------- 两比例：样本量 / 检验 / CI
def n_per_arm(p0, p1, alpha=0.05, power=0.80):
    """两比例、等额分配的每组样本量（正态近似）。"""
    za, zb = z_quantile(1 - alpha), z_quantile(power)
    pbar = (p0 + p1) / 2
    num = (za * math.sqrt(2 * pbar * (1 - pbar))
           + zb * math.sqrt(p0 * (1 - p0) + p1 * (1 - p1))) ** 2
    return num / (p0 - p1) ** 2


def z_test_improve(xb, nb, xc, nc):
    """H0: p_cand >= p_base  vs  H1: p_cand < p_base。z>0 表示候选更好。"""
    pb, pc = xb / nb, xc / nc
    pbar = (xb + xc) / (nb + nc)
    se = math.sqrt(pbar * (1 - pbar) * (1 / nb + 1 / nc))
    z = (pb - pc) / se
    return z, 1 - phi(z)


def mde(p0, n, alpha=0.05, power=0.80):
    """给定每组 n，反推可分辨的最小绝对差。"""
    za, zb = z_quantile(1 - alpha), z_quantile(power)
    return (za + zb) * math.sqrt(2 * p0 * (1 - p0) / n)


def power_at(p0, p1, n, alpha=0.05):
    za = z_quantile(1 - alpha)
    return 1 - phi(za - (p0 - p1) / math.sqrt(2 * p0 * (1 - p0) / n))


def wilson(x, n, z=1.96):
    p = x / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return c - h, c + h


# ------------------------------------------------------------------ SPRT
def sprt_bounds(p0, p1, alpha=0.05, beta=0.20):
    """H0: p=p0（候选不更好） vs H1: p=p1 < p0（候选更好）。"""
    return math.log((1 - beta) / alpha), math.log(beta / (1 - alpha))


def sprt_run(p0, p1, true_p, seed, A, B, n_max=200000, rng=None):
    """跑一条序贯路径；增量 = ln[P(x|H1)/P(x|H0)]。返回 (结论, n)。"""
    if rng is None:
        rng = random.Random(seed)
    inc_err = math.log(p1 / p0)          # 出错：p1<p0 → 负 → 支持 H0
    inc_ok = math.log((1 - p1) / (1 - p0))  # 没出错：→ 正 → 支持 H1
    llr = 0.0
    for n in range(1, n_max + 1):
        llr += inc_err if rng.random() < true_p else inc_ok
        if llr >= A:                 # 上界 A=ln((1-β)/α) → 判"更好"（H1）
            return "H1（候选更好）", n
        if llr <= B:                 # 下界 B=ln(β/(1-α)) → 判"不更好"（H0）
            return "H0（候选不更好）", n
    return "未判定", n_max


def sprt_mc(p0, p1, true_p, A, B, runs=5000, seed=0):
    """蒙特卡洛：返回 (判 H1 的比例, 平均样本量)。"""
    rng = random.Random(seed)
    hit, tot = 0, 0
    for _ in range(runs):
        verdict, n = sprt_run(p0, p1, true_p, seed, A, B, rng=rng)
        hit += (verdict.startswith("H1"))
        tot += n
    return hit / runs, tot / runs

  2. 把一次历史发布复盘成假设检验： （a）找出上一次发布的候选与基线在评测集上的原始计数（不是百分比），算 z 与单侧 p； （b）如果当时用的是"p<0.05"，换成"p<0.05/m"（m 是当时看过的指标数）会怎样？ （c）回答：那次发布的结论是否会被改写？如果会，说明门禁当时漏掉了什么。

小结#

  • 发布决策 = 一个假设 + 一个规模 + 一个成本比 + 一个多重性方案。写不出这四样，门禁就是橡皮图章。
  • 样本量 n∝1/δ2：p0​=0.10 下检出 2pp 只要每组 2531，检出 0.2pp 要 275738。"没看出来"通常是样本量不足，不是模型等价。 MDE 是门禁的分辨率，不足时应输出"证据不足"而不是"通过"。
  • 同一份 0.8pp 的观测改善，在 n=2000 不显著、n=10000 显著 —— 翻转结论的是样本量。所以判据必须在看到结果前写下（含样本量），否则"看数据说话"必然变成"看数据挑话"。
  • 误拦与漏放的成本比 C放​/C拦​≈10∼103，最优 α 由它决定：代码网格扫描显示 k=5→α∗=0.015、k=20→0.070、k=50→0.260、k=200→0.300。阈值不是 0.05，是 argminα​[α+kβ(α)]。
  • winner's curse：从 k 组挑最好的一组，报告值虚高 ≈σ^2lnk​；k=20、n=104 时约 1.04pp。处置：留出确认集 / 显式扣减 / 减少选择。
  • 多重比较：m=20 个 null 指标各自 0.05 → FWER =0.642。护栏用 Holm/Bonferroni 控 FWER（m=20 时最小阈值 0.0025），探索性对比用 BH 控 FDR（同一组 p 值下 BH 通过 5 个、Bonferroni 只通过 3 个）。
  • 序贯与多查看：k 次等额 α/k 花费把 FWER 压回 0.05 以下（k=4 时 0.0491），代价是 z 边界从 1.64 提到 2.24（等价样本量 +86%）。两看设计的实测：单看 n=10630，两看最终 n=13495、中间看 n=6747，中间看就跨过 z=1.96 停住。
  • SPRT 的判据是每样本信息量：E[lnP(x∣H0​)P(x∣H1​)​] 在 p0​ 下为负、在 p1​ 下为正；p0​→p1​ 差 1pp 时序贯平均只要 4217/5981 个样本，而固定样本要 19410。但 Wald 边界只是近似：效果量小到 E[增量]∼10−4 时必须用模拟校准，否则实测 α/功效会偏离设计值（本节实测 0.0535 / 0.8105）。
  • 护栏是最容易漏的一项：主指标要"显著更好"，护栏只要"非劣"（单侧 + Bonferroni）。要求所有护栏都更好，会让任何发布都通不过，最终逼团队绕过门禁。

下一节：到这里，离线门禁已经能给出"发 / 不发 / 证据不足"的三态判断。但离线评测集永远只是线上分布的一个样本 —— 第 3 节要把门禁推到线上：影子流量（用户看不到，用它抓分歧）与灰度放量（用可控流量做真对照），并给出放量的样本量判据、分配单元（请求/用户/会话）的选择，以及"小流量阶段该看什么指标、不该看什么指标"。
