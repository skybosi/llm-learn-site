结果与复盘（RAG 问答系统）#

RAG 项目最容易"看着能聊、其实答错"，所以本课的重点是把质量量化：评估引用准确性、对比 chunk 策略，并准备好面试话术与常见坑。做完本课，你手上会有一张"可复现的评估表"和一套"可对答的优化理由"。

一、目标与步骤#

  1. 构造评测集：准备一组带"金标准答案"的问题。
  2. 检索质量评估：命中率 Hit@k、MRR。
  3. 引用准确性与忠实度评估：用 RAGAS + 人工核对。
  4. chunk 策略对比实验：256 / 512 / 1024 的量化结论。
  5. 面试话术：预演高频追问。

二、代码骨架与实现指导#

1. 构造评测集（本项目的"测试集"）#

评测集是你项目可信度的地基。人工写 30~50 个有明确事实答案的问题，每条标注金标准片段：

# data/eval_set.json 结构示例
# [{"question": "框架支持哪几种向量库？", "gold_snippet": "支持 Chroma、FAISS、Pinecone 等"},
#  {"question": "切块的默认 overlap 是多少？", "gold_snippet": "默认 overlap 为 64"}]

import json
eval_set = json.load(open("data/eval_set.json", encoding="utf-8"))
print(f"评测问题 {len(eval_set)} 条")

要点：问题要来自文档、答案唯一，覆盖"精确数值、章节概念、跨段综合"三类，才能测出 RAG 的真实短板。

2. 检索质量：命中率与 MRR#

def hit_rate(retriever, eval_set, k=5):
    hits = 0
    for item in eval_set:
        nodes = retriever.retrieve(item["question"])[:k]
        # 命中：检索到的任一节点包含金标准答案的关键词/片段
        if any(item["gold_snippet"] in n.text for n in nodes):
            hits += 1
    return hits / len(eval_set)

def mrr(retriever, eval_set, k=5):
    """平均倒数排名：答案片段排得越靠前，得分越高。"""
    scores = []
    for item in eval_set:
        nodes = retriever.retrieve(item["question"])[:k]
        for rank, n in enumerate(nodes, start=1):
            if item["gold_snippet"] in n.text:
                scores.append(1 / rank)
                break
        else:
            scores.append(0.0)
    return sum(scores) / len(scores)

print("Hit@5:", hit_rate(mmr_retriever, eval_set))
print("MRR@5:", mrr(mmr_retriever, eval_set))

注意 gold_snippet in n.text 是精确子串匹配，简单但严格；更鲁棒可用"答案关键词集合的交集比"。面试时说明你用了哪种、有何局限即可。

3. 引用准确性与忠实度（RAGAS）#

RAGAS 提供 faithfulness（答案是否可由上下文推出）与 context_precision 等指标：

from ragas import evaluate
from ragas.metrics import faithfulness, context_precision, answer_relevancy
from datasets import Dataset

# 把 (question, answer, retrieved_contexts) 组织成数据集
samples = []
for item in eval_set:
    out = answer(item["question"])
    samples.append({
        "question": item["question"],
        "answer": out["answer"],
        "contexts": [n.text for n in out.get("retrieved_nodes", [])],
    })
ds = Dataset.from_list(samples)
score = evaluate(ds, metrics=[faithfulness, context_precision, answer_relevancy])
print(score)

人工核对的引用准确率（citation accuracy）单独做：随机抽 30 条回答，逐条判断"每个 [来源N] 是否真的支持该结论"，正确引用数 / 总引用数 即为引用准确率。机器指标 + 人工抽查结合，才可信。

4. chunk 策略对比实验#

把切块大小当作变量，其余固定，跑一遍指标，得到"用数据说话"的结论：

results = []
for size, overlap in [(256, 32), (512, 64), (1024, 128)]:
    nodes = chunk_documents(documents, chunk_size=size, overlap=overlap)
    idx = build_index(nodes)          # 复用 lesson-02 的建索引函数
    r = idx.as_retriever(similarity_top_k=5)
    results.append({
        "chunk": f"{size}/{overlap}",
        "hit@5": hit_rate(r, eval_set),
        "mrr": mrr(r, eval_set),
        "node_count": len(nodes),
    })

import pandas as pd
print(pd.DataFrame(results).to_markdown(index=False))

预期方向：块太小命中率低（信息被切散）、块太大命中率高但生成时上下文噪声大；512/64 通常在中文文档上取到较好的"命中率 × 忠实度"平衡。你的具体数据会因语料不同而异，结论必须来自你的实验，而不是抄结论。

三、面试话术#

Q1：RAG 和微调你选哪个？为什么这个项目用 RAG？ 答：RAG 解决的是"基于外部事实、可追溯、易更新"的问答，微调解决的是"稳定格式/风格/领域习惯"。我的语料会持续更新，且客户要求每个答案可查证，所以用 RAG 更合适；同时我保留了提示词与生成端可替换的接口，未来若要固化回答风格，再考虑微调。关键判断是知识的更新频率与可追溯需求。

Q2：你怎么防止模型"一本正经地胡说"？ 答：三层。第一，提示词强制"只用参考资料、逐句引用、不知道就说不知道"；第二，检索侧多召回 + 相似度阈值过滤，减少"喂错料"；第三，评估侧用 RAGAS 忠实度 + 人工核对引用准确率，把幻觉变成可量化、可回归的指标。我无法保证零幻觉，但我能测出幻觉率并持续压低它。

Q3：chunk 大小你是怎么定的？ 答：不是拍脑袋，是做了 256/512/1024 的对比实验。结论是 512 在"命中率 × 忠实度"上最平衡：256 把完整答案切散导致命中率下降，1024 命中率高但把无关内容塞进上下文、稀释了 embedding 语义并抬高生成噪声。overlap 取 64 是为了避免把关键句从边界切断。

Q4：如果用户问的问题答案在两个不同文档里，你的系统怎么办？ 答：我的检索会跨文档召回多个片段，提示词要求"综合多来源并分别标注 [来源N]"；但这正是当前系统的已知短板——跨段综合问题的正确率低于单事实问题，我已在复盘里把它列为下一步要做的"查询改写 + 重排序"方向。

Q5：embedding 为什么用 bge 而不是 OpenAI？ 答：三点——中文检索效果、可本地部署不依赖外部 API、成本与隐私。若追求更高召回，可换 bge-large 或加 rerank 模型，那是下一步的性价比权衡。

四、常见坑（复盘清单）#

  1. 无评测集就上线：只能"目测"，无法回归，改一处不知道是变好还是变坏。
  2. chunk 太大或太小：前者噪声多、后者信息断裂，都要靠实验验证。
  3. 只看相似度、不看重排：召回 5 条几乎重复的片段，生成端"巧妇难为无米之炊"。
  4. 提示词不强制引用：模型自由发挥，幻觉无法追责，引用准确率无从谈起。
  5. 把机器指标当真理：RAGAS 分数不等于真实质量，必须辅以人工抽查。
  6. 忽略元数据：不存来源文件名/页码，最后"答对了但说不出出处"，引用变成摆设。
