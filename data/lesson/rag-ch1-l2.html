稀疏检索：BM25 的推导、两个饱和参数与结构性失效#

这一节要解决什么#

BM25 发表于 1994 年前后，比 Transformer 早了二十多年，但它至今仍是真实 RAG 系统里最强的单一基线之一，而且在很多业务语料上打败神经检索。这件事有两种可能的解释：

  1. 它是"经验调出来的好公式"，好用但不知道为什么；
  2. 它有一个明确的推导，只是推导的前提在大多数教程里被跳过了。

这一节要证明是第 2 种，而且要把推导走完整。因为只有走完推导，你才能回答三个工程上必须回答的问题：

  • k1​ 和 b 这两个参数各自在纠正什么偏差？为什么 k1​ 管饱和、b 管长度，而不是反过来？
  • 换一组参数（比如 k1​=0.9,b=0.4 或 k1​=2.0,b=0.75）会发生什么？什么语料上该改，什么语料上不该动？
  • BM25 的失效是调参能修的吗？如果不能，那它失效的机制是什么？

最后一个问题最重要：BM25 有三类失效，其中两类是结构性的 —— 再多的调参、再大的 k1​ 网格搜索都修不好，因为它们来自"用词是否重叠"这个信号本身的局限。分清"调参能修的"和"必须换方案的"，是这一节的核心产出。

一、先把"检索"写成一个概率问题#

在写公式之前，必须先把任务定义清楚。检索要解决的不是"哪篇文档和查询最像"，而是：

给定查询 q，把文档按"它是否与 q 相关"排序。

这两个说法的差别是本质性的。"像不像"是一个相似度概念（对称、可度量、与任务无关），而"相不相关"是一个相关性概念（不对称、不可度量、依赖用户意图）。BM25 的推导从后者出发。

概率排序原理#

概率排序原理（Probability Ranking Principle, PRP）：如果检索系统对每篇文档给出的相关性判断是按正确概率排序的，那么它对该查询的检索效果最优。形式化地，最优排序是按

P(R=1∣d,q)

从大到小排列文档，其中 R∈{0,1} 表示文档 d 与查询 q 相关。

由于 P(R=1∣d,q) 随 d 单调变化，且它的排序与任意单调变换后的量一致，我们只需要一个能保序的量。用对数几率（log-odds）更方便，因为它把"相关概率"与"不相关概率"的比变成加法形式，而加法形式可以直接按词拆开：

rank(d)∝logP(R=0∣d,q)P(R=1∣d,q)​

为什么这一步是关键：到这里为止，我们还没有假设任何东西是"词袋"。下面会引入二元独立模型，正是那一步把 log 里的连乘拆成按词的求和 —— 也就是说，"打分 = 每个词贡献相加"这个看似天经地义的形式，其实是"词之间条件独立"这个假设的产物。记住这一点，后面解释失效时要用。

二元独立模型（BIM）#

两个假设：

  1. 二元性：文档是否与查询相关，只取决于词是否出现，不取决于出现几次（暂时的简化，后面第 4 节会修掉它）。
  2. 独立性：在给定相关性 R 的条件下，各词的出现相互独立。

设词表为 V，文档表示为 d=(x1​,…,x∣V∣​)∈{0,1}∣V∣，xt​=1 表示词 t 出现。在独立性假设下：

P(d∣R=1,q)=t:xt​=1∏​pt​t:xt​=0∏​(1−pt​),P(d∣R=0,q)=t:xt​=1∏​ut​t:xt​=0∏​(1−ut​)

其中 pt​=P(xt​=1∣R=1)，ut​=P(xt​=1∣R=0)。取对数几率并逐项整理（只在 xt​=1 的项上，两项的比偏离 1）：

logP(R=0∣d,q)P(R=1∣d,q)​=logP(R=0∣q)P(R=1∣q)​+t∈q∩d∑​logut​(1−pt​)pt​(1−ut​)​

第一项与文档无关（对所有文档是常数），不影响排序，可以丢掉。于是：

 score(d,q)=t∈q∩d∑​logut​(1−pt​)pt​(1−ut​)​ ​

这是一个"词是否命中就贡献一份固定分数"的形式：文档分 = 命中的查询词各自的权重之和。权重 wt​=logut​(1−pt​)pt​(1−ut​)​ 就是经典的 RSJ 权重（Robertson–Spärck Jones）。

二、把 pt​,ut​ 换成可估的量：IDF 从这里来#

RSJ 权重里的 pt​ 与 ut​ 是未知量，必须估计。做两个常用近似：

  1. 相关文档里词的分布近似均匀：pt​≈ 常数。（这是一个粗糙但有效的近似。）
  2. 不相关文档里词的出现比例约等于它在全语料里的文档频率比例：ut​≈Ndft​​，其中 dft​ 是包含词 t 的文档数，N 是总文档数。

代入 wt​ 并整理（把常数部分吸收进与排序无关的项）：

wt​=logut​(1−pt​)pt​(1−ut​)​≈logdft​/N1−dft​/N​+const=logdft​+0.5N−dft​+0.5​

（分子分母各加 0.5 是平滑，避免 dft​=0 或 dft​=N 时出现 0 或 ∞；这是实现层面的常用写法，不是推导的必然结果。）

这就是 IDF 的来源。它的含义现在很清楚：

df_t 小（稀有词）  → (N − df) 大、df 小 → 权重 大 → 这个词命中是强证据
df_t 大（常见词）  → 权重趋近 0         → 命中它几乎不提供信息
df_t = N           → 权重约 0           → 停用词自动被"降权"，不需要停用词表

一个常被误解的点：IDF 不是"发明的技巧"，它是"用文档频率估计 ut​"这一条近似的结果。理解这一点很重要 —— 它意味着当 dft​ 无法代表 ut​ 时（语料漂移），IDF 就会失效。这是第 5 节第三类失效的根源。

三、修掉"二元性"：词频饱和与 BM25#

BIM 的二元假设（只看"出现没出现"）在实践中很糟：一篇提到"图神经网络"20 次的文档，显然比只提 1 次的更可能相关。于是要把 xt​∈{0,1} 换成词频 tft​。

3.1 为什么不能直接用 tft​#

如果直接把词频乘上权重（即 ∑t​tft​⋅wt​），会出现两个问题：

  1. 线性增长不合理：一个词从出现 1 次到 2 次，其"证据增量"远大于从 20 次到 21 次。相关性对词频是边际递减的。
  2. 长文档占便宜：长文档天然有更高的 tf，会系统性地压过短文档。

所以需要一个饱和函数（解决 1）和一个长度归一化（解决 2）。BM25 的贡献就是给出这两者的具体形状，而且它们是从"2-泊松模型"推出来的，不是硬凑的。

3.2 2-泊松模型的思想#

2-泊松模型（two-Poisson model）：把文档分成两类 —— "精英"文档（与主题相关，词的出现服从均值较大的泊松分布）与"非精英"文档（服从均值较小的泊松分布）。词在文档中的出现次数是两个泊松分布的混合。

在这个模型下，可以推出"给定词频 tf，文档属于精英类的后验概率"具有如下的饱和形状：

wt(elite)​(tft​)≈logut​(1−pt​)pt​(1−ut​)​⋅tft​+Ktft​​

其中 K 是一个与文档长度和平均长度有关的量。这个形式正是 BM25 的核心：一个线性因子（RSJ 权重）乘一个饱和因子 tf+Ktf​，当 tf→∞ 时饱和因子上界为 1。

3.3 BM25 的最终形式#

K=k1​((1−b)+b⋅avgdl∣d∣​)

 BM25(d,q)=t∈q∑​IDF(t)⋅tft,d​+k1​((1−b)+bavgdl∣d∣​)tft,d​(k1​+1)​ ​

IDF(t)=logdft​+0.5N−dft​+0.5​

三个部件的语义，逐条对应推导来源：

部件 形式 来源 在纠正什么
IDF logdf+0.5N−df+0.5​ 用 df/N 估 ut​ 后的 RSJ 权重 常见词信息量低（不依赖停用词表）
词频饱和 tf+Ktf(k1​+1)​ 2-泊松模型下的精英类后验概率 词频边际递减（k1​ 控制递减速度）
长度归一化 K 里的 avgdl∣d∣​ 长文档 tf 偏高的系统性偏差 长文档天然占优（b 控制归一化强度）

注意 (k1​+1) 的位置：它把饱和因子的上界从 1 抬到 ≈(k1​+1)（当 tf→∞）。这只是一个整体缩放常数，不影响单个词的排序，但影响多词之间的相对权重（因为不同词的 tf 不同，缩放对它们作用不同）。很多实现里保留它，是为了与文献中的公式一致。

3.4 饱和因子的两个极限（这是理解 k1​ 的关键）#

f(tf)=tf+Ktf(k1​+1)​,K 固定

  • k1​→0：f(tf)→tf+Ktf⋅1​，但由于 K=k1​(⋯)→0，故 f(tf)→1（对任意 tf>0）。退化成二元模型：只看命中与否。所以 k1​ 小 = "出现次数不重要"。
  • k1​→∞：tf+k1​(⋯)tf(k1​+1)​≈k1​(⋯)tf(k1​+1)​→(1−b)+b∣d∣/avgdltf(k1​+1)​，饱和消失，变成线性：k1​ 大 = "出现次数几乎线性增益"。

于是 k1​ 的工程含义是：

k1​ 控制"重复一个词还能带来多少额外收益"的速度。 语料里"主题词的高频重复"确实是相关性信号（例如技术文档、法律条文），就该调大 k1​；语料里重复主要是噪声（例如网页里反复出现的导航词、模板文本），就该调小 k1​。

经典默认值 k1​∈[1.2,2.0]（常用 1.2）是一个跨语料的折中，不是最优值。它有意义的范围通常是 [0.3,3]；超出这个范围往往意味着语料或分词出了别的问题。

3.5 b 的语义：长度归一化是"两个极端之间的插值"#

把 K 里的 (1−b)+bavgdl∣d∣​ 单独看：

b K 效果
b=0 k1​（常数） 完全不做长度归一化：长文档因为词多而系统占优
b=1 k1​avgdl∣d∣​ 完全归一化：tf 被按长度折算成"每单位长度的出现率"
b∈(0,1) 二者插值 部分归一化（默认 0.75）

b 依赖一个隐含假设："文档主题的重复出现"与"文档长度"的关系是什么？ 如果一篇讲某个主题的长文档里，该主题词的词频随长度同比增长（即"长度只是量的增加，主题强度不变"），b=1 就是对的。但如果一篇更长的文档里，主题词的出现更多样（长度增长带来新话题而非同一话题的重复），b=1 会过度惩罚长文档，此时该取较小的 b。

这解释了一个实践现象：在"文档长度差异巨大"的语料上（例如把一页说明书和一个 200 页手册混在一起），b 的选择比 k1​ 重要得多；而在长度接近的语料上（例如统一规格的产品文档），b 几乎无所谓。

3.6 为什么不带查询词频（BM25 与 BM25+ 之外的一个细节）#

完整的概率推导里会出现一个查询词频因子 k3​+qf(k3​+1)qf​。实践中绝大多数实现把它丢掉（等价于 k3​=0），原因是：网络查询里重复同一个词通常不表示更强的信息需求（更多是输入习惯或分词产物）。这是一个"推导给出但工程主动省略"的典型例子 —— 值得记住，因为推导告诉你公式里能有什么，工程告诉你该留什么。

四、稀疏检索的可行性：倒排索引与它的成本#

BM25 的值算得再对，如果没有廉价的方式找到"命中了哪些词"的文档，它也没法用。这一步靠倒排索引（inverted index）：

词项 → 倒排列表 [(doc_id, tf), ...]      （按 doc_id 排序，可压缩）

检索时：对每个查询词取倒排列表 → 求交集/并集 → 只对候选文档算 BM25。

复杂度（N 文档、平均长度 L、查询有 m 个词）：

操作 复杂度 说明
取一个词的倒排列表 O(dft​) 词典查询 O(1)（哈希或 FST）
累积打分（并集语义） O(∑t∈q​dft​) 最坏情况是所有词都极常见
求交集（AND 语义） O(mint​dft​)（按 df 升序推进） 用"按 df 从小到大处理"可大幅剪枝
常见词剪枝 跳过 df>θN 的词 与 IDF 趋 0 一致：它们本来就不该贡献分数

这里有一个漂亮的一致性：IDF 让常见词几乎不贡献分数，而倒排索引让常见词的处理代价最高 —— 两者指向同一个优化：跳过 df 超过阈值的词。这个技巧在工程上叫"停用词剪枝"，但它的正当性来自 IDF，不是来自一张停用词表。

关键结论：稀疏检索的成本随"查询词覆盖的文档数"增长，与 N 的关系是次线性的（因为不用扫全库）。这正是它能处理千万级文档的原因，也是稠密检索（第 3 节）需要专门的近似索引的原因 —— 后者天然要算全库相似度。

五、BM25 的三类失效：哪两类调参修不好#

现在进入本节最重要的部分。BM25 的失效可以分成三类，只有第三类与参数有关。

5.1 失效一：词汇不匹配（vocabulary mismatch）—— 结构性#

现象：查询用"如何提升模型推理速度"，文档里写"降低大语言模型解码时延的优化手段"。二者没有共同的实词，BM25 得分接近 0。

机制：BM25 的分数完全由 ∑t∈q∩d​ 决定 —— 一旦 q∩d=∅，分数恒为 0，与文档内容多相关无关。 这不是参数问题，是形式问题：k1​,b 只影响命中的词如何计分，无法创造不存在的命中。b 甚至会让情况更糟（长文档被归一化后，单次命中的分数更低）。

量级估算：设每个查询词在"相关文档"里被命中的概率为 phit​（取决于同义/变形/术语差异的概率），独立近似下，一篇相关文档的实词命中数服从二项分布。查询有 m 个实词时，"至少命中一个"的概率：

P(命中≥1)=1−(1−phit​)m

m \ phit​ 0.3 0.5 0.7
3 0.66 0.88 0.97
5 0.83 0.97 0.998
8 0.94 0.996 0.9999
12 0.99 0.9998 ≈1

读法：短查询（m 小）是词汇不匹配的重灾区 —— m=3、phit​=0.3 时有 34% 的相关文档一个词都不命中，直接被排除。而加长查询能显著缓解（因为只要有一个词命中就能进入候选池）。

这给出两条修补路径，注意它们都不在 BM25 内部：

  1. 扩大查询（query expansion）：加入同义词、缩写展开、上下位词 → 提高 phit​。代价是引入噪声词，可能污染排序（会有专门的一章讲查询改写与它的风险）。
  2. 加一路语义检索：让"意思相近但用词不同"能被另一套信号捕获 → 这就是混合检索（第 4 节）。

常见的错误对策：加大 k1​。它只会让"已命中的词"拿更多分，对"没命中"零帮助。诊断方法：看相关文档在候选池里的"零命中率"。如果这个比例高，问题在词汇层，调参无用。

5.2 失效二：语义不匹配与多义词 —— 结构性#

现象：

  • 查询"苹果的市值"，文档讲水果苹果的营养价值 —— 词全命中，但无关（假阳性）。
  • 查询"这个函数为什么会抛异常"，文档讲"异常处理的最佳实践" —— 共享"异常"但没有回答（相关但不回答）。

机制：BIM 的"独立性 + 只看词是否出现"假设丢掉了词序、句法结构与上下文。具体地：

  • 多义词：同一个词在两类文档里的 df 被合并统计，IDF 无法区分（"苹果"的 df 混合了公司与水果）；
  • 否定与修饰："不支持增量索引"与"支持增量索引"在词袋里几乎一样；
  • 组合性："A 比 B 快"与"B 比 A 快"共享全部实词。

这些全是词袋表示的固有损失，k1​,b 无法触及。

一个可用的诊断量：词袋充分性。对一批已标注相关的 (query, doc) 对，计算"仅凭词袋重叠能否区分相关与不相关"——例如用逻辑回归只输入重叠词特征，看 AUC。如果 AUC 已经接近 1，说明该语料上词袋信号够用（BM25 会很好）；如果 AUC 只有 0.7 量级，说明大量相关性信息在词袋之外，必须引入序列/上下文信号（重排、稠密检索）。这是第 4 章"是否需要重排"的判据来源之一。

注意词袋充分性必须用"难负样本"来测。如果负样本与查询毫无词重叠（例如拿"苹果市值"去对"膳食纤维"），任何简单特征都能把它们分开，AUC 恒为 1，这个实验就完全失去信息量。只有让负样本与查询共享实词（同词不同义、同主题不同问题），AUC 才会暴露出词袋的真实上限。 本节的代码示例会演示这组对比。

5.3 失效三：语料统计漂移与长度畸变 —— 这一类调参（部分）能修#

这一类是统计假设被破坏，不是表示能力不足。

(a) 语料统计漂移。 IDF 依赖 dft​/N 近似 ut​。当语料变化（新领域文档加入、分词器更换、语言混合），IDF 的含义随之改变：

变化 后果
加入大量新领域文档 领域词的 df 突增 → IDF 骤降 → 原本靠它命中的查询失效
分词器/停用词表更换 df 统计口径变了 → 全库打分尺度变了 → 历史阈值（如"分数 > 5 算命中"）全部失效
多语言混合 同一实体的中英文名算两个词项 → 命中率下降（又回到词汇不匹配）
语料极大 df≫1 时 logdfN−df​ 的动态范围被压缩，区分度下降

这一类部分可以用 b 与 avgdl 的重新标定缓解（当加入的文档显著改变平均长度时，旧 b 对应的归一化强度已经变了）。但 IDF 的绝对尺度变化无法靠参数修复 —— 因为参数是标量，而问题是全库的分布变了。正确做法是重新计算 IDF 统计并重新标定任何硬编码阈值。

(b) 长度归一化的反例。 前文说过 b=1 假设"词频随长度同比增长"。在真实语料里有两种典型违反：

  • 模板/导航文本：网页文档长度增长的主因是模板，主题词频不增长 → b 应该更大（强制折算），否则长模板文档被高估；
  • 多主题长文档：长度增长带来新话题，单个主题词的相对频率下降 → b 应该更小，否则长文档被过度惩罚。

这两者方向相反，且在同一份语料里可能同时存在（网页语料尤其如此）。这就是为什么"b 调参到底该往哪边调"常常没有稳定答案 —— 问题不在参数，在"一篇文档 = 一个主题"这个前提。第 2 章的切分策略，本质上就是在用更小的、主题更单一的单元去让这个前提重新成立。

本节的收敛结论：

失效一（词汇不匹配）：调参无效 → 查询扩展 / 混合检索
失效二（语义不匹配）：调参无效 → 上下文相关模型 / 重排 / 稠密检索
失效三（统计漂移）：部分可修   → 重算统计 + 重标定 b/阈值；根源常在切分粒度

六、什么时候该用稀疏检索（而不是"它是基线所以先用"）#

BM25 有明确的优势区间。判据不是"它简单"，而是任务是否需要精确匹配：

场景 BM25 优势来源
精确标识符：订单号、错误码、函数名、法律条款号、药品名 这些 token 必须逐字匹配，稠密模型会把它们泛化掉（见第 3 节失效四）
罕见专有名词：IDF 极高，一次命中就是强证据 稀疏的"证据强度"语义与任务完全对齐
长查询 / 文档集含大量共享术语 词频与长度的统计信号仍然有效
无标注数据、无 GPU 零训练成本，冷启动即可用
需要可解释的排序依据 每个词的 IDF 与贡献都可见（对比稠密的隐空间打分）
强合规/可复现要求 打分确定、无随机性、无模型版本漂移

反过来，下面这些是 BM25 的明确劣势区：短查询 + 同义改写密集（客服问答、口语提问）；跨语言检索；需要"语义蕴含"而非"词面匹配"的任务（"能退吗" vs "退货政策"）。

代码：从零实现倒排 BM25，并把三类失效变成可测的量#

下面只用标准库实现倒排索引 + BM25，然后把"词汇不匹配率"与"词袋充分性"变成可计算的诊断函数。不实现任何向量库或框架 API —— 这一节的对象是算法本身。

"""
极简倒排索引 + BM25，以及三类失效的量化诊断。

设计决策（都是刻意的，不是简化）：
  1. 分词用一个极简的正则切分，且把"分词器"做成可替换的组件 ——
     因为第 5.3 节说明"换分词器会改变 df，进而改变全库打分尺度"，这个耦合
     必须在代码结构里可见。
  2. 保留 k1、b 作为构造参数并给出默认值 1.2 / 0.75 —— 但要能一眼看出
     它们只出现在饱和项里，不进 IDF（证明"调参修不了词汇不匹配"）。
  3. 所有统计量（df、avgdl）在 build() 时一次算好；增量更新会使其过期，
     这一"过期"是刻意的：第 2 章会讲索引更新为什么是个真问题。
"""
import math
import re
from collections import Counter, defaultdict

TOKEN_RE = re.compile(r"[a-z0-9]+|[\u4e00-\u9fff]")


def tokenize(text: str):
    """可替换的分词器。中文按单字切（够用且不依赖任何分词库）。"""
    return TOKEN_RE.findall(text.lower())


class InvertedIndexBM25:
    def __init__(self, k1: float = 1.2, b: float = 0.75):
        self.k1, self.b = k1, b
        self.postings = defaultdict(list)   # term -> [(doc_id, tf)]  倒排
        self.forward = {}                   # doc_id -> {term: tf}     正向（打分用）
        self.doc_len = {}
        self.doc_text = {}
        self._avgdl = 0.0
        self._N = 0

    # ---------------------------------------------------------------- 建索引
    def build(self, docs: dict):
        """docs: {doc_id: text}。统计量在这里一次算好（增量更新见第 2 章）。"""
        self.postings.clear(); self.forward.clear()
        self.doc_len.clear(); self.doc_text.clear()
        for did, text in docs.items():
            toks = tokenize(text)
            self.doc_text[did] = text
            self.doc_len[did] = len(toks)
            tf_map = Counter(toks)
            self.forward[did] = dict(tf_map)     # 设计决策：显式维护正向索引，
            for t, tf in tf_map.items():         # 使打分不必扫描全部倒排列表
                self.postings[t].append((did, tf))
        self._N = len(docs)
        self._avgdl = (sum(self.doc_len.values()) / self._N) if self._N else 0.0
        return self

    # ---------------------------------------------------------------- 打分
    def idf(self, term: str) -> float:
        """IDF 只依赖 df 与 N —— 与 k1/b 无关，这是'调参修不了失效一'的形式证据。"""
        df = len(self.postings.get(term, ()))
        if df == 0:
            return 0.0
        return math.log((self._N - df + 0.5) / (df + 0.5) + 1e-12)

    def _sat(self, tf: int, dl: int) -> float:
        """
        饱和项 tf(k1+1) / (tf + k1((1-b) + b·dl/avgdl))。
        注意：k1→0 时该项→1（退化为二元）；k1→∞ 时退化为线性。
        """
        K = self.k1 * ((1 - self.b) + self.b * dl / (self._avgdl or 1.0))
        if K <= 0:
            return 1.0                      # k1 = 0 的极端：只看是否命中
        return tf * (self.k1 + 1) / (tf + K)

    def score(self, query: str, doc_id) -> float:
        dl = self.doc_len[doc_id]
        tf_map = self.forward[doc_id]
        return sum(self.idf(t) * self._sat(tf_map.get(t, 0), dl)
                   for t in tokenize(query))

    def search(self, query: str, k: int = 5, df_cutoff: float = 0.5):
        """
        并集语义 + 常见词剪枝。

        设计决策：df > df_cutoff·N 的词直接跳过 ——
        依据不是"停用词表"，而是 IDF 趋 0（它们本来就不该贡献分数）；
        同时这也是唯一能压住倒排列表长度的手段。
        """
        scores = defaultdict(float)
        N = self._N or 1
        for t in tokenize(query):
            plist = self.postings.get(t)
            if not plist or len(plist) > df_cutoff * N:
                continue
            w = self.idf(t)
            for did, tf in plist:
                scores[did] += w * self._sat(tf, self.doc_len[did])
        return sorted(scores.items(), key=lambda kv: -kv[1])[:k]


# ------------------------------------------------------- 诊断 1：词汇不匹配率
def zero_hit_rate(queries, relevant: dict, index: InvertedIndexBM25):
    """
    相关文档里"一个查询实词都不命中"的比例 —— 失效一的核心指标。

    为什么用实词：把 df > 0.5N 的词（停用词级）排除，否则虚词命中会掩盖问题。
    """
    total = miss = 0
    for q in queries:
        terms = [t for t in tokenize(q)
                 if index.postings.get(t) and len(index.postings[t]) <= 0.5 * index._N]
        for d in relevant.get(q, []):
            total += 1
            dtoks = set(tokenize(index.doc_text[d]))
            if not any(t in dtoks for t in terms):
                miss += 1
    return {"相关对总数": total, "零命中数": miss,
            "零命中率": round(miss / total, 3) if total else None,
            "诊断": "零命中率高 → 问题在词汇层，调 k1/b 无效"}


def hit_probability_bound(m: int, p_hit: float) -> float:
    """至少命中一个词的概率 1−(1−p)^m —— 用来说明短查询为什么最脆弱。"""
    return 1 - (1 - p_hit) ** m


# ------------------------------------------------------- 诊断 2：词袋充分性
def bag_of_words_sufficiency(pairs):
    """
    只用语料重叠特征做逻辑回归，看 AUC 能到多少。

    设计决策：这是"该不该上重排/稠密检索"的判据，而不是"BM25 好不好"的判据。
      · AUC 接近 1 → 词袋信号足够，稀疏检索会很强，重排收益有限
      · AUC 明显偏低 → 相关性信息大量在词袋之外，必须引入上下文相关模型

    为避免依赖第三方库，这里实现一个极简的梯度下降逻辑回归与手写 AUC。
    """
    def feats(q, d):
        qt, dt = set(tokenize(q)), set(tokenize(d))
        inter = qt & dt
        return [1.0, float(len(inter)),                          # 命中数
                len(inter) / (len(qt) + 1e-9),                   # 查询覆盖率
                len(inter) / (len(dt) + 1e-9)]                   # 文档覆盖率

    X = [feats(q, d) for q, d, _ in pairs]
    y = [float(lab) for _, _, lab in pairs]
    w = [0.0] * len(X[0])
    lr = 0.5
    for _ in range(400):
        grad = [0.0] * len(w)
        for xi, yi in zip(X, y):
            z = sum(wi * xij for wi, xij in zip(w, xi))
            p = 1 / (1 + math.exp(-max(-30, min(30, z))))
            for j in range(len(w)):
                grad[j] += (p - yi) * xi[j]
        w = [wi - lr * g / len(X) for wi, g in zip(w, grad)]

    # 手写 AUC：正负样本对的排序正确率
    pos = [sum(wi * xij for wi, xij in zip(w, xi)) for xi, yi in zip(X, y) if yi == 1]
    neg = [sum(wi * xij for wi, xij in zip(w, xi)) for xi, yi in zip(X, y) if yi == 0]
    if not pos or not neg:
        return None
    wins = sum(1.0 if p > n else 0.5 if p == n else 0.0 for p in pos for n in neg)
    auc = wins / (len(pos) * len(neg))
    return {"词袋充分性 AUC": round(auc, 3),
            "判据": "AUC 高 → 稀疏够用；AUC 低 → 需要序列/上下文信号（第 4 章重排）"}

    docs = {

三处关键设计决策：

  1. idf() 与 _sat() 被刻意拆成两个方法。这不是代码风格，而是把本节的中心结论写进结构：k1​、b 只出现在 _sat 里，idf 完全不含它们。于是"调 k1​ 修不了零命中"在代码层面就是显然的。
  2. search() 的 df_cutoff 剪枝依据 IDF 趋 0，而不是停用词表。这保证了"剪枝"与"打分"用的是同一个语义，不会出现"剪掉了本该有分的词"的自相矛盾。
  3. bag_of_words_sufficiency 用逻辑回归 + 手写 AUC而不是引入任何模型库。它的输出是一个判据（要不要上重排），不是性能指标 —— 所以实现可以简陋，但特征的语义必须清楚（命中数 / 查询覆盖率 / 文档覆盖率分别对应三种不同的"重叠"含义）。

练习#

  1. 推饱和因子：令 K 固定，画出（或列表算出）f(tf)=tf+Ktf(k1​+1)​ 在 k1​=0.5,1.2,3、tf=1,2,5,10,50 处的取值。回答：(a) k1​ 变大时，tf=1 与 tf=10 的分数比 f(10)/f(1) 怎么变？(b) 这对应"重复一个词值多少"的什么变化？(c) 为什么 k1​ 大在"技术文档"上更好，在"含大量模板文本的网页语料"上更差？

小结#

  • 检索的目标不是"哪篇文档最像查询"，而是"哪篇文档最可能相关"（概率排序原理）。BM25 是从 PRP 出发、经二元独立模型推导出来的排序函数。
  • "打分 = 每个词贡献相加"是"词间条件独立"假设的产物，不是天经地义的形式。这条假设被破坏时（多义词、否定、组合性），BM25 的失效是结构性的。
  • IDF 来自"用 df/N 估计 ut​"这一条近似：IDF=logdf+0.5N−df+0.5​。常见词自动降权，所以停用词表在 BM25 里是多余的。
  • k1​ 管词频饱和：k1​→0 退化为二元模型（只看命中与否），k1​→∞ 退化为线性（重复几乎线性增益）。语义是"重复一个词还能带来多少额外收益的衰减速度"。经典默认 1.2 只是跨语料折中，有意义范围约 [0.3,3]。
  • b 管长度归一化：b=0 不归一（长文档占优），b=1 完全归一（tf 折成出现率）。它依赖"词频随长度同比增长"这个隐含前提；网页模板文本与该前提相反，多主题长文档也与该前提相反 —— 所以 b 常常没有稳定答案，根源是"一篇文档一个主题"这个前提，归第 2 章的切分解决。
  • 倒排索引让稀疏检索的代价与 N 次线性；IDF 让常见词几乎无贡献，因此"跳过 df>θN 的词"这个剪枝在语义与性能上同时成立。
  • 三类失效，只有一类与参数有关：
    • 词汇不匹配（q∩d=∅ → 得分恒 0）：调参无效 → 查询扩展 / 混合检索；
    • 语义不匹配（多义词、否定、组合性）：调参无效 → 上下文相关模型 / 重排 / 稠密检索；
    • 统计漂移与长度畸变：部分可修 → 重算 df、重标定 b 与阈值。
  • 短查询是词汇不匹配的重灾区：1−(1−phit​)m 表明 m=3,phit​=0.3 时约 34% 的相关文档零命中。
  • 诊断工具有三个：零命中率（失效一）、词袋充分性 AUC（失效二 / 是否值得上重排）、df 分布与 avgdl 漂移（失效三）。
  • 稀疏检索的优势区间是"精确匹配"：标识符、错误码、专有名词、长查询、零训练冷启动、可解释与可复现。它不该被当作"过时的基线"，而该被当作"精确信号的那一路"。

下一节：稀疏检索靠"用词重叠"，那"意思相近但用词不同"能不能被直接建模？双塔模型给出了一个优雅的答案 —— 也带来了三个新的、可以预测的失效。我们把对比学习目标推出来，看清温度、批内负样本和难负样本各自在做什么。
