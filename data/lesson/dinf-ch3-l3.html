网络成为瓶颈的判据：什么时候扩带宽、什么时候改并行策略#

这一节要解决什么#

前两节把账算清了：单次集合通信多少字节（第 1 节）、一个 token 要付几次（第 2 节）。但账算清之后，真实会议里出现的是这样一个判断：

"我们的 TPOT 不达标，是不是网络带宽不够？要不要换 800G 网卡？"

这个问题没法用"通信占了 74%"来回答。因为第 2 节已经算出：decode、N=8、环形的通信占比 ρ=0.737 —— 通信确实占了七成。但通信的七成里，能用钱买的那部分几乎为零：

单次通信=延迟14.00μs​​+带宽0.032μs​​

带宽项只占 0.23%。所以 74% × 0.23% = 0.17% —— 把带宽扩到无穷大，端到端只快 0.17%。

这一节要把这个判断变成两个可测量、可计算的无量纲数，并给出它们对应的动作：

ρ=Tcomm​+WTcomm​​(通信在关键路径上占多少),sbw​=Tlat​+Tbw​Tbw​​(其中多少能花钱买)

ρ=Tcomm​+WTcomm​​(通信在关键路径上占多少),sbw​=Tlat​+Tbw​Tbw​​(其中多少能花钱买)

带宽→∞ 的加速上界=1−ρ⋅sbw​1​​

这个上界是本节的核心。它有一个很好的性质：只需要两个可直接测量的量（通信时间、可重叠窗口），就能判断"该不该买网络"。

本节的四件事：

  1. 两个诊断数：ρ 与 sbw​，以及它们的组合判据 ρ⋅sbw​（四象限诊断）。
  2. 一个独立于 α 的量：Unet​（每卡实际推出去的字节 / 链路带宽）。它与 ρ 指向相反的动作 —— 这正是"诊断"这件事的难点。
  3. 同一把尺子下的四个动作：扩带宽 / 降 N / 换算法 / 加重叠。给出"每个动作在当前 N 上是正收益还是负收益"的判据，以及带宽扩容的 break-even 倍数。
  4. 拓扑感知放置的三个旋钮：分层集合通信（省跨机步数）、rail 对齐（αeff​ 随绕行跳数涨）、rail 负载均衡（最差/平均 =G，与带宽无关）。

speedup_law 与 max_speedup 实现的是同一个 Amdahl：

Speedup(f)=1−ρsbw​(1−f1​)1​,f→∞lim​Speedup=1−ρsbw​1​

反解出"要达到 target 倍加速需要的最小 f"：

f∗=ρsbw​−(1−1/target)ρsbw​​

f∗=0.00112−0.04760.00112​<0⟹无解（任何带宽都到不了 1.05×）

这就是"买带宽"这条路的天花板：上界 1.001×，任何预算都达不到 1.05×。先算上界，再谈预算 —— 这是本节最有操作价值的一条工作流。

2.2 Unet​ 的两条阈值#

Unet​ 含义 动作
<0.3 链路空闲，排队延迟可忽略 加带宽无收益（瓶颈在 α/步数）

两条必须说清的边界：

  1. 这是每卡利用率。N 卡同时发，聚合流量是 N 倍。如果集群的汇聚链路（spine、上联口）超订，每卡 Unet​=0.2 也可能拥塞。所以 Unet​ 要在与被测链路相同的位置测（网卡 vs 上联口 vs spine）。
  2. 它是时间平均值。decode 的流量是脉冲式（每层两次突发），峰值利用率远高于平均。用 nvidia-smi/dcgm 的 1 秒均值会严重低估瞬时峰值 —— 这也是为什么 nccl-tests 的 busbw 在 decode 负载上偏乐观。

3.2 为什么"降 N"看起来总有效，但又总是次优#

看 N=16 环形那行：降 N 到 8 给 3.123→1.826（1.71×），仅次于换树形（3.10×）。但"降 N"有一个隐藏代价：显存。

降 N 可行⟺{T(N′)<T(N)ΨB​/N′+KV≤HBM​时间（本例总是满足）容量（常常不满足）​

降 N 可行⟺{T(N′)<T(N)ΨB​/N′+KV≤HBM​时间（本例总是满足）容量（常常不满足）​

这就是第 1 章"为时间而拆 vs 为容量而拆"在这里的再次出现。 如果容量已经卡住（N 不能降），那么唯一有效且无显存代价的动作就是换算法 + 加重叠。

"降 N 是负收益"这个结论与 decode 完全相反，原因值得单独说清：

  • decode：窗口 ∝1/N（访存，Tmem​∝1/N），通信 ∝N。降 N → 窗口变大、通信变小 → 双赢。
  • prefill：窗口也 ∝1/N（FLOP）。降 N（8→4）时窗口从 53.364 涨到 106.727（+53.4 ms），而通信只从 134.965 降到 115.108（−19.9 ms）→ 净增 33.5 ms，是负收益。

这条对比的一般形式：T=W(N)+C(N)，W=A/N、C≈cN，则

dNdT​=−N2A​+c ⟹ 降 N 有利⟺N<A/c​=N∗

一般判据（对 T=W(N)+C(N)，W=A/N，C≈cN）：

dNdT​=−N2A​+c ⟹ 降 N 有利⟺N<A/c​=N∗

所以"降 N"只在 N>N∗ 时有利 —— 这就是第 1 章 N∗ 的另一种用法。prefill 的 N∗ 很大（因为 A 大），所以 N=8<N∗，降 N 必然负收益。

"扩带宽"要给一个可执行的数字：扩到几倍才值得做？ 由 Amdahl 反解：

f∗=ρsbw​−(1−1/target)ρsbw​​

4.2 旋钮二：rail 对齐（αeff​ 与绕行跳数）#

rail-optimized 拓扑的结构是：每个节点有 K 张网卡，第 k 张接到第 k 条 rail 交换机；同一个 local rank 的卡走同一条 rail。这样"跨节点的同一位置卡"之间只有一跳，而"跨节点不同位置卡"要绕 spine。

用两个参数建模：

αeff​=αnet​⋅(1+cross_pose),βeff​=1+spillβnet​​

αeff​=αnet​⋅(1+cross_pose),βeff​=1+spillβnet​​

  • cross_pose：跨 rail 的比例（0 = 完全对齐，1 = 全部多绕一跳，2 = 绕两跳）。
  • spill：跨节点流量里被迫绕 spine 的比例（超订比导致）。

分层值得⟺2(P−1)αnet​ ≫ (分层的额外内核启动开销)

代码：两个诊断数、四动作横评与拓扑放置#

脚本只用标准库，做七件事：(1) 算 ρ 与 sbw​；(1b) 算 Unet​；(2) prefill 的同一张表；(3)(4) 四个动作的端到端横评；(5) 平环 vs 分层；(6) 放置质量的两个旋钮；(7) rail 负载均衡（含 optimal 贪心搜索）。

"""
网络成为瓶颈的判据 + 拓扑感知的放置策略（只用 Python 标准库）。

设计决策：
  1. **先算两个无量纲数，再做决定**：
       ρ     = T_comm / (T_comm + 窗口)        通信在关键路径上的占比
       s_bw  = 带宽项 / (延迟项 + 带宽项)       其中多少是"能用钱买"的
     ρ 高 → 该管通信；ρ·s_bw 高 → 该扩带宽。两者指向相反的动作，
     混着看必然给出错误建议（正文 §1）。
  2. **U_net 是第三个数，且它不含 α**：
       U_net = 每卡每 token 字节 × 单卡吞吐 / β
    它的价值在于"α 测得不准时仍可信"，用来交叉验证 ρ 的结论（正文 §2）。
  3. **"改并行策略"和"扩带宽"必须放在同一把尺子上比**，
     否则会得出"两个都做"的空话。尺子 = 同一个字节账 + 同一个重叠模型。
  4. 拓扑错配建模成"平环 vs 分层"：**两者的字节数完全相同**，
     差别只在每一步走的是 β_dom 还是 β_net。这把"拓扑"从玄学变成算术。
"""
from math import ceil, log2

DT = 2
L, H = 32, 4096
B_HBM = 3.35e12
A_DOM, B_DOM = 1.5e-6, 450e9     # 域内（NVSwitch）
A_NET, B_NET = 2.0e-6, 50e9      # 跨机（NDR IB）
A_SLOW, B_SLOW = 8.0e-6, 25e9    # 拥塞 / RoCE 落回（诊断用）


# ==================== (1) 全归约的 α-β 成本 ====================
def ring_ar(N, S, alpha, beta):
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * (N - 1)
    nbytes = 2 * (N - 1) / N * S
    lat, bw = steps * alpha, nbytes / beta
    return lat + bw, lat, bw, steps


def tree_ar(N, S, alpha, beta):
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * int(ceil(log2(N)))
    lat, bw = steps * alpha, (N - 1) / N * S / beta
    return lat + bw, lat, bw, steps


def ar(N, S, alpha, beta, algo="ring"):
    return (ring_ar if algo == "ring" else tree_ar)(N, S, alpha, beta)


# ==================== (2) 三个诊断数 ====================
def comm_share(N, S, alpha, beta, algo="ring", ars_per_layer=2, layers=L,
               T_window=None):
    """
    ρ = 通信时间 / (通信时间 + 可重叠窗口)，以及带宽占比 s_bw。
      s_bw = 带宽项 / (延迟项 + 带宽项)：ρ 里有多少是**能用钱买**的
    返回 (rho, s_bw, T_comm, T_window, lat, bw)。
    """
    t1, lat, bw, _ = ar(N, S, alpha, beta, algo)
    T_comm = ars_per_layer * layers * t1
    if T_window is None:
        # L 层合计的权重访存（decode 的窗口）
        T_window = layers * 12 * H * H * DT / N / B_HBM
    s_bw = bw / t1 if t1 else 0.0
    rho = T_comm / (T_comm + T_window) if (T_comm + T_window) else 0.0
    return rho, s_bw, T_comm, T_window, lat, bw


def bytes_per_token(N, S, ars_per_layer=2, layers=L, algo="ring"):
    """
    一个 token 在 TP 下**每卡实际推出去的字节数**：
        L · ars_per_layer · 2(N−1)/N · S      （环形，每步发 S/N 的 N−1 份）
        L · ars_per_layer · (N−1)/N · S       （树形，容量取下界）
    这个量与 α 无关、与 β 无关，只由模型与算法决定 —— 它是 U_net 的分子。
    """
    if N <= 1:
        return 0.0
    frac = 2 * (N - 1) / N if algo == "ring" else (N - 1) / N
    return layers * ars_per_layer * frac * S


def network_utilization(N, S, throughput_tok_s, beta, algo="ring", **kw):
    """
    U_net = 该卡每 token 发出的字节 × 单卡吞吐 / 该卡链路带宽。
      >0.7：排队延迟开始非线性（该扩容或减流量）
      <0.3：加带宽基本无收益（瓶颈在 α 或步数）
    ⚠️ 这是**每卡**利用率。N 卡同时发，聚合流量是 N 倍；
    "网卡饱和"与"单卡带宽不够"是两个判据（正文 §2.2）。
    """
    return bytes_per_token(N, S, algo=algo, **kw) * throughput_tok_s / beta


def speedup_law(rho, s_bw, f):
    """Amdahl：只加速"通信里的带宽项"（占 s_bw）时，f 倍带宽的端到端加速。"""
    return 1.0 / (1.0 - rho * s_bw * (1 - 1.0 / f))


def max_speedup(rho, s_bw):
    """带宽 → ∞ 时的加速上界（Amdahl 极限）。"""
    return 1.0 / (1.0 - rho * s_bw)


def break_even_f(rho, s_bw, target):
    """要达到 target 倍加速所需的最小 f（解析解）；无解返回 inf。"""
    denom = 1.0 - 1.0 / target
    if rho * s_bw <= 0:
        return float("inf")
    f = rho * s_bw / (rho * s_bw - denom)
    return f if f > 0 else float("inf")

# ==================== (3) 三种动作放同一把尺子上 ====================
def strategy_time(N, S, alpha, beta, algo="ring", ars_per_layer=2, layers=L,
                  weight_bytes=None):
    """
    端到端时间 = 窗口(N) + 通信(N)（串行口径，重叠在 decide 里单独处理）。
    窗口取"整模型权重 / N / HBM 带宽"——这是 decode 的窗口（第 2 节）。
    """
    if weight_bytes is None:
        weight_bytes = layers * 12 * H * H * DT
    window = weight_bytes / N / B_HBM
    t1, lat, bw, steps = ar(N, S, alpha, beta, algo)
    return window + ars_per_layer * layers * t1, window, ars_per_layer * layers * t1


def decide(N, S, alpha, beta, algo, eta, layers=L, weight_bytes=None):
    """
    四个动作的可比表：
      A 扩带宽 f 倍（β → fβ）：只减带宽项
      B 降并行度 N → N/2
      C 换算法 ring → tree（减步数）
      D 加重叠 η
    """
    if weight_bytes is None:
        weight_bytes = layers * 12 * H * H * DT
    T0, win, Tc = strategy_time(N, S, alpha, beta, algo, weight_bytes=weight_bytes)
    t1, lat, bw, _ = ar(N, S, alpha, beta, algo)
    rho = Tc / T0
    s_bw = bw / t1 if t1 else 0.0
    A = strategy_time(N, S, alpha, beta * 2, algo, weight_bytes=weight_bytes)[0]
    Np = max(1, N // 2)
    B = strategy_time(Np, S / 2 if Np else S, alpha, beta, algo,
                      weight_bytes=weight_bytes)[0]
    C = strategy_time(N, S, alpha, beta, "tree", weight_bytes=weight_bytes)[0]
    ov = max(0.0, Tc - eta * win)
    D = win + ov
    return {"T0": T0, "N": N, "A_bw2": A, "B_Nhalf": B, "C_tree": C, "D_overlap": D,
            "rho": rho, "s_bw": s_bw, "fmax": max_speedup(rho, s_bw),
            "U_hi": rho * s_bw > 0.5, "win": win, "Tc": Tc}


# ==================== (4) 拓扑感知：平环 vs 分层 ====================
def flat_ring(K, P, S, alpha_l, beta_l, alpha_g, beta_g):
    """
    一个 N=K·P 的"平环"（rank 顺序 = 先节点内后节点间）。
    环上共 2P 条跨机链路（每个节点两条边界），最差延迟取 max(α_l, α_g)，
    字节按链路比例分摊。这是"拓扑无视"的最小模型。
    """
    N = K * P
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * (N - 1)
    g = min(2 * P, N)
    l = N - g
    lat = steps * max(alpha_l, alpha_g)
    nbytes = 2 * (N - 1) / N * S
    bw = (l / N) * nbytes / beta_l + (g / N) * nbytes / beta_g
    return lat + bw, lat, bw, steps


def stratified(K, P, S, alpha_l, beta_l, alpha_g, beta_g):
    """
    两级分层全归约：岛内 2(K−1) 步走 β_dom；岛间 2(P−1) 步走 β_net。
    字节数与平环**完全相同**（都是 2(N−1)/N·S），差别只在每条链路的速度。
    """
    if K <= 1 or P <= 1:
        return ring_ar(K * P, S, alpha_l, beta_l)
    steps_l, steps_g = 2 * (K - 1), 2 * (P - 1)
    nbytes = 2 * (K * P - 1) / (K * P) * S
    lat = steps_l * alpha_l + steps_g * alpha_g
    bw = (2 * (K - 1) / (K * P)) * S / beta_l + (2 * (P - 1) / (K * P)) * S / beta_g
    return lat + bw, lat, bw, steps_l + steps_g

四处关键设计决策：

  1. comm_share 同时返回五个量（ρ、sbw​、Tcomm​、窗口、延迟/带宽项）。只返回 ρ 会让调用方以为"ρ 高就该扩带宽" —— 这正是本节要破除的误解。
  2. bytes_per_token 与 α 完全解耦。这是 Unet​ 能"交叉验证 ρ"的前提：两个诊断数如果都依赖同一个易测错的参数，交叉验证就没有意义。
  3. decide 把"降 N"的参数写成 S / 2，即假设"总激活量不变、参与 rank 减半，所以每 rank 的输入也减半"。这是一个刻意的简化：严格说 S 是"每 rank 的输入"，N 减半后每 rank 的输入应该不变或变大（活的 rank 少了，每卡要算更多）。两种口径下 (3) 表的"降 N"结论方向一致（都指向"收益远小于换算法"），但数值不要直接引用 —— 要精确算请把 S 保持不变重跑。
  4. flat_ring 的延迟取 max(α_dom, α_net)，stratified 分别取。两者的字节数公式都写成 2(N−1)/NS —— 这是刻意的，为了让"字节数相同、只有链路不同"这件事在代码里可见。

小结#

  • 两个诊断数：ρ=Tcomm​/(Tcomm​+W)（通信在关键路径上占多少）与 sbw​=Tbw​/Tcomm​（其中多少能花钱买）。只有 ρ⋅sbw​ 才是买带宽的收益，上界 1−ρsbw​1​。
  • decode 的诊断结论是"别买带宽"：N=16 环形 ρ=0.923（像瓶颈）但 sbw​=0.0008（买不到），ρ⋅sbw​=0.0007 → 带宽上界 1.001×。"ρ 高"绝不等于"该扩带宽"。
  • prefill 的结论相反：sbw​≥0.98，N=8 环形的 ρ⋅sbw​=0.710 → 上界 3.44×，f∗(1.5×)=2.43（"400G→800G"不够，需要更多）。
  • Unet​ 是独立的第三个诊断数（不含 α）：decode N=8 环形只有 896 KiB/token，1000 tok/s 时占 450 GB/s 的 0.2%。ρ 高而 Unet​ 低 = 延迟瓶颈的定义。 要让 Unet​ 过 0.3，吞吐得涨到十几万 tok/s —— 这是连续批处理（第 2 章）与带宽讨论的接口。
  • 四个动作同一把尺子：decode 下"换算法/加重叠"收益 1.6～3.1×，"降 N"1.7×（但受显存约束），"扩带宽"1.001×。prefill 下"扩带宽"2.64×（×8），"降 N"0.85×（负收益）。
  • "降 N"的双约束：时间判据 N<A/c​=N∗ + 容量判据 ΨB​/N+KV≤HBM。先问能不能降（容量），再问值不值（时间）。
  • Amdahl 反解给出采购规格：f∗=ρsbw​−(1−1/target)ρsbw​​。无解 = 这条路不存在；有解 = 拿到"扩几倍"的数字。
  • 拓扑感知的三个旋钮：分层（省跨机步数，字节数完全相同，N=64 时 5.14×）、rail 对齐（αeff​ 每多绕一跳涨 1 µs，延迟主宰区比 β 掉到 1/5 更伤：×2.13 vs ×1.05）、rail 负载均衡（naive 最差/平均 =G，optimal 接近 1，收益 4×，与带宽无关）。
  • 拓扑感知有代价：启动探测（秒级）+ 误判风险 + 弹性变差。P=2 时分层的账面收益（2.40×）可能被内核启动开销吃掉 —— 分层的额外内核开销 ∼μs× 次数，与 2(P−1)αnet​ 同量级。
  • 一句话："是不是网络带宽不够"这个问题的答案不写在"通信占比"里，而写在"通信时间的分解"与"链路利用率"两个数里；把这两个数算出来，问题就从"要不要买"变成"买几倍"或"这条路不存在"。

下一节：本节的所有判断都基于平均值 —— α、β、ρ、Unet​ 都是期望。但多机系统的真实体验由尾部决定：一个慢节点的 max 会拖垮同步屏障，一次链路抖动的超时会触发重试，而重试又吃掉容量余量。第 4 节把这些变成概率模型：次序统计量、重尾分布、超时的两条账、冗余与故障域，以及降级后的排队发散。
