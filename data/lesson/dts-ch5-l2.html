张量并行（TP）：切分数学与对 Attention / MLP 的具体切法#

数据并行省时间但不省显存，模型一大就装不下。一个自然的念头是"把矩阵切开分给不同卡"——这就是张量并行（Tensor Parallelism，TP）。难点不在"切开"这个动作，而在切完之后哪一步需要通信、通信量是多大。切得不好，每层都会插入一次代价高昂的 AllReduce，卡越多越慢。本课用两条矩阵恒等式把切法推导出来，并逐层算出通信账本。

一、概念讲解#

1. TP 切什么：切层内的矩阵，通信落在关键路径上#

TP 把单个算子（GEMM、Attention）的权重矩阵沿某个维度切开，t 个 rank 各算一部分再拼起来。关键区别：DP 的通信每个 step 一次（梯度），PP 的通信只在 stage 边界，而 TP 的通信每一层都要发生且在关键路径上——不通信就算不出下一步。

Megatron-LM 在 2021 年的系统论文里给了这条结论的实证口径：TP 用的是 all-reduce（每层前向、反向各两次），PP 用的是便宜得多的点对点，因此TP 一般只用在一个多卡节点内（例如 8 卡），跨节点交给 PP；论文的配置里峰值性能出现在"张量并行度 = 单节点 GPU 数"处。

2. MLP 的切法：列切 + 行切，中间不通信#

Transformer 的 MLP 是两层 GEMM 夹一个非线性：Z=GeLU(XA)、Y=Dropout(ZB)。切法由两条恒等式决定。

第一条（列切 A）：把 A=[A1​,A2​] 按列切成两半，则

[Y1​,Y2​]=[GeLU(XA1​), GeLU(XA2​)]

因为 GeLU 是逐元素函数，对每个输出元素独立作用。列切让非线性可以就地计算，中间不需要任何同步；如果改成行切，GeLU 之前就必须先把各部分加起来。

第二条（行切 B）：B=[B1​B2​​]，于是

Z=YB=Y1​B1​+Y2​B2​

也就是每个 rank 算出一个部分和，需要一次 AllReduce（求和）才能得到完整的 Z。注意通信发生在第二个 GEMM 之后，而不是两个 GEMM 之间——这正是"中间不通信"的意思。

3. f 与 g：一对共轭算子，一层共 4 次 AllReduce#

Megatron-LM 把上面两个位置抽象成一对共轭算子：

算子 前向 反向 对应位置
f 恒等（无通信） AllReduce 列切 GEMM 的输入梯度
g AllReduce 恒等（无通信） 行切 GEMM 的输出

一个 Transformer 层里有两处"列切 + 行切"的组合：MLP（第一层列切、第二层行切）和 Attention（QKV 列切、输出投影行切）。于是论文给出的结论是：前向需要 2 次 AllReduce、反向需要 2 次 AllReduce。这 4 次通信就是 TP 的全部代价，也是它必须待在高速域里的原因。

4. Attention 的切法：按 head 切是免费的#

多头注意力天然可切：H 个头之间本来就不相互作用，把 H 个头分给 t 个 rank，每个 rank 负责 H/t 个头，自注意力部分完全不需要通信。具体地：

  • WQ​,WK​,WV​ 沿输出维列切（等价于按 head 分），Q/K/V 各 rank 只算自己那部分头；
  • 每个 rank 对自己那几个头算 softmax(QK⊤/dh​​)V；
  • 输出投影 WO​ 按行切，各 rank 算出部分和后再 AllReduce（g 算子）——这一层就是 Attention 的唯一通信点。

约束直接：头数必须能被 t 整除，embedding 维与每头维度也要对齐，所以真实的 TP 配置几乎都是 2 的幂。

5. 通信账本：为什么 TP ≤ 8#

每次 AllReduce 的消息量就是激活 b⋅s⋅h 个元素（b micro-batch、s 序列长、h hidden），fp16 下字节数为 2bsh。层内不切序列，所以消息量不随 t 变小——这是 TP 与 DP 最本质的差别：DP 把消息量除以 P（梯度按参数切），TP 的消息量是固定的。而每卡的计算量却随 t 线性下降，于是

计算通信​∝24h2⋅bs/t2bsh⋅4​=3ht​

t 越大、h 越小，通信占比越高。示例 3 给出的示例参数很直观：h=8192、s=2048、micro-batch 1 时，t=8 在 300 GB/s 链路上通信只占每层计算的 28.2%，换成 25 GB/s 跨机链路则变成 256.2%——通信已经比计算还贵。这就是"TP 不跨机"的定量理由。

6. 序列并行：把激活也切了#

TP 只切权重，不切激活，所以每层要 AllReduce 的消息量不随 t 缩小。序列并行（Sequence Parallelism，SP）补上这一刀：把 LayerNorm、Dropout 这些逐 token 独立的算子按序列维切开，只在进入 TP 区（GEMM）前聚合。Megatron 论文给出的做法是用一对新的共轭算子替代 f 与 g：g 前向 all-gather、反向 reduce-scatter，gˉ​ 前向 reduce-scatter、反向 all-gather，充当"序列并行区"与"张量并行区"的转换器。收益有明确数字：激活内存减少 5 倍，激活重计算的时间开销降低 90% 以上；530B 参数的 GPT-3 风格模型在 2240 张 A100 上 MFU 从 42.1% 提升到 54.2%（快约 29%）。

7. 常见坑#

  • 把 TP 铺到跨机：每层 4 次 AllReduce 的延迟项会直接吃掉收益，见示例 3。
  • head 数不能被 t 整除：t 必须整除 head 数（以及 GQA 的 KV head 数），否则要么报错要么得到错误的切分。
  • 忘了 f/g 是成对的：列切处反向要 AllReduce、行切处前向要 AllReduce；只补一半会得到"数值上看起来在下降、其实梯度是错的"训练。
  • 用 torch.distributed 手写切分：PyTorch 已提供 ColwiseParallel / RowwiseParallel / SequenceParallel 三种 ParallelStyle，配合 parallelize_module 与 init_device_mesh 使用，比自己拼 AllReduce 更不容易错。

二、可运行代码示例#

两段代码用 numpy 模拟 t=4 的 TP：先验证 MLP 的列切 + 行切拼回来与单卡逐位一致，再验证 Attention 按 head 切后的等价性。第三段算 TP 的通信账本。全程不需要 GPU。

# ===== 示例 1：列切 + 行切：MLP 的张量并行与它唯一的一次 all-reduce =====
import numpy as np
rng = np.random.default_rng(0)

def gelu(x): return 0.5*x*(1+np.tanh(np.sqrt(2/np.pi)*(x+0.044715*x**3)))

b, h, t = 4, 32, 4                      # batch 4、hidden 32、张量并行度 4
X  = rng.normal(size=(b, h))
A  = rng.normal(size=(h, 4*h))/np.sqrt(h)      # 第一层：h → 4h
B  = rng.normal(size=(4*h, h))/np.sqrt(4*h)    # 第二层：4h → h

Z_ref = gelu(X@A) @ B                            # 单卡参考结果
def rank_mlp(r):                                 # 每个 rank 只拿 1/t 的列与行
    sl = slice(r*4*h//t, (r+1)*4*h//t)
    A_r = A[:, sl]                               # A 按列切
    B_r = B[sl, :]                               # B 按行切
    return gelu(X@A_r) @ B_r                     # 局部输出，形状 (b, h)
Z_parts = [rank_mlp(r) for r in range(t)]
Z_allreduce = sum(Z_parts)                       # 行切后需要 all-reduce（求和）
print("示例 1：MLP 张量并行（列切 A、行切 B，GeLU 可本地做）")
print(f"  4 个 rank 局部结果求和 == 单卡结果：{np.allclose(Z_allreduce, Z_ref, atol=1e-12)}")
print(f"  每 rank 参数量 {(A[:, :4*h//t].size + B[:4*h//t].size)}，单卡是 {(A.size + B.size)}")
print(f"  前向需要 1 次 all-reduce（每层共 2 次：MLP 一次 + Attention 一次）")

# ===== 示例 2：Attention 按 head 切，再在输出投影后 all-reduce =====
b2, s, heads, dh, t2 = 2, 8, 8, 4, 4
Xq = rng.normal(size=(b2, s, heads, dh))
Wq = rng.normal(size=(heads*dh, heads*dh))/np.sqrt(heads*dh)
Wo = rng.normal(size=(heads*dh, heads*dh))/np.sqrt(heads*dh)
def attention_from_heads(Q):
    H = Q.reshape(b2, s, heads, dh)
    out = np.zeros((b2, s, heads, dh))
    for hd in range(heads):
        q = H[:, :, hd, :]
        att = np.exp(q@q.transpose(0, 2, 1)/np.sqrt(dh))
        att = att/att.sum(-1, keepdims=True)
        out[:, :, hd, :] = att@q
    return out.reshape(b2, s, heads*dh)
Q_full = Xq.reshape(b2, s, heads*dh)@Wq
Y_full = attention_from_heads(Q_full)@Wo          # 单卡参考
hp = heads//t2                                     # 每个 rank 拿 2 个头
def attention_from_heads_rows(Q, heads_r, rows):
    H = Q.reshape(b2, s, len(heads_r), dh)
    out = np.zeros_like(H)
    for k, hd in enumerate(heads_r):
        q = H[:, :, k, :]
        att = np.exp(q@q.transpose(0, 2, 1)/np.sqrt(dh))
        att = att/att.sum(-1, keepdims=True)
        out[:, :, k, :] = att@q
    return out.reshape(b2, s, len(rows))
def rank_attn(r):
    heads_r = list(range(r*hp, (r+1)*hp))
    # 本 rank 只需要自己的 head：QKV 按 head 列切
    rows = [hd*dh + j for hd in heads_r for j in range(dh)]
    Q_r = (Xq.reshape(b2, s, heads*dh)@Wq)[..., rows]
    Y_r = attention_from_heads_rows(Q_r, heads_r, rows)
    Wo_r = Wo[rows, :]                             # 输出投影按行切
    return Y_r@Wo_r
Y_parts = [rank_attn(r) for r in range(t2)]
print("\n示例 2：Attention 头并行（8 头切给 4 个 rank，输出投影行切）")
print(f"  4 个 rank 局部结果求和 == 单卡结果：{np.allclose(sum(Y_parts), Y_full, atol=1e-12)}")
print(f"  每 rank 计算 {hp} 个头（单卡 {heads} 个头），通信仍是 1 次 all-reduce")

# ===== 示例 3：TP 的通信账本：每层 4 次 all-reduce 值不值 =====
def tp_layer(B_tok, s_len, hidden, t, tflops, beta_gbs, alpha_us=5.0, mfu=0.35):
    """返回 (每 rank 单层计算 ms, 每次 all-reduce 的 ms, 每 rank 每次发送字节)。"""
    tokens = B_tok*s_len
    acts = tokens*hidden*2                       # fp16 激活 = 一次 all-reduce 的消息量
    per_rank = 2*(t-1)/t*acts                    # ring：每 rank 发送 2(t-1)/t·s
    t_ar = 2*(t-1)*(alpha_us + (acts/t)/(beta_gbs*1e9)*1e6)/1e3   # ms
    comp = 24*hidden**2*tokens/(tflops*1e12*mfu)/t*1e3            # 每层 ~24h² FLOPs/token
    return comp, t_ar, per_rank

print("\n示例 3：TP 每层通信账本（micro-batch 1、序列 2048、hidden 8192、"
      "每卡 312 TFLOPS@35% MFU、α=5 us）")
print("  t   每层计算(ms)  单次 all-reduce(ms)  4 次通信(ms)  通信/计算  每 rank 发送(MiB)")
for t in (2, 4, 8, 16):
    c, ar, pr = tp_layer(1, 2048, 8192, t, 312, 300)
    print(f"  {t:<3} {c:12.2f} {ar:19.2f} {4*ar:14.2f} {4*ar/c:10.1%} {pr/2**20:16.1f}")
print("  同一条账本换成跨机 25 GB/s 链路（示例值）：")
for t in (2, 4, 8, 16):
    c, ar, pr = tp_layer(1, 2048, 8192, t, 312, 25)
    print(f"  {t:<3} {c:12.2f} {ar:19.2f} {4*ar:14.2f} {4*ar/c:10.1%} {pr/2**20:16.1f}")

三、练习#

  1. 实现：把示例 1 的 MLP 改成"两个 GEMM 都行切"，并补上 GeLU 前所需的 AllReduce；统计这样每层多出几次通信，解释为什么 Megatron-LM 选择"列切 + 行切"而不是"行切 + 行切"。
  2. 解释：f 与 g 为什么叫共轭算子？用链式法则说明"f 前向恒等、反向 AllReduce"和"g 前向 AllReduce、反向恒等"分别对应哪一步的梯度求和。
  3. 对比/验证：把示例 3 的 hidden 从 8192 改成 2048，重算 t=8 时"通信/计算"的比值；说明为什么小模型即使在同一台机器上也不该用大 t。
  4. 思考：TP 度 t=8、序列并行打开（SP）、序列长 8192、micro-batch 2、hidden 8192。写出 SP 区每 rank 的激活字节数、以及 g 算子一次 all-gather 的每 rank 收字节数；说明 SP 省的是显存还是通信。
