掩码自编码器 MAE#

上一课讲的对比学习，是"把正样本拉近、负样本推远"。这一课换一条完全不同的自监督路线——掩码自编码。它的灵感来自 NLP 的 BERT：把输入的一部分盖住，让模型去猜被盖住的内容。把"掩码重建"搬到视觉上，就是掩码自编码器 MAE（Masked Autoencoder）。MAE 的精髓在于一个乍看浪费的设计：掩掉 75% 的补丁。为什么盖得越多反而越好？为什么图像和文本在这里表现如此不同？搞清楚这些，你就理解了自监督学习里"信号冗余"这个关键概念。

一、概念讲解#

1. 从 BERT 到"盖图猜图"#

BERT 的做法是：随机遮住句子里的一些词，让模型根据上下文预测被遮住的词。因为词是离散的符号，一个词遮掉了，靠上下文往往猜不回来，所以 BERT 通常只遮 15%。MAE 把这个思路搬到了图像上：随机遮住一部分补丁，让模型根据剩下的补丁，重建出被遮住的像素。

但图像和文本有一个根本差异——空间冗余。一个词遮掉，语义就缺了一块；而图像里一块 16×16 的补丁，往往和周围高度相关（天空的一角、草地的一角）。遮得少，模型用"插值"就能糊弄过去，学不到深层语义。MAE 因此反直觉地把掩码比例拉到 75%：只留 1/4 的补丁给模型看，逼它必须理解全局结构和语义，才能把剩下 3/4 的内容猜出来。

2. 非对称设计：重编码器 + 轻解码器#

MAE 的第二个关键设计是"非对称"：

  • 编码器只处理可见补丁（25% 的那些）。被掩掉的补丁根本不进编码器，所以计算量、显存都大幅下降，能让编码器做得又大又深——这正是能训练大模型的前提。
  • 解码器很轻（只有几层），它的输入是"可见补丁的编码 + 被掩位置的共享掩码 token"，输出重建的像素。解码器只在预训练时用，训练完就丢掉，下游只用编码器。

这个分工很聪明：编码器负责"看懂"，只需要处理 25% 的补丁就能高效学习；解码器负责"画出来"，是临时的、用完即弃的。非对称让整个预训练既便宜又能撑起大模型。

3. 重建目标：归一化像素的 MSE#

MAE 的损失是在被掩补丁上做像素级的均方误差（MSE），比较"重建像素"和"真实像素"。一个重要的细节是：MAE 先对每个补丁的像素做归一化（减去均值、除以标准差），再在归一化后的空间里算 MSE。为什么？因为如果不归一化，模型会去学"平均颜色"这种和内容无关的东西；归一化后，模型被迫去重建补丁的纹理和结构（对比度、边缘），这些才是更有迁移价值的视觉特征。

这里有个和对比学习的呼应：对比学习靠"增强不变性"学特征，MAE 靠"重建高频细节"学特征。两条路得到的东西有重叠也有互补，第 3 课我们会正面比较它们。

4. 预训练之后怎么用#

MAE 预训练完，拿到的是编码器（通常基于 ViT）。要把它用于下游任务，主要有两种评估方式：

  • 微调（fine-tuning）：在编码器后接任务头（分类头、检测头），用有标签数据端到端微调。这是 MAE 主打的用法，效果最好。
  • 线性探测（linear probing）：冻结编码器，只在上面训练一个线性分类器。它衡量的是"特征本身的可分性"，更严格，MAE 在线性探测上的优势比对比学习更明显。

理解这两种评估方式的区别很重要，下一课讲"自监督 vs 监督"时，几乎所有公平比较都建立在这套评估协议之上。

二、可运行代码示例#

先实现 MAE 最核心的"随机掩码"逻辑，直观看到 75% 掩码率下图像还剩多少信息：

import torch

torch.manual_seed(0)


def random_masking(x, mask_ratio=0.75):
    """x: (N, L, D) 的补丁序列。随机掩掉 mask_ratio 比例的补丁。"""
    N, L, D = x.shape
    len_keep = int(L * (1 - mask_ratio))          # 保留的补丁数

    # 每个样本独立地生成随机噪声，按噪声大小选出保留的补丁
    noise = torch.rand(N, L, device=x.device)     # (N, L)
    ids_shuffle = torch.argsort(noise, dim=1)     # 打乱顺序的索引
    ids_keep = ids_shuffle[:, :len_keep]          # 保留前 len_keep 个

    x_kept = torch.gather(x, dim=1, index=ids_keep.unsqueeze(-1).repeat(1, 1, D))
    return x_kept, ids_keep, ids_shuffle


# 一张图切成的 196 个补丁，每个 64 维
x = torch.randn(2, 196, 64)
x_kept, ids_keep, ids_shuffle = random_masking(x, mask_ratio=0.75)

print("原始补丁数: 196")
print("保留补丁数:", x_kept.shape[1])   # 应为 49，即 25%
print("掩掉的补丁数:", 196 - x_kept.shape[1])

可以看到，196 个补丁只保留 49 个进编码器，其余 147 个被掩掉。编码器只算这 49 个 token，计算量直接降到原来的 1/4——这就是 MAE 能"用大模型做预训练还便宜"的底气。

接着写一个极简的"重建 + 归一化 MSE 损失"，体会重建目标的含义：

import torch.nn.functional as F


def patch_norm_mse(pred, target):
    """在归一化后的像素空间里算 MSE。pred/target: (B, num_masked, patch_pixels)。"""
    # 对每个补丁的像素做实例归一化：减均值、除标准差
    mean = target.mean(dim=-1, keepdim=True)
    var = target.var(dim=-1, keepdim=True).clamp(min=1e-6)
    target_norm = (target - mean) / var.sqrt()
    pred_norm = (pred - mean) / var.sqrt()
    return F.mse_loss(pred_norm, target_norm)


# 模拟 8 个被掩补丁，每个补丁 16*16*3 = 768 维像素
pred = torch.randn(8, 768)
target = torch.randn(8, 768)
print("归一化 MSE 损失:", patch_norm_mse(pred, target).item())

最后用一个完整但极简的 ViT 编码器 + 轻量解码器骨架，串起"掩码 → 编码 → 重建"的端到端数据流：

import torch.nn as nn

class MAESkeleton(nn.Module):
    """只展示 MAE 的结构骨架，不做真实训练。"""
    def __init__(self, patch_dim=768, enc_dim=64, dec_dim=32, mask_ratio=0.75):
        super().__init__()
        self.mask_ratio = mask_ratio
        self.encoder = nn.Linear(patch_dim, enc_dim)         # 简化编码器
        self.mask_token = nn.Parameter(torch.zeros(1, 1, dec_dim))
        self.decoder = nn.Linear(enc_dim, dec_dim)           # 简化解码器
        self.recon_head = nn.Linear(dec_dim, patch_dim)      # 重建像素

    def forward(self, patches):
        # patches: (B, L, patch_dim)
        x_kept, ids_keep, ids_shuffle = random_masking(patches, self.mask_ratio)
        enc = self.encoder(x_kept)                            # 只编码可见补丁

        # 解码：把可见补丁的编码和被掩位置拼回原顺序（此处简化为直接重建可见部分）
        dec = self.decoder(enc)
        recon = self.recon_head(dec)
        return recon, x_kept


m = MAESkeleton()
recon, kept = m(torch.randn(2, 196, 768))
print("可见补丁:", kept.shape)      # (2, 49, 768)
print("重建输出:", recon.shape)     # (2, 49, 768) —— 真实 MAE 会重建全部 196 个补丁

真实 MAE 比这复杂：它会把被掩位置的 mask_token 补回原序列再喂给解码器，最终输出全部 196 个补丁的重建，只对被掩的那 147 个算损失。上面骨架刻意做了简化，但"只编码可见补丁"这个最省算力的核心已经体现出来了。

三、练习#

  1. 把 mask_ratio 分别设为 0.3、0.75、0.9，打印保留补丁数，并解释为什么 MAE 在 0.75 附近表现最好，而 0.9 会太极端、0.3 又太"容易"。
  2. 用 timm 加载一个预训练 ViT，实现一个最小 MAE：编码器取 ViT 的补丁嵌入 + 前几层，解码器用一个两三层的小 MLP，在 CIFAR-10 或 STL-10 上做掩码重建预训练，可视化前几个 epoch 的重建效果。
  3. 比较两种损失：直接用原始像素算 MSE，和用归一化像素算 MSE。在同一批数据上分别训练几十步，观察重建图是"糊成一团平均色"还是"保留了纹理结构"，并解释原因。
  4. 思考：MAE 只重建被掩的 75%，为什么就能让编码器学到全局语义？如果改为重建"随机选的任意补丁"而非"被掩补丁"，会有什么不同？
