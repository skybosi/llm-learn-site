子系统边界与上下文隔离（为什么子 Agent 常常比"更大的提示"更好）#

这一节要解决什么#

前两节讲了多智能体的成本：通信、协调、重复、死锁。这一节讲它的收益 —— 而且要把收益也量化，因为"多智能体"唯一的正当理由就在这里。

最常见的做法是把任务规模当成拆分的理由："任务太大、上下文装不下，所以拆成多个 Agent"。这个推理只对了一半：

装不下⇒必须拆但装得下⇒不该拆

因为"更大的上下文"本身不是中性的。第 4 章讲过：上下文的效用不是信息量的单调函数 —— 干扰项会稀释注意力、位置偏差会让首尾主导结果。所以正确的对照不是"60k 上下文 vs 3 个 20k 上下文"，而是：

单上下文（相关信息 + 干扰信息）vsn 个子上下文（各自相关信息 + 通信开销）

子 Agent 的收益来自三件具体的事（不是"人多力量大"）：抗污染、压缩、并行；再加上第四件 —— 权限隔离。而它的代价是通信与协调（前两节已量化）。

这一节要给出边界怎么切的可操作准则，以及什么时候边界是错的。后者同样重要，因为有一个很贵的失败模式：把需要全局视野的任务硬拆开，得到"每个子任务都正确、合起来矛盾"的结果。

学完这一节你应该能回答：

  • 为什么"任务太大装不下"不是拆分的唯一理由？"装得下但拆开更好"的情形是什么？
  • 子 Agent 的收益能拆成哪四件事？各自的判据是什么？
  • 上下文隔离为什么能阻断错误传播？它阻断的机制是什么？
  • 什么样的任务切开之后会变贵？给出至少四条判据。
  • "子 Agent 就是用自然语言编程的工具"这句话的工程含义是什么？（提示：第 3 章的错误分类与反馈设计要求全部适用。）
  • 递归深度有没有上限？"深度换宽度"是什么意思？

一、隔离收益的形式化#

1.1 大上下文的问题不是"装不下"，而是信噪比#

先把"单体大上下文"的效用写成一个可讨论的形式：

Usingle​≈f(相关信息R​​)−g(干扰信息N​​)−h(位置偏差P​​)

三个符号的含义与依据：

符号 含义 依据
R 完成当前子任务真正需要的信息量 越多越好（正贡献、边际递减）
N 无关但存在的信息量（其它子任务的中间产物、废弃草稿、失败的尝试） 负贡献：干扰项稀释注意力（第 4 章）
P 位置偏差的强度：关键信息落在中段时的损失 首尾优势（第 4 章）

为什么这是一个"经验形式"而不是精确公式：f,g,h 的形状（尤其 g 的曲率）随模型与任务变化，必须实测。但这个形式有三个立的住的定性推论：

  1. N 是成本项：把无关信息塞进上下文主动损害性能，不只是浪费 token。
  2. U 对 R 边际递减：相关的信息超过某个量之后收益趋平，而 N 常常随 R 一起增长（"把所有相关文档都拿来"会把干扰也带来）。
  3. P 与 R 的位置有关：同样的 R，放在中段比放在首尾损失更大 —— 这是"关键信息要放首尾"的量化依据。

1.2 子 Agent 方案的效用#

拆成 n 个子 Agent 之后：

Umulti​≈i=1∑n​[f(Ri​)−g(Ni​)]−Ccomm​−Csummarize​−Ccoord​

其中每个子上下文里的 Ni​ 小得多（这是隔离的核心收益），但引入了三项成本。什么条件下 Umulti​>Usingle​？

i∑​g(Ni​)+（主上下文的 g(Nagg​) 差额）>Ccomm​+Csummarize​+Ccoord​

这个不等式给出三条判据（都可估计）：

判据 形式 含义
干扰削减量 ∑i​g(Ni​) 相对 g(Nsingle​) 的下降 子任务之间信息局部，才能拿到这个收益
通信开销 Ccomm​+Csummarize​（第 2 节已经能算） 子任务的输入输出必须可压缩
协调开销 Ccoord​（编排者思考 + 协商轮次） 子任务之间依赖弱，才能压低协调

反过来说：如果一个任务切开后，每个子任务仍然需要全部信息（Ni​≈N），那隔离收益为零，而通信与协调成本为正 —— 这就是负优化（第 2 节判据 ①）。

1.3 压缩比：隔离收益的第二个来源#

子 Agent 的第二个收益是它把大搜索空间压成一个结果：从 200 条里挑出 3 条、把 20 页文档压成 10 行结论。主上下文只接收"结论 + 证据句柄"：

主上下文增量=结论长度+句柄长度≪子任务的完整过程

所以隔离的总成本账要算清楚：

Cisolation​=n×csetup​+i∑​cwork,i​+压缩成本i∑​csummarize,i​​​+Ccomm​

Cbaseline​=cwork​+大上下文里失败更多？cretry​⋅E[失败次数]​​

关键：Csummarize​ 是隔离的新成本，而它常常被忽略。一个要把 50k token 的过程压成 500 token 结论的子任务，压缩本身就是一次模型调用（可能还要多次），有时比原任务还贵。如果子任务的产物不可压缩（必须原样传回），隔离的压缩收益就是零 —— 这是"什么任务切开后会变贵"的第一条判据。

1.4 抗污染：隔离最强的收益，也最难量化#

隔离的第三个收益不是"省钱"，而是阻断错误传播。机制很具体：

  • 子 Agent 的中间探索、错误尝试、被否决的方案都留在它自己的上下文里，不进入主上下文。
  • 主上下文只接收"结论 + 证据"，所以主 Agent 不会因为读到"曾经考虑过方案 X 后来否掉了"而重新动摇。
  • 第 1 章的"误差累积"与"目标漂移"都被削弱：目标漂移往往来自上下文里残留的旧目标表述，隔离把它们挡在外面。

用概率形式可以粗略量化。设每个"错误结论"被后续继承的概率为 β（判断力越弱、上下文越混乱，β 越大）。在单体方案里，一个错误的中间结论经过 k 步会被继承的概率约为 1−(1−β)k；在隔离方案里，错误只有在"结论被写进摘要"时才会传出去，概率大幅降低：

Ppropagate-single​(k)≈1−(1−β)k,Ppropagate-isolated​≈β⋅γsummary​

其中 γsummary​ 是"子 Agent 把这个错误写进它对外结论"的比例。如果子 Agent 能自我检查、或者它的结论会被主 Agent 校验，γ 就更小。 这就是"抗污染"的可讨论形式：隔离把"每一步都可能传播"变成"只有结论边界上可能传播"。

二、边界怎么切：五条可操作准则#

边界设计的目标是"最大化隔离收益、最小化通信与协调"。五条准则：

# 准则 判据 违反的后果
1 信息局部性 子任务所需信息量 ≤ 其独立预算的 60% 子任务仍需全局信息 → 隔离收益为零，纯付通信
2 产物可命名 输入输出都是可传递的对象（结构化结果 / 句柄），不是"理解" 接口不可传递 → 伪隔离（第 5 章 2.3）
3 失败可隔离 一个子任务失败不污染其它子任务的上下文 失败会扩散 → 协调成本爆炸
4 判据可下放 子 Agent 自带完成判据（不依赖主 Agent 判定） 主 Agent 必须反复介入 → 协调轮次 ×n
5 依赖最小 接口面窄（输入输出字段少） 每个字段都是一次同步义务 → 通信量随字段数增长

准则 1（信息局部性）是决定性的：它决定隔离收益是否存在。其余四条决定收益能保住多少。这个顺序很重要 —— 先问"切了有没有用"，再问"怎么切才不亏"。

准则 2 值得展开：产物必须能"被传递"，而不是"被理解"。反例：

✗ "输入：你对整个项目背景的理解；输出：一份更好的方案"
   → 无法校验、无法版本化、无法回退（第 5 章 2.3 的伪分解）
✓ "输入：句柄 h_3（上游产物）+ 摘要（≤200 字）；输出：{字段…} 的 JSON"
   → 可校验、可版本化、可回退、可缓存

三、隔离的四种作用#

3.1 抗污染（1.4）#

判据：子任务的中间过程长度 ≫ 结论长度，且中间过程里有大量"试错/否决"。 例子：从 200 个候选里筛 3 个 —— 199 个被否决的候选留在子上下文里，主上下文只看到 3 个。

3.2 压缩（1.3）#

判据：子任务的产物可被压缩（结论 + 证据），且压缩比高（如 50k→500）。 反判据：产物必须原样传回（大段代码、完整文档）→ 压缩收益为零，隔离变贵。

3.3 并行（墙钟，不是成本）#

判据：子任务之间无依赖（第 5 章第 1 节的依赖图给出）。 注意：并行只省时间，不省成本（第 5 章 1.2）。把并行当成本优化是错误归因。并行的上界由关键路径锁定。

3.4 权限隔离（与第 7 章衔接）#

判据：任务中存在需要不同权限等级的动作（只读 / 可逆写 / 不可逆写）。 机制：把不可逆操作集中在少数持有相应凭据的子 Agent 里，于是能力上限被结构限制：

一个只读子 Agent 不可能"不小心"付款⟸它没有付款工具的凭据

这比"在提示词里说不要付款"强得多。提示词是请求，权限是结构。

四、隔离的反面：什么时候边界是错的#

这是本节最实用的部分。四类"切开就变贵"的任务：

类型 为什么切开变贵 替代方案
需要全局最优 局部最优相加 ≠ 全局最优（例如"预算在 5 个方向间分配"：每个子 Agent 都想要更多） 单 Agent，或编排者持有全局约束并下发配额
需要一致的世界观 两个子 Agent 各自局部正确，合起来矛盾（术语不一致、时间线矛盾、风格断裂） 单 Agent + 共享术语表/风格指南（作为硬约束而不是背景信息）
强顺序依赖 串联度 s>0.8：每步输出是下一步唯一输入 → 切开只增加搬运（第 5 章第 1 节） 单 Agent 单循环
信息高度共享 每次同步都要搬运全量知识 → 通信量 ≈ 工作量的 n 倍 共享黑板（第 1 节 2.1）：一次写入、多次读取，搬运从 O(n) 降到 O(1)

第一类（全局最优）有一个特别隐蔽的变体：局部目标被写出后，子 Agent 会为自己的局部目标最大化。如果主 Agent 分给三个子 Agent 的任务是"把这一部分做到最好"，那么边界本身就成了它们竞争的根源 —— 而这不是任何子 Agent"不听话"，是激励结构导致的。

局部优化冲突⟺子任务的目标函数之和=全局目标函数

处置：显式下发约束（配额、上限、必须满足的全局性质），而不是只下发目标。约束是全局目标在局部可执行的投影。

第二类（一致的世界观）的处置细节：把"必须一致"的东西变成共享的硬约束（术语表、风格指南、模板），并且它们必须是同一份、带版本的（否则两个子 Agent 各自更新出自己的版本，反而不一致）。这就是"共享黑板 + 版本号"的又一个用途。

五、子 Agent 就是"用自然语言编程的工具"#

这是本节最重要的一个视角转换，它让第 3 章的全部要求自动适用于子 Agent。

子 Agent≡一个工具，它的实现是"一个带上下文的循环"

于是第 3 章的每一条都适用：

第 3 章的工具要求 对子 Agent 的对应要求
schema 设计（参数语义、可选性） 输入输出的字段必须显式、类型明确，不能是"你对背景的理解"
错误语义（不是把异常原样抛出） 子 Agent 失败时必须返回可行动的理由（缺什么、试过什么），而不是一堆内部日志
幂等与副作用 子 Agent 可能调用有副作用的工具 → 幂等键与去重同样必需（第 2 节 2.1）
最小权限 子 Agent 只拿自己需要的工具与凭据（3.4）
描述即契约 主 Agent 无法看到子 Agent 的内部实现，只能看它的描述 → 描述写错就是能力边界错（第 3 章开篇的论断）

特别重要的一条：子 Agent 必须能说"我不确定"和"我做不了"。如果它的输出只有"结果"一种形态，那么它面对无解时会编一个结果给出（这是模型的本能：任务要求输出，它就输出）。所以接口必须至少三态：

class SubAgentResult:
    status: str          # "done" | "cannot" | "uncertain"
    output: object       # done 时的产物
    reason: str          # cannot/uncertain 时的理由（必须可行动）
    evidence: list       # 证据引用（配合第 7 章的归因）
    cost: float

三态输出⟺子 Agent 能诚实表达边界⟹主 Agent 能做正确的回退决策（第 5 章第 3 节）

只有两态（成功/失败）的接口是设计缺陷：它把"不确定"逼成"成功"，而"不确定"是 Agent 世界里最常见的真实状态之一。

六、递归的边界#

子 Agent 能不能再拆？可以，但深度有上限，原因是成本随深度叠加，而隔离收益不叠加：

深度 d 的总成本=l=1∑d​(Ccomm(l)​+Csummarize(l)​+Ccoord(l)​)+Cwork​

而收益（信息局部性）在每一层是同一个数量级的削减 —— 第二层再拆时，每个子任务的 Ni​ 已经很小了，g(Ni​) 的边际收益远低于第一层。所以：

递归值得⟺g(Ni(l)​) 仍然很大（子任务仍然超载）

实践判据：递归深度通常不超过 2 层（主干 → 子 Agent；子 Agent 到需要再拆时，往往说明第一层的边界切错了）。替代方案是深度换宽度：不问"这个子任务能不能再拆"，而问"我能不能把第一层切得更宽、更平"。

边界错误的表现⟺一个子 Agent 还需要再拆⟹回到第一层的切法重审

代码：上下文隔离的收益/成本模拟器 + 边界切分决策器#

下面的代码实现：(1) 上下文预算与效用模型（相关 / 干扰 / 位置偏差）；(2) 隔离收益判据（信息局部性 + 可压缩性 + 依赖度 + 全局一致 + 并行度）；(3) 错误传播对比（单体 vs 隔离）；(4) 三态子 Agent 契约。

"""
ch6-l3：上下文隔离的收益/成本模拟器 + 边界切分决策器。

设计目标：把"子 Agent 比更大的提示更好"这句话变成可算的成本账，
并明确边界切错的四种判据。
"""
from dataclasses import dataclass, field


# ==================== (1) 上下文效用模型 ====================
@dataclass
class ContextModel:
    """U ≈ f(R) - g(N) - h(P)。

    ★ 设计决策：h（位置偏差）单独建模，而不是折进 g。
      因为它的处置方式不同：干扰要靠"不放进去"，位置偏差要靠"放对位置"。
    """
    f_gain_per_k: float = 0.012      # 每 1k 相关 token 的效用增益上限（边际递减见 f）
    f_saturation_k: float = 40.0     # 相关信息的饱和点（k token）
    g_penalty_per_k: float = 0.020   # 每 1k 干扰 token 的效用损失（近似线性）
    h_mid_penalty: float = 0.15      # 关键信息落中段的最大损失

    def f(self, r_k: float) -> float:
        import math
        return self.f_gain_per_k * self.f_saturation_k * (1 - math.exp(-r_k / self.f_saturation_k))

    def g(self, n_k: float) -> float:
        return self.g_penalty_per_k * n_k

    def h(self, key_at: str) -> float:
        return {"start": 0.0, "end": 0.0, "middle": self.h_mid_penalty}.get(key_at, self.h_mid_penalty)

    def utility(self, r_k: float, n_k: float, key_at: str = "start") -> float:
        return round(self.f(r_k) - self.g(n_k) - self.h(key_at), 4)


def single_context(related_k: float, irrelevant_k: float, key_at: str = "start",
                   m: ContextModel | None = None) -> dict:
    m = m or ContextModel()
    return {"方案": "单上下文", "相关 token": related_k, "干扰 token": irrelevant_k,
            "效用": m.utility(related_k, irrelevant_k, key_at),
            "上下文总量": related_k + irrelevant_k}


def isolated_context(subtasks: list[dict], proc_k: float = 60.0,
                     summary_k: float = 0.8, comm_k: float = 1.2,
                     m: ContextModel | None = None) -> dict:
    """子 Agent 方案。

    每个子任务：subtasks[i] = {"related_k":…, "irrelevant_k":…, "compressible":bool}
    ★ 设计决策：显式把"压缩成本"proc_k 计入 —— 把 60k 过程压成 0.8k 结论本身要花模型调用，
      这是隔离的新成本，也是最常被忽略的一项（1.3）。
    """
    m = m or ContextModel()
    total_u, details = 0.0, []
    for i, s in enumerate(subtasks):
        u = m.utility(s["related_k"], s["irrelevant_k"], "start")
        total_u += u
        cost = m.g(proc_k) if s.get("compressible", True) else 0.0
        details.append({"子任务": i + 1, "效用": round(u, 4),
                        "结论 token": summary_k,
                        "压缩成本(效用损失)": round(cost, 4)})
    agg_related = sum(s["related_k"] for s in subtasks)
    agg_summary = len(subtasks) * summary_k
    agg_comm = len(subtasks) * comm_k
    main_u = m.utility(agg_summary, 0.0, "start")   # 主上下文只装摘要
    return {"方案": "隔离", "子任务数": len(subtasks), "子任务效用合计": round(total_u, 4),
            "主上下文效用": round(main_u, 4),
            "总效用": round(total_u + main_u, 4),
            "通信 token": agg_comm,
            "详情": details,
            "基线总效用": single_context(agg_related, 0.0, "middle", m)["效用"]}


# ==================== (2) 隔离收益判据 ====================
@dataclass
class TaskShape:
    name: str
    locality: float            # 信息局部性 [0,1]：子任务所需信息自足程度
    compressibility: float     # 产物可压缩性 [0,1]
    dependency: float          # 子任务间依赖度 [0,1]
    needs_global: bool         # 是否需要全局一致的世界观/全局最优
    parallelism: float         # 可并行比例 [0,1]
    context_fit: float         # 单上下文可容纳性（>1 表示装不下）
    subtasks: int = 3


def isolation_decision(t: TaskShape) -> dict:
    reasons: list[str] = []
    if t.needs_global:
        reasons.append("✗ 需要全局一致/全局最优：局部最优相加 ≠ 全局最优")
        return {"任务": t.name, "结论": "不隔离", "理由": reasons,
                "替代方案": "单 Agent；或编排者持有全局约束并下发配额/术语表"}
    if t.context_fit > 1.0:
        reasons.append(f"✓ 单上下文装不下（u={t.context_fit:.2f}）：隔离是唯一可行路线")
    if t.locality >= 0.6:
        reasons.append(f"✓ 信息局部性高（{t.locality:.2f}）：隔离能真正削减干扰")
    else:
        reasons.append(f"✗ 信息局部性低（{t.locality:.2f}）：子任务仍需全局信息，隔离收益接近零")
    if t.compressibility >= 0.5:
        reasons.append(f"✓ 产物可压缩（{t.compressibility:.2f}）：主上下文只收结论 + 句柄")
    else:
        reasons.append(f"✗ 产物不可压缩（{t.compressibility:.2f}）：必须原样传回 → 隔离反而更贵")
    if t.dependency <= 0.4:
        reasons.append(f"✓ 依赖弱（{t.dependency:.2f}）：协调成本低")
    else:
        reasons.append(f"✗ 依赖强（{t.dependency:.2f}）：每次同步要搬运全量知识 → 用共享黑板")
    if t.parallelism >= 0.5:
        reasons.append(f"✓ 可并行（{t.parallelism:.2f}）：省墙钟时间（注意：不省成本）")

    positive = sum([t.context_fit > 1.0 or t.locality >= 0.6, t.compressibility >= 0.5,
                    t.dependency <= 0.4])
    verdict = "隔离" if positive >= 2 and t.locality >= 0.5 else "不隔离"
    alt = {"隔离": "子 Agent 拓扑（编排者 + 摘要/句柄接口）",
           "不隔离": "单 Agent + 工具；若上下文超载先做剪裁与引用（第 4 章第 3 节）"}[verdict]
    return {"任务": t.name, "结论": verdict, "理由": reasons, "替代方案": alt,
            "命中正向条件数": positive}


# ==================== (3) 错误传播对比 ====================
def propagate_probability(steps: int, beta: float) -> float:
    """单体：任一步的错误结论被继承的概率 1-(1-β)^k。"""
    return round(1 - (1 - beta) ** steps, 4)


def propagate_isolated(beta: float, gamma_summary: float, boundaries: int) -> float:
    """隔离：错误只在"被写进对外结论"时传播（1.4）。

    ★ 设计决策：boundaries 独立相乘 —— 每次跨边界都是一次独立的"是否写进摘要"的机会。
      这与单体"每一步都可能传播"形成对比：隔离把传播面从"步数"压到"边界数"。
    """
    p_one = beta * gamma_summary
    return round(1 - (1 - p_one) ** boundaries, 4)


# ==================== (4) 三态子 Agent 契约 ====================
@dataclass
class SubAgentResult:
    """★ 设计决策：必须三态（done / cannot / uncertain）。

    只有两态（成功/失败）的接口会把"我不确定"逼成"我编一个结果"，
    因为模型在本能上倾向于"任务要求输出，我就输出"。
    """
    status: str                 # done | cannot | uncertain
    output: object = None
    reason: str = ""
    evidence: list[str] = field(default_factory=list)
    cost: float = 0.0

    def __post_init__(self) -> None:
        assert self.status in ("done", "cannot", "uncertain"), self.status
        if self.status != "done":
            assert self.reason, "cannot/uncertain 必须给出可行动的理由"


class SubAgent:
    def __init__(self, name: str, inputs: list[str], outputs: list[str],
                 tools: list[str], judge: str) -> None:
        self.name, self.inputs, self.outputs, self.tools, self.judge = (
            name, inputs, outputs, tools, judge)

    def contract(self) -> dict:
        """接口即契约（第 3 章的 schema 设计在这里的全部含义）。"""
        return {"name": self.name, "输入字段": self.inputs, "输出字段": self.outputs,
                "可用工具": self.tools, "完成判据": self.judge,
                "返回状态": ["done", "cannot", "uncertain"]}

    def run(self, ctx: dict) -> SubAgentResult:
        """演示：输入缺字段 → cannot；证据不足 → uncertain。"""
        missing = [k for k in self.inputs if k not in ctx]
        if missing:
            return SubAgentResult("cannot", reason=f"缺少输入字段 {missing}，"
                                                   f"需要上游提供或换数据源")
        if ctx.get("evidence_count", 0) < 2:
            return SubAgentResult("uncertain", evidence=ctx.get("evidence", []),
                                  reason=f"仅 {ctx.get('evidence_count', 0)} 条证据，"
                                         f"不足以支撑结论：需要补充来源或降低结论强度")
        return SubAgentResult("done", output={k: f"<{k} 的值>" for k in self.outputs},
                              evidence=ctx.get("evidence", []), cost=1.5)

七处关键设计决策：

  1. ContextModel 把 h（位置偏差）与 g（干扰）分开建模。理由是两者的处置方式不同：干扰要靠"不放进去"（隔离/剪裁），位置偏差要靠"放对位置"（首尾优先）。合成一个参数会让两种手段无法分别评估。
  2. utility 里 g 是成本项（线性惩罚），f 是饱和增益（指数饱和）。演示里 (20, 0) 的效用 0.787 与 (20, 30) 的 0.427 对比，量化了 1.1 的第一条推论：把无关信息塞进上下文是主动损害，不只是浪费。
  3. isolated_context 显式把压缩成本 proc_k 计入（默认为把 60k 过程压成 0.8k 结论的效用损失）。这是 1.3 的重点：压缩本身是一次模型调用，是隔离的新成本，也是最常被忽略的一项。
  4. isolated_context 的返回里带 基线总效用，且刻意用 key_at="middle" 计算单体基线。这不是调参作弊，而是真实的对照条件：单体方案里关键信息必然落在长上下文的某处，而长上下文的中段是最差位置。把对照设成"单体 + 关键信息在开头"会系统性高估单体。
  5. isolation_decision 把"需要全局一致"提到第一个检查并直接返回"不隔离"。这是 4.1 第一类反面的硬化：局部最优相加 ≠ 全局最优时，其余指标再好也不该拆 —— 顺序错了会得到"各项指标都不错但结果矛盾"的方案。
  6. SubAgentResult.__post_init__ 用断言强制三态，且 cannot/uncertain 必须带理由。演示里三种输入分别得到 cannot（缺字段）、uncertain（证据不足）、done —— 这就是"子 Agent 必须能诚实表达边界"的接口形态。只有两态的接口会把不确定逼成编造。
  7. 演示最后一段把递归深度的成本叠加算出来（每层 1.2+0.8+1.5），并给出"深度 ≤ 2"与"需要再拆说明第一层切错了"两条实践准则。把"收益不叠加"的理由（第二层起子上下文已经很小，g(Ni​) 的边际收益骤降）写清楚，而不是只给一个数字上限。

小结#

  • "装不下"是拆分的充分条件，不是必要条件。真正的对照是"单上下文（相关 + 干扰）"vs"n 个子上下文（各自相关 + 通信/压缩成本）"。大上下文的问题不是容量，而是信噪比：U≈f(R)−g(N)−h(P)，其中 N（干扰）是主动的损害，P（位置偏差）要靠"放对位置"而不是"少放"来解决。
  • 隔离的收益有四项，各有判据：抗污染（中间试错不进入主上下文）、压缩（过程 → 结论 + 句柄）、并行（只省时间不省成本，上界由关键路径锁定）、权限隔离（能力上限被结构限制，比提示词强）。注意隔离有新成本 Csummarize​（压缩本身要花钱），产物不可压缩时这一项就吃掉全部收益。
  • 边界切分的五条准则，按重要性排序：信息局部性（决定性：决定收益是否存在）→ 产物可命名 → 失败可隔离 → 判据可下放 → 依赖最小。产物必须"可传递"而不是"可理解"，否则是伪隔离（第 5 章 2.3）。
  • 四类任务切开就变贵：需要全局最优（局部最优相加 ≠ 全局最优）、需要一致的世界观、强顺序依赖、信息高度共享。第一类最隐蔽：局部目标被写出后，子 Agent 会为自己的局部目标最大化 —— 这不是不听话，是激励结构。处置是下发约束（配额/上限/全局性质）而不是只下发目标；共享类问题用共享黑板把搬运从 O(n) 降到 O(1)。
  • 子 Agent ≡ 用自然语言编程的工具，于是第 3 章的全部要求自动适用：显式 schema、可行动的错误语义、幂等键、最小权限，以及"描述即契约"。接口必须三态（done / cannot / uncertain）：只有两态会把"不确定"逼成"编一个结果"，因为模型的本能是"要求输出就输出"。
  • 递归深度有上限（实践 ≤ 2 层）：成本逐层叠加而收益不叠加（第二层起子上下文的 Ni​ 已经很小）。"一个子 Agent 还需要再拆"应当被读作第一层边界切错的信号，正确反应是回到第一层重审切法（深度换宽度），而不是继续往下递归。
  • 抗污染可以粗略量化：单体 P≈1−(1−β)k（每一步都可能传播），隔离 P≈1−(1−βγ)m（只有 m 个边界可能传播，γ 是"把错误写进对外结论"的比例）。隔离把传播面从"步数"压到"边界数"，而降低 γ 的手段（子 Agent 自检、主 Agent 校验结论、强制证据引用）就是抗污染的工程抓手。
