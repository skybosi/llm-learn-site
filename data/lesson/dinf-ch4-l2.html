弹性伸缩与冷启动：带纯滞后的控制回路，与"提前决策"的价值#

这一节要解决什么#

第 1 节把容量 C 当成常数，只解决"怎么分"。真实的容量本身是控制变量：负载涨了要加副本，落了要回收。而这件事有一个前两章没有出现过的性质：

改变容量需要时间⟹弹性是一个带纯滞后（dead time）的控制回路

Tcold​=60 s 的含义不是"扩容慢一点"，而是：你在 t 时刻看到的负载，对应的容量要 t+60 s 才存在。 在这 60 s 内，无论控制器多聪明、观测多细，都改变不了集群的算力。这就是为什么"弹性的问题"不能用"调 PID 参数"解决。

先看一组数（本节模拟，同一份突发负载）：

固定 4 副本（不伸缩） : 违反率 93.22%，成本 46.66 / 千请求
反应式（周期 10s）    : 违反率 32.47%，冷启动 19 次，成本 16.43 / 千请求
反应式 + 8 副本起步    : 违反率 31.28%，冷启动 15 次，成本 15.85 / 千请求
预测式（提前 T_cold）  : 违反率  0.05%，冷启动 19 次，成本  0.27 / 千请求

四个方案的硬件与代码完全相同，唯一区别是"什么时候做决定"。 违反率从 32.5% 到 0.05% 是 650 倍的差距，而"反应式 + 预热"这种最常见的工程答案只把 32.5% 改善到 31.3% —— 因为预热池是有限的（8 个），一旦突发超过池子的容量，后面的请求仍然要等冷启动。

这一节要给出四样东西：

  1. 扩容判据：R≥λ/(μρt​) 以及为什么它是取整的（余量的代价在整数边界上跳）。
  2. 冷启动的分解：五项各自的量级，以及为什么"权重加载"之外的优化挤不出量级收益。
  3. 两个经济分界：预热的最优规模 kpre​ 与实例回收的空闲阈值 Tidle∗​ —— 它们都是"成本 vs 期望损失"的等式解。
  4. 联合目标函数：J=副本成本+∑(违反⋅Cslo​)，以及为什么它必须包含 Cslo​（否则"不伸缩"或"无限扩容"永远赢）。

先把符号写死：

符号 含义 本节取值
λ(t) 到达率（随时间变） 20→120 req/s
μ 单副本服务率 8 req/s
ρt​ 目标利用率（=1−余量） 0.7
Tcold​ 冷启动时间（从决定到可服务） 60 s
Tperiod​ 观测/决策周期 10 s
Tidle​ 空闲实例保留时长 由 §3 的公式定
c 副本单价 4 元/h
Cslo​ 一次 SLO 违反的代价 0.05（元）
Pviol​ "回收后被立刻打回"的概率 0.05 / 0.2 / 0.5

一、扩容判据：一个不等式与它的取整效应#

最朴素的判据来自排队论的基本事实：稳态队列要有限，就必须有剩余容量。

R≥μρt​λ​​其中 ρt​<1 是留给突发的余量

但它有一个常被忽略的性质：R 是整数。所以"多留一点余量"在中小集群里不是连续的成本，而是整数跳变：

λ ρt​=0.9 0.8 0.7 0.6 0.5
20 2.8 3.1 3.6 4.2 5.0
120 16.7 18.8 21.4 25.0 30.0
480 66.7 75.0 85.7 100.0 120.0

λ=20 时：ρt​=0.9 要 3 个副本，ρt​=0.5 要 5 个（1.67×），而利用率只降了 0.4。"余量"的价格在小集群里是阶跃的：算出的值刚过整数线，多留 10% 余量就要多买一整台。

这个现象的直接后果是：目标利用率不能拍一个数，要用"成本-违反"的总目标反解（§4）。因为 R 的阶跃意味着 J(R) 是分段常数 + 阶跃，它的最优点总落在某条整数线上。

二、冷启动的分解：只有一项值得优化#

把 Tcold​ 拆成五项（典型 70B 级模型的量级）：

阶段 时间 占比
容器调度 + 镜像拉取 6.0 s 10.0%
权重从对象存储加载 42.0 s 70.0%
引擎初始化（warmup / 显存池） 7.0 s 11.7%
CUDA graph 捕获 3.0 s 5.0%
健康检查 + 就绪探针 2.0 s 3.3%
合计 60.0 s 100%

把除权重加载外的四项全部优化到 0，Tcold​ 也只从 60 s 降到 42 s（−30%）​

而权重加载时间是可算的：

Tload​=对象存储出口带宽权重字节数⋅(1+副本并发数)​

两个可算的结论：

  1. 提高对象存储带宽是唯一有量级的动作。把带宽翻倍，Tload​ 从 42 s 到 21 s，Tcold​ 从 60 s 到 39 s（-35%）。
  2. "扫描式并发拉取"会互相抢带宽。一次扩容 20 个副本，如果每个都全速从同一存储拉 130 GiB，总传输量是 2.6 TiB —— 出口带宽成了新的瓶颈，Tload​ 反而变长。这就是预热池存在的理由：让"冷启动"发生在负载到来之前，而不是把它做快。

三、观测滞后与"纯滞后"的数学#

3.1 盲区周期数#

控制器在 Tcold​ 完成之前做的任何决策，都无法影响这段时间的容量。所以"盲区"是

Nblind​=⌈Tperiod​Tcold​​⌉

Tperiod​ Tcold​=60 s 120 s 300 s
5 s 12 个周期 24 60
10 s 6 12 30
30 s 2 4 10
60 s 1 2 5

读法：把观测周期从 60 s 缩到 10 s，盲区只从 5 个周期缩到 3 个 —— 而且这 3 个周期都是虚的，因为下限 Tcold​/Tperiod​ 与周期无关，只与 Tcold​ 有关。缩短周期买到的是"更早发现"，不是"更早生效"。

3.2 控制器会震荡：一个可算的边界#

设观测到的到达率用指数平滑：λ^t+1​=αλt​+(1−α)λ^t​。当 λ^ 越过 Rμρt​ 时扩容，扩容在 Tcold​ 后生效。这是一个"测量滞后 Tperiod​ + 执行滞后 Tcold​"的回路，它的稳定条件是

α≤1+Tcold​/Tperiod​2​​

本节参数（Tcold​/Tperiod​=6）给出 α≤0.286，而代码里用的是 0.5 —— 它在数学上是过冲的。模拟里"反应式"的违反率比"预热"只低 1.2 个百分点，一部分原因就是它的震荡：副本数在 19 次冷启动之间反复。

推论：在纯滞后面前，把反馈调慢（小 α）比调快更安全；而真正的解法是提前决策

四、两个经济分界#

4.1 回收分界：空闲实例留多久#

设：保留一个空闲实例的成本是 c 每小时；回收它之后，如果 Δt 内有请求到来，就要重新付 Tcold​ 的冷启动成本，并可能产生 Cslo​ 的违反代价。设"回收后被立刻打回"的概率是 Pviol​（这是一个可测的量：统计回收后 60 s 内该组是否被重新拉起）。

令两者相等：

保留成本3600c​Tidle∗​​​=回收的期望代价Pviol​Cslo​+3600c​Tcold​​​

保留成本3600c​Tidle∗​​​=回收的期望代价Pviol​Cslo​+3600c​Tcold​​​

Tidle∗​=c/3600Pviol​Cslo​+cTcold​/3600​=Tcold​+c3600Pviol​Cslo​​​

Tidle∗​=c/3600Pviol​Cslo​+cTcold​/3600​=Tcold​+c3600Pviol​Cslo​​​

它有一个极干净的形式：Tidle∗​=Tcold​+一个修正项。修正项由"违反代价 / 单价"决定。

代入 Tcold​=60 s、Cslo​=0.05：

c (元/h) Pviol​=0.05 0.2 0.5
2.0 64.5 s (1.075×) 78.0 s (1.300×) 105.0 s (1.750×)
4.0 62.2 s (1.038×) 69.0 s (1.150×) 82.5 s (1.375×)
8.0 61.1 s (1.019×) 64.5 s (1.075×) 71.2 s (1.188×)

Tidle∗​≈Tcold​；"早点回收省下的钱"几乎等于"重新启动的代价"​

Tidle∗​≈Tcold​；"早点回收省下的钱"几乎等于"重新启动的代价"​

这解释了一个常见的组织现象："弹性"与"成本优化"这两个团队会用同一套数据得出相反的结论。成本团队算的是"空闲实例每小时浪费 c"，弹性团队算的是"回收后的期望损失 ≈ cTcold​/3600" —— 两个数相等，所以决策完全取决于 Pviol​ 与 Cslo​ 这两个业务参数。

4.2 预热的最优规模#

预热 k 个实例的成本是 c⋅k（每小时），收益是"突发到达时不用等 Tcold​"。设突发到达时"需要预热的请求数"分布为 F(k)，则

k∗=argkmin​[ck+λburst​Cslo​(1−F(k))]⟹F(k∗)=1−λburst​Cslo​c​

k∗=argkmin​[ck+λburst​Cslo​(1−F(k))]⟹F(k∗)=1−λburst​Cslo​c​

读法：预热规模由"边际成本 = 边际期望损失"决定。如果 c/(λburst​Cslo​)>1（一次突发的期望损失小于一个副本的时价），那一个都不该预热 —— 直接让它排队。

本节算例里 c=4、λburst​Cslo​=120×0.05=6 元/h，所以 F(k∗)=1−4/6=0.33：只预热到"覆盖 33% 的突发规模"。这与模拟一致 —— 8 个预热实例把违反率从 32.47% 改善到 31.28%，收益确实很小。

五、联合目标函数与取舍#

J=容量成本副本∑​c⋅3600Δt​​​+SLO 成本请求∑​1[违反]⋅Cslo​​​​

本节模拟的 J（元/千请求）：

方案 副本·时 违反次数 SLO 成本 总成本 元/千请求
固定 4 副本 1.867 34310 1715.5 1717.4 46.66
反应式 7.190 11952 597.6 604.8 16.43
反应式 + 8 起步 7.801 11512 575.6 583.4 15.85
预测式 8.812 20 1.0 9.8 0.27

这张表是本节的存在理由：只看副本成本，固定方案最省（1.867）；只看违反率，预测式最好。只有把两者放在同一把尺子上，才能选出预测式（它多花了 4.7 倍的容量成本，但省掉了 1715 的 SLO 成本）。

三个边界要注意：

  1. Cslo​ 是业务参数，不是技术参数。把 Cslo​ 从 0.05 提到 0.5，最优策略会更偏向预测式（多买容量）；降到 0.005，最优策略会偏向"让它排队"（固定少量副本）。弹性策略的"对错"取决于 Cslo​，不取决于 SRE 的偏好。
  2. 预测式的成立前提是"负载形状可预测"。本节用的是合成的周期突发（30 s 线性爬升）。真实的日周期、活动开场、上游批处理都是可预测的；但"某个租户突然火了"不可预测 —— 那类负载只能靠预热池 + 限流兜住，不能用预测式。
  3. 不伸缩不是"稳定"，是"把成本变成了延迟"。固定 4 副本的 93.22% 违反率不是 bug，是把 J 里的 SLO 项推到了 1715。它的"便宜"只在 Cslo​→0 时成立。

代码#

这段程序是本节所有数字的来源。它把弹性建模成"M/M/c 风格"的离散事件模拟：每个实例是一个服务台，冷启动期间只计成本、不计容量；控制器按 EWMA 观测的到达率决定目标副本数。对比四种策略：固定、反应式、反应式 + 起步预热、预测式（按已知负载形状把决策提前 Tcold​）。

⚠️ 合成负载：到达过程是泊松 + 分段线性爬升，seed 固定，结果可复现但不对应任何真实业务。

"""第 4 章第 2 节：弹性伸缩与冷启动 —— 扩容判据、预热、实例回收的联合优化。

纯标准库。§1/§2/§3/§5 是公式与算例；§4 是离散事件模拟（⚠️ 合成负载，seed 固定）。
模拟采用"M/M/c 风格"：每个实例是一个服务台，空闲实例立即接管排队请求，
不足时才产生冷启动；冷启动期间该实例只计成本、不计容量。
"""
import math
import random

DT = 0.05           # 模拟步长（秒）
MU = 8.0            # 单副本服务率 req/s（每请求 125 ms）
LAM_LOW = 20.0
LAM_HIGH = 120.0
T_RAMP_START = 120.0
RAMP = 30.0
SLO_TTFT = 0.30
COST_REPL = 4.0     # 副本 $/h
COST_VIOL = 0.05    # 一次违反 SLO 的惩罚
T_COLD = 60.0
T_READY = 30.0      # 空闲实例保留多久；由 §5 的分界公式给出


def replicas_needed(lam, mu=MU, rho_target=0.7):
    return lam / (mu * rho_target)


def blind_windows(t_cold, t_period):
    return math.ceil(t_cold / t_period)


def cold_start_breakdown(components):
    tot = sum(v for _, v in components)
    return tot, [(n, v, v / tot) for n, v in components]


def arrival_rate(t):
    if t < T_RAMP_START:
        return LAM_LOW
    if t < T_RAMP_START + RAMP:
        return LAM_LOW + (LAM_HIGH - LAM_LOW) * (t - T_RAMP_START) / RAMP
    return LAM_HIGH


def idle_threshold(t_cold, c, c_slo, p_viol):
    """实例回收的空闲分界：保留成本 = 回收后被打回的期望代价。"""
    return (p_viol * c_slo + c / 3600.0 * t_cold) / (c / 3600.0)


# ---------------- 弹性模拟（⚠️ 合成负载） ----------------
class Inst:
    __slots__ = ("busy_until", "idle_until", "started")

    def __init__(self, t, started=True, idle_for=T_READY):
        self.busy_until = t
        self.idle_until = t + idle_for
        self.started = started


def simulate(mode, n_sec=420, seed=7, k_pool=4, t_period=10.0, alpha=0.5):
    """mode: fixed | reactive | preheat | predictive（见正文 §4）。"""
    rng = random.Random(seed)
    n = int(n_sec / DT)
    pool = [Inst(0.0, True) for _ in range(k_pool)]
    cold_pool = []                     # [(ready_at)] 正在冷启动的实例
    queue = []                         # [t_arrive]
    arrivals = violations = served = 0
    cost = 0.0
    cold_starts = 0
    filt = LAM_LOW
    win_arrivals, win_t = 0, 0.0
    last_scale = -1e9
    last_scale_down = -1e9
    max_queue = 0
    live_trace = []

    for step in range(n):
        t = step * DT
        lam = arrival_rate(t)
        # ---- 冷启动完成 → 加入可用池 ----
        done_cold = [x for x in cold_pool if x <= t]
        cold_pool = [x for x in cold_pool if x > t]
        for _ in done_cold:
            pool.append(Inst(t, True))
        # ---- 到达 ----
        k, p = 0, 1.0
        L = math.exp(-lam * DT)
        while True:
            p *= rng.random()
            if p <= L:
                break
            k += 1
        for _ in range(k):
            arrivals += 1
            win_arrivals += 1
            queue.append(t)
        # ---- 服务：每个空闲实例接管一个排队请求 ----
        idle = [x for x in pool if x.busy_until <= t and x.idle_until > t]
        take = min(len(idle), len(queue))
        for j in range(take):
            x = idle[j]
            x.busy_until = t + 1.0 / MU
            x.idle_until = x.busy_until + T_READY
        for _ in range(take):
            ta = queue.pop(0)
            served += 1
            if t - ta > SLO_TTFT:
                violations += 1
        # ---- 观测 + 伸缩决策 ----
        win_t += DT
        if win_t >= t_period:
            meas = win_arrivals / win_t
            filt = alpha * meas + (1 - alpha) * filt
            win_arrivals, win_t = 0, 0.0
            if mode != "fixed":
                target = math.ceil(replicas_needed(filt, MU, 0.7))
                if mode == "predictive":
                    lead = min(T_RAMP_START + RAMP, t + T_COLD + 5.0)
                    target = max(target, math.ceil(
                        replicas_needed(arrival_rate(lead), MU, 0.7)))
                live = len(pool) + len(cold_pool)
                if target > live and t - last_scale >= t_period:
                    for _ in range(target - live):
                        cold_pool.append(t + T_COLD)
                        cold_starts += 1
                    last_scale = t
                elif mode == "preheat" and live < k_pool:
                    for _ in range(k_pool - live):
                        cold_pool.append(t + T_COLD)
                        cold_starts += 1
                elif target < live - 1 and t - last_scale_down >= T_READY:
                    # 迟滞 + 冷却：只回收"老到不值得再留"的实例
                    cand = [x for x in pool if x.busy_until <= t
                            and t > x.idle_until]
                    drop = min(len(cand), live - target)
                    for x in cand[:drop]:
                        pool.remove(x)
                    last_scale_down = t
        # ---- 客户端超时：排队 > 1 s 即放弃 ----
        keep = [x for x in queue if t - x <= 1.0]
        violations += len(queue) - len(keep)
        queue = keep
        # ---- 回收过期空闲实例 ----
        if mode != "fixed":
            for x in list(pool):
                if x.busy_until <= t and t > x.idle_until:
                    pool.remove(x)
        cost += (len(pool) + len(cold_pool)) * COST_REPL * DT / 3600.0
        max_queue = max(max_queue, len(queue))
        live_trace.append((t, lam, len(pool) + len(cold_pool), len(queue)))
    cost += violations * COST_VIOL
    return dict(arrivals=arrivals, served=served, violations=violations,
                cost=cost, cold=cold_starts, max_queue=max_queue,
                live=len(pool) + len(cold_pool), trace=live_trace)


def viol_rate(r):
    return r["violations"] / max(1, r["arrivals"])


def cost_per_1k(r):
    return r["cost"] / max(1, r["arrivals"]) * 1000

五处关键设计决策：

  1. 冷启动用 cold_pool（一个"就绪时刻"的列表）建模，而不是给实例加状态机。原因：冷启动期间实例不提供任何容量，唯一重要的是"它什么时候可服务"。用一个浮点列表就够，避免了状态机里极易出现的"计了容量但没计成本"或反之的错误。
  2. 违反的判定分成两处：服务时判断 t - ta > SLO_TTFT（等太久了），以及超时清队时把 len(queue)-len(keep) 全记违反（永远没被服务的请求也是违反）。这两处不能合并，否则"排队到 1 s 后被丢弃"的请求会从统计里消失 —— 而那正是过载的最危险一段。
  3. live 的口径是 len(pool)+len(cold_pool)（已启动 + 正在启动），与成本口径一致。成本按同一口径累加，所以"冷启动期间也要付钱"这件事在模拟里是自动成立的 —— 这很关键，否则"无限扩容"看起来是免费的。
  4. 回收同时受两个条件约束：t > x.idle_until（实例自己已经空闲够久）与 t - last_scale_down >= T_READY（控制器冷却）。前者防止抖动，后者防止"刚扩又缩"。两个条件缺一个，模拟都会出现无意义的翻腾。
  5. 预测式的"提前量"取 T_COLD + 5 秒，即"让扩容在负载到达前完成"。这不是调参：Tcold​ 是物理下限，提前量小于它就没有意义。

读输出的三处要点：

  • (4) 段的 93.22% → 32.47% 是"有控制"的收益，32.47% → 0.05% 是"有预测"的收益。后者大 650 倍，而它的实现成本只是"知道负载形状"（一次离线统计）。
  • (4) 段的"峰值队列"是 172（固定方案）与 18（预测式）。队列长度比违反率更容易监控，且与 SLO 直接相关（第 3 节的 τ∗ 判据用它）。
  • (5) 段的 T_idle* 全部落在 1.02∼1.75×Tcold​ 之间：这印证了 §4.1 的结论 —— 回收阈值几乎由 Tcold​ 独立决定，c 与 Pviol​ 只是修正。

小结#

  • 弹性是一个带纯滞后的控制回路：Tcold​ 内做的任何决策都不改变这段容量。所以"缩短观测周期"买到的是更早发现、不是更早生效（盲区下限是 Tcold​/Tperiod​）。
  • 扩容判据 R≥λ/(μρt​) 是取整的，所以"多留一点余量"在中小集群里是阶跃成本：λ=20 时 ρt​ 从 0.9 降到 0.5，副本从 3 到 5（1.67×）。
  • 冷启动只有一项值得优化：权重加载占 70%，其余四项全清零也只省 30%。真正的解法是预热（把冷启动挪到负载之前），而不是把它做快。
  • 两个经济分界都是等式解：Tidle∗​=Tcold​+3600Pviol​Cslo​/c≈Tcold​（回收阈值几乎只由冷启动决定），F(k∗)=1−c/(λburst​Cslo​)（预热规模由边际成本 = 边际损失定）。
  • 联合目标函数 J=副本成本+∑违反⋅Cslo​ 是唯一正确的判据。只看副本数会选"不伸缩"（93.22% 违反），只看违反率会选"无限扩容"。Cslo​ 是业务参数，它的取值决定弹性策略的对错。
  • 本节最强的数字：预测式（提前 Tcold​ 决策）把违反率从反应式的 32.47% 压到 0.05%、元/千请求从 16.43 压到 0.27。提前一分钟决策比快一分钟扩容值钱 650 倍。
  • 一句话：弹性做得好不好，不由"扩容快不快"衡量，而由"决策超前量够不够 Tcold​"衡量。

下一节：本节把 SLO 当成一个已经给定的约束（TTFT ≤ 300 ms），只优化"要几个副本"。但 SLO 本身是容量参数：p50 与 p99.9 对应的副本数能差 1.67 倍，而"TTFT 超时"与"TPOT 超时"是两个不同的排队系统。第 3 节把 TTFT/TPOT 的百分位目标反解成副本数与 KV 显存，给出 R∗=max(Rtail​,Rslots​) 的联合解与 $/1M output token 的 U 形曲线。
