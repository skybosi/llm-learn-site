用 Triton 重写第 6 章的两个算子并对比#

第 6 章你手写过归约与 FlashAttention：前者要决定 warp shuffle 怎么做树、后者要自己管在线 softmax 的 alpha 与累加器缩放。用 Triton 重写，少掉的是同步与布局代码，但掩码、两段归约、运行 max 这三件算法层面的事一件都没少。这一课把它们重写一遍，并量出"换框架后哪些变了、哪些必须自己负责"。

一、概念讲解#

1. 重写的对象：归约与 FlashAttention#

选这两个算子是因为它们恰好覆盖两类难点。

行归约（如 softmax 的分母、LayerNorm 的均值）：每个 program 负责若干行，行内归约。手写版的核心是"两级树 + warp shuffle"；Triton 版的核心只有一句 tl.sum(x, axis=1)——但 program 之间还得你自己再归约一次，这就是两段式归约（two-stage reduction）：第一段 P 个 program 各算一部分和，第二段把 P 个部分和收起来再算一次。

FlashAttention：第 6 章讲过它的三层含义（分块、在线 softmax、重算）。Triton 版把"分块"翻译成 BLOCK 常量、"在线"翻译成对 m_i（运行最大值）与 l_i（运行分母）的更新。

2. 掩码：三种越界语义，抄错一种就静默算错#

tl.load 的 mask + other 不是"性能优化"，是语义的一部分。同一个 tl.arange(0, BLOCK) 越过边界时：

场景 越界位置的正确填充 抄错会怎样
GEMM 的 K 维 other=0.0 乘 0 无害；若用 % K 折叠（教程写法）也凑巧不错，因为贡献是 0
行归约/求和 other=0.0 若沿用"取模折叠"，把本行的元素又加了一遍——静默错误
softmax / attention 的打分 other=-inf 填 0 会让 exp(0)=1 参与归一化，注意力分数被平均掉

下一节的第 1、3 段分别把"取模折叠把 19.0 算成 25.0"和"填 0 导致整行报废"跑出来看。

3. tl.sum 的两段结构与误差账#

tl.sum 在 program 内做的是树形归约（不是顺序累加），这是它比单线程顺序累加准得多的原因。归约误差取决于两个量：累加项数与动态范围。

下一节的实验：106 个混合量级 float32，float64 参考值 52724.732285——单线程顺序累加得 52726.2031（相对误差 2.79×10−5），"每 1024 个一块出部分和、再归约 1024 个部分和"得 52724.732285（1.38×10−16，即 float64 舍入极限）。误差是被"更早缩小累加项数"修掉的：第二段只在 1024 个数上做一次归约，代价可忽略。

4. 在线 softmax：三行更新与它的不变量#

设第 j 块之后运行最大值 mj​、运行分母 ℓj​、运行累加器 Oj​，新来一块打分 S：

mj+1​=max(mj​, rowmax(S)),α=emj​−mj+1​,ℓj+1​=αℓj​+rowsum(eS−mj+1​),Oj+1​=αOj​+eS−mj+1​V

三行里最容易被漏的是累加器也要乘 α——O 的每一项都是相对于 mj​ 归一化出来的，m 一变，历史贡献必须跟着缩放。第 6 章的图 2（FlashAttention 的一轮 KV 块迭代）画的正是同一套更新，这里的 Triton 版在这一点上完全一致。

实验给出两个结论：

  • 有它与没有它是"能不能跑"的区别：把 q 放大到 logit 超过 float32 的 exp 上限（约 88.7）后，不做 max 减法的朴素实现第一块就上溢成 inf，最终 max|O-ref| = nan（整行报废）；在线法误差 5.45×10−7。两遍法（先扫全行求 max）误差 0，但要多遍历一遍 K/V。
  • 块大小几乎不影响精度：固定 program 持有 256 行，BLOCK_N 取 16 / 64 / 256 时 max|O-ref| 都是 5.82×10−7。扫描还给出"每块需要 rescale 的行数"：BLOCK_N=16 时前几块是 256、141、90、49 行，BLOCK_N=256 时没有块间 rescale。块越小 → rescale 越频繁 → 精度略降，换来片上占用变小、program 数变多。

5. 片上容量就是 program 的粒度#

FlashAttention 的关键不是算法更省 FLOP（它的 FLOP 数和普通注意力同阶，分块还带来少量重复计算），而是把 M×N 的中间矩阵 S/P 留在片上。把 HBM 流量数一遍（fp16）：

形状 朴素注意力 分块在线 FLOPs 在线实现算术强度
1024×1024, d=64 10 MiB 0.5 MiB 0.2 GFLOP 512 FLOP/B
2048×2048, d=64 41 MiB 1.0 MiB 1.0 GFLOP 1024 FLOP/B
4096×4096, d=128 164 MiB 4.0 MiB 8.0 GFLOP 2048 FLOP/B
8192×8192, d=128 648 MiB 8.0 MiB 32.0 GFLOP 4096 FLOP/B

朴素版本里 S 是 M×N 的实体张量，softmax 的多遍读写都要过 HBM，所以流量是 O(MN)；分块在线只搬 Q/K/V/O，流量 O(Md+Nd)。但"留在片上"要还账：program 持有的 Q 块与 K/V 块直接吃 shared memory——d=32、fp16 时 BM=64/BK=64 单缓冲 12 KB、双缓冲 24 KB（228 KB/SM 约同驻 9 块）；BM=256/BK=128 涨到 64 KB（同驻 3 块）。BLOCK 不是越大越好，和第 1 课的结论完全一致。

6. 常见坑#

  • 越界列填 0 而不是 -inf：softmax 里这是最常见的静默错误（填 0 → exp(0)=1）。
  • 漏乘累加器的 α：只更新分母不更新 O，误差在小 logit 下看不出来，一旦 logit 跨度大就整行错。
  • p 不做精度处理就转低精度：p 统一转 fp16/bf16 能省带宽，但累加器必须留 fp32。
  • autotune 只调 BLOCK 不调 num_stages：attention 的瓶颈常在 shared memory 与流水深度，只扫 BLOCK 会漏掉一半空间。
  • 把"重写"当成"翻译"：Triton 版更短，但两段归约与因果掩码（causal mask）的边界仍要自己判。

二、可运行代码示例#

下面的纯 numpy 版本把归约与 FlashAttention 的算法层原样实现：掩码语义、两段归约、在线 softmax 的三行更新、以及搬运量账本。不需要 GPU。

# ===== ch7-l2：用 Triton 重写归约与 FlashAttention（纯 numpy，无 GPU 也能跑完）=====
import numpy as np, warnings
warnings.filterwarnings('ignore')

# ---------- 1. 掩码语义：为什么 tl.load 必须给 mask 与 other ----------
def load_masked(x, size, BLOCK):
    """复现 tl.load(ptr + tl.arange(0,BLOCK), mask=offs<size, other=0.0)"""
    offs = np.arange(BLOCK)
    return np.where(offs < size, x[np.minimum(offs, size - 1)], 0.0)
x = np.array([1.0, 2.0, 3.0, 5.0, 8.0]); size, BLOCK = 5, 8
m = load_masked(x, size, BLOCK)
print(f"[1] size={size}, BLOCK={BLOCK}：mask + other=0.0 之后 = {m.tolist()}")
print(f"    tl.sum → {m.sum():.1f}（正确）")
print(f"    若沿用 GEMM 教程的『% size 折叠』代替 mask：{x[np.arange(BLOCK) % size].sum():.1f}"
      f"  ← 多算一份数据。GEMM 里它被乘 0 兜住，归约类算子会静默算错")

# ---------- 2. 归约：单线程顺序累加 vs 两段式（block 内树形 + program 间再归约）----------
def seq_sum_f32(x):
    s = np.float32(0.0)
    for v in x: s = np.float32(s + v)
    return float(s)
rng = np.random.default_rng(11)
xs = (rng.standard_normal(1 << 20) * 100.0).astype(np.float32); xs[::1000] = 1.0
exact = float(np.asarray(xs, dtype=np.float64).sum())
BLOCK = 1024
part = np.array([np.asarray(xs[i:i+BLOCK], dtype=np.float64).sum() for i in range(0, xs.size, BLOCK)])
print(f"\n[2] 10^6 个混合量级 float32 求和，float64 参考 = {exact:.6f}")
print(f"    单线程顺序累加(float32)：{seq_sum_f32(xs):.4f}  相对误差 {abs(seq_sum_f32(xs)-exact)/exact:.2e}")
print(f"    两段式（{part.size} 个 program 各出一份部分和 → 再归约 {part.size} 个值）："
      f"{part.sum():.6f}  相对误差 {abs(part.sum()-exact)/exact:.2e}")

# ---------- 3. 在线 softmax：分块 + 运行 max / 运行分母 ----------
def attn(mode, q, k, v, BLOCK_N=64, BC=256):
    M, d = q.shape; N = k.shape[0]
    O = np.zeros((M, d)); info = []
    for m0 in range(0, M, BC):
        rows = slice(m0, min(m0 + BC, M)); qc = q[rows]
        if mode == 'naive':
            p = np.exp(qc @ k.T); O[rows] = (p @ v) / p.sum(axis=1)[:, None]; continue
        if mode == 'two':
            s = qc @ k.T; mx = s.max(axis=1); p = np.exp(s - mx[:, None])
            O[rows] = (p @ v) / p.sum(axis=1)[:, None]; continue
        mx = np.full(qc.shape[0], -np.inf); den = np.zeros(qc.shape[0]); acc = np.zeros((qc.shape[0], d))
        for n0 in range(0, N, BLOCK_N):
            s = qc @ k[n0:n0+BLOCK_N].T
            mx_new = np.maximum(mx, s.max(axis=1))
            alpha = np.exp(mx - mx_new)
            p = np.exp(s - mx_new[:, None])
            den = den * alpha + p.sum(axis=1)                   # 分母跟着缩放
            acc = acc * alpha[:, None] + p @ v[n0:n0+BLOCK_N]    # 累加器跟着缩放
            mx = mx_new
            if n0 + BLOCK_N < N:
                info.append((n0 // BLOCK_N, float(np.median(alpha)), int((alpha < 0.99).sum())))
        O[rows] = acc / den[:, None]
    return O, info

M = N = 256; d = 32
rng = np.random.default_rng(3)
k = rng.standard_normal((N, d), dtype=np.float32); v = rng.standard_normal((N, d), dtype=np.float32)
q8 = (rng.standard_normal((M, d), dtype=np.float32) * 8.0).astype(np.float32)
s = q8 @ k.T
ref8 = np.exp(s - s.max(axis=1, keepdims=True)); ref8 = (ref8 @ v) / ref8.sum(axis=1)[:, None]
print(f"\n[3] 溢出实验：M=N={M}, d={d}，q 放大到 logit 越过 float32 的 exp 上限（约 88.7）")
print(f"    logit 范围 [{s.min():.0f}, {s.max():.0f}] → np.exp(最大 logit) 直接上溢")
for mode in ('naive', 'two', 'online'):
    O, _ = attn(mode, q8, k, v)
    e = np.abs(O - ref8).max()
    print(f"    {mode:>6}：max|O-ref| = " + ("nan（inf/inf，整行报废）" if not np.isfinite(e) else f"{e:.2e}"))

q3 = (rng.standard_normal((M, d), dtype=np.float32) * 3.0).astype(np.float32)
s = q3 @ k.T
ref3 = np.exp(s - s.max(axis=1, keepdims=True)); ref3 = (ref3 @ v) / ref3.sum(axis=1)[:, None]
print(f"\n[4] 精度实验（q 缩小到不溢出，logit ∈ [{s.min():.0f}, {s.max():.0f}]）：扫 BLOCK_N")
print(f"    {'BLOCK_N':>7} {'块数':>5} {'max|O-ref|':>11} {'需要 rescale 的行数（逐块）':>34}")
for bn in (16, 64, 256):
    O, info = attn('online', q3, k, v, BLOCK_N=bn)
    cnt = ",".join(str(c) for _, _, c in info[:4])
    print(f"    {bn:>7} {N//bn:>5} {np.abs(O-ref3).max():>11.2e}   {cnt} …")

# ---------- 5. 片上容量决定 program 粒度 ----------
def smem_flash(BM, BK, d, elem=2): return (BM*d + 2*BK*d) * elem
print(f"\n[5] d={d}、fp16：一个 program 的片上占用（Q 块 + K/V 块）与 228 KB/SM 下的同驻块数")
for BM, BK in [(64, 64), (128, 64), (128, 128), (256, 128)]:
    sm = smem_flash(BM, BK, d)
    print(f"    BM={BM:>3}, BK={BK:>3} → 单缓冲 {sm/1024:>6.1f} KB；双缓冲 {2*sm/1024:>6.1f} KB"
          f" → 同驻 {228*1024//(2*sm)} 块")

# ---------- 6. 搬运量：分块在线把 O(MN) 的中间矩阵留在片上 ----------
def bytes_naive(M, N, d, elem=2):   # S/P 是 M×N，softmax 的多遍读写都经过 HBM
    return (M*d + 2*N*d)*elem + 5*M*N*elem + M*d*elem
def bytes_flash(M, N, d, elem=2):   # HBM 只见 Q/K/V/O
    return (M*d + 2*N*d)*elem + M*d*elem
print(f"\n[6] 朴素注意力要把 M×N 的 S/P 写回再读回；分块在线只搬 Q/K/V/O")
print(f"{'shape':>20} {'朴素 HBM':>10} {'分块在线':>10} {'FLOPs':>8} {'算术强度(在线)':>14}")
for M, N, d in [(1024, 1024, 64), (2048, 2048, 64), (4096, 4096, 128), (8192, 8192, 128)]:
    b1, b2 = bytes_naive(M, N, d), bytes_flash(M, N, d)
    f = 4.0*M*N*d
    print(f"{f'{M}x{N}x{d}':>20} {b1/2**20:>8.0f}MiB {b2/2**20:>8.1f}MiB {f/2**30:>6.1f}G {f/b2:>12.0f}")

把 6 段连起来看，"重写"到底重写了什么就清楚了：第 1、2 段是算法层的坑（掩码、两段归约），第 3、4 段是在线 softmax 的数值行为，第 5、6 段是资源账。Triton 只替你做掉第 5 段里"layout 与同步"那一小块，其余照旧。

可选，需自备或云上按需：把归约重写成 Triton kernel（对照 tl.sum 与第 6 章手写版的树形归约）：

# pip install triton；需要 NVIDIA GPU。行归约：每个 program 负责一行
import torch, triton, triton.language as tl

@triton.jit
def rowwise_sum_kernel(x_ptr, out_ptr, n_cols, BLOCK: tl.constexpr):
    row = tl.program_id(0)
    cols = tl.arange(0, BLOCK)
    x = tl.load(x_ptr + row * n_cols + cols, mask=cols < n_cols, other=0.0)  # 归约必须 other=0.0
    tl.store(out_ptr + row, tl.sum(x, axis=0))   # 块内树形归约由编译器展开

# 完整的 FlashAttention 见官方教程 06-fused-attention：它的 kernel 里就是
# m_i（运行 max）、l_i（运行分母）、acc *= alpha 这三件本课第 3 段模拟过的事。
# 观察替代方案（无 GPU 也能做）：
#   ① 用上面第 3 段的 numpy 实现当参考：它逐行对应 Triton 的 m_i / l_i / acc 更新；
#   ② 有 GPU 时与 torch 的 F.scaled_dot_product_attention 逐元素比对；
#   ③ causal 掩码的越界列必须 other=-inf（不是 0），把这一点做成单测：
#        attn 的行内 max 只会增大，alpha 恒在 (0,1]，一旦出现 alpha>1 就说明 max 更新写反了。

三、练习#

  1. 实现：把第 3 段的 online 分支里的 acc = acc * alpha[:, None] + ... 改成 acc = acc + ...，重跑第 3 段与第 4 段，分别记录误差。解释为什么在小 logit 场景下错误不明显，而在第 3 段那种跨度下会放大。
  2. 解释：为什么两段式归约能把相对误差从 2.79×10−5 压到 1.38×10−16？提示：从"浮点加法不满足结合律"与"累加项数"两个角度回答，并说明第一段的 BLOCK 取小或取大各有什么影响。
  3. 对比/验证：把第 4 段的 BLOCK_N 从 16 扫到 256，记录"需要 rescale 的行数"总和与误差。再把它和第 6 章的 CUDA 版实现（分块 + 在线 softmax）对照：哪些量在两者中同名同义、哪些量只存在于 Triton 侧。
  4. 思考：分块在线注意力的 FLOP 数与朴素实现同阶，分块还引入了块边界的重复计算，为什么它仍然更快？如果要给"值不值得重写"下一个判据，你会用第 3 章讲的哪个量来表述？
