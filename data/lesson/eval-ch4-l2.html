这一节要解决什么#

第 1 节把 judge 的偏差拆开了。这一节解决一个更落地的问题：既然偏差存在，判定 prompt 该怎么写，才能让结论尽量只反映被测对象的差异？

先明确一个立场：judge 的可复现性不是"跑两次结果一样"。同输入同输出只说明它确定性，不说明它可复现。真正的要求是：另一个人，在另一个时间，用你记录下来的材料，能重放出同一个结论。 这需要记录的东西远超一条 prompt 字符串。

本节分三块：

  1. 判定协议的设计：判什么（单点打分 vs 成对偏好 vs rubric 分解）、怎么保证位置对称、怎么处理平局与"都差"、怎么让输出可解析。
  2. 可复现性的硬要求：模型版本、解码参数、prompt 哈希、题目顺序、缓存与批次；以及"同一天内跑一次 vs 分三天跑"为什么可能给出不同结论。
  3. prompt 敏感性：换一个措辞、加一句强调、改一个 rubric 描述，结论会变多少？怎么把这种敏感性测出来而不是假设它不存在。

核心取舍会在最后一节给出：约束越强的输出格式，解析越稳定但越容易诱发"为了输出合法而编分数"；自由度越高的推理，判断质量可能更好但解析失败率上升。 这个取舍决定你的工程成本（重试、人工兜底、失败样本处理）。

一、判定协议：先决定"判什么"#

三种基本形态，各有明确的适用范围：

形态 输入 输出 适用 主要问题
成对偏好（pairwise） 问题 + 两个回答 A / B / 平局 模型选型、版本对比 需要 O(n) 次判定；不可加性；位置偏差
单点打分（pointwise） 问题 + 一个回答 1~5 分 粗筛、监控、回归门禁 尺度漂移、集中趋势、跨批次不可比
rubric 分解（rubric-based） 问题 + 一个回答 + 分项标准 各分项 + 汇总 需要可解释性、需要定位失败 分项权重任意；rubric 本身要验收

为什么首选成对偏好：因为人类与模型在"哪个更好"上的判断一致性，系统地高于"这个值几分"。相对判断把绝对尺度消掉了，也把"这个模型今天整体偏高"这类漂移消掉了。取样的代价是：pairwise 只能给你相对排序，且排序可能非传递（第 1 章讲过），所以最终排序要用 Bradley-Terry 这类模型拟合，而不是简单数胜场。

rubric 分解的独特价值：它能让失败可定位（"事实错误" vs "格式问题"分开），以及在长度偏差上的缓解——把"完整性"单独列为一个分项后，judge 不必用"更长"来间接表达"更完整"。代价是 rubric 本身变成了被测对象：你必须验证 rubric 的分项与人工判断的相关性。

平局与"都不行"必须显式处理。三种做法与后果：

  • 不设平局（强制 A/B）：会把大量"实质相同"的样本转成噪声，且这个噪声可能系统性偏向位置（第 1 节）。除非模型间差距很大，否则不推荐。
  • 设平局，且允许"都不合格"：信息量最大，但平局率会很高（30%~50% 常见），降低有效样本量。
  • 设平局 + 只统计非平局：等价于把比较局限在"有差异的样本"上，这会引入选择效应——被比较的样本子集不再代表总体。

推荐：设平局，报告时同时给出"平局率"与"非平局中的胜率"，并在方法说明里写清平局如何计入。不要把平局当 0.5 胜偷偷处理掉——那样读者无法判断结论对平局规则的敏感性。

二、位置对称：从"提醒模型别偏心"到协议级消除#

不要指望在 prompt 里写"请忽略顺序"来消除位置偏差。 位置偏差来自模型的注意力与自回归机制，不是它能"遵守的指令"。有效的做法是协议级的：

（a）双顺序 + 聚合。每一对都跑 (A,B) 与 (B,A) 两次，然后：

聚合规则 胜场计法 性质
一致才算胜 两次都选 A 才算 A 胜 保守，丢掉所有位置敏感样本；引入选择偏差
不一致记 0.5 一次胜一次负 → 各 0.5 无偏（位置偏差一阶抵消），方差更大
不一致转人工 交给人工或第三个 judge 最准、最贵；不一致比例是很好的质量指标

（b）随机化并记录顺序。即使只跑一次，也要对每对随机决定哪个在前，并记录。这样位置偏差会变成随机噪声而非系统偏差——虽然增大了方差，但不会让某个模型系统受益。这是"便宜但次优"的方案。

（c）对称化的 prompt 模板。保证两个候选的模板片段逐字节相同（除内容外）：标签（"回复 1 / 回复 2" vs "A / B"）、分隔符、缩进、前后说明都要对称。一个常见 bug 是"先在 prompt 里介绍候选 A 的背景"，这本身就是位置偏差的来源。

三、结构化输出与解析失败：把失败当一等公民#

judge 的输出解析失败（格式不符、复述了 prompt、给了两个答案、输出被截断）是工程上最常被忽略的误差源，因为它会造成选择性丢失：如果你把解析失败当缺失值丢掉，剩下的样本就不再是原样本。

三条要求：

  1. 失败率必须报告。 失败率超过 5% 就需要重试机制；超过 15% 说明 prompt 或任务的输出协议有问题，结论不可用。
  2. 失败不能静默丢弃。 记录失败样本，分析它们的分布（是否集中在长回答、特定语言、特定题目类型？）。如果失败与某个候选系统相关，你就会得到一个系统性偏向的评测。
  3. 重试要有策略。 简单重试（同 prompt 再跑）对确定性模型无效；有效的是：(a) 降低约束（先让它自由推理，再用第二个轻量解析步骤抽取答案）；(b) 用不同的模板复述要求；(c) 重试仍失败则转人工/标记。

推荐的输出协议（兼顾稳定与可推理）：

  • 先让 judge 写简短的判断理由（1~3 句），再输出一个固定标记的行，如 FINAL: A / FINAL: B / FINAL: TIE。
  • 用正则只抓最后一行。不要把 JSON 作为唯一协议：长推理后模型很容易在多处输出 JSON 片段，解析歧义比一行标记大得多。
  • 若必须用 JSON：要求单个代码块、固定键名、禁止额外文本，并接受"第一个合法 JSON 对象"作为解析结果。

取舍：让 judge 先推理再判定，通常能提高一致性（尤其是复杂任务），代价是失败率上升与成本上升。先推理后判定的最大风险是"合理化"——judge 先写了一段支持某个结论的理由，然后给出与该理由不一致的分数。防护是要求理由与结论一致性检查：如果理由里说"回答 2 有明显事实错误"而 FINAL: 2，这条样本应被标记为可疑并复核。

四、可复现性的硬要求#

把"可复现"拆成可检查的清单。一个 judge 实验的报告里应至少能追溯到：

项 为什么必须记录 常见遗漏
judge 模型确切版本 同名模型的不同快照判定风格差异明显 只写"某模型最新版"
解码参数（temperature / top_p / seed / max_tokens） temperature>0 时同输入不同输出 只写模型名
prompt 全文 + 哈希 prompt 是判定标准的一部分 只写"用了标准 prompt"
候选顺序与聚合规则 位置偏差处理方式直接影响结论 不写聚合规则
题目顺序与批次划分 批次效应（服务端版本、缓存）会进入结果 不写
失败样本数与处置 选择性丢失 只报成功样本
入参（是否截断、上下文长度、多轮历史） 截断会改变被判内容 不写

批次效应是最隐蔽的一项。如果你第一天跑候选 A、第二天跑候选 B，那么两天的服务端版本、缓存状态、甚至流量负载都可能不同。判定的差异会混入系统差异。规范做法：把 A 与 B 的样本打散混在同一个批次里跑，并记录批次号；或者保证两组的批次分布一致。 这与 A/B 实验的分流均衡是同一个道理。

"同一天跑一次 vs 分三天跑"的检验方法：抽 100 对样本，每天跑一次，共三天，算三次结果两两之间的一致率（或 ICC）。如果日内一致率 0.95、日间一致率 0.85，那么任何小于 (1-0.85) 量级的模型差异都不能被可靠解释。 这项检验的成本极低，但能发现最致命的问题。

五、prompt 敏感性：必须测量，不能假设#

prompt 敏感性指：在判定标准不变的情况下，改动词句/顺序/措辞，结论变多少。

三种常见诱因：

  1. 标签措辞：用"A/B"还是"回复1/回复2"还是"助手1/助手2"。后者可能触发模型对"助手"身份的先验。
  2. rubric 描述：把"准确性"描述为"不包含事实错误"或"所有事实性陈述都正确"，判定的边界会变。
  3. 长度/顺序强调：写"注意不要因为答案更长就给更高分"会同时改变长度偏差与整体判定风格（可能变得过度惩罚长度）。

测量方法（prompt 敏感性实验）：从你的任务里抽 200~500 对，用 k 个语义等价的 prompt 变体各跑一遍，然后：

  • 报变体间一致率（两两比较）与结论的稳定区间（比如胜率的 min/max）。
  • 用第 1 节的偏差回归看每个变体的 βL​,βS​ 是否显著不同——这比只看总胜率更有诊断力。
  • 定义敏感度：胜率在不同变体间的极差。如果极差（比如 6 个点）大于你要检测的效应（比如 3 个点），那么这次评测的结论是 prompt 决定的，不是模型决定的。

取舍：变体越多，敏感性估计越稳，成本线性上升。实践建议：至少两个变体（一个正式、一个"朴素版"），因为两个变体之间的一致率已经能发现大部分脆弱性。三个以上才有方差估计。

一个反直觉的结论：prompt 敏感性本身可以是评测报告的一个有用指标。 如果某个任务上 judge 对措辞极度敏感，说明这个任务的判定标准本身不清晰（人的判断也会不稳），此时更该做的是先把标准写清楚（rubric + 锚点示例），而不是继续调 prompt。

代码#

⚠️ 以下为合成数据与示例输出，仅用于展示协议与统计量的行为；代码只用标准库，可直接运行。

import hashlib
import math
import random
import re
import statistics

rng = random.Random(211)


# ============================================================
# 1. 双顺序协议 + 三种聚合规则
# ============================================================
def judge_once(dq, first_is_a, prob_lazy, noise_sd, r):
    # 返回 "A" / "B" / "TIE"（TIE 由感知差接近 0 触发）
    if r.random() < prob_lazy:
        return "A" if first_is_a else "B"          # 位置偏差：选先出现的
    z = (dq if first_is_a else -dq) + r.gauss(0, noise_sd)
    if abs(z) < 0.25:                               # "实质相同" -> 平局
        return "TIE"
    win_first = z > 0
    return ("A" if first_is_a else "B") if win_first else ("B" if first_is_a else "A")


def run_protocol(pairs, prob_lazy=0.15, noise_sd=0.5, seed=17):
    # 返回：一致才算胜 / 不一致记 0.5 / 不一致率 / 双平局率
    r = random.Random(seed)
    agree_score = half_score = 0.0
    n_disagree = n_both_tie = 0
    for dq in pairs:
        w1 = judge_once(dq, True, prob_lazy, noise_sd, r)     # A 在前
        w2 = judge_once(dq, False, prob_lazy, noise_sd, r)    # B 在前
        if w1 == w2:
            agree_score += 1.0 if w1 == "A" else (0.5 if w1 == "TIE" else 0.0)
            half_score += 1.0 if w1 == "A" else (0.5 if w1 == "TIE" else 0.0)
        else:
            n_disagree += 1
            # 一致才算胜：不一致 -> 不计 A 胜（记 0.5 会让它变成"平局"）
            agree_score += 0.5
            half_score += 0.5
        if w1 == "TIE" and w2 == "TIE":
            n_both_tie += 1
    n = len(pairs)
    return agree_score / n, half_score / n, n_disagree / n, n_both_tie / n


def true_win_rate(pairs):
    # 真实质量差 dq = q_A - q_B，平局阈值 0.25 之内的算平局
    s = 0.0
    for dq in pairs:
        s += 0.5 if abs(dq) < 0.25 else (1.0 if dq > 0 else 0.0)
    return s / len(pairs)


pairs = [rng.gauss(0.0, 1.0) for _ in range(400)]
print("== 1. 双顺序协议与聚合规则（合成，A 与 B 真实水平相同） ==")
print(f"真实 A 胜率 = {true_win_rate(pairs):.3f}（两者同分布，期望 0.5）")
for lazy in (0.0, 0.15, 0.30):
    # 只跑"A 在前"（不随机化、不交换）
    r2 = random.Random(3)
    single = 0.0
    for dq in pairs:
        w = judge_once(dq, True, lazy, 0.5, r2)
        single += 1.0 if w == "A" else (0.5 if w == "TIE" else 0.0)
    single /= len(pairs)
    agr, half, dis, tie = run_protocol(pairs, prob_lazy=lazy)
    print(f"位置偏差 {lazy:.2f}: 只跑 A 在前 -> {single:.3f} | "
          f"双顺序(一致才算胜) -> {agr:.3f} | 双顺序(不一致记 0.5) -> {half:.3f} | "
          f"不一致率 {dis:.3f} | 双平局率 {tie:.3f}")
print("  <- 只跑一种顺序时，'A 胜率'随位置偏差线性虚高；")
print("     双顺序 + 不一致记 0.5 把期望拉回 0.5（代价是方差更大）")


# ============================================================
# 2. 解析失败：解析器与失败率
# ============================================================
FINAL_RE = re.compile(r"FINAL\s*[:：]\s*(A|B|TIE)\b", re.IGNORECASE)

RAW_OUTPUTS = [
    "理由：回答 2 更完整、有具体数据。\nFINAL: B",
    "两者都不错。\nfinal: TIE",
    "我认为 A 更好\nFINAL: A",
    "Let me think... The answer 1 is better.\nFINAL: 1",          # 非法取值
    "FINAL: A\n\n（另外我认为 B 也不错）FINAL: B",                  # 多个标记
    "",                                                              # 空输出
    "抱歉，我无法比较这两个回答。",                                     # 拒答
]


def parse_verdict(text):
    # 取"最后一个"合法标记，并报告歧义
    hits = FINAL_RE.findall(text or "")
    if not hits:
        return None, "no_marker"
    if len(set(h.upper() for h in hits)) > 1:
        return hits[-1].upper(), "ambiguous"
    return hits[-1].upper(), "ok"


print("\n== 2. 解析失败与歧义（示例输出） ==")
fail = ambig = ok = 0
for t in RAW_OUTPUTS:
    v, status = parse_verdict(t)
    print(f"  status={status:10s} verdict={str(v):5s} <- {t[:28]!r}")
    ok += status == "ok"
    ambig += status == "ambiguous"
    fail += status == "no_marker"
print(f"可解析 {ok}/{len(RAW_OUTPUTS)}，歧义 {ambig}，失败 {fail}")
print("  <- 失败率必须报告；失败若与某个候选相关，评测就有系统性偏差")


# ============================================================
# 3. 可复现性：prompt 指纹 + 批次效应检验
# ============================================================
def prompt_hash(prompt):
    return hashlib.sha256(prompt.encode("utf-8")).hexdigest()[:16]


PROMPT_TEMPLATE = (
    "你是评审。比较两个候选回答，判定哪个更好。\n"
    "判定标准：事实正确性优先，其次是完整性与清晰度。\n"
    "候选 1:\n{c1}\n候选 2:\n{c2}\n"
    "先给出 1-3 句理由，最后一行输出 FINAL: 1 / FINAL: 2 / FINAL: TIE"
)
print("\n== 3. prompt 指纹（可复现的最小凭证） ==")
print(f"模板哈希 = {prompt_hash(PROMPT_TEMPLATE)}")
v2 = PROMPT_TEMPLATE.replace("FINAL: 1 / FINAL: 2", "FINAL: A / FINAL: B")
print(f"改一处标签后哈希 = {prompt_hash(v2)}  <- 变化了，但语义等价")
print("  -> 指纹只保证'能追溯'，不保证'语义不变'；两者都要记录")

# 批次效应：同一天 vs 跨天的一致性
def batch_agreement(day_var, n=200, seed=9):
    r = random.Random(seed)
    a, b, c = [], [], []
    for _ in range(n):
        dq = r.gauss(0.2, 1.0)
        base = 1 if dq > 0 else 0
        # 每次判定有 5% 的随机翻转（judge 日内噪声）
        a.append(base if r.random() > 0.05 else 1 - base)
        b.append(base if r.random() > 0.05 else 1 - base)
        # 第三天有系统漂移：把一部分判定整体翻向另一边
        b3 = base
        if r.random() < day_var:
            b3 = 1 - b3
        c.append(b3 if r.random() > 0.05 else 1 - b3)
    def agr(x, y):
        return sum(1 for i in range(n) if x[i] == y[i]) / n
    return agr(a, b), agr(a, c), agr(b, c)


print("\n== 4. 批次效应：日内 vs 跨天一致率 ==")
for drift in (0.0, 0.05, 0.10, 0.20):
    d12, d13, d23 = batch_agreement(drift)
    print(f"第三天漂移 {drift:.2f} -> 日内一致 {d12:.3f} | 跨天一致 {d13:.3f} / {d23:.3f}")
print("  <- 日内 0.9、跨天 0.8 时，任何小于 20% 的模型差异都无法可靠解释")
print("     防御手段：A/B 样本混在同一批次跑，并记录批次号")


# ============================================================
# 4. prompt 敏感性：同一批样本在不同 prompt 变体下的判定翻转率
# ------------------------------------------------------------
# 每个变体有自己的位置偏好、长度偏好与平局带宽；在"同一批题目"上比较，
# 这样能直接数出"有多少个判定被 prompt 改动改变了"
# ============================================================
def variant_verdict(dq, first_is_a, cfg, r):
    # cfg: lazy（位置偏差）, w_len（长度权重）, tie_band（平局带宽）
    if r.random() < cfg["lazy"]:
        return 0                                    # 0 = 选先出现的
    z = (dq if first_is_a else -dq) + cfg["w_len"]
    if abs(z) < cfg["tie_band"]:
        return 2                                    # 2 = 平局
    win_first = z > 0
    if win_first:
        return 0
    return 1                                        # 1 = 选后出现的


def variant_win_rate(pairs, cfg, seed):
    # 在固定题目顺序下跑一个变体，返回 A 的胜率（平局 0.5）与逐题判定
    r = random.Random(seed)
    s = 0.0
    verdicts = []
    for (dq, dlen) in pairs:
        c = dict(cfg)                                # 每题的副本，别污染变体配置
        c["w_len"] = cfg["w_len"] * dlen / 100.0     # 长度差 -> logit 偏移
        v = variant_verdict(dq, True, c, r)          # 统一 A 在前（比较 prompt 本身）
        verdicts.append(v)
        s += 0.5 if v == 2 else (1.0 if v == 0 else 0.0)
    return s / len(pairs), verdicts


rng2 = random.Random(23)
sim_pairs = [(rng2.gauss(0.10, 1.0), rng2.gauss(0.0, 150.0)) for _ in range(500)]
variants = {
    "正式版": dict(lazy=0.10, w_len=0.000, tie_band=0.25),
    "强调完整性": dict(lazy=0.10, w_len=0.500, tie_band=0.25),
    "显式反长度提示": dict(lazy=0.10, w_len=-0.400, tie_band=0.25),
    "换标签(回复1/回复2)": dict(lazy=0.16, w_len=0.008, tie_band=0.30),
}
print("\n== 5. prompt 敏感性（合成，同一批 500 对题目） ==")
rates, verdicts = {}, {}
for name, cfg in variants.items():
    rates[name], verdicts[name] = variant_win_rate(sim_pairs, cfg, seed=31)
    print(f"  {name:20s} -> A 胜率 {rates[name]:.3f}")
spread = max(rates.values()) - min(rates.values())
print(f"变体间胜率极差 = {spread:.3f}")
base = verdicts["正式版"]
print("\n  逐题判定翻转率（相对'正式版'）：")
for name in variants:
    if name == "正式版":
        continue
    flip = sum(1 for x, y in zip(base, verdicts[name]) if x != y) / len(base)
    print(f"    {name:20s} 翻转率 {flip:.3f}  "
          f"(胜败互换 {sum(1 for x,y in zip(base,verdicts[name]) if x!=y and 2 not in (x,y))/len(base):.3f})")
print("  <- 胜率极差可能很小（互为反向的效应会抵消），但逐题翻转率不会：")
print("     翻转率是 prompt 敏感性的稳健度量，也是结论可信度的上限")

代码里五个值得注意的点：

  • 第 1 段给出双顺序协议的完整对照：只跑"A 在前"时 A 的胜率随位置偏差线性虚高（0.00/0.15/0.30 对应 0.48/0.55/0.63）；双顺序 + 不一致记 0.5 把期望稳定拉回 0.49。"一致才算胜"看起来更严格，但它丢掉的是位置敏感样本，会改变被测总体（不一致率高达 0.43 时，损失近一半样本）。
  • 第 2 段把解析失败变成可统计的量：FINAL: 1（合法格式但非法取值）、多个标记共存、空输出、拒答，都必须有明确处置。"取最后一个标记"与"取第一个标记"会给出不同答案，协议里必须写死；多标记样本往往出现在模型"改主意"时，信息量最高，应单独复核。
  • 第 3 段区分了两件事：prompt 哈希保证可追溯（能证明用的是哪一版），但不保证语义等价（改一个标签就换哈希）。所以要同时记录哈希与变更说明，否则你会得到一堆无法比较的哈希。
  • 第 4 段是本节最实用的一项检验：日内一致率约 0.9，跨天一致率随系统漂移降到 0.8 以下。如果你把候选 A 和候选 B 分两天跑，两天的漂移会直接进入结论，而它完全不体现在置信区间里（和位置偏差一样，是"精确地错"）。防御手段：A/B 样本混在同一批次跑 + 记录批次号 + 把批次作为随机效应。
  • 第 5 段给出更稳健的敏感性度量：注意胜率极差可能很小（互为反向的效应在聚合时会抵消），但逐题翻转率不会。三个变体各有百分之几到十几的逐题翻转，意味着几十个判定是 prompt 决定的。报告里应同时给出胜率极差与逐题翻转率——后者是你结论可信度的上限。这也提示：若某任务的判定对措辞极度敏感，问题通常不在 prompt，而在判定标准本身不清晰，该做的是补 rubric 与锚点示例。

练习#

  1. 协议设计：为"比较两个客服回复草稿的质量"设计完整的判定协议。 （a）选择判定形态（pairwise / pointwise / rubric）并说明理由； （b）写出输出协议（理由 + 结束标记）与解析规则； （c）写出平局与"都不合格"的处置，以及聚合规则（含位置处理）； （d）列出这条协议必须记录的元数据（至少 8 项）。

  2. 聚合规则的代价：某评测 400 对，双顺序结果：两次一致 300 对（其中 A 胜 180、B 胜 120），不一致 100 对（其中 60 对是"谁在前谁赢"的位置驱动，40 对是其他）。 （a）分别用"一致才算胜""不一致记 0.5""不一致转人工"三种规则算 A 的胜率； （b）哪种规则给出最大的 A 优势？为什么？ （c）如果这 100 对不一致样本的构成与总体不同（比如集中在长回答上），三种规则的偏差方向是什么？

  3. 解析失败率：某次 judge 运行 5000 条，解析失败 380 条（7.6%），且失败样本的平均输出长度是被判样本的 2.3 倍。 （a）直接丢弃失败样本会带来什么方向的偏差？ （b）设计一套重试与降级策略（至少三级）； （c）写出报告中必须披露的三项信息。

  4. 可复现性清单：你要把一次 judge 评测交给同事复核。 （a）写出交接包的内容清单（文件 + 字段）； （b）说明"同一天跑一次 vs 分三天跑"的一致性检验怎么做、需要多少样本、报告哪个统计量； （c）如果你的评测要跨一个月分四批跑，设计批次控制方案（提示：混样、锚点样本、批次作为随机效应）。

  5. 敏感性实验：你设计了 4 个语义等价的 prompt 变体，得到 A 胜率：0.562 / 0.541 / 0.578 / 0.524，逐题翻转率（相对正式版）分别为 0.04 / 0.07 / 0.11。 （a）算胜率极差与逐题翻转率，判断这次评测的可靠性； （b）如果正式版是 0.562，你会报哪个数？附什么说明？ （c）设计一个方案，用"锚点样本"（已知优劣的构造对）把变体间差异与真实差异分离。

  6. 输出协议取舍（开放题）：你的任务是判定"代码是否修复了 bug"。 （a）为什么这类任务上"先推理再判定"收益很大？ （b）"先推理"会引入什么新风险（提示：合理化的方向）？给出检测"理由与结论不一致"的规则； （c）如果要求输出 JSON，写出最小 schema 与三条解析容错规则。

小结#

  • 判定形态先于 prompt：pairwise 用于选型（人类与模型在"哪个更好"上更一致）、pointwise 用于粗筛与监控（有尺度漂移风险）、rubric 用于需要定位失败与需要可解释性的场景（rubric 本身要验收）。
  • 平局必须显式处理并报告：平局率、非平局中的胜率、聚合规则。把平局当 0.5 胜偷偷处理掉，会让读者无法判断结论对规则的敏感性（本节的合成例子里双平局率约 3%4%，但"两次判定不一致"的比例高达 0.310.45）。
  • 位置偏差只能靠协议消除：双顺序 + 聚合（一致才算胜 / 不一致记 0.5 / 转人工），或至少随机化并记录顺序（把系统偏差转成随机噪声）。模板的每个字节都要对称，不要指望 prompt 里写"请忽略顺序"。
  • 解析失败必须当一等公民：报失败率、分析失败样本分布、三级降级（同 prompt 重试 → 降约束 + 二次抽取 → 人工）。选择性丢失会制造系统性偏差。
  • 可复现 ≠ 确定性：记录模型版本、解码参数、prompt 全文 + 哈希、顺序与聚合规则、批次划分、失败处置。批次效应是最隐蔽的杀手——日内与跨天一致率之差就是你的噪声地板。
  • prompt 敏感性必须测量：用 2~4 个语义等价变体算胜率极差与逐题翻转率。极差大于目标效应（或翻转率高于你能接受的判定不确定度）时，结论由 prompt 决定。
