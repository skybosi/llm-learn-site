通用 GNN 层#

上一课我们用"聚合 + 结合"描述了一层 GNN 的直觉。这一课把它提炼成一个正式的、可复用的框架——消息传递（message passing），并解释为什么 PyTorch Geometric 里几乎所有图卷积层都继承自同一个 MessagePassing 基类。把这个框架吃透，你就拿到了"看懂任何 GNN 论文"的万能钥匙：GraphSAGE、GCN、GAT、GIN 都只是这个框架下不同的"消息函数、聚合函数、更新函数"组合而已。

一、概念讲解#

1. 消息传递的三步#

Gilmer 等人在论文《Neural Message Passing for Quantum Chemistry》里提出的消息传递神经网络（MPNN），把一层 GNN 分解成三个清晰的步骤。设 h_v^(k) 是节点 v 在第 k 层的表示：

  1. 消息（message）：每条边上的邻居 u 向 v 发一条消息，由消息函数 M 计算，输入是 u 和 v 的表示以及边特征 e_uv： m_{u→v}^{(k)} = M( h_u^(k), h_v^(k), e_uv )

  2. 聚合（aggregate）：节点 v 把自己收到的所有消息合并成一个向量，聚合函数通常是对称的（求和、平均、取最大）： m_v^{(k)} = AGGREGATE( { m_{u→v}^{(k)} : u ∈ N(v) } )

  3. 更新（update）：节点 v 用聚合到的消息更新自己的表示： h_v^{(k+1)} = U( h_v^(k), m_v^{(k)} )

这三步环环相扣：消息决定"邻居传什么"，聚合决定"怎么合并"，更新决定"如何用消息刷新自己"。上一课的均值聚合，就是"消息 = 恒等 + 邻居特征"、"聚合 = 平均"、"更新 = 线性变换 + 激活"的特例。

2. 为什么聚合必须是对称的#

聚合函数有一个硬性要求：必须对输入集合的顺序不敏感（对称）。因为邻居集合 N(v) 里的节点没有天然顺序——你把邻居列表打乱，聚合结果必须不变。这直接保证了第一章说的置换等变性：节点编号怎么换，每个节点的输出都跟着节点走，不依赖编号。求和、平均、取最大都满足对称性，而"把邻居排成一列接个 LSTM"就不满足（顺序变了结果就变），除非额外设计。

3. 向量化：用邻接矩阵批量计算#

逐节点套消息传递很直观，但太慢。实战中我们把它向量化成矩阵运算。以最简形式（消息 = W h_u，聚合 = 求和，更新 = 自身变换 + 激活）为例：

H^{(k+1)} = σ( A H^{(k)} W^{(k)ᵀ} )

其中 A 是邻接矩阵，H^{(k)} 是所有节点表示堆成的 (n, d) 矩阵，W^{(k)} 是可学习的权重。A @ H 这一步就完成了"对每个节点，把它所有邻居的表示求和"——矩阵乘法天然地并行化了消息聚合。这就是为什么上一章要把图表示成邻接矩阵：它能一步完成全网的消息传递。

4. 统一的抽象：PyG 的 MessagePassing#

PyTorch Geometric 把这套框架做成了基类 torch_geometric.nn.conv.MessagePassing。你只需实现三个钩子函数：message()（消息函数 M）、aggregate()（聚合函数，默认求和）、update()（更新函数 U），PyG 会自动帮你根据 edge_index 收集邻居、分发消息。GCNConv、SAGEConv、GATConv、GINConv 全都是在这个基类上覆写出来的。理解 MPNN，你就理解了 PyG 的整个图层设计。

二、可运行代码示例#

下面用 NumPy 逐节点实现一个完整的 MPNN 层，再给出等价的向量化写法，验证两者结果一致。

import numpy as np

def relu(x):
    return np.maximum(0.0, x)

# 1) 图：5 个节点围成一个环
edges = [(0, 1), (1, 2), (2, 3), (3, 4), (4, 0)]
n = 5
A = np.zeros((n, n))
for u, v in edges:
    A[u, v] = A[v, u] = 1.0

# 2) 节点特征：每节点 3 维
rng = np.random.default_rng(0)
X = rng.normal(size=(n, 3))
d_in, d_hidden = 3, 4
Wm = rng.normal(size=(d_hidden, d_in))   # 消息变换
Wu = rng.normal(size=(d_hidden, d_in))   # 自身变换

# 3) 逐节点消息传递（MPNN 三步）
H_new = np.zeros((n, d_hidden))
for v in range(n):
    neighbors = np.nonzero(A[v])[0]
    # 消息：每个邻居 u 发给 v 的消息 = Wm @ h_u
    messages = [Wm @ X[u] for u in neighbors]
    # 聚合：求和（对称函数）
    m_v = sum(messages) if messages else np.zeros(d_hidden)
    # 更新：自身变换 + 聚合消息，再过 ReLU
    H_new[v] = relu(Wu @ X[v] + m_v)
print("逐节点消息传递结果 H^1：\n", np.round(H_new, 3))

# 4) 等价的向量化写法：H^1 = relu(A X Wm^T + X Wu^T)
H_vec = relu(A @ X @ Wm.T + X @ Wu.T)
print("向量化结果 H^1：\n", np.round(H_vec, 3))
print("两种写法是否一致：", np.allclose(H_new, H_vec))

运行后你会看到两种实现输出完全相同，但向量化写法只用一次矩阵乘法就完成了所有节点的消息聚合。真实框架（PyTorch/PyG）内部就是靠稀疏矩阵乘法 spmm 来并行做这件事的，能轻松扩展到千万级节点的图。

三、练习#

  1. 把聚合函数从"求和"改成"平均"，逐节点实现里要怎么改？对应的向量化写法又该怎么改（提示：用度矩阵 D）？
  2. 把消息函数改成同时依赖两端节点的拼接：M = Wm @ concat(h_u, h_v)。修改逐节点实现，思考这种"依赖接收方"的消息函数相比"只依赖发送方"多了什么表达能力。
  3. 给边加上特征 e_uv（比如给每条边赋一个标量权重），把消息函数改成 M = e_uv · (Wm @ h_u)，即"按边权缩放消息"，实现之并解释它和加权图的关系。
  4. 思考：如果聚合函数用"按节点度数归一化的求和"（即 GraphSAGE 的 mean 聚合），对度数差异很大的节点各有什么影响？为什么有时要用归一化、有时反而要用纯求和？
