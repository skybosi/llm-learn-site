CPU/GPU/专用加速器分工#

上一课我们说了"为什么需要专用硬件"。这一课把镜头拉远，看看一台跑推理的机器里，CPU、GPU、专用加速器各自扮演什么角色，以及衡量它们的三个核心指标：算力、显存容量、显存带宽。这三个数，是后面所有计算的锚点。

一、概念讲解#

1. CPU：指挥官，而不是搬运工#

CPU 的强项是控制与串行逻辑：分支多、依赖复杂、需要快速响应单条指令的场景，CPU 无可替代。在推理服务里，CPU 负责：

  • 请求调度、token 解码的循环控制；
  • 数据预处理、分词、后处理；
  • 把数据从网络/磁盘搬到 GPU 显存（走 PCIe 或 NVLink）。

CPU 核少（几十个）、单核强、主频高、缓存大，但并行度和带宽有限。让它去算大矩阵乘，等于让指挥官亲自去扛沙袋——既慢又浪费。

2. GPU：吞吐主力#

GPU 的设计哲学和 CPU 相反：用数量换吞吐。几千上万个更简单的小核（CUDA Core）＋ 极高的显存带宽（HBM），让它擅长"大量独立的、可预测的计算"，也就是矩阵乘、卷积这类数据并行负载。推理时 90% 以上的浮点运算都在 GPU 上完成。

GPU 的代价是：单线程延迟不如 CPU，也不适合分支纷乱的代码；它要的是"喂饱它"，让成千上万线程同时有事干。

3. 专用加速器：为矩阵乘"量身定做"#

在 GPU 之外，还有一类更进一步定制的芯片：

  • TPU（Google）：用脉动阵列（systolic array）组织乘加单元，数据像流水线一样在单元间流动，专为矩阵乘设计；
  • NPU / AI ASIC：手机、边缘设备里的推理芯片，把矩阵乘和量化算子做成专用电路，追求极致能效；
  • FPGA：可编程逻辑，能针对特定模型结构定制数据通路，灵活性介于 ASIC 与 GPU 之间。

它们的共同点是：砍掉通用性，换能效和面积效率。对"只跑推理"的场景，往往比 GPU 更省电、单位算力更便宜，但生态和灵活性不如 GPU。

4. 一张卡的三要素#

不管哪类硬件，判断"它能跑什么、跑多快"都只看三个数：

指标 含义 决定的问题
算力（TFLOPS/TOPS） 每秒能做多少次运算 算得动多快的计算量
显存容量（GB） 能放下多少权重、激活、KV cache 能不能装下这个模型
显存带宽（TB/s） 每秒能搬运多少字节 权重读完要多久、吞吐上限

拿 H100 举例：算力 989 TFLOPS（FP16 张量）、显存 80 GB、带宽 3.35 TB/s。这三个数会在本课程中反复出现，请先记住它们。

5. 分工的本质：扬长避短#

一句话概括：CPU 管调度，GPU 管算，加速器管极致能效，带宽和容量决定一切的上限。理解分工，你才能看懂一张推理集群拓扑图里为什么是"CPU 做主机、多卡 GPU 做计算、PCIe/NVLink 做连接"。

二、可运行代码示例#

用字典把几类硬件的"三要素"建模，直观比较它们的分工定位。

# ---- 硬件三要素建模（数值为公开规格的典型值，四舍五入） ----
hardware = {
    "高端服务器 CPU":  {"算力 TFLOPS(FP32)": 3.0,   "带宽 TB/s": 0.1,   "容量 GB": 512},
    "NVIDIA A100 SXM": {"算力 TFLOPS(FP16)": 312.0, "带宽 TB/s": 2.0,   "容量 GB": 80},
    "NVIDIA H100 SXM": {"算力 TFLOPS(FP16)": 989.0, "带宽 TB/s": 3.35,  "容量 GB": 80},
    "NVIDIA H200 SXM": {"算力 TFLOPS(FP16)": 989.0, "带宽 TB/s": 4.8,   "容量 GB": 141},
    "边缘 NPU(示例)":  {"算力 TFLOPS(INT8)": 50.0,  "带宽 TB/s": 0.05,  "容量 GB": 8},
}

for name, spec in hardware.items():
    print(f"{name}: {spec}")

# ---- 谁装得下 70B 模型？----
def fits_model(params, bytes_per_param, capacity_gb):
    weight_bytes = params * bytes_per_param
    return weight_bytes <= capacity_gb * 1e9

for name, spec in hardware.items():
    ok = fits_model(7e10, bytes_per_param=2, capacity_gb=spec["容量 GB"])
    print(f"{name} 能否装下 70B FP16 模型(140GB)? {'能' if ok else '不能'}")

# ---- 装得下还不够，还要搬得动：读一遍权重的时间 ----
def read_weight_time(params, bytes_per_param, bw_tb_s):
    return params * bytes_per_param / (bw_tb_s * 1e12)

for name in ["NVIDIA A100 SXM", "NVIDIA H100 SXM", "NVIDIA H200 SXM"]:
    t = read_weight_time(7e10, 2, hardware[name]["带宽 TB/s"])
    print(f"{name} 读完 70B FP16 权重 ≈ {t*1e3:.1f} ms")

要点：fits_model 和 read_weight_time 分别对应"容量"和"带宽"两个维度——容量决定能不能跑，带宽决定跑多快。注意 A100、H100 都能装下 70B，但 H200 因为带宽更高，读一遍权重明显更快。这个"读一遍要多久"的思路，正是本课程最核心的估算方法。

三、练习#

  1. 归类：下面任务分别更适合 CPU、GPU 还是专用加速器？——(a) 每轮请求的分词与调度；(b) 大矩阵乘；(c) 手机端常驻的语音识别推理。说明理由。
  2. 计算：用 fits_model 判断一块 24GB 的消费级显卡能否装下 13B 的 FP16 模型（26GB）？如果换成 INT8（每参数 1 字节）呢？
  3. 对比：H200 和 H100 算力相同（989 TFLOPS），但 H200 带宽更高。对"读一遍权重"这类操作，H200 比 H100 快多少倍？这对"访存密集"的推理意味着什么？
  4. 思考：为什么专用加速器（NPU）常常标 INT8 算力，而数据中心 GPU 常标 FP16 算力？结合"推理常用低精度"想一想。
