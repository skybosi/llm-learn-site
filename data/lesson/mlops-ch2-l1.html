模型流水线与软件流水线的四个结构差异：数据验证门禁为什么必须有#

这一节要解决什么#

第 1 章把"记账"这件事做完了：一次实验的完整描述被记下来、引用关系被连成血缘图、环境差异被压到统计等价、多重比较被校正。那次修正把 code_ref、data_ref、env_ref 都写进了 manifest，并把"这次训练用了哪份数据、哪个 commit、哪个镜像"变成了可查询状态。

于是工程上很自然地出现下一步：

既然什么都记全了，那把它接进 CI —— 每次 push 跑一边，指标不掉就发布。听起来就是普通 CI/CD 加一个"跑评测"的步骤。

这句话是本章要拆掉的第一个错觉。 把模型流水线当成"软件流水线 + 一个评测步骤"，会在四个地方结构性失效：

# 结构差异 软件流水线的假设 模型流水线的现实
D1 触发源不止代码 只有代码变更触发构建 数据更新、上游模型更新、依赖漂移、定时重训都会触发，而它们没有 diff
D2 验证是统计的 测试要么绿要么红 指标是随机变量，同一份代码两次运行数值不同（第 1 章第 3 节），"通过/不通过"必须先定样本量与效应量
D3 失败可以静默 编译失败、测试失败都会立刻报错 模型可以成功构建、成功发布、指标全绿，然后在业务指标上悄悄变差
D4 "回滚到上一个 commit"不等于"上一个模型" 代码是唯一可变输入 模型是 (D,C,H,E,Σ) 的函数；数据会变、上游模型会变，重建不等于恢复

这四条不是"更麻烦一点"，而是改变了流水线的形状：软件流水线是一条"构建 → 测试 → 发布"的直线；模型流水线必须是一条带数据验证与统计门禁、并且能在发布后继续观测和回退的回路。

本节回答三件事：

  1. D1–D4 各自要求流水线补上什么，以及"补上"的最小结构是什么（触发矩阵 + 四类门禁 + 观测回路）。
  2. 数据验证门禁的三个层次：schema（结构）、分布（统计）、语义（含义）。为什么只做 schema 是必漏的 —— 本节会给出一个 schema 完全通过、但模型必然变差的实例：上游把 time_on_page 的单位从秒改成毫秒。
  3. 门禁放在流水线的哪个位置：用期望成本模型把"放哪个门禁、放在哪"变成一个可计算的决策，并推出门槛单价 c∗。

一句话给出本节的结论：流水线的价值等于它拦截事故的期望收益减去它的运行成本；当你说不清某道门禁的门槛单价和检出率时，那道门禁既不能证明有效，也不能在预算被砍时被辩护。

一、D1–D4：四条差异各自要求什么#

1.1 D1：触发源不止代码#

普通 CI 的触发是 {push,PR,tag}。模型流水线的触发还要加上：

触发源 例子 有没有 diff 需要什么额外机制
数据更新 上游埋点口径调整、补数据、去重 没有代码 diff 数据版本指纹（ch1-l2 的 manifest）+ 分布门禁
上游模型更新 依赖的 embedding / reranker 换版本 依赖清单有 diff 依赖锁 + 端到端评测（不是单元测试）
依赖漂移 基础镜像重建、CUDA 小版本升级 无 diff（镜像 tag 未变但 digest 变） 记录 digest 而非 tag（ch1-l3）
定时重训 "每周一用最近 90 天数据重训" 无 diff 评测与当前线上模型的对照，不是"绝对阈值"
配置变更 阈值、prompt 模板、解码参数 有 diff，但不在代码仓 把这类配置当代码审（ch1-l2 §推理单元）

这张表最重要的结论是最后两列：触发源越多，能依赖"代码 diff"的地方越少，能依赖"关于产出的断言"的地方越多。 普通 CI 的核心资产是"测试套件"，模型流水线的核心资产是关于产出的断言集（数据断言 + 模型断言 + 服务断言）。

1.2 D2：验证是统计的#

普通 CI 的测试是确定性的：assert f(x) == y。模型门禁比较的是两个随机变量的差：

Δ^=μ^​cand​−μ^​base​,SE(Δ^)≈sncand​1​+nbase​1​​

于是"通过"必须写成一条带样本量的判据，例如单侧检验：

H0​: Δ≤0vsH1​: Δ>0,拒绝 H0​⟺SE(Δ^)Δ^​>z1−α​

这里立刻出现两个在普通 CI 里不存在的量：

  • α（误拦率）：好模型被门禁拒掉，代价是研发节奏 + 一次白跑的训练；
  • β（漏放率）：差模型被放上线，代价是线上事故。

这两个错误的成本差两三个数量级（下面第六节会算），因此门禁的设计目标不是"把 α 压到最小"，而是在给定预算下最小化 αC拦​+βC放​。第 2 节整节都在处理这件事。

还有一个 D2 特有的陷阱：样本量决定了门禁能分辨多小的差异。n 太小，"通过"只是"没看出来"，不是"没问题"。这就是第 2 节要给的最小可分辨效应（MDE）：

MDE≈(z1−α​+z1−β​)sncand​1​+nbase​1​​

1.3 D3：失败可以静默#

软件流水线的失败模式是"显式的"：编译不过、测试红、部署失败。模型流水线多出一类：

全绿通过，然后线上变差。

它的机制有好几种，本课程后面几节会分别处理：

静默失败机制 在哪一节处理
离线评测集不代表线上分布 本节（数据门禁）+ 第 3 节（影子流量）
门禁样本量不足，"没看出来"被当成"没问题" 第 2 节（MDE / 样本量）
离线指标涨了，但业务护栏（延迟、拒答率、成本）掉了 第 2 节（多指标 + FWER）、第 3 节（护栏指标）
发布本身不原子：权重换了、prompt/缓存没换 第 4 节（版本一致性）
回滚不回来：数据/上游依赖已变 第 4 节（可回滚性）

D3 的工程含义：模型流水线必须有一个发布后观测回路（canary / 影子 / 线上指标），而门禁只负责把"明显坏的"挡在门外。把门禁当成安全保证，是把"离线能测到的"当成"线上会发生的"——这两者之间的差距，正是本课程第 2、3 节的全部内容。

1.4 D4：回滚不是 checkout#

软件的"上一个好版本"由 commit 唯一确定。模型不是：

  • 权重文件在制品库里是内容寻址的（ch1-l2），回滚权重是确定的；
  • 但训练数据可能已经被清理/追加，重建同一个 commit 得到的不是同一个模型；
  • 上游依赖模型可能已经换了版本；
  • 在线特征/缓存里可能已经写入了新模型产生的中间结果（第 4 节）。

所以 D4 的要求不是"能回滚代码"，而是把一次发布定义成一个不可变的绑定（manifest），回滚 = 把指针指回上一个绑定，并保证绑定外的状态不被污染。这直接推导出第 4 节的两条设计原则：manifest 内容寻址 + 指针层可解析历史（ch1-l2 的三层命名空间）。

1.5 把四条差异合成一张流水线图#

二、数据验证门禁：三个层次#

2.1 为什么只做 schema 必然漏#

data validation 在业界通常被等价成"检查字段名和类型"。这个等价关系错得很有代表性，因为它只覆盖了结构这一层。三层的关系是：

层 断言的对象 典型判据 谁来写 漏掉会怎样
L1 schema 字段名、类型、可空性、枚举域 集合相等 / 类型匹配 数据契约 直接崩（容易发现，危害小）
L2 分布 数值的统计形状、类别占比、空值率 PSI / KS / 占比 z 数据 + 算法 模型悄悄变差（D3 的主源）
L3 语义 字段的含义与单位 语义契约（人工 + 对照实验） 数据 + 业务 模型必然变差，且 schema/分布都可能"看起来正常"

L1 的失败是响亮的（崩溃），L2 的失败是安静的（指标掉 0.3 个点），L3 的失败是灾难性的——因为一个语义变化会让整列特征变成噪声，而统计量可能因为"分布形状相似"而不报警。

2.2 一个 schema 全绿的语义事故#

本节代码里的合成数据 ⚠️ 就是这件事：上游把 time_on_page 的单位从秒改成毫秒。

  • L1：字段名还是 time_on_page，类型还是 int，非空率还是 100% → 全绿。
  • L2：分布形状仍然是同一个指数分布的缩放（同一个 expovariate(1/45) 乘 1000），所以 KS 统计量会剧烈报警（本节实测 0.988），但前提是你真的做了 L2。
  • L3：只有对照实验（"用新数据训一版，和旧模型在同一评测集上比"）或人工语义审查才能发现"单位错了"。

关键洞察：这个事故的最优检出位置是 L3 上游的数据契约，而不是下游的模型评测 —— 因为模型的评测集里也带着同样的错单位，门禁可能给出"模型指标没变"的错误安全感（评测集和数据一起被缩放，模型只是学到了一个新尺度）。

2.3 L2 的三个判据：PSI、KS、占比 z#

PSI（Population Stability Index），分位数分箱后按箱比较占比：

PSI=k=1∑K​(qk​−pk​)lnpk​qk​​,pk​,qk​>0

经验阈值（本节采用的判据）：<0.10 通过 / 0.10∼0.25 告警 / >0.25 阻断。

数值算例（来自本节代码实测）：

列 PSI KS 判据结论
amount（未变） 0.00035 0.00714 通过
time_on_page（秒→毫秒） 6.60170 0.98836 阻断
null_rate（0.0310→0.0328） 0.00000 ⚠️ 0.96898 PSI 退化，不可用

amount 的 PSI =0.00035 说明这个统计量在"没漂移"时确实接近 0，噪声量级在 10−4；time_on_page 的 6.60 是阈值的 26 倍，属于无可争议的阻断。

null_rate 那一行是本节最重要的工程细节：二值列只有两个取值，分位数分箱会产生 9/10 个空箱，空箱被 ε 平滑后 PSI 变成 0 —— 一个"看起来完全稳定"的假象。所以：

PSI 适用于连续/多取值列；二值列与低基数类别列要用占比判据（两比例 z 检验或直接设占比阈值）。 代码里用"空箱数 > 0"作为自动切换判据的触发条件。

null_rate 的占比 z 检验：

z=p^​(1−p^​)(n1​1​+n2​1​)​p^​2​−p^​1​​=0.0319⋅0.9681⋅500002​​0.0328−0.0310​=1.566

z=1.566<1.96，p≈0.117：这个空值率变化不显著，正确的处置是"告警但放行"，不是"阻断"。这一行同时演示了另一个纪律：门禁的每个判据都要给出它的不确定性，否则 2% 的占比波动会被误读成"数据质量下降"。

KS 统计量（sup 距离）：

Dn,m​=xsup​​F1,n​(x)−F2,m​(x)​

它的阈值随样本量变化，标准临界值近似 Dcrit​(α)≈c(α)nmn+m​​（n,m→∞ 时双样本 KS 的分布与样本量无关，c(0.05)≈1.36）。本节 n=m=50000：

Dcrit​≈1.362.5×109100000​​=1.36×0.00632=0.0086

amount 实测 D=0.00714<0.0086 → 不显著；time_on_page 的 0.988 远超阈值 → 极显著。注意这个算例的教训：n=5×104 时 KS 的临界值只有 0.0086，这意味着大样本下 KS 会非常敏感，一点点真实漂移（比如上游多了一个 0.1% 的极值）都会显著。所以 KS 适合"告警"，而不适合单独做"阻断"判据 —— 阻断要看效应量（PSI 或占比差），不是看显著性。这正是第 2 节要反复强调的原则：显著 ≠ 重要。

2.4 L2 与 L3 的分界：什么必须人来定#

一个可执行的划分：

问题 归属 自动化程度
字段名/类型变了吗 L1 全自动（阻断）
数值分布的形状变了吗 L2 全自动（告警/阻断按效应量）
类别集合多了一个值 L1 + L2 全自动（新类别单独统计占比）
这个字段的单位/口径变了吗 L3 无法自动，靠数据契约 + 对照实验
这个字段现在算的是另一件事了吗 L3 同上

L3 无法自动的原因不是工具不够好，而是单位与含义是外部知识：time_on_page=30 和 30810 在数值层面都是合法的整数。工程上唯一可行的自动化替代品是：

  1. 数据契约进代码仓：字段的单位与口径写成可评审的声明（"秒，客户端上报，剔除后台标签页"），改它要走 code review；
  2. 对照实验的兜底：任何数据变更都要跑一次"同一评测集上新旧数据的对照"，语义错误在这里会表现为异常的特征重要度或指标跳变；
  3. 范围断言作为廉价代理：给每个数值列声明物理/业务上界（0 <= time_on_page <= 86400），单位错 1000 倍会立刻撞上界。⚠️ 注意这是代理不是判据：它只能抓住"跨量级"的单位错误。

三、L1/L2/L3 之外：把门禁写成"断言集"#

把上面三层落成可维护的东西，最小形态是一份断言集（每行一条断言 + 一个动作）：

# 数据断言（G1）
schema.equal          columns                → block
schema.type           time_on_page:int       → block
range.within          time_on_page ∈ [0, 86400]  → block   # L3 代理
drift.psi             amount            < 0.10 → pass / 0.10~0.25 warn / >0.25 block
drift.psi_binary      null_rate         Δp      → warn if p<0.01
drift.ks              all_numeric_columns D>Dcrit → warn（不 block：大样本过敏）
null.rate_delta       any_column        Δnull > 0.05 → block
freshness.max_lag     event_time        24h     → block
# 服务断言（G4，第 3 节）
perf.p99              < 1.5 × baseline  → block

三条设计纪律：

  1. 每条断言必须带动作（pass/warn/block），不能只有判据。"PSI 是多少"不是门禁，"PSI 超过多少就阻断"才是。
  2. 每条断言必须带它的假阳性代价。block 级断言要能回答"误拦一次多少钱"（第六节）。
  3. 断言集要能被评测：定期回放历史数据，统计每条断言的历史告警中"事后证明是真问题"的比例（即精确率）。一条从不命中或命中后从来不是真问题的断言，是纯成本。

四、门禁放在哪：一个可计算的期望成本模型#

4.1 模型#

设流水线有 m 道门禁按顺序执行，门禁 i 的：

  • 单批成本 ci​（算力 + 等待机会成本）；
  • 条件检出率 di​（给定这一批确实是坏的，门禁 i 拦住它的概率）；
  • 逃逸代价 Cesc​（事故发生后回滚 + 修复 + 信任损失 + 业务损失）。

在观察窗口内的 N 批里，门禁 i 的期望成本是：

E[cost]=门禁运行成本i∈S∑​N(j<i,j∈S∏​(1−dj​))ci​​​+逃逸成本N(j∈S∏​(1−dj​))Cesc​​​

4.2 数值算例（本节代码实测）#

参数：N=200 批、Cesc​=900（每批的期望事故代价），三道门禁

门禁 di​ ci​
G1 数据校验 0.55 0.4
G2 回归测试 0.45 2.0
G3 离线评测 0.60 25.0

逐项账单（代码输出，逐字一致）：

  门禁                 到达批次      单价         小计
  G1 数据校验             200     0.4       80.0   → 通过 90.0 批
  G2 回归测试              90     2.0      180.0   → 通过 49.5 批
  G3 离线评测              49    25.0     1237.5   → 通过 19.8 批
  逃逸上线         19.800     900    17820.0
  合计（全开）                       19317.5

手算核对：200×0.4=80；通过 200×0.45=90 批；90×2=180；通过 90×0.55=49.5 批；49.5×25=1237.5；通过 49.5×0.40=19.8 批；逃逸 19.8×900=17820；合计 80+180+1237.5+17820=19317.5。

这道账单最重要的读法是：门禁自身的运行成本只占 1497.5/19317.5=7.8%，逃逸成本占了 92.2%。换句话说，在这个参数下"砍掉门禁省钱"是错的，因为钱根本不花在门禁上，花在逃逸上。

子集穷举的完整结果（代码输出）：

    G1+G2+G3               期望成本=  19317.50
    G1+G3                  期望成本=  34730.00
    G2+G3                  期望成本=  42750.00
    G1+G2                  期望成本=  44810.00
    G3                     期望成本=  77000.00

全开最优。注意 G1+G3（跳过 G2）比 G1+G2（跳过 G3）便宜：便宜的不是 G2，而是 G3 —— 离线评测的检出率更高（0.60 vs 0.45），单价虽贵 12.5 倍，但它拦下的批次会以 900 的单价折算。

4.3 门槛单价 c∗：什么时候该砍掉一道门禁#

对顺序固定的一组门禁，单独加入门禁 i 的期望收益是：

Δi​=N(j<i∏​(1−dj​))di​下游还会拦住的比例(j>i∏​(1−dj​))​​Cesc​

除以它要处理的批次数 (∏j<i​(1−dj​))N，得到门槛单价：

ci∗​=di​Cesc​j>i∏​(1−dj​)

即：门禁 i 的单价低于 ci∗​ 就该保留，高于就该砍掉。 本节参数下的三门槛（代码输出）：

        c*_G1 = 108.9   c*_G2 = 162.0   c*_G3 = 540.0（实际单价 0.4 / 2 / 25，均低于门槛）

手算：cG3∗​=0.60×900=540；cG2∗​=0.45×0.40×900=162；cG1∗​=0.55×0.55×0.40×900=108.9。三个实际单价都远低于门槛，所以全开。

敏感性（代码输出）：

  G2 单价=   2.0 → 最优 G1+G2+G3   期望成本=  19317.50
  G2 单价= 150.0 → 最优 G1+G2+G3   期望成本=  32637.50
  G2 单价= 162.0 → 最优 G1+G2+G3   期望成本=  33717.50
  G2 单价= 200.0 → 最优 G1+G3      期望成本=  34730.00

c2​=162.0 正好是门槛（成本相等，输出保留 G2 是判平局时的枚举顺序），200>162 时 G2 被砍掉，与 cG2∗​=162 完全吻合。

4.4 这个模型怎么用（以及它不回答什么）#

它能回答：

  • 预算被砍时先砍哪道门禁（答案：ci​/ci∗​ 最大的那道）；
  • 新加一道门禁值不值（算 c∗，和实现成本比）；
  • 门禁顺序要不要调（c∗ 里的 ∏j>i​(1−dj​) 告诉你：便宜的粗筛应该在前，因为它保护了后面所有昂贵门禁的到达批次）。

它不回答：

  • di​ 从哪来。检出率只能靠历史事故回放估计（"过去 20 次事故里，G1 能拦住几次"），样本量通常很小 —— 所以这个模型给出的是量级，不是小数点后两位。
  • Cesc​ 对每一批都一样。真实事故的代价是重尾的（一次 PII 泄露 ≫ 一千次指标回退），重尾下应该用"最坏情况 + 概率"而不是期望值。
  • 门禁之间的相关性。模型假设门禁的检出事件独立；实际上一道脏数据往往同时撞坏分布判据和评测指标（d 高度相关），此时 ∏(1−dj​) 低估逃逸率。保守做法是把 di​ 按"去重后的独立检出"估计（回放历史事故，只把"第一道拦住的"算给它）。

代码#

本节代码只用标准库，包含三个 L2 判据（PSI / KS / 占比 z）和第四节的期望成本模型。合成数据 ⚠️：两批 5 万条伪造埋点，唯一真实差异是 time_on_page 的单位被乘了 1000，且候选批里有 2% 的流量来自"未升级的上游"。

"""第 2 章第 1 节：数据验证门禁 —— 分布漂移判据 + 门禁位置的期望成本。

只用标准库。合成数据已标注 ⚠️。
"""
import math
import random

# ---------------------------------------------------------------- 合成数据 ⚠️
# 两个"批次"来自同一份伪造的埋点：唯一真实差异是 time_on_page 的单位
# 被上游从"秒"改成了"毫秒"（语义变更，schema 无法发现）。
random.seed(20260921)
N = 50000


def session(unit_scale):
    return {
        "amount": round(random.lognormvariate(2.0, 0.5), 2),
        "channel": random.choice(["a", "b", "c", "d"]),
        "time_on_page": int(random.expovariate(1 / 45.0) * unit_scale),
        "null_rate": 1 if random.random() < 0.031 else 0,
    }


BASE = [session(1) for _ in range(N)]
CAND = [session(1000) for _ in range(N - 200)] + [session(1) for _ in range(200)]


# ------------------------------------------------------- 判据 1：PSI（分箱）
def psi(base, cand, col, bins=10):
    """分位数分箱的 Population Stability Index。

    返回 (PSI, 基线箱占比, 候选箱占比, 空箱数)。
    空箱数 > 0 时该列的 PSI 不可信（重结/二值列的分位数边界会退化）。
    """
    xs = sorted(r[col] for r in base)
    edges = [xs[int(len(xs) * i / bins)] for i in range(1, bins)]

    def hist(rows):
        h = [0] * bins
        for r in rows:
            v = r[col]
            k = 0
            while k < len(edges) and v >= edges[k]:
                k += 1
            h[k] += 1
        return [c / max(1, len(rows)) for c in h]

    p, q = hist(base), hist(cand)
    eps = 1e-6
    terms = [(qi - pi) * math.log((qi + eps) / (pi + eps)) for pi, qi in zip(p, q)]
    degenerate = sum(1 for pi, qi in zip(p, q) if pi < eps and qi < eps)
    return sum(terms), p, q, degenerate


# ------------------------------------------------------- 判据 2：KS 统计量
def ks(base, cand, col):
    xs = sorted(r[col] for r in base)
    ys = sorted(r[col] for r in cand)
    i = j = 0
    d = 0.0
    while i < len(xs) and j < len(ys):
        if xs[i] <= ys[j]:
            i += 1
        else:
            j += 1
        d = max(d, abs(i / len(xs) - j / len(ys)))
    return d


# ------------------------------------------- 判据 3：类别 / 空值占比的 z 判据
def z_two_prop(x1, n1, x2, n2):
    p1, p2 = x1 / n1, x2 / n2
    p = (x1 + x2) / (n1 + n2)
    se = math.sqrt(p * (1 - p) * (1 / n1 + 1 / n2))
    return (p2 - p1) / se if se > 0 else 0.0


# ------------------------------------------- 门禁位置的期望成本（穷举 vs 贪心）
ESCAPE = 900.0        # 一次上线事故的期望代价（含回滚与信任损失）
N_BATCH = 200         # 观察窗口内的批次数
GATES = [
    # (名称, 单批检出率 d, 单批成本 c)
    ("G1 数据校验", 0.55, 0.4),
    ("G2 回归测试", 0.45, 2.0),
    ("G3 离线评测", 0.60, 25.0),
]


def total_cost(gates, idx):
    """期望成本 = Σ_i 到达批次数_i × c_i + 逃逸批次数 × C_escape。

    到达批次数_i = N · Π_{j<i, j∈idx}(1 - d_j)，门禁按流水线顺序排列。
    """
    tot = 0.0
    reach = float(N_BATCH)
    for i in range(len(gates)):
        if i in idx:
            tot += reach * gates[i][2]
            reach *= 1 - gates[i][1]
    return tot + reach * ESCAPE


def greedy(gates):
    """比值贪心：每轮加入"边际成本下降 / 单价"最大的那个门禁。"""
    chosen = []
    for _ in range(len(gates)):
        best = None
        for i in range(len(gates)):
            if i in chosen:
                continue
            v = total_cost(gates, set(chosen) | {i})
            if best is None or v < best[0]:
                best = (v, i)
        chosen.append(best[1])
    return chosen


def main():
    print("== 1. 分布漂移：PSI / KS / 类别占比 ==")
    for col in ("amount", "time_on_page", "null_rate"):
        v, p, q, deg = psi(BASE, CAND, col)
        d = ks(BASE, CAND, col)
        note = f"  ⚠️ 空箱 {deg}/{len(p)}" if deg else ""
        print(f"{col:13s} PSI={v:8.5f}  KS={d:.5f}  首箱 p={p[0]:.4f} q={q[0]:.4f}{note}")
    b = sum(r["null_rate"] for r in BASE)
    c = sum(r["null_rate"] for r in CAND)
    print(f"null_rate 类别占比 z={z_two_prop(b, N, c, N):.3f} "
          f"(基线 {b/N:.4f} → 候选 {c/N:.4f})")

    print()
    print("== 2. 固定阈值判据（<0.10 通过 / 0.10~0.25 告警 / >0.25 阻断）==")
    for col in ("amount", "time_on_page", "null_rate"):
        v, _, _, deg = psi(BASE, CAND, col)
        verdict = "通过" if v < 0.10 else ("告警" if v < 0.25 else "阻断")
        if deg:
            verdict += "（PSI 在重结/二值列上退化 → 改用占比 z 判据）"
        print(f"{col:13s} PSI={v:8.5f} → {verdict}")

    print()
    print("== 3. schema 层的盲区：字段名 / 类型 / 非空全都通过 ==")
    med = sorted(r["time_on_page"] for r in BASE)[N // 2]
    med2 = sorted(r["time_on_page"] for r in CAND)[N // 2]
    print(f"time_on_page 中位数 {med} → {med2}（schema 无感）")

    print()
    print(f"== 4. 门禁位置：{N_BATCH} 个批次、逃逸代价 {ESCAPE:.0f}/次 ==")
    idx = {0}
    reach = N_BATCH
    print(f"  {'门禁':14s} {'到达批次':>8s} {'单价':>7s} {'小计':>10s}")
    tot = 0.0
    for i in range(3):
        arrive = reach
        cost = arrive * GATES[i][2]
        ok = arrive * (1 - GATES[i][1])
        print(f"  {GATES[i][0]:14s} {arrive:8.0f} {GATES[i][2]:7.1f} {cost:10.1f}"
              f"   → 通过 {ok:.1f} 批")
        tot += cost
        reach = ok
    print(f"  逃逸上线       {reach:8.3f} {ESCAPE:7.0f} {reach * ESCAPE:10.1f}")
    print(f"  合计（全开）   {'':8s} {'':7s} {tot + reach * ESCAPE:10.1f}")

    ranked = []
    for mask in range(1 << len(GATES)):
        sub = {i for i in range(len(GATES)) if mask & (1 << i)}
        ranked.append((total_cost(GATES, sub), sub))
    ranked.sort(key=lambda t: t[0])
    print()
    print("  子集穷举（前 5）:")
    for v, sub in ranked[:5]:
        names = "+".join(GATES[i][0].split()[0] for i in sorted(sub)) or "（无门禁）"
        print(f"    {names:22s} 期望成本={v:10.2f}")
    print("    穷举最优 =", "+".join(GATES[i][0].split()[0]
                                  for i in sorted(ranked[0][1])))
    print("    比值贪心 =", "+".join(GATES[i][0].split()[0]
                                  for i in sorted(greedy(GATES))))

    print()
    print("== 5. 敏感性：G2 单价上升时最优集合怎么变（G2 到达 90 批）==")
    for c2 in (2.0, 150.0, 162.0, 200.0):
        g = [GATES[0], ("G2 回归测试", 0.45, c2), GATES[2]]
        best = min(((total_cost(g, {i for i in range(3) if m & (1 << i)}),
                     {i for i in range(3) if m & (1 << i)}) for m in range(8)),
                   key=lambda t: t[0])
        names = "+".join(g[i][0].split()[0] for i in sorted(best[1])) or "（无门禁）"
        print(f"  G2 单价={c2:6.1f} → 最优 {names:10s} 期望成本={best[0]:10.2f}")
    print("  解析：加入门禁 i 的收益 = 到达批次数_i × d_i ×（它漏掉的批次被下游拦住的"
          "失败部分）× C_escape，")
    print("        除以到达批次数_i → 门槛单价 c*_i = d_i ×（1 − 下游累计检出）× C_escape：")
    print(f"        c*_G1 = {0.55 * (1 - 0.45) * (1 - 0.60) * ESCAPE:.1f}"
          f"   c*_G2 = {0.45 * (1 - 0.60) * ESCAPE:.1f}"
          f"   c*_G3 = {0.60 * ESCAPE:.1f}（实际单价 0.4 / 2 / 25，均低于门槛）")


main()

读输出的五个要点#

  1. amount 的 PSI =0.00035 是"噪声基线"。任何 PSI 阈值低于 10−3 的门禁都会持续误报 —— 阈值必须留出统计噪声裕度，而这个裕度应该用无变化的对照批次实测（把同一批数据随机切两半算 PSI，重复 k 次取分位数）。
  2. null_rate 的 PSI =0.00000 是假象：空箱 9/10。如果只看这一行，你会认为一个真实变化了 5.8% 的占比"完全稳定"。 这是本节最重要的反例：判据与列类型必须匹配。
  3. KS 在 n=5×104 时临界值只有 0.0086：amount 的 0.00714 距临界值只有 17% 的裕度。真实系统里这类"接近临界"的列会随机翻红，所以 KS 只配做告警。
  4. time_on_page 的中位数 30→30810：两者都是合法整数，schema 层完全无感。L3 事故的检出只能靠契约/对照，范围断言（≤86400）是廉价代理。
  5. 门槛单价 c∗ 的量级（102）远高于实际单价（100）：说明在 Cesc​=900 的假设下，门禁预算还有大量余量 —— 真正稀缺的不是算力，而是能提高 di​ 的断言。这条结论会直接引出第 2 节：把资源投在"更准的判据"（更高 d），而不是"更快的门禁"（更低 c）。

练习#

  1. 给你自己的流水线做触发矩阵： （a）列出所有能导致"线上模型变了"的事件（代码 / 数据 / 上游模型 / 依赖 / 定时 / 配置）； （b）对每个事件标注：有没有 diff、现在由谁负责发现、现有门禁能不能发现； （c）指出至少一个当前完全无人负责的触发源，并给出最小补法。

  2. PSI 阈值要用噪声基线定，不能拍脑袋： （a）取你的一条真实特征，把同一个批次随机切成两半，计算 k=20 次 PSI，报告它的均值与 p95​； （b）用 p95​ 作为"通过"阈值、5×p95​ 作为"阻断"阈值，替换现有的固定阈值； （c）回答：原来 0.10/0.25 的阈值相对你的噪声基线是太松还是太紧？

  3. 二值列与低基数列的判据替换： （a）找出你所有基数 ≤5 的列，检查它们的 PSI 是否出现了空箱（本节 null_rate 的反例）； （b）对每列改用占比 z 检验，并给出"需要多大样本量才能检出 1 个百分点的绝对变化"（用 n≈2p^​(1−p^​)(z1−α​+z1−β​)2/δ2 手算）； （c）说明为什么大基数类别列（如 channel）反而可以用 PSI。

  4. 一条 L3 断言的设计： （a）选你数据里的一个数值字段，写下它的单位、口径、物理上界； （b）用"范围断言 + 契约评审"实现 L3 的最小代理，给出误报率估计； （c）构造一个不改变字段名与类型但改变含义的变更（例如把"平均值"改成"中位数"），说明你的断言集能否发现；如果不能，缺什么。

  5. 门禁期望成本的实测校准： （a）回放你过去 6 个月的事故记录，估出每道门禁的 di​（用"第一道拦住的事故数 / 总事故数"去重）； （b）估 Cesc​ 时不要用平均值：把事故按代价排序，报告 p50​ 与 p95​，并说明重尾下用均值会怎样影响 c∗； （c）计算每道门禁的 ci​/ci∗​，给出"预算砍 30% 时先砍谁"的排序。

  6. 判据的精确率回放： （a）取一个季度内所有触发 block 的告警，逐条标注"事后证明是真问题 / 假阳性"； （b）计算每条断言的精确率与召回率； （c）给出处置：精确率低于 50% 的断言该放宽还是该删除，为什么"从来不触发的断言"也要审查。

小结#

  • 模型流水线不是"软件流水线 + 评测步骤"，四条结构差异（D1 触发源不止代码、D2 验证是统计的、D3 失败可以静默、D4 回滚不是 checkout）分别要求补上：触发矩阵、带样本量的判据、发布后观测回路、manifest 绑定 + 可解析指针。
  • 数据验证门禁有三层，只做 schema 必漏：L1 结构（响亮失败）、L2 分布（安静失败）、L3 语义（灾难失败）。本节实例：time_on_page 秒→毫秒，schema 全绿、中位数 30→30810。
  • 判据要与列类型匹配：连续列用 PSI（<0.10 通过 / >0.25 阻断）或 KS；二值/重结列上 PSI 会因空箱退化成 0（本节 null_rate 的 PSI =0.00000 是假象），必须改用占比 z 检验。KS 的临界值随 n 缩小（本节 n=5×104 时仅 0.0086），故只配做告警 —— 显著 ≠ 重要。
  • 每条断言必须带动作（pass/warn/block）与它的假阳性代价；断言集本身要能被回放评估（精确率 / 召回率），否则它既不可辩护也不可优化。
  • 门禁位置是可计算的：E[cost]=∑i​N∏j<i​(1−dj​)ci​+N∏j​(1−dj​)Cesc​。本节算例中门禁运行成本只占 7.8%、逃逸成本占 92.2%；全开门禁最优（19317.5 vs 次优 34730）。
  • 门槛单价 ci∗​=di​Cesc​∏j>i​(1−dj​) 是砍预算的判据：本节 cG1∗​=108.9、cG2∗​=162.0、cG3∗​=540.0，敏感性扫描在 c2​ 越过 162 时精确翻转。
  • 便宜的粗筛要放在前面：c∗ 里的 ∏j>i​(1−dj​) 说明早置门禁保护的是后面所有昂贵门禁的到达批次。
  • 模型给出的是量级不是小数：di​ 只能靠历史事故回放估计（样本极小），Cesc​ 是重尾的（应按 p95​ + 概率看，而不是均值），门禁之间还有相关性（∏(1−dj​) 会低估逃逸）。

下一节：这一节把"脏数据"挡在了门外，但门禁的最后一关 —— 离线评测 —— 还完全是空的：我们只说"要有一个评测门禁"，没说阈值定在哪、样本量要多大、p < 0.05 是不是就够、几十个指标一起看时怎么算。第 2 节要把发布决策写成 H0​/H1​，给出误拦与漏放的成本比、MDE 与样本量公式、多重比较的两套校正（FWER / FDR）与序贯检验（SPRT），并回答"离线涨了 1.2 个点，真的敢发吗"。
