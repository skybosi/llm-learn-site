向量召回（双塔/ANN）#

上一课说到向量召回是最主流的一路召回，本课就把它彻底讲透。核心要回答两个"为什么"：为什么向量召回比协同过滤更能泛化？为什么它在百万级物品池上还能快到毫秒级？ 答案分别藏在"双塔模型"和"近似最近邻（ANN）"里。

一、概念讲解#

1. 从"共现"到"语义"：向量召回解决了什么#

ItemCF 的召回逻辑是"物品 A 和物品 B 被同一批用户喜欢过，所以喜欢 A 的人可能也喜欢 B"。它依赖共现——两个物品必须在行为数据里一起出现过。这带来两个盲区：

  • 稀疏盲区：冷门物品共现次数少，相似度算不准。
  • 语义盲区：两部从没被同一用户看过的电影，风格、题材可能高度相似，但 ItemCF 完全看不到。

向量召回换了一条思路：把用户和物品都投影到同一个向量空间，用"用户向量与物品向量的内积/余弦"直接度量"这个用户会不会喜欢这个物品"。只要模型学会把"喜欢电竞的用户"和"电竞类物品"映射到相近的方向，那么即便某个电竞物品从未和这个用户产生过交互，只要它自己的向量落在电竞区域，也能被内积打高分。这就是向量召回"能泛化到未见交互"的根本原因——它建模的是内容/兴趣的语义，而不是行为共现的表象。

2. 双塔模型：让用户塔和物品塔"各算各的"#

如果让一个模型把"用户特征 + 物品特征"拼在一起进网络做交互（像精排那样），那么给一个用户召回时，需要把它和每一个候选物品都过一遍网络——百万次前向，时延爆炸。双塔（two-tower）模型的妙处就是把"用户"和"物品"拆成两个独立的塔：

用户特征 ──> User Tower（MLP）  ──> e_u ∈ R^d
物品特征 ──> Item Tower（MLP）  ──> e_i ∈ R^d
打分 = <e_u, e_i>（内积）

两塔独立编码、最后只做一次内积。这带来一个决定性的工程优势：物品向量可以离线批量算好，存进向量索引；线上只算一次用户向量，然后去索引里做内积检索。用户向量每请求算一次，物品向量离线预计算，检索时用 ANN 加速——这就是向量召回能"快"的结构基础。

训练双塔的样本从行为日志来：正样本 = 用户点击过的 (用户, 物品) 对；负样本 = 随机采样的 (用户, 物品) 对。损失常用交叉熵或对比损失（如把内积当作 logit，正样本推向 1、负样本推向 0）。一个高频技巧是 in-batch negatives：把一个 batch 里其他用户的正样本，当作当前用户的负样本，几乎零成本地扩大负样本量，还能顺带学到"用户之间要有区分度"。

双塔也有代价：用户和物品在最后一刻才交互（只做内积），表达力弱于精排里"特征全程交叉"的模型。所以双塔适合召回（粗筛），不适合精排（精打分）。后续演进出的"多兴趣向量"（一个用户学多个兴趣向量，分别召回）就是为了缓解"单向量难以概括用户多种兴趣"的问题。

3. 为什么"快"：近似最近邻检索（ANN）#

即使所有物品向量都算好了，如果给每个物品都做一次内积（暴力检索），百万物品仍是百万次乘法，达不到毫秒级。近似最近邻（ANN）牺牲一点点"找到的绝对最优性"，换取数量级的加速。主流思路：

  • 基于图的检索（HNSW）：把向量建成多层"近邻图"，检索时像爬山一样沿边走到局部最优，复杂度近似对数级，召回质量高，是当前最常用的方案之一。
  • 倒排 + 量化（IVF + PQ）：先用聚类把向量分成若干桶（倒排），检索时只查最近的几个桶；桶内再用乘积量化（PQ）把向量压缩成短码，用查表法快速算近似距离，内存占用大幅下降。
  • 哈希（LSH）：把相近的向量以高概率哈希到同一个桶，检索时只比对同桶向量，最简单但精度通常较低。

工业界通常用现成的向量检索引擎，如 Faiss（Facebook 开源）、Milvus、Annoy 等。它们的共性思路是：离线建索引，在线查近似近邻，把"百万次内积"变成"对数级跳跃 + 少量精确计算"。

整个检索流程可以概括为：

离线：全部物品 ──> Item Tower ──> 物品向量库 ──> 建 ANN 索引（HNSW/IVF+PQ）
在线：当前用户 ──> User Tower ──> 用户向量 q  ──> ANN 检索 topK ──> 候选物品

二、可运行示例#

示例 1：PyTorch 简化双塔 + in-batch 负采样#

训练一个极简双塔，用 in-batch negatives 拉大正负样本内积差距。

import torch
import torch.nn as nn

class TwoTower(nn.Module):
    def __init__(self, num_users, num_items, embed_dim=16, hidden=32):
        super().__init__()
        self.user_emb = nn.Embedding(num_users, embed_dim)
        self.item_emb = nn.Embedding(num_items, embed_dim)
        # 两个塔：各自一个全连接，把 embedding 投影到打分空间
        self.user_tower = nn.Sequential(nn.Linear(embed_dim, hidden), nn.ReLU(),
                                        nn.Linear(hidden, embed_dim))
        self.item_tower = nn.Sequential(nn.Linear(embed_dim, hidden), nn.ReLU(),
                                        nn.Linear(hidden, embed_dim))

    def forward(self, u, i):
        eu = self.user_tower(self.user_emb(u))   # (B, d)
        ei = self.item_tower(self.item_emb(i))   # (B, d)
        return eu, ei

def train_two_tower():
    torch.manual_seed(0)
    num_users, num_items = 200, 500
    model = TwoTower(num_users, num_items)
    opt = torch.optim.Adam(model.parameters(), lr=1e-2)
    loss_fn = nn.BCEWithLogitsLoss()

    for step in range(300):
        B = 64
        # 正样本：用户 u 点击了物品 i
        u = torch.randint(0, num_users, (B,))
        i = torch.randint(0, num_items, (B,))
        eu, ei = model(u, i)
        # 打分矩阵 S[b, b'] = <eu_b, ei_b'>，对角线是正样本，其余是 in-batch 负样本
        S = eu @ ei.T                        # (B, B)
        labels = torch.eye(B)                # 对角线为 1
        loss = loss_fn(S, labels)
        opt.zero_grad()
        loss.backward()
        opt.step()
        if step % 100 == 0:
            print(f"step {step:>3}: loss = {loss.item():.4f}")

    # 验证：正样本内积应明显大于随机负样本内积
    with torch.no_grad():
        u = torch.randint(0, num_users, (100,))
        i = torch.randint(0, num_items, (100,))
        eu, ei = model(u, i)
        pos = (eu * ei).sum(dim=1)
        i_neg = torch.randint(0, num_items, (100,))
        _, ei_neg = model(u, i_neg)
        neg = (eu * ei_neg).sum(dim=1)
        print("正样本内积均值:", round(pos.mean().item(), 3))
        print("负样本内积均值:", round(neg.mean().item(), 3))

train_two_tower()

示例 2：用 NumPy 模拟"离线建索引 + 在线暴力/近似检索"#

演示物品向量离线入库、在线用内积检索 topK，并对比暴力检索与"先聚类分桶再桶内检索"的加速思路。

import numpy as np

np.random.seed(0)
n_items, d = 100000, 32
item_vecs = np.random.randn(n_items, d)
item_vecs /= np.linalg.norm(item_vecs, axis=1, keepdims=True)  # 归一化

def brute_search(q, item_vecs, k=5):
    """暴力检索：对所有物品算内积，取 topK。"""
    s = item_vecs @ q                       # (n_items,)
    return np.argsort(-s)[:k]

def ivf_search(q, centroids, item_vecs, nprobe=2, k=5):
    """简化 IVF：先找最近的 nprobe 个桶，再只在桶内暴力检索。"""
    bucket = np.argmax(centroids @ q)       # 找最近的一个聚类中心(简化)
    # 这里简化为：取离 q 最近的 nprobe 个中心所代表的桶
    center_sim = centroids @ q
    top_centers = np.argsort(-center_sim)[:nprobe]
    cand = np.concatenate([np.where(np.argmax(item_vecs @ centroids.T, axis=1) == c)[0]
                           for c in top_centers])
    s = item_vecs[cand] @ q
    return cand[np.argsort(-s)[:k]]

q = np.random.randn(d)
q /= np.linalg.norm(q)

# 聚类出 64 个中心，模拟倒排桶
n_centers = 64
centroids = item_vecs[np.random.choice(n_items, n_centers, replace=False)]
centroids /= np.linalg.norm(centroids, axis=1, keepdims=True)

import time
t0 = time.time(); brute = brute_search(q, item_vecs); t1 = time.time()
ivf = ivf_search(q, centroids, item_vecs); t2 = time.time()
print("暴力检索 top5:", brute.tolist(), f"耗时 {(t1-t0)*1000:.2f} ms")
print("IVF 检索 top5:", ivf.tolist(), f"耗时 {(t2-t1)*1000:.2f} ms")
print("两法 top5 重合数:", len(set(brute.tolist()) & set(ivf.tolist())))
