数据类型#

一、概念讲解#

DataFrame 里每一列都有自己的数据类型（dtype），它决定了这列数据怎么存储、能做什么运算、占多少内存。类型不对是数据清洗阶段最常见的坑——比如"价格"读进来是字符串，直接求和会得到一串拼起来的文本而不是数值。

1. 常见 dtype 一览#

  • 数值型：int64、float64，可参与加减乘除。
  • object：最宽泛的类型，通常表示 Python 字符串，也常是"类型混乱"的信号——真正的数字本不该以 object 存储。
  • bool：布尔型，逻辑运算的结果。
  • category：分类型，适合取值种类很少但重复极多的列（如"性别""城市"），能显著节省内存并加速分组。
  • datetime64：时间类型，支持按年、月、周等时间维度运算。

2. 类型转换的两条路径#

  • astype(dtype)：直接转换。适合数值之间的互转（如 int64 → float64），但如果字符串里混着无法解析的内容，会直接报错。
  • pd.to_numeric(...)：把"看起来像数字的字符串"安全地转成数值，配合 errors="coerce" 可以把无法解析的项转成 NaN 而不是报错——这是清洗脏数据的标准姿势。
  • pd.to_datetime(...)：把日期字符串统一转成 datetime64，同样支持 errors="coerce"。

3. 为什么要关心类型#

一是正确性：数值存成 object 会导致 sum、mean 等运算出错或结果诡异；二是性能：category 类型把重复字符串变成整数编码，内存和速度都更优。养成"拿到数据先看 dtypes"的习惯，很多奇怪 bug 都能提前避免。

二、可运行代码示例#

import pandas as pd

df = pd.DataFrame({
    "编号": [1, 2, 3],
    "价格": ["12.5", "8.0", "15.3"],        # 故意存成字符串
    "是否会员": [True, False, True],
    "城市": ["北京", "上海", "北京"],
})
print("原始 dtypes：\n", df.dtypes)

# 1. to_numeric：字符串转数值，非法值 -> NaN
df["价格"] = pd.to_numeric(df["价格"], errors="coerce")
print("\n价格转数值后 dtypes：\n", df.dtypes)

# 2. astype：数值类型之间的互转
df["编号"] = df["编号"].astype("float64")
print("\n编号转 float64 后：\n", df.dtypes)

# 3. category：重复值多的列改用分类类型
df["城市"] = df["城市"].astype("category")
print("\n城市转 category 后：\n", df.dtypes)
print("分类的取值种类：", df["城市"].cat.categories)

# 4. to_datetime：日期字符串转时间类型
dates = pd.Series(["2024-01-01", "2024-06-15", "bad-date"])
dt = pd.to_datetime(dates, errors="coerce")
print("\n日期转换：\n", dt)
print("类型：", dt.dtype)
print("提取年份：", dt.dt.year.tolist())

运行后注意两处：to_numeric(..., errors="coerce") 和 to_datetime(..., errors="coerce") 都把"解析不了的值"变成了 NaN，而不是中断程序——这让清洗脏数据可以一步完成。

三、练习#

  1. 创建一列字符串形式的数字 ["10", "20", "abc", "30"]，用 pd.to_numeric(errors="coerce") 转换，指出哪个元素变成了 NaN。
  2. 把一列 int64 用 astype("float64") 转换，再尝试把一列含 NaN 的浮点数用 astype("int64") 转换，观察后者为什么报错（提示：NaN 无法转成整数）。
  3. 对一个"取值种类少、重复多"的列（如 100 个元素只取 "男"/"女"），尝试转成 category 类型并查看 cat.categories，说说这样转换的好处。
