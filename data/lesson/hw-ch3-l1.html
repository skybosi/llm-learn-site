FP32/FP16/BF16#

从这一章起，我们进入"精度"这个主题。你已经知道 FP16 比 FP32 快、省显存，但"快多少、省多少、代价是什么"，得先看懂浮点数是怎么用二进制位拼出来的。这一课讲三种最常见的浮点格式：FP32、FP16、BF16。

一、概念讲解#

1. 浮点数的三段式：符号 + 指数 + 尾数#

一个 IEEE 754 浮点数由三部分组成：

值=(−1)符号×2指数×1.尾数

位数分配决定了两个关键属性：指数位数决定"范围"（能表示多大/多小的数），尾数位数决定"精度"（相邻可表示数的间距）。

2. 三种格式对比#

格式 符号位 指数位 尾数位 总位数 大致范围 有效十进制位数
FP32 1 8 23 32 约 10±38 ~7 位
FP16 1 5 10 16 约 ±65504，最小正规数 ≈6.1×10−5 ~3 位
BF16 1 8 7 16 约 10±38（与 FP32 同范围） ~2-3 位

3. FP16 的软肋：范围小，易溢出/下溢#

FP16 只有 5 位指数，能表示的最大值是 65504，最小正规数约 6.1×10−5。一旦中间结果超过 65504 就溢出（变成无穷大），小于 6.1×10−5 就下溢（变成 0）。深度学习的梯度常常小到 10−6 甚至更小，直接全程用 FP16 训练很容易出问题——所以才有混合精度训练（loss 用 FP32 缩放）。

4. BF16：保范围、弃精度#

BF16 是 Google 提出、为深度学习设计的格式：把 FP32 的高 16 位截下来。它保留了 FP32 的 8 位指数（范围不丢，几乎不溢出），但尾数只剩 7 位，精度反而略低于 FP16。好处是：和 FP32 转换几乎零成本（截断高位），且训练时不用精细的 loss scaling。于是出现分工：FP16 精度略好但范围小，BF16 范围大但精度略差，各有适用场景。

5. 为什么推理爱用 FP16/BF16#

回到本课程的目标"怎么跑最划算"：

  1. 显存减半：70B 模型 FP32 要 280 GB，FP16/BF16 只要 140 GB；
  2. 带宽需求减半：每 token 读的字节数减半，吞吐近似翻倍；
  3. 算力更高：H100 的 FP16 张量算力 989 TFLOPS，是 FP32 标量 67 TFLOPS 的约 15 倍。

三者叠加，FP16/BF16 几乎成了推理的默认选择，代价只是"每个数少几位精度"，对已训练好的模型通常影响很小。

二、可运行代码示例#

用 NumPy 亲手感受 FP16 的溢出、下溢和精度损失，并模拟 BF16。

import numpy as np

# ---- 例 1：FP16 能表示的范围 ----
print("FP32 最大有限值:", np.finfo(np.float32).max)
print("FP16 最大有限值:", np.finfo(np.float16).max)       # 65504
print("FP16 最小正规数:", np.finfo(np.float16).tiny)      # 约 6.1e-5
print("FP16 机器精度(eps):", np.finfo(np.float16).eps)    # 约 0.000977

# ---- 例 2：溢出：超过 65504 会怎样 ----
a = np.float16(65504.0)          # 最大值，OK
b = np.float16(65504.0) + np.float16(1.0)   # 溢出 -> inf
print("\n65504 + 1 在 FP16 中 =", b)

# ---- 例 3：下溢：太小会被"吞掉" ----
tiny = np.float16(3e-5)          # 小于最小正规数，进入次正规/下溢区
print("3e-5 在 FP16 中 =", tiny)

# ---- 例 4：精度损失：FP32 转 FP16 后的误差 ----
x32 = np.array([1.0, 1.1, 1.123456, 1000.5], dtype=np.float32)
x16 = x32.astype(np.float16).astype(np.float32)
print("\n原始 FP32  :", x32)
print("往返 FP16 后:", x16)
print("绝对误差    :", np.abs(x32 - x16))

# ---- 例 5：模拟 BF16（截取 FP32 高 16 位，四舍五入近似） ----
def to_bf16(x32):
    u = x32.view(np.uint32)                        # 按位重解释
    u = (u + np.uint32(0x7FFF)) & np.uint32(0xFFFF0000)  # 加 0x7FFF 后截低 16 位
    return u.view(np.float32)

y32 = np.array([1.0, 1.1, 3.14159, 1e-30], dtype=np.float32)
y_bf16 = to_bf16(y32)
print("\n原始 FP32   :", y32)
print("模拟 BF16    :", y_bf16)
print("BF16 仍能表示 1e-30（范围大）:", y_bf16[-1] != 0.0)

# ---- 例 6：精度换来的收益：显存与带宽减半 ----
params = 70e9
for name, bpp in {"FP32": 4, "FP16/BF16": 2}.items():
    print(f"\n70B 模型 {name}: 权重 {params*bpp/1e9:.0f} GB")

要点：例 2、例 3 让你直观看到 FP16 的溢出/下溢边界；例 4 的误差来自"尾数变少、间距变大"；例 5 中 BF16 连 10−30 都能表示，印证了"BF16 保范围"；例 6 把精度问题落到最实在的收益——显存和带宽减半。

三、练习#

  1. 计算：FP16 的最大正规数为什么是 65504？写出它的二进制指数与尾数，验证 215×(2−2−10)=65504。
  2. 对比：把 x32 = [100000.0, 0.00001, 0.3] 分别转成 FP16 和 BF16，观察哪个数在 FP16 里溢出、在 BF16 里仍能表示，体会两者的取舍。
  3. 估算：一个 8B 模型，FP32 权重占多少 GB？转 FP16/BF16 后占多少 GB？省下的显存能装一个多大的额外模型？
  4. 思考：训练用 FP16 需要 loss scaling 来防下溢，但 BF16 通常不需要，为什么？（提示：看指数位数。）
