项目规划#

前面五章，你从 CLIP 的对比学习一路走到多模态大模型，手里已经攒齐了理论武器。从本课开始进入实战：从零规划并落地一个"文生图"项目。很多人在这一步会犯同一个错——急着写代码，结果在显存、成本、效果评估上反复返工。好的项目规划，能让你少走一半弯路。

一、概念讲解#

1. 先定义"做什么"和"做到什么程度算成功"#

动手之前，用一句话把项目钉死。以本课程为例，我们做一个"中文文生图演示应用"：

  • 输入：一句中文描述（例如"一只戴着红围巾的柯基，卡通风格"）。
  • 输出：一张满足描述的图片。
  • 成功标准（可量化）：单张生成延迟 ≤ 某阈值；生成的图与描述在语义上一致（后续用 CLIP score 衡量）；在给定预算内稳定运行不 OOM（显存溢出）。

这一步的价值在于：后面所有技术选型，都是为了满足这几条标准，而不是"因为新潮所以用"。

2. 技术选型：模型、框架、部署#

  • 模型：入门用 runwayml/stable-diffusion-v1-5（生态最全、教程最多、显存友好）；追求画质用 SDXL（分辨率更高、构图更好，但更吃显存）；有中文需求可考虑社区的中文模型或对英文 prompt 做翻译。模型不是越新越好，而是够用且可控。
  • 推理框架：用 Hugging Face diffusers。它把模型加载、调度器（scheduler）、pipeline 全部封装好，几行代码就能跑，也方便后面换模型、做微调。
  • 部署形态：演示项目可以先跑在本地脚本或简单 Web 服务上；小程序/线上服务则需要考虑 GPU 实例、排队与限流。本课程聚焦"跑通并验证效果"，部署留到后续部署类课程。

3. 资源规划：显存、延迟、成本三本账#

生成模型对资源敏感，规划时要提前算清楚：

  • 显存：SD v1.5 在 fp16 + 注意力切片下，约需 4~6 GB 显存；SDXL 则要 10 GB 以上，必要时用 enable_model_cpu_offload 把部分模块卸到内存。低于门槛就会 OOM，这是最常见的"翻车点"。
  • 延迟：推理步数（num_inference_steps）与分辨率几乎线性影响耗时。先测一次，再据此定"成功标准"里的延迟阈值是否现实。
  • 成本：若用云 GPU，按"单次生成耗时 × 单价 × 调用量"估算月度账单；本地则主要是一次性显卡投入。

4. 里程碑与风险#

把项目切成可验收的小步，每步都有明确交付：

里程碑 交付物 验收方式
M1 环境就绪 依赖装好、能加载模型 smoke test 跑通
M2 单图生成 给定 prompt 输出一张图 人工看效果
M3 参数调优 对比步数/CFG/seed 生成质量对比表
M4 客观评估 CLIP score 等指标脚本 输出量化分数

风险清单（提前想好对策）：显存不足（→ 用 offload/降低分辨率）、生成内容不合规（→ 加内容安全过滤与提示词约束）、结果不稳定（→ 固定 seed 复现）。

5. 合规与安全红线#

生成模型必须守住两条底线：

  • 内容合规：不生成违法违规、暴力、涉黄、侵权肖像等内容；生产环境要叠加内容审核与提示词过滤。
  • 可追溯：保留每次生成的 prompt、seed、模型版本，便于复现与责任追踪。

二、可运行代码示例#

示例 1：环境检查与依赖版本#

项目第一步是确认环境。下面脚本打印关键库版本与可用显存，作为 M1 里程碑的验收。

import sys
import torch

print("Python 版本:", sys.version.split()[0])
print("PyTorch 版本:", torch.__version__)
print("CUDA 是否可用:", torch.cuda.is_available())

if torch.cuda.is_available():
    gpu_name = torch.cuda.get_device_name(0)
    total = torch.cuda.get_device_properties(0).total_memory / 1024**3
    free = torch.cuda.mem_get_info()[0] / 1024**3
    print(f"GPU: {gpu_name}")
    print(f"显存: 总量 {total:.1f} GB / 当前空闲 {free:.1f} GB")
else:
    print("未检测到 GPU，文生图将非常慢，建议使用带 GPU 的环境")

try:
    import diffusers, transformers
    print("diffusers 版本:", diffusers.__version__)
    print("transformers 版本:", transformers.__version__)
except ImportError as e:
    print("缺少依赖，请先执行: pip install diffusers transformers accelerate")

示例 2：最小 smoke test（M1 验收）#

跑通一个最小 pipeline，证明"环境 → 模型 → 生成"整条链路是通的。这一步先不求图好看，只求不报错。

from diffusers import StableDiffusionPipeline
import torch

# 用 fp16 降低显存占用; 无 GPU 的环境可去掉 torch_dtype 与 to("cuda")
pipe = StableDiffusionPipeline.from_pretrained(
    "runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16
)
pipe = pipe.to("cuda")

# 最小生成: 步数少、分辨率默认, 只验证链路通不通
image = pipe("a simple red circle", num_inference_steps=5).images[0]
image.save("smoke_test.png")
print("smoke test 通过，已生成 smoke_test.png")

如果你只有 CPU，把 .to("cuda") 删掉、torch_dtype=torch.float16 也删掉即可，但生成会很慢，仅适合验证链路。真实项目请务必用 GPU。

三、练习#

  1. 目标拆解：为"中文文生图演示应用"补全三条可量化的成功标准（提示：延迟、一致性、稳定性各一条）。
  2. 动手实验：运行示例 1，记录你的环境信息（Python/PyTorch 版本、显存大小）。据此判断你能否跑 SD v1.5，以及是否需要 offload。
  3. 选型论证：如果你的目标变成"在小程序里生成高清壁纸"，上面第 2 节的技术选型要如何调整？从模型、分辨率、延迟三方面说明。
  4. 风险预案：假设生成一张图需要 8 秒，而产品要求 2 秒内返回。列出至少两种可能的优化方向（提示：步数、分辨率、模型蒸馏、缓存）。
