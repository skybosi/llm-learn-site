为什么需要 KV Cache#

从第 1 章我们知道 decode 阶段是"逐 token 串行生成"。如果不加任何优化，每生成一个新 token，都要把从第一个 token 到当前 token 的全部历史重新算一遍注意力，计算量随生成长度平方级增长。KV Cache 就是用来砍掉这些重复计算的。学完本课，你应当能解释"不缓存会重复算什么"，以及"KV Cache 具体存了什么、为什么能省"。

一、概念讲解#

1. 注意力机制的回顾#

Transformer 的每一层，对每个 token 都要算一次注意力：

Attention(Q,K,V)=softmax(dk​​QK⊤​)V

其中 Q（查询）、K（键）、V（值）分别由当前 token 的输入向量乘以三个权重矩阵得到。注意一个关键事实：在自回归生成中，已生成 token 的 K、V 是永远不会变的——因为前面的 token 是确定的，它们的隐状态不随后续生成而改变。

2. 没有 KV Cache 时：重复计算#

假设已生成 t 个 token，现在要生成第 t+1 个 token。如果没有缓存，模型要把 t+1 个 token 全部过一遍网络，算出它们各自的 Q、K、V，再做注意力。这意味着：

  • 第 1 个 token 的 K、V 被重复算了 t 次；
  • 第 2 个 token 的 K、V 被重复算了 t−1 次；
  • ……合计的计算量是 O(t2) 量级。

生成 1000 个 token，就要算约 50 万次"单个 token 的注意力前向"，其中绝大多数是纯粹重复。

3. 有 KV Cache 时：只算新 token#

KV Cache 的做法很直接：把已经算好的历史 token 的 K 和 V 显式存下来。生成第 t+1 个 token 时：

  1. 只对新 token 算它的 Q、K、V；
  2. 从缓存里取出历史所有 K、V，与新的 K、V 拼接；
  3. 用新 token 的 Q 与拼接后的 K 做点积、再与拼接后的 V 做加权和。

于是每一步的计算量从 O(t) 降到 O(1)（只算一个新 token），整体生成的计算量从 O(t2) 降到 O(t)。这是让 decode 阶段可行、可控的根本原因。

4. 代价：显存#

天下没有免费的午餐。KV Cache 省了计算，却要付出显存——因为要把每一层、每一个 token 的 K 和 V 都存着，而且每个请求都有一份独立的缓存。显存会被 KV Cache 大量占用，甚至成为"能同时服务多少请求"的瓶颈。下一课我们就来精确算这笔显存账。

二、可运行示例#

下面的 Python 量化对比"无缓存"与"有缓存"两种策略的累计计算量，直观感受 O(t2) 与 O(t) 的差距。

# -*- coding: utf-8 -*-
# 对比无 KV Cache 与有 KV Cache 的累计计算量

def cost_no_cache(t):
    """无缓存：第 i 步重算 i 个 token，累计 ~ t*(t+1)/2（O(t^2)）。"""
    return sum(i for i in range(1, t + 1))

def cost_with_cache(t):
    """有缓存：每步只算 1 个新 token，累计 t（O(t)）。"""
    return t

for t in [100, 500, 1000, 2000]:
    no = cost_no_cache(t)
    yes = cost_with_cache(t)
    print(f"生成 {t:>5} token：无缓存累计计算 {no:>10} 次 | 有缓存 {yes:>5} 次 | "
          f"省 {no - yes:>10} 次（无缓存是有缓存的 {no/yes:6.0f} 倍）")

运行后你会看到，生成 2000 个 token 时，无缓存要做约 200 万次"单 token 前向"，而有缓存只需 2000 次——差了一千倍。这就是 KV Cache 的价值，也是所有推理引擎都把它当作一等公民来管理的原因。

三、练习#

  1. 手算验证：用手算填一个表——生成 4 个 token 时，无缓存每一步分别算几个 token？累计是多少？对照代码结果。
  2. 改公式：把 cost_with_cache 改成"每步仍要算全部历史但用缓存省掉一半计算"（即 t*0.5），观察曲线形状，理解"只要还在重复算历史，就逃不掉平方项"。
  3. 扩展思考：KV Cache 存的是 K 和 V，那 Q 为什么不缓存？（提示：每一步的 Q 只属于"当前要生成的新 token"，用过一次就没用了。）
  4. 联系显存：如果每个 token 的 KV 要占几 MB 显存（下一课会算），一个长请求的 KV Cache 可能吃掉多少显存？先直觉估一下，再带着这个数字进入下一课。
