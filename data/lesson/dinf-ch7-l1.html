这套账的边界：模型假设在什么条件下失效，以及"何时必须重算"的判据#

这一节要解决什么#

前六章给出的是一台可以自己算的机器：给模型、硬件、负载、SLO、预算，它输出并行度、副本数、缓存决策、成本与上线顺序。第 6 章第 4 节甚至连"优化按什么顺序做"都算成了清单。

但这份账本有一件事从未被检验：它的自变量是可以随便取的吗？

第 1 章：α-β 模型假定通信是"固定延迟 + 线性带宽"
第 2 章：连续批处理假定"每步耗时 = 常数 + 很小的 ∝ b 项"
第 3 章：拓扑模型假定"同步算法的耗时由 max_i T_i 决定"
第 4 章：容量模型假定"故障与过载是分布 + 不动点 + 相变"
第 5 章：可观测性假定"分位可以从样本里估出来"（n ≳ 10/(1−p)）
第 6 章：账本假定"请求长度分布是单峰的、模型是稠密的、prefill 线性于 L"

这些假设大多数时候是对的，少数时候错得离谱 —— 而错的时候通常不是"数字偏了 10%"，而是结论翻转：

"加 batch 是免费的"      → 长上下文 K V 读把带宽吃满，加 batch 直接变慢
"算力越大越好"            → 在带宽区，算力提升只改变延迟，不改变吞吐
"稀疏/MoE 省算力省钱"     → 容量因子 + 统计波动两笔税，decode 侧只剩 24%
"端侧做 prefill 更省云"   → KV 上行是 128 KiB/token，比 prompt 大 3 万倍
"这套账要每月重算"        → 其实硬件参数很鲁棒，需求画像变 2% 就该重算

本节把"什么时候这套账还能用、什么时候必须重算"变成可算的判据。它给四样东西：

2.1 为什么"弹性"必须和"翻转距离"分开用#

这是本节最容易被忽略、也最容易出错的一点。看两个事实（本节的程序会算出它们）：

① 成本对输入几乎"不敏感"：S_月成本 ≡ 0
      —— 因为成本是 N* 的阶梯函数，N* 不变时成本一格都不动
② 但 N* 有一个明确的翻转点：λ 涨 44% 就翻

弹性的问题在于它是局部量。当某个约束接近被撞上时，函数是分段的两条直线，一阶导数在折点左侧完全测不到折点的存在：

对 λ:SC1​​≈−0.004 ⇒ 外推预算 −526%,真实翻转点 +44% ⇒ 错 12 倍

而如果把弹性换成"即将接班的那条约束"的弹性，误差立刻降到 16%：

用哪条约束的弹性 弹性 外推预算 真值 误差
C1​ 吞吐（当前 binding） −0.0035 −526% +44% 12×
C3​ prefill（扫描发现会先翻） −1.0000 −36.8% +44% 16%

判据：弹性用来排序，翻转距离用来定阈值；而"该用哪条约束的弹性"要先扫描确定​

这条推论改变了判断力的定义：不是"盯着当前最紧的那个量"，而是提前判断"谁接班"。第 3 节到第 8 节就是把六类边界各自的"接班人"算出来。

  • 要 6.1 倍（B 涨 6.1 倍，或算力降 6.1 倍）才换 binding。所以"算力不够"在本工作点不是主约束 —— 反过来，买更快的卡对吞吐几乎无用（弹性 Sthr​(C)=−0.014，见程序第 (2) 段）。
  • 一个反直觉的负号：Sthr​(C)<0。原因不是噪声，而是需求受限区的耦合：算力变强 → prefill 变快 → 稳态 b 变小 → 摊销变差 → 单卡吞吐略降。在 b 由需求决定的区间，吞吐与延迟是对立的。
  • 边界之外：B 涨到 16 倍时 binding 换成算力，此时 tstep​ 的斜率结构变了，第 2 章"加 batch 免费"的结论才第一次真正成立。

四、边界二：稀疏化与新硬件 —— 只在算力 binding 时才兑现#

4.1 为什么"稀疏省一半算力"在这里等于 0#

tstep​ 是一个 max：

tstep​(b)=访存 vs 算力max(cw​+bckv​, NC⋅sp​2Pb​)​​+comm+T0​

稀疏只改第二项（sp​ 是有效加速比）。程序算出的表：

sparse 1× → 16×：算力项 0.572 → 0.036 ms，访存项恒为 4.138 ms
t_step 恒为 7.143 ms，吞吐恒为 6,792 tok/s（相对 = 1.000）

算力项/访存项=0.138 ⇒ 算力侧要加速 7.23× 才追平；追平后 max 不变，收益仍为 0​

这是本节最重要的"边界"之一：稀疏化的收益完全取决于它落在哪个约束里。它在算力区是纯收益，在带宽区是纯浪费 —— 而本工作点在带宽区。

读法：σ 减半时 bkv​ 翻倍（容量侧放松）而 bridge​ 减半（算力侧变紧）—— 两个方向相反。所以"换低精度"在哪一侧兑现，要先看当前 binding 的是带宽还是容量：

若 binding=C2​ (KV 容量) ⇒ 降精度直接省卡;若 binding=C1​ (带宽/吞吐) ⇒ 降精度只降延迟，不省卡

若 binding=C2​ (KV 容量) ⇒ 降精度直接省卡;若 binding=C1​ (带宽/吞吐) ⇒ 降精度只降延迟，不省卡

本例（b/bkv​=0.63，binding 是 C1​）正好是第二种：三档精度的月成本完全相同（5,832 元）。这与第 6 章 §3.3 的"S2/S3 的 ΔC=0"是同一件事的另一种说法。

class Svc:
    """与第 6 章第 4 节同一份模型，只是把常数参数化以便做扰动。"""

    def __init__(self, **over):
        d = dict(BASE)
        d.update(over)
        self.__dict__.update(d)
        self.kv_1 = 2 * self.layers * self.kv_heads * self.head_dim * self.wbytes
        self.w_gpu = self.P * self.wbytes / self.wq
        self.w_tot = self.P * self.wbytes
        self.kv_budget = self.vgpu - self.w_gpu - self.act
        self.seq_max = self.lp99 + self.pout
        self.b_kv = self.kv_budget / (self.seq_max * self.kv_1 * self.kv_scale)
        self.r_pref = self.tp * self.peak * self.mfu / (2 * self.P)
        self.Lkv = self.lp50 + self.pout / 2
        self.c_w = self.w_gpu / (self.bw * self.bw_eff) * 1e3
        self.c_kv = self.Lkv * self.kv_1 * self.kv_scale / (self.tp * self.bw * self.bw_eff) * 1e3
        self.thr_req = self.lam * self.pout
        self.b_cap = min(self.b_kv, self.qmax)
        self.thr_max = self.b_cap / (self.t_step(self.b_cap) / 1e3)

    # ---- 时间账 ----------------------------------------------------------
    def tp_comm_ms(self, b):
        act = b * self.d_model * self.wbytes / 2
        attn = self.tp * self.seq_max * self.head_dim * self.wbytes / 2
        return 4.0 * (act + attn) / self.nvlink * 1e3

    def t_mem_ms(self, b):
        return self.c_w + b * self.c_kv

    def t_comp_ms(self, b):
        return 2 * self.P * b / (self.tp * self.peak * self.sparse * self.mfu) * 1e3

    def t_step(self, b):
        return max(self.t_mem_ms(b), self.t_comp_ms(b)) + self.tp_comm_ms(b) + self.t0

    def t_prefill(self, L):
        return (2 * self.P * L / (self.tp * self.peak * self.mfu) * 1e3
                + self.tp_comm_ms(self.b_cap) + self.t0)

    @property
    def T_pref(self):
        return self.t_prefill(self.lp99 * (1 - self.h))

    # ---- 解一个 N --------------------------------------------------------
    def solve(self, N):
        lam_r = self.lam / N
        cap = self.b_cap
        s = self.T_pref / 1e3 + self.pout * self.t_step(cap) / 1e3
        for _ in range(800):
            b = min(lam_r * s, cap)
            s_new = self.T_pref / 1e3 + self.pout * self.t_step(b) / 1e3
            if abs(s_new - s) < 1e-13:
                s = s_new
                break
            s = 0.5 * (s + s_new)
        b = min(lam_r * s, cap)
        t = self.t_step(b)
        thr = b / (t / 1e3)
        mu = self.qmax / s
        rho = lam_r / mu
        tq = math.log(50.0) / (mu - lam_r) * 1e3 if rho < 1 else float("inf")
        ttft = tq + self.T_pref
        margin = thr * N / self.thr_req
        pref_m = self.r_pref * N / (self.lam * self.lp99 * (1 - self.h))
        why = []
        if margin < 1.0:
            why.append(f"C1吞吐{margin:.2f}x")
        if lam_r * s > cap + 1e-9:
            why.append("C2显存")
        if t > self.tpot_slo:
            why.append(f"C4TPOT{t:.1f}")
        if ttft > self.ttft_slo:
            why.append(f"C5TTFT{ttft:.0f}")
        if rho >= 1:
            why.append(f"C5rho{rho:.2f}")
        if pref_m < 1:
            why.append(f"C3prefill{pref_m:.2f}x")
        return dict(N=N, gpus=N * self.wq, nodes=math.ceil(N * self.wq / self.node_gpus),
                    b=b, cap=cap, b_kv=self.b_kv, t=t, thr_gpu=thr, thr_tot=thr * N,
                    margin=margin, rho=rho, tq=tq, ttft=ttft, pref_m=pref_m,
                    kv_used=b * self.seq_max * self.kv_1 * self.kv_scale / self.tp,
                    kv_budget=self.kv_budget, ok=not why, why=" ".join(why))

    def best(self, nmax=200):
        for N in range(1, nmax):
            r = self.solve(N)
            if r["ok"]:
                return r
        return None

    def money(self, r, days=30):
        rev_h = r["N"] * self.price
        return dict(month=rev_h * 24 * days,
                    usd_M=rev_h * self.usd / (r["thr_tot"] * 3600) * 1e6)


def Y(thr=3, **over):
    """返回固定 N 下的连续量 + 最优 N。"""
    s = Svc(**over)
    r = s.solve(thr)
    b = s.best()
    m = s.money(r)
    return dict(s=s, r=r, b=b, m=m, Nstar=b["N"] if b else None)

def crossing(f, a, b, iters=90):
    """f 单调；返回 f 由 False 变 True 的横坐标（顺序无关）。"""
    fa, fb = f(a), f(b)
    if fa == fb:
        return None
    if fa:
        a, b = b, a
    for _ in range(iters):
        m = 0.5 * (a + b)
        if f(m):
            b = m
        else:
            a = m
    return 0.5 * (a + b)

五处关键设计决策：

  1. 两个 b∗ 分开算、分开命名：bridge​=σC/(2B) 与 bthr∗​=(cw​+T0​)/ckv​​ 在本例相差 18.6 倍（295.2 vs 15.9）。混用它们会让"该允许 batch 涨到多少"这类结论错一个数量级。
  2. 弹性只算在固定 N∗ 上：N∗ 是离散的，它的弹性是阶跃函数的导数（无意义）。所以程序把"连续量"与"离散量"分开：连续量给弹性，离散量给翻转距离。
  3. 翻转距离用二分扫描而不是解析反解：因为 b 是不动点（b=λs(b)/N，s 里又含 tstep​(b)），且 bcap​ 是 min，整条曲线是分段的。二分是唯一稳的做法。
  4. KV 混合税按"p99 预留 / 均值使用"定义：不是随便挑的数，而是 seqmax​=Lp99​+Pout​ 这个实现约定直接推出来的 —— 换实现就换税。
  5. MoE 的 T 明确取 decode 的 T=b：这是本例最容易被含糊过去的地方。若取 prefill 的 T= prompt 长度，效率会从 30% 立刻升到 80% 以上 —— 同一个模型在两个阶段的边界完全不同。

小结#

  • 账本有七条隐含前提（单峰长度、稠密、带宽区、通信可忽略、KV 常数、prefill 线性、策略固定）。"边界"就是其中某一条的失效，判据是"哪一行被违反、违反了多远"。
  • 失效分三类：硬失效（余量 < 1）、软失效（数值偏 >5%）、结构失效（公式形式不成立）。三类判据完全不同，不能用同一套阈值。
  • 最紧的余量决定一切：本例吞吐裕度只有 1.019×（+1.86%），任何让单卡吞吐降 1.86% 的变化都把 N∗ 从 3 推到 4（+1,944 元/月）。
  • 两个 b∗ 不是一个量：bridge​=σC/(2B)=295.2 是"加 batch 不再免费"的点；bthr∗​=(cw​+T0​)/ckv​​=15.9 是单卡吞吐峰；bcap​=min(bkv​,qmax​)=77 是容量帽。工作点 b=48.51 由需求决定，不是可选的。
  • 稀疏/MoE 在带宽区是零收益：算力项/访存项 = 0.138，加速 16 倍吞吐仍恒为 6,792 tok/s；MoE 还要再付 1/C 与 E[maxe​Le​] 两笔税（C=1.25、T=48.5 时只剩 24.1%）。
  • 混合负载吃的是 KV 容量而不是步长：混合税 1.816×（双峰 1.864×），而步长抖动只 1.64%（按 cv​/b​ 衰减，b≥5.2 即满足 5% 预算）。分池只省 10.6% 显存 —— 它买的是隔离，不是显存。
  • 多模态用等效 token：κ=1+(ΔFenc​/n)/(2P)；判据是 (κ−1)n>5%Lp99​。1 张图 42.9（不必重算），10 张图 428.6（必须重算）。
  • 超长上下文的第一约束不是注意力：s∗=42,725（GQA）是公式换形式的地方，但 ckv​∝E[L] 早就把舰队推到了几十个副本（32k 上下文 → N∗=50、100 卡、97,200 元/月）。
  • 精度不改变结构：σ 同时改 cw​、ckv​、bkv​；本例 b/bkv​=0.63（C1​ binding），所以三档精度月成本完全相同 —— 降精度省卡的前提是容量 binding。
  • 弹性只能排序，不能定阈值：12 个输入里 5 个弹性≈0 却在 ±55% 内翻结论。要用"即将接班的那条约束"的弹性估阈值（λ 的例子：用 C1​ 估错 12 倍，用 C3​ 估只错 16%）。
  • 一句话：这套账的边界不是"模型对不对"，而是"哪条约束还剩多少余量、下一个接班的会是谁"；把所有结论与它们的输入绑定写下来，把"要不要重算"变成一次 5 步的增量计算，这套账就能一直用下去 —— 而它失效的那天，你会在余量表上先看到它，而不是在账单上。
