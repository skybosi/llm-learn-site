为什么需要注意力#

这一课是整个课程的出发点。我们已经会用 LSTM/GRU 搭序列到序列（seq2seq）模型，但它有一个绕不开的硬伤：编码器必须把整条输入压缩成一个固定长度的向量。输入越长，这个"瓶子口"越窄，信息丢得越多。注意力机制正是为打通这个瓶颈而生——它让解码器在生成的每一步，都能回头从整条输入里挑出当前最需要的部分。我们先看清问题，再理解注意力是如何解决的。

一、概念讲解#

1. seq2seq 的"固定长度瓶颈"#

回忆上一课的综合项目：编码器把整条输入读完后，只把最后一个时间步的隐藏状态交给解码器。这意味着无论输入是 4 个字母还是一整段文章，能被传递的信息都只有一个向量那么大。两个问题随之而来：

  • 长句丢信息：句首的词经过几十上百个时间步，早已被"冲淡"，最后的状态记不住开头；
  • 生成时"抓瞎"：解码器每生成一个词，只能依靠同一个压缩向量，无法区分"这个位置该看原句的哪一部分"。

打个比方：翻译一句很长的德语时，模型就像只能看一眼"整句摘要"再动笔，而不是能随时回到原文查证某个词——出错在所难免。

2. 人的"选择性注意"给了灵感#

人做翻译时并不把整句平均对待。写到一个名词时，目光会扫回原文，重点落在对应的那个词上，其余部分只是背景。这种"有重点地看，而非全盘平均"的机制，就是注意力。

把它搬到模型里：与其只给解码器一个固定向量，不如保留编码器的全部隐藏状态，然后让解码器每生成一步，都算出一个"该看谁"的权重，用这些权重把隐藏状态加权求和，得到一个针对当前时刻量身定制的上下文向量。不同时刻关注不同位置，长句的信息就不必再挤过一个窄口。

3. 注意力的三要素：Query、Key、Value#

注意力本质上可以抽象成一次"软检索"：

  • Query（查询）：解码器当前想知道什么，比如"我现在要生成的这个词，需要原句里的什么信息"；
  • Key（键）：编码器每个位置对外提供的"标签"，描述"我这里有什么"；
  • Value（值）：编码器每个位置真正承载的内容。

计算时，用 Query 和每个 Key 比对相关程度（打分），把打分归一化成权重，再用这些权重对 Value 加权求和。Query 和某个 Key 越相关，对应 Value 在结果里占的比重就越大。这三件套是后面所有注意力变体的共同骨架。

4. 这一章要学什么#

我们把注意力拆成三步，正好对应本章三课：

  1. 为什么需要注意力（本课）：看清瓶颈，理解"软检索"的直觉；
  2. 注意力打分：Query 和 Key 怎么"比对相关程度"；
  3. 注意力权重：打分怎么变成权重，又怎么加权求和成上下文。

先把直觉立住，数学和代码在后面两课逐步精确化。

二、可运行代码示例#

下面用一段最朴素的代码，直观对比"旧做法"和"注意力做法"。我们假设编码器对一条 5 个词的输入，产出了 5 个隐藏状态（这里用随机向量模拟），解码器手上有一个查询向量 query。

import torch
import torch.nn.functional as F

torch.manual_seed(0)

# 模拟编码器输出：5 个时间步的隐藏状态，每个是 4 维向量
# 真实模型里这些向量来自 RNN 每个时间步的输出，这里用随机数代替
hidden_states = torch.randn(5, 4)   # (时间步, 维度)
query = torch.randn(4)              # 解码器当前"想找信息"的查询向量

# 1) 旧做法：把整句压成"最后一个时间步"的固定向量
old_context = hidden_states[-1]
print("旧做法 context（只用了最后一个向量）:", old_context)

# 2) 注意力思路：先算 query 与每个时间步的相关性（用点积当最朴素的打分）
scores = hidden_states @ query          # (5,)
print("相关打分 scores =", scores)

# 3) 把打分归一化成权重，再对 hidden_states 加权求和，得到"能回头看"的 context
weights = F.softmax(scores, dim=0)      # 每个时间步被"关注"的比例
context = (weights.unsqueeze(1) * hidden_states).sum(dim=0)
print("注意力 context =", context)

# 看看注意力把重心放在了哪一步
print("注意力权重 =", weights)
print("权重之和 =", weights.sum().item())   # 应为 1.0

运行后注意对比两点：

  • 旧做法的 context 就是 hidden_states 的第 5 行，前面 4 行完全没参与；
  • 注意力做法的 context 是所有 5 行按权重混合的结果，weights 告诉我们在当前查询下"哪一步更值得看"。

这就是注意力的全部直觉：不丢弃任何输入，但给不同位置不同的分量。它没有把信息硬塞进一个固定向量，而是按需取用。

三、练习#

  1. 把 hidden_states 的行数从 5 改成 50，重新运行。观察"旧做法"丢掉了多少信息（只保留最后一行），而注意力仍能覆盖全部 50 行，体会瓶颈随长度加剧的问题。
  2. 换一个 query（比如改成 hidden_states[2] 本身，模拟"想找第 3 个词"），观察 weights 的最大值是否落到了对应位置，理解"查询决定关注点"。
  3. 把打分函数从点积换成"负的欧氏距离"（-((hidden_states - query) ** 2).sum(dim=1)），观察权重分布的变化，思考不同打分方式对"谁更相关"的定义有何不同。
  4. 思考：如果不做 softmax、直接用原始 scores 当权重去加权求和，会出现什么问题？（提示：权重会为负、之和也不等于 1，难以解释成"注意力比例"。）

为什么这样做？——理论推导#

前面把注意力描述成"软检索"，这一节用数学把每一步的合理性推出来。注意力的最终形式你已经见过：

Attention(Q,K,V)=softmax(dk​​QK⊤​)V

我们从直觉出发，推导它为什么"非长成这样不可"。

第一步：注意力就是加权平均#

注意力的目标，是让"当前位置的输出"从所有位置的 V 里按需取用。最自然的取法是一个凸组合——给每个位置一个非负、且总和为 1 的权重：

outputi​=j∑​αij​vj​,αij​≥0,  j∑​αij​=1

为什么必须"非负且和为 1"？因为我们要把 αij​ 解释成"第 i 个查询对第 j 个位置的关注比例"：负权重没有物理意义，和不为 1 则无法比较不同查询之间的关注分布。这一条约束，直接决定了后面 softmax 的出现。

第二步：用点积衡量相似度#

权重 αij​ 应当反映"查询 qi​ 与键 kj​ 有多相关"。两个向量"相关"最朴素的度量，就是内积：

sij​=qi⊤​kj​=∥qi​∥∥kj​∥cosθ

它等于"两向量长度之积 × 夹角余弦"：方向越一致、模长越大，得分越高。相比欧氏距离，点积可以一次性并行算出整个打分矩阵 S=QK⊤，这正是它能被 Transformer 大规模采用的计算原因。

第三步：用 softmax 把打分变成权重#

打分 sij​ 可正可负、没有上下界，不能直接当权重。softmax 把它"规整"成合法权重：

αij​=∑j′​esij′​esij​​

这里有三处讲究：

  1. 指数保证非负：esij​>0 恒成立，权重不再为负；
  2. 分母保证和为 1：∑j​αij​=1，得到真正的概率分布；
  3. 指数放大差异：softmax 是"可微的 argmax"，打分最大的项被指数放大、近似独热，但梯度仍然连续、处处可导——既保留了"挑出最相关的那个"，又不丢失反向传播能力。

第四步：除以 dk​​ 防梯度消失#

最后一个细节：为什么要除 dk​​？假设 q、k 的每个分量近似独立、均值为 0、方差为 1，那么点积的方差会随维度线性增长：

Var(qi⊤​kj​)=m=1∑dk​​Var(qi,m​kj,m​)=dk​

dk​ 越大，sij​ 的绝对值越"发散"。当打分幅度很大时，softmax 会饱和到近似 one-hot——而 softmax 在饱和区的梯度几乎为零，训练时梯度就消失了。除以 dk​​ 把打分方差拉回 1 量级：

Var(dk​​qi⊤​kj​​)=1

于是打分始终落在 softmax 梯度"不饱和"的区间，训练才稳定。这也是 Transformer 论文里"点积注意力在 dk​ 大时会失效，缩放点积注意力可以修复"这句话的数学来源。

母原理连接：注意力是"加权平均"这一母原理的具体实例——给不同来源分配非负且和为 1 的权重，再凸组合。它和卷积（固定权重的局部加权平均）、全连接（可学习权重的加权平均）、集成学习的加权投票同源；注意力的独特之处在于权重是数据相关的（由 q、k 当场算出），这是它比固定权重更强大、更灵活的根源。
