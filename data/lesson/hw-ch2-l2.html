Tensor Core#

上一课我们算出的 67 TFLOPS，只是 H100 的 FP32 标量算力。可 H100 标称的 FP16 算力高达 989 TFLOPS——多出来的这部分从哪来？答案是 Tensor Core：一块专为矩阵乘设计的硬件，它才是现代 GPU 跑深度学习的真正引擎。

一、概念讲解#

1. Tensor Core 是什么#

Tensor Core 是一个矩阵乘加单元，一条指令就能完成一个小块的矩阵运算：

D=A×B+C

其中 A、B、C、D 都是小矩阵片段（fragment）。它把"取数、乘法、累加"这些步骤固化进电路，用一条指令替换掉 CUDA Core 需要几十条指令才能完成的循环。2017 年 NVIDIA 在 Volta 架构首次引入 Tensor Core，之后每一代都在升级。

2. 混合精度：低精度输入，高精度累加#

Tensor Core 的精髓是混合精度：矩阵乘的输入 A、B 用低精度（FP16、BF16、TF32、INT8、INT4、FP8），但累加在 FP32 里进行。这样既享受低精度带来的速度与省显存，又用 FP32 累加兜住了累加过程中的精度损失——深度学习对"中间累加"的精度远比"单个输入"敏感。

3. 为什么它快这么多#

一个 4 代 Tensor Core 每时钟能算一个小矩阵乘，一个 SM 里有 4 个 Tensor Core，再乘上 132 个 SM 和高时钟，累加出巨大的吞吐。对比 H100：

精度 算力（H100 SXM，dense）
FP32（CUDA Core 标量） 67 TFLOPS
TF32（Tensor Core） 495 TFLOPS
FP16 / BF16（Tensor Core） 989 TFLOPS
FP8（Tensor Core） 1979 TFLOPS
INT8（Tensor Core） 1979 TOPS

从 67 到 989，约 15 倍的提升，全来自"用专用硬件算矩阵乘 + 用低精度输入"。

4. 精度支持的演进#

Tensor Core 支持的精度随架构代际快速扩展，这直接决定了"新卡能用什么精度跑得更快"：

  • Volta（2017）：FP16；
  • Ampere（2020）：新增 TF32、BF16、INT8、INT4，并支持 2:4 结构化稀疏（算力再 ×2）；
  • Hopper（2022）：新增 FP8（E4M3 / E5M2）；
  • Blackwell（2024）：进一步支持 FP4。

你会发现一个趋势：支持的精度越来越低，算力越来越高——这正是"推理越来越依赖低精度量化"的硬件基础。

5. 上层如何"用到"Tensor Core#

你几乎不用手动写 Tensor Core 指令。PyTorch 的 matmul、cuBLAS、cuDNN、CUTLASS 在底层会自动把符合条件的矩阵乘映射到 Tensor Core 上。作为使用者，你要做的是：让数据用对精度、让维度对齐到合适的块大小，剩下的交给库。

二、可运行代码示例#

算一算 Tensor Core 的吞吐差异，并理解"一条 mma 指令"背后的 FLOPs。

# ---- 例 1：对比 CUDA Core 与 Tensor Core 的算力差距 ----
h100_fp32 = 67.0      # FP32 CUDA Core，TFLOPS
h100_fp16 = 989.0     # FP16 Tensor Core，TFLOPS
print(f"H100 上 Tensor Core(FP16) 是 CUDA Core(FP32) 的 {h100_fp16/h100_fp32:.0f} 倍")

# ---- 例 2：一条 mma（矩阵乘加）指令做了多少 FLOPs ----
def mma_flops(m, n, k):
    # D[m,n] = A[m,k] @ B[k,n] + C[m,n]，乘加 = 2*m*n*k 次浮点运算
    return 2 * m * n * k

# 常见 mma 形状之一 m16n8k16
print(f"m16n8k16 一条 mma = {mma_flops(16, 8, 16)} FLOPs")

# ---- 例 3：算力为什么随"低精度"翻倍 ----
# 同一块硬件，位宽减半 -> 每时钟能打包的数据翻倍 -> 吞吐翻倍
precisions = {"FP16/BF16": 989.0, "FP8": 1979.0, "INT8": 1979.0}
base = precisions["FP16/BF16"]
for name, tflops in precisions.items():
    print(f"H100 {name}: {tflops:.0f} TFLOPS/TOPS（相对 FP16 的 {tflops/base:.0f}x）")

# ---- 例 4：结构化稀疏(2:4)让算力再翻倍 ----
dense = 989.0
sparse = 1979.0
print(f"H100 FP16 dense={dense} TFLOPS -> 2:4 稀疏={sparse} TFLOPS（×{sparse/dense:.0f}）")

# ---- 例 5：用 Tensor Core 跑矩阵乘，大约要多久 ----
def matmul_time(m, n, k, tflops):
    flops = mma_flops(m, n, k)
    return flops / (tflops * 1e12)

m = n = k = 4096
t_fp32 = matmul_time(m, n, k, h100_fp32)
t_fp16 = matmul_time(m, n, k, h100_fp16)
print(f"\n4096^3 的 GEMM：CUDA Core(FP32) ≈ {t_fp32*1e3:.2f} ms，Tensor Core(FP16) ≈ {t_fp16*1e3:.3f} ms")

要点：例 2 是理解 Tensor Core 的关键——一条指令就完成 4096 次浮点运算，配合例 3 的"位宽减半、吞吐翻倍"，你就明白为什么 H100 的 FP8 算力能到 1979 TFLOPS。例 5 是纯算力理想值，真实运行还要受带宽限制（第 4 章会补上这块短板）。

三、练习#

  1. 计算：一条 mma 的形状是 m16n8k8，它一次完成多少 FLOPs？如果 Tensor Core 每时钟能发一条这样的指令、频率 1.98 GHz，单 SM 上 4 个 Tensor Core 的 FP16 算力是多少 TFLOPS？（提示：先算单 Core 再乘 4，再乘 132 SM 对照 989。）
  2. 对比：用代码里的 matmul_time，算 81923 的 GEMM 在 FP16 和 FP8 下各要多长时间。
  3. 解释：为什么 Tensor Core 用"FP16 输入 + FP32 累加"而不是全程 FP32？它牺牲了什么、换来了什么？
  4. 思考：2:4 结构化稀疏要求"每 4 个元素里最多 2 个非零"。这种稀疏是训练中自然出现的，还是需要专门剪枝？它对"推理加速"意味着什么？
