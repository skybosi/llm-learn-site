指令微调#

预训练得到的基座模型只会"续写"，不会"照做"。你输入 把下面这句话翻译成英文：今天天气很好，它不会翻译，而是接着往下编。指令微调（instruction tuning / 监督微调 SFT）就是第二阶段：用大量"指令—回答"成对数据继续训练，让模型学会遵循指令。本课讲清它的动机、数据格式、损失怎么算，以及它为什么能带来零样本泛化。

一、概念讲解#

1. 为什么基座模型"不听话"#

基座模型只优化过一个目标：预测下一个 token。它的世界观是"把文本接下去"，而不是"理解并执行你的意图"。你给它一句问句，它给出的"续写"可能是一模一样的问题、一串无关的文字，甚至反问一句。想让模型把"问题"当成任务、把"回答"当成目标，就需要一种新的训练信号——人写的标准答案。

2. 指令微调在做什么#

指令微调（instruction tuning）把每一条训练样本组织成 （指令，理想回答） 的形式，例如：

  • 指令：把下面的句子翻译成英文：今天天气很好
  • 回答：The weather is nice today.

然后用和预训练完全相同的下一 token 目标继续训练，区别只在数据形态：模型要学着在"看到指令之后"生成"理想回答"。这个阶段也叫监督微调（supervised fine-tuning, SFT），因为监督信号就是人工（或模型）给出的标准回答。

3. 数据格式与"只算回答的损失"#

一条指令样本通常被拼成如下结构（示意）：

<指令>把下面句子翻译成英文：今天天气很好</指令>
<回答>The weather is nice today.</回答>

训练时有个关键细节：损失只在"回答"部分的 token 上计算，指令部分的 token 不参与损失。理由很直接——指令是"输入条件"，不是模型要学的输出；如果连指令部分也要求模型逐字复现，会让模型浪费容量去"背题目"。工程上通过 label 掩码实现：把指令位置的标签设为 -100，交叉熵会自动忽略这些位置。

4. 指令数据从哪来#

  • 人工标注：InstructGPT 的 SFT 阶段只用了约 1.3 万条人工撰写的（指令，回答）对——量不大，但质量高。
  • 模型生成（self-instruct）：让一个较强的模型按"种子指令"批量生成新指令和答案，再筛选。这样能以低成本把指令多样性快速扩起来。

5. 为什么指令微调能带来"零样本泛化"#

研究发现（FLAN 等）：一旦在足够多样的指令上微调过，模型面对从没见过的任务指令，也能较好地执行。这是因为指令微调让模型学会了"把任意指令当作任务描述、按要求作答"这个通用模式，而不是只记住某几道题。换言之，它学的是"听指令"这个行为，而非具体的题目。

二、可运行示例#

下面用一段真实可跑的代码演示两件事：① 如何把（指令，回答）渲染成 chat 格式；② 如何用 label 掩码让损失只落在回答部分。

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# —— 极简词表：为演示，手动给几个关键 token 编号 ——
tokens = ["<s>", "指令:", "回答:", "</s>", "翻译", "今天", "天气", "The", "weather",
          "is", "nice", "today"]
t2i = {t: i for i, t in enumerate(tokens)}
V = len(tokens)

# —— 一条（指令, 回答）样本，渲染成序列 ——
instruction = ["<s>", "指令:", "翻译", "今天", "天气"]          # 指令部分
response    = ["回答:", "The", "weather", "is", "nice", "today", "</s>"]  # 回答部分
full_seq    = [t2i[t] for t in instruction + response]
labels      = [-100] * len(instruction) + [t2i[t] for t in response]  # 指令位置掩码掉

print("输入序列 id :", full_seq)
print("label 序列   :", labels, "（-100 表示该位置不参与损失）")

# —— 模拟模型输出 logits：真实 token 给高分，其余给低分 ——
logits = torch.zeros(1, len(full_seq), V) - 2.0        # 初始都给低分
for pos, tok_id in enumerate(full_seq):
    logits[0, pos, tok_id] = 5.0                        # 正确 token 给高分

# —— 两种损失对比 ——
loss_all = F.cross_entropy(logits.view(-1, V),
                           torch.tensor(full_seq))                     # 全序列都算
loss_resp = F.cross_entropy(logits.view(-1, V),
                            torch.tensor(labels),
                            ignore_index=-100)                          # 只在回答部分算

print(f"整个序列都算损失：{loss_all.item():.4f}")
print(f"只在回答部分算损失：{loss_resp.item():.4f}")

关键在最后两行：labels 里指令位置被设成 -100，ignore_index=-100 让交叉熵自动跳过这些位置。两种损失的数值不同，反映的是"模型被要求学习的内容范围"不同——指令微调只要求模型学会在指令之后给出正确回答。

三、练习#

  1. 改写损失：把示例中的 response 人为改错一个 token（如把 today 换成 weather），观察 loss_resp 如何变化；再把指令部分改错，确认它不会影响 loss_resp。
  2. 设计指令对：为以下任务各写一条（指令，回答）样本——① 情感分类 ② 摘要 ③ 扩写。体会"指令要具体、回答要可作为监督信号"。
  3. 思考数据量：InstructGPT 的 SFT 仅约 1.3 万条人工样本，相比预训练的万亿 token 微不足道，为什么却能让模型行为发生质的改变？
  4. 思考泛化：为什么在"多样指令"上微调，比在"单一任务"上微调更能提升对新指令的零样本表现？这和"过拟合到某个任务"有何区别？
  5. 思考边界：指令微调能让模型"听话"，但它能让模型"诚实""无害"吗？举一个"会执行但不该执行"的指令例子。
