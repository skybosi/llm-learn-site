ViT 架构#

你已经完整学过目标检测与分割：Faster R-CNN、Mask R-CNN 这类模型都有一个共同的地基——卷积神经网络（CNN）。卷积用共享的小窗口在整张图上滑动，逐层把局部特征堆叠成高层语义，这套范式统治了计算机视觉很多年。而 Vision Transformer（ViT）走的是一条截然不同的路：它把图像切成一块块小"补丁"（patch），把它们当作"词"丢进一个几乎原封不动的 Transformer 编码器。这一课我们要拆开 ViT，看清它到底长什么样、每一块零件在干什么。理解清楚这套"图像当句子"的构造，是后面讲"为什么它有效"和"Swin 这类分层改进"的基础。

一、概念讲解#

1. 一个大胆的迁移：图像 → token 序列#

Transformer 在 NLP 里处理的是"一串离散的 token"。图像不是离散的，它是一张二维的连续像素网格。ViT 要做的第一件事，就是把这张网格改造成 Transformer 能吃的序列。它的做法是"切块"：把一张图切成不重叠的正方形补丁（原论文里是 16 × 16 像素），每个补丁展平成一个一维向量，再用一个线性层映射到固定维度 D。这样一个补丁就变成了一个"图像词"（patch embedding），整张图就变成了一串"词向量"。

以 224 × 224 的输入为例：切成 16 × 16 的补丁后，长宽各得到 224 / 16 = 14 个格子，一共 14 × 14 = 196 个补丁。所以一句话有 196 个 token，每个 token 是 D 维向量。这个"切块 + 线性投影"的步骤就是 ViT 里唯一和卷积"亲缘"接近的地方——线性投影其实等价于一个步长等于补丁大小的卷积核。

2. [CLS] token 与位置编码#

Transformer 编码器输出的是一串向量，而我们最终只要一个分类结果。ViT 借鉴了 BERT 的做法：在序列最前面额外加一个可学习的 [CLS] token，让它在整个编码器里和其他 token 一起交互，最后只把这个 token 的输出交给分类头。这样模型自己学会了"把全局信息汇总到这个特殊 token 上"。

位置编码同样必不可少。上一章你已经知道，自注意力是置换等变的——它分不清"第一个补丁"和"第五个补丁"。图像的空间结构（左上角是天空、右下角是地面）恰恰高度依赖位置，所以 ViT 给每个补丁加一个可学习的 1D 位置编码。注意这里是"1D"：196 个补丁只是按行展开成一维序号 0, 1, 2, ...，并没有用二维坐标 (row, col)。模型要自己从这些序号里"悟"出二维排布规律。

3. 编码器：和 BERT 几乎一样#

切好补丁、加好位置之后，剩下的就是一个标准的 Transformer 编码器堆栈：多头自注意力（MSA）→ 前馈网络（MLP），每层前后都有 LayerNorm 和残差连接。ViT 对 BERT 做的改动很小：LayerNorm 放在注意力/MLP 之前而不是之后（Pre-LN），这能让深层网络训练更稳定。前馈网络是一个两层 MLP，中间用 GELU 激活。

之所以强调"几乎原封不动"，是因为这一点直接引出本课的主题——ViT 的精髓不在发明新算子，而在于把已有的 Transformer 原样搬到视觉上，然后靠规模和预训练把性能推上去。

4. 分类头与整体数据流#

把整个流程串起来，一张图经过 ViT 的完整路径是：

图像 (3, 224, 224)
  → 切成 196 个 16×16 补丁，展平 → (196, 768)
  → 线性投影到 D 维 → (196, D)
  → 前面拼上 [CLS] → (197, D)
  → 加上可学习位置编码 → (197, D)
  → L 层 Transformer 编码器 → (197, D)
  → 取 [CLS] 输出 → (D,)
  → MLP 分类头 → logits

5. 两个必须知道的工程细节#

  • 分辨率固定：ViT 在预训练时用的是 224 × 224，位置编码也是按 196 个位置学的。推理时换分辨率，补丁数量会变，位置编码就对不上了，需要插值缩放位置编码——这是一个经典坑，第 3 课讲 Swin 时会看到它如何绕开这个问题。
  • 参数量与计算量：自注意力的复杂度是序列长度 N 的平方。N=197 时还可接受，但如果补丁切得更细（比如 8 × 8，N 变成 28 × 28 ≈ 785），代价就迅速上升。这是 ViT 在高分辨率任务上的先天短板，也是分层架构（第 3 课）要解决的核心矛盾。

二、可运行代码示例#

下面用一个精简实现把 ViT 跑通：先做补丁嵌入，再过两层 Transformer 编码器，最后用 [CLS] 输出做分类。代码刻意只保留主干，注释标出了每个张量的形状。

import math
import torch
import torch.nn as nn

torch.manual_seed(0)


class PatchEmbed(nn.Module):
    """把图像切成补丁并线性投影成 token，等价于一个步长=补丁大小的卷积。"""
    def __init__(self, img_size=224, patch_size=16, in_chans=3, dim=768):
        super().__init__()
        self.num_patches = (img_size // patch_size) ** 2
        # 用卷积实现"切块 + 投影"：输出通道数 = 补丁数 * D
        self.proj = nn.Conv2d(in_chans, dim, kernel_size=patch_size, stride=patch_size)

    def forward(self, x):
        # x: (B, 3, 224, 224)
        x = self.proj(x)                     # (B, D, 14, 14)
        x = x.flatten(2)                     # (B, D, 196)
        x = x.transpose(1, 2)                # (B, 196, D) —— 变成"序列"
        return x


class ViT(nn.Module):
    def __init__(self, img_size=224, patch_size=16, dim=768, depth=2,
                 heads=12, mlp_ratio=4.0, num_classes=1000):
        super().__init__()
        num_patches = (img_size // patch_size) ** 2

        self.patch_embed = PatchEmbed(img_size, patch_size, 3, dim)
        self.cls_token = nn.Parameter(torch.zeros(1, 1, dim))          # [CLS]
        self.pos_embed = nn.Parameter(torch.zeros(1, num_patches + 1, dim))  # 可学习位置编码

        # 用 PyTorch 自带的 TransformerEncoder 搭 L 层
        layer = nn.TransformerEncoderLayer(
            d_model=dim, nhead=heads, dim_feedforward=int(dim * mlp_ratio),
            activation="gelu", batch_first=True, norm_first=True,  # norm_first=True 即 Pre-LN
        )
        self.encoder = nn.TransformerEncoder(layer, num_layers=depth)

        self.head = nn.Linear(dim, num_classes)

    def forward(self, x):
        B = x.shape[0]
        x = self.patch_embed(x)                          # (B, 196, D)

        cls = self.cls_token.expand(B, -1, -1)           # (B, 1, D)
        x = torch.cat([cls, x], dim=1)                   # (B, 197, D)
        x = x + self.pos_embed                           # 加位置编码

        x = self.encoder(x)                              # (B, 197, D)
        cls_out = x[:, 0]                                # 只取 [CLS] 的输出
        return self.head(cls_out)                        # (B, num_classes)


model = ViT(num_classes=10)
x = torch.randn(2, 3, 224, 224)          # 两张假图
logits = model(x)
print("输出 logits 形状:", logits.shape)  # 应为 (2, 10)

# 打印参数量级，直观感受 ViT 有多大
n_params = sum(p.numel() for p in model.parameters())
print(f"可训练参数量: {n_params / 1e6:.1f} M")

再写一个"最小可运行单元"，单独验证补丁嵌入 + 位置编码这条数据流，方便你打断点观察中间形状：

pe = PatchEmbed()                # 默认 224/16/3/768
out = pe(torch.randn(1, 3, 224, 224))
print("补丁嵌入输出:", out.shape)   # (1, 196, 768)

# 观察位置编码矩阵的形状：197 = 1 个 [CLS] + 196 个补丁
m = ViT(num_classes=10)
print("[CLS] token 形状:", m.cls_token.shape)      # (1, 1, 768)
print("位置编码形状:", m.pos_embed.shape)          # (1, 197, 768)

运行时你会看到：补丁嵌入把 (1, 3, 224, 224) 变成 (1, 196, 768)；位置编码张量有 197 个位置，多出来的那 1 个正是留给 [CLS] 的。这就是 ViT 最核心的"形状契约"，后面所有关于分辨率、计算量的讨论都建立在这串数字上。

三、练习#

  1. 把 patch_size 改成 32 和 8，分别打印 num_patches 和位置编码的形状，解释为什么位置编码长度会跟着变，以及这会给"预训练好的模型换分辨率"带来什么麻烦。
  2. 用 timm 加载一个预训练 ViT（如 timm.create_model("vit_base_patch16_224", pretrained=True)），打印它的 patch_embed.proj 权重形状，验证它等价于"步长 16 的卷积"，并说明为什么不直接叫它"卷积层"。
  3. 思考：[CLS] token 的信息是"凭空"汇聚出来的。如果不用 [CLS]，而是把 196 个补丁的输出全局平均池化后再接分类头，效果会有什么差别？动手把 cls_out = x[:, 0] 改成 x[:, 1:].mean(dim=1) 跑一版，比较两种做法。
  4. ViT 原论文的 Base 模型参数量约为 86M。请依据 dim=768、depth=12、heads=12 估算：绝大部分参数集中在哪个子模块（MSA、MLP 还是补丁嵌入）？带着这个直觉进入下一课关于"注意力到底学到了什么"的讨论。
