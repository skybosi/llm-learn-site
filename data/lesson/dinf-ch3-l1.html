多机拓扑与链路：带宽-延迟层级的算术，与集合通信的量下界#

这一节要解决什么#

前两章里，通信是一个两参数黑盒：α（单次固定延迟）与 β（单向带宽）。第 1 章靠这两个数解出了最优并行度，第 2 章靠它们算出了 Nhide​。这个抽象在一台机器内部是够用的 —— 8 卡 NVLink 全互连，任意两张卡之间的 α、β 基本一样。

一旦跨出机箱，这个抽象立刻失效，原因不是"更慢"，而是不再均匀：

同一份 8 KiB 的 all-reduce，N=8：
  域内（NVLink 岛，α=1 µs、β=450 GB/s） ：14.00 µs + 0.032 µs = 14.03 µs
  跨机（NDR IB，α=2 µs、β=50 GB/s）    ：28.00 µs + 0.287 µs = 28.29 µs
同一份 512 MiB 的 all-reduce，N=8：
  域内                                  ：14.00 µs + 2087.8 µs  = 2.102 ms
  跨机                                  ：28.00 µs + 18790.5 µs = 18.818 ms

注意这两组数的方向是反的。 8 KiB 时跨机只慢 2.02 倍（α 之比），512 MiB 时跨机慢 8.95 倍（β 之比）。所以"跨机比域内慢几倍"这句问句本身是不完整的 —— 必须先说清消息多大。

这一节要给出四样东西：

  1. 一张有量纲的层级表：HBM / NVLink / NVSwitch / PCIe / InfiniBand / RoCE 各自的 β 与 α，以及"带宽跨度 268× / 延迟跨度 63×"这个事实。
  2. 三个不同的下界：AllReduce 的 2NN−1​S、AllGather 的 NN−1​S、AllToAll 的 NN−1​S。它们不是同一个数，混用会让整本通信账错 2 倍。
  3. "消息多小算延迟主宰"的交叉点 S∗=Nαβ。这是第 1 章那句"decode 是纯延迟问题"的定量版本，也是本节最有操作价值的判据。
  4. 拓扑错配的最小模型：一个 N=8P 的"平环"与"分层"对比。两者的字节数完全相同，N=64 时差 5.11 倍 —— 差额全部来自"贵的那一级发生了几次"。

一、α-β 模型在跨机时为什么不够用#

1.1 单层账的复述#

第 1 章已经把 decode 的单层成本写成：

T(N)=访存∝1/NNA​​​+通信∝N 或 logN2L⋅TAR​(N)​​

其中一次环形全归约（N 个 rank、每 rank 输入 S 字节）是

TARring​(N,S)=延迟项2(N−1)α​​+带宽项2NN−1​βS​​​

这个式子里 α、β 是常数。跨机之后它们不再是常数，因为一个算法会同时用到多条链路：环上某些步走 NVLink、某些步走 IB。于是"这一步花多少时间"取决于"这一步在哪根线上"，而 TAR​ 变成

TAR​=rank i∑​step k∑​(αhop(i,k)​+βhop(i,k)​S/N​)关键路径​

关键路径上的每一项都有自己的 α,β。这就是"拓扑"进入公式的唯一入口 —— 它不是一个形容词，而是一个求 max / 求和的下标。

1.2 一条先把话说清楚的结论#

由这一节的两个算例可以立刻得到一条判据：

跨机的代价={αnet​/αdom​βdom​/βnet​​S<S∗ (延迟主宰)S>S∗ (带宽主宰)​​

S∗=Nαβ 就是两族曲线的交叉点，见 §3。在下面的层级表里：

αdom​αnet​​=1.02.0​=2,βnet​βdom​​=50450​=9

同一个网络，两个答案，比值差 4.5 倍。 所以第 1 章里"用 α=5μs、β=450 GB/s 代表 NVLink，用 α=10μs、β=25 GB/s 代表 IB"这种写法，只在"你已经知道消息在哪个区间"的前提下才对。

1.3 为什么 max 而不是平均#

同步集合通信（环形、树形、分层）的每一步都要等所有参与的 rank。所以：

Tstep​=i∈ranksmax​(αhop(i)​+βhop(i)​S/N​)

由此得到本节最重要的一条方法论：

同步算法里，"平均带宽"不是观测量，"最差链路"才是​

这条结论在第 4 节会变成"慢节点"的全部数学（次序统计量）。在这里它先给出一个直接后果：一个环上只要有 g 条跨机链路，整个环的 α 就取 αnet​，与 g 有多小无关。这就是"拓扑错配"的算术根源。

读这张表的三个要点：

  1. 带宽跨度看起来很大（268×），但对小消息无效。 因为小消息的时间由 α 而不是 β 决定：S=8 KiB 时带宽项只有 0.032μs，把 β 从 450 GB/s 提到 3.35 TB/s 省下 0.028μs —— 占总时间的 0.2%。
  2. 延迟跨度（25×）比带宽跨度（36×）小，但它的作用范围大得多。 α 乘的是步数 2(N−1)，N=64 时是 126 步；α 从 1 µs 涨到 2 µs，N=64 的环形凭空多 126 µs。
  3. PCIe 与 IB 在这一代几乎同速同延迟。 这不是巧合：PCIe 5.0 的 50 GB/s 与 NDR 的 50 GB/s 是同一档，而 PCIe 的 α（1.8 µs）甚至略低于 IB（2.0 µs）。所以"跨节点一定比机内慢"是错的 —— 慢的是"没有 NVLink 的机内"和"有拥塞的以太网"，不是"跨机"这个动作本身。

PCIe vs NVLink 的真实差距在 α 与拓扑，不在 β。 一台 8 卡 PCIe 机器里，任意两卡通信要过 CPU/PCIe switch，α 可能是 3∼10μs 而不是 2 µs，而且拓扑不再均匀（NUMA 分组）。这正是为什么 torchrun 在多机 PCIe 机器上要做拓扑探测与 rank 重排。

三、集合通信的量：三个不同的下界#

这是本节最容易被记混、也最值得写清楚的一处。AllReduce / AllGather / AllToAll 的"每卡通信量"是三个不同的数，而且"下界"与"可达"要分开说。

3.1 记账的口径#

设 N 个 rank，每个 rank 初始持有长度 S 字节的数据。

  • 发送量 Vsend​：一个 rank 在一个方向（i→j）上推出去的字节数，求和。
  • 接收量 Vrecv​：一个 rank 从别人那里收进来的字节数，求和。
  • 总流量 Vtot​=Vsend​+Vrecv​。

对环形算法，每个 rank 只用两条链路（左右邻居），所以 Vsend​ 就是它压在自己那条出链上的字节数。

3.2 AllReduce：2NN−1​S#

算法（环形，reduce-scatter + all-gather）：

ReduceScatter（N-1 步）：rank i 在第 k 步把 chunk (i-k) mod N 发给 i+1，收到后累加
                          → N-1 步后 rank i 持有第 i 块的**完整**和
AllGather（N-1 步）    ：把自己那块沿环传开
每步消息大小 = S/N 字节

总步数 2(N−1)，每 rank 总发送量：

VsendAR​=RSNN−1​S​​+AGNN−1​S​​=2NN−1​S

下界（收）：每个 rank 最终要知道 S 字节的完整和，其中 NN−1​S 来自别人。要算出别人的贡献，就必须收到那些贡献 —— 所以

Vrecv​≥NN−1​S,故NN−1​βS​≤TAR​≤2NN−1​βS​

环形（可达） 下界 差距
带宽项 2NN−1​S/β NN−1​S/β 2 倍
延迟项 2(N−1)α ⌈log2​N⌉α O(N/logN)，很松

"换更好的通信算法"能赢的是 α 项（logN 而非 N），不是 β 项​

这里必须说清一个细节：NN−1​S 是下确界，不是任何算法的可达值。严格地说，真实算法的每卡发送量在 [2NN−1​S, S] 之间：环形取到 2NN−1​S，而"每 rank 向所有人各发一份自己的数据"（S 字节）是平凡上界。所以：

NN−1​S≤Vsend​≤S⋅朴素 all-to-all 广播NN​​​

工程上关心的是环形离下界只差 2 倍（而且只用两条链路，这对拓扑友好），所以环形是默认选择。这就是为什么"更聪明的算法"在带宽上几乎没有空间 —— 2 倍已经是天花板。

3.3 AllGather：NN−1​S#

每个 rank 输出 S 字节（所有 rank 的数据），其中自己的那份本来就有，所以

Vrecv​≥NN−1​S,Vsendring,AG​=NN−1​S

步数只有 N−1（环形）或 ⌈log2​N⌉（递归倍增）—— 因为不需要归约阶段，没有"先涨后广播"的两倍结构。

3.4 AllToAll：NN−1​S#

AllToAll（EP 的 dispatch/combine 用的原语）是"每个 rank 把第 j 块发给 rank j"：

Vsend​=Vrecv​=NN−1​S (对称输入),环形步数=N−1

它比 AllReduce 少一半的容量，这一点很重要：

VA2AVAR​=NN−1​S2NN−1​S​=2

所以"EP 的 all-to-all 比 TP 的 all-reduce 贵"这个说法，在容量上是错的 —— AllToAll 每字节更便宜。EP 真正贵的地方是 S 大得多（tk​Hσ，几 MiB 量级）与容量因子造成的非对称。第 2 节会把这笔账算完。

3.5 三个数放在一起#

原语 每卡接收下界 每卡接收上界 环形步数 α 下界
AllReduce NN−1​S 2NN−1​S 2(N−1) ⌈log2​N⌉
AllGather NN−1​S NN−1​S N−1 ⌈log2​N⌉
AllToAll NN−1​S NN−1​S N−1 1（可直发）

三个原语的下界相同，可达值不同。 AllReduce 的 2 倍差距来自"归约 + 广播"的两阶段结构；AllGather 与 AllToAll 只有一阶段，所以环形就是最优的容量。

五、拓扑错配：平环与分层的字节账完全相同#

现在进入本节的核心算例。设 N=8P 张卡分布在 P 个节点上，每节点 8 卡 NVLink 全互连。

5.1 两个候选算法#

平环（flat ring）：把 N 个 rank 排成一个环，按 rank 顺序"先节点内后节点间"。环上有 2P 条跨机链路（每个节点两条边界）。

分层（stratified / hierarchical）：

第一级：每个节点内的 8 张卡做 2(K-1) 步全归约（K=8），走 β_dom
第二级：8 个节点的对应卡（同 rank）做 2(P-1) 步全归约，走 β_net
        —— 这就是 rail-optimized 拓扑的原型：同 rail 的卡在一张网上

5.2 为什么两者的字节数一样，时间差 5 倍#

字节数完全相同：两者都是 2NN−1​S，因为都是"归约 N 份"。差别在每条链路走多少：

平环:Tbw​=域内部分Nl​⋅N2(N−1)​βdom​S​​​+跨机部分Ng​⋅N2(N−1)​βnet​S​​​,g=min(2P,N)

分层:Tbw​=2NK−1​βdom​S​+2NP−1​βnet​S​

而延迟项的差别更大：

平环:Tlat​=2(N−1)⋅max(αdom​,αnet​)=2(N−1)αnet​

分层:Tlat​=2(K−1)αdom​+2(P−1)αnet​

关键在最后一行：平环的跨机步数是 O(N)=O(8P)，分层的跨机步数是 O(P)，而且分层里域内那 2(K−1)=14 步只付 αdom​=1μs。

5.4 取舍与边界#

情形 该做什么 不该做什么
P=1（单机） 只用域内账，别按 αnet​ 估 别为"未来跨机"过度设计
P≥2，延迟主宰（decode） 分层 + 树形/递归倍增 只扩带宽

一个必须承认的边界：本节所有模型都假设"链路带宽独立、无拥塞"。真实 IB 交换机是共享资源，P 个节点同时打到同一个上行口时，βnet​ 会掉、αnet​ 会涨。第 3 节会把这件事变成 rail 负载模型（最差/平均比），第 4 节把它变成尾部概率。

代码：带宽-延迟层级、下界与算法横评#

下面的脚本只用标准库，做七件事：(1) 建层级表并算跨度；(2) 实现三个原语的下界；(3) 实现环形/树形/分层三种可达算法；(4) 求交叉点 S∗；(5) 算拓扑错配的平环代价；(6) 给 EP 的 all-to-all 账；(7) 用 70B 参数复核。

"""
多机拓扑的带宽-延迟层级、集合通信的量-下界与代价（只用 Python 标准库）。

设计决策：
  1. 全课统一口径：α = 单向消息的固定延迟，β = **单向**链路带宽。
     不这么钉死，环形账会差 2 倍（很多资料把 β 写成双向聚合带宽）。
  2. 下界与算法分开表述：`bound_*` 给的是**不可改进的下界**，
     `ring_*` / `tree_*` / `stratified_*` 给的是**可达上界**。
     两者的差就是"还有多少算法优化空间"——这是本节的诊断量。
  3. 延迟层级表里同时给"跨度倍数"与"以 β 归一的对数份额"：
     后者才是"当链路速度整体提升 x 倍时哪一级先松绑"的依据（正文 §1）。
  4. 分层（stratified）全归约单独建模，因为跨机环的 α 取**两级中最差的那个**，
     不是平均——这正是"rail-optimized 部署不是优化而是修正"的算术原因（正文 §5）。
"""
from math import ceil, log2


# ==================== (1) 带宽-延迟层级的口径 ====================
# (名称, 单向β B/s, 单向α s, 典型范围下界, 上界, 说明)
LEVELS = [
    ("HBM3e (H100 SXM)",   3.35e12, 0.4e-6,  2.0e12,  3.9e12, "显存，算 HBM:compute 拐点用"),

    ("PCIe 4.0 x16",       25e9,    2.0e-6,  20e9,    28e9,   "32 GB/s 线速的理论可达"),
    ("PCIe 5.0 x16",       50e9,    1.8e-6,  45e9,    56e9,   "无 NVLink 的 8 卡机内"),
    ("NDR InfiniBand",     50e9,    2.0e-6,  45e9,    50e9,   "400 Gb/s ÷ 8"),
    ("800G IB (NDR×2)",    100e9,   1.8e-6,  90e9,    100e9,  "新一代 rail 网络"),

def hierarchy(levels, ref_bw=None, ref_lat=None):
    """
    给每一级算两个归一化量：
      span_bw  = log(β_max/β) / log(β_max/β_min)   —— 带宽在总体谱系里的对数位置
      span_lat = log(α/α_min) / log(α_max/α_min)   —— 延迟在总体谱系里的对数位置
    """
    bws = [x[1] for x in levels]
    lats = [x[2] for x in levels]
    bmax, bmin = max(bws), min(bws)
    lmax, lmin = max(lats), min(lats)
    rows = []
    for name, bw, lat, lo, hi, note in levels:
        sb = log2(bmax / bw) / log2(bmax / bmin) if bmax != bmin else 0.0
        sl = log2(lat / lmin) / log2(lmax / lmin) if lmax != lmin else 0.0
        rows.append((name, bw, lat, sb, sl, note))
    return rows


# ==================== (2) 下界 ====================
def bound_allreduce(N, S):
    """
    全归约的容量下界/延迟下界（字节数，不含每步的固定开销）。
      容量：每 rank 至少接收 (N-1)/N·S（信息论紧）；发送同量 → 总计 2(N-1)/N·S。
      延迟：⌈log2 N⌉ 轮（每轮最多把已知 rank 集合翻倍）。
    返回 (每卡接收下界, 每卡发送下界, 轮数下界)。
    注意：这是**下界/下确界**，不是任何算法可达的上界——见 ring_*。
    """
    if N <= 1:
        return 0.0, 0.0, 0
    return (N - 1) / N * S, (N - 1) / N * S, int(ceil(log2(N)))


def bound_allgather(N, S):
    """all-gather：每 rank 需收 (N-1)/N·S（自己的那块本来就有），⌈log2 N⌉ 轮。"""
    if N <= 1:
        return 0.0, 0
    return (N - 1) / N * S, int(ceil(log2(N)))


def bound_alltoall(N, S):
    """
    全交换（EP 的 dispatch/combine）：每 rank 必须把 S 里的 (N-1)/N 发出去。
    容量 = (N-1)/N·S；轮数下界 1（对端可以不重叠地直发，这点与 all-reduce 不同）。
    """
    if N <= 1:
        return 0.0, 0
    return (N - 1) / N * S, 1


# ==================== (3) 三种算法的可达上界 ====================
def ring_allreduce(N, S, alpha, beta):
    """环形：2(N-1) 步，每 rank 发 2(N-1)/N·S 字节（reduce-scatter + all-gather）。"""
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * (N - 1)
    nbytes = 2 * (N - 1) / N * S
    lat, bw = steps * alpha, nbytes / beta
    return lat + bw, lat, bw, steps


def tree_allreduce(N, S, alpha, beta):
    """
    递归倍增/二叉树：2⌈log2 N⌉ 步。容量取紧下界 (N-1)/N·S——真实实现受
    信道数限制会略高，这里按最优实现记账（对"换算法有多值"给上界估计）。
    """
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * int(ceil(log2(N)))
    nbytes = (N - 1) / N * S
    lat, bw = steps * alpha, nbytes / beta
    return lat + bw, lat, bw, steps


def stratified_allreduce(K, M, S, alpha_l, beta_l, alpha_g, beta_g):
    """
    两级分层全归约：先在 K 卡岛内（local）全归约，再在 M 个岛的副本间（global）。
    岛内 β_dom（NVLink），岛间 β_net（IB）——这就是 rail-optimized 拓扑的模型。
      Σ 第一级：M 次岛内全归约，S 不变
      Σ 第二级：（N/K 组 = M）全局全归约，S 不变
      延迟上界 = 岛内步数·α_dom + 岛间步数·α_net
    """
    if K <= 1 or M <= 1:
        return ring_allreduce(K * M, S, alpha_l, beta_l)
    # 岛内：2(K-1) 步；岛间：2(M-1) 步。两级的字节各自只走一遍。
    steps_l, steps_g = 2 * (K - 1), 2 * (M - 1)
    lat = steps_l * alpha_l + steps_g * alpha_g
    bw = 2 * (K - 1) / K * S / beta_l + 2 * (M - 1) / M * S / beta_g
    return lat + bw, lat, bw, steps_l + steps_g


def ring_alltoall(N, S, alpha, beta):
    """环形全交换：N-1 步直发（无归约阶段），每 rank 发 (N-1)/N·S。"""
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = N - 1
    nbytes = (N - 1) / N * S
    lat, bw = steps * alpha, nbytes / beta
    return lat + bw, lat, bw, steps


# ==================== (4) 判定：消息多小算"延迟主宰" ====================
def kink_bytes(N, alpha, beta, factor, algo="allreduce"):
    """
    求解「固定开销 = factor × 带宽时间」的消息字节数：
      allreduce: 2(N-1)·α = factor·2(N-1)/N·S/β  →  S = N·α·β/factor
      alltoall : (N-1)·α   = factor·(N-1)/N·S/β  →  S = N·α·β/factor
    factor=1 → 两项相等（交叉点）；factor=10 → 延迟大 10 倍（纯延迟区）。
    """
    return N * alpha * beta / factor


def mixed_ring(K, M, S, alpha_l, beta_l, alpha_g, beta_g):
    """
    拓扑错配的环形：一个 N=K·M 的环里有 2M 条跨机链路。
    每步的实际成本 = 该步所在链路的成本；环的 α 取 **最差** 的那一级（关键路径）。
    这是"拓扑错误放置"的最小模型：S 不变、步数不变，但每条跨机步都贵一个量级。
    """
    N = K * M
    if N <= 1:
        return 0.0, 0.0, 0.0, 0
    steps = 2 * (N - 1)
    g = min(2 * M, N)                      # 环上跨机链路的条数
    l = N - g
    # 延迟步数不变，但每一步按最差链路计价（同步算法：最慢参与者决定）
    dmax = max(alpha_l, alpha_g)
    lat = steps * dmax
    # 字节：l/N 的比例走域内，g/N 走域间（各走一半，两个方向对称）
    nbytes = 2 * (N - 1) / N * S
    bw = (l / N) * nbytes / beta_l + (g / N) * nbytes / beta_g
    return lat + bw, lat, bw, steps

四处关键设计决策：

  1. 下界函数与算法函数分开命名（bound_* vs ring_*/tree_*/stratified_*）。这是正文 §3.2 那个"下界不是可达值"的结构化表达 —— 混在一个函数里，代码注释就没法说清"这个数是天花板还是地板"。
  2. stratified_allreduce 单独建模，不复用 mixed_ring。因为两者的步数公式不同（2(K−1)+2(P−1) vs 2(N−1)），而字节数相同。共用函数会把"分层省的是跨机步数，不是步数"这个结论藏起来。
  3. 交叉点用 kink_bytes 参数化 factor：factor=1 给交叉点，factor=10 给"延迟大 10 倍"的边界。只报一个交叉点会让人误以为它是硬边界，其实它是一条连续曲线。
  4. mixed_ring 的延迟项取 max(α_dom, α_net)。这不是近似，是同步算法的正确性要求：一个环上只要有跨机跳，整个环的每一步都要等最慢的那一跳。

小结#

  • 跨机的代价不是一个数，而是一条分段的曲线：S<S∗ 时等于 αnet​/αdom​（本例 2×），S>S∗ 时等于 βdom​/βnet​（本例 9×）。同一个网络的这两个答案差 4.5 倍 —— 所以"跨机慢几倍"这句问句必须先补上"消息多大"。
  • 同步算法里没有"平均带宽"：Tstep​=maxi​(αhop(i)​+(S/N)/βhop(i)​)。一个环上只要有一条跨机链路，整环的 α 就取跨机值。这是拓扑错配的算术根源，也是第 4 节"慢节点"的同一个数学。
  • 三个下界必须分开记：AllReduce 2NN−1​S、AllGather 与 AllToAll 各 NN−1​S。AllReduce 的 2 倍差距来自"归约 + 广播"的两阶段结构；AllToAll 每字节比 AllReduce 便宜一半，EP 的贵在 S 大而不是单价高。
  • 换算法只能赢 α 项：环形步数 2(N−1) vs 树形 2⌈log2​N⌉，N=64 时提速 10.50×；容量上的差距永远只有 2 倍（下界）且小消息下无关紧要。
  • 交叉点 S∗=Nαβ 是本节的诊断工具。N=8、域内时 3.6 MB（本脚本 α=5μs 口径下 17.6 MiB）；decode 的 8 KiB 在它左侧 2000 倍，prefill 的 512 MiB 在它右侧 146 倍。(Tlat​/Tbw​)>100 时，"合并消息、压缩激活"是白做工，只该减步数。
  • 拓扑感知是修正记账口径，不是优化：平环与分层的字节数完全相同，N=64 时差 5.11×（P=16 时 6.25×）。差别全在"跨机步数"：平环 O(N)、分层 O(P)。
  • PCIe 5.0 与 NDR IB 在这一代同档（50 GB/s、约 2 µs）。所以"跨机一定慢"是错的 —— 慢的是没有 NVLink 的机内与有拥塞的以太网。
  • 70B 跨机 TP 在时间账上是负收益：N=8 时每 token 通信 64.0 ms，是单卡权重访存时间 4.81 ms 的 13.3 倍。若最终仍部署跨机 TP，那是容量动机，不是时间动机。
  • 一句话："多机慢多少"不是一个经验值，而是 S、N、α、β 四个量的一次分段判断；先把消息大小写进式子，再谈拓扑。
