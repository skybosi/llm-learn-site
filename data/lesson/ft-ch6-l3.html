完整项目#

这是《LLM 微调》的最后一课。前面每一课都是一块拼图，这一课我们把它们拼成一张完整的项目蓝图：从需求定义到数据工程，再到训练、评估、部署与迭代，用一个真实可复用的项目骨架串起来。学完这一课，你应该能独立接手一个"把通用模型改造成领域助手"的完整任务，并知道每一步该看什么、防什么。

一、概念讲解#

1. 项目全景：五个阶段#

一个严谨的微调项目按顺序走五步：

  1. 需求与基线：明确任务（做什么、给谁用、怎么算成功），并先测基座模型在当前任务上的表现，作为必须超越的基线；
  2. 数据工程：收集、清洗、去重、切分、格式化，产出训练集/验证集/测试集；
  3. 训练：选定路线（纯 SFT / 先 CPT 后 SFT / 结合 RAG），配好 QLoRA + SFTTrainer，管理好实验；
  4. 评估：困惑度 + 基准 + 人工抽查，与基座做增量对比，防过拟合、防遗忘；
  5. 部署与迭代：合并适配器、量化推理、接入服务，并根据线上反馈回流数据、进入下一轮。

2. 工程化的三个支柱#

① 配置管理：把模型名、数据路径、超参、LoRA 配置都放进一个 YAML/JSON，代码只读配置，杜绝"改了代码忘了同步参数"的隐患。

② 实验跟踪：用 wandb（或 MLflow）记录每次运行的超参、损失曲线、评估分数，否则几十次实验后你根本记不住"哪个配置最好"。

③ 可复现性：固定随机种子、记录数据版本（数据也要版本化）、记录依赖版本（requirements.txt 或 lock 文件）。"昨天能跑、今天崩了"通常是依赖漂移。

3. 部署的关键决策#

  • 是否合并：追求极致推理速度就 merge_and_unload；要保留多任务可插拔就只存适配器；
  • 量化推理：部署到低配/高并发环境，用 bitsandbytes 的 8-bit/4-bit，或 vLLM 这类高性能推理框架做批量服务；
  • 在线 vs 离线：需要实时响应用 HTTP 服务（FastAPI + vLLM），离线批量任务直接脚本批处理。

4. 一张防翻车清单#

  • 训练/推理用同一套 chat template；
  • 验证集绝不出现在训练数据里（先去重再切分）；
  • 每轮实验都和基座对比，而非只看绝对分；
  • CPT 时混入通用语料，防灾难性遗忘；
  • 学习率、轮数、lora_alpha/r 有记录、可回溯；
  • 部署前在测试集上做最终评估，不拿训练分数充数。

二、可运行代码示例#

下面是一个项目骨架：把配置、训练、推理拆成三个清晰的文件/函数，体现"配置驱动 + 可复现"。依赖 transformers、peft、trl、datasets。

# ============ config.py：集中管理配置 ============
CONFIG = {
    "model_id": "HuggingFaceH4/zephyr-7b-beta",
    "data_path": "./data/train.jsonl",
    "output_dir": "./runs/exp-01",
    "lora": {"r": 16, "alpha": 32, "dropout": 0.05,
             "target_modules": ["q_proj", "k_proj", "v_proj", "o_proj"]},
    "train": {"lr": 2e-4, "epochs": 1, "batch": 1, "accum": 8, "max_len": 512},
}

# ============ train.py：训练入口 ============
import torch
from datasets import load_dataset
from transformers import (AutoModelForCausalLM, AutoTokenizer,
                          BitsAndBytesConfig, TrainingArguments)
from peft import LoraConfig, prepare_model_for_kbit_training
from trl import SFTTrainer
from config import CONFIG as C

dataset = load_dataset("json", data_files=C["data_path"])["train"]
dataset = dataset.train_test_split(test_size=0.1)  # 留 10% 验证

bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_use_double_quant=True,
                         bnb_4bit_compute_dtype=torch.bfloat16)
model = AutoModelForCausalLM.from_pretrained(C["model_id"],
                                             quantization_config=bnb,
                                             device_map="auto")
tokenizer = AutoTokenizer.from_pretrained(C["model_id"])
tokenizer.pad_token = tokenizer.eos_token
model = prepare_model_for_kbit_training(model)

peft_cfg = LoraConfig(r=C["lora"]["r"], lora_alpha=C["lora"]["alpha"],
                      lora_dropout=C["lora"]["dropout"],
                      target_modules=C["lora"]["target_modules"],
                      bias="none", task_type="CAUSAL_LM")

args = TrainingArguments(output_dir=C["output_dir"],
                         per_device_train_batch_size=C["train"]["batch"],
                         gradient_accumulation_steps=C["train"]["accum"],
                         learning_rate=C["train"]["lr"],
                         num_train_epochs=C["train"]["epochs"],
                         bf16=True, gradient_checkpointing=True,
                         logging_steps=1, save_strategy="epoch",
                         report_to="wandb")  # 实验跟踪

trainer = SFTTrainer(model=model, args=args, train_dataset=dataset["train"],
                     tokenizer=tokenizer, peft_config=peft_cfg,
                     max_seq_length=C["train"]["max_len"])
trainer.train()
trainer.save_model(C["output_dir"] + "/adapter")

# ============ infer.py：推理入口 ============
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer
from config import CONFIG as C

base = AutoModelForCausalLM.from_pretrained(C["model_id"], device_map="auto")
model = PeftModel.from_pretrained(base, C["output_dir"] + "/adapter")
tok = AutoTokenizer.from_pretrained(C["model_id"])

def ask(question):
    msgs = [{"role": "user", "content": question}]
    ids = tok.apply_chat_template(msgs, return_tensors="pt").to(model.device)
    out = model.generate(ids, max_new_tokens=128, do_sample=False)
    return tok.decode(out[0][ids.shape[1]:], skip_special_tokens=True)

print(ask("请用一句话解释什么是 LoRA。"))

这个骨架把配置、训练、推理解耦：改超参只动 config.py，训练产物按 output_dir 分实验存放，推理脚本单独维护。把它作为你未来项目的起点，逐步往里加"评估脚本"和"数据版本号"，就是一个可落地的微调工程。

三、练习#

  1. 基于这个骨架，补一个 eval.py：加载验证集，计算困惑度，并输出 10 条基座与微调模型的对比回答，供人工抽查。
  2. 给 config.py 增加"数据版本号"字段，并在训练前打印当前使用的数据哈希，实现简单的数据可复现。
  3. 接入 wandb，跑两次不同学习率的实验，对比 wandb 面板上的损失曲线，体会实验跟踪的价值。
  4. 把 infer.py 的模型换成一个 merge_and_unload 后的合并模型，再换成一个 4-bit 量化加载的模型，比较三者的推理延迟。

到这里，你已经完整走通了 LLM 微调从原理（LoRA/QLoRA/PEFT）、方法（指令微调/SFT/评估）到工程（端到端、领域适配、完整项目）的全程。剩下的就是拿一个你真正关心的领域，动手做一个属于你自己的模型。
