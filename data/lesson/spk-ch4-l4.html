音频理解与多模态：事件检测、音频-文本对比学习与可复现评测协议#

这一节要解决什么#

前三节的任务都以人声为对象：谁在说、几个人在说、他是什么状态。这一节把范围扩到整个声场：环境里发生了什么事件（狗叫、玻璃碎、警报、引擎、雨声），以及这些事件能不能与文本描述对齐。

这一扩，标签重新变得客观——"这段音频里有没有狗叫"不像"这个人有多生气"那样依赖感知判断。但换来三个新的结构问题：

  1. 音频与语音的差别是"任务 vs 信号"的双重差别。 语音任务几乎总是单一的（一段音频一个人说话）、有时序的（帧级对齐）、类别封闭的（音素/词表）；音频事件任务常常是多标签的（同时有雨声和引擎）、时间尺度差异巨大的（玻璃碎 0.2 秒 vs 雨声 30 秒）、并且类别是开放长尾的。所以"把语音识别的架构搬到事件检测上"会同时错两次。
  2. 评测口径可以决定结论。 同一段音频、同一个系统输出，在四种口径下读出完全不同的数：段级 IoU≥0.5 给出 F1 =0.6667/1.0000/1.0000（逐类），事件级 collar=0.10 s 给出 0.0000，collar=0.50 s 给出 0.5556，而 clip 级多标签给出 0.8889（阈值 0.5）。它们的差别不是"精度不同"，而是"问的问题不同"。
  3. 对比学习的"负样本"可以是假阴性。 在 200 个语义类别的池子上采样 batch，同类碰撞的概率是生日问题：B=16 时至少一对同类概率 0.4512（每样本 0.07 对），B=256 时每样本 1.27 对。本节实测：B=256、τ=0.05 时朴素 InfoNCE 与"剔除同类项"的损失只差 0.00218——但正样本的梯度系数 κ 从 0.0668（B=16）掉到 0.0029（B=256）。

 音频任务的评测协议必须先固定「问的是哪个问题」，再谈指标高低 ​

⚠️ 本节代码中的事件、系统输出、概念向量与相似度全部是合成的，只用标准库。它们的作用是把"口径差异"和"假阴性"变成可核对的算术，不是对任何真实系统成绩的断言。

一、任务 vs 信号：音频理解与语音任务的三重差别#

1.1 三条差别#

语音任务（识别/合成/说话人） 音频理解（事件/场景/标签）
时间尺度 帧级（10 ms 量级），边界由音素/词决定 跨 4 个数量级：0.1 s（敲击）到 100 s（雨声）
标签结构 单一序列（转写）或单一身份 多标签、可重叠、可嵌套（"餐厅"里同时有"人声""餐具""音乐"）
类别空间 封闭（音素表、词表、注册说话人集） 开放长尾（AudioSet 类体系有几百类，且长尾极重）
相位/带宽要求 高（16 kHz 起，第 1 章） 视事件而定：低频事件（引擎、雷）在 8 kHz 下几乎不损；高频事件（玻璃碎、钥匙）需要 16 kHz 以上

第一处容易被忽略的差别是带宽。 第 1 章讲了"为什么语音常用 16 kHz"；音频事件任务的带宽需求由事件类别决定，不能全局套用语音的结论。玻璃碎的判别信息主要在 4∼8 kHz；雷声的能量主要在 100 Hz 以下。把两者放进同一个 16 kHz / 25 ms 的前端，其中一类必然被浪费。

1.2 三种输出粒度，对应三种任务#

粒度 输出 任务名 典型指标
clip 级多标签 每个类别一个 [0,1] 音频标注（tagging） mAP、宏 F1
段级（segment-based） 每个类别一串 (tstart​,tend​) 声音事件检测（SED） 段级 F1（IoU 阈值）
事件级（event-based） 每个事件一个 (tstart​,tend​,class) 事件检测/定位 事件级 F1（collar 容差）

三者不能互相替代，因为丢失的信息不同：

  • clip 级丢掉全部时间信息（"出现过"vs"出现几次"vs"什么时候"）；
  • 段级保留"哪些时间段被占"，但不区分"一个长事件"与"两个连着的短事件"；
  • 事件级保留事件个数，因此对边界精度和漏检/虚警更敏感。

二、事件检测的评测口径#

2.1 段级口径：交并比#

对同类别的参考事件 Ri​=(si​,ei​) 与系统输出 Hj​：

IoU(Ri​,Hj​)=∣[si​,ei​]∪[sj​,ej​]∣∣[si​,ei​]∩[sj​,ej​]∣​=(ei​−si​)+(ej​−sj​)−交max(0,min(ei​,ej​)−max(si​,sj​))​

当 IoU≥θ（常用 θ=0.5）时记为命中。段级 F1 就是在这个命中判据下的精确率/召回率的调和平均。

段级口径的一个已知弱点：它对"碎片化"不敏感。一个 10 秒的事件被切成 10 个 1 秒的片段输出，段级匹配会逐个匹配（每个片段的 IoU 可能都不够 0.5，所以会被判成漏检 + 虚警），但如果系统输出一个 10 秒的事件而参考是两个 5 秒的事件，段级可能会把它们都算命中（取决于 IoU 定义的具体变体）。所以段级 F1 必须与事件级 F1 一起报。

2.2 事件级口径：collar 容差与匹配方式#

事件级口径允许边界误差：只要两个事件的起点与终点分别落在 ±collar 内，就算命中：

命中⟺max(∣si​−sj​∣, ∣ei​−ej​∣)≤collar

匹配方式有两种，必须声明：

  • 贪心匹配：把所有 "（代价, i, j）" 按代价升序排序，依次取第一个两端都未匹配的对；
  • 最优匹配（匈牙利/Kuhn–Munkres）：求"在容差内的最大基数匹配"，即最大化命中数。

贪心不保证最优，但在真实数据上两者常常接近。本节的合成实验中，collar=0.05 s 时两者都是 0.0000（容差太严，无命中）；collar=0.50 s 时贪心 0.5587、最优 0.5772（差 0.0185，相对 3.2%）。

本节刻意让边界抖动（σ=0.35 s）远大于小 collar，所以 collar=0.05 s 与 0.10 s 的结果几乎是零。这不是缺陷，而是要点：collar 的取值必须与标注的边界精度匹配。人工标注的边界精度通常在 50∼200 ms，所以 collar 小于标注精度时，"系统很差"和"口径太严"无法区分。

在 [0.30,0.50] 之间有一个平台（都等于 1.0000）——因为合成数据的正负分布分得很开。真实数据上不存在这种平台，阈值必须用开发集选。当有人报"mAP =0.9 以上"时，要问的第一个问题是：正负样本比例是多少？ 在极度不平衡的长尾类别上，即使是随机打分，mAP 也可能虚高（因为它只关心排序，而长尾负样本让排序"看起来"很好）。

三、音频-文本对比学习#

3.1 目标函数#

给定 B 对（音频 ai​，文本 ti​），编码器给出归一化嵌入 ui​,vi​，相似度 sij​=ui⊤​vj​/τ（τ 是温度）。InfoNCE（音频→文本方向）：

L=−B1​i=1∑B​log∑j=1B​exp(sij​)exp(sii​)​

对称版本再加一个文本→音频方向的项。它等价于"在 B 个候选里做 B 分类"，正类是 j=i。

温度的机制：τ 越小，softmax 越尖锐（更接近 argmax），梯度只由最难的负样本决定；τ 越大，分布越平坦，所有负样本都参与。本节在同一个 batch 上扫 τ：

τ InfoNCE top-1
0.02 13.5585 0.0625
0.05 6.0000 0.0625
0.10 4.1137 0.0625
0.20 3.7803 0.0625
0.50 3.9159 0.0625

top-1 完全不随 τ 变（因为 top-1 只看排序，与温度无关），而 InfoNCE 从 13.5585 掉到 3.7803。这给出一条判据：拿 InfoNCE 的绝对值比较不同模型是没有意义的，它随 τ 可以差 3.6 倍。要比就固定 τ，或者用不依赖 τ 的检索指标。

3.2 模态偏置：对齐质量的直接来源#

在合成实验里，两个模态共享同一个概念向量，但各自加一个 ±bias 的模态偏置与噪声：

bias noise 对角相似度 异类相似度 top-1
0.60 0.10 0.3573 −0.2041 0.8906
0.30 0.10 0.6364 −0.0660 1.0000
0.15 0.10 0.7295 −0.0202 1.0000
0.30 0.40 0.1371 −0.0177 0.0625
0.30 0.80 0.0397 −0.0067 0.0156
0.15 0.80 0.0462 −0.0030 0.0156

读法：

  • 模态偏置 0.60 时对角相似度只有 0.3573，但 top-1 仍有 0.8906——因为异类相似度被压到 −0.2041，绝对相似度低不代表排序坏；
  • 噪声才是杀手：noise=0.40 时对角相似度掉到 0.1371（与异类的 −0.0177 只差 0.1548），top-1 崩到 0.0625。

判据：评估音频-文本对齐时，只看对角相似度是不够的，必须同时看异类相似度（或直接看检索 top-1）。一个把"绝对相似度"当质量指标的系统，可能在异类相似度同样低的情况下显得很好。

3.3 假阴性：概率、偏差与梯度稀释#

在类别数为 Ncat​ 的池子上独立采样 B 个样本，至少出现一对同类的概率（生日问题）：

P碰撞​=1−exp(−2Ncat​B(B−1)​),E[同类对数]=2Ncat​B(B−1)​

Ncat​=200 时：

B 超过 2Ncat​​=20.0 之后，同类碰撞就不再可忽略。这就是"对比学习需要大 batch"的另一面：大 batch 带来了更多负样本，也带来了更多假阴性。

这里有一个反直觉但重要的结论：在这个设置下，修掉假阴性只让损失变了 0.02%∼0.5%——因为正样本对的相似度远高于假阴性，softmax 里假阴性那一项本来就很轻。真正被影响的是梯度尺度：κi​=exp(sii​)/∑j​exp(sij​) 从 0.0668 掉到 0.0020（33 倍）。κ 变小意味着有效学习率被摊薄，训练变慢。

读法：训练会把假阴性推到很低（τ=0.05 时 sfn​→0.0747，τ=0.20 时 →0.0189），正样本相似度几乎不受影响（spos​ 在有/无假阴性时差不到 0.02）。所以在这个模型里，假阴性的"损失代价"很小，代价在别处：

  1. 被浪费掉的监督信号：那个同类样本本该是一个"难负样本"（信息量最大的那类），却被推成强负样本，等于把一个高质量训练样例扔了；
  2. 梯度稀释（上一张表的 κ）；
  3. 温度越低越严重：τ=0.05 时假阴性贡献占损失的 10−5，τ=0.5 时占 7.68%——低温把假阴性"压掉"了，高温下它才是问题。

判据：做音频-文本对比学习时，去重（或至少记录同类碰撞率）是必要步骤；但"不去重就必然坏"不是无条件的——它的后果取决于 τ、正样本相似度、以及类别数。最稳妥的做法是把"每样本同类对数"当作一个必须监控的训练统计量。

3.4 音频-文本对比学习与语音任务的关系#

音频-文本对比学习 语音识别
监督信号 粗粒度（"这段音频对应这句话"） 细粒度（帧到字符的对齐）

最重要的一条：对比学习不产生时间定位。一个 CLAP 类模型可以把"狗叫"这句话与一段 10 秒音频对齐得很好，但你无法从它直接读出"狗叫发生在第几秒"。要做事件检测，必须在对比预训练之上再接一个时间定位头（或把音频切窗后逐窗打标签）。把检索指标（top-1、mAP）当作检测指标是这类系统最常见的误用。

四、可复现的评测协议#

一份能被人重跑的音频评测协议必须固定下面七件事。少任何一件，数字都不能跨论文比较。

4.1 协议清单#

# 必须声明的东西 为什么
1 数据划分：训练/验证/测试的录音级（不是片段级）划分 同一条录音切出的片段进不同集合会泄漏
2 类别集合与本体版本 类别的合并/拆分直接改变指标
3 输出粒度：clip / 段级 / 事件级 见第 2 节，三者不可比
4 匹配准则：IoU 阈值或 collar 宽度、贪心还是最优匹配 collar 0.10→0.50 把 F1 从 0.0000 抬到 0.5772
5 决策阈值（clip 级）及其选取集合 见第 2.4 节，[0.30,0.50] 的平台是合成数据特有的
6 是否允许事件重叠 有些事件天然重叠（雨声 + 引擎），评测器必须规定一个时间点能否属于多个事件
7 聚合方式：宏平均 / 微平均 / 按类别加权 长尾类别会让宏平均与微平均差很多

4.2 划分泄露：一个具体的检查#

录音级划分是硬要求。一个可执行的检查：对每个测试片段，在训练集里找与它同源的片段（同一录音 ID、或音频指纹相同）；如果找到，说明划分错误。这一检查必须自动化，因为人工核对在几万条数据上不可行。

4.3 统计显著性#

事件检测的指标是集合级统计量（精确率、召回率、F1），它们的抽样方差不能直接用二项公式。正确做法是按录音整块自助重采样（block bootstrap）：每次重采样抽录音、把该录音的全部事件一起带进来。这样做出来的置信区间会显著宽于按事件独立重采样的结果——原因与第 2 章第 4 节的"句内聚集"完全相同。

报告规范：给 F1 时必须同时给按录音整块自助的 95% 区间。如果一个系统的 F1 是 0.55、另一个是 0.58，而区间宽度是 ±0.05，那么这两个系统在这份测试集上无法区分。

4.4 一份可复制的评测脚本骨架#

1. 读入 ref 与 hyp（每个事件：(class, start, end)）
2. 断言两边的时间单位一致（秒），断言 start < end
3. 对每个类别：
   a. 段级：贪心匹配 IoU >= 0.5 -> (P, R, F1)
   b. 事件级：collar = 0.20s，贪心 + 最优两种匹配 -> (P, R, F1)
4. clip 级（如果任务需要）：把 [0, T] 按固定窗长切分，
   每窗内出现过的类别记为 1，逐类算 F1 再宏平均
5. 结构化输出：JSON，含类别、粒度、匹配准则、阈值、样本量
6. 置信区间：按录音整块自助 1000 次

第 5 步的结构化输出是协议可复现的关键：把口径写进结果文件，而不是写在论文的方法段里。

下面的脚本只用标准库，数据全部合成。它依次做三件事：A 事件检测的三种口径与两种匹配方式；A2 同一段音频上四种口径的对照；B 对比学习的温度、模态偏置、假阴性与梯度稀释。

"""第 4 章 第 4 节 · 音频理解与多模态（纯标准库，数据合成）"""
import math
import random

EPS = 1e-300
D = 32
N_CAT = 200
SPARSE = 0.25


def unit(x):
    n = math.sqrt(sum(v * v for v in x)) + EPS
    return [v / n for v in x]


def concept_vec(r):
    """稀疏概念向量：每维以概率 SPARSE 非零，再归一化 -> 不同概念近似正交。"""
    v = [r.gauss(0, 1) if r.random() < SPARSE else 0.0 for _ in range(D)]
    if all(abs(x) < 1e-12 for x in v):
        v[0] = 1.0
    return unit(v)


def embed(concept, noise, bias, r):
    y = unit([concept[k] + (bias if k == 0 else 0.0) for k in range(D)])
    return unit([y[k] + r.gauss(0, noise) for k in range(D)])


def batch_pairs(B, noise, bias, seed):
    r = random.Random(seed)
    cats = [r.randrange(N_CAT) for _ in range(B)]
    P = []
    for _ in cats:
        cc = concept_vec(r)
        P.append((embed(cc, noise, bias, r), embed(cc, noise, -bias, r)))
    return cats, P


def info_nce(pairs, tau, exclude=None):
    B = len(pairs)
    S = [[sum(pairs[i][0][k] * pairs[j][1][k] for k in range(D)) / tau for j in range(B)]
         for i in range(B)]
    loss = 0.0
    for i in range(B):
        idx = [j for j in range(B) if j == i or exclude is None or not exclude[i][j]]
        m = max(S[i][j] for j in idx)
        loss += -(S[i][i] - m) + math.log(sum(math.exp(S[i][j] - m) for j in idx))
    return loss / B


def top1(pairs):
    B = len(pairs)
    hit = 0
    for i in range(B):
        sims = [sum(pairs[i][0][k] * pairs[j][1][k] for k in range(D)) for j in range(B)]
        if sims.index(max(sims)) == i:
            hit += 1
    return hit / B


# ---------------- 事件检测的三种口径 ----------------
def iou(a, b):
    lo = max(a[0], b[0])
    hi = min(a[1], b[1])
    inter = max(0.0, hi - lo)
    union = (a[1] - a[0]) + (b[1] - b[0]) - inter
    return inter / union if union > 0 else 0.0


def _prf(tp, fp, fn):
    p = tp / (tp + fp) if tp + fp else 0.0
    r = tp / (tp + fn) if tp + fn else 0.0
    f = 2 * p * r / (p + r) if p + r else 0.0
    return p, r, f


def segment_f1(ref, hyp, cls, thr=0.5):
    R = sorted([e for e in ref if e[0] == cls])
    H = sorted([e for e in hyp if e[0] == cls])
    used = [False] * len(H)
    tp = 0
    for r in R:
        best, bestv = -1, thr
        for j, h in enumerate(H):
            if used[j]:
                continue
            v = iou((r[1], r[2]), (h[1], h[2]))
            if v >= bestv:
                bestv, best = v, j
        if best >= 0:
            used[best] = True
            tp += 1
    return _prf(tp, len(H) - tp, len(R) - tp)


def _max_matching(cost, limit):
    adj = [[j for j in range(len(cost[0])) if cost[i][j] <= limit] for i in range(len(cost))]
    matchL = [-1] * len(cost[0])

    def try_kuhn(u, seen):
        for v in adj[u]:
            if not seen[v]:
                seen[v] = True
                if matchL[v] == -1 or try_kuhn(matchL[v], seen):
                    matchL[v] = u
                    return True
        return False

    res = 0
    for u in range(len(cost)):
        if try_kuhn(u, [False] * len(cost[0])):
            res += 1
    return res


def event_f1_collar(ref, hyp, cls, collar=0.2, match="greedy"):
    R = sorted([e for e in ref if e[0] == cls])
    H = sorted([e for e in hyp if e[0] == cls])
    if not R or not H:
        return 0.0, 0.0, 0.0
    cost = [[max(abs(r[1] - h[1]), abs(r[2] - h[2])) for h in H] for r in R]
    if match == "greedy":
        pairs = sorted((cost[i][j], i, j) for i in range(len(R)) for j in range(len(H)))
        usedR = [False] * len(R)
        usedH = [False] * len(H)
        tp = 0
        for c, i, j in pairs:
            if usedR[i] or usedH[j]:
                continue
            if c <= collar:
                usedR[i] = True
                usedH[j] = True
                tp += 1
    else:
        tp = _max_matching(cost, collar)
    return _prf(tp, len(H) - tp, len(R) - tp)


def multi_label_f1(ref_lab, hyp_score, thr=0.5):
    n_cls = len(ref_lab[0])
    fs = []
    for c in range(n_cls):
        tp = fp = fn = 0
        for r, s in zip(ref_lab, hyp_score):
            pred = 1 if s[c] >= thr else 0
            if r[c] and pred:
                tp += 1
            elif pred and not r[c]:
                fp += 1
            elif r[c] and not pred:
                fn += 1
        fs.append(_prf(tp, fp, fn)[2])
    return sum(fs) / n_cls

小结#

  • 音频理解与语音任务是"任务 + 信号"的双重差别：时间尺度跨 4 个数量级、标签可多可重叠、类别开放长尾、带宽需求由事件决定。把语音的"帧级单一序列"假设搬过来会同时错两次。
  • 评测口径比模型选择影响更大。同一个系统在段级 IoU≥0.5 下 F1 =0.6368，在事件级 collar=0.05 s 下 =0.0000，在 collar=0.50 s 下 =0.5587；同一小段音频在事件级 collar=0.10 s 下是 0.0000，在段级下是 0.6667/1.0000/1.0000，在 clip 级（阈值 0.60）是 1.0000。
  • collar 必须与标注精度匹配。人工边界精度约 50∼200 ms；collar 小于它时，"系统差"与"口径严"无法区分。
  • 对比学习的温度只改变损失数值，不改变排序（top-1 恒为 0.0625，InfoNCE 从 13.5585 到 3.7803）。跨模型比较 InfoNCE 绝对值没有意义。
  • 假阴性的概率很高（B=256 时每样本 1.27 对），但它的后果取决于设置：在正样本相似度远高于假阴性时，损失偏差只有 0.00218，spos​ 几乎不受影响；真正的代价是梯度稀释（κ 从 0.0668 掉到 0.0020，33 倍）与浪费难负样本。τ 越大，假阴性的损失贡献越大（τ=0.5 时占 7.68%）。
  • 对比学习不产生时间定位。把 top-1/mAP 当作检测指标是这类系统最常见的误用；要定位必须接时间头或逐窗打标签。
  • 报告规范：音频读数必须带上——录音级划分、类别本体版本、输出粒度、匹配准则与容差、决策阈值及其选取集合、重叠规则、聚合方式、按录音整块自助的区间。七项缺一，数字不可跨论文比较。
