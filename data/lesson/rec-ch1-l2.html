协同过滤/内容/混合#

上一课的地图里画了三大流派：基于内容、协同过滤、混合。这一课把三者讲透：它们各自用什么信息、怎么算、强在哪弱在哪，尤其要回答一个被大多数人跳过的问题——协同过滤的"相似度"为什么有效？ 这不是一句"物以类聚"能敷衍过去的，它背后有扎实的统计理由，我们放在末尾的推导里说清楚。

一、概念讲解#

1. 基于内容：给物品和用户各画一张像#

基于内容的推荐（Content-based Filtering）只依赖物品的内容特征，完全不看"别人"的行为。它分两步：

  1. 物品画像（Item Profile）：把每个物品表示成特征向量。比如电影可以用"科幻、动作、爱情、喜剧"四个维度的强度来描述，星际穿越 = [0.9, 0.2, 0.1, 0.0]。
  2. 用户画像（User Profile）：把用户历史喜欢过的物品特征聚合起来（常见做法是取平均），得到用户的兴趣向量。
  3. 匹配：对新物品，算它与用户画像的相似度（常用余弦），按相似度排序推荐。

它的优势是天然抗冷启动——新物品只要有内容特征就能立刻被推荐，不依赖任何历史交互。缺点是画像质量受限于特征工程：很多"感觉"（比如"这部片子的气质"）很难被有限的显式特征捕捉，且它只会推荐"和你过去相似的"，缺乏惊喜感。

2. 协同过滤：让群体的行为替你说话#

协同过滤（Collaborative Filtering）是反过来的思路：它完全不懂内容，只懂行为。核心假设只有一条——"过去行为相似的人，未来行为也相似"。据此它从"用户 × 物品"交互矩阵里直接挖掘模式，分成两大类：

  • 基于用户的协同过滤（UserCF）：找口味相似的用户，用他们的偏好预测你的偏好。
  • 基于物品的协同过滤（ItemCF）：找与你喜欢过的物品相似的物品，推荐给你。

协同过滤最迷人的地方在于：它不依赖任何人工标注的内容特征，却常常能"发现"内容特征之外的隐藏结构（比如"喜欢 A 的人也喜欢 B"这种无法预先定义的关系）。代价是它严重依赖历史数据，对冷启动和稀疏性最敏感。

3. 混合推荐：1 + 1 > 2#

单一方法都有短板，于是有了混合（Hybrid）：

  • 加权（Weighted）：最终分 = α·内容分 + (1−α)·协同分，α 是超参数；
  • 切换（Switching）：新用户/新物品没有协同数据时，自动切到内容推荐；
  • 级联（Cascade）：先用一个粗方法筛出一批候选，再用另一个精排；
  • 特征组合（Feature Combination）：把内容特征和协同特征拼进同一个模型一起训练。

三者对比一目了然：

维度 基于内容 协同过滤 混合
依赖信息 物品内容特征 用户行为矩阵 两者兼有
冷启动 好（有内容即可） 差（无历史即失效） 中（可切换兜底）
惊喜度 低（越推越像） 高（跨域发现） 可调
特征工程成本 高 低 中

4. 协同过滤的相似度为什么有效#

这是本课要"知其所以然"的核心。协同过滤的本质，是在用相似用户的评分做"邻域平滑（neighborhood smoothing）"：对一个 (u, i) 的未知评分，我们不是凭空瞎猜，而是去找一群"在历史行为上和 u 高度一致"的用户，看他们给 i 打了多少分，然后加权平均。

它之所以有效，是因为它把一个高方差、几乎无信息的估计，替换成了一个低方差、有先验支撑的估计。统计学上，"单看用户 u 自己的历史"几乎没有关于 i 的直接信息（他可能从没碰过 i）；而"相似用户的评分"相当于引入了一个条件于相似度的先验分布——相似度越高，先验越集中、越可信。于是加权平均出来的预测，比瞎猜均值稳定得多。这个直觉会在第 2 章用 UserCF/ItemCF 的公式精确地落地。

二、可运行代码示例#

先手动实现一个基于内容推荐的最小闭环，直观体会"画像 + 相似度"的流水线。协同过滤的完整 NumPy 实现放到第 2 章，这里先用最简形式看清结构。

import numpy as np

# 电影特征向量：每个维度是一个"内容属性"的强度（科幻 / 动作 / 爱情 / 喜剧）
movies = {
    "星际穿越":      np.array([1.0, 0.2, 0.1, 0.0]),
    "盗梦空间":      np.array([0.9, 0.4, 0.0, 0.1]),
    "泰坦尼克号":    np.array([0.0, 0.0, 1.0, 0.1]),
    "爱在黎明破晓前": np.array([0.0, 0.0, 0.9, 0.2]),
    "王牌特工":      np.array([0.2, 1.0, 0.1, 0.5]),
}

def cosine(a, b):
    """余弦相似度：两个向量的夹角越小越相似。"""
    denom = np.linalg.norm(a) * np.linalg.norm(b)
    return float(a @ b / denom) if denom > 0 else 0.0

# 用户画像 = 用户喜欢过的电影特征的"平均向量"（最简单、最常用的画像构建方式）
liked = ["星际穿越", "盗梦空间"]
profile = np.mean([movies[m] for m in liked], axis=0)
print("用户画像向量：", np.round(profile, 3))

# 对未看过的电影，按"与用户画像的余弦相似度"降序推荐
candidates = {m: cosine(profile, v) for m, v in movies.items() if m not in liked}
for name, score in sorted(candidates.items(), key=lambda x: -x[1]):
    print(f"{name:<8s} 相似度 = {score:.3f}")

你会看到"泰坦尼克号""爱在黎明破晓前"这类爱情片排在末尾，而"王牌特工"（含动作成分）比它们更靠前——这就是"越看越像你"的内容推荐逻辑，也是它"惊喜度低"的直观来源。

三、练习#

  1. 把 liked 改成 ["泰坦尼克号", "爱在黎明破晓前"]，观察排序变化，验证"用户画像跟随历史偏好漂移"。
  2. 把画像构建从"平均"改成"加权平均"（比如最近喜欢的那部权重加倍），思考这种改动的动机与代价。
  3. 手写一个 2 维示例：两个向量 a=[1,1] 与 b=[1,1] 的余弦相似度是多少？a=[1,1] 与 b=[10,10] 呢？为什么余弦相似度对"尺度缩放"不敏感，而欧氏距离敏感？这对"用户打分普遍偏高/偏低"意味着什么？
  4. 思考：如果某个新电影 "全新科幻片" 特征向量是 [1.0, 0, 0, 0]，内容推荐能立刻推荐它；但协同过滤却对这部电影毫无办法。请结合上一课"冷启动"的定义，说明这是为什么，并指出混合推荐如何用"切换"策略解决它。

为什么这样做？——理论推导#

为什么"取平均"是合理的画像：一次最大似然#

内容推荐里"把用户喜欢过的物品特征取平均当用户画像"，同样不是随手选的。把"用户画像"记作向量 p，假设用户对每个候选物品的"喜欢程度"与该物品特征 x 和 p 的内积成正比，且观测到的"喜欢/不喜欢"围绕 p·x 有一个高斯噪声。那么在"用户喜欢过的物品集合"上做最大似然估计，最大化：

argmax_p Σ_{j ∈ liked} [ −(score_j − p · x_j)² ]

对这个二次式求导令其为 0，解出来的 p 恰好就是"喜欢物品特征的均值"（当评分全部设为相同时）。所以"取平均"是高斯噪声假设 + 内积模型 + 最大似然的闭式解，而不是"图省事"。一旦评分有强弱、或希望更重视近期行为，就应当改用加权最小二乘——这正是"加权平均"练习题的出处。

协同过滤的相似度：一个条件先验#

再把"相似度为什么有效"收紧一点。设要预测 R[u, i]。朴素的无信息估计是全局均值 μ，它的方差很大（把所有用户混为一谈）。协同过滤的改进是：把预测限定在与 u 相似的一小撮人身上，于是估计变成了一个条件均值：

R̂[u, i] ≈ 关于 v 的加权平均 { R[v, i] | v 与 u 相似 }

相似度 sim(u, v) 在这里扮演"权重"，它本质上是先验的编码："我认为 v 的口味能代表 u，可信度与 sim(u, v) 成正比"。相似度越高，我们越相信 v 的评分靠近 u 的真实偏好，于是给它更大的权重。这就是为什么协同过滤不需要懂内容、却能从行为里挖出有效信号——它把"懂内容"这个难题，转化成了"找谁更可信"这个更容易用数据回答的问题。

母原理连接： 无论是内容推荐的"取平均"还是协同过滤的"相似度加权"，都是在"数据不足以给出精确答案"时，用一个参数化的先验 + 最大似然/加权最小二乘去逼近真实偏好——这是机器学习"用有限样本估计条件期望"的同一母题。
