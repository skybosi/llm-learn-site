从"会用框架"到"能改瓶颈"：三层能力模型#

同一段 PyTorch 训练代码，有人只知道"换个卡会快一点"，有人能指着 ncu 的报告说"这个 kernel 只跑到峰值带宽的 38%，因为访存没有合并"。差别不在 API 熟练度：后者能把程序结构换算成机器代价。这一课给这门课划地图，并回答为什么第一件事是学会算账而不是学会写 kernel。

一、概念讲解#

1. 三层能力：调用、诊断、改写#

把"GPU 编程能力"拆开，三层各自有明确的判据（不是"知道得更多"）：

层 能力 典型行为 判据（答不上来就说明还没到这一层）
L1 调用 用框架/库把活干完 torch.matmul、F.scaled_dot_product_attention、cuBLAS 结果对不对、在哪块设备上
L2 诊断 说清"慢在哪、为什么慢" 用 profiler 定位、读 roofline、算算术强度 这个 kernel 是带宽瓶颈还是算力瓶颈？依据是什么？
L3 改写 亲手改变代价结构 写 kernel、改 tiling、换精度、换库、改数据布局 优化后瓶颈转移到了哪里？还剩多少空间？

L1 到 L2 的门槛是测量：没有 profile 就没有诊断，只有猜测。L2 到 L3 的门槛是代价账本：不知道该目标的上限，就无法判断"还剩多少空间"，也无法判断"这次优化值不值得做"（第三课）。本课与第 3 课负责 L2，第 2 章到第 8 章把 L3 落到具体手段上。

2. 唯一需要的账本：算力、带宽与算术强度#

一个 kernel 的性能上限，由两个峰值与一个比值决定：峰值算力 P（FLOP/s，一次乘或一次加记 1 FLOP、乘加记 2）、峰值带宽 B（byte/s，单位时间能从 HBM 搬进/搬出多少字节）、算术强度（arithmetic intensity，AI）AI = 浮点运算次数 / 访存字节数（FLOP/byte）。

roofline 模型把两者合成一句判据：把该目标的 P / B 记为转折点 R，则 AI < R → memory-bound（带宽瓶颈，算力翻倍也没用，性能 ≈ B × AI）；AI > R → compute-bound（算力瓶颈，带宽翻倍也没用，性能 ≈ P）。直觉就是每搬 1 字节能做多少运算。

3. 用它给算子分类：ReLU 与 GEMM 是两个极端#

以 float32（每元素 4 字节）计，把访存量按读写数组个数相加：

算子 FLOP 字节 AI ≈
ReLU（逐元素） 2N 2 × 4N（读 + 写） 0.25
c = a + b（逐元素） N 3 × 4N 0.08
Softmax（max/exp/sum/div，含 2 读 1 写） ≈5N 3 × 4N ≈0.4
LayerNorm（5N，2 读 1 写） ≈5N 2 × 4N ≈0.6
GEMM（n×n @ n×n，2n³） 2n³ 3 × 4n² ≈n/6，n=4096 时 ≈ 683

结论一眼可辨：逐元素与归一化类算子全在 AI < 1 的一侧，而 GEMM 高出三个数量级。所以"ReLU 慢"和"GEMM 慢"是两个完全不同的问题：前者只该关心"能不能少搬字节、搬得更整齐"，后者才轮到关心 tiling 与数据复用（第 4 章）。这个分类在写代码之前就能推出。

4. 三层能力的判据：从"知道"到"算得出"#

L2 的标志是能把代码结构换算成一个量级判断：

  1. 这个算子属于上表哪一行？AI 与转折点谁大？
  2. 用实测带宽反推时间下界：t ≥ 字节数 / B。实测时间若已接近下界，说明它到顶了。
  3. 收益上限：若某 kernel 占端到端 12%，把它做到无穷快，端到端也只快 13%（第三课）。

L3 的标志是决策顺序：先算账 → 再选手段（合并访存 / tiling / 换精度 / 换库）→ 再验证（回归 + 正确性）。反过来先写"高性能 kernel"，通常是在优化不存在的瓶颈。

5. 常见坑#

  • 没有 profile 就下结论："感觉是访存瓶颈"和实测"DRAM 带宽用满"是两回事。
  • 对着结果而不是对着 AI 优化：同一个 ReLU 改 tiling 没用；同一个 GEMM 改循环顺序可能快数倍。
  • 忘记搬字节包含读写两头：in-place ReLU 是"读 N + 写 N"，只按 N 算会把带宽估高一倍。
  • 忘了转折点随精度与架构变：换低精度（TF32/FP16）时 P 上升、B 基本不变，R 变大，归属可能翻转。

二、可运行代码示例#

下面这段纯标准库代码不依赖 GPU 与 numpy：它按上面的公式算出五个典型算子的算术强度与访存字节数，再用 array 实测本机的可达内存带宽，最后把算子逐个判成 memory-bound / compute-bound。这套"算账—分类"的动作在 GPU 上完全同构，只是把实测带宽换成显存带宽。

# ---- 算术强度与 roofline 分类：纯 Python，无第三方依赖 ----
import sys, time
from array import array

GB = 1e9

def ai(flops, bytes_moved):
    """算术强度：每搬 1 字节能做多少次浮点运算"""
    return flops / bytes_moved

print('== 1. 五个典型算子的算术强度（单精度 float32，每元素 4 字节）==')
print('   规则：每读/写一个元素记 4 字节；一次乘加记 2 FLOP')
rows = [
    ('ReLU (N=2^20)',            2 * 2**20,       2 * 4 * 2**20),
    ('向量加 c=a+b (N=2^20)',     1 * 2**20,       3 * 4 * 2**20),
    ('Softmax (N=2^20)',         5 * 2**20,       3 * 4 * 2**20),
    ('LayerNorm (B=4096,F=4096)', 5 * 4096 * 4096, 2 * 4 * 4096 * 4096),
    ('GEMM (n=4096, 2n^3)',      2 * 4096**3,     3 * 4 * 4096**2),
]
print(f"{'算子':<28}{'FLOP':>13}{'字节':>13}{'AI (FLOP/byte)':>17}")
for name, f, b in rows:
    print(f'{name:<28}{f/1e6:>11.1f}M{b/1e6:>11.1f}MB{ai(f, b):>17.2f}')

print()
print('== 2. 本机实测可达带宽（标准库 array，块拷贝，5 次取最小）==')
N, CH = 8 * 2**20, 2**16           # N 个 double 元素；CH 为拷贝块大小
src, dst = array('d', bytes(8 * N)), array('d', bytes(8 * N))
def copy_once():
    for i in range(0, N, CH):
        dst[i:i + CH] = src[i:i + CH]
for _ in range(2):
    copy_once()                     # 预热：让页表与缓存进入稳定状态
ts = []
for _ in range(5):
    t0 = time.perf_counter(); copy_once(); t1 = time.perf_counter()
    ts.append(t1 - t0)
bw_gbs = 2 * N * 8 / min(ts) / GB   # 一块数据读 + 写，共 2 份流量
print(f'  Python {sys.version.split()[0]}；元素数 N={N}；块大小 CH={CH}')
print(f'  单次耗时（5 次取最小）= {min(ts)*1e3:.2f} ms  →  可达带宽 ≈ {bw_gbs:.2f} GB/s')
print(f'  均值 {sum(ts)/len(ts)*1e3:.2f} ms，最小/均值 = {min(ts)/(sum(ts)/len(ts)):.2f}（越大说明抖动越多）')

print()
print('== 3. roofline 分类：转折点 R = 峰值算力 / 峰值带宽 ==')
for peak_tflops, bw_tbs in ((30.0, 2.0), (60.0, 3.0)):
    ridge = peak_tflops / bw_tbs     # 单位 FLOP/byte；数值仅为量级示意，以官方规格为准
    print(f'  -- 假设峰值 {peak_tflops} TFLOPS + {bw_tbs} TB/s → 转折点 R = {ridge:.1f} FLOP/byte')
    for name, f, b in rows:
        kind = 'memory-bound' if ai(f, b) < ridge else 'compute-bound'
        print(f'     {name:<28}{ai(f, b):>8.2f}  →  {kind}')

第 2 节是可复现的量级，不是常量：同一台机器连测多遍，最小耗时在 3.14.5 ms、换算带宽在 3043 GB/s 之间摆动（"最小/均值"本身也在 0.74~0.98 之间跳）。这预告了第三课的核心问题——测量有噪声地板。两点必须自己核对：

  1. 第 2 节的带宽是本机 CPU 内存可达带宽，不是任何 GPU 的显存带宽——它只演示"如何把字节数换成时间下界"。把 bw_gbs 代进 t ≥ 字节数 / B，就是该算子在同带宽器件上的下界。
  2. 第 3 节的 30 TFLOPS + 2 TB/s 是假设值，真实值以器件官方规格为准；转折点是两个数的比值，量级对则分类结论稳。
# ---- 可选（需自备 GPU 或云上按需）：把同一套账本搬到真实器件上 ----
# 需要 PyTorch 的 CUDA 构建；没有 GPU 时跳过，不影响本课结论。
import torch, time

x = torch.randn(1 << 26, device='cuda')          # 约 268 MB 的 float32
for _ in range(3):
    y = torch.relu(x)                             # 预热：排除 context 与分配开销
torch.cuda.synchronize()
t0 = time.perf_counter()
for _ in range(20):
    y = torch.relu(x)
torch.cuda.synchronize()                          # 计时必须把异步 kernel 等到真正做完
dt = (time.perf_counter() - t0) / 20
bytes_moved = 2 * x.numel() * 4                  # 读 + 写，各 4 字节/元素
print(f'ReLU 实测 {dt*1e6:.1f} µs → 有效带宽 {bytes_moved/dt/1e9:.1f} GB/s')
print(f'时间下界 = 字节数 / 器件峰值带宽；实测越接近下界，越说明已经到顶')
# 器件峰值可用 nvidia-smi 自己读：nvidia-smi -q -d CLOCK

三、练习#

  1. 实现：给上面 §1 的 rows 表补三个算子——GELU（逐元素，含 erf）、RMSNorm、Attention scores（QKᵀ，2n³ 或实测形状下的实际 FLOP 数），算出它们的 AI，并判断各自属于哪一类。
  2. 解释：为什么逐元素算子的 AI 与 N 无关，而 GEMM 的 AI 随 n 线性增长？据此说明"大矩阵乘比小矩阵乘更容易跑满算力"的原因。
  3. 对比/验证：把 §2 的块大小 CH 依次改成 2**10、2**16、2**22 重测带宽，解释为什么太小和太大都会掉；再解释"最小/均值"这个比值在指导什么。
  4. 思考：若把 GEMM 从 float32 换成更低精度（TF32/FP16），P 会上升、B 基本不变，R 会怎么变？GEMM 的"compute-bound"结论会不会被推翻？什么算子会因此从 compute-bound 变成 memory-bound？
