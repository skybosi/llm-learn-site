GPT 架构#

上一课讲了 GPT 怎么"生成"，这一课讲 GPT 的"身体"长什么样。GPT 用的是仅解码器（decoder-only）的 Transformer：把上一门课里解码器的"掩码自注意力"作为核心，去掉交叉注意力，再按"前归一化（pre-LN）"堆叠很多层。我们会拆解每个零件，对比 GPT-1/2/3 三代的具体参数，并亲手搭一个最小的 GPT 块，把"架构"从论文里落到代码里。

一、概念讲解#

1. 整体结构：一个"读上文、猜下文"的堆栈#

GPT 的输入是一串 token，输出是对每个位置"下一个 token"的预测。从输入到输出，数据依次流过：

token 嵌入 + 位置嵌入
   → 堆叠 N 个 Transformer 块（每个块 = 掩码自注意力 + 前馈网络，均带残差与 LayerNorm）
   → 最终 LayerNorm
   → 线性层（映射到词表大小）→ softmax

它与你在注意力课程里见过的标准 Transformer 解码器有两个关键区别：

  1. 没有编码器，也没有交叉注意力：自注意力只发生在"自己和自己"之间，且带因果掩码；
  2. LayerNorm 放在子层之前（pre-LN）：这是 GPT-2 之后的默认做法，训练更稳定，允许把网络堆得很深。

因为结构里只有"解码器"这一半，所以称 decoder-only。

2. 输入表示：token 嵌入 + 位置嵌入#

每个 token 先查表得到 token embedding，再与一个可学习的绝对位置嵌入相加。GPT 没有像 BERT 那样单独设"分段嵌入"（它不需要区分两个句子），输入就两样：词 + 位置。

输入向量 = token_embedding[token_id] + position_embedding[位置下标]

嵌入维度记为 d_model（GPT-2 是 768，GPT-3 是 12288）。词表由 BPE（Byte Pair Encoding）子词算法切分得到，GPT-2 词表约 5 万个 token。

3. 一个 Transformer 块：掩码自注意力 + 前馈#

每个块做两件事（都带残差连接 + LayerNorm）：

  1. 掩码多头自注意力：让每个位置只能"看到"自己及之前的 token（上一课的因果掩码），捕捉上下文；
  2. 前馈网络（FFN）：两层线性 + 一个非线性激活，中间维度通常放大 4 倍（4 × d_model）。GPT 系列用的是 GELU 激活。

用伪代码表示一个块的前向：

x = x + MultiHeadSelfAttention(LayerNorm(x), causal_mask)   # 注意力子层
x = x + FFN(LayerNorm(x))                                   # 前馈子层

注意 LayerNorm 在进入子层之前作用（pre-LN）。相比之下，原始 Transformer 和 BERT 用的是 post-LN（子层之后归一化）。pre-LN 让梯度在残差路径上更"顺"，是 GPT-2 能把层数一路加上去、GPT-3 堆到 96 层的关键工程技巧。

4. 输出头与权重共享#

最后一个块出来后，过一层最终 LayerNorm，再乘一个线性层把 d_model 维映射到词表大小，softmax 后得到"下一个 token"的概率分布。GPT 有个省参数的细节叫 权重共享（weight tying）：输入嵌入矩阵和输出线性层的权重共用同一份。因为输入嵌入和输出头都是"词表大小 × d_model"，共享后能省下大量参数。

5. 三代 GPT 的参数对比#

模型 参数量 层数 注意力头数 d_model 词表 上下文长度
GPT-1 1.17 亿 12 12 768 约 4 万 512
GPT-2 15 亿 48 — 1600 约 5 万 1024
GPT-3 1750 亿 96 96 12288 约 5 万 2048

从 GPT-1 到 GPT-3，结构几乎没变，变的主要是规模：层数、宽度、数据量。这再次印证了第 1 章的缩放定律——架构复用了，能力靠规模堆出来。

二、可运行代码示例#

先用 Hugging Face 读 GPT-2 的配置，把上表变成可验证的数字。

from transformers import GPT2Config, GPT2LMHeadModel

cfg = GPT2Config.from_pretrained("gpt2")
print("层数 n_layer     =", cfg.n_layer)
print("注意力头 n_head   =", cfg.n_head)
print("嵌入维 n_embd     =", cfg.n_embd)
print("词表 vocab_size   =", cfg.vocab_size)
print("上下文 n_positions=", cfg.n_positions)

model = GPT2LMHeadModel(cfg)
params = sum(p.numel() for p in model.parameters())
print("总参数量 =", f"{params/1e6:.1f}M")   # gpt2 约 124M
print("权重共享? ", model.lm_head.weight is model.transformer.wte.weight)

最后一行会输出 True，印证"输入嵌入与输出头共享权重"。

再亲手搭一个最小的 GPT 块，体会 pre-LN + 残差 + 因果掩码的完整流程：

import torch
import torch.nn as nn

class GPTBlock(nn.Module):
    """一个最小 GPT 块：pre-LN + 掩码多头自注意力 + FFN。"""
    def __init__(self, d_model, n_head, ffn_mult=4):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)                 # 进入注意力前先归一化
        self.attn = nn.MultiheadAttention(d_model, n_head, batch_first=True)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, ffn_mult * d_model),      # 先放大 4 倍
            nn.GELU(),                                   # GPT 用 GELU
            nn.Linear(ffn_mult * d_model, d_model),
        )

    def forward(self, x, causal_mask):
        h = self.attn(self.ln1(x), self.ln1(x), self.ln1(x),
                      attn_mask=causal_mask, need_weights=False)[0]
        x = x + h                                        # 残差连接
        x = x + self.ffn(self.ln2(x))                    # 前馈 + 残差
        return x

# 构造因果掩码：位置 i 只能 attend 到 j <= i
def causal_mask(T):
    return torch.triu(torch.ones(T, T), diagonal=1).bool()

d_model, n_head, T = 64, 4, 8
block = GPTBlock(d_model, n_head)
x = torch.randn(1, T, d_model)             # batch=1, 长度 8
out = block(x, causal_mask(T))
print("\nGPT 块输出形状:", out.shape)       # 应与输入一致 [1, 8, 64]

# 验证因果性：把输入最后一个位置替换成大数，只影响输出最后位置，不影响前面
x2 = x.clone()
x2[:, -1, :] += 100.0
diff = (block(x2, causal_mask(T)) - out).abs()
print("受最后位置影响的输出位置:", (diff > 0.1).any(dim=-1).nonzero().squeeze().tolist())

最后一个实验很有趣：因为因果掩码，改动输入序列的最后一个 token，只会改变输出序列的最后一个位置（以及它之后的，但这里它已是末尾），前面位置纹丝不动——这正是"未来信息被屏蔽"的直接证据。

三、练习#

  1. 修改 GPTBlock，把 nn.GELU 换成 nn.ReLU，观察前向能否照常运行；结合 GPT 论文说明为什么原作者选 GELU 而非 ReLU。
  2. 用 GPT2Config 分别实例化 gpt2、gpt2-medium、gpt2-large、gpt2-xl，打印各自的 n_layer / n_embd / n_head，对照上表验证规模如何逐级放大。
  3. 在 GPTBlock 基础上，补一个词嵌入层与输出头，拼成一个能前向的微型 GPT（输入 token id → 嵌入 → 若干块 → LayerNorm → 线性输出），输入随机 token id，确认输出形状为 [batch, T, vocab]。
  4. 思考题：pre-LN 为什么比 post-LN 更容易训练更深的网络？从"残差路径上梯度如何流动"的角度给出你的解释。
