时间序列分解#

预测一条序列之前，最常见的做法是先把它拆开：把趋势、季节、残差三个分量分离开，看懂"哪部分是规律的、哪部分是噪声"，再决定对谁建模。这一课讲分解的原理，重点放在现代最常用的 STL 分解上。

一、概念讲解#

1. 分解的两种基本形式#

把序列 y_t 拆成三部分：趋势 T_t、季节 S_t、残差 R_t。有两种组合方式：

  • 加性模型：y_t = T_t + S_t + R_t
  • 乘性模型：y_t = T_t × S_t × R_t

两者的选择看季节波动的幅度是否随水平变化：

  • 如果全年波动"高度"恒定，用加性；
  • 如果销量越大、旺季的绝对增量也越大（波动随水平放大），用乘性。

乘性模型只需对序列取对数就能转成加性：log(y_t) = log(T_t) + log(S_t) + log(R_t)，所以实务上"取对数 + 加性分解"是处理乘性序列的通用套路。更一般的做法是 Box–Cox 变换 y^λ，λ 可估计，λ=0 时退化为对数。

2. 经典分解：移动平均抓趋势#

最朴素的做法来自经典分解（classical decomposition）：

第一步，用移动平均估计趋势。 对周期为 m 的季节序列，取 m 阶的中心化移动平均：

T̂_t = (y_{t-k} + ... + y_{t-1} + y_t + y_{t+1} + ... + y_{t+k}) / m

为什么移动平均能"抹掉"季节？因为一个完整季节周期内，季节分量 S_t 的和约为 0（加性下），平均之后就只剩趋势（和噪声）。移动平均的阶数选奇数时窗口对称好处理；偶数阶需要再平均一次做中心化（这就是 2×m 移动平均的来历）。

第二步，去趋势求季节。 用 y_t − T̂_t 得到"去趋势序列"，再对每个季节位置（如每个 1 月、每个 2 月）取平均，得到季节分量 Ŝ_t。

第三步，取残差。 R̂_t = y_t − T̂_t − Ŝ_t。

经典分解简单直观，但有几个毛病：移动平均在序列两端会丢失若干期（没有足够邻居），趋势估计对异常值敏感，且季节分量被假设成"每年完全一样、永不变化"。这些问题推动了 STL 的出现。

3. STL：季节性-趋势 Loess 分解#

STL（Seasonal-Trend decomposition using Loess）是现代分解的事实标准，几乎全面优于经典分解。它反复迭代两个步骤，把趋势和季节逐渐"磨"出来。

先认识它的砖块——Loess（局部加权回归）：给定一点 x，只取它附近的邻居，按距离远近加权，拟合一条局部直线/二次曲线来预测 x 处的值。距离越近权重越大，于是趋势可以在局部弯曲，而不是全局固定形状。

STL 的内循环（对每一轮迭代）：

  1. 去趋势：y_t − T_t^(k)；
  2. 季节子序列平滑：把去趋势序列按季节位置拆成若干子序列（所有"1 月"一条、所有"2 月"一条……），对每条子序列做 Loess，再拼回完整的季节分量；
  3. 低通滤波：对拼出的季节分量再做一次长窗口移动平均 + Loess，去掉其中残留的趋势，得到"纯季节" S_t^(k+1)；
  4. 去季节：y_t − S_t^(k+1)；
  5. 趋势平滑：对去季节序列做 Loess，得到新的趋势 T_t^(k+1)。

外循环则计算残差 R_t = y_t − T_t − S_t，用残差的大小给每个点分配一个鲁棒权重（异常点权重趋近 0），下一轮内循环的 Loess 就会自动"无视"这些异常点。这就是 STL 的鲁棒性来源。

STL 相比经典分解的优势：

  • 趋势不需要固定形状，能贴合非线性趋势；
  • 季节分量允许随时间慢慢变化（不是每年一模一样）；
  • 对异常值鲁棒；
  • 可以处理任意频率的季节（周、月、甚至每天每小时）。

4. 分解之后做什么#

分解本身不是预测，而是预处理和洞察：

  • 季节调整：y_t − Ŝ_t 得到去掉季节影响的序列，常用于经济指标（如 CPI 环比）的跨期比较；
  • 看清趋势：把 T̂_t 单独拿出来，判断业务是在扩张还是收缩；
  • 对残差建模：确认 R̂_t 是否接近白噪声，若仍有结构（如自相关），说明还有信息没被趋势/季节解释，需要进一步建模。

二、可运行示例#

构造一条"趋势 + 变化幅度季节 + 噪声"的月度序列，分别用经典分解和 STL 拆解。

import numpy as np
import pandas as pd
from statsmodels.tsa.seasonal import seasonal_decompose, STL

# 构造 60 个月（5 年）数据：线性趋势 + 周期 12 的季节 + 噪声
idx = pd.date_range("2018-01-01", periods=60, freq="MS")
n = len(idx)
rng = np.random.default_rng(3)
trend = 20 + 0.4 * np.arange(n)                       # 线性上升趋势
season = 8 * np.sin(2 * np.pi * np.arange(n) / 12)    # 固定幅度的季节
noise = rng.normal(0, 2, size=n)
y = trend + season + noise
series = pd.Series(y, index=idx)

# 1) 经典加性分解（周期 m=12）
res_classic = seasonal_decompose(series, model="additive", period=12)
print("经典分解分量：")
print(pd.DataFrame({
    "趋势": res_classic.trend.round(2),
    "季节": res_classic.seasonal.round(2),
    "残差": res_classic.resid.round(2),
}).head(6))

# 2) STL 分解（robust=True 打开外循环的鲁棒权重）
res_stl = STL(series, period=12, robust=True).fit()
print("\nSTL 分解后残差标准差：", round(res_stl.resid.std(), 3))

# 3) 验证：加性分解的残差应接近白噪声
print("STL 趋势最后 3 期：", np.round(res_stl.trend[-3:], 2))
print("STL 季节前 12 期（一个周期）：", np.round(res_stl.seasonal[:12], 2))

注意经典分解的前后各 6 期（半周期）趋势是 NaN，因为中心化移动平均在两端没有足够邻居；而 STL 用 Loess 外推，能给到接近两端的位置——这也是 STL 更实用的原因之一。

换一个"波动随水平放大"的序列，试试乘性分解：

# 乘性序列：季节是比例，波动随趋势放大
trend_m = 20 + 0.4 * np.arange(n)
season_m = 1 + 0.2 * np.sin(2 * np.pi * np.arange(n) / 12)
y_m = trend_m * season_m + rng.normal(0, 2, size=n)
series_m = pd.Series(y_m, index=idx)

# 方法一：直接乘性分解
res_m = seasonal_decompose(series_m, model="multiplicative", period=12)
print("\n乘性分解季节分量(前12期)：", np.round(res_m.seasonal[:12], 3))

# 方法二：取对数转加性，再用 STL（等效且更鲁棒）
stl_log = STL(np.log(series_m), period=12, robust=True).fit()
print("对数-加性 STL 残差标准差：", round(stl_log.resid.std(), 3))

两条路线得到一致结论：乘性序列可以先取对数，再套加性分解工具。

三、练习#

  1. 把 season 的幅度改成"随时间线性增大"（模拟波动逐年放大），分别用加性和乘性分解，比较两种模型残差的标准差，说明哪种更合适。
  2. 用 statsmodels.datasets.co2.load_pandas() 加载真实 CO₂ 浓度数据，对 co2 列做 STL（周期 12），观察趋势与季节分量；思考为什么 CO₂ 序列更适合"趋势 + 强季节"的分解。
  3. 解释：为什么周期 m 为偶数时，经典分解需要做 2×m 中心化移动平均，而不是直接用 m 阶？
  4. 思考：如果残差 R_t 的 ACF 在第 1 阶仍显著不为 0，说明什么？分解"漏"掉了什么信息，接下来该怎么处理？
