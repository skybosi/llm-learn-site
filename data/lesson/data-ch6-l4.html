事故判定与回退：坏数据已经进了训练集怎么办#

这一节要解决什么#

前三节把管线做到了"可上线、有契约、有监控"。这一节处理剩下的那个场景：监控已经告警了，坏数据已经在训练集里了。

这是一个决策问题，而不是检测问题。它要回答四个具体问题：

  1. 跑的是哪一版？ 回退之前必须先能归因。本节实测四份指纹的分辨力：同一批打乱行序、改列顺序，内容指纹不变（hex 差异位 0）；只改一行的一个取值，差异位 59/64。
  2. 判据要在什么之前触发？ 本节实测单批 KS 与 CUSUM 的到检时间：每批 500 行时 19 批 vs 7 批（提前 12 批）；每批 10000 行时 6 批 vs 4 批（提前 2 批）。到检时间直接决定污染量：D 从 4 缩到 1，污染份额从 25% 降到 10%，总损失从 4.05 降到 1.75 人周。
  3. 回退还是继续用？ 本节给出闭式边界 ρ∗=Cunc​−Chold​−Crecor​Crebuild​​=0.25641，并给出判定对 Cunc​ 的敏感度：在实测污染率 0.119 上，Cunc​ 要涨到 5.4517（1.7037 倍，+70.4%）才翻转结论。
  4. 检测投入花多少？ 期望损失 C(x)=Cdet​x+Linc​e−λx 的最优值是 x∗=λ1​lnCdet​λLinc​​=5.7762 项，净省 6.8836 人周。它同时说明"多上一套监控"与"少上一套"都可能更贵。

本节末尾是全课收束：把第 1 章到第 6 章的骨架串成一条线。

一、回退之前的第一问：跑的是哪一版#

1.1 概念：归因需要四份指纹#

回退的粒度取决于你能把差异定位到哪一层。本节把归因需要的指纹列成四份：

    manifest_id = 12348cdbbbe5c8c06decac091bcb9414…（配方：第 1 节）
    contract_id = cc8321d6375c494d043fdd0260f21bc0…（契约：第 2 节）
    batch_fp    = e22e47c63d15252fb62cb7a90d9e3443…（这一批数据的字节）
    code_sha    = 4292086f1d116d76098f68d370cdd390…（管线的代码版本）

四者各管一段：

指纹 回答的问题 缺了它的后果
manifest_id 配方是哪一版 不知道阈值/形/种子改没改
contract_id 接口是哪一版 不知道下游被判据拒收的原因
batch_fp 这批数据的字节 回退点的边界说不清
code_sha 管线代码是哪一版 同一个 manifest 跑出不同结果

注意它们之间的关系是"与"而不是"或"：四者全对才能说"这批数据是怎么来的"。任何一份对不上，回退动作就没有依据。

1.2 内容指纹的分辨力实测#

  核对动作                                  指纹相同      hex 差异位   
  原样重算（同一批）                             是         0         
  打乱行序后重算                               是         0         
  改列顺序（字段名不变）后重算                        是         0         
  只改一行的一个取值（quality 第 137 行）            否         59

三行"相同"说明内容指纹对表示顺序不敏感：行序、列序都不改变它（因为它在哈希前先排序）。这是设计选择，好处是"同一批数据以不同顺序写入"不会分裂成两个版本；代价是它不能证明"写入顺序相同"——如果顺序本身有意义（例如课程式训练的样本顺序），必须额外记录 ingest_order 或 mtime 摘要。

第四行说明它对内容变化极敏感：改一行的一个取值（quality 从 ≈0.30 变到 1.00），hex 差异位 59/64。sha256 的雪崩性意味着这个数字的期望值是 32，实测 59 属于正常波动范围。

1.3 怎么做：把归因做成"逐层二分"#

有了四份指纹，归因可以做成逐层二分：

  1. batch_fp 一致、指标不同 → 问题在训练侧（模型、超参、数据加载顺序），不在数据侧；
  2. batch_fp 不一致 → 往下比 manifest_id：一致说明管线实现变了（code_sha）或上游数据变了；不一致说明配方变了；
  3. manifest_id 不一致 → 比 canonical 字符串，直接读出改了哪个字段（第 1 节的差异位表就是干这个的）。

这套流程的价值是把"指标掉了两个点"从一个全局谜题变成一个逐层可判的二分。没有它，团队会花两天在"是不是数据的问题"上打转。

1.4 取舍与边界#

  • 四份指纹都有维护成本。code_sha 最容易漏：如果管线代码不在版本控制里，或者换了依赖版本，code_sha 相同但结果不同。要把它扩展成"代码 + 依赖锁"的哈希。
  • 指纹只能证明"相同"，不能证明"正确"。两个都错的版本可以有一致的指纹。
  • 回退点必须与冻结边界对齐。第 1 节的 manifest 是回退点的天然边界：能回到某个 manifest_id，就能说清"回到的是哪一版"。

二、增量检出：单批 KS 与 CUSUM#

2.1 概念：两类判据的形态不同#

  两种判据的形态完全不同：
    A 单批 KS：看每一批与干净参考批的绝对偏差（水平判据）
    B CUSUM  ：把每批的标准化均值累加，看累计量是否越线（变化率判据）
  • 水平判据问："现在已经偏离了多少？"它的触发条件是偏移大到一定程度；
  • 变化率判据问："偏移正在以什么速度累积？"它的触发条件是偏移持续存在一段时间。

两者的差别在慢漂移上最明显：偏移每批只加一点点，水平判据要等它攒够；变化率判据每批都在记账，几批就能越线。

2.2 实测：到检时间差多少#

  每批行数      KS 临界值          KS 到检         CUSUM h       CUSUM 到检      提前批数        
  500       0.1160          19            5.40          7             12          
  2000      0.0580          11            5.40          6             5           
  10000     0.0255          6             5.40          4             2

漂移设定是每批 +0.010σ 的线性增长；两个判据的弃真率都控制在"约 60 批一次"的量级（KS 用 5% 经验分位，CUSUM h=5.4 的实测 ARL =45 批）。

读表要读最后一列的递减：每批 500 行时 CUSUM 提前 12 批，每批 10000 行时只提前 2 批。原因很直接：单批样本越大，KS 的临界值越小（0.1160→0.0255），单批自己就越灵敏；CUSUM 的优势来自"把多批的偏移累加"，当单批已经足够时，累加带来的边际收益就小了。

2.3 为什么 CUSUM 不能单独用：突变的拖尾#

  批号   偏移      当天 KS       CUSUM S       越线判据

  3    0.00    0.03050     2.814         无           
  4    0.30    0.14400     16.377        KS+CUSUM

第 4 批一个 0.30σ 的跳变，KS 与 CUSUM 同日越线。但第 5 批起，KS 已经回到基线（0.02750，未越线），而 CUSUM 的 S 还在 15.6，继续报警到第 11 批。

这是 CUSUM 的结构性代价：它把历史累加，所以一次大偏移会污染后面很多批的读数。S 要回落到 0 才安静，而回落速度取决于后续批的均值（在基线附近，S 下降很慢）。

所以生产里两条判据并联：KS 管突变（当日拒收），CUSUM 管慢漂移（提前告警）。并且要给 CUSUM 加一条"复位规则"（例如"已确认事故后强制复位"），否则一次事故会让监控连响两周。

2.4 取舍与边界#

  • CUSUM 的 h 与 ARL 是一对。h 大 → 误报少但到检慢。本节用 h=5.4 对应 ARL ≈45 批，与 KS 的观察窗口同量级。选 h 时要比的是两种判据在同一误报预算下的到检时间，而不是各自的默认值。
  • CUSUM 假设偏移是持续的。对脉冲式故障（来一次就走），它反而比 KS 差。
  • 两者都需要干净参考。参考批一旦被污染，两个判据都会"习惯"新的分布。

三、到检时间与污染量#

3.1 公式#

设每天新增数据占总量的比例 s，一天坏批的期望损失 L，回收率随滞后从 1 线性降到 0，则到检延迟 D 天的总损失：

总损失(D)=Li=0∑D​(1−si)

3.2 实测#

  到检天数 D      污染份额          未回收损失           总损失(含回收)        未回收占比       
  1           0.10          0.09            1.75            0.05        
  2           0.15          0.14            2.56            0.05        
  3           0.20          0.18            3.33            0.05        
  4           0.25          0.23            4.05            0.06        
  6           0.35          0.32            5.36            0.06        
  到检从 D=4 缩到 D=1：污染份额 25% -> 10%，总损失 4.05 -> 1.75 人周

顺带一个容易被忽略的细节：未回收损失占比只有约 5%。这说明在这个模型里，绝大部分损失来自"被污染的数据虽然能回收、但回收不干净"的那部分，而不是"彻底找不回来"的那部分。这个结论会直接影响决策：提升回收率（例如更好的按行溯源）与提前到检同样重要，而前者往往被忽略。

3.3 边界#

  • "回收率随滞后线性下降"是模型假设。真实系统里它可能是阶梯的（例如"上一个 checkpoint 之后的数据全部可回收"）。
  • 污染份额不等于损失份额。25% 的污染份额并不等于"模型效果掉 25%"：损失函数对污染的敏感度是非线性的（第 4 章的合成数据实验就是这个问题）。
  • D 的度量要写清：是"批次"还是"天"？本节的表按天算，且假定每天一批。多批/天时要把 s 换成"每批新增占比"。

四、判定：回退清洗 vs 继续使用#

4.1 模型#

两个动作：

Costrollback​(ρ)=Crebuild​+Crecor​ρ,Costreuse​(ρ)=(Cunc​−Chold​)ρ

其中 ρ 是已污染 token 占未修正总预算的比例，Crebuild​ 是重建到冻结点（与 ρ 无关），Crecor​ 是按比例重算的单位成本，Cunc​ 是满污染时带毒训练的损失，Chold​ 是持币（不训练）的机会成本。

4.2 实测与闭式边界#

  rho     Cost_rollback（回退）     Cost_reuse（继续用）       结论          
  0.02    0.5150                0.0540                继续用         
  0.05    0.5375                0.1350                继续用         
  0.10    0.5750                0.2700                继续用         
  0.12    0.5893                0.3213                继续用         
  0.19    0.6395                0.5022                继续用         
  0.25    0.6875                0.6750                继续用         
  0.40    0.8000                1.0800                回退          
  0.60    0.9500                1.6200                回退          
  闭式边界：C_rebuild + C_recor*rho = (C_unc - C_hold)*rho
    => rho* = C_rebuild / (C_unc - C_hold - C_recor)
    rho*（闭式）= 0.25641；rho*（数值找交点，步长 1e-5）= 0.25641

两个退化条件值得单独写出来：

  • 若 Cunc​−Chold​≤Crecor​，则 ρ∗≥1：回退永远不划算。含义是"带毒训练没那么贵，或按比例重算没那么便宜"。这对应一些真实情形：下游有强正则约束、或者重算一次要两周。
  • 若 Crebuild​ 很大，ρ∗ 靠近 1：回退只在几乎全污染时才值得。

4.3 真正的边界：判定对 Cunc​ 有多敏感#

闭式边界 ρ∗ 依赖四个成本参数，其中 Cunc​ 是最难估的（"带毒训练到底损失多少"）。把 ρ 固定在实测值 0.119，反解"两个动作打平"的 Cunc​：

Cunc∗​=Chold​+ρCrebuild​+Crecor​ρ​

Cunc∗​=Chold​+ρCrebuild​+Crecor​ρ​

实测：

    C_unc* = C_hold + (C_rebuild + C_recor*rho)/rho = 5.4517 人周损耗 / 满污染预算
    而当前估计 C_unc=3.20 —— 判定的裕度 = 1.7037 倍（估计值要涨 70.4% 才翻转）

1.7037 倍就是这个决策的稳健性。它比"ρ=0.119<0.25641，所以继续用"有用得多，因为后者把 Cunc​=3.20 当成了事实。

这里与第 5 章第 4 节的"回滚点三元组"是同一个判断的两个刻度：第 5 章回答"能不能回到某个点"（需要数据版本 + 配比 + 阶段表三样齐全），本节回答"值不值得回去"（需要 ρ 与四个成本参数）。前者是能力，后者是定价；只有能力没有定价，回退会被滥用成"出事就重跑"。

所以回退判定的第一步不是算 ρ，而是把 Cunc​ 的上界写下来：只要上界 <Cunc∗​，就继续用并加正则；否则回退。

4.4 可选动作不止两个#

    rho=0.050：整批重跑 4.60 人周；继续用+正则抑制 0.1350 人周；按行清洗（只重跑受影响的 K=3 步） 2.70 人周
    rho=0.119：整批重跑 4.60 人周；继续用+正则抑制 0.3213 人周；按行清洗（只重跑受影响的 K=3 步） 2.70 人周
    rho=0.300：整批重跑 4.60 人周；继续用+正则抑制 0.8100 人周；按行清洗（只重跑受影响的 K=3 步） 2.70 人周
    rho=0.500：整批重跑 4.60 人周；继续用+正则抑制 1.3500 人周；按行清洗（只重跑受影响的 K=3 步） 2.70 人周

三个动作的成本形态完全不同：

  • 整批重跑：与 ρ 无关（重来一遍），4.60 人周；
  • 继续用 + 正则抑制：随 ρ 线性涨，0.1350→1.3500；
  • 按行清洗（只重跑受影响的 K=3 步）：固定 2.70 人周。

三条线的交点给出三档策略：ρ 小 → 继续用；ρ 中 → 按行清洗；ρ 大 → 整批重跑。注意"按行清洗"要求按行溯源（能定位哪些行来自哪个坏批）—— 这是第 2 章内容指纹与批次台账的直接用途。

4.5 取舍与边界#

  • ρ 本身要估。它来自"坏批影响了多少 token"，而这需要批次台账与去重后的计数。没有台账，ρ 就只能拍。
  • 成本模型只能给可行动作排序。如果污染是"数据源被撤销授权"，继续用不是选项，回退是唯一合法动作——这时模型无话可说。
  • 决策要留证据。把 ρ、四个成本参数、Cunc​ 的裕度一起写进事故记录，半年后重看才能复盘。

5.1 公式与实测#

C(x)=Cdet​x+Linc​e−λx ⟹ x∗=λ1​lnCdet​λLinc​​

取 Cdet​=0.15 人周/项、Linc​=8.00 人周/次、λ=0.60：

  投入 x      投入成本            事故期望              合计              
  0.0000    0.0000          8.0000            8.0000          
  2.0000    0.3000          2.4096            2.7096

  x*（闭式：rate*L_inc*exp(-rate*x)=C_det）= 5.7762 项

  闭式复核：rate*L_inc*exp(-rate*x*) = 0.150000（应等于 C_det=0.15）

x∗=5.7762 是内点解：x=6 与 x=5.7762 的合计只差 0.0022 人周（1.1186 vs 1.1164），说明在最优点附近很平坦；但 x=14 的合计是 2.1018，比最优高 88%。

5.2 为什么"多上一套监控"可能更贵#

C(x) 的两项方向相反：Cdet​x 线性增长，Linc​e−λx 指数下降。当 x 超过 x∗ 之后，新增监控的边际收益（λLinc​e−λx）低于它的边际成本（Cdet​）。

这给出一个可判的条件：第 1 项监控值得上，当且仅当 λLinc​>Cdet​。本节 0.6×8.0=4.8>0.15，所以值得；如果 Linc​ 只有 0.2 人周，0.12<0.15，那么任何监控都是净支出。

5.3 边界#

  • x 的"项"要归一化。与第 1 节的 m 一样，不同监控项的成本差异很大，要按成本折算成"标准项"。
  • λ 不是常数。真实系统里每加一项监控的边际衰减会变（前几项抓大头，后面越来越难）。这时 x∗ 要用数值扫，而不是闭式。
  • "检测投入"与"回退能力"是两笔预算。x 降低的是事故发生频率，ρ∗ 那套降低的是事故损失。两者要一起看：如果回退很便宜（Crebuild​ 小），可以少花检测预算。

六、全量回滚的成本与确定性重放#

6.1 全量回滚不是免费的#

  回滚到上一个冻结点的成本 = 重建 K=4 步 + 重训，第 i 步成本 0.8^i 人周：
    1.0000 + 0.8000 + 0.6400 + 0.5120 = 2.9520 人周
  与继续用（rho=0.119）的 0.3213 人周相比：回滚更贵

注意这里的 2.9520 与 §4 的 Crebuild​=0.5 口径不同：前者是按步骤摊开算的成本上界（每一步都重跑），后者是"回退到冻结点并重算受影响部分"的合并估计。两个数都要在事故记录里出现，因为它们回答不同的问题：0.5 用于决策，2.9520 用于说明"回退不是免费的、上限在哪"。

6.2 确定性重放的两个反例#

    同一批、行序不同                 内容指纹是否与参考一致：是
    同一批、改一个取值                内容指纹是否与参考一致：否
    结论 1：内容指纹不依赖行序（先排序再哈希），所以它能证明字节相同；
            它不能证明写入顺序相同 —— 需要额外记 ingest_order 或 mtime 摘要。
    结论 2：解析器必须把未登记字段当错误而不是忽略，否则改一个取值这种改动
            在只做 schema 校验的实现里会被静默吸收（第 2 节块 1 的类型判据同理）。

两个反例指向同一条原则：确定性重放能覆盖的范围，取决于你记了什么。行序、列序、字段存在性、解析器版本，每一样都要么被记进指纹、要么被写进流程纪律。指望"再跑一遍就好了"是最贵的一种假设。

6.3 取舍与边界#

  • 回滚点的粒度越细，回滚越便宜，维护成本越高。每天一个 checkpoint 比每周一个贵，但把 ρ 的上界从 25% 压到 5%。
  • "回滚"与"修复"是两条路。修复（按行清洗）需要溯源能力；回滚需要冻结边界。两者都要在平时建设，事故当天建不出来。
  • 回滚要有一次演练。没演练过的回滚路径，在事故当天大概率会卡在某个没有人记得的步骤上。

D_SLOW, REPS = 0.010, 200       # 每批新增的均值偏移；每个设置的重复次数

def ks_stat(a, b):
    a, b = sorted(a), sorted(b)
    i = j = 0
    d = 0.0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            x = a[i]; i += 1
        else:
            x = b[j]; j += 1
        while i < len(a) and a[i] == x:
            i += 1
        while j < len(b) and b[j] == x:
            j += 1
        d = max(d, abs(i / len(a) - j / len(b)))
    return d

# ---------- 判据 A：单批 KS（绝对水平判据）----------
def crit_run(n, alpha, hz=30):
    """用模拟定单批 KS 的临界值：在 hz 批纯噪声上，首次越线的比例等于 alpha（经验分位）。"""
    vals = []
    for s in range(REPS):
        r = random.Random(9000 + s)
        ref = [r.gauss(0, 1) for _ in range(n)]
        vals.append(max(ks_stat(ref, [r.gauss(0, 1) for _ in range(n)]) for _ in range(hz)))
    vals.sort()
    return vals[int((1 - alpha) * len(vals))]

def first_cross_ks(n, thr, mu_of_t, seed, hz=24):
    r = random.Random(seed)
    ref = [r.gauss(0, 1) for _ in range(n)]
    for t in range(1, hz + 1):
        if ks_stat(ref, [r.gauss(mu_of_t(t), 1) for _ in range(n)]) > thr:
            return t
    return hz + 1

# ---------- 判据 B：CUSUM（变化率判据）----------
def cusum_arl(h, reps=REPS, horizon=2000, seed=12345):
    """纯噪声下 CUSUM(参考均值 0，尺度 1) 首次越过 h 的平均批数。"""
    tot = 0
    for s in range(reps):
        r = random.Random(seed + s)
        S = 0.0
        for t in range(1, horizon + 1):
            S = max(0.0, S + r.gauss(0, 1))
            if S > h:
                tot += t
                break
        else:
            tot += horizon
    return tot / reps

def first_cross_cusum(n, h, mu_of_t, seed, hz=24):
    r = random.Random(seed)
    S = 0.0
    for t in range(1, hz + 1):
        z = (sum(r.gauss(mu_of_t(t), 1) for _ in range(n)) / n) / (1.0 / math.sqrt(n))
        S = max(0.0, S + z)
        if S > h:
            return t
    return hz + 1

小结#

  • 回退之前先能归因：四份指纹（manifest_id / contract_id / batch_fp / code_sha）缺一份，回退就是赌博。内容指纹对行序、列序不敏感（差异位 0），对取值变化极敏感（59/64）。
  • 两类判据并联：单批 KS 管突变（当日拒收），CUSUM 管慢漂移（提前告警）。实测到检提前量随每批行数递减：500 行时提前 12 批，10000 行时只提前 2 批。CUSUM 的代价是拖尾（一次突变能让它连响多批）。
  • 到检时间就是污染量：总损失(D)=L∑(1−si)，D 从 4 到 1 省 56.7%。未回收损失只占约 5%，所以"提升回收率"与"提前到检"同等重要。
  • 回退判定有闭式边界：ρ∗=Crebuild​/(Cunc​−Chold​−Crecor​)=0.25641。两个退化条件（分母 ≤0 或 Crebuild​ 很大）都有明确的工程含义。
  • 判定的稳健性要写出来：在实测 ρ=0.119 上，Cunc∗​=5.4517，是当前估计的 1.7037 倍。先估 Cunc​ 的上界，再决定回退。
  • 可选动作不止两个：继续用（随 ρ 线性）、按行清洗（要求溯源能力）、整批重跑（与 ρ 无关）。三条线的交点给出三档策略。
  • 检测投入是内点解：x∗=λ1​lnCdet​λLinc​​=5.7762 项，净省 6.8836 人周；上到 x=14 反而比最优贵 88%。
  • 全量回滚不免费：按步骤摊开是 2.9520 人周。回滚路径必须平时演练，且回滚点的粒度决定 ρ 的上界。

全课收束：第 1 章把数据放回模型里看，说明最贵的错误是静默错误——它不报错、指标不响、只改行为，所以整套课程后来做的每一件事都是在给静默错误装"对账工具"。第 2 章把原始来源变成一条确定性、幂等、带内容指纹的管线，解决的是"同一份输入能不能产出同一份字节"；第 3 章把配比与顺序写成可拒绝的命题，解决的是"数据侧的决策能不能被判据挡住"；第 4 章补齐唯一由人产生的那一段，说明标注与合成的错也不会自己响；第 5 章给所有这些产物发版本号，把"这批数据是怎么来的"变成一个可查的字段。这一章把前五章装成一条可上线的管线：第 1 节用 manifest_id 冻结配方，第 2 节用数据契约把静默错误变成响亮的拒绝，第 3 节用监控让"坏了"在损失之前触发，第 4 节用成本模型回答"坏数据已经进来了怎么办"。四节的判据形态不同，但定价方式完全一致：先量效应，再乘成本，最后写下这个结论在什么条件下翻转 —— m∗=2.2842、τ∗=0.02439、dc∗=29.8282、x∗=5.7762、ρ∗=0.25641 都是同一套算法在五个不同决策上的结果。全课最后留下的不是一个模型或一个框架，而是一种工作方式：每一个关于数据的判断，都要能给出一个可算的依据、一个数值算例，以及它失效的边界。
