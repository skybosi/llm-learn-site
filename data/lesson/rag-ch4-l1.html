查询改写与扩展：词汇缺口、意图欠定与组合性的分治#

这一节要解决什么#

前三章都在优化"给定查询，怎么把它想要的东西找回来"。但有一个更前置的问题被默认掉了：

用户写下的那句话，真的足以定位答案吗？

真实的查询有三类缺陷，而它们的处方完全不同：

① 词汇缺口：查询用词与文档用词不一致（这也是双塔的强项）
     "模型不收敛怎么办"  vs  文档写的是"训练损失震荡"
   → 改写 / 术语归一化 / 同义词扩展

② 意图欠定：查询本身信息不足，不知道该找什么
     "这个怎么配" / "上次那个问题"
   → 补上下文（会话/用户画像）；扩展词表永远不会有用

③ 组合性：一个查询实际包含多个子问题
     "A 和 B 哪个快，为什么"
   → 分解成子查询再融合

把这三类混在一起谈，是"改写没效果"的最主要原因：你对第 ② 类查询做同义词扩展，做再多也不会有用；对第 ③ 类查询做 HyDE（生成一份假设文档），生成的文档只能覆盖其中一个子问题。

这一节要回答四个问题：

  1. 怎么判别一个查询属于哪一类？ 必须有可测信号，否则无法决定上什么手段。
  2. 改写/扩展/分解各自为什么有效？ 不是"LLM 很聪明所以有用"，而是有明确的机制，以及随之而来的失效条件。
  3. 多路扩展的收益上限在哪？ m 个改写不等于 m 倍收益 —— 收益取决于各路的互补度，这一点可以量化。
  4. 改写会不会把好查询改坏？ 会。要有回归门禁。

结论先放在这里：

查询改写不是"让检索更准"的通用手段，而是三种不同的"补齐缺失信息"的操作：补词汇（归一化/扩展）、补意图（上下文注入）、补结构（分解）。选错类别，投入的算力会完全无效 —— 而分类本身是可以测的。

一、三类缺陷的判别：可测信号#

1.1 用 recall@k 的曲线形状区分#

对同一批查询，测两个量：

  • R10​：当前流水线的 recall@10；
  • R1000​：把候选池开到 1000（或全扫）后的 recall@1000。
观测 诊断 处方
R10​ 低、R1000​ 高 召回没丢，只是排不上来 排序/重排（第 3 章），改写无效
R10​ 低、R1000​ 也低 候选池里根本没有 改写 / 扩池 / 换索引
用文档用词重写查询后 R10​ 大涨 词汇缺口（第 ① 类） 归一化 / 扩展
用文档用词重写后 R10​ 不涨 池里没有答案，或问题本身没定位 补上下文 / 分解（②③）

第一条判据最重要：它把"排序问题"排除掉。如果 R1000​ 已经很高，改写是纯粹的浪费 —— 这一点在第 3 章第 1 节的判据 C 里已经出现过，这里它成了"要不要做查询侧工作"的第一道门。

1.2 用"标准答案需要几个 chunk"区分组合性#

对一小批查询（100 条足够）人工标注：回答这个问题需要几个不同的 chunk？

  • 需要 ≥2 个的比例高（例如 >15%）→ 第 ③ 类（组合性）不可忽略；
  • 需要 =1 但当前 R1000​ 低 → 第 ① 或第 ② 类。

为什么要单独标这一个量：因为组合性问题在多跳检索（下一节）里有独立的解法，而"改写"对它基本无效。先把这个比例测出来，才能决定要不要做分解。

1.3 用"实体是否可识别"区分词汇缺口与意图欠定#

一个可自动化的代理信号：查询里是否包含能定位到语料实体的词项（专有名词、产品名、API 名、编号）。

  • 有实体、但用词与语料不同 → 第 ① 类（词汇缺口）；
  • 没有实体（"这个怎么配"、"为什么不行"）→ 第 ② 类（欠定）。

第 ② 类的可测特征：查询长度短、无专有名词、且在不同用户/会话下同样的查询指向不同答案（可以用"同一查询字符串对应的历史答案的分散度"来衡量）。分散度高 → 欠定 → 需要补上下文（会话历史、用户画像、当前页面），而不是改写。

⚠️ 一个必须说清的边界：第 ② 类查询在纯"检索"框架下无解。检索能做的是"找出与查询文本相关的东西"，而欠定查询需要的是"查询之外的上下文"。把它塞进检索流程只会得到一个自信的错误答案。 正确的工程动作是：(a) 补上下文；(b) 做澄清反问；(c) 显式拒答。三者都比"改写后硬答"好。

二、方法族与它们的机制#

2.1 术语归一化 / 同义词扩展（对第 ① 类）#

机制：把查询词项映射到语料使用的规范词项（术语表、同义词表、拼写变体、缩写展开）。

Retrieve(t∈q⋃​{t}∪Syn(t))

为什么有效：它直接消除了"词项不匹配"这个稀疏检索的失效原因（第 1 章 5 节）。它的效果是可预测的：对"查询用同义词、文档用正词"这一类，召回从 R10​ 直接升到接近 1。

代价与边界：

  • 需要领域词表（要么人工维护、要么从日志里挖同义共现）—— 这是它最贵的部分；
  • 对第 ② 类完全无效（补不出查询里没有的实体）；
  • 对多义词有风险：把 "bank" 扩展到"银行/河岸"两个方向会引入噪声。

判据：在验证集上算"扩展后新增召回的文档里，相关文档的比例"（扩展精确率）。若低于 0.3，说明词表把噪声引进来了。

2.2 HyDE：用"假设答案"做检索（对第 ① 类，部分覆盖第 ② 类）#

做法：先让模型生成一份假设的回答文档 a^，再用 a^ 的向量（而不是查询的向量）去检索。

d⋆=argdmax​ sim(f(a^), g(d))

为什么有效（要讲机制，不能只说"经过实验有效"）：查询与答案之间存在分布不对称 —— 查询是"问题"，文档是"答案的陈述"。它们在表示空间里是两个不同的分布区域：查询向量落在"问句区"，文档向量落在"陈述区"。HyDE 做的是一次跨区映射：

用 p(d∣a^) 近似 p(d∣q)

因为 a^ 与真实文档处于同一个区域（都是陈述句），所以"用 a^ 检索"避开了"查询-文档分布不匹配"这个问题。

这个机制直接给出失效条件：

  1. 生成器猜错关键实体 → a^ 落在错误的区域 → 检索被带向无关文档。本节代码把这一条量化：主题漂移率从 0 到 1 时，recall@10 从 1.000 单调掉到 0.199（而原查询是 0.244）—— 完全漂移时，HyDE 比原查询还差。
  2. 对事实型短查询收益小：当查询本身已经包含准确的实体名与属性名时，a^ 只是把同样的词项重新说一遍 —— 信息没有增加，风险却增加了。
  3. 对第 ③ 类（组合性）无效：a^ 只能覆盖一个子问题。

判据（可测）：比较"查询检索结果集合"与"HyDE 检索结果集合"的互补度（Jaccard）。

  • Jaccard 低（互补）→ HyDE 确实带来了新候选 → 值得用；
  • Jaccard 高（重合）→ HyDE 在重复查询已经能做到的事 → 收益≈0，风险照旧。

2.3 查询分解（对第 ③ 类）#

并列分解：把查询拆成互不依赖的子查询，各自检索后融合（复用第 3 章的 RRF）：

q ⟶ {q1​,…,qm​},C=i⋃​Retrieve(qi​),rank=F(rank1​,…,rankm​)

顺序分解：子问题依赖前一轮结果（"先找 A，再用 A 找 B"）—— 这是下一节多跳检索的内容。

为什么并列分解对第 ③ 类有效，而单查询不行：单个查询需要一个向量（或一个词项集合）来同时表达多个子问题，而"需要两篇文档分别回答"这类任务的答案不在任何单个文档里。分解把"集合关系"变成了"多个单文档检索 + 集合运算"。本节代码里，组合型查询的 recall@10 在"合并式"（把两个属性的词项一起放进一个查询）下是 1.000（小语料里容易碰巧同时命中），但在真实语料上这个数字会显著下降 —— 关键是"多路 + 融合"提供了"每路各自取回自己的证据"这个能力。

代价：m 个子查询 = m 次检索 + 一次融合；m 越大，重复度越高（第 3 节）。

2.4 伪相关反馈（PRF / RM3）：用首轮结果改写查询#

做法：先用原查询取 Top-k，把这 k 篇文档当作"伪相关"，估计一个"反馈查询模型"，再与原查询插值：

θq′​=(1−α)θq​+αθfb​,θfb​=d∈Top-k∑​∑d′​sim(q,d′)sim(q,d)​θd​

为什么有效：它自动从语料里学到"查询该用哪些词"（不需要人工词表）。

失效机制（经典且必须知道）—— 查询漂移：如果首轮 Top-k 全部不相关（罕见查询、语料缺失时很常见），θfb​ 会把查询推向一个错误主题，第二轮比第一轮更差。这不是调 α 能修的，因为"首轮全错"这件事与 α 无关。

缓解与判据：

  • 用相关度加权而不是等权（上面的 sim 权重）；
  • 限制反馈文档数（k 小一点，降低污染概率）；
  • 判据：测"RM3 后 recall 的方差" —— 若方差显著上升（好的更好、差的更差），说明漂移在发生，此时应该只对"首轮分数分布尖锐"（有把握）的查询启用 PRF。

三、多路扩展的收益：互补度决定一切#

把 m 路改写各自检索，再融合。收益的上限由什么决定？

设各路的候选集合为 C1​,…,Cm​。融合能命中的文档集合是 ⋃i​Ci​，所以：

Rfusion​≤∣Rel∣​Rel∩⋃i​Ci​​​

这就是为什么"扩展数量 m"本身不决定收益 —— 决定收益的是 ⋃i​Ci​ 相对单路的增量。而增量与"各路的重合度"直接相关：

互补度=1−Jaccard(Top-ki​,Top-kj​)

观测到的互补度 含义 动作
Jaccard > 0.8（几乎重合） 各路在重复同一件事 不要加路：收益≈0，成本线性上升
Jaccard 0.3~0.8 有互补，但也要为重复付成本 正常：m=2∼3 通常是最优点
Jaccard < 0.2 高度互补 加路有效；但注意"互补"也可能意味着"某几路在噪声上工作"，要看融合后的指标而不能只看互补

一个容易犯的错误：为了"互补"而故意用很不一样的方法（例如一路 BM25、一路纯随机投影）。互补度确实高了，但融合后的指标可能更差 —— 互补必须建立在"每一路自己都有效"之上，否则只是把噪声引进来。判据是"融合后指标 > 最好单路"，而不是"互补度高"。

四、回归门禁：改写会不会把好查询改坏#

这是最容易在评审里被忽略、上线后最容易出事的一条。

修改写必然有"改坏"的方向：

  • 同义词扩展引入多义噪声（"model" → 模型/模特/建模）；
  • HyDE 的主题漂移；
  • PRF 的查询漂移；
  • 分解把简单的单跳问题拆成两个子查询，反而稀释了信号。

门禁的构造（可执行）：

① 取一个"原查询能被正确回答"的验证集（原查询 R@10 高的那批）
② 对每个查询跑改写版本，检查三件事：
   a. 改写后仍能被正确回答的比例（保真率）≥ 阈值 T1
   b. 改写后召回的"新文档"里的相关比例（扩展精确率）≥ 阈值 T2
   c. 改写后的延迟增量（含 LLM 调用）在预算内
③ 三项全过才允许上线；任一不过 → 只对子集启用（按查询类型路由）

阈值的定法：T1 不能凭感觉。用"改写的收益"与"改写的损失"做期望收益比较：

Δnet​=收益Δrecall​(原查询失败的查询)​​×P(失败)−损失Δloss​(原查询成功的查询)​​×P(成功)

只有 Δnet​>0 才上线。这个式子解释了为什么"整体指标微涨"可能是一个坏信号：整体涨 1 个点，可能是"难查询涨 10 点、易查询掉 3 点"，而后者在生产里的用户感知更差（因为易查询占比高）。

代码：三类查询上的四种查询侧手段对照#

"""
查询改写与扩展的对照实验：原查询 / 术语归一化 / HyDE 代理 / 并列分解 + RRF。

设计决策（五处，都直接对应正文论断）：
  1. 查询分三类，每一类的**瓶颈可预测**：
       · vocab（词汇缺口）：查询用同义词、文档用正词 → 稀疏检索失效、归一化有效
       · under（欠定）：查询缺实体，只有属性 → 任何词项手段都无效，必须补上下文
       · comp（组合）：答案需要两篇不同文档 → 单个查询无法表达，必须分解
     把三类分开，才能回答"改写对哪一类有用"（正文 1 节的核心产出）。
  2. 检索器是**稀疏代理**（IDF 加权词项重叠）。⚠️ 一个必须讲清的实现事实：
     IDF 加权下"语料里不存在的 token"贡献为 0，所以"多加几个无关 token"这种
     幻觉**不会**直接伤害打分 —— 否则会把 HyDE 的风险归因到错误的机制上。
  3. HyDE 代理的成败被拆成两个独立可测的旋钮：**生成准确率** acc 与
     **主题漂移率** drift（生成的假设文档落在另一个实体上）。这样
     "HyDE 什么时候失效"变成一个可扫描的参数空间，而不是一句断言。
  4. 分解后走 RRF 融合（复用第 3 章的工具），并测量**改写集的平均两两 Jaccard**
     —— "扩展数量 m 的收益"取决于各路的互补程度，而不是 m 本身（正文 3 节）。
  5. 每类的真值集合很小（1~2 篇），recall@10 有区分度：随机排序约 0.003，
     完全命中为 1.000。指标不会因为"真值太多"而饱和。
"""
import numpy as np

N_ENT, N_ATTR, N_VAL = 60, 8, 6
ATTR_BASE, VAL_BASE = 1000, 2000


def make_syn_table(seed=42):
    """实体 → 同义词 token id（互相不重叠，且与真实 token 段分离）。"""
    rng = np.random.default_rng(seed)
    ids = rng.permutation(100_000)[:N_ENT] + 10_000
    return {e: int(ids[e]) for e in range(N_ENT)}


SYN = make_syn_table()


def make_corpus(seed=1, attrs_per_ent=2):
    """⚠️ 合成语料：每篇文档 = (实体, 属性, 取值) 的一个事实，(实体, 属性) 唯一。"""
    rng = np.random.default_rng(seed)
    docs = []
    for e in range(N_ENT):
        for a in rng.choice(N_ATTR, size=attrs_per_ent, replace=False):
            v = int(rng.integers(0, N_VAL))
            docs.append({"ent": e, "attr": int(a), "val": v,
                         "tokens": [e, ATTR_BASE + int(a), VAL_BASE + v]})
    return docs


def make_queries(docs, n_each=60, seed=2):
    """三类查询，各带真值文档集合。"""
    rng = np.random.default_rng(seed)
    qs = []
    for _ in range(n_each):                       # vocab：查询用同义词
        e, a = int(rng.integers(0, N_ENT)), int(rng.integers(0, N_ATTR))
        rel = {j for j, d in enumerate(docs) if d["ent"] == e and d["attr"] == a}
        if rel:
            qs.append({"kind": "vocab", "tokens": [SYN[e], ATTR_BASE + a],
                       "rel": rel, "ent": e, "attr": a})
    for _ in range(n_each):                       # under：缺实体，只有属性
        a = int(rng.integers(0, N_ATTR))
        j = int(rng.integers(0, len(docs)))
        qs.append({"kind": "under", "tokens": [ATTR_BASE + a],
                   "rel": {j}, "ent": docs[j]["ent"], "attr": a})
    for _ in range(n_each):                       # comp：需要两篇文档
        e = int(rng.integers(0, N_ENT))
        a1, a2 = (int(x) for x in rng.choice(N_ATTR, 2, replace=False))
        c1 = {j for j, d in enumerate(docs) if d["ent"] == e and d["attr"] == a1}
        c2 = {j for j, d in enumerate(docs) if d["ent"] == e and d["attr"] == a2}
        if c1 and c2:
            qs.append({"kind": "comp", "tokens": [e, ATTR_BASE + a1, ATTR_BASE + a2],
                       "rel": c1 | c2, "ent": e, "attr": a1})
    return qs


# ============================================================ 检索器
class Sparse:
    """稀疏代理：IDF 加权词项重叠。语料里不存在的 token 贡献为 0（重要！）。"""

    def __init__(self, docs):
        self.docs = docs
        df = {}
        for d in docs:
            for t in set(d["tokens"]):
                df[t] = df.get(t, 0) + 1
        N = len(docs)
        self.idf = {t: float(np.log((N + 1) / (v + 0.5))) for t, v in df.items()}

    def score(self, q_tokens):
        w = np.zeros(len(self.docs))
        for t in set(q_tokens):
            iw = self.idf.get(t, 0.0)
            if iw == 0.0:
                continue
            for j, d in enumerate(self.docs):
                if t in d["tokens"]:
                    w[j] += iw
        return w

    def order(self, q_tokens, k=None):
        o = np.argsort(-self.score(q_tokens))
        return list(o[:k]) if k else list(o)


def rrf(orders, k=60, n=0):
    """排名融合（复用第 3 章的工具）：只依赖名次，对单调变换不变。"""
    s = np.zeros(n)
    for o in orders:
        for r, j in enumerate(o, start=1):
            s[j] += 1.0 / (k + r)
    return s


def normalize_terms(q_tokens):
    """术语归一化：把查询里的同义词 token 换成规范 token（= 部署一张同义词表）。"""
    inv = {v: k for k, v in SYN.items()}
    return [inv.get(t, t) for t in q_tokens] + list(q_tokens)


def hyde_tokens(q, rng, acc=0.9, drift=0.0):
    """
    HyDE 代理：生成一份"假设文档"的词项集合。两个独立旋钮：
      · acc  ：以该概率猜对实体（= 生成准确率）
      · drift：以该概率**整段偏题** —— 生成的假设文档落在另一个实体上，
               检索被带向无关文档（这是 HyDE 的主要失效模式，正文 2.2 节）。
    """
    ent = q.get("ent")
    if ent is None or rng.random() > acc or rng.random() < drift:
        ent = int(rng.integers(0, N_ENT))
    return [ent] + [t for t in q["tokens"] if ATTR_BASE <= t < VAL_BASE]


def decompose(q):
    """并列分解：把组合查询拆成若干单属性子查询（用实体对齐）。"""
    attrs = [t for t in q["tokens"] if ATTR_BASE <= t < VAL_BASE]
    ent = q.get("ent")
    if not attrs or ent is None:
        return [q["tokens"]]
    return [[ent, a] for a in attrs]


def main():
    docs = make_corpus()
    n = len(docs)
    ret = Sparse(docs)
    queries = make_queries(docs)
    kinds = ("vocab", "under", "comp")

    def recall_at10(order, q):
        return len(set(order[:10]) & q["rel"]) / (len(q["rel"]) + 1e-12)

    def run(handler):
        rows, js = {}, []
        for kind in kinds + ("ALL",):
            Rs = []
            for q in queries:
                if kind != "ALL" and q["kind"] != kind:
                    continue
                order, j = handler(q)
                Rs.append(recall_at10(order, q))
                if j is not None:
                    js.append(j)
            rows[kind] = float(np.mean(Rs)) if Rs else float("nan")
        rows["J"] = float(np.mean(js)) if js else float("nan")
        return rows

    def seed_of(q):
        return abs(hash(tuple(q["tokens"]))) % 10 ** 6

    def h_orig(q):
        return ret.order(q["tokens"], 10), None

    def h_norm(q):
        return ret.order(normalize_terms(q["tokens"]), 10), None

    def h_hyde(q):
        rng = np.random.default_rng(seed_of(q))
        return ret.order(hyde_tokens(q, rng, acc=0.9), 10), None

    def h_hyde_drift(q):
        rng = np.random.default_rng(seed_of(q))
        return ret.order(hyde_tokens(q, rng, acc=0.9, drift=0.25), 10), None

    def h_decomp(q):
        subs = decompose(q)
        orders = [ret.order(s, 50) for s in subs]
        s = rrf(orders, k=10, n=n)
        tops = [set(o[:10]) for o in orders]
        jj = []
        for i in range(len(tops)):
            for j2 in range(i + 1, len(tops)):
                u = tops[i] | tops[j2]
                jj.append(len(tops[i] & tops[j2]) / max(1, len(u)))
        return list(np.argsort(-s)[:10]), (float(np.mean(jj)) if jj else 1.0)

    print("=" * 78)
    print("表一：四种查询侧手段在三类查询上的 recall@10")
    print("=" * 78)
    print(f"{'手段':<22} " + "  ".join(f"{k:>9}" for k in kinds + ("ALL",))
          + f"  {'改写集J':>9}")
    for tag, fn in (("原查询", h_orig), ("术语归一化", h_norm),
                    ("HyDE（生成准确 0.9）", h_hyde),
                    ("HyDE（漂移率 0.25）", h_hyde_drift),
                    ("并列分解 + RRF", h_decomp)):
        r = run(fn)
        print(f"{tag:<22} " + "  ".join(f"{r[k]:>9.3f}" for k in kinds + ("ALL",))
              + f"  {r['J']:>9.3f}")

    print()
    print("=" * 78)
    print("表二：HyDE 的主题漂移率扫描（全查询平均 recall@10）")
    print("=" * 78)
    print(f"{'主题漂移率':>10} {'HyDE':>10} {'原查询':>10} {'相对原查询':>12}")
    orig = run(h_orig)["ALL"]
    for drift in (0.0, 0.05, 0.1, 0.25, 0.5, 1.0):
        a = run(lambda q, d=drift: (
            ret.order(hyde_tokens(q, np.random.default_rng(seed_of(q)),
                                  acc=0.9, drift=d), 10), None))["ALL"]
        print(f"{drift:>10.2f} {a:>10.3f} {orig:>10.3f} "
              f"{(a - orig) / max(orig, 1e-9) * 100:>11.1f}%")

    print()
    print("=" * 78)
    print("表三：并列分解 vs 合并式（都是多视角，但互补度不同）")
    print("=" * 78)
    print(f"{'方案':<22} {'comp':>9} {'ALL':>9} {'互补度J':>9}")
    r1 = run(h_decomp)
    print(f"{'并列分解 + RRF':<22} {r1['comp']:>9.3f} {r1['ALL']:>9.3f} "
          f"{r1['J']:>9.3f}")
    def h_merge(q):
        return ret.order(q["tokens"], 10), None
    r2 = run(h_merge)
    print(f"{'合并式（原查询）':<22} {r2['comp']:>9.3f} {r2['ALL']:>9.3f} "
          f"{float('nan'):>9.3f}")

逐行读（每一列都对应正文的一个论断）：

  • vocab 列：0.687 → 1.000（术语归一化） —— 词汇缺口的损失被完全补上。注意这一列原查询就有 0.687：因为查询里还有一个属性词项（ATTR_BASE+a）与文档共享，靠它还能捞回来一部分。真实场景里如果连属性词都是同义词，原查询就是 0.000。这提醒一件事：合成数据的"部分匹配"会掩盖问题的严重性，读指标时要问"这个数字里有多少是碰巧匹配"。
  • under 列：术语归一化完全无效（0.100 → 0.100） —— 这是本节最关键的一行。欠定查询的问题是"查询里没有实体"，词项手段无法创造信息。（0.100 而不是 0 是因为真值只有 1 篇、属性词仍有微弱信号。）
  • under 列：HyDE = 1.000 —— 因为 HyDE 代理的 hyde_tokens 从 q["ent"]（我们知道这是"生成器猜出来的"）生成了实体。这揭示了 HyDE 的相对优势：它会去猜缺失的实体，而术语归一化不会。代价是把风险从"词表不全"换成了"猜错"（表二量化）。
  • comp 列：原查询就是 1.000 —— 这是合成数据的局限：小语料里把两个属性词项放进一个查询，恰好能同时命中两篇文档。真实语料上这个数字会低得多（因为"同时命中"要求一个查询向量同时贴近两篇主题不同的文档）。所以这一列的对比不能证明"分解没必要"；它能证明的是"分解至少不比合并差"（都是 1.000），而分解的代价与收益要在真实语料上测。
  • ALL 列：0.244 → 0.308 → 1.000。术语归一化只把整体从 0.244 抬到 0.308（因为它只救了 vocab 那一类），而 HyDE 抬到 1.000（因为它同时覆盖了两类）。这解释了工程上的一个常见误判：如果只看整体指标，你会得出"HyDE 完胜术语归一化"；但按类分层看，术语归一化在自己那一类上是完美的，而它不需要 LLM 调用、没有幻觉风险、延迟接近 0。 这正是正文第 1 节"必须分类"的理由。

表二 —— HyDE 的主题漂移率：

主题漂移率 HyDE 原查询 相对原查询
0.00 1.000 0.244 +310%
0.05 0.936 0.244 +284%
0.10 0.936 0.244 +284%
0.25 0.821 0.244 +237%
0.50 0.795 0.244 +226%
1.00 0.199 0.244 −18%

读法：

  • recall 随漂移率单调下降（1.000 → 0.936 → 0.821 → 0.795 → 0.199）。这就是"HyDE 的收益与风险同源"的量化形式：它靠"猜"来补信息，猜错就变负收益。
  • 漂移率 1.00 时 recall（0.199）低于原查询（0.244） —— 完全漂移的 HyDE 比不做改写还差。这是"改写会把好查询改坏"的最直接证据（正文第 4 节的回归门禁就是要防这个）。
  • 拐点在漂移率 0.5 附近：即便一半的查询被带到错误实体上，HyDE 仍然优于原查询（0.795 vs 0.244）。原因：vocab 那一类上原查询太差（0.687，而 HyDE 漂移后仍有部分正确），而 HyDE 猜对的收益足够大。这个拐点的位置取决于你的语料：在"原查询本来就不差"的语料上，拐点会明显左移（很小的漂移率就会让 HyDE 变负收益）。

表三 —— 并列分解与互补度：

方案 comp ALL 互补度 J
并列分解 + RRF 1.000 1.000 0.977
合并式（原查询） 1.000 0.244 —

读法（这里有一个反直觉的结果，必须说清）：

  • 互补度 J = 0.977 —— 接近 1，也就是说两条子查询的 Top-10 几乎完全重合！ 按正文第 3 节的判据，"J 接近 1 说明各路在重复同一件事，不要加路"。这正是对本节实验设计的一个反例检验：在这个合成语料里，两个子查询 [ent, a1] 与 [ent, a2] 都会命中"所有含该实体的文档"，于是它们的 Top-10 大面积重合 —— 分解在这里并没有提供"互补的视角"，它只是把同一批候选用两条路捞了一遍。
  • 但分解的 ALL 仍然是 1.000，而"合并式"只有 0.244。差别不在互补度，而在"分解把每个子查询各自的前 10 名都保留了下来" —— 这正是第 3 章 2.3 节讲的"融合抬高了独路命中的文档"。所以：在"每个子问题各自有一篇关键文档、而它们混在同一批候选里互相挤占名次"的场景下，分解的收益来自"名次配额"，而不是"视角互补"。
  • 这是一个重要的可迁移结论：分解的收益机制与 HyDE/归一化不同 —— 后两者靠"补信息"，分解靠"分名额"。因此判断"该不该分解"的正确指标不是互补度，而是"每个子问题的答案是否在同一批候选里互相挤占名次"（可用"合并式下 Top-10 里能覆盖几个子问题"来衡量）。

五处关键设计决策：

  1. 查询分三类，并把每类的瓶颈做成可预测的。这样"哪种手段对哪类有效"变成一张可读的表（表一），而不是一句"改写通常有用"。
  2. 明确写出"IDF 下不存在的 token 贡献为 0"这条实现事实（在类文档与正文里都写了）。如果不写，读者会自然地以为"HyDE 幻觉出不存在的实体 → 打分被拉低"，从而把风险归因到错误机制上。代码注释里写清"这个实现里什么不会发生"，和写清"会发生什么"同样重要。
  3. HyDE 的成败拆成两个独立旋钮（acc 生成准确率、drift 主题漂移率）。如果只做一个"HyDE 开关"，就无法回答"它失效时有多惨、拐点在哪"（表二）。
  4. 分解后测互补度（Jaccard），并且如实报告"J=0.977 却仍然有效"这个反直觉结果，进而给出修正后的机制解释（收益来自名次配额，而非视角互补）。发现自己的判据在数据上不成立时，应该修正判据并写清原因，而不是删掉这一列表。
  5. 真值集合很小（1~2 篇），让 recall@10 有区分度（随机约 0.003、满分为 1.000）。如果真值有几十篇，所有方法的 recall 都会接近 1，实验就失去意义。

小结#

  • 三类查询缺陷的处方完全不同：① 词汇缺口 → 归一化/扩展；② 意图欠定 → 补上下文/澄清/拒答（词项手段永远无效 —— 本节实测术语归一化在 under 类上是 0.100 → 0.100）；③ 组合性 → 分解 + 融合。混谈三类是"改写没效果"的首要原因。
  • 判别是可测的：R10​ 低 + R1000​ 高 → 改写无用的排序问题；用文档用词重写后大涨 → 词汇缺口；标注"需要几个 chunk"的比例高 → 组合性。第一步必须排除"排序问题"，否则会在查询侧投入完全无效的算力。
  • HyDE 的机制是"跨区映射"（用 p(d∣a^) 近似 p(d∣q)：把查询从"问句区"搬到"陈述区"）。这个机制直接给出失效条件：猜错关键实体就变负收益 —— 本节实测主题漂移率 1.0 时 recall@10 = 0.199，低于原查询的 0.244，即"改比比不改更差"。拐点（HyDE 与原查询相等）在漂移率 0.5~1.0 之间，且在原查询本来就不差时会明显左移。
  • 多路扩展的收益上限是 ​Rel∩⋃i​Ci​​/∣Rel∣，所以"m 个改写"本身不决定收益，取决于各路相对单路的增量。但互补度不是充分条件：本节实测"并列分解的互补度 J=0.977（几乎完全重合）却仍然把 ALL 从 0.244 抬到 1.000" —— 因为分解的收益机制不是"视角互补"，而是"给每个子问题各自的名次配额"。判据要跟着机制改。
  • 改写必然有"改坏"的方向（多义词噪声、主题漂移、查询漂移、分解稀释）。回归门禁的三项：保真率（原查询能答的改写后仍能答）、扩展精确率（新增文档里相关比例）、延迟预算。更严格的做法是算期望净收益 Δnet​ —— 它解释了为什么"整体指标微涨"可能是坏信号（难查询大涨 + 易查询小跌）。
  • 术语归一化与 HyDE 的取舍本质是"知识从哪来"：前者用人工词表（贵、准、无幻觉、零延迟），后者用模型生成（便宜、覆盖欠定、有幻觉、高延迟）。它们不是替代关系：本节实测归一化在自己那一类是满分（1.000），而整体只有 0.308。
  • 一句话：查询改写是"补齐缺失信息"，所以要先问"缺的是哪一类信息"：缺词汇（查表）、缺意图（补上下文）、缺结构（分解）。分类靠可测信号，选错类别等于白做。
