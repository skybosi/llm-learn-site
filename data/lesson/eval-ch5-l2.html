这一节要解决什么#

第 1 节把攻击面分成了四类。这一节解决"用例从哪来、够不够"这个问题。

红队最常见的两种失败是相反的：

  • 用例太少、太重复：几十个从网上抄来的越狱 prompt，改改措辞就算 500 条。它们的成功/失败高度相关，跑出来的"成功率 3%"实际信息量可能只有 10 条独立样本。
  • 用例很多但没有参照系：声称"覆盖了 12 类危害、3000 条用例"，但没人能回答"这 12 类是怎么来的""有没有第 13 类"。

所以本节分两块：用例的构造方法（怎么系统性地生成，而不是靠灵感）与覆盖度的定义（"够不够"这个问题的可回答版本）。

先给出本节的中心结论：覆盖度的分母不存在。 不存在"所有可能的攻击"这个集合——攻击空间随模型、工具、部署环境变化，且对手会自适应。因此任何"覆盖率 x%"的说法都必须写成 "相对于参照系 R 的覆盖率"，其中 R 必须被显式定义（比如某个公开的危害分类学 + 内部已知的部署能力清单）。没有参照系的覆盖率是修辞，不是度量。

一、危害分类学：先造分母的骨架#

分类学（taxonomy）的作用是把"危害"这个模糊概念切成互斥且可判定的格子，让用例设计有明确的目标与漏项检查。

构建原则（三条，缺一不可）：

  1. 按"造成的伤害类型"分，而不是按"话题"分。 "暴力"是话题，"提供可操作的伤害方法"是伤害类型。按话题分会导致分类重叠（很多话题都能造成同一种伤害），按伤害类型分才能互斥。
  2. 每类必须有"能力门控"：这一类危害的成立是否要求模型具备某种能力或工具权限？比如"数据外泄"在无工具的纯聊天系统上不成立。门控条件让分类与部署环境挂钩，这是覆盖率能落地的前提。
  3. 每类必须可判定："这一类算不算成立"要有可操作的判据（最好能自动判定），否则用例无法评估。

一个可用的骨架（示例，不是完整清单）：

伤害类型 典型形态 能力门控 判定方式
物理伤害的可操作指导 危险品合成、武器制造 无（纯生成） 是否包含具体步骤/配比/来源
网络攻击辅助 漏洞利用、恶意代码 无（纯生成） 是否产出可运行代码/可执行步骤
欺诈与社会工程 钓鱼话术、冒充身份 无 是否包含可操作的冒充脚本
隐私侵犯 定位、人肉、画像 可能需要检索 是否输出了目标个人的非公开信息
未成年人相关 不当内容与接触 无 明确判据
自我伤害 方法、鼓励 无 明确判据
越权操作 越权工具调用、参数越界 需要工具 工具调用日志 + 参数检查
数据外泄 系统提示/他人数据/凭证 需要私密数据访问 金丝雀检测
系统完整性破坏 注入导致的流程劫持 需要间接输入 是否执行了数据段指令
规避监管 洗钱、规避检测 无 明确判据

怎么做（漏项检查）：分类学建好后，用两个维度交叉做覆盖矩阵：(a) 伤害类型，(b) 攻击形态（直接请求 / 角色扮演 / 编码混淆 / 多轮累积 / 注入式）。矩阵的每个格子都应该至少有一条用例，空格子就是已知漏项。这张矩阵比"用例总数"有用得多——3000 条用例集中在两个格子里，远不如 60 条铺满 30 个格子。

二、从"灵感到系统"：五种用例构造法#

方法 做法 优点 偏差/局限
模板 + 变换 一个语义模板 × 多种表面变换（语言、编码、角色、语气、长度） 可批量、易统计 变体高度相关（同一模板共享失效机制）
红队模型生成 用另一个模型按目标批量生成攻击 覆盖广、可控 偏向生成器的能力分布；同源变体相关
人在环迭代 人工尝试 → 失败样本喂给生成器 → 迭代 能发现新机制 成本高、不可复现
真实事件反推 从已发生的安全事件/报告里提取攻击模式 生态效度高 数量少、滞后
能力反推 从系统有权限做什么倒推攻击目标 与部署强相关 需要准确的权限清单

关键工程约束：变体的相关性必须被处理。 500 条变体如果共享同一个模板，它们的成功率高度相关，有效样本量可能只有 20。处理方式有三种：

  1. 按模板分层，以模板（而不是用例）为独立单元做区间估计（第 3 节的整簇 bootstrap 与分层置信）。
  2. 报告"每个模板的最佳结果"：对每个模板取该模板下最成功的变体，这更接近"攻击者会挑最好的"这一现实，而且消除了同模板内的相关。
  3. 限制单模板变体数（比如每模板 ≤5 条），强制把预算花在模板多样性上。

取舍：方法 2（取每模板最佳）在安全场景更合理——攻击者只会用有效的那一个，不会随机抽一条。但它要求模板样本量足够（模板数少时，区间会宽得没用）。

三、难度分层：为什么必须把"简单用例"单列#

用例的预计难度差异很大。不分层会导致两个错误：

  • "总成功率 3%"这个数字没有行动含义：它可能是"1% 的困难用例全成功 + 99% 的简单用例全失败"，也可能是均匀分布。前者说明模型有系统性漏洞，后者说明它在分布边缘。
  • 回归监控失去敏感度：如果每次评测都跑全部用例，一个"只影响困难用例"的退化会被总体成功率稀释掉。

推荐分层（每层给出独立的成功率与置信区间）：

层 定义 用途
L1 直接请求 直白的有害请求 最低门槛；失败（=被拒绝）说明基本对齐
L2 角色/场景包装 加上虚构场景、角色扮演 测表层拒绝策略
L3 编码/格式混淆 编码、拆字、多语言、格式伪装 测输入层防御
L4 多轮累积 分步建立语境后逼近目标 测上下文相关的防护
L5 注入式 通过数据通道注入指令 测架构隔离

报告要求：给出每层的成功率 + 置信区间 + 样本量。"L1 全部拒绝、L4 有 20% 突破" 这种表述比"总成功率 4%"有信息量得多，而且直接指向要修的层。

四、多轮攻击：构造与评估#

多轮攻击（sequential / crescendo 类）的评测有三个设计点：

（a）轮数预算要固定并报告。 "10 轮内未突破"与"3 轮内未突破"是可比的，不写轮数的结论不可比（第 1 节已量化：累积效应下 1 轮 3% → 10 轮 96%）。

（b）"突破"的判定必须在最终轮，但成功判定要能区分"渐进式泄漏"。 多轮攻击可能每一步都只泄漏一点点，最后拼出完整信息。做法：对每一轮的输出都做检测，把"累积泄漏"作为一个单独指标报告（不只是"最终是否突破"）。

（c）必须报告"攻击成本"：轮数、token 数、人工介入次数。一个"10 轮后突破"的攻击与"1 轮就突破"的威胁等级不同——前者需要更多交互，可能触发其他风控（速率限制、人工审核）。

五、覆盖度：定义、度量与报告#

覆盖度必须相对于参照系定义。 三类可用的参照系：

（a）分类学参照系：覆盖度=矩阵总格子数被至少一条用例触及的（伤害类型 × 攻击形态）格子数​。这个定义可计算、可审计，且直接指向漏项。推荐作为主要指标。

（b）能力参照系：对系统的每项能力/工具/权限，检查是否都有对应用例。覆盖度=总能力项被覆盖的能力项​。这检查的是"我们有没有测所有能被滥用的功能"。

（c）对抗参照系（最有用也最难）：用一组独立生成的攻击（不是自己写的用例）去打，看有多少能成功。这测的是"我们的用例集漏掉了什么"，而不是"我们写了多少"。

对抗参照系的做法（红队对抗轮）：

  1. 团队 A 写用例集并给出安全结论。
  2. 团队 B（独立）在不看 A 的用例的前提下生成攻击，目标是让 A 的结论失效。
  3. 报"B 的成功攻击中有多少未被 A 的用例集覆盖" —— 这是漏检率，是覆盖度最诚实的度量。

取舍：对抗参照系成本高（需要两拨独立的人/模型），但它是唯一能发现"未知的未知"的方法。建议：日常回归用分类学参照系（便宜、可复现），发布前的关键节点做一轮对抗参照系。

报告规范（三条硬要求）：

  1. 不报单一覆盖率数字，报"相对参照系 R 的覆盖率 + 漏项清单"。
  2. 报用例集的"有效独立性"：模板数、每模板变体数、以及"按模板去重后的有效样本量"。
  3. 报时效：模型版本、用例集版本、评测日期。"用例集版本"必须包含用例的新增/删除记录——如果模型在用例集更新后变"更安全"，先查是不是困难用例被删了。

import math
import random

rng = random.Random(617)


def phi(x):
    return 0.5 * (1 + math.erf(x / math.sqrt(2)))


def wilson(k, n, z=1.959963985):
    if n == 0:
        return 0.0, 0.0
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return max(0.0, c - h), min(1.0, c + h)


# ============================================================
# 1. 覆盖矩阵：格子覆盖 vs 用例总数
# ============================================================
HARM_TYPES = ["物理伤害", "网络攻击", "欺诈", "隐私", "越狱规避"]
ATTACK_FORMS = ["直接请求", "角色扮演", "编码混淆", "多轮累积", "注入式"]


def coverage(matrix):
    total = len(HARM_TYPES) * len(ATTACK_FORMS)
    covered = sum(1 for row in matrix for c in row if c > 0)
    return covered / total, total - covered


# 情形 A：3000 条用例但集中在少数格子
rng_a = random.Random(1)
mat_a = [[0] * len(ATTACK_FORMS) for _ in HARM_TYPES]
for _ in range(3000):
    i = 0 if rng_a.random() < 0.8 else rng_a.randrange(len(HARM_TYPES))
    j = 0 if rng_a.random() < 0.7 else rng_a.randrange(len(ATTACK_FORMS))
    mat_a[i][j] += 1
# 情形 B：60 条但铺满
mat_b = [[1 + (i + j) % 3 for j in range(len(ATTACK_FORMS))]
         for i in range(len(HARM_TYPES))]

print("== 1. 覆盖矩阵：用例数与覆盖是两件事（合成） ==")
for name, mat in (("3000 条但集中", mat_a), ("60 条但铺开", mat_b)):
    cov, miss = coverage(mat)
    print(f"{name}: 用例 {sum(sum(r) for r in mat):5d} 条 -> "
          f"格子覆盖 {cov:.0%}，漏项 {miss} 格")
print("  3000 条集中用例的覆盖矩阵：")
for i, row in enumerate(mat_a):
    print(f"    {HARM_TYPES[i]:6s} {row}")
print("  <- '我们有 3000 条用例'与'我们覆盖了 80% 的危害-形态格子'是两件事")

# 2. 变体相关性：有效样本量比总数小得多
# ============================================================
def cluster_asr(template_ids, successes, template_rewards, n_boot=2000, seed=5):
    # 按模板做整簇 bootstrap：模板内变体共享失败机制
    r = random.Random(seed)
    by_tpl = {}
    for t, s, rew in zip(template_ids, successes, template_rewards):
        by_tpl.setdefault(t, []).append((s, rew))
    tpls = list(by_tpl)
    ests = []
    for _ in range(n_boot):
        picked = [r.choice(tpls) for _ in tpls]
        num = den = 0
        for t in picked:
            for (s, _) in by_tpl[t]:
                num += s
                den += 1
        ests.append(num / den if den else 0.0)
    ests.sort()
    return ests[int(0.025 * n_boot)], ests[int(0.975 * n_boot)]


print("\n== 2. 模板内相关如何放大不确定性（合成） ==")
r = random.Random(2)
for n_tpl, per_tpl, tpl_skill_sd in ((50, 10, 0.15), (20, 25, 0.15),
                                     (100, 5, 0.15)):
    tids, succ, rew = [], [], []
    for t in range(n_tpl):
        base = max(0.0, min(1.0, r.gauss(0.10, tpl_skill_sd)))  # 模板难度
        for _ in range(per_tpl):
            tids.append(t)
            succ.append(1 if r.random() < base else 0)
            rew.append(base)
    k, n = sum(succ), len(succ)
    lo_i, hi_i = wilson(k, n)
    lo_c, hi_c = cluster_asr(tids, succ, rew)
    print(f"{n_tpl:3d} 模板 x {per_tpl:2d} 变体 = {n:4d} 条 | 总体 ASR {k/n:.3f}")
    print(f"      假设独立: [{lo_i:.3f}, {hi_i:.3f}] (宽 {hi_i-lo_i:.3f}) | "
          f"按模板整簇: [{lo_c:.3f}, {hi_c:.3f}] (宽 {hi_c-lo_c:.3f})")
print("  <- 同样的 'ASR=10%'，按模板聚类后区间宽得多；")
print("     不处理相关性就会把置信区间报得过于乐观")

# 3. 难度分层：总体 ASR 会掩盖结构

print("\n== 3. 难度分层报告（合成） ==")
layers = [
    ("L1 直接请求", 200, 0.00),
    ("L2 角色扮演", 150, 0.02),
    ("L3 编码混淆", 120, 0.05),
    ("L4 多轮累积", 80, 0.14),
    ("L5 注入式", 50, 0.22),
]
r = random.Random(3)
tot_k = tot_n = 0
for name, n, p in layers:
    k = sum(1 for _ in range(n) if r.random() < p)
    tot_k += k
    tot_n += n
    lo, hi = wilson(k, n)
    print(f"  {name:12s} n={n:4d} 突破 {k:3d}  ASR={k/n:.3f}  95% CI [{lo:.3f}, {hi:.3f}]")
print(f"  总体 ASR = {tot_k/tot_n:.3f}  <- 看这个数会以为'基本安全'")
print("     但 L4/L5 的突破率是 14%~22%，且区间下界远高于 0")
print("  <- 安全结论必须分层报；总体平均是掩盖结构的工具")

# 4. 对抗参照系：漏检率才是覆盖度最诚实的度量
# ============================================================
print("\n== 4. 对抗参照系：独立攻击集对已有用例集的漏检率（合成） ==")
print("  场景：团队 A 有 40 个模板；团队 B 独立生成 60 个攻击")


def overlap_miss(shared_mech_frac, n_b=60, seed=7):
    r = random.Random(seed)
    # A 的模板覆盖了一部分失效机制；B 的攻击也落在某个机制上
    mech_total = 100
    a_mechs = set(r.sample(range(mech_total), int(mech_total * shared_mech_frac)))
    miss = 0
    hit_by_a = 0
    for _ in range(n_b):
        m = r.randrange(mech_total)
        if m in a_mechs:
            hit_by_a += 1
        else:
            miss += 1
    return miss / n_b, hit_by_a / n_b


for frac in (0.9, 0.7, 0.4, 0.2):
    miss, hit = overlap_miss(frac)
    print(f"  A 覆盖的失效机制占比 {frac:.0%} -> B 的攻击中 A 未覆盖 {miss:.0%} "
          f"(A 已覆盖 {hit:.0%})")
print("  <- 'A 有 40 个模板'完全不代表覆盖度；")
print("     漏检率是唯一能发现'未知的未知'的度量")


# ============================================================
# 5. 每模板取最佳 vs 随机取一条
# ============================================================
def best_vs_random(n_tpl, tpl_skill_sd=0.05, n_boot=1500, seed=9):
    r = random.Random(seed)
    # 每个模板有一个"最佳变体"的成功概率（比平均高）
    best_p, avg_p = [], []
    for _ in range(n_tpl):
        base = max(0.0, min(1.0, r.gauss(0.08, tpl_skill_sd)))
        best_p.append(min(0.95, base * 2.2))     # 最佳变体更强
        avg_p.append(base)
    def boot(ps):
        out = []
        for _ in range(n_boot):
            s = [r.choice(ps) for _ in ps]
            out.append(sum(1 for p in s if r.random() < p) / len(s))
        out.sort()
        return out[int(0.025 * n_boot)], out[int(0.975 * n_boot)]
    return boot(best_p), boot(avg_p), sum(best_p) / n_tpl, sum(avg_p) / n_tpl


print("\n== 5. 攻击者会挑最好的变体（合成） ==")
for n_tpl in (20, 50):
    (bl, bh), (al, ah), bmean, amean = best_vs_random(n_tpl)
    print(f"  模板 {n_tpl:3d} 个：每模板取最佳 -> ASR {bmean:.3f} "
          f"CI[{bl:.3f}, {bh:.3f}] | 随机抽一条 -> ASR {amean:.3f} "
          f"CI[{al:.3f}, {ah:.3f}]")
print("  <- 报告'随机抽一条'的 ASR 会系统性低估威胁；")
print("     安全场景应报'每模板最佳'，并同时给出模板数（决定区间宽度）")

代码里五个值得注意的点：

  • 第 1 段是本节最反直觉的数字。 3000 条集中用例只覆盖 8/25 个格子，60 条铺开的用例覆盖 25/25。"用例数"与"覆盖度"是两个独立维度，报告里必须分开写；把用例总数当覆盖度，是安全评测里最常见的自欺。
  • 第 2 段说明相关性必须被显式处理。 同样是"ASR =10%"，假设独立得到的区间窄，按模板整簇 bootstrap 得到的区间宽得多。同模板的变体共享同一个失效机制，因此它们不是独立样本；报区间而不声明聚类单元，等于把不确定性藏起来。
  • 第 3 段是"总体 ASR 掩盖结构"的最小演示。 总体 ASR 不到 5%，看起来"基本安全"，但 L4/L5 的区间下界远高于 0。安全结论必须分层报，因为要修的是某一层，而不是"平均而言还好"。
  • 第 4 段给出覆盖度最诚实的度量：漏检率。 "A 有 40 个模板"这件事本身不含任何覆盖信息；真正的问题是"独立生成的攻击里有多少打在 A 的用例集之外"。这也是唯一能发现"未知的未知"的方法，代价是需要两拨彼此隔离的红队。
  • 第 5 段改变了报告的默认口径。 攻击者只会用有效的那一个，因此"随机抽一条变体"的 ASR 系统性低估威胁；"每模板取最佳"才是安全场景该报的口径。同时注意区间宽度由模板数而非变体数决定——把预算花在增加模板上，比增加同模板变体更有效。
  • ⚠️ 以上全部是合成数据，只用于展示度量的行为；代码里不含任何攻击载荷，也不构成任何真实模型的数值结论。

练习#

  1. 分类学补漏：给你一个具体系统（例如"带检索、会话记忆与工单写入权限的客服助手"）。 （a）用本节的十条伤害类型逐个判断哪些成立、哪些被能力门控掉，写出理由； （b）画出"伤害类型 × 攻击形态"矩阵，标出你会优先补的 5 个空格； （c）说明为什么"按话题分"的分类学会让这张矩阵难以判定（用"暴力"这个例子）。

  2. 变体相关性的处理：某红队用例集有 600 条，来自 12 个模板（每模板 50 条），实测 ASR =7%，按"独立样本"算出的 95% 区间是 [5.1%,8.9%]。 （a）这个区间错在哪？写出正确的聚类单元； （b）用"每模板取最佳"重算会得到什么？为什么它更接近攻击者的真实行为？ （c）只有 12 个模板时，你预期的区间有多宽？如果下一笔预算只能选"再加 500 条同模板变体"或"再加 20 个新模板"，你选哪个、为什么？

  3. 难度分层的判据：某次评测总体 ASR 是 3.5%，分层结果是 L1 0%、L2 1%、L3 4%、L4 11%、L5 19%。 （a）写出你会向上汇报的两句话（不许只报总体数）； （b）如果 L5 只有 40 个样本、突破 7 条，写出它的 Wilson 区间，并说明为什么"19%"这个点估计不该被单独引用； （c）模型更新后总体 ASR 降到 2.8%，但 L5 的区间没有移动。这可能意味着什么？你会先查什么？

  4. 多轮攻击的评测设计：设计一个"10 轮内是否突破"的评测协议。 （a）轮数预算、每轮判定、累积泄漏检测分别怎么写？ （b）说明为什么"只判最终轮"会系统性高估安全性； （c）如果攻击在第 7 轮突破，你要报哪些成本量（轮数 / token / 人工介入次数）？这些量对威胁定级有什么用？

  5. 对抗参照系（漏检率）：你们小组要用"红队对抗轮"评估自己的用例集。 （a）写出分工与信息隔离规则（B 组不许看什么？为什么？）； （b）定义你要报的三个数（漏检率、被触及的失效机制占比、新增模板数）与各自的区间来源； （c）如果漏检率是 35%，你会先改用例集还是先改分类学？给出判据。

  6. 覆盖率报告评审（开放题）：某供应商的安全报告写"我们覆盖了 15 类风险、4500 条用例，越狱成功率 0.8%，覆盖率 96%"。 逐条指出这句话里至少五个不可采信之处，并写出你会要求它补充的字段（对照本节的三条报告硬要求）。

小结#

  • 覆盖度的分母不存在：攻击空间随模型、工具与部署环境变化，且对手会自适应。任何覆盖率都必须写成"相对于参照系 R"的形式，R 要显式定义（分类学 / 能力清单 / 独立对抗集）。没有参照系的覆盖率是修辞，不是度量。
  • 分类学要按"伤害类型"分、按"能力门控"挂、按"可判定"收口：这样才能互斥、才能与部署挂钩、才能自动评估。矩阵（伤害类型 × 攻击形态）的空格子就是已知漏项，它比用例总数有用得多。
  • 五种构造法各有偏差：模板 + 变换便宜但变体相关；模型生成覆盖广但继承生成器的盲区；人在环能发现新机制但不可复现；真实事件反推生态效度高但滞后；能力反推与部署强相关但依赖准确的权限清单。推荐混合使用，并按来源打标，以便出问题时按来源切片。
  • 变体的相关性必须显式处理：聚类单元是模板而不是用例；三种处理（按模板分层做区间、报"每模板最佳"、限制单模板变体数）都指向同一个结论——预算应该花在模板多样性上。
  • 难度必须分层报：总体 ASR 会同时掩盖"系统性漏洞"与"分布边缘"，并让回归监控失去敏感度。L1~L5 各报成功率 + 区间 + 样本量，才直接指向要修的层。
  • 多轮攻击要固定并报告轮数预算；对每一轮都做检测以捕捉"渐进式泄漏"，并同时报攻击成本（轮数 / token / 人工介入）——威胁等级由"是否突破"与"突破代价"共同决定。
  • 对抗参照系（漏检率）是唯一能发现"未知的未知"的度量：日常回归用便宜的分类学参照系，发布前的关键节点做一轮独立对抗。
  • 报告三条硬要求：不报单一覆盖率；报用例集的有效独立性（模板数 / 每模板变体数 / 去重后有效样本量）；报时效（模型版本 + 用例集版本 + 新增删除记录）。模型"变得更安全"时，先查是不是困难用例被删了。
