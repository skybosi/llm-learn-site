目标代码与汇编：从 IR 到可运行程序#

前三课分别解决了"选哪条指令""用哪个寄存器""按什么顺序发"，但合起来仍是一串抽象操作。要让它真的跑起来，还得走完最后一段：发射成汇编（或目标文件）、交给汇编器与链接器、变成一个进程。本课用 Python 发射一段真实的 AArch64 汇编，用系统自带的 clang 汇编链接后直接运行，并用退出码验证语义；顺带看清 .s 里除了指令还有什么，以及为什么"符号名差一个下划线"就能让链接失败。

一、概念讲解#

1. 最后一段路：从 IR 到可执行#

LLVM 的目标无关代码生成文档把后端拆成七步：指令选择 → 调度与形成 → SSA 机器码优化 → 寄存器分配 → 序言/尾声插入 → 晚期机器码优化 → 代码发射。第 1–3 课覆盖前四步的主体，本课走完剩下的部分：

产物 谁产生 里面有什么
.ll（IR） 前端 + 中端 pass 类型化 SSA，优化在这一层
.s（汇编） 后端代码发射 段、标签、指令、符号声明
.o（目标文件） 汇编器 as 机器码 + 符号表 + 重定位
可执行文件 链接器 ld 多个 .o + 启动代码，地址定下来

关键认知：IR 的语义在每一步都会被"具体化"一次，每次具体化都可能引入新的正确性责任——指令编码范围、寄存器占用、栈对齐、符号可见性。前面几课验证"语义等价"，从 .o 往后验证的是"链接与装载能不能成立"。

2. 汇编文件里除了指令还有什么#

看本课产物就能对上：.text 说明内容进代码段，.globl main 声明全局符号，main: 是标签（符号的地址），.L1: 是单元内可见的局部标签。真正让程序"成为进程"的不是 main，而是启动代码（crt）——它准备参数、调用 main、把返回值交给 exit。这也是本课用退出码验证的原因：main 返回 55，./demo 的退出码就是 55。

3. 调用约定是一份契约#

调用约定（calling convention）规定参数放哪、返回值放哪、哪些寄存器由被调用者保存：

AArch64（AAPCS64） x86-64（System V AMD64）
前几个整型参数 x0–x7 rdi, rsi, rdx, rcx, r8, r9
返回值 x0 rax
被调用者保存 x19–x28、x29(FP)、x30(LR)、sp rbx, rbp, r12–r15
栈对齐 16 字节 16 字节（调用点）

这份契约直接落到第 2 课的分配器上：被调用者保存的寄存器若要跨调用使用，必须在序言里存、尾声里恢复；调用者保存的寄存器在调用点之后就地失效。更麻烦的是固定寄存器——某些指令强制结果落在指定寄存器（如 x86 的 div 只能用 EAX/EDX），指令选择器必须插入搬运，分配器必须把它当作"已占用"。所以"分配"从来不是纯图着色，而是"图着色 + 契约约束"。

4. 从 .s 到进程：符号、重定位与两种目标格式#

汇编器把 .s 变成 .o，其中每个未解析的引用变成一条重定位记录，链接器负责补上地址。这一步最容易踩的坑是符号命名：ELF（Linux）里 C 符号就叫 main，Mach-O（macOS）里要加下划线 _main。本课实测（macOS + Apple clang 17.0.0）：把 ELF 风格的 main 交上去链接，链接器直接报 Undefined symbols ... "_main"；改成 _main 就能跑通。这不是编译器 bug，而是目标文件格式约定——移植后端时，符号前缀、段名、重定位类型都要一起改。

5. -O0 与 -O2：后端的上限由中端决定#

同一段 C（int main(){int s=0;for(int i=1;i<=10;i++)s+=i;return s;}），本机实测两种优化级别：-O0 老实分配栈帧（sub sp, sp, #16）、把 s/i 放栈上反复 ldr/str、写成三段式循环；-O2 把整段循环折叠成 mov w0, #55 + ret——常量传播 + 循环消除（第 5 章）让后端无事可做。

这个对照比"优化很重要"有用：后端只能把已经确定的工作高效落地。如果中端没把 i、s 提升成 SSA 值、没做归纳变量分析，后端就只能生成 -O0 那种反复访存的代码。Kaleidoscope 教程第 4 章把 IR 交给优化器、第 8 章编译到目标文件，官方路径同样是"先把中端做对，再谈发射"。

6. 常见坑#

  • 栈对齐：调用点前 sp 必须是 16 字节对齐，少调一次就可能在某些 SIMD 访存上崩。
  • 调用者/被调用者保存弄反：把 x19 当临时寄存器用而不保存，调用者会看到被悄悄改掉的值——这类 bug 在不同优化级别下表现不同。
  • 只写 .s 忘了汇编/链接：clang -c 只出 .o、clang -S 只出 .s，要可执行必须走完整流程。
  • 位宽混用：AArch64 的 w0 与 x0 是同一寄存器的低 32 位与全 64 位；-O0 代码里到处是 w，而指针与长度必须是 x；另外 main 的返回值只是退出码，不是打印输出。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）把"寄存器已定"的 IR 发射成 AArch64 汇编，并用一个 20 行的解释器跑同一份 IR 做对拍基准。示例是 sum = 1+2+…+10，返回值即退出码。

# ---- 从 IR 到可运行程序：AArch64（ARM64）目标代码生成 + 语义解释器 ----
# 纯 Python，无第三方依赖。
# 目标一：把已定寄存器映射的 IR 发射成汇编文本（AArch64 / AAPCS64）
# 目标二：同一份 IR 用一个 20 行的解释器跑一遍，用来对拍汇编的语义
import sys

# ---------- 1. 输入：已经过指令选择 / 寄存器分配 / 调度 的 IR ----------
#   每个变量已经映射到一个物理寄存器（第 2 课的分配结果）
REGMAP = {'sum': 'x19', 'i': 'x20'}
IR = [
    ('mov_imm', 'sum', 0, None),          # sum = 0
    ('mov_imm', 'i', 1, None),            # i = 1
    ('label', 'L1', None, None),
    ('cmp_br', 'gt', 'i', 10, 'L2'),      # if i > 10 goto L2
    ('add_rr', 'sum', 'sum', 'i'),        # sum = sum + i
    ('add_imm', 'i', 'i', 1),             # i = i + 1
    ('br', 'L1', None, None),             # goto L1
    ('label', 'L2', None, None),
    ('ret', 'sum', None, None),           # return sum（main 返回值 = 进程退出码）
]

# ---------- 2. 目标代码生成：IR 指令 → 汇编行 ----------
CC = {'gt': 'b.gt', 'lt': 'b.lt', 'ge': 'b.ge', 'le': 'b.le', 'eq': 'b.eq', 'ne': 'b.ne'}

def emit(ir, regmap, symbol_prefix=''):
    """symbol_prefix：Linux ELF 与 macOS Mach-O 的差别之一 —— Mach-O 的 C 符号带下划线"""
    out = ['    .text',
           f'    .globl {symbol_prefix}main',
           f'{symbol_prefix}main:']
    for ins in ir:
        op = ins[0]
        if op == 'mov_imm':   out.append(f'    mov   {regmap[ins[1]]}, #{ins[2]}')
        elif op == 'add_rr':  out.append(f'    add   {regmap[ins[1]]}, {regmap[ins[2]]}, {regmap[ins[3]]}')
        elif op == 'add_imm': out.append(f'    add   {regmap[ins[1]]}, {regmap[ins[2]]}, #{ins[3]}')
        elif op == 'label':   out.append(f'.L{ins[1]}:')
        elif op == 'br':      out.append(f'    b     .L{ins[1]}')
        elif op == 'cmp_br':
            _, cond, lhs, rhs, tgt = ins
            out.append(f'    cmp   {regmap[lhs]}, #{rhs}')
            out.append(f'    {CC[cond]:<5} .L{tgt}')
        elif op == 'ret':
            out.append(f'    mov   x0, {regmap[ins[1]]}')   # AAPCS64：返回值放 x0
            out.append('    ret')
        else:
            raise ValueError(f'未知操作码 {op}')
    return out

# ---------- 3. 同一份 IR 的解释器：不依赖汇编器，用来对拍语义 ----------
def run_ir(ir, regmap, limit=10**6):
    val = {v: 0 for v in regmap}
    pos, steps = 0, 0
    labels = {ins[1]: k for k, ins in enumerate(ir) if ins[0] == 'label'}
    while pos < len(ir):
        steps += 1
        if steps > limit: raise RuntimeError('疑似死循环')
        ins = ir[pos]; op = ins[0]
        if op == 'mov_imm': val[ins[1]] = ins[2]
        elif op == 'add_rr': val[ins[1]] = val[ins[2]] + val[ins[3]]
        elif op == 'add_imm': val[ins[1]] = val[ins[2]] + ins[3]
        elif op == 'cmp_br':
            _, cond, lhs, rhs, tgt = ins
            taken = {'gt': val[lhs] > rhs, 'lt': val[lhs] < rhs,
                     'ge': val[lhs] >= rhs, 'le': val[lhs] <= rhs,
                     'eq': val[lhs] == rhs, 'ne': val[lhs] != rhs}[cond]
            if taken:
                pos = labels[tgt]; continue
        elif op == 'br':
            pos = labels[ins[1]]; continue
        elif op == 'ret':
            return val[ins[1]], steps
        pos += 1

if __name__ == '__main__':
    pre = '_' if '--darwin' in sys.argv else ''
    asm = emit(IR, REGMAP, pre)
    if '--emit' in sys.argv:
        path = sys.argv[sys.argv.index('--emit') + 1]
        open(path, 'w').write('\n'.join(asm) + '\n')
        print(f'已写出 {path}（{len(asm)} 行）')
    else:
        print('=== 发射出的 AArch64 汇编 ===')
        print('\n'.join(asm))
        result, steps = run_ir(IR, REGMAP)
        print(f'\n=== 同一份 IR 的解释器结果 ===')
        print(f'返回值 = {result}（共执行 {steps} 条 IR 指令）')
        print(f'main 的返回值就是进程退出码，所以 ./demo 的退出码应为 {result}')

运行结果（本机实跑，输出原样粘贴）：

=== 发射出的 AArch64 汇编 ===
    .text
    .globl main
main:
    mov   x19, #0
    mov   x20, #1
.LL1:
    cmp   x20, #10
    b.gt  .LL2
    add   x19, x19, x20
    add   x20, x20, #1
    b     .LL1
.LL2:
    mov   x0, x19
    ret

=== 同一份 IR 的解释器结果 ===
返回值 = 55（共执行 56 条 IR 指令）
main 的返回值就是进程退出码，所以 ./demo 的退出码应为 55

接着把这段汇编真的跑起来（--darwin 让符号带下划线，适配 macOS；Linux 上去掉这个参数）：

python3 l4_codegen.py --emit demo.s --darwin    # 已写出 demo.s（14 行）
clang -o demo demo.s                            # 汇编 + 链接
./demo; echo "exit=$?"
exit=55

解释器算出 55，真实进程的退出码也是 55——两条独立路径对上了。再把符号换成 ELF 风格（不带下划线）链接一次：

python3 l4_codegen.py --emit demo_elf.s         # 符号名是 main
clang -o demo_elf demo_elf.s

      <initial-undefines>

最后看一眼"优化的上限由中端决定"这件事。同一段 C（int main(){int s=0;for(int i=1;i<=10;i++)s+=i;return s;}）：

clang -O0 -S demo.c -o demo_O0.s    # 看忠实的循环与栈访问
clang -O2 -S demo.c -o -            # 看中端把活干完之后的样子
nm demo | head -4                   # 目标文件里的符号表
file demo                           # 产物类型
# clang -O2 -S（关键两行）
_main:                                  ; @main
    mov	w0, #55                         ; =0x37
    ret

# clang -O0 -S（节选：栈帧 + 把 i、s 放在栈上）
_main:                                  ; @main
    sub	sp, sp, #16
    str	wzr, [sp, #12]
    str	wzr, [sp, #8]
    mov	w8, #1                          ; =0x1
    str	w8, [sp, #4]
    b	LBB0_1
LBB0_1:                                 ; =>This Inner Loop Header: Depth=1
    ldr	w8, [sp, #4]
    subs	w8, w8, #10
    b.gt	LBB0_4

# nm / file
00000001000002e0 t .LL1
00000001000002f4 t .LL2
0000000100000000 T __mh_execute_header
00000001000002d8 T _main
demo: Mach-O 64-bit executable arm64

四件事一次看全：-O0 忠实到"每次用 i 都从栈上取"，-O2 把循环折叠成 mov w0, #55，符号表里 .LL1/.LL2 是局部符号（t）、_main 是全局符号（T），产物是 Mach-O 可执行文件。"能读懂汇编 + 能对照 IR"，到这里闭环。

三、练习#

  1. 实现：给示例 IR 加一条"从内存数组读元素"的指令，让程序改成计算数组前 n 项和；先跑解释器、再跑 clang 链接，确认两条路径一致。
  2. 解释：为什么只 .globl 了 main，而 .LL1/.LL2 不需要？若把局部标签也声明成全局符号，链接同名符号的大程序会怎样？
  3. 对比/验证：在 Linux（ELF）或 macOS（Mach-O）上验证符号前缀规则；再对同一段 C 用 -O0 -S 与 -O2 -S，找出三处中端优化导致的后端差异。
  4. 思考：本课用退出码验证结果，真实程序为什么不能这样？若改成输出到标准输出，要引入哪些新约定（参数传递、库调用、调用者保存寄存器）？
