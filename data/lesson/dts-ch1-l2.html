α-β 通信模型：延迟项与带宽项#

同一个 AllReduce，跑在两种链路上能差一个数量级；同一段代码在小消息和大消息上，瓶颈也会换人。原因很简单：通信不是一个数字，而是两个数字——一次收发要付的固定开销，和每字节的搬运成本。这一课把 Hockney 的 α-β 模型（1994 年提出，至今仍是集合通信性能分析的标准口径）建起来，并教你在任何一台机器上（包括只有 CPU 的笔记本）亲手量出这两个参数。

一、概念讲解#

1. 两个参数，一个公式#

点对点发一条 s 字节的消息，用模型写成

T(s)=α+βs​

符号 含义 量纲 谁决定它
s 消息字节数 byte 你的算法（分块大小、梯度大小）
α 固定延迟项：每次通信都要付一次（协议握手、软件栈、启动、链路往返的一半） 时间 硬件与软件栈（NIC、驱动、通信库）
β 稳态带宽：单位时间能搬多少字节 byte/时间 链路（NVLink、PCIe、InfiniBand、以太网）

量纲核对一下：α 用 μs、β 用 GB/s 时 s/β 的换算要写成 s[B]/(β[GB/s]×103) μs。这个模型的价值不在于精确，而在于它逼你分开问两个问题："我付了几次 α？""我总共搬了多少字节？"

2. 谁是瓶颈：交叉点 s∗=αβ#

两项相等时 s∗=αβ：比它小的消息被 α 支配（加多少带宽都没用），比它大的消息被 β 支配。取示例参数（请用自己机器的实测值替换）：

链路量级 α β s∗=αβ 含义
示例：跨机 25 GB/s 级 5 μs ≈25 GB/s ≈0.12 MiB 120 KiB 以下的消息几乎全是延迟
示例：节点内 300 GB/s 级 5 μs ≈300 GB/s ≈1.43 MiB 1.4 MiB 以下的消息几乎全是延迟

这张表解释了训练系统里一个反复出现的工程动作：梯度分桶（bucket）。把上百个小梯度拼成一条大消息，α 的次数从"每个张量一次"降到"每桶一次"，而字节数（β 项）一点没变——所以分桶的全部收益，就是把 k 次 α 变成 1 次。

3. 多条消息与流水：α 只付一次#

若一共要发 V 字节、切成 k 块：

  • 逐块同步（发一块、等对方确认再发下一块）：T=k(α+kβV​)=kα+βV​
  • 分块流水（第一块付 α，后续块紧跟前一块的尾部，链路不空转）：T=α+βV​

代入 V=128 MiB、k=8、α=5 μs、β=300 GB/s：逐块同步 0.487 ms，分块流水 0.452 ms——差的就是那 7 次多余的 α。结论有普适性：流水不改变带宽账，只把延迟项从"每块一次"摊销成"每轮一次"。

4. 从实测反解 α 与 β#

α、β 不用查表，测两条消息就能解：由 ti​=α+si​/β 相减得

β=t2​−t1​s2​−s1​​,α=t1​−βs1​​

工程上有两个必须知道的细节。其一，截距对噪声远比斜率敏感：示例代码用 ±2% 抖动造数据时，真值 α=3 μs 会被拟合成 1.41 μs；抖动降到 ±0.5% 才回到 2.60 μs。所以正规做法是用小消息段单独量 α、用大消息段的斜率量 β，而不是对全表做一次最小二乘就完事。其二，nccl-tests 输出表里的 algbw（算法带宽）与 busbw（总线带宽）是两个口径，后者按算法结构折算（AllReduce 的换算式是 busbw=algbw×p2(p−1)​），报数时必须说清用的是哪个。

5. 与 work–depth 合起来：通信也有一个 depth#

把第 1 课的两个坐标搬过来：一次通信的"work"是总字节数 V，"depth"是轮数 D（消息必须串行等待的次数）。于是

T通信​≥D⋅α+βV​

这正是后面所有"通信下界"的统一形式：轮数决定付几次延迟，字节数决定带宽账。要更快只有两条路——减少轮数（换算法：树比环轮数少），或减少字节数（换精度、换分片方式、换并行策略）。

6. 常见坑#

  • 拿链路峰值带宽当 β：实测有效带宽通常明显低于标称值，且随消息大小变化。
  • 拿大消息的斜率外推到小消息：小消息段是 α 主导的另一条线，外推必然低估。
  • 把往返当单程：ping-pong 测的是 RTT =2α+2s/β，折算时要除以 2，否则 α 翻倍。
  • 忽略"每条消息一次 α"：把 100 个小张量分别通信，等价于把 α 乘以 100。
  • 以为 α 固定不变：并发通信数、CPU 花在"谁来发起"上的时间都会抬高它；跨 NUMA、跨 PCIe switch 也会。

二、可运行代码示例#

三段纯 Python：拟合器自检（合成数据）、α 的摊销（分块流水）、在没有任何 GPU 的机器上实测一条真实链路的 α-β（本机回环 socket，只有标准库）。

# ===== 示例 1：α-β 参数的两个来源 —— 最小二乘拟合 =====
def fit_alpha_beta(sizes, times_us):
    """拟合 t = α + s/β：对 (s, t) 做最小二乘，返回 (α_μs, β_GB/s)。"""
    n = len(sizes)
    mx = sum(sizes) / n
    my = sum(times_us) / n
    slope = sum((s - mx) * (t - my) for s, t in zip(sizes, times_us)) / sum((s - mx) ** 2 for s in sizes)
    intercept = my - slope * mx            # 斜率单位 μs/byte，截距单位 μs
    return intercept, 1.0 / slope / 1e3    # β = 1/斜率：byte/μs → GB/s

def synth(alpha_us, beta_gbps, sizes, jitter=0.005, seed=0):
    """用已知 α、β 造带抖动的合成数据，用来验证拟合器本身没写错。"""
    import random
    r = random.Random(seed)
    return [alpha_us + s / (beta_gbps * 1e3) * (1 + r.uniform(-jitter, jitter)) for s in sizes]

sizes = [4 << 10, 64 << 10, 1 << 20, 16 << 20, 128 << 20]
print("拟合器自检（合成数据加 ±0.5% 抖动，真值 → 拟合值）：")
for a, b in ((5.0, 300.0), (3.0, 25.0)):
    fa, fb = fit_alpha_beta(sizes, synth(a, b, sizes))
    print(f"  α={a:>4.1f} μs β={b:>6.1f} GB/s  →  α={fa:5.2f} μs β={fb:7.2f} GB/s")

# ===== 示例 2：α 无法被带宽摊薄，但可以被"分块流水"只付一次 =====
def naive_chunks(s_bytes, k, alpha_us, beta_gbps):
    """k 块各自发、每块都等对方确认：T = k·(α + s/(kβ)) = k·α + s/β。"""
    return k * (alpha_us + (s_bytes / k) / (beta_gbps * 1e3))
def pipelined_chunks(s_bytes, alpha_us, beta_gbps):
    """流水发送：第一块付 α，后续块紧跟前一块的尾部：T = α + s/β。"""
    return alpha_us + s_bytes / (beta_gbps * 1e3)

s = 128 << 20
print(f"\n128 MiB 消息，k=8 块，α=5 μs、β=300 GB/s（单位 ms）：")
print(f"  逐块同步（付 8 次 α）：{naive_chunks(s, 8, 5.0, 300.0) / 1e3:7.3f}")
print(f"  分块流水（付 1 次 α）：{pipelined_chunks(s, 5.0, 300.0) / 1e3:7.3f}")
print("\nα 与带宽项打平的消息大小 s* = αβ（此大小以下，延迟项占多数）：")
for b in (25.0, 300.0):
    print(f"  β={b:>5.0f} GB/s → s* = {5.0 * b * 1e3:>10.0f} B ≈ {5.0 * b * 1e3 / 2**20:5.2f} MiB")

# ===== 示例 3：在本机量一条真实链路的 α 与 β（不需要 GPU） =====
import socket, threading, time
def echo(sock):
    while True:
        try:
            data = sock.recv(1 << 20)
        except OSError:
            return
        if not data:
            return
        sock.sendall(data)

def pingpong_rtt(nbytes, iters):
    """一次往返 = 2α + 2s/β。先把收发缓冲调大，避免消息大于缓冲时自锁。"""
    a, b = socket.socketpair()
    for sk in (a, b):
        sk.setsockopt(socket.SOL_SOCKET, socket.SO_SNDBUF, 1 << 22)
        sk.setsockopt(socket.SOL_SOCKET, socket.SO_RCVBUF, 1 << 22)
    threading.Thread(target=echo, args=(b,), daemon=True).start()
    msg = b"x" * nbytes
    for _ in range(5):                     # 预热
        a.sendall(msg); got = 0
        while got < nbytes:
            got += len(a.recv(1 << 20))
    t0 = time.perf_counter()
    for _ in range(iters):
        a.sendall(msg); got = 0
        while got < nbytes:
            got += len(a.recv(1 << 20))
    dt = (time.perf_counter() - t0) / iters * 1e6
    a.close()
    return dt

sm = [256, 4096, 65536, 262144, 1 << 20]
rtt = [min(pingpong_rtt(n, 200 if n <= 65536 else 50) for _ in range(3)) for n in sm]
print("\n本机 socketpair 往返实测（回环链路，数字随机器变化）：")
for n, t in zip(sm, rtt):
    print(f"  {n:>8} B：RTT = {t:8.2f} μs")
a_hat, b_hat = fit_alpha_beta(sm, rtt)
print(f"  按 RTT = 2α + 2s/β 折算：α ≈ {a_hat / 2:5.2f} μs，β ≈ {b_hat * 2:6.2f} GB/s（含 Python 与回环栈开销，只看量级）")

三、练习#

  1. 实现：把示例 3 的 sm 扩成 [64,256,1024,…,4 MiB] 的等比序列，分别用"全表最小二乘"和"只用 ≥64 KiB 的点"拟合，比较两次得到的 α；解释差异为什么主要落在 α 上。
  2. 解释：为什么分块流水能把 kα 压成 α，却压不动 V/β？用"链路利用率"的语言回答（提示：流水只填满了原本空转的链路）。
  3. 对比/验证：取 α=5 μs，β 分别取 25 与 300 GB/s，算 s=4 KiB、256 KiB、16 MiB 三行的"延迟占比" kα/(kα+V/β)（各消息单独一条，k=1）；说明哪一行最先因为 β 变化而受益。
  4. 思考：训练每步要通信 1 GiB 梯度，通信与计算都排在同一条流上。若单步计算 100 ms、α 付了 200 次、β 按 25 GB/s 算，通信时间是多少？把它藏起来需要哪两个条件同时成立？第 3 课给出精确的下界形式。
