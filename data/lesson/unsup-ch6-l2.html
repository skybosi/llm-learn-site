图像压缩#

聚类不仅能给客户分群，还能干一件很直观的事——压缩图片。一张彩色照片里的每个像素用 24 位（红绿蓝各 8 位）存储，理论上能有上千万种颜色，但人眼往往只需要几十种颜色就能认出画面。用 KMeans 把几百万个像素"聚"成少数几类颜色，再用每类的代表色替换回去，就能大幅压缩图片。这一课就用 scikit-learn 自带样例图，亲手做一次颜色量化。

一、概念讲解#

1. 颜色量化：用少数颜色替代千万颜色#

一张 RGB 图片可以看成一个大集合：每个像素是一个三维点 (R, G, B)。所谓颜色量化（color quantization），就是把这些三维点聚成 K 类，每类的质心就是一种"代表色"，然后把属于该类的所有像素统一替换成这个代表色。K 越小，颜色越少、画面越"斑驳"，但数据量也越小。

2. 为什么 KMeans 能做这件事#

KMeans 的目标恰好是"把相近的点分到同一簇，簇内尽量相似"。在颜色空间里，"相近"就是颜色相近。于是：

  1. 把图片摊平成 高 × 宽 行、3 列的像素矩阵；
  2. 用 KMeans 把这些像素聚成 K 个颜色簇；
  3. 用 cluster_centers_（K 个代表色）按每个像素的标签重建图片。

整个过程不需要任何标签，是纯无监督的做法。

3. 压缩率怎么算#

原图每个像素需要 24 位直接存颜色。压缩后，每个像素只需一个"调色板索引"：K 种颜色用 log2(K) 位就能编码，另外还要存一张 K×24 位的调色板（通常可忽略）。于是压缩比约为 24 / log2(K) 倍——比如 K=16 时，每像素只需 4 位索引，压缩比约 6 倍。K 越小压缩越狠，但画质损失越大，这是典型的"存储 vs 画质"权衡。

4. K 的选择与代价#

K 取得太小，天空、人脸等渐变色会变成明显的色块（色带现象）；K 取得太大，压缩收益变小。实践中常取 8、16、32 等 2 的幂（方便用整数位编码），并观察原图与压缩图的视觉差异来定。

二、可运行代码示例#

示例 1：加载图片并摊平为像素矩阵#

scikit-learn 自带一张中国风景样例图，不需要另外下载：

from sklearn.datasets import load_sample_image
import numpy as np

china = load_sample_image("china.jpg")   # 形状 (高, 宽, 3)，数值 0~255 的 uint8
h, w, d = china.shape
print("原图形状:", china.shape)

pixels = china.reshape(h * w, d).astype(np.float32) / 255.0
print("摊平后的像素矩阵形状:", pixels.shape)   # (高*宽, 3)，每行一个像素

要点：load_sample_image("china.jpg") 返回的是 NumPy 数组。除以 255 把颜色归一到 0~1，能让 KMeans 的数值更稳定（颜色三个通道量纲一致，这一步不是必须，但更规范）。

示例 2：KMeans 颜色量化并重建图片#

from sklearn.datasets import load_sample_image
from sklearn.cluster import KMeans
import numpy as np
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['SimHei', 'Microsoft YaHei', 'Noto Sans CJK SC']
plt.rcParams['axes.unicode_minus'] = False

china = load_sample_image("china.jpg")
h, w, d = china.shape
pixels = china.reshape(h * w, d).astype(np.float32) / 255.0

K = 16
km = KMeans(n_clusters=K, random_state=42, n_init=1)   # n_init=1 加快演示
km.fit(pixels)                                          # 对全部像素聚类，可能耗时几秒

# 用每个像素所属簇的质心（代表色）重建图片
compressed = km.cluster_centers_[km.labels_].reshape(h, w, d)

fig, axes = plt.subplots(1, 2, figsize=(12, 5))
axes[0].imshow(china)
axes[0].set_title('原图（约 1670 万种颜色）')
axes[0].axis('off')
axes[1].imshow(compressed)
axes[1].set_title(f'KMeans 压缩（K={K}）')
axes[1].axis('off')
plt.show()

bits_orig = 24
bits_new = np.log2(K)
print(f"每像素位数：原 {bits_orig} bit → 压缩后 {bits_new:.1f} bit（另加 {K * 24} bit 调色板）")
print(f"压缩比约 {bits_orig / bits_new:.1f} 倍（忽略调色板开销）")

要点：km.cluster_centers_[km.labels_] 按"每个像素的标签"取出对应代表色，再 reshape(h, w, d) 还原成图片。若你的机器较慢，可以把 pixels 换成随机抽取的子集来聚类，再对全量像素做 predict。

示例 3：对比不同 K 的画质#

from sklearn.datasets import load_sample_image
from sklearn.cluster import KMeans
import numpy as np
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['SimHei', 'Microsoft YaHei', 'Noto Sans CJK SC']
plt.rcParams['axes.unicode_minus'] = False

china = load_sample_image("china.jpg")
h, w, d = china.shape
pixels = china.reshape(h * w, d).astype(np.float32) / 255.0

fig, axes = plt.subplots(1, 4, figsize=(16, 4))
for ax, K in zip(axes, [2, 4, 8, 32]):
    km = KMeans(n_clusters=K, random_state=42, n_init=1).fit(pixels)
    img = km.cluster_centers_[km.labels_].reshape(h, w, d)
    ax.imshow(img)
    ax.set_title(f'K={K}')
    ax.axis('off')
plt.show()

要点：K=2 时画面几乎只剩两种色块，随着 K 增大细节逐渐恢复。这张对比图能让你直观感受"K 越小越省空间，但画质越差"的权衡曲线。

三、练习#

  1. 压缩率计算：分别取 K=2、8、16、64，用公式 24 / log2(K) 计算压缩比，列成一张表，说说 K 与压缩比的数学关系。
  2. 量化误差：计算压缩图与原图的均方误差（np.mean((china/255 - compressed) ** 2)），观察它随 K 增大如何变化。
  3. 换图片：把 load_sample_image("china.jpg") 换成 load_sample_image("flower.jpg")，重跑示例 2，比较两类图片在相同 K 下的视觉差异。
  4. 思考：为什么 KMeans 适合做颜色量化？如果改成"每个像素取周围邻居的平均色"，和 KMeans 的做法相比有什么本质不同？
