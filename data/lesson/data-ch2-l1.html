来源、许可与合规：把法律约束变成数据字段#

这一节要解决什么#

技术团队处理合规问题的方式通常是：在项目启动时确认一次"这些数据我们能拿到，应该没问题"，然后把它写进文档的一句话里，此后再也不提。这种做法有三个结构性缺陷：

  1. 它不可计算。"应该没问题"不能回答"如果用这批数据训出的模型对外提供 API，行不行？"——而这恰恰是唯一重要的问题。
  2. 它不可追溯。三个月后有人问"这批数据从哪来的"，没人答得上来，因为来源信息只存在于某次群聊里。
  3. 它不可撤下。某个来源突然要求删除（法律投诉、许可变更、站长抗议）时，你无法回答"这会影响多少样本"，于是只能全量重跑 —— 或者更常见地，什么都不做，把风险留着。

这一节要把这三件事变成工程产出：来源登记表（把许可变成可以 join 的字段）、溯源链（每个样本能追到 source_id）、撤下流程（从 source_id 回追到受影响样本，重跑管线）。加上 PII 的处理与采集系统的设计。

一、来源的六种类型与它们的工程属性#

先把来源分类，因为每一类的法律地位、工程成本、失效模式都不同。

类型 例子 可得性 许可清晰度 PII 风险 偏差特征 可复现性
自有数据 自己的产品日志、客服对话 高 最高（你拥有它，但可能含用户个人信息） 最高（真实用户） 与自己的业务强相关，域很窄 高（但要防用户删号导致数据变动）
授权数据 采购的语料、合作方提供 中（有合同） 高（合同写清了范围） 视合同 视提供方 中（对方可能不给版本）
公开网页爬取 Common Crawl 类 高 最低（默认保留所有权利） 中高（用户生成内容） 与"谁在网上写字"强相关 低（网页会变、会消失）
开放许可数据集 CC0/CC-BY 语料、维基 高 高（但要读清条款） 中（维基含传记） 偏正式、偏英文/主流语言 高（有固定快照）
用户生成内容 评论、论坛、问答 中 低（平台 ToS 常禁止再分发） 高 口语化、噪声高 低
合成数据 模型生成、规则生成 最高（想要多少有多少） 取决于基础模型与生成过程 低（但可能复现训练数据里的 PII） 继承教师的偏差，尾部缺失 高（有种子就完全可复现）

三条从表里直接读出的推论：

  1. "可得性高"与"许可清晰"几乎负相关。 最容易拿到的数据（爬网页）许可最不清晰；许可最清晰的（自有）域最窄。所以真实管线必然是混合来源 —— 而混合正是麻烦所在（下一节）。
  2. PII 风险与"是不是真人写的"正相关，与"是不是合成"负相关。但合成数据不是免责的：如果基础模型记住了训练数据里的 PII，合成数据会把它再吐出来。
  3. 可复现性最差的是爬取。网页会变、会 404、会 A/B 测试。所以爬取类采集的第一原则是保存原始快照（4.1）。

二、许可：从法律文本到可计算字段#

2.1 许可阶梯#

把常见许可按"授予的权利"排序，而不是按名字记：

CC0 / 公有领域      → 放弃全部权利（无义务）
MIT / Apache-2.0 / BSD → 宽松：可商用、可改、可再分发（需保留声明）
CC-BY-4.0           → 可商用可改（需署名）
CC-BY-SA-4.0        → 上面 + 传染性（衍生作品需同许可）
CC-BY-ND-4.0        → 可商用但**禁止衍生**（对训练用途基本不可用）
CC-BY-NC-*          → **禁止商用**（含 NC 的一律不能用）
无许可 / 全版权保留  → 默认保留所有权利 —— 没有声明 ≠ 可以用

两个最常见的误解：

  1. "没有版权声明就是公共领域" —— 完全相反。版权在作品产生时自动生效，没有声明意味着作者保留全部权利。写"版权所有"不是获得版权的前提，只是提醒。
  2. "公开可访问 = 可以使用" —— 公开可访问是事实状态，许可是法律状态，两者无关。你把一本书放在公园长椅上，不等于授权别人复印它。

2.2 权利取交集，义务取并集#

混合来源时，一个自然的直觉是"取交集"：整份数据能做什么，等于所有来源都能做的事的交集。这个直觉对权利是对的，对义务是错的。本节代码的实测：

整份数据（含两个 all-rights-reserved 来源）：
  权利交集 = []                                   义务并集 = [传染性, 署名]
去掉两个 all-rights-reserved 来源后：
  权利交集 = [commercial, derivatives, redistribute, train]
  义务并集 = [传染性, 署名]   <- 义务没有被取交集消掉

读法：权利交集从空集变成了四项，看起来"只把 CC0 与 CC-BY-SA 混在一起，CC0 没义务，所以没义务了"—— 错。义务必须按来源分别记录并传播：只要语料里有任何一个 CC-BY-SA 的部分，署名与传染性义务就存在。

工程上的写法：登记表里对每个来源记 rights（它授予的）与 duties（它要求的）两个字段，然后：

  • 权利：对某个用途，所有来源都必须授予 → 交集；
  • 义务：任一来源要求的都要履行 → 并集。

本节代码里的 strictest() 就是这么实现的，并且刻意在注释里标出这是"取交集"直觉唯一会出错的地方。

2.3 传播问题：模型权重是不是"衍生作品"#

这是生成式 AI 时代最尖锐的未定问题：用 CC-BY-SA 的数据训练出的模型权重，是不是衍生作品？ 如果是，那模型也要按 CC-BY-SA 分发（传染）；如果不是，那只需署名。

现状是：法律上没有定论。各国判例与立法都在演进，不同司法辖区的答案可能不同。但工程上不能因为"未定"就不做决策，所以正确做法是按最保守的假设登记，并把不确定性显式写下来：

假设 后果 什么时候选
权重是衍生作品 必须署名 + 可能传染 对外发布模型权重 / 高合规要求场景
权重不是衍生作品 只需署名（CC-BY 类） 内部使用 / 明确的法律意见支持

为什么这个选择必须写进登记表：因为它决定了"能否换掉某个来源"。如果一个 CC-BY-SA 来源被撤下，在保守假设下你需要重训（因为权重被"污染"了）；在宽松假设下你只需要更新数据卡。两种假设下的撤下成本差一个数量级，所以它不能是一个含糊的默认值。

一个实用的折中：把许可分级（tier），只把最严格的许可（CC-BY-SA、无许可）用于必须的内核数据，把宽松来源用于可替换的部分。这样撤下时影响面可控。

2.4 ToS 与 robots.txt：技术可达 ≠ 法律许可#

  • robots.txt 是技术约定，不是法律授权文件。遵守它是必要不充分：遵守 robots 不代表 ToS 允许你把内容用于训练；反之，robots 允许抓取也不代表允许用于训练（很多网站的 ToS 明确禁止"用于机器学习训练"）。
  • 反爬措施的存在本身是一个信号：站点表达了"不希望被自动采集"的意愿。绕过它（换 UA、代理池、破解验证码）在法律上会加重不利解释，在工程上还会引入下一节的"静默降级"风险。
  • Crawl-delay 与速率：除了合规，还有工程质量问题 —— 高频抓取会让站点返回错误页/限流页，而这些页面会作为"内容"进入语料（4.4）。

实践纪律：采集前把三件事写进登记表 —— ToS 的具体条款位置、是否允许训练用途、以及依据。"我们查过了"不是记录，"ToS §3.2 禁止将内容用于训练"才是记录。

2.5 为什么许可必须是一个数据字段#

抽象地讨论合规没有意义，落地只有一个动作：把许可变成可以 join 的字段。

# 不是这样：
#   "本数据集由公开网页和维基百科构成，许可情况已确认。"   ← 无法回答任何问题

# 而是这样：
#   {"doc_id": "d0", "source_id": "web-crawl-01", "license": "all-rights-reserved", ...}

一旦它是字段，你就能：

  • SELECT count(*) FROM docs WHERE license = 'CC-BY-NC-4.0' —— 找出必须清除的部分；
  • 回答"这批数据的 rights 交集是什么"（能不能商用）；
  • 回答"撤下 source_id=X 影响多少样本"（下一节）；
  • 在数据卡里自动生成许可段落，而不是手写一段会过期的文字。

三、PII 与重识别：为什么删掉姓名远远不够#

3.1 四类标识符#

类别 例子 特点
直接标识符 姓名、邮箱、手机号、身份证号、护照号 单独即可识别个人 —— 必须删/掩码
准标识符 邮编、出生年月、性别、职业、机构 组合起来可唯一识别 —— 最容易被忽略
敏感属性 健康、性取向、宗教、政治立场、生物特征 即使不可识别个人，泄露也构成伤害
行为/设备标识 IP、设备 id、Cookie、精确位置轨迹 在"关于自然人的信息"这个定义下通常也算个人信息

为什么删掉姓名不够：本节代码的最小演示（删掉姓名后，仅凭 邮编 + 出生年 + 性别 分组）：

出现大小为 1 的等价类，意味着那条记录仍然可以被唯一识别 —— 也就是这条记录关于某个具体的人。这说明"删除直接标识符"只是第一步，真正的目标是让每条记录不可区分（或不可信的区分）。

3.2 三个层次的保护，以及各自的代价#

方法 机制 保证 代价
k-匿名 泛化准标识符，使每个等价类至少 k 条 不能把某人从 k 人中区分出来 泛化越强信息损失越大；不防同质性攻击（等价类内敏感属性全相同）
ℓ-多样性 每个等价类内敏感属性至少 ℓ 种取值 防同质性攻击 更难满足；可能仍需大量泛化
差分隐私 对输出/统计加噪，保证相邻数据集输出分布接近 数学可证的隐私界 需要噪声预算 ϵ，ϵ 小则可用性差；对非结构化文本很难直接套用

⚠️ 一个必须说清的边界：上面这些是表格数据的工具。 对一段自然语言文本（客服对话、病历记录），"泛化邮编"这种操作没有对应物 —— 你得先把它结构化，或者做实体替换（把人名/地名换成占位符）。实体替换的问题是它可以被上下文反推（"我们镇上唯一的那家三甲医院"），也有研究表明替换后的文本仍可被重识别。

3.3 LLM 特有的问题：记忆化 → 提取攻击#

前面都是"数据处理"层面的隐私。LLM 引入了一个新层面：模型会记住训练数据。

链条是：训练数据里的个人信息 → 模型在参数里记住了它 → 通过成员推断（membership inference）可以判断"某个人的数据是否在训练集里" → 通过训练数据提取攻击（training data extraction）可以让模型逐字吐出训练样本里的 PII（这在多个大模型的公开研究里被实际演示过，包括邮箱、电话、住址）。

三个推论，都影响管线设计：

  1. 重复数据的隐私风险是超线性的。同一段含 PII 的文本出现 r 次，被记住的概率大幅上升 —— 这是"去重也有隐私收益"的机制（第 2 节）。
  2. PII 检测必须在去重之前还是之后，是一个真问题。检测"这个字符串是不是 PII"需要上下文；但脱敏会改变文本表示。本节代码把脱敏做成确定性替换（同一实体一律换同一占位符），这样它和去重可以共存 —— 顺序问题在第 4 节展开。
  3. "删掉训练数据"不等于"模型忘记了"。这直接引出下一小节。

3.4 被遗忘权与"模型不会忘记"的工程后果#

GDPR 的被遗忘权（right to erasure）/ 个人信息保护法里的删除权，要求数据主体可以要求删除其个人信息。而对一个已训练好的模型，没有"删除某个人的数据"这个操作 —— 梯度已经融进参数，你无法定位它。

工程上只有四条路，各有代价：

方案 做法 代价
重训 从数据集中删除该主体数据，从头训 最彻底、最贵
近似遗忘（unlearning） 用专门的算法"抹掉"特定影响 研究阶段；效果难以验证（"忘了多少"很难测）
抑制/过滤 在推理时过滤输出 只能挡已知形态；不改变模型内部状态
前置避免 训练前就把 PII 清干净，不留需要删的东西 需要高质量 PII 检测；会损失一部分数据

这四条路的共同结论是：隐私工作的重心必须前移到数据管线。 一旦 PII 进了模型，唯一可靠的选择就是重训 —— 这就是为什么"3.3 的检测"不是可选的合规装饰。

四、采集工程：系统设计与失败模式#

4.1 原始层不可变#

数据湖的经典分层对训练数据同样适用：

raw（原始快照，只追加、永不修改）
  → bronze（解析后的文本 + 元数据，可重跑）
  → silver（规范化 + 去重 + 过滤后）
  → gold（配比好的最终训练集）

为什么 raw 必须不可变：

  • 可复现：规范化/过滤/去重的代码会改（一定会改），只有保留原始字节才能重跑出"当时那份数据"；
  • 可复核许可：许可争议时，你需要证明"我们抓到的确实只有这些"；
  • 可修复：发现解析器有 bug 时可以只重跑 bronze，不用重新爬。

代价：存储成本（raw 通常比 silver 大 3~10 倍，因为含 HTML/PDF 原始字节与重复内容）与访问管理。这个成本几乎总是值得的 —— 唯二的例外是"来源有明确的保留期限要求"（此时要按期限删除，并行记录删除动作）与"原始数据本身是敏感的"（此时要考虑加密与访问审计）。

4.2 礼貌与稳定#

  • robots.txt：解析 User-agent / Disallow / Crawl-delay（本节代码实现了最小解析与虚拟时钟限速）。
  • User-Agent 标识：给出可联系的身份，而不是伪装成浏览器。伪装会让站点无法区分你和恶意爬虫，于是它会对所有流量一起降级。
  • 缓存与条件请求：用 ETag/If-Modified-Since 避免重复下载，也避免给站点造成无谓压力。
  • 失败重试要有界：指数退避 + 上限；无界重试会在站点故障时产生请求风暴。

4.3 内容去重（采集期的第一道去重）#

同一个 URL 会被抓多次（更新、重定向），同一个内容会出现在多个 URL（镜像、转载、参数化 URL）。采集期要做：

  1. URL 规范化：去掉跟踪参数（?utm_*、?ref=）、统一大小写与结尾斜杠、解析重定向到最终 URL、把 http:// 与 https:// 视为同一资源（当内容相同时）；
  2. 内容指纹：对原始字节做 hash，重复的直接跳过（注意：这一步是精确去重，近似去重在第 2 节）；
  3. 快照版本：内容变了要保留新快照（而不是覆盖），并记录抓取时间 —— 否则时间泄漏审计（第 1 章 E13）无法做。

4.4 五类失败模式（都会静默污染语料）#

失败 表现 后果 检测
软 404 HTTP 200，但内容是"该页面不存在" 大量无信息的短文本涌入 响应体长度 + 关键词模板检测
反爬静默降级 HTTP 200，但返回登录页/验证页 登录提示被当成正文 登录/验证关键词检测（代码演示）
动态渲染 HTTP 200，但正文由 JS 生成，拿到空壳 有效内容丢失，只剩导航 正文提取后的长度比检查
编码错误 出现大量 U+FFFD 或乱码 语料被污染，且影响 tokenizer U+FFFD 比例、语言识别置信度
日历/分页陷阱 无限翻页或"上一世纪"的日期 采集量爆炸、陈旧数据混入 采集上限 + 日期分布监控

它们的共同点是全部返回 200。 任何"只看状态码"的采集器都会把它们全部当成成功。本节代码把前两类做成了显式检查：

保留 https://x.test/a  hash=c598fc92d6c8  虚拟时刻 t=1.0s（Crawl-delay=1s）
跳过 https://x.test/b                 原因: 内容重复
跳过 https://x.test/c                 原因: 反爬静默降级：返回登录页
跳过 https://x.test/private/x         原因: robots 禁止
跳过 https://x.test/missing           原因: 空响应（软 404）

注意"空响应"与"登录页"这两条：如果它们不被显式识别，就会作为低质语料进入训练集 —— 而它们的量往往很大（一个反爬策略变更就能让整个批次的采集全部降级），所以这是一次典型的"静默的大规模污染"。

五、两个可交付产物#

5.1 来源登记表#

字段设计（每一项都有下游用途，不是装饰）：

字段 类型 用途
source_id 稳定标识 溯源的主键；撤下时用它回追
kind 六类之一 决定默认风险等级
url_or_path 定位 复核与重抓
license 枚举 权利/义务计算
license_evidence 文本（ToS 条款位置） 合规审计
acquired_at 时间戳 时效性评估、快照定位
method 采集方式（爬取/API/采购） 复现
pii_categories 列表 决定脱敏策略
scale 样本数/字节数 影响面估算
pipeline_version 处理它的管线版本 数据版本三元组的一部分
notes 自由文本 已知问题（例如"某月起 ToS 变更"）

一个常见的设计错误：把 license 记成自由文本（"CC-BY 或类似"）。枚举化是让它可计算的前提；遇到未知许可就用 unknown，而 unknown 在权利集合里是空集 —— 于是它会自动被拦下，这正是我们想要的默认行为。

5.2 溯源链与撤下流程#

溯源链 = 从 doc_id 到 source_id 的映射（在管线里逐层保留，而不是最后才 join）：

lineage = defaultdict(list)
for d in docs:
    lineage[d["source_id"]].append(d["doc_id"])

# 撤下 source_id = "web-crawl-01"
affected = lineage.get("web-crawl-01", [])     # ['d0', 'd4', 'd8']

本节代码的实测输出：

撤下流程（可执行版）：

  1. 定位：从登记表拿 source_id → 从 lineage 拿全部 doc_id；
  2. 评估影响面：这些样本覆盖了哪些域、占配比多少；是否在测试集里（如果在 → 评测集也要重建，第 1 章 E34）；
  3. 决定动作：删除后重跑管线；如果许可假设是"权重是衍生作品"，还要重训；
  4. 验证：新数据集的指纹、规模、以及受影响的评测指标（重跑同一套评测，报告变化）；
  5. 记录：变更记录（第 1 章 E55）。

没有溯源链时，第 1 步就无法完成，整个流程退化成"重训一遍"或者"什么都不做"。

5.3 数据卡（datasheet）#

数据卡是给下游使用者的说明书，最少要包含：动机（为什么收集）、构成（来源与配比）、采集过程（时间、方式、是否含用户生成内容）、预处理（清洗/去重/过滤的具体步骤与参数）、用途限制（许可、禁止用途）、分发方式、维护计划（多久更新、谁来更新）。

它最有价值的部分是"用途限制"与"已知缺陷"，因为这两块正是下游最容易踩坑的地方。数据卡不是文档工作，它是把撤下成本前移的手段：写清用途限制，才能让下游在选它之前就知道自己不能用。

六、取舍清单#

取舍 一端 另一端 怎么选
许可假设 权重是衍生作品（保守） 权重不是（宽松） 对外发布/高合规场景取保守；把选择写进登记表
raw 留存 全存（可复现） 不存（省存储） 除非有法定保留期限或原始数据极敏感，一律全存
PII 处理强度 只删直接标识（省事） 泛化+加噪（隐私强） 按敏感属性和部署场景定；训练语料一律至少做到"直接标识 + 已知准标识"
PII 召回 vs 精度 高召回（宁删错） 高精度（宁漏） 合规风险场景取高召回 —— 漏一条 PII 的代价远大于误删一条文本
采集覆盖 vs 礼貌 抓得多 抓得慢但稳定 长期管线一律取礼貌：被站点封禁的代价远大于多花的时间
来源数量 少（许可清晰、易审计） 多（覆盖广） 每加一个来源都要问"撤下它的成本是多少"
合成数据比例 高（无限供应） 低（保真） 与第 1 章 E43 同一条纪律：真实数据占比必须显式记录

代码：许可审计、溯源、礼貌采集与 PII 的最小实现#

四段代码对应四个可交付产物。刻意不依赖任何第三方库（re/json/hashlib 都是标准库），因为这一段应该能嵌进任何管线。

# -*- coding: utf-8 -*-
"""来源、许可与合规：四个环节的最小实现（登记表 / 溯源 / 采集 / PII）。"""
import hashlib
import re
from collections import Counter, defaultdict

# ============ 1. 许可阶梯：把法律约束变成可计算的字段 ============
# 每个许可声明的不是"能不能用"，而是**一组被授予的权利**。
RIGHTS = ("train", "commercial", "redistribute", "derivatives", "attribution", "share_alike")
LICENSES = {
    "CC0-1.0":        {"train", "commercial", "redistribute", "derivatives"},
    "MIT":            {"train", "commercial", "redistribute", "derivatives", "attribution"},
    "Apache-2.0":     {"train", "commercial", "redistribute", "derivatives", "attribution"},
    "CC-BY-4.0":      {"train", "commercial", "redistribute", "derivatives", "attribution"},
    "CC-BY-SA-4.0":   {"train", "commercial", "redistribute", "derivatives", "attribution", "share_alike"},
    "CC-BY-NC-4.0":   {"train", "redistribute", "derivatives", "attribution"},   # 无 commercial
    "all-rights-reserved": set(),                                               # 默认保留所有权利
    "unknown":        set(),
}

def audit_use(sources, use="commercial"):
    """给定来源清单与用途，返回 (是否全部允许, 阻塞来源, 需履行的义务)。"""
    blocked = [s["source_id"] for s in sources if use not in LICENSES[s["license"]]]
    duties = set()
    for s in sources:
        r = LICENSES[s["license"]]
        if "attribution" in r:
            duties.add("署名（保留来源与许可声明）")
        if "share_alike" in r:
            duties.add("传染性：衍生作品需同许可（模型权重的法律地位未定）")
    return (not blocked), blocked, sorted(duties)

def strictest(sources):
    """混合来源的约束：**权利取交集，义务取并集**。

    这是"取交集"这个直觉唯一会出错的地方：把 CC0 与 CC-BY-SA 混合时，
    权利交集等于 CC0，看起来"没有额外要求" —— 但署名与传染性义务不会因为
    另一个来源权利更宽就消失。义务必须独立记录并按来源传播。
    """
    rights, duties = set(RIGHTS), set()
    for s in sources:
        r = LICENSES[s["license"]]
        rights &= r
        if "attribution" in r:
            duties.add("署名")
        if "share_alike" in r:
            duties.add("传染性（share-alike）")
    return rights, duties

if __name__ == "__main__":
    print("=== 1. 许可：一组来源，不同用途能不能用 ===")
    REG = [
        {"source_id": "web-crawl-01", "license": "all-rights-reserved", "kind": "公开网页爬取"},
        {"source_id": "wiki-dump",    "license": "CC-BY-SA-4.0",        "kind": "开放数据集"},
        {"source_id": "internal-cs",  "license": "all-rights-reserved", "kind": "自有数据"},
        {"source_id": "cc0-corpus",   "license": "CC0-1.0",             "kind": "开放数据集"},
    ]
    for use in ("train", "commercial", "redistribute"):
        ok, blocked, duties = audit_use(REG, use)
        print(f"   用途 {use:13s} 全部允许 = {ok}   阻塞来源 = {blocked}")
    r_all, d_all = strictest(REG)
    print(f"   整份数据：权利交集 = {sorted(r_all)}   义务并集 = {sorted(d_all)}")
    REG2 = [s for s in REG if s["license"] != "all-rights-reserved"]
    r2, d2 = strictest(REG2)
    print(f"   去掉两个 all-rights-reserved 来源后：权利交集 = {sorted(r2)}")
    print(f"                                        义务并集 = {sorted(d2)}   <- 义务没有被取交集消掉")
    print("   注：'train' 在 all-rights-reserved 下为空集 —— 最保守假设下即不可用")

    # ============ 2. 来源登记 + 溯源 + 撤下 ============
    print("\n=== 2. 溯源：从 source_id 回追受影响的样本 ===")
    docs = [{"doc_id": f"d{i}",
             "source_id": ["web-crawl-01", "wiki-dump", "internal-cs", "cc0-corpus"][i % 4]}
            for i in range(12)]

    print("\n=== 3. 采集：robots + 限速 + 内容去重 + 软 404 检测 ===")
    ROBOTS = "User-agent: *\nDisallow: /private\nCrawl-delay: 1\n"
    def robots_allows(path, rule=ROBOTS):
        dis = [l.split(":", 1)[1].strip() for l in rule.splitlines()
               if l.lower().startswith("disallow")]
        return not any(path.startswith(d) for d in dis if d)
    PAGES = {
        "https://x.test/a": "深度学习模型的训练需要大量高质量数据。",
        "https://x.test/b": "深度学习模型的训练需要大量高质量数据。",     # 重复内容

        "https://x.test/private/x": "机密内容",
    }
    LOGIN_MARKERS = ("请登录", "登录后查看", "Sign in")
    def fetch(url):
        return PAGES.get(url, "")

    delay = float([l.split(":", 1)[1] for l in ROBOTS.splitlines()
                   if l.lower().startswith("crawl-delay")][0])
    clock = {"t": 0.0}
    def schedule(url):
        """虚拟时钟：同一站的两次请求至少间隔 crawl-delay 秒。"""
        clock["t"] += delay
        return clock["t"]
    for url in ["https://x.test/a", "https://x.test/b", "https://x.test/c",
                "https://x.test/private/x", "https://x.test/missing"]:
        path = "/" + url.split("/", 3)[3]
        if not robots_allows(path):
            skipped.append((url, "robots 禁止")); continue
        html = fetch(url)
        if not html:
            skipped.append((url, "空响应（软 404）")); continue
        if any(m in html for m in LOGIN_MARKERS):
            skipped.append((url, "反爬静默降级：返回登录页")); continue
        h = hashlib.sha256(html.encode()).hexdigest()[:12]
        if h in seen_hash:
            skipped.append((url, "内容重复")); continue
        seen_hash.add(h); kept.append((url, h, schedule(url)))
    for u, h, t in kept:
        print(f"   保留 {u}  hash={h}  虚拟时刻 t={t:.1f}s（Crawl-delay={delay:g}s）")
    for u, why in skipped:
        print(f"   跳过 {u:32s} 原因: {why}")
    print("   关键：'登录页'与'空响应'都必须被显式识别 —— 否则它们会作为低质语料进入训练集")

    # ============ 4. PII：删掉姓名远远不够（准标识重识别） ============
    print("\n=== 4. PII 与准标识：k-匿名的最小演示 ===")
    PII = [("邮箱", re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")),
           ("手机", re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")),
           ("身份证", re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)"))]
    text = "联系 zhang@example.com 或 13812345678，身份证 11010119900307123X。"
    masked, hits = text, []
    for name, pat in PII:
        for m in pat.finditer(masked):
            hits.append((name, m.group()))
        masked = pat.sub(f"[{name}]", masked)        # 确定性替换：同一实体 -> 同一占位符
    print("   原始:", text)
    print("   脱敏:", masked)
    print("   命中:", hits)
    # 准标识（邮编+出生年+性别）—— 即使删掉姓名，仍可唯一化
    rows = [(100084, 1990, "男"), (100084, 1990, "男"), (100084, 1990, "女"),
            (200000, 1985, "男"), (200000, 1985, "男"), (200000, 1985, "男"),
            (518000, 1978, "女")]
    cls = Counter(rows)
    print(f"   删掉姓名后，准标识等价类大小 = {sorted(cls.values())}")
    print("   上面出现大小为 1 的等价类 —— 该记录仍可被唯一识别；"

每个实现决策背后的理由：

  • 许可用"权利集合"而不是"能否使用"的布尔值：因为用途是多维的（训练/商用/再分发/衍生），布尔值会在遇到"能训练但不能再分发"这种许可时立刻失效。集合模型天然支持"取交集"与"逐用途查询"。
  • unknown 与 all-rights-reserved 都映射到空集：这是fail-closed（默认拒绝）的设计。如果未知许可被当成允许，那么任何一个字段缺失都会变成一次无意的侵权；反过来，字段缺失只会让一部分数据被拦下，人工复核后放行。在合规问题上，默认值必须是拒绝。
  • strictest() 同时返回权利与义务，并且在注释里点名这是"取交集"直觉的出错点。代码实测证明了这一点：去掉两个全版权来源后权利交集从 [] 变成了四项，但义务并集一个字都没少。
  • 溯源用 defaultdict(list) 在管线内逐层保留，而不是最后才 join。原因是"最后 join"在真实管线里几乎做不到 —— 中间步骤（过滤、去重）会丢字段。溯源链必须在每一步都显式传递，这是管线设计的一部分，不是查询技巧。
  • 采集器把"空响应"和"登录页"当成显式跳过原因，而不是靠状态码。这两条检查是本节最有工程价值的两行代码：它们的量可能占整个批次，而危害（低质语料 + 隐私风险）完全静默。
  • PII 脱敏是确定性替换（[邮箱]、[手机]），不是随机加噪。这一点决定了它能否与去重共存（第 4 节展开）：确定性替换后同一内容的指纹稳定，去重仍然有效；随机化则会破坏去重。
  • k-匿名的演示只用了三个准标识，就产生了大小为 1 的等价类。这说明"已删除姓名"这种合规声明几乎没有保护作用 —— 有效的做法是先定义"什么是可接受的不可识别性"，再决定泛化到什么粒度。
  • ⚠️ 本段代码是教学实现：正则 PII 检测的召回率很低（姓名、地址、机构名、以及"我们镇上唯一的三甲医院"这类可反推表述全都抓不到）。生产环境要用 NER 模型 + 人工抽检，并明确记录已知的漏检类别。

小结#

  • 来源分六类，工程属性（许可清晰度、PII 风险、可复现性）差异极大，而且"可得性高"与"许可清晰"几乎负相关 —— 所以真实管线必然是混合来源，混合就是麻烦的来源。
  • 许可阶梯按"授予的权利"记，而不是按名字记。两个最常见的误解：没有声明 ≠ 可以用（版权自动生效）；公开可访问 ≠ 可以使用。
  • 混合来源时：权利取交集，义务取并集。 代码实测证明"取交集"的直觉会在义务上出错（去掉全版权来源后权利交集从空集变成四项，义务一个字都没少）。unknown 与 all-rights-reserved 都映射到空集 —— 合规问题的默认值必须是拒绝。
  • 传播问题（模型权重是否衍生作品）法律未定，工程上必须按最保守假设登记并把选择写下来，因为它决定了撤下成本差一个数量级。
  • 删掉姓名远远不够：代码里仅用"邮编+出生年+性别"三个准标识就产生了大小为 1 的等价类。k-匿名/ℓ-多样性/差分隐私各有代价，且对非结构化文本很难直接套用（要先结构化或做实体替换）。
  • LLM 引入了新层面：模型会记住训练数据 → 成员推断与训练数据提取攻击。重复数据的隐私风险是超线性的，所以去重也有隐私收益。"删除训练数据"≠"模型忘记"，唯一可靠的隐私手段是前移到数据管线。
  • 采集的五类失败模式（软 404、反爬静默降级、动态渲染、编码错误、分页陷阱）全部返回 200，只看状态码的采集器会把它们全部当成成功。代码把前两类做成了显式检查。
  • 两个可交付产物：来源登记表（许可枚举化、fail-closed）与溯源链（逐层传递，不在最后 join）。有它们，撤下是一条命令；没有它们，撤下是一场灾难。
  • raw 层不可变是所有可复现性与许可复核的基础，代价是 3~10 倍存储 —— 除非法定保留期限或原始数据极敏感，这个代价几乎总是值得的。
