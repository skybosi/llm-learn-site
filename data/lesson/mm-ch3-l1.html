Stable Diffusion 架构#

第 2 章讲的是"像素空间里的扩散"。直接对高分辨率图像跑扩散，每一步都要在高维像素张量上做前向/反向，计算量巨大。Stable Diffusion 的核心创新是把扩散搬进一个低维潜空间（latent space），再配上文本条件，让"文生图"真正跑进消费级显卡。这一课拆解它的整体架构——三件套（VAE、U-Net、文本编码器）各司其职，以及它们如何串成一条流水线。

一、概念讲解#

1. 动机：像素空间太"贵"#

一张 512×512×3 的图像约 78 万个值，而 DDPM 要在其上跑上百步。扩散模型真正要学的，是图像在语义层面的变化（物体结构、纹理、光照），这些语义信息其实存在于一个低得多的维度里。于是有了 Latent Diffusion（潜空间扩散） 的想法：先用一个自编码器把图像压缩到潜空间，在潜空间里做扩散，最后再解码回像素。

2. 三件套：VAE、U-Net、文本编码器#

Stable Diffusion 由三个神经网络组成：

  • VAE（变分自编码器）：负责像素 ↔ 潜变量的双向转换。编码器 E 把图像压成潜变量（通常下采样 8 倍，如 512×512×3 → 64×64×4），解码器 D 把潜变量还原成图像。注意：这个 VAE 是预先训练好的感知压缩器，在扩散训练时通常冻结，不参与去噪。
  • U-Net（去噪网络）：潜空间里的 ε_θ，执行第 2 章讲的反向去噪，只不过输入输出都是潜变量而非像素。它含编码器、解码器、跳跃连接，以及注意力层（用于注入文本）。
  • 文本编码器（CLIP Text Encoder）：把 prompt 变成一个语义向量序列，作为条件喂给 U-Net。它来自 CLIP，在图文对数据上用对比学习训练，能理解"自然语言 ↔ 图像"的对应关系。

3. 为什么在潜空间扩散又快又好#

  • 省算力：潜变量维度远小于像素，单步计算量骤降，百步扩散在普通 GPU 上也可行；
  • 语义集中：VAE 的压缩会"留住语义、丢掉像素级噪声"，潜空间里的扩散更关注"内容"，天然对高频纹理没那么敏感；
  • 解耦：压缩（VAE）与生成（U-Net）分离，各部分可以独立训练、独立复用。

4. 一条完整的生成流水线#

文生图的推理过程是：

  1. 文本编码：prompt 经 CLIP 文本编码器变成条件向量序列；
  2. 采样初始噪声：z_T ~ N(0, I)，形状如 [1, 4, 64, 64]；
  3. 潜空间去噪：U-Net 在文本条件下，逐步把 z_T 去噪成 z_0；
  4. 解码：VAE 解码器把 z_0 放大 8 倍，得到最终 512×512 图像。

可以看到，第 2 章的 DDPM 在这里被完整复用了——只是"数据"从像素换成了潜变量，数学几乎一字不差。这就是"理解 DDPM，就能读懂 Stable Diffusion"的原因。

5. 关键参数量级#

以 stable-diffusion-v1-5 为例：VAE 编码器把 512×512×3 压到 64×64×4（48 倍压缩）；U-Net 约 8.6 亿参数，是整条流水线的算力主力；CLIP 文本编码器约 1.2 亿参数，负责"读懂提示词"。三者合计，让文生图模型能装进一张消费级显卡。

二、可运行代码示例#

用 diffusers 加载 Stable Diffusion，拆开看三件套各自的类型与潜空间的维度。首次运行会联网下载权重。

from diffusers import StableDiffusionPipeline
import torch

# —— 加载完整流水线（VAE + U-Net + CLIP + 调度器都已打包好） ——
pipe = StableDiffusionPipeline.from_pretrained(
    "runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16
)
pipe.to("cuda")   # 无 GPU 则改为 pipe.to("cpu")

# —— 三个神经网络各司其职 ——
print("文本编码器:", type(pipe.text_encoder).__name__)   # CLIPTextModel
print("去噪 U-Net :", type(pipe.unet).__name__)          # UNet2DConditionModel
print("VAE        :", type(pipe.vae).__name__)           # AutoencoderKL
print("调度器     :", type(pipe.scheduler).__name__)     # PNDMScheduler 等

# —— 潜空间的维度：512×512 图像 → 64×64×4 的潜变量 ——
latent = torch.randn(1, 4, 64, 64, device="cuda", dtype=torch.float16)
print("潜变量形状:", tuple(latent.shape))   # (1, 4, 64, 64)：比像素小 8×8=64 倍面积

再跑一次完整生成，感受三件套的协同：

# —— 一条 prompt → 一张图 ——
prompt = "a red panda reading a book, studio light, highly detailed"
image = pipe(prompt, num_inference_steps=25, guidance_scale=7.5).images[0]
image.save("red_panda.png")
print("已生成 red_panda.png")

这段代码在背后依次完成了第 4 节的四步流水线。你只需要记住一个对应关系：pipe.text_encoder 读懂文字、pipe.unet 在潜空间去噪、pipe.vae 把潜变量变成图像、pipe.scheduler 决定"怎么一步步去噪"（采样与加速在第 3 课）。

三、练习#

  1. 运行上面的代码，打印三件套的参数量（sum(p.numel() for p in m.parameters())），对比 U-Net、VAE、CLIP 各自的规模，体会谁是算力主力。
  2. 把 num_inference_steps 固定为 25，换几个风格迥异的 prompt（写实照片 / 油画 / 3D 渲染），观察文本编码器如何把不同语义"翻译"进同一套生成流程。
  3. 思考题：为什么把扩散从像素搬到潜空间，图像质量反而能保持甚至更好？从"VAE 压缩丢掉了什么、留住了什么"的角度说明。
  4. 用 pipe.vae.encode 对一张真实图片编码得到潜变量，再 pipe.vae.decode 还原，对比原图与还原图的差异，直观理解"感知压缩"的有损程度。
  5. 调研题：查阅 Latent Diffusion 论文，找出 VAE 下采样倍数（8 倍）与潜通道数（4）这两个超参数，讨论放大/缩小它们对"质量 vs 速度"的影响。
