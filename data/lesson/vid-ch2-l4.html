跟踪与分割：关联问题、ID switch 的代价与时序一致性#

这一节要解决什么#

前三节的对象都是"整段视频"：一个类别、一个区间、一句话。这一节把粒度降到对象：

同一帧里有 n 个对象，模型不仅要检出它们，还要知道"这一帧的左车"和"上一帧的左车"是同一个东西。这个"知道"的代价是什么？分割还多一层——对象的掩码必须跨帧稳定。

这一节的结论如下：

  1. 关联就是逐帧的二分图匹配，而它的代价函数是一个可校准的旋钮。 构造算例里，纯运动（λ=0）的判定是错的：正确指派总代价 1.641026 高于交换指派的 1.518519（表 1）。

  2. 翻转判定所需的 λ 有一个可算下界。 本算例 λ∗>0.031037：外观项必须强到足以翻转运动项的符号——λ 不是可以"拍一个 0.5"的超参（表 1）。

  3. 贪心关联不是最优解。 同一份代价矩阵，贪心比匈牙利差 +0.215005 到 +1.121369（三个随机反例，规模 n=2,3,4）；匈牙利与暴力枚举在 n≤4 上给出完全相同的总代价，而复杂度是 O(n3) 对 O(n!)（表 2）。

  4. ID switch 的期望数与轨迹长度成正比，而"从未断链"的概率随长度指数衰减。 E[switches]=L(1−p)：p=0.999 时 L=30→0.030000、L=1000→1.000000；p=0.99,L=300 时"从未断链"只剩 0.049041，而 sd=1.723369 与均值 3.0 同量级（表 3）。

  5. ID switch 的代价可以换算成标注工时。 每小时素材 18.00 次断链、每次修正 5 秒 ⇒ 0.025000 工时/小时素材 ⇒ 1000 小时素材要 25.00 工时（表 3）。这个数字直接进第 1 章第 4 节那条成本公式的 c 项。

  6. IDF1 与 MOTA 的排名可以相反。 关联误差 0.20、检测误差 0.05 时 IDF1 =0.790000 而 MOTA =0.875000；反过来（检测 0.20、关联 0.05）IDF1 =0.910000、MOTA =0.800000。"跟踪得更好"必须指定指标（表 3）。

  7. 掩码传播是一条几何衰减链。 单帧传播成功率 q 时，可传播时长是 1/(1−q) 帧：q=0.999→1000 帧、q=0.99→100 帧、q=0.95→20 帧。要传 300 帧（10 秒 @30 fps）最低要求 q≥1−1/300=0.996667（表 4）。

  8. 重锚周期不是工程习惯，而是算出来的。 tmax​(ρ)=lnρ/lnq：ρ=0.9,q=0.99 时只能传 10.48 帧——"每隔约 10 帧重锚一次"就是这个式子的输出（表 4）。

  9. 时序一致性必须按物体大小分层，因为抖动代价差两个量级。 5 px 的边界抖动对 R=5 px 的物体打掉 0.756990 的 IoU，对 R=100 px 的物体只打掉 0.061692（表 5）。

  10. 闪烁有三个来源，必须分别量。 逐帧独立分割、传播漂移、重锚跳变——三者的修法完全不同（加传播 / 加锚 / 平滑过渡），只报一个"全局时序 IoU"会把它们混成一个数（表 5）。

主线一句话：跟踪与分割把"时序"从"模型的输入维度"变成了"输出的约束"——跟踪约束的是身份，分割约束的是掩码；两者的失败都不是"某一帧错了"，而是"错误在时间上累积"。

一、任务定义：从"检出"到"对应"#

1.1 多目标跟踪（MOT）的形式化#

给定视频，输出轨迹集合 {τk​}k=1K​，每条轨迹是一串 (帧,框)：

τk​={(t,bt(k)​)}t∈Tk​​,bt(k)​∈R4.

它比第二节的时序检测多了互斥性约束：

∀t, ∀k=k′,IoU(bt(k)​,bt(k′)​) 应当很小（同一帧一个对象只属于一条轨迹）.

这个约束是本节全部难度的来源：预测不再是"每个输出独立"，而是"输出之间必须互相一致"。

1.2 视频分割的形式化#

视频分割（VOS / VIS）输出掩码序列 {Mt​}t=1T​，Mt​∈{0,1}H×W（或多类标签图），并满足时序一致性：

若 p∈Mt​ 且 p 在 t→t+1 的运动是 u, 则 p+u∈Mt+1​.

注意这条约束不是损失函数——它是对输出的约束，模型可以选择不满足，但会体现在指标上。

1.3 两个任务共享的一个结构#

任务 逐帧子问题 跨帧约束 失败形态
MOT 检测 + 关联 身份唯一、框不重叠 ID switch
VOS 逐帧分割 掩码随运动一致 抖动、漂移、闪烁

共同点：逐帧的质量上界由检测/分割模型给出，跨帧的质量上界由"传播/关联"给出，而后者往往才是瓶颈。本节的算例全部围绕后者。

二、关联：从代价函数到指派算法#

2.1 代价函数#

第 t 帧的轨迹集合 O（用运动模型外推到 t）、检测集合 D。关联的代价

C[i][j]=运动项∈[0,1]1−IoU(bipred​,jdet​)​​+λ⋅外观项∈[0,2]dapp​(i,j)​​.

C[i][j]=运动项∈[0,1]1−IoU(bipred​,jdet​)​​+λ⋅外观项∈[0,2]dapp​(i,j)​​.

外观项归一化到 [0,2]（余弦距离）不是审美选择，而是量纲要求——否则 λ 的数值不可比，调参变成调量纲。

四条读法：

  1. λ=0（纯运动）会选错。这就是"只看 IoU 的跟踪在交叉/遮挡处必然崩"的算术形式。
  2. 翻转所需的 λ∗>0.031037 是算出来的下界，不是经验值。
  3. λ 太大时外观误差会盖住运动（遮挡后外观模型漂移）；所以 λ 通常按轨迹年龄/遮挡状态分段设置。
  4. 代价函数的形状决定了一切。它同时决定了"关联算法的输入"与"跟踪器的失效模式"，所以在跟踪系统里它比主干网络更值得调。

2.3 指派算法：贪心不是最优#

关联是线性指派问题：在 n×n 代价矩阵上找最小总代价的置换。

算法 复杂度 精确性
暴力枚举 O(n!) 精确
匈牙利 / Jonker–Volgenant O(n3) 精确
贪心（按边权排序取不冲突的边） O(n2logn) 一般不最优

实测（三个固定种子的随机代价矩阵）：

规模 n 暴力 O(n!) 匈牙利 O(n3) 贪心 贪心是否最优
2（seed=3） 2 8 4.0 否（差 +0.652618）
3（seed=1） 6 27 14.3 否（差 +0.215005）
4（seed=2） 24 64 32.0 否（差 +1.121369）

读法：

  1. 匈牙利与暴力在这三个反例上给出完全相同的总代价——这是对实现的正确性校验。
  2. 贪心在 n=2 上就有反例，偏差在 +0.215005 到 +1.121369 之间。同一份代价矩阵，换个匹配算法就差这么多。
  3. 轨迹数与检测数不等时要补虚拟节点（代价设成大于任何真实配对的常数），否则算法会强行全部匹配。
  4. 关联的复杂度与检测数超线性相关，所以"先按置信度/NMS 裁剪检测再关联"是常规做法；代价是漏检直接变成关联失败——检测阈值与关联阈值不能分开调。

3.3 指标：IDF1 与 MOTA 可以给出相反的排名#

把跟踪误差拆成检测误差与关联误差两部分。两个指标对它们的敏感度完全不同：

  • IDF1：只看"关联是否保持"来判正误，对关联误差敏感；
  • MOTA =1−(FN+FP+IDS)/GT：对检测误差敏感，而 IDS 只占一小项。

构造关系（IDF1 =1−0.20⋅det−1.00⋅assoc，MOTA =1−0.90⋅det−0.40⋅assoc）：

0.20 0.05 0.910000 0.800000 IDF1
0.20 0.20 0.760000 0.740000 IDF1

读法：关联误差大时 IDF1 更低（关联主导），检测误差大时 MOTA 更低（检测主导）。"跟踪得更好"这句话必须指定指标；在跟踪文献里换指标的收益有时比换模型更大。

判据：报跟踪结果时至少给 (IDF1, MOTA, IDS) 三元组，并说明关联代价函数（λ 与外观模型）——因为这两个数字都可以被"把检测裁剪得更狠"或"把轨迹切得更碎"单独推高。

def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1 for ch in s)


def pad(s, w, align=">"):
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2

def iou_1d(a, b):
    lo = max(a[0], b[0])
    hi = min(a[1], b[1])
    inter = max(0.0, hi - lo)
    union = (a[1] - a[0]) + (b[1] - b[0]) - inter
    return inter / union if union > 0 else 0.0

print("  O(n^3)       匈牙利 / Jonker-Volgenant（精确）")
print("  O(n log n)   贪心（按边权排序依次选不冲突的边，**一般不最优**）")

def brute(C, n):
    best, arg = float("inf"), None
    for p in itertools.permutations(range(n)):
        v = sum(C[(i, p[i])] for i in range(n))
        if v < best:
            best, arg = v, p
    return best, arg


def hungarian(C, n):
    """O(n^3) 匈牙利算法（最小化）。"""
    INF = float("inf")
    u = [0.0] * (n + 1)
    v = [0.0] * (n + 1)
    p = [0] * (n + 1)
    way = [0] * (n + 1)
    for i in range(1, n + 1):
        p[0] = i
        j0 = 0
        minv = [INF] * (n + 1)
        used = [False] * (n + 1)
        while True:
            used[j0] = True
            i0 = p[j0]
            delta = INF
            j1 = -1
            for j in range(1, n + 1):
                if not used[j]:
                    cur = C[(i0 - 1, j - 1)] - u[i0] - v[j]
                    if cur < minv[j]:
                        minv[j] = cur
                        way[j] = j0
                    if minv[j] < delta:
                        delta = minv[j]
                        j1 = j
            for j in range(n + 1):
                if used[j]:
                    u[p[j]] += delta
                    v[j] -= delta
                else:
                    minv[j] -= delta
            j0 = j1
            if p[j0] == 0:
                break
        while j0:
            j1 = way[j0]
            p[j0] = p[j1]
            j0 = j1
    assign = [0] * n
    for j in range(1, n + 1):
        assign[p[j] - 1] = j - 1
    return sum(C[(i, assign[i])] for i in range(n)), tuple(assign)


def greedy(C, n):
    edges = sorted(((C[(i, j)], i, j) for i in range(n) for j in range(n)))
    used_i, used_j, assign, tot = set(), set(), [-1] * n, 0.0
    for c, i, j in edges:
        if i in used_i or j in used_j:
            continue
        used_i.add(i)
        used_j.add(j)
        assign[i] = j
        tot += c
    return tot, tuple(assign)

# 构造：半径为 R 的圆，中心以 v px/帧 运动，每帧独立分割抖动 sigma_j
def circle_overlap_area(R, d):
    """半径 R 的两圆、圆心距 d 的交叠面积（精确）。"""
    if d >= 2 * R:
        return 0.0
    if d <= 0.0:
        return math.pi * R * R
    return 2 * R * R * math.acos(d / (2 * R)) - 0.5 * d * math.sqrt(4 * R * R - d * d)


def circle_iou(R, d):
    inter = circle_overlap_area(R, d)
    return inter / (2 * math.pi * R * R - inter)

小结#

  • 关联是二分图匹配，代价函数是可校准的旋钮。 λ=0（纯运动）在算例里判定错误（正确总代价 1.641026 > 交换 1.518519）；翻转所需 λ∗>0.031037——下界可以算，不必拍脑袋。外观项必须归一化到 [0,2]，否则调参变成调量纲。
  • 贪心不是最优：三组随机代价矩阵上偏差 +0.215005 到 +1.121369；匈牙利与暴力在 n≤4 上总代价完全相同，复杂度 O(n3) vs O(n!)。轨迹数与检测数不等时要补虚拟节点。
  • ID switch 的账：E[switches]=L(1−p)（p=0.999：L:30→1000 时 0.030000→1.000000），P(从未断链)=pL（p=0.99,L=300 时 0.049041），sd 与均值同量级。长轨迹是主要来源。
  • 标签错误的代价是工时：18 次/小时、5 秒/次 ⇒ 0.025000 工时/小时素材 ⇒ 1000 小时素材 25.00 工时——这笔钱进第 1 章第 4 节的成本公式。
  • IDF1 与 MOTA 排名可以相反：关联误差 0.20 时 IDF1 0.790000 < MOTA 0.875000；检测误差 0.20 时 IDF1 0.910000 > MOTA 0.800000。报数必须给 (IDF1,MOTA,IDS) 三元组。
  • 掩码传播是一条几何衰减链：可传播时长 1/(1−q)（q=0.999→1000、0.99→100、0.95→20 帧）；传 300 帧需 q≥0.996667。
  • 重锚周期可算：tmax​(ρ)=lnρ/lnq；ρ=0.9,q=0.99→10.48 帧。"每隔约 10 帧重锚"是算出来的，不是习惯；且真实误差相关，实际比这更短。
  • 时序一致性必须按物体大小分层：5 px 抖动打掉 R=5 的 0.756990 IoU、只打掉 R=100 的 0.061692——差两个量级。
  • 闪烁的三个来源（独立分割 / 传播漂移 / 重锚跳变）必须分别量，因为修法完全不同。
