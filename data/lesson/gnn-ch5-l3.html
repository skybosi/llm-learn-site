评估#

模型训完了，怎么判断它到底好不好？评估不是"跑一遍 acc 就完事"——图数据有几类特有的陷阱，稍不注意就会得出虚高的结论。本课系统梳理节点分类与图分类的评估指标、数据划分的正确姿势，以及 GNN 论文里反复强调的评估误区。

一、概念讲解#

1. 基础指标：准确率之外的维度#

准确率（Accuracy）是默认指标，但在类别不平衡时具有欺骗性：一个"全部预测为多数类"的模型也能拿到高准确率。因此要补充：

  • 精确率（Precision）：预测为正的样本里，真正为正的比例。P = TP / (TP + FP)
  • 召回率（Recall）：真正的正样本里，被预测出来的比例。R = TP / (TP + FN)
  • F1 分数：精确率与召回率的调和平均。F1 = 2PR / (P + R)
  • 宏平均（macro）与微平均（micro）：多分类里，宏平均对每类指标取平均（每个类别一视同仁，适合类别不平衡），微平均先汇总 TP/FP/FN 再算（受大类影响大）。
  • ROC-AUC：二分类时，遍历阈值画出真阳率-假阳率曲线下的面积，衡量"排序"能力，对类别不平衡更稳健。

选择建议：平衡数据看准确率即可；不平衡数据必须看宏 F1 或 AUC。

2. 数据划分：图数据最容易踩的坑#

这是 GNN 评估的重灾区，务必分场景记牢：

  • 节点分类（直推式）：训练/验证/测试共享一张图。标准做法是用数据集自带的掩码（Cora 等）或随机按节点划分。风险在于结构泄漏——测试节点的邻居可能就在训练集里，模型"见过"它们的特征和连边。这不是 bug，而是直推式设定的固有属性，但报告结果时要明白其含义。
  • 图分类（归纳式）：必须按整图划分，绝不能按节点划分。若把一个分子图的部分原子划进训练、部分划进测试，等价于把答案泄漏给模型，准确率会虚高。PyG 里 random_split 直接按图对象切分即可。
  • 固定划分 vs 随机划分：Cora 等数据集有公认的固定划分（每类 20 个训练节点），用它能保证与文献可比；自建数据集常用分层抽样，保证每个类别在训练/测试里比例一致。

3. 模型选择与实验协议#

  • 验证集选模型、测试集只报一次：在验证集上挑超参数/早停，最后只在测试集上报告一次结果。反复在测试集上调参等于把测试集变成了训练集，结果不可信。
  • 多次随机种子报告均值±标准差：GNN 训练对初始化、数据划分敏感，单次结果波动大。应跑 5–10 个种子，报告 均值 ± 标准差，而不是"某一次最好的数"。
  • 早停：监控验证集指标，连续若干轮不提升就停止，防止过拟合（训练集极小、噪音大时尤其必要）。

4. GNN 特有的评估陷阱#

文献中反复被点名的几个问题：

  • 只用一层模型就下结论：GNN 效果高度依赖层数、隐藏维、dropout，简单模型没调好不等于方法不好。
  • 拿"全监督"与"半监督"比：训练标签数量不同，准确率不可直接比较，必须对齐训练规模。
  • 忽略"过平滑"导致的退化：一味堆层数，测试集反而下降，评估时要报告层数敏感性。
  • 小数据集上的过拟合：MUTAG、ENZYMES 这类几十到几百个图的数据集，方差极大，报告单次最优毫无意义，务必多种子。

5. 一个可复用的评估 checklist#

  1. 明确任务（节点/图分类）与数据划分方式是否合理；
  2. 选对指标（平衡→acc，不平衡→宏 F1/AUC）；
  3. 用验证集早停，测试集只报一次；
  4. 跑多种子，报告均值±标准差；
  5. 与同设定、同训练规模的基线对比，而非与"全监督"或"更多标签"的结果比。

二、可运行示例#

示例：节点分类的多指标评估 + 多种子报告

import torch
import torch.nn.functional as F
from torch_geometric.nn import GCNConv
from torch_geometric.datasets import Planetoid
from sklearn.metrics import accuracy_score, f1_score, confusion_matrix, roc_auc_score

dataset = Planetoid(root='./data/Cora', name='Cora')
data = dataset[0]

class GCN(torch.nn.Module):
    def __init__(self, in_ch, hidden_ch, out_ch):
        super().__init__()
        self.conv1 = GCNConv(in_ch, hidden_ch)
        self.conv2 = GCNConv(hidden_ch, out_ch)
    def forward(self, x, ei):
        x = F.relu(self.conv1(x, ei))
        x = F.dropout(x, p=0.5, training=self.training)
        return F.log_softmax(self.conv2(x, ei), dim=1)

def run_once(seed):
    torch.manual_seed(seed)   # 固定随机种子，保证可复现
    model = GCN(dataset.num_features, 16, dataset.num_classes)
    opt = torch.optim.Adam(model.parameters(), lr=0.01, weight_decay=5e-4)
    best_val = 0.0; best_state = None
    for epoch in range(200):
        model.train(); opt.zero_grad()
        out = model(data.x, data.edge_index)
        loss = F.nll_loss(out[data.train_mask], data.y[data.train_mask])
        loss.backward(); opt.step()
        model.eval()
        pred = model(data.x, data.edge_index).argmax(dim=1)
        val = (pred[data.val_mask] == data.y[data.val_mask]).float().mean().item()
        if val > best_val:        # 早停：只保留验证集最优
            best_val = val
            best_state = {k: v.clone() for k, v in model.state_dict().items()}
    model.load_state_dict(best_state)
    model.eval()
    pred = model(data.x, data.edge_index).argmax(dim=1)
    y_true = data.y[data.test_mask].cpu().numpy()
    y_pred = pred[data.test_mask].cpu().numpy()
    acc = accuracy_score(y_true, y_pred)
    macro_f1 = f1_score(y_true, y_pred, average='macro')   # 不平衡时更可靠
    return acc, macro_f1

# 跑 5 个种子，报告均值 ± 标准差
accs, f1s = [], []
for seed in range(5):
    a, f = run_once(seed)
    accs.append(a); f1s.append(f)

import statistics
print(f'Accuracy : {statistics.mean(accs):.4f} ± {statistics.stdev(accs):.4f}')
print(f'Macro-F1 : {statistics.mean(f1s):.4f} ± {statistics.stdev(f1s):.4f}')

# 打印混淆矩阵（可选）：看哪几类之间容易混淆
model = GCN(dataset.num_features, 16, dataset.num_classes)
# （此处省略重复训练，实际应复用上面某次训练的模型）

Cora 是多分类且类别较平衡，准确率与宏 F1 接近。若换成不平衡数据，二者会出现明显差距——这正是"为何不能只看 acc"的最好说明。

图分类的评估：只需把预测目标从 data.y[test_mask] 换成 data.y（整图标签），并改用 random_split 按图划分、DataLoader 批处理，指标计算逻辑完全一致。关键是划分单位是"图"。

三、练习#

  1. 手算指标：给定一个二分类混淆矩阵 TP=8, FP=2, FN=4, TN=86，手算准确率、精确率、召回率、F1，并判断该任务是否类别不平衡。
  2. 划分陷阱：写一小段代码，把 MUTAG 数据集分别按"整图"和"按节点打乱"两种方式划分，都训练同一个 GIN，对比测试准确率，解释差异从何而来。
  3. 多种子报告：把示例改成跑 10 个种子，观察均值±标准差是否比单次结果更稳定，理解"报告单次最优"为何会误导。
  4. 指标选择：构造（或找一个）类别严重不平衡的数据集，分别计算准确率与宏 F1，说明哪个指标更能反映真实性能。
  5. AUC 探究：用 roc_auc_score 对二分类图任务（如 MUTAG）计算 AUC，并解释 AUC 为什么对类别不平衡不敏感。
