评估基准#

模型练得再好，也要能"量"出来才知道好不好。评估基准（benchmark）就是一套标准化的测试题 + 计分规则，用来客观比较不同模型的水平。本课讲清为什么要评估、常见的基准有哪些、各类指标怎么算，以及评估时必须警惕的"数据污染"问题。

一、概念讲解#

1. 为什么要评估#

预训练时我们只看困惑度（perplexity），但它只反映"语言流利度"，不反映"会不会解题、会不会写代码、会不会诚实作答"。要判断一个模型"能不能用"，必须放到下游任务上考。评估基准提供了统一、可复现的"考卷"，让不同模型的分数可以横向比较。

2. 常见的评估基准#

按考察维度分类：

  • 知识问答：MMLU（57 个学科的多选题，覆盖人文、STEM、社科），衡量通用知识广度。
  • 数学推理：GSM8K（约 8500 道小学应用题），考察多步数值推理。
  • 代码生成：HumanEval（手写的编程题 + 单元测试），看模型能否写出通过测试的代码。
  • 常识/自然语言理解：HellaSwag（选最合理的句子续写），考察常识推理。
  • 真实性：TruthfulQA（专门挑"容易诱导模型编造"的问题），考察是否诚实。

3. 常用指标怎么算#

不同任务用不同指标：

  • 准确率（accuracy）：多选题/分类题——答对的比例。
  • 精确匹配（Exact Match, EM）：生成题——模型输出与标准答案逐字符相等才算对。
  • pass@k：代码题——生成 k 份代码，只要有一份通过全部单元测试，该题即算通过；再对题目求平均。
  • PPL（困惑度）：衡量语言建模本身，越低越好。

指标的选择直接影响结论：EM 太严（"16 颗"和"16"也算不同），pass@k 太松（k 越大越容易碰对）。看排行榜时，先看"用的什么指标"。

4. 评估协议：怎么"考"#

主流做法是少样本（few-shot）：把每条题用统一模板包装，前面附几个示例，让模型生成答案，再用规则或脚本判分。也有零样本考法。评估时通常用贪心解码（temperature≈0）保证可复现；生成类任务则可能采样多次（配合 pass@k 或自一致性投票）。

5. 警惕数据污染#

基准题如果被混进了预训练语料，模型可能背过答案，分数虚高却毫无意义——这叫数据污染（contamination）。评估时要做去污检测：检查题目（或其改写）是否出现在训练语料里。这也是为什么"新出、保密、定期更新"的基准更有公信力。

二、可运行示例#

下面写一个迷你评估 harness：给定一批题目的参考答案和模型的输出，分别计算准确率、精确匹配，并演示 pass@k 的计分。

# —— 一个极简的评估脚本：算准确率 / 精确匹配 / pass@k ——

def accuracy(preds, golds):
    """分类/选择类：答对比例。"""
    correct = sum(p == g for p, g in zip(preds, golds))
    return correct / len(golds)

def exact_match(preds, golds):
    """生成类：逐字符相等的比例。"""
    correct = sum(p.strip() == g.strip() for p, g in zip(preds, golds))
    return correct / len(golds)

def pass_at_k(samples_per_question, is_pass):
    """代码类：每题生成 k 份，只要有 1 份通过测试即算过。"""
    total = len(samples_per_question)
    passed = sum(any(is_pass(code) for code in samples) for samples in samples_per_question)
    return passed / total

# —— 模拟一个 MMLU 风格的多选题评估 ——
preds = ["A", "C", "B", "A", "D"]
golds = ["A", "C", "D", "A", "D"]
print("多选题准确率：", f"{accuracy(preds, golds):.0%}")

# —— 模拟 GSM8K 风格的生成题评估 ——
gen_preds = ["16 颗", "16", "25", "7 个", "0.5"]
gen_golds = ["16", "16", "25", "7", "0.5"]
print("精确匹配(EM) ：", f"{exact_match(gen_preds, gen_golds):.0%}",
      "（注意 '16 颗' 与 '16' 因字符不同被判错）")

# —— 模拟 HumanEval 风格的 pass@k ——
def tests_pass(code):
    return "def solve" in code and "return" in code   # 示意：粗略判断

questions = [
    ["def solve():\n    pass",              "def solve():\n    return 42"],  # 第 1 份没过、第 2 份过
    ["def solve():\n    return 1",          "def solve():\n    return 2"],  # 两份都过
    ["def solve():\n    pass",              "def solve():\n    pass"],      # 两份都不过
]
print("pass@2       ：", f"{pass_at_k(questions, tests_pass):.0%}")

这段代码复现了真实评估的三个核心动作：统一判分规则、按任务选指标、生成类任务允许多次采样。真实 harness（如 EleutherAI 的 lm-evaluation-harness）做的事本质相同，只是规模放大到数万题、上百模型。

三、练习#

  1. 选指标：为以下任务各选一个最合适的指标并说明理由——① 情感三分类 ② 数学应用题 ③ 代码生成 ④ 摘要质量（提示：摘要没有唯一标准答案，指标会很难选）。
  2. 算 EM：对 gen_preds/gen_golds 手工核对，找出所有被判错的对，并说明 EM 对"格式敏感"这一缺点。
  3. 实现去污检测：写一个函数，判断某基准题（或其连续 13 个字符的子串）是否出现在给定训练语料串里，返回是否"疑似污染"。
  4. 理解 pass@k：若每题单次通过概率 p=0.3，k=5 时该题 pass@k 的期望是多少？（提示：1 减去 5 次全不过的概率）
  5. 思考局限：为什么"分数高"不等于"真有用"？举一个模型在基准上刷分、但在真实场景翻车的例子。
