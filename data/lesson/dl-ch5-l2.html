GRU#

LSTM 用三个门换来了强大的长期记忆，但也带来了大约 4 倍的参数量。门控循环单元（Gated Recurrent Unit, GRU）是 LSTM 的一个"精简版"：它把三个门合并成两个门，还砍掉了独立的细胞状态，用更少的参数达到了和 LSTM 相近的效果。这一课我们看清 GRU 是怎么"做减法"的，以及什么时候该选它。

一、概念讲解#

1. 精简思路：两个门 + 一个状态#

GRU 的出发点是：LSTM 的"遗忘门 + 输入门"其实有点冗余——遗忘门删掉一部分、输入门又加回一部分，两者常常互补。GRU 干脆把它们合并成一个更新门，再用一个重置门控制"新信息该参考多少历史"。

GRU 只有一个状态 hₜ，同时承担了 LSTM 里"细胞状态"和"隐藏状态"两个角色。它的每步更新可以写成：

zₜ = σ(W_z · [hₜ₋₁, xₜ])          # 更新门：新旧信息各占多少比例
rₜ = σ(W_r · [hₜ₋₁, xₜ])          # 重置门：候选值参考多少历史
h̃ₜ = tanh(W_h · [rₜ ⊙ hₜ₋₁, xₜ])  # 候选隐藏状态
hₜ = (1 − zₜ) ⊙ hₜ₋₁ + zₜ ⊙ h̃ₜ    # 最终状态：在旧状态与候选之间加权

其中 σ 是 sigmoid，⊙ 是逐元素相乘。

2. 两个门各自管什么#

  • 更新门 zₜ：决定"旧状态保留多少、新候选写入多少"。当 zₜ 接近 0，状态几乎原样保留（记得久）；当 zₜ 接近 1，状态被新候选覆盖（更新快）。它同时扮演了 LSTM 遗忘门和输入门的角色。
  • 重置门 rₜ：决定"生成候选值时，该参考多少上一刻的状态"。当 rₜ 接近 0，候选值几乎只由当前输入决定，相当于"忘掉历史、重新开始"；当 rₜ 接近 1，则充分利用历史。

最后一行的 hₜ = (1 − zₜ) ⊙ hₜ₋₁ + zₜ ⊙ h̃ₜ 是个漂亮的"加权平均"：新状态是旧状态和新候选的插值，而且两个权重之和恒为 1。这种"要么保留、要么更新"的互补设计，让信息的流动既平滑又高效。

3. GRU 与 LSTM 的对比#

维度 LSTM GRU
门的数量 3（遗忘、输入、输出） 2（更新、重置）
状态数量 2（细胞状态 cₜ + 隐藏状态 hₜ） 1（只有 hₜ）
参数量 约 4× 同尺寸 RNN 约 3× 同尺寸 RNN
表达能力 更强、更灵活 略简洁，但通常够用
训练速度 较慢 较快、更省显存

该选哪个？ 这没有铁律，但工程上有几条经验：

  • 数据充足、任务复杂（如机器翻译、需要精细长期记忆）时，LSTM 常常表现更好；
  • 数据量不大、模型要跑得快、显存紧张时，GRU 是更实惠的选择，且小数据集上 GRU 往往更不容易过拟合；
  • 两个都试一下，用验证集说话，才是最终判断标准。

二、可运行代码示例#

torch.nn.GRU 的用法和 LSTM 几乎一样，只是状态从两个变成一个。下面我们把它和 LSTM 放在一起跑，对比参数量、输出形状，并做一个"二者都能学会"的小任务，验证 GRU 确实能用更少参数达到相近效果。

import torch
import torch.nn as nn

batch, seq_len, input_size, hidden_size = 3, 6, 5, 8

# —— 对比形状：GRU 与 LSTM ——
x = torch.randn(seq_len, batch, input_size)

gru = nn.GRU(input_size, hidden_size)
lstm = nn.LSTM(input_size, hidden_size)

out_gru, h_gru = gru(x)              # GRU 只返回一个最终状态
out_lstm, (h_lstm, c_lstm) = lstm(x) # LSTM 返回隐藏状态和细胞状态

print("GRU output 形状：", out_gru.shape)   # (6, 3, 8)
print("GRU 最终状态形状：", h_gru.shape)    # (1, 3, 8)
print("LSTM 最终状态形状：", h_lstm.shape, c_lstm.shape)  # (1,3,8) 各一个

# —— 对比参数量 ——
gru_params = sum(p.numel() for p in gru.parameters())
lstm_params = sum(p.numel() for p in lstm.parameters())
print(f"GRU 参数 {gru_params} vs LSTM 参数 {lstm_params}")
print(f"GRU 约为 LSTM 的 {gru_params / lstm_params:.2%}")

# —— 小任务：让 GRU 学会"记住序列里是否出现过数字 1"（二分类） ——
class SeqClassifier(nn.Module):
    def __init__(self, cell):
        super().__init__()
        self.embed = nn.Embedding(10, 4)      # 输入是 0~9 的数字
        self.rnn = cell(4, 8, batch_first=True)
        self.fc = nn.Linear(8, 2)

    def forward(self, x):
        out, _ = self.rnn(self.embed(x))
        return self.fc(out[:, -1, :])         # 多对一：只取最后一步

torch.manual_seed(0)
model = SeqClassifier(nn.GRU)
opt = torch.optim.Adam(model.parameters(), lr=0.01)
loss_fn = nn.CrossEntropyLoss()

# 构造数据：序列里含 1 则标签为 1，否则为 0
xs = torch.randint(0, 10, (200, 10))          # 200 条长度 10 的序列
ys = (xs == 1).any(dim=1).long()              # 是否包含 1

for step in range(500):
    logits = model(xs)
    loss = loss_fn(logits, ys)
    opt.zero_grad()
    loss.backward()
    opt.step()

with torch.no_grad():
    acc = (model(xs).argmax(1) == ys).float().mean().item()
print(f"训练后准确率：{acc:.3f}，最终损失：{loss.item():.4f}")

运行后你会发现：GRU 的参数量大约是 LSTM 的 75%，但同样能轻松学会"序列里是否出现过 1"这种需要跨越几步记忆的任务，准确率很快逼近 1.0。这个"减配不减能"的特性，就是 GRU 受欢迎的原因。

三、练习#

  1. 把上面的 SeqClassifier(nn.GRU) 换成 SeqClassifier(nn.LSTM)（注意 LSTM 前向返回的是元组），比较两者的参数量与收敛速度，看哪个先达到同样的准确率。
  2. 把任务改难一点：判断"序列里是否出现过 1 且后面紧跟 2"（即出现过子串 1,2），重新构造标签，观察 GRU 还能不能学会，为什么这个任务更需要"记住顺序"。
  3. 解释公式 hₜ = (1 − zₜ) ⊙ hₜ₋₁ + zₜ ⊙ h̃ₜ：当 zₜ 分别为 0、1、0.5 时，新状态各是什么含义？这和 LSTM 的细胞状态更新有什么对应关系？
  4. 思考：为什么 GRU 参数更少反而在小数据集上更不容易过拟合？这跟"模型容量"有什么关系？
