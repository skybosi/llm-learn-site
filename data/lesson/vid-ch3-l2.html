扩散与时序：时空联合、逐帧加时序约束与隐空间#

这一节要解决什么#

第 1 节把"时间维带来什么"算清了：多了一个独立的误差轴、代价由时长决定、漂移有可拟合的指数。但那一节始终把扩散过程当成一个黑箱——噪声怎么加、怎么去、几步去完这三件事一件都没碰。这一节把它们逐个摊开，并且回答一个具体的问题：

图像扩散的公式 xt​=αˉt​​x0​+1−αˉt​​ϵ 里，αˉt​ 只是"第 t 步"的函数。把它搬到视频上，这个"步"到底该沿哪条轴走？

全部结论如下：

  1. 扩散目标在时空张量上是逐元素的，但"时间"进了条件。 训练目标 L=Ex0​,ϵ,t​[∥ϵ−ϵθ​(xt​,t,c)∥2] 里没有显式的时间耦合项；时间耦合全部来自 ϵθ​ 的架构（3D 卷积、时空注意力）与条件 c。"把扩散搬到视频"这件事 90% 的工作量在架构与条件里，不在公式里。
  2. 噪声调度决定"哪一段采样步负责运动一致性"。 同一 T=1000 的离散步，线性调度在 t/T=0.30 时 SNR 已跌到 0.657758，余弦调度此时还有 3.721119；达到同一 SNR 的步数之比在 1.85∼2.03 之间（表 1）。余弦调度把低噪声阶段拉长约一倍，等价于把采样步数更多地投给细节与一致性——这是它在视频里更常见的算术原因，而不是"效果更好"的经验说法。
  3. 潜空间的噪声不是白噪声。 时间 VAE 的编码器/解码器都在时间方向做滤波/下采样，白噪声过它之后自相关 ρ(1) 可达 0.154663∼0.253855（实测，k=2,3,5），与窗向量的精确理论值（0.166667/0.210526/0.235294）一致到 0.018561 以内（Nlat​=4096 的抽样误差 0.015625）；真正的扩散残差 e=n−y~​ 的自相关是负的（k=3 时 −0.227971，k=5 时 −0.111067），rel=1+2∑τ≥1​ρ(τ)2 从 1.000000 涨到 1.171162/1.075790（表 2）。"时间压缩换算力"被压掉的不只是时长，还有时间上的独立可分辨性。
  4. 三条路线的参数账差大约 3 倍，但真正的分界不在参数。 同一个 4 级 U-Net，把时间核从 kt​=1 换成 kt​=3：参数量 29.9008M→88.8832M（2.9726 倍），潜帧 FLOPs 15.0995→45.2985 GFLOP（表 3）；权重 fp16 只有 0.055695→0.165558 GiB。决定路线可行性的不是这 0.11 GiB，而是激活与 score（第 1 节表 1 的 930.2500 GiB）。
  5. 隐空间压缩的账要两边一起算。 算力侧：T=8 时把 ft​ 从 1 提到 8，总成本比 R=20.8276；T=481 时 R=59.7311，其中 VAE 那 3,078.4000 GFLOP 始终是固定成本（表 4）。能力侧：可表示的时间频率上界从 12.0000 Hz 掉到 1.5000 Hz。压缩比的选择是"目标内容里最快的时间频率"与算力预算的交点，不是越大越好。
  6. 采样步数与"能看多远"是两件事。 设每步的时间等效位移 vstep​=0.05 潜帧/步，则 S=1000 步只覆盖 400.0000 原始帧（83.1601% 的 20 秒视频），要覆盖整段需要 S≥1202.5000 步（表 5）。长程一致性靠的是架构里的自回归/分块机制，不是把采样步数堆上去。

本节的主线：扩散的目标函数对时间维是"无感"的，所以视频扩散的所有设计工作都发生在三处——噪声调度怎么分配步数、架构怎么把时间耦合进去、隐空间压缩把哪些时间细节换成了算力。

一、扩散目标在时空张量上的确切形式#

1.1 从图像到视频：公式没变，条件变了#

图像扩散的前向过程（T 个离散步，αˉt​=∏k≤t​(1−βk​)）：

（式 3）式 3 里没有任何一项显式地耦合时间。这不是笔误，也不是简化：扩散的推导对张量形状是无感的，THWC 与 HWC 在推导里都是"一组独立的标量通道"。于是有三个直接的推论：

  1. 时间耦合只能来自 ϵθ​ 的结构。 如果 ϵθ​ 对每一帧独立地算（2D 卷积），式 3 的训练会收敛到"每帧各自像一个图像模型"，帧间一致性完全没有来源。要让模型学到运动，必须让网络内部或条件里出现跨帧的信息通路。
  2. "时间"可以只出现在条件里。 一个最简单的方案是 c 里带上前一帧（逐帧条件生成），网络本身仍是 2D。这时时间耦合在推理循环里而不在网络里——第 1 节的漂移公式 D(n)=ϵdnα 描述的就是这种方案的误差行为。
  3. βt​ 调度只决定"每步削掉多少信息"，与时间轴无关。 但"每步削掉多少"决定了采样时有多少步落在"能改变运动"的区间里——这正是下一小节的内容。

1.2 为什么不是"给每一帧配一个 t"#

一个自然的想法是：既然视频有时间维，就给每一帧一个独立的噪声等级 tf​（帧级调度）。这在数学上也能写出目标函数，但它引入一个无法回避的问题：不同噪声等级的帧之间无法比较。 若第 5 帧是纯噪声、第 6 帧是清晰图，网络在预测第 5 帧噪声时能否用第 6 帧？能——但那时它学到的是"用清晰帧补噪声帧"，这恰好是条件生成而不是联合建模。于是帧级调度实际上把问题退化成了"逐帧生成 + 前向条件"，与第 1 节讨论的路线重合。

所以"时空联合扩散"的标准做法是：所有帧共享同一个 t。这条选择不是审美，它保证式 3 的每一条训练样本都是一段"同等模糊程度"的视频，网络必须同时利用空间与时间结构去噪。代价是采样时无法只细化某一段——要做局部重绘/编辑，就得引入掩码式的条件（第 4 节）。

2.2 时间压缩改变了什么：temporal SNR#

2.3 怎么测：一条可复现的协议#

上面两件事都有便宜的可测做法：

  1. 生成一批潜码（不做生成，只跑 VAE 的编码器-解码器），算 e 的 lag-1 自相关。要在 95% 置信下分辨 ρ(1)=0.4 与 0，需要 N≥(1.96/0.4)2=24.0100，取 25 帧即可——这个检验极便宜，应该成为任何视频 VAE 的标配验收项。
  2. 扫 ft​，在每个 ft​ 上重复步骤 1，得到 ρ(1) 随压缩比的变化曲线。ρ(1) 明显上升的位置就是"再压就要牺牲时间可分辨性"的位置。
  3. 把调度换一遍（线性/余弦），在同一 SNR 网格上比较步数分配（表 1 的第二张表）。不要只报最终指标——调度的作用机制是"分配步数"，那就应该直接报分配。

边界：ρ(1) 是线性相关，它对非线性的时间伪影（例如周期性的闪烁）不敏感；因此 ρ 只能证明"存在时间耦合"，不能证明"一致性足够好"。第 4 节的多口径评测协议才是完整的。

  1. 采样步数不足时，长程一致性靠的不是采样器，而是架构里的自回归/分块机制（下一节）。把步数从 50 提到 1000 不会让单次生成看清 20 秒——它只是把每步的时间位移累加到 50 个潜帧。
  2. 反过来，如果一段视频能被 50 步"覆盖"（50vstep​ft​≥481），说明每步的时间位移被设得过大，采样器在用步长换覆盖，这会牺牲细节一致性。

def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1
               for ch in s)


def pad(s, w, align=">"):
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2
    return " " * left + s + " " * (gap - left)


def row(cells, widths, aligns=None):
    aligns = aligns or [">"] * len(cells)
    return " | ".join(pad(c, w, a) for c, w, a in zip(cells, widths, aligns))

class LCG:
    def __init__(self, seed=20260923):
        self.s = seed & 0xFFFFFFFFFFFFFFFF

    def u(self):
        self.s = (6364136223846793005 * self.s + 1442695040888963407) \
            & 0xFFFFFFFFFFFFFFFF
        return (self.s >> 11) / float(1 << 53)

    def n(self):
        u1 = max(self.u(), 1e-12)
        u2 = self.u()
        return math.sqrt(-2.0 * math.log(u1)) * math.cos(2.0 * math.pi * u2)

T_STEP = 1000
BETA_MIN, BETA_MAX = 1e-4, 2e-2


def linear_alpha_bar(T=1000):
    ab, out = 1.0, []
    for t in range(T):
        beta = BETA_MIN + (BETA_MAX - BETA_MIN) * t / T
        ab *= (1.0 - beta)
        out.append(ab)
    return out


def cosine_alpha_bar(T=1000, s=0.008):
    out = []
    for t in range(T):
        f = math.cos((t / T + s) / (1.0 + s) * math.pi / 2.0) ** 2
        f0 = math.cos(s / (1.0 + s) * math.pi / 2.0) ** 2
        out.append(f / f0)
    return out

def cross(f, snr_target, T=1000):
    """找到一个调度达到 snr_target 的离散步，返回该步。"""
    for t in range(T):
        a = f[t]
        if a >= 1.0:
            continue
        if a / (1 - a) <= snr_target:
            return t
    return None

def _periodic_ma(x, k):
    """白噪声序列过长度 k 的滑动平均（环形/周期边界）。"""
    n = len(x)
    return [sum(x[(i - j) % n] for j in range(k)) for i in range(n)]


def acf_of_ma(k, n=4096):
    """经验自相关 rho(tau)，tau = 0..8；理论值 = (k-|tau|)/k，|tau| < k。"""
    r = LCG(777)
    x = [r.n() for _ in range(n)]
    y = _periodic_ma(x, k)
    m = sum(y) / n
    var = sum((v - m) ** 2 for v in y) / n
    out = []
    for tau in range(9):
        c = sum((y[i] - m) * (y[(i + tau) % n] - m) for i in range(n)) / n
        out.append(c / var)
    return out, var


def conv_full(a, b):
    """有限支撑序列的线性卷积（索引 0..len(a)+len(b)-2）。"""
    out = [0.0] * (len(a) + len(b) - 1)
    for i, ai in enumerate(a):
        if ai == 0.0:
            continue
        for j, bj in enumerate(b):
            out[i + j] += ai * bj
    return out

def run_chain(k, n_lat=N_LAT, seed=777):
    """返回 (输出序列 y, 噪声 n, 自相关 rho[0..M_LAG])。

    索引约定（统一用「前向窗」）：
      编码器：把输出帧按 k 个一组求均值 -> 潜帧 y_i
      解码器：把每个潜帧复制 k 次、再过长度 k 的滑动平均 -> ytilde
    """
    r = LCG(seed)
    n_out = k * n_lat
    n = [r.n() for _ in range(n_out)]
    lat = [sum(n[k * i + j] for j in range(k)) / k for i in range(n_lat)]
    up = []
    for v in lat:
        up.extend([v] * k)
    y = [0.0] * n_out
    for i in range(n_out):
        lo = max(0, i - k + 1)
        y[i] = sum(up[lo:i + 1]) / k
    m = sum(y) / len(y)
    var = sum((v - m) ** 2 for v in y) / len(y)
    acf = [1.0]
    for tau in range(1, M_LAG + 1):
        lag = tau * k
        c = sum((y[i] - m) * (y[i + lag] - m)
                for i in range(len(y) - lag)) / (len(y) - lag)
        acf.append(c / var)
    return y, n, acf, var


def resid_acf(y, n, m_lag=M_LAG):
    e = [a - b for a, b in zip(n, y)]
    m = sum(e) / len(e)
    var = sum((v - m) ** 2 for v in e) / len(e)
    if var <= 1e-24:
        return [1.0] + [0.0] * m_lag, var
    out = [1.0]
    for tau in range(1, m_lag + 1):
        c = sum((e[i] - m) * (e[i + tau] - m)
                for i in range(len(e) - tau)) / (len(e) - tau)
        out.append(c / var)
    return out, var

    g = [0.0] * (2 * k - 1)

        g[i] = (hi - lo + 1) / k if hi >= lo else 0.0
    return g

        out.append(num / den)
    return out

r = LCG(4242)
NF = 48
x0 = [r.n() for _ in range(NF)]


def denoise_pass(x, step_scale, corr):
    """一次「去噪」：向零收缩 step_scale 倍，再叠加相关噪声（corr = rho1）。"""
    e = [r.n() for _ in range(NF)]
    nz = [0.0] * NF
    for i in range(NF):
        nz[i] = e[i] if i == 0 else corr * nz[i - 1] + \
            math.sqrt(max(0.0, 1 - corr * corr)) * e[i]
    return [(1 - step_scale) * v + step_scale * z for v, z in zip(x, nz)]


def mse(a, b):
    return sum((u - v) ** 2 for u, v in zip(a, b)) / len(a)

表 2  时间维的噪声不是白噪声：维纳滤波的自相关与它的可测后果
================================================================================================================
video VAE 的编码器与解码器都在**时间方向**做卷积（或时间下采样）。因此
「噪声在时间上 iid」在潜空间里并不成立。构造（可逐项复算）：
  · 编码器：把 k 个连续输出帧取均值当成一个潜帧（时间下采样 k 倍）
  · 解码器：把每个潜帧复制 k 次，再过长度 k 的滑动平均（零填充）
  于是输出帧写成 n 与零填充窗的卷积，自相关可由窗向量直接算出。

----------------------------------------------------------------------------------------------------------------

编码器 k=3 + 解码器 k=3 |     0.216408 |    -0.009540 |    -0.006310 |    -0.017488 |       0.237731

把这条链路写成线性滤波：输出帧 = 白噪声 n 与窗向量 g 的卷积，
g 的长度是 2k-1（复制带来的台阶 + 解码器的滑动平均），自相关由 g 精确决定：
  rho(tau) = sum_j g(j) g(j + tau*k) / sum_j g(j)^2。

因为复制-平均的边界把相关性稀释到了**更低的时间频率**（rho 在 lag = k, 2k

 所以有效残差是 e；e 的自相关决定「时间方向还剩多少独立自由度」。）
                  链路 |    e 的 rho(1) |      e 的 rho(2) | rel = 1 + 2*sum rho^2

要覆盖整段 20 s（481 帧 = 61 个潜帧），需要 S >= 61/0.0500 = 1,202.5000 步。
这给出两条可算的边界：
  1) 采样步数不足时，长程一致性靠的**不是**采样器，而是架构里的自回归/分块
     机制（第 3 节）；把步数从 50 提到 1000 不会让单次生成看清 20 秒。
  2) 反过来，如果一段视频能被 50 步「覆盖」（即 50*v_step*f_t >= 481），
     则说明每步的时间位移被设得过大，采样器在用大步长换覆盖 —— 这会牺牲
     细节一致性，是另一个可测的取舍（表 6 用同一批噪声算它的方差后果）。

这张表把三条路线的差别落在两个可测量上：
  · 残差 MSE 衡量「离目标多远」：逐帧与时空联合在 iid 噪声下同为 0.450371（同一批噪声、同一收缩率），
    而相关噪声（rho=0.4）把它抬到 0.468605（1.0405 倍）。
  · 时间方差衡量「帧间残差是否抖动」：相关噪声把它从 0.758336 抬到 0.816594（1.0768 倍），
    因为相关噪声的低频成分更难被采样器在有限步数里抹掉。
  · 把步数从 50 降到 10：残差 MSE 从 0.468605 变成 0.046338（0.0989 倍）。

三条边界（本节结论）：
  1) 时空联合与逐帧不是「谁更对」，是「谁把哪一笔账放到哪一侧」：
     联合把一致性放进架构（算力 O(N^2)），逐帧把一致性放进损失/条件（可能不收敛）。
  2) 隐空间压缩省的是生成侧算力，付的是时间方向的可分辨性：编码器/解码器
     的时间滤波把噪声变相关（rho(1) 可达 0.4 以上），这部分相关性又通过
     扩散目标与采样步数回到结果里。
  3) 噪声调度是「哪一段采样步决定运动一致性」的分配器：余弦调度把低噪声阶段
     拉长，等价于把更多步数投给细节与一致性。

小结#

  • 扩散目标对时间维是无感的（式 3）：L=E∥ϵ−ϵθ​(xt​,t,c)∥2 里没有显式时间耦合，视频扩散的全部设计发生在调度、架构、隐空间三处。
  • 帧级独立调度会退化成条件生成：不同帧噪声等级不同时无法联合去噪，所以时空联合的标准做法是所有帧共享同一个 t。
  • 两条调度曲线的差别是"步数分配"：同一 SNR 水平上 tcos​/tlin​∈[1.8532,2.0323]（表 1）；线性在 t/T=0.30 时 SNR 已 0.657758，余弦还有 3.721119。
  • 潜噪声不是白噪声：ρ(1) 实测 0.154663/0.216408/0.253855（k=2/3/5），理论 0.166667/0.210526/0.235294，偏差 ≤0.018561（抽样误差 0.015625）。相关性集中在时间频率 1/(kft​) 附近。
  • 残差自相关是负的：k=3 时 −0.227971、k=5 时 −0.111067；rel=1+2∑ρ2 从 1.000000 到 1.171162/1.075790——时间独立自由度被破坏，但方向与"噪声被摊平"相反。
  • 结构账：kt​:1→3 使参数 29.9008M→88.8832M（2.9726 倍）、潜帧 FLOPs 15.0995→45.2985 GFLOP；权重 fp16 仅 0.055695→0.165558 GiB——真正的墙是激活与 score。
  • 隐空间压缩的两条曲线：算力比 R(T) 从 20.8276（T=8）到 59.7311（T=481，其中 VAE 固定 3,078.4000 GFLOP）；时间频率上界从 12.0000 Hz（ft​=1）掉到 1.5000 Hz（ft​=8）。选 ft​ 是 fs​/(2ft​)≥fmaxcontent​ 与预算的交点（式 6）。
  • 采样步数不等于"能看多远"：vstep​=0.05 时 1000 步只覆盖 400.0000 帧（83.1601%），全覆盖需 S≥1202.5000（式 7）。长程一致性来自架构而不是步数。
  • 表 6 的"残差"是相对初始样本的距离：步数 50→10 让 MSE 从 0.468605 掉到 0.046338（0.0989 倍）——指标必须先写清相对谁，这是本节最容易被误读的一处。
