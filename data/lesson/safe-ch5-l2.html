端到端设计案例：指令/数据分离、工具权限、沙箱、输出校验、审计与熔断的组合设计#

这一节要解决什么#

上一节把"钱怎么分"算清楚了：等边际原则给出六层的投入，G=2.02446，残余风险 800000.0 元，正好压在 R∗=800000 上。

但那个解依赖一个从第 3 章借来的假设：

G(b)=j∑​[−ln(1−εj​(bj​)ϕj​)]⟸Pblock​=1−j∏​(1−εeff,j​)

这个乘积形式只在各层独立失效时成立。 而真实的防护层几乎从不独立：两个"不同的"检测器常常读同一份数据、用同一个模型判断、依赖同一份配置。第 3 章 §7.1 把这件事叫"共线失效"，并给了它的上界形式：

Pblock​≤1−jmax​(1−εeff,j​)(完全共线),Pblock​=1−j∏​(1−εeff,j​)(完全独立)

本节要做的，是把这句话从定性变成一份可以签字的设计。具体回答四个问题：

  1. 六项措施各自怎么落地？ 每一项给：可算判据、代价、失效条件；
  2. 它们合起来挡住多少？ 独立口径与共线口径差多少；
  3. 差距怎么补？ 哪些修正动作真的有用（换判据来源、加独立层），哪些是白花钱；
  4. 设计表长什么样？ 每一条判据都要能接上第 3 节的门禁。

对象仍然是那门企业知识库 Agent，但这一节把它拆开看内部。

本节的第一条纪律：

 每一项防护都必须同时交出「判据」与「代价」，只给判据的防护无法进入预算表 ​

因为第 1 节的分配算法需要 εeff,j​，而第 4 章的验收需要代价；两样缺一，这条防护就无法被排序、也无法被验收。

⚠️ 本节所有数值均为合成（合成词元数、合成工具权重、合成逃逸率、合成汇点清单、合成留痕字段），作用是把"组合设计"变成可核对的算术。

一、设计对象与五条信任边界#

1.1 数据流#

用户 ──→ [网关] ──→ 检索器 ──→ 上下文装配 ──→ 模型 ──→ 工具层 ──→ 汇点
  ↑         ↑           ↑            ↑            ↑          ↑
 B1        B2          B2           B2/B3        B5         B4

第 1 章已经确立了信任边界的记号（B1–B5）。在这个系统里：

边界 穿过它的数据 谁控制 边界上的检查
B1 用户输入 用户（不可信） 意图分类 + 速率限制
B2 检索文档正文 文档作者（半可信） 来源白名单 + provenance 标记
B3 工具返回内容 外部系统（不可信） schema 校验 + 不可信标记
B4 工具调用参数 Agent（受注入影响） 参数溯源 + 作用域检查
B5 模型输出 模型（概率性） 汇点校验 + 引用核验

1.2 为什么重心压在 B4#

五条边界里只有 B4 是有副作用的。 越权读取是一个数据问题（可以事后补救、可以通知、可以删缓存）；越权写入是一个不可逆的业务问题（邮件已经发出去了、工单已经建了、代码已经跑了）。

于是设计的第一条原则：

 把不可逆的动作从 Agent 手里拿走，比把它的准确率提高更值钱 ​

这条原则在后面的三处会反复出现：工具权限里"草稿 + 人工放行"、沙箱里"断网"、熔断里"停用高危写工具"。它们都是同一个动作的三种形态：降低 E（利用因子），而不是降低 p。

二、指令/数据分离：定界符解决"谁说的"，不解决"谁被信"#

2.1 两种装法#

上下文预算是 8000 词元。两种装法：

通道 词元数 角色 可信度 可渲染指令?
系统指令（含策略） 600 system 可信 是
用户指令 400 user 可信 是
检索文档正文 5600 data 不可信 否
工具返回内容 1100 data 不可信 否

旧装法是把工具返回内容直接拼进 system 通道（这是很多早期实现的默认做法，因为它在调用格式上最省事）。此时攻击者可影响的词元占比是：

ρ=80005600+1100​=0.8701,1−ρρ​=0.12990.8701​=6.7000

攻击者的份额超过合法份额 6.7 倍。 更糟的是"可渲染指令 = 是"：模型没有任何结构性信号能区分"这一段是系统说的"与"这一段是外部系统塞进来的"。

新装法做三件事：

  1. 不可信内容只进 data 角色；
  2. 每段带 provenance 标记（来源 ID、抓取时间、是否经人工审核）；
  3. 工具调用的每个参数必须能溯源到"用户指令段里的某个槽位"，否则拒绝执行。

装完之后，残余的可控面只剩"经 B4 泄进工具参数"的那一段（例如攻击者让 Agent 把某段文档内容当成收件人地址）。合成读数是 ρ=0.06：

1−ρρ​=0.940.06​=0.0638,改善倍数=0.06386.7000​=104.97

这条 104.97 倍是本设计里最大的一项改善，而它的代价是：

  • 上下文多约 8% 的词元（provenance 标记）；
  • 需要一个参数溯源器（属于 L1 层的一部分）；
  • 每个工具的参数 schema 必须写清楚"这个参数能来自哪一段"——这是纯粹的工程量，没有模型侧的工作。

2.2 为什么"加大定界符比特数"几乎没有用#

常见的下一招是把定界符加长（从 32 bit 到 64 bit），理由是"攻击者猜不中"。用第 3 章 §二 的模型：攻击者在单请求内可尝试 216 次闭合猜测，成功率是

p(b)=pforge​+(1−pforge​)min(1,216−b),pforge​=0.0100

8 1.000×100 0.0100 1.000000 —
16 1.000×100 0.0100 1.000000 —
24 3.906×10−3 0.0100 0.013867 —
32 1.526×10−5 0.0100 0.010015 1.0000
48 2.328×10−10 0.0100 0.010000 0.9985
64 3.553×10−15 0.0100 0.010000 0.9985

读数：b 从 32 加到 64，总成功率只从 0.010015 掉到 0.010000 —— 相对改善 0.1508%。

 超过 32 bit 之后总成功率由 pforge​ 支配，定界符的边际收益是 0 ​

可算的判据是：只要 pforge​/(1−pforge​)>216−b，加比特就买不到任何东西。而 pforge​=0.0100 意味着"伪造一段看起来像系统指令的内容"有 1% 的成功率 —— 这一项与比特数无关，它只能靠 §2.1 的通道分离来降。

这条算术是"两本账"的第一个实例：定界符买的是穷举成本，通道分离买的是影响上限。前者是比特数，后者是结构。

2.3 失效条件与边界#

  1. 参数溯源器的失效条件是"新工具没登记参数来源"。一旦某个新工具的参数被标成 free（无来源约束），ρ 就直接跳回高位。所以"新工具上线必须过参数溯源评审"是 L1 层的一部分，不是 L2 层。
  2. 通道分离不防"模型自愿"把 data 段当指令。它降低的是"模型没有任何理由拒绝"这一便利，不改变第 1 章的结构性事实（指令与数据同信道）。所以 L1 的 a1​ 只有 0.55（第 1 节 §3.2），不可能更高。
  3. provenance 标记本身可能被伪造（如果标记由检索器写入而检索器可被污染）。所以标记的可信度依赖 B2 上的来源白名单 —— 这是 §三 权限设计与 §五 审计留痕的接口。

3.3 缓解：把自主外部写拿走#

缓解动作不是"给 send_email 加过滤"，而是取消它的自主调用：

  • mail:send、data:export 改为"生成草稿 + 人工放行"；
  • code:exec 断网（去掉 net:fetch）。

代价（必须一起报）：

  • 每 1000 条合法请求里有 37 条需要人工放行（合成误伤率 3.70%）；
  • 平均多 1.4 轮确认 × 90 秒 =126 秒的 P95 延迟增量。

这笔账的读法：它把一次"可能外发敏感数据"的尾部风险，换成了一条流水线上的固定延迟。这正是第 1 节 §2.2 讲的"削 σ 而不是削 R"的一个具体形态 —— 它的期望收益可能不大，但它把尾部砍掉了。

3.4 参数级缺口：可判定的最小权限只到作用域级#

作用域检查能回答"这个工具能不能读 HR"，不能回答"这次调用该读哪一条 HR 记录"。合成统计：

量 值

 作用域级是可判定的，参数级不是 —— 缺口必须写进失效条件 ​

第 3 章第 3 节已经给出了这条结论的形式（∣scope∣=8≪220）。在本设计里它的具体形态是："读哪一条"这 17 个槽要靠运行时判据（例如"只能读当前工单关联的客户记录"），而运行时判据本身是一个模型或一条规则，它有自己的错误率 —— 它必须按 §四 的方式当成一个 ROC 点来测量，不能当成一个布尔开关。

3.5 失效条件与边界#

  1. 新增工具绕过评审是最常见的失效。判据是"新工具上线时危险组合计数是否为 0"，这条要进 §七 的评审表，也要进第 3 节的门禁（结构型 gate）。
  2. "草稿 + 人工放行"依赖人工真的会看。第 4 章 §2 讲过"人在环里"必须写成三元组（谁看、看什么、看到什么算通过）；否则它退化成一次点击。可核对的判据是人工放行的拒绝率：如果某类草稿的拒绝率长期为 0，说明人工环节没有实际过滤作用。
  3. 作用域数量会随业务膨胀。8 个作用域现在是可枚举的；到 30 个时，230 的子集不可枚举，危险组合必须靠规则（读集 × 写集）而不是枚举来维护。

四、沙箱：逃逸面与信息外流面是两本账#

4.1 账一：逃逸面随层数变大#

一个反直觉但正确的算术：每加一层隔离，就多出一组接口与配置，因此至少一处逃逸的概率是上升的（各层是并联而不是串联）：

配置 本层逃逸率 累计至少一次逃逸 相对单层
仅进程隔离 + seccomp 0.00200 0.002000 1.000
+ 用户态内核（gVisor） 0.00040 0.002399 1.200
+ microVM 0.00020 0.002599 1.299
+ 物理隔离机器 0.00005 0.002649 1.324

读数：累计逃逸率不是下降，而是从 0.002000 升到 0.002649（1.324 倍）。

那为什么还要加层？因为沙箱层数买到的是降低利用因子 E，不是降低逃逸概率：

逃逸→无网络、无凭据、无持久化⟹E↓↓

这是第 3 章"两本账"的工程形态。如果一个方案声称"加了沙箱所以更安全"，它必须说清自己是降 p 还是降 E —— 因为这个沙箱实际上把 p 抬高了一点。

这条结论与第 3 章 §四 的"逃逸不是主要风险"完全一致，只是这里把"白名单"与"净化器"的代价差别写在了一起。

4.3 失效条件与边界#

  1. 白名单的失效条件是"临时放开"。真实事故里最常见的形态是"为了排查故障临时开了一条出网通路，忘了关"。可核对判据是白名单变更的审计：每次变更必须有工单号 + 到期时间 + 自动回收。
  2. 断网会砍掉一类合法功能。http_fetch 与 exec_code 出网都是真实需求；把它们拿掉的代价要由业务方确认。所以"断网"在评审表里必须与"人工放行"并列给出，让业务方选。
  3. 净化器的 0.98 拦截率是一个 ROC 点（见 §五），不是常数。不要把它当配置项写在架构图里。

五、输出校验：汇点覆盖率是它的上界#

5.1 汇点清单#

输出的下一个消费者（"汇点"）决定了校验的成本与必要性：

 汇点覆盖率=∣汇点清单∣∣已校验汇点∣​ ​

合成清单 13 个汇点，校验覆盖 8 个：

汇点覆盖率=138​=0.6154,未覆盖 5 个（对它们的有效性是 0，不是"较低"）

未覆盖的五个里，最危险的是下游 LLM 的上下文（第 3 章：输出层的判定问句只有一句"这个输出接下来被谁解析"）。如果这个答案最终会被另一个 LLM 读进上下文，那么输出的每一句话都是潜在的注入载荷。

注意"有效性是 0"这个措辞：对未覆盖的汇点，输出校验器不是"效果差一点"，而是完全没有作用。这与第 3 章 §五.1 的结论一致，也是为什么把汇点覆盖率作为 a5​ 的上界：

a5​≤汇点覆盖率=0.6154（而第 1 节取 a5​=0.60，正是这个意思）

 输出校验的阈值不是一个技术参数，它是一条 ROC 上的点，必须与业务方一起选 ​

因为选择它等价于选择"我们愿意误伤多少正常回答，来换取少漏多少"。

5.3 引用可核验率：唯一不依赖模型的输出侧判据#

为什么这一项重要：其它输出侧判据（有害性、越权内容）都要靠一个分类器，而分类器自己就是 ROC 上的点（§5.2）。引用可核验率是唯一可以由规则判定的输出侧判据 —— 把答案里的引用与检索到的原文 span 做字符串/位置匹配即可。所以它应该作为唯一可以进硬门禁的输出侧指标。

5.4 失效条件与边界#

  1. 新汇点上线未登记是最常见的失效（新接了一个 webhook、新加了一个下游 LLM）。判据是"上线检查表里有'新汇点登记'一项"，并把它做成结构型 gate。
  2. 校验器与 §二 的注入检测常常共用模型。一旦共用，它们就是共线的 —— 这正是 §六 要算的东西。
  3. 引用可核验率的失效条件是"引用格式被伪造"：如果模型可以生成一个看起来合法但不存在的 span ID，这个判据就退化。所以要把它做成"ID 必须是检索器发的"（而不是模型生成的）。

六、审计与熔断#

6.1 审计留痕：字段数不是指标，"可复算率"才是#

合成设计里留痕 22 个字段（prompt 哈希、检索文档 ID 列表、工具调用参数摘要、判据版本、模型版本、策略版本、决策结论、拒绝原因码、人工放行签名……）。

但字段数量没有意义，有意义的是：

可复算率=决策链上的节点总数能从日志重建的决策链上节点数​=0.9600

缺口 0.0400 落在"检索器的排序分数未落盘"，于是"为什么这一条被召进上下文"不可复算。这条缺口的后果：当一次间接注入事故发生后，你无法回答"这个被污染的文档为什么排在第一位" —— 只能回答"它确实被召回了"。

 留痕的设计判据是「事后要回答哪个问题」，不是「记录尽可能多」 ​

每天 M 条请求抽 k 条人工审，零发现时违规率的 95% 上界是 1−0.051/k：

这条算术与第 3 章 §五.2、第 4 章 §6.2 是同一条：抽样审计不能替代独立通道。它的作用是"存在性证明"（证明系统里有真人审过、有记录），不是"覆盖率证明"。

有效拦截率=min(1,λτk​)

2.0 6.0 12 12.0 1.0000

读数：λ=2 次/分时窗口内有 12 次违规，阈值 3 只拦到 0.2500。把 τ 压到 2 分（用自动化判定替代人工确认）可到 0.7500。

6.5 失效条件与边界#

  1. 对手把速率压到阈值以下（低速慢渗）会让熔断完全失效，而这一点正是第 4 节 CUSUM 要解决的问题（累计信息 vs 单点信息）。
  2. 熔断本身是一笔可用性支出。所以它的门槛必须由期望损失算出来（第 4 节 §3），不能由"看到异常就停"的直觉定。
  3. 审计留痕的版本字段是事后归因的前提。没有"判据版本 + 模型版本"，事后无法判断"当时那套规则该不该拦住它" —— 也就无法完成第 4 章 §2 的责任切分。

7.6 失效条件与边界#

  1. "判据来源"的划分本身是一个判断，不是观测。两个检测器"看起来用不同模型"但共享同一份训练数据时，它们的失效仍然是相关的。可操作的近似是问三个问题：它们读同一份数据吗？用同一个模型/规则库吗？依赖同一份配置吗？ 三个都是"是"→ 共线；有两个是"是"→ 部分共线（此时既不能用 ∏ 也不能用 max，必须给区间）。
  2. 共线口径是一个下界（悲观）。完全独立是一个上界（乐观）。真实值在两者之间，所以报数时必须同时给两个数，并注明"真实值在此区间内，需要实验来收窄"。
  3. 收窄区间的方法：做故障注入（人为关掉一层，看总拦截率掉多少）。如果关掉 L1 后总拦截率几乎不变，说明 L1 与其它层高度共线；如果掉了接近 εeff,1​ 那么多，说明它独立。这个实验的成本远低于重做全部红队。

=== 3. 沙箱与出网控制：逃逸面 vs 信息外流面 ===
  账一：逃逸。每加一层隔离就多一组接口，**逃逸面单调变大**：
  配置                                  本层逃逸率      累计至少一次逃逸              相对单层
  仅进程隔离 + seccomp                     0.00200              0.002000                 1.000
  + 用户态内核 (gVisor)                    0.00040              0.002399                 1.200
  + microVM                                0.00020              0.002599                 1.299
  + 物理隔离机器                           0.00005              0.002649                 1.324
  读数：累计逃逸率不是下降而是从 0.002000 升到 0.002649（1.324 倍）——
        沙箱层数买到的是**降低利用因子 E**（逃出去之后没有网络、没有凭据、
        没有持久化），不是降低逃逸概率。这是第 3 章「两本账」的工程形态。

  账二：信息外流。m 条出网通路，每条每月泄漏概率 q：
           m               q    至少一条泄漏                缓解动作              缓解后
          30          0.0010          0.0296                      无            0.029569
          30          0.0100          0.2603                      无            0.260300
          30          0.0100          0.2603        出网白名单 30->3            0.029701
          30          0.0100          0.2603  白名单 + 内容净化 0.98 拦截            0.000600
          30          0.0100          0.2603         断网（air gap）            0.000000
  读数：同样的沙箱，出网口径从 0.2603 压到 0.000600（434 倍）。
        可算判据：外流风险对 m 的弹性是 q/(1-(1-q)^m) * m；**降 m 比降 q 便宜**——
        白名单是配置改动，净化器是要维护的模型。

=== 4. 输出校验：汇点覆盖率 + 校验器的两个错误率 ===
  汇点清单 13 个，校验覆盖 8 个 -> 汇点覆盖率 = 0.6154；未覆盖 5 个（对它们的有效性是 0）
  未覆盖里最危险的一个：下游 LLM 的上下文（第 3 章：输出层的判定问句是「接下来谁解析」）

  校验器是一条 ROC 上的点。基率 p=0.01，报出事件里真问题占比 = p*Se / (p*Se + (1-p)*(1-Sp))：
          Se          Sp          漏过       误伤/万条正常    报出事件里真问题占比
      0.9400      0.9800        0.0600               198.0                  0.3219
      0.9000      0.9950        0.1000                49.5                  0.6452
      0.8000      0.9980        0.2000                19.8                  0.8016
      0.7000      0.9995        0.3000                 4.9                  0.9340
      0.6000      0.9999        0.4000                 1.0                  0.9838
  读数：Se 从 0.94 放到 0.80，漏过率从 0.06 涨到 0.20（3.33 倍），
        但报出事件里真问题占比从 0.3219 涨到 0.8016——**误伤/真问题从 2.11 倍变成 0.25 倍**。
        这就是「输出校验的阈值」必须与业务方一起定的原因：它是一条 ROC，不是开关。

  引用可核验率（唯一不依赖模型的输出侧判据）：
    答案带 6 条引用，能回溯到原文 span 的 5 条 -> 可核验率 0.8333
    答案带 6 条引用，能回溯到原文 span 的 6 条 -> 可核验率 1.0000
    答案带 6 条引用，能回溯到原文 span 的 4 条 -> 可核验率 0.6667

小结#

  • 重心压在 B4（工具调用参数）：五条信任边界里只有它是有副作用的，越权写入不可逆。设计的第一原则是把不可逆动作从 Agent 手里拿走（降 E），而不是把它的准确率提高（降 p）。
  • 指令/数据分离是本设计里最大的一项改善：可达影响比从 6.7000 降到 0.0638（104.97 倍）；代价是上下文多 8% 词元 + 一个参数溯源器。
  • 定界符加比特几乎没有用：b 从 32 加到 64，总成功率只从 0.010015 掉到 0.010000（0.1508%）—— 超过 32 bit 后由 pforge​=0.0100 支配，边际收益为 0。定界符买穷举成本，通道分离买影响上限。
  • 工具层的危险来自组合：并集膨胀比 5.1429，危险组合 8 对；k=6 时"既读敏感又能外发"的概率 0.2119。缓解动作是取消自主外部写（危险组合 →0），代价是 3.70% 合法请求人工放行与 126 秒 P95 延迟。参数级覆盖率只有 0.6304，17 个参数槽只能靠运行时判据 —— 这个缺口必须写进失效条件。
  • 沙箱是两本账：累计逃逸率从 0.002000 升到 0.002649（1.324 倍，层数越多接口越多）；真正的账是信息外流 1−(1−q)m，白名单 30→3 加 0.98 净化把 0.2603 压到 0.000600（434 倍）。降 m 是配置改动，降 q 是要维护的模型。
  • 输出校验的上界是汇点覆盖率：8/13=0.6154，未覆盖的汇点有效性是 0 而不是"较低"。校验器是一条 ROC（Se 从 0.94 放到 0.80 时误伤/真问题从 2.11 倍降到 0.25 倍），阈值必须与业务方一起选。引用可核验率是唯一可由规则判定的输出侧判据，因此是唯一适合进硬门禁的。
  • 审计的价值在可复算率（0.9600）而不在字段数；抽样审计 1% 零发现只能排除违规率 >0.001497（全天仍可能 299.4 条）。熔断的有效拦截率是 min(1,k/(λτ)) —— 压延迟比抬阈值值钱；迟滞把单窗误停 0.1205 压到 0.0145，代价是误停与漏检的互换。
  • 组合的结论是本节的核心：独立口径残余 799938.1 元（"达标"），共线口径 1814046.9 元（低估 2.2677 倍）。换判据来源只买到 1.11 倍（→1630102.5 元）；真正救回方案的是加一条独立的新层（→326020.5 元），并反解出它的门禁阈值 ε7​≥0.509233。
  • "再加一层"的价值取决于判据是否独立：同类检测在共线口径下边际为 0。判据来源的近似划分只需问三个问题（同一份数据？同一个模型？同一份配置？），而收窄区间靠故障注入而不是重做全部红队。
