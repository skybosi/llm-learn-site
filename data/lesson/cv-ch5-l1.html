对比学习（SimCLR/MoCo）#

你已经能用监督学习训练检测分割模型，但监督学习有一个绕不开的瓶颈：它需要海量的人工标注。标注一张图可能要几十秒，标注百万张图就是天文数字的成本。自监督学习（Self-Supervised Learning，SSL）的思路是：不依赖人工标签，让模型从数据本身构造"任务"来学习表征。这一章我们先讲其中最成功的一支——对比学习，用 SimCLR 和 MoCo 两个代表作把它的原理吃透。关键不是背公式，而是理解"为什么让相似样本靠近、不相似样本远离"这件事能让模型学到可迁移的特征。

一、概念讲解#

1. 核心思想：不靠标签，靠"像不像"#

监督学习用标签告诉模型"这是猫、那是狗"。对比学习换了个角度：对同一张图做两种不同的数据增强（比如两次随机裁剪 + 颜色抖动），得到的两个视图本质上还是同一张图，它们构成一对"正样本对"；来自不同图的视图则是"负样本对"。训练目标很朴素——在表征空间里，让正样本对靠得尽可能近，让负样本对离得尽可能远。

为什么这个"像不像"的游戏能学到好东西？因为模型要在一堆扰动（裁剪、颜色、翻转）之下，仍然认出"这两个视图是同一个东西"，它就必须学到对增强不变、又能区分不同物体的稳定特征——而这恰恰是下游任务（分类、检测、分割）最想要的那类特征。

2. SimCLR：简单有效的四件套#

SimCLR 的洞察是，对比学习不需要复杂的结构，靠四个精心设计的组件就能追上甚至超越当时的监督预训练：

  1. 更强的数据增强组合：随机裁剪 + 颜色抖动 + 高斯模糊等叠加。作者证明增强的"组合"至关重要——裁剪负责全局形状，颜色抖动负责防止模型靠颜色直方图"作弊"。
  2. 投影头（projection head）：在编码器（如 ResNet）之后加一个小 MLP g(·)，对比学习在 g 的输出上做，但下游只用编码器的输出 f(·)。一个反直觉的发现是：投影头学到的表征"用前即弃"反而更好——它帮编码器在训练时"藏起"那些和增强有关、但不通用的信息。
  3. NT-Xent 损失（InfoNCE）：对每个正样本对算相似度，再对一批里所有负样本做 softmax 归一化，本质是"把正样本当成唯一正确答案的分类问题"。
  4. 大批量：负样本来自同一个 batch 里的其他样本，所以 batch 越大，负样本越多，对比越充分。SimCLR 用到了 4096 甚至 8192 的大 batch。

3. MoCo：负样本不够？建一个"字典"#

SimCLR 依赖大批量提供负样本，硬件门槛高。MoCo 提出另一个思路：把"负样本来源"从 batch 里拆出来，变成一个常驻的负样本队列（dictionary）：

  • 维护一个先进先出的队列，存最近若干 batch 的编码结果，作为负样本库（比如 65536 个）；
  • 用两个编码器：一个在线编码器（正常梯度更新），一个动量编码器（参数用在线编码器的指数移动平均更新，θ_m ← m·θ_m + (1−m)·θ_q，m 接近 1）；
  • 队列里的负样本由动量编码器生成，因为动量更新很慢，队列里的表征在短时间内保持"同一批人"的口径一致，不会因为参数突变而混乱。

可以这样理解：SimCLR 是"临时凑一批当负样本"，MoCo 是"养一个长期更新的负样本字典"。两者殊途同归——都是让模型在足够多的负样本压力下，把正样本对对齐。

4. 为什么它 work：对齐 + 均匀#

理论分析（Wang & Isola 等）把对比学习的目标拆成两个优雅的性质：

  • 对齐（Alignment）：正样本对的表征要接近——这保证了对增强不变性；
  • 均匀性（Uniformity）：所有样本的表征要尽量在球面上铺开、分布均匀——这防止了模型把所有样本都坍缩到同一点（即"平凡解"）。

只有"对齐"没有"均匀"，模型会退化；两者同时满足，表征空间才既有判别性又不塌缩。这个"对齐 + 均匀"的框架，是理解"为什么对比学习不崩"的钥匙，也是后面几课评价其他自监督方法的一面镜子。

二、可运行代码示例#

先实现 SimCLR 的核心——NT-Xent（InfoNCE）损失，用一个小 batch 的假表征跑通前向：

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)


def nt_xent_loss(z1, z2, temperature=0.5):
    """NT-Xent 损失。z1、z2 是同一批图两种增强的投影表征，形状 (N, d)。"""
    z = torch.cat([z1, z2], dim=0)          # (2N, d)
    z = F.normalize(z, dim=-1)              # 先 L2 归一化，点积即余弦相似度

    sim = z @ z.T / temperature             # (2N, 2N) 相似度矩阵
    N = z1.shape[0]

    # 每个样本的正样本，是"它在另一半增强里的对应项"
    labels = torch.arange(N, device=z.device).repeat(2)
    labels = (labels + N * torch.arange(2, device=z.device).unsqueeze(1)).flatten()
    # 即：z1 第 i 个的正样本是 z2 第 i 个，反之亦然

    # 把自己与自己的相似度屏蔽掉，避免退化解
    mask = torch.eye(2 * N, dtype=torch.bool, device=z.device)
    sim = sim.masked_fill(mask, float("-inf"))

    # 以"正样本"为唯一正确答案做交叉熵
    loss = F.cross_entropy(sim, labels)
    return loss


# 模拟一个 batch=4 的投影表征（维度 8）
z1 = torch.randn(4, 8)
z2 = torch.randn(4, 8)
print("NT-Xent 损失:", nt_xent_loss(z1, z2).item())

再写一个精简的 MoCo 动量更新 + 队列，体会"字典"是怎么维护的：

class MoCoQueue:
    """简化的 MoCo：维护一个负样本队列，用动量编码器更新。"""
    def __init__(self, dim=8, queue_size=16, momentum=0.999):
        self.queue_size = queue_size
        self.momentum = momentum
        # 队列初始用随机向量填充
        self.register_queue(torch.randn(queue_size, dim))

    def register_queue(self, q):
        self.queue = F.normalize(q, dim=-1)

    def enqueue_dequeue(self, keys):
        """新 batch 的负样本入队，最旧的出队（先进先出）。"""
        keys = F.normalize(keys, dim=-1)
        self.queue = torch.cat([self.queue, keys], dim=0)[keys.shape[0]:]

    def momentum_update(self, online_params, momentum_params):
        """把动量编码器参数往在线编码器参数上缓慢靠近。"""
        with torch.no_grad():
            for p_o, p_m in zip(online_params, momentum_params):
                p_m.mul_(self.momentum).add_(p_o, alpha=1 - self.momentum)


q = MoCoQueue()
keys = torch.randn(4, 8)                 # 新 batch 由动量编码器算出的负样本
q.enqueue_dequeue(keys)
print("入队后队列长度（保持不变）:", q.queue.shape)  # (16, 8)

# 演示动量更新：把两个参数"缓慢对齐"
online = [torch.tensor([1.0, 2.0])]
momentum_p = [torch.tensor([0.0, 0.0])]
q.momentum_update(online, momentum_p)
print("动量更新后的参数:", momentum_p[0])   # 接近 [0.001, 0.002]

运行后你能直观看到两件事：NT-Xent 通过"屏蔽自身 + 交叉熵"把正样本对齐；MoCo 队列长度恒定、先入先出，动量更新让参数每步只挪动 1 − m 的一小步。把这两个机制合起来，就是对比学习在工业界落地时的标准形态。

三、练习#

  1. 修改 nt_xent_loss，把 temperature 分别设为 0.1、0.5、2.0，观察损失值变化，并解释温度如何控制"对难负样本的惩罚强度"（提示：温度越小，softmax 分布越尖锐）。
  2. 用手写的小例子验证"对齐 + 均匀"：构造一批全部坍缩到同一点的表征，计算它们的 InfoNCE 损失和"均匀性"指标（可近似为两两平均相似度），说明为什么只有对齐没有均匀会失败。
  3. 用 torchvision 加载 ResNet18，去掉最后的全连接层作为编码器，接一个两层 MLP 投影头，在 CIFAR-10（或你自己的小数据集）上实现一个最小 SimCLR 训练循环，记录前 100 步损失的下降趋势。
  4. 思考 MoCo 与 SimCLR 的本质差异：如果硬件允许用超大 batch，队列机制还有必要吗？什么场景下 MoCo 的"动量 + 队列"反而更划算？
