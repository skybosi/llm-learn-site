SSA：φ 函数与支配关系#

上一课给了我们"前驱 / 后继"，但三地址码里 prod = prod + i 这种写法仍然让分析很难受：同一个名字 prod 在循环的每一轮代表不同的值，而名字只有一个。想知道"B4 里用的 prod 是谁算出来的"，你得在图上倒着搜。SSA（Static Single Assignment，静态单赋值）用一个极端的约束解决这个问题：每个名字只允许被赋值一次；做不到就造新名字，并在汇合处用 φ 函数（phi function）把不同来源的值接起来。

一、概念讲解#

1. 反复赋值让分析变难#

prod 被赋值 N 次，就有 N 个不同的值，但名字只有一个。于是"这个 use 用的是哪个 def"不再是名字匹配问题，只能退化成集合问题：到达定值分析维护"某个程序点上可能有哪些定值到达"的集合，再迭代到不动点。代价不只是慢，还有精度损失：汇合处集合里会同时出现多个候选，给不出确定答案。

2. SSA 的定义与三条收益#

SSA 的规则只有一句：每个名字只能被赋值一次。做法是给每次赋值产生新版本：prod1、prod2…于是：

  1. 每个名字的唯一 def 点就是它的定义处，use-def 链可以直接从名字读出来；
  2. 值编号、常量传播、死代码消除从"集合迭代"退化成"沿 def-use 链的局部改写"；
  3. 优化后重新做 SSA 维护的成本可控，pass 之间不容易互相破坏。

LLVM IR 就是 SSA 形式：%x = add i32 %a, %b，每个 %x 只赋值一次。代价是必须有东西表达"两条路径汇合后取哪个值"——这就是 φ。

3. φ 函数：由边决定取值的伪指令#

把 if-else 两条分支都赋值的变量改成 SSA，会立刻卡住：

B1: x1 = 1
B2: 分支 → B3 / B4
B3: x2 = 2 ; goto B5
B4: x3 = 3 ; goto B5
B5: y = ? + 1        ← 该用 x2 还是 x3？

"用哪个"取决于从哪条边进来，普通指令表达不了。于是：

B5: x4 = φ(x2, x3)
    y  = x4 + 1

φ 的语义有三条必须记牢：① 入参按前驱的顺序一一对应，取值由控制流走的边决定，不是运行时"挑选"；② 它是并行赋值，所有 φ 同时生效，不存在先后；③ 它不是可执行指令——只活在编译器的图里，退出 SSA 时会被拆成各前驱末尾的 copy。

4. 支配关系与支配树#

φ 该插在哪里？答案依赖支配（dominance）：

  • d 支配 n（记 d dom n）：从入口到 n 的每一条路径都经过 d；
  • 立即支配者 idom(n)：支配 n 的严格支配者中"最深"的那个；
  • 把每个 n 连到 idom(n)，得到支配树（dominator tree）。

支配集可以照定义迭代（这也是第 5 章数据流框架的一个实例）：

Dom(entry) = {entry}
Dom(n)     = {n} ∪ ⋂ Dom(p),  p ∈ pred(n)

本课例子里：Dom(B2)={B1,B2}、Dom(B3)={B1,B2,B3}、Dom(B4)={B1,B2,B4}，且 idom(B3)=idom(B4)=B2。

5. 支配边界：φ 的落点#

支配边界 DF(n) 指：所有"n 支配它的某个前驱、但 n 不严格支配它"的块。直觉上，DF 是"支配作用刚失效的地方"——两条控制流可能重新汇合的地方。计算可以照定义走：

对每个有 ≥ 2 个前驱的块 b，对它的每个前驱 p：从 p 沿支配树往上走，走到 idom(b) 为止；沿途每个块都把 b 记进自己的 DF。

本课例子里 DF(B3)={B2}、DF(B2)={B2}——B2 在自己的支配边界里，这正是循环头必须要 φ 的原因：下一轮的 i 要取"循环体算出的版本"。

φ 的插入规则：对变量 v 的定值块取 DF+（迭代支配边界，新插的 φ 等价于一个新定值点），在这些块里插 φ。这是 Cytron 等人 1991 年提出的构造法。

6. 重命名、退出 SSA 与常见坑#

插完 φ 还要给所有名字加版本。做法是沿支配树 DFS，为每个变量维护一个版本栈：① 进入块时给它的每个 φ 压一个新版本；② 块内指令先把右值的名字替换成当前版本，再给左值压新版本；③ 对每个后继的每个 φ，用当前版本回填属于本块的那个入参；④ 处理完所有子节点后统一弹栈（φ 与赋值一起弹）。第 ③ 步是关键，它让入参自动对应到"前驱出口处的版本"。

后端（寄存器分配、指令调度）不需要 φ，退出 SSA 是反向操作：对每个 x = φ(v1, v2)，在第 1 个前驱末尾插 x = v1、第 2 个前驱末尾插 x = v2。这里要小心关键边（critical edge，从出度 ≥ 2 的块进入入度 ≥ 2 的块的那条边）：直接在前驱末尾插 copy 会连带影响它的其他后继，需要先拆边（插入一个空块）。

常见坑：① 把 φ 当运行时指令处理，或给只有一个前驱的块插 φ（无意义）；② φ 的入参顺序与前驱顺序不一致——这是最常见的实现 bug；③ 忘了循环头的 φ 有一个入参来自回边；④ 被取地址的变量无法提升成 SSA——LLVM 的 mem2reg 只处理没有被取地址的 alloca，被取地址的对象必须留在内存里；⑤ 插出大量死 φ：老式算法在支配边界上无脑插，靠死代码消除清理（minimal SSA 改用活跃变量，见第 5 章）。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）把整条链路走通：算支配集 → 求 idom → 算支配边界 → 插 φ → 沿支配树重命名。例子是上一课那个 while 循环：

# ---- 支配关系 → 支配边界 → 插入 φ → 重命名（纯 Python，无第三方依赖）----
# 等价源码：i = 1; prod = 0; while (i <= 10) { prod = prod + i; i = i + 1; } 用 prod;
import re
BLOCKS = {
    'B1': ([('=', 'i', '1'), ('=', 'prod', '0')],            ['B2']),
    'B2': ([('if', 'i <= 10')],                             ['B3', 'B4']),
    'B3': ([('=', 'prod', 'prod + i'), ('=', 'i', 'i + 1')], ['B2']),
    'B4': ([('use', 'prod')],                               []),
}
ENTRY = 'B1'

def predecessors(blocks):
    return {b: [p for p in blocks if b in blocks[p][1]] for b in blocks}

def dominators(blocks, entry):
    """迭代到不动点：Dom(n) = {n} ∪ ⋂ Dom(前驱)"""
    preds, nodes = predecessors(blocks), set(blocks)
    dom = {b: set(nodes) for b in blocks}
    dom[entry] = {entry}
    changed = True
    while changed:
        changed = False
        for b in blocks:
            if b == entry or not preds[b]:
                continue
            new = {b} | set.intersection(*[dom[p] for p in preds[b]])
            if new != dom[b]:
                dom[b], changed = new, True
    return dom

def immediate_dominators(dom, entry):
    """严格支配者构成一条链，最深（被其余严格支配者支配）的那个就是 idom"""
    idom = {entry: None}
    for b in dom:
        if b == entry:
            continue
        strict = dom[b] - {b}
        idom[b] = next(d for d in strict if all(e in dom[d] for e in strict if e != d))
    return idom

def dominance_frontier(blocks, idom):
    """汇合块的每个前驱沿支配树往上走，直到 idom(汇合块)，沿途块都把它记进 DF"""
    preds, df = predecessors(blocks), {b: set() for b in blocks}
    for b in blocks:
        if len(preds[b]) < 2:
            continue
        for p in preds[b]:
            runner = p
            while runner is not None and runner != idom[b]:
                df[runner].add(b)
                runner = idom[runner]
    return df

def definitions(blocks):
    d = {}
    for b, (body, _) in blocks.items():
        for ins in body:
            if ins[0] == '=':
                d.setdefault(ins[1], set()).add(b)
    return d

def insert_phi(blocks, df, defs):
    """在迭代支配边界 DF+ 上插 φ。这里只处理「有多个定义块」的变量；
    严格的 minimal SSA 还要求变量在块入口活跃（见第 5 章活跃变量分析）"""
    phi = {b: [] for b in blocks}
    for v, sites in sorted(defs.items()):
        if len(sites) < 2:
            continue
        work, placed = list(sites), set()
        while work:
            for d in sorted(df[work.pop()]):
                if d in placed:
                    continue
                placed.add(d); phi[d].append(v)
                if d not in sites:
                    work.append(d)
    return {b: sorted(v) for b, v in phi.items()}

def rename(blocks, idom, phi, entry):
    """沿支配树 DFS：先给本块的 φ 与赋值压新版本，再回填后继 φ 的入参，最后统一弹栈"""
    children, stack, result, operands = {}, {}, {}, {}

    def cur(v):
        return stack[v][-1] if stack.get(v) else v

    def push(v):
        stack.setdefault(v, []).append(f'{v}{len(stack[v]) + 1}')
        return stack[v][-1]

    def subst(expr):
        return re.sub(r'[A-Za-z_]\w*', lambda m: cur(m.group(0)), expr)

    def walk(b):
        pushed, phis = [], []
        for v in phi[b]:
            phis.append((push(v), v)); pushed.append(v)
        body = []
        for ins in blocks[b][0]:
            if ins[0] == 'use':
                body.append(('use', subst(ins[1])))
            elif ins[0] == 'if':
                body.append(('if', subst(ins[1])))
            else:
                rhs = subst(ins[2])          # 先用：右值的名字按当前版本替换
                body.append(('=', push(ins[1]), rhs)); pushed.append(ins[1])
        result[b] = (phis, body)
        for s in blocks[b][1]:                       # 回填后继块的 φ 入参
            for v in phi.get(s, []):
                operands.setdefault(s, {}).setdefault(v, {})[b] = cur(v)
        for c in sorted(children.get(b, [])):
            walk(c)
        for v in pushed:                             # 统一弹栈（φ 与赋值一起）
            stack[v].pop()

    for b, p in idom.items():
        children.setdefault(p, []).append(b)
    walk(entry)
    return result, operands

dom = dominators(BLOCKS, ENTRY)
idom = immediate_dominators(dom, ENTRY)
df = dominance_frontier(BLOCKS, idom)
defs = definitions(BLOCKS)
phi = insert_phi(BLOCKS, df, defs)
ssa, operands = rename(BLOCKS, idom, phi, ENTRY)
preds = predecessors(BLOCKS)

print('Dom   :', {b: sorted(dom[b]) for b in sorted(dom)})
print('idom  :', {b: idom[b] for b in sorted(idom)})
print('DF    :', {b: sorted(df[b]) for b in sorted(df) if df[b]})
print('定义块:', {v: sorted(s) for v, s in sorted(defs.items())})
print('φ 位置:', {b: phi[b] for b in phi if phi[b]})
print('\nSSA 形式:')
for b in sorted(ssa):
    phis, body = ssa[b]
    head = [f'{n} = φ(' + ', '.join(operands[b][v][p] for p in preds[b]) + ')'
            for n, v in phis if len(preds[b]) > 1]
    line = [f'{ins[1]} = {ins[2]}' if ins[0] == '=' else
            (f'use {ins[1]}' if ins[0] == 'use' else f'if {ins[1]}') for ins in body]
    print(f'  {b}: ' + '；'.join(head + line) + f'    → {BLOCKS[b][1]}')

运行结果——支配集、idom、DF 全部与手算一致，φ 只插在 B2：

Dom   : {'B1': ['B1'], 'B2': ['B1', 'B2'], 'B3': ['B1', 'B2', 'B3'], 'B4': ['B1', 'B2', 'B4']}
idom  : {'B1': None, 'B2': 'B1', 'B3': 'B2', 'B4': 'B2'}
DF    : {'B2': ['B2'], 'B3': ['B2']}
定义块: {'i': ['B1', 'B3'], 'prod': ['B1', 'B3']}
φ 位置: {'B2': ['i', 'prod']}

SSA 形式:
  B1: i1 = 1；prod1 = 0    → ['B2']
  B2: i2 = φ(i1, i3)；prod2 = φ(prod1, prod3)；if i2 <= 10    → ['B3', 'B4']
  B3: prod3 = prod2 + i2；i3 = i2 + 1    → ['B2']
  B4: use prod2    → []

逐行核对三处最有信息量的地方：i2 = φ(i1, i3) 的两个入参分别来自"初始化块"和"循环体末尾"（即回边）；prod3 = prod2 + i2 里两个右值都是汇合之后的新版本；B4: use prod2 用的是循环退出时最后一次累加的结果，而不是某个"所有版本混在一起"的集合。

三、练习#

  1. 实现：把 BLOCKS 换成 if-else 菱形（B1 → B2 → B3/B4 → B5），运行代码并解释 φ 出现在哪个块、两个入参分别是什么。
  2. 解释：为什么 φ 必须是"并行赋值"？如果按顺序执行 x2 = φ(x1, x3); x3 = φ(x2, x4)，会得到什么错误结果？
  3. 对比/验证：把 insert_phi 的 DF+ 迭代改成"只对真实汇合块插一次 φ"，用含嵌套循环的 CFG 说明哪种做法会漏插。
  4. 思考：为什么寄存器分配要放在退出 SSA 之后？如果在带 φ 的 SSA 图上直接分配寄存器，φ 会带来什么麻烦？
