U-Net#

FCN 打通了"像素到像素"端到端分割，但它的上采样路径比较"瘦"——解码阶段只靠几层操作，浅层细节恢复得不够充分。U-Net 把这条思路推到极致：一个完全对称的编码器-解码器结构，配一条条把编码器与解码器逐层相连的跳跃连接，形如字母 "U"。

它诞生于医学图像分割（ISBI 细胞分割挑战赛），但如今已经是图像分割、图像生成（如扩散模型去噪）、图像修复等任务里最常见的主干结构之一。这一课我们搞懂它"为什么长成 U 形"，以及它和 FCN 的关键区别。

一、概念讲解#

1. 结构：收缩路径 + 扩张路径#

U-Net 分左右两半：

  • 收缩路径（编码器，左侧）：和普通 CNN 一样，反复做 卷积 → 卷积 → 下采样，每下一层，空间尺寸减半、通道数翻倍，逐步把图像压缩成语义越来越强的特征；
  • 扩张路径（解码器，右侧）：对称地反复做 上采样 → 卷积 → 卷积，每上一层，空间尺寸翻倍、通道数减半，逐步把特征"解码"回像素空间。

两半在同一分辨率层级上用跳跃连接对接——这正是 "U" 的来源。

2. U-Net 的跳跃连接与 FCN 有何不同#

这是理解 U-Net 的关键，也常被面试问到。FCN 的跳跃连接是相加（element-wise add），且只融合少数几个尺度（8s/16s/32s）；U-Net 的跳跃连接是拼接（concatenation，沿通道维连接），并且是每一个分辨率层级都连。

两者差别的含义：

  • 相加：把浅层和深层特征当作"强度叠加"的同一种东西，通道数不变，更省参数，但信息被"平均"掉一部分；
  • 拼接：把浅层的精细特征和深层的语义特征原样并排保留，让后面的卷积层自己去学"怎么组合它们"，信息不丢失，代价是通道数翻倍、参数更多。

配合 U-Net 对称、深的扩张路径，这种"逐层拼接"让网络能把高分辨率细节一路精细地传到最后，因而在边界精细度上通常优于 FCN——这对医学图像里毫米级的病灶边界至关重要。

3. 为什么 U-Net 特别适合小数据集#

U-Net 最早是在几十上百张标注图像上训练并夺冠的，这在小数据时代几乎是奇迹。原因有两层：

  1. 密集的跳跃连接提供了极好的梯度通路：浅层也能收到强梯度，训练稳定、收敛快，不容易"学不动"；
  2. 结构强先验（strong prior）：U 形对称 + 逐层拼接，相当于把"分割就是编码再解码、且要保留细节"这个先验知识硬编码进了结构里。先验强，需要从数据里学的东西就少，数据量小也能工作。

再加上重数据增强（医学图像常用随机弹性形变模拟组织形变）和重叠滑窗预测（处理超大图），U-Net 在小样本场景的鲁棒性至今仍是标杆。

4. 与 FCN 的定位之别#

一句话概括：FCN 是"范式奠基者"——它证明了全卷积 + 上采样 + 跳跃连接能端到端分割；U-Net 是"结构极致化"——它把对称编解码 + 逐层拼接做到极致，成为各类密集预测任务（分割、去噪、超分、生成）的通用模板。理解了 FCN 的"为什么"，再理解 U-Net 的"怎么做得更好"，你就完整掌握了这条演进线。

二、可运行代码示例#

下面从零实现一个迷你 U-Net，重点演示"收缩-扩张对称"和"拼接式跳跃连接"。代码只依赖 PyTorch，可直接跑通并验证形状。

import torch
import torch.nn as nn
import torch.nn.functional as F

class DoubleConv(nn.Module):
    """U-Net 的基本模块：两个 3x3 卷积（保持尺寸）+ BN + ReLU"""
    def __init__(self, in_ch, out_ch):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(in_ch, out_ch, 3, padding=1), nn.BatchNorm2d(out_ch), nn.ReLU(inplace=True),
            nn.Conv2d(out_ch, out_ch, 3, padding=1), nn.BatchNorm2d(out_ch), nn.ReLU(inplace=True),
        )
    def forward(self, x):
        return self.net(x)

class MiniUNet(nn.Module):
    def __init__(self, in_ch=3, num_classes=2):
        super().__init__()
        # 收缩路径：每下采样一次，通道翻倍
        self.enc1 = DoubleConv(in_ch, 32)
        self.enc2 = DoubleConv(32, 64)
        self.enc3 = DoubleConv(64, 128)
        self.pool = nn.MaxPool2d(2)                      # 下采样
        # 扩张路径：每上采样一次，通道减半，并与同层编码器特征拼接
        self.up2 = nn.ConvTranspose2d(128, 64, 2, stride=2)
        self.dec2 = DoubleConv(128, 64)                  # 64(上采样) + 64(拼接 enc2)
        self.up1 = nn.ConvTranspose2d(64, 32, 2, stride=2)
        self.dec1 = DoubleConv(64, 32)                   # 32(上采样) + 32(拼接 enc1)
        self.head = nn.Conv2d(32, num_classes, 1)        # 1x1 卷积输出类别分数

    def forward(self, x):
        e1 = self.enc1(x)                                # (N, 32, H, W)
        e2 = self.enc2(self.pool(e1))                    # (N, 64, H/2, W/2)
        e3 = self.enc3(self.pool(e2))                    # (N, 128, H/4, W/4)
        d2 = self.up2(e3)                                # (N, 64, H/2, W/2)
        d2 = torch.cat([d2, e2], dim=1)                  # 拼接式跳跃连接 -> 128 通道
        d2 = self.dec2(d2)                               # (N, 64, H/2, W/2)
        d1 = self.up1(d2)                                # (N, 32, H, W)
        d1 = torch.cat([d1, e1], dim=1)                  # 拼接 -> 64 通道
        d1 = self.dec1(d1)                               # (N, 32, H, W)
        return self.head(d1)                             # (N, C, H, W)

model = MiniUNet(in_ch=3, num_classes=2)
x = torch.rand(2, 3, 64, 64)
out = model(x)
print("输入形状：", tuple(x.shape))
print("输出形状：", tuple(out.shape))   # 期望 (2, 2, 64, 64)：与输入同尺寸、通道=类别数

# 模拟一次分割训练：用交叉熵监督逐像素分类
label = torch.randint(0, 2, (2, 64, 64))
loss = F.cross_entropy(out, label)
print("像素级交叉熵损失：", round(loss.item(), 4))

注意 torch.cat([d2, e2], dim=1) 这行的注释：上采样后的 64 通道 + 编码器同层的 64 通道拼接成 128 通道，dec2 的输入通道因此是 128。这种"通道数对齐再拼接"的记账，是手写 U-Net 最容易出错的地方，务必逐层核对。

三、练习#

  1. 把跳跃连接从 torch.cat（拼接）改成 d2 + e2（相加），相应调整 dec2 的输入通道为 64，对比两种实现的可学习参数量；结合正文说说"相加"为何会损失信息。
  2. 给 MiniUNet 增加一层下采样（enc4 / up3），让网络变成 4 层对称结构，核对每一层的通道与尺寸记账是否正确。
  3. 用随机图做一次完整的前向，打印每层特征图形状，画出这棵"U 形"的尺寸-通道变化表，验证收缩与扩张是否严格对称。
  4. 讨论：为什么 U-Net 在医学影像这种小数据集上表现好？把原因拆成"结构先验"和"数据增强"两个维度来答。
