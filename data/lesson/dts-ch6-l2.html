激活重计算：显存-算力权衡的定量分析#

上一课把模型状态（参数、梯度、优化器状态）切干净之后，往往还剩一笔账没解决：激活值。它和参数不同——参数只与模型大小有关，激活值却随 batch 与序列长度线性增长，而且中间还藏着一个随序列长度平方增长的矩阵。一个 2048 序列长度的 GPT-3 量级配置，光是把注意力打分矩阵留住，每层就要 1.5 GiB。这一课把"哪些张量值得留、哪些应该重算"变成可以算出来的决定。

一、概念讲解#

1. 激活值为什么必须存：反向要用#

训练一步包含前向与反向。反向计算某层的权重梯度需要该层的输入激活，计算当前层的输入梯度还需要该层内部的中间量。做前向时这些张量都出现过，但默认会被释放；如果要保留下来，就在显存里一直占着，直到反向用完。

单层要留的张量（以 Transformer block 为例）是：

张量 形状 为什么要留
block 输入 [b,s,h] 反向算该层第一个线性层的权重梯度
注意力 4 个投影输出 Q/K/V/O 各 [b,s,h] 反向算投影权重梯度
注意力打分矩阵 [b,a,s,s] 反向算 softmax 的输入梯度
MLP 中间张量（gate/up 与激活后） 各 [b,s,ffn] 反向算 MLP 权重梯度
MLP 输入 [b,s,h] 反向算 MLP 第一层权重梯度

b 是 batch，s 是序列长度，h 是 hidden 维度，a 是注意力头数，ffn 是前馈中间维度。把这张表按 bf16（2 B/元素）加总就是单层激活值，再乘层数 L 就是全模型。"激活值随序列平方增长"的出处就在这里：只有打分矩阵那一项带 s2。

2. 重计算：用一次前向换掉全部中间张量#

激活重计算（activation recomputation，也叫 gradient checkpointing）的思路很简单：前向时只保存每个 block 的输入，反向要用中间张量时把该 block 的前向再算一遍（算完立刻释放）。

方案 保留什么 每层激活值 额外算力
全部保留 上表全部 最大 0
逐层重计算 只留 block 输入 约 2bsh⋅字节 多一次前向
选择性重计算 留 block 输入 + 注意力输出，重算 MLP 中等 只重算 MLP
FlashAttention 式 不构造打分矩阵 去掉 s2 项 反向重算注意力块

算力账是严格可算的：训练一步的前向/反向 FLOPs 约为前向的 3 倍（前向 1 份、反向 2 份）。逐层重计算在反向里多跑一次前向，因此总算力变成 3→4 份，即多付 33%。选择性重计算只重算 MLP：若 MLP 占该层参数 75%，则只多付 0.75/3=25%。这就是"用三成算力换十倍显存"的来源。

3. 长序列时该重算谁：注意力矩阵才是主项#

把上面两张表代进实际数字（s=2048,h=12288,a=96,ffn=4h，bf16，单层）：

  • 保留全部（含打分矩阵）：2352 MiB，其中打分矩阵 [1,96,2048,2048] 占 1536 MiB（65%）；
  • 不构造打分矩阵：816 MiB；
  • 逐层重计算只留 block 输入：96 MiB，即前者的 1/24、全模型 9.00 GiB。

序列继续变长时，打分矩阵迅速吃掉一切：s=8192 时它占 88%，s=32768 时占 96.8%（此时单层不打分矩阵是 12.8 GiB，打分矩阵是 384 GiB）。结论很硬：长序列训练里，重算注意力的收益远大于重算 MLP。Megatron 那篇论文的原话是：配合序列并行，选择性重计算把激活显存减少 5 倍，同时把重计算的执行时间开销削减 90% 以上（530B 模型在 2240 张 A100 上，MFU 从 42.1% 提到 54.2%）。

4. 工程上必须处理的两件事：RNG 与粒度#

重计算要求"重算出的前向结果与第一次完全一致"，否则梯度就错了。所以：随机数状态（RNG state）必须保存与恢复——dropout 等操作在前向里消耗随机数，重算时要消耗同一串，PyTorch 的 torch.utils.checkpoint 默认会处理这一点；粒度决定取舍——太细则重算次数与启动开销抬升，太粗则峰值显存降不下来，常见做法是按 block 或按"注意力块 / MLP 块"分别 checkpoint。

5. 常见坑#

  • 以为重计算省的是参数显存：它只影响激活值；模型状态要靠 ZeRO / FSDP 解决。
  • 拿重计算当免费午餐：逐层重计算固定多 33% 算力，在 GPU 已打满的任务上直接变成 33% 的墙钟时间。
  • 忘了 RNG 一致性：带 dropout 的模型若手工重算而没恢复 RNG，训练会静默发散。
  • 在小序列上套用长序列结论：s=512 时打分矩阵只占 32%，此时优先该省的往往是 MLP 中间张量。
  • 只测峰值显存不测算力：必须同时记录 tokens/s 与峰值显存，否则无法判断是否划算。

二、可运行代码示例#

纯 Python，不需要 GPU。它把激活值账本（含"哪些张量值得留"）与重计算的算力代价一起算出来。

# ===== 示例：激活值账本与"重计算换显存"的定量取舍 =====
MB = 2**20; GB = 2**30

def layer_cost(s, h, a, ffn, b=1, dt=2, keep_attn=True):
    """单层激活值字节数（bf16）。
    保留下来的张量：4 个注意力投影输出 + 3 个 MLP 中间张量 + 1 个 block 输入，
    以及（可选）注意力打分矩阵 [b, a, s, s]。"""
    lin = (4 * b * s * h + 3 * b * s * ffn + b * s * h) * dt
    att = (2 * b * a * s * s) * dt if keep_attn else 0
    return lin + att

def fwd_flops_layer(s, h, ffn, b=1):
    """单层前向 FLOPs ≈ 2 × (该层参数量) × token 数。"""
    n_layer = 4 * h * h + 3 * h * ffn
    return 2 * n_layer * b * s

cfg = dict(s=2048, h=12288, a=96, ffn=4 * 12288)
L = 96
print(f"配置：s={cfg['s']}, h={cfg['h']}, a={cfg['a']}, ffn={cfg['ffn']}, L={L}, bf16（单卡单层）")
base = layer_cost(**cfg)
print(f"  单层激活值（保留注意力矩阵）  {base/MB:9.1f} MiB")
print(f"    其中注意力矩阵 [1,96,2048,2048] {2*1*96*2048*2048*2/MB:9.1f} MiB"
      f"（占 {2*1*96*2048*2048*2/base:.0%}）")
print(f"  单层激活值（不保留注意力矩阵，FlashAttention 式）{layer_cost(**cfg, keep_attn=False)/MB:9.1f} MiB")
print(f"  全模型 {L} 层（保留注意力矩阵）{base*L/GB:9.1f} GiB；"
      f"不保留 {layer_cost(**cfg, keep_attn=False)*L/GB:8.1f} GiB")

ckpt = 2 * 1 * cfg["s"] * cfg["h"] * 2          # 逐层重计算：只存 block 输入（两个张量）
print(f"\n逐层重计算：每层只存 block 输入 {ckpt/MB:.1f} MiB → 全模型 {ckpt*L/GB:.2f} GiB，"
      f"是「不重算且不存注意力」的 1/{layer_cost(**cfg, keep_attn=False)/ckpt:.0f}")

f = fwd_flops_layer(cfg['s'], cfg['h'], cfg['ffn'])
print(f"\n算力账：单层前向 ≈ 2·N_layer·tokens = {f/1e12:.2f} TFLOP（tokens={cfg['s']}）")
print(f"  训练一步（前向 1× + 反向 2×）≈ {3*f/1e12:.2f} TFLOP / 层")
print(f"  逐层重计算多跑一次前向 → 多付 {f/(3*f):.1%}（即 4/3 倍）")
r = 3*cfg['h']*cfg['ffn']/(4*cfg['h']**2+3*cfg['h']*cfg['ffn'])
print(f"  只重算 MLP（MLP 占该层参数 {r:.0%}）→ 多付 {r/3:.1%}；"
      f"选择性重计算存注意力输出、重算 MLP，省的是注意力矩阵那份")

print("\n序列越长，注意力矩阵越是主项（b=1, h=12288, a=96, bf16）：")
for s in (512, 2048, 8192, 32768):
    c = dict(cfg); c["s"] = s
    with_att = layer_cost(**c); without = layer_cost(**c, keep_attn=False)
    print(f"  s={s:<6} 不含注意力 {without/MB:8.1f} MiB  注意力矩阵 "
          f"{2*96*s*s*2/MB:9.1f} MiB  注意力占比 {(with_att-without)/with_att:6.1%}")

print("\n单层重算的墙钟代价（示例算力，仅看量级）：")
for tf in (1000, 400, 100):
    print(f"  设备 {tf:>4} TFLOP/s：{f/(tf*1e12)*1e3:8.2f} ms / 层 / 设备")

三、练习#

  1. 实现：把 layer_cost 扩展成"按张量逐项列出"的版本（每一项打印形状与字节数），并算出 s=4096、h=8192、a=64、ffn=4h、L=80 时每一项的占比排名。
  2. 解释：为什么逐层重计算的额外算力恰好是 33%，而它省下的显存却是 8 倍以上？分别用"算力只与前向 FLOPs 成正比"和"激活值含 s2 项"回答。
  3. 对比/验证：在 s=512 与 s=32768 两个配置下，分别比较"重算 MLP"与"不重算 MLP"的显存收益；说明为什么两个配置该做的选择相反。
  4. 思考：一个任务把重计算粒度从"每层一次"改成"每层两次"（前后半段各一次），显存与算力各会怎么变？再说明它与流水线并行（PP）的 1F1B 调度为什么需要一起考虑。
