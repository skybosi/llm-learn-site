微调类型#

"微调"不是一个单一动作，而是一个大家族。按"改多少参数"可以分成全参数微调和参数高效微调（PEFT）；按"训练目标"可以分成指令微调（SFT）、对齐微调（RLHF/DPO）和领域继续预训练。本课先把这张全景图铺开，为后面两章（全参数微调、LoRA）建立坐标系。

一、概念讲解#

1. 按"改动范围"分类#

全参数微调（Full Fine-Tuning，FFT）：训练时更新模型的所有参数。效果上限高，但显存和算力开销大——权重、梯度、优化器状态（Adam 需要两倍于权重的动量和方差）都要驻留显存。第 2 章专门讲它。

参数高效微调（Parameter-Efficient Fine-Tuning，PEFT）：冻结原模型权重，只训练极少量的新增参数或极少量原参数，用 1% 甚至更少的可训练参数逼近全参数微调的效果。PEFT 是一个方法族，主流成员包括：

  • Adapter（适配器）：在 Transformer 层之间插入小型瓶颈结构，只训练这些瓶颈参数。
  • LoRA（低秩适配）：给权重矩阵加一个低秩增量 ΔW = BA，只训练 A 和 B。这是本课程第 3 章的重点。
  • Prefix Tuning / Prompt Tuning：在输入前追加可学习的"软提示"向量，只训练这些向量。
  • P-Tuning v2：在每一层都注入可学习的提示向量，弥补早期方法"可训参数太少"的不足。
  • IA3 / AdaLoRA / QLoRA 等衍生：进一步压缩或量化，降低训练成本。

PEFT 的共同红利是：能训练更大的模型、能在单卡上跑、能像插件一样快速切换（每个任务存一小份适配器，而不是存一整份模型）。

2. 按"训练目标"分类#

  • 指令微调（SFT，Supervised Fine-Tuning）：用（指令，期望回答）对训练，教模型"听懂并执行指令"。这是最常用的入门微调，第 2 章的数据准备主要围绕它。
  • 对齐微调（Alignment）：在 SFT 之后进一步用人类偏好校准行为，典型是 RLHF（基于人类反馈的强化学习）和 DPO（直接偏好优化，更简单稳定）。目标是"更安全、更有用、更符合价值观"。
  • 领域继续预训练（Domain-Adaptive Pretraining / Continued Pretraining）：拿领域语料继续做语言建模，把领域知识"灌"进模型。成本接近预训练，一般只用于领域差距特别大的场景。

这三者常串联使用：先领域继续预训练补知识 → 再 SFT 教指令与格式 → 最后对齐校准偏好。

3. 为什么要认识"PEFT 家族"#

因为"改多少参数"直接决定了成本结构和工程方案：

方法 可训练参数占比 显存需求 典型用途
全参数微调 100% 很高（要存梯度+优化器状态） 领域差距大、算力充足
LoRA ~0.1%–1% 低（可训参数极少） 最通用的折中选择
Adapter ~1%–5% 低（但推理略有延迟） 多任务插拔
Prefix/Prompt Tuning <0.1% 很低 资源极度受限、任务简单

4. 选择指南#

  • 算力充足、任务和预训练分布差距大、追求极限效果 → 全参数微调。
  • 单卡、想快速迭代、要在一份基座上并行维护多个任务 → LoRA/QLoRA。
  • 任务很简单、只差一点点引导 → 先试试 Prompt Tuning，甚至先用提示工程。

记住一个原则：不是越"全"越好，而是"够用 + 可维护"最好。多数中小团队的实际起点是 LoRA。

二、可运行代码示例#

下面用 PEFT 库快速"预览"不同参数高效方法的配置长相，体会它们共用的接口。真正的训练会在第 2、3 章展开，这里先建立直觉。

# 安装：pip install peft transformers
from peft import LoraConfig, PrefixTuningConfig, PromptTuningConfig, IA3Config

# 1) LoRA：给部分权重矩阵加低秩增量 ΔW = BA
lora = LoraConfig(
    r=8,                     # 低秩维度
    lora_alpha=16,           # 缩放系数
    target_modules=["q_proj", "v_proj"],  # 只作用于注意力层的 Q、V 投影
    task_type="CAUSAL_LM",
)

# 2) Prefix Tuning：在每层 key/value 前追加可学习前缀向量
prefix = PrefixTuningConfig(
    num_virtual_tokens=20,   # 虚拟 token 数量
    task_type="CAUSAL_LM",
)

# 3) Prompt Tuning：只在输入前追加可学习的软提示向量
prompt = PromptTuningConfig(
    num_virtual_tokens=8,    # 可学习提示的 token 数
    task_type="CAUSAL_LM",
)

# 4) IA3：对 key/value/FFN 输出做逐元素缩放，可训参数更少
ia3 = IA3Config(
    target_modules=["q_proj", "v_proj", "k_proj", "down_proj"],
    feedforward_modules=["down_proj"],
    task_type="CAUSAL_LM",
)

print("四种 PEFT 方法的核心区别（用一句话概括）：")
print("  LoRA          -> 学习权重的低秩增量 ΔW=BA")
print("  Prefix Tuning -> 在每层 key/value 前插可学习前缀")
print("  Prompt Tuning -> 只在输入前插可学习软提示")
print("  IA3           -> 对已有激活做逐元素缩放")

再直观感受一下"可训练参数量"的差异——这是 PEFT 相对全参数微调最直接的收益。

# 模拟一个模型的总参数量，对比不同方法的可训练参数占比
total_params = 7_000_000_000   # 假设基座模型 70 亿参数

methods = {
    "全参数微调": 1.0,               # 100% 参数都要训练
    "Adapter":    0.03,              # 约 3%
    "LoRA":       0.003,             # 约 0.3%
    "Prompt Tuning": 0.0001,         # 约 0.01%
}

for name, ratio in methods.items():
    trainable = total_params * ratio
    print(f"{name:<14} 可训练参数约 {trainable/1e6:.1f} M（{ratio*100:.2f}%）")

print("\n要点：可训练参数越少，梯度与优化器状态占用的显存越少，")
print("     越容易在单张消费级显卡上完成训练。")
