同步与协作：__syncthreads、warp shuffle、协作组#

上一课说清了 warp 之间是"各自为战"的：调度器挑谁发射是自由的，所以你不能假设别的 warp 走到哪了。但 shared memory 恰恰是整个 block 共用的——A 线程写、B 线程读，读到的到底是新值还是旧值？这一课讲三种把顺序"钉死"的手段：block 级屏障 __syncthreads()、warp 内的 shuffle 原语，以及把它们包装成类型的 cooperative groups（协作组）。同一份归约，用屏障写要 8 轮同步，用 shuffle 写只要 1 轮——这个差距就是本课的全部意义。

一、概念讲解#

1. __syncthreads()：屏障 + 可见性，不只是"等一等"#

官方文档对 __syncthreads() 的定义包含两件事：等到 block 内所有线程都到达这个点，并且这些线程在此点之前对 global 与 shared memory 的写，对 block 内所有线程可见。第二条常被忽略：没有它，即使所有线程都"到了"，编译器与硬件也没有义务让你看到同伴刚写的 shared 值。

两条硬规则：

  1. 所有线程必须到达同一个屏障。把 __syncthreads() 放在"只有一部分线程会进"的分支里，是未定义行为——实际表现通常是整个 block 挂死（其余 warp 永远等不到）。边界判断要写在屏障之外，或者改成所有线程都到达的等价写法。
  2. 屏障不是免费的。它把 block 内所有 warp 卡在同一个点上，前面第 2 课讲过的"用别的 warp 填空"在屏障处失效。所以归约这类算法要尽量减少屏障轮数，而不是只在循环里加同步。

2. 数一数屏障：两种归约写法的差距#

以 256 个元素求和为例：

写法 同步结构 __syncthreads() 次数
朴素 shared 树形归约 每轮 stride 减半，每轮都要同步 log2(256) = 8
两级归约 每 warp 用 shuffle 出部分和（0 屏障）→ 写 shared → 1 次屏障 → warp 0 归约 1

两级写法的结构是：① 每个 warp 内部用 5 步 shuffle（32 = 2^5）算出 32 个 lane 的和；② 8 个 warp 各把自己 lane 0 的部分和写进 shared[8]；③ 一次 __syncthreads()；④ 让 warp 0 读这 8 个数，再用 3 步 shuffle 求和。屏障从 8 次降到 1 次，这个改进与"共享内存银行冲突"（第 3 章）是两件事，别混着算。

3. warp 级协作：__syncwarp 与 shuffle#

Volta 及之后，warp 内线程拥有独立调度——不能再用"warp 天然锁步"来当同步。官方语言扩展文档给出的要求是：warp 级原语都要带一个 mask 参数，明确声明哪些 lane 参与。

  • __syncwarp(mask)：参与 lane 的 warp 级屏障（只保证这些 lane 到达同一处，不涉及 shared 可见性语义）；
  • __shfl_sync(mask, v, srcLane)、__shfl_down_sync(mask, v, offset)、__shfl_up_sync、__shfl_xor_sync：让 lane 直接读同伴的寄存器值；
  • __ballot_sync(mask, pred)、__any_sync、__all_sync：把 32 个 lane 的谓词汇总成 mask/布尔。

关键性质：shuffle 是寄存器到寄存器的交换，不经过 shared memory，也不需要屏障。__shfl_down_sync(mask, v, k) 的语义是"lane i 取 lane i+k 的值，越界的 lane 保持自己的值不变"。所以 warp 内归约可以写成 5 步：offset = 16, 8, 4, 2, 1，每步 v += shfl_down(v, offset)，最后 lane 0 就是 32 个 lane 的和。

坑也集中在这里：mask 必须覆盖所有真正参与的 lane（漏掉就是未定义行为）；只能用 _sync 版本（老的 __shfl 已被弃用）；shuffle 只在本 warp 内有效，不能跨 warp；__shfl_up_sync 在 lane 0 处没有"上一个 lane"，越界语义同样是保持原值。

4. 协作组：把"范围"变成类型#

cooperative groups（协作组，头文件 cooperative_groups.h，命名空间 cg）做的事是：把"我在哪个范围内同步"从约定变成类型。

对象 范围 典型用法
cg::thread_block 整个 block cg::sync(block) 等价于 __syncthreads()；block.thread_rank() 给块内线性号
cg::tiled_partition<32>(block) 一个 warp 给 warp 级原语加上静态范围与类型安全
cg::coalesced_threads() 当前能一起走的那些 lane 收敛后立刻组队，减少显式 mask 出错
cg::grid_group 整个 grid 需要 cudaLaunchCooperativeKernel 启动，能做 grid 级同步

grid 级同步的代价要算清楚：只有能被同时驻留的 block 才可能全到齐，所以 grid 的规模必须不超过"每 SM 可驻留 block 数 × SM 数"。这个上限正是上一课 occupancy 的产出——occupancy 算不清，协作组 grid 同步就启动不起来（官方文档专门有一节 "When to use cudaLaunchCooperativeKernel"）。device 是否支持，也要用 cudaDevAttrCooperativeLaunch 之类的属性查询确认。

5. 常见坑#

  • 在分叉分支里调用 __syncthreads()：只要有一个 warp 到不了，就是 UB/挂死。
  • 用 volatile 代替屏障：volatile 只影响编译器优化的可见性，不建立线程之间的执行顺序。
  • 把 __syncthreads() 当 warp 内同步用：明明 5 步 shuffle 能解决，却让整个 block 停 8 次。
  • 以为 grid 同步免费：它要求"整个 grid 同时驻留"，规模一超就启动失败。
  • mask 写 0xffffffff 却只让 16 个 lane 参与：多出来的 lane 在等待，属于 UB；mask 要如实反映参与集合。

二、可运行代码示例#

下面用纯 Python/numpy 把上面两种归约各跑一遍：路线 A 模拟"shared memory + 每轮 __syncthreads()"，路线 B 模拟"warp 内 shuffle + 唯一一次屏障"。shfl_down_sync 按官方语义实现（越界 lane 保持不变），屏障次数也真的数出来。

# ---- 无 GPU 模拟 __syncthreads 屏障归约 与 warp shuffle 归约（纯 Python/numpy）----
import numpy as np

WARP = 32


class Block:
    """模拟一个线程块：shared 是块内共享内存，barrier() 当一次 __syncthreads。"""

    def __init__(self, threads, data):
        self.t = threads                      # 块内线程数
        self.shared = np.zeros(threads, dtype=np.int64)
        self.shared[:threads] = data          # 每个线程先把自己那份写进 shared
        self.barriers = 0

    def barrier(self, all_threads_arrive=True):
        self.barriers += 1
        if not all_threads_arrive:            # 只有部分线程到达 → 未定义行为
            raise RuntimeError('__syncthreads 只被部分线程到达：CUDA 里是未定义行为')


def tree_reduce_shared(block):
    """朴素 shared-memory 树形归约：每轮"活着的一半线程"读另一半、写回、再屏障。"""
    stride = block.t // 2
    round_no = 0
    while stride >= 1:
        for i in range(stride):
            block.shared[i] += block.shared[i + stride]
        block.barrier()                        # 每轮都必须同步，否则读到脏数据
        round_no += 1
        print(f'  shared 归约第 {round_no} 轮后（stride={stride}）：'
              f'前 8 项 = {block.shared[:8].tolist()}')
        stride //= 2
    return int(block.shared[0])


def shfl_down_sync(val, offset):
    """__shfl_down_sync(0xffffffff, val, offset)：lane 取 lane+offset 的值，越界则保持不变。"""
    out = val.copy()
    for lane in range(WARP):
        src = lane + offset
        if src < WARP:
            out[lane] = val[src]
    return out


def warp_reduce(v, verbose=True):
    """warp 内归约：5 步 shuffle、零屏障。要求 v 是长度 32 的数组。"""
    v = v.copy()
    offset, step = WARP // 2, 0
    while offset >= 1:
        v = v + shfl_down_sync(v, offset)
        step += 1
        if verbose:
            print(f'  shuffle 第 {step} 步（offset={offset:>2}）：'
                  f'lane 0..7 = {v[:8].tolist()}')
        offset //= 2
    return int(v[0])


rng = np.random.default_rng(1)
T = 256
data = rng.integers(0, 10, T).astype(np.int64)
golden = int(data.sum())
print(f'输入 {T} 个整数，参考和 = {golden}\n')

print('=== 路线 A：shared memory 树形归约（每轮一次 __syncthreads）===')
blk = Block(T, data)
got_a = tree_reduce_shared(blk)
print(f'结果 = {got_a}，正确 = {got_a == golden}，__syncthreads 次数 = {blk.barriers}\n')

print('=== 路线 B：两级归约 = warp 内 shuffle（0 屏障）+ warp 间 1 次屏障 ===')
n_warps = T // WARP
partials = np.zeros(n_warps, dtype=np.int64)
for w in range(n_warps):
    print(f'warp {w}：' if w == 0 else f'warp {w}：（步骤同上，只列部分和）')
    partials[w] = warp_reduce(data[w * WARP:(w + 1) * WARP], verbose=(w == 0))
print(f'  各 warp 的部分和 = {partials.tolist()}')
barriers = 1                                  # 只有"写 shared + 读 shared"之间需要一次
print(f'  把 {n_warps} 个部分和写进 shared → __syncthreads（第 1 次，也是唯一一次）')
padded = np.zeros(WARP, dtype=np.int64)
padded[:n_warps] = partials                   # 补 0 到 32，让 shuffle 能在整 warp 上跑
print(f'  补齐到 32 个 lane = {padded.tolist()}')
print('  warp 0 再对自己归约（offset=16/8 落在补 0 的 lane 上，等于空转）：')
warp0_sum = warp_reduce(padded)
print(f'结果 = {warp0_sum}，正确 = {warp0_sum == golden}，__syncthreads 次数 = {barriers}')
print(f'\n两种路线的屏障数：{blk.barriers} vs {barriers}（{blk.barriers / barriers:.0f}x）\n')

print('=== 反面例子：屏障放进"只有一半线程会进"的分支 ===')
try:
    Block(64, data[:64]).barrier(all_threads_arrive=False)
except RuntimeError as e:
    print('  抛出：', e)

三、练习#

  1. 实现：把 shfl_down_sync 换成 shfl_xor_sync 的语义（lane i 与 lane i ^ offset 交换），重写 warp_reduce，验证 5 步之后每个 lane 都得到同一个总和（蝶形归约），并解释为什么 xor 版本不需要 if (lane + offset < 32) 这种越界保护。
  2. 解释：为什么 __syncthreads() 的定义里要包含"此点之前对 shared/global 的写对块内所有线程可见"？如果只有"等所有线程到达"这一句，会出现什么样的错误程序？
  3. 对比/验证：把 T 从 256 改成 512、1024，分别记录两条路线的屏障次数与总 shuffle 步数，画一张小表，说明"两级归约"的屏障次数为什么与 T 无关（提示：只与"warps 数是否超过一个 warp 能一次归约的规模"有关），而朴素树形归约是 log2(T)。
  4. 思考：cg::grid_group 的 grid 同步要求"整个 grid 同时驻留"。请用第 2 课的 occupancy 公式估算：某架构每 SM 可驻留 2 个 512 线程的 block、共 100 个 SM，那么协作组 grid 最多能放多少个 block？如果模型要求 8 万个 block 才能算完，这条路走不走得通？
