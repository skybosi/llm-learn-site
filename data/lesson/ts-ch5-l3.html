多变量预测#

前面的课程大多是单变量预测：只拿一条序列的历史，预测它自己的未来。但真实业务里，序列之间往往互相影响——用电量受气温影响，车流量受节假日影响，股价受大盘影响。把这些相关序列一起喂给模型，让模型在预测目标变量时"顺带参考"其它变量，就是多变量预测。这一课讲清楚多变量预测的数据形态、两种建模路线，以及 Transformer 类模型如何自然地吃掉多维输入。

一、概念讲解#

1. 什么是多变量预测#

多变量时间序列是一组在同一时间轴上同步采样的序列。比如一个气象站每小时记录温度、湿度、气压、风速，这 4 条序列构成一个 4 维的时间序列。多变量预测通常有两种目标：

  • 单目标多变量：输入多个变量，但只预测其中一个（如只用"温度+湿度+风速"预测"用电量"）；
  • 多目标多变量：同时预测多个变量的未来（如同时预测温度和湿度）。

两者本质相同，只是输出维度不同。核心价值在于：相关变量携带了目标变量未来的信息，把它们纳入输入能提升预测精度。

2. 数据形态：三维张量#

多变量序列在张量里是 (批量, 时间步, 特征数)。相比单变量的 (批量, 时间步, 1)，只是最后一维从 1 变成了 C（特征数）。这个形状正是 LSTM/GRU/Transformer 天然接受的输入——LSTM 的 input_size=C，Transformer 的每个"token"是一个 C 维向量。

要特别注意数据泄露：预测 t+1 时刻的目标变量时，其它变量也只能用到 ≤t 时刻的值。如果把"明天的气温"也喂进模型去预测"明天的用电量"，那叫泄露（用未来预测未来），模型上线后必然失效。

3. 两条建模路线：通道混合 vs 通道独立#

多变量怎么融合，学界有两条思路：

  • 通道混合（channel mixing）：把所有变量的信息在一个模型里交互融合。传统 Transformer 就是这样——每个时间步的 C 维向量被整体当作 token，注意力在时间步之间进行，变量之间通过 FFN 的权重隐式交互。好处是变量间关系被显式建模；风险是不同变量的分布、尺度差异大，混在一起容易互相干扰。
  • 通道独立（channel independence）：每条变量各用一个模型独立预测，再汇总。近年 PatchTST 等模型发现，在不少基准上简单地对每条通道独立建模反而更稳——因为避免了跨变量的噪声干扰，且参数共享、易于训练。代价是放弃了变量间可能存在的真实因果信息。

选哪条，取决于数据：变量间耦合强（如气象变量共同驱动负荷）时混合可能更优；变量相关性弱、噪声大时独立更稳。工程上两条都值得试，用验证集说话。

4. 协变量：过去已知 vs 未来已知#

多变量预测里有一类特殊输入叫协变量（covariate）。按"未来是否提前可知"分两类：

  • 过去协变量（dynamic past）：和预测目标一样，未来未知，只能用到当前时刻，如实时传感器读数；
  • 未来协变量（dynamic future / known future）：未来也可提前知道，如日历特征（星期几、节假日）、计划性事件。这类变量未来取值已知，可以放心地用到预测窗口里，是很好的"免费信息"。

Informer 的输入设计里就区分了这些。理解协变量的"可知性"，能帮你在建模时既不泄露、又不错过可利用的未来信息。

5. 标准化：多变量必做的一步#

不同变量的量纲差异极大（温度 040，负荷 010000，湿度 0~100%）。直接喂进模型，梯度会被大数值变量主导。因此多变量预测几乎必须做逐变量标准化（如对每个变量分别做 z-score），预测后再对目标变量逆标准化还原到原始量纲。这一步骤在下一章实战里会完整走一遍。

二、可运行代码示例#

下面用一个多变量 Transformer 编码器做"多对多"预测：输入 3 条相关序列的 60 步历史，预测其中 1 条的 10 步未来。重点展示三维张量的流动，以及如何用因果掩码 + 单次前向一次输出整段预测。

import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np

torch.manual_seed(0)
np.random.seed(0)

# 1) 生成 3 条相关序列：目标序列由趋势+周期+噪声构成，另两条作为协变量
t = np.arange(0, 800)
target = 0.02 * t + 5 * np.sin(t / 12.0) + np.random.randn(800) * 0.3
cov1 = 5 * np.cos(t / 12.0) + np.random.randn(800) * 0.2   # 与目标相关的协变量
cov2 = np.random.randn(800) * 1.0                            # 无关噪声协变量
data = np.stack([target, cov1, cov2], axis=-1)               # (800, 3)

# 2) 逐变量 z-score 标准化（多变量预测的必备步骤）
mean = data.mean(axis=0)
std = data.std(axis=0) + 1e-6
data = (data - mean) / std

# 3) 构造样本：输入 60 步 × 3 变量，输出目标变量未来 10 步
IN_LEN, OUT_LEN, C = 60, 10, 3
def make_dataset(data, in_len, out_len, target_idx=0):
    X, y = [], []
    for i in range(len(data) - in_len - out_len):
        X.append(data[i:i + in_len])                       # (in_len, C)
        y.append(data[i + in_len:i + in_len + out_len, target_idx])  # 只预测目标变量
    return (torch.tensor(X, dtype=torch.float32),
            torch.tensor(y, dtype=torch.float32))

X, y = make_dataset(data, IN_LEN, OUT_LEN)
print("X 形状:", X.shape, " y 形状:", y.shape)   # (N, 60, 3) 与 (N, 10)

# 4) 简易多变量 Transformer 编码器：时间步之间做因果自注意力
class MultivarTransformer(nn.Module):
    def __init__(self, d_model=32, nhead=4, num_layers=2, out_len=10):
        super().__init__()
        self.input_proj = nn.Linear(C, d_model)             # 把 C 维特征投影到 d_model
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead, dim_feedforward=64,
            batch_first=True)
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers=num_layers)
        self.head = nn.Linear(d_model, out_len)             # 一次输出未来 out_len 步

    def forward(self, x):
        # x: (batch, in_len, C)
        h = self.input_proj(x)                              # (batch, in_len, d_model)
        # 因果掩码：让时间步 i 只能看到 <=i 的位置
        L = h.size(1)
        causal_mask = torch.triu(torch.ones(L, L), diagonal=1).bool()
        h = self.encoder(h, mask=causal_mask)               # (batch, in_len, d_model)
        # 取最后一个时间步的特征，映射到未来 out_len 步
        return self.head(h[:, -1, :])                       # (batch, out_len)

model = MultivarTransformer()
criterion = nn.MSELoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

model.train()
for epoch in range(400):
    optimizer.zero_grad()
    pred = model(X)
    loss = criterion(pred, y)
    loss.backward()
    optimizer.step()
    if (epoch + 1) % 50 == 0:
        print(f"epoch {epoch+1:3d}  loss={loss.item():.4f}")

# 5) 推断并逆标准化目标变量
model.eval()
with torch.no_grad():
    src = torch.tensor(data[-IN_LEN:], dtype=torch.float32).unsqueeze(0)
    pred = model(src)                                       # (1, out_len)
pred_origin = pred[0].numpy() * std[0] + mean[0]            # 还原到原始量纲
print("逆标准化后的未来 10 步预测:", np.round(pred_origin, 2))

要点：

  • 输入是 (N, 60, 3) 的三维张量，最后一维 3 就是"多变量"，Transformer 的 input_proj 把它投影到 d_model；
  • 因果掩码 torch.triu 保证第 i 个时间步只看到历史，不会偷看未来；
  • 输出只取目标变量，head 把最后一个时间步的特征直接映射成未来 10 步——这是一次前向出整段预测，符合 Informer 的生成式思想；
  • 标准化在训练前做、预测后逆标准化，二者必须用同一组 mean/std，否则量纲错乱。

三、练习#

  1. 把 cov2（无关噪声）从输入里去掉再训练，比较预测精度。无关变量是否一定有害？多加入变量带来的"信息"与"噪声"如何权衡？
  2. 把目标从"只预测 target"改成"同时预测 3 个变量"（输出 (N, out_len, 3)），修改 head 层，观察多目标预测的难度变化。
  3. 把 num_layers 从 2 加到 4，观察是否过拟合（训练 loss 更低但验证 loss 更高）。多变量 + 小数据时，模型容量该如何控制？
  4. 思考：本示例用"通道混合"（所有变量进一个模型）。若要改成"通道独立"（每条变量单独建模再汇总），模型结构该如何拆？两者在什么数据上各有优势？
