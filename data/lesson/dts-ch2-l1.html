AllReduce 三种做法：ring / tree / recursive-doubling 的步数与通信量#

8 张卡各持一份 100 MiB 的梯度，要逐元素求和并把结果交回每张卡。最直白的写法是"所有卡发给 0 号卡，0 号卡求和再广播回去"——总发送量 2(p−1)s 看起来不算离谱，但 0 号卡一进一出两块带宽会直接变成整个作业的天花板。同一件事，工业库（NCCL）实际用的是一族结构完全不同的算法。这一课把其中三种主流做法折算成同一套账：步数、每步消息大小、每 rank 发送量、全体发送量，再用第 1 章的 α-β 模型换成时间。

一、概念讲解#

1. 先把符号和四个口径定死#

AllReduce（全归约）指：p 个 rank 各持一份同形状张量，每个 rank 输入 s 字节，输出是各 rank 逐元素归约（通常求和）后的结果，所有 rank 结果相同。四个口径必须分开记，混用是这一章最常见的错误：

口径 含义 谁在惩罚它
步数 所有 rank 同时收发一次算一步 固定延迟 α
每步消息大小 一个 rank 一步发出多少字节 单次传输时间 s/β，以及小消息的效率
每 rank 发送量 一个 rank 在整个 AllReduce 里发出的总字节 该卡自己的出向带宽
全体发送量 p× 每 rank 发送量 网络汇总带宽（bisection / 交换机）

2. ring（环）：reduce-scatter + allgather#

ReduceScatter（归约散射）：把缓冲区切成 p 块，归约后第 r 块完整结果落到 rank r。AllGather（全收集）：每 rank 拿一块，最后每 rank 都拿到全部块。NCCL 文档把这条等价关系写得很直白：先 ReduceScatter 再 AllGather，等于一次 AllReduce。

ring 的做法：rank 排成一个逻辑环，每步向左邻居收一块、向右邻居发一块。

  • reduce-scatter 阶段 p−1 步：第 k 步 rank r 收到块 (r−k−1)modp 的部分和并累加；
  • allgather 阶段 p−1 步：把已完整的块沿同一个环传一圈。

账本（代码实测 p=8）：14 步，每步每 rank 只发 s/p（实测 0.125s），每 rank 发送 2(p−1)s/p=1.75s，全体 2(p−1)s=14s。每一步所有链路都在忙、没有 rank 空转，且每 rank 发送量 2(p−1)s/p 已经贴着 AllReduce 的信息量下界走——Patarasuk 与 Yuan 2009 年证明的"环式 AllReduce 带宽最优"就是这个意思。代价在延迟项：2(p−1)α 随 p 线性增长（NVIDIA 自己的说法是 "the downside of rings is that latency scales linearly with the number of GPUs"）。

3. tree（树）：延迟换总字节#

二项树（binomial tree）做法：第 k 步，rank 号第 k 位为 1 的把当前部分和交给"把这一位清零"的伙伴；⌈lgp⌉ 步后 rank 0 拿到完整和。再沿同一棵树反向广播 ⌈lgp⌉ 步，人人有结果。

  • 步数 2⌈lgp⌉（p=8 时 6 步），延迟项从 2(p−1)α 降到 2⌈lgp⌉α；
  • 但每步消息是整个缓冲区 s（没有切块），每 rank 恰好发 ⌈lgp⌉ 次；
  • 账本（实测）：每 rank 3.0s、全体 24s，比 ring 的 14s 多 71%。

所以朴素二项树是"延迟换带宽"的标准例子。NCCL 用的不是这棵树：它构建双二叉树（double binary tree），两棵互补的树各承担一半数据，按 NVIDIA 官方博客的说法，"每 rank 最多把一半数据发两次、收两次，和 ring 的收发量同级"，同时保留对数级延迟；当树换不来带宽时 NCCL 会自动切回 ring。常见误解是把树想成"根是唯一瓶颈"——二项树里每个 rank 都发 ⌈lgp⌉ 次，真正的代价是"每步都发整个缓冲区"和总字节数。

4. recursive-doubling / butterfly（折半 + 倍增）#

第三种做法把 reduce-scatter 改成每步折半（掩码 p/2,p/4,…,1）、把 allgather 改成每步倍增（掩码 1,2,…,p/2），伙伴是 rank ^ mask：

  • reduce-scatter：第 k 步 rank 只保留"块号与自己在掩码位上相同"的那一半，把另一半发给伙伴并累加收到的对应块；
  • allgather：反过来，每步把自己已有的块集发一份给伙伴、收下自己没有的。

账本（实测 p=8）：6 步，消息大小是 [s/2,s/4,s/8,s/8,s/4,s/2]——首尾大、中间小；每 rank 发送仍是 1.75s、全体 14s，与 ring 的带宽账完全同级，步数却只有 ring 的 6/14。代价是通信对象：最后几步每 rank 要发 s/2 并与距离 p/2 的伙伴互换，网络要求从"邻居链路可用"升级成"同时可用的远距离通路"；跨机时这些步要走 NIC，直接吃网络的 bisection 带宽（第 3 课量化）。

MPICH 里对非 2 的幂要额外处理（把非 2 的幂归并成 2 的幂再补步，步数上界 2⌊lgp⌋），这也是 Thakur 等人 2005 年那篇集合通信优化论文里的做法。

5. 三张账本摆在桌上#

算法 步数 每步消息 每 rank 发送 全体发送（p=8 实测）
ring 2(p−1) s/p，均匀 2(p−1)s/p≈2s 14 s，14 步
tree（朴素二项树） 2⌈lgp⌉ s，均匀但都很大 ⌈lgp⌉s 24 s，6 步
butterfly（折半+倍增） 2⌈lgp⌉ 几何增减 2(p−1)s/p≈2s 14 s，6 步

常见坑：① 把"每 rank 发送量"与"全体发送量"混着比（差 p 倍）；② 认为 ring 延迟最优（小消息下 2(p−1)α 是纯亏）；③ 认为树省带宽（朴素树的总字节是 ring 的 p/2 倍量级）；④ 以为非 2 的幂直接照搬（要补步或做二进块分解）；⑤ 把示例 α/β 当自己机器的参数（用 nccl-tests 实测，见下）。

二、可运行代码示例#

三个算法都用 numpy 在本地跑一遍：结果与逐元素参考求和比对（偏差为 0），同时把每步消息、每 rank 发送量、全体发送量记成账。

# ===== 示例 1：三种 AllReduce 的步数与通信量（纯 Python/numpy，无需 GPU） =====
import math
import numpy as np


def make_inputs(P, n, seed=7):
    rng = np.random.default_rng(seed)
    return [rng.integers(0, 256, size=n).astype(np.float64) for _ in range(P)]


def ring_allreduce(inputs):
    """ring：reduce-scatter (P-1) 步 + allgather (P-1) 步，每步每 rank 发 s/P 字节。"""
    P, n = len(inputs), inputs[0].size
    m = n // P
    assert n % P == 0, "ring 需要 s 能被 P 整除"
    b = [v.reshape(P, m).copy() for v in inputs]
    msgs, sent = [], [0] * P
    for k in range(P - 1):                                   # reduce-scatter
        nxt = [c.copy() for c in b]
        for r in range(P):
            c = (r - k - 1) % P
            nxt[r][c] = b[r][c] + b[(r - 1) % P][c]
            sent[r] += m * 8
        b = nxt
        msgs.append(m * 8)
    for k in range(P - 1):                                   # allgather
        nxt = [c.copy() for c in b]
        for r in range(P):
            c = (r - k) % P
            nxt[r][c] = b[(r - 1) % P][c]
            sent[r] += m * 8
        b = nxt
        msgs.append(m * 8)
    return [c.reshape(n) for c in b], {"steps": len(msgs), "msgs": msgs, "sent": sent}


def tree_allreduce(inputs):
    """tree：二项树归约到 rank0（lg P 步）+ 沿同一棵树广播（lg P 步），每步消息 = 整个缓冲区。"""
    P, n = len(inputs), inputs[0].size
    lg = int(math.log2(P))
    assert 2 ** lg == P, "二项树演示要求 P 是 2 的幂"
    b = [v.copy() for v in inputs]
    msgs, sent = [], [0] * P
    for k in range(lg):                                      # 归约：第 k 位为 1 的送给第 k 位为 0 的
        nxt = [c.copy() for c in b]
        for r in range(P):
            if (r >> k) & 1:
                p = r ^ (1 << k)
                nxt[p] = nxt[p] + b[r]
                sent[r] += n * 8
        b = nxt
        msgs.append(n * 8)
    for k in reversed(range(lg)):                            # 广播：父节点结果交给子节点
        nxt = [c.copy() for c in b]
        for r in range(P):
            if (r >> k) & 1:
                p = r ^ (1 << k)
                nxt[r] = b[p].copy()
                sent[p] += n * 8
        b = nxt
        msgs.append(n * 8)
    return b, {"steps": len(msgs), "msgs": msgs, "sent": sent}


def butterfly_allreduce(inputs):
    """butterfly：递归折半 reduce-scatter + 递归倍增 allgather，共 2 lg P 步，消息大小按 2 的幂增减。"""
    P, n = len(inputs), inputs[0].size
    m = n // P
    lg = int(math.log2(P))
    assert 2 ** lg == P, "butterfly 演示要求 P 是 2 的幂"
    chunks = [[v.reshape(P, m)[c].copy() for c in range(P)] for v in inputs]
    held = [set(range(P)) for _ in range(P)]
    msgs, sent = [], [0] * P

    mask = P // 2
    while mask >= 1:                                         # reduce-scatter（折半）
        old = [[c.copy() for c in row] for row in chunks]
        gives, msg = [], 0
        for r in range(P):
            g = [c for c in held[r] if (c & mask) != (r & mask)]
            gives.append(g)
            msg = max(msg, len(g) * m * 8)
        for r in range(P):
            p = r ^ mask
            for c in gives[r]:
                chunks[p][c] = chunks[p][c] + old[r][c]
                sent[r] += m * 8
        held = [{c for c in held[r] if (c & mask) == (r & mask)} for r in range(P)]
        msgs.append(msg)
        mask //= 2

    mask = 1
    while mask < P:                                          # allgather（倍增）
        old = [[c.copy() for c in row] for row in chunks]
        sends, msg = [], 0
        for r in range(P):
            g = [c for c in held[r] if (c & mask) == (r & mask)]
            sends.append(g)
            msg = max(msg, len(g) * m * 8)
        for r in range(P):
            p = r ^ mask
            for c in sends[r]:
                chunks[p][c] = old[r][c]
                sent[r] += m * 8
        held = [held[r] | set(sends[r ^ mask]) for r in range(P)]
        msgs.append(msg)
        mask *= 2

    outs = [np.concatenate([chunks[r][c] for c in range(P)]) for r in range(P)]
    return outs, {"steps": len(msgs), "msgs": msgs, "sent": sent}


P, n = 8, 8192
inputs = make_inputs(P, n)
expect = np.sum(inputs, axis=0)
s_bytes = n * 8
print(f"P = {P} 个 rank，每个 rank 一份 {n} 个 float64（s = {s_bytes} B）")

for name, fn in (("ring      ", ring_allreduce), ("tree      ", tree_allreduce),
                 ("butterfly ", butterfly_allreduce)):
    outs, info = fn(inputs)
    err = max(float(np.abs(o - expect).max()) for o in outs)
    frac = [round(b / s_bytes, 4) for b in info["msgs"]]
    s_ = info["sent"]
    print(f"{name}:步数 {info['steps']:2d} | 每步消息/s = {frac}")
    print(f"           每 rank 发送 {min(s_)/s_bytes:.3f}~{max(s_)/s_bytes:.3f} s"
          f" | 全体合计 {sum(s_)/s_bytes:.3f} s | 与精确求和最大偏差 {err:.1e}")


# ===== 示例 2：用 α-β 模型把上面的账换成时间（α、β 是示例参数，请换成实测值） =====
def t_model(info, s, P, alpha_us, beta_gbs):
    return sum(alpha_us + f * s / (beta_gbs * 1e9) * 1e6 for f in
               [b / (n * 8) for b in info["msgs"]])


res = {name: fn(inputs)[1] for name, fn in (("ring", ring_allreduce),
                                            ("tree", tree_allreduce),
                                            ("butterfly", butterfly_allreduce))}
alpha, beta = 5.0, 300.0
print(f"\nα = {alpha} μs，β = {beta} GB/s（NVLink 级示例参数），P = {P}，单位 μs：")
print(f"{'消息 s':>10} {'ring':>10} {'tree':>10} {'butterfly':>10}   最快")
for kb in (4, 64, 1024, 16384, 262144):
    s = kb * 1024
    t = {k: t_model(v, s, P, alpha, beta) for k, v in res.items()}
    best = min(t, key=t.get)
    row = "".join(f"{t[k]:>10.1f}" for k in ("ring", "tree", "butterfly"))
    print(f"{kb:>7} KiB{row}   {best}")

三、练习#

  1. 实现：把 butterfly_allreduce 的 allgather 阶段改成"先折半 reduce-scatter、再朴素环式 allgather"，统计步数与每 rank 发送量；用 p=8 跑一遍，解释为什么总字节数会比 butterfly 多。
  2. 解释：为什么朴素二项树每 rank 都恰好发 ⌈lgp⌉ 次（无论它在树里是叶子还是根）？用 p=8 的 rank 0 与 rank 7 各画一遍。
  3. 对比/验证：把示例 1 的 p 从 8 改成 16、64，分别打印三种算法的步数与每 rank 发送量，验证 ring 的步数是 2(p−1)、两个对数算法是 2lgp。
  4. 思考：如果一次 AllReduce 只有 4 KiB，你更在意 α 还是 β？把示例 2 的 α 从 5 μs 提到 20 μs，重算 4 KiB 那一行，说明哪一项在决定结果。
