算力 FLOPs vs 显存带宽#

前两课把"精度"讲透了，现在回到那张卡的三个数字，正式引入贯穿后半程的核心概念：算术强度（arithmetic intensity）。它回答一个问题——一个算子跑起来，到底是"算力不够"还是"数据搬得不够快"。

一、概念讲解#

1. 先分清两个单位#

  • FLOPs：浮点运算次数（数量），比如 GEMM 的 2mnk；
  • TFLOPS：每秒万亿次浮点运算，即算力（速率），是 FLOPs 除以时间的上限；
  • 带宽：每秒能搬运的字节数（速率），如 H100 的 3.35 TB/s。

2. 任何算子都分"搬"和"算"两步#

一个 kernel 的执行，先要从显存读输入，算完再写回结果。它的耗时被两个上限同时卡住：

时间≥max(算力FLOPs​, 带宽字节数​)

取 max 的含义是：慢的那个才是真正的瓶颈。算力再高，数据喂不过来也白搭；带宽再大，算力不够也白搭。

3. 算术强度：把"搬"和"算"比一比#

定义：

算术强度=搬运的字节数FLOPs​(FLOP/byte)

它描述"每搬 1 字节数据，能做多少次运算"。强度高的算子是"计算密集"，强度低的是"访存密集"（下一章展开）。

4. 机器自己的"强度分界线"：峰值算力 ÷ 带宽#

把一台机器的峰值算力和带宽一除，就得到它自己的分界线：

  • H100：989 TFLOPS ÷ 3.35 TB/s ≈ 295 FLOP/byte；
  • A100：312 TFLOPS ÷ 2.0 TB/s ≈ 156 FLOP/byte。

这个数（后面叫 ridge point，拐点）的含义是：如果算子的算术强度低于它，这台机器跑这个算子就是"带宽不够"，反之是"算力不够"。换句话说，机器在告诉你"我擅长算多少强度以上的活"。

5. 用几个算子练手#

算子 大致算术强度 在 H100 上
大矩阵乘（GEMM，分块复用后） 高（几十到几百） 偏计算密集
逐元素激活 / 加法 ~0.2（读2写1，每元素1次运算） 访存密集
LayerNorm / Softmax 很低 访存密集
矩阵乘向量（矩阵瘦长） ~1 访存密集

看到没？不是所有矩阵运算都"计算密集"——矩阵乘向量（decode 阶段的核心）强度就极低，这正是 LLM 推理卡在带宽上的伏笔。

二、可运行代码示例#

把上面这套判断写成代码：算强度、算两个时间上限、取 max 找瓶颈。

# ---- 例 1：机器的"强度分界线"（ridge point） ----
def ridge(peak_tflops, bw_tb_s):
    return peak_tflops * 1e12 / (bw_tb_s * 1e12)   # 换算成 FLOP/byte

machines = {
    "A100 SXM": (312.0, 2.0),
    "H100 SXM": (989.0, 3.35),
    "H200 SXM": (989.0, 4.8),
}
for name, (flops, bw) in machines.items():
    print(f"{name}: ridge = {ridge(flops, bw):.0f} FLOP/byte")

# ---- 例 2：算一个算子的算术强度 ----
def op_intensity(flops, bytes_moved):
    return flops / bytes_moved

# 4096^3 GEMM（理想复用后，近似只搬 3 个矩阵）
n = 4096
ge = op_intensity(2*n**3, 3*n*n*2)      # FP16 每元素 2 字节
print(f"\n4096^3 GEMM(FP16) 强度 ≈ {ge:.0f} FLOP/byte")

# 逐元素操作：读 1 个数、写 1 个数、做 1 次运算
elem = op_intensity(1, 2 * 2)           # 读+写共 2 个元素 × 2 字节
print(f"逐元素 op(FP16) 强度 = {elem} FLOP/byte")

# ---- 例 3：耗时 = max(算力时间, 带宽时间)，谁才是瓶颈 ----
def kernel_time(flops, bytes_moved, peak_tflops, bw_tb_s):
    compute_t = flops / (peak_tflops * 1e12)
    memory_t  = bytes_moved / (bw_tb_s * 1e12)
    return compute_t, memory_t, max(compute_t, memory_t)

# 场景 A：大 GEMM
fA, bA = 2*n**3, 3*n*n*2
ct, mt, tt = kernel_time(fA, bA, 989.0, 3.35)
print(f"\n大 GEMM：算力 {ct*1e3:.2f}ms vs 带宽 {mt*1e3:.2f}ms -> 瓶颈 {'算力' if ct>mt else '带宽'}")

# 场景 B：读 140GB 权重但只做很少运算（模拟 decode）
fB, bB = 2*70e9, 70e9*2
ct, mt, tt = kernel_time(fB, bB, 989.0, 3.35)
print(f"读 70B 权重：算力 {ct*1e6:.0f}us vs 带宽 {mt*1e3:.1f}ms -> 瓶颈 {'算力' if ct>mt else '带宽'}")

要点：例 1 的 ridge 就是"机器的强度分界线"；例 2 让你看到 GEMM 强度可达几百、逐元素 op 只有 0.25，天差地别；例 3 的对照最直观——大 GEMM 卡在算力，而"读一遍 70B 权重"卡在带宽，两者差了三个数量级。"读权重"这类活，算力再翻倍也没用，只能靠加带宽或减字节数。

三、练习#

  1. 计算：一个算子做 1010 FLOPs、搬运 2×109 字节，它的算术强度是多少？在 H100（ridge ≈ 295）上它更可能卡在算力还是带宽？
  2. 判断：用 kernel_time 分别计算"算力时间"和"带宽时间"，判断一个强度为 10 FLOP/byte、总共 109 FLOPs 的算子在 H100 上的瓶颈。
  3. 对比：为什么 H200 的 ridge（206）比 H100（295）更低？带宽变高、算力不变，对"访存密集"的负载是好事还是坏事？
  4. 思考：如果给 H100 换上 989 TFLOPS 但带宽只有 1 TB/s 的"假想卡"，ridge 会变成多少？这对大模型推理意味着什么？
