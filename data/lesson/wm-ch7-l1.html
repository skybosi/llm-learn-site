与 LLM 的关系与分工：两个建模对象、一条接口，以及"谁替代谁"为什么是错问题#

这一节要解决什么#

第 1 章第 1 节（wm-ch1-l1）已经划过一次界：LLM 建模离散 token 序列的条件分布，世界模型建模状态—动作—观测的动力学，差别在建模对象而不在模态。但那一次只是"分家"。真实工程里更常见、也更容易出错的问题是分家之后怎么合作：

  • 一个机器人系统里，把"把桌上的杯子拿给我"翻译成子目标，和"这一帧该给多大关节力矩"，应该由同一个模型负责吗？
  • 一个已经能推理、能写代码的 LLM，为什么还需要一个只会预测下一帧的模型？反过来，一个能精确预测物理的系统，为什么还需要 LLM？
  • 如果两者都要，接口长什么样？谁错了由谁发现？"两个都上"什么时候是负优化？

而这两个方向在公共讨论里最常被表述成一个替代关系：要么"世界模型是 LLM 的下一站"，要么"LLM 已经能做动力学，世界模型是多余的"。这一节要证明这个提法本身是错的，并给出可判定的分工判据——不是"两者互补"这种无法执行的结论，而是"给定任务，问五个可测量，就能决定这一层交给谁"。

本节的交付是四样东西：

  1. 两个方向的接口契约：各自吃什么、吐什么、以及为什么这五条结构性差异不能互相吸收（§一）；
  2. "谁替代谁"是错问题的三条论证，每一条都落在一个可观测的失败上（§二）；
  3. 一层的分工接口：高层规划层 / 低层预测层怎么接，接口的四个必填字段，以及三种具体接法各自的失效模式（§三）；
  4. 五条可判定的分工判据 C1–C5，配套一个决策流程与一份"两个都上也会亏"的成本清单（§四、§五）。

配套代码把"接口精度"这件事量化：同一个环境、同一个规划器，只把动作从连续通道换成 token 通道，看规划后悔怎么变；然后看同一批模型放在粗粒度决策与细粒度决策上，代价差多少；最后看"高层符号层 + 低层连续层"的分层组合在什么接口条件下才真的划得来。

定位提醒：世界模型是与 LLM 同等地位、方向不同的独立模型方向。这一节不讨论"谁更先进"，只讨论"各自建模什么、各自强在哪、接口怎么接、什么时候该用谁"。判断"谁替代谁"之所以是错问题，根本原因是两者的输出不是同一种东西，因而无法在同一个目标函数下比较。

一、先把两个方向的契约钉死#

1.1 两个接口的形状#

把两个方向各自压缩成一行接口，差别立刻可见：

LLM:c⟼pθ​(x1:T​∣c),xt​∈V, ∣V∣∼104–105

其中 c 是上下文（提示、历史 token、工具返回），输出是词表上的分布。

WM:(st​,at​)⟼pθ​(st+1​∣st​,at​),at​∈A, st​∈S

其中 at​ 是外生的控制输入，st​ 是状态（显式或隐式），输出是状态空间上的分布。

两个接口的形状不同，决定了它们能回答的问题不同。 LLM 能回答"接下来最可能出现的 token 是什么"，世界模型能回答"如果我这样做，世界会变成什么样"。后者是一个反事实问题，它的条件里有一项是"我做了什么"。

1.2 五条结构性差异，以及为什么它们不能互相吸收#

第 1 章第 1 节给过一张对照表。这里把它推进到"为什么不能靠工程手段抹平"——每一条都给出可观测的后果，这也是后面判据表的依据。

# 差异 LLM 一侧 世界模型一侧 不能互相吸收的原因（可观测后果）
1 取值空间 离散、有限词表 连续/高维（或结构化符号） 离散化的分辨率是有损的：同一 token 内的两个动作在模型里无法区分。本课实测：3 个 token 时 33.4% 的动作对不可分辨，规划后悔是连续模型的 7 倍
2 控制输入 无外生通道，动作只能混进 token 动作是分离通道，带干预语义 混进 token 的动作无法被搜索算法枚举：规划要在 A 上取 argmax，而"提示词"不是一个可枚举、可求梯度的空间
3 时间语义 序列位置（语义步） 物理时间步 Δt 语义步与物理步不重合，导致"预测多少步"与"未来多少秒"无法对齐；误差的乘积放大按 Δt 累积（第 2 章第 4 节）
4 数据来源 人类文本（被动、相关性强） 交互轨迹（主动、含干预） 文本只记录了"实际发生的那一条轨迹"，反事实信息不在里面。本课实测：只看被动数据时，一个 MDP 的后验价值区间宽 1.8393（真值尺度 4.71），而"留出准确率"完全看不出来（§二会给这条数字）
5 目标函数 交叉熵，天然规范化 需要一个度量（MSE/NLL/下游收益） 度量即归纳偏置：换一个度量就换一个最优模型。用预测似然选出来的模型，可能在决策相关子空间上恰好是错的（第 4 章第 4 节表 D 的实测）

这五条里，只有第 1 条是"程度问题"，其余四条是"种类问题"。 第 1 条可以靠加 token 缓解（代价见代码）；第 2–5 条无法靠把数据、模型、算力堆上去消除，因为它们描述的是接口的形状。这也是为什么"世界模型是 LLM 的一个模态/一个分支"这个说法从一开始就不成立：一个没有外生控制通道的模型，无论多大，都无法被规划器查询。

二、"谁替代谁"是错问题#

2.1 三条论证，每条落到一个可观测的失败#

论证一（接口）：动作空间被离散化后不可枚举。 把连续动作编码成 token 需要先划分离散的档位。档位一粗，规划器在动作空间上的搜索就退化为"在几个桶之间选"：同一桶内的所有动作对模型完全等价。这不是模型能力问题，而是接口分辨率问题。

本节的代码把这条量化：在同一个线性动力学环境里，只把动作换成 n 个 token，用同一个随机射击规划器：

动作 token 数 不可分辨动作对占比 反事实分离度 ρˉ​cf​ 规划后悔
连续（无 token） 0.000 1.000 0.0039
3 0.334 0.856 0.0273
5 0.195 0.920 0.0141
11 0.087 1.002 0.0065
21 0.045 0.978 0.0040
51 0.018 1.011 0.0039

（N=3000 条转移，H=3，15 个候选动作，3 个规划种子；完整表见 §代码表 A。）

3 个 token 的规划后悔是连续接口的 7 倍。 而三行的一步预测误差几乎相同——用"预测得准不准"是看不出这个差别的，因为差异全部在动作通道的分辨率上。

论证二（数据）：反事实信息不在被动数据里。 文本记录的是"实际发生的事"，而世界模型要回答的是"如果换一个动作会怎样"。第 7 章第 2 节的实验把这条算成了一个数：一份由固定行为策略采集的 400 条交互数据，用后验采样可以得到一族在数据上完全一致的动力学模型（留出准确率恒为 0.7997∼0.8030），但它们的真实策略值区间宽 1.8393，最差的那 7% 后验样本会在第一步就选错动作。这一点在纯被动数据上是不可判定的：要把它定住，必须让干预数据覆盖那些从未被访问过的 (s,a)。

论证三（失败模式）：两种错误不能互相修补。 LLM 的失败是"语义上没有根据"（幻觉、与事实不符），世界模型的失败是"动力学历时变坏"（复合误差、被规划器利用）。前者可以靠检索与验证缓解，后者只能靠约束视界、保守化、闭环校正缓解。一个不会因为"读了一篇论文"而变准，另一个不会因为"参数更多"而停止发散。 所以"用 LLM 修世界模型的误差"和"用世界模型修 LLM 的幻觉"都不是可行的替代路径——它们只能互相检测（见 §3.2 的三种接法）。

2.2 两种"看起来能替代"的做法及其代价#

做法 表面上 实际代价
把状态/动作序列化成 JSON/文本，让 LLM 预测下一个状态 "LLM 也能做动力学" ① 每个物理步都要过一次前向，时间步 = token 步，长 rollout 的成本随上下文长度二次增长；② 连续量被量化，分辨率损失如论证一；③ 没有校准的不确定性，规划无法做风险取舍（第 4 章第 3 节）；④ 天然对"动作幅度"不敏感（第 1 章第 1 节误用 1）
让世界模型承担语言任务 "一个模型全包" ① 语言任务没有对应的动作空间，"干预"无从定义；② 组合泛化是它的开放问题（第 7 章第 2 节表 B：联合表模型在没见过的组合上只有 0.07 的准确率）；③ 符号输出没有可读的中间产物，人无法审计
用 LLM 的输出直接当低层动作 "少一层接口" 高层规划的输出是符号/文本，缺少容差、时间标度与约束；低层执行需要的是带量纲的连续量。这层转换必须显式建模，否则错误会在接口处被放大（§3.3）

2.3 正确的问法#

替代关系的问法是"哪一个模型更通用"；正确的问法是：

给定任务，决策链的哪一段需要什么级别的精度，而那一段由谁提供最便宜？

这个问题有可判定的答案，因为它只依赖任务的三个客观属性：动作空间的形状、目标的可表达性、以及反事实查询的次数。§四把它写成 C1–C5。

三、分工的接口：高层规划层 / 低层预测层#

3.1 三层结构#

一个现实的分工不是"两层"，而是三层：

① 任务层（语言/符号）      "把杯子拿给用户，别碰倒水壶"        —— 目标、约束、常识
        │  子目标 + 约束 + 时间预算
② 符号规划层（LLM）        把任务分解成有序的子目标/路点/宏动作   —— 组合、检索、失败重规划
        │  子目标（带容差）、动作空间声明、代价版本号
③ 动力学层（世界模型）     在给定子目标与代价下做反事实排序       —— 连续量、可行性、代价估计
        │  可行性、代价、风险、违反的约束
        └── 反馈回 ②（不可行/代价过高 → 重规划）

为什么中间要有一层：任务层的语言是"拿杯子"，动力学层的语言是"关节力矩 0.42"，二者的接口必须由某一方做转换。把转换放在 LLM 里（生成子目标与容差）比放在动力学模型里（把力矩反解成语言）容易得多，因为符号层的组合能力是 LLM 的强项，而连续量的精度是动力学模型的强项——这正是能力表按行取用的具体形态。

3.2 三种具体接法#

接法 A：LLM 提议 + 世界模型打分（proposal & verify）。 LLM 生成 K 个候选（方案、路点序列、宏动作），世界模型给每个候选估计代价/风险，选择器取最优。

  • 接口：LLM 输出候选列表；世界模型输出 (J^k​, σ^k​, 违反约束k​)。
  • 强项匹配：LLM 负责"想得出"，世界模型负责"排得准"。
  • 失效模式：候选集不含正确解（LLM 的提议分布是瓶颈）——此时再准的打分器也救不回来。可观测症状：所有候选的模型代价都很高，而最优候选的真实代价显著低于模型估计。

接法 B：LLM 出子目标/路点 + 世界模型执行 MPC。 LLM 给出路点序列与容差，低层在每个控制周期用世界模型做短视界规划。

  • 接口：路点（带容差与时间窗口）+ 代价版本；低层返回实际到达情况。
  • 强项匹配：长程符号导航给 LLM，连续控制给动力学模型。
  • 失效模式：容差给错。给太松，世界模型会在一个错误的区域内找到"最优"；给太紧，不可行。本课代码实测了这条：高层的宏观动作如果只允许低层在 ±0.25 的小窗口内微调，规划后悔 0.0069；把窗口放宽到 ±0.50，后悔降到 0.0031 并低于单层连续模型（0.0039），同时低层搜索步数只用 54%。

接法 C：LLM 出代价/约束（写代码或结构化配置）+ 世界模型内规划。 把"什么叫好"变成可执行的代价函数，规划器在这个代价下搜索。

  • 接口：代价函数版本号 + 约束列表；这是最容易出错也最容易审计的一种，因为代价函数是文本/代码，人可以读。
  • 强项匹配：LLM 把任务语义翻译成数学目标，世界模型做搜索。
  • 失效模式：目标错位。代价函数漏掉了一个约束（例如"别碰倒水壶"），世界模型会忠实地把水壶撞倒并拿到很高的回报。第 3 节表 D 给出了这条的量化：规划用的奖励与真实奖励越错位，世界模型的真实收益越差（m=0.25 时真值掉 0.287），而无模型方法因为直接优化真实回报几乎不受影响。

三种接法的共同结构是：LLM 负责把"要什么"变清楚，世界模型负责把"怎么做"算清楚。 任何试图让一方兼任另一方的设计，都会在能力表的某一行上撞墙。

3.3 接口契约的四个必填字段#

接口不规范是"两个方向组合"最常见的失败来源。下面四个字段缺一个，系统就会在某个 corner case 上悄悄退化：

字段 为什么必须显式 缺失时的症状
状态的来源与版本 状态由谁定义（原始观测？编码器输出？显式物理量？），以及编码器版本 高层按旧编码器规划，低层按新编码器执行；两个"状态"不同构，接口静默失效
动作空间的所有者 动作是连续的还是离散的？范围、单位、频率由谁定？ LLM 生成的动作超出低层可执行范围；低层偷偷裁剪，规划目标被改写
时间步对齐 语义步与物理步的换算，以及两层的更新频率 "预测 10 步"与"未来 10 秒"混用；误差累积的尺度算错
失败回退的归属 由谁检测不可行、由谁负责重规划、重规划的触发阈值 低层知道"做不到"却不说，高层一直按不可能的假设往下规划

一个可用的最小 schema（示例，字段名可换，语义必须齐全）：

LLM → WM:  {subgoal: {region, tolerance}, constraints: [...], horizon_s,
            cost_version, confidence_required}
WM → LLM:  {feasible, best_cost, top_k: [{macro, cost, p_success}],
            violations: [...], model_confidence: {calibrated, ece}}

为什么"confidence_required"要放在请求里：世界模型的不确定性建模（第 2 章第 3 节）只有在被请求时才会被用于决策。如果高层从不问"这个估计有多不确定"，模型就会退化成一个点预测器，而点预测器在规划里是危险的（第 4 章第 3 节）。

3.4 两个常见的架构错误#

错误一：让 LLM 输出低层动作。 症状是"系统能跑，但动作抖动、精度差、对连续量不敏感"，而且无论如何调提示词都不改善。根因是把连续控制塞进了离散通道——正好踩在论证一上。

错误二：让世界模型回答常识问题。 症状是"模型能预测下一帧，但被问'这个杯子能不能放进那个抽屉'时给出无意义的答案"。根因是这个问题需要的是语义先验（抽屉与杯子的类别关系），而不是动力学外推。这类问题应该由 LLM 或检索回答，世界模型可以回答的是"给我这个动作序列，会不会撞上"。

四、可判定的分工判据（本节核心交付）#

4.1 五条判据#

不要问"该用哪个"，问这五个量：

# 判据 怎么测 判据方向 该谁做
C1 动作空间的分辨率需求 ra​ = 决策所需的最小可区分动作间隔 在真环境里扫动作，找出"代价差超过决策阈值"的最小间隔 ra​ 小于任务容差 → 必须连续通道；ra​ 与粗档位同量级 → 符号层足够 连续 → 世界模型；离散 → LLM 即可
C2 目标的可符号化程度 rg​ = 目标/约束能被文本或代码无损表达的比例 让一个人（或 LLM）只看文本描述去执行，测与真实目标的偏差 rg​≈1 → 高层可交给 LLM；rg​ 低（涉及连续权衡、隐性偏好）→ 必须给代价函数/示教 符号化好的 → LLM
C3 反事实查询次数 Ncf​ = 每次决策需要比较的候选动作数 数规划器的候选集大小 Ncf​ 大 → 需要一次前向给出整个动作空间的排序（世界模型）；Ncf​=1（无比较）→ 模型无用武之地 大 → 世界模型
C4 决策链长度与可逆性 有效视界 1/(1−γ) 或回合步数；以及"做错能否撤销" 链短且可逆 → 直接策略/LLM 直出；链长或不可逆 → 需要模型内推演（但见第 3 节：链太长又会被模型误差反噬） 中间区间 → 世界模型
C5 数据的可得性与成本 能负担的真实交互次数；是否有干预数据 交互便宜且充足 → 无模型/直接策略；交互贵或不可交互 → 需要模型（但先看第 3 节的反面清单） 交互贵 → 世界模型（有前提）

这五条的共同结构：C1、C3 判"动力学层需不需要"，C2 判"符号层能不能承担"，C4、C5 判"模型这笔账划不划算"。前三条是能力判据，后两条是成本判据。能力判据说的是"能不能"，成本判据说的是"值不值"，两者必须分开问——把它们混在一起就是"世界模型到底有没有用"这类无法回答的问题。

4.2 判据的用法：三步流程#

① 先问 C2：目标能不能写清楚？
   ├─ 不能（隐性偏好、连续权衡）→ 先修目标（示教/奖励学习），别急着上模型
   └─ 能 → 进入 ②

② 再问 C1+C3：这一层需要多少分辨率、要做多少次反事实比较？
   ├─ 分辨率粗 + 几乎不比候选 → 交给 LLM/规则，不需要世界模型（走反面清单）
   └─ 分辨率细 或 候选很多 → 需要一个能接受连续动作、能一次排序的模型 → 世界模型

③ 最后问 C4+C5 算账：用模型的净收益 = 收益（规划/复用/安全）− 成本（数据、算力、维护、接口风险）
   ├─ 收益项说不出来（链极短 / 真环境很便宜 / 只有一个任务）→ 不用
   └─ 收益项能落到一个可测量上（长视界规划、多任务复用、不可交互环境）→ 用，并按第 6 章的协议评测

4.3 "两个都上"也会亏：接口成本清单#

分工不是免费的。把两层拼起来会引入下面这些新成本，它们是"两个都上"的负优化来源：

成本 机制 可观测症状
串行延迟 高层 + 低层两次前向（外加低层的规划循环） 决策频率掉到任务要求以下
接口误差放大 状态/动作/时间步定义不一致（§3.3） 系统在特定 corner case 上表现异常，且换个随机种子就复现不了
错误归因困难 最终失败可能是高层、低层或接口造成的 迭代时"改哪一层都像有用"
双重维护 两条链路各有一套超参与失效模式 一条链路静默退化，被另一条掩盖
过度自信的传话 低层给出点估计，高层当确定事实用 低层说"可行"，真环境里频繁失败

本课代码给出的一个具体教训：分层不是自动更好。高层用一个粗动作模型选宏观方向、低层只在小窗口内微调时，后悔 0.0069 差于单层连续模型（0.0039）；把低层窗口放宽后才反超（0.0031）。也就是说，分层的收益取决于接口（窗口/容差）给得对不对，而不是取决于"套了两层"。

五、取舍与边界#

选择 好处 代价 / 边界
只上 LLM 迭代快、接口简单、可读 连续控制精度不够；反事实排序要反复调用且不稳定
只上世界模型 精度、可规划、可批量想象 没有语义先验；换任务要重学；组合泛化弱
分层（LLM + 世界模型） 各取所长；高层可审计、低层可规划 引入上表五类成本；接口设计错误会吃掉全部收益
用 LLM 兼职动力学 少一个模型 分辨率损失（本课实测 7 倍后悔）+ 无校准 + 长 rollout 成本
用世界模型兼职语义 少一个模型 组合泛化与语义先验都不成立

三条必须写进设计文档的边界：

  1. "两个都上"不是默认答案。 只有当收益项能落到一个可测量上（C4/C5）时才值得引入第二层。§4.3 的五项成本是实打实的工程量。
  2. 分工的失败大多是接口失败，不是模型失败。 §3.3 的四个字段如果没写全，后面所有的模型改进都会被接口误差掩盖。诊断顺序应该是：先验证接口（状态同构、动作范围、时间对齐），再验证各层。
  3. LLM 的先验不可直接验证。 LLM 给出的子目标/约束看起来合理，但"合理"不等于"与真实目标一致"。C2 的低分恰恰说明这一点：目标的可符号化程度低时，任何符号层的输出都不可信，此时应该去修目标（示教、奖励学习、约束显式化），而不是换更大的模型。

代码#

下面的代码不调用任何 API、只用 Python 标准库。它在一个 2D 线性动力学环境上做三件事：

  • 表 A/B：把动作从连续通道换成 token 通道，测"不可分辨动作对占比"、"反事实分离度 ρˉ​cf​"（与第 1 章第 1 节 D2 同定义）与"规划后悔"随 token 数的变化；再对比两种回退（backoff）方式。
  • 表 C：分工——同一批模型放在粗粒度决策（5 个候选动作）与细粒度决策（15 个候选）上，看代价差；再看"高层粗动作 + 低层连续微调"的分层组合在不同窗口下是否真的更优，并统计它用的模型步数。
  • 表 D：token 的样本分布，说明细 token 的稀疏性来自哪里。

⚠️ 环境与数据全部为本代码合成，不代表任何真实数据集。

"""WM ch7-l1 演示：动作 token 化的分辨率代价，以及"高层符号层 + 低层预测层"的分工
环境与数据全部为合成数据（不代表任何真实数据集），只用 Python 标准库。
运行：/opt/homebrew/bin/python3.10 _scratch_l1.py   环境：python 3.10.16
"""
import math
import random

# ---------- 1. 环境：2D 线性动力学，动作是连续力（外生、与观测分离的通道） ----------
A0 = ((0.99, 0.10), (-0.05, 0.97))
B0 = (0.0, 0.20)

def step(s, a):
    return (A0[0][0] * s[0] + A0[0][1] * s[1] + B0[0] * a,
            A0[1][0] * s[0] + A0[1][1] * s[1] + B0[1] * a)

def true_cost(s, a):
    """一步代价：把位置拉到 0 + 速度惩罚 + 控制代价（决策目标）"""
    s2 = step(s, a)
    return s2[0] ** 2 + 0.1 * s2[1] ** 2 + 0.02 * a * a

def seq_cost(s, seq):
    c = 0.0
    for a in seq:
        c += true_cost(s, a)
        s = step(s, a)
    return c

# ---------- 2. 小工具：高斯消元解线性方程组（标准库，不依赖 numpy） ----------
def solve(M, b):
    n = len(M)
    M = [list(row) + [b[i]] for i, row in enumerate(M)]
    for col in range(n):
        p = max(range(col, n), key=lambda r: abs(M[r][col]))
        if abs(M[p][col]) < 1e-12:
            continue
        M[col], M[p] = M[p], M[col]
        pv = M[col][col]
        for j in range(col, n + 1):
            M[col][j] /= pv
        for r in range(n):
            if r != col and M[r][col] != 0.0:
                f = M[r][col]
                for j in range(col, n + 1):
                    M[r][j] -= f * M[col][j]
    return [M[i][n] for i in range(n)]

def lstsq(X, Y, lam=1e-8):
    """X: 特征行列表；Y: 输出元组列表 -> 每个输出一组系数。"""
    d, m = len(X[0]), len(Y[0])
    XtX = [[sum(X[k][i] * X[k][j] for k in range(len(X))) + (lam if i == j else 0.0)
            for j in range(d)] for i in range(d)]
    XtY = [[sum(X[k][i] * Y[k][o] for k in range(len(X))) for o in range(m)]
           for i in range(d)]
    return [solve(XtX, [XtY[i][o] for i in range(d)]) for o in range(m)]

def dot(w, x):
    return sum(wi * xi for wi, xi in zip(w, x))

# ---------- 3. 数据：连续状态 + 连续动作的转移样本（行为策略是均匀随机动作） ----------
def gen_data(n, rng):
    D, s = [], (rng.uniform(-1.2, 1.2), rng.uniform(-1.2, 1.2))
    for _ in range(n):
        a = rng.uniform(-1.0, 1.0)
        s2 = step(s, a)
        D.append((s, a, s2))
        s = s2 if (abs(s2[0]) < 3.0 and abs(s2[1]) < 3.0) else \
            (rng.uniform(-1.2, 1.2), rng.uniform(-1.2, 1.2))
    return D

# ---------- 4. 两个候选：区别只在"动作进模型的形式" ----------
class Continuous:
    """连续动力学：特征是 [1, s0, s1, a] —— 动作作为连续的外生通道进入。"""
    n_bins = 0
    def fit(self, D):
        X = [[1.0, s[0], s[1], a] for s, a, _ in D]
        self.W = lstsq(X, [s2 for _, _, s2 in D])
    def pred(self, s, a):
        x = [1.0, s[0], s[1], a]
        return (dot(self.W[0], x), dot(self.W[1], x))
    def cost(self, s, seq):
        c = 0.0
        for a in seq:
            s2 = self.pred(s, a)
            c += s2[0] ** 2 + 0.1 * s2[1] ** 2 + 0.02 * a * a
            s = s2
        return c

class Token:
    """动作 token 化：动作被切成 n_bins 个 token；每个 token 有自己的局部模型。
    数据不足的 token 回退（backoff）到全局模型或"原地不动"。"""
    def __init__(self, n_bins, backoff="global", min_count=8):
        self.n_bins, self.backoff, self.min_count = n_bins, backoff, min_count
    def bin_of(self, a):
        return min(self.n_bins - 1, max(0, int((a + 1.0) / 2.0 * self.n_bins)))
    def center(self, b):
        return -1.0 + 2.0 * (b + 0.5) / self.n_bins
    def fit(self, D):
        glob = Continuous(); glob.fit(D); self.glob = glob
        buckets = [[] for _ in range(self.n_bins)]
        for s, a, s2 in D:
            buckets[self.bin_of(a)].append((s, a, s2))
        self.local = []
        for B in buckets:
            if len(B) >= self.min_count:
                X = [[1.0, s[0], s[1]] for s, a, _ in B]
                self.local.append(lstsq(X, [s2 for _, _, s2 in B]))
            else:
                self.local.append(None)
        self.counts = [len(B) for B in buckets]
    def pred(self, s, a):
        b = self.bin_of(a)
        W = self.local[b]
        if W is None:
            if self.backoff == "hold":
                return (s[0], s[1])
            return self.glob.pred(s, self.center(b))
        x = [1.0, s[0], s[1]]
        return (dot(W[0], x), dot(W[1], x))
    def cost(self, s, seq):
        c = 0.0
        for a in seq:
            s2 = self.pred(s, a)
            c += s2[0] ** 2 + 0.1 * s2[1] ** 2 + 0.02 * a * a
            s = s2
        return c

# ---------- 5. 度量：不可分辨对占比、反事实分离度 ρ_cf、规划后悔 ----------
def indist_frac(model, rng, n_state=200, n_pair=40):
    if model.n_bins == 0:
        return 0.0
    same = tot = 0
    for _ in range(n_state):
        for _ in range(n_pair):
            a1, a2 = rng.uniform(-1, 1), rng.uniform(-1, 1)
            same += (model.bin_of(a1) == model.bin_of(a2))
            tot += 1
    return same / tot

def rho_cf(model, rng, n_state=60, n_pair=25):
    """反事实分离度：同一状态、两个动作，模型预测差 / 真实差（与第 1 章第 1 节 D2 同定义）。"""
    rs = []
    for _ in range(n_state):
        s = (rng.uniform(-1.2, 1.2), rng.uniform(-1.2, 1.2))
        for _ in range(n_pair):
            a1, a2 = rng.uniform(-1, 1), rng.uniform(-1, 1)
            p1, p2 = model.pred(s, a1), model.pred(s, a2)
            t1, t2 = step(s, a1), step(s, a2)
            num = math.hypot(p1[0] - p2[0], p1[1] - p2[1])
            den = math.hypot(t1[0] - t2[0], t1[1] - t2[1])
            if den > 1e-9:
                rs.append(num / den)
    return sum(rs) / len(rs)

def candidates(m, lo=-1.0, hi=1.0):
    return [lo + (hi - lo) * k / (m - 1) for k in range(m)]

def plan_shoot(model, s, cand, K, H, rng):
    """随机射击规划：返回（选中的动作序列, 模型步数）。"""
    best, best_seq = None, None
    for _ in range(K):
        seq = [rng.choice(cand) for _ in range(H)]
        c = model.cost(s, seq)
        if best is None or c < best:
            best, best_seq = c, seq
    return best_seq, K * H

def oracle(s, cand, H):
    best, best_seq = None, None
    seq = [0.0] * H
    def rec(i):
        nonlocal best, best_seq
        if i == H:
            c = seq_cost(s, seq)
            if best is None or c < best:
                best, best_seq = c, list(seq)
            return
        for a in cand:
            seq[i] = a
            rec(i + 1)
    rec(0)
    return best, best_seq

def test_states(n, seed=7):
    rs = random.Random(seed)
    return [(rs.uniform(-1.2, 1.2), rs.uniform(-1.2, 1.2)) for _ in range(n)]

def regret(model, cand, K, H, seeds=(0, 1, 2), n_state=40):
    """规划后悔：模型选出的动作序列在真环境里的代价 - 同一候选集上的 oracle 代价。"""
    states = test_states(n_state)
    oracles = [oracle(s, cand, H)[0] for s in states]
    tot, steps = 0.0, 0
    for sd in seeds:
        rng = random.Random(sd)
        for s, oc in zip(states, oracles):
            seq, ns = plan_shoot(model, s, cand, K, H, rng)
            tot += seq_cost(s, seq) - oc
            steps += ns
    return tot / (len(seeds) * len(states)), steps // len(seeds)

# ---------- 6. 主表：token 粒度 vs 分辨率 vs 规划后悔 ----------
def run_table(N, bins_list, K=120, H=3, m=15, seed=0):
    rng = random.Random(seed)
    D = gen_data(N, rng)
    cand = candidates(m)
    cont = Continuous(); cont.fit(D)
    rows = [("连续（无 token）", indist_frac(cont, rng), rho_cf(cont, rng)) +
            regret(cont, cand, K, H)]
    for nb in bins_list:
        tk = Token(nb); tk.fit(D)
        rows.append((f"token {nb} 个", indist_frac(tk, rng), rho_cf(tk, rng)) +
                    regret(tk, cand, K, H))
    for nb in (51, 201):
        tk = Token(nb, backoff="hold"); tk.fit(D)
        rows.append((f"token {nb}(保守回退)", indist_frac(tk, rng), rho_cf(tk, rng)) +
                    regret(tk, cand, K, H))
    return rows

# ---------- 7. 分工表：粗粒度 vs 细粒度 + 两种接口的分层组合 ----------
def plan_hier(tok_hi, cont_lo, s, macro_cand, H_hi, fine_cand_fn, K_lo, H_lo, rng):
    macro = min(macro_cand, key=lambda am: tok_hi.cost(s, [am] * H_hi))
    loc = fine_cand_fn(macro)
    seq, ns = plan_shoot(cont_lo, s, loc, K_lo, H_lo, rng)
    return seq, len(macro_cand) * H_hi + ns

def run_division(N=3000, K=120, H=3, seed=1):
    rng = random.Random(seed)
    cont = Continuous(); cont.fit(gen_data(N, rng))
    tk5 = Token(5); tk5.fit(gen_data(N, rng))
    tk51 = Token(51); tk51.fit(gen_data(N, rng))
    coarse, fine = candidates(5), candidates(15)
    out = {}
    for tag, cand in (("粗粒度(5 候选)", coarse), ("细粒度(15 候选)", fine)):
        out[tag] = {name: regret(m, cand, K, H)
                    for name, m in (("连续", cont), ("token5", tk5), ("token51", tk51))}
    states = test_states(40)
    oracles = [oracle(s, fine, H)[0] for s in states]
    for tag, win in (("分层·窄窗(±0.25)", 0.25), ("分层·宽窗(±0.50)", 0.50)):
        tot, steps = 0.0, 0
        for sd in (0, 1, 2):
            r2 = random.Random(sd)
            for s, oc in zip(states, oracles):
                f = lambda mac, w=win: candidates(9, max(-1.0, mac - w), min(1.0, mac + w))
                seq, ns = plan_hier(tk5, cont, s, coarse, H, f, 60, H, r2)
                tot += seq_cost(s, seq) - oc
                steps += ns
        out[tag] = {"regret": tot / (3 * len(states)), "steps": steps // 3}
    return out

# ---------- 8. 打印 ----------
print("[表 A] 动作 token 化的分辨率与统计代价（N=3000 条转移，H=3，15 个候选动作，3 个规划种子）")
print("   模型                | 不可分辨对占比 | 反事实分离度 rho_cf | 规划后悔 | 模型步数")
for tag, ind, rho, reg, st in run_table(3000, [3, 5, 11, 21, 51, 201]):
    print(f"   {tag:<18} | {ind:>14.3f} | {rho:>19.3f} | {reg:>8.4f} | {st:>8}")

print("\n[表 B] 数据量减到 N=400：细 token 大部分落到回退分支，回退方式决定成败")

for tag, ind, rho, reg, st in run_table(400, [3, 5, 11, 21, 51, 201], seed=3):
    print(f"   {tag:<18} | {ind:>14.3f} | {rho:>19.3f} | {reg:>8.4f} | {st:>8}")

print("\n[表 C] 分工：同样的模型放在粗粒度决策与细粒度决策上，代价不同（K=120，H=3）")
div = run_division()

    print(f"   {tag:<16} | 后悔 {div[tag]['regret']:.4f} | 平均模型步数 {div[tag]['steps']}")

这段代码想让你看到的五件事：

  1. 离散化接口的损失是可测的，而且不在预测精度上。 表 A：3 个 token 时 33.4% 的动作对不可分辨，ρˉ​cf​=0.856，规划后悔 0.0273；连续接口的后悔是 0.0039——7 倍差距。而两类模型的一步预测误差几乎不可分，因为损失全部在动作通道上。
  2. token 变密不会自动变好，回退（backoff）方式决定成败。 表 A 里 51 个 token 的后悔已经与连续模型相同（0.0039）；但在表 B（数据减到 N=400）里，同样 51 个 token 的"保守回退"版本后悔涨到 0.0700（18 倍），ρˉ​cf​ 甚至涨到 1.377（过度敏感）。稀疏 token 的正确处理是"共享统计强度"（回退到全局模型），而不是让每个 token 各自保守。
  3. 同样的模型，放在粗粒度决策上不吃亏，放在细粒度决策上吃亏。 表 C：5 个候选动作时，token5 模型与连续模型的后悔是 0.0016 vs 0.0014（差 14%）；15 个候选时变成 0.0140 vs 0.0039（差 3.6 倍）。这就是分工判据 C1 的实测形态：粗粒度决策可以交给符号层，细粒度必须交给连续通道。
  4. 分层组合的收益完全取决于接口。 表 C：高层（token5）选宏观方向、低层（连续模型）在 ±0.25 窗口内微调时，后悔 0.0069，比单层连续模型更差；窗口放宽到 ±0.50 后降到 0.0031，并且低层搜索只用 7800/14400=54% 的模型步数。同一套模型、同一个规划器，只改一个接口参数（窗口），结论就翻转。
  5. A @ B.T 之类的矩阵便利在此处不可用（本机 numpy/torch 的该操作有缺陷），所以全部线性代数用手写高斯消元完成——这同时说明：这一节的结论不依赖任何深度学习框架，它是关于接口形状的结论。

⚠️ 诚实说明这个实验的边界：环境是二维线性动力学，动作是一维连续力，状态完全可观测。因此这个实验只隔离了"动作通道的分辨率"这一件事，没有覆盖 LLM 真正独有的能力（语义先验、组合推理）。表 A 的 ρˉ​cf​=1.000 这一行也不是"世界模型更好"的证据——它只是说明当模型类恰好正确时，连续通道的信息没有损失。另外，规划后悔是在 40 个测试状态、3 个规划种子上平均的，量级在 10−3，比较时只看倍数而不要看绝对值。

小结#

  • 两个方向建模的对象不同：LLM 建模 p(xt​∣x<t​)（离散有限、无外生控制、时间步=语义步、目标规范化）；世界模型建模 p(st+1​∣st​,at​)（连续/高维、动作是分离的干预通道、时间步是物理量、度量即归纳偏置）。五条差异里只有"取值空间"是程度问题，其余四条是种类问题。
  • "谁替代谁"是错问题，三条论证都落到可观测失败：① 动作被 token 化后不可枚举、分辨率有损（本课实测：3 个 token 的规划后悔是连续接口的 7 倍）；② 反事实信息不在被动数据里（第 7 章第 2 节：留出准确率恒为 0.80，而真实值区间宽 1.8393）；③ 两种失败模式（语义无根据 vs 动力学历时变坏）不能互相修补，只能互相检测。
  • 正确的问法是"决策链的哪一段需要什么级别的精度，由谁提供最便宜"，它可判定，因为只依赖动作空间形状、目标可符号化程度与反事实查询次数。
  • 分工的形态是三层：任务层（语言）→ 符号规划层（LLM：分解、路点、容差、重规划）→ 动力学层（世界模型：连续量、可行性、代价、风险），并把结果反馈回上层。三种接法（提议+打分 / 路点+MPC / 代价函数+规划）各有明确的失效模式：候选集缺解、容差给错、目标错位。
  • 接口契约有四个必填字段：状态来源与版本、动作空间所有者、时间步对齐、失败回退归属。缺一个就会出现"模型都没错但系统错"的静默退化；分工的失败大多是接口失败，不是模型失败。
  • 五条可判定判据 C1–C5：动作分辨率需求、目标可符号化程度、反事实查询次数、决策链长度与可逆性、数据可得性与成本。前三判"能不能"（能力），后两判"值不值"（成本），必须分开问。
  • 分层不是自动更好：本课实测，高层粗模型 + 低层窄窗（±0.25）的后悔 0.0069 差于单层连续模型 0.0039；窗口放宽到 ±0.50 后降到 0.0031，且低层搜索步数只用 54%。收益来自接口参数，不来自层数。
  • "两个都上"的代价：串行延迟、接口误差放大、错误归因困难、双重维护、过度自信的传话。只有当收益项能落到一个可测量（长视界规划 / 多任务复用 / 不可交互环境）时才值得引入第二层。
