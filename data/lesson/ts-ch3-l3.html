评估（时间序列交叉验证）#

你花两天调出的预测模型，上线后效果暴跌，最常见的原因之一就是评估方式错了：用了随机切分或随机 K-fold，让模型"偷看未来"，指标虚高。这一课讲为什么时间序列不能随机切分、该用什么指标、以及正确的时间序列交叉验证长什么样。

一、概念讲解#

1. 为什么不能随机切分：三条硬理由#

机器学习的标准套路是 train_test_split + K-fold，但在时间序列里这是错的，原因有三：

理由一：未来信息泄漏。 随机切分会把 2024 年的样本放进训练集、把 2023 年的放进测试集。模型于是"用未来预测过去"，测试集指标漂亮，线上却一塌糊涂。时间序列预测的本质约束是只能用过去预测未来，切分必须保证：训练集的全部时间点都早于测试集。

理由二：时序依赖被破坏。 时间序列的观测彼此相关（y_t 依赖 y_{t-1}）。随机切分把相邻观测拆开，训练集里到处都是"缺了邻居的洞"，模型既学不到真实的依赖结构，测试时又因为邻点信息"泄漏"过来而虚高。这种相关性意味着测试样本不再独立，经典 CV 的独立性假设根本不成立。

理由三：目标泄漏（label leakage）。 这比"时间泄漏"更隐蔽。哪怕你按时间切分了，如果特征/标准化在切分之前用了全量数据的统计量（全序列均值、全序列编码），未来信息仍会通过特征溜进训练。正确做法是：切分后再在训练段上计算所有统计量，或使用只能"向前看"的管道。

一句话：时间序列评估的黄金规则是"时间有序"——训练在前、测试在后，且特征构造只用训练段及其之前的信息。

2. 评估指标：别只会用 RMSE#

  • MAE / RMSE：最常用，量纲与数据一致。RMSE 对大误差更敏感（平方放大），MAE 更稳健；
  • MAPE：百分比误差 mean(|(y−ŷ)/y|)，直观但有两个坑——y 接近 0 时爆炸，且对"预测偏低"不对称惩罚；
  • sMAPE：对称版百分比误差，缓解 MAPE 的不对称，但在 y 与 ŷ 都接近 0 时仍不稳；
  • MASE：平均绝对比例误差，把模型的 MAE 除以"朴素预测（naive）"的 MAE。MASE = 1 表示和"直接用上期值预测"打平；MASE < 1 才说明模型有真实价值。它无量纲、对 0 值稳健，且天然可跨序列比较。

实务建议：报 RMSE/MAE 为主、MASE 为辅。MASE 的分母用训练集上的朴素误差计算，这样能避免测试集太短导致分母为 0 的问题。

3. 时间序列交叉验证：三种滑动窗口#

正确的 CV 放弃"随机打乱"，改用沿时间向前滑动的窗口：

① 扩展窗口（expanding window）：训练集从序列开头开始，逐次向后扩一个测试点，像滚雪球一样越来越大。适合样本少、想充分利用全部历史的场景。

② 滑动窗口（sliding/rolling window）：训练集保持固定长度，随测试点一起向前滚动，丢弃过老的样本。适合序列机制会随时间漂移、旧数据已"过时"的场景。

③ TimeSeriesSplit：scikit-learn 提供的实现，本质是扩展窗口，第 i 折的训练集 = 前 i+1 段、测试集 = 紧接着的下一个 block。

无论哪种，都有两条铁律：测试段永远在训练段之后；不同折的测试段互不重叠。对每一折算指标后取平均，就得到对模型泛化能力更诚实的估计。

4. 一定要有基准模型#

评估模型之前，先建立基线，否则你连"有没有进步"都不知道。三个经典基线：

  • 朴素法（naive）：ŷ_{t+h} = y_t，直接拿最后一期当预测；
  • 季节朴素法（seasonal naive）：ŷ_{t+h} = y_{t−m+h}，用上一个季节周期同一位点；
  • 漂移法（drift）：ŷ_{t+h} = y_t + h·(y_t − y_1)/(t−1)，把首尾连线外推。

如果精心调出的模型连季节朴素都打不过，那它就只是"昂贵的自我安慰"。

二、可运行示例#

用 TimeSeriesSplit 和手动扩展窗口做评估，并用 MASE 对照朴素基线。

import numpy as np
import pandas as pd
from sklearn.model_selection import TimeSeriesSplit
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error

# 1) 构造序列
idx = pd.date_range("2022-01-01", periods=180, freq="D")
rng = np.random.default_rng(1)
t = np.arange(180)
y = 20 + 0.2 * t + 8 * np.sin(2 * np.pi * t / 7) + rng.normal(0, 3, size=180)
series = pd.Series(y, index=idx)

# 2) 特征工程（只用过去信息）
def make_features(s):
    df = pd.DataFrame({"y": s})
    for lag in (1, 2, 7):
        df[f"lag_{lag}"] = s.shift(lag)
    df["roll_mean_7"] = s.shift(1).rolling(7).mean()
    df["target"] = s.shift(-1)
    return df.dropna()

data = make_features(series)
feats = [c for c in data.columns if c not in ("y", "target")]

# 3) TimeSeriesSplit：训练段始终在测试段之前
tscv = TimeSeriesSplit(n_splits=4)
maes = []
for train_idx, test_idx in tscv.split(data):
    X_tr, X_te = data.iloc[train_idx][feats], data.iloc[test_idx][feats]
    y_tr, y_te = data.iloc[train_idx]["target"], data.iloc[test_idx]["target"]
    model = HistGradientBoostingRegressor(random_state=0)
    model.fit(X_tr, y_tr)
    mae = mean_absolute_error(y_te, model.predict(X_te))
    maes.append(mae)
    print(f"训练 {len(train_idx):3d} 期 -> 测试 {len(test_idx):2d} 期，MAE = {mae:.3f}")
print("平均 MAE =", round(float(np.mean(maes)), 3))

# 4) MASE：与朴素基线对比（分母 = 训练段朴素误差）
naive_err = series.diff().abs().dropna()  # 朴素法的一步误差 = |y_t - y_{t-1}|
naive_mae = float(naive_err.mean())
print("朴素基线 MAE =", round(naive_mae, 3))
print("MASE =", round(float(np.mean(maes)) / naive_mae, 3),
      "（<1 表示优于朴素基线）")

关键点：每一折的测试段都严格在训练段之后，且模型从未"看"到过测试段及其未来。MASE < 1 才能说明模型比"照着昨天抄"更有价值。

三、练习#

  1. 把 TimeSeriesSplit 换成随机 KFold（shuffle=True），比较平均 MAE，观察它是否虚高，并解释为什么这个数字不可信。
  2. 实现一个滑动窗口 CV（固定训练窗口长度，如 90 期），和扩展窗口的结果对比，思考什么情况下滑动窗口更合适。
  3. 计算季节朴素法的 MAE（用滞后 7 期作预测），与上面的梯度提升模型对比，看谁更强。
  4. 思考：为什么 MASE 的分母建议用训练段的朴素误差，而不是测试段的？这能避免什么问题？
