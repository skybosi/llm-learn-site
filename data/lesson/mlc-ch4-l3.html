内存规划与复用：生命周期分析与显存峰值#

上一课把转置的代价从"必须搬"降到了"零拷贝"。但视图仍占着那块内存，直到最后一个消费者读完。一个 512 token 的 Transformer 层，每个中间张量各占一块、永不释放时本课实测要 225 KiB；按生命周期复用同一块池子只要 177 KiB，省 21.3%。内存规划（memory planning）回答的就是"哪块内存什么时候能给谁用"。

一、概念讲解#

1. 峰值不是"所有张量之和"，而是"同时在世的最大值"#

朴素做法给每个张量各开一块，峰值 = Σ(参数) + Σ(中间张量)。但只要两个张量的生命周期不重叠，就可以共用同一块内存。TVM 论文（OSDI'18）把这项技术列为图级优化的第三件事：静态内存规划（static memory planning）——执行前一次性算好每块缓冲的偏移，运行时零分配。

关键量是两个数：

  • 单时刻并发下界：maxt​∑n 活到 t​size(n)。任何 allocator 都躲不过它，因为那一刻这些张量必须同时存在。
  • allocator 高水位：实际分配器给出的峰值。它 ≥ 下界，差值来自"空洞拼不成"与"贪心不做最优打包"。

2. 生命周期是"近似"，不是精确事实#

生产级编译器用最后一次使用（last use）作为死亡时刻：张量活到"最后一次被读"那一轮。它便宜（一次反向扫描）且总是保守——真实寿命只会更短，所以静态数字常高于实测峰值。图里若有控制流（if、循环），"最后一次使用"要按支配关系与循环边界处理，简单线性扫描会错；也有编译器改用更紧的活跃区间分析换更小的池子，代价是编译时间。

3. 贪心首次适配：贴住下界的常用做法#

算法很短：按执行序申请；维护"已被占用的区间 + 释放时刻"；分配时把释放时刻 ≤ 当前时刻的区间合并成空洞，找第一个够大的洞；找不到就把水位往后展。实测（512 token 层，中间张量共 96.0 KiB）：

方案 中间池峰值 总峰值
朴素（不释放） 96.0 KiB 225.0 KiB
贪心复用 48.0 KiB 177.0 KiB

48.0 KiB 正好等于"单时刻并发的最大值"——贪心这一例贴住了下界。生命周期链是"一个接一个、尺寸相近"时，首次适配的合并几乎总能命中下界。

4. 想再降只能改图：原地写回#

池子已经贴住下界，最后的空间在图本身：如果某个算子读它的输入是最后一次读，且输出与输入元素数相同，就可以原地写回（in-place）——不再要新的块。实测允许原地写回后，中间池从 48.0 KiB 再降到 42.0 KiB，总峰值 171.0 KiB。代价是别名，要求三条同时成立：

  1. 被覆盖的输入在此之后不再被任何节点读（实测自检通过）；
  2. 算子数值上允许按元素覆盖（x = relu(x) 可以，x = x + shift(x) 不行）；
  3. 框架/用户接受"原地"语义（PyTorch 里对应 relu_()、add_() 这类带下划线的算子）。

再想降就只能算子融合：把 gelu 融进上一个 linear，中间那个 24 KiB 张量根本不落地——第 5 章的主题。

5. 训练与推理的内存账不同#

推理（本课） 训练
关键张量 激活（前向即死） 激活 + 反向需要的中间量
生命周期 出生到最后一读，短 常延长到最后一次反向更新
典型手段 复用 + 原地写回 复用 + 重算（activation checkpointing，用时间换空间）
峰值出现在 单次前向的某一层 反向的中段

所以"推理引擎的显存规划器"与"训练框架的显存优化"是两套账，不要拿前向峰值预测训练。

6. 常见坑#

  • 把"下界"当"可达"：下界只是不能再低，能否达到取决于生命周期形状与分配次序。
  • 原地写回忘了别名：视图（第 2 课）与原地写回叠加时，一个缓冲可能被两个名字引用，释放时机算错就是读到脏数据。
  • 忽略对齐：为向量化，块常按 16/32/64 字节对齐；小张量多时对齐浪费会显著抬高真实占用。
  • 忘记输出：模型输出与跨图传递的张量不能复用，否则回传数据被覆盖。

二、可运行代码示例#

下面这段纯 Python（无第三方依赖）在一个 10 节点的 Transformer 层上做四件事：算生命周期、算并发下界、跑贪心分配器（含原地写回模式）、最后自检别名冲突。

# ---- 第 3 课示例：生命周期分析 + 贪心内存复用（纯 Python，无第三方依赖）----
# 节点 = (输出名, [输入名], 输出元素数)；1 元素 = 4 字节（fp32）
# 真实系统把"参数池"和"生命周期池"分开：参数常驻，中间张量（activation）按需分配

OPS = [('h',    ['x'],            1536),
       ('q',    ['h', 'Wq'],      1536),
       ('k',    ['h', 'Wk'],      1536),
       ('v',    ['h', 'Wv'],      1536),
       ('attn', ['q', 'k'],       1536),
       ('p',    ['attn'],         1536),
       ('o',    ['p', 'v'],       1536),
       ('mid',  ['o', 'W1'],      6144),
       ('act',  ['mid'],          6144),
       ('out',  ['act', 'W2'],    1536)]
PARAMS = {'x': 1536, 'Wq': 2304, 'Wk': 2304, 'Wv': 2304, 'W1': 18432, 'W2': 6144}
KB = lambda n: n * 4 / 1024

def lifespans(ops):
    """一次反向扫描：中间张量活到"最后一次被读"那一轮（可验证的近似，不是精确寿命）。"""
    last = {}
    for t, (out, deps, size) in enumerate(ops, 1):
        for d in deps: last[d] = t
    return {out: (t, last.get(out, t)) for t, (out, deps, size) in enumerate(ops, 1)}

def free_intervals(active, high):
    """可用空洞 = [0, high) 减去所有"仍活着"的区间，再加上水位之后的尾巴。"""
    free, end = [], 0
    for a, b in sorted(active):
        if a > end: free.append((end, a - end))
        end = max(end, b)
    if end < high: free.append((end, high - end))
    return free

def place(order, sizes, spans, inp=False, ops=None):
    """按给定顺序分配；inp=True 时允许"输入最后一次被读"的算子原地写回输入块。"""
    last_read = {}
    for t, (out, deps, sz) in enumerate(ops or [], 1):
        for d in deps: last_read[d] = t
    taken, high, table, inplace = [], 0, {}, []
    sizes = dict(sizes)
    for name in order:
        cur, need = spans[name][0], sizes[name]
        if inp and ops:
            deps = next((d for o, d, _ in ops if o == name), [])
            for d in deps:
                if last_read.get(d) == cur and d in sizes and sizes[d] >= need:
                    table[name] = table[d]                 # 复用输入的块，不再新分配
                    inplace.append((name, d)); need = None; break
        if need is None: continue
        active = [(a, b) for a, b, rel in taken if rel >= cur]
        off = next((a for a, sz in free_intervals(active, high) if sz >= need), None)
        if off is None: off, high = high, high + need
        taken.append((off, off + need, spans[name][1]))
        table[name] = (off, need)
    return high, table, inplace

def concurrency_lb(sizes, spans, params_total=0):
    """单时刻并发下界：任何 allocator 在那一刻都至少要占这么多。"""
    tmax = max(r for _, r in spans.values())
    return max(sum(sizes[n] for n, (b, r) in spans.items() if b <= t <= r) + params_total
               for t in range(1, tmax + 1))

if __name__ == '__main__':
    sizes = {out: s for out, deps, s in OPS}
    spans = lifespans(OPS)
    params_total = sum(PARAMS.values())

    print('=== 0. 场景：512 token 的 Transformer 层（batch=1, d=768, ffn=3072, fp32）===')
    print(f'  参数 {len(PARAMS)} 个共 {params_total} 元素 = {KB(params_total):.1f} KiB（常驻）')
    print(f'  中间张量 {len(OPS)} 个共 {sum(sizes.values())} 元素 = {KB(sum(sizes.values())):.1f} KiB')
    print(f'  朴素做法（全都不释放）= {params_total + sum(sizes.values())} 元素 = '
          f'{KB(params_total + sum(sizes.values())):.1f} KiB')

    print('\n=== 1. 生命周期（中间张量：存活到"最后一次被读"那一轮）===')
    for name, (b, r) in spans.items():
        readers = [u for u, deps, _ in OPS if name in deps]
        print(f'  {name:<5} 存活 [{b:>2}, {r:>2}]  {sizes[name]:>5} 元素 = {KB(sizes[name]):5.1f} KiB'
              f'   读者 {readers}')
    lb = concurrency_lb(sizes, spans, params_total)
    print(f'\n  单时刻并发下界（allocator 躲不过的底线）= {lb} 元素 = {KB(lb):.1f} KiB')

    print('\n=== 2. 贪心复用（执行序 = 出生序）===')
    high1, tb1, _ = place(list(spans), sizes, spans)
    print(f'  {"张量":<6}{"元素":>6}{"起始":>7}{"结束":>7}   存活')
    for nm, (off, s) in tb1.items():
        print(f'  {nm:<6}{s:>6}{off:>7}{off + s:>7}   {spans[nm]}')
    print(f'  中间池高水位 {high1} 元素 = {KB(high1):.1f} KiB；'
          f'总峰值 = {KB(high1 + params_total):.1f} KiB（朴素 {KB(params_total + sum(sizes.values())):.1f} KiB，'
          f'省 {100 * (1 - (high1 + params_total) / (params_total + sum(sizes.values()))):.1f}%）')

    print('\n=== 3. 比"换序"更有效的一招：原地写回（in-place）===')
    high3, tb3, ip = place(list(spans), sizes, spans, inp=True, ops=OPS)
    print(f'  允许"输入最后一次被读"的算子原地写回：{ip}')
    print(f'  中间池高水位 {high1} → {high3} 元素（{KB(high1):.1f} → {KB(high3):.1f} KiB）；'
          f'总峰值 {KB(high3 + params_total):.1f} KiB')
    print(f'  这就是"单时刻并发下界"的价值：下界 {KB(lb - params_total):.1f} KiB（中间池部分），'
          f'贪心 {KB(high1):.1f} KiB 已经贴住它；')
    print('  想再降只能改图本身——融合掉中间张量（第 5 章），或让算子原地写（本课）——'
          '而不是指望 allocator 更聪明。')
    print('\n=== 4. 自检：复用不得制造别名冲突 ===')
    last_read = {}
    for t, (out, deps, sz) in enumerate(OPS, 1):
        for d in deps: last_read[d] = t
    for label, tb, ip in (('原序', tb1, []), ('原地写回', tb3, ip)):
        names, bad = list(tb), []
        for i, n1 in enumerate(names):
            for n2 in names[i + 1:]:
                t_ov = not (spans[n1][1] < spans[n2][0] or spans[n2][1] < spans[n1][0])
                (o1, s1), (o2, s2) = tb[n1], tb[n2]
                if t_ov and not (o1 + s1 <= o2 or o2 + s2 <= o1): bad.append((n1, n2))
        print(f'  {label:<6} 生命周期重叠且内存重叠的组合：'
              f'{"✅ 无" if not bad else "⚠ " + str(bad) + "（原地写回时这是允许的）"}')
        if ip:
            wrong = [(o, d) for o, d in ip if last_read.get(d) != next(b for n, (b, r) in spans.items() if n == o)]
            print(f'  {label} 原地写回的前置条件自检：'
                  f'{"✅ 每个被覆盖的输入都在这之后不再被读" if not wrong else "❌ " + str(wrong)}')
            print(f'  别名（输出与输入共用一块内存）：{ip}')

四处可核对的结论：并发下界是硬底线（中间池那一刻至少要 48.0 KiB，贪心给出的 12288 元素恰好等于它：mid 6144 + act 6144）；复用把峰值从 225.0 降到 177.0 KiB（省 21.3%）；原地写回再省 6.0 KiB（把 act 写进 mid 的块，out 写进 act 的块）；别名必须逐条验——自检确认每个被覆盖的输入此后不再被读，否则就是读到脏数据的经典 bug。

三、练习#

  1. 实现：把 place 的"首次适配"改成"最佳适配"（选够大的洞里最小的那个），在本课的图和第 3 节的小例上分别重跑，比较高水位。
  2. 解释：为什么 mid（24 KiB）与 act（24 KiB）能共用同一条 24576 元素的槽，而 h 与 q 不行？用第 1 节的存活区间直接回答。
  3. 对比/验证：把 OPS 里 act 的 gelu 换成 add(act, 1.0) 这类"需要同时读两个输入"的算子（例如 mul(mid, out)），重跑并观察原地写回列表与高水位怎么变；解释多输入算子为什么更难原地化。
