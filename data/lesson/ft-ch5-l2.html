SFT#

上一课我们把指令数据整理成了"对话 + 回答"的形式。这一课进入正题：SFT（Supervised Fine-Tuning，监督微调），也就是在成对的"指令—回答"数据上，用标准的监督学习目标去微调模型。SFT 是整个"对齐"管线（预训练 → SFT → RLHF/DPO）里的第一环，也是让一个"只会续写"的基座模型变成"会听话"的助手的关键一步。我们重点讲清它的损失函数到底怎么算，以及如何用 trl 的 SFTTrainer 把它压成几十行代码。

一、概念讲解#

1. SFT 在做什么#

预训练模型学的是"预测下一个 token"，它擅长续写，但不擅长"回答指令"。SFT 给模型看大量 <指令, 期望回答> 样本，让模型学会：给定一段以指令开头的序列，去最大化期望回答的对数似然。本质仍是自回归语言模型目标，只是数据从"网页文本"换成了"问答对"。

2. 核心细节：损失只在回答部分计算#

一条 SFT 样本 = [system?] + user 指令 + assistant 回答。如果对整段序列都算交叉熵损失，模型会同时去学"预测用户会问什么"，浪费容量、还可能学偏。正确做法是掩码：

  • prompt 部分（system + user）：labels 设为 -100，不贡献损失；
  • 回答部分（assistant）：labels 保留真实 token id，贡献损失。

这个"只对回答算 loss"的设计，是 SFT 与普通继续预训练最本质的区别，也是上一课练习里我们手动构造 labels 的原因。

3. 训练目标与超参直觉#

SFT 的损失是回答部分的平均交叉熵。由于 LoRA 只动一小撮参数、数据又相对同质，几个直觉很重要：

  • 学习率：比预训练高一些，LoRA 下常见 1e-4 ~ 5e-4；
  • 轮数：指令数据通常 1~3 个 epoch 就够，多了容易过拟合、遗忘通用能力；
  • 小批量 + 梯度累积：长序列吃显存，用梯度累积等效放大批量；
  • 梯度裁剪：防止长文本导致梯度爆炸。

4. SFT 在"对齐"管线中的位置#

SFT 之上还有 RLHF / DPO 等偏好对齐阶段：SFT 先让模型"会回答"，偏好对齐再让模型"答得让人喜欢"。近年也有 DPO（Direct Preference Optimization） 直接跳过显式奖励模型。但在学习路径上，先跑通 SFT、拿到一个"能用的助手"，再去碰偏好对齐，是最稳的路线。

5. SFTTrainer：trl 把流程封装好了#

手写 SFT 循环要处理分词、掩码、打包（packing）、数据整理等一堆琐事。Hugging Face 的 trl 库提供 SFTTrainer，把"格式化对话 → 掩码 → 训练"全自动完成，是社区做 SFT 的主流工具。下面我们就用它。

二、可运行代码示例#

下面用 trl 的 SFTTrainer 微调一个小模型，展示完整 SFT 流程。依赖 transformers、peft、trl、datasets。

from datasets import Dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig
from trl import SFTTrainer

model_id = "HuggingFaceH4/zephyr-7b-beta"  # 示例：可换成任意可用模型

# 1) 准备指令数据：OpenAI Chat 风格的 messages
raw_data = [
    {"messages": [
        {"role": "user", "content": "什么是过拟合？"},
        {"role": "assistant", "content": "过拟合指模型在训练集上表现很好，但在新数据上泛化很差。"}]},
    {"messages": [
        {"role": "user", "content": "怎么缓解过拟合？"},
        {"role": "assistant", "content": "可以增加数据、使用正则化、早停或 dropout。"}]},
]
dataset = Dataset.from_list(raw_data)

# 2) 分词器（带 chat_template），SFTTrainer 会自动用它渲染对话并掩码
tokenizer = AutoTokenizer.from_pretrained(model_id)
tokenizer.pad_token = tokenizer.eos_token

# 3) 可选：LoRA 配置，让 SFT 只训练低秩增量
peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

# 4) 训练参数
training_args = TrainingArguments(
    output_dir="./sft-output",
    per_device_train_batch_size=2,
    gradient_accumulation_steps=4,      # 等效 batch = 2 * 4 = 8
    learning_rate=2e-4,
    num_train_epochs=1,
    logging_steps=1,
    save_strategy="epoch",
    bf16=True,                          # 有 GPU 时用 bf16 省显存
    report_to="none",                   # 本地跑关闭 wandb 上报
)

# 5) SFTTrainer：把"格式化 + 掩码 + 训练"一步到位
trainer = SFTTrainer(
    model=model_id,
    train_dataset=dataset,
    tokenizer=tokenizer,
    peft_config=peft_config,
    args=training_args,
    max_seq_length=512,
)

# 6) 开训，并保存适配器
trainer.train()
trainer.save_model("./sft-output")
print("SFT 完成，适配器已保存到 ./sft-output")

运行后，SFTTrainer 会：用 chat_template 把每条 messages 渲染成文本 → 自动把 prompt 部分设为 -100 → 打包成 batch → 用 LoRA 只训练增量矩阵。训练完成后 ./sft-output 里就是可插拔的适配器权重。用一张 T4 就能跑通小型数据上的完整 SFT 流程。

提示：若要手工确认"损失只算回答"，可以用 DataCollatorForCompletionOnlyLM，传入回答的起止标记（如 response_template="<|assistant|>"），它会帮你生成掩码 labels，适合在自定义数据管线里使用。

三、练习#

  1. 把 num_train_epochs 分别设为 1、3、5，观察损失曲线和验证集表现，体会"指令数据训几轮就过拟合"的现象。
  2. 用 DataCollatorForCompletionOnlyLM 手动构造一批 labels，打印出来核对：prompt 位置是否为 -100、assistant 位置是否为真实 token id。
  3. 关闭 peft_config（即不做 LoRA，改为全量 SFT），对比训练耗时与显存占用，理解 LoRA 在 SFT 中的实际收益。
  4. 查 trl 文档，找出 SFTTrainer 中 packing=True 的作用，用一句话说明它如何提升长序列样本的训练效率。
