Excel 与 JSON#

一、概念讲解#

CSV 虽通用，但有两个明显短板：它只能存一张表，且存不了格式、公式和多工作表。当数据来自业务同事的 Excel 工作簿，或来自 Web 接口返回的 JSON 时，就需要另一套读写方法。

1. Excel：read_excel 与 to_excel#

  • pd.read_excel("文件.xlsx")：默认读取第一个工作表。常用参数：
    • sheet_name：读指定工作表，可以是名字、序号（0 起），传 None 则读取全部工作表，返回一个"工作表名 → DataFrame"的字典。
    • header / index_col：与 read_csv 同义，指定表头和索引列。
  • df.to_excel("文件.xlsx", index=False, sheet_name="成绩表")：把 DataFrame 写成一个工作表。写 .xlsx 需要依赖 openpyxl 引擎（engine="openpyxl"），未安装时可用 pip install openpyxl 补上。

Excel 适合与"人"打交道（发报表、收集数据），但不适合做大规模数据交换——文件大、读取慢，正式的数据管道里通常只在入口出口处用。

2. JSON：read_json 与 to_json#

JSON 是 Web 接口和数据交换的事实标准。它本身没有"行/列"概念，因此读入时orient（方向）参数至关重要，它告诉 Pandas 该怎么理解这段 JSON：

  • orient="records"：一个列表，每个元素是一行（一个字典），键为列名——最常见。
  • orient="columns"：一个字典，每个键是一列，值为该列数据。
  • orient="index"：一个字典，每个键是行索引。

to_json(orient=..., force_ascii=False) 反向写出；force_ascii=False 能保证中文不被转成 \uXXXX 转义。

二、可运行代码示例#

import pandas as pd

# ===== JSON 部分（可完整运行）=====

# 1. orient="records"：每个元素是一行
json_records = '[{"姓名":"张三","成绩":88},{"姓名":"李四","成绩":79}]'
df = pd.read_json(json_records, orient="records")
print("records 方向读入：\n", df)

# 2. orient="columns"：每个键是一列
json_columns = '{"姓名":["张三","李四"],"成绩":[88,79]}'
df2 = pd.read_json(json_columns, orient="columns")
print("\ncolumns 方向读入：\n", df2)

# 3. 写出 JSON，force_ascii=False 保证中文可读
df2["城市"] = ["北京", "上海"]
print("\nto_json(records)：", df2.to_json(orient="records", force_ascii=False))
print("to_json(columns)：", df2.to_json(orient="columns", force_ascii=False))

# ===== Excel 部分（需要 .xlsx 文件与 openpyxl）=====

JSON 部分可直接运行，注意对比 records 与 columns 两种方向读入的结果完全一致，只是 JSON 的"写法"不同——这正说明 orient 是在帮 Pandas 对齐"JSON 结构"和"表格结构"。

三、练习#

  1. 用 orient="records" 读入一段包含 姓名、年龄、城市 三列的 JSON 列表，再用 to_json(orient="columns", force_ascii=False) 写回，观察输出结构的变化。
  2. 用 to_excel 把一个 DataFrame 写成一个名为 "汇总" 的工作表（index=False），再用 read_excel(sheet_name="汇总") 读回来验证。
  3. 思考题：同样一份数据，为什么在"发给同事看"时选 Excel，而在"程序间交换"时更推荐 CSV 或 JSON？
