PCIe 带宽#

GPU 内部算得再快，数据进出也要走一条"公路"——PCIe（Peripheral Component Interconnect Express）。它连接 CPU 与 GPU，也常常是多卡之间兜底的通信通道。学完本课，你应当能说清 PCIe 各代带宽是多少、它和显存带宽差多少个数量级，以及什么场景下它会成为性能瓶颈。

一、概念讲解#

1. PCIe 是什么#

PCIe 是 CPU 与外设（GPU、网卡、NVMe 盘）之间的高速串行总线。带宽由两件事决定：代数（Gen）决定每条通道（lane）的速度，通道数（×1、×4、×8、×16）决定并了多少条通道。GPU 通常用 ×16。

2. 各代带宽#

PCIe 用 GT/s（每秒十亿次传输）标速率，实际数据要扣掉 128b/130b 的编码开销。每 lane 单向带宽大致是：

代数 每 lane 速率 每 lane 单向带宽 ×16 单向带宽
PCIe 3.0 8 GT/s ≈ 0.985 GB/s ≈ 15.75 GB/s
PCIe 4.0 16 GT/s ≈ 1.97 GB/s ≈ 31.5 GB/s
PCIe 5.0 32 GT/s ≈ 3.94 GB/s ≈ 63 GB/s

注意这是单向带宽；标注"双向"时通常再翻一倍。

3. 和显存带宽的巨大差距#

对比一下就明白了：H100 的 HBM3 显存带宽高达 约 3.35 TB/s，而最快的 PCIe 5.0 ×16 只有 约 63 GB/s——差了两个数量级。这意味着数据一旦要跨过 PCIe 这条窄路，速度立刻被拖慢 50 倍以上。这就是为什么推理引擎拼命让权重和数据留在显存里、避免反复通过 PCIe 搬运。

4. 什么场景会撞上 PCIe 瓶颈#

  • 权重/数据从主机搬上 GPU：首次加载模型、每次从 CPU 内存搬运输入输出；
  • 显存装不下时的"权重卸载（offload）"：把部分权重放 CPU 内存，用时经 PCIe 取，速度被 PCIe 卡死；
  • 无 NVLink 的多卡通信：两卡之间靠 CPU 中转或 PCIe 直连，带宽同样受限。

传输时间可以用一个简单公式估算：时间 = 数据量 ÷ 带宽。

二、可运行示例#

用纯 Python 算一算"过 PCIe 搬数据要多久"，再和显存带宽对比，直观感受数量级差距。

# -*- coding: utf-8 -*-
# 传输时间 = 数据量 ÷ 带宽

def transfer_time_seconds(data_bytes, bandwidth_bytes_per_sec):
    return data_bytes / bandwidth_bytes_per_sec

# 各代 PCIe x16 单向带宽（GB/s -> B/s）
PCIe_BW = {
    "PCIe 3.0 x16": 15.75e9,
    "PCIe 4.0 x16": 31.5e9,
    "PCIe 5.0 x16": 63.0e9,
}
HBM_BW = 3.35e12   # H100 HBM3 约 3.35 TB/s

# 场景一：把 7B 模型的 FP16 权重（约 14 GB）从 CPU 搬进 GPU
weight_bytes = 6.74e9 * 2   # 参数量 × 2 字节
print("搬运 7B FP16 权重（约 %.1f GB）所需时间：" % (weight_bytes / 1e9))
for name, bw in PCIe_BW.items():
    t = transfer_time_seconds(weight_bytes, bw)
    print(f"  {name:<16} {t*1000:>7.1f} 毫秒")

# 场景二：同一份数据，显存内部（HBM）读取要多久
t_hbm = transfer_time_seconds(weight_bytes, HBM_BW)
print(f"  显存 HBM（对照） {t_hbm*1e6:>7.1f} 微秒")
print(f"\n  PCIe 5.0 比 HBM 慢了约 {PCIe_BW['PCIe 5.0 x16']/HBM_BW:.0f} 倍 → 差 {HBM_BW/PCIe_BW['PCIe 5.0 x16']:.0f} 倍带宽")

# 场景三：权重卸载——如果每次前向都要经 PCIe 重读权重，吞吐会被卡成多少？
#   解码一个 token 要读一遍全部权重；吞吐 ≈ 带宽 ÷ 每 token 需搬运字节数
print("\n权重卸载时（经 PCIe 重读权重）的理论解码吞吐：")
for name, bw in PCIe_BW.items():
    tokens_per_sec = bw / weight_bytes   # 每 token 读 14 GB 权重
    print(f"  {name:<16} 约 {tokens_per_sec:>6.2f} token/s")

tokens_hbm = HBM_BW / weight_bytes
print(f"  显存 HBM（对照） 约 {tokens_hbm:>6.1f} token/s")

运行后你会看到：经 PCIe 5.0 搬 14 GB 权重约要 0.2 秒，而 HBM 内部读只需几十微秒；如果做权重卸载，每生成一个 token 都要重读一遍权重，吞吐会从显存内的上百 token/s 暴跌到每秒几个——这就是"别让数据频繁过 PCIe"的原因。

三、练习#

  1. 手算：PCIe 4.0 ×16 单向带宽约 31.5 GB/s，搬 100 GB 数据要几秒？
  2. 换车道：把通道数从 ×16 改成 ×8（带宽减半），重算 14 GB 权重的搬运时间，说明为什么 GPU 插槽要插满 ×16。
  3. 双向：PCIe 带宽"双向"通常约是单向的两倍。若全双工搬运，上面场景一的时间会变成多少？为什么实际往往达不到理论双向值？
  4. 卸载吞吐：把模型换成 70B（FP16 约 138 GB），重算权重卸载下的解码吞吐，对比 7B，体会"模型越大，PCIe 卸载越不可行"。
  5. 思考：为什么推理引擎要把 KV cache 和权重都常驻显存、而不是按需从 CPU 内存取？如果必须"省显存"而做卸载，你会优先卸载权重还是 KV cache？理由是什么？
