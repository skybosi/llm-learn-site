边界、开放问题与判断力：判据表、三角约束与仍未收敛的问题#

这一节要解决什么#

前两节把级联与端到端的两笔账算了：延迟可以解出交叉点，误差是乘法结构，数据与算力可以换成卡·天，语音 token 的码率有硬下限。但账算完了不等于会做选择。真实工程里决策者面对的是这样一个问题：

我要做的这个语音系统，应该用级联还是端到端？

前两节的账给不出"应该"，只能给出"如果你在某几个量上取这些值，那么答案是 X"。这一节要把这个条件补全，交付三样东西：

  1. 一张判据表：五个可测量轴（正确率、延迟、成本、可控性、可归因）各自的可算判据；以及哪些任务端到端确实更好、哪些级联仍占优。
  2. 延迟-成本-可控性三角的可解形式：把三者都换成同一单位（元），最优点必在端点；真正的工程形态是按请求类型硬分流，分流点由临界的"单次泄漏合规损失"决定。
  3. 三个仍未收敛的开放问题：长音频、说话人一致性、评估标准——每个都给可算的结论，并明确标出哪一部分是已确证的机制、哪一部分是推测（C 级）。

本节的核心立场是一句判断力的表述：

 架构选择=先问「哪个轴在约束你」，再问「谁的下限更低」，最后才问「现在谁更好」 ​

顺序不能颠倒。反过来（从"现在谁更好"出发）会产生两类系统性错误：把在无约束轴上胜出的架构搬到有约束的场景，以及把"下限更低但当前更差"的架构当成"不行"而提前放弃。

⚠️ 本节所有具体数值都是构造值，用于展示判据的形状；凡涉及真实系统能力的地方一律标 C 级推测，并给出判定它所需的实验设计。本节不引用任何未核对的系统级指标。

二、延迟-成本-可控性三角：一个线性规划#

2.1 把三个量换成同一个单位#

"三角"这个说法常被当成修辞。它可以被写成严格的优化问题。设走端到端的请求比例为 q∈[0,1]：

c(q)ℓ(q)r(q)​=qce2e​+(1−q)ccasc​=qℓe2e​+(1−q)ℓcasc​=qre2e​+(1−q)rcasc​​​（成本，元/千次）（延迟，ms）（含 PII 请求的泄漏率）​

c(q)ℓ(q)r(q)​=qce2e​+(1−q)ccasc​=qℓe2e​+(1−q)ℓcasc​=qre2e​+(1−q)rcasc​​​（成本，元/千次）（延迟，ms）（含 PII 请求的泄漏率）​

总代价把三者折成钱：

J(q)=c(q)⋅V+r(q)⋅V⋅Lcomp​

V 是请求量、Lcomp​ 是单次泄漏的合规损失。J(q) 对 q 是线性的，所以

dqdJ​=(ce2e​−ccasc​)V+(re2e​−rcasc​)VLcomp​

线性函数的最优点必然落在端点。 端到端占优的条件因此是一个可以直接比较的式子：

 (ccasc​−ce2e​)>(re2e​−rcasc​)Lcomp​ ​

左边是端到端省下的钱，右边是它多付的合规风险。本节的构造值（ce2e​=0.90、ccasc​=1.20 元/千次；re2e​=6%、rcasc​=2%）给出临界值

Lcomp∗​=re2e​−rcasc​ccasc​−ce2e​​=0.040.30​=7.50 元/次

Lcomp∗​=re2e​−rcasc​ccasc​−ce2e​​=0.040.30​=7.50 元/次

表 3 里 Lcomp​=3.0 元/次 <7.50，所以 dJ/dq=−180<0、最优在 q=1（全端到端）。当单次泄漏的合规损失超过 7.50 元时，端点翻转。

2.2 为什么工程形态是"分流"而不是"调比例"#

上面的结论说"最优点在端点"，但表 4 展示了看起来矛盾的结果：按请求类型分流（70% 交互型走端到端、30% 合规型走级联）比两个端点都好。

这不矛盾。表 3 说的是"单一比例下最优在端点"；表 4 说的是"按类型分开取端点"才是真最优。把它写成公式：设请求有两类 i，各自有 (ci​,ri​)，则

{qi​}min​i∑​Vi​[ci​(qi​)+ri​(qi​)Lcomp​]⟹qi∗​∈{0,1} 逐类决定

{qi​}min​i∑​Vi​[ci​(qi​)+ri​(qi​)Lcomp​]⟹qi∗​∈{0,1} 逐类决定

所以工程上不该做"混合比例调参"，而应该做按请求类型硬分流，每类的分流点用上面那个 Lcomp∗​ 判据逐类算。这解释了实际系统的形态：端到端做快通道、级联做合规/长文通道。共存的代价是维护两套模型与两套数据管线——这个代价必须与上式算出的收益相比，不能凭直觉。

⚠️ C 级提醒：re2e​=6% 与 rcasc​=2% 是构造值。真实系统的泄漏率取决于训练数据、模型规模与攻击面，没有任何公开数字可以直接搬用。判定它的实验设计是：用同一批含 PII 的探针输入，分别测两个系统"是否会在输出里复述 PII"，样本量按第 5 节的公式算（检测 4 个百分点的绝对差异、p=0.06 vs 0.02，需要每系统约 600 次探针）。这项测量必须先做，否则三角里的第三边是空的。

三、开放问题一：长音频#

3.1 先撞墙的是 KV cache，不是注意力 FLOPs#

长音频（会议、通话、播客）是端到端语音模型最有价值也最难的目标。把两项开销算出来（d=4096、Llayer​=32、fp16、token 率 50/s）：

音频时长 token 数 T KV cache 注意力 FLOPs 单卡地板（20% 峰值）
1 分钟 3000 1.57 GB 4.719×1012 23.9 ms
5 分钟 15000 7.86 GB 1.180×1014 596.4 ms
30 分钟 90000 47.19 GB 4.247×1015 21469.8 ms
1 小时 180000 94.37 GB 1.699×1016 85879.3 ms
10 小时 1800000 943.72 GB 1.699×1018 8587932.9 ms

量级上有一个关键的不对称：注意力 FLOPs 是 O(T2)，但 1 小时的 1.699×1016 FLOPs 在 20% 峰值算力下只要 1.4 分钟；而 KV cache 是 O(T) 且必须常驻显存——1 小时音频的 94.37 GB 单请求就已经超过一张消费级卡。

 长音频的第一个约束是显存（O(T)），第二个才是算力（O(T2)） ​

3.2 分段：两个方向相反的约束#

既然整段放不下，就分段。但分段有信息损失。用"跨段需要的远端信息随距离衰减"的构造模型（D0​=120 s）：

段内可见度=1−e−s/D0​

段长 s 段数（1 h） 段内可见度 摘要读取次数
10 s 360 0.0800 359
30 s 120 0.2212 119
60 s 60 0.3935 59
300 s 12 0.9179 11
1800 s 2 1.0000 1

两个约束方向相反：段太长则 KV cache 撞显存，段太短则跨段信息丢失。最优段长由"跨段信息的时间尺度 D0​"与"显存上限"共同决定。本表的构造值下，60∼300 s 一段是折中区间。

3.3 开放问题所在：D0​ 本身不知道#

⚠️ 这是本节明确标注的开放问题：D0​（"跨段信息的时间尺度"）是构造值。真实语音里它取决于任务——会议纪要需要记住"谁在什么时候承诺了什么"（可能跨越几十分钟），而语音听写只需要记住局部音素上下文（几秒）。没有任何单一 D0​ 适用于所有长音频任务，这是当前没有共识的地方。

给一个可判定的实验设计：构造"远处关键信息"的探针集（在第 k 分钟埋入一个后续必须用到的实体，k 从 1 到 60 扫描），测"答案正确率 vs k"。这条曲线直接给出 D0​ 的估计，并可以直接判定"分段 + 摘要"的方案在哪个 k 之后失效。这个实验的样本量需求：要分辨"k=30 分钟时正确率从 0.9 掉到 0.8"，每个 k 需要约 200 个探针（用第 5 节的配对检验公式）——总共约 1.2 万个探针。这是一个可执行但昂贵的测量，目前的公开比较中很少见到。

四、开放问题二：说话人一致性#

4.1 把"听起来是不是同一个人"写成 sigma 上限#

分段合成/对话的场景里，每个段的说话人音色可能漂移。设说话人嵌入是 d 维单位向量、第 j 段的每个维度叠加独立的 σ 噪声，则第 j 段与参考的余弦相似度期望为

cosj​=1+jdσ4​1​

4.2 为什么级联在这里占优，而这不是终局#

级联系统把说话人一致性"外包"给一个独立的说话人编码器：每段都用同一个参考嵌入，段间一致性是构造保证的，不需要学。端到端必须自己学出跨段稳定性——这是它目前没有解决好的问题之一。

⚠️ C 级推测：端到端能否通过"在训练里加入跨段一致性正则"达到同等水平，目前没有公开的确定结论。判定它所需的最小实验：(a) 测同一模型在 k=1,10,100 段上的 cos 分布（不是均值——要看尾部）；(b) 用 ABX 或偏好检验判定"cos 降到多少时人耳能听出换人"（这是 4.1 里 τ=0.85 这个构造值的来源，必须实测）；(c) 报告正则项系数的完整扫描。没有 (b)，σ 的上限就没有意义——因为它把"机器学习指标"当成了"感知阈值"。

⚠️ 开放问题所在：目前缺少的不是"更好的指标"，而是多轴的联合报告规范。任何把五个轴压成一个分数的做法都必须先声明权重，而权重是业务决策、不是技术结论。这是本课最后一条判断力：不要用技术指标替业务做决定，但必须把每个轴的可算判据交出来。

def dw(s):
    return sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in str(s))

    return " " * l + s + " " * (n - l)

def cos_one(sigma, d=D_EMB):
    """单段嵌入与参考嵌入的 cos 期望（闭式）。"""
    return 1.0 / math.sqrt(1.0 + d * sigma ** 4)


def cos_after(k, sigma, d=D_EMB):
    """k 段之后与参考的 cos：每段独立扰动 -> 总噪声方差是单段的 k 倍。"""
    return 1.0 / math.sqrt(1.0 + k * d * sigma ** 4)

    c10 = cos_after(10, sigma)
    c100 = cos_after(100, sigma)
    flag = "是" if c100 < 0.85 else "否"
    print("  " + pad(f"{sigma:.2f}", 7, ">") + " | " + pad(f"{adj:.6f}", 10, ">") + " | "

小结#

  • 五个可测量轴：语义正确率（pe2e​>pcasc​ 且差 >CI）、延迟（L∗=(S+T1​−K)/(25g−35)）、单位成本（ce2e​/step<1.5cllm​）、可控性（泄漏率差 × 合规损失）、可归因（ASR 损失 =p2​−p1​）。前两个是技术性的、后三个是系统与合规性的——"端到端更好"只在前两个轴上成立。
  • 端到端真正赢的任务：副语言/韵律必须保留的（文本接口装不下，级联上限被结构性封死）、延迟敏感且回答短的（级联固定开销 900+150 ms 占比过高）、全双工对话（无分段接口）。级联真正赢的任务：可归因、可控性、低资源、长回答的成本（35.0 vs 62.5 ms/字）。
  • 延迟-成本-可控性三角是一个线性规划：J(q)=c(q)V+r(q)VLcomp​ 对 q 线性，最优点必在端点；翻转判据 ccasc​−ce2e​>(re2e​−rcasc​)Lcomp​，临界值 Lcomp∗​=0.30/0.04=7.50 元/次。所以工程上应做按请求类型硬分流而不是调比例。
  • 分流的收益可算：70% 交互 +30% 合规时，分流比全端到端延迟 +210 ms（+32.3%）、总代价 +54.00 元（+5.0%）；比全级联延迟 −490 ms（−36.3%）、总代价 −126.00 元（−10.0%）。最优方案随合规份额切换。
  • 长音频的第一个约束是显存：KV cache =T⋅d⋅2⋅bytes⋅Llayer​，1 分钟 1.57 GB、1 小时 94.37 GB、10 小时 943.72 GB；而 1 小时的注意力 FLOPs 只值 1.4 分钟算力。分段的最优长度由 D0​ 与显存共同决定，D0​ 本身是开放问题（⚠️）。
  • 说话人一致性可以写成 σ 上限：cosj​=1/1+jdσ4​，100 段要 cos≥0.85 则 σ≤0.0622（d=256）、τ=0.95 时 σ≤0.0453。级联靠独立说话人编码器天然稳定，端到端要靠训练——"τ 取多少"必须实测（⚠️ C 级）。
  • 评估的交付物是"效应量 + CI + 判定规则"：配对偏好检验 n=(z1−α/2​0.25​+zpower​p1​(1−p1​)​)2/(p1​−0.5)2，p1​=0.55 要 783 对、p1​=0.60 要 194 对、3 轴 Bonferroni 后 1045/259。表 9 里"音质"一行的效应量 0.05< CI 半宽 0.06，因此不可判定。
  • 判断力的顺序：先问"哪个轴在约束你"，再问"谁的下限更低"，最后才问"现在谁更好"。反过来会产生四类系统性错误：在无约束的轴上比、用当前分数代替极限、把构造值当实测、把多轴压成单轴。
