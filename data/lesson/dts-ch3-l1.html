PCIe / NVLink / NVSwitch：域内带宽的层级#

第 2 章你选好了算法，式子里还剩一个没着落的参数：β 到底是多少。它不是常数——同一台服务器上，卡 0 到卡 1 可能走 NVLink（每秒几百 GB），也可能绕 PCIe 根复合体（每秒几十 GB），而这两种情况在 nvidia-smi topo -m 里只差一个单词。本课把机器内部拆成三级链路，把每一级换算成可以直接代进 α-β 模型的单向 β。

一、概念讲解#

1. 一台机器里其实有三条"卡间链路"#

两块 GPU 之间传数据，物理上可能走三种路：

域内路径 站在谁的肩膀上 单向带宽量级 100 MiB ring AllReduce（P=8）
NVLink + NVSwitch 专用高速串行链路网络 数百 GB/s（NVLink 4 双向 900 GB/s） 0.44 ms
PCIe 交换机 / 根复合体 PCIe 树（可能过 switch，不过 CPU） x16 数十 GB/s 2.98 ms（PCIe 5.0 x16）
经 CPU / NUMA 互连 PCIe 主机桥 + QPI/UPI 之类的 SMP 链路 更低的有效带宽、更高延迟 5.91 ms（PCIe 4.0 x16）

三行是同一份 100 MiB 梯度、同一个 ring 算法（每步每条环边只传 s=S/p，共 2(p−1) 步，即 T=2(p−1)α+p2(p−1)​⋅βS​），只有 β 换了一级。域内选择比算法选择更能决定量级——这是本章的第一条结论。

2. PCIe：它是一棵树，不是一条线#

PCIe 是分层的树：GPU（endpoint）挂在 root complex 或 switch 下，switch 再向上汇聚。所以"两张卡之间的 PCIe 路径"可能是"同一个 switch 内的两跳（PIX）"，也可能是"各自过主机桥、再跨 NUMA 节点（SYS）"，带宽与延迟都不同。

带宽不能靠背，要会算：每通道速率 × 通道数 × 编码效率 ÷ 8。PCIe 3.0/4.0/5.0 用 128b/130b 编码（效率 128/130），6.0 换 PAM4 并引入 FLIT/FEC。于是 x16 单向是：

代际 每通道速率 x16 单向 x16 双向 x8 单向
PCIe 3.0 8 GT/s 15.8 GB/s 31.5 GB/s 7.9 GB/s
PCIe 4.0 16 GT/s 31.5 GB/s 63.0 GB/s 15.8 GB/s
PCIe 5.0 32 GT/s 63.0 GB/s 126.0 GB/s 31.5 GB/s
PCIe 6.0 64 GT/s 128.0 GB/s（未计 FLIT/FEC 开销，实际略低） 256.0 GB/s 64.0 GB/s

关键推论：x8 就是 x16 的一半，所以"卡插在 x16 槽"这句话不完整，还要看链路协商到的宽度（nvidia-smi -q 的 PCIe 段会给出 Link Width）。

3. NVLink 与 NVSwitch：把 8 张卡变成一个域#

NVLink 是点对点的高速链路，NVSwitch 是把这些链路接成非阻塞全互连的交换芯片。按 NVIDIA 官方口径的代际量级：

代 出现时间 每 GPU 链路数 每 GPU 双向带宽
第 1 代 2014（P100 之前） — 160 GB/s
第 3 代 2020（A100） 12 600 GB/s
第 4 代 2022（H100） 18 900 GB/s
第 5 代 2024（Blackwell） 18 1.8 TB/s

官方都按双向报数，工程上按单向记账时要除以 2：NVLink 4 单向 450 GB/s，正好是 PCIe 5.0 x16 单向（63 GB/s）的约 7.1 倍——这也解释了官方"N×PCIe Gen5"的说法从哪来。上到第 5 代，一颗 NVLink 交换机托盘就能提供 144 个 100 GB/s 端口，把 72 颗 Blackwell 接成单一 NVLink 域（GB200 NVL72 官方给出域内总带宽 130 TB/s）。

NVSwitch 还有一个容易被忽略的能力：把 AllReduce 卸载到交换机（NVLink SHARP / NVLS）。NCCL 由 NCCL_NVLS_ENABLE 控制（默认 2：不支持则回落，资源分配失败则报错），要求第三代 NVSwitch（NVLink 4）与 Hopper 及之后的架构。

4. 三个最容易算错的地方#

  • 双向 vs 单向：ring 的每一步只往一个方向发 s 字节，用单向带宽；把 900 GB/s 直接代进 β 会把账算少一半。
  • Gb/s vs GB/s：网络侧常说 Gb/s（bit），除以 8 才是 GB/s。NVLink 与 PCIe 的 GB/s 已经是字节口径，两边混用是常见错误。
  • 峰值 vs 有效：上面都是规范峰值。实测里还有协议头、PCIe 事务开销与共享上行，有效带宽通常低于峰值，所以第 1 课的态度是"用实测反解 α、β"，规范值只用来定预期量级。

5. 读自己的机器：nvidia-smi topo -m#

它输出一张卡间/NIC 矩阵，官方图例：X 自己、SYS 过 PCIe + NUMA 间 SMP 互连、NODE 过同一 NUMA 内的 PCIe 主机桥互连、PHB 过 PCIe 主机桥（通常就是 CPU）、PXB 过多个 PCIe 交换机、PIX 只过一个 PCIe 交换机、NV# 过一组 # 条 NVLink。

读法只有三条：看到 NV# 就是最快一级；PIX 好过 PXB 与 PHB；出现 SYS 说明这段通信要跨 NUMA。配套命令：nvidia-smi topo -p2p r -i 0 看卡 0 能否被 peer 读，nvidia-smi topo -mp 只看 PCIe 路径（排除 NVLink），nvidia-smi topo -C -i 0 给出最近的 NUMA 节点。

6. 常见坑#

  • 只报 GPU 型号、不看 topo：同样是 8×H100，全 NVLink 与 4+4 拼接的机器，ring 的 β 差一倍以上。
  • 假设"服务器内一定是 NVLink"：nvidia-smi topo -m 里出现 PHB/SYS 的机比想象中多。
  • 忽略 PCIe 上行共享：多张卡挂同一个 switch、switch 再共用一条上行时，同时通信会互相抢带宽，"每卡 x16"只是名义值。
  • 拿双向带宽算单向账（见上节）。

7. 这一课到哪里为止#

域内层级只解决"β 取哪个数量级"。一旦通信要出门，路径上必然出现网卡，链路代际换成 InfiniBand / RoCE 的说法，还会多出一次"GPU 与网卡之间怎么传"的选择——这正是下一课。

二、可运行代码示例#

三段纯 Python（只用标准库），先把 PCIe 带宽算出来，再用同一份梯度看三级链路的差距，最后做层级换算。参数取规范速率与量级值，请用自己机器的 nccl-tests 实测替换。

# ===== 示例 1：PCIe 各代带宽由"规范速率 × 编码 × 通道数"推出来，不靠背数字 =====
PCIe = [("3.0", 8.0, 128 / 130), ("4.0", 16.0, 128 / 130),
        ("5.0", 32.0, 128 / 130), ("6.0", 64.0, 1.0)]     # (代, GT/s/通道, 编码效率)


def pcie_uni(rate_gts, enc, lanes=16):
    """单向有效带宽（GB/s）= 每通道速率 × 通道数 × 编码效率 / 8。"""
    return rate_gts * 1e9 * lanes * enc / 8 / 1e9


print("x16 插槽的带宽（6.0 未计 FLIT/FEC 开销，实际略低）：")
for gen, rate, enc in PCIe:
    uni = pcie_uni(rate, enc)
    print(f"  PCIe {gen} x16: 单向 {uni:6.1f} GB/s   双向 {2 * uni:6.1f} GB/s")
print(f"  PCIe 5.0 x8 : 单向 {pcie_uni(32.0, 128 / 130, 8):6.1f} GB/s"
      f"   双向 {2 * pcie_uni(32.0, 128 / 130, 8):6.1f} GB/s")


# ===== 示例 2：同一算法、同一消息量，只换域内链路 =====
def ring_allreduce_ms(total_bytes, P, alpha_us, beta_gbps):
    """ring AllReduce：总消息量 total_bytes，每步每条环边只传 s = total/P 字节，共 2(P-1) 步。
    T = 2(P-1)·α + 2(P-1)/P · total/β；β 用单向带宽。返回毫秒。"""
    lat = 2 * (P - 1) * alpha_us
    bw = 2 * (P - 1) / P * total_bytes / (beta_gbps * 1e9) * 1e6
    return (lat + bw) / 1e3


grad = 100 * 2**20                       # 100 MiB 梯度
print(f"\n{grad / 2**20:.0f} MiB AllReduce，P=8，链路换成各级实测的量级：")
for link, alpha, beta in [("PCIe 4.0 x16（单向）", 6.0, 31.5),
                          ("PCIe 5.0 x16（单向）", 5.0, 63.0),
                          ("NVLink 4（单向）", 2.0, 450.0)]:
    t = ring_allreduce_ms(grad, 8, alpha, beta)
    print(f"  {link:<20} β={beta:5.1f} GB/s   ring = {t:8.2f} ms")


# ===== 示例 3：层级换算 —— 一条 NVLink 抵几条 PCIe =====
nv4_uni = 900 / 2                        # NVLink 4：900 GB/s 双向 → 450 GB/s 单向
print(f"\n链路代差换算（NVLink 4 单向 {nv4_uni:.0f} GB/s 为基准）：")
for gen, rate, enc in PCIe:
    print(f"  1 条 NVLink 4 ≈ {nv4_uni / pcie_uni(rate, enc):4.1f} 条 PCIe {gen} x16 单向")

三、练习#

  1. 实现：把示例 2 改成"按 topo 矩阵自动选 β"：给一个 {('0','1'):'NV4', ('0','2'):'PIX'...} 的字典，输出 P=8、100 MiB ring AllReduce 的预测时间，并与"全部按 NVLink 4"的假设对比差多少。
  2. 解释：为什么 PCIe 6.0 的每通道速率翻倍（64 GT/s）而单向带宽却不是 PCIe 5.0 的严格两倍？请从编码与 FLIT/FEC 两个角度各说一句。
  3. 对比/验证：把示例 1 的 lanes 从 16 改成 8、4，重算四代 x8/x4 的单向带宽；再解释为什么"推理卡的 KV cache 传输"更关心 x16 与 x8 的差别。
  4. 思考：如果一台 8 卡机器里，卡 03 之间是 NVLink、卡 47 之间是 PCIe、跨半区只有 PCIe，那么一个 P=8 的 ring AllReduce 的 β 应该取哪个值？换成 tree 算法结论会不会变？
