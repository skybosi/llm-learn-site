从图像生成到视频生成：时间维带来的三笔新账#

这一节要解决什么#

第 2 章处理的是判别任务：给定一段视频，输出标签、时间区间或答案。这一章开始处理生成任务：给定一个条件，输出一段视频。介于两者之间的那句"把图像生成模型搬到时间轴上"，听上去像是把 H×W 换成 T×H×W，做一次维度的替换。不是。 这一节的结论是：

  1. 时间维引入的不是一个更大的空间，而是一个独立的误差轴。 一段视频的误差可以写成 E=E空间​+E时间​+交叉项（式 3），而"每一帧单看都对"与"整段看起来一致"是两个不可互相推导的性质。表 3 用四种互不蕴含的口径（抖动、速度/末帧误差、外观漂移、长程对齐）在同一批合成轨迹上给出互相矛盾的排序：一个把抖动压到 0.4 倍的生成器，末帧误差反而是另一个的 8.5 倍（表 3）。
  2. 生成代价的规模由"时长"而不是"数据集大小"决定。 潜码字节按 nlat​ 线性长（T=481 时 1.9062 MiB，只有 61 倍），但注意力矩阵按 N2 长（同一段视频物化 score 是 930.2500 GiB，3,723 倍于潜码的二进制位宽增长）（表 1）。同一个"20 秒"，两笔账差了三个数量级。
  3. 二次项追上线性项的位置是可算的。 单步算力 c1​(N)=a+bN，a=72.5000 GFLOP/潜帧、b=0.0110 GFLOP/潜 token，解 a=bNs​(T/ft​) 得交叉帧数 T∗=12.8729 帧 =0.54 秒（表 2）。在"一次生成 1 秒"的可行区间里卷积还是主项，所以第一代视频扩散可以照搬图像 U-Net；一旦要推到分钟级，架构必须换——这是"时空分解/窗口/自回归"这些方法的唯一动机。
  4. 长时漂移有可拟合的定量形式。 把每步误差看成加性扰动，长程偏差 D(n)=ϵdnα：无偏随机游走 α=0.5、系统偏差 α=1.0、有回复力 α=1.5，24 与 24000 帧之间的 log-log 斜率把三个值分别恢复成 0.500000/1.000000/1.500000，最大残差 ≤1.8×10−15（表 4）。由此可反解：容差 ρ=0.01 时，无偏噪声 ϵ=10−4 能撑 104 帧，而带系统偏差时只能撑 102 帧——消掉误差的均值比压小它的方差值钱 50 倍。
  5. 一致性的每一分都从别处借。 关键帧重置把 1920 帧的平均漂移从 14.0217 压到 0.7634（K=8），代价是段数从 1 涨到 240 个接缝；数据侧，片段有效率 pL 让 L=64 的样本要采样 25.3170 倍，而单位算力的有效覆盖 pL/L 在 L∗=−1/lnp=19.4957 帧处取极大（表 4、表 5）。"更长"与"更稳"在同一张预算表里对冲。
  6. 可控性有信息量的上限。 一段 20 秒视频的潜码元素 983,040 个（每分量按 4 bit 有效熵计，内容熵约 3.9322 Mbit），而 77 token 的文本条件只有 231 bit，占 0.005875%；深度图这类逐帧几何条件能到 25.000000%，代价是这些 bit 必须由用户或另一个模型提供（表 6）。"文字控制不住细节"首先是信息量问题，不是模型容量问题。

本节的主线是一句话：视频生成不是"图像生成加一维"，而是"多了一条会自己累积误差的时间轴"，因此判据要重新写。 后面三节分别处理这条轴上的三件事：扩散过程怎么扩展到时间维（第 2 节）、长时一致性与显存的具体机制（第 3 节）、以及条件控制与评测协议（第 4 节）。

一、多一维像素，还是多一个误差轴#

1.1 先说清"多了什么"#

图像生成模型学到的是一个分布 pθ​(x)，x∈RH×W×C。视频生成的目标分布换成了 pθ​(x)，x∈RT×H×W×C。如果只把张量维度写出来，这是一个"更大的空间"，于是很自然的推断是：更大的模型、更多的数据、更长的训练就能解决。

这个推断在三个地方立刻失效，而三处的失效方式不同：

第一处是采样率。 第 1 章已经算过时间轴上的混叠：f^​=∣f−kfs​∣。生成模型不是"看"视频，它要产生运动；如果训练片段的帧率与目标帧率不匹配，模型学到的是折叠后的频率。这不是容量问题——给再多参数也换不回被采样定理丢掉的信息。

第二处是误差的分解。 设目标视频 x、生成视频 x^，两者都是 T 帧序列。逐帧误差的均方和可以按"帧内"与"帧间"两项拆开：

Eframe​=T1​t=1∑T​∥x^t​−xt​∥2,Etime​=T−11​t=2∑T​​(x^t​−x^t−1​)−(xt​−xt−1​)​2.

Eframe​=T1​t=1∑T​∥x^t​−xt​∥2,Etime​=T−11​t=2∑T​​(x^t​−x^t−1​)−(xt​−xt−1​)​2.

（式 3）这两项不可互相推导：Eframe​=0 不蕴含 Etime​=0（如果生成器输出的每一帧都是同一张"平均图"，逐帧误差可能很小，但帧间差全错）；反过来 Etime​ 小也不蕴含 Eframe​ 小（每帧都偏同一个颜色，帧间差完全正确）。用一个常数图去拟合一段含运动的视频，Eframe​ 与 Etime​ 的关系完全取决于运动幅度与颜色偏差谁的范数更大——没有一般的不等式。

第三处是误差的累积。 视频生成的主流实现是自回归的（逐帧或逐块），或者至少是分块的。只要生成过程是"用前一段的输出当后一段的条件"，误差就进入了递归：

xt+1​=Fθ​(xt​)+δt​ ⟹ 偏差t​ 不是 ∥δt​∥ 的函数，而是 s≤t∑​δs​ 的函数.

（式 4）第 4 节会把 ∑s≤t​δs​ 写成 D(n)=ϵdnα 并给出 α 的拟合方法。这里只先记住：图像生成本质上是一次性映射，视频生成（自回归/分块时）是递归映射，两者的误差传播性质不同。

既然多了这么多东西，为什么第一代视频扩散模型（如把 2D U-Net 换成带时序卷积的 3D U-Net，或在 2D 卷积后加时间注意力）确实工作得不错？表 2 给出了算术上的答案。

把单步算力写成两项：

c1​(N)=a+bN,N=nlat​⋅Ns​,nlat​=⌈T/ft​⌉.

（式 5）其中 a 是与帧数无关的卷积项、bN 是随 token 数线性增长的注意力项。表 2 用 642 的潜格、4 级 U-Net（通道 320→320→640→1280）、8 头、dhead​=40 的构造锚点算出 a=72.5000、b=0.0110。于是注意力占比为

在 T≤24（nlat​≤3）时 share =65.09%；在 T=481（nlat​=61）时 97.43%；在 T=2881 时 99.56%。"一次能生成 1 秒"这件事，恰好落在"卷积还值得优化、注意力刚成为主项"的区间里，所以那一代模型的设计重心是"怎么把图像 U-Net 扩成 3D"而不是"怎么重构注意力"。一旦目标时长变成分钟级，share 逼近 1，任何"把卷积做得更好"的努力都不再有意义——架构的更换不是品味问题，是 share 的极限问题。

二、时间一致性的四个口径，以及它们为什么不互相蕴含#

2.1 四个口径的定义#

"时间一致性"在文献里至少被用来指四件不同的事。本节把它们各自写成一个可算的量，并在同一批合成轨迹上测：

  1. 抖动（jitter）：位移相对时间平滑趋势的残差。本节的算例取 5 帧滑动均值作为趋势，jitter=T1​∑t​∣xt​−xˉt(5)​∣。
  2. 速度偏差（slope）：把轨迹对帧号做最小二乘，斜率与意图速度 1 px/帧 的差。
  3. 长程误差（end error）：末帧位置相对意图位置的偏差 ∣xT​−refT​∣。
  4. 外观漂移（appearance）：帧特征向量（亮度均值、色度）相对基准的 drift，折算成"等效像素"：equiv=∣ΔI∣​Capp​/Gfeat​，其中 Gfeat​ 是特征距离对亮度变化的灵敏度。

第一，"运动预平滑"与"系统偏差"在抖动口径上几乎不可区分，在长程口径上差 22.5 倍。 平滑把抖动从 0.037568 压到 0.015122（2.4843 倍），末帧误差从 1.480473 降到 0.557478；但这个改善完全来自方差。给同一个平滑轨迹加上 0.05 px/帧 的偏差：抖动只从 0.015122 动到 0.015747（几乎不变），末帧误差跳到 12.557478 px（0.05×240=12.00 的量级），速度从 1.002194 变成 1.052194。任何只报帧间平滑度的评测，对系统偏差是结构性失明的。

第二，"外观漂移"在位移口径上与基线完全相同。 它的抖动、末帧误差、速度三个数与"独立逐帧生成"逐位相同（0.037568、1.480473、1.005547），因为它的位移误差为零；但外观等效误差是 6.373333 px（逐帧平均；末帧等效 12.6933 px）。只测光流/warp 的评测会把它判成"完全一致"。

第三，抖动指标的"地板"要显式报出来。 零误差基线的抖动不是 0 而是 0.012500——这是滑动均值去趋势在序列端点上的效应，不是生成质量问题。一个改进如果小于这个地板，就不能声称有效；这正是第 2 章讨论"评测口径骗人"时那条纪律在生成任务上的复现。

第四，四个口径的排序会随失效类型改变。 表 3 里"独立逐帧生成"的抖动最大（0.037568）而末帧误差中等；"运动预平滑+偏差"的抖动最小之列而末帧误差最大；"外观漂移"的位移指标最优而外观指标最差。不存在一个标量能同时代表这四件事，这是"多了一个误差轴"的工程含义。

2.3 怎么做：先在协议里写清四件事#

一个可复现的时间一致性评测，至少要固定：

  1. 口径：抖动用几帧窗口去趋势？长程是测末帧还是平均？外观用哪个特征空间？
  2. 时长：240 帧与 24000 帧上，同一模型的排序可能不同（表 3 的第 2 行与表 4 的 α 讨论）。
  3. 地板：用零误差或真值轨迹跑一遍同一套指标，报出地板值。
  4. 方差：抖动、末帧误差都是随机变量；至少给多次采样的均值与标准差（第 2 章已经给过统计门槛 1.962p(1−p)/V​ 的同类判据）。

边界：这四条只保证"可比"，不保证"对"。四个口径都是对"时间一致性"的代理，代理与实际观感之间没有定理；把四个都报出来，是为了让"在哪种失效上变好"这件事无法被隐藏。

三、漂移的定量形式：D(n)=ϵdnα#

3.1 三个 α 的来历#

把生成过程看成每步注入一个误差分量、且这些分量在潜空间里叠加。设潜宽度 d、单步误差各分量的标准差 ϵ、第 n 步的长程偏差 D(n)。三种常见情形的 D(n) 各不相同：

  1. 无偏随机游走（每步误差独立同分布、均值为零）：方差按 n 线性叠加，标准差按 n​，故 D=ϵdn1/2，α=0.5。
  2. 每步同向偏差（存在一个系统性的偏差向量，例如固定的渲染/量化偏置）：n 步线性叠加，D=ϵdn1，α=1.0。
  3. 被拉回（存在回复力，例如每步都向某个锚点收缩）：偏差被约束在有限范围内，观测上拟合出的指数可以大于 1（构造算例取 1.5）。

为什么这不是"几种可能性"而是"要测的量"：真实系统的 α 落在三者之间，且随着时长变化——短片段上噪声主导（看起来像 0.5），长片段上系统偏差主导（看起来像 1.0）。因此"这个模型的漂移指数是多少"本身就是一个评测问题，不是模型属性。

给定相对容差 ρ（要求 D(n)/d≤ρ），解出

（式 12）注意 D/d=ϵnα 与 d 无关（分子分母同乘 d 约掉）——这条式子给出了一个反直觉但重要的结论：换更宽的潜空间不会延长可生成时长。宽度买的是容量（能表示多少内容），不是稳定性（能走多远）。

  • α=0.5、ρ=0.01：ϵ 从 10−2 降到 10−4，nmax​ 从 100 涨到 1,000,000（104 倍）。
  • α=1.0、ρ=0.01：同样 ϵ 变化只让 nmax​ 从 1 涨到 100（102 倍）。
  • 换算成时长（24 fps）：α=0.5,ϵ=10−4 时 416.67 s；α=1.0,ϵ=10−4 时 4.17 s。

结论：把误差的均值消掉，比把它的方差压小更值钱——在同一个 ρ 下，前者给的是 104 倍、后者只是 102 倍。这条判据直接指向两类工程手段：零均值化（把系统偏差显式建模并减去，例如显式的运动先验、锚点对齐）与降方差（更好的采样器、更小的步长、更稳的数值）。

Dchunk​(K)=ϵdK​,Dseam​=ϵd,Dˉ≈32​Dchunk​(K)+21​Dseam​.

4.3 步数是乘性的#

采样步数 S 只乘一个常数：总算力 =S⋅T⋅c1​(N)。因此"把步数从 50 降到 20"与"把时长从 20 s 缩到 8 s"在同一量级上取舍。表 2 的 50 步列可以直接读：T=481 时 8,603,793.8000 GFLOP——这是"一次生成 20 秒"的算力下限，与步数无关的部分（模型前向本身的 a）在长时长下被注意力项淹没。

5.1 片段有效率与样本数#

判别任务里，一段视频要"能用"只需采样到有效帧即可；生成任务里，训练片段通常是连续 L 帧，要求这 L 帧全部有效（不糊、不裁切、字幕对齐）。设单帧有效率 p，则片段有效率是 pL。表 5 取 p=0.95：

5.2 单位算力的有效覆盖：L∗=−1/lnp#

长片段更贵（注意力 O(L2)）但覆盖更长的时间跨度，两笔合成：

（式 19）p=0.95 时 L∗=19.4957 帧；p=0.99 时 99.4992 帧；p=0.999 时 999.4999 帧；p=0.90 时 9.4912 帧。"最优片段长度"随数据质量 p 指数级地移动，而且它是架构的函数：如果 cost(L)∝L（自回归分块），coverage 变成 pL、单调下降，"越短越好"。所以任何"我们用了 16 帧，所以你也用 16 帧"的说法都缺两个前提：p 与 cost 的指数。

5.3 标注与条件的耦合#

第 1 章算过弱标注的乘性折扣（ASR 的 (1−p)k 叠上定位熵）。生成任务里这笔账换了形式：条件（文本、深度、姿态）本身要标注，而条件的 bit 数决定它能控多少（见下节）。这是视频生成相对图像生成多出来的第二笔"数据账"：不仅要视频，还要与视频逐帧对齐的条件。

六、可控性：条件的信息量上限#

6.1 把"控制"写成 bit 数#

一段 20 秒视频的潜码有 983,040 个元素；按每个潜分量 4 bit 有效熵计，内容熵约 3.9322 Mbit。各类条件能给多少 bit（表 6）：

条件类型 可数信息量 占内容熵 每帧等效 bit

首帧（一张 512 潜图 @ 4 bit/分量） 65,536 bit 1.666667% 136.5333
姿态 17 关节 @ 8 bit × 480 帧 65,280 bit 1.660156% 136.0000
深度 16×16 @ 8 bit × 480 帧 983,040 bit 25.000000% 2,048.0000

文本条件占 231/3,932,160≈58.7463 ppm。"文字控制不住细节"首先是这个比例问题：模型有 99.994% 的自由度没有被文本约束，它必须用先验去填，先验填出来的是什么就只能是什么。逐帧几何条件（深度/姿态）能把比例提到千分之几到百分之几十，代价是这些 bit 必须由用户或另一个模型提供——控制的每一 bit 都是从标注/前处理那边借来的。

6.2 引导：只放大，不产生#

分类器无关引导把条件与无条件两次前向组合：ϵ^=ϵuncond​+w(ϵcond​−ϵuncond​)。w 越大条件一致性单调变好：

P(条件满足)≈1−e−(w−1),相对多样性≈w1​.

（式 21）w=2 时一致性 0.632121、多样性 1/2；w=7.5 时一致性 0.998497、多样性 1/7.5。引导不产生新信息，它只是把条件已有的信息放大成更强的梯度；能控多少仍然由式 21 上面的 bit 比例封顶。这是"可控性"与"多样性"取舍的算术形式，第 4 节会把它展开成完整的条件控制分类。

6.3 本节的三条边界#

  1. 时间维引入独立的误差轴：Eframe​ 与 Etime​ 无一般不等式（式 3），所以"逐帧都对的模型连起来可以完全不一致"不是修辞。评测必须同时报口径与时长。
  2. 代价由时长而非数据集大小决定：FLOPs∝nlat2​ 的系数由架构决定（式 5、式 16），交叉点 T∗ 可以算出来；一旦超过它，"优化卷积"是无意义的方向。
  3. 可控性有信息量上限：条件给多少 bit 决定能控多少（表 6），引导只能放大不能增加；长时一致性的每一分改善都要在接缝数量或数据有效率上还账（式 13、式 19）。

import math
import unicodedata


def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1
               for ch in s)


def pad(s, w, align=">"):
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2
    return " " * left + s + " " * (gap - left)


def row(cells, widths, aligns=None):
    aligns = aligns or [">"] * len(cells)
    return " | ".join(pad(c, w, a) for c, w, a in zip(cells, widths, aligns))


def rule(t, w=112):
    print("=" * w)
    print(t)
    print("=" * w)


class LCG:
    def __init__(self, seed=20260923):
        self.s = seed & 0xFFFFFFFFFFFFFFFF

    def u(self):
        self.s = (6364136223846793005 * self.s + 1442695040888963407) \
            & 0xFFFFFFFFFFFFFFFF
        return (self.s >> 11) / float(1 << 53)

    def n(self):
        u1 = max(self.u(), 1e-12)
        u2 = self.u()
        return math.sqrt(-2.0 * math.log(u1)) * math.cos(2.0 * math.pi * u2)

G_FEAT = 0.30       # 特征距离对亮度变化的灵敏度（|dI| = G_FEAT * d(亮度)）


def make_case(jit_code, bias, a0, seed):
    """生成 (位移序列, 外观序列, 参考基准) 三个量。

    jit_code: "white" 逐帧独立 | "smooth" 时间平滑（抖动小但可能有系统偏差）
    bias:     每帧的系统速度偏差（px/帧）
    a0:       每帧的外观漂移（亮度单位/帧）
    """
    r = LCG(seed)
    e, col, ref = [], [], []
    x, xs = 0.0, []
    for i in range(NF):
        if jit_code == "white":
            eps = r.n() * 0.05
        elif jit_code == "smooth":
            eps = r.n() * 0.02
        else:
            eps = 0.0
        x += INTENT_V + bias + eps
        xs.append(x)
        e.append(eps)
        col.append(a0 * i)
        ref.append(INTENT_V * (i + 1))
    if jit_code == "smooth":            # 时间平滑：抖动降到 1/4，但偏差保留
        sm = [e[0]]
        for i in range(1, NF):
            sm.append(0.25 * e[i] + 0.75 * sm[-1])
        x, xs = 0.0, []
        for i in range(NF):
            x += INTENT_V + bias + sm[i]
            xs.append(x)
        e = sm
    return e, xs, ref, col


def metrics(eps, xs, ref, col):
    # 0) 速度的最小二乘斜率（用于检查「偏差是否被恢复」）
    # 1) 瞬时抖动：位移相对**时间平滑趋势**的残差 MAD（用 5 帧滑动均值去趋势）
    k = 5
    k = 5
    trend = []
    for i in range(len(xs)):
        lo, hi = max(0, i - k // 2), min(len(xs), i + k // 2 + 1)
        trend.append(sum(xs[lo:hi]) / (hi - lo))
    jit = sum(abs(a - b) for a, b in zip(xs, trend)) / len(xs)
    # 2) 长程：末帧位置相对意图的误差
    end_err = abs(xs[-1] - ref[-1])
    # 3) 速度斜率（最小二乘）
    n = len(xs)
    mi = (n - 1) / 2.0
    mx = sum(xs) / n
    slope = sum((i - mi) * (x - mx) for i, x in enumerate(xs)) / \
        sum((i - mi) ** 2 for i in range(n))
    # 4) 外观漂移：每帧色彩相对基准的 mean|dI| / G_FEAT（等效 px）
    dcol = sum(abs(c) for c in col) / len(col)
    return jit, end_err, slope, dcol * C_APP / G_FEAT, xs

NS = [24, 48, 96, 192, 384, 768, 1536, 3072, 6144, 12288, 24000]


def fit_exponent(ns, ds):
    us = [math.log(n) for n in ns]
    vs = [math.log(d) for d in ds]
    n = len(us)
    ub, vb = sum(us) / n, sum(vs) / n
    sxy = sum((u - ub) * (v - vb) for u, v in zip(us, vs))
    sxx = sum((u - ub) ** 2 for u in us)
    a = sxy / sxx
    b = vb - a * ub
    return a, math.exp(b), max(abs(v - (a * u + b)) for u, v in zip(us, vs))

本身就是评测对象（不同模型可能给出 0.5~1.5 之间的任意数）。

两笔折扣方向相反，合成判据是「单位算力买到的有效时间覆盖」：
  coverage(L) = L * p^L / cost(L)；cost(L) ∝ L^2（注意力）时 coverage = p^L / L，
  它在 L* = -1/ln p = -1/ln(0.9500) = 19.4957 帧取最大。
  p=0.99 -> L* = 99.4992 帧；p=0.999 -> L* = 999.4999 帧；p=0.90 -> L* = 9.4912 帧

  因为最优值 L* = 19.50 落在 L=8 与 L=16 之间，且 p^L/L 的下降很快。
  L* 的意义是「片段长度不该超过这个量级」，不是「最优值就在表里」。

这条判据的边界：cost(L) 的指数取决于架构。自回归分块生成的 cost 接近 O(L)，
  此时 coverage = p^L 单调下降（越短越好）；只有联合时空注意力是 O(L^2) 时
  才出现内部极大值。**「最优片段长度」是架构的函数，不是常数。**

  引导不产生新信息，它只把条件的信息放大成梯度 —— 与上面的「条件通道 bit 数」
  是同一件事的两种写法：能控多少，最终由条件的 bit 数封顶。

三条边界（本节结论）：
  1) 时间维不是「多了一维像素」，它引入了一个与空间误差独立的误差轴：
     每一帧都对、连起来可以完全不一致（表 3 的四个口径互不蕴含）。
  2) 生成代价的规模由「时长」而不是「数据集大小」决定：算力 ∝ n_lat^2（表 2），
     且这个二次项的系数由架构（是否时空联合）决定，不是超参。
  3) 把图像生成器改成视频生成器不是改最后一层，而是重新分配三笔预算：
     算力（二次项出现在时间轴）、显存（score/潜缓存随 N 增长）、
     控制信息（条件给多少 bit、从哪里来）。

小结#

  • 时间维引入独立的误差轴：Eframe​ 与 Etime​ 无一般不等式（式 3），"逐帧都对、连起来完全不一致"是可构造的事实。
  • 四个口径互不蕴含（表 3）：抖动 0.037568/0.015122/0.015747、末帧误差 1.480473/0.557478/12.557478 px、速度 1.005547/1.002194/1.052194 px/帧、外观等效 6.373333 px。抖动指标对系统偏差是盲的；外观漂移在位移口径上与基线逐位相同。
  • 抖动指标有地板：零误差基线的抖动是 0.012500 px（滑动均值去趋势的端点效应），改进小于地板就不能声称有效。
  • 代价由时长决定：潜码按 nlat​ 线性（T=481 时 1.9062 MiB），物化 score 按 N2（同一段 930.2500 GiB），分块后 7,808.0000 KiB（差 3,123.2000 倍）；省的是显存，4N2d 的 FLOPs 不变。
  • 交叉帧数 T∗=ft​a/(bNs​)=12.8729 帧 =0.54 s（式 16）：T≤24 时注意力占比 65.09%，T=481 时 97.43%，T=2881 时 99.56%。超过 T∗ 之后"优化卷积"不再有意义。
  • 单步算力：图像 117.5560 GFLOP，T=121 时 12,694.3360（107.9854×），T=481 时 172,075.8760（1,463.7779×），50 步合计 8,603,793.8000 GFLOP。步数是乘性因子。
  • 漂移的定量形式 D(n)=ϵdnα：log-log 拟合恢复 α=0.5/1.0/1.5（残差 ≤1.8×10−15）；D/d=ϵnα 与 d 无关，加宽潜空间不延长可生成时长。
  • 反解 nmax​=(ρ/ϵ)1/α：α=0.5 时按 ϵ−2 走（ϵ:10−2→10−4 给 100→106 帧），α=1.0 时按 ϵ−1 走（1→100 帧）——消均值比压方差值钱 100 倍以上。
  • 关键帧重置：T=1920 不重置漂移 14.0217，K=8 时 Dˉ=0.7634（相对 0.0544），代价是 240 个接缝（式 13）。
  • 数据侧：p=0.95 时 L=64 的样本要多采样 25.3170 倍；L∗=−1/lnp=19.4957 帧（p=0.99→99.4992、p=0.999→999.4999）；L∗ 是架构的函数（cost∝L 时最优变"越短越好"）。
  • 可控性有信息量上限：文本 231 bit =0.005875% 内容熵（58.7463 ppm），首帧 1.666667%，姿态 1.660156%，深度 25.000000%；引导 w:2→7.5 把一致性从 0.632121 抬到 0.998497，多样性从 1/2 降到 1/7.5（式 21）——引导只放大不产生。
