交叉注意力#

自注意力是"自己看自己"，Q、K、V 都来自同一个序列。而 Transformer 的解码器里还有第二类注意力，它是整个"编码器—解码器"架构的桥梁：Query 来自解码器（目标语言），Key 和 Value 来自编码器（源语言）。这就是交叉注意力（cross-attention），也常叫"编码器—解码器注意力"。正是它让解码器在生成目标语言的每个词时，能够"回头"去查阅源句子的相关信息——就像翻译 I have a cat 时，生成"猫"之前要先去源句子里找到 cat。这一课讲清它和自注意力的本质区别，并实现一个最小例子。

一、概念讲解#

1. 三种注意力，三种"信息流"#

先把编码器—解码器架构里的三处注意力摆在一起，看它们各自的 Q、K、V 从哪来：

类型 Query 来自 Key 来自 Value 来自 作用
编码器自注意力 源序列 源序列 源序列 源句子内部建模（双向）
解码器自注意力 目标序列 目标序列 目标序列 目标句子内部建模（因果）
交叉注意力 目标序列 源序列 源序列 连接两种语言/两种序列

关键在最后一行：Query 是"我要找什么"，Key/Value 是"我能提供什么"。解码器拿着自己当前的表示当 Query，去编码器输出的"源语言记忆"里检索，把检索到的 Value 加权求和，融合进自己的表示。

2. 为什么要"Q 在解码器、K/V 在编码器"#

这是交叉注意力最容易背混、也最值得想明白的一点。直觉如下：

  • Query 代表"查询方"的需求：解码器当前要生成的这个词，需要知道"源句子里哪部分对我有用"。
  • Key 代表"被查方的索引"：编码器为源句子的每个位置提供一个 key，供查询方来匹配。
  • Value 代表"被查方的实际内容"：匹配到之后，真正取走的是源位置的内容向量。

所以，是解码器在提问、编码器在作答。把 Q 和 K/V 的来源对调（用编码器当 Q、解码器当 K/V）在数学上当然也能算，但那就不再是"生成时查阅源句子"的语义了，也就丧失了架构设计的本意。

3. 形状上的一点差别#

自注意力里 Q、K、V 长度相同（都是序列长 T），得到的注意力权重是 (T, T) 方阵。交叉注意力里，Query 的长度是目标序列长度 T_tgt，Key/Value 的长度是源序列长度 T_src，二者通常不相等：

scores = Q(tgt) @ K(src)^T / sqrt(d_k)    # 形状 (T_tgt, T_src)
weights = softmax(scores, dim=-1)          # 每行：某个目标位置对全体源位置的关注
output  = weights @ V(src)                 # 形状 (T_tgt, d_model)

权重矩阵是 (T_tgt, T_src) 的长方形，不再是方阵。每个目标位置都拥有一个"对整条源序列的关注分布"——这正是"翻译时逐词对齐"的几何表现。

4. 交叉注意力不需要因果掩码#

上一课说过，因果掩码只用于"禁止看未来"，而交叉注意力看的不是未来，而是另一条完全已知的序列——编码器早已把整条源句子读完了。因此在生成目标位置 t 时，让它看源句子的任意位置都是合法的。交叉注意力唯一可能需要的掩码是 padding 掩码（源序列里的 <pad> 不应被关注）。

二、可运行代码示例#

先写一个最小的交叉注意力，手动看清 Q、K、V 的来源和形状。

import torch
import torch.nn.functional as F

def cross_attention(query, key, value):
    """query 来自解码器，key/value 来自编码器"""
    d = query.shape[-1]
    scores = query @ key.T / (d ** 0.5)   # (T_tgt, T_src)
    weights = F.softmax(scores, dim=-1)    # 每个目标位置对源位置的关注分布
    return weights @ value, weights

d = 8
src = torch.randn(6, d)   # 编码器输出（源序列），长度 T_src=6
tgt = torch.randn(4, d)   # 解码器当前的表示（目标序列），长度 T_tgt=4

out, w = cross_attention(tgt, src, src)   # Q=解码器, K/V=编码器
print("交叉注意力权重形状:", w.shape)      # (4, 6)：目标长度 × 源长度
print("输出形状:", out.shape)              # (4, 8)：仍是目标长度 × d_model
print("每行关注分布之和:", w.sum(dim=-1))   # 全为 1

注意输出形状是 (4, 8)——长度由 Query（目标序列）决定，而不是由 Key/Value（源序列）决定。这也再次印证"Q 是主导方"。

接下来用 nn.MultiheadAttention 把同一个交叉注意力写成"生产可用"的形式，并和自注意力做一个对照：

import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=d, num_heads=2, batch_first=True)

# 交叉注意力：query 用目标序列，key/value 用源序列
cross_out, cross_w = mha(query=tgt.unsqueeze(0),     # (1, 4, 8)
                         key=src.unsqueeze(0),       # (1, 6, 8)
                         value=src.unsqueeze(0),
                         need_weights=True)
print("nn 交叉注意力输出:", cross_out.shape)          # (1, 4, 8)
print("nn 交叉注意力权重:", cross_w.shape)            # (1, 4, 6)

# 自注意力对照：query/key/value 全部用目标序列自己
self_out, self_w = mha(query=tgt.unsqueeze(0),
                       key=tgt.unsqueeze(0),
                       value=tgt.unsqueeze(0),
                       need_weights=True)
print("nn 自注意力权重:", self_w.shape)               # (1, 4, 4) 方阵

两相对比一目了然：自注意力的权重是 (4, 4) 方阵，交叉注意力是 (4, 6) 长方形，且长短边分别对应目标长和源长。

三、练习#

  1. 把 src 的长度改成 10、tgt 改成 3，重跑上面的交叉注意力，确认权重形状变为 (3, 10)，并解释为什么输出的"行数"始终等于目标长度。
  2. 写一个"多步对齐"的演示：固定同一个 src，让 tgt 依次是 3 个不同的查询向量，观察每次查询得到的关注分布如何变化，说明"不同目标词会关注源句子的不同部分"。
  3. 思考：如果交叉注意力的 Key/Value 不直接等于编码器最终输出，而是再经过一层线性变换（W_k、W_v），这与直接用原始输出有什么区别？参数量和表达能力如何变化？
  4. 在 nn.MultiheadAttention 里给交叉注意力传入一个源序列的 padding 掩码（key_padding_mask），观察被 pad 的源位置权重是否归零。
