资源利用率与排队：共享集群的公平与优先级#

这一节要解决什么#

第 2 节把"花多少钱"管住了，但钱花出去换回多少算力，取决于另外三件事：排队、利用率的口径、以及谁先跑。这三件事在本节都变成可算的量。

  1. "利用率 85%"是什么利用率？ 分配率 ρalloc​ 与有效利用率（MFU）是两回事，两者相乘才是 goodput。实测：ρalloc​=0.85, MFU=0.40 的集群 goodput =0.340，而 ρalloc​=0.60, MFU=0.55 的集群 goodput =0.330 —— 前者多占用 25 个百分点的卡，产出只多 3%。
  2. 利用率能不能提到 95%？ 能，但代价是指数级的。M/M/1 下 Wq​=λ/(μ(μ−λ))：ρ 从 0.80 到 0.95（相对 +18.75%），等待时间从 0.4000 h 涨到 1.9000 h（4.75 倍）；到 0.98 是 12.25 倍。
  3. 同样的利用率、同样的平均服务时间，为什么等待能差 4 倍？ 因为等待由方差决定：Pollaczek–Khinchine 公式 Wq​=λE[S2]/(2(1−ρ)) 里的 (1+CV2) 是乘数。实测三种服务分布（CV2=0/1/2.94）：Wq​=0.2000/0.4040/0.8316 h。
  4. 优先级公平吗？ 静态优先级把高优的等待从 54.00 min 压到 9.00 min，代价是低优涨到 90.00 min，而 ρ 加权总等待恰好不变（都是 54.00 min）。aging（等待超过 T 就提升）能把低优压回 45.88 min，代价是高优从 9.00 涨到 15.88 min。
  5. 该不该抢占？ 判据是一句算术：vhi​ΔWhi​>cpreempt​。实测 cpreempt​=40.00 元、vhi​=500 元/h → ΔW∗=4.80 min，提前不到 5 分钟的抢占是纯亏。顺带得到最优检查点间隔 T∗=2Cckpt​/(qV)​=0.7906 h。

一句话：利用率是一个应该被最小化的成本，而不是一个应该被最大化的指标。

一、概念：把"忙"与"有效"分开#

1.1 三个利用率的乘积#

有效算力产出goodput​​=卡被分配出去的比例ρalloc​​​×已分配的卡真的在算的比例MFU​​×没在等依赖/等数据/等通信的比例ηsched​​​

三个因子相乘的关系决定了：任何一个因子接近 1 都不代表产出接近 1。实测：

集群 ρalloc​ MFU goodput 元/有效卡·h
A：高分配率/低效率 0.85 0.40 0.340 7.35
B：低分配率/高效率 0.60 0.55 0.330 7.58
C：逼近满载/极低效率 0.95 0.28 0.266 9.40

A 与 B 的产出几乎相同，但 A 的分配率高 25 个点。C 看起来最"满"，实际最贵（9.40 元/有效卡·h vs 7.35）。"我们利用率 85%"这句话，在 A 构型下掩盖了 60% 的算力被浪费在低效率内核上。

1.2 排队：M/M/1 与那条不该被忽略的渐近线#

1.3 等待由方差决定，而不是由均值决定#

M/G/1 的 Pollaczek–Khinchine 公式：

Wq​=2(1−ρ)λE[S2]​=1−ρρ​⋅2E[S]​(1+CV2)

同一个 ρ=0.80、同一个 E[S]=0.1 h，只改服务时间的分布：

服务分布 CV2 ρ（实测） Wq​（P-K） Wq​（模拟）
确定性 D 0.00 0.8000 0.2000 0.1993
指数 M 1.00 0.8013 0.4040 0.4007
重尾（CV2≈3） 2.94 0.8071 0.8316 0.8397

等待时间差 4.16 倍。 这给出一个反直觉但可执行的推论：在提高利用率之前，先压服务时间的方差（把长作业拆短、大小作业分池、限制单作业时长）。压方差不需要停机，而提高利用率需要牺牲等待 —— 前者是免费的收益。

1.4 空闲但不可用：碎片化#

利用率还有一个隐藏的限定词：对哪种作业规模的利用率。同一份 18 个作业、总需求 43 卡，在 8 节点 × 8 卡上两种摆法：

共享池 best-fit：各节点剩余 0 0 0 0 0 5 8 8   → 最大连续空闲 8 卡
配额分区（每队2节点）：0 5 0 5 0 5 0 6          → 最大连续空闲 6 卡

两者空闲完全相同（21 卡，32.8%），但共享池里新提交的 8 卡作业可以立即开始，分区后必须等。原因不是资源不够，而是空闲卡在"错误的地方"。

这条与 §1.1 合起来给出利用率的完整定义：

可用性=多少卡被占用ρalloc​​​×碎片化的反面可拼成大块的能力​​

所以任何"把利用率提到 X%"的目标都必须同时写明作业规模分布，否则它会以"大作业永远排队"的方式被实现。

二、为什么这样设计：等待是有价格的#

2.1 容量不是越多越好，也不是越满越好#

设集群有 C 张卡、到达率 λ 作业/h、每个作业的等待价值 v 元/作业·小时，单位时间的总成本是：

cost(C)=容量成本ph​⋅C​​+等待成本λ⋅v⋅Wq​(C)​​,Wq​(C)=C(C−λ)λ​

（这里把"每卡一小时服务一个作业"当作归一化单位。）对 C 做网格搜索：

等待价值 v 最优容量 C∗ ρ∗ Wq∗​/h 成本/元·h−1 减到 0.8C∗ 加到 1.25C∗
50 55 0.582 0.0253 178.0 +16.3% +7.3%
200 74 0.432 0.0103 250.9 +10.0% +6.5%
800 105 0.305 0.0042 369.4 +7.6% +5.8%

三个可读的结论：

  1. 等待越贵，最优利用率越低：v=50 时 ρ∗=0.582，v=800 时 ρ∗=0.305。
  2. 最优利用率远低于直觉：即便等待很便宜（v=50），最优也只在 58%；因为 1/(1−ρ) 的斜率在 ρ>0.6 之后已经比线性容量成本更陡。
  3. 欠配比超配更贵，但两边都不贵：减到 0.8C∗ 多花 7.6%∼16.3%，加到 1.25C∗ 多花 5.8%∼7.3% —— 欠配的代价是超配的 1.3∼2.2 倍。这与第 2 节报童解"承诺量低于均值"是同一个非对称结构：成本函数在最优点附近是平的，所以容量规划不需要精确到小数点，但必须偏在安全的一侧。

反过来说：任何"把利用率提到 90%"的目标，都在隐含地给等待定了一个很低的价格。 这个隐含价格必须被说出来，否则争论会停在"要不要提利用率"这种无法回答的层面。

2.2 优先级：把等待的分布重新切分#

非抢占优先级的 M/G/1 等待时间（第 k 类）：

Wq(k)​=(1−∑i<k​ρi​)(1−∑i≤k​ρi​)∑i=1K​λi​E[Si2​]/2​

两类、同为指数服务（μ=10/h，λhi​=4、λlo​=5，ρ=0.90）：

策略 高优 Wq​ 低优 Wq​ ρ 加权均值
FCFS 54.00 min 54.00 min 54.00 min
静态优先级 9.00 min 90.00 min 54.00 min
+aging（T=0.5 h） 15.88 min 45.88 min —

三个要点：

  • 优先级不改变总等待量，只改变分布：两行的 ρ 加权均值都是 54.00 min。这是一个可验证的恒等式（∑ρi​Wi​/(∑ρi​) 对非抢占优先级不变），也是一个组织沟通的要点："我们给高优提速了"必然意味着"有人被拖慢了"。
  • 低优的等待被放大到 1.67 倍（90 vs 54 min）。如果低优是训练任务（可等待）而高优是在线推理（不可等待），这个交换是划算的；如果低优是另一种在线流量，这就是把事故从 A 团队搬到 B 团队。
  • aging 是一个可算的折中：设等待超过 Tage​ 的低优作业提升到高优类。对 M/M/1，等待尾巴恰好是指数分布 P(W>t)=e−t/W2​，于是提升率 =λlo​e−Tage​/W2​，把它加到高优类上再迭代求不动点：

λhi(n+1)​=λhi​+λlo​e−Tage​/W2(n)​,W1(n+1)​=1−ρ1(n)​∑i​λi(n)​E[Si2​]/2​,W2(n+1)​=Tage​+W1(n+1)​

λhi(n+1)​=λhi​+λlo​e−Tage​/W2(n)​,W1(n+1)​=1−ρ1(n)​∑i​λi(n)​E[Si2​]/2​,W2(n+1)​=Tage​+W1(n+1)​

Tage​=0.5 h 的不动点：W1​=15.88 min、W2​=45.88 min，触发提升的作业占低优的 52.0%。低优被压 49%，高优涨 76%（9.00→15.88）。 这是一个必须由业务方拍板的交换，而不是平台可以默认的。

说明：这一行的 aging 数是不动点近似（假定提升后立即被服务、等待尾巴指数），只保证方向与量级；要更准就得做完整的仿真。

2.3 抢占：一句可算的判据#

抢占的收益与成本都能写成钱：

高优提前的收益vhi​⋅ΔWhi​​​>被抢占作业白干的部分cpreempt​​​

其中 cpreempt​=2Tckpt​​×ncards​×ph​（期望损失是检查点间隔的一半）。实测：Tckpt​=1 h、ncards​=32、ph​=2.50 元/卡·h → cpreempt​=0.5×32×2.50=40.00 元；vhi​=500 元/h →

ΔW∗=50040.00​=0.08 h=4.80 min

ΔW∗=50040.00​=0.08 h=4.80 min

提前不到 4.80 分钟的抢占是纯亏。 这条判据把"要不要抢占"从一个价值观问题变成一个算术问题，也顺手给出了两个工程动作：

  1. 降低 cpreempt​：更频的检查点（但有上界，见下）；
  2. 只抢占关键路径上的作业：如果高优作业还要等另外三个资源，提前 10 分钟一文不值。

检查点间隔本身也有最优解。单位时间成本是"检查开销 + 期望重算"：

f(T)=TCckpt​​+2qVT​,T∗=qV2Cckpt​​​

f(T)=TCckpt​​+2qVT​,T∗=qV2Cckpt​​​

实测（Cckpt​=0.50 元、q=0.02/h、V=32×2.50=80 元/h）：T∗=2×0.50/(0.02×80)​=0.7906 h，最优成本 1.2649 元/h。

2.4 公平：DRF 与"平均分任务数"#

容量 (12,24)（GPU, CPU），A 的任务需要 (1,4)、B 的任务需要 (4,1)：

策略 A 任务数 B 任务数 GPU CPU A 主导份额 B 主导份额
DRF 渐进填充 4 2 12 18 0.667 0.667
平均分任务数 2 2 10 10 0.333 0.667

主导份额（dominant share）是"该租户使用的资源中，占集群比例最大的那一个"：

dshare(t)=rmax​Cr​ut,r​​

三个结论：

  1. "每个团队任务数相同"不等于公平：A 拿 2 个任务时的主导份额只有 0.333，B 是 0.667 —— 差 2 倍。按任务数收费/分配会系统性偏袒"任务大"的团队。
  2. DRF 把两者都推到 0.667（渐进填充：每次给主导份额最小的租户加一个任务，用全局容量约束检查可行性）。
  3. 代价是资源闲置：DRF 解下 GPU 打满（12/12）、CPU 只用 75%（18/24）。公平不是免费的，它以一个可测量的效率损失为代价 —— 平台的责任是把这笔损失算出来给业务方看，而不是宣称"公平即最优"。

三、怎么做：把排队做成日常运维的一部分#

3.1 三个必须分别记录的指标#

指标 定义 为什么必须单列
分配率 ρalloc​ 已分配卡时 / 总卡时 财务与配额
有效利用率 goodput ρalloc​×MFU×η 优化对象
等待时间分位数 Wq​ 的 p50/p90/p99，按作业规模分层 体验与容量规划

按作业规模分层是本节的硬要求：8 卡作业与 1 卡作业的等待时间分布完全不同（§1.4），把它们混在一个均值里，8 卡作业的排队会被完全掩盖。

3.2 容量规划的输入是 v，不是"目标利用率"#

流程：①估 v（作业等待一小时值多少钱：工程师时间 + 交付延迟 + 违约）；②用实际作业时长分布估 CV2；③解 minC​cost(C)；④把 C∗ 与 ρ∗ 一起报给业务方确认 v。

这四步里，最容易出错的是第①步，因为它没有技术答案。可行的做法是给出"隐含价格"：把当前"提高利用率到 X%"的方案反解出它隐含的 v，然后问一句"这个价格合理吗"。

3.3 队列设计的三条规则#

  1. 优先级只设 2∼3 级，每级必须有明确、可审计的准入规则（谁可以进高优）；
  2. 必须有防饿死机制：aging（本节 §2.2）或预留槽位（给低优留 1 个节点，不让高优占满）；
  3. 抢占必须先演练：cpreempt​ 不能是估算值，而是实测的"从检查点恢复需要多久"，否则判据 ΔW∗ 没有意义（这与第 2 章"回滚要在发布前演练"是同一件事）。

四、取舍与边界#

4.1 模型与现实的差距#

  • M/M/1 假设泊松到达与指数服务，真实集群两者都不是（作业时长重尾、到达有日内峰谷）。本节的做法是先用它算数量级，再用模拟校核；不要用它做容量决策的最终依据，除非你会算 §1.3 的 CV2；
  • 非抢占优先级的公式假定服务时间与优先级无关，真实系统里高优作业往往更短（在线推理 vs 训练），这会让真实差距比公式更小。

4.2 "抢占"破坏可复现性#

被抢占后重启的作业，其浮点累加顺序、数据读入顺序都可能变化（第 1 章的环境确定性等级）。如果一次实验的结论要可复现，被抢占过的运行必须在元数据里标记，否则你会得到"同一份配置两次结果不同"的悬案。

4.3 公平与效率的 Pareto 面#

DRF 的公平是在主导资源维度上的公平，它不保证：

  • 完成时间公平（大作业天然更晚完成）；
  • 吞吐公平（小作业多的团队拿到更多任务数）；
  • 组织公平（一个团队内部还有子团队）。

所以要明确公布"我们在哪个维度上公平"。没有写清楚维度的公平声明，等于没有公平声明。

4.4 边界：本节不做的事#

  • 不做拓扑感知调度（NVLink/InfiniBand 的亲和性）——那是并行策略侧的问题；
  • 不做能耗（电价、冷却）——它与成本核算同构，但时间尺度完全不同；
  • 不给"最优利用率"的具体数值：它是 v 的函数，本节给的是求解流程。

def wq_mm1(lam: float, mu: float = MU) -> float:
    """M/M/1 平均排队等待时间。"""
    return lam / (mu * (mu - lam))


def wq_pk(lam: float, e_s2: float, rho: float) -> float:
    """M/G/1 的 Pollaczek–Khinchine 平均等待时间。"""
    return lam * e_s2 / (2.0 * (1.0 - rho))


def lindley(lam: float, sampler, n: int, rng: random.Random) -> tuple[float, float, float]:
    """单服务器 G/G/1 的 Lindley 递推：返回 (平均等待, 平均服务, 平均 E[S²])。"""
    w = 0.0
    tot_w = 0.0
    tot_s = 0.0
    tot_s2 = 0.0
    for _ in range(n):
        s = sampler(rng)
        a = rng.expovariate(lam)
        w = max(0.0, w + s - a)      # 下一个作业的排队等待
        tot_w += w
        tot_s += s
        tot_s2 += s * s
    return tot_w / n, tot_s / n, tot_s2 / n


# ==================================================================== [0] 自检
def self_check() -> None:
    rng = random.Random(SEED)
    lam = 8.0
    w_sim, s_bar, s2_bar = lindley(lam, lambda r: r.expovariate(MU), N_SIM, rng)
    w_exact = wq_mm1(lam)
    assert abs(w_sim / w_exact - 1.0) < 0.05, (w_sim, w_exact)
    # M/M/1 的 E[S²] = 2/μ² → P-K 必须退回 M/M/1
    assert abs(wq_pk(lam, 2.0 / MU ** 2, lam / MU) - w_exact) < 1e-12
    # Little 定律：Lq = λ·Wq
    assert abs(lam * w_exact - 3.2) < 1e-12
    print("[0] 自检（λ=8, μ=10, ρ=0.80）")
    print(f"    解析 Wq = λ/(μ(μ-λ)) = {w_exact:.6f} h")
    print(f"    模拟 Wq（Lindley，{N_SIM:,} 作业）= {w_sim:.6f} h"
          f"  相对误差 {(w_sim/w_exact-1)*100:+.2f}% ✅")
    print(f"    样本 E[S] = {s_bar:.6f} h（理论 {1/MU:.6f}）"
          f"｜E[S²] = {s2_bar:.6f}（理论 {2/MU**2:.6f}）")
    print(f"    P-K 在指数服务下退回 M/M/1 ✅；Little 定律 Lq = λWq = {lam*w_exact:.4f} 作业 ✅")


# ==================================================================== [1] 利用率
def rho_sweep() -> list[tuple[float, float, float, float, float]]:
    rng = random.Random(SEED + 1)
    rows = []
    for rho in RHO_GRID:
        lam = rho * MU
        w_ex = wq_mm1(lam)
        w_sim, _, _ = lindley(lam, lambda r: r.expovariate(MU), N_SIM, rng)
        rows.append((rho, lam, w_ex, w_sim, lam * w_ex))
    return rows


# ==================================================================== [2] CV²
def service_dists() -> list[tuple[str, callable]]:
    def det(r: random.Random) -> float:
        return 0.1

    def expo(r: random.Random) -> float:
        return r.expovariate(10.0)

    def heavy(r: random.Random) -> float:
        # 两相超指数：一半作业 0.2 h，一半 ~0（E[S]≈0.1，CV²≈3）
        return r.expovariate(5.0) if r.random() < 0.5 else r.expovariate(1000.0)

    return [("确定性 D", det), ("指数 M", expo), ("重尾（CV²≈3）", heavy)]


def cv_table() -> list[tuple[str, float, float, float, float]]:
    rng = random.Random(SEED + 2)
    rows = []
    lam = 0.8 * MU
    for name, fn in service_dists():
        w_sim, s_bar, s2_bar = lindley(lam, fn, N_SIM, rng)
        rho = lam * s_bar
        cv2 = s2_bar / (s_bar ** 2) - 1.0
        rows.append((name, cv2, rho, wq_pk(lam, s2_bar, rho), w_sim))
    return rows

def place(jobs: list[tuple[str, int]], nodes: list[int],
          pools: dict[str, list[int]] | None) -> tuple[list[int], int, int]:
    """best-fit；pools 给定时，每个团队只能用自己的节点（配额分区）。"""
    for team, size in jobs:
        allowed = pools[team] if pools else range(len(nodes))
        best = -1
        for i in allowed:
            if nodes[i] >= size and (best < 0 or nodes[i] < nodes[best]):
                best = i
        if best < 0:
            return nodes, size, sum(nodes)
        nodes[best] -= size
    return nodes, 0, sum(nodes)


def fragmentation() -> dict:
    """同一份作业清单，两种摆法：共享池 best-fit vs 配额分区后 best-fit。"""
    sh_nodes, _, _ = place(JOBS, [8] * 8, None)
    pools = {"t1": [0, 1], "t2": [2, 3], "t3": [4, 5], "t4": [6, 7]}
    pt_nodes, blocked, free_at = place(JOBS, [8] * 8, pools)
    return {"shared": sh_nodes, "part": pt_nodes, "blocked": blocked,
            "free_at": free_at, "demand": sum(sz for _, sz in JOBS),
            "shared_blocked": 0 if 8 in [8 - x for x in sh_nodes] or max(sh_nodes) >= 8 else -1}


# ==================================================================== [4] 容量优化
def capacity_opt(v: float) -> tuple[int, float, float]:
    best = None
    for c in range(33, 400):
        rho = LAMBDA_JOB / c
        if rho >= 1.0:
            continue
        cost = c * P_GPU_H + LAMBDA_JOB * v * wq_mm1(LAMBDA_JOB, float(c))
        if best is None or cost < best[2]:
            best = (c, rho, cost)
    return best


# ==================================================================== [5] 优先级
def priority_two_class(mu: float = MU) -> dict:
    rho1, rho2 = LAM_HI / mu, LAM_LO / mu
    num = (LAM_HI + LAM_LO) * (2.0 / mu ** 2) / 2.0
    w1 = num / (1.0 - rho1)
    w2 = num / ((1.0 - rho1) * (1.0 - rho1 - rho2))
    fcfs = (LAM_HI + LAM_LO) * (2.0 / mu ** 2) / (2.0 * (1.0 - rho1 - rho2))
    return {"rho1": rho1, "rho2": rho2, "w1": w1, "w2": w2, "fcfs": fcfs, "num": num}


def aging_fixed_point(t_age: float, pr: dict, iters: int = 60) -> tuple[float, float, float]:
    """aging：等待超过 t_age 的低优作业提升到高优类；迭代求不动点。"""
    w2 = pr["w2"]
    for _ in range(iters):
        p_promote = math.exp(-t_age / w2)          # M/M/1 的等待尾巴恰好是指数
        lam1 = LAM_HI + LAM_LO * p_promote
        rho1 = lam1 / MU
        num = (lam1 + LAM_LO * (1 - p_promote)) * (2.0 / MU ** 2) / 2.0
        w1 = num / (1.0 - rho1)
        w2_new = t_age + w1
        if abs(w2_new - w2) < 1e-12:
            w2 = w2_new
            break
        w2 = 0.5 * w2 + 0.5 * w2_new
    return w1, w2, p_promote


# ==================================================================== [6] 抢占
def preemption() -> dict:
    t_ckpt = 1.0
    lost = t_ckpt / 2.0 * N_CARDS * P_GPU_H          # 期望白干的卡·小时价值
    d_thr = lost / V_HI                              # 只值得抢占的最小提前量
    v_cards = N_CARDS * P_GPU_H
    t_star = math.sqrt(2.0 * CKPT_COST / (Q_PREEMPT * v_cards))
    costs = {t: CKPT_COST / t + Q_PREEMPT * v_cards * t / 2.0
             for t in (0.25, 0.5, 0.79, 1.0, 1.58, 2.0, 4.0)}
    return {"t_ckpt": t_ckpt, "lost": lost, "d_thr": d_thr,
            "v_cards": v_cards, "t_star": t_star, "costs": costs,
            "best_cost": CKPT_COST / t_star + Q_PREEMPT * v_cards * t_star / 2.0,
            "always": math.sqrt(2.0 * CKPT_COST * Q_PREEMPT * v_cards)}


# ==================================================================== [7] DRF
def drf(cap: tuple[float, float], tasks: list[tuple[float, float]]) -> dict:
    """渐进填充：每次把「主导份额最小」的租户加一个任务，直到两个都加不下。"""
    use = [[0.0, 0.0], [0.0, 0.0]]
    alloc = [0, 0]

    def dshare(t: int) -> float:
        return max(use[t][r] / cap[r] for r in (0, 1))

    while True:
        done = True
        for t in sorted((0, 1), key=dshare):
            if all(sum(use[k][r] for k in (0, 1)) + tasks[t][r] <= cap[r]
                   for r in (0, 1)):
                for r in (0, 1):
                    use[t][r] += tasks[t][r]
                alloc[t] += 1
                done = False
                break
        if done:
            break
    shares = [max(use[0][0] / cap[0], use[0][1] / cap[1]),
              max(use[1][0] / cap[0], use[1][1] / cap[1])]
    total = [use[0][r] + use[1][r] for r in (0, 1)]
    return {"alloc": alloc, "used": total, "shares": shares, "own": use}


def equal_tasks(cap: tuple[float, float], tasks: list[tuple[float, float]]) -> dict:
    n = 0
    while all((n + 1) * (tasks[0][r] + tasks[1][r]) <= cap[r] for r in (0, 1)):
        n += 1
    used = [n * tasks[0][r] + n * tasks[1][r] for r in (0, 1)]
    shares = [max(n * tasks[0][0] / cap[0], n * tasks[0][1] / cap[1]),
              max(n * tasks[1][0] / cap[0], n * tasks[1][1] / cap[1])]
    return {"n": n, "used": used, "shares": shares}

小结#

  • 利用率是三个因子的乘积：goodput=ρalloc​×MFU×η。实测 A（0.85×0.40）与 B（0.60×0.55）产出几乎相同（0.340 vs 0.330），但 A 多占 25 个点的卡。
  • 利用率是应该被最小化的成本：Wq​=ρ/(μ(1−ρ))；ρ 从 0.80 到 0.95（+18.75%）→ Wq​ 涨 4.75 倍（0.4000→1.9000 h），到 0.98 是 12.25 倍。
  • 模拟会低估高利用率下的等待：ρ=0.98 时 200,000 作业只测到 4.1823 h（解析 4.9000）—— 尾巴重，样本不够。
  • 等待由方差决定：Wq​=1−ρρ​⋅2E[S]​(1+CV2)；同样 ρ、同样 E[S]，CV2=0/1/2.94 给出 0.2000/0.4040/0.8316 h（差 4.16 倍）。先压方差，再谈提利用率。
  • 最优容量由 v 决定：v=50→C∗=55,ρ∗=0.582；v=800→C∗=105,ρ∗=0.305。超配 25% 只多花 5.8%∼7.3%，欠配的代价大一个量级。
  • 空闲 ≠ 可用：同一份作业，共享池最大连续空闲 8 卡（8 卡作业能跑），配额分区只有 6 卡（必须等），两者总空闲都是 21 卡（32.8%）。
  • 优先级只改变等待的分布：FCFS 与静态优先级的 ρ 加权均值都是 54.00 min；高优 54→9 min，低优 54→90 min（×1.67）。
  • aging 是可算的折中：不动点 W1​=15.88 min、W2​=45.88 min（Tage​=0.5 h，提升率 52.0%）；低优压 49%，高优涨 76%。
  • 抢占判据：vhi​ΔWhi​>cpreempt​；cpreempt​=(Tckpt​/2)ncards​ph​=40.00 元 → ΔW∗=4.80 min。
  • 最优检查点间隔 T∗=2Cckpt​/(qV)​=0.7906 h（成本 1.2649 元/h）；"越勤越安全"是错的，且曲线在 T∗ 附近很平。
