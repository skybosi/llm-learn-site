算法-调度分离：Halide / TVM 的核心思想#

第 5 课判完"哪些算子能融"，交出来的是一个融合后的张量程序：它说清了每个输出由哪些输入算出，却没说该按什么顺序算。而顺序决定性能——y[i,j] = Σ_k a[i,k]·b[k,j] 能展开成十几种都正确的循环嵌套，访存量相差一个数量级。本课讲清"算法"与"调度"为什么必须分开，并用一个两百行的模型把差异算出来。

一、概念讲解#

1. 一段循环同时表达两件事，是问题的根源#

看这段手写循环：

for (int i = 0; i < M; i++)
  for (int j = 0; j < N; j++)
    for (int k = 0; k < K; k++)
      C[i][j] += A[i][k] * B[k][j];

前两行是算什么（对每个输出元素求一遍和），第三行是怎么算（按 k 逐个累加）。想试"先分块再算"就得重写整个函数，想试十种顺序就写十份代码——优化空间被代码结构锁死了。

算法-调度分离（algorithm–schedule separation）把这两件事拆成可独立修改的两部分：算法只描述"每个输出由哪些输入、按什么表达式算出"，调度只描述"索引以什么顺序、什么粒度被遍历"。Halide 用它描述图像流水线，TVM 把它搬进深度学习——算法用 te.compute 写，调度用 sch.split / reorder / tile / bind 写。换来的是同一份算法可被自动枚举大量实现，这正是后两课自动调优的前提。

2. 一个最小的模型：算法是数据，调度也是数据#

算法 Program：维度表 {i: M, j: N, k: K}、归约维 ('k',)、输出名与访问模式。调度 Schedule：循环次序、各维 tile 大小、归约维是否提前、向量宽度、绑核维、展开次数。两者都不含表达式树和机器码，全是可打印、可比较的数据——于是能打印成循环嵌套、喂给代价模型打分（第 2、3 课）、序列化进调优日志（第 4 课）。

3. 五种基本变换，对应 CUDA 的五种优化手法#

调度的词汇表不大，但与前一门课的手工优化一一对应：

调度原语 做什么 CUDA 上的对应物
split / tile 把一个索引拆成外层+内层，合起来构成 tile shared memory 分块、二维线程块
reorder 改变循环由外向内的顺序 交换内外层、把归约维提到最外做流水
vectorize 最内层一个索引同时算 N 个元素 float4 / ldmatrix 向量化访存
bind / parallel 把某个索引绑到线程块或线程 blockIdx.x / threadIdx.x
unroll 把最内层展开若干次 #pragma unroll、寄存器级复用

这些变换互相耦合：tile 变大增加片上复用也增加寄存器压力（第 5 课算融合代价时已见过）；向量化省指令但要求最内层访存连续；归约维提前能让流水线跑起来，代价是中间结果要落地。所以调度空间不是"五个开关随便拨"，而是一张有峰有谷的地形图——这才是得靠搜索的原因。

4. 成本从哪来：三类账#

模型只算三类账。片上搬运：每个输出 tile 要把 a 的 ti×K、b 的 K×tj 搬进寄存器或共享内存，tile 越大、每元素复用越多、总搬运越少。跨层搬运：并行维被切成块后块间不再复用，驻留量 = 块内尺寸 × K；超过 L2 容量时同一份数据会被反复从 DRAM 取回——这是"分块省带宽"的可算形式。指令数：2MNK / vec。模型里的常数（L2 容量、每元素字节数）只是明示假设，换机器只改这两个数，结论方向不变；下文数字因此只是趋势与量级，不是任何显卡的实测值。

5. 常见坑#

  • 把调度当算法改：算法里写死"分成 64 块"后，就没法再试 32 或 128。
  • 只盯一个原语调参：tile 从 16 改到 64 能带来数倍收益时，unroll 从 4 改到 8 可能是负收益——收益不独立。
  • 用未分块模型估性能：不分块时复用推理失效，估出的算术强度与真值差一个数量级。
  • 忘了合法性：归约维不能被并进向量化维、向量化维必须连续访存；不合法调度在真实编译器里直接编译失败，本课模型只算代价、不查合法性。

二、可运行代码示例#

模型只用 numpy（本机 python3.10 + numpy 1.26.2 实跑，无需 GPU）：execute 按调度解释执行，用结果一致证明调度不改语义；analyze 算三类账。

# ---- 算法-调度分离的最小模型（纯 Python + numpy；第 6 章第 1 课）----
# 算法：只说"算什么"；调度：只说"怎么算"。两者分开，才能拿同一个算法比不同调度。
import numpy as np


class Program:
    """算法：y[i,j] = sum_k A[i,k] * B[k,j]，输出维 i/j 并行，归约维 k。"""

    def __init__(self, name, dims, reds, out, terms):
        self.name, self.dims, self.reds, self.out, self.terms = name, dims, reds, out, terms


def matmul(M, K, N):
    return Program('matmul', {'i': M, 'j': N, 'k': K}, ('k',), 'y',
                   [('a', ('i', 'k')), ('b', ('k', 'j'))])


class Schedule:
    """调度：循环次序 + 每个维的 tile 大小 + 把哪个归约维提到最外 + 向量宽度 + 绑核维。"""

    def __init__(self, order, tiles, file_loop=None, vec=1, parallel=(), unroll=0, name=''):
        self.order, self.tiles = tuple(order), tuple(tiles)
        self.file_loop, self.vec = file_loop, vec
        self.parallel, self.unroll, self.name = tuple(parallel), unroll, name

    def loops(self):
        """展开成由外到内：(循环名, outer|inner|plain, 算法索引)。"""
        d = list(self.order)
        if self.file_loop is not None:            # file_loop：把归约维提前（TVM 的 reorder/import）
            d.remove(self.file_loop)
            d.insert(0, self.file_loop)
        out = []
        for v in d:
            t = self.tiles[self.order.index(v)]
            out += [(f'{v}#o', 'outer', v), (f'{v}#i', 'inner', v)] if t > 1 else [(v, 'plain', v)]
        return out

    def text(self, prog):
        """调度的文本形态：这就是"同一算法、不同循环嵌套"的可读证据。"""
        lines, depth = [], 0
        for nm, kind, v in self.loops():
            idx = self.order.index(v)
            ann = []
            if v in self.parallel:
                ann.append('bind=gpu')
            if v in prog.reds and self.unroll:
                ann.append(f'unroll={self.unroll}')
            if self.vec > 1 and kind == 'inner':
                ann.append(f'vectorize={self.vec}')
            lines.append('  ' * depth + f'for {nm:<5} # {kind:<5} ' + ' '.join(ann))
            depth += 1
        lines.append('  ' * depth + f'{prog.out}[i,j] = a[i,k] * b[k,j]')
        return '\n'.join(lines)


def execute(prog, sched, env):
    """按调度给定的循环嵌套执行（最内两层用 numpy 向量化；语义与逐点循环一致）。"""
    M, N, K = prog.dims['i'], prog.dims['j'], prog.dims['k']
    ti = sched.tiles[sched.order.index('i')]
    tj = sched.tiles[sched.order.index('j')]
    res = np.zeros((M, N), dtype=env['a'].dtype)
    for io in range(0, M, ti):
        for jo in range(0, N, tj):
            acc = res[io:io + ti, jo:jo + tj].copy()
            for k in range(K):
                acc += np.outer(env['a'][io:io + ti, k], env['b'][k, jo:jo + tj])
            res[io:io + ti, jo:jo + tj] = acc
    return res


def analyze(prog, sched, l2=131072, elem=4):
    """解析访存模型（只给趋势与量级，不是实测）。三条账：
      ① 片上复用：最内层是归约维时，每个输出 tile 只需把 a 的 ti×K、b 的 K×tj 从 L2 搬进寄存器；
         若归约维没被分块（算法维度 K 整体在内层），则退化成"每个 (输出块, k) 都重读一个完整操作数"。
      ② 跨层搬运：并行维会被切成块，块与块之间不再复用，驻留量 = 块内尺寸 × K（或 K × 块内 j）。
         驻留量超过 L2 就按超出倍数从 DRAM 补搬 —— 这就是"分块省带宽"的可算形式。
      ③ 表达式里不含任何硬件常数，只含维度与 tile；换成真实硬件后结论方向不变。"""
    d = prog.dims
    M, N, K = d['i'], d['j'], d['k']
    ti = sched.tiles[sched.order.index('i')]
    tj = sched.tiles[sched.order.index('j')]
    tk = sched.tiles[sched.order.index('k')]
    par = set(sched.parallel)
    if ti == 1 and tj == 1 and tk == 1:            # 未分块：没有可驻留的 tile
        onchip = (M * K * N + K * N * M) * elem
        ws_a, ws_b = M * K, K * N
    else:                                          # 分块：块内复用
        outer = (M / ti) * (N / tj)
        onchip = outer * (ti * K + K * tj) * elem
        ws_a = (ti if 'i' in par else M) * K
        ws_b = K * (tj if 'j' in par else N)

    def dram_side(ws):
        """装得下 L2 就只交一次强制读写；装不下按超出倍数补。"""
        return (M * K + K * N) * elem * max(1.0, ws / l2)

    dram = dram_side(ws_a) + dram_side(ws_b) + M * N * elem
    flops = 2 * M * N * K
    return dict(dram=dram, onchip=onchip, ai=flops / dram,
                ws_a=ws_a, ws_b=ws_b, spill_a=ws_a / l2, spill_b=ws_b / l2)


if __name__ == '__main__':
    rng = np.random.default_rng(0)
    env = {'a': rng.random((128, 128)), 'b': rng.random((128, 128))}
    small = matmul(128, 128, 128)
    ref = env['a'] @ env['b']

    scheds = [
        Schedule(('i', 'j', 'k'), (1, 1, 1), parallel=('i', 'j'), name='无分块 ij k'),
        Schedule(('j', 'i', 'k'), (1, 1, 1), parallel=('j', 'i'), name='仅换次序 ji k'),
        Schedule(('i', 'j', 'k'), (64, 64, 1), parallel=('i', 'j'), vec=4, name='tile 64 + 向量化'),
    ]
    print('=== 1. 同一算法、三条调度：循环嵌套与误差 ===')
    for s in scheds:
        y = execute(small, s, env)
        err = np.abs(y - ref).max()
        print(f'--- {s.name}（与 numpy 最大差 {err:.2e}）---')
        print(s.text(small))

    print('\n=== 2. 同一个算法在 2048³ 上的解析代价（不是实测，只看趋势）===')
    big = matmul(2048, 2048, 2048)
    big_scheds = scheds + [
        Schedule(('i', 'j', 'k'), (64, 64, 1), parallel=('j',), vec=4, name='tile 64 只并 j'),
        Schedule(('i', 'j', 'k'), (64, 64, 1), parallel=('i',), vec=4, name='tile 64 只并 i'),
    ]
    print(f"{'调度':<18}{'驻留(元素)':>20}{'DRAM MB':>10}{'片上 MB':>12}{'AI(flop/B)':>12}")
    for s in big_scheds:
        a = analyze(big, s)
        ws = f'{a["ws_a"]}/{a["ws_b"]}'
        print(f'{s.name:<18}{ws:>20}{a["dram"] / 1e6:>10.1f}'
              f'{a["onchip"] / 1e6:>12.1f}{a["ai"]:>12.2f}')
    print('  参考：算法本身的强制访存 = (M*K + K*N + M*N)*4B = '
          f'{(2048 * 2048 * 3) * 4 / 1e6:.1f} MB')

运行结果（Python 3.10.14 + numpy 1.26.2）：

=== 1. 同一算法、三条调度：循环嵌套与误差 ===
--- 无分块 ij k（与 numpy 最大差 1.42e-14）---

  for j     # plain bind=gpu
    for k     # plain 
      y[i,j] = a[i,k] * b[k,j]
--- 仅换次序 ji k（与 numpy 最大差 1.42e-14）---
for j     # plain bind=gpu
  for i     # plain bind=gpu
    for k     # plain 
      y[i,j] = a[i,k] * b[k,j]
--- tile 64 + 向量化（与 numpy 最大差 1.42e-14）---
for i#o   # outer bind=gpu
  for i#i   # inner bind=gpu vectorize=4
    for j#o   # outer bind=gpu
      for j#i   # inner bind=gpu vectorize=4
        for k     # plain 
          y[i,j] = a[i,k] * b[k,j]

四条可核对的结论：

  1. 调度不改结果：三条调度的最大绝对差都是 1.42e-14，量级等于机器精度——调度是"保语义的重写"，这条先成立，自动搜索才有意义。
  2. 分块是最大的一笔：同在 2048³ 上，未分块与 tile 64 的 DRAM 搬运是 2164 MB 对 83.9 MB（约 26 倍），片上搬运 68719 MB 对 1073 MB（约 64 倍）。
  3. 向量化不改访存、只改指令：vec 不出现在访存账里（有意简化），只影响指令数；硬件上还要求最内层连续访存，所以它是最后一个拨的开关。
  4. 并行维的选择会反噬：两侧都并行时驻留量 131072/131072；只并行 j 时 a 的驻留量涨到 4194304（K×N 全体），DRAM 搬运从 83.9 MB 反弹到 1124 MB。"哪个维绑核"不是并行度问题，而是复用边界问题。

三、练习#

  1. 实现：给 Schedule.loops() 加合法性检查：若 file_loop 指向的不是归约维，或 parallel 里同时含归约维与输出维，就抛异常说明原因。再让 execute 支持 tk（归约维也分块）的调度。
  2. 解释：为什么"仅换次序 ji k"在本课模型里与"ij k"代价相同，在真实 GPU 上却可能差很多？提示：本课只看最内层是哪个索引，不看块间调度顺序（Triton 的 GROUP_SIZE_M 管的正是后者）。
  3. 对比/验证：把 analyze 的 l2 依次改成 32768、524288 重跑第 2 节，记录哪些调度的 DRAM 账变了、哪些没变，说明"驻留量超过 L2"在什么区间最灵敏。
  4. 思考：这种分离把优化空间变成显式数据，代价是算法里不能再写实现专有的技巧（如 flash attention 的在线 softmax 重缩放）。这类"算法本身依赖调度"的情况该算哪一边？
