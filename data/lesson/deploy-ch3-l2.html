多卡集群部署#

上一课用 TP 把大模型拆到多卡，这一课把视野从"单机多卡"扩展到"多机多卡集群"，并回答一个更实际的问题：当流量大到单实例扛不住时，怎么用多副本 + 负载均衡横向扩展。这里要分清三件事——并行（拆一个模型）、副本（复制多个服务）、集群（把卡组织起来调度）。学完本课，你应当能区分张量/流水线/数据并行，能搭起单机多卡与多机 Ray 集群，并理解多副本 + LB 的横向扩展方式。

一、概念讲解#

1. 三种"多卡"根本不是一回事#

方式 拆什么 解决什么 典型参数/机制
张量并行 TP 单层权重按维度拆 单卡装不下模型 --tensor-parallel-size
流水线并行 PP 按层切成几段，逐段流过 模型层数多、跨机通信少 --pipeline-parallel-size
数据并行 / 多副本 DP 复制多个完整服务 流量大、吞吐不够、高可用 多实例 + 负载均衡

要点：TP/PP 解决"装得下"，DP 解决"扛得住"。三者可以组合（TP=2 + 4 副本），vLLM 通过 --data-parallel-size 或直接起多个进程 + LB 实现。

2. 单机多卡：最简形态#

单机 8 卡是绝大多数中小规模的上限。单机内用 NVLink 互连（比跨机 PCIe/以太网快一个数量级），所以能单机解决就别跨机：

# 单机 4 卡 TP=4 跑 70B
vllm serve Qwen/Qwen2.5-72B-Instruct --tensor-parallel-size 4 \
    --gpu-memory-utilization 0.9 --max-model-len 8192

启动前用 nvidia-smi topo -m 确认卡间拓扑，优先让 TP 组落在 NVLink 直连的卡上。

3. 多机多卡：Ray 集群#

单机 8 卡不够（超大模型或超大流量）时，用 Ray 把多台机器的卡聚合成一个逻辑集群，vLLM 通过 Ray 调度跨机 TP/PP：

# 每台机器（头节点 + 工作节点）都执行
ray start --head --num-gpus=8            # 头节点
ray start --address='<头节点IP>:6379' --num-gpus=8   # 工作节点加入

# 任意节点上，用 Ray 启动 vLLM 跨机并行
vllm serve Qwen/Qwen2.5-72B-Instruct \
    --tensor-parallel-size 8 \           # 跨 2 台机器各 4 卡
    --gpu-memory-utilization 0.9

跨机通信走网络（NCCL over IB/以太网），带宽远低于 NVLink，所以跨机 TP 的通信开销很大——这也是为什么跨机场景更倾向"TP 留单机内 + 多副本"而不是"超大 TP 跨机"。

4. 多副本 + 负载均衡：横向扩展的常态#

生产里最常用的扩容不是加 TP，而是多副本 + 负载均衡（LB）：

用户请求 -> 负载均衡器 -> 副本1 (TP=2) / 副本2 (TP=2) / 副本3 (TP=2)
  • 每副本是一个独立 vLLM 实例（可能各自 TP=2）；
  • LB 按轮询/最少连接分发请求；
  • 副本数 = 峰值吞吐 / 单副本达标吞吐（第一章的容量规划公式）；
  • 多副本同时带来高可用：单个副本挂了，LB 自动摘除。

vLLM 在 Kubernetes 上常配 HPA 按 QPS/延迟自动扩缩容，闲时缩到 0、忙时弹上去。

二、可运行示例#

示例 1：单机多卡（TP=2 双副本 + 简单负载均衡）#

# 同机两张 A100-80G：先起 TP=2 单实例验证
vllm serve Qwen/Qwen2.5-72B-Instruct-AWQ --quantization awq \
    --tensor-parallel-size 2 --host 0.0.0.0 --port 8000

# 横向扩展：再起第二个副本（TP=2）到 8001，两张卡跑两个 70B 副本需 4 卡，这里示意
vllm serve Qwen/Qwen2.5-72B-Instruct-AWQ --quantization awq \
    --tensor-parallel-size 2 --host 0.0.0.0 --port 8001

示例 2：用 Python 做一个最简轮询负载均衡#

# -*- coding: utf-8 -*-
# 最简轮询负载均衡：把请求轮流分发到多个 vLLM 副本
import itertools, httpx

REPLICAS = ["http://localhost:8000", "http://localhost:8001"]
pool = itertools.cycle(REPLICAS)          # 轮询游标

def chat(prompt: str, max_tokens: int = 64):
    url = next(pool) + "/v1/chat/completions"
    resp = httpx.post(url, json={
        "model": "Qwen/Qwen2.5-72B-Instruct-AWQ",
        "messages": [{"role": "user", "content": prompt}],
        "max_tokens": max_tokens,
    }, timeout=120)
    return resp.json()["choices"][0]["message"]["content"]

for i in range(6):                          # 6 个请求应均匀落到两个副本
    print(f"请求{i} -> {chat('一句话介绍张量并行')[:20]}...")

示例 3：多机 Ray 集群启动命令#

# 头节点（机器 A，IP 10.0.0.1）
ray start --head --num-gpus=8 --dashboard-host 0.0.0.0

# 工作节点（机器 B、C）
ray start --address='10.0.0.1:6379' --num-gpus=8

# 集群就绪后，任意节点跨机跑 TP=8（2 台 × 4 卡）
vllm serve Qwen/Qwen2.5-72B-Instruct --tensor-parallel-size 8 \
    --gpu-memory-utilization 0.9 --max-model-len 8192

# 查看集群与拓扑
ray status              # 节点、GPU 数、资源使用
nvidia-smi topo -m      # 单机内卡间拓扑

三、练习#

  1. 组合并行：一个 70B 模型要服务 200 峰值 QPS，单副本（TP=2）达标吞吐 400 token/s。用第一章的公式计算需要多少个 TP=2 副本，并画出"LB + N 副本"的拓扑。
  2. 单机 vs 跨机：解释为什么"TP=8 跨 2 机"的吞吐通常不如"TP=4 单机 × 2 副本"，从通信带宽角度说明，并给出你会优先选哪个。
  3. 加健康检查：给示例 2 的 LB 加上"副本探活 + 失败摘除"，说明生产 LB 为什么必须有健康检查，而不只是轮询。
  4. Ray 排障：ray start 报"地址不可达/端口占用"时，写出你的排查顺序（先查 6379 端口、再查头节点 IP 是否可达、再看防火墙/安全组）。
