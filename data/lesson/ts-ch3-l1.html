时间特征工程#

统计模型（ARIMA、指数平滑）把"时间依赖"内建在模型结构里；而机器学习的回归/树模型本身不认时间，它只看得懂一张 (X, y) 表格。要让梯度提升、随机森林这些利器做预测，唯一的办法是把时间信息手工变成特征。这一课讲怎么把一条序列"摊平"成监督学习表格，以及其中最容易踩的坑——特征泄漏。

一、概念讲解#

1. 核心思想：把预测转成监督学习#

时间序列预测的监督学习表述是：用过去的信息，预测未来某期的值。给定序列 y_1..y_T，我们想预测 y_{t+h}，就把"截至 t 期为止能看到的一切"打包成一行特征 X_t，把 y_{t+h} 当作标签 y：

样本 i：X_i = 截至 t_i 期可用的特征，y_i = y_{t_i + h}

"截至 t 期可用"这半句是红线：任何要用到 t+1 期以后信息的特征，都是泄漏（第 3 课会严格讨论其危害）。特征工程的本质，就是诚实且充分地刻画"在 t 时刻，我们到底知道什么"。

2. 三大类时间特征#

（1）滞后特征 Lag#

最直接：把过去若干期的观测值本身搬进表格。

lag_1 = y_{t-1},  lag_2 = y_{t-2},  ...,  lag_k = y_{t-k}

滞后特征回答"最近几期是什么水平"。它是最强的信号，尤其对短程依赖强的序列。滞后期数 k 是超参数：太小抓不住长记忆，太大则维度膨胀、噪声增多。

（2）滑动窗口统计 Rolling#

对过去一个窗口做聚合，把"局部形态"总结成几个数：

roll_mean_7 = 最近 7 期均值
roll_std_7  = 最近 7 期标准差
roll_min/max/median = 最近 k 期的极值、中位数

滑动均值捕捉"近期水平"，滑动标准差捕捉"近期波动"。窗口要覆盖有意义的尺度（如 7 天、30 天），且只能统计过去的窗口，不能把未来也卷进来。

（3）日历特征 Calendar#

时间戳本身携带大量规律，可以拆出：

  • 数值型：年、月、日、小时、星期几（dayofweek）、一年中的第几天（dayofyear）、季度；
  • 布尔型：是否周末、是否节假日、是否月末/季末；
  • 类别型：星期几、月份（常做 one-hot 或目标编码）。
（4）周期编码：sin/cos 变换#

直接拿"月份 = 12"和"月份 = 1"当数值，会让 12 月和 1 月看起来相距 11，但它们在日历上其实是相邻的（周而复始）。这种"循环变量"的正确编码是映射到圆上，用一对 sin/cos：

x_sin = sin(2π · k / period)
x_cos = cos(2π · k / period)

其中 period 是周期（月份=12、星期=7、小时=24），k 是周期内的序号。sin 和 cos 成对使用，才能唯一确定圆周上的位置——只用其中一个，会在圆上"上下对称"造成信息丢失。这样 1 月和 12 月在二维空间里就真正相邻了。

（5）变换特征#

差分、变化率等，帮助模型看到"变化"而非"绝对水平"：

diff_1  = y_{t} − y_{t-1}         # 一阶差分
pct_chg = (y_t − y_{t-1}) / y_{t-1}  # 环比变化率

这类特征更平稳，对树模型尤其友好。

3. 泄漏：时间特征工程的生死线#

构造特征时最常见的错误，是不小心用到了未来信息，典型场景：

  • 用全序列的均值/标准差做标准化，再拿去训练——标准化统计量应只用训练段计算；
  • 滑动窗口把当前期之后的点也卷进去（窗口没有"对齐到过去"）；
  • 对整个序列做 one-hot 或目标编码时，编码用了全量标签。

泄漏会让验证集的指标虚高，上线后却崩盘。守则只有一条：构造第 t 期的特征时，只允许使用第 t 期及之前的信息。

二、可运行示例#

用 pandas 把一条日度序列摊平成监督学习表格。

import numpy as np
import pandas as pd

# 构造 120 天的日度序列（带周周期和轻微趋势）
idx = pd.date_range("2023-01-01", periods=120, freq="D")
rng = np.random.default_rng(2)
y = 30 + 0.1 * np.arange(120) + 5 * np.sin(2 * np.pi * np.arange(120) / 7) \
    + rng.normal(0, 2, size=120)
df = pd.DataFrame({"y": y}, index=idx)

# 1) 滞后特征：前 1/2/3 天
for lag in [1, 2, 3]:
    df[f"lag_{lag}"] = df["y"].shift(lag)

# 2) 滚动窗口统计：过去 7 天的均值与标准差
df["roll_mean_7"] = df["y"].shift(1).rolling(7).mean()
df["roll_std_7"] = df["y"].shift(1).rolling(7).std()

# 3) 日历特征
df["dayofweek"] = df.index.dayofweek          # 0=周一 ... 6=周日
df["is_weekend"] = (df["dayofweek"] >= 5).astype(int)
df["dayofyear"] = df.index.dayofyear

# 4) 星期几的 sin/cos 周期编码（period=7）
df["dow_sin"] = np.sin(2 * np.pi * df["dayofweek"] / 7)
df["dow_cos"] = np.cos(2 * np.pi * df["dayofweek"] / 7)

# 5) 差分与变化率
df["diff_1"] = df["y"].diff()
df["pct_chg"] = df["y"].pct_change()

# 目标：预测下一天，所以把 y 前移作为标签
df["target"] = df["y"].shift(-1)

# 丢掉无法构造完整特征/标签的前几行，看看表格长什么样
print(df.dropna().head(8).round(2))
print("\n特征列：", [c for c in df.columns if c not in ("y",)])

注意两处关键：滚动窗口用了 .shift(1) 先错开一天，保证窗口只含过去；标签用 .shift(-1) 取下一天的值。丢掉 NaN 行后，每一行就是"用截至 t 期的特征预测 t+1 期"的一个干净样本。

三、练习#

  1. 增加一个 roll_max_14（过去 14 天最大值）和 lag_7（前 7 天），观察表格的变化，并说明为什么这些特征都必须先 shift 再 rolling。
  2. 把序列改成小时级（freq="h"），为"小时"构造 sin/cos 编码（period=24），并解释为什么小时适合用周期编码而"年份"通常不适合。
  3. 找出上面代码里哪些特征存在泄漏风险（如果有），并修复它们；用一句话说明泄漏为什么危险。
  4. 思考：树模型（如梯度提升）能直接利用"滞后 7 期 = 上上周"这种线性外推吗？如果不能，它靠什么捕捉趋势？
