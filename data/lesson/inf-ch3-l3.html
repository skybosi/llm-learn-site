SGLang 与选型对比#

推理引擎的版图里还有一位新锐——SGLang。它不只做 serving，还引入了一套"结构化生成"的编程模型，并用 RadixAttention（基数注意力） 做前缀缓存，在长上下文、多轮对话、并行采样等场景下吞吐突出。学完本课，你应当能说出 SGLang 的独门技术，并建立一张可复用的四引擎选型对照表。

一、概念讲解#

1. SGLang 是什么#

SGLang 是一个集 DSL（领域专用语言）+ 运行时 于一体的 LLM 服务框架，由 Stanford、UC Berkeley 等团队开发。它有两大组成部分：

  • SGLang 前端：一种 Python 嵌入的 DSL，让你用"程序式"的方式描述生成流程（分支、并行、多轮、约束），而不是只发一个孤立的 prompt；
  • SGLang Runtime：一个高吞吐 serving 引擎，提供 OpenAI 兼容 API。

2. RadixAttention：前缀缓存的核心#

RadixAttention 是 SGLang 的招牌技术，它用一个基数树（radix tree）来管理 KV Cache，实现跨请求的前缀自动复用：

  • 把所有已见过的 token 前缀组织成一棵 trie（字典树）；
  • 新请求到来时，在树里找最长公共前缀，直接复用那部分的 KV，只计算新增的尾巴部分；
  • 特别适合多轮对话（每轮都带着越来越长的历史）、共享系统提示词、并行采样/搜索（大量请求共享同一个前缀）等场景。

论文在真实负载下报告，相比 vLLM，SGLang 在部分场景吞吐可提升 1.5–6 倍（因前缀复用程度而异）。

3. 其它亮点#

  • 结构化/约束生成：支持正则、JSON Schema 约束输出，适合做可控格式输出；
  • 快速启动：相比 vLLM，冷启动与换模型更轻量；
  • 持续演进：后来 vLLM 也补了前缀缓存，但 RadixAttention 在"树形前缀复用"的细腻度上仍是标杆。

4. 四引擎选型对照#

二、可运行示例#

1. 启动 SGLang 服务#

# 安装与启动（OpenAI 兼容）
pip install "sglang[all]"
python -m sglang.launch_server \
    --model-path meta-llama/Llama-2-7b-chat-hf \
    --port 30000

2. 用 SGLang DSL 写结构化/多路生成#

# -*- coding: utf-8 -*-
# SGLang 前端：程序式描述生成流程（分支 + 约束）
import sglang as sgl
from sglang import function, system, user, assistant, gen

@sgl.function
def multi_answer(s, question):
    s += system("你是严谨的助手，回答要简洁。")
    s += user(question)
    # 并行采样 3 条候选（共享同一个前缀，RadixAttention 会复用 KV）
    s += sgl.gen("candidate1", max_tokens=64)
    s += sgl.gen("candidate2", max_tokens=64)
    s += sgl.gen("candidate3", max_tokens=64)
    # 再让模型从候选中选一个最优的
    s += user("从上面三条里选一条最好的，只输出它的编号：")
    s += sgl.gen("best", max_tokens=4, regex=r"[123]")

# 实际使用时需先设置后端 RuntimeEndpoint，这里仅展示 DSL 结构
print("DSL 定义完成：多路生成 + 正则约束选择，共享前缀由 RadixAttention 复用。")

3. 选型决策函数#

# -*- coding: utf-8 -*-
# 四引擎选型决策：按硬约束与场景打分推荐

def choose_engine(platform, scenario):
    rules = {
        ("cpu", "local"): "llama.cpp",
        ("gpu", "general"): "vLLM",
        ("gpu", "peak_perf"): "TensorRT-LLM",
        ("gpu", "long_context"): "SGLang",
        ("gpu", "multi_turn"): "SGLang",
    }
    return rules.get((platform, scenario), "vLLM（默认通用选择）")

cases = [("cpu", "local"), ("gpu", "general"), ("gpu", "peak_perf"),
         ("gpu", "long_context"), ("gpu", "multi_turn")]
for p, s in cases:
    print(f"平台={p} 场景={s:12s} -> {choose_engine(p, s)}")

三、练习#

  1. 跑服务：按示例 1 启动 SGLang，用 curl http://localhost:30000/v1/models 验证，再用 OpenAI SDK 指向该地址发一次对话。
  2. 前缀复用实验：构造 100 个"共享同一段长系统提示词、各自问题不同"的请求，分别打到 vLLM 与 SGLang，对比总耗时，观察 RadixAttention 的收益。
  3. 改 DSL：把示例 2 里的并行采样从 3 条改成 5 条，或把 regex 改成 [12345]，理解约束生成的写法。
  4. 写对照表：结合本课和第 3 章前两课，自己手写一张四引擎选型表，并为"在线客服（多轮、长上下文、高并发）"给出你的推荐及理由。
