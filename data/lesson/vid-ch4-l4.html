评测与可复现工程：分段与全片口径、切分纪律、可复现清单#

这一节要解决什么#

前三节把长视频做得出来、做得便宜、部署得下去。最后一节回答唯一能让前三节有意义的问题：

怎么知道它真的更好？ 长视频的评测比图像评测多出四个可算的陷阱：口径（分段 vs 全片、micro vs macro）、采样（抽多少帧才不漏掉稀有事件）、切分（近重复与时间自相关造成的泄漏）、统计（段数不是样本数）。再加一条工程要求：别人必须能复核你的数。

这一节的结论全部可以当场算出来：

  1. 分段指标与全片指标不是同一个东西，也不能互相换算。 段准确率 a、每视频 K 段时全片指标 =aK：a=0.95,K=10 时 0.598737（与分段指标差 0.351263）；a=0.99,K=100 时 0.366032。而全片指标的误差棒更大：a=0.95,K=10 时 sd 是分段指标的 5.1667 倍，取得同等误差棒需要 26.694557 倍的视频数（表 1）。
  2. micro 与 macro 的排名可以完全相反。 长视频 100 段、短视频 10 段、各 50 个时：模型 A micro 0.668182 > 模型 B 0.631818，而 macro 上 A 0.750000 < B 0.775000——因为长视频贡献 0.9091 的段却只占 0.5000 的视频（表 2）。
  3. 抽多少帧评测，是"漏检概率"的函数。 事件占空比 1%（G=1080 帧）、只抽 n=100 帧时，完全看不到这个事件的概率是 0.365863；n=1000 时降到 4.1189×10−5（期望命中 10.00 次）。精确式是超几何尾概率 P0​=(nN−G​)/(nN​)，对 n 与 G 对称，两个常用近似要按"哪一边更小"选（表 3）。
  4. 稀有正例是评测成本的主要来源。 相对误差 ε 需要 n≥(1−p)/(pε2)：p=0.01、ε=0.1 时要 9900 帧（素材的 9.17%）；p:0.5→0.01 使样本量涨 99.0 倍（表 3）。
  5. 随机切分的泄漏率由"每场景片段数" v 决定，而不是由数据集大小决定。 泄漏占测试集的比例 =1−(1−f)v−1：v=10,f=0.2 时 0.865782，v=50 时 0.999982（表 4）。近重复越多，随机切分越等于"把训练集当测试集"。
  6. 近重复检测的阈值可以按语料规模反解。 64 位感知哈希、汉明距离阈值 t：t=6 时对撞概率 4.5145×10−12，106 条语料的期望假阳性只有 2.257252 对；t=10 时 9.9825×10−9，同语料假阳性 4991.240568 对（表 4）。
  7. 时序切分的 purge 可行性判据是 ntest​≫2w，不是 w 的绝对值。 L=108000,w=64 时 purge 只吃掉测试集的 0.005926；L=300,w=256 时测试集 60 帧扣掉 512 帧 purge 后是 −452 帧——短视频上"按时间切"与"留出边界"不可兼得（表 5）。
  8. 段数不是样本数。 DEFF=1+(K−1)ρ、Neff​=MK/DEFF，且 K→∞ 时 Neff​→M/ρ：ρ=0.5,K=10 时 Neff​=181.818182（名义 1000）、sd 是独立情形的 2.3452 倍；K=200 时也只到 199.004975。要在 δ=0.03 上分辨差异，需 M≥422.58（ρ=0.5）vs 76.83（ρ=0）——忽略组内相关会把所需数据低估 5.5 倍（表 6）。
  9. 不可复现的一手来源是浮点归约顺序。 同一个 ∑i=1106​1/i，仅换求和顺序，fp32 结果就差 2.4582×10−3（相对）：正向 14.35735798（误差 2.4574×10−3）、反向 14.39265156（5.2224×10−6）、成对归约 14.39272881（1.4470×10−7）（表 7）。

1.2 micro vs macro：排名可以相反#

第二个岔路是加权单位：按段加权（micro）还是按视频加权（macro）。表 2 的算例（100 段的长视频 50 个 + 10 段的短视频 50 个）：

micro 下 A 赢，macro 下 B 赢。 根源是权重错配：长视频贡献 5000/5500=0.9091 的段，却只占 0.5000 的视频。所以

micro 被长视频主导,macro 被短视频主导

二、评测采样的偏差与成本#

2.1 漏检概率：一个对 n 与 G 对称的超几何尾概率#

从 N 帧里均匀抽 n 帧，一个占 G 帧的相关事件被完全漏掉的概率是

P0​=(nN​)(nN−G​)​=i=0∏G−1​N−iN−n−i​

这个式子对 n 与 G 完全对称——这是一个很有用的性质：它意味着"抽 n 帧看 G 帧的事件"与"抽 G 帧看 n 帧的事件"漏检概率相同，所以两个方向都能用来估。两个常用近似分别把较小的一边放进指数：

A_1=\left(1-\frac GN\right)^n\ (G>n\ \text{更准}),\qquad\rA_2=\left(1-\frac nN\right)^G\ (n>G\ \text{更准})

A_1=\left(1-\frac GN\right)^n\ (G>n\ \text{更准}),\qquad\rA_2=\left(1-\frac nN\right)^G\ (n>G\ \text{更准})

  2. 选哪个近似是一道计算题：G=10800,n=100（G≫n）时 A1​ 差 5.109×10−3，而 A2​ 差 7.100×10−1（差两个量级）。

2.3 固定步长 vs 随机采样#

方式 偏差 方差 适用
固定步长 s 与周期事件共振（第 2 节的混叠）；边界量化到 s 低 已知事件时长下限，且 s≤fτ/3

取舍：固定步长便宜（可复用、可缓存），但它的失败模式是系统性的（共振会稳定地漏掉某类事件，而不是随机波动）；随机采样无偏但需要 n 足够大（§2.2）。工程建议是两者都做：固定步长做主指标（可复现），随机采样做稳健性检查（发现共振）。

三、数据泄漏与切分纪律#

3.1 随机切分的泄漏率：由 v 决定#

泄漏占测试集比例=1−(1−f)v−1

五、可复现工程#

5.1 一手证据：归约顺序改变结果#

"同代码同数据两次结果不同"最常见的原因不是随机种子，而是浮点加法不满足结合律。表 7 用纯标准库（struct 把每步结果量化到 fp32）算了一遍 ∑i=1106​1/i：

归约方式 结果 相对误差 与正向之差
正向顺序 14.35735798 2.4574×10−3 0
反向顺序 14.39265156 5.2224×10−6 2.4582×10−3
成对归约 14.39272881 1.4470×10−7 2.4636×10−3

（参考值 14.3927267229，与闭式 lnN+γ+1/(2N) 逐位一致。）

只换顺序，fp32 结果就差 2.4582×10−3（相对）。 误差量级与 n⋅u 估计一致（nu=5.9605×10−2，u=2−24=5.9605×10−8）。GPU 上的原子加、线程划分、BLAS 版本都会改变归约顺序，所以

可复现 ⟹ 固定归约顺序（或接受"统计等价"而非"逐位相同"）

取舍：逐位可复现通常要求确定性 kernel（牺牲性能），而统计等价只需要固定种子 + 多次运行报分布。工程上应该明确声明是哪一种：声称逐位可复现但没关掉非确定性原子加，是最常见的可复现性谎言。

一份"看起来完整但不可复现"的报告通常缺这五项：权重与产物哈希、随机种子与确定性开关、误差棒与统计判据、近重复检测、最高频基线——得分 63/100。这五项恰好是"别人无法复核"与"结果可能虚假"的分界：

  • 没有哈希 → 不知道跑的是不是同一份权重；
  • 没有种子 → 不知道是不是同一次运气；
  • 没有误差棒 → 不知道提升是否超过噪声；
  • 没有近重复检测 → 不知道测试集是否被污染；
  • 没有最高频基线 → 不知道模型是否真的看了输入。

建议门槛：≥80 分才允许把结果写进对外材料。

5.3 最小可复现包#

一个可复核的长视频结果至少包含：

code/            训练与评测脚本（含 splits 生成脚本）
env/             锁文件 + 驱动/CUDA 版本
data/manifest    (uri, sha256, scene_id, duration, split)
ckpt.sha256      权重哈希
eval/command     逐字可复制的评测命令
eval/output      原始输出（不是整理后的表格）
stats/           sd / CI / N_eff / DEFF 的估计方式

关键点是 eval/output 要是原始输出：整理后的表格无法验证，而原始输出可以被重新解析。

def dwidth(s):
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1 for ch in s)


def pad(s, w, align=">"):
    gap = max(0, w - dwidth(s))
    if align == ">":
        return " " * gap + s
    if align == "<":
        return s + " " * gap
    left = gap // 2
    return " " * left + s + " " * (gap - left)


def row(cells, widths, aligns=None):
    aligns = aligns or [">"] * len(cells)

def ln_comb(a, b):
    if b < 0 or b > a:
        return float("-inf")
    return math.lgamma(a + 1) - math.lgamma(b + 1) - math.lgamma(a - b + 1)


def p0_log(N, n, G):
    if n > N - G:
        return float("-inf")
    return ln_comb(N - G, n) - ln_comb(N, n)

小结#

  • 口径是三个正交选择：分段 vs 全片（a vs aK：a=0.95,K=10 时 0.950000 vs 0.598737）、micro vs macro（排名可相反：A 0.668182/0.750000 vs B 0.631818/0.775000）、主指标预先声明。全片指标更诚实但同等误差棒要 26.694557∼257.836296 倍视频数。
  • 采样决定"能不能看见"：漏检概率 P0​=(nN−G​)/(nN​)，对 n,G 对称；占空比 1%、n=100 时 P0​=0.365863。近似的选择看哪边小（G≫n 用 (1−G/N)n：5.109×10−3 vs 7.100×10−1）。
  • 稀有正例是成本主项：n≥(1−p)/(pε2)，p=0.01、ε=0.1 需 9900 帧（9.17% 素材）；p:0.5→0.01 样本涨 99.0 倍。
  • 泄漏由 v 决定、与 N 无关：1−(1−f)v−1，v=10,f=0.2 时 0.865782、v=50 时 0.999982。测试集的有效多样性由 U 决定（U=200,f=0.2⇒40 个测试场景）。
  • 近重复阈值可反解：64 位哈希、t=6 时对撞概率 4.5145×10−12，C=106 只有 2.257252 对假阳性；t=10 时 4991.240568 对。报告必须带 (t,C,期望假阳性)。
  • purge 判据是 ntest​≫2w：L=108000,w=64 只损 0.005926；L=300,w=256 时测试集是 −452 帧——短视频上必须换切分单位。
  • 段数不是样本数：DEFF=1+(K−1)ρ、Neff​→M/ρ（ρ=0.5,K=10 时 181.818182；K=200 也只到 199.004975）。反解 Δp=0.03 需 M≥422.58（ρ=0.5）vs 76.83（ρ=0）——忽略组内相关低估 5.5 倍。
  • 不可复现的一手来源是归约顺序：仅换顺序，fp32 的 ∑1/i 差 2.4582×10−3（正向误差 2.4574×10−3、反向 5.2224×10−6、成对 1.4470×10−7）。必须声明"逐位相同"还是"统计等价"。
  • 可复现清单 12 项 100 分，门槛 80。常缺的五项（哈希、种子、误差棒、近重复、最高频基线）= 63/100，而这五项正是"无法复核"与"结果可能虚假"的分界。
