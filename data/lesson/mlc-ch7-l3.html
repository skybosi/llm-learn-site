回退与兜底：生成失败时的正确性保障#

编译器不能承诺"我支持所有算子"，它只能承诺"我不支持的时候结果仍然是对的"。这句话把回退从"失败分支"变成了必须被设计、被记账、被验收的一等路径：默认行为是切开图、编译能编译的、其余交给 eager（PyTorch 文档称之为 skipped function / graph break）；开关一拨可以是 fullgraph=True 直接报错，也可以 suppress_errors 把编译异常吞掉整图降级。本课用六十行 Python 把三种策略、区域边界的成本、兜底的红线（原地写）与三重验收全部跑出来。

一、概念讲解#

1. 三种兜底策略，三种失败模式#

  • 报错（fullgraph=True，等价于 error_on_graph_break）：遇到不支持就抛错。好处是性能不静默流失，代价是模型里有一个未支持算子就完全跑不起来——适合性能回归必须拦住的生产基线。
  • 切区域回退（默认）：把图切成"编译区域"与"回退区域"，回退区域按 eager 语义执行。性能有损但可用，是绝大多数框架的默认选择。
  • 静默降级（torch._dynamo.config.suppress_errors 一类开关）：把编译异常吞掉、整图退化到 eager，只在日志里留一句警告。它是排障期的救命开关，也是生产事故的常见来源——没人看日志，加速比就悄悄回到 1.0。

2. 区域边界的成本是具体的#

代码第 1 节对一张 6 节点图给出分区结果：const→mm→add→relu（编译）、rmsnorm（回退）、mul（编译），区域数 3、边界 2 处、kernel 启动约 3 次。每一条边界都意味着：上游区域的结果必须材料化到内存（否则回退算子看不到），下游区域必须重新读入（否则没法融合）。回退的代价因此不是"多一个算子"，而是"多两处 DRAM 往返 + 一次框架调用 + 一段无法融合的图"。

3. 兜底的红线：原地写与状态#

第 4 节给出的是一个真实故障模式：区域里既有读 x 的算子（t = mul(x, w)），又有原地修改 x 的算子（回退的 iadd），最后还有用到修改后 x 的算子。如果生成器把整个区域当成纯函数、在区域入口把输入快照进寄存器复用，结果就完全错了——y 从 [13, 18, 25, 34] 变成 [3, 8, 15, 24]，差 [10, 10, 10, 10]。这不是精度问题，是读到了过期值。合法的收口只有两条：把原地写函数化成新张量，或在原地写处插屏障、把该区域降级。TorchInductor 的作者在公告讨论里也承认这一点——IR 直接支持 mutation 与 scatter，同时依赖 dispatcher 层做函数化，而"把一串只改少量元素的 scatter 函数化"会把 O(n) 变成 O(n²)。

4. 回退节点的准入也要检查#

TVM BYOC 的 check 函数给了工业范例：除了 dtype 与 shape 约束，还要拒绝中间结果泄漏到融合组之外（has_leaking_intermediate_variables()）的片段，否则外部库算出的中间值没人接得住，只能整段失效。分区不是"pattern 匹配到就行"，而是"匹配 + 可交付"两件事。

5. 验收：容差、NaN、台账#

第 5 节给出三件必须同时做的事： 容差：同一组数 [1e16, 1, 1, -1e16]，顺序累加得 0.0、精确累加得 2.0——抵消型差异是路径变了的信号，任何容差都不该放行；而 [0.1]*10 的差异只有 1e-16，相对容差应当放行。先分类，再比较。 特殊值：nan == nan 恒为 False，验收脚本必须显式判 math.isnan，并单独列出 inf / -0.0。 台账：把每次回退记成 (算子, 原因, 段数)。回退段数为 0，才能说"这个模型被真正编译了"。

6. 常见坑#

  • 用 suppress_errors 换"跑得起来"：结果对但加速比归零，且日志里只有一行警告。
  • 只对拍最终输出：中间张量的原地写可能被后续算子掩盖，要用随机输入 + 多次运行 + 逐层对拍。
  • 把 graph break 当纯性能问题：断裂点两侧的编译区域各自优化，语义没变，但"看不到对方的假设"会让优化机会消失（第 2 章已量化过代价）。
  • 忘了回退路径的精度/顺序可能与生成路径不同：容忍它，但要在容差与特殊值上写清楚。

二、可运行代码示例#

纯标准库 Python（本机 python3.10.16 实跑）。五段：分区与台账、fullgraph 报错、区域编译 + 回退执行的逐元素对拍、原地写故障复现、容差/NaN/台账验收。

# ---- 第 3 课：回退与兜底（纯标准库，无需 numpy / GPU）----
import math

# ============ 0. 一张带「编译器没实现」算子的图 ============
# 节点 = (op, [输入名], 输出名, attrs)；x/b/s 是外部输入，w 是常量
GRAPH = [
    ("const",   [],           "w",  {"value": [2.0, 3.0, 4.0, 5.0]}),
    ("mm",      ["x", "w"],   "h",  {}),      # 有 lowering
    ("add",     ["h", "b"],   "h1", {}),      # 有 lowering
    ("relu",    ["h1"],       "h2", {}),      # 有 lowering
    ("rmsnorm", ["h2"],       "h3", {}),      # 没有 lowering → 回退
    ("mul",     ["h3", "s"],  "y",  {}),      # 有 lowering
]
SUPPORTED = {"const", "mm", "add", "relu", "mul"}
FALLBACK_REASON = {"rmsnorm": "没有 IR lowering（算子尚未接入）"}

def op_eager(op, ins, at):
    """回退路径的语义基准：与框架 eager 完全一致的解释执行。"""
    if op == "const":   return list(at["value"])
    if op == "mm":      return [u * v for u, v in zip(ins[0], ins[1])]
    if op == "add":     return [u + v for u, v in zip(ins[0], ins[1])]
    if op == "relu":    return [max(u, 0.0) for u in ins[0]]
    if op == "rmsnorm": return [u / math.sqrt(sum(v * v for v in ins[0]) / len(ins[0]) + 1e-6)
                                for u in ins[0]]
    if op == "mul":     return [u * v for u, v in zip(ins[0], ins[1])]
    raise KeyError(op)

def run_eager(graph, feeds):
    env = {k: (list(v) if isinstance(v, list) else v) for k, v in feeds.items()}
    for op, deps, out, at in graph:
        env[out] = op_eager(op, [env[d] for d in deps], at)
    return env

# ============ 1. 分区：连续支持算子合成区域，中间夹回退节点 ============
def partition(graph, supported):
    regions, cur = [], []
    for node in graph:
        if node[0] in supported:
            cur.append(node)
        else:
            if cur:
                regions.append(("compiled", cur)); cur = []
            regions.append(("fallback", [node]))
    if cur:
        regions.append(("compiled", cur))
    return regions

def report(regions):
    n_comp = sum(1 for kind, _ in regions if kind == "compiled")
    n_fb = sum(1 for kind, _ in regions if kind == "fallback")
    print(f"  区域数 = {len(regions)}（编译区域 {n_comp}，回退区域 {n_fb}）")
    print(f"  区域边界（张量必须落到内存） = {max(len(regions) - 1, 0)} 处")
    print(f"  kernel 启动次数 ≈ {n_comp + n_fb}（回退区域就是一次框架算子调用）")
    for i, (kind, nodes) in enumerate(regions):
        print(f"    region{i}: [{kind:<8}] " + " → ".join(n[0] for n in nodes))

print("=== 1. 分区结果：回退节点把图切成区域 ===")
regions = partition(GRAPH, SUPPORTED)
report(regions)
print("  回退原因台账：" + "; ".join(f"{op}（{why}）" for op, why in FALLBACK_REASON.items()))

# ============ 2. 策略 A：fullgraph / error_on_graph_break ============
print("\n=== 2. 策略 A：fullgraph=True（等价于 error_on_graph_break）===")
def compile_fullgraph(graph, supported):
    for op, _, out, _ in graph:
        if op not in supported:
            raise RuntimeError(f"Unsupported: {op}（输出 {out}）—— fullgraph 下这是编译错误，不是警告")
    return "整图已编译"

try:
    compile_fullgraph(GRAPH, SUPPORTED)
except RuntimeError as e:
    print(f"  抛错：{e}")
print("  好处：性能不会静默丢失；代价：模型里只要有一个未支持算子就跑不起来")

# ============ 3. 策略 B：区域编译 + 回退执行，逐元素对拍 ============
def run_partitioned(graph, feeds, regions):
    env = {k: (list(v) if isinstance(v, list) else v) for k, v in feeds.items()}
    trace, ledger = [], []
    for kind, nodes in regions:
        if kind == "compiled":
            local = {}                                  # 区域内中间值只活在「寄存器」里

            def val(name):
                return local[name] if name in local else env[name]

            for op, deps, out, at in nodes:
                local[out] = op_eager(op, [val(d) for d in deps], at)
            env.update(local)
            trace.append((nodes[-1][2], "compiled", ",".join(n[0] for n in nodes)))
        else:
            op, deps, out, at = nodes[0]
            env[out] = op_eager(op, [env[d] for d in deps], at)
            trace.append((out, "fallback", op))
            ledger.append((op, out, FALLBACK_REASON.get(op, "未知")))
    return env, trace, ledger

feeds = {"x": [1.0, -2.0, 3.0, 4.0], "b": [0.5, -1.0, 2.0, 0.0], "s": [0.1, 0.2, 0.3, 0.4]}
e_ref = run_eager(GRAPH, feeds)
p_ref, trace, ledger = run_partitioned(GRAPH, feeds, regions)

print("\n=== 3. 策略 B：区域编译 + 回退执行（默认行为）===")
for out, kind, what in trace:
    print(f"  {out:<4} ← {kind:<8} {what}")
print(f"  结果对拍：最大绝对差 = {max(abs(a - b) for a, b in zip(e_ref['y'], p_ref['y']))}")
print(f"  逐元素全等 = {e_ref['y'] == p_ref['y']}（同一顺序同一精度下必须全等，不接受「差不多」）")
print("  回退台账：" + "; ".join(f"{op}: {out} ← {why}" for op, out, why in ledger))

# ============ 4. 兜底红线：原地写与「把区域当纯函数」不能共存 ============
MUT_GRAPH = [
    ("mul",  ["x", "w"], "t", {}),   # 读 x
    ("iadd", ["x", "k"], "u", {}),   # 原地写 x 的存储（没有 lowering → 回退）
    ("add",  ["t", "u"], "y", {}),   # 又用到修改后的 x
]

def run_mut(assume_pure):
    env = {"x": [1.0, 2.0, 3.0, 4.0]}
    snapshot = {"x": list(env["x"])}       # 区域入口的寄存器快照
    w, k = [2.0, 3.0, 4.0, 5.0], 10.0
    # t = x * w（读 x）
    src = snapshot["x"] if assume_pure else env["x"]
    env["t"] = [a * b for a, b in zip(src, w)]
    # u = x + k（原地写 x）
    for i in range(len(env["x"])):
        env["x"][i] += k
    env["u"] = list(env["x"])
    # y = t + u：assume_pure 时第二个操作数复用入口快照 → 过期值
    second = snapshot["x"] if assume_pure else env["u"]
    env["y"] = [a + b for a, b in zip(env["t"], second)]
    return env

good, bad = run_mut(False), run_mut(True)
print("\n=== 4. 兜底红线：原地写 vs 「区域入口快照输入」===")
print("  x = [1,2,3,4]，w = [2,3,4,5]，iadd 把 x 每个元素 +10（原地写）")
print(f"  每次使用都读内存（正确）：y = {good['y']}")
print(f"  区域入口快照、之后复用寄存器（错误）：y = {bad['y']}")
print(f"  差 = {[a - b for a, b in zip(good['y'], bad['y'])]}  ← 不是精度问题，是读到了过期值")
print("  两种合法收口：把原地写函数化成新张量；或在原地写处插屏障、把该区域降级")

# ============ 5. 验收：容差、NaN、以及静默回退台账 ============
print("\n=== 5. 验收三件事：容差 / NaN / 台账 ===")
def seq_sum(v):
    t = 0.0
    for x in v:
        t += x
    return t

for tag, vals in [("灾难性抵消：相对误差 100%，任何容差都不该放行", [1e16, 1.0, 1.0, -1e16]),
                  ("量级相当的重排：差 ~1e-16，容差应当放行", [0.1] * 10)]:
    seq, pair = seq_sum(vals), math.fsum(vals)
    print(f"  {tag}")
    print(f"    顺序累加 = {seq!r}  精确累加 = {pair!r}")
    print(f"    逐位相等 = {seq == pair}；只给相对容差 = {math.isclose(seq, pair, rel_tol=1e-9)}；"
          f"相对+绝对容差 = {math.isclose(seq, pair, rel_tol=1e-9, abs_tol=1e-6)}")
print("  所以验收要先分类：量级相当的重排用容差放行；抵消型差异本身就说明数值路径变了，必须查")
nan = float("nan")
print(f"  NaN 验收：nan == nan → {nan == nan}（不能这么写）；math.isnan(nan) → {math.isnan(nan)}")
print("  验收脚本必须同时用：容差比较 + NaN/inf/-0.0 的显式清单")

events = [("region0", "compiled", "mm,add,relu"),
          ("rmsnorm", "fallback", FALLBACK_REASON["rmsnorm"]),
          ("region1", "compiled", "mul"),
          ("整图降级", "fallback", "suppress_errors=True 吞掉了 lowering 异常")]
print("\n  静默回退台账（suppress_errors 下唯一看得见的信号）：")
counts = {}
for name, kind, why in events:
    counts[kind] = counts.get(kind, 0) + 1
    print(f"    - {name:<9}{kind:<10}{why}")
print(f"  汇总：compiled {counts.get('compiled', 0)} 段，fallback {counts.get('fallback', 0)} 段")
print("  台账里 fallback 段数为 0，才能说这个模型被真正编译了；否则加速比会静默缩水")

三、练习#

  1. 实现：给 partition 加一条"合并规则"——当两个编译区域之间只隔一个回退算子、且回退算子的输入输出形状一致时，允许把它并进同一区域（用一次 extern 调用替代）。统计合并前后区域边界数与启动次数。
  2. 解释：为什么第 4 节的错误版本会把 y 算成 [3, 8, 15, 24]？如果把 iadd 换成"返回新张量"的函数式版本，即使生成器继续在区域入口做快照，结果还会错吗？
  3. 对比/验证：把第 5 节的验收改成"逐位相等"，在 [0.1]*10 这个例子上会发生什么？再改成"只用相对容差"，在 [1e16, 1, 1, -1e16] 上又会发生什么？据此写出一段可复用的验收断言。
  4. 思考：suppress_errors=True 把整图降级成 eager 之后，用户手里还剩什么信号可以判断"这次编译其实没生效"？如果让你给框架加一个指标，你会加哪一个，为什么？
