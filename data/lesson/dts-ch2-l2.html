ReduceScatter / AllGather / All2All 及其在 TP、EP 里的角色#

上一课把 AllReduce 拆成 ring / tree / butterfly，但训练循环里最常被真正调用的原语并不是 AllReduce：张量并行（TP）的一次"归约"经常被拆成 AllGather 与 ReduceScatter 两步来做，MoE 的一层几乎全靠两次 All2All 搬运 token。这一课把这四个原语的语义、组合关系和账本对齐，再看它们在 TP 与 EP 里各自干什么活——只要能把"谁发给谁、发多少、输出怎么排布"说清楚，后面所有并行策略的通信账都能自己算。

一、概念讲解#

1. 四个原语：语义先对齐 NCCL 口径#

原语 输入 输出 一句话
AllReduce 每 rank 一份 s 每 rank 一份，内容相同 归约结果人人有份
ReduceScatter 每 rank 一份 s 每 rank 一块 s/p 归约后按 rank 分块
AllGather 每 rank 一块 s/p 每 rank s 把各家的块拼起来给所有人
All2All 每 rank p 段、共 s 每 rank p 段、共 s 第 j 段发给 rank j，第 i 段来自 rank i

两处细节必须记住。第一，NCCL 文档写明了等价关系："先 ReduceScatter 再 AllGather 等于一次 AllReduce"，"先 Reduce 再 Broadcast 也等于 AllReduce"——AllReduce 是个复合操作，不是原子操作。第二，AllGather 的输出按 rank 索引排序，All2All 的输入输出段序由 rank 与 device 的映射决定；NCCL 专门提示 rank 到设备的映射会改变布局，写错布局得到的不是"精度差一点"，而是数据错位。

2. 组合关系与账本：三个数与上一课完全对得上#

ring 实现下（p=4、s=96 B 的实测）：

  • ReduceScatter：p−1=3 步，每步每 rank 发 s/p=24 B，每 rank 共 0.75s；
  • AllGather：同样 3 步、0.75s；
  • 两者相加：2(p−1)=6 步、每 rank 1.5s——正是上一课 ring AllReduce 的账（2(p−1)/p⋅s）。

All2All 的账不同：均匀情况下每个 rank 要把 p−1 段送出去、只留 1 段（s/p），所以每 rank 发送 (p−1)s/p，全局发送量恰好等于全局数据量——每个字节只被搬一次，没有任何冗余。它本质是一次"分组转置"：out[r] 的第 j 段 = in[j] 的第 r 段，转置两次就是恒等（代码里已验证 True）。真实 MoE 用的是变长版本（各家段长不同，业界常称 all-to-allv），但语义不变。

原语 ring 步数 每 rank 发送 是否做计算
AllReduce 2(p−1) 2(p−1)s/p≈2s 是（归约）
ReduceScatter p−1 (p−1)s/p 是（归约）
AllGather p−1 (p−1)s/p 否（纯搬运）
All2All 一轮交换 (p−1)s/p（均匀） 否（纯重排）

关键差异在语义：All2All 是重排而不是归约，没有计算可以掩盖它，成本全在搬运，因此它最吃网络带宽、最怕负载不均衡。

3. 在 TP 里：AllReduce 是零件，AllGather/ReduceScatter 是它的两半#

Megatron-LM 的张量并行把 FFN 的第一个 GEMM 按列切分（A=[A1​ A2​]）、第二个按行切分（B=[B1​;B2​]），于是

Y=act(XA1​)B1​+act(XA2​)B2​

每个 rank 只算一半，再用一次 AllReduce 把两项加起来。论文摘要的原话是这套做法"只需在 native PyTorch 里插入少量通信算子"——前向一次 AllReduce，反向对输入的梯度再来一次。

Megatron 的序列并行（sequence parallelism）（Korthikanti 等，2022）把这一步往前推：把 LayerNorm/Dropout 的激活沿序列维切分后，列 GEMM 需要的是完整激活，所以前向用 AllGather 换回整段激活；反向梯度天然是逐 rank 的序列分片，用 ReduceScatter 直接落地。结果是把"两倍 s 的 AllReduce"换成"s 的 AllGather + s 的 ReduceScatter"：实测里 fp32 的激活是 512 B，TP 的 AllReduce 与 SP 的 AllGather 在这一维上同阶，而 RS 与 AG 各只占一半——这正是第 1 课"组合决定账本"的直接应用。

坑：TP 的通信发生在每一层的前向与反向，层数越多、通信次数越多，所以 TP 一般只用在一个节点内（走 NVLink），这也解释为什么 TP 度数与节点内卡数强相关（第 5 章展开）。

4. 在 EP 里：dispatch / combine 就是两次 All2All#

MoE 层里，token 被 router 分给不同专家，而专家分布在不同 rank 上：dispatch 把 token 送到它所属专家所在的 rank，combine 把专家输出按原路送回原 rank 并累加。GShard 论文把这件事讲得很直接：MoE 的 expert dispatching 需要切换切分维度，而跨分区的通信就是 AllToAll（论文里 "MoE dispatch and combine" 对应 AllToAll 通信）。

账本：均匀路由下，一次 All2All 的全局发送量 = 1 倍全局 token 字节（每个 token 只送一次），所以 dispatch + combine ≈ 2 倍 token 字节。与 DP 的梯度 AllReduce（≈2s 且要归约）相比，EP 的通信是变长、可重排的：路由不均衡时，热门专家所在 rank 要收更多 token，整层的时间由最慢的那个 rank 决定（工程上用 capacity factor、token drop/pad 来兜底，第 5 章专家并行详述）。

坑：① 把 All2All 当 AllReduce 用（一个重排、一个归约，结果必然错位）；② 两端段序约定不一致（第 j 段发给谁、第 i 段来自谁必须严格对齐）；③ 忘了变长消息要按各段长度分别打包；④ 在 EP 里忽略路由热点的长尾等待。

5. 谁在训练里用谁#

原语 典型出处 你在代码里会看到的调用
AllReduce DP 梯度、TP 前/反向 DDP 的梯度分桶、all_reduce_perf
ReduceScatter TP+SP 反向、ZeRO/FSDP 梯度分片 torch.distributed.reduce_scatter_tensor
AllGather TP+SP 前向、FSDP 参数收集 torch.distributed.all_gather_into_tensor
All2All EP/MoE、部分序列并行实现 torch.distributed.all_to_all_single、DeepSpeed/GShard 的 dispatch/combine

PyTorch FSDP 的分片对象是参数、梯度与优化器状态：前向要 AllGather 参数、反向用 ReduceScatter 归约梯度分片（详见 FSDP 文档；第 6 章会算它的通信代价）。

二、可运行代码示例#

下面四段都用 numpy 在本地验证：RS + AG 复现 AllReduce、All2All 两遍回到原样、TP 的"列切分 + 行切分 + 求和"等于完整结果、EP 的 dispatch/combine 让每个 token 算对。

# ===== 示例 1：ReduceScatter + AllGather = AllReduce（纯 numpy，无 GPU） =====
import numpy as np

P, n = 4, 12                      # 4 个 rank，每个 rank 一份 12 个 float64
m = n // P                        # 每块 3 个数
rng = np.random.default_rng(3)
parts = [rng.integers(0, 100, size=n).astype(np.float64) for _ in range(P)]
ref = np.sum(parts, axis=0)


def reduce_scatter_ring(parts):
    """ring reduce-scatter：P-1 步后 rank r 手里是第 (r+1)%P 块的完整归约结果。"""
    P, n = len(parts), parts[0].size
    b = [v.reshape(P, m).copy() for v in parts]
    sent = [0] * P
    for k in range(P - 1):
        nxt = [c.copy() for c in b]
        for r in range(P):
            c = (r - k - 1) % P
            nxt[r][c] = b[r][c] + b[(r - 1) % P][c]
            sent[r] += m * 8
        b = nxt
    return [b[r][(r + 1) % P].copy() for r in range(P)], sent


def all_gather_ring(shards):
    """ring allgather：shards[r] 是 rank r 手里已完整的第 (r+1)%P 块。"""
    P = len(shards)
    blocks = [[None] * P for _ in range(P)]
    for r in range(P):
        blocks[r][(r + 1) % P] = shards[r].copy()
    sent = [0] * P
    for k in range(P - 1):
        old = [list(b) for b in blocks]
        for r in range(P):
            snd = (r + 1 - k) % P
            blocks[(r + 1) % P][snd] = old[r][snd].copy()
            sent[r] += m * 8
    return [np.concatenate(blocks[r]) for r in range(P)], sent


shards, s1 = reduce_scatter_ring(parts)
full, s2 = all_gather_ring(shards)
err = max(float(np.abs(f - ref).max()) for f in full)
print(f"P = {P}，s = {n*8} B（每块 {m*8} B）")
print(f"  reduce_scatter：{P-1} 步，每 rank 发送 {s1[0]} B = {(P-1)/P:.3f} s")
print(f"  all_gather    ：{P-1} 步，每 rank 发送 {s2[0]} B = {(P-1)/P:.3f} s")
print(f"  两者相加共 {2*(P-1)} 步、每 rank {2*(P-1)/P:.3f} s，"
      f"与直接求和的最大偏差 {err:.1e}")

# ===== 示例 2：All2All 就是一次"分组转置"，做两遍回到原样 =====
blocks = [np.stack([np.full(m, r * 10 + j) for j in range(P)]) for r in range(P)]


def all_to_all(blk):
    """blk[r] 形状 (P, m)：第 j 段发给 rank j；返回 out[r]，第 i 段来自 rank i。"""
    P = len(blk)
    return [np.concatenate([blk[i][r] for i in range(P)]) for r in range(P)]


once = all_to_all(blocks)
twice = all_to_all([b.reshape(P, m) for b in once])
same = all(np.array_equal(twice[r], blocks[r].reshape(-1)) for r in range(P))
sent = (P - 1) * m * 8
print(f"\n  all2all：{P} 段各 {m*8} B → 每 rank 送出 {(P-1)*m*8} B = {(P-1)/P:.3f} s"
      f"（只有 s/P 留在本地）")
print(f"  连做两遍 all2all 是否回到原样：{same}"
      f"（out[r] 的第 j 段 = in[j] 的第 r 段，转置两次即恒等）")

# ===== 示例 3：张量并行（TP）：局部结果 all-reduce 起来 = 完整结果 =====
S, H, F = 8, 16, 32
X = rng.standard_normal((S, H))
A = rng.standard_normal((H, F))
B = rng.standard_normal((F, H))
act = lambda Z: np.maximum(Z, 0)                     # 用 ReLU 代替 GeLU，结论与激活函数无关
Y_full = act(X @ A) @ B

tp = 2
As = np.split(A, tp, axis=1)                          # 列切分
Bs = np.split(B, tp, axis=0)                          # 行切分
Y_parts = [act(X @ As[i]) @ Bs[i] for i in range(tp)]
Y_tp = sum(Y_parts)                                   # all-reduce 做的事：逐元素求和
print(f"\n  完整 Y 与 TP={tp}（列切分 + 行切分 + all-reduce）的最大偏差 "
      f"{np.abs(Y_tp - Y_full).max():.3e}")

# 序列并行（SP）：激活先按序列切分，列 GEMM 前 all-gather 回来，通信量与激活同阶
Xs = np.split(X, tp, axis=0)
X_gathered = np.concatenate(Xs, axis=0)               # all-gather 的结果
Y_sp = sum(act(X_gathered @ As[i]) @ Bs[i] for i in range(tp))
print(f"  SP：激活先按序列切成 {tp} 份，all-gather 后计算，最大偏差 "
      f"{np.abs(Y_sp - Y_full).max():.3e}")
print(f"  通信量账本（fp32）：TP 前向 all-reduce = {X.shape[0]*H*4} B；"
      f"SP 前向 all-gather = {X.shape[0]*H*4} B，反向 reduce-scatter 同阶")

# ===== 示例 4：专家并行（EP）：dispatch / combine 就是两次 all2all =====
P2, T, D = 4, 3, 5
tokens = [rng.standard_normal((T, D)) for _ in range(P2)]
route = [[(r + t) % P2 for t in range(T)] for r in range(P2)]     # 每个 token 归属哪个专家 rank
W = [rng.standard_normal((D, D)) for _ in range(P2)]
idx = [[[t for t in range(T) if route[r][t] == j] for j in range(P2)] for r in range(P2)]

# dispatch：rank r 把去专家 j 的 token（按原顺序）发给 j
blocks = [[tokens[r][idx[r][j]] for j in range(P2)] for r in range(P2)]
recv = [[blocks[i][j] for i in range(P2)] for j in range(P2)]     # recv[j][i]：专家 j 收到来自 rank i 的
# 专家计算：rank j 用自己的 W[j] 处理收到的 token
out = [[recv[j][i] @ W[j] for i in range(P2)] for j in range(P2)]
# combine：专家 j 把结果发回来源 rank i
rebuilt = []
for i in range(P2):
    acc = np.zeros((T, D))
    for j in range(P2):
        acc[idx[i][j]] = out[j][i]                                # 按 token 原下标放回
    rebuilt.append(acc)
expect = [np.stack([tokens[r][t] @ W[route[r][t]] for t in range(T)]) for r in range(P2)]
err = max(float(np.abs(rebuilt[r] - expect[r]).max()) for r in range(P2))
one_wave = sum(b.nbytes for br in blocks for b in br)
print(f"\n  EP：{P2} 个专家 rank、每 rank {T} 个 token（d={D}）")
print(f"  dispatch + combine 两次 all2all 后，token 逐一算对：最大偏差 {err:.1e}")
print(f"  一次 all2all 全体发送 {one_wave} B = {one_wave/(P2*T*D*8):.3f} × 全局 token 量")

三、练习#

  1. 实现：给 all_to_all 加上"变长段"的版本（每个 rank 发往各家的 token 数不同），用一个 4 rank × 3 token 的路由表验证：原样做两遍仍能还原。
  2. 解释：为什么 NCCL 文档说"ReduceScatter + AllGather = AllReduce"？用第 1 课的 ring 账本说明两者步数与每 rank 发送量完全一致。
  3. 对比/验证：把示例 3 的 tp 从 2 改成 4（F 用 4 的倍数），验证仍然等于完整结果，并给出 AllReduce 与 AllGather 的字节账本比值。
  4. 思考：如果 MoE 的路由极度不均衡（一个专家收到 10 倍 token），EP 的 All2All 时间由谁决定？给出两种工程处理方向，并说明各自的代价。
