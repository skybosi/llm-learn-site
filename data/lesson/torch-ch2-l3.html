计算图#

前两课我们反复提到"计算图"，却一直把它当黑盒。本课揭开它：计算图由什么组成、grad_fn 是什么、为什么它是动态的，以及 PyTorch 如何靠它做到"边前向边建图、反向完就释放"。理解计算图，是理解 PyTorch 自动微分实现机制的最后一块拼图。

一、概念讲解#

1. 计算图长什么样#

计算图是一个有向无环图（DAG）：

  • 节点：张量（数据），以及产生张量的算子信息。
  • 边：数据从输入流向输出的依赖关系。前向时数据正向流动，反向时梯度逆着边流动。

例如 z = x * y + y ** 2 会形成一张小图：叶子 x、y → mul 与 pow → add → 结果 z。图 2-3 画出了这张图及反向时梯度沿边的传播。

2. grad_fn：每个节点的"来历"#

每个由运算产生的张量都带一个 grad_fn，指向产生它的那个算子（Function），例如：

  • 加法 → <AddBackward0>
  • 乘法 → <MulBackward0>
  • 幂运算 → <PowBackward0>

grad_fn 里封装了该算子的反向逻辑（局部导数）。backward() 时，PyTorch 沿着每个节点记录的 grad_fn 一路往回调用，正是链式法则的落地。叶子张量没有 grad_fn（为 None），因为它们不是"算"出来的，而是用户给的。

3. 动态图 vs 静态图#

PyTorch 用的是动态计算图（define-by-run）：

  • 图随前向代码的执行逐步构建，你写多少层、走哪个分支，图就是什么样；
  • 同一段代码跑两次前向，会得到两张全新的图；
  • 因此网络里可以自由使用 Python 的 if、for，模型结构可以是"数据相关的"。

对照之下，TensorFlow 1.x 的静态图是"先定义整张图，再喂数据执行"，控制流需要专门的算子表达。动态图的好处是直观、易调试，代价是每次前向都要重建图（有少量开销，PyTorch 已通过缓存和 torch.compile 等手段优化）。

4. 图的生与死#

  • 构建：只要运算涉及 requires_grad=True 的张量，结果就会记录 grad_fn，边就被连上。
  • 释放：backward() 跑完后，中间节点的图信息默认被释放以回收显存；之后再次 backward() 就会报错（除非 retain_graph=True）。
  • 不建图：no_grad() 内、或对 requires_grad=False 的张量运算，不产生 grad_fn。

二、可运行代码示例#

import torch

# ---- 1. 观察 grad_fn：每个节点的"来历" ----
x = torch.tensor(1.0, requires_grad=True)
y = torch.tensor(2.0, requires_grad=True)

z = x * y + y ** 2                    # 一张小计算图
print("z        =", z)
print("z.grad_fn =", z.grad_fn)       # <AddBackward0>

# 拆开看中间节点
mul = x * y
pow_ = y ** 2
print("\nmul.grad_fn =", mul.grad_fn)   # <MulBackward0>
print("pow_.grad_fn =", pow_.grad_fn)   # <PowBackward0>
print("x.grad_fn   =", x.grad_fn)       # None（叶子）

# ---- 2. 反向：沿图传播 ----
z.backward()
# dz/dx = y = 2；dz/dy = x + 2y = 1 + 4 = 5
print("\nx.grad =", x.grad)             # 2.0
print("y.grad =", y.grad)               # 5.0

# ---- 3. 动态图：控制流也能建图 ----
def f(a):
    if a > 0:                           # 依赖数据的分支
        return a ** 2
    return -a

a1 = torch.tensor(3.0, requires_grad=True)
a2 = torch.tensor(-3.0, requires_grad=True)
r1, r2 = f(a1), f(a2)                   # 两次前向走出不同分支
r1.backward(); r2.backward()
print("\n正数分支导数 a1.grad =", a1.grad)   # 6.0（d(a^2)/da = 2a）
print("负数分支导数 a2.grad =", a2.grad)     # -1.0（d(-a)/da = -1）

# ---- 4. no_grad 内不建图 ----
with torch.no_grad():
    q = x * y
print("\nno_grad 内 q.grad_fn =", q.grad_fn)   # None

重点观察：z.grad_fn 是 AddBackward0，而叶子 x.grad_fn 是 None；带 if 的函数在动态图下可以正常反向，两次前向各走各的分支、各算各的导数。

三、练习#

  1. 对 z = x * y + y ** 2 手工画出它的计算图：标出节点、边、每个节点的算子，以及反向时各边上的局部导数。
  2. 创建 a = torch.tensor(2.0, requires_grad=True)，依次计算 b = a * a、c = b + a，打印 b.grad_fn 和 c.grad_fn，说明它们分别是什么算子、为什么不同。
  3. 用带 if/for 的 Python 代码写一个前向函数，验证在动态图下可以正常反向并得到梯度，解释静态图为什么难以直接支持这种写法。
  4. 连续调用两次 z.backward()（不设 retain_graph），观察报错信息；再改用 retain_graph=True 重跑，说明两者在"图释放"上的差异。
