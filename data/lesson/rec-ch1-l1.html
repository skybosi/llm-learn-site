推荐系统是什么与分类#

搜索引擎解决的是"我知道要什么，帮我找到它"；推荐系统解决的则是更难的另一种情况："我其实不知道自己想要什么，请你猜一个我能接受的答案"。前者是信息检索（Information Retrieval），后者是信息过滤（Information Filtering）——推荐系统就是信息过滤最主流的落地形态。这一课先建立全局地图：推荐系统到底在解决一个什么样的数学问题、有哪几类主流方法、以及它身上背着哪些与生俱来的难题。

一、概念讲解#

1. 一个"预测缺失值"的问题#

抛开五花八门的产品形态，推荐系统在数学上可以被压缩成一句话：给定一个稀疏的"用户 × 物品"交互矩阵，预测其中缺失的那些格子。

  • 用户（User）、物品（Item）、上下文（Context，时间/地点/设备等） 是推荐系统的基本输入；
  • 交互矩阵 R 的第 (u, i) 个元素，要么是显式打分（1~5 星），要么是隐式行为（点击/购买/观看时长）换算出的偏好；
  • 矩阵极其稀疏：一个用户一辈子接触到的物品，相对全网物品总量，比例可以低到百万分之一以下。

于是"推荐"这个动词，翻译成数学就是"补全矩阵"：预测 R[u, i] 对所有未交互的 (u, i) 取值，挑最大的几个 i 推给 u。

2. 显式反馈与隐式反馈#

"用户表达了什么"决定了数据的可信度与噪声水平，也决定了后面所有算法怎么写：

类型 例子 优点 缺点
显式反馈 打分、点赞/踩、写评论 直接表达偏好，信号干净 获取成本高，用户懒得打；有"评分偏差"
隐式反馈 点击、购买、观看时长、停留 海量、无感知、天然可得 只能推断"可能感兴趣"，噪声大，且无法表达"不喜欢"

真实系统几乎都以隐式反馈为主、显式反馈为辅。这也解释了为什么后面矩阵分解课要专门讲"隐式反馈 + 置信度加权"的变体——隐式数据的"0"不代表"不喜欢"，只代表"没观察到的未知"。

3. 按方法分类：一张地图#

推荐算法按"用什么信息做预测"，大体分成几大流派：

  1. 基于统计的基线（Baseline）：不看个人差异，只按全局流行度/均值推荐。简单、稳健，常被当作"及格线"用来给其他算法打分。
  2. 基于内容的推荐（Content-based）：利用物品的内容特征（文本、标签、图像）和用户的历史偏好画像做匹配——"你爱看科幻片，这部也是科幻片"。
  3. 协同过滤（Collaborative Filtering, CF）：完全不看内容，只用"群体行为"——"和你口味相似的人也喜欢它"。这是本课程的重头戏，下一课展开。
  4. 混合推荐（Hybrid）：把上面几种组合起来取长补短。
  5. 更进阶的方法：矩阵分解（本课程第 3 章）、图方法、序列/会话模型、以及把物品和用户都编码成向量的深度学习模型。

4. 与生俱来的三大难题#

理解了"补矩阵"这个任务，就能推导出推荐系统最难的三件事，它们会反复出现在后续每一课里：

  • 冷启动（Cold Start）：新用户/新物品在矩阵里整行/整列都是空的，没有历史可借。
  • 稀疏性（Sparsity）：绝大多数格子没观测值，可用的"锚点"极少，算法容易过拟合噪声。
  • 长尾（Long Tail）：少数热门物品霸占了绝大多数交互，冷门物品永远得不到曝光，形成"富者愈富"的马太效应。

这些难题没有银弹，但每一种主流算法本质上都是在"如何在没有足够信息时做出合理猜测"上做不同的妥协——带着这个问题去读后续章节，会更有方向感。

二、可运行代码示例#

先把"补矩阵"这件事最朴素的做法跑起来：热门基线（Popularity Baseline）。它不看用户差异，只统计每个物品被多少用户交互过，然后把最热的、且该用户还没碰过的物品推荐出去。这既是理解推荐系统数据结构的"hello world"，也是后续所有算法都要与之比较的及格线。

import numpy as np

# 用户 × 物品 隐式交互矩阵：1 表示有过交互（点击/购买），0 表示未知或未交互
# 行 = 用户，列 = 物品
R = np.array([
    [1, 1, 0, 0, 1],   # 用户 0
    [0, 1, 1, 0, 0],   # 用户 1
    [1, 0, 1, 1, 1],   # 用户 2
    [0, 0, 1, 0, 1],   # 用户 3
    [1, 1, 0, 1, 0],   # 用户 4
])

# 1) 每个物品的"热度" = 有多少用户与之交互（列求和）
item_popularity = R.sum(axis=0)
print("各物品热度：", item_popularity)

def popularity_recommend(R, user_idx, k=3):
    """热门基线：按物品热度降序，排除该用户已交互过的物品，返回 top-k。"""
    pop = R.sum(axis=0)                                  # 物品热度
    already = set(np.where(R[user_idx] > 0)[0])          # 用户已交互的物品编号
    candidates = [(i, p) for i, p in enumerate(pop) if i not in already]
    candidates.sort(key=lambda x: -x[1])                 # 热度从高到低
    return [item for item, _ in candidates[:k]]

print("给用户 0 推荐（热门基线）：", popularity_recommend(R, user_idx=0, k=3))

运行后你会看到：所有用户拿到的是同一份热门清单（只是各自剔除已交互项）。这就是"非个性化推荐"的全部内容——它没有任何"猜你"的能力，但它的推荐质量却是评价个性化算法时必须跨过的最低门槛。

三、练习#

  1. 修改 R 造一个"热度极其集中"的矩阵（某列几乎全是 1），观察热门基线给所有用户推荐的结果是否趋同，解释长尾问题如何在这里体现。
  2. 把"热度"从"交互人数"改成"平均评分"：给矩阵换成 1~5 的评分值，重写 popularity_recommend，思考两种热度定义各自的适用场景。
  3. 手写一个 topk_by_global_mean：预测 R[u, i] = R 的全局均值，比较它与热门基线在"推荐列表"上的差异，说明基线为什么常被当作基准线。
  4. 思考：如果系统里 99% 的交互都集中在 1% 的头部物品上，热门基线会一直推荐这些头部物品，冷门物品永远无法被验证"是否真的没人喜欢"——这种"观测偏差"为什么会让后续所有基于行为数据的算法都难以纠正？请用一两句话写下你的理解。

为什么这样做？——理论推导#

热门基线其实是"无条件最大似然"#

热门基线看似拍脑袋，实则是最优估计的一个特例。假设我们没有任何用户特征、物品特征，只有一个"某用户是否交互某物品"的伯努利随机变量。若进一步假设所有用户同质（交互概率只与物品有关，与用户无关），那么物品 i 的交互概率 p_i 的最大似然估计就是：

p̂_i = （与物品 i 交互的用户数）/（总用户数） ∝ 物品 i 的热度

也就是说，"按热度排序"等价于"在'用户之间无差异'这个假设下，对每个物品交互概率做最大似然估计"。一旦我们引入用户之间的差异，就从'无条件'滑向了'条件'：p(交互 | 用户 u, 物品 i) 不再只依赖 i。协同过滤、矩阵分解，本质上都是在往这个条件概率里注入"用户的个性化结构"——先注入"相似用户的邻域"（UserCF），再注入"物品的低维隐向量"（矩阵分解）。

把推荐系统当作条件概率估计问题，是贯穿全课程的一条主线：热门基线是"什么条件都不加的裸估计"，后面每一课都在给这条公式添加越来越聪明的"条件"。

母原理连接： 这与机器学习课里"从最大似然推出损失函数"是同一台引擎——用"最大化观测数据的似然"这条第一性原理，去反推"每个算法形式为什么长这样"。
