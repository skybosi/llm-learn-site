基准的分类学：知识、推理、代码、长文、多模态各测什么#

这一节要解决什么#

基准的数量已经多到无法逐个记住，但它们的类型只有少数几种，而每一类都有它固有的盲区——这个盲区来自"构念被操作化的方式"，不是来自数据集做得不够好。学会按类型看基准之后，你拿到一个从没听过的榜单，也能在五分钟内判断它的分数能支撑什么结论、不能支撑什么。

这一节建立两样东西：

  1. 一张分类地图：按"测什么构念 + 用什么评分函数"把基准分成知识、推理、代码、长文、多模态（外加安全与 Agent，留给后续课程），并给出每类的代表基准与结构性盲区；
  2. 一套验收问题：对任意基准问四个问题——构念是什么？样本从哪来？评分函数是什么？失效条件是什么？ 这四个问题比记住榜单名字有用得多。

验收任意基准的四个问题#

① 构念（construct）：它声称测什么？这个构念能拆成哪几个子面？子面覆盖了吗？
② 样本（sampling）  ：题目从什么总体里抽的？谁写的？难度分布如何？有多少题？
③ 评分（scoring）   ：答案怎么判对错（精确匹配/程序执行/模型评审/人工）？抽取规则是什么？
④ 失效（failure）   ：猜测基线多高？会不会污染？格式有多敏感？分布与我的场景差多远？

四个问题里，第 ③ 个最常被忽略、也最容易造成"莫名其妙的分差"。评分函数是基准的一部分，不是实现细节：同一份模型输出，换一个答案解析正则就是换了一个基准。

知识类基准：测的是"记得"，还是"会用"#

形态#

最典型的形态是多项选择题：给一个题干和 k 个选项，评分是精确匹配。代表有 MMLU（57 个学科、约 1.4 万道测试题、4 选项）、MMLU-Pro（选项扩到 10 个、题目更难，据报道能降低提示敏感性）、GPQA（研究生水平、号称"可 Google 不到"的物理/化学/生物题，其中经专家验证的 diamond 子集最难）、C-Eval（中文多学科）。

猜测基线：所有选择题分数都必须先减掉它#

随机猜的期望正确率是 1/k：

Accchance​=k1​,Accnorm​=1−1/kAcc−1/k​

归一化准确率才是"净能力"。这带来一个日常错误：不同 k 的选择题基准的准确率不可直接比较。同样是 0.60 的净准确率，4 选项时原始分是 0.70，10 选项时只有 0.64——把两个数放在一张表里排名是错的。

构念上的三个盲区#

盲区一：闭卷假设。 选择题基准默认模型"只能靠参数记忆"。但真实使用中几乎总有检索、工具、上下文。因此选择题分数衡量的是参数记忆的覆盖与提取，而不是"能否解决需要这些知识的问题"。一个检索能力强的系统在闭卷基准上可能很差，在真实任务上很好。

盲区二：没有"不知道"这个选项。 标准选择题不给弃权项，于是校准（calibration）——"它知不知道自己不知道"——完全测不到。而这一项在产品里往往比准确率更重要（要不要转人工、要不要检索）。

盲区三：形式合规 ≠ 内容正确。 选项数量、选项长度、答案先验分布都可能成为捷径。一个经典诊断是：把选项顺序打乱后重测；若分数明显变化，说明模型部分依赖位置先验。

饱和#

知识类基准最容易饱和：题库固定、题目公开、训练语料持续膨胀，头部模型分数不断逼近上限。饱和的直接后果是方差压缩：当所有强模型都在 88%~92% 之间，模型间真实差异被压进噪声，排行榜的名次变动主要由抽样误差驱动（第 2 节展开）。

推理类基准：答案对 ≠ 推理对#

形态#

给一道需要多步推导的题，要求给出最终答案，评分是对最终答案做精确匹配。代表有 GSM8K（小学数学应用题）、MATH（竞赛数学）、BBH（23 个 BIG-Bench 的"难"子任务）、ARC（科学推理选择题），以及近年为对抗饱和而出现的、难度极高且刻意不公开题面的基准（如 FrontierMath 类）。

核心盲区：过程不可验证#

最终答案对，不蕴含推理过程对。 可能的原因至少有四类：

现象 机制 例子（示意）
捷径/模式匹配 题目有可从表面特征推断的答案分布 问句里出现"总共"就做加法
记忆 题目或同模板题在训练语料中 换数字就崩（见第 2 节 GSM-Symbolic 类实验）
中间错但结论对 多步推导中错误相互抵消 符号错、代入时又错回来
抽取意外正确 输出中有多个数字，抽取规则恰好抓到对的 中间量恰好等于答案

因此推理类基准的分数只应被解读为"最终答案正确率"，而不是"推理能力"。要谈推理，必须引入过程评测：

  • 可验证的中间步骤：让模型输出结构化步骤，对关键中间量单独校验（例如"先写方程，再求解"）；
  • 反事实扰动：改一个无关细节（人名、无关从句）或改一个关键数字，看结果是否按预期变化。对无关扰动敏感 = 记忆或模式匹配；对关键数字不敏感 = 没真算；
  • 多次采样的一致性：同一题多解，正确解是否稳定（第 3 节的自一致性/多数投票）；
  • 人工或 judge 的过程评分（要先用第 1 章的方法校准）。

评分函数的额外风险#

推理题答案通常是数字或表达式，需要从自由文本里抽取。于是出现一个隐蔽的失真：抽取规则是基准的一部分。模型写"答案是 7"和写"答案：7"，对宽松正则都是对的；对严格正则可能只认后者。当两个模型的输出风格不同（一个爱加 \boxed{}、一个爱写自然语言），分差里会混进"格式契合度"。这件事的量化在第 3 节的代码里给出。

代码类基准：唯一有"可执行真值"的一类#

为什么这一类是"硬"的#

代码基准（HumanEval、MBPP、以及面向真实仓库的 SWE-bench 类）用执行测试评分：跑单元测试，通过即正确。它的优势是真值由运行环境给出，而不是由人写的参考答案比对：

  • 不接受同义改写式的"看起来对"；
  • 不接受"答案抽取运气好"；
  • 对语法/边界条件的错误会直接暴露。

这也是为什么代码基准通常比同规模的自然语言基准更难被"表面功夫"刷高。

但它的盲区同样结构性地存在#

盲区一：测试是规范的有限样本。 通过测试只说明"没被这批测试抓到"，不说明"符合意图"。一个函数可以满足全部测试却在语义上错（测试覆盖不到的分支、未定义行为、性能要求）。测试集是规范的一个抽样，抽样之外全是盲区。

盲区二：可以通过"读测试"作弊。 如果被测代码能访问测试文件，或者题目文本里泄露了期望行为，模型可以直接把测试的期望值硬编码。这是"对抗型 Goodhart"在评测里的标准形态。SWE-bench 类的公开数据还有一层额外风险：修复补丁可能已经存在于开源仓库的历史提交中，而模型的训练语料包含这些提交。

盲区三：环境与 flaky test。 依赖版本、超时、随机失败都会引入与能力无关的方差。一个 5% flaky 的测试套件在 200 题上引入的噪声可以吃掉好几个点的分差。

盲区四：pass@k 的协议依赖。 代码基准是 pass@k 的发源地，因此第 1 章第 3 节那三条规则（固定 k 与 n、k≤n、用无偏估计）在这里最常被违反。

一句话定位#

代码基准的可靠性来自"可执行"，它的盲区来自"规范不可穷尽"。 因此它适合做回归门禁（能跑、结果对），不适合单独证明"这个模型会写软件"——后者需要真实仓库上的多步任务（Agent 类评测，本课程后续章节与 agent-systems 课程交叉）。

长文基准：检索 ≠ 理解，长度 ≠ 有效上下文#

形态#

把一段很长的文本（几万到上百万 token）作为上下文，在其中埋入需要的信息，然后提问。最有名的是"大海捞针"（needle-in-a-haystack，NIAH）：在长文里放一句随机事实，问它的值。更系统的有 RULER（可控长度与任务类型的合成长文）、LongBench（真实长文档任务集合）。

三个必须区分的构念#

① 能力性长度（context window）  ：模型接口能接受多少 token —— 由架构/位置编码决定
② 有效长度（effective context） ：性能不显著退化的长度 —— 必须测出来，不是一个规格数字
③ 长文理解（long-context reasoning）：在长文中做多跳、聚合、比较，而非定位单条信息

NIAH 主要测 ① 能否用上、部分测 ②，几乎不测 ③。 单针检索是一个"查找并复制"任务，它甚至不需要理解上下文结构。一个在 NIAH 上接近满分、却在"把 30 份文档综合成一份报告"上崩溃的模型完全可能存在。

失效模式#

失效 机制 诊断设计
U 型位置偏差 开头和结尾的信息可用，中间的信息被"丢掉"（lost in the middle 现象） 把针放在多个位置，画位置-正确率曲线
单针太简单 只查一条信息，不涉及整合 多针、跨针比较、聚合（求和/计数）
干扰敏感 上下文里有语义相近的干扰项 加入近似针（相同实体不同值）
长度与难度混淆 加长上下文时同时加了难度，退化被误归因为长度 固定任务、只变长度；或固定长度、变任务类型
haystack 不自然 用无关随机文本填充，与真实长文档分布不同 用真实文档（报告、代码库、对话日志）构造

实践上怎么用#

长文评测的正确输出不是一个分数，而是一条曲线：横轴是上下文长度，纵轴是各子任务的正确率（检索/多跳/聚合/摘要各一条）。"有效长度"定义为正确率跌破某个阈值（例如相对短上下文下降超过 10%）的长度。 只报"支持 1M token"和只报一个平均分，都不足以支撑"能处理长文档"这个结论。

多模态基准：多出来的自由度#

形态#

图像（或音频/视频）加文本的问答或生成，评分可能是选择题、精确匹配、或模型评审。代表有 MMMU（大学水平多学科多模态选择题）、MathVista（图表与几何推理）、MMBench（能力维度细分的选择题），以及幻觉评测如 POPE（用"是/否"探针问图中是否存在某物体）与 CHAIR（在图像描述里统计提到的物体是否真在图中）。

结构性难点：可调自由度比纯文本更多#

多模态评测里，除了第 1 章说的提示模板，还多出至少四个维度：图像分辨率/缩放方式、图像格式与压缩、OCR 是否可用、多图顺序。这些维度的选择可以让同一模型同一数据的分数相差很大。因此多模态基准的头号问题是：

你报的是模型的能力，还是你的推理管线（分辨率、模板、解析器）的能力？

一个务实的纪律：多模态评测必须冻结并公开整条推理管线（预处理、模板、抽取），并且用管线消融（去掉 OCR、降分辨率）来区分"模型的视觉能力"与"管线的辅助能力"。

幻觉类评测的额外问题#

POPE 类设计（把"图中的物体"与"不在图中的物体"混成是/否问题）同时混合了两件事：感知（能不能看见）与语言先验（这个物体在场景里常见吗）。模型答"是"可能因为看见，也可能因为"厨房里通常有冰箱"这一先验。要分开，需要共现控制：选取与场景强相关但不在图中的物体作为负样本，才测得到"看图"而不是"背常识"。

一张地图：五类基准的构念、评分与盲区#

类型 代表 评分函数 真值强度 结构性盲区 典型误用

取舍#

按类型选基准，本质是在真值强度、覆盖面、抗作弊三者之间取舍：

  • 要真值硬 → 代码/执行类、数学最终答案类。代价是任务面窄、规范覆盖不全。
  • 要覆盖广 → 选择题类（知识）。代价是猜测基线、闭卷假设、极易饱和与污染。
  • 要贴近产品 → 只有自建评测集 + 人工/judge（第 4 节）。代价是要自己承担全部统计与标注工作。
  • 要抗污染 → 滚动/私有基准。代价是失去跨时间可比性。

一个可用的组合原则：用公开基准做"底线回归"（守住已知能力不退化），用私有评测集做"决策"（选型、上线），用人工/红队做"发现未知的坏"。 三者测的东西不同，不能互相替代。

代码：猜测基线、归一化，与"抽取规则造成的分差"#

import numpy as np, re

rng = np.random.default_rng(11)

# ---------- 1. 猜测基线：不同 k 的准确率不可直接比 ----------
def normalize(acc, k):
    """把原始准确率换算成净能力（扣掉 1/k 的猜测基线）。"""
    return (acc - 1/k) / (1 - 1/k)

for k in (4, 5, 10):
    print(f"k={k:2d}: 猜测基线={1/k:.3f} | 原始 0.60 的分 -> 净能力 {normalize(0.60, k):.3f}")
print("→ 同样是 0.60 原始分，k 越大代表的净能力越高；跨 k 排名是错的\n")

# 反过来：同样是 0.70 的净能力，原始分可以差很多
for k in (4, 10):
    print(f"k={k:2d}: 净能力 0.70 -> 原始分 {0.70*(1-1/k)+1/k:.3f}")
print()

# ---------- 2. 抽取规则：与模型能力无关的分差 ----------
n, p_true = 1000, 0.72
gold = rng.integers(0, 100, n)
wrong = (gold + 1) % 100
correct = rng.random(n) < p_true
ans = np.where(correct, gold, wrong)
# 输出风格与是否正确无关：92% 用"答案："，8% 用"答案是 "
style = rng.choice(["colon", "plain"], n, p=[0.92, 0.08])
texts = [f"推理若干步……\n答案：{a}" if s == "colon" else f"推理若干步……\n答案是 {a}"
         for a, s in zip(ans, style)]

strict = re.compile(r"答案：\s*(-?\d+)")          # 只认一种写法
loose = re.compile(r"答案[是为：:]*\s*(-?\d+)")   # 容忍常见变体

def score(pat):
    hit = 0
    for t, g in zip(texts, gold):
        m = pat.search(t)
        hit += int(bool(m) and int(m.group(1)) == g)
    return hit / n

s_loose, s_strict = score(loose), score(strict)
print(f"模型真实正确率 = {p_true:.3f}")
print(f"宽松抽取得分   = {s_loose:.3f}")
print(f"严格抽取得分   = {s_strict:.3f}")
print(f"→ 纯由抽取规则造成的分差 = {s_loose - s_strict:+.3f}（模型一个 token 都没变）")

# ---------- 3. 位置先验捷径检测：打乱选项顺序重测 ----------
# 模拟：模型真实能力 0.60，但它额外有 +0.10 的"总选 A"倾向；正确答案均匀分布在 4 个位置
k, m = 4, 2000
gold_pos = rng.integers(0, k, m)
p_a = 0.35                                   # 模型选 A 的基准倾向（正确率之外的偏置）
choice = np.where(rng.random(m) < p_a, 0, rng.integers(0, k, m))
acc_raw = np.mean(choice == gold_pos)
# 若正确答案的位置分布是偏斜的（真实数据常这样），这个偏置会被读成能力
skewed_pos = rng.choice([0, 1, 2, 3], m, p=[0.4, 0.2, 0.2, 0.2])
acc_skew = np.mean(choice == skewed_pos)
print(f"\n正确答案位置均匀时: 准确率 = {acc_raw:.3f}")
print(f"正确答案偏斜(40% 在 A): 准确率 = {acc_skew:.3f}")
print(f"→ 同一个模型，仅因答案位置分布不同就差 {acc_skew-acc_raw:+.3f}；打乱选项顺序可测出这个捷径")

三个设计决策：

  • 归一化不是数学美化：它把"可猜对的部分"从分数里剥掉，使不同 k 的基准至少能在净能力尺度上对话。但注意它不能修正"题目可被常识猜对"——真实选择题的猜测基线通常高于 1/k（干扰项不是等概率可排除的），所以归一化只是下界修正。
  • 抽取规则的效应是可量化的：这个例子里严格正则只损失了几个点，但真实场景中不同实验室的抽取规则差异可以到十几个点。因此跨论文比较分数时，必须看它的抽取实现，否则比的是管线。
  • 位置先验的检测很便宜：只需打乱选项顺序（或统计正确答案位置分布）重测一次。如果分数随位置分布变化，说明分数里混着"先验运气"。这是"反捷径扰动"的最简单形式。
  • ⚠️ 上面是合成数据，不构成任何真实基准的数值结论。

练习#

  1. 验收一个陌生基准：给你一个没听过的基准（假设它叫"X-Bench，1000 道多选，5 选项，中文，2024 年发布"）。写出你的四个验收问题及各自需要查什么资料；再说明为什么"2024 年发布"这条信息对 2026 年的模型评测很关键。

  2. 猜测基线与可比性：A 基准 4 选项、准确率 0.68；B 基准 10 选项、准确率 0.52。 （a）算两者的归一化准确率； （b）如果你只知道裸准确率就排名，会得出什么错误结论？ （c）除了 1/k，还有哪些因素会让真实猜测基线高于 1/k？这会让归一化偏高还是偏低？

  3. 推理基准的扰动实验设计：你要检验"某模型在 GSM8K 上是真推理还是记模板"。设计三组扰动： （a）替换人名、地点等无关实体； （b）替换关键数字并保持题目可解； （c）加入一个与解题无关的干扰从句（例如"其中 3 个苹果是绿色的"）。 分别预测"真推理"与"记忆/模式匹配"两种模型在三组扰动下的表现，并写出你会报什么指标。

  4. 长文评测：某模型宣称"支持 200K 上下文"，并在 NIAH 上 200K 处达到 98%。 （a）写出至少三个理由说明这不足以证明"能处理 200K 的真实文档"; （b）设计一个由真实文档构成的多跳-聚合任务，说明它的评分方式与你会画的曲线； （c）如果预算只允许测一种长度，你会选哪个长度、为什么？

  5. 多模态的管线归因：某多模态模型在 MMMU 上比竞品高 3 个点，但你发现它用了更高分辨率输入与 OCR 预处理。 （a）设计一个消融实验把"模型视觉能力"与"管线辅助"分开； （b）如果分开后发现竞品的纯模型能力更强，这个结论对选型意味着什么？（提示：你最终比较的是"系统"，不是"模型"）

小结#

  • 验收任何基准只需四个问题：构念、样本来源、评分函数、失效条件。其中"评分函数"常被当成实现细节，实际它会独立制造分差（抽取规则、模板、后处理）。
  • 知识类（选择题）：必须减掉猜测基线 1/k 才能跨基准比较；盲区是闭卷假设、无弃权项（测不到校准）、位置先验捷径；极易饱和。
  • 推理类：答案对 ≠ 推理对。盲区包括捷径、记忆、中间错结论对、抽取意外正确；要谈推理必须加过程验证与反事实扰动。
  • 代码类：唯一有可执行真值的一类，可靠性来自运行环境；盲区是"测试是规范的有限样本"、可读测试作弊、flaky、pass@k 协议依赖。
  • 长文类：必须区分接口长度、有效长度、长文理解；NIAH 主要测检索。正确输出是"长度-子任务"曲线，而不是一个分数。
  • 多模态类：可调自由度比纯文本更多（分辨率/OCR/模板/顺序），必须冻结并公开管线，并用消融区分模型能力与管线辅助；幻觉评测要控制语言先验。
  • 组合原则：公开基准守底线，私有评测集做决策，人工/红队发现未知的坏。
