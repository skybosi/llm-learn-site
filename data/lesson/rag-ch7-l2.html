评测驱动迭代：指标树、失败分类与统计判据#

这一节要解决什么#

上一节把架构解出来了。但架构只是起点：接下来的每一天都要回答同一个问题：

这次改动，到底有没有让系统变好？

这个问题在 RAG 里格外难回答，原因有三个：

  1. 指标不是单一的：召回变好可能让生成变差（更多干扰，第 5 章第 3 节）；延迟降低可能以质量为代价。
  2. 信号很弱：典型改动的收益是几个百分点，而评测集往往只有几百题 —— 在 300 题上，你连 10 个百分点的变化都测不准。
  3. 失败混在一起：一个"答错了"可能来自召回、排序、生成、拒答策略中的任何一个，而它们的处方完全不同。

本节要回答四个问题：

  1. 指标怎么组织成树？为什么"用户满意度"不能直接作为优化目标？
  2. 评测集怎么建？为什么每题都必须标注黄金证据 id，而不只是答案？
  3. 失败怎么分类？怎么保证分类是基于可观测信号而不是人工印象？
  4. 判断"改动有效"需要哪些统计判据？你的评测集到底能检出多大的效应？

结论先放在这里：评测只有一个目的 —— 把"哪个改动值得做"变成一个可判定的问题。做法是三步：①把北极星指标拆成可干预的叶子指标（指标树）；②用基于可观测信号的判定树把失败归类，按最大类排序优先级；③用配对统计判据（bootstrap CI + McNemar）而不是点估计比较。⚠️ 实测示例：候选系统 B 各项指标全面上升（端到端 0.390→0.477），但与此同时评测集的最小可检出效应（MDE）约为 10.3 个百分点 —— 也就是说，如果真实提升只有 3 个百分点，这个 300 题的评测集根本测不出来（要检出 +3pt 需要约 3547 题）。

一、指标树：从北极星到可干预的叶子#

1.1 构造规则#

指标树必须满足三条规则（缺一条就会退化成"看板上的一堆数字"）：

  1. 可观测：线上或离线都能被测量，不需要额外的人工作业；
  2. 可归因：指标下降时能指向某个具体环节；
  3. 可干预：存在明确的改动能提升它 —— 这是最容易被违反的一条。

反例："用户满意度"不可直接干预。你无法"提升满意度"，只能通过提升它的代理指标（答案正确率、引用可信度、延迟、拒答恰当性）来间接提升。所以满意度只能作为北极星的命名，不能作为优化的叶子。

1.2 一棵可用的指标树#

北极星：端到端有用回答率（answer_ok AND citation_ok）
├─ 答案正确率
│  ├─ 召回覆盖（黄金证据命中率）      <- 切分/索引/检索/查询改写
│  ├─ 排序质量（黄金证据进入上下文）    <- 重排/融合/预算分配
│  └─ 生成利用率（有证据时是否采用）    <- grounding 指令/去干扰/拒答
├─ 引用可信度（引用一致性）
├─ 拒答恰当性
│  ├─ 该拒答就拒答（召回为空/证据不足）  <- 拒答阈值
│  └─ 不该拒答却拒（覆盖率损失）        <- 阈值过高的代价
├─ 延迟（P95 总延迟、TTFT）
└─ 成本（每查询、每正确回答）

为什么"每正确回答成本"要和"每查询成本"并列：降价可以靠降质量实现，所以只有"每正确回答成本"才是真正的效率指标。⚠️ 示例数据里，B 系统端到端正确率 0.477，若每查询成本 c，则每正确回答成本 ≈c/0.477；任何质量变化都会改变这个分母。

1.3 代理指标的失效#

代理指标会骗人。三种典型失效：

失效 表现 例
优化代理、损害目标 代理涨、北极星跌 提高 recall@10 却引入干扰，答案正确率下降
代理可被"作弊" 指标好看但无用 引用率可以通过"抄一个 doc id"提高（装饰性引用）
代理与目标脱钩 长期不相关 早期 recall 与最终正确率强相关，后期饱和后相关性消失

判据：每个代理指标都要有周期性校验 —— 在人工标注的一小批样本上验证"代理涨是否伴随目标涨"。没有校验的代理指标迟早会说谎。

二、评测集：构建、标注与防过拟合#

2.1 分层的 golden set#

评测集必须分层构造，否则它只反映最容易的那一类问题：

分层维度 分层示例 为什么必须覆盖
查询类型 单跳 / 多跳 / 聚合 / 应拒答 各类的失败机理不同
难度 词汇匹配 / 语义改写 / 需要推理 平均分会掩盖长尾
文档类型 正文 / 表格 / 代码 / 邮件 切分策略对它们效果不同
租户/权限 单租户 / 多租户 / 无权限 权限是最容易出事故的一类
时间 新增文档 / 陈旧文档 索引更新相关失败

配额：每层至少 20~30 题起（够做粗略比较），关键层（如应拒答、权限）建议 50 题以上。

2.2 每题必须标注黄金证据#

这是评测集设计里最重要的一条：

只标注"标准答案"的评测集，无法区分召回失败与生成失败。

因为当系统答错时，你不知道是"没找到那篇文档"还是"找到了但没用好"。而这两者的处方完全不同（前者改检索，后者改 prompt 与装配）。

因此每题的标注必须包含：

{
  "query": "...",
  "golden_evidence": ["doc:123#chunk-4", "doc:456#chunk-1"],   // 必需
  "answer": "...",                                             // 可选（抽取式任务必需）
  "must_refuse": false,                                        // 拒答类必需
  "tenant": "acme",                                            // 权限校验必需
  "type": "multi", "difficulty": "hard"
}

附带好处：有了黄金证据 id，就能自动计算召回覆盖（第 7 章第 3 节案例会用到），也能自动做第 6 章第 4 节的归因。

2.3 难负样本#

只有正例的评测集会高估系统。难负样本（near-duplicate 但答案不同、同主题不同事实）是检出"干扰敏感"与"过度自信"的关键。构造方式：

  • 从语料里取与黄金证据相似度高但事实不同的 chunk（例如同产品的上一代参数）；
  • 标注为"不应作为证据"；
  • 断言系统在加入这些负例后不会答错（或至少会降低置信/拒答）。

2.4 防过拟合：评测集也会"被训坏"#

只要你在同一批题上反复调参，指标就会开始过拟合。三条防腐措施：

  1. dev / test 切分：dev 用于迭代，test 冻结（只在发布决策时打开）；
  2. 定期换血：每季度替换一部分题（保留旧题用于纵向比较，新增题用于防漂移）；
  3. hidden set：保留一小批（20%）从不公开给调参者。

判据：如果 test 与 dev 的指标差距在连续多次迭代中持续扩大，说明已经在过拟合。

三、失败分类：基于可观测信号的判定树#

3.1 判定树#

分类必须唯一且可复算。一棵可用的判定树（输入全部来自 trace：第 6 章第 4 节）：

if 行为 != 回答 且 不应拒答:        -> 拒答错误（过度拒答）
if 应拒答 且 行为 != 拒答:          -> 该拒不拒
if 黄金证据命中数 == 0:            -> 召回失败
if 进入上下文的黄金证据数 == 0:      -> 排序失败
if 答案不正确:                      -> 生成未用
if 引用不一致:                      -> 引用不一致
else:                              -> 无失败

顺序很重要：先判"行为层"（拒答），再判"检索层"，再判"生成层"。因为后面的判据在拒答的情况下没有意义。

3.2 分类分布 → 优先级#

⚠️ 示例（合成评测集 N=300，系统 B）：

失败类 数量 占失败比例
召回失败 120 56.6%
生成未用 55 25.9%
排序失败 22 10.4%
该拒不拒 12 5.7%
引用不一致 3 1.4%

结论：最大类是召回失败，占 56.6%。所以下一步该做的是检索侧（切分、索引、混合、查询改写），而不是继续调 prompt。

这条结论的价值在于它反直觉：团队的直觉往往指向"模型不够好"（换更大的模型），而数据说 56.6% 的失败根本没把证据找回来 —— 换模型一分钱都赚不到。

3.3 边界#

  • 判定树依赖 trace 的完整性：没有黄金证据标注、没有候选名次，就无法分类。所以评测集与 trace 设计必须一起做（第 6 章第 4 节）。
  • "生成未用"包含多种子因：位置（ch5-l3）、干扰、先验冲突、指令缺失。分类只到这一层，进一步要跑第 5 章第 3 节的四个测试。
  • 分类是"当前配置下"的：k、预算、模型一变，分布就变。每次大改动后要重新分类。

四、统计判据：改动到底显著吗#

4.1 配对设计#

比较两个系统时，必须用同一批查询（配对），因为题目难度差异极大。配对设计能消掉"题目难度"这部分的方差，因此检定力远高于两组独立样本。

配对后，比较的对象是不一致对：

B 错 B 对
A 错 一致 b01​
A 对 b10​ 一致

只有 b01​ 与 b10​ 携带"两系统不同"的信息 —— 一致的部分再多也不增加判别力。

4.2 两个判据#

① bootstrap 置信区间（对配对差分重采样）：

Δ=n1​i∑​(yiB​−yiA​),CI95%​=[Δ2.5%∗​, Δ97.5%∗​]

Δ=n1​i∑​(yiB​−yiA​),CI95%​=[Δ2.5%∗​, Δ97.5%∗​]

Δ∗ 是重采样的分位数。判据：CI 不含 0 才算显著。

② McNemar 检验（配对二分类）：

χ2=b01​+b10​(∣b01​−b10​∣−1)2​

（分子减 1 是连续性校正。）H0​：两系统在配对上的错误率相同。p 值由 χ12​ 分布给出。

⚠️ 示例（A 为基线、B 为候选，端到端正确率）：

Δ = +0.0867   95% CI = [+0.0166, +0.1567]   显著（不含 0）
列联: A错B对=74  A对B错=48  一致=178
统计量 χ²=5.123  p≈0.0236  拒绝原假设（有显著差异）

两个判据结论一致：B 显著更好。

4.3 样本量：你的评测集能检出多大效应#

这是最常被忽略、也最容易导致错误结论的一项。单比例（双侧 α=0.05、power =0.8、p≈0.5）：

n≈δ2(zα/2​+zβ​)2p(1−p)​

⚠️ 示例：

要检出的提升 δ 所需题量（独立） 配对（不一致率 15%）
+1% 19,623 —
+3% 2,181 1,309
+5% 785 471
+10% 197 —

反过来说，给定题量就能算出"最小可检出效应"（MDE）：

MDE≈(zα/2​+zβ​)npdisc​​​

⚠️ 示例：N=300、实测不一致率 pdisc​=122/300=0.407：

MDE ≈ 0.103，即约 10.3 个百分点
-> 本评测集无法可靠检出小于 ~10pt 的提升；
   想检出 +3pt 需要约 3547 题。

这条数字是本节最有用的一个。它解释了大量真实场景里的困惑：

"我改了一处，指标涨了 2%，要不要上？" ——在 300 题上，你看到的 2% 完全在噪声范围内，涨或跌都不构成证据。

4.4 显著性之外：效应量与多重比较#

  • 统计显著 ≠ 实际重要：N 很大时，+0.5% 也能显著，但它不值得上线成本。同时报告效应量与 CI 宽度。
  • 多重比较：如果你一次比较了 8 个指标，其中 1 个"显著"很可能是偶然（家族错误率上升）。做法：预先指定主指标（primary），其余作为探索性指标；或对 p 值做 Bonferroni 校正（阈值 α/m）。
  • 不要反复看、看到显著就停（peeking）：会显著抬高假阳率。要么固定样本量，要么用序贯检验。

五、离线-在线差距与上线门禁#

5.1 离线涨、线上不涨的五个原因#

原因 机理 检查方法
分布漂移 评测集题目与真实查询分布不同 对比线上 query 类型分布 vs 评测集分层
评测集泄漏 调参时反复看 test，或评测集与训练语料重叠 检查 test 的访问记录与语料重叠
缓存影响 线上大量请求走缓存，改动只影响 miss 的部分 看命中率与改动生效比例
延迟/拒答权衡 质量涨但延迟超预算，触发降级或用户放弃 联合看质量与延迟分位数
用户行为变化 用户看到更好的回答后，问更难的问题 看查询难度分布随时间的变化

判据：每次离线涨、线上不涨，必须从这五个原因里指认一个并给出证据。指认不出来，就说明观测能力不够（回到第 6 章第 4 节）。

5.2 上线门禁（regression gate）#

一个改动必须同时满足四个条件才允许上线：

① 主指标不降（例如召回覆盖不低于基线 -1pt，或用 CI 下界判定）
② 目标指标上升且显著（CI 下界 > 0）
③ 延迟与成本不超预算（P95、每查询成本）
④ 没有新增失败类型（失败分类分布里不出现新的类，且最大类没有变大）

⚠️ 示例判定：

{'primary_not_worse': True, 'target_up': True, 'cost_latency_ok': True,
 'no_new_failure': True}
-> 通过（要求主指标不降、目标指标升、成本延迟不超、无新增失败类型，且 CI 下界 > 0）

为什么必须四条一起：只满足 ② 是危险的 —— 一个改动可以提高平均正确率、同时新增一整类失败（例如"引用不一致"从 1% 涨到 20%）。门禁的作用是防止"用平均分掩盖新问题"。

代码#

# -*- coding: utf-8 -*-
"""⚠️ 合成数据：指标树 / 失败分类（判定树）/ bootstrap CI / McNemar / 样本量估算。
   所有数字为构造数据，用于演示判据；真实结论必须用自己的评测集重算。"""
import math, numpy as np
from collections import Counter

rng = np.random.default_rng(11)
N, K, CTX = 300, 10, 5
Q = []
for i in range(N):
    t = ["single", "multi", "refuse"][i % 3]
    n_gold = 3 if t == "multi" else 1
    Q.append(dict(qid=i, type=t, golden=set(range(i * 5, i * 5 + n_gold))))

def recall_at_k(p_recall, q, k=K):
    """模拟检索：p_recall 是单条黄金证据被正确打高分的概率。"""
    rng2 = np.random.default_rng(q["qid"] * 1000003 + int(p_recall * 1000))  # 稳定种子
    pool = list(range(6000))
    scores = rng2.normal(0, 1, len(pool))
    for g in q["golden"]:
        if rng2.random() < p_recall:
            scores[g] += 3.0
    order = np.argsort(-scores)[:k]
    return [int(x) for x in order], len(q["golden"]), len(set(order) & q["golden"])

def run_system(p_recall, p_gen, p_refuse_ok):
    rows = []
    for q in Q:
        order, n_gold, hit = recall_at_k(p_recall, q)
        in_ctx = len(set(order[:CTX]) & q["golden"])
        if q["type"] == "refuse":
            behaviour = "refuse" if rng.random() < p_refuse_ok else "answer"
            ans_ok, cite_ok = (behaviour == "refuse"), True
        else:
            enough = in_ctx >= (1 if q["type"] == "single" else 2)
            ans_ok = bool(enough and rng.random() < p_gen)
            behaviour, cite_ok = "answer", bool(enough and rng.random() < 0.90)
        rows.append(dict(qid=q["qid"], type=q["type"], n_gold=n_gold, hit=hit,
                         in_ctx=in_ctx, ans_ok=ans_ok, behaviour=behaviour, cite_ok=cite_ok))
    return rows

A = run_system(0.74, 0.90, 0.70)      # 基线
B = run_system(0.86, 0.90, 0.85)      # 候选（召回与拒答策略更好）

def metrics(rows, name):
    e2e = np.mean([1.0 if (r["ans_ok"] and r["cite_ok"]) else 0.0 for r in rows])
    return dict(name=name, end_to_end=e2e,
                answer=np.mean([r["ans_ok"] for r in rows]),
                recall=np.mean([r["hit"] / r["n_gold"] for r in rows]),
                citation=np.mean([r["cite_ok"] for r in rows]),
                refuse_ok=np.mean([r["behaviour"] == "refuse" for r in rows if r["type"] == "refuse"]))

mA, mB = metrics(A, "A"), metrics(B, "B")
print("== 指标树（⚠️ 合成评测集，N=300）==")
print(f"{'指标':<16} {'A(基线)':>9} {'B(候选)':>9} {'Δ':>9}")
for k, label in [("end_to_end", "北极星:端到端"), ("answer", "答案正确"), ("recall", "召回覆盖"),
                 ("citation", "引用一致"), ("refuse_ok", "该拒答就拒答")]:
    print(f"{label:<16} {mA[k]:>9.3f} {mB[k]:>9.3f} {mB[k]-mA[k]:>+9.3f}")

def classify(r):
    """基于可观测信号的判定树（输入来自 trace）。"""
    if r["behaviour"] == "refuse" and r["type"] != "refuse": return "拒答错误"
    if r["type"] == "refuse" and r["behaviour"] != "refuse": return "该拒不拒"
    if r["hit"] == 0:                                       return "召回失败"
    if r["in_ctx"] == 0:                                    return "排序失败"
    if not r["ans_ok"]:                                     return "生成未用"
    if not r["cite_ok"]:                                    return "引用不一致"
    return "无失败"

print("\n== 失败分类分布（B 系统）==")
cnt = Counter(classify(r) for r in B)
tot = sum(v for k, v in cnt.items() if k != "无失败")
for k, v in cnt.most_common():
    print(f"  {k:<12} {v:>4}  占失败 {(v/tot if k != '无失败' and tot else 0):>6.1%}")

# ---- bootstrap CI（配对差分）----
a_e2e = [1.0 if r["ans_ok"] and r["cite_ok"] else 0.0 for r in A]
b_e2e = [1.0 if r["ans_ok"] and r["cite_ok"] else 0.0 for r in B]
d = np.array(b_e2e) - np.array(a_e2e)
rb = np.random.default_rng(0)
boot = d[rb.integers(0, len(d), (10000, len(d)))].mean(axis=1)
lo, hi = float(np.percentile(boot, 2.5)), float(np.percentile(boot, 97.5))
print(f"\n== bootstrap 95% CI（端到端正确率的配对差分 B-A）==")
print(f"  Δ = {d.mean():+.4f}   95% CI = [{lo:+.4f}, {hi:+.4f}]   "
      f"{'显著（不含 0）' if lo > 0 or hi < 0 else '不显著（含 0）'}")

# ---- McNemar ----
b01 = sum(1 for x, y in zip(a_e2e, b_e2e) if x == 0 and y == 1)
b10 = sum(1 for x, y in zip(a_e2e, b_e2e) if x == 1 and y == 0)
stat = (abs(b01 - b10) - 1) ** 2 / (b01 + b10) if (b01 + b10) else 0.0
p_val = math.erfc(math.sqrt(stat / 2))          # χ²(1) 的正态近似
print(f"\n== McNemar（配对二分类）==")
print(f"  列联: A错B对={b01}  A对B错={b10}  一致={len(d)-b01-b10}")
print(f"  统计量 χ²={stat:.3f}  p≈{p_val:.5f}  "
      f"{'拒绝原假设' if p_val < 0.05 else '不能拒绝原假设'}")

# ---- 样本量与 MDE ----
def n_for_effect(delta, p=0.5):
    za, zb = 1.959964, 0.841621
    return math.ceil(((za + zb) ** 2) * p * (1 - p) / (delta ** 2))
print("\n== 样本量估算（单比例、α=0.05、power=0.8）==")
for delta in (0.01, 0.03, 0.05, 0.10):
    print(f"  检出 +{delta:.0%} -> 约 {n_for_effect(delta):>6} 题")
p_disc = (b01 + b10) / len(Q)
mde = (1.959964 + 0.841621) * math.sqrt(p_disc / len(Q))
print(f"\n== 本评测集的最小可检出效应（配对）==")
print(f"  不一致对比例 = {b01+b10}/{len(Q)} = {p_disc:.3f}")
print(f"  N={len(Q)} 时 MDE ≈ {mde:.3f}（约 {mde*100:.1f} 个百分点）")
print(f"  想检出 +3pt 需要约 {math.ceil(((1.959964+0.841621)**2)*p_disc/(0.03**2))} 题")

print("\n== 上线门禁 ==")
gate = dict(primary_not_worse=(mB["recall"] >= mA["recall"] - 0.01),
            target_up=(mB["end_to_end"] > mA["end_to_end"]),
            cost_latency_ok=True, no_new_failure=True)
print(f"  {gate}")
print(f"  -> {'通过' if all(gate.values()) and lo > 0 else '不通过'}")

关键设计决策：把 classify() 写成只依赖 trace 字段的纯函数，而不是"人看日志打标签"。这是本节的中心选择：人工标签有两个致命问题 —— 不可复算（换个人结论不同）与不可规模化（评测集一大就做不动）。而判定树的顺序（先行为、再检索、再生成）保证了分类的唯一性与可解释性。代价是它只能分到较粗的粒度（"生成未用"内部还有位置/干扰/先验三种子因），需要第 5 章第 3 节那套反事实测试再往下钻。

练习#

  1. 为你的系统画指标树。要求：每个叶子满足"可观测/可归因/可干预"三条；对每个叶子写出"哪个改动能提升它"；找出树里不满足第三条的叶子（如果有，说明它是伪指标，需要继续拆）。

  2. 重算你的 MDE。用你评测集的题量与实测不一致率，计算 MDE。然后回答：(a) 你最近一次"提升了 2%"的改动，是否在这个 MDE 之内？(b) 要把 MDE 压到 3pt，需要多少题？按你的标注成本算总价。

  3. 配对 vs 独立。用同一批模拟数据，分别按配对（同一批题）与独立（两组不同题）做检验，比较检定力。回答：在什么条件下配对带来的增益最大（提示：题目难度方差越大，配对收益越大）。

  4. 多重比较的代价。假设你一次比较 10 个指标，每个用 α=0.05。计算家族错误率；然后给出 Bonferroni 校正后的阈值，并说明"预先指定主指标"为什么是更好的做法。

  5. 构造"平均分掩盖新问题"的场景。设计一组数据，使候选系统端到端正确率提升 3pt，但新增了一类失败（例如引用不一致从 1% 涨到 15%）。说明门禁的四条件如何拦住它，以及为什么第 ④ 条不可省略。

  6. 评测集过拟合的检测。设计一个实验：连续 20 次在同一 test 上选择"最好"的配置，画出 test 指标与 hidden set 指标的差距随迭代次数的变化。回答：差距在多少次后开始显著？你会怎么设置防腐规则？

  7. 拒答类的指标设计。拒答有两类错误方向相反（该拒不拒 vs 不该拒答却拒）。设计一个单一可优化指标（提示：用代价加权的错误率），并说明权重怎么从业务里估。然后给出它的可干预叶子。

  8. 从失败分类到路线图。假设你的失败分布是：召回失败 30%、排序失败 35%、生成未用 25%、引用不一致 10%。按"预期收益/成本"排序给出接下来三件该做的事，每件写明预期能消除多少百分点、依据是什么（提示：排序失败的处方是重排，成本可从第 5 章第 4 节的 MC 表估）。

小结#

  • 指标树三原则：可观测、可归因、可干预。"用户满意度"不可干预，只能作为北极星的命名，必须拆成答案正确率、引用可信度、拒答恰当性、延迟、每正确回答成本。
  • 代理指标会失效（优化代理损害目标、可被作弊、后期脱钩），必须有周期性的人工标注校验。
  • 每题必须标注黄金证据 id，否则无法区分召回失败与生成失败 —— 这是评测集设计里最重要的一条。附带好处：可自动算召回覆盖、可做第 6 章的归因。
  • 难负样本（相似但事实不同）是检出"干扰敏感"的关键；防过拟合靠 dev/test 切分 + 定期换血 + hidden set。
  • 失败分类必须是基于可观测信号的判定树（先行为、再检索、再生成），输入全部来自 trace。⚠️ 示例分布：召回失败 56.6%、生成未用 25.9%、排序失败 10.4%、该拒不拒 5.7%、引用不一致 1.4% → 优先级指向检索侧，而不是换模型。
  • 必须配对比较（同一批题），因为只有不一致对携带信息。判据用 bootstrap CI（不含 0）与 McNemar（连续性校正）。⚠️ 示例：Δ=+0.0867、CI [+0.0166, +0.1567]、χ2=5.123、p≈0.0236 → 显著。
  • 样本量决定你能检出多大效应：⚠️ N=300 时 MDE ≈ 10.3pt，即小于 10 个百分点的变化在噪声内；要检出 +3pt 需要约 3547 题（单比例口径 2181 题）。"涨了 2% 要不要上"在 300 题上不是证据问题，是样本量问题。
  • 显著 ≠ 重要：同时报告效应量与 CI 宽度；预先指定主指标，避免多重比较与 peeking。
  • 上线门禁四处同时满足：主指标不降、目标指标升且 CI 下界 > 0、延迟成本不超、无新增失败类型。第四条防止"用平均分掩盖新问题"。
  • 离线涨线上不涨必须从五个原因（分布漂移、评测集泄漏、缓存、延迟/拒答权衡、用户行为变化）中指认一个并给证据。
  • 一句话：评测不是算一个分数，而是回答"哪个改动值得做、改动是否真的有效"。前者靠失败分类，后者靠配对统计；而两者都受同一个约束限制：你的评测集能检出多大的效应。
