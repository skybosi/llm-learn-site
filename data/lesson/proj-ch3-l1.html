项目规划（LLM 领域微调）#

第三个项目是 LLM 领域微调（LoRA）：用一份领域指令数据，把一个 7B 开源模型调成"懂你领域、按你格式回答"的专家。你已经学完微调原理与 LoRA 基础，本课聚焦"怎么把它做成一个可写进简历、可展示的实战项目"——重点是数据、模型、算力的现实选型，而不是复述 LoRA 公式。

一、目标与步骤#

1. 项目目标：微调出一个"可量化提升"的领域模型#

微调项目最容易失败在"没有明确目标"。本项目的验收不是"训出来了"，而是能证明"微调后比微调前好"：

  • 有一个明确的领域（医疗问诊 / 法律咨询 / 电商客服 / 财报问答，选一个）。
  • 有一份领域指令数据集，能训、能测。
  • 用 LoRA 在 7B 模型上微调，记录 rank/alpha 与显存/时间成本。
  • 用同一套测试问题对比"基座 vs 微调"，输出可复现的分数与样例。

一句话验收："在领域测试集上，微调模型在格式遵循率、领域准确率上相比基座有可量化提升，且能给出 2~3 条具体样例对比。"

2. 选领域与数据：从公开数据集起步#

建议先选一个"有现成公开指令数据"的领域，避免把时间花在造数据上。可选的公开指令数据集：

数据集 领域/用途 获取方式
Alpaca（Stanford） 通用指令跟随，可作"格式打底"数据 https://github.com/tatsu-lab/stanford_alpaca
Alpaca-Chinese / 中文指令集 中文指令跟随 Hugging Face 数据集仓库
医疗问答公开集（如 CMeEE / 医疗对话） 医疗领域 Hugging Face datasets
法律咨询公开集 法律领域 Hugging Face datasets

数据策略：用"少量高质量领域数据（1k~5k 条）+ 通用指令数据打底"的组合，比"几万条噪声数据"更稳。每条数据统一成指令格式：

{"instruction": "判断以下症状最可能是什么病，并给出就医建议。", "input": "发热、咳嗽、乏力三天", "output": "……"}

质量红线：微调是"垃圾进垃圾出"。花一天清洗数据（去重、去格式错乱、人工抽检 100 条）比多训一个 epoch 更有价值。

3. 模型选型：7B 基座怎么选#

模型 参数量 中文能力 生态 说明
Qwen2.5-7B-Instruct 7B 强 Hugging Face 原生支持好 中文领域首选，指令版底子好
Llama-3-8B-Instruct 8B 中 生态最广 英文强、社区资源多
Mistral-7B-Instruct 7B 中 社区活跃 结构清晰、教程多

本项目建议选 Qwen2.5-7B-Instruct：中文领域 + 指令版已对齐，用 LoRA 在它上面做领域微调，收敛快、效果可预期。面试时能说出"为什么是它"即可，不必纠结最新榜单。

4. 算力与显存预算（先算账，再动手）#

7B 全参数微调需要约 112GB 显存（用 AdamW + fp32），一般个人显卡扛不住；LoRA 把它压到消费级可跑：

方案 显存需求（约） 适用
LoRA（fp16/bf16） ~16-20GB 单张 24GB（3090/4090/A10）
QLoRA（4-bit 量化 + LoRA） ~8-10GB 单张 12GB 或免费 Colab T4
全参数微调 ~112GB+ 多卡 A100

没有大显存就用 QLoRA，效果接近 LoRA，成本降一半以上。本课代码骨架同时给出 LoRA 与 QLoRA 两个开关。

5. 里程碑#

步骤 产出物
1. 数据准备与清洗 指令 JSONL + 训练/验证切分
2. 微调脚本（LoRA/QLoRA） 可复现训练配置
3. 训练与 checkpoint 保存 LoRA 权重 + 合并模型
4. 评估 基座 vs 微调的分数与样例对比
5. rank/alpha 小实验 参数选择结论
6. 复盘与话术 成本/效果表 + 面试问答

二、代码骨架（本节先搭框架）#

先立起环境与"最小训练通路"——用一个极小的配置跑通"加载模型 → 加载数据 → 训几步 → 保存 LoRA"，确认环境无误：

pip install transformers datasets peft accelerate trl bitsandbytes
# finetune-project/
# ├── data/train.jsonl  data/val.jsonl
# ├── src/
# │   ├── prepare_data.py    # 数据清洗与格式化
# │   ├── train_lora.py      # LoRA/QLoRA 训练
# │   └── evaluate.py        # 基座 vs 微调对比
# └── outputs/lora/          # LoRA 权重

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model, TaskType

model_name = "Qwen/Qwen2.5-7B-Instruct"

# 最小通路：加载模型与分词器，套上 LoRA，验证参数规模
tokenizer = AutoTokenizer.from_pretrained(model_name, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_name, torch_dtype=torch.bfloat16, device_map="auto"
)

lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=8,                 # 低秩维度，第 2 课展开讲怎么选
    lora_alpha=16,       # 缩放系数，常取 r 的 2 倍
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],  # 只训注意力投影
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()  # 预期：可训练参数远小于总参数（<1%）

最小通路通过标准：能打印出"可训练参数占比"，且训练一步 loss 能下降。先跑通再谈效果，避免在环境问题上周旋。

三、验收与复盘（规划视角）#

  1. 领域与数据已锁定：写下你选的领域、数据集来源、数据量级与清洗计划。
  2. 选型能自圆其说：30 秒讲清"为什么 Qwen2.5-7B + LoRA/QLoRA + 这份数据"。
  3. 算力账已算清：明确用 LoRA 还是 QLoRA，预估显存与单卡训练时长。
  4. 最小通路已跑通：print_trainable_parameters() 输出可训练参数占比 <1%。
  5. 简历一句话初稿："LoRA fine-tuned Qwen2.5-7B on a 3k domain instruction set, improving format-following from 62% to 91% with only 0.3% trainable params on a single 24GB GPU."（数字后续补全）
